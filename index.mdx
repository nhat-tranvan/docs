CloudThinker [agents](/guide/agents/overview) investigate incidents, pull requests, app security gaps, and cloud spend across your systems, find the root cause with evidence, and propose a fix.

Reads run on their own. A write (any change to your systems) runs only when your [approval settings](/guide/approvals/approval-mode) allow it. New workspaces start on **Auto · Rules + AI · Ask me**: your Rules, or AI judgment for a safe write that matches your request, can let a write run, and everything else waits for a person. Switch to **Manual** to approve every write yourself.

## Is it a fit?

| Question | Short answer | Details |
|---|---|---|
| What does it connect to? | Clouds (AWS, Google Cloud, Azure), Kubernetes, Git hosts (GitHub, GitLab, Bitbucket, Azure DevOps, CodeCommit), alert sources such as Datadog and PagerDuty, IaC such as Terraform, and ticketing such as Jira | [Connection catalog](/guide/connections/overview#connection-catalog) |
| What can agents touch? | Only what your connections allow. Turn off **Allow writes** on a connection and every change to it is refused. | [How access works](/guide/connections/overview#how-access-works) |
| Where does it run? | A CloudThinker-managed service at `app.cloudthinker.io` by default | [Deployment](/guide/deployment/overview) |
| Where do I use it? | The web app, the [CLI](/guide/cli/overview), [Slack](/guide/slack-integration), [Google Chat](/guide/google-chat-integration), and [Microsoft Teams](/guide/teams-integration) | |
| What does it cost? | Plans are priced per seat and include credits, the unit agent work uses. Every chat message and product run spends credits. A Free plan is available. | [Pricing](/guide/billing/pricing), [Usage](/guide/billing/usage) |
| How do I review it for my company? | Identity, data handling, access, and audit in one place | [Security overview](/guide/security/overview) |

## Pick a product

Each product needs only its own connection, so you can start with the one that matches your pain and add the rest later.

<CardGroup cols={2}>
  <Card title="Resolve (incidents)" icon="triangle-exclamation" href="/guide/incident/overview">
    Investigates every incident. Pulse filters alert noise, then an agent finds the root cause with evidence and proposes a fix. Needs an alert source such as Datadog or PagerDuty, or log an incident by hand.
  </Card>
  <Card title="Review (pull requests)" icon="code-pull-request" href="/guide/code-review/overview">
    Reviews every pull request with inline comments and suggested fixes, using your team's conventions. Needs a Git connection such as GitHub, GitLab, or Bitbucket. Setup takes about 10 minutes, and GitHub and Bitbucket need no webhook step.
  </Card>
  <Card title="Cyber (app security)" icon="shield-halved" href="/guide/security/cyber-overview">
    Pentests a running app you're authorized to test, then tracks each finding with its evidence until a retest confirms the fix. Needs the app's URL and a DNS TXT record that proves you own its domain. A test login is optional.
  </Card>
  <Card title="Optimize (cloud spend)" icon="dollar-sign" href="/guide/cost-optimization/overview">
    Ranks what to fix in your cloud bill: idle resources, oversized instances, and cost anomalies. Needs an AWS, Google Cloud, or Azure connection.
  </Card>
</CardGroup>

To connect an alert source for Resolve, start with [Datadog](/guide/connections/datadog) or [PagerDuty](/guide/connections/pagerduty), or see [all alert sources](/guide/incident/integrations).

## How CloudThinker works

Every product runs the same agentic loop: **Detect → Analyze → Resolve → Validate**.

<WorkflowScene />

| Stage | What happens | Example |
|---|---|---|
| **Detect** | A signal arrives from one of your [connections](/guide/connections/overview). | A Datadog alert, a new pull request, a cost spike |
| **Analyze** | The agent gathers evidence from your real systems, plus [memory](/guide/memory) of past work and your [knowledge](/guide/knowledge). | Checks the recent deploy, pod events, and database metrics |
| **Resolve** | The agent proposes or runs the fix. Every write passes your [approvals](/guide/approvals/overview) first. | Proposes a rollback and waits for your **Approve** |
| **Validate** | The agent checks the outcome and saves what it learned. | Confirms error rates recovered, saves the lesson for next time |

Each run feeds shared memory, so the next investigation starts with what the last one learned. [See how the pieces fit](/guide/concepts).

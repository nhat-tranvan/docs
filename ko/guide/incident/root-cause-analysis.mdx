근본 원인 분석(RCA)은 CloudThinker가 인시던트가 왜 일어났는지 밝히는 단계입니다. 인시던트, 그 뒤의 알림, 연결된 시스템을 읽고 가능한 설명을 검증한 뒤, 서면 판정, 장애가 어떻게 전개되었는지 보여주는 다이어그램, 제안된 수정 목록을 전달합니다. 사용자는 이를 검토하고 다음에 할 일을 결정합니다.

RCA는 [Resolve](/ko/guide/incident/overview)의 Investigate 단계입니다. 이미 설정한 [연결](/ko/guide/connections/overview)을 통해 로그, 지표, 트레이스, 최근 변경, 의존성을 읽으며, 그 연결이 닿는 곳까지만 접근할 수 있습니다. 조사는 읽기만 합니다. 모든 변경은 [runbook](/ko/guide/incident/runbooks)과 [Approvals](/guide/approvals/overview) 설정을 거칩니다. 모델이 보는 것과 시크릿 처리 방식은 [Data protection](/guide/security/data-protection)을 참고하세요.

## 시작하기 전에

- 클라우드 계정, Kubernetes 클러스터, 모니터링 도구처럼 관련 시스템에 대한 [연결](/ko/guide/connections/overview) 하나 이상. RCA는 읽을 수 있는 것만 확인할 수 있습니다.
- 조사를 시작하고, 제안을 정리하고, 인시던트 상태를 변경(종료 포함)하려면 워크스페이스 **Admin** 역할. Developer와 Viewer는 결과를 읽을 수 있습니다. [Roles](/guide/security/roles)를 참고하세요.
- 크레딧. 자동으로 시작되는 것을 포함해 각 조사는 에이전트 작업이며, 다른 실행과 마찬가지로 크레딧이 청구됩니다. [Usage](/ko/guide/billing/usage)에서 지출을 확인하고, [Credit limits](/guide/billing/credit-limits)로 워크스페이스 상한을 설정하세요. 자동 실행을 멈추려면 웹훅의 **Auto-investigate**를 끄거나 **AI auto-investigate**를 끄세요. [What starts an investigation](/guide/incident/settings#what-starts-an-investigation)을 참고하세요.

## 조사가 시작되는 방식

| 인시던트 출처 | RCA 시작 시점 |
|---|---|
| [Signals](/ko/guide/pulse/overview)(알림 소스) | **AI auto-investigate**가 켜져 있고 웹훅 옵션이 허용할 때, triage가 인시던트를 열거나 다시 열면 자동으로. 전체 규칙은 [What starts an investigation](/guide/incident/settings#what-starts-an-investigation)에 있습니다. |
| [Log Incident](/ko/guide/incident/manual-logging)(사람) | **AI auto-investigate**가 꺼져 있어도 양식을 제출하는 즉시. |
| 아직 조사가 없는 인시던트. **Not started**에서 대기합니다. | **Investigate**를 클릭할 때. |
| 조사가 한 번도 없었는데 **Investigating**으로 설정된 인시던트(예: 누군가 상태 배지에서 **Investigating**을 선택한 경우). **Not started**에서 대기합니다. | **Investigate**를 클릭할 때. |

## 조사 실행

<Steps>
  <Step title="인시던트 열기">
    **Resolve → Issues**로 이동해 대기열에서 인시던트를 선택합니다.
  </Step>
  <Step title="시작되지 않았다면 RCA 시작">
    인시던트가 한 번도 조사되지 않았다면 인시던트 헤더에서 **Investigate**를 클릭합니다.

    **성공 상태:** 인시던트가 **AI is handling**으로 이동하고, 인시던트 페이지에 **Watch live** 버튼과 함께 **CloudThinker is investigating**이 표시됩니다.
  </Step>
  <Step title="따라가기 (선택 사항)">
    **Watch live**를 클릭하면 CloudThinker가 작업 중인 대화가 열립니다. 실행되는 각 검사를 실시간으로 볼 수 있습니다. 결과는 저장되는 대로 인시던트 페이지에도 나타납니다.
  </Step>
  <Step title="판정 읽기">
    분석이 끝나면 인시던트가 **Needs you**로 이동합니다. 상태가 **Identified**인 인시던트는 결과의 제목이 **Root cause**로 표시됩니다. [조사 결과](#조사-결과)에 모든 상태와 각 상태가 놓이는 위치가 나와 있습니다. [결과 읽기](#결과-읽기)에서 페이지의 각 섹션을 설명합니다.

    새 결과가 나타나지 않고 **Watch live**에 활동이 없다면 [Investigation stuck](/guide/incident/troubleshooting#investigation-stuck)을 참고하세요.
  </Step>
  <Step title="각 제안 정리">
    **Actions** 아래의 각 항목을 완료 또는 무시로 표시합니다. [각 개선 제안 정리](#각-개선-제안-정리)를 참고하세요.
  </Step>
  <Step title="인시던트 종료">
    인시던트 헤더의 상태 배지를 클릭하고 **Resolved** 또는 **False alarm**을 선택한 뒤 **Change Status**로 확인합니다. 워크스페이스 Admin만 상태를 변경할 수 있습니다. 다른 역할에는 메뉴 없이 배지만 보입니다.

    | 현재 상태 | 메뉴의 종료 옵션 |
    |---|---|
    | **Open**, **Acknowledged**, **Investigating**, **Identified** | **Resolved** 또는 **False alarm** |
    | **On hold** | **Resolved**만. **False alarm**으로 표시하려면 먼저 **Investigating**으로 옮기세요. |
    | **Not found** | 둘 다 없음. 메뉴에는 **Investigating**만 있습니다. 종료하려면 **Investigating**을 선택한 뒤, 배지를 다시 열고 **Resolved** 또는 **False alarm**을 선택하세요. |

    **성공 상태:** 인시던트가 **Resolved** 또는 **Dismissed** 그룹으로 이동합니다.
  </Step>
</Steps>

## 조사 대기열

**Resolve → Issues**는 사용자에게 필요한 것에 따라 인시던트를 그룹화합니다.

| 그룹 | 포함되는 것 |
|---|---|
| **AI is handling** | 조사가 실행 중 |
| **Needs you** | 판정이 준비되었거나, 조사가 입력을 기다리며 일시 중지되었거나, 검사 결과가 결론에 이르지 못함 |
| **Not started** | 아직 조사가 실행되지 않았거나 대기 중. **Investigate**를 클릭해 시작합니다. |
| **Resolved** | **Resolved** 또는 **Auto-resolved**로 종료됨 |
| **Dismissed** | **False alarm**으로 종료됨 |
| **Triaged** | triage가 알림을 확인했지만 대응이 시작되지 않음. 예: 알림에 조치가 필요 없다고 판단한 경우 |

## 결과 읽기

인시던트 페이지는 답을 먼저, 뒷받침 자료를 그 아래에 둡니다.

답의 제목은 조사가 어디까지 왔는지 나타냅니다: **Triage**, **Working theory**, **Root cause**, **On hold**, **No root cause found**, **False alarm**, **Resolution**. 그 옆에는 증거가 얼마나 강한지 나타내는 증거 라벨(아래 참고)이 있고, 세션이 실행 중이면 **Running**이 표시됩니다. 판정 아래에는 **Impact**, **Cause**, **Fix**, **Risk and undo**, **Confidence** 같은 짧은 행이 요약을 제공하며, 근본 원인을 찾는 데 걸린 시간도 표시됩니다.

답 아래의 각 섹션은 클릭하면 열립니다.

| 섹션 | 알려주는 것 |
|---|---|
| **How it happened** | 첫 장애부터 눈에 보이는 영향까지의 인과 그래프 |
| **Actions** | 각각 우선순위(**Critical**, **High**, **Medium**, **Low**)가 있는 제안된 수정. **Critical**부터 처리하세요. |
| **What happened** | 인시던트의 타임라인 |
| **Evidence** | 판정의 근거가 되는 결과 |
| **Full analysis** | 나열할 결과가 없을 때의 전체 서면 분석 |
| **Investigation trail** | 나열할 결과가 없을 때 CloudThinker가 거친 모든 단계 |
| **Affected services** | 관련된 서비스와 의존성 |
| **Duplicate webhooks** | 같은 알림이 반복 전달된 경우 그 내역. 중복이 많다면 재시도하는 소스를 의미합니다. 도구의 재시도 설정이나, Pulse가 중복을 찾는 데 사용하는 필드를 [Limits and responses](/ko/guide/incident/webhook-integrations/overview#제한과-응답)에서 확인하세요. |
| **Was Resolve's diagnosis right?** | 판정에 대한 좋아요 또는 싫어요. 이 응답은 **Accuracy and trust** 탭에 반영됩니다. [Mark a diagnosis right or wrong](/guide/incident/insights#mark-a-diagnosis-right-or-wrong)을 참고하세요. |

CloudThinker가 심각도가 잘못되었다고 판단하면, 인시던트의 **More actions** 메뉴에 제안 수준과 함께 **AI suggests**가 표시됩니다. 클릭하면 현재 수준과 제안 수준이 보이며, 제안 수준을 **Apply**하거나 현재 수준을 **Keep**할 수 있습니다.

짧은 결과는 다음과 같을 수 있습니다.

```text
Root cause                                     Strong evidence
checkout-api pods ran out of memory after payment-client v2.3 doubled
its connection pool. Restarts cleared it for minutes at a time.

Actions
High    Roll back payment-client to v2.2 on prod-eu
Medium  Set a pool size limit in the payment-client config
```

### 증거 라벨

제목 옆의 라벨은 CloudThinker가 자신의 증거를 얼마나 강하게 평가하는지 나타냅니다.

| 라벨 | 의미 | 다루는 방법 |
|---|---|---|
| **Strong evidence** | 시스템의 데이터로 확인되었으며 **Evidence** 아래에 표시됨 | 근거가 되는 결과를 검토한 뒤 조치하세요. 모든 변경은 여전히 runbook과 Approvals 설정을 거칩니다. |
| **Probable** | 증거로부터 추론했지만 직접 확인되지 않음 | 조치 전에 증거를 확인하세요 |
| **Possible** | 판정이 가정에 기반함 | 단서로 다루세요. 접근 권한이나 컨텍스트를 추가하고 [다시 조사](#재조사)하세요. |

**Possible**은 근거가 약한 판정입니다. **Not found**는 판정이 전혀 없다는 뜻의 상태입니다.

### 각 개선 제안 정리

**Actions**에서 제안 위로 마우스를 올리고 **More remediation actions** 메뉴를 열어 선택합니다.

| 작업 | 사용 시점 | 메모할 내용 |
|---|---|---|
| **Mark as Done** | 팀이 작업을 완료함 | 실제로 한 일 |
| **Dismiss** | 해당되지 않거나 할 가치가 없음 | 이유 |

메모는 선택 사항이며, 인시던트를 검토하는 사람을 위해 제안에 남습니다. 정리는 최종적입니다. 제안이 표시되면 메뉴가 사라지고 되돌릴 수 없습니다. 이후 조사 세션도 이를 덮어쓰지 않습니다.

## 조사 결과

각 상태는 대기열 그룹에 대응합니다.

| 상태 | 의미 | 대기열 그룹 |
|---|---|---|
| **Open**, **Acknowledged** | 아직 결과 없음. **Acknowledged**는 대응자가 맡았다는 뜻입니다. | 조사 전에는 **Not started**, 조사가 끝난 후에는 **Needs you** |
| **Identified** | 근본 원인을 찾음 | **Needs you** |
| **On hold** | 사람의 정보, 접근 권한, 결정을 기다리는 중 | **Needs you** |
| **Not found** | 사용 가능한 증거가 근본 원인을 뒷받침하지 못함 | 없음. 대기열에 표시되지 않습니다. |
| **False alarm** | 알림이 실제 문제가 아니었음 | **Dismissed** |
| **Resolved** | 사람이 관여해 수정하고 종료함 | **Resolved** |
| **Auto-resolved** | 아무도 관여하지 않고 에이전트가 수정하고 종료함 | **Resolved** |

인시던트는 다음 이유 중 하나로 **Needs you**에 있을 수도 있습니다.

| 보이는 것 | 의미 | 할 일 |
|---|---|---|
| 결과가 있지만 상태가 여전히 **Open**, **Acknowledged**, **Investigating** | 조사가 상태를 바꾸지 않고 끝남 | 결과를 읽은 뒤 직접 상태를 설정하세요 |
| 행에 **Failed**가 표시되고 인시던트 페이지에 조사가 멈췄다고 나옴 | 세션이 실패했거나 취소됨 | **Retry investigation**을 클릭하세요 |
| triage 메모는 있지만 판정이 없음 | triage가 알림에 조치가 필요한지 판단하지 못함 | **View origin**으로 소스 알림을 읽은 뒤 직접 상태를 설정하세요 |

<Warning>
알려진 제한 사항: **Not found** 인시던트는 대기열에서 빠집니다. 어떤 대기열 그룹이나 필터에도 표시되지 않습니다. 페이지를 떠나기 전에 다음 단계로 옮기거나 URL을 복사하세요.

- 계속 작업하려면 빠진 [연결](/ko/guide/connections/overview)을 추가하고 상태 배지를 클릭해 **Investigating**을 선택하세요. 이전에 조사된 인시던트는 **Not started**가 아니라 **Needs you**로 돌아가며, 그곳에서 [다시 조사](#재조사)할 수 있습니다.
- 버리려면 **Investigating**을 선택한 뒤, 배지를 다시 열고 **Resolved** 또는 **False alarm**을 선택하세요.
- 나중에 돌아오려면 인시던트 URL을 북마크하세요. 그것이 돌아오는 유일한 방법입니다.
</Warning>

## 재조사

인시던트에는 조사 기록이 하나 있습니다. 세션은 하나의 조사 대화입니다. 그 대화에서 다시 질문하면 같은 세션에 머뭅니다. triage가 새 알림을 인시던트에 매칭하면 이후 세션이 시작될 수 있습니다.

**Investigate** 버튼은 첫 조사 전에만 나타납니다. 새 접근 권한이나 컨텍스트로 다시 조사하려면:

<Steps>
  <Step title="빠진 것 추가">
    빠진 [연결](/ko/guide/connections/overview)을 추가하거나, CloudThinker가 사용할 컨텍스트를 메모합니다.
  </Step>
  <Step title="대화 열기">
    인시던트 헤더에서 **More actions → Open AI Conversation**을 엽니다.
  </Step>
  <Step title="다시 살펴보도록 요청">
    무엇이 바뀌었는지 말합니다. 예: `I've connected the prod-eu Datadog account. Re-check the root cause.`

    **성공 상태:** 기록한 결과가 인시던트 페이지에 나타나고, 근본 원인이 바뀌면 상단의 답이 업데이트됩니다. 아무것도 바뀌지 않으면 답변이 인시던트를 바꾸지 않은 것입니다.
  </Step>
</Steps>

세션이 실패했다면(대기열 행에 **Failed** 표시) 인시던트 페이지에 조사가 멈췄다고 나옵니다. 그곳에서 **Retry investigation**을 클릭하세요. Admin 전용입니다.

## 연관 인시던트

여러 알림이 같은 원인을 공유할 가능성이 있으면, Resolve는 이를 하나의 상위 인시던트 아래로 묶고 그곳에서 RCA를 한 번 실행합니다. 묶인 알림을 열면 **Part of a Correlated Group** 카드가 표시됩니다.

| 옵션 | 동작 |
|---|---|
| **View Parent Analysis** | 조사를 소유한 상위 인시던트를 엽니다 |
| **Promote to Standalone** | 알림을 독립된 인시던트로 분리합니다. 확인 후 지금 RCA를 시작할지 나중으로 미룰지 선택합니다. Admin 전용입니다. |

그룹화는 Pulse에서 시작됩니다. 관련 알림이 올바르게 묶이도록 각 웹훅에서 **Resource ID Path**를 매핑해 한 장애의 반복이 묶이게 하고, **Service Path**를 단일 서비스 이름에 매핑해 한 서비스에 대한 서로 다른 알림이 합쳐지게 하세요. [How signals join a cluster](/ko/guide/pulse/clusters#신호가-클러스터에-합류하는-방식)를 참고하세요.

## 결과 공유 또는 내보내기

인시던트의 **More actions** 메뉴에서:

- **Download analysis PDF**는 분석을 PDF로 저장합니다.
- **Open AI Conversation**은 후속 질문을 할 수 있는 전체 조사 대화를 엽니다.
- **View origin**은 인시던트의 출처가 된 알림과 Pulse 데이터를 보여줍니다.

## 문제 해결

| 문제 | 해결 |
|---|---|
| **Investigate** 버튼이 없음 | 인시던트에 이미 조사가 있거나([재조사](#재조사) 참고), 세션이 실행 중이거나, 연관 그룹의 일부입니다(**View Parent Analysis** 사용). Admin 역할도 필요합니다. |
| 알림이 조사된 인시던트가 되지 않음 | **AI auto-investigate**, 웹훅의 **Auto-investigate**와 최소 심각도를 [What starts an investigation](/guide/incident/settings#what-starts-an-investigation)과 대조해 확인하세요. 지금 시작하려면 **Resolve → Signals**에서 해당 클러스터의 **Open incident**와 **Send to triage**를 클릭하세요. |
| 인시던트가 **Not started**에 머무름 | **Investigate**를 클릭하세요. |
| 판정이 **Possible**이거나 상태가 **Not found** | RCA가 충분히 읽지 못했습니다. 빠진 [연결](/ko/guide/connections/overview)을 추가한 뒤 대화에서 다시 요청하세요. **Not found** 인시던트는 먼저 **Investigating**으로 되돌려야 합니다. [Not found 경고](#조사-결과)와 [재조사](#재조사)를 참고하세요. |
| **On hold**에 머무름 | **Open AI Conversation**으로 대화를 열고 CloudThinker가 요청한 것에 답하세요. |

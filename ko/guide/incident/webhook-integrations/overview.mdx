CloudThinker는 PagerDuty, Datadog, Grafana 등 알림 및 모니터링 플랫폼과 통합됩니다. 각 통합에는 플랫폼별 필드 매핑, 유연한 인증, 자동 AI 조사 트리거가 포함됩니다.

---

### 커스텀 통합

| 플랫폼 | 비고 |
|---|---|
| **Generic Webhook** | 인증: Bearer Token (구성 가능). 모든 플랫폼을 위한 완전히 커스터마이징 가능한 웹훅. JSONPath 표현식을 사용하여 자체 필드 매핑을 정의합니다. |

## 웹훅 통합 설정

설정 마법사가 플랫폼 선택, 웹훅 구성, 자동 근본 원인 분석 설정을 안내합니다.

<Frame>
  <img src="/images/incidents/setup/01-setup-wizard-home.jpg" alt="AI 기반 근본 원인 분석 개요가 있는 Deep Response Engine 설정 마법사 홈 페이지" />
</Frame>
<p style={{textAlign: 'center', fontSize: '0.9em', color: '#666', marginTop: '8px'}}>설정 마법사 진입점이 있는 Deep Response Engine 대시보드</p>

<Steps>
  <Step title="통합으로 이동">
    **Deep Response Engine** → **Settings** → **Integrations** 탭으로 이동하여 웹훅 관리에 접근합니다.
  </Step>
  <Step title="웹훅 생성">
    플랫폼 카드에서 **Connect**를 클릭합니다. 생성 마법사가 플랫폼별 기본값이 미리 구성된 상태로 열립니다.

    <Frame>
      <img src="/images/incidents/setup/02-select-platform-modal.jpg" alt="PagerDuty, Datadog, Grafana, AWS CloudWatch를 포함한 모니터링 및 알림 플랫폼 옵션을 보여주는 플랫폼 선택 모달" />
    </Frame>
    <p style={{textAlign: 'center', fontSize: '0.9em', color: '#666', marginTop: '8px'}}>사용 가능한 옵션에서 모니터링 플랫폼 선택</p>
  </Step>
  <Step title="기본 정보 구성">
    웹훅의 이름과 선택적 설명을 입력합니다. 필요한 경우 전송률 제한을 설정합니다(기본값: 시간당 100 요청).
  </Step>
  <Step title="필드 매핑 검토">
    각 플랫폼에는 웹훅 페이로드에서 인시던트 필드를 추출하는 미리 구성된 JSONPath 매핑이 있습니다. 필요한 경우 커스터마이징하세요:

    | 인시던트 필드 | JSONPath 예시 | 설명 |
    |----------------|------------------|-------------|
    | Title | `event.data.title` | 인시던트 헤드라인 |
    | Description | `event.data.description` | 상세 정보 |
    | Severity | `event.data.priority` | Critical, High, Medium, Low, Info |
    | Service | `event.data.service.name` | 영향받은 서비스 이름 |

    플랫폼의 심각도 값(예: `warning` → `medium`, `P1` → `critical`)을 CloudThinker의 심각도 수준으로 변환하는 **심각도 매핑**도 구성할 수 있습니다.

    <Frame>
      <img src="/images/incidents/setup/03-configure-webhook-fields.jpg" alt="Title Path, Severity Path, Description Path, Services Path JSONPath 표현식이 있는 필드 매핑 웹훅 구성 폼" />
    </Frame>
    <p style={{textAlign: 'center', fontSize: '0.9em', color: '#666', marginTop: '8px'}}>웹훅 페이로드를 위한 JSONPath 필드 매핑 구성</p>
  </Step>
  <Step title="자동 트리거 설정 구성">
    인시던트가 [근본 원인 분석](/ko/guide/incident/root-cause-analysis)을 트리거하는 방식을 제어합니다:

    - **Auto-trigger RCA:** 인시던트가 생성될 때 자동으로 AI 조사 시작
    - **Minimum severity:** 이 심각도 수준 이상의 인시던트에만 RCA 트리거 (기본값: Medium)
    - **Send all fields to agent:** RCA 에이전트에 완전한 웹훅 페이로드를 전달하여 더 풍부한 분석 가능

    <Frame>
      <img src="/images/incidents/setup/05-configure-rca-settings.jpg" alt="Auto-trigger RCA 토글 및 Minimum Severity 드롭다운이 Medium으로 설정된 근본 원인 분석 구성 패널" />
    </Frame>
    <p style={{textAlign: 'center', fontSize: '0.9em', color: '#666', marginTop: '8px'}}>자동 RCA 트리거 및 심각도 임계값 구성</p>
  </Step>
  <Step title="웹훅 URL 및 인증 정보 복사">
    **Setup** 탭에 웹훅 URL과 인증 세부 정보가 표시됩니다. 이 자격 증명을 복사하여 알림 플랫폼에 구성합니다.

    <Frame>
      <img src="/images/incidents/setup/04-webhook-url-code-examples.jpg" alt="웹훅 URL, 요청 형식, HTTP 헤더, 웹훅 통합을 위한 코드 예시가 있는 Setup 탭" />
    </Frame>
    <p style={{textAlign: 'center', fontSize: '0.9em', color: '#666', marginTop: '8px'}}>알림 플랫폼에 구성하기 위한 웹훅 URL 및 인증 헤더 복사</p>
  </Step>
</Steps>

## 인증 방법

CloudThinker는 플랫폼 요구 사항에 맞는 네 가지 인증 방법을 지원합니다. 올바른 방법은 플랫폼 선택 시 미리 선택되지만, 커스텀 통합을 위해 변경할 수 있습니다.

| 방법 | 작동 방식 | 사용 플랫폼 |
|--------|-------------|---------|
| **Bearer Token** | `Authorization` 헤더를 통한 표준 토큰 기반 인증 | Datadog, Grafana, Prometheus, Splunk, GCP Monitoring, BigPanda |
| **HMAC-SHA256** | 암호화 서명 검증 — CloudThinker가 공유 비밀을 사용하여 요청 본문 서명을 검증 | PagerDuty, Sentry |
| **API Key** | 선택적 접두사가 있는 커스텀 헤더 (예: `GenieKey`, `Api-Token`) | Opsgenie, New Relic, Dynatrace, ServiceNow, AWS CloudWatch |
| **No Authentication** | 다른 메커니즘으로 신원을 확인하는 플랫폼용 | Azure Monitor |

<Note>
  기존 웹훅에서 인증 방법을 변경하면, 이전 방법을 사용하는 기존 통합이 즉시 작동을 중지합니다. 인증 방법 변경 후 자격 증명을 재생성하세요.
</Note>

## 알림 상관

짧은 시간 내에 여러 알림이 도착하면, CloudThinker는 자동으로 이를 중복을 생성하는 대신 단일 인시던트로 상관합니다. 이는 연쇄 실패로 인한 알림 피로를 줄입니다.

### 시간 창 상관

구성 가능한 창(기본값: 5분) 내에 수신된 알림을 그룹화합니다. 새 알림이 기존 열린 인시던트와 일치하면, 새 인시던트를 생성하는 대신 상관된 알림으로 첨부됩니다.

### 규칙 기반 상관

공유 속성을 기반으로 기존 인시던트에 들어오는 알림을 매핑하는 커스텀 규칙을 정의합니다. 규칙은 웹훅 카드 메뉴의 **Correlation Rules** 아래에서 구성합니다.

각 규칙은 다음을 지정합니다:
- AND/OR 로직을 사용한 매핑을 위한 **조건**
- 평가 순서를 제어하는 **우선순위** (0-1000)
- 매칭 신뢰도를 나타내는 **가중치** (0.0-1.0)
- 상관 허용을 위한 **최소 매칭 가중치** 임계값

**사용 가능한 연산자:**

| 연산자 | 설명 |
|----------|-------------|
| `equals` / `not_equals` | 정확한 일치 또는 불일치 |
| `contains` / `not_contains` | 부분 문자열 일치 |
| `starts_with` / `ends_with` | 접두사 또는 접미사 일치 |
| `regex` | 정규 표현식 일치 |
| `in` / `not_in` | 목록에 있거나 없는 값 |
| `intersects` | 배열 겹침 (예: 공유 태그) |
| `exists` | 필드가 존재함 |

## 보안 & 제한

### 페이로드 제한

| 제한 | 값 |
|-------|-------|
| 최대 HTTP 본문 크기 | 1 MB |
| 최대 저장 페이로드 크기 | 100 KB |
| 최대 필드 길이 | 10,000자 |
| 최대 배열 항목 수 | 100개 |
| 최대 중첩 깊이 | 10단계 |

### 전송률 제한

| 제한 | 값 |
|-------|-------|
| 기본 전송률 제한 | 웹훅당 시간당 100 요청 |
| 인증 실패 제한 | 15분 창당 10회 실패 |
| 초과 시 응답 | HTTP 429 |

전송률 제한은 웹훅별로 구성 가능합니다. 무제한은 0으로 설정합니다.

### 보안 기능

- **타이밍 공격 방지 서명 검증** — HMAC 검증의 타이밍 공격 방지
- **암호화된 비밀 저장** — 웹훅 비밀은 저장 시 암호화
- **자격 증명 교체** — 웹훅을 재생성하지 않고 웹훅 토큰 및 비밀 재생성
- **페이로드 정화** — 크기 초과 필드는 자동으로 잘림
- **민감한 헤더 필터링** — 인증 헤더는 감사 로그에서 제외

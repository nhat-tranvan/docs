알림보다 문제가 먼저 전달될 때 인시던트를 기록하세요. 고객 이메일, 채팅으로 알려온 동료, 이상해 보이는 대시보드 같은 경우입니다. 무슨 일이 일어나고 있는지 설명하고 가진 자료를 첨부하면, 제출하는 즉시 CloudThinker가 근본 원인 조사를 시작합니다. 조사를 시작하지 않고 인시던트를 기록하는 방법은 없으므로, 이미 해결된 일을 기록하는 용도가 아닙니다. 알림 소스를 연결할 필요는 없습니다.

## 시작하기 전에

- 워크스페이스 **Admin** 역할. Developer와 Viewer는 인시던트를 읽을 수 있지만 기록할 수는 없습니다. 역할은 고정되어 있으므로 이 권한만 따로 부여할 수는 없습니다. [Roles](/guide/security/roles)를 참고하세요.
- 조사가 실제 데이터를 확인할 수 있도록 관련 시스템에 대한 [연결](/ko/guide/connections/overview).
- 선택 사항: 첨부할 스크린샷, 로그 내보내기, 오류 출력. `.log` 파일은 허용되지 않으므로 로그는 `.txt`로 저장하세요.
- 크레딧. 기록된 각 인시던트는 **AI auto-investigate**가 꺼져 있어도 제출하는 순간 조사를 시작하며, 다른 실행과 마찬가지로 크레딧이 청구됩니다. [Usage](/ko/guide/billing/usage)와 [What starts an investigation](/guide/incident/settings#what-starts-an-investigation)을 참고하세요.

<Warning>
기록된 인시던트는 실제 인시던트입니다. 테스트라면 먼저 [안전하게 테스트하기](#안전하게-테스트하기)를 읽으세요.
</Warning>

## 인시던트 기록하기

<Steps>
  <Step title="양식 열기">
    **Resolve → Issues**로 이동해 **Log Incident**를 클릭합니다.
  </Step>
  <Step title="템플릿 선택 (선택 사항)">
    **Quick Start Template**은 제목 접두사, 설명 개요, 심각도를 채워 줍니다. 채워진 내용은 무엇이든 편집할 수 있습니다. 다섯 가지 템플릿은 고정되어 있어 직접 추가할 수 없습니다. 예를 들어 **API Outage**는 제목을 `[API Outage] `로, 컨텍스트를 다음과 같이 설정합니다.

    ```text
    Affected API:
    Error Type: (5xx, timeout, connection refused)
    First Detected:
    Impact: (users affected, dependent services)
    Error Rate:
    ```

    | 템플릿 | 제목 접두사 | 개요 항목 | 미리 채워지는 심각도 |
    |---|---|---|---|
    | API Outage | `[API Outage]` | 영향받는 API, 오류 유형, 최초 감지, 영향, 오류율 | High |
    | Database Issue | `[Database]` | 데이터베이스, 문제 유형, 최초 감지, 영향, 현재 지표 | High |
    | Deployment Failure | `[Deployment]` | 서비스, 환경, 배포 ID 또는 버전, 실패 원인, 롤백 상태 | Medium |
    | Service Degradation | `[Degradation]` | 서비스, 저하 유형, 최초 감지, 현재 및 기대 성능 | Medium |
    | Infrastructure Alert | `[Infrastructure]` | 리소스, 알림 유형, 인스턴스 또는 노드, 현재 값, 임계값 | Medium |
  </Step>
  <Step title="문제 설명">
    | 필드 | 필수 | 입력할 내용 |
    |---|---|---|
    | **What's happening?** | 예 | 한 줄 요약. 인시던트 제목이 됩니다. |
    | **Context** | 아니요 | 증상, 영향, 시점, 이미 시도한 것 |
    | **Attach** | 아니요 | **Attach**를 클릭하거나, 끌어다 놓거나, 붙여넣습니다. 최대 5개 파일, 각 25 MB이며 `.csv`, `.tsv`, `.xlsx`는 최대 100 MB입니다. 파일 선택기는 이미지(PNG, JPG, GIF, WebP), `.pdf`, `.txt`, `.md`, `.json`, `.yaml`, `.yml`, `.xml`, `.csv`, `.tsv`, `.docx`, `.xlsx`, `.pptx`, `.zip`, `.tar`, `.gz`를 받습니다. 압축 파일은 바로 읽히지 않고 조사 과정에서 먼저 풀어야 하므로, 가능하면 로그 파일 자체를 첨부하세요. |
    | **Severity** | 예 | **Critical**, **High**, **Medium**, **Low**, **Info**. 기본값은 **Medium**입니다. |
    | **Occurred At** | 아니요 | 시작된 시점(브라우저 로컬 시간). 기본값은 현재입니다. 최대 30일 전까지 지정할 수 있으며 미래는 지정할 수 없습니다. |

    <Note>
    심각도는 Slack war room을 열지 여부를 결정합니다. [Resolve Triggers & Outcomes](/guide/incident/triggers-and-outcomes#outcomes)에서 설정한 하한(기본값 **High & critical**)을 넘을 때만 열립니다. 사람을 호출할지는 심각도가 아니라 triage(인시던트에 지금 대응자가 필요한지 CloudThinker가 확인하는 과정)가 결정합니다. [How Resolve decides an incident needs people](/guide/incident/oncall#how-resolve-decides-an-incident-needs-people)을 참고하세요.
    </Note>

    구체적인 컨텍스트는 조사에 더 나은 출발점을 줍니다. 예:

    ```text
    What's happening?
    Checkout API returning 502s for EU customers

    Context
    Service: checkout-api (EKS cluster prod-eu)
    First reported: 14:05 UTC by support, three customer tickets
    Impact: roughly 1 in 5 checkout requests fail, EU only
    Recent change: payment-client v2.3 deployed at 13:50 UTC
    Already tried: restarted two pods, no change
    ```
  </Step>
  <Step title="제출">
    **Log Incident**를 클릭합니다.

    **성공 상태:** 새 인시던트가 **Resolve → Issues**에서 선택된 상태로 열리고, **AI auto-investigate**가 꺼져 있어도 RCA가 이미 시작되어 있습니다. 상태는 **AI is handling**이며, 인시던트 페이지에 **Watch live** 버튼이 표시됩니다.
  </Step>
</Steps>

## 다음에 일어나는 일

1. CloudThinker가 설명과 첨부 파일을 읽은 뒤, 연결된 시스템을 확인해 가능한 설명을 검증합니다.
2. 결과가 저장되는 대로 인시던트 페이지에 나타납니다. 대화를 따라가려면 **Watch live**를 클릭하세요.
3. 완료되면 인시던트가 서면 판정, 인과 그래프, 개선 제안과 함께 **Needs you**로 이동합니다.

결과를 읽고 각 제안을 정리하는 방법은 [Investigation and RCA](/ko/guide/incident/root-cause-analysis)에서 설명합니다.

## 안전하게 테스트하기

기록된 인시던트는 실제 인시던트이며 크레딧을 사용합니다. 테스트를 기록하기 전에:

- [Resolve Triggers & Outcomes](/guide/incident/triggers-and-outcomes#outcomes)에서 **Post incident updates**를 끄거나 테스트 채널로 지정하세요. 그렇지 않으면 인시던트가 열리고, 상태가 바뀌고, 해결될 때 해당 채널에 메시지가 갑니다.
- **Info** 심각도를 선택하세요. 하한이 **All severities**로 설정되지 않는 한 Slack war room이 열리지 않습니다.
- 누군가 호출되는지는 심각도가 아니라 [On-call](/guide/incident/oncall) 설정과 triage의 판단에 따라 결정됩니다.
- 테스트도 [Resolve insights](/guide/incident/insights)에 집계됩니다. 예를 들어 **Event → incident reduction**의 인시던트 총계에 포함됩니다. **False alarm**으로 종료해도 제거되지 않습니다.
- 테스트 인시던트를 종료하려면 인시던트 헤더의 상태 배지를 클릭하고 **False alarm**을 선택한 뒤 **Change Status**로 확인하세요.

## 직접 기록할까, Pulse가 잡게 할까?

| 상황 | 할 일 |
|---|---|
| 고객이나 동료가 문제를 보고함 | 인시던트 기록 |
| 모니터가 울리기 전에 조사하고 싶음 | 인시던트 기록 |
| 알림 도구가 웹훅을 보낼 수 있음 | [Pulse source](/ko/guide/pulse/setup)로 연결해 이후 알림이 자동으로 인시던트가 되게 함 |
| Signals가 이미 알림을 묶음 | 중복을 기록하지 말고 기존 인시던트에서 작업. 먼저 확인하세요: **Resolve → Issues**의 **Search issues**에서, 또는 **Resolve → Signals**의 **History** 레인에 있는 **Search signals...**에서 알림 제목의 단어를 검색합니다. [Clusters](/ko/guide/pulse/clusters)를 참고하세요. |

## 문제 해결

| 문제 | 해결 |
|---|---|
| **Log Incident** 버튼이 없음 | 워크스페이스 Admin만 인시던트를 기록할 수 있습니다. 워크스페이스 Admin에게 요청하세요. |
| **Log Incident**가 회색으로 비활성화됨 | 파일이 아직 업로드 중이거나 검증에 실패했습니다(잘못된 유형 또는 너무 큰 파일). 파일을 제거하거나 업로드가 끝날 때까지 기다리세요. |
| 날짜를 선택할 수 없음 | **Occurred At**은 최근 30일만 받으며 미래는 받지 않습니다. |
| 판정이 **Possible**이거나 상태가 **Not found** | 조사가 올바른 시스템을 읽지 못했습니다. 빠진 [연결](/ko/guide/connections/overview)을 추가하세요. **Not found**라면 먼저 상태 배지를 클릭하고 **Investigating**을 선택하세요([Not found 경고](/ko/guide/incident/root-cause-analysis#조사-결과) 참고). 그런 다음 **More actions → Open AI Conversation**을 열고 더 자세히 다시 요청하세요. [재조사](/ko/guide/incident/root-cause-analysis#재조사)를 참고하세요. |

워크스페이스는 [조직](/ko/guide/organization) 안의 별도 영역으로, 자체 연결, 에이전트, 메모리, 대화, 설정을 가집니다. 한 워크스페이스의 에이전트와 멤버는 다른 워크스페이스의 연결, 데이터, 대화를 사용할 수 없으므로, 워크스페이스는 프로덕션과 스테이징을 분리하는 방법입니다. 조직 Owner와 Admin은 모든 워크스페이스를 열 수 있으며, 사용량과 감사 로그는 모든 워크스페이스를 다룹니다.

## 워크스페이스에 담기는 것

작업하면서 설정하는 모든 것은 현재 워크스페이스에 저장됩니다.

| 영역 | 예시 |
|---|---|
| 시스템 접근 | [연결](/ko/guide/connections/overview) 및 [자격 증명](/guide/credentials) |
| 에이전트 동작 방식 | [커스텀 에이전트](/ko/guide/agents/customize), [스킬](/ko/guide/skills/overview), [메모리](/guide/memory) |
| 안전 제어 | [Approvals](/guide/approvals/overview) 모드와 규칙 |
| 작업과 결과 | 대화, [아티팩트](/ko/guide/artifacts/overview), [자동화](/guide/automation/automations), 그리고 Optimize, Review, Cyber, Resolve 데이터 |
| 사람 | [워크스페이스 멤버](/ko/guide/workspace-users)와 워크스페이스 역할 |

청구, 멤버십, SSO, 감사 로그는 워크스페이스가 아니라 조직에 속합니다.

## 구성 방식 선택

대부분의 팀은 하나의 워크스페이스로 시작하고, 접근이나 노이즈가 문제가 될 때 나눕니다.

| 패턴 | 나누는 기준 | 선택하는 경우 |
|---|---|---|
| 환경 | Production, Staging, Dev | 프로덕션에 더 엄격한 승인과 쓰기 권한을 가진 사람이 더 적어야 하는 경우 |
| 팀 | Platform, Security, App team | 각 팀이 다른 연결, 스킬, 메모리를 사용하는 경우 |
| 고객 또는 사업부 | 고객당 워크스페이스 하나 | 여러 고객의 운영을 맡고 있으며 데이터를 분리해야 하는 경우 |

예시: AWS 계정이 12개인 플랫폼 팀은 하나의 워크스페이스를 사용하고, 계정마다 연결을 하나씩 추가하고, 각 연결에 **Environment**(Production, Staging 또는 Development)를 설정하여 [승인 규칙](/guide/approvals/rules)이 프로덕션 변경을 더 엄격하게 다루도록 합니다. [환경 설정](/ko/guide/connections/overview#environment-설정)을 참조하세요. 프로덕션에 더 엄격한 Approvals나 별도의 크레딧 한도가 필요할 때만 프로덕션을 자체 워크스페이스로 분리합니다.

만들 수 있는 워크스페이스 수는 플랜이 정합니다. [플랜 및 요금](/ko/guide/billing/pricing)을 참조하세요.

## 사전 요구사항

- 워크스페이스를 만들거나 삭제하려면 조직 **Owner** 또는 **Admin**이어야 합니다.
- 워크스페이스 이름을 바꾸거나 설정을 변경하려면 워크스페이스 **Admin**이어야 합니다. 조직 Owner와 Admin은 항상 그렇습니다. 워크스페이스 Admin은 워크스페이스 설정에서 워크스페이스를 삭제할 수 없습니다.
- Developer와 Viewer는 할당된 워크스페이스에서만 작업할 수 있습니다.

## 워크스페이스 만들기

가입하면 첫 번째 워크스페이스가 이미 만들어집니다. [구성 방식 선택](#구성-방식-선택)처럼 별도의 접근, Approvals, 데이터가 필요할 때만 다른 워크스페이스를 만드세요.

<Tip>
이미 실제 작업이 있는 조직에서 CloudThinker를 시험해 보나요? 평가용으로 `Eval` 워크스페이스를 만드세요. 끝나면 삭제 한 번으로 평가의 연결과 대화가 모두 제거됩니다.
</Tip>

<Steps>
  <Step title="새 워크스페이스 시작">
    사이드바 상단의 워크스페이스 메뉴를 클릭한 다음, 조직의 워크스페이스 아래에서 **New workspace**를 클릭합니다. **Settings → Organization → Workspaces**로 이동하여 **New workspace**를 클릭할 수도 있습니다.
  </Step>
  <Step title="이름 지정">
    **Create workspace in &lt;organization&gt;** 대화상자에서 **Name**(필수)과 선택적 **Description**을 입력합니다. `Production`이나 `Platform team`처럼 전환기에서 사람들이 알아볼 수 있는 이름을 사용하세요.
  </Step>
  <Step title="만들기">
    **Create**를 클릭합니다.

    **성공 상태:** 워크스페이스가 **Settings → Organization → Workspaces** 목록과 워크스페이스 메뉴에 나타납니다.
  </Step>
  <Step title="시스템 연결">
    새 워크스페이스는 비어 있는 상태로 시작합니다. 워크스페이스로 전환하고 [연결](/ko/guide/connections/overview)을 추가하여 에이전트가 작업할 대상을 주세요. **No cloud connected**가 표시된 워크스페이스 행에는 아직 연결이 필요합니다.
  </Step>
  <Step title="팀 추가">
    처음에는 조직 Owner와 Admin만 새 워크스페이스를 볼 수 있습니다. 워크스페이스의 **Members** 페이지에서 Developer와 Viewer를 추가하세요. [워크스페이스 멤버](/ko/guide/workspace-users)를 참조하세요.
  </Step>
</Steps>

## 워크스페이스 전환

사이드바 상단의 워크스페이스 메뉴를 클릭하고 목록에서 워크스페이스를 고릅니다. 다른 조직의 워크스페이스는 **Other organizations** 아래에 있습니다. **Settings → Organization → Workspaces**에서 행의 **Go to workspace**를 클릭하고 **Switch workspace**를 확인할 수도 있습니다.

**성공 상태:** 페이지가 새로고침되고 사이드바에 새 워크스페이스 이름이 표시됩니다.

## 워크스페이스 설정 열기

사이드바 상단의 워크스페이스 메뉴를 클릭한 다음 **Settings**를 클릭합니다. Settings는 **Workspace** 탭에서 열립니다. ⌘,(Windows와 Linux에서는 Ctrl+,)를 누르거나, **Settings → Organization → Workspaces**에서 현재 워크스페이스 행의 **Settings**를 클릭할 수도 있습니다.

[워크스페이스 설정](/guide/workspace-settings)에는 모든 페이지, 그곳에서 설정하는 것, 볼 수 있는 사람이 나열되어 있습니다. 각 역할이 바꿀 수 있는 것은 [워크스페이스 역할](/ko/guide/workspace-users#워크스페이스-역할)을 참조하세요.

**BYOK** 페이지는 이 워크스페이스가 사용할 LLM 키를 고릅니다. 조직 키, 워크스페이스 키, 또는 없음입니다. 워크스페이스 키는 이 페이지에서 설정합니다. 조직 키 자체는 Owner가 **Settings → Organization → BYOK**에서 설정하며, Owner는 모든 곳에서 조직 키를 필수로 할 수 있습니다. [조직 및 워크스페이스 키](/ko/guide/byok#조직-키와-워크스페이스-키)를 참조하세요.

## 워크스페이스 이름 바꾸기

<Steps>
  <Step title="General 열기">
    **Settings → Workspace → General**로 이동합니다.
  </Step>
  <Step title="편집 및 저장">
    워크스페이스 이름 옆의 **Edit**를 클릭합니다. **Edit workspace** 대화상자에서 **Name** 또는 **Description**을 바꾼 다음 **Save**를 클릭합니다.

    **성공 상태:** 사이드바와 워크스페이스 메뉴에 새 이름이 표시됩니다.
  </Step>
</Steps>

보고서에 사용되는 로고와 색상을 바꾸려면 [워크스페이스 브랜딩](/ko/guide/workspace-branding)을 참조하세요.

## 기능 켜기 또는 끄기

**Settings → Workspace → Capabilities**에는 Advisor와 Blind Spot이 나열됩니다. 조직에서 사용할 수 있으면 둘 다 모든 워크스페이스에서 켜진 상태로 시작하며 워크스페이스의 크레딧을 사용합니다. 조직 Owner가 모든 워크스페이스에 대해 설정하지 않았다면, 워크스페이스 Admin이 스위치로 각각 끄거나 다시 켭니다. [Capabilities](/guide/capabilities)를 참조하세요.

## 워크스페이스 삭제

<Warning>
워크스페이스를 삭제하면 연결, 대화, 설정을 포함해 모든 멤버에게서 제거됩니다. 앱에는 복원 버튼이 없습니다. 삭제하기 전에 워크스페이스 멤버와 확인하세요.
</Warning>

<Steps>
  <Step title="다른 워크스페이스로 전환">
    현재 있는 워크스페이스는 삭제할 수 없습니다. 먼저 다른 워크스페이스로 전환하세요.
  </Step>
  <Step title="삭제">
    **Settings → Organization → Workspaces**로 이동하여 워크스페이스 행의 **Delete**(휴지통 아이콘)를 클릭하고 **Delete Workspace** 대화상자에서 확인합니다. 이름을 입력하지 않으므로 먼저 행을 확인하세요.

    **성공 상태:** 행이 목록에서 사라집니다.
  </Step>
</Steps>

그 밖에 일어나는 일:

| 항목 | 일어나는 일 |
|---|---|
| 예약된 리소스 탐색 | 꺼집니다. 워크스페이스를 만든 사람이 알림을 받습니다 |
| 워크스페이스 수 | 하나 줄어들어 플랜 한도 안에 여유가 생깁니다 |
| 감사 로그 | 삭제가 워크스페이스 이름과 함께 [감사 로그](/guide/security/audit-logs)에 기록됩니다 |

## 문제 해결

<AccordionGroup>
  <Accordion title="New workspace가 회색으로 비활성화됨">
    **원인:** Developer 또는 Viewer이거나, 조직이 플랜의 워크스페이스 한도에 도달했습니다. 한도에 도달하면 **Settings → Organization → Workspaces**에 **Workspace limit reached**가 표시됩니다.

    **해결:** Owner나 Admin에게 생성을 요청하거나, 더 이상 사용하지 않는 워크스페이스를 삭제하거나, [플랜을 업그레이드](/ko/guide/billing/subscription)하세요. 기존 워크스페이스는 한도에 도달해도 계속 동작합니다.
  </Accordion>
  <Accordion title="삭제 아이콘이 없음">
    워크스페이스를 삭제할 수 없으면 행에 휴지통 아이콘이 숨겨집니다.

    - 현재 있는 워크스페이스입니다. 먼저 다른 워크스페이스로 전환하세요.
    - 조직의 마지막 워크스페이스입니다. 이 워크스페이스를 삭제하기 전에 다른 워크스페이스를 만드세요.
  </Accordion>
  <Accordion title="팀원이 워크스페이스를 볼 수 없음">
    **원인:** Developer 또는 Viewer이며 워크스페이스에 추가되지 않았습니다.

    **해결:** 워크스페이스의 **Members** 페이지에서 추가하세요. [워크스페이스 멤버](/ko/guide/workspace-users)를 참조하세요.
  </Accordion>
  <Accordion title="에이전트가 추가한 연결을 찾지 못함">
    **원인:** 연결은 하나의 워크스페이스에 속합니다. 연결이 다른 워크스페이스에 추가되었을 가능성이 높습니다.

    **해결:** 사이드바에서 워크스페이스 이름을 확인한 다음, 채팅 중인 워크스페이스에 연결을 추가하세요.
  </Accordion>
</AccordionGroup>

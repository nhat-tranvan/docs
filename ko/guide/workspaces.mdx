워크스페이스는 [조직](/ko/guide/organization) 내의 격리된 환경으로, 자체 에이전트, [연결](/ko/guide/connections/overview), [지식 베이스](/ko/guide/knowledge)를 보유합니다. 모든 계정은 가입 시 기본 조직과 워크스페이스를 받으며, 청구 및 멤버 관리는 조직 수준에서 이루어집니다.

## 왜 워크스페이스인가

- **격리** — 별도의 환경 (dev, staging, production), 팀, 프로젝트가 각자의 에이전트, 자격 증명, 설정을 갖습니다.
- **멀티 클라우드 구조** — 각 워크스페이스는 하나의 기본 클라우드 공급자를 대상으로 하므로, 별도의 워크스페이스에서 AWS, GCP, Azure 운영을 나란히 실행할 수 있습니다.
- **접근 제어** — 세밀한 권한을 위한 선택적 역할 재정의와 함께 워크스페이스별로 멤버 접근을 부여합니다.
- **체계화된 리소스** — 에이전트, 연결, 지식 베이스, 운영 내역이 해당 워크스페이스에 범위 지정되어 유지됩니다.

## 워크스페이스 생성

조직 Owner와 Admin만 워크스페이스를 생성할 수 있습니다.

<Steps>
  <Step title="조직 열기">
    Organizations 페이지로 이동하여 조직을 찾습니다.
  </Step>
  <Step title="New workspace 클릭">
    조직 카드에서 **New workspace**를 클릭합니다.
  </Step>
  <Step title="클라우드 공급자 선택">
    이 워크스페이스의 기본 클라우드 인프라 공급자를 선택합니다.
  </Step>
  <Step title="워크스페이스 세부 정보 입력">
    명확하고 설명적인 이름 (예: "Production AWS" 또는 "Dev Team GCP")과 워크스페이스 목적에 대한 설명을 입력한 후 워크스페이스를 생성합니다.
  </Step>
</Steps>

<Warning>
  클라우드 공급자 선택은 워크스페이스 생성 후에는 변경할 수 없습니다. 기본 인프라를 기반으로 선택하세요.
</Warning>

### 공급자 옵션

| 공급자 | 에이전트가 작업하는 서비스 예시 |
| --- | --- |
| <img src="/images/icons/aws.svg" alt="AWS logo" width="16" style={{display: 'inline'}} /> **Amazon Web Services** | EC2, S3, RDS, Lambda |
| <img src="/images/icons/gcp.svg" alt="GCP logo" width="16" style={{display: 'inline'}} /> **Google Cloud Platform** | Compute Engine, Cloud Storage, BigQuery, Kubernetes Engine |
| <img src="/images/icons/azure.svg" alt="Azure logo" width="16" style={{display: 'inline'}} /> **Microsoft Azure** | Virtual Machines, Blob Storage, SQL Database, Container Instances |

## 워크스페이스에 포함되는 것

각 워크스페이스는 자체 리소스 세트를 유지합니다:

| 리소스 | 범위 |
| --- | --- |
| [Agents](/ko/guide/agents) | 에이전트 커스터마이징, 지시, 워크스페이스별 지식 |
| [Connections](/ko/guide/connections/overview) | 클라우드 공급자, 데이터베이스, 서비스 자격 증명 |
| [Knowledge bases](/ko/guide/knowledge) | 에이전트가 참조하는 문서, 절차, 참고 자료 |
| Operations | 사전 구축 및 커스텀 운영과 실행 내역 |

워크스페이스 선택기로 워크스페이스 간에 전환합니다. 각 워크스페이스는 자체 에이전트, 연결, 설정을 유지하므로 환경 간에 아무것도 누출되지 않습니다.

## 워크스페이스 접근

접근은 조직 역할을 통해 관리됩니다:

| 조직 역할 | 기본 워크스페이스 접근 | 워크스페이스별 재정의 가능 여부 |
| --- | --- | --- |
| **Owner** | 모든 워크스페이스의 Admin (암묵적) | 아니요 — 항상 Admin |
| **Admin** | 모든 워크스페이스의 Admin (암묵적) | 아니요 — 항상 Admin |
| **Developer** | 할당된 워크스페이스에서만 Developer | 예 |
| **Viewer** | 할당된 워크스페이스에서만 Viewer | 예 |

Owner와 Admin은 모든 워크스페이스를 자동으로 봅니다. Developer와 Viewer는 특정 워크스페이스에 할당되어야 하며, 각 할당은 조직 역할을 상속하거나 해당 워크스페이스에만 적용되는 Admin, Developer, Viewer 재정의를 사용할 수 있습니다.

### 워크스페이스 접근 부여

<Steps>
  <Step title="조직 멤버 열기">
    **Admin Settings → Organization**으로 이동하여 Members 섹션까지 스크롤합니다.
  </Step>
  <Step title="워크스페이스 접근 편집">
    Developer 또는 Viewer를 찾은 후, 이름 옆의 그리드 아이콘을 클릭하여 워크스페이스 접근 설정을 엽니다.
  </Step>
  <Step title="워크스페이스 토글">
    워크스페이스를 체크하거나 해제하여 접근을 부여하거나 취소합니다.
  </Step>
  <Step title="역할 설정 및 저장">
    각 워크스페이스에 대해 **Inherit from Org**를 유지하거나 역할 재정의를 선택한 후 **Save**를 클릭합니다.
  </Step>
</Steps>

<Info>
  역할 재정의는 세밀한 제어를 가능하게 합니다. 예를 들어, 조직 Viewer가 운영을 실행해야 하는 워크스페이스에서 Developer 접근을 받을 수 있습니다. 새 멤버를 초대하려면 [조직 멤버](/ko/guide/organization#organization-members)를 참조하세요.
</Info>

## 일반적인 워크스페이스 패턴

| 패턴 | 분리 방식 | 일반적인 사용 |
| --- | --- | --- |
| **환경 기반** | Dev → Staging → Production | 별도의 클라우드 계정, 프로덕션에서 더 엄격한 접근 및 인시던트 대응 지식 |
| **팀 기반** | 플랫폼, 기능, 보안 팀 | 각 팀이 자신의 초점에 맞게 튜닝된 에이전트와 지식 베이스 보유 |
| **공급자 기반** | 클라우드 공급자당 하나의 워크스페이스 | AWS, GCP, Azure 자격 증명과 운영을 분리 |

어떤 패턴을 선택하든, 워크스페이스 간에 일관된 네이밍을 사용하고, 접근 할당 시 최소 권한 원칙을 따르며, 더 이상 사용하지 않는 워크스페이스를 정리하세요.

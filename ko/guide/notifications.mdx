Notifications 페이지는 에이전트가 승인을 기다리거나 자동화가 실패하는 것처럼 CloudThinker가 앱 밖으로 보낼 워크스페이스 이벤트와 각 이벤트를 보낼 곳을 결정합니다. 모든 알림은 [Inbox](/guide/activity)의 **Notifications** 탭에도 도착하며, 이 탭은 항상 켜져 있고 스위치가 없습니다.

## 사전 요구 사항

- 설정을 변경하려면 워크스페이스 **Admin** 역할. Developer와 Viewer는 페이지를 열 수 있지만 편집할 수 없습니다. [워크스페이스 역할](/ko/guide/workspace-users)을 참조하세요.
- Slack, Microsoft Teams, Google Chat 전송의 경우: **Team** 플랜 이상([요금제](/ko/guide/billing/pricing) 참조)과 설정된 통합.
  - [Slack integration](/ko/guide/slack-integration) 연결.
  - [Teams integration](/ko/guide/teams-integration) 연결, 봇 설치 및 워크스페이스 매핑.
  - [Google Chat integration](/guide/google-chat-integration) 설정, 조직 관리자가 이 워크스페이스에 Google Chat 스페이스를 매핑.

## 전송 채널 설정

전송 채널은 알림이 가는 곳입니다. 이메일은 기본적으로 준비되어 있습니다. 채팅 채널은 각각 선택한 채널이나 스페이스 하나에 게시합니다.

<Steps>
  <Step title="Notifications 열기">
    **Settings → Workspace → Notifications**로 이동합니다. Settings를 열려면 사이드바 상단의 워크스페이스 메뉴를 클릭한 다음 **Settings**를 클릭합니다. 페이지에는 먼저 보낼 이벤트가 나열되고, 그 다음 워크스페이스 이름이 표시되는 **Where … sends them** 제목 아래에 전송 채널이 나열됩니다.
  </Step>
  <Step title="이메일 수신자 선택">
    **Email** 카드에서 **Manage email recipients**를 엽니다. 워크스페이스 멤버는 기본적으로 이메일을 받습니다. 팀 별칭처럼 워크스페이스 밖의 사람을 포함하려면 주소를 입력하고 **Add email**을 클릭합니다.

    **성공 상태:** 카드에 **Workspace members**가 표시되며, 주소 두 개를 추가하면 **Members + 2 more**가 표시됩니다.
  </Step>
  <Step title="Slack 채널, Teams 채널 또는 Google Chat 스페이스 선택">
    연결된 **Slack**, **Teams**, **Google Chat** 카드에는 하나를 선택할 때까지 **Pick a channel**(Google Chat은 **Pick a space**)이 표시됩니다. 카드의 설정 버튼(**Change Slack channel**, **Change Teams channel**, **Change Google Chat space**)을 클릭한 다음 검색하여 하나를 선택합니다. 공유 채널에 게시하면 팀 전체가 알림을 볼 수 있으며, 사람들은 채널에 참여하여 구독합니다. 각 통합은 워크스페이스당 정확히 하나의 채널 또는 스페이스에 게시하므로, 승인은 한 Slack 채널로, 다이제스트는 다른 채널로 보낼 수 없습니다. 두 번째 대상에게 보내려면 그 이메일 별칭을 이메일 수신자로 추가하세요.

    **성공 상태:** 카드에 채널 또는 스페이스 이름이 표시됩니다. **Not set up**, **Finish setup**, **Map a space to finish**, **Upgrade to enable**이 표시된 카드는 아직 전송하지 않습니다. [문제 해결](#문제-해결)을 참조하세요.
  </Step>
</Steps>

## 보낼 이벤트 선택

<Steps>
  <Step title="모듈 그룹 열기">
    페이지 상단에서 이벤트는 Resolve, Review, Optimize, Agents & Tasks 같은 모듈별로 그룹화되어 있습니다. 그룹을 클릭하여 펼칩니다.
  </Step>
  <Step title="이벤트별로 채널 켜기">
    각 행은 이벤트 하나이고, 각 열은 전송 채널입니다. 해당 이벤트가 도달해야 할 채널의 셀을 켭니다. 대시(-)는 해당 이벤트에 그 채널을 사용할 수 없다는 뜻입니다.
  </Step>
  <Step title="제공되는 경우 심각도 임계값 설정">
    **Alerts**와 **Keepers** 행은 채널이 켜지면 심각도 선택기를 표시합니다. 해당 채널에 도달해야 할 가장 낮은 심각도를 고릅니다.

    | 임계값 | 보내는 내용 |
    |---|---|
    | **Low** | 모두 |
    | **Medium** | Medium 이상 |
    | **High** | High와 Critical |
    | **Critical** | Critical만 |

    각 채널에는 자체 임계값이 있습니다. 예를 들어 Slack에는 Medium 이상을, 이메일에는 Critical만 보낼 수 있습니다.
  </Step>
</Steps>

**성공 상태:** 변경 사항은 바로 저장됩니다. 다음에 일치하는 이벤트가 켠 채널에 게시됩니다.

## 라우팅할 수 있는 이벤트

"기본 이메일" 열은 아무도 설정을 바꾸기 전에 어떤 이벤트가 이메일을 보내는지 보여 줍니다. Alerts와 Keepers 행은 목록 맨 위에 있으며 자체 설정을 유지하므로, 현재 상태는 페이지에서 확인하세요. Slack, Teams, Google Chat 셀은 꺼진 상태로 시작하므로, 각 채널이 받을 이벤트를 켜세요.

| 모듈 | 이벤트 | 보내는 시점 | 기본 이메일 |
|---|---|---|---|
| Alerts | Alerts | 에이전트가 새 알림을 만들 때. 심각도 임계값이 있습니다. | 행 참조 |
| Keepers | Keepers | [Optimize](/ko/guide/cost-optimization/overview)가 비용 절감을 찾거나 자동 비용 점검이 끝날 때. 행 하나가 둘 다 다룹니다. 이 행은 이전 이름인 **Keepers**를 유지하며, 제품은 Optimize입니다. 심각도 임계값이 있습니다. | 행 참조 |
| Assessment | Assessment completion | AWS Well-Architected Assessment가 완료될 때 | 아니요 |
| Agents & Tasks | Agent approvals | 에이전트가 쓰기를 실행하기 위해 [승인](/guide/approvals/overview)이 필요할 때, 그리고 승인 또는 거부될 때 | 예 |
| Agents & Tasks | Rule proposals | 사람이 참여하지 않은 실행이 검토를 기다리는 Rule을 제안할 때 | 아니요 |
| Agents & Tasks | Runbook proposals | 사람이 참여하지 않은 실행이 검토를 기다리는 runbook을 제안할 때 | 예 |
| Agents & Tasks | Automation run failed | [automation](/guide/automation/automations)이 성공 후 처음으로 실행에 실패할 때 | 예 |
| Agents & Tasks | Automation turned off | 반복된 실패나 플랜 변경으로 automation이 꺼질 때 | 예 |
| Agents & Tasks | Watched condition met | automation이 지켜보던 조건이 충족되었다고 보고할 때 | 예 |
| Agents & Tasks | Agent reduced its monitoring | 스스로 automation을 실행하는 에이전트가 트리거 하나를 제거하거나 일시 중지하거나, 점검 빈도를 줄일 때 | 예 |
| Agents & Tasks | Automation resource missing | 필요한 리소스가 삭제되어 automation을 실행할 수 없을 때 | 예 |
| Resolve | Incident created | 수동 또는 웹훅으로 새 [인시던트](/ko/guide/incident/overview)가 만들어질 때 | 예 |
| Resolve | Awaiting approval | 인시던트 안의 작업에 승인이 필요할 때 | 예 |
| Resolve | Runbook approvals | runbook 실행에 승인이 필요할 때 | 예 |
| Resolve | RCA completed | 인시던트의 근본 원인 분석이 끝날 때 | 아니요 |
| Resolve | Incident resolved | 인시던트가 해결됨으로 표시될 때 | 아니요 |
| Resolve | Monitoring updates | Monitor가 바뀌거나, Alert Audit이 준비되거나, 주간 Monitoring scorecard가 나오거나, 승격 pull request가 열리거나 실패할 때 | 아니요 |
| Resolve | Incident upkeep | 재확인 결과 분석된 인시던트가 복구되었거나, 여전히 활성 상태이거나, 사람이 필요할 때 | 아니요 |
| Resolve | Incident upkeep digest | 하루 한 번: 여전히 활성 상태인 인시던트, 유지되지 않은 수정, 끝난 감시, 실행할 수 없는 점검, upkeep이 종료한 인시던트 | 예 |
| Resolve | Postmortem ready | 인시던트 포스트모템을 검토할 준비가 되었을 때 | 아니요 |
| Resolve | Runbook draft generated | CloudThinker가 인시던트에 대한 [runbook](/ko/guide/incident/runbooks) 초안을 작성할 때 | 아니요 |
| Review | Review findings | pull 또는 merge request에서 [Review](/ko/guide/code-review/overview) 실행이 끝날 때 | 예 |
| Review | Pipeline analysis | 파이프라인 분석이 실패한 파이프라인에서 문제를 찾을 때 | 예 |
| Review | Reports ready | 저장소 수준 Review 보고서 PDF 생성이 끝날 때 | 아니요 |
| Cyber | Dependency risk changes | 모니터링 중인 라이브러리가 취약해지거나 위험이 증가할 때. 이메일과 채팅 게시는 High와 Critical 변경만 다룹니다 | 예 |
| Cyber | New Pentest findings | Pentest 실행이 확인된 새 결과를 저장할 때 | 아니요 |
| Cyber | New Code Audit findings | Code Audit이 확인된 새 결과를 게시할 때 | 아니요 |
| Cyber | Pentest completion reports | Pentest가 끝날 때, 심각도 합계와 우선순위 결과 포함 | 예 |
| Cyber | Code Audit completion reports | Code Audit이 끝나거나 실패할 때, 심각도 합계와 우선순위 결과 포함 | 예 |
| Cyber | Cyber run failed or blocked | pentest 실행이 실패하거나, 저장된 로그인이 더 이상 작동하지 않아 차단될 때 | 예 |
| Optimize | Optimize refresh paused | [Optimize](/ko/guide/cost-optimization/overview)가 비용 데이터를 새로 고치기 전에 연결에 조치가 필요할 때 | 예 |
| Optimize | Optimize report ready | 예약된 [비용 보고서](/ko/guide/cost-optimization/reports)를 읽을 준비가 되었을 때 | 아니요 |
| Optimize | High cost anomalies | Optimize가 연결에서 높은 심각도의 비용 이상 징후를 기록할 때 | 아니요 |
| Optimize | Optimize weekly digest | Cost Health, 새 결과, 만료 예정 약정, 검토된 이상 징후의 월요일 요약 | 아니요 |
| Optimize | Optimize monthly digest | 지난달 지출, 새 결과, 이상 징후, Cost Health, 매월 2일 발송 | 예 |
| Recommendations | Recommendation assignments | 추천 항목이 나에게 할당되거나 할당이 해제될 때 | 예 |
| Recommendations | Replies | 누군가 내 댓글에 답글을 달 때 | 예 |
| Recommendations | Resolved discussions | 내가 참여한 논의가 해결됨으로 표시될 때 | 아니요 |
| Connections | Connection needs attention | 만료되거나 취소된 키처럼 [연결](/ko/guide/connections/overview)의 자격 증명이 작동을 멈출 때 | 예 |
| Rooms | Mentions | 다른 사람과 공유된 채팅인 room에서 누군가 나를 멘션할 때. 이메일 전용. | 예 |

**Automation run failed**는 실패한 실행마다가 아니라 연속된 실패 구간마다 알림을 하나 보냅니다. automation이 꺼질 때까지 실패가 계속되면 **Automation turned off**를 받습니다.

두 가지 승인 알림에는 자체 행이 없습니다. 사람을 기다리는 파괴적인 쓰기는 High 알림을 발생시키므로, **Alerts** 행에서 임계값이 High 이하인 모든 채널에 도달합니다. [break-glass](/guide/approvals/approvers#break-glass) 사용은 워크스페이스 소유자와 모든 워크스페이스 **Admin**(모든 조직 Owner와 Admin 포함)에게 앱 내 알림을 보냅니다.

테스트 버튼은 없습니다. 라우팅을 처음부터 끝까지 확인하려면 채널에 **Agent approvals**를 켜고, 테스트 채팅을 **Manual** [Approval mode](/guide/approvals/approval-mode)로 설정하고, 테스트 연결에서 작은 쓰기를 요청한 다음 카드에서 **Decline**을 클릭하세요.

<Tip>
공유 채널에서 승인, 인시던트, 연결 상태부터 시작하세요. 팀이 평소 알림량을 파악한 후에 다이제스트와 낮은 심각도 이벤트를 추가하세요.
</Tip>

## 워크스페이스 설정과 개인 이메일

이 페이지는 워크스페이스가 보내는 내용을 설정합니다. 각 멤버는 다른 사람에게 영향을 주지 않고 **Settings → Personal → Notifications**에서 자신이 받는 이메일을 음소거할 수 있습니다. 기본적으로 이메일이 꺼진 이벤트는 멤버가 그곳에서 자신의 사본을 켤 수 있습니다. 개인 설정은 이메일만 다룹니다. Slack, Teams, Google Chat 게시는 이 페이지와 채널 자체 설정을 따릅니다.

<Note>
[Agent CLI](/ko/guide/cli/agent) 세션은 승인 카드가 이미 터미널과 브라우저에 있으므로 스스로 승인 알림을 보내지 않습니다. 세션에서 `/cloudthinker notify`를 실행하면 워크스페이스 승인자에게 한 번 알립니다.
</Note>

## 문제 해결

<AccordionGroup>
  <Accordion title="채팅 카드에 Upgrade to enable이 표시됨">
    Slack, Teams, Google Chat 전송에는 Team 플랜 이상이 필요합니다. 이메일과 앱 내 알림은 모든 플랜에서 작동합니다. [Subscription](/ko/guide/billing/subscription)을 참조하세요.
  </Accordion>
  <Accordion title="채팅 카드에 Not set up 또는 Finish setup이 표시됨">
    **Not set up**은 통합이 아직 연결되지 않았다는 뜻입니다. Teams에서 **Finish setup**은 봇이 설치되지 않았거나 워크스페이스가 매핑되지 않았다는 뜻입니다. Google Chat은 조직 관리자가 이 워크스페이스에 스페이스를 매핑해야 합니다. [사전 요구 사항](#사전-요구-사항)에 링크된 통합 가이드를 따르세요.
  </Accordion>
  <Accordion title="Slack 채널이 목록에 없음">
    선택기는 입력하는 대로 검색하며 부분 이름도 일치시킵니다. 그래도 채널이 표시되지 않으면 Slack에서 CloudThinker 앱이 그 채널을 볼 수 있는지 확인한 다음 다시 검색하세요.
  </Accordion>
  <Accordion title="토글이 잠겨 있음">
    알림 설정을 변경하려면 워크스페이스 **Admin** 역할이 필요합니다. 워크스페이스 Admin에게 변경하거나 역할을 바꿔 달라고 요청하세요.
  </Accordion>
  <Accordion title="이벤트가 켜져 있는데 아무도 이메일을 받지 못함">
    해당 이벤트의 이메일 셀이 켜져 있는지, (Alerts와 Keepers의 경우) 심각도 임계값이 이벤트보다 높지 않은지, 수신자가 **Settings → Personal → Notifications**에서 자신의 사본을 음소거하지 않았는지 확인하세요. Inbox의 **Notifications** 탭에는 항상 기록이 있습니다.
  </Accordion>
</AccordionGroup>

중요한 클라우드 운영 상황을 지능적인 역할별 알림으로 놓치지 마세요. CloudThinker 기능에 대한 알림을 받는 방법과 채널을 유연한 심각도 필터링 및 다양한 전달 채널로 구성하세요.

---

## 알림 피로의 문제

일반적인 클라우드 알림은 모든 것을 모두에게 전송합니다 — 모두가 모든 것을 받으면, 아무도 읽지 않게 됩니다. 보안 엔지니어는 모든 비용 권고 사항을 볼 필요가 없습니다. 재무팀은 Kubernetes OOMKill 알림이 필요하지 않습니다. 온콜 엔지니어는 새벽 3시에 컴플라이언스 요약 이메일이 필요하지 않습니다.

결과적으로 중요한 알림은 노이즈 속에 묻히고, 팀은 알림을 완전히 비활성화하며, 중요한 발견 사항은 조치 없이 방치됩니다.

CloudThinker의 알림 센터는 역할 기반 라우팅과 심각도 필터링으로 이 문제를 해결합니다: 각 팀원은 자신이 관심 있는 항목, 심각도 임계값, 채널을 개별적으로 구성할 수 있어 적절한 사람이 적절한 시간에 적절한 알림을 받을 수 있습니다.

| 기능 | 설명 |
|---|---|
| **스마트 라우팅** (채널 기반 전달) | 기능 카테고리 및 심각도 수준에 따라 이메일 또는 Slack 채널로 알림 라우팅 |
| **알림 피로 제어** (지능형 필터링) | 역할에 맞는 알림만 받도록 심각도 임계값 구성 |
| **멀티 채널 지원** (유연한 기본 설정) | 각 기능에 맞게 이메일, Slack, Microsoft Teams 또는 조합으로 알림 수신 |
| **멀티 워크스페이스** (워크스페이스 격리) | 관리하는 각 워크스페이스에 대해 별도의 알림 기본 설정 구성 |

## 빠른 시작

<Steps>
  <Step title="알림 설정으로 이동">
    CloudThinker에서 **설정 > 알림**으로 이동합니다
  </Step>
  <Step title="기능 카테고리 선택">
    알림을 구성할 CloudThinker 기능을 선택합니다
    (알림, 에이전트 및 태스크, Code Review 등)
  </Step>
  <Step title="채널 활성화">
    선택한 기능에 대해 이메일, Slack 및/또는 Microsoft Teams를 켭니다
  </Step>
  <Step title="심각도 수준 설정">
    최소 심각도 임계값을 선택합니다 (Critical, High, Medium, Low)
  </Step>
  <Step title="이메일 인증 (해당하는 경우)">
    외부 이메일 수신자의 경우, 이메일 주소로 발송된 인증 링크를 확인합니다
  </Step>
</Steps>

알림 시스템은 CloudThinker의 핵심 기능을 중심으로 구성되어 각 영역을 독립적으로 구성할 수 있습니다. 각 기능 카테고리를 선택하여 포괄적인 설정에 액세스할 수 있습니다.

### 기능 카테고리

각 영역에 대해 독립적으로 알림을 구성합니다:

- **알림** - 시스템 이벤트에 대한 중요 및 운영 알림
- **에이전트 및 태스크** - 에이전트 중단 및 태스크 완료
- **[Code Review](/ko/guide/code-review/setup) / 파이프라인 모니터링** - 심각도별 코드 리뷰 발견 사항, 파이프라인 실행 상태 및 실패 알림
- **[CloudKeepers](/ko/guide/infrastructure/cloudkeepers) / [평가](/ko/guide/infrastructure/assessment)** - 비용 최적화 권고 사항 및 AWS 평가 업데이트
- **토론** - 팀 토론 활동, 답변, 해결된 토론
- **리소스** - 인프라 리소스 변경 및 업데이트

  <img

    style={{ width: "100%", height: "auto" }}

개인 메시지 대신 Slack 채널로 알림을 라우팅하여 팀 인식을 유지하면서 알림 피로를 줄입니다. 채널 이름으로 필터링하려면 입력을 시작하세요 — 검색은 부분 이름을 매칭하며 대소문자를 구분하지 않아, 대규모 워크스페이스에서도 채널을 쉽게 찾을 수 있습니다.

**주요 기능:**

- 채널 기반 라우팅 (개인 메시지가 아닌)
- 타입 어헤드 필터링이 있는 검색 가능한 채널 선택기
- 알림 과부하 감소
- 팀 전체 가시성 및 옵트인
- 컨텍스트 인식 채널 선택

### [Microsoft Teams 연동](/ko/guide/teams-integration)

Adaptive Card를 사용하여 Microsoft Teams 채널로 알림을 라우팅하여 구조화된 풍부한 알림을 제공합니다. Teams 알림은 Slack과 동일한 방식으로 작동합니다 — 기능별 카테고리를 구성하고, Teams 채널을 선택하고, 심각도 임계값을 설정합니다.

**주요 기능:**

- 구조화된 데이터 및 액션 버튼이 있는 Adaptive Card 형식
- 검색 가능한 선택기를 통한 채널 기반 라우팅
- 카테고리별 채널 선택 (예: 코드 리뷰 발견 사항은 `#code-reviews`, 인시던트는 `#incidents`)
- 다른 채널과 동일한 심각도 임계값 필터링
- 먼저 [Teams 연동](/ko/guide/teams-integration)을 연결해야 합니다

## 심각도 필터링

<Frame caption="이메일 및 Slack을 통한 알림에 대한 심각도 임계값 구성">
  <img
    src="/images/notification-center/03-alerts-configuration.webp"
    alt="High 및 Medium 임계값으로 이메일 및 Slack 심각도 필터 컨트롤을 보여주는 알림 섹션"
    style={{ width: "100%", height: "auto" }}
  />
</Frame>

심각도 수준별로 알림을 필터링하여 임계값을 충족하는 알림만 받습니다:

- **Low** - 정보성 업데이트 및 일반 알림
- **Medium** - 주의와 검토가 필요한 중요 업데이트
- **High** - 즉각적인 조치가 필요한 운영에 영향을 미치는 중요한 문제
- **Critical** - 즉각적인 조치가 필요한 시스템 중요 알림

각 채널은 독립적인 심각도 임계값을 가질 수 있습니다. 예를 들어, Slack은 Medium 이상으로, 이메일은 High 이상으로 구성할 수 있습니다.

#### 코드 리뷰 발견 사항

AI 코드 리뷰가 풀/머지 리퀘스트에서 완료되면, CloudThinker는 다음 내용이 포함된 알림을 전송합니다:

- **심각도 요약** — Critical, High, Medium, Low 발견 사항 수
- **발견 사항 세부 정보** — 최대 10개의 발견 사항에 대한 제목, 심각도, 파일 경로, 줄 번호
- **해결 추적** — 이전에 식별되어 해결된 발견 사항 수
- **액션 링크** — 코드 리뷰 대시보드로의 직접 링크

<Info>
  코드 리뷰 발견 사항 알림은 각 리뷰가 완료된 후 자동으로 전송됩니다. 알림을 트리거할 리뷰를 제어하려면 심각도 임계값을 구성하세요 — 예를 들어, **High**로 설정하면 Critical 또는 High 심각도 발견 사항이 감지될 때만 알림을 받습니다.
</Info>

각 알림 채널은 해당 채널의 네이티브 형식으로 발견 사항을 렌더링합니다:
- **Slack** — 심각도 이모지 표시기가 있는 [Block Kit 메시지](/ko/guide/slack-integration)
- **Microsoft Teams** — FactSet 심각도 테이블이 있는 [Adaptive Card](/ko/guide/teams-integration)
- **Email** — 발견 사항 세부 정보 및 대시보드 링크가 있는 HTML 테이블

## 주요 기능

### 이메일 인증

무단 액세스 및 데이터 유출을 방지하기 위해 외부 이메일 수신자는 알림을 받기 전에 인증해야 합니다:

1. 알림 설정에 외부 이메일 주소를 입력합니다
2. 해당 이메일 주소로 인증 링크가 전송됩니다
3. 수신자가 인증 링크를 클릭하여 확인해야 합니다
4. 인증된 주소만 워크스페이스 알림을 받습니다

이를 통해 민감한 클라우드 운영 데이터가 의도된 수신자에게만 배포됩니다.

### Slack 채널 기반 라우팅

개인 사용자에게 직접 메시지를 보내는 대신, 알림은 Slack 채널로 라우팅됩니다:

- **더 나은 컨텍스트** - 모든 팀원이 채널에서 알림을 볼 수 있습니다
- **피로 감소** - 개별 메시지 대신 기능별 단일 채널
- **옵트인 구독** - 팀원이 특정 알림 채널을 선택하여 참여할 수 있습니다
- **팀 인식** - 팀 전체에 걸친 운영 가시성

### 멀티 워크스페이스 지원

속한 각 워크스페이스에 대해 별도의 알림 기본 설정을 구성합니다:

- 워크스페이스별 다른 심각도 임계값
- 역할별 구성
- 워크스페이스별 채널
- 워크스페이스 컨텍스트에 기반한 맞춤형 알림 전략

## 모범 사례

### 알림 피로 줄이기

- **적절한 심각도 필터 구성** - 많은 기능을 관리하는 역할에는 High 또는 Critical로 설정
- **Slack 또는 Teams 채널 사용** - 팀 알림을 직접 메시지 대신 채널로 라우팅
- **사용하지 않는 기능 비활성화** - 팀에서 적극적으로 관리하지 않는 기능의 알림 끄기
- **점진적 활성화** - Critical 알림부터 시작하여 점차 낮은 심각도 수준 추가

### 보안 고려 사항

- **항상 외부 이메일 인증** - 권한이 있는 수신자만 민감한 데이터에 액세스할 수 있도록 보장
- **워크스페이스별 채널 사용** - 민감한 운영을 전용 Slack 또는 Teams 채널로 라우팅
- **수신자 정기 검토** - 누가 알림을 받는지 주기적으로 감사
- **채널 액세스 제한** - 알림 채널 멤버십을 관련 팀원으로 제한
- **알림 활동 모니터링** - 컴플라이언스를 위해 누가 어떤 알림을 받는지 추적

### 구성 전략

1. 중요 운영 알림에 **Critical + High 심각도로 시작**
2. 팀이 시스템에 익숙해지면 **점진적으로 Medium 심각도 추가**
3. **기능별로 다른 채널 사용** - 인프라 알림과 비용 알림을 분리
4. **역할별 맞춤화** - 팀원 책임에 따라 임계값 조정
5. **알림 전달 테스트** - 이메일과 Slack 메시지가 의도한 수신자에게 전달되는지 확인

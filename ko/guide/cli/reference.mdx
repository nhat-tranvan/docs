`cloudthinker` 바이너리의 모든 명령과 플래그, 종료 코드입니다. CLI가 처음이라면 [CLI 개요](/ko/guide/cli/overview)부터 시작하세요.

```bash
cloudthinker [--url <URL>] [--workspace <ID or NAME>] <command> [flags]
```

설치한 버전의 정확한 구문은 `cloudthinker <command> --help`로 확인하세요.

## 전역 옵션

전역 옵션은 명령 이름 앞에 둡니다.

| 옵션 | 설명 |
|---|---|
| `--url <URL>` | CloudThinker 주소. 기본값은 마지막 `login --url`의 주소이며, 없으면 `https://app.cloudthinker.io`입니다. 경로나 끝 슬래시 없이 origin만 전달하세요: `--url https://ct.example.com` |
| `--workspace <ID or NAME>` | 이 워크스페이스에 저장된 로그인을 사용합니다. `review setup`과 `doctor`를 제외하고 `CLOUDTHINKER_TOKEN`과 함께 쓸 수 없습니다(종료 코드 2) |
| `--tui-mode <MODE>` | 인수 없는 `cloudthinker`에서만: `fullscreen`(기본값) 또는 채팅을 터미널 스크롤백에 남기는 `regular`. `cloudthinker agent`에서는 대신 `agent` 뒤에 전달하세요 |
| `-y`, `--yes` | 삭제나 `connections disconnect`처럼 먼저 묻는 명령을 묻지 않고 실행합니다. 스크립트나 CI처럼 응답할 터미널이 없을 때는 필수입니다 |
| `--skill [MODULE]` | AI 코딩 에이전트를 위한 CLI 운영 가이드를 출력하고 종료합니다. 로그인이 필요 없습니다. 값이 없으면 색인을 출력하며, 모듈은 `api`, `auth`, `chat`, `cloud`, `connections`, `policy`, `review`, `cyber`, `cyber-scan`, `cyber-verify`, `cyber-report`, `worker`, `remote`입니다 |
| `-h`, `--help` | 도움말을 출력합니다 |
| `-V`, `--version` | CLI 버전을 출력합니다 |

## 로그인 명령

| 명령 | 설명 |
|---|---|
| `login` | 브라우저로 로그인합니다. SSH를 통하거나 디스플레이가 없으면 대신 짧은 코드를 표시합니다 |
| `login --device-auth` | 항상 짧은 코드 흐름을 사용합니다 |
| `login --no-browser` | 브라우저를 열지 않고 로그인 URL을 출력합니다 |
| `login --token` | stdin에서 개인 API 토큰(`ct_pat_`)을 읽어 서버에서 확인하고, 토큰이 다루는 각 워크스페이스에 저장합니다: `cloudthinker login --token < token.txt`. 파이프 입력 없이 터미널에서 실행하면 2로 종료합니다 |
| `logout` | 선택되었거나 활성인 워크스페이스의 로그인을 지웁니다 |
| `logout --all` | 이 호스트에 저장된 모든 로그인을 지웁니다 |
| `whoami [--json]` | 로그인 뒤의 계정과 워크스페이스를 실시간으로 확인해 표시합니다 |
| `auth status [--json]` | 이 머신에 저장된 워크스페이스 로그인을 나열하고 활성 로그인을 표시합니다 |
| `auth switch <WORKSPACE>` | 저장된 로그인을 활성 로그인으로 만듭니다 |
| `auth token` | 현재 액세스 토큰을 stdout에 출력합니다. 비밀 정보입니다 |
| `workspace ls [--json]` | 현재 로그인의 조직에서 접근할 수 있는 워크스페이스와 역할을 실시간으로 나열합니다. 선택된 워크스페이스를 표시하고, 각 워크스페이스에 대해 이 머신에 저장된 로그인이 있는지 보여줍니다. 나열해도 활성 로그인은 바뀌지 않습니다 |
| `doctor [--json]` | 이 머신을 진단합니다: 서버 주소와 그 출처, 로그인, API 접근, 기록된 Connection 테스트, 에이전트와 스킬, 최신 릴리스, 터미널 지원, 이 폴더의 `AGENTS.md` 또는 `CLAUDE.md`, 설치 경로. 모두 정상이면 한 줄을 출력하고, 그렇지 않으면 문제마다 해결 방법과 함께 한 행씩 출력합니다. 테스트, 복구, 로그인을 시작하지 않습니다 |

자세한 내용과 CI 패턴: [CLI 인증](/ko/guide/cli/authentication).

## Agent

명령 없는 `cloudthinker` 또는 `cloudthinker agent`는 현재 폴더에서 [CloudThinker Agent](/ko/guide/cli/agent)를 시작합니다. `agent` 뒤의 모든 인수는 그대로 에이전트에 전달됩니다.

아래 플래그는 `agent` 명령이 필요합니다. 세션을 다시 열려면 `cloudthinker agent --session <id>`를 실행하세요. CLI는 `cloudthinker --session <id>`를 거부합니다. CLI 0.11.0 이하는 종료할 때 이 거부되는 형식을 출력했으므로 `cloudthinker update`로 업데이트하세요.

| 플래그 | 설명 |
|---|---|
| `-p`, `--print <PROMPT>` | 헤드리스로 실행합니다: 답하고, 출력하고, 종료합니다 |
| `--mode json` | `-p`와 함께 이벤트를 JSON 줄로 스트리밍합니다 |
| `-c`, `--continue` | 이 폴더의 가장 최근 세션을 이어갑니다 |
| `-r`, `--resume` | 이어갈 세션을 고릅니다 |
| `--session <ID>` | ID 또는 파일로 세션을 엽니다 |
| `-n`, `--name <NAME>` | 이 세션의 이름을 정합니다 |
| `--model <MODE>` | 에이전트 모드: `light`, `pro`, `ultra` |
| `--list-models` | 워크스페이스가 제공하는 에이전트 모드를 나열합니다 |
| `--add-dir <PATH>` | 에이전트가 이 추가 폴더를 읽고 편집할 수 있게 합니다. 여러 개면 반복합니다 |
| `--max-turns <N>` | `-p`와 함께 사용하며, 모델 턴 N번 후에 멈추고 오류로 종료합니다 |
| `--tools <NAMES>` | 쉼표로 구분한 이 로컬 도구만 허용합니다 |
| `--exclude-tools <NAMES>` | 쉼표로 구분한 이 로컬 도구를 끕니다 |
| `--tui-mode <MODE>` | `fullscreen`(기본값) 또는 `regular`. 인수 없는 `cloudthinker`의 전역 옵션과 같습니다 |
| `-a`, `--approve` | 이번 실행에서 이 프로젝트의 로컬 파일을 신뢰합니다 |
| `-na`, `--no-approve` | 이번 실행에서 이 프로젝트의 로컬 파일을 무시합니다. 대시 하나와 두 글자로 씁니다 |

CLI 자체 옵션은 `agent` 앞에 두세요. `--` 뒤의 모든 것은 CLI가 읽지 않고 에이전트로 전달됩니다:

```bash
cloudthinker --workspace Production agent    # start the agent in the Production workspace
cloudthinker agent --help                    # the CLI's summary of agent flags
cloudthinker agent -- --help                 # the agent's own, full help
```

`agent`는 에이전트 프로세스에 제어를 넘기므로, `agent -p`는 [종료 코드](#종료-코드)의 코드가 아니라 에이전트 자체의 종료 코드를 반환합니다.

### 원격 에이전트

`remote [TARGET]`은 SSH로 다른 머신에서 에이전트를 실행하며, 연결이 끊기거나 노트북이 잠자기에 들어가도 계속 실행되게 합니다. 원격 머신의 CLI가 에이전트를 백그라운드 프로세스로 유지하므로 `tmux`가 필요 없습니다. `TARGET`은 `~/.ssh/config`의 호스트, `user@host`, `user@host:port`, `ssh://user@host:port`이며, 기본값은 마지막으로 사용한 머신입니다. 처음에는 이름을 지정하세요: 대상도 없고 이전 머신도 없으면 명령은 `Which machine? Run: cloudthinker remote <ssh-host>`와 함께 2로 종료합니다. 두 머신 모두 macOS 또는 Linux에 CLI가 있어야 합니다. Linux 머신에 CLI가 없거나 스스로 업데이트하기에 너무 오래된 CLI가 있으면, 노트북이 같은 SSH 로그인으로 맞는 빌드를 복사하겠다고 제안합니다. 해당 머신에는 `tar`만 있으면 됩니다.

| 플래그 | 설명 |
|---|---|
| `--cwd <DIR>` | 고르는 대신 사용할 원격 머신의 폴더 |
| `--name <NAME>` | 이 이름의 에이전트에 연결하거나 이 이름으로 시작합니다 |
| `--detach` | 연결하지 않고 에이전트를 시작한 뒤, 돌아오는 방법을 출력합니다. 터미널 없이도 작동합니다 |
| `--via <COMMAND>` | `ssh -J` 같은 다른 명령으로 머신에 접근합니다. 머신과 함께 저장됩니다 |
| `-- <AGENT_ARGS>` | 시작할 때 에이전트에 전달할 인수 |

`remote ls`는 저장된 머신을, `remote ls <MACHINE> [--json]`은 그곳에서 실행 중인 에이전트를 나열하며, `remote forget <MACHINE>`은 저장된 머신을 제거합니다.

원격 에이전트는 원격 머신의 `cloudthinker`를 실행하므로 그 머신의 로그인과 워크스페이스를 사용합니다. 먼저 그곳에서 `cloudthinker login`을 실행하세요. SSH에서는 짧은 코드가 표시됩니다.

<Note>
`cloudthinker remote` 안에서 Ctrl+Z를 누르면 연결이 분리되고 에이전트는 원격 머신에서 계속 실행됩니다. 로컬 작업을 일시 중지하지 않습니다. 돌아가려면 `cloudthinker remote`를 다시 실행하세요.
</Note>

## Chat

| 명령 | 설명 |
|---|---|
| `chat -p <PROMPT>` | CloudThinker에게 프롬프트를 보내고 답변을 기다립니다. `-p -`는 stdin에서 프롬프트를 읽습니다 |
| `chat -p … --continue <UUID>` | 실행 ID 또는 대화 ID로 대화를 이어갑니다 |
| `chat -p … --agent <UUID or ALIAS>` | 이 턴에 커스텀 에이전트가 답하게 합니다 |
| `chat -p … --no-wait` | 실행이 대기열에 들어가자마자 반환합니다 |
| `chat -p … --timeout <SECS>` | 이 초가 지나면 대기를 멈춥니다. 기본값 2400. 실행은 계속됩니다 |
| `chat -p … --json` | 일반 답변 대신 JSON 객체 하나를 출력합니다 |
| `chat status <RUN_ID> [--wait] [--timeout <SECS>] [--json]` | 실행의 상태와 답변을 표시합니다. `--wait`는 끝날 때까지 폴링합니다 |
| `chat ls [--conversation <UUID>] [--limit <N>] [--json]` | 최근 헤드리스 실행을 최신순으로 나열합니다. `--limit`은 1~50, 기본값 10 |
| `chat search <QUERY> [--regex \| --fuzzy [--min-score <SCORE>]] [--json]` | 볼 수 있는 지난 대화를 검색합니다. 쿼리는 기본적으로 최대 200자의 리터럴 텍스트입니다. `--regex`는 이를 정규식으로 읽고, `--fuzzy`는 오타 같은 근사 일치를 찾습니다(`--min-score` 60~100, 기본값 85). 제목, 메시지 텍스트, 도구 이름, 도구 입력과 출력, 첨부 파일 이름을 검색하지만 사고 과정이나 첨부 파일 내용은 검색하지 않습니다. 각 일치 항목에는 제목, 대화 UUID, 시크릿을 가린 발췌, 링크가 표시됩니다. `--since`, `--until`, `--time-field`, `--type`(`chat`, `headless`, `rca` 등 여러 개면 반복)으로 범위를 좁힙니다. `--limit`은 1~50, 기본값 10입니다. 부분 검색은 이어서 검색할 `--cursor`를 출력하며, 일치 항목이 없는 부분 검색은 코드 1로 종료합니다. 에이전트 실행을 시작하지 않으며 모델을 사용하지 않습니다 |
| `chat trace <CONVERSATION_ID> [--limit <N>] [--json]` | 대화의 최근 메시지, 도구 이름, 실패, 사용량을 표시합니다. 도구 인수, 도구 출력, 사고 과정은 제외되고 오래된 메시지는 개수가 제한되므로 완전한 기록이 아닙니다. 실행 ID가 아니라 대화 ID를 받습니다. 에이전트 CLI 세션은 지원하지 않습니다 |

`--json`이 없으면 stdout에는 답변만 나오며, 진행 상황과 `continue_with=` 줄은 stderr로 갑니다. [헤드리스 채팅](/ko/guide/cli/headless-chat)을 참고하세요.

## Review

로컬 Git 변경을 리뷰하거나, CloudThinker가 머지 리퀘스트나 풀 리퀘스트에서 이미 실행한 [Review](/ko/guide/code-review/overview)를 읽습니다.

| 명령 | 설명 |
|---|---|
| `review` | 스테이징된 변경, 스테이징되지 않은 변경, 추적되지 않은 변경을 `HEAD` 기준으로 리뷰합니다 |
| `review --base <REF>` | 커밋하지 않은 편집을 포함해 `REF`와의 merge base부터의 브랜치 diff를 리뷰합니다 |
| `review status <MR_URL>` | 요약: 제공자, 제목, 상태, 판정, 발견 항목 수 |
| `review findings <MR_URL>` | 발견 항목을 심각도가 높은 순으로 나열합니다 |
| `review findings <FINDING_ID>` | 발견 항목 하나를 읽습니다 |
| `review --no-upload` | 로컬 리뷰의 발견 항목을 CloudThinker로 보내지 않고 이 머신에 둡니다 |
| `review setup`, `review doctor` | 공유 Worker에 Loupe를 준비하거나 Worker의 사전 요구 사항을 확인합니다 |
| `review watch <MR_URL>` | 리뷰가 끝날 때까지 폴링합니다 |

모든 review 명령은 `--json`을 받습니다. `review`와 `review watch`는 `--timeout <SECS>`(기본값 2400. 로컬 `review`에서는 큰 diff의 모든 부분을 합친 총합)와 `--fail-on <low|medium|high|critical>`도 받으며, 후자는 해당 심각도 이상의 발견 항목이 있으면 6으로 종료합니다.

로컬 `review`는 읽기 전용 도구로 체크아웃을 읽고 터미널에 발견 항목을 출력합니다. 코멘트를 게시하거나, 수정을 적용하거나, Git 인덱스나 작업 트리를 바꾸지 않습니다. 끝나면 발견 항목을 CloudThinker로 보내므로, 이 브랜치의 풀 리퀘스트에 대한 첫 Review가 그 항목을 반영합니다. `--no-upload`는 항목을 머신에 둡니다. 워크스페이스의 Code Review 모델로 실행되므로 diff와 읽는 모든 파일이 CloudThinker의 모델 게이트웨이로 전송되며, 워크스페이스 크레딧을 사용합니다. [머신 밖으로 나가는 데이터](/ko/guide/cli/agent#머신-밖으로-나가는-데이터)를 참고하세요.

```bash
cloudthinker review --base origin/main --fail-on high
cloudthinker review findings https://github.com/acme/api/pull/412 --json
```

| 필드 | 값 |
|---|---|
| Review 상태 | `queued`, `in review`, `review complete`, `filtered`, `failed`, `stopped` |
| Review 판정 | `in review`, `approved`, `review suggested`, `changes requested`, `filtered`, `failed`, `stopped` |

`filtered`는 저장소 필터가 머지 리퀘스트를 건너뛰어 리뷰가 실행되지 않았다는 뜻입니다. `review suggested`는 살펴볼 만한 발견 항목이 있지만 차단하는 것은 없다는 뜻입니다. 종료 코드: `--fail-on`에 걸리지 않고 끝난 리뷰는 0으로 종료하며, `filtered` 또는 `stopped`도 마찬가지입니다. `failed` 리뷰, 또는 리뷰가 없는 MR URL은 1로 종료합니다. `--timeout`을 넘긴 대기는 4로 종료합니다.

## 인시던트와 권장 사항

| 명령 | 설명 |
|---|---|
| `incident ls [--status <STATUS>] [--limit <N>] [--json]` | [인시던트](/ko/guide/incident/overview)를 최신순으로 나열합니다. `--limit`은 1~100, 기본값 25 |
| `incident status <ID> [--wait] [--timeout <SECS>] [--json]` | 인시던트를 표시합니다. `--wait`는 종료될 때까지 대기합니다 |
| `recommendations ls [--status <STATUS>] [--limit <N>] [--json]` | 월간 절감액과 함께 [비용 권장 사항](/ko/guide/cost-optimization/recommendations)을 나열합니다. `--limit`은 1~100, 기본값 25 |

인시던트 상태: `open`, `acknowledged`, `investigating`, `identified`, `on-hold`, `not-found`, `false-alarm`, `resolved`, `auto-resolved`. `not-found`는 조회 오류가 아니라 상태입니다: 조사에서 증거가 뒷받침하는 근본 원인을 찾지 못했다는 뜻입니다. `incident status --wait`는 인시던트가 `resolved`, `auto-resolved`, `false-alarm`, `not-found`가 되면 0으로 종료합니다. 먼저 `--timeout`이 지나면 4로 종료합니다.

권장 사항 상태: `pending`, `in-progress`, `implemented`, `ignored`.

## Cyber

보안 테스트를 실행하려면 에이전트를 시작하고 평이한 말로 요청하세요(예: "Test http://localhost:3000 for security issues"). 아래 명령은 결과를 확인합니다. [Cyber](/guide/security/cyber-overview)를 참고하세요.

| 명령 | 설명 |
|---|---|
| `cyber app ls` | 이 워크스페이스가 테스트하는 앱을 나열합니다 |
| `cyber domain ls` | 워크스페이스 도메인과 소유권 증명을 나열합니다 |
| `cyber domain add <DOMAIN>` | DNS TXT 레코드로 소유권을 증명할 도메인을 추가합니다. [앱 등록](/ko/guide/security/security-testing#앱-등록)을 참고하세요 |
| `cyber domain verify <ID>` | 도메인의 소유권 증명을 다시 확인합니다 |
| `cyber run status <RUN_ID> [--wait]` | 실행의 상태와 발견 항목 수를 표시합니다. 실행을 나열하는 명령은 없습니다: 실행 ID는 에이전트가 테스트 실행을 시작할 때 출력에 나옵니다 |
| `cyber run cancel <RUN_ID>` | 실행 중인 테스트를 중지합니다 |
| `cyber finding ls <APP_ID>` | 앱의 발견 항목을 나열합니다. 필터: `--severity`, `--status`, `--triage`. 페이지: `--page`(1부터, 기본값 1)와 `--take`(페이지당, 기본값 50) |
| `cyber finding get <FINDING_ID>` | 발견 항목 하나를 표시합니다 |
| `cyber finding export <APP_ID> [--finding-id <ID>]` | 발견 항목을 PDF 리포트로 내보냅니다. 로컬 파일을 쓰지 않으며, 가져올 `filename`과 `download_url`을 출력합니다 |
| `cyber config show`, `get <KEY>`, `set <KEY> <VALUE> [--user]` | 이 프로젝트의 Cyber 설정 또는 기본 설정을 읽거나 변경합니다 |
| `cyber doctor [--fix]` | 이 머신이 로컬 Cyber 테스트를 실행할 수 있는지 확인합니다. `--fix`는 누락된 도구를 설치합니다 |

모든 Cyber 명령은 `--json`을 받습니다.

`finding ls` 필터 값: `--severity`는 `critical`, `high`, `medium`, `low`, `info`. `--status`는 `open`, `resolved`, `dismissed`, `needs-verification`. `--triage`는 `none`, `in-progress`, `awaiting-retest`입니다.

`cyber doctor --fix`는 고정된 버전의 `httpx`와 `katana`를 홈 폴더의 `~/.cloudthinker/tools/` 아래에 설치하므로 `sudo`가 필요 없습니다. `curl`이 없으면 알려주지만 설치하지는 않습니다.

`cyber config`는 프로젝트의 `.cloudthinker/config.toml`과 기본 설정용 `~/.cloudthinker/config.toml`(`--user`)을 읽습니다. 직접 설정한 값이 파생된 값보다 우선합니다. `cyber config show`는 둘 다 나열합니다.

| 키 | 의미 |
|---|---|
| `app` | 이 프로젝트가 테스트하는 앱 |
| `repo_path` | 저장소 루트. 설정하지 않으면 Git에서 파생됩니다 |
| `auth.<role>` | 해당 테스트 신원의 인증 헤더를 담은 환경 변수의 이름이며, 비밀 정보 자체가 아닙니다. 프로젝트 파일에서는 `CYBER_<ROLE>_AUTH`여야 합니다 |
| `context.<name>` | OpenAPI 스펙, Postman 컬렉션, HAR 파일처럼 테스트에 필요한 컨텍스트의 경로 또는 URL |

## Public API

| 명령 | 설명 |
|---|---|
| `api <module>.<resource>.<verb> [IDS…] [--<param> <VALUE>]` | Public API 작업 하나를 호출하고 JSON을 출력합니다. 쿼리 매개변수는 플래그가 됩니다 |
| `api … --all` | 모든 페이지를 따라가 모든 항목을 최대 10,000개까지 출력합니다 |
| `api … --body <JSON or @FILE or ->` | 요청 본문을 인라인, 파일, stdin으로 보냅니다 |
| `api … --set <KEY=VALUE>` | 본문 필드 하나를 설정합니다 |
| `api … --key <KEY>` | `Idempotency-Key`. 생략하면 새 키가 전송됩니다 |
| `api … --etag <ETAG>` | 업데이트용 `If-Match` 값. 읽기는 stderr에 `ETag: …`를 출력합니다 |
| `api <METHOD> <PATH> [--query <NAME=VALUE>]` | 메서드와 경로에 맞는 작업을 호출합니다. `--query`는 이 형식에서만 쿼리 매개변수를 전달하며, 더 필요하면 반복하세요 |
| `api … --yes` | 먼저 묻는 작업에서 질문을 건너뜁니다. 터미널이 없으면 필수입니다 |
| `api --list [--json]` | 모든 작업을 명령, 이름, 메서드, 범위와 함께 나열합니다 |
| `<module> <resource> <verb>` | 같은 호출의 모듈 형식(예: `review reviews list`) |

[Public API용 CLI](/guide/cli/api)를 참고하세요.

## 연결, 에이전트, Policy

TARGET은 `connections list`의 연결 ID, 별칭, 또는 prefix입니다.

| 명령 | 설명 |
|---|---|
| `connections list [--json]`(별칭 `ls`) | 선택된 워크스페이스에 추가된 [Connections](/ko/guide/connections/overview)를 나열합니다 |
| `connections show <TARGET> [--json]` | Connection 하나의 유형, 상태, 가리키는 대상을 표시합니다. 자격 증명은 출력되지 않습니다 |
| `connections status <TARGET> [--wait] [--timeout <SECS>] [--json]` | 최신 테스트를 표시합니다. `--wait`는 끝날 때까지 대기하며 실패하면 1로 종료합니다 |
| `connections retry <TARGET> [--wait] [--timeout <SECS>] [--json]` | 저장된 자격 증명으로 내장 Connection을 다시 테스트합니다(워크스페이스 관리자) |
| `connections disconnect <TARGET> [--json]` | Connection과 저장된 자격 증명을 제거합니다(워크스페이스 관리자). 먼저 묻습니다. `--yes`는 질문을 건너뛰며 터미널이 없으면 필수입니다 |
| `connections connect-url <PREFIX> [--wait] [--timeout <SECS>] [--json]` | `aws`나 `github` 같은 Connection을 추가하는 페이지를 출력하고 데스크톱에서 엽니다. 자격 증명은 브라우저에 남습니다. `--wait`는 새 Connection의 첫 테스트를 따라갑니다 |
| `agents ls [--json]` | 워크스페이스의 에이전트와 각 에이전트를 `chat --agent`로 고를 수 있는지 나열합니다 |
| `agents show <UUID_OR_ALIAS> [--json]` | 에이전트 하나의 신원, 설명, 채팅에서 고를 수 있는지를 표시합니다. 별칭은 대소문자를 무시하고 정확히 일치해야 합니다 |
| `policy export [--output <PATH>]` | 워크스페이스 Policy를 YAML로 출력하거나 새 비공개 파일에 씁니다 |
| `policy import <PATH> [--apply] [--prune] [--activate] [--json]` | YAML 또는 JSON Policy 파일 가져오기를 미리 봅니다. `--apply`만 씁니다. `--prune`은 없는 Rules를 해제하고 생략된 재정의를 지웁니다. `--activate`는 가져온 Allow Rules를 켭니다 |

## Environments

`worker`는 이 머신을 environment로 실행하므로, 채팅이나 automation이 이곳의 폴더에서 작업할 수 있습니다. 전체 가이드: [Environments](/guide/workers).

| 명령 | 설명 |
|---|---|
| `worker outpost create <NAME> [--shared]`, `ls`, `archive <OUTPOST>` | environment를 등록, 나열, 폐기합니다 |
| `worker start --outpost <OUTPOST> --workdir <DIR>` | 중단될 때까지 폴더 하나를 제공합니다. `--background`는 터미널을 닫은 후에도 계속 실행되게 합니다 |
| `worker service install`, `uninstall`, `status`, `start`, `stop` | environment를 systemd(Linux) 또는 launchd(macOS)에서 실행합니다. `install --system --user <ACCOUNT>`(root로 실행)는 머신 전체 서비스를 설치합니다 |
| `worker status --outpost <OUTPOST>` | 워크스페이스에서 보는 environment의 가용성을 표시합니다 |
| `worker doctor` | 이 머신이 environment를 실행할 수 있는지 확인하고, 문제마다 해결 방법을 하나씩 알려줍니다 |
| `worker worktrees ls`, `prune` | 대화용으로 만든 Git worktree를 나열하거나 정리합니다 |

## 업데이트와 셸 자동 완성

| 명령 | 설명 |
|---|---|
| `update` | CLI와 에이전트의 최신 릴리스를 함께 설치합니다 |
| `update --force` | 이미 최신이어도 다시 설치합니다 |
| `update --version <VERSION>` | 최신 대신 해당 릴리스(이전 또는 이후, 예: `0.12.2`)를 설치해 호스트를 고정하거나 롤백합니다. 릴리스된 적 없는 버전은 2로 종료합니다 |
| `update --json` | 결과를 JSON으로 출력합니다 |
| `completion <bash\|zsh\|fish\|…>` | 셸 자동 완성 스크립트를 출력합니다 |

대화형 터미널에서는 더 새로운 릴리스가 있으면 CLI가 최대 20시간마다 업데이트를 제안합니다. `update`는 CLI 설치 프로그램이 만든 설치에서만 작동합니다. 다른 설치에서는 거부하고 재설치 명령 `curl -fsSL https://cloudthinker.io/install.sh | sh`를 출력합니다. [CLI 개요](/ko/guide/cli/overview)를 참고하세요.

```bash
cloudthinker completion zsh > "${fpath[1]}/_cloudthinker"
cloudthinker completion bash > ~/.local/share/bash-completion/completions/cloudthinker
cloudthinker completion fish > ~/.config/fish/completions/cloudthinker.fish
```

`${fpath[1]}`에 쓸 수 없으면 zsh 파일을 직접 만든 폴더에 저장하고, `~/.zshrc`에서 `compinit` 전에 그 폴더를 `fpath`에 추가하세요.

## 환경 변수

| 변수 | 효과 |
|---|---|
| `CLOUDTHINKER_URL` | `--url`과 같습니다 |
| `CLOUDTHINKER_WORKSPACE` | `--workspace`와 같습니다 |
| `CLOUDTHINKER_TOKEN` | 저장된 로그인 대신 사용할 개인(`ct_pat_`) 또는 서비스 계정(`ct_sat_`) [API 토큰](/guide/api/tokens), 또는 `auth token`의 토큰. API 토큰은 `chat`, `incident ls`와 `incident status`, Public API 명령, `api`용이며, 대부분의 다른 명령에는 로그인 또는 `auth token` 토큰이 필요합니다. `review setup`과 `doctor`를 제외하고 `--workspace` 또는 `CLOUDTHINKER_WORKSPACE`와 함께 쓸 수 없습니다 |
| `CLOUDTHINKER_LOGIN` | `browser` 또는 `device`로 이 머신의 로그인 흐름을 강제합니다 |
| `CLOUDTHINKER_NO_UPDATE_CHECK` | `1`로 설정하면 업데이트 제안을 끕니다 |
| `CLOUDTHINKER_OUTPOST_ID` | `worker` 명령의 기본 environment |
| `CLOUDTHINKER_CONFIG_DIR` | 플랫폼 설정 폴더 대신 이 폴더에 자격 증명과 worker 상태를 보관합니다. OS 계정 하나를 공유하는 사람들이 각자 로그인을 유지할 수 있습니다 |
| `CLOUDTHINKER_RELEASE_URL` | 같은 체크섬 확인을 거쳐 `https` 미러, `file://` URL, 또는 `<base>/v<version>/<asset>` 구조의 로컬 폴더에서 에이전트를 설치합니다 |
| `CLOUDTHINKER_REMOTE` | `0`으로 설정하면 SSH에서 인수 없는 `cloudthinker`를 끊긴 연결에도 살아남는 백그라운드 에이전트 대신 현재 셸에서 실행합니다 |
| `CLOUDTHINKER_AUTO_BACKGROUND_SECONDS` | 에이전트가 긴 셸 명령을 백그라운드로 옮기기 전까지의 초. 기본값 10. `0`이면 끕니다 |
| `NO_COLOR` | stderr의 색상을 끕니다. stderr가 터미널이 아니어도 색상은 꺼집니다 |
| `HTTPS_PROXY`, `ALL_PROXY` | CLI의 트래픽을 이 프록시로 보냅니다. `NO_PROXY`의 호스트는 건너뜁니다 |
| `SSL_CERT_FILE`, `SSL_CERT_DIR` | HTTPS를 재서명하는 프록시를 위해 이 CA 번들 또는 폴더를 신뢰합니다. 없으면 CLI는 OS 신뢰 저장소를 사용합니다 |

## 종료 코드

| 코드 | 의미 |
|---|---|
| 0 | 성공 |
| 1 | 작업 실패: 실패한 실행, 알 수 없는 실행 또는 리뷰, 충돌이나 속도 제한 같은 서버 오류, 또는 네트워크 재시도 소진 |
| 2 | 잘못된 사용법, 또는 서버가 요청을 잘못된 것으로 거부함(HTTP 422) |
| 3 | 로그인하지 않았거나, 자격 증명이 만료되었거나, 접근이 거부됨 |
| 4 | CLI가 대기를 멈춤. 작업은 서버에서 계속됩니다 |
| 5 | 실행이 브라우저 승인을 위해 일시 중지됨 |
| 6 | 리뷰가 `--fail-on` 심각도 이상의 문제를 발견함 |
| 130 | Ctrl-C가 `chat` 대기, `incident status --wait`, 또는 `login`을 중지함. 실행이나 인시던트는 서버에서 계속됩니다 |

## 파일

| 경로 | 내용 |
|---|---|
| `~/.local/bin/cloudthinker` | 설치 프로그램이 `PATH`에 두는 바이너리 |
| `~/Library/Application Support/cloudthinker/credentials.json`(macOS), `$XDG_CONFIG_HOME/cloudthinker/credentials.json` 또는 `~/.config/cloudthinker/credentials.json`(Linux), 설정 시 `$CLOUDTHINKER_CONFIG_DIR/credentials.json` | 호스트별로 워크스페이스당 로그인 하나 |
| `~/.cloudthinker/agent/` | `settings.json`을 포함한 에이전트 설정 |
| `~/.cloudthinker/agent/bin/<version>/` | 해당 CLI 버전의 에이전트 빌드 |
| `~/.cloudthinker/agent/sessions/` | 로컬 에이전트 세션 기록 |
| `~/.cloudthinker/tools/` | `cyber doctor --fix`가 설치한 도구 |
| `.cloudthinker/config.toml` | 프로젝트 폴더에 저장된 프로젝트의 Cyber 설정 |
| `~/.cloudthinker/config.toml` | `cyber config set --user`로 설정한 기본 Cyber 설정 |

`credentials.json`은 `0700` 폴더 안에 파일 모드 `0600`으로 저장된 일반 JSON이므로 본인 사용자만 읽을 수 있습니다. CLI는 OS 키체인을 사용하지 않습니다. 0.5.3 이전 릴리스는 사용했으며, 새 릴리스를 처음 실행하면 그 로그인을 파일로 옮기고 키체인 항목을 삭제합니다. 다른 사람도 로그인하는 머신에서는 각자에게 별도 OS 계정을 주고, 작업이 끝나면 `cloudthinker logout --all`을 실행하세요.

### 제거

1. 이 머신이 environment를 서비스로 실행한다면 `cloudthinker worker service uninstall`을 실행하세요.
2. 로그인한 각 호스트마다 `cloudthinker logout --all`을 한 번씩 실행하세요. 기본값이 아닌 호스트에는 `--url`을 사용하세요. 또는 `credentials.json`을 삭제하세요.
3. 바이너리 `~/.local/bin/cloudthinker`를 삭제하세요.
4. `~/.cloudthinker` 폴더와 저장한 자동 완성 스크립트(예: `"${fpath[1]}/_cloudthinker"`)를 삭제하세요.
5. 선택 사항: 프로젝트 안의 `.cloudthinker/` 폴더를 삭제하세요.

SonarQube를 연결하면 CloudThinker 에이전트가 품질 게이트가 실패한 이유를 알려 주고, 그 원인이 된 blocker 및 high 심각도 이슈를 나열하고, 열려 있는 보안 핫스팟을 검토하고, 테스트 커버리지가 가장 낮은 파일을 찾을 수 있습니다. 이 연결은 SonarQube **user token** 하나로 로그인하고 공식 SonarSource MCP 서버를 실행하므로 SonarQube Cloud와 셀프 호스팅 SonarQube Server 모두에서 작동합니다.

## 사전 요구 사항

- SonarQube Cloud 조직, 또는 CloudThinker에서 HTTPS로 접근할 수 있는 SonarQube Server나 Community Build 인스턴스. 비공개 인스턴스는 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
- 에이전트가 읽을 프로젝트에 **Browse** 권한이 있는 CloudThinker용 SonarQube 계정([필수 권한](#필수-권한) 참조).
- 연결을 추가하는 데 필요한 CloudThinker 워크스페이스의 **Admin** 역할. [역할](/guide/security/roles)을 참조하세요.

## 설정

<Tabs>
  <Tab title="SonarQube Cloud">
    <Steps>
      <Step title="user token 생성">
        CloudThinker가 사용할 계정으로 [SonarQube Cloud](https://sonarcloud.io)에 로그인합니다. **My Account → Security**로 이동하여 `cloudthinker` 같은 이름을 입력하고, 만료일을 설정한 다음 **Generate Token**을 클릭합니다.

        토큰을 복사합니다. SonarQube는 토큰을 한 번만 보여 줍니다.
      </Step>
      <Step title="조직 키 찾기">
        조직을 엽니다. 키는 URL의 마지막 부분입니다: `https://sonarcloud.io/organizations/<org-key>`.
      </Step>
      <Step title="프로젝트에 Browse 부여">
        에이전트가 읽을 각 프로젝트를 열고 **Administration → Permissions**로 이동하여 CloudThinker 계정에 **Browse**를 부여합니다. 이 권한이 없으면 확인 프롬프트의 결과가 비어 있습니다.
      </Step>
      <Step title="CloudThinker에 연결 추가">
        **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **SonarQube**를 선택합니다. 다음을 입력합니다.

        - **SONARQUBE_TOKEN**: 복사한 토큰
        - **SONARQUBE_DEPLOYMENT_TYPE**: **SonarQube Cloud**
        - **SONARQUBE_ORG**: 조직 키

        **Connect**를 클릭합니다.

        **성공 상태:** **Connect SonarQube** 대화 상자가 오류 없이 닫힙니다. 아래 확인 프롬프트를 실행하세요.
      </Step>
    </Steps>
  </Tab>
  <Tab title="SonarQube Server">
    <Steps>
      <Step title="user token 생성">
        CloudThinker가 사용할 계정으로 SonarQube 인스턴스에 로그인합니다. **My Account → Security**로 이동하여 `cloudthinker` 같은 이름을 입력하고, **User Token** 유형을 선택하고, 만료일을 설정한 다음 **Generate**를 클릭합니다.

        토큰을 복사합니다. SonarQube는 토큰을 한 번만 보여 줍니다.
      </Step>
      <Step title="프로젝트에 Browse 부여">
        에이전트가 읽을 각 프로젝트를 열고 **Project Settings → Permissions**로 이동하여 CloudThinker 계정에 **Browse**를 부여합니다. 권한 템플릿을 사용하면 여러 프로젝트에 한 번에 적용할 수 있습니다. 이 권한이 없으면 확인 프롬프트의 결과가 비어 있습니다.
      </Step>
      <Step title="CloudThinker에 연결 추가">
        **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **SonarQube**를 선택합니다. 다음을 입력합니다.

        - **SONARQUBE_TOKEN**: 복사한 토큰
        - **SONARQUBE_DEPLOYMENT_TYPE**: **SonarQube Server**
        - **SONARQUBE_URL**: `https://sonarqube.example.com` 같은 인스턴스 주소

        **Connect**를 클릭합니다.

        **성공 상태:** **Connect SonarQube** 대화 상자가 오류 없이 닫힙니다. 아래 확인 프롬프트를 실행하세요.
      </Step>
    </Steps>
  </Tab>

## 연결 세부 정보

양식은 선택한 배포 유형에 따라 **SONARQUBE_ORG** 또는 **SONARQUBE_URL**을 표시합니다. **SonarQube Cloud** 옵션은 `sonarcloud.io`에 연결합니다. 리전 필드는 없습니다.

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **SONARQUBE_TOKEN** | CloudThinker 계정의 user token | `squ_...` |
| **SONARQUBE_DEPLOYMENT_TYPE** | Cloud 조직은 **SonarQube Cloud**(기본값), 셀프 호스팅 Server 또는 Community Build 인스턴스는 **SonarQube Server** | SonarQube Cloud |
| **SONARQUBE_ORG** | 조직 키. Cloud 전용 | `my-org` |
| **SONARQUBE_URL** | HTTPS 인스턴스 주소. Server 전용 | `https://sonarqube.example.com` |

## 필수 권한

user token은 토큰을 만든 계정의 권한으로 작동합니다. SonarQube에서 프로젝트별로 또는 권한 템플릿을 통해 해당 계정에 프로젝트 권한을 부여하세요.

| 목적 | SonarQube 권한 |
|------|----------------------|
| 프로젝트, 품질 게이트, 이슈, 측정값, 커버리지, 중복, 핫스팟 읽기 | **Browse** |
| false positive로 표시하는 등 이슈 상태 변경 | **Administer Issues** |
| 보안 핫스팟 검토 및 상태 설정 | **Administer Security Hotspots** |

<Tip>
**Browse**만으로 시작하세요. 에이전트는 이 권한만으로 모든 게이트와 이슈를 설명할 수 있습니다. 에이전트가 상태 변경을 제안하게 하려는 프로젝트에만 두 Administer 권한을 추가하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 | 승인 |
|------------|--------------------|----------|
| **Discovery** | 품질 게이트 상태(**OK** 또는 **ERROR**)와 심각도별 이슈 수와 함께 프로젝트 나열 | 아니요 |
| **Quality gates** | 프로젝트 또는 pull request의 게이트 상태와 실패한 조건 확인 | 아니요 |
| **Issues** | 프로젝트, pull request, 심각도, 상태로 이슈를 검색하고 이슈의 원인 규칙과 수정 가이드 표시 | 아니요 |
| **Security hotspots** | 검토할 핫스팟을 나열하고 각 핫스팟의 코드와 위험 표시 | 아니요 |
| **Measures, coverage, and duplication** | 코드 줄 수, 커버리지, 버그, 취약점, 코드 스멜, 중복 줄을 읽고 커버리지 임계값 미만의 파일 찾기 | 아니요 |
| **Change status** | 이슈 상태 변경 또는 핫스팟 검토 | Approvals를 거침 |

심각도 이름은 인스턴스의 모드를 따릅니다. Multi-Quality Rule 모드는 **BLOCKER**, **HIGH**, **MEDIUM**, **LOW**, **INFO**를 보고합니다. Standard Experience는 **BLOCKER**, **CRITICAL**, **MAJOR**, **MINOR**, **INFO**를 보고합니다.

<ApprovalDefault />

거부된 요청은 재시도되지 않습니다. 이슈를 false positive로 표시하는 것처럼 각 상태 변경을 직접 결정하려면 **Manual**을 선택하여 모든 변경을 사람이 승인하도록 하세요. **Ask first** [Rule](/guide/approvals/rules)을 사용하면 이를 SonarQube 연결에만 적용할 수 있습니다. 일부 도구는 SonarQube 에디션에 따라 다릅니다. 의존성 위험에는 Advanced Security 라이선스가 필요하고, 시스템 상태 도구는 SonarQube Server에서만 작동합니다.

에이전트는 각 프로젝트의 수치를 현재 상태 그대로 보고합니다. SonarQube는 현재 측정값을 반환하므로, 브랜치나 pull request 비교를 요청하지 않는 한 에이전트는 추세를 주장하지 않습니다.

### 연결 확인

```text
List my SonarQube projects with their quality gate status and issue counts by severity
```

프로젝트 키와 이름, 각 프로젝트의 **OK** 또는 **ERROR** 게이트 상태, **BLOCKER** 같은 심각도별 이슈 수가 담긴 표가 표시됩니다.

### 예시 프롬프트

```text
Why did the quality gate fail on payments-api? List the failed conditions and the blocker issues behind them
Show the security hotspots still to review in payments-api, highest risk first
Which files in payments-api have under 50% coverage?
```

실제 프로젝트 키를 사용하세요. 에이전트는 프로젝트 목록에서 키를 찾으며 추측하지 않습니다.

## 문제 해결

<Accordion title="요청이 401을 반환함">
토큰이 잘못되었거나, 만료되었거나, 취소되었습니다. 새 user token을 생성하고 연결을 편집하여 **SONARQUBE_TOKEN**에 붙여 넣으세요.
</Accordion>

<Accordion title="SonarQube Server에서 Connect가 실패함">
CloudThinker가 **SONARQUBE_URL**에 접근할 수 없습니다. 주소가 `localhost`나 비공개 호스트 이름이 아닌, 인터넷에서 접근 가능한 HTTPS 주소인지, SonarQube 서비스가 실행 중인지 확인하세요.
</Accordion>

<Accordion title="프로젝트가 하나도 표시되지 않음 (Cloud)">
**SONARQUBE_ORG**가 잘못되었거나 토큰 계정이 해당 조직의 구성원이 아닙니다. 조직 URL에서 키를 복사하고 구성원 자격을 확인하세요.
</Accordion>

<Accordion title="일부 프로젝트가 누락됨">
토큰 계정에 해당 프로젝트의 **Browse** 권한이 없습니다. SonarQube에서 해당 프로젝트에 **Browse**를 부여하세요. 다시 연결할 필요는 없으며, 권한은 다음 요청부터 적용됩니다.
</Accordion>

<Accordion title="상태 변경이 403을 반환함">
계정에 해당 프로젝트의 **Administer Issues** 또는 **Administer Security Hotspots** 권한이 없습니다. SonarQube에서 권한을 부여한 다음 다시 요청하세요.
</Accordion>

<Accordion title="의존성 위험 또는 시스템 상태를 사용할 수 없음">
사용 중인 에디션에 해당 도구가 포함되어 있지 않습니다. 의존성 위험에는 Advanced Security 라이선스가 필요하고, 시스템 상태 도구는 SonarQube Server에만 있습니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **user token 사용**: SonarQube Server에서는 Global Analysis Token이 아닌 **User Token** 유형을 선택하여 접근이 한 계정의 프로젝트 권한을 따르도록 하세요.
- **만료일 설정**: 토큰에 만료일을 지정하고 만료되기 전에 교체하세요.

GitGuardian 워크스페이스를 연결하면 CloudThinker 에이전트가 시크릿 인시던트를 나열하고 분류하고, 노출된 각 자격 증명을 출처와 발생 위치까지 추적하고, 허니토큰을 검토할 수 있습니다. 연결은 GitGuardian **Personal Access Token (PAT)**과 대시보드 URL로 로그인하므로, 같은 설정이 US, EU, 셀프 호스팅 인스턴스에서 모두 작동합니다.

## 사전 요구 사항

- 에이전트가 읽을 인시던트가 있는 GitGuardian 워크스페이스.
- 해당 워크스페이스에서 Personal Access Token을 만들 수 있는 권한.
- 연결을 추가하고 편집할 수 있는 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참조하세요.
- 대시보드 URL. 로그인하는 주소를 사용하세요.

| 인스턴스 | GitGuardian URL |
|----------|-----------------|
| US (SaaS) | `https://dashboard.gitguardian.com` |
| EU (SaaS) | `https://dashboard.eu1.gitguardian.com` |
| 셀프 호스팅 | 인스턴스 URL(예: `https://gitguardian.example.com`) |

## 설정

<Steps>
  <Step title="Personal Access Token 만들기">
    GitGuardian에 로그인합니다. 사이드바에서 **Settings → API → Personal Access Tokens**를 열고 **Create token**을 클릭합니다.

    - **Name**: `cloudthinker`
    - **Expiration**: 교체 정책에 맞는 날짜를 선택합니다
    - **Scopes**: `incidents`, `secrets`, `sources`의 읽기 변형(예: `incidents:read`)을 선택합니다. 이것으로 확인 프롬프트와 예시 프롬프트가 모두 작동합니다. 다른 범위는 필요한 경우에만 [필수 권한](#필수-권한)에서 추가하세요.

    토큰을 즉시 복사하세요. GitGuardian은 토큰을 한 번만 표시합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **GitGuardian**을 선택합니다. 다음을 입력합니다.

    - **GITGUARDIAN_URL**: 위 표의 대시보드 또는 인스턴스 URL
    - **GITGUARDIAN_PERSONAL_ACCESS_TOKEN**: 방금 만든 토큰

    **Connect**를 클릭합니다.

    **성공 상태:** Connections 목록에서 GitGuardian에 **Connected**가 표시됩니다. 그런 다음 새 채팅을 열고 [확인 프롬프트](#연결-확인)를 보내 토큰의 범위를 확인하세요.
  </Step>
</Steps>

<Warning>
토큰을 분실하면 다시 볼 수 없습니다. GitGuardian에서 새 토큰을 만들어 연결에 붙여 넣으세요.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **GITGUARDIAN_URL** | 대시보드 또는 셀프 호스팅 인스턴스 URL. CloudThinker가 이 URL에서 API 엔드포인트를 알아냅니다. | `https://dashboard.eu1.gitguardian.com` |
| **GITGUARDIAN_PERSONAL_ACCESS_TOKEN** | 워크스페이스의 Personal Access Token | `<your-token>` |

두 번째 GitGuardian 워크스페이스에 접근하려면 자체 토큰을 사용하는 별도 연결로 추가하세요.

## 필수 권한

각 PAT 범위는 에이전트 기능 한 묶음을 엽니다. GitGuardian이 `:read`와 `:write` 변형을 제공하는 경우 `:read`를 선택하세요. 에이전트가 무언가를 할 수 없다고 하면, 보통 토큰에 해당 범위가 없는 것입니다.

| 범위 | 허용되는 것 |
|-------|---------|
| `incidents` | 시크릿 인시던트 나열, 검사, 분류. 최소 세트. |
| `secrets` | 탐지된 시크릿과 각 시크릿의 발생 위치 읽기. 최소 세트. |
| `sources` | 모니터링되는 소스(리포지토리) 나열과 검사. 최소 세트. |
| `scan` | 요청 시 콘텐츠에서 시크릿 스캔 |
| `honeytokens` | 읽기로 허니토큰 나열. 쓰기로 생성. |
| `custom_tags` | 사용자 지정 태그 읽기와 관리 |
| `audit_logs` | 워크스페이스 감사 로그 읽기 |

<Tip>
PAT는 만든 사람의 워크스페이스 역할도 상속합니다. 필요한 접근 권한을 가진 멤버 중 권한이 가장 적은 멤버로 만들고, 범위가 읽기 권한을 제공할 때는 항상 읽기를 선택하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 | 필요한 범위 | 승인 |
|------------|--------------------|--------------|----------|
| **인시던트 분류** | 상태와 심각도와 함께 시크릿 인시던트를 나열하고 검사 | `incidents` | 아니요 |
| **인시던트 조사** | 노출된 자격 증명의 출처와 발생 위치 표시 | `incidents`, `secrets`, `sources` | 아니요 |
| **토큰 검사** | 연결된 토큰이 가진 범위 보고 | 모든 범위 | 아니요 |
| **허니토큰** | 허니토큰과 그 상태 나열 | `honeytokens` 읽기 | 아니요 |
| **허니토큰 생성** | 새 허니토큰 생성 | `honeytokens` 쓰기 | Approvals를 거침 |

읽기는 묻지 않고 실행됩니다. 허니토큰을 만들려면 `honeytokens:write`와 **Manager**가 만든 토큰이 필요하며, 요청할 때만 실행됩니다.

<ApprovalDefault />

허니토큰이 만들어질 때마다 확인을 받으려면 **Manual**을 선택하세요. **Ask first** [Rule](/guide/approvals/rules)로 허니토큰 생성만 따로 지정할 수도 있습니다.

### 연결 확인

```text
Check the GitGuardian connection, list the scopes on the token, and count open secret incidents
```

토큰의 범위 목록과 열린 인시던트 수, 즉 **Triggered** 또는 **Assigned** 상태인 인시던트 수가 표시되어야 합니다. 예상한 범위가 보이지 않으면 토큰을 업데이트해야 합니다.

### 예시 프롬프트

```text
List open GitGuardian incidents sorted by severity, with the repository for each one
Investigate the newest GitGuardian incident and summarize the exposed credential and its sources
```

## 문제 해결

<Accordion title="연결이 실패하거나 요청이 401을 반환함">
토큰이 잘못되었거나, 만료되었거나, 취소되었습니다. 새 Personal Access Token을 만드세요. **Settings → Workspace → Connections**에서 **GitGuardian**을 열고, 연결 행의 연필 아이콘을 클릭하고, **Replace…**를 클릭한 다음 **GITGUARDIAN_PERSONAL_ACCESS_TOKEN**에 토큰을 붙여 넣고 **Save and test**를 클릭합니다.
</Accordion>

<Accordion title="요청이 403을 반환함">
토큰에 해당 요청의 범위가 없거나, 토큰을 만든 사람의 워크스페이스 역할이 너무 낮습니다. GitGuardian에서 범위를 추가하고(허니토큰 생성에는 **Manager**가 필요합니다) 새 토큰으로 연결을 업데이트하세요.
</Accordion>

<Accordion title="에이전트가 기능을 사용할 수 없다고 함">
토큰에 해당 범위가 없습니다. 요청을 [필수 권한](#필수-권한)과 비교하고, 그 범위를 가진 토큰을 만들어 연결을 업데이트하세요.
</Accordion>

<Accordion title="인시던트가 없거나 엔드포인트에 접근할 수 없음">
**GITGUARDIAN_URL**이 잘못된 리전이나 인스턴스를 가리킵니다. US 토큰은 EU 대시보드에서 작동하지 않습니다. 로그인하는 주소를 정확히 사용하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **읽기 범위부터**: 에이전트가 허니토큰을 만들게 하려는 경우에만 `honeytokens:write`나 Manager 역할 토큰을 추가하세요.
- **전용 토큰**: 이름을 `cloudthinker`로 지정하면 다른 도구에 영향을 주지 않고 GitGuardian에서 취소할 수 있습니다.

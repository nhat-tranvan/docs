Argo CD를 연결하면 CloudThinker 에이전트가 애플리케이션을 나열하고, 앱이 동기화되지 않았거나 성능이 저하된 이유를 설명하고, Kubernetes 이벤트와 Pod 로그를 읽고, 승인을 거쳐 동기화할 수 있습니다. 이 연결은 Argo CD **API token** 하나로 로그인하며, 자체 호스팅 Argo CD와 Akuity Platform에서 작동합니다.

## 사전 요구 사항

- CloudThinker에서 HTTPS로 접근할 수 있는 Argo CD 서버. `localhost`나 클러스터 내부 주소는 작동하지 않습니다.
- 로컬 계정을 만들고 토큰을 생성할 수 있는 Argo CD 관리자 권한.
- 토큰을 생성할 머신의 [Argo CD CLI](https://argo-cd.readthedocs.io/en/stable/cli_installation/).
- 자체 호스팅 전용: `argocd-cm`과 `argocd-rbac-cm` ConfigMap을 편집할 수 있는 `argocd` 네임스페이스에 대한 `kubectl` 접근 권한.

서버가 사설 네트워크에 있다면 [사설 서비스에 접근하기](/ko/guide/connections/overview#비공개-서비스-접근)를 참고하세요.

## 설정

`admin`을 쓰는 대신 전용 `cloudthinker` 계정을 만드세요. 그러면 토큰에는 부여한 RBAC 권한만 담기며, 다른 사람에게 영향을 주지 않고 취소할 수 있습니다.

<Tabs>
  <Tab title="자체 호스팅 Argo CD">
    <Steps>
      <Step title="API 키 접근 권한이 있는 로컬 계정 만들기">
        웹 로그인이 아닌 API 키만 사용할 수 있는 `cloudthinker` 계정을 추가하세요:

        ```bash
        kubectl -n argocd patch configmap argocd-cm --type merge \
          -p '{"data":{"accounts.cloudthinker":"apiKey"}}'
        ```
      </Step>
      <Step title="토큰 생성하기">
        관리자로 로그인한 다음 새 계정의 토큰을 생성하세요:

        ```bash
        argocd login argocd.example.com --username admin
        argocd account generate-token --account cloudthinker --expires-in 90d
        ```

        토큰을 복사하세요. 서버가 자체 서명 인증서를 사용할 때만 두 명령 모두에 `--insecure`를 추가하세요. `--expires-in`이 없으면 토큰이 만료되지 않으므로, 유효 기간을 정하고 만료되기 전에 새 토큰을 생성하세요.

        **성공 상태:** 두 번째 명령이 긴 토큰 문자열을 출력합니다.
      </Step>
      <Step title="계정에 읽기 권한 부여하기">
        `kubectl -n argocd edit configmap argocd-rbac-cm`을 실행하고 기존 `policy.csv`에 다음 줄을 추가하세요:

        ```csv
        p, role:cloudthinker, applications, get, */*, allow
        p, role:cloudthinker, logs, get, */*, allow
        g, cloudthinker, role:cloudthinker
        ```

        새 ConfigMap을 적용하지 말고 기존 ConfigMap을 편집하세요. 새 `argocd-rbac-cm`으로 `kubectl apply`를 하면 전체 정책이 교체되어 다른 사용자가 접근하지 못할 수 있습니다. 에이전트가 변경할 수 있게 하려면 [필요한 권한](#필요한-권한)의 줄을 추가하세요.
      </Step>
      <Step title="CloudThinker에 연결 추가하기">
        **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **ArgoCD**를 선택하세요. 다음을 입력하세요:

        - **ARGOCD_BASE_URL**: 서버 주소(예: `https://argocd.example.com`)
        - **ARGOCD_API_TOKEN**: 복사한 토큰
        - **NODE_TLS_REJECT_UNAUTHORIZED**(TLS 검증): **Verify TLS (default)**, 자체 서명 인증서라면 **Skip TLS verification**
        - **READ_ONLY**: **Read-only**로 바꾸세요. 양식의 기본값은 **Full access (default)**입니다.

        **Connect**를 클릭하세요.

        **성공 상태:** 대화 상자가 닫히고 연결에 **Connected**가 표시됩니다. 이 상태가 토큰이나 RBAC가 작동한다는 것을 증명하지는 않으므로, 아래 확인 프롬프트를 실행하세요.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Akuity Platform">
    <Steps>
      <Step title="시스템 계정 만들기">
        [Akuity Portal](https://akuity.cloud)에서 Argo CD 인스턴스를 열고 **Settings → System Accounts**로 이동해 **apiKey** 기능이 있는 `cloudthinker` 계정을 추가하세요.
      </Step>
      <Step title="토큰 생성하기">
        관리자로 인스턴스에 로그인하고 새 계정의 토큰을 생성하세요:

        ```bash
        argocd login <instance-id>.cd.akuity.cloud --grpc-web --username admin
        argocd account generate-token --account cloudthinker --grpc-web --expires-in 90d
        ```

        토큰을 복사하세요.
      </Step>
      <Step title="계정에 읽기 권한 부여하기">
        Akuity Portal에서 인스턴스의 RBAC 정책에 다음 줄을 추가하세요:

        ```csv
        p, role:cloudthinker, applications, get, */*, allow
        p, role:cloudthinker, logs, get, */*, allow
        g, cloudthinker, role:cloudthinker
        ```
      </Step>
      <Step title="CloudThinker에 연결 추가하기">
        **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **ArgoCD**를 선택하세요. 다음을 입력하세요:

        - **ARGOCD_BASE_URL**: `https://<instance-id>.cd.akuity.cloud`
        - **ARGOCD_API_TOKEN**: 복사한 토큰
        - **NODE_TLS_REJECT_UNAUTHORIZED**(TLS 검증): **Verify TLS (default)**
        - **READ_ONLY**: **Read-only**로 바꾸세요. 양식의 기본값은 **Full access (default)**입니다.

        **Connect**를 클릭하세요.

        **성공 상태:** 대화 상자가 닫히고 연결에 **Connected**가 표시됩니다. 토큰과 RBAC가 작동하는지 확인하려면 아래 확인 프롬프트를 실행하세요.
      </Step>
    </Steps>

## 연결 세부 정보

| 필드 | 설명 | 기본값 |
|-------|-------------|---------|
| **ARGOCD_BASE_URL** | Argo CD 서버 주소, HTTPS | 없음 |
| **ARGOCD_API_TOKEN** | CloudThinker가 사용하는 계정의 토큰 | 없음 |
| **NODE_TLS_REJECT_UNAUTHORIZED** | TLS 검증. **Verify TLS (default)**는 서버 인증서를 확인합니다. **Skip TLS verification**은 자체 서명 인증서를 허용하며, 로컬 또는 개발 서버에서만 사용하세요 | Verify TLS |
| **READ_ONLY** | **Read-only**는 동기화, 생성, 업데이트, 삭제, 리소스 작업 도구를 끕니다. **Full access (default)**는 이를 켜 둡니다 | Full access |

<Warning>
**READ_ONLY**의 기본값은 **Full access (default)**입니다. 에이전트가 동기화와 변경을 제안하길 원하지 않는다면 **Read-only**로 바꾸세요. RBAC는 여전히 계정에 부여되지 않은 모든 것을 차단합니다.
</Warning>

## 필요한 권한

설정의 읽기 줄은 모든 읽기를 다룹니다: `applications, get`은 애플리케이션 상태, 리소스 트리, 관리 리소스, 이벤트를 다루며, `logs, get`은 에이전트가 Pod 로그를 읽게 합니다. 에이전트가 제안하길 원하는 변경마다 줄을 추가하세요:

| 기능 | 정책 줄 |
|------------|-------------|
| 동기화 | `p, role:cloudthinker, applications, sync, */*, allow` |
| 애플리케이션 변경 | `p, role:cloudthinker, applications, create, */*, allow`<br />`p, role:cloudthinker, applications, update, */*, allow`<br />`p, role:cloudthinker, applications, delete, */*, allow` |
| 리소스 작업 | `p, role:cloudthinker, applications, action/*, */*, allow` |

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 | 승인 |
|------------|--------------------|----------|
| **Discovery** | 동기화 상태, 상태, 저장소, 경로, 네임스페이스와 함께 애플리케이션을 나열하고, 비정상이거나 동기화되지 않은 앱의 리소스 트리와 최근 이벤트를 가져옵니다 | 아니요 |
| **애플리케이션 세부 정보** | 앱 하나의 spec, 관리 리소스, 실제 상태와 원하는 상태의 diff를 읽습니다 | 아니요 |
| **이벤트와 로그** | 앱 또는 리소스의 Kubernetes 이벤트와 워크로드의 Pod 로그를 읽습니다 | 아니요 |
| **동기화** | 애플리케이션 하나의 동기화를 트리거합니다 | 예. Read-only에서는 꺼짐 |
| **애플리케이션 변경** | 애플리케이션을 생성, 업데이트, 삭제합니다 | 예. Read-only에서는 꺼짐 |
| **리소스 작업** | 관리 리소스에서 재시작 같은 작업을 실행합니다 | 예. Read-only에서는 꺼짐 |

모든 변경은 [Approvals](/guide/approvals/overview)를 거치며, 거절된 요청은 재시도되지 않습니다. 에이전트가 동기화하게 하려면 **READ_ONLY**를 **Full access (default)**로 설정하고 `applications, sync` 권한을 추가하세요. 둘 중 하나라도 빠지면 에이전트는 읽기만 할 수 있습니다.

### 연결 확인

```text
List my Argo CD applications with their sync status and health, and call out any that are OutOfSync or Degraded
```

**Synced** 또는 **OutOfSync** 같은 동기화 상태와 **Healthy** 또는 **Degraded** 같은 상태가 포함된 애플리케이션 이름 표와, 끝에 개수가 표시되어야 합니다.

### 예시 프롬프트

```text
Why is the checkout app Degraded? Check its resource tree, recent events, and pod logs
Which resources in payments-api differ from Git, and what changed?
Sync the payments-api app and tell me when it's Healthy
```

애플리케이션 이름을 지정하세요. 에이전트는 애플리케이션 목록의 실제 이름을 사용하며 추측하지 않습니다. 동기화 프롬프트에는 **Full access (default)**와 `applications, sync` 권한이 필요합니다.

## 문제 해결

<Accordion title="Connect가 fetch failed로 실패합니다">
CloudThinker가 **ARGOCD_BASE_URL**에 접근할 수 없거나 서버 인증서가 거부되었습니다. 주소가 `localhost`나 클러스터 내부 이름이 아닌 공개 HTTPS인지 확인하세요. 자체 서명 인증서라면 **NODE_TLS_REJECT_UNAUTHORIZED**를 **Skip TLS verification**으로 설정하세요.
</Accordion>

<Accordion title="요청이 401을 반환합니다">
토큰이 없거나, 만료되었거나, 다른 계정용으로 생성되었습니다. `argocd account generate-token --account cloudthinker --expires-in 90d`를 다시 실행하고, 연결을 편집해 새 토큰을 붙여 넣으세요.
</Accordion>

<Accordion title="Permission denied (code 7)">
계정의 RBAC 역할이 해당 작업을 허용하지 않습니다. [필요한 권한](#필요한-권한)의 `policy.csv` 줄을 확인하세요: 로그에는 `logs, get`이, 동기화에는 `applications, sync`가 필요합니다.
</Accordion>

<Accordion title="애플리케이션 목록이 비어 있습니다">
역할이 해당 프로젝트에 대한 접근 권한을 부여하지 않습니다. 정책의 `*/*` 패턴은 모든 프로젝트를 포함합니다. 범위를 좁혔다면 에이전트가 볼 프로젝트를 추가하세요.
</Accordion>

<Accordion title="동기화, 생성, 업데이트, 삭제를 사용할 수 없습니다">
**READ_ONLY**가 **Read-only**로 설정되어 있습니다. 에이전트가 이런 변경을 제안하길 원한다면 연결을 편집해 **Full access (default)**로 바꾸세요.
</Accordion>

<Accordion title="토큰 생성이 실패합니다">
계정에 `apiKey` 기능이 없습니다. `argocd account get --account cloudthinker`로 확인한 다음 첫 번째 설정 단계를 반복하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **전용 계정**: CloudThinker에는 API 키 접근만 있는 자체 `cloudthinker` 계정을 주고, `admin` 토큰은 절대 주지 마세요.
- **프로덕션에서는 TLS 검증을 켜 두세요**: 자체 서명 인증서를 쓰는 로컬 또는 개발 서버에서만 건너뛰세요.

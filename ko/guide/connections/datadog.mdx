Datadog을 연결하면 CloudThinker가 알림 중인 모니터를 분류하고, 로그를 검색하고, 메트릭을 쿼리하고, 트레이스를 따라가고, 인시던트·호스트·대시보드를 읽을 수 있습니다. CloudThinker는 Datadog MCP 서버를 통해 Datadog에 접근하며, API 키와 읽기 권한으로 범위가 지정된 Application 키로 인증합니다.

Datadog에는 별개의 설정이 두 가지 있습니다. Datadog 알림에 대한 자동 근본 원인 분석을 사용하려면 둘 다 필요합니다.

| 설정 | 하는 일 | 필요한 경우 |
|---|---|---|
| 조사(이 연결) | 에이전트가 로그, 메트릭, 트레이스, 모니터를 읽을 수 있게 합니다 | 항상. 이 연결이 없으면 에이전트가 Datadog 내부를 볼 수 없습니다. |
| 알림 수신(webhook) | 모니터가 발생하면 Resolve 인시던트를 엽니다 | 인시던트가 자동으로 열리게 하려는 경우. [Datadog 알림을 Resolve로 보내기](#datadog-알림을-resolve로-보내기)를 참조하세요. |

## 사전 요구 사항

- 다음 사이트 중 하나에 있는 Datadog 조직: **US1**, **US3**, **US5**, **EU1**, **AP1**, **AP2**. 정부 사이트(`ddog-gov.com`)는 Datadog MCP 서버에서 지원되지 않습니다.
- Datadog **Organization Settings**에서 **MCP Access**가 켜져 있어야 합니다. Datadog 관리자가 조직당 한 번 설정합니다.
- API 키와 Application 키를 생성할 수 있는 Datadog 권한.
- CloudThinker 워크스페이스에 연결을 추가할 수 있는 권한.

## 설정

<Steps>
  <Step title="사이트 확인">
    Datadog에 로그인한 상태에서 주소 표시줄을 확인합니다:

    | Datadog URL | CloudThinker에서 선택할 값 |
    |------------------|----------------------|
    | `app.datadoghq.com` | **US1 (datadoghq.com)** |
    | `us3.datadoghq.com` | **US3 (us3.datadoghq.com)** |
    | `us5.datadoghq.com` | **US5 (us5.datadoghq.com)** |
    | `app.datadoghq.eu` | **EU1 (datadoghq.eu)** |
    | `ap1.datadoghq.com` | **AP1 (ap1.datadoghq.com)** |
    | `ap2.datadoghq.com` | **AP2 (ap2.datadoghq.com)** |
  </Step>
  <Step title="API 키 생성">
    Datadog에서 **Organization Settings → API Keys**로 이동하여 **New Key**를 클릭하고, 이름을 `cloudthinker`로 지정한 다음 값을 복사합니다.
  </Step>
  <Step title="범위가 지정된 Application 키 생성">
    **권장:** 키가 특정 사람의 권한에 묶이지 않도록 **Datadog Read Only Role**이 있는 Datadog 서비스 계정에서 키를 생성합니다. **Organization Settings → Service Accounts**로 이동하여 해당 역할로 `cloudthinker`를 생성하고, 그 계정에 Application 키를 추가합니다.

    그렇지 않으면 **Organization Settings → Application Keys**로 이동하여 **New Key**를 클릭합니다.

    어느 방법이든 키 이름을 `cloudthinker`로 지정하고 [필요 권한](#필요-권한)의 범위를 선택합니다. 저장한 후 바로 키를 복사합니다.

    <Warning>
    범위가 없는 Application 키는 쓰기를 포함한 소유자의 모든 권한을 상속합니다. 항상 범위를 선택하세요.
    </Warning>

    **성공 상태:** 키의 범위 목록에 `_write` 항목 없이 읽기 권한만 표시됩니다.
  </Step>
  <Step title="연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **Datadog**을 선택합니다. 다음을 입력합니다:
    - **Alias**(선택 사항): `datadog-prod` 같은 짧은 이름. 소문자, 숫자, 하이픈을 사용합니다.
    - **Description**(선택 사항): 어떤 조직 또는 환경인지. 에이전트는 이를 읽고 올바른 인스턴스를 선택합니다.
    - **DD_API_KEY**: API 키.
    - **DD_APPLICATION_KEY**: Application 키.
    - **DD_SITE**: 1단계에서 확인한 사이트.

    **Connect**를 클릭합니다. CloudThinker가 **Connecting**과 **Verifying**을 표시한 다음 **Connected** 상태를 표시합니다. **Verifying**은 해당 사이트의 Datadog MCP 서버와 세션을 열고 도구 목록을 가져옵니다. 데이터 쿼리는 실행하지 않으므로, 누락된 범위는 나중에 해당 유형의 질문에서 403으로 드러납니다. 검증에 실패하면 **Failed**가 표시되고 오류 메시지가 나타납니다. 메시지를 [문제 해결](#문제-해결)과 대조합니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **DD_API_KEY** | 조직의 Datadog API 키 | |
| **DD_APPLICATION_KEY** | 범위가 지정된 Datadog Application 키. 이 키의 범위가 CloudThinker가 읽을 수 있는 내용을 결정합니다 | |
| **DD_SITE** | 조직의 Datadog 사이트. 기본값은 **US1**입니다 | `EU1 (datadoghq.eu)` |

두 키가 모두 필요합니다. CloudThinker는 호출할 때마다 두 키를 해당 사이트의 Datadog MCP 서버로 보냅니다.

## 필요 권한

Datadog MCP 서버는 호출할 때마다 Datadog 자체 권한을 확인합니다. CloudThinker가 볼 데이터에 해당하는 행을 선택합니다.

| Scope ID | Datadog에서의 이름 | 가능해지는 작업 |
|----------|--------------------------|-----------------|
| `mcp_read` | `mcp_read` | Datadog MCP 서버의 모든 사용. 필수 |
| `monitors_read` | Monitors Read | 모니터 검색 및 알림 분류 |
| `logs_read_data`, `logs_read_index_data` | Logs Read Data, Logs Read Index Data | 로그 검색 |
| `timeseries_query` | Timeseries | 로그 분석, 호스트 메트릭, 이벤트 |
| `metrics_read` | Metrics | 메트릭 검색 및 쿼리 |
| `hosts_read` | Hosts Read | 호스트 인벤토리 |
| `incident_read` | Incidents Read | Datadog 인시던트 |
| `dashboards_read`, `user_access_read` | Dashboards Read, User Access Read | 대시보드 검색 |
| `apm_read` | APM Read | 스팬 및 트레이스 |
| `events_read` | Events | 이벤트 검색 |
| `notebooks_read` | Notebooks Read | 노트북 검색 |

<Tip>
`mcp_write`와 모든 `_write` 범위는 제외하세요. CloudThinker의 Datadog 조사는 읽기만 합니다.
</Tip>

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 |
|------------|------------------------|
| **Discovery** | 상태별(OK, Alert, Warn, No Data) 모니터, 호스트, 활성 인시던트, 대시보드, 서비스를 요약합니다 |
| **Monitors** | 상태, 이름, 태그로 모니터를 찾고 무엇이 알림 중인지 설명합니다 |
| **Logs** | `service:web status:error` 같은 Datadog 쿼리 구문으로 최근 15분부터 로그를 검색하고 그룹화합니다 |
| **Metrics** | 메트릭을 찾고 `avg:system.cpu.user{host:web-1}` 같은 집계로 쿼리합니다 |
| **Traces** | 서비스와 지속 시간으로 스팬을 검색한 다음 전체 트레이스를 엽니다 |
| **Incidents** | Datadog 인시던트를 나열하고 세부 정보를 읽습니다 |
| **Infrastructure** | 앱, 음소거 상태, 주요 시스템 메트릭과 함께 호스트를 나열합니다 |
| **Services** | 카탈로그 서비스를 나열하고 종속성을 매핑합니다 |
| **Dashboards, events, notebooks** | 맥락을 얻기 위해 검색하고 읽습니다 |

연결이 처음 **Connected**에 도달하면 CloudThinker가 [deep look](/ko/guide/connections/overview#연결한-다음에-일어나는-일) 채팅을 열고, 에이전트가 계정을 살펴봅니다.

### 연결 검증

```text
Run Datadog discovery and list monitors by state, the number of hosts, and any active incidents
```

정상적인 답변은 OK, Alert, Warn, No Data 상태의 모니터 수를 세고 알림 중인 모니터의 이름을 제시합니다.

### 예시 프롬프트

```text
Which Datadog monitors are alerting right now, and what do the error logs for those services show in the last 15 minutes?
Find the slowest checkout spans in the last hour and walk me through one trace
Which hosts have the highest CPU right now, and do any have muted monitors?
```

## Datadog 알림을 Resolve로 보내기

Resolve는 Datadog 프리셋을 제공하므로 **Resolve → Triggers & Outcomes**가 필드 및 심각도 매핑을 미리 채워 줍니다. 대화상자 전체 설명은 [Webhook Signals](/ko/guide/incident/webhook-integrations/overview)에 있으며, 아래 단계는 Datadog에 특화된 내용입니다. 프리셋이 없는 도구는 [Connect alert sources](/guide/incident/connect-alert-sources)를 참조하세요.

<Steps>
  <Step title="CloudThinker에서 webhook 생성">
    **Resolve → Triggers & Outcomes**로 이동하여 **Datadog**을 선택하고, **Signals to Resolve** 아래에서 **Add signal**을 클릭합니다. **Basic Info**, **Configure**, **Advanced**를 차례로 진행한 다음 **Create**를 클릭합니다. **Webhook URL**과 **Secret Key**를 복사합니다. 키는 한 번만 표시됩니다.
  </Step>
  <Step title="매핑이 서비스를 가리키도록 설정">
    프리셋은 `title`, `body`, `alert_type`을 읽지만 **Service Path** 기본값이 `tags`이며, 이는 목록을 가리키므로 아무것에도 매핑되지 않습니다. **Field Mapping** 아래에서 **Service Path**를 `service`로 변경한 다음, 아래 페이로드에서 해당 키를 보냅니다. [Map the fields](/ko/guide/incident/webhook-integrations/overview#필드-매핑)를 참조하세요.
  </Step>
  <Step title="모니터가 보내는 심각도 행 추가">
    프리셋의 **Severity Mapping**은 `alert`, `warn`, `ok`, `no data`를 다루지만, Datadog의 `$ALERT_TYPE`은 `error`, `warning`, `info`, `success`를 보냅니다. **Severity Mapping** 아래에서 **Customize**를 클릭한 다음, 모니터가 보내는 각 값에 대해 **Add Mapping**을 클릭합니다. 매핑되지 않은 값은 **medium**이 됩니다.
  </Step>
  <Step title="Datadog에 webhook 추가">
    Datadog에서 **Integrations → Webhooks**를 열고 `CloudThinker`라는 이름의 webhook을 추가합니다. **Webhook URL**을 **URL**에 붙여넣고, **Custom Headers** 상자에 `{"Authorization": "Bearer <your-secret-key>"}`를 입력합니다. 다음과 같은 페이로드를 사용합니다:

    ```json
    {
      "title": "$EVENT_TITLE",
      "body": "$EVENT_MSG",
      "alert_type": "$ALERT_TYPE",
      "service": "web-api"
    }
    ```

    고정된 `service` 값은 이 webhook에 알림을 보내는 모든 모니터에 적용됩니다. 시크릿은 Datadog의 webhook 구성에 저장되므로, 해당 통합을 관리할 수 있는 사람은 누구나 시크릿을 읽을 수 있습니다. 해당 접근을 제한하고, 유출되면 Resolve의 webhook 행에서 **Regenerate credentials**를 사용합니다.
  </Step>
  <Step title="모니터에서 webhook으로 알림 보내기">
    인시던트를 열어야 하는 각 모니터의 메시지에 `@webhook-CloudThinker`를 추가합니다. 복구 알림은 빼고 알림만 보내려면 멘션을 Datadog의 알림 조건으로 감쌉니다:

    ```text
    {{#is_alert}}@webhook-CloudThinker{{/is_alert}}
    ```
  </Step>
  <Step title="테스트 이벤트 하나 보내기">
    모니터에서 **Test Notifications**를 클릭하거나, webhook 대화상자의 **Integration Examples** 아래 **cURL** 탭을 사용합니다.
  </Step>
</Steps>

**성공 상태:** 해당 모니터의 다음 알림이 모니터 제목과 함께 [Resolve → Signals](/ko/guide/pulse/overview)에 표시되고, 에이전트가 이 연결을 통해 조사합니다.

## 문제 해결

<Accordion title="Verifying 단계 또는 모든 호출에서 401 또는 403">
- **DD_SITE**가 조직과 일치하지 않습니다. Datadog 키는 자체 사이트에서만 작동하므로 1단계 표를 사용해 Datadog URL과 비교한 다음 연결을 편집합니다.
- 키 중 하나가 잘못되었거나, 취소되었거나, 다른 Datadog 조직의 키입니다. 같은 조직에서 새 키를 만들고 연결의 세부 정보 패널에서 연결을 업데이트합니다.
- 조직에서 **MCP Access**가 꺼져 있거나 Application 키에 `mcp_read`가 없습니다.
</Accordion>

<Accordion title="일부 질문에서만 403 Forbidden">
Application 키에 해당 데이터의 범위가 없습니다(예: 트레이스의 경우 `apm_read`). **Organization Settings → Application Keys**에서 범위를 추가합니다.
</Accordion>

<Accordion title="메트릭 또는 서비스를 찾을 수 없음">
CloudThinker는 쿼리하기 전에 메트릭 및 서비스 이름을 검색합니다. 이름과 일치하는 메트릭을 나열해 달라고 요청한 다음, 반환된 정확한 이름을 사용합니다.
</Accordion>

<Accordion title="429 Too Many Requests">
Datadog이 키에 속도 제한을 적용하고 있습니다. 더 짧은 시간 범위로 좁은 질문을 하거나 1분 후에 다시 시도합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **Application 키 범위 지정**: 범위가 없는 키는 쓰기를 포함한 생성자의 전체 권한을 가집니다.
- **전용 키**: 다른 통합에 영향을 주지 않고 취소할 수 있도록 CloudThinker 전용 키를 만듭니다.

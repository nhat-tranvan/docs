Datadog 계정을 연결하여 CloudThinker 에이전트가 전체 스택에서 로그를 검색하고, 메트릭을 쿼리하며, 인프라를 모니터링하고, 인시던트를 조사할 수 있도록 합니다. Datadog은 **API 키**와 **범위 지정된 Application 키** 쌍으로 인증합니다.

---

## 지원 사이트

| 사이트 | URL |
|--------|-----|
| **US1** | `app.datadoghq.com` |
| **US3** | `us3.datadoghq.com` |
| **US5** | `us5.datadoghq.com` |
| **EU1** | `app.datadoghq.eu` |
| **AP1** | `ap1.datadoghq.com` |
| **AP2** | `ap2.datadoghq.com` |

<Warning>
GovCloud (US1-FED)는 Datadog MCP 서버에서 지원되지 않습니다.
</Warning>

---

## 사전 요구 사항

**Datadog API 키**와 **범위 지정된 Application 키**가 필요합니다.

**API 키 생성:**

1. Datadog 계정에서 **Organization Settings → API Keys**로 이동합니다.
2. **+ New Key**를 클릭하고 이름(예: `CloudThinker`)을 지정한 후 저장합니다.
3. 키 값을 복사합니다.

**범위 지정된 Application 키 생성:**

1. **Organization Settings → Application Keys**로 이동합니다.
2. **+ New Key**를 클릭하고 이름(예: `CloudThinker`)을 지정합니다.
3. **Scopes**에서 [필요 권한](#필요-권한)에 나열된 권한을 선택합니다.
4. 저장하고 키 값을 복사합니다.

<Tip>
항상 범위가 없는 키 대신 범위 지정된 Application 키를 사용하세요. 범위가 없는 키는 생성한 사용자의 모든 권한을 상속합니다.
</Tip>

## 설정

<Steps>
  <Step title="CloudThinker 열기">
    CloudThinker 워크스페이스에서 **Connections → Datadog**으로 이동합니다.
  </Step>
  <Step title="Datadog 사이트 선택">
    계정에 맞는 Datadog 사이트를 선택합니다 (예: `datadoghq.com`은 US1, `datadoghq.eu`는 EU1).
  </Step>
  <Step title="API 키 입력">
    Datadog **API 키**를 붙여 넣습니다.
  </Step>
  <Step title="Application 키 입력">
    Datadog **Application 키**를 붙여 넣습니다.
  </Step>
  <Step title="연결">
    **Connect**를 클릭합니다. CloudThinker가 자격 증명을 확인하고 **Connected** 상태를 표시합니다.
  </Step>
</Steps>

## 필요 권한

Application 키 생성 시 이 범위를 선택합니다. 읽기 범위는 모든 조사 도구를 지원합니다. `notebooks_write`는 선택 사항으로 노트북 생성을 활성화합니다.

| 범위 | 활성화 기능 |
|------|------------|
| `logs_read_data`, `logs_read_index_data` | 로그 검색 및 분석 |
| `metrics_read`, `timeseries_query` | 메트릭 및 시계열 데이터 쿼리 |
| `monitors_read` | 상태 및 태그로 모니터 검색 |
| `incidents_read` | 인시던트 검색 및 세부 정보 조회 |
| `dashboards_read` | 대시보드 구성 검사 |
| `hosts_read` | 인프라 호스트 목록 조회 및 검사 |
| `apm_read` | 트레이스 조회 및 APM 스팬 검색 |
| `apm_service_catalog_read` | 서비스 목록 조회 및 의존성 매핑 |
| `events_read` | 플랫폼 및 커스텀 이벤트 검색 |
| `notebooks_read` | 조사 노트북 검색 및 조회 |
| `rum_apps_read` | Real User Monitoring 데이터 검색 |
| `notebooks_write` | 조사 노트북 생성 및 편집 (선택) |

<Tip>
읽기 범위만으로 시작하세요. 에이전트가 조사 노트북을 생성해야 하는 워크플로에서만 `notebooks_write`를 추가하세요.
</Tip>

## 에이전트 기능

연결 후 에이전트는 Datadog 환경 전반에서 읽기 및 쓰기 작업을 수행할 수 있습니다.

| 기능 | 에이전트가 할 수 있는 것 |
|------|------------------------|
| **로그** | 서비스 및 환경 전반의 로그 검색, 패턴 및 트렌드 분석 |
| **메트릭** | 사용 가능한 메트릭 검색, 시계열 데이터 쿼리, 메트릭 메타데이터 조회 |
| **모니터** | 상태, 이름, 또는 태그로 모니터 검색 |
| **인시던트** | 활성 및 해결된 인시던트 검색, 전체 인시던트 세부 정보 조회 |
| **대시보드** | 대시보드 구성 검색 및 검사 |
| **인프라** | 인프라 전반의 호스트 목록 조회 및 검사 |
| **APM** | 분산 트레이스 조회, 지연 분석을 위한 스팬 검색 |
| **서비스 카탈로그** | 서비스 목록 조회 및 서비스 의존성 관계 매핑 |
| **이벤트** | 플랫폼 및 커스텀 이벤트 검색 |
| **노트북** | 조사 노트북 검색, 조회, 생성, 편집 |
| **RUM** | Real User Monitoring 데이터 검색 |
| **연결 상태** | Datadog 연결이 정상 작동하는지 확인 |

<Warning>
노트북 쓰기 작업은 실행 전 사용자 승인이 필요합니다.
</Warning>

### 연결 확인

```text
@alex run the Datadog connection health check and summarize active monitors and host count
```

### 예시 프롬프트

```text
@alex search for error logs in the production environment from the last 15 minutes
@alex check for active Datadog incidents and investigate root causes
@alex analyze APM traces for the checkout service and identify latency bottlenecks
```

## 문제 해결

<Accordion title="연결 테스트 403 실패">
API 키가 유효하고 취소되지 않았는지 확인합니다. Application 키에 필요한 범위가 있는지, 두 키가 동일한 Datadog 조직에 속하는지 확인합니다.
</Accordion>

<Accordion title="연결 후 데이터가 없음">
Application 키 범위에 쿼리하는 데이터 유형이 포함되어 있는지 확인합니다 (예: 로그의 경우 `logs_read_data`). Datadog 보존 설정을 확인하고 서비스 또는 호스트가 데이터를 활발히 전송하고 있는지 확인합니다.
</Accordion>

<Accordion title="잘못된 Datadog 사이트 선택">
쿼리가 빈 결과를 반환하는 경우, 잘못된 사이트를 선택했을 수 있습니다. Datadog URL을 확인하세요 — `app.datadoghq.com`은 US1, `us3.datadoghq.com`은 US3, `app.datadoghq.eu`는 EU1입니다. 연결을 해제하고 올바른 사이트로 다시 연결합니다.
</Accordion>

<Accordion title="API 키와 Application 키 혼동">
두 키 모두 필요하며 서로 다른 역할을 합니다. **API 키**는 요청을 인증합니다. **Application 키**는 에이전트가 접근할 수 있는 Datadog 기능과 데이터를 제어합니다. 하나만으로는 충분하지 않습니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **범위 지정된 Application 키** — 항상 명시적 범위를 지정하세요. 범위가 없는 키는 생성한 사용자의 전체 권한을 상속합니다.
- **통합별 별도 키** — CloudThinker 전용 API 및 Application 키를 생성하여 독립적으로 취소할 수 있도록 합니다.

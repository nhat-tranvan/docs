Netlify 계정을 연결하여 CloudThinker 에이전트가 팀과 프로젝트를 조회하고, 배포 상태를 확인하고, 폼 제출을 읽고, 확장을 검사하고, 배포 시작이나 프로젝트 설정 변경 같은 승인 게이트 작업을 실행할 수 있도록 합니다.

Netlify는 **개인 액세스 토큰**으로 인증합니다. 토큰은 이를 생성한 Netlify 사용자와 동일한 접근 권한을 가지므로, 해당 사용자의 팀이 에이전트가 접근할 수 있는 범위를 결정합니다. OAuth 플로우가 필요하지 않습니다.

---

## 사전 요구 사항

- 조사하려는 팀과 프로젝트에 접근할 수 있는 **Netlify 계정**.
- 해당 계정에서 생성한 **개인 액세스 토큰**.
- Netlify 사용자 설정에서 토큰을 생성할 권한.

<Info>
CloudThinker가 필요한 팀에만 속한 계정으로 토큰을 생성하세요. 읽기 작업은 Netlify 리소스를 변경하지 않으며, 모든 쓰기 작업에는 승인 게이트가 적용됩니다.
</Info>

---

## 설정

<Steps>
  <Step title="개인 액세스 토큰 생성">
    Netlify에서 **사용자 설정**을 열고 **OAuth applications → Personal access tokens**로 이동하여 새 토큰을 생성하세요:
    - **Description**: `cloudthinker`
    - **Expiration**: 유효 기간을 선택하고 교체 계획을 세우세요

    토큰을 즉시 복사하세요 — Netlify는 한 번만 표시합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Connections → Netlify**로 이동하여 다음을 입력하세요:
    - **Personal access token**: 방금 생성한 토큰

    **Connect**를 클릭하세요. CloudThinker가 Netlify로 토큰을 검증하고 사이트 수와 함께 **Connected** 상태를 표시합니다.
  </Step>
</Steps>

<Warning>
개인 액세스 토큰을 생성 직후 복사하세요. 분실 시 새 토큰을 생성해야 합니다.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **NETLIFY_PERSONAL_ACCESS_TOKEN** | CloudThinker가 검사할 프로젝트를 보유한 팀용 Netlify 개인 액세스 토큰 | — |

## 필요 권한

Netlify 개인 액세스 토큰은 이를 생성한 사용자의 권한을 상속하며, 생성 시점에 범위를 선택할 수 없습니다. CloudThinker가 접근해야 할 팀에만 속한 계정으로 토큰을 생성하고, 해당 계정에는 프로젝트·배포·폼·확장을 읽을 수 있는 최소한의 팀 역할만 부여하세요.

<Tip>
최소 권한을 따르세요: 소유자 계정 대신 전용 Netlify 사용자를 사용하고, 만료 기간을 설정하고, 다른 자격 증명과 동일한 주기로 토큰을 교체하세요.
</Tip>

## 에이전트 기능

연결되면 에이전트가 Netlify 팀, 프로젝트, 배포에 대한 읽기 접근 권한을 갖습니다.

| 기능 | 설명 |
|------------|-------------|
| **계정 & 팀** | 인증된 사용자 읽기, 팀 목록 조회, 개별 팀 검사 |
| **프로젝트** | 프로젝트 목록 조회 및 프로젝트 구성, URL, 현재 배포 검사 |
| **배포** | 배포 또는 프로젝트의 현재 배포 검사, 실패했거나 오래된 배포 식별 |
| **폼** | 프로젝트에 구성된 폼과 제출 건수 목록 조회 |
| **확장** | 확장 목록 조회 및 전체 확장 세부 정보 읽기 |
| **변경 작업** | 배포 시작, 프로젝트 생성, 프로젝트 설정 변경, 폼 제출 및 환경 변수 관리, 확장 상태 변경 — **승인 필요** |

<Info>
읽기가 아닌 모든 Netlify 작업에는 승인 게이트가 적용됩니다. CloudThinker는 실행 전에 영향과 정확한 입력값을 제시하고 확인을 기다립니다.
</Info>

### 연결 검증

```text
@alex check the Netlify connection and list my teams and projects
```

### 예시 프롬프트

```text
@alex list my Netlify projects with their current deploy state and #report as a table
@alex which Netlify projects have a failed or stale production deploy — #recommend what to fix first
@alex audit Netlify Forms across my projects and #report which ones collect submissions
```

## 문제 해결

<Accordion title="Netlify 개인 액세스 토큰이 유효하지 않거나 만료됨">
CloudThinker는 연결을 저장하기 전에 Netlify API로 토큰을 검증하는데, Netlify가 401 또는 403을 반환했습니다. Netlify 사용자 설정에서 토큰을 재발급하고 다시 연결하세요.
</Accordion>

<Accordion title="에이전트 실행 중 Failed to get Netlify token 표시">
연결이 사용 가능한 토큰을 보유하고 있지 않습니다. 연결이 여전히 **Connected** 상태인지 확인한 다음 개인 액세스 토큰을 재발급하고 다시 연결하세요.
</Accordion>

<Accordion title="에이전트가 프로젝트나 배포에 대해 404를 보고함">
토큰의 사용자가 해당 프로젝트를 볼 수 없습니다. 토큰을 생성한 계정이 해당 프로젝트를 소유한 팀에 속해 있는지 확인한 다음, 접근 권한이 있는 계정으로 토큰을 재발급하고 다시 연결하세요.
</Accordion>

<Accordion title="Netlify API 속도 제한 도달">
Netlify가 429를 반환했습니다. 나중에 다시 시도하고, 실행당 호출 수가 줄어들도록 단일 팀이나 프로젝트로 요청 범위를 제한하세요.
</Accordion>

<Accordion title="변경을 요청했지만 실행되지 않음">
쓰기 작업은 같은 턴에서의 명시적 승인이 필요합니다. 메시지가 나타나면 작업을 승인하세요. 거부된 호출은 최종적이며 에이전트는 재시도하지 않습니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **토큰 만료 설정** — 토큰을 생성할 때 만료 기간을 선택하고 교체 계획을 세우세요. Netlify 토큰은 자동 순환되지 않습니다.
- **쓰기 작업 승인** — 배포, 프로젝트 설정, 환경 변수, 확장 변경은 안전 장치를 제거하지 말고 승인 게이트를 유지하세요.

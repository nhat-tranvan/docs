ServiceNow 인스턴스를 연결하면 CloudThinker 에이전트가 열린 인시던트, 변경 요청, 문제, CMDB 구성 항목을 검토하고, [Approvals](/guide/approvals/overview)를 거쳐 업데이트할 수 있습니다. 연결은 ServiceNow 사용자의 **사용자명과 비밀번호**로 로그인하며, 전용 서비스 계정을 사용하는 것이 좋습니다.

## 사전 요구사항

- ServiceNow 인스턴스와 `https://<instance>.service-now.com` 형식의 URL.
- 해당 인스턴스에서 사용자를 만들고 역할을 할당할 권한, 또는 이를 대신해 줄 관리자.
- 로컬 ServiceNow 비밀번호로 로그인할 수 있는 서비스 계정. 인스턴스가 사용자를 SSO로 보내거나 MFA를 요구하더라도, 이 계정은 API 호출을 위해 자체 비밀번호로 인증할 수 있어야 합니다.
- 연결을 추가하는 데 필요한 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참고하세요.

## 설정

<Steps>
  <Step title="서비스 계정 만들기">
    ServiceNow에서 **User Administration → Users**를 열고 **New**를 클릭합니다.

    - **User ID**: `cloudthinker`
    - **Password**: 강력하고 고유한 비밀번호
    - **Active**: 체크

    인스턴스에 **Web service access only**가 표시되면 켜세요. 그러면 계정이 API는 호출할 수 있지만 ServiceNow UI에는 로그인할 수 없습니다.
  </Step>
  <Step title="역할 할당">
    사용자 레코드에 [필요 권한](#필요-권한)의 역할을 추가합니다. `itil`과 `cmdb_read`부터 시작하세요.
  </Step>
  <Step title="CloudThinker에서 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **ServiceNow**를 선택합니다. 양식에는 아래와 똑같은 필드 이름이 표시됩니다. 다음을 입력합니다.

    - **SERVICENOW_INSTANCE_URL**: `https://acme.service-now.com` 같은 인스턴스 URL
    - **SERVICENOW_USERNAME**: `cloudthinker`
    - **SERVICENOW_PASSWORD**: 설정한 비밀번호

    **Connect**를 클릭합니다.

    **성공 상태:** Connect가 연결 테스트를 실행하고, ServiceNow에 **Connected** 상태가 표시됩니다. 테스트가 실패하면 연결에 이유와 함께 오류가 표시됩니다. 아래 확인 프롬프트를 실행해 계정 자체가 레코드를 읽을 수 있는지 확인하세요.
  </Step>
</Steps>

<Tip>
개인 개발자 인스턴스에서 테스트하나요? 빠른 체험에는 해당 인스턴스의 admin 계정으로도 충분합니다. 프로덕션 인스턴스를 연결하기 전에는 전용 계정으로 바꾸세요.
</Tip>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **SERVICENOW_INSTANCE_URL** | 인스턴스 주소, 뒤에 경로 없음 | `https://acme.service-now.com` |
| **SERVICENOW_USERNAME** | 서비스 계정의 User ID | `cloudthinker` |
| **SERVICENOW_PASSWORD** | 해당 사용자의 비밀번호 | `<password>` |

서브 프로덕션 인스턴스 같은 다른 인스턴스에 접근하려면 별도의 연결로 추가하세요.

## 필요 권한

ServiceNow는 역할과 테이블 접근 규칙(ACL)으로 계정이 볼 수 있는 것을 결정합니다. 에이전트는 계정이 읽고 변경할 수 있는 것만 읽고 변경할 수 있습니다.

| 역할 | 에이전트에게 부여되는 권한 |
|------|--------------|
| `itil` | 인시던트, 변경 요청, 문제 읽기 및 업데이트 |
| `cmdb_read` | CMDB 구성 항목과 그 관계 읽기 |

<Tip>
읽기 전용으로 사용하려면 `itil` 대신 `incident`, `change_request`, `problem`, `sys_user`, `sys_user_group`, `cmdb_ci` 테이블에 대한 읽기 권한이 있는 커스텀 역할을 ServiceNow 관리자에게 요청하세요. 에이전트는 여전히 조사할 수 있으며, 모든 쓰기는 ServiceNow에서 실패합니다. 에이전트가 쿼리하거나 스키마를 읽게 할 다른 테이블에도 읽기 권한을 추가하세요. 그렇지 않으면 해당 읽기도 실패합니다.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 | 승인 |
|------------|--------------------|----------|
| **인시던트** | 상태, 우선순위, 쿼리로 인시던트를 나열하고 읽기 | 아니요 |
| **변경과 문제** | 변경 요청과 활성 문제 나열 | 아니요 |
| **CMDB** | 구성 항목을 나열하고 의존 관계 따라가기 | 아니요 |
| **사용자와 그룹** | 사용자, 그룹, 할당 조회 | 아니요 |
| **Any table** | 테이블을 쿼리하거나, 스키마를 읽거나, 자연어로 여러 테이블 검색 | 아니요 |
| **인시던트 업데이트** | 인시던트 생성, 할당, 해결, 종료, 코멘트 또는 작업 노트 추가 | Approvals 거침 |
| **변경과 문제 업데이트** | 변경 요청 할당 또는 승인, 문제에 코멘트, 문제 종료 | Approvals 거침 |
| **레코드 업데이트** | 계정이 쓸 수 있는 모든 테이블에서 레코드 생성 또는 업데이트 | Approvals 거침 |

읽기는 묻지 않고 실행됩니다.

<ApprovalDefault />

<Warning>
**Any table** 읽기는 먼저 묻지 않으므로, 에이전트는 HR이나 사용자 레코드를 포함해 계정이 읽을 수 있는 모든 테이블을 읽을 수 있습니다. 민감한 테이블은 계정의 역할과 ACL에서 제외하세요.
</Warning>

변경 요청을 승인하려면 계정이 ServiceNow에서 해당 변경의 승인자여야 합니다. `itil` 역할만으로는 승인자가 되지 않습니다.

### Resolve와 함께 사용

ServiceNow는 [Resolve](/guide/incident/triggers-and-outcomes#outcomes)와 연동됩니다. **Resolve → Triggers & Outcomes → ServiceNow**에서 **Create follow-up tickets** outcome은 인시던트가 마무리될 때 남은 작업을 위한 ServiceNow 레코드를 생성합니다. **Assignment group**을 설정하세요(예: `Cloud Operations`). ServiceNow는 [webhook signal](/ko/guide/incident/webhook-integrations/overview)로 인시던트를 Resolve에 보낼 수도 있습니다.

### 연결 확인

```text
List open P1 and P2 incidents in ServiceNow with their number, assignment group, and state
```

인시던트의 짧은 표나 "열린 인시던트 없음"이라는 명확한 답이 나와야 합니다. 권한 오류는 계정에 `itil` 또는 테이블 읽기 권한이 없다는 뜻입니다.

### 예시 프롬프트

```text
Which ServiceNow change requests scheduled this week touch production, and which are still waiting for approval?
Find ServiceNow problems with more than three linked incidents in the last 30 days
Map what depends on the CMDB item payments-db-01 before we patch it
```

서비스, CI, 기간을 지정하세요. ServiceNow 테이블에는 수백만 행이 있을 수 있으므로, 범위가 좁은 요청일수록 빨리 돌아옵니다.

## 문제 해결

<Accordion title="Connect가 실패하거나 요청이 401을 반환함">
사용자명이나 비밀번호가 틀렸거나, 사용자가 비활성 상태이거나, 계정이 잠겼습니다. 관리자로 ServiceNow에 로그인해 사용자 레코드를 확인하고, 필요하면 비밀번호를 재설정한 뒤 연결을 편집하세요.

비밀번호가 맞다면 SSO나 MFA가 이 계정의 비밀번호 로그인을 막고 있는지 확인하세요. 계정에는 API 호출에 동작하는 로컬 비밀번호가 필요합니다.
</Accordion>

<Accordion title="일부 테이블이 권한 오류를 반환함">
계정에 해당 테이블의 역할이나 ACL이 없습니다. CMDB 읽기에는 `cmdb_read`가 필요합니다. 인시던트, 변경, 문제 읽기에는 `itil` 또는 동등한 커스텀 역할이 필요합니다. ServiceNow에서 역할을 추가하고 다시 요청하세요. 다시 연결할 필요는 없습니다.
</Accordion>

<Accordion title="요청이 시간 초과되거나 503을 반환함">
인스턴스가 유지보수 중이거나 절전 상태입니다. 개인 개발자 인스턴스는 유휴 상태에서 최대 절전 모드로 들어갑니다. ServiceNow 개발자 포털에서 인스턴스를 깨운 뒤 다시 시도하세요. 또한 인스턴스가 IP 접근 규칙으로 CloudThinker를 차단하지 않는지 확인하세요. CloudThinker를 허용하려면 해당 규칙에 CloudThinker의 egress IP를 추가하세요. 이 문서에는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [contact us](https://cloudthinker.io/contact)로 연락하세요.
</Accordion>

<Accordion title="번호로 레코드를 찾을 수 없음">
에이전트는 `INC0012345` 같은 번호가 아니라 `sys_id`로 레코드를 조회합니다. 조회가 실패하면 대신 번호로 검색하도록 요청하세요.

```text
Search ServiceNow incidents for number INC0012345 and show its state and assignment group
```

인스턴스 URL이 틀려도 "not found"로 나타나므로, 브라우저 주소와 일치하는지 확인하세요.
</Accordion>

<Accordion title="요청이 429를 반환함">
인스턴스가 API 호출 속도를 제한하고 있습니다. 1분 기다린 뒤 범위를 좁혀 다시 요청하세요. ServiceNow 관리자가 인스턴스의 속도 제한 규칙을 검토할 수 있습니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **전용 서비스 계정**: CloudThinker 전용으로 만든 계정에 **Web service access only**를 켜서 사용하세요. 그러면 사람에게 영향을 주지 않고 교체하거나 비활성화할 수 있습니다.
- **admin 대신 역할**: 프로덕션 인스턴스를 `admin` 역할로 연결하지 마세요. `itil`과 `cmdb_read`로 인시던트, 변경, 문제, CMDB 작업을 처리할 수 있습니다. 변경을 승인하려면 계정이 승인자로 설정되어야 하며, **Any table** 읽기에는 각 테이블의 읽기 권한이 필요합니다.

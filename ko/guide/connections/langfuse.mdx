Langfuse 프로젝트를 연결하면 [CloudThinker](/ko/guide/agents/overview)가 LLM 호출이 실패한 이유, 트레이스의 비용, 프롬프트 버전의 점수를 알려 줄 수 있습니다. 이 연결은 프로젝트 범위의 API 키 쌍(공개 키와 비밀 키)을 사용하며 Langfuse Cloud와 자체 호스팅 Langfuse 모두에서 작동합니다.

## 사전 요구 사항

- 애플리케이션에서 트레이스를 받고 있는 Langfuse Cloud 또는 자체 호스팅 프로젝트.
- 해당 프로젝트에서 API 키를 만들 수 있는 권한.
- Langfuse 호스트: 로그인하는 기본 URL(예: `https://cloud.langfuse.com`(EU) 또는 `https://us.cloud.langfuse.com`(US)) 또는 자체 호스팅 도메인.
- 자체 호스팅 Langfuse의 경우: 인스턴스가 HTTPS로 `/api/public/mcp`를 제공하고 인터넷에서 오는 연결을 받아야 합니다. 방화벽 뒤에 있다면 CloudThinker의 egress IP를 허용합니다. 이 문서는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의](https://cloudthinker.io/contact)하세요. 다른 옵션은 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요. CloudThinker는 일반 `http://` 호스트를 거부합니다.
- 연결을 추가하고 편집할 수 있는 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참조하세요.

## 설정

<Steps>
  <Step title="Langfuse에서 API 키 쌍 생성">
    Langfuse에 로그인하고 CloudThinker가 읽을 프로젝트를 연 다음 **Project → Settings → API Keys**로 이동합니다. **Create new API keys**를 클릭합니다.

    Langfuse가 **Public Key**(`pk-lf-`로 시작)와 **Secret Key**(`sk-lf-`로 시작)를 표시합니다. 지금 둘 다 복사합니다. Langfuse는 비밀 키를 한 번만 표시합니다.
  </Step>
  <Step title="CloudThinker에서 Langfuse 연결 열기">
    CloudThinker에서 **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **Langfuse**를 선택합니다.
  </Step>
  <Step title="호스트와 키 입력">
    | 필드 | 입력할 내용 | 예시 |
    |-------|---------------|---------|
    | **LANGFUSE_HOST** | 프로젝트가 있는 Langfuse 인스턴스의 경로 없는 기본 URL. `https://`가 없는 호스트에는 자동으로 추가됩니다. | `https://cloud.langfuse.com` |
    | **LANGFUSE_PUBLIC_KEY** | 프로젝트의 공개 키 | `pk-lf-...` |
    | **LANGFUSE_SECRET_KEY** | 프로젝트의 비밀 키 | `sk-lf-...` |

    키 쌍은 이를 발급한 호스트와 프로젝트에서만 작동합니다. 두 번째 프로젝트를 읽으려면 해당 프로젝트의 키로 두 번째 Langfuse 연결을 추가합니다.
  </Step>
  <Step title="연결">
    **Connect**를 클릭합니다. CloudThinker는 `/api/public/mcp`에 있는 Langfuse의 MCP 서버와 세션을 열어 연결을 테스트합니다.

    **성공 상태:** Langfuse 연결이 **Connected** 상태로 표시됩니다. 아래 검증 프롬프트를 실행하여 키가 프로젝트를 읽는지 확인합니다.
  </Step>
</Steps>

## 연결 검증

```text
Summarize my Langfuse project: recent traces, error count, models in use, and prompts
```

**성공 상태:** CloudThinker가 이 프로젝트에서 최근 7일간의 트레이스 샘플, 최근 observation, 프롬프트, 데이터 세트를 나열합니다. 트레이스가 없는 프로젝트는 오류가 아니라 빈 목록을 반환합니다. 401은 키가 잘못되었다는 뜻입니다. [문제 해결](#문제-해결)을 참조하세요.

## 필요 권한

Langfuse 키 쌍은 하나의 프로젝트에 속하며 해당 프로젝트의 트레이스, 점수, 데이터 세트, 프롬프트에 접근합니다. 프로젝트를 선택하는 것이 CloudThinker가 볼 수 있는 범위를 제한하는 방법입니다.

키 쌍은 해당 프로젝트에 점수, 댓글, 주석 대기열 항목 같은 쓰기도 할 수 있습니다. CloudThinker는 특정 변경을 요청할 때만 쓰기를 하며, 모든 쓰기는 [Approvals](/guide/approvals/overview)를 거칩니다.

<ApprovalDefault />

<Tip>
SDK가 트레이스를 보낼 때 사용하는 키와 별도로 CloudThinker 전용 키 쌍을 만드세요. 그러면 수집을 중단하지 않고 키를 취소할 수 있습니다.
</Tip>

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 |
|------------|------------------------|
| **Trace investigation** | 최근 실패하거나 느린 observation의 순위를 매기고 오류, 지연 시간, 모델 사용을 연관 짓습니다 |
| **Conversation tracing** | 하나의 대화 또는 세션을 오류가 표시된 모델 및 도구 호출의 순서 있는 흐름으로 재구성합니다 |
| **Usage reports** | 시간 범위의 토큰, 비용, 지연 시간을 합산하고 모델과 세션별로 나눕니다 |
| **Quality review** | 점수, 데이터 세트, 주석 대기열, 댓글, 프롬프트 버전을 검토하고 평가 공백을 지적합니다 |
| **Changes on request** | 점수나 댓글 추가, 주석 대기열 항목 변경 같은 쓰기는 대상과 변경 내용을 지정했을 때만 합니다. 조사, 보고서, 검토 중에는 절대 쓰지 않습니다. 호출은 [Approvals](/guide/approvals/overview)를 거칩니다. |

## 예시 프롬프트

```text
Which Langfuse traces failed in the last hour, and what do the errors have in common?
Break down LLM cost and latency by model for the last 24 hours in Langfuse
Which prompt versions have the lowest evaluation scores this week?
```

각 요청에 시간 범위를 언급합니다. 트레이스와 사용량 쿼리에는 한도가 있으며, 짧은 시간 범위가 더 빠르고 집중된 답을 반환합니다.

## 문제 해결

<Accordion title="401 Unauthorized">
공개 키나 비밀 키가 잘못되었거나, 삭제되었거나, 두 키가 서로 다른 프로젝트의 것입니다. 같은 프로젝트에서 두 키를 다시 복사하고, 불필요한 공백이 없는지 확인한 다음 연결을 업데이트합니다.
</Accordion>

<Accordion title="Langfuse Cloud에 대한 연결이 실패함">
각 Langfuse Cloud 리전은 데이터를 분리해 보관하므로, 키 쌍은 이를 발급한 호스트에서만 작동합니다. **LANGFUSE_HOST**를 로그인하는 기본 URL로 설정합니다(예: EU는 `https://cloud.langfuse.com`, US는 `https://us.cloud.langfuse.com`).
</Accordion>

<Accordion title="모든 요청이 404를 반환함">
**LANGFUSE_HOST**의 도메인 뒤에 경로가 있습니다. 기본 URL만 설정합니다. 하나의 트레이스나 데이터 세트에서 404가 나온다면 해당 ID가 이 프로젝트에 없다는 뜻입니다.
</Accordion>

<Accordion title="자체 호스팅 Langfuse가 503을 반환하거나 응답하지 않음">
인스턴스가 HTTPS로 `/api/public/mcp`를 제공하는지, 프록시가 공개 `Host` 헤더를 유지하는지, 방화벽이 호스트에서 CloudThinker를 차단하지 않는지 확인합니다. CloudThinker를 허용 목록에 추가하려면 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
</Accordion>

<Accordion title="검색 결과가 없음">
빈 답변은 연결이 끊어졌다는 뜻이 아닙니다. 시간 범위를 한 단계씩 넓히고, 프로젝트가 애플리케이션에서 트레이스를 받고 있는지 확인합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **키 쌍마다 프로젝트 하나**: 키 쌍은 프로젝트 전체에 접근하므로, CloudThinker가 읽어야 할 프로젝트만 연결합니다.
- **HTTPS만**: CloudThinker는 HTTPS가 아닌 호스트를 거부하므로 키가 평문으로 전송되지 않습니다.

Cloudflare를 연결하면 CloudThinker가 계정과 영역(zone)을 나열하고, HTTP 트래픽과 캐시 동작을 요약하고, 방화벽 이벤트를 검토하고, Cloudflare 문서를 찾아볼 수 있습니다. CloudThinker는 Cloudflare의 호스팅 MCP 서버를 사용하며 하나의 **API 토큰**으로 인증합니다. 이 토큰의 권한이 CloudThinker가 접근할 수 있는 범위를 결정합니다.

## 사전 요구 사항

- 영역이 하나 이상 있는 Cloudflare 계정.
- [Cloudflare 대시보드](https://dash.cloudflare.com/)에서 API 토큰을 생성할 수 있는 권한.

## 설정

<Steps>
  <Step title="커스텀 API 토큰 생성">
    Cloudflare 대시보드에서 **My Profile → API Tokens → Create Token**으로 이동합니다. **Create Custom Token** 아래에서 **Get started**를 클릭합니다. [필요 권한](#필요-권한) 표의 각 권한을 추가합니다. Cloudflare 양식의 각 행에는 드롭다운이 세 개 있으므로, **Zone → Analytics → Read**는 그룹 **Zone**, 권한 **Analytics**, 접근 수준 **Read**를 의미합니다.
  </Step>
  <Step title="필요한 계정과 영역으로 토큰 제한">
    **Account Resources** 아래에서 **Include → your account**를 선택합니다. **Zone Resources** 아래에서 CloudThinker가 볼 각 영역에 대해 **Include → Specific zone**을 선택합니다. CloudThinker가 모든 영역을 다루게 하려는 경우에만 **All zones**를 사용합니다.
  </Step>
  <Step title="만료일 설정 후 토큰 생성 및 복사">
    **TTL** 아래에서 종료일을 설정합니다(예: 오늘부터 90일). **Client IP Address Filtering**은 비워 둡니다. API 호출은 사용자가 관리하는 주소가 아니라 Cloudflare의 호스팅 MCP 서버를 통해 Cloudflare에 도달하기 때문입니다. **Continue to summary → Create Token**을 클릭합니다. 지금 토큰을 복사합니다. Cloudflare는 토큰을 한 번만 표시합니다.

    <Note>
    알려진 IP 주소로 제한된 토큰이 필요합니까? IP 허용 목록 지원은 Enterprise에서 제공됩니다. [support@cloudthinker.io](mailto:support@cloudthinker.io)로 문의하세요.
    </Note>

    붙여넣기 전에 토큰을 확인하려면 다음을 실행합니다:

    ```bash
    curl -H "Authorization: Bearer <token>" https://api.cloudflare.com/client/v4/user/tokens/verify
    ```

    **성공 상태:** 응답에 `"status": "active"`가 포함됩니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Cloudflare**를 선택한 다음 **Connect**를 클릭합니다. **Alias**(예: `main-account`)와 **Description**(예: `Main Cloudflare account, production zones`)을 입력합니다. 연결이 여러 개일 때 에이전트는 설명을 읽고 올바른 연결을 선택합니다. 토큰을 **Cloudflare API token**에 붙여넣고 **Connect**를 클릭합니다.

    **성공 상태:** 연결이 **Connecting**과 **Verifying**을 거쳐 **Connected** 상태로 표시됩니다. 그런 다음 CloudThinker가 [deep look](/ko/guide/connections/overview#연결한-다음에-일어나는-일) 채팅을 열고, 에이전트가 계정을 살펴봅니다.
  </Step>
  <Step title="환경 설정">
    **Settings → Workspace → Connections**에서 **Cloudflare**를 열고 연결 행의 연필 아이콘을 클릭한 다음 **Edit Instance**에서 **Environment**를 설정합니다. 이 값은 사람과 에이전트를 위해 연결에 레이블을 붙입니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 입력할 내용 |
|-------|---------------|
| **Alias** | 이 연결의 짧은 이름. 비워 두면 자동으로 정해집니다. |
| **Description** | 계정이 다루는 범위. 에이전트는 이를 사용해 연결 중에서 선택합니다. |
| **Cloudflare API token** | 생성한 API 토큰. CloudThinker는 CloudThinker Cloud에서 직접 `https://mcp.cloudflare.com/mcp`의 Cloudflare 호스팅 MCP 서버로 이 토큰을 Bearer 토큰으로 보냅니다. |

데이터 경로는 CloudThinker Cloud → Cloudflare의 [호스팅 MCP 서버](https://github.com/cloudflare/mcp-server-cloudflare) → Cloudflare API이므로, 토큰과 API 응답은 Cloudflare 자체 서비스를 거칩니다.

계정 ID는 입력하지 않습니다. CloudThinker가 토큰이 볼 수 있는 계정과 영역을 찾습니다. 토큰이 여러 영역을 다루고 요청이 둘 이상의 영역과 일치하면 CloudThinker가 어느 영역인지 묻습니다. Cloudflare 연결은 둘 이상 추가할 수 있습니다(예: 계정마다 토큰 하나).

## 필요 권한

각 권한은 Cloudflare 양식에 표시되는 그대로 그룹 → 권한 → 접근 수준 순서로 적었습니다.

| 권한 | 가능해지는 작업 | 필요 여부 |
|---|---|---|
| **Account → Account Settings → Read** | 계정 나열 | 예 |
| **Account → Account Analytics → Read** | 계정 수준 분석 | 예 |
| **Zone → Zone → Read** | 영역 나열 및 영역 설정 읽기 | 예 |
| **Zone → DNS → Read** | DNS 레코드 읽기 | 예 |
| **Zone → Analytics → Read** | 트래픽 분석 및 방화벽 이벤트 | 예 |
| **Account → Workers Scripts → Read** | Workers 검사 | Workers를 검사할 때만 |

CloudThinker는 토큰이 허용하는 범위에만 접근할 수 있습니다.

<Tip>
토큰은 읽기 전용으로 유지하고 특정 영역으로 범위를 제한하세요. 쓰기 작업의 고정된 목록은 없습니다. **execute**는 모든 Cloudflare API 엔드포인트를 호출할 수 있으므로, **Zone → DNS → Edit**처럼 토큰에 추가하는 모든 편집 권한은 에이전트가 제안할 수 있는 변경이 됩니다. 각 호출은 여전히 승인 절차를 거칩니다.
</Tip>

## 에이전트 기능

이 연결에는 도구가 세 개 있습니다. 두 개는 자유롭게 실행됩니다. 세 번째는 Cloudflare API를 호출하며, 같은 도구로 변경도 할 수 있기 때문에 읽기 작업이라도 항상 [Approvals](/guide/approvals/overview)를 거칩니다.

| 도구 | CloudThinker가 하는 일 | 승인 |
|------|------------------------|----------|
| **docs** | Cloudflare 문서 검색 | 아니요 |
| **search** | 요청에 맞는 Cloudflare API 엔드포인트 찾기 | 아니요 |
| **execute** | Cloudflare API 호출: 계정과 영역 나열, 영역 설정과 DNS 레코드 읽기, GraphQL 분석 실행, 방화벽 이벤트 읽기, Workers 검사 | 예 |

<ApprovalDefault />

**execute**를 호출하는 자동화는 자체 Approval mode(기본값 **Refuse**)를 사용하므로, 승인을 요청하게 될 호출은 대신 거부됩니다.

기본 제공 쿼리 제한으로 결과가 작게 유지됩니다. 트래픽 요약은 한 영역에 대해 최대 7일의 시간별 데이터를 다루고, 방화벽 검토는 최대 24시간과 샘플 이벤트 50개를 다룹니다. 방화벽 출력에는 클라이언트 IP 주소가 포함되지 않습니다.

### 연결 검증

```text
List the Cloudflare accounts and zones this token can see
```

답변은 **execute** 도구에서 나오므로 먼저 승인 절차를 거칩니다. CloudThinker가 채팅에 승인 요청을 올리면 승인합니다. 답변에 실제 계정 이름과 영역 이름이 나열됩니다.

### 예시 프롬프트

```text
Summarize HTTP requests, bandwidth, and cache behavior for example.com over the last 7 days
Show which firewall rules blocked or challenged requests on example.com in the last 24 hours
How do I set up a WAF custom rule to rate limit a login path? Use the Cloudflare docs
```

## 문제 해결

<Accordion title="권한 거부">
CloudThinker가 `CLOUDFLARE_PERMISSION_DENIED`를 보고합니다. 요청한 내용에 대한 읽기 권한이 토큰에 없습니다. **My Profile → API Tokens**에서 토큰을 편집하여 권한을 추가한 다음 다시 요청합니다.
</Accordion>

<Accordion title="영역이 없거나 영역을 찾을 수 없음">
`CLOUDFLARE_NO_ZONES`는 토큰이 나열하는 영역이 없다는 뜻입니다. `CLOUDFLARE_ZONE_NOT_FOUND`는 지정한 영역이 토큰에 보이지 않는다는 뜻입니다. 토큰의 **Zone Resources**를 확인하고 정확한 영역 이름을 사용합니다.
</Accordion>

<Accordion title="질문해도 아무 일도 일어나지 않음">
모든 Cloudflare API 호출은 승인 절차를 거치며, 일부는 사람을 기다립니다. 채팅에서 대기 중인 승인 요청을 확인하거나 [Approval mode](/guide/approvals/approval-mode)를 검토합니다. 요청을 거부하면 CloudThinker는 다시 시도하지 않습니다.
</Accordion>

<Accordion title="분석 결과가 비어 있음">
새 영역이나 트래픽이 적은 영역에는 아직 분석 데이터가 없을 수 있습니다. 영역이 Cloudflare를 통해 트래픽을 받고 있는지, 토큰에 **Zone → Analytics → Read**가 있는지 확인합니다.
</Accordion>

<Accordion title="레거시: 이전 연결에 'Cloudflare moved to Cloudflare's hosted endpoint'가 표시됨">
새 연결에서는 이 문제가 발생하지 않습니다. Cloudflare 호스팅 MCP 서버로 전환되기 전에 만든 연결은 이 메시지와 함께 **Error**를 표시하며, CloudThinker가 자동으로 다시 연결합니다. 상태가 바뀌지 않으면 연결을 열고 **Retry**를 클릭합니다. 이전의 Account ID와 Enabled Services 값은 더 이상 사용되지 않습니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **영역 제한**: 영향 범위를 줄이려면 모든 영역 대신 특정 영역으로 토큰을 제한합니다.
- **TTL 종료 전 교체**: 토큰을 만들 때 설정한 **TTL** 종료일 전에 [토큰을 교체](/ko/guide/connections/overview#자격-증명-교체)합니다.

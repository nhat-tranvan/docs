Better Stack을 연결하면 CloudThinker 에이전트가 어떤 모니터가 다운되었는지 확인하고, 열린 인시던트와 현재 온콜 담당자를 읽고, 텔레메트리 소스의 로그와 오류를 검색할 수 있습니다. OAuth로 Better Stack에 한 번 로그인하므로 API 토큰을 만들거나 붙여 넣을 필요가 없습니다.

## 사전 요구 사항

- 에이전트가 읽길 원하는 모니터, 인시던트, 텔레메트리 소스를 볼 수 있는 Better Stack 계정.
- Better Stack에서 서드파티 앱을 승인할 수 있는 권한.

## 설정

<Steps>
  <Step title="연결 시작하기">
    **Settings → Workspace → Connections**를 열고 **Better Stack**을 선택한 뒤 **Connect**를 클릭하세요. CloudThinker가 Better Stack의 승인 페이지를 엽니다.
  </Step>
  <Step title="CloudThinker 승인하기">
    에이전트가 사용할 Better Stack 계정으로 로그인한 다음 접근을 승인하세요. 브라우저가 다른 Better Stack 계정에 로그인되어 있다면 먼저 로그아웃하세요.
  </Step>
  <Step title="CloudThinker로 돌아오기">
    Better Stack이 CloudThinker로 돌려보내며, CloudThinker가 토큰을 저장합니다.

    **성공 상태:** 연결에 **Connected**가 표시됩니다. 새 채팅에서 [연결 확인](#연결-확인)의 프롬프트를 실행해 계정이 접근할 수 있는 범위를 확인하세요.
  </Step>
</Steps>

## 연결 세부 정보

입력할 필드는 없습니다.

| 항목 | 값 |
|------|-------|
| **인증** | OAuth. Better Stack이 토큰을 발급하고 CloudThinker가 저장합니다 |
| **엔드포인트** | `https://mcp.betterstack.com`, Better Stack의 호스팅 MCP 서버 |

에이전트 요청은 CloudThinker에서 그 서버로 가며, 서버가 Better Stack 계정을 읽습니다. 네트워크 안으로 들어오는 연결은 없으므로 추가할 방화벽 규칙이 없습니다.

## 필요한 권한

에이전트는 승인한 Better Stack 계정이 보는 것을 봅니다. CloudThinker는 그 권한을 좁힐 수 없으므로, 에이전트가 사용하길 원하는 팀에만 접근할 수 있는 계정으로 승인해 접근을 제한하세요.

<Tip>
승인한 계정 자체의 Better Stack 권한이 상한입니다. 읽기 전용 연결을 원하면 인시던트나 대시보드를 변경할 수 없는 계정으로 승인하세요. 모든 변경을 사람이 승인하도록 **Manual**을 선택하거나, Better Stack 변경을 완전히 차단하는 **Deny** [Rule](/guide/approvals/rules)을 추가하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 |
|------------|--------------------|
| **Discovery** | 모니터, 최근 24시간의 인시던트, 텔레메트리 소스, 상태 페이지를 한 번에 나열합니다 |
| **업타임** | 기간별 모니터 가용성과 응답 시간, 그리고 cron 및 예약 작업의 heartbeat 적중률을 읽습니다 |
| **인시던트와 온콜** | 인시던트, 타임라인, 코멘트, 온콜 일정과 현재 순번, 에스컬레이션 정책, 심각도를 읽습니다 |
| **상태 페이지** | 상태 페이지, 구성 요소, 과거 보고서를 읽습니다 |
| **텔레메트리** | 지정한 소스의 로그와 지표를 쿼리하고, 대시보드, 차트, 알림, 오류, 애플리케이션, 릴리스를 읽습니다 |
| **변경(Approvals를 거침)** | 인시던트를 확인, 해결, 다시 열기, 에스컬레이션, 코멘트, 생성합니다. 상태 페이지 보고서나 업데이트를 게시합니다. 대시보드, 차트, 알림을 생성, 편집, 삭제합니다 |

Better Stack은 모든 리소스를 ID로 식별하므로, 에이전트는 무언가를 변경하기 전에 먼저 이름으로 모니터, 인시던트, 소스를 찾고 일치하는지 확인합니다. 인시던트를 확인(acknowledge)하면 온콜 호출이 멈추므로, 누군가 실제로 인시던트를 처리하고 있을 때만 승인하세요. 어떤 변경을 먼저 묻고 어떤 변경을 완전히 거부할지 정하려면 [Rules](/guide/approvals/rules)를 참고하세요.

<ApprovalDefault />

<Note>
Better Stack의 MCP 서버는 모니터를 일시 중지하거나 재개할 수 없습니다. 유지 관리 기간은 Better Stack 대시보드에서 설정하세요.
</Note>

### 연결 확인

새 채팅에서 CloudThinker에게 물어보세요:

```text
List open Better Stack incidents, monitors that are down, and who is on call now
```

열린 인시던트와 해당 모니터 및 시작 시간, 현재 실패 중인 모니터, 일정별 현재 온콜 담당자가 표시되어야 합니다. 모두 정상이라면 빈 목록도 유효한 답변입니다.

### 예시 프롬프트

```text
24-hour availability and p95 response time for every production monitor
Count 5xx errors by status code in the api-gateway logs over the last hour
Which heartbeats missed a check-in today?
```

Better Stack에는 전역 로그 검색이 없습니다: 모든 쿼리는 소스 하나에 대해 실행됩니다. 위의 `api-gateway`처럼 프롬프트에 소스 이름을 적거나, 먼저 에이전트에게 소스를 나열해 달라고 요청하세요.

## 문제 해결

<Accordion title="OAuth 흐름이 완료되지 않습니다">
브라우저가 다른 Better Stack 계정에 로그인되어 있을 가능성이 높습니다. Better Stack에서 올바른 계정으로 로그인한 다음 다시 **Connect**를 클릭하세요.
</Accordion>

<Accordion title="호출이 401 Unauthorized로 실패합니다">
OAuth 토큰이 만료되었거나 Better Stack에서 접근이 취소되었습니다. Better Stack 연결을 열고 **Connect**를 클릭해 다시 승인하세요. 연결의 에이전트, 설정, 메모리는 유지됩니다.
</Accordion>

<Accordion title="모니터나 인시던트가 404 Not Found를 반환합니다">
리소스가 승인한 계정이 볼 수 없는 팀에 속하거나 삭제되었습니다. 에이전트에게 모니터나 인시던트를 다시 나열해 현재 ID를 가져오라고 요청하세요.
</Accordion>

<Accordion title="로그 쿼리가 구문 오류를 반환합니다">
Better Stack 로그 쿼리는 자체 쿼리 언어를 사용합니다. 에이전트는 Better Stack의 쿼리 구문을 불러와 스스로 재시도합니다. 그래도 실패하면 평이한 말로 다시 묻고 소스 이름을 지정하세요. 예: "count 5xx errors in api-gateway over the last hour".
</Accordion>

<Accordion title="요청이 429 Too Many Requests로 실패합니다">
Better Stack의 속도 제한에 걸렸습니다. 에이전트는 대기 후 재시도합니다. 계속 발생하면 질문의 시간 범위나 모니터 수를 줄이세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **사용하지 않으면 취소하세요**: 연결을 더 이상 사용하지 않으면 Better Stack에서 CloudThinker의 승인을 제거한 다음 CloudThinker에서 연결을 삭제하세요.
- **계정 전환**: 연결을 해제한 다음, 다른 Better Stack 계정으로 로그인한 상태에서 다시 연결하세요.

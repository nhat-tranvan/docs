Prometheus를 연결하면 CloudThinker가 PromQL 쿼리를 실행하고, 메트릭과 레이블을 나열하고, 스크레이프 대상 상태를 확인하고, 활성 알림과 알림 규칙을 읽을 수 있습니다. 이 연결은 읽기 전용이며, 인증 없음, bearer 토큰, HTTP Basic 인증 중 하나로 인증합니다.

## 지원 플랫폼

규칙: 엔드포인트가 주소의 루트에서 인증 없음, bearer 토큰, HTTP Basic 인증 중 하나로 `<your URL>/api/v1/query`에 응답해야 합니다.

| 플랫폼 | 지원 여부 | 참고 |
|----------|-----------|-------|
| **Self-hosted Prometheus** | 예 | |
| **Thanos Querier** | 예 | |
| **Grafana Mimir, Cortex, Grafana Cloud metrics** | 아니요 | 쿼리 API가 `/prometheus`나 `/api/prom` 같은 경로 접두사 아래에 있습니다. Grafana Cloud는 대신 [Grafana 연결](/ko/guide/connections/grafana)을 사용합니다 |
| **Amazon Managed Service for Prometheus** | 아니요 | AWS SigV4 요청 서명이 필요합니다 |
| **Google Cloud Managed Service for Prometheus** | 아니요 | Google Cloud 인증이 필요합니다 |

## 사전 요구 사항

- 인터넷에서 접근할 수 있는 Prometheus HTTP API. 연결은 네트워크 내부가 아니라 CloudThinker Cloud에서 실행됩니다.
- URL이 HTTPS를 사용한다면 공개적으로 신뢰할 수 있는 TLS 인증서. 비공개 CA를 추가할 필드는 없습니다.
- Prometheus 앞의 프록시나 게이트웨이가 요구한다면 bearer 토큰 또는 사용자 이름과 비밀번호.
- CloudThinker 워크스페이스에 연결을 추가할 수 있는 권한.

<Tip>
Prometheus가 Kubernetes 안의 비공개 주소에 있습니까? TLS가 있는 ingress와 bearer 토큰 또는 Basic 인증을 확인하는 인증 프록시를 통해 노출한 다음, CloudThinker의 egress IP를 허용 목록에 추가하세요. 이 문서는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의](https://cloudthinker.io/contact)하세요. 다른 옵션은 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
</Tip>

<Warning>
URL에는 경로를 포함할 수 없습니다. `https://metrics.example.com/prometheus/api/v1`처럼 접두사 아래에서만 응답하는 엔드포인트는 연결 테스트에 실패합니다. 대신 호스트 이름의 루트에서 API를 노출하세요.
</Warning>

## 설정

<Steps>
  <Step title="기본 URL 확인">
    `/api/v1` 앞에 오는 주소를 경로와 끝의 슬래시 없이 사용합니다(예: `https://prometheus.example.com` 또는 `http://prometheus.example.com:9090`).

    연결하기 전에 터미널에서 확인합니다:

    ```bash
    # No auth
    curl -s "https://prometheus.example.com/api/v1/query?query=count(up)"
    # Bearer token
    curl -s -H "Authorization: Bearer <token>" "https://prometheus.example.com/api/v1/query?query=count(up)"
    # Basic auth
    curl -s -u <user>:<password> "https://prometheus.example.com/api/v1/query?query=count(up)"
    ```

    CloudThinker에 제공할 것과 같은 자격 증명으로, 네트워크 외부의 컴퓨터에서 실행합니다.

    **성공 상태:** 응답이 `{"status":"success","data":{"resultType":"vector"`로 시작합니다.
  </Step>
  <Step title="인증 모드 선택">
    | 모드 | 사용할 때 | 나타나는 필드 |
    |------|-------------|--------------------|
    | **None** | 엔드포인트가 열려 있거나 네트워크 규칙으로 제한된 경우 | URL만 |
    | **Bearer Token** | 프록시가 `Authorization: Bearer <token>`을 기대하는 경우 | **PROMETHEUS_TOKEN** |
    | **Basic Auth** | 프록시가 사용자 이름과 비밀번호를 기대하는 경우 | **PROMETHEUS_USERNAME**, **PROMETHEUS_PASSWORD** |

    <Warning>
    Prometheus는 접근할 수 있는 누구에게나 로드된 구성, 내부 호스트 이름, 대상 주소를 노출합니다. **None**은 CloudThinker의 egress IP만 허용하는 방화벽 규칙 뒤에서만 사용하세요. 인터넷 전체에 열린 엔드포인트에는 절대 **None**을 사용하지 마세요.
    </Warning>
  </Step>
  <Step title="연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **Prometheus**를 선택합니다. 다음을 입력합니다:
    - **Alias**(선택 사항): `prod-metrics` 같은 짧은 이름. 소문자, 숫자, 하이픈을 사용합니다.
    - **Description**(선택 사항): 이 Prometheus가 다루는 범위. 둘 이상 연결할 때 에이전트는 이를 읽고 올바른 인스턴스를 선택합니다.
    - **PROMETHEUS_URL**: 1단계의 기본 URL.
    - **PROMETHEUS_AUTH_TYPE**: **None**, **Bearer Token**, **Basic Auth** 중 하나를 선택한 다음 나타나는 자격 증명 필드.
    - **LOG_LEVEL**: **Info**로 둡니다.

    **Connect**를 클릭합니다. CloudThinker가 엔드포인트에 대해 `count(up)`을 실행하고, **Connecting**과 **Verifying**을 표시한 다음 **Connected** 상태를 표시합니다. 검증에 실패하면 **Failed**가 표시되고 오류 메시지가 나타납니다. 메시지를 [문제 해결](#문제-해결)과 대조합니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 기본값 | 설명 |
|-------|----------|---------|-------------|
| **Alias** | 아니요 | 자동으로 정해짐 | `prod-metrics` 같은 짧은 이름. 소문자, 숫자, 하이픈 |
| **Description** | 아니요 | `Prometheus` | 이 엔드포인트가 다루는 범위. 에이전트는 이를 읽고 올바른 인스턴스를 선택합니다 |
| **PROMETHEUS_URL** | 예 | 없음 | 경로 없는 Prometheus HTTP API의 기본 URL(예: `https://prometheus.example.com`) |
| **PROMETHEUS_AUTH_TYPE** | 예 | **None** | **None**, **Bearer Token**, **Basic Auth** |
| **PROMETHEUS_TOKEN** | Bearer Token 모드 | 없음 | `Authorization: Bearer`로 보내는 토큰 |
| **PROMETHEUS_USERNAME** | Basic Auth 모드 | 없음 | HTTP Basic 사용자 이름 |
| **PROMETHEUS_PASSWORD** | Basic Auth 모드 | 없음 | HTTP Basic 비밀번호 |
| **LOG_LEVEL** | 아니요 | **Info** | 커넥터 로그 상세 수준. 지원팀이 요청하지 않는 한 **Info**로 둡니다 |

## 필요 권한

Prometheus에는 기본 제공 사용자 권한이 없으므로, 접근 범위는 프록시나 게이트웨이가 허용하는 대로입니다. CloudThinker에는 다음 영역에 대해 `/api/v1/` 아래의 읽기(`GET`) 접근이 필요합니다:

| 영역 | 용도 |
|------|----------|
| Query API | 즉시 및 범위 PromQL 쿼리, 시리즈 조회 |
| Metadata | 메트릭 이름, 레이블 이름, 유형 및 도움말 텍스트 |
| Targets | 스크레이프 대상 상태 |
| Alerts and rules | 활성 알림과 알림 규칙 정의 |
| Status config | 요청할 때만 로드된 구성 읽기 |

<Tip>
프록시가 지원한다면 CloudThinker에 `/api/v1/` 아래의 `GET` 요청으로 제한된 전용 토큰을 주세요. 이 연결은 Prometheus에 아무것도 쓰지 않습니다.
</Tip>

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 |
|------------|------------------------|
| **Discovery** | 스크레이프 대상(up 및 down), 발생 중인 알림, 알림 규칙과 그 상태, 메트릭, `job`·`instance`·`namespace` 같은 레이블의 수를 셉니다 |
| **Instant queries** | 한 시점에서 PromQL 표현식을 평가합니다 |
| **Range queries** | 간격(step)을 두고 기간에 걸쳐 PromQL을 평가합니다. 최근 15분부터 시작하고 결과가 비어 있으면 범위를 넓힙니다 |
| **Metric and label discovery** | 쿼리가 실제 이름을 사용하도록 메트릭 이름, 유형 및 도움말 텍스트, 레이블 이름을 나열합니다 |
| **Target health** | 스크레이프 대상과 그중 다운된 대상을 나열합니다 |
| **Alerts** | 발생 중이거나 대기 중인 알림과 구성된 알림 규칙을 나열합니다 |
| **Configuration** | 요청 시 로드된 구성을 읽고, 답변에서 자격 증명 값을 가립니다 |

연결이 처음 **Connected**에 도달하면 CloudThinker가 에이전트가 엔드포인트를 탐색하는 [deep look](/ko/guide/connections/overview#연결한-다음에-일어나는-일) 채팅을 엽니다.

### 연결 검증

```text
Run Prometheus discovery and tell me how many scrape targets are up and down, and how many alerts are firing
```

정상적인 답변은 상태별 대상 수, 발생 중인 알림 수, 엔드포인트의 샘플 메트릭 이름 몇 개를 제공합니다.

### 예시 프롬프트

```text
Which scrape targets are down right now, and which jobs do they belong to?
Show 5xx rate by service from http_requests_total over the last hour and flag anything above 1%
List firing alerts and the alert rule behind each one
```

관심 있는 메트릭과 레이블을 지정합니다. CloudThinker는 레이블 이름을 나열할 수 있으므로, "split by `namespace`" 같은 프롬프트가 정확한 셀렉터를 더 빨리 얻습니다.

인시던트가 자동으로 열리도록 Prometheus 알림을 Resolve로 보내려면 [webhook integration](/ko/guide/incident/webhook-integrations/overview)을 설정합니다.

## 문제 해결

<Accordion title="Prometheus가 자격 증명을 거부함">
엔드포인트가 401 또는 403을 반환했습니다. **PROMETHEUS_AUTH_TYPE**이 프록시가 기대하는 것과 일치하는지 확인한 다음, 토큰 또는 사용자 이름과 비밀번호를 다시 입력합니다. 프록시에서 취소된 토큰도 같은 방식으로 실패합니다.
</Accordion>

<Accordion title="해당 URL에 Prometheus 쿼리 API가 없음">
엔드포인트가 404를 반환했습니다. URL에 `/api/v1`이나 `/prometheus` 같은 경로가 있을 가능성이 높습니다. 스킴, 호스트, 포트만 입력합니다. API가 접두사 아래에서만 응답한다면 지원되지 않습니다.
</Accordion>

<Accordion title="URL이 응답했지만 Prometheus 쿼리 API로서는 아님">
Prometheus 앞의 다른 무언가가 대신 응답했습니다. 대개 로그인 페이지나 SSO 프록시입니다. URL이 API 자체를 가리키도록 하거나, 프록시가 브라우저 로그인 없이 받아들이는 bearer 토큰 또는 Basic 인증을 사용합니다.
</Accordion>

<Accordion title="Prometheus에 접근할 수 없거나 시간 안에 응답하지 않음">
CloudThinker가 연결을 열 수 없었습니다. 호스트 이름, 포트, TLS 인증서를 확인하고, 엔드포인트가 인터넷에서 오는 트래픽을 받는지 확인합니다. `10.0.0.5` 같은 비공개 주소는 CloudThinker에서 접근할 수 없습니다.
</Accordion>

<Accordion title="쿼리가 데이터를 반환하지 않음">
먼저 CloudThinker에게 이름과 일치하는 메트릭을 나열해 달라고 요청하여 메트릭이 존재하는지 확인합니다. 그런 다음 범위 쿼리는 15분부터 시작하므로 시간 범위를 넓힙니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **쓰기 없음**: 이 연결은 Prometheus HTTP API를 읽기만 하므로, `GET` 요청으로 제한된 토큰이면 충분합니다.
- **구성에 시크릿이 있음**: `/api/v1/status/config`에는 스크레이프 자격 증명과 내부 호스트 이름이 포함될 수 있습니다. 읽히지 않게 하려면 프록시에서 해당 경로를 차단합니다.

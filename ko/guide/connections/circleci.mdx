CircleCI를 연결하면 CloudThinker 에이전트가 파이프라인 상태를 읽고, 빌드 및 테스트 로그를 가져와 실행이 실패한 이유를 찾고, 불안정한(flaky) 테스트를 발견하고, `.circleci/config.yml`을 검증할 수 있습니다. 연결은 CircleCI Personal API Token을 사용하므로, 에이전트는 토큰 사용자가 볼 수 있는 프로젝트에만 정확히 접근합니다.

## 사전 요구 사항

- 에이전트가 조사할 조직과 프로젝트를 볼 수 있는 CircleCI 계정.
- 해당 계정이 팔로우하는 프로젝트가 하나 이상 있어야 합니다. 에이전트는 팔로우한 목록에서 프로젝트를 찾습니다. 프로젝트를 팔로우하려면 토큰 사용자로 CircleCI에 로그인하고 **Projects**를 열어 각 리포지토리 옆의 **Follow Project**를 클릭합니다.
- 불안정한 테스트와 작업 테스트 결과를 보려면: 작업이 `store_test_results`로 JUnit 결과를 업로드해야 합니다. 그렇지 않으면 CircleCI가 반환할 테스트 데이터가 없습니다.
- 에이전트가 파이프라인을 시작하거나 재실행하게 하려면: 같은 계정에 해당 프로젝트의 파이프라인을 트리거할 권한이 있어야 합니다.
- 셀프 호스팅 CircleCI Server의 경우: CloudThinker에서 HTTPS로 서버에 접근할 수 있어야 합니다. [비공개 서비스 접근](/ko/guide/connections/overview#비공개-서비스-접근)을 참조하세요.

## 설정

<Steps>
  <Step title="Personal API Token 생성">
    CircleCI에서 **User Settings → Personal API Tokens** ([app.circleci.com/settings/user/tokens](https://app.circleci.com/settings/user/tokens))를 열고 **Create New Token**을 클릭합니다. 이름은 `cloudthinker`로 지정합니다.

    토큰을 즉시 복사하세요. CircleCI는 토큰을 한 번만 표시합니다.
  </Step>
  <Step title="연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **CircleCI**를 선택합니다. 다음을 입력합니다.
    - **CIRCLECI_TOKEN**: 방금 생성한 토큰.
    - **CIRCLECI_BASE_URL**: CircleCI 클라우드에서는 `https://circleci.com`으로 그대로 둡니다. 셀프 호스팅 CircleCI Server 설치에서만 변경합니다.

    **Connect**를 클릭합니다.

    **성공 상태:** 대화상자가 닫히고 연결에 **Connected**가 표시됩니다.
  </Step>
  <Step title="토큰 작동 확인">
    [연결 확인](#연결-확인)의 프롬프트를 실행합니다. CloudThinker는 연결할 때 CircleCI에서 토큰을 확인하지 않으므로, **Connected** 상태만으로는 토큰이 유효하다는 것이 증명되지 않습니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 설명 | 예시 |
|-------|----------|-------------|---------|
| **CIRCLECI_TOKEN** | 예 | Personal API Token. 생성한 사용자의 접근 권한을 가집니다 | `CCIPAT_...` |
| **CIRCLECI_BASE_URL** | 아니요 | CircleCI 설치의 호스트. 호스트만 입력하고 뒤에 경로를 붙이지 않습니다 | `https://circleci.com` |

입력할 조직 또는 프로젝트 ID는 없습니다. 에이전트가 토큰의 팔로우한 프로젝트에서 이를 확인합니다.

## 필수 권한

Personal API Token은 생성한 CircleCI 사용자와 같은 접근 권한을 가집니다. 해당 사용자의 프로젝트 접근 권한이 에이전트가 읽거나 변경할 수 있는 범위의 상한입니다.

| 에이전트에게 맡길 작업 | 토큰 사용자에게 필요한 것 |
|----------------------------|-----------------------------|
| 상태, 로그, 테스트 결과, 아티팩트 읽기 | 프로젝트 읽기 권한 |
| 파이프라인 시작, 워크플로 재실행, 평가 테스트 실행 | 프로젝트의 파이프라인 트리거 권한 |
| 배포 롤백 | CircleCI **Deploys**에서 프로젝트용으로 설정된 롤백 파이프라인과 그 파이프라인의 트리거 권한 |

**평가 테스트**는 CircleCI의 프롬프트 템플릿 테스트입니다. 에이전트는 이를 CircleCI에서 파이프라인으로 실행합니다.

<Tip>
조사할 프로젝트에만 속한 전용 CircleCI 사용자로 토큰을 생성하세요. 해당 사용자는 GitHub 또는 Bitbucket 조직의 멤버여야 하므로 보통 VCS 머신 사용자를 사용합니다. CircleCI 플랜에서 사용자로 계산되는지 확인하세요. 쓰기 작업은 여전히 [Approvals](/guide/approvals/overview)를 거치므로, 토큰이 상한을 정하고 Approvals가 각 작업을 결정합니다.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 |
|------------|--------------------|
| **프로젝트 탐색** | 팔로우한 프로젝트와 해당 조직 목록 조회 |
| **파이프라인 상태** | 프로젝트와 브랜치의 최신 파이프라인 상태 읽기 |
| **실패 분류** | 빌드 실패 로그와 작업 테스트 결과를 가져와 실패한 단계 찾기 |
| **불안정한 테스트** | 같은 코드에서 통과와 실패를 반복하는 테스트 찾기 |
| **구성 검증** | `.circleci/config.yml`을 확인하고 오류 설명 |
| **아티팩트** | 작업이 생성한 아티팩트 목록 조회 |
| **사용량 검토** | 사용량 데이터를 다운로드하고 충분히 사용되지 않는 리소스 클래스 표시 (유료 플랜 전용) |
| **파이프라인 제어** | 파이프라인 실행, 워크플로 재실행, 평가 테스트 실행, 배포 롤백. **각 작업은 Approvals를 거칩니다** |

쓰기 작업 전에 에이전트는 무슨 일이 일어날지 알려 주고(예: "`gh/acme/api`의 `main` 브랜치에서 파이프라인을 시작합니다") 정확한 입력값을 보여 줍니다. 롤백은 현재 버전과 대상 버전도 나열하고 대상을 확인하도록 요청합니다.

<ApprovalDefault />

매번 확인을 받으려면 [Approval mode](/guide/approvals/approval-mode)로 **Manual**을 선택하여 사람이 모든 변경을 승인하도록 하세요. **Ask first** [Rule](/guide/approvals/rules)을 사용하면 이 연결에만 적용되도록 범위를 좁힐 수 있습니다.

### 연결 확인

```text
List my followed CircleCI projects and show the latest pipeline status for each
```

팔로우한 각 프로젝트가 슬러그(예: `gh/acme/api`)와 최신 파이프라인 상태와 함께 표시되어야 합니다. 예상한 프로젝트가 보이지 않으면 토큰 사용자가 해당 프로젝트를 팔로우하지 않은 것입니다.

### 예시 프롬프트

```text
The main branch of gh/acme/api failed on CircleCI. Pull the failure logs and tell me which step broke and why
Which tests in gh/acme/api are flaky, and how often does each one fail?
```

## 문제 해결

<Accordion title="모든 요청이 401 Unauthorized를 반환함">
토큰이 없거나, 만료되었거나, 취소되었습니다. 새 Personal API Token을 생성하고 연결의 **CIRCLECI_TOKEN** 필드를 업데이트하세요.
</Accordion>

<Accordion title="읽기는 되지만 파이프라인 시작 또는 재실행 시 권한 오류가 반환됨">
토큰 사용자가 프로젝트를 읽을 수는 있지만 파이프라인을 트리거할 수 없습니다. 해당 프로젝트에 트리거 권한이 있는 사용자로 토큰을 생성한 다음 연결을 업데이트하세요.
</Accordion>

<Accordion title="연결은 Connected이지만 프로젝트가 나타나지 않음">
토큰 사용자가 팔로우하는 프로젝트가 없습니다. CircleCI에서 프로젝트를 하나 이상 팔로우한 다음 다시 요청하세요.
</Accordion>

<Accordion title="불안정한 테스트 또는 작업 테스트 결과가 비어 있음">
작업이 테스트 결과를 업로드하지 않습니다. JUnit XML 출력을 가리키는 `store_test_results` 단계를 추가하고, 파이프라인을 몇 번 실행한 다음 다시 요청하세요.
</Accordion>

<Accordion title="프로젝트가 404를 반환함">
프로젝트 슬러그에는 VCS 접두사가 필요합니다. GitHub는 `gh/<org>/<repo>`, Bitbucket은 `bb/<org>/<repo>`입니다. 에이전트에게 팔로우한 프로젝트 목록을 요청하고 그 목록의 슬러그를 사용하세요.
</Accordion>

<Accordion title="사용량 분석에서 조직 ID를 요청함">
사용량 데이터에는 조직 UUID가 필요하지만, 이를 반환하는 CircleCI API 호출은 없습니다. CircleCI의 **Organization Settings → Overview → Organization ID**에서 복사하여 채팅에 붙여 넣으세요. 사용량 API는 유료 플랜 전용이며 요청당 최대 32일을 다룹니다.
</Accordion>

<Accordion title="셀프 호스팅 설치에서 404 또는 인증 오류가 반환됨">
**CIRCLECI_BASE_URL**이 여전히 `https://circleci.com`이거나 경로를 포함하고 있습니다. `https://circleci.example.com`처럼 CircleCI Server 호스트만 입력하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **전용 사용자 사용**: CircleCI Personal Token에는 자체 범위(scope)가 없으므로, 토큰 사용자의 프로젝트 멤버십이 접근 범위를 제한하는 유일한 방법입니다.
- **제어 작업은 승인 게이트 유지**: 파이프라인 실행은 컴퓨팅 비용이 청구되고 배포를 수행할 수 있습니다. 이러한 작업을 자동 승인하지 말고 [Approval mode](/guide/approvals/approval-mode) 뒤에 두세요.

ClickUp을 연결하면 CloudThinker 에이전트가 목록에서 주의가 필요한 항목을 찾고, 담당자별 워크로드를 비교하고, 작업 토론, 문서, 채팅 채널을 읽고, 승인을 거쳐 작업을 업데이트할 수 있습니다. **OAuth**(ClickUp 자체 페이지에서 접근을 승인하는 방식)로 로그인하므로 만들거나 붙여 넣을 API 토큰이 없습니다. 목록이나 작업 ID를 찾아볼 필요도 없습니다. 에이전트가 먼저 워크스페이스 구조를 읽고 "Platform Team" 같은 이름을 스스로 확인합니다.

## 사전 요구 사항

- 에이전트가 작업할 스페이스와 목록을 볼 수 있는 ClickUp 계정.
- CloudThinker 워크스페이스에서 연결을 편집할 권한.
- 이 CloudThinker 워크스페이스에 기존 ClickUp 연결이 없어야 합니다. 각 CloudThinker 워크스페이스는 하나만 가질 수 있습니다. 확인하려면 **Settings → Workspace → Connections**에서 ClickUp을 엽니다. **Connected**가 표시되면 먼저 상세 패널에서 **Disconnect**를 클릭하세요.

<Warning>
승인할 때 ClickUp 워크스페이스를 정확히 **하나만** 선택하세요. ClickUp의 도구는 로그인 후 워크스페이스를 전환할 수 없으며, 여러 워크스페이스에 대해 승인된 연결은 모든 요청에 실패합니다.
</Warning>

## 설정

<Steps>
  <Step title="CloudThinker에서 ClickUp 열기">
    **Settings → Workspace → Connections**를 엽니다. **Discover** 탭에서 **ClickUp**을 검색하고 **Connect**를 클릭합니다.
  </Step>
  <Step title="ClickUp에 로그인">
    ClickUp의 승인 페이지가 열립니다. 에이전트가 봐야 할 범위와 접근 권한이 일치하는 계정으로 로그인합니다. 브라우저가 이미 다른 ClickUp 계정에 로그인되어 있다면 먼저 그곳에서 로그아웃하세요.
  </Step>
  <Step title="워크스페이스 하나 승인">
    CloudThinker가 사용할 ClickUp 워크스페이스 하나를 선택한 다음 접근을 승인합니다.

    **성공 상태:** CloudThinker로 돌아오고 ClickUp 연결에 **Connected**가 표시됩니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 설명 |
|-------|-------------|
| **OAuth authorization** | 접근을 승인할 때 ClickUp이 발급하며, CloudThinker가 암호화하여 저장합니다 |
| **ClickUp workspace** | 승인 중에 선택한 하나의 워크스페이스 |

## 필수 권한

에이전트는 연결을 승인한 ClickUp 사용자로 작동합니다. 해당 사용자가 할 수 있는 것만 읽고 변경할 수 있으며, 변경은 ClickUp에서 그 사용자의 이름으로 표시됩니다.

| 접근 | 범위 | 승인 |
|--------|--------|----------|
| **Read** | 워크스페이스 계층 구조, 목록, 폴더, 작업, 사용자 지정 필드, 댓글과 스레드, 멤버, 시간 기록, 상태별 체류 시간, 문서 페이지, 채팅 채널과 메시지 | 묻지 않고 실행됩니다 |
| **Write** | 작업 생성, 업데이트, 이동 또는 삭제, 댓글 추가, 태그 추가 또는 제거, 기존 Doc 안의 페이지 추가 또는 편집 | 쓰기이므로 [Approvals](/guide/approvals/overview)가 결정합니다 |

<Tip>
CloudThinker에 필요한 스페이스만 볼 수 있는 ClickUp 사용자(또는 전용 서비스 계정)로 승인하세요. 에이전트는 그 사용자가 열 수 없는 스페이스에 절대 접근할 수 없습니다. 서비스 계정은 일반 ClickUp 사용자이므로 ClickUp 플랜에서 멤버로 계산됩니다. CloudThinker에 필요한 스페이스에만 초대하세요.
</Tip>

### 에이전트가 할 수 없는 작업

CloudThinker는 ClickUp이 제공하는 것보다 좁은 도구 세트를 유지하므로, 일부 작업은 승인이 있어도 의도적으로 꺼져 있습니다.

| 사용할 수 없음 | 이유 |
|---------------|-----|
| 스페이스, 폴더, 목록 또는 Doc 생성, 스페이스, 폴더, 목록 편집 | 에이전트는 구조 안에서 작업하며 구조를 바꾸지 않습니다. 기존 Doc 안의 페이지는 추가하거나 편집할 수 있습니다. |
| 작업 병합, 댓글 삭제, 다른 사람의 댓글 편집 | 되돌릴 수 없거나 사람이 직접 쓴 말을 바꿉니다 |
| 시간 추적 시작 또는 중지 | ClickUp은 사용자당 실행 중인 타이머가 하나이므로, 에이전트가 사용자의 타이머를 멈출 수 있습니다 |
| 채팅 메시지 보내기 | 사람들이 쓰는 채널에 원치 않는 게시물이 올라가는 것을 막습니다 |
| 첨부 파일, 알림, 작업 종속성과 링크 | 현재 범위 밖입니다 |

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 |
|------------|--------------------|
| **워크스페이스 탐색** | 스페이스, 폴더, 목록, 최근 작업을 파악하고, 입력한 이름을 ClickUp ID로 확인 |
| **목록 분류** | 한 목록에서 기한이 지났거나, 담당자가 없거나, 일정이 없는 작업 찾기 |
| **워크로드 검토** | 담당자와 상태별 진행 중인 작업을 비교하고, 작업이 각 상태에 머무는 시간 측정 |
| **작업 조사** | 작업 세부 정보, 사용자 지정 필드, 댓글, 스레드 답글 읽기 |
| **문서와 채팅** | 연결된 사용자가 볼 수 있는 문서 페이지와 채팅 채널 메시지 읽기 |
| **작업 변경** | 작업 생성, 업데이트, 이동 또는 삭제, 태그 변경 |
| **댓글과 문서** | 댓글 추가, 기존 Doc 안의 페이지 추가 또는 편집 |

에이전트가 작업 다섯 개의 태그를 바꾸는 것처럼 여러 변경을 한 번에 계획하면, 승인 카드가 실행 전에 모든 변경을 나열합니다.

### 연결 확인

```text
Show the structure of our ClickUp workspace and list what needs attention in the biggest list
```

연결이 작동하면 실제 스페이스와 목록의 이름을 보여 준 다음, 그중 하나에서 기한이 지났거나, 담당자가 없거나, 일정이 없는 작업을 반환합니다. 승인 오류가 나오면 다시 연결해야 합니다.

### 예시 프롬프트

```text
List overdue, unassigned, and unscheduled tasks in the Platform Team → Sprint 42 list
Compare open ClickUp work by assignee in the Engineering space and flag anyone with more than 10 tasks in progress
Which tasks in the Backend list have been in "In review" the longest?
Read the comments on the oldest overdue task in Sprint 42 and suggest the next step
Move every task tagged blocked in Sprint 42 to Sprint 43 and add a comment explaining why
```

## 문제 해결

<Accordion title="OAuth 페이지가 끝나지 않거나 잘못된 계정이 연결됨">
브라우저가 다른 ClickUp 계정에 로그인되어 있을 가능성이 높습니다. ClickUp에서 로그아웃하고 올바른 계정으로 로그인한 다음 **Connect**를 다시 클릭하세요.
</Accordion>

<Accordion title="모든 요청이 여러 워크스페이스 오류로 실패함">
연결이 둘 이상의 ClickUp 워크스페이스에 대해 승인되었습니다. **Settings → Workspace → Connections**에서 ClickUp을 열고 상세 패널에서 **Disconnect**를 클릭한 다음, **Connect**를 클릭하고 워크스페이스를 정확히 하나만 선택하세요.
</Accordion>

<Accordion title="요청이 갑자기 401 Unauthorized로 실패함">
ClickUp 승인이 만료되었거나 취소되었습니다. **Settings → Workspace → Connections**에서 ClickUp을 열고 **Connect**를 클릭해 다시 로그인하세요.
</Accordion>

<Accordion title="에이전트가 스페이스, 목록 또는 작업을 찾지 못함">
승인한 사용자에게 접근 권한이 없거나 항목이 이동했을 수 있습니다. 그 사용자가 ClickUp에서 해당 항목을 열 수 있는지 확인한 다음, 에이전트에게 워크스페이스 구조를 다시 읽도록 요청하세요.
</Accordion>

<Accordion title="상태 체류 시간이 사용할 수 없음으로 표시됨">
상태별 체류 시간에는 **Total time in Status** ClickApp이 필요합니다. ClickUp 워크스페이스 소유자나 관리자가 워크스페이스 설정의 **ClickApps**에서 켤 수 있습니다. 작업과 워크로드 읽기는 이것 없이도 계속 작동하며, CloudThinker는 측정값을 0이 아니라 사용할 수 없음으로 보고합니다.
</Accordion>

<Accordion title="요청이 속도 제한 오류로 실패함">
ClickUp 계정이 API 할당량에 도달했습니다. 한도는 ClickUp 플랜에 따라 다릅니다. [ClickUp의 속도 제한](https://developer.clickup.com/docs/rate-limits)을 참조하세요. 기간이 초기화될 때까지 기다린 다음 같은 요청을 다시 시도하세요.
</Accordion>

<Accordion title="변경이 대기 상태에서 멈춤">
쓰기가 사람을 기다리고 있습니다. 채팅에서 승인 카드를 찾아 **Approve**를 클릭하거나, 직접 승인할 수 없다면 **Notify approvers**를 클릭하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **연결당 워크스페이스 하나.** CloudThinker가 접근해야 하는 ClickUp 워크스페이스만 승인하세요.
- **승인하는 사용자를 신중하게 선택하세요.** 모든 읽기와 쓰기는 그 사용자의 ClickUp 접근 권한으로 실행됩니다. 그 사용자가 떠나면 다른 계정으로 다시 연결하세요.

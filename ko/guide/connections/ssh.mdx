SSH로 서버를 연결하면 [CloudThinker](/ko/guide/agents/overview)가 서버에서 셸 명령을 실행해 디스크와 메모리를 확인하고, 로그를 읽고, 프로세스와 서비스를 점검할 수 있습니다. 개인 키로 로그인하며, CloudThinker는 처음 연결할 때 서버의 호스트 키를 고정해 두어 ID 변경을 감지할 수 있습니다.

## 사전 요구사항

- SSH 포트에서 CloudThinker의 인바운드 SSH를 허용하는 서버. CloudThinker는 **Host**에 직접 연결하며, jump host나 bastion 필드는 없습니다. 방화벽 뒤에 있거나 공용 주소가 없는 서버는 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)에서 environment 옵션을 참고하세요. 이 문서에는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [contact us](https://cloudthinker.io/contact)로 연락하세요.
- 셸 접근 권한이 있고 `sshd`에서 공개 키 인증이 활성화된 로그인 사용자.
- 공개 키가 해당 사용자의 `~/.ssh/authorized_keys`에 있는 키 쌍.
- 연결을 추가하는 데 필요한 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참고하세요.

## 설정

<Steps>
  <Step title="전용 키 쌍 만들기">
    다른 것에 영향을 주지 않고 취소할 수 있도록 CloudThinker만 사용하는 키를 생성합니다.

    ```bash
    ssh-keygen -t ed25519 -C "cloudthinker" -f ./cloudthinker_key
    ```

    이 명령은 `cloudthinker_key`(개인 키)와 `cloudthinker_key.pub`(공개 키)를 만듭니다. OpenSSH 또는 PEM 형식의 기존 RSA, ECDSA 키도 사용할 수 있습니다.
  </Step>
  <Step title="서버에서 공개 키 승인">
    ```bash
    ssh-copy-id -i ./cloudthinker_key.pub ubuntu@server.example.com
    ```

    또는 `cloudthinker_key.pub`의 내용을 사용자의 `~/.ssh/authorized_keys`에 직접 추가합니다.
  </Step>
  <Step title="CloudThinker에서 연결 추가">
    **Settings → Workspace → Connections**를 열고 **SSH**를 선택한 뒤 **Connect**를 클릭하고 **Host**, **User**, **Port**, **Private key**를 입력합니다. 키에 암호가 있을 때만 **Passphrase**를 추가합니다. **Connect**를 클릭합니다.

    CloudThinker가 연결하고 서버의 호스트 키를 기록한 뒤 테스트를 실행합니다. 테스트는 보통 30초 안에 끝나며 45초가 지나면 시간 초과됩니다.

    **성공 상태:** 대화 상자에 "SSH connection verified and saved."와 함께 **Connected**가 표시됩니다.
  </Step>
</Steps>

서버마다 별도의 SSH 연결입니다. CloudThinker가 접근할 모든 서버에 대해 마지막 단계를 반복하세요. 프롬프트를 특정 서버로 지정하려면 프롬프트 상자에서 `#`으로 해당 연결을 선택하세요.

## 연결 세부 정보

| 필드 | 필수 | 설명 | 예시 |
|-------|----------|-------------|---------|
| **Host** | 예 | 호스트 이름 또는 IP 주소 | `server.example.com` 또는 `203.0.113.10` |
| **User** | 예 | 셸 접근 권한이 있는 로그인 사용자 | `ubuntu` |
| **Port** | 아니요 | SSH 포트. 기본값은 `22` | `22` |
| **Private key** | 예 | `BEGIN`과 `END` 줄을 포함한 전체 키 | `-----BEGIN OPENSSH PRIVATE KEY-----` |
| **Passphrase** | 아니요 | 암호화된 키에만 사용. 그 외에는 비워 둡니다 | 숨김 |

## 필요 권한

명령은 로그인 사용자로, 정확히 그 사용자의 권한으로 실행됩니다. 그 사용자의 권한이 CloudThinker가 서버에서 할 수 있는 일의 실제 경계입니다.

<Tip>
관심 있는 로그와 경로에 읽기 권한이 있고, 프로덕션 경로에는 쓰기 권한이 없는 non-root 사용자를 CloudThinker용으로 만드세요. 대부분의 상태 확인과 로그 읽기에는 그 이상이 필요하지 않습니다.
</Tip>

명령은 터미널 없이 실행되므로 `sudo` 비밀번호 프롬프트에 응답할 수 없습니다. CloudThinker가 권한이 필요한 명령을 실행하게 하려면 `/etc/sudoers.d/`에서 해당 명령만 비밀번호 없이 허용하세요.

```text
cloudthinker ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
```

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 | 승인 |
|------------|------------------------|----------|
| **시스템 점검** | 디스크, 메모리, CPU, 가동 시간, 프로세스, 서비스 상태 확인 | 아니요 |
| **로그 분석** | 애플리케이션 및 시스템 로그 읽기와 검색 | 아니요 |
| **진단** | 호스트의 장애, 연결성, 구성 조사 | 아니요 |
| **변경** | 서비스 재시작처럼 서버를 변경하는 명령 실행 | 예 |

### 연결 확인

```text
Show uptime, disk usage per filesystem, and the top 5 processes by memory on the server
```

가동 시간, 파일 시스템별 사용량 표, 메모리 사용량이 높은 프로세스 다섯 개가 나와야 합니다.

### 예시 프롬프트

```text
Flag any filesystem above 80% full and list the largest directories on it
Summarize the last 100 lines of /var/log/app/error.log and group them by error type
Is nginx running, and when did it last restart?
```

## 쓰기 권한

읽기 명령은 묻지 않고 실행됩니다. 서버를 변경하는 명령은 Approvals를 거치며, CloudThinker가 요청에 명령을 표시합니다.

<ApprovalDefault />

셸 명령은 자유 형식이며, 어떤 명령이 변경에 해당하는지는 CloudThinker가 판단합니다. 승인 단계는 두 번째 확인으로 여기고, CloudThinker가 절대 해서는 안 되는 일은 로그인 사용자의 권한으로 막으세요.

## 호스트 키 확인

처음 연결할 때 CloudThinker는 서버의 호스트 키를 신뢰하고 기록합니다. 이후의 모든 연결에서 키가 여전히 일치하는지 확인합니다. CloudThinker는 지문(fingerprint)을 표시하지 않으므로, 첫 연결이 올바른 서버에 도달하는지 확인하세요.

키가 바뀌면 연결이 멈추고 **Host key changed**가 표시됩니다. 서버를 다시 구축했거나 호스트 키를 교체한 뒤라면 정상입니다. 새 키를 수락하려면 서버 옆의 방패 아이콘(**Trust new host key**)을 클릭하고 **Trust**로 확인하세요.

<Warning>
예상하지 못한 새 호스트 키는 신뢰하지 마세요. 예상치 못한 변경은 누군가 연결을 가로채고 있다는 뜻일 수 있습니다. 신뢰할 수 있는 콘솔에서 먼저 서버의 지문을 확인하세요.

```bash
for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done
```
</Warning>

## 문제 해결

<Accordion title="Authentication failed">
- 공개 키가 로그인 사용자의 `~/.ssh/authorized_keys`에 있는지 확인하세요.
- **User**가 키가 승인된 계정인지 확인하세요.
- `BEGIN`과 `END` 줄을 포함해 개인 키 전체를 붙여넣으세요.
- 키에 암호가 있으면 **Passphrase**를 입력하세요.
</Accordion>

<Accordion title="Could not reach the host">
- **Host**와 **Port**를 확인하세요.
- 방화벽, 보안 그룹, 허용 목록에서 CloudThinker의 인바운드 SSH를 허용하세요.
- `sshd`가 실행 중이고 해당 포트에서 수신 대기 중인지 확인하세요.
- 45초보다 오래 걸리는 테스트는 같은 안내와 함께 시간 초과됩니다.
</Accordion>

<Accordion title="Host key changed">
재구축이나 키 교체 후라면 정상입니다. 서버에서 지문을 확인한 뒤 **Trust new host key**를 선택하세요. 예상하지 못했다면 신뢰하기 전에 조사하세요.
</Accordion>

<Accordion title="원격 명령이 0이 아닌 코드로 종료됨">
SSH는 동작했지만 서버에서 명령이 실패했습니다. 명령, 경로, 그리고 로그인 사용자에게 실행 권한이 있는지 확인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **전용 키를 사용하세요.** CloudThinker만 사용하는 키는 다른 사람에게 영향을 주지 않고 `authorized_keys`에서 제거할 수 있습니다.
- **키를 교체하세요.** 새 키 쌍을 생성하고 새 공개 키를 `authorized_keys`에 추가합니다. **Settings → Workspace → Connections**를 열고 **SSH**를 선택한 뒤 서버 옆의 연필 아이콘을 클릭하고, **Edit SSH Connection**의 **Rotate private key**에 새 키를 붙여넣은 뒤 **Save**를 클릭합니다. 확인 프롬프트를 실행해 동작하면 서버에서 이전 공개 키를 제거하세요.
- **다시 신뢰하기 전에 확인하세요.** 지문을 확인하기 전까지는 모든 호스트 키 변경을 의심하세요.

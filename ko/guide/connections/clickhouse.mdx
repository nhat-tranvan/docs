ClickHouse를 연결하면 CloudThinker가 데이터베이스와 테이블을 나열하고, 파트 수와 테이블 크기를 확인하고, `system.query_log`에서 느린 쿼리의 순위를 매기고, 분석 SQL로 질문에 답할 수 있습니다. CloudThinker는 HTTP 인터페이스를 통해 ClickHouse 사용자로 로그인하며, 새 연결은 읽기 전용입니다.

<Warning>
ClickHouse에는 승인이 적용되지 않습니다. **Write access**를 **Full access**로 설정하면 쓰기가 누구에게도 묻지 않고 실행됩니다. [Write access](#write-access)를 참고하세요.
</Warning>

---

## 사전 요구 사항

- CloudThinker에서 **HTTP 인터페이스**로 접근할 수 있는 ClickHouse 서버: TLS 사용 시 `8443`, 미사용 시 `8123`. ClickHouse Cloud와 셀프 호스팅 클러스터 모두 작동합니다. 네이티브 TCP 포트(`9000`)는 사용하지 않습니다.
- 전용 사용자를 만들기 위한 ClickHouse 관리자 로그인. ClickHouse Cloud에서는 서비스의 **SQL console**에서 `default` 사용자로 Setup SQL을 실행합니다.
- 연결을 추가하기 위한 CloudThinker 워크스페이스 Admin 역할. [접근 권한 작동 방식](/ko/guide/connections/overview#접근-권한이-작동하는-방식)을 참고하세요.

## 설정

<Steps>
  <Step title="읽기 권한이 있는 전용 사용자 생성">
    관리자로 연결하여 다음을 실행합니다.
    ```sql
    CREATE USER cloudthinker IDENTIFIED BY 'your-secure-password';
    GRANT SELECT ON your_database.* TO cloudthinker;
    GRANT SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT SELECT ON system.tables TO cloudthinker;
    GRANT SELECT ON system.columns TO cloudthinker;
    GRANT SELECT ON system.parts TO cloudthinker;
    GRANT SELECT ON system.query_log TO cloudthinker;
    ```
    ClickHouse Cloud에서는 비밀번호가 서비스의 복잡성 규칙(길이, 대소문자 혼합, 숫자, 특수 문자)을 충족해야 하며, 그렇지 않으면 `CREATE USER`가 실패합니다.

    `system.*` 권한은 테이블 상태와 느린 쿼리에 대한 답변을 가능하게 합니다. 이를 건너뛰면 해당 질문은 실패하지만 스키마 질문은 계속 작동합니다.

    <Warning>
    `system.query_log`에는 `WHERE` 절의 리터럴을 포함한 모든 사용자의 쿼리 전문이 담기며, 여기에 개인 정보가 있을 수 있습니다. 이 권한을 주면 에이전트가 그 쿼리를 읽고 채팅에서 인용할 수 있습니다. 우려된다면 이 권한을 건너뛰세요. 그러면 느린 쿼리 답변이 실패합니다.
    </Warning>

    여러 노드가 있는 셀프 호스팅 클러스터에서는, 클러스터가 접근 저장소를 복제하지 않는 한 이렇게 만든 사용자는 실행한 노드에만 존재합니다. 대신 클러스터 이름으로 다음 버전을 실행하세요.
    ```sql
    CREATE USER cloudthinker ON CLUSTER '<cluster>' IDENTIFIED BY 'your-secure-password';
    GRANT ON CLUSTER '<cluster>' SELECT ON your_database.* TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.tables TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.columns TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.parts TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.query_log TO cloudthinker;
    ```
    `SELECT name FROM clusterAllReplicas('<cluster>', system.users) WHERE name = 'cloudthinker'`로 모든 노드에 사용자가 있는지 확인하세요.
  </Step>
  <Step title="서버에서 사용자를 읽기 전용으로 고정 (권장)">
    **Write access**를 켤 계획이라면 이 단계를 건너뛰세요. 그렇지 않다면 클라이언트가 무엇을 요청하든 ClickHouse 자체가 쓰기를 거부하도록 설정 프로필을 추가합니다.
    ```sql
    CREATE SETTINGS PROFILE cloudthinker_readonly SETTINGS readonly = 1 READONLY;
    ALTER USER cloudthinker SETTINGS PROFILE cloudthinker_readonly;
    ```
    이 프로필은 CloudThinker를 망가뜨리지 않습니다. 읽기는 평소처럼 작동하고 ClickHouse 자체가 모든 쓰기를 거부합니다.
  </Step>
  <Step title="네트워크 접근 열기">
    이 문서에는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의하기](https://cloudthinker.io/contact)를 이용하세요. 그런 다음:
    - **ClickHouse Cloud**: 서비스 **Settings → Security**에서 서비스의 IP 접근 목록에 추가합니다.
    - **셀프 호스팅**: 방화벽이나 보안 그룹에서 해당 IP의 인바운드 `8443`(또는 `8123`)을 허용합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**로 이동하여 **ClickHouse**를 선택하고, [연결 세부 정보](#연결-세부-정보)의 필드를 채우고, **Write access**를 **Read-only (default)**로 둔 채 **Connect**를 클릭합니다.

    CloudThinker가 그 사용자로 `SELECT version()`을 한 번 실행합니다.

    **성공 상태:** ClickHouse에 **Connected** 상태가 표시되고 메시지는 `ClickHouse <version> reachable as cloudthinker`입니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 설명 | 기본값 |
|-------|----------|-------------|---------|
| **Host** | 예 | `https://`와 포트 없이 호스트 이름만. ClickHouse Cloud는 `abc123.ap-southeast-1.aws.clickhouse.cloud` 형태입니다 | |
| **Port** | 예 | HTTP 인터페이스 포트: TLS 사용 시 `8443`, 미사용 시 `8123` | `8443` |
| **Username** | 예 | 전용 사용자. 예: `cloudthinker` | |
| **Password** | 예 | 그 사용자의 비밀번호 | |
| **Use TLS** | 아니요 | 일반 HTTP 대신 HTTPS. 옵션: **Yes**, **No** | **Yes** |
| **Verify the TLS certificate** | 아니요 | 자체 서명 또는 내부 CA 인증서일 때만 **No**로 설정합니다. TLS가 켜져 있을 때만 표시됩니다. 옵션: **Yes (default)**, **No** | **Yes (default)** |
| **Default database** | 아니요 | 쿼리에 데이터베이스가 지정되지 않을 때 사용하는 데이터베이스. 비워 두면 서버 기본값을 사용합니다 | 비어 있음 |
| **Write access** | 아니요 | CloudThinker가 쓸 수 있는지 여부. 옵션: **Read-only (default)**, **Full access** | **Read-only (default)** |
| **Allow DROP and TRUNCATE** | 아니요 | **Full access**에서만 표시됩니다. 옵션: **Blocked (default)**, **Allowed** | **Blocked (default)** |

<Tip>
**Port**와 **Use TLS**는 함께 바꾸세요. `8443`은 TLS 켜짐, `8123`은 TLS 꺼짐과 짝입니다. 맞지 않으면 연결 시 실패합니다.
</Tip>

## 필수 권한

Setup의 권한으로 읽기 전용 작업은 모두 다룹니다. **Write access**를 **Full access**로 설정하는 경우에만, 에이전트가 변경해야 할 데이터베이스에만 쓰기 권한을 추가하세요.

```sql
-- ALTER includes ALTER ... DELETE, DROP PARTITION, and DROP COLUMN, which remove data.
-- See "Blocked protects the table, not the rows" under Write access.
GRANT INSERT, ALTER, CREATE TABLE, CREATE VIEW ON your_database.* TO cloudthinker;
-- Only if the agent should remove tables:
GRANT DROP TABLE, TRUNCATE ON your_database.* TO cloudthinker;
```

<Tip>
`*.*`에 쓰기 권한을 주지 마세요. ClickHouse 권한이 실제 경계입니다. **Write access** 필드는 CloudThinker가 `readonly=1`을 보낼지 여부만 정하며, ClickHouse가 부여하지 않은 권한을 사용자에게 줄 수 없습니다.
</Tip>

## 에이전트 기능

| 기능 | 설명 |
|------------|-------------|
| **Schema discovery** | 엔진, 정렬 키, 행 수, 열 유형과 함께 데이터베이스와 테이블 나열 |
| **Analytical queries** | 집계, 조인, 윈도 함수가 있는 SQL 실행 |
| **Table health** | `system.parts`에서 파트 수, 압축 및 비압축 크기, 인덱스 granularity 확인 |
| **Query investigation** | `system.query_log`에서 느리거나 비용이 큰 쿼리 순위 매기기 |
| **Changes** | **Full access**에서만: 행 삽입, 테이블 변경, 테이블과 뷰 생성 |

`system.query_log`와 `system.parts`는 노드별로 보관됩니다. 복제본이 여러 개인 클러스터에서는 답변이 쿼리를 받은 노드만 다룹니다. 모든 노드를 다루려면 프롬프트에서 요청하세요.

- **셀프 호스팅**: "use `clusterAllReplicas('<cluster>', system.query_log)`"
- **ClickHouse Cloud**: "use `clusterAllReplicas('default', system.query_log)`"

### 연결 확인

```text
List the ClickHouse databases and the tables in each one
```

**성공 상태:** CloudThinker가 테이블, 엔진, 행 수와 함께 데이터베이스를 반환합니다.

### 예시 프롬프트

```text
Which ClickHouse tables are the largest by compressed size, and how many parts does each have?
Show the 10 slowest queries from system.query_log in the last 24 hours, with the user and table for each
Suggest a better sorting key for our largest MergeTree table, based on the queries that hit it
```

## Write access

| Write access | Allow DROP and TRUNCATE | 에이전트가 할 수 있는 일 |
|--------------|-------------------------|------------------------|
| **Read-only (default)** | 숨김 | `SELECT`만. ClickHouse는 그 밖의 것을 오류 `164`(`READONLY`)로 거부합니다 |
| **Full access** | **Blocked (default)** | 승인 단계 없이 `INSERT`, `ALTER`, `CREATE`. `DROP TABLE`과 `TRUNCATE`는 거부됩니다 |
| **Full access** | **Allowed** | 위의 모든 것과 `DROP TABLE`, `TRUNCATE`. 사용자가 그 권한을 가지고 있다면 `DROP DATABASE`도 실행되며, 필수 권한에는 이 권한이 빠져 있습니다 |

**Full access**를 선택하기 전에:

- **Blocked는 행이 아니라 테이블을 보호합니다.** `ALTER TABLE ... DELETE`, `DROP PARTITION`, `DROP COLUMN`은 여전히 실행되며 데이터를 제거합니다. **Full access**는 "에이전트가 데이터를 파괴할 수 있음"으로 취급하세요.
- **아무것도 롤백되지 않습니다.** ClickHouse에는 트랜잭션이 없으므로 복구는 백업에서 복원하는 것을 의미합니다.

**Write access**는 연결 후 잠깁니다. **Edit Instance**에서 **Replace…**를 누르면 저장된 필드를 편집할 수 있지만, **Write access**와 **Use TLS**는 "Reconnect to change."와 함께 회색으로 비활성화됩니다. 변경하려면 ClickHouse 연결을 [연결 해제](/ko/guide/connections/overview#연결-해제)한 뒤 새 **Write access**로 다시 추가하세요.

**Full access**가 켜져 있다면 **Allow DROP and TRUNCATE**는 그 자리에서 전환할 수 있습니다. **Settings → Workspace → Connections**를 열고 **ClickHouse**를 선택한 뒤 인스턴스 행의 연필 아이콘을 클릭하고, **Edit Instance**에서 **Replace…**를 클릭하여 옵션을 고르고, 저장된 비밀번호를 유지하려면 **Password**를 비워 둔 채 **Save and test**를 클릭합니다. 테스트가 실패하면 연결은 이전 설정을 유지합니다.

Setup 2단계의 `READONLY` 프로필을 적용했다면 먼저 해제하세요. 그렇지 않으면 ClickHouse가 계속 쓰기를 거부합니다.

```sql
ALTER USER cloudthinker SETTINGS PROFILE default;
DROP SETTINGS PROFILE cloudthinker_readonly;
```

승인이 적용되지 않는 이유: ClickHouse는 모든 쿼리를 하나의 도구로 실행하므로, CloudThinker가 쓰기를 읽기와 따로 물을 수 없습니다. Rules와 Approval mode는 ClickHouse 쓰기를 보지 못합니다. 대시보드가 읽는 클러스터보다 먼저 스테이징 클러스터에서 **Full access**를 시험해 보세요.

## 비밀번호 교체

1. ClickHouse 사용자에 새 비밀번호를 설정합니다.
   ```sql
   ALTER USER cloudthinker IDENTIFIED BY 'new-secure-password';
   ```
   이전 비밀번호는 즉시 작동을 멈추므로, 2단계를 마칠 때까지 CloudThinker의 쿼리가 실패합니다. 두 단계를 함께 진행하세요.
2. **Settings → Workspace → Connections**를 열고 **ClickHouse**를 선택한 뒤 인스턴스 행의 연필 아이콘을 클릭하고, **Edit Instance**에서 **Replace…**를 클릭합니다. 새 **Password**를 입력하고 **Save and test**를 클릭합니다.

**성공 상태:** 테스트가 통과하고 연결이 **Connected**로 유지됩니다. 테스트가 실패하면 CloudThinker는 이전 설정을 유지하고 오류를 표시합니다.

## 문제 해결

처음 네 제목은 연결 테스트의 메시지와 일치하므로, 이 페이지에서 해당 메시지를 검색할 수 있습니다. 다섯 번째는 ClickHouse 자체 오류 텍스트이고, 여섯 번째는 채팅에서 보이는 증상입니다.

<Accordion title="ClickHouse rejected the username or password">
`SHOW USERS;`로 사용자가 있는지 확인한 뒤, 붙여넣지 말고 비밀번호를 다시 입력하세요. 줄바꿈이 있는 값은 CloudThinker가 서버에 연결하기 전에 거부됩니다. ClickHouse Cloud에서는 콘솔 로그인을 재사용하지 말고 데이터베이스 사용자를 만드세요.
</Accordion>

<Accordion title="ClickHouse is unreachable, or rejected the request path">
- **Port**와 **Use TLS**가 맞아야 합니다: TLS 사용 시 `8443`, 미사용 시 `8123`. `9000`은 HTTP 인터페이스가 아니라 네이티브 TCP 포트입니다.
- **Host**에 `https://` 접두사와 `:port` 접미사가 없어야 합니다.
- ClickHouse Cloud에서는 CloudThinker의 egress IP를 서비스 IP 접근 목록에 추가하세요. 셀프 호스팅이라면 방화벽과, `<listen_host>`가 노출된 인터페이스를 포함하는지 확인하세요.
</Accordion>

<Accordion title="ClickHouse did not answer in time">
ClickHouse Cloud에서는 유휴 서비스가 일시 중지되며, 깨어날 때까지 연결이 시간 초과됩니다. ClickHouse Cloud 콘솔에서 서비스를 깨운 뒤 다시 연결하세요.
</Accordion>

<Accordion title="ClickHouse has no database named ...">
**Default database**가 존재하지 않습니다. 이름은 대소문자를 구분합니다. 철자를 고치거나 필드를 비워 두세요.
</Accordion>

<Accordion title="Cannot execute query in readonly mode">
연결이 기본값인 읽기 전용입니다. 에이전트가 써야 한다면 **Write access**를 **Full access**로 설정하여 다시 연결하세요([Write access](#write-access) 참고). 그래도 실패한다면 서버 쪽 제한입니다. `SHOW CREATE USER cloudthinker;`를 실행하여 `readonly` 설정 프로필이나 누락된 쓰기 권한을 찾으세요.
</Accordion>

<Accordion title="테이블 목록이 비어 있습니다">
사용자에게 개별 테이블만이 아니라 데이터베이스에 대한 `SHOW TABLES`와 `SELECT`, 그리고 `system.tables`에 대한 `SELECT`가 필요합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **스위치보다 권한**: ClickHouse 사용자의 권한이 무엇이 가능한지 결정합니다. **Write access**는 CloudThinker가 무엇을 요청할지만 정합니다.
- **서버 측 읽기 전용**: 절대 쓰면 안 되는 연결에는 Setup 2단계의 `READONLY` 설정 프로필을 유지하세요. 어떤 클라이언트도 이를 해제할 수 없습니다.

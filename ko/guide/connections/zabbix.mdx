Zabbix를 연결하면 CloudThinker 에이전트가 활성 문제를 분류하고, 호스트 메트릭과 로그 아이템을 읽고, 트리거·템플릿·대시보드를 검토하고, 허용한 경우 이벤트를 확인(acknowledge)하거나 유지보수를 예약할 수 있습니다. 이 연결은 API 토큰 또는 사용자 이름과 비밀번호로 Zabbix API에 로그인하며, 에이전트는 해당 Zabbix 사용자에게 허용된 작업만 수행할 수 있습니다.

## 사전 요구 사항

- `https://zabbix.example.com`처럼 CloudThinker에서 인터넷을 통해 접근할 수 있는 Zabbix 프런트엔드. 방화벽으로 보호되거나 비공개로 유지해야 한다면 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
- 사용자, 사용자 그룹, API 토큰을 만들 수 있는 Zabbix Super admin.
- API 토큰을 사용하려면 Zabbix 5.4 이상. 이전 버전은 사용자 이름과 비밀번호를 사용합니다.
- 연결을 추가하는 데 필요한 CloudThinker 워크스페이스의 **Admin** 역할. [역할](/guide/security/roles)을 참조하세요.

## 설정

<Steps>
  <Step title="API 접근 권한이 있는 역할 만들기">
    **Users → User roles**(Zabbix 6.x에서는 **Administration → User roles**)로 이동하여 **Create user role**을 클릭합니다. 이름을 `CloudThinker`로 지정하고, **User type**을 **User**(쓰기가 필요하면 **Admin**, [필수 권한](#필수-권한) 참조)로 설정하고, **Access to API**가 활성화되어 있는지 확인한 다음 **Add**를 클릭합니다.
  </Step>
  <Step title="호스트 그룹 접근 권한이 있는 사용자 그룹 만들기">
    **Users → User groups**(6.x에서는 **Administration → User groups**)로 이동하여 **Create user group**을 클릭합니다. 이름을 `CloudThinker`로 지정합니다. **Host permissions** 탭(6.x에서는 **Permissions**)에서 에이전트가 볼 호스트 그룹을 선택하고 **Read**를 고른 다음 **Add**를 클릭합니다.
  </Step>
  <Step title="사용자 만들기">
    **Users → Users**(6.x에서는 **Administration → Users**)로 이동하여 `CloudThinker` 그룹에 `cloudthinker`라는 사용자를 만듭니다. **Permissions** 탭에서 `CloudThinker` 역할을 선택한 다음 **Add**를 클릭합니다.
  </Step>
  <Step title="API 토큰 만들기 (Zabbix 5.4+)">
    **Users → API tokens**(Zabbix 5.4~6.x에서는 **Administration → General → API tokens**)로 이동하여 **Create API token**을 클릭합니다. `cloudthinker` 사용자를 선택하고, 교체 일정에 맞게 **Expires at**을 설정한 다음 **Add**를 클릭합니다. 토큰을 복사합니다. Zabbix는 토큰을 한 번만 보여 줍니다.

    5.4 미만 버전에서는 이 단계를 건너뛰고 사용자의 비밀번호를 사용하세요.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Zabbix**를 선택한 다음 다음을 입력합니다.

    - **ZABBIX_URL**: `https://zabbix.example.com` 같은 Zabbix 프런트엔드 URL.
    - **ZABBIX_AUTH_TYPE**: **API Token**으로 바꿉니다. 기본값은 **Username & Password**이지만, 토큰은 비밀번호를 바꾸지 않고도 만료시키거나 취소할 수 있습니다.
    - **ZABBIX_TOKEN**, 또는 **ZABBIX_USERNAME**과 **ZABBIX_PASSWORD**: 위 단계에서 얻은 자격 증명. CloudThinker는 선택한 인증 유형의 필드만 표시합니다.

    **Connect**를 클릭합니다. CloudThinker가 로그인하고 호스트를 나열하여 자격 증명을 확인합니다.

    **성공 상태:** 연결에 **Connected** 상태가 표시됩니다. 이는 로그인만 증명하므로, 새 채팅에서 [연결 확인](#연결-확인)의 프롬프트를 실행하여 예상한 호스트가 보이는지 확인하세요.
  </Step>
</Steps>

## 연결 세부 정보

양식에는 아래에 적힌 그대로 필드 이름이 표시됩니다.

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **ZABBIX_URL** | Zabbix 프런트엔드 URL | `https://zabbix.example.com` |
| **ZABBIX_AUTH_TYPE** | **Username & Password**(기본값) 또는 **API Token** | **API Token** |
| **ZABBIX_TOKEN** | Zabbix API 토큰. **API Token**일 때 표시 | **API tokens**에서 |
| **ZABBIX_USERNAME** | Zabbix 사용자 이름. **Username & Password**일 때 표시 | `cloudthinker` |
| **ZABBIX_PASSWORD** | 해당 사용자의 비밀번호. **Username & Password**일 때 표시 | |

## 필수 권한

Zabbix는 두 곳에서 접근을 결정합니다. 사용자의 역할(어떤 종류의 사용자인지, API를 사용할 수 있는지)과 사용자 그룹(어떤 호스트 그룹을 읽거나 변경할 수 있는지)입니다. 에이전트는 사용자 그룹이 읽을 수 있는 호스트 그룹의 호스트만 볼 수 있습니다.

| 에이전트에게 원하는 작업 | 역할 | 호스트 그룹 권한 |
|--------------------|------|-----------------------|
| 문제, 메트릭, 로그, 트리거, 템플릿, 대시보드 조사 | **User** 유형, API 접근 활성화 | **Read** |
| 이벤트 확인, 호스트와 트리거 활성화 또는 비활성화, 템플릿 연결, 유지보수 창 생성까지 | **Admin** 유형, API 접근 활성화 | **Read-write** |
| 호스트 그룹 또는 사용자 생성까지 | **Super admin** 유형 | 전체 |

<Warning>
Super admin은 피하세요. 호스트 그룹 권한을 무시하고 사용자를 만들고 변경할 수 있으므로, 사람이나 AI 판단에 의한 잘못된 승인 하나가 모든 호스트와 계정에 영향을 줄 수 있습니다. 꼭 사용해야 한다면 **Manual**을 선택하여 모든 변경을 사람이 승인하도록 하세요. Zabbix 사용자 생성에 대한 **Deny** [Rule](/guide/approvals/rules)을 사용하면 그 작업 하나를 아예 차단할 수 있습니다.
</Warning>

<Tip>
User 유형 역할과 관심 있는 호스트 그룹의 Read로 시작하세요. 모든 쓰기는 여전히 [Approvals](/guide/approvals/overview)를 거치지만, 읽기 전용 Zabbix 사용자라면 잘못된 승인이든 자동 승인이든 아무것도 바꿀 수 없습니다.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 |
|------------|--------------------|
| **Discovery** | Zabbix 버전, 호스트, 호스트 그룹, 활성 문제, 템플릿 보고 |
| **Problems and events** | 심각도, 호스트, 호스트 그룹별로 활성 문제를 나열하고 이벤트 내역 읽기 |
| **Metrics and logs** | 호스트의 아이템을 나열하고, 최근 값을 읽고, 로그 아이템 tail |
| **Configuration** | 트리거, 템플릿, 액션, 유지보수 창, 대시보드, 사용자를 읽고 호스트 또는 템플릿 구성 내보내기 |
| **Writes (through Approvals)** | 이벤트 확인, 호스트 생성·업데이트·활성화·비활성화·삭제, 트리거와 액션 활성화 또는 비활성화, 템플릿 연결 또는 해제, 유지보수 창 생성 또는 삭제, 호스트 그룹과 사용자 생성, 구성 가져오기 |

에이전트는 Zabbix의 심각도 척도를 사용합니다: Not classified, Information, Warning, Average, High, Disaster.

<ApprovalDefault />

따라서 기본 모드에서는 에이전트가 사람이 보지 않은 상태로 유지보수 창을 만들거나, 호스트를 삭제하거나, 사용자를 만들 수 있습니다. **Manual**을 선택하면 모든 변경을 사람이 승인합니다. **Ask first** [Rule](/guide/approvals/rules)을 사용하면 대기를 해당 작업으로만 좁힐 수 있습니다. 채팅에서 `Propose an Ask first Rule for maintenance windows, host deletes and user creation on the Zabbix connection`이라고 요청한 다음, **Settings → Workspace → Autonomy → Rules**의 **Needs review**에서 이를 수락하세요.

<Warning>
에이전트가 만든 유지보수 창은 즉시 시작되며, 끝날 때까지 해당 호스트의 알림이 억제됩니다. 미래 시작 시간을 지정할 수 없으므로 작업이 시작될 때 요청하세요. 승인하기 전에 승인 요청에서 호스트 목록과 기간을 확인하세요. 호스트 삭제나 데이터와 함께 템플릿 연결을 해제하는 작업은 되돌릴 수 없습니다.
</Warning>

### 연결 확인

새 채팅에서 CloudThinker에게 요청합니다.

```text
Run Zabbix discovery and summarize the version, host count, host groups, and active problems by severity
```

Zabbix 서버 버전, 샘플이 포함된 호스트 수, 호스트 그룹, 심각도별로 그룹화된 활성 문제가 표시됩니다. 호스트가 누락되었다면 사용자 그룹이 해당 호스트 그룹을 읽을 수 없는 것입니다.

### 예시 프롬프트

```text
List active Zabbix problems at High or Disaster and tell me which hosts they're on
Is db-prod-01 running out of disk? Show the trend from its recent disk values
Schedule a 2-hour Zabbix maintenance window for the hosts in Database servers
```

마지막 프롬프트에는 해당 호스트 그룹에 **Read-write**가 있는 Admin 유형 역할이 필요하며, 먼저 [Approvals](/guide/approvals/overview)를 거칩니다. **Manual**에서는 사람을 기다리고, 기본 Auto 모드에서는 AI 판단으로 묻지 않고 실행될 수 있습니다.

## 문제 해결

<Accordion title="Failed to connect to Zabbix">
CloudThinker가 로그인하거나 호스트를 나열하지 못했습니다. **ZABBIX_URL**이 프런트엔드 주소이고 CloudThinker에서 접근 가능한지, **ZABBIX_AUTH_TYPE**이 입력한 자격 증명과 일치하는지, 사용자의 역할에 API 접근이 활성화되어 있는지 확인하세요.
</Accordion>

<Accordion title="401 또는 세션 만료">
토큰이 만료되었거나 삭제되었거나, 비밀번호가 변경되었습니다. **API tokens**에서 새 토큰을 만들어 **ZABBIX_TOKEN**을 업데이트하거나 비밀번호를 업데이트하세요.
</Accordion>

<Accordion title="호스트 또는 문제가 누락됨">
사용자 그룹에 해당 호스트 그룹의 권한이 없어 Zabbix가 그 호스트를 제외합니다. 사용자 그룹의 권한에서 해당 호스트 그룹에 **Read**를 부여하세요.
</Accordion>

<Accordion title="쓰기가 권한 오류(403)로 실패함">
사용자가 User 유형 역할이거나 호스트 그룹에 **Read**만 있습니다. 에이전트가 그 변경을 하게 하려면 역할을 Admin 유형으로 바꾸고 **Read-write**를 부여하세요.
</Accordion>

<Accordion title="429, 500 또는 503 오류">
Zabbix API가 속도 제한 중이거나, 실패하고 있거나, 유지보수 중입니다. 1분 정도 기다린 다음 호스트 하나나 호스트 그룹 하나로 범위를 좁힌 질문을 하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **API 토큰 권장**: 토큰은 한 사용자에게 속하고, 자체 만료일이 있으며, 비밀번호를 바꾸지 않고 취소할 수 있습니다.
- **호스트 그룹으로 범위 지정**: CloudThinker 사용자 그룹에는 에이전트에게 필요한 호스트 그룹에만 권한을 부여하세요.

MySQL 데이터베이스를 연결하면 CloudThinker 에이전트가 SQL을 실행하여 스키마, 인덱스, 테이블 상태, 느린 쿼리를 검사할 수 있습니다. CloudThinker에는 전용 데이터베이스 사용자의 연결 URL(`MYSQL_URL`) 하나를 제공합니다. 에이전트는 해당 사용자의 권한이 허용하는 작업을 할 수 있으며, 모든 쓰기는 먼저 [Approvals](/guide/approvals/overview)를 거칩니다.

## 사전 요구 사항

- 자체 호스팅 MySQL, Amazon RDS for MySQL, Cloud SQL for MySQL처럼 CloudThinker가 인터넷에서 접근할 수 있는 MySQL 엔드포인트. 에이전트는 CloudThinker Cloud에서 연결하므로 `localhost`와 비공개 주소는 사용자의 네트워크가 아니라 그곳에서 해석됩니다. [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
- `CREATE USER`와 `GRANT`를 실행할 수 있는 관리자 계정.
- 느린 쿼리 분석을 원한다면 Performance Schema가 켜져 있어야 합니다. 자체 호스팅 MySQL 5.7 이상에서는 기본적으로 켜져 있습니다. Amazon RDS에서는 파라미터 그룹의 `performance_schema` 파라미터에 따라 다릅니다.

## 설정

<Steps>
  <Step title="전용 사용자 생성">
    관리자로 연결하여 CloudThinker용 사용자를 만듭니다. `%`는 사용자가 모든 호스트에서 로그인할 수 있게 합니다. CloudThinker로 고정하려면 대신 egress IP마다 `'cloudthinker_readonly'@'203.0.113.10'`처럼 한 번씩 만들고, 각각에 대해 아래 권한 부여를 실행합니다. 이 문서는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의](https://cloudthinker.io/contact)하세요.

    ```sql
    CREATE USER 'cloudthinker_readonly'@'%' IDENTIFIED BY '<secure-password>';
    ```
  </Step>
  <Step title="읽기 권한 부여">
    분석할 데이터베이스에 대한 읽기 권한과, 에이전트가 세션 및 쿼리 통계에 필요한 모니터링 권한을 부여합니다:

    ```sql
    GRANT SELECT, SHOW VIEW ON your_database.* TO 'cloudthinker_readonly'@'%';
    GRANT PROCESS ON *.* TO 'cloudthinker_readonly'@'%';
    GRANT SELECT ON performance_schema.* TO 'cloudthinker_readonly'@'%';
    ```

    `GRANT`는 즉시 적용되므로 `FLUSH PRIVILEGES`는 필요하지 않습니다. 복제 확인을 추가하려면 [필요 권한](#필요-권한)을 참조하세요.
  </Step>
  <Step title="Performance Schema 확인">
    ```sql
    SHOW VARIABLES LIKE 'performance_schema';
    ```

    **성공 상태:** 값이 `ON`입니다. `OFF`라면 `my.cnf`의 `[mysqld]` 아래에 `performance_schema = ON`을 설정하고 MySQL을 다시 시작합니다. RDS나 Cloud SQL에서는 파라미터 그룹 또는 데이터베이스 플래그에서 변경합니다. 이 파라미터는 정적이므로 재부팅한 후에만 적용됩니다.
  </Step>
  <Step title="네트워크 접근 허용">
    방화벽, 보안 그룹, 또는 승인된 네트워크 목록에서 CloudThinker의 egress IP로부터 MySQL 포트(기본값 `3306`)로 들어오는 연결을 허용합니다. 이 연결에는 private-link 옵션이 없으므로, 비공개 네트워크에서만 수신하는 데이터베이스는 먼저 접근 가능한 엔드포인트가 필요합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **MySQL**을 선택한 다음 세부 정보 패널에서 **Connect**를 클릭합니다. 대화상자에서 필요하면 **Alias**와 **Description**을 변경합니다(여러 데이터베이스를 연결할 때 에이전트는 설명을 읽고 올바른 데이터베이스를 선택합니다). URL을 **MYSQL_URL**에 붙여넣고 **Connect**를 클릭합니다:

    ```text
    mysql://cloudthinker_readonly:<secure-password>@db.example.com:3306/your_database
    ```

    **성공 상태:** 연결이 **Connecting**과 **Verifying**을 거쳐 **Connected**로 표시됩니다. 그런 다음 CloudThinker가 연결을 읽기 전용으로 깊이 살펴보는 채팅을 엽니다("Often takes about 15 min. You can leave the chat."). 나중에 다시 실행하려면 카드의 **More** 메뉴를 열고 **Try in chat**을 선택합니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 설명 | 예시 |
|-------|----------|-------------|---------|
| **Alias** | 아니요 | 이 데이터베이스의 짧은 이름. `mysql-1`처럼 다음으로 사용 가능한 별칭이 미리 채워집니다 | `prod-db` |
| **Description** | 아니요 | 이 데이터베이스가 무엇인지. 에이전트는 이를 읽고 인스턴스 중에서 선택합니다 | `Production orders database` |
| **MYSQL_URL** | 예 | 사용자, 비밀번호, 호스트, 포트, 데이터베이스를 포함한 전체 연결 URL | `mysql://cloudthinker_readonly:<password>@db.example.com:3306/shop` |

비밀번호에 `@`, `:`, `/`, `#`이 포함되어 있다면 URL 인코딩합니다(예: `@`는 `%40`이 됩니다). 그렇지 않으면 URL을 파싱할 수 없습니다.

## 필요 권한

원하는 기능에 필요한 권한만 부여합니다.

| 에이전트에게 원하는 작업 | 부여할 권한 |
|--------------------|-------|
| 스키마, 테이블, 인덱스 읽기 | `SELECT, SHOW VIEW ON your_database.*` |
| 활성 세션과 실행 중인 쿼리 보기 | `PROCESS ON *.*` |
| 느린 쿼리와 인덱스 사용 찾기 | `SELECT ON performance_schema.*` |
| 복제본 상태와 지연 확인 | `REPLICATION CLIENT ON *.*` |

<Tip>
사용자를 읽기 전용으로 유지하세요. 쓰기가 필요한 워크플로가 없다면 `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `ALL PRIVILEGES`를 절대 부여하지 마세요. [쓰기 권한](#쓰기-권한)을 참조하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 |
|------------|--------------------|
| **Schema inspection** | 데이터베이스와 테이블을 나열하고, 열 유형, 키, 테이블 크기를 읽습니다 |
| **Index review** | 누락되었거나, 사용되지 않거나, 중복된 인덱스를 찾습니다 |
| **Slow queries** | Performance Schema에서 총 지연 시간과 평균 지연 시간으로 문의 순위를 매깁니다 |
| **Table health** | 테이블별 행 수, 데이터 및 인덱스 크기, 여유 공간을 확인합니다 |
| **Sessions and replication** | 실행 중인 세션과 긴 쿼리를 나열하고, 복제본 지연을 확인합니다(`REPLICATION CLIENT` 필요) |

### 연결 검증

```text
List the tables in the connected MySQL database with their row counts and sizes
```

이름, 대략적인 행 수, 데이터 및 인덱스 크기가 담긴 표가 표시됩니다. 누락된 권한을 지목하는 오류는 어떤 권한을 추가해야 하는지 알려 줍니다.

### 예시 프롬프트

```text
Which 10 queries spend the most total time on MySQL, and which indexes would help them?
Find indexes that haven't been used since the last restart
Is anything blocking right now? Show long-running sessions and what they're waiting on
```

## 쓰기 권한

CloudThinker는 에이전트가 보내는 각 SQL 문을 실행하기 전에 분류합니다.

- `SELECT`, `SHOW`, `DESCRIBE`, `EXPLAIN`, 읽기 전용 `WITH` 문은 묻지 않고 실행됩니다.
- `INSERT`, `UPDATE`, `ALTER` 같은 그 밖의 모든 문은 쓰기로 간주되어 [Approvals](/guide/approvals/overview)를 거칩니다.
- `DELETE`, `DROP`, `TRUNCATE`는 파괴적인 작업으로 간주됩니다. [규칙](/guide/approvals/rules)으로 먼저 묻거나 거부할 수 있습니다.
- 승인된 문이라도 사용자의 권한이 허용하지 않으면 실패합니다. 읽기 전용 사용자가 확실한 차단 장치입니다.

## 문제 해결

<Accordion title="연결 거부 또는 시간 초과">
CloudThinker가 호스트에 접근할 수 없습니다. **MYSQL_URL**의 호스트와 포트가 공개되어 있거나 달리 접근 가능한지, 방화벽이나 보안 그룹이 CloudThinker를 허용하는지, `my.cnf`의 `bind-address`가 `127.0.0.1`이 아닌지 확인합니다. RDS에서는 인스턴스가 공개적으로 접근 가능하거나 네트워크 설정을 통해 접근 가능해야 합니다.
</Accordion>

<Accordion title="Access denied for user">
사용자, 비밀번호 또는 호스트 부분이 일치하지 않습니다. `'cloudthinker_readonly'@'localhost'`로 만든 사용자는 원격으로 로그인할 수 없으므로 `'%'` 또는 CloudThinker의 주소 범위로 만듭니다. 또한 **MYSQL_URL**에서 비밀번호가 URL 인코딩되어 있는지 확인합니다.
</Accordion>

<Accordion title="SELECT command denied 또는 느린 쿼리 데이터 없음">
에이전트가 시도한 작업에 대한 권한이 사용자에게 없습니다. 느린 쿼리의 경우 `SELECT ON performance_schema.*`를 부여하고 `SHOW VARIABLES LIKE 'performance_schema'`가 `ON`을 반환하는지 확인합니다. Performance Schema 통계는 재시작 시 초기화되므로, 방금 재시작한 서버에는 기록이 거의 없습니다.
</Accordion>

<Accordion title="Unknown database">
**MYSQL_URL** 끝의 데이터베이스 이름이 존재하지 않거나 사용자가 볼 수 없습니다. 해당 사용자로 `SHOW DATABASES;`를 실행하고 이름을 수정합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **권한을 하나의 데이터베이스로 제한**: 에이전트가 `mysql` 시스템 스키마나 다른 앱의 데이터를 읽지 못하도록 `*.*`가 아니라 `your_database.*`에 `SELECT`를 부여합니다.
- **서버에서 TLS 요구**: 서버가 지원한다면 사용자에 `REQUIRE SSL`(`ALTER USER ... REQUIRE SSL`)을 설정하여 자격 증명과 결과가 전송 중에 암호화되도록 합니다.

SigNoz Cloud 또는 셀프 호스팅 SigNoz 인스턴스를 연결하면 CloudThinker 에이전트가 서비스에서 가장 느린 작업의 순위를 매기고, 로그를 검색하고 그룹화하고, 전체 트레이스 워터폴을 열고, 메트릭을 쿼리하고, 알림 규칙과 그 내역을 검토할 수 있습니다. CloudThinker에는 SigNoz 기본 URL과 Service Account API 키, 두 가지 값을 제공합니다. 설정 방법은 SigNoz Cloud와 셀프 호스팅이 동일합니다.

## 사전 요구 사항

- 텔레메트리를 보내는 계측된 서비스가 하나 이상 있는 SigNoz Cloud 또는 셀프 호스팅 SigNoz 인스턴스. SigNoz는 애플리케이션의 텔레메트리로 서비스를 만들기 때문에 에이전트가 대신 서비스를 만들 수 없습니다.
- Service Account와 그 API 키를 만들 수 있는 SigNoz-Admin 역할의 SigNoz 사용자.
- SigNoz 기본 URL: SigNoz Cloud는 `https://<your-tenant>.signoz.cloud`, 셀프 호스팅은 `https://signoz.internal.example.com`처럼 SigNoz를 여는 주소입니다.
- 셀프 호스팅 SigNoz의 경우: 인스턴스가 CloudThinker Cloud의 연결을 허용해야 합니다. CloudThinker의 이그레스 IP를 허용 목록에 추가하려면 최신 목록이 필요합니다. 이 문서는 CloudThinker의 이그레스 IP 목록을 게시하지 않으므로 CloudThinker 담당자에게 문의하거나 [문의하기](https://cloudthinker.io/contact)를 이용하세요. 다른 방법은 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
- 연결을 추가하는 데 필요한 CloudThinker 워크스페이스의 **Admin** 역할. [역할](/guide/security/roles)을 참조하세요.

## 설정

<Steps>
  <Step title="Service Account 만들기">
    SigNoz에서 **Settings → Service Accounts**를 열고 **New Service Account**를 클릭한 다음 `cloudthinker`처럼 나중에 알아볼 수 있는 이름을 지정합니다. 단계는 SigNoz Cloud와 셀프 호스팅에서 동일합니다.
  </Step>
  <Step title="역할 선택">
    계정의 **Overview** 탭에서 **Roles** 드롭다운으로 가장 좁은 역할을 선택합니다.

    | 에이전트에게 원하는 작업 | 역할 |
    |--------------------|------|
    | 서비스, 로그, 트레이스, 메트릭, 대시보드, 알림 조사 | **SigNoz-Viewer** |
    | 대시보드와 알림의 생성, 업데이트, 삭제까지 | **SigNoz-Editor** |
    | 저장된 뷰와 알림 채널 관리까지 | **SigNoz-Admin** |

    키를 만들기 전에 **Save**를 클릭합니다. SigNoz-Admin은 사용자, 역할, 서비스 계정도 관리할 수 있으므로 필요할 때만 선택하세요.
  </Step>
  <Step title="API 키 만들기">
    계정의 **Keys** 탭을 열고 **Add Key**를 클릭한 다음 이름(예: `cloudthinker-key`)을 지정하고, 정책상 필요하면 만료일을 설정하고, 키를 복사합니다. SigNoz는 키를 한 번만 보여 줍니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **SigNoz**를 선택합니다. 다음을 입력합니다.

    - **SIGNOZ_URL**: 기본 URL만 입력합니다(예: `https://<your-tenant>.signoz.cloud`). `/api/v1`이나 다른 경로를 추가하지 마세요.
    - **SIGNOZ_API_KEY**: 복사한 키.
    - **LOG_LEVEL**: **Info**로 둡니다. 연결이 CloudThinker 진단 로그에 기록하는 상세 수준을 설정하며, 지원팀이 문제 해결 시 사용합니다.

    **Connect**를 클릭합니다.

    **성공 상태:** SigNoz에 **Connected**가 표시됩니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 설명 | 예시 |
|-------|----------|-------------|---------|
| **SIGNOZ_URL** | 예 | 경로가 없는 인스턴스 기본 URL | `https://<your-tenant>.signoz.cloud` |
| **SIGNOZ_API_KEY** | 예 | Service Account API 키 | 계정의 **Keys** 탭에서 |
| **LOG_LEVEL** | 아니요 | 지원팀이 사용하는 CloudThinker 내부 연결 로그의 상세 수준. 기본값 **Info** | **Info** |

## 필수 권한

에이전트는 Service Account의 역할이 허용하는 작업만 정확히 수행할 수 있으며, SigNoz가 이를 강제합니다.

- **SigNoz-Viewer**는 아래 기능 표의 모든 읽기를 다룹니다.
- **SigNoz-Editor**는 대시보드와 알림 쓰기를 추가합니다. SigNoz는 저장된 뷰나 알림 채널에 대한 Editor 접근을 문서화하지 않으므로, 이 작업에는 SigNoz-Admin을 사용하세요.
- **SigNoz-Admin**은 모든 쓰기와 함께 SigNoz의 사용자, 역할, 서비스 계정 관리를 추가합니다.

<ApprovalDefault />

[Rule](/guide/approvals/rules)을 사용하면 CloudThinker가 쓰기 전에 먼저 묻거나 쓰기를 아예 거부하도록 할 수 있습니다.

<Tip>
SigNoz-Viewer로 시작하세요. 대시보드와 알림을 변경하려면 SigNoz-Editor로, 에이전트가 저장된 뷰나 채널을 대신 관리하게 하려는 경우에만 SigNoz-Admin으로 바꾸세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 | 승인 |
|------------|--------------------|----------|
| **Services** | 계측된 서비스 목록을 조회하고 서비스의 상위 작업을 지연 시간순으로 정렬 | 아니요 |
| **Logs** | 심각도 같은 필터로 로그를 검색하고 서비스 같은 필드로 집계 | 아니요 |
| **Traces** | 트레이스를 검색하고 집계하며, 트레이스 ID로 전체 트레이스 워터폴 열기 | 아니요 |
| **Metrics** | 메트릭 목록을 조회하고 시계열 쿼리 실행 | 아니요 |
| **Dashboards** | 대시보드와 템플릿 목록을 조회하고 대시보드의 전체 정의 읽기 | 아니요 |
| **Alerts** | 알림 규칙을 상태와 함께 나열하고 규칙의 상태 변경 내역 읽기 | 아니요 |
| **Saved views and channels** | 저장된 쿼리 뷰와 알림 채널 읽기 | 아니요 |
| **Writes** | 알림, 대시보드, 저장된 뷰, 알림 채널을 생성, 업데이트, 삭제하고 JSON에서 대시보드 가져오기. SigNoz-Editor(대시보드, 알림) 또는 SigNoz-Admin(저장된 뷰, 채널) 필요 | Approvals를 거침 |

로그, 트레이스, 메트릭 검색은 항상 시간 범위를 대상으로 실행됩니다. 에이전트는 최근 15분으로 시작하고 결과가 없으면 범위를 넓히므로, 특정 기간이 중요하다면 프롬프트에 범위를 지정하세요.

<Warning>
SigNoz 삭제는 되돌릴 수 없습니다. 삭제된 알림은 내역을 잃고, 알림 채널을 삭제하면 그 채널로 라우팅되던 알림은 보낼 곳이 없어집니다. 에이전트는 업데이트나 삭제 전에 현재 레코드를 보여 주므로, 승인하기 전에 읽어 보세요.
</Warning>

### 연결 확인

```text
List my SigNoz services, dashboards, and alert rules, and tell me which alerts are firing
```

서비스, 대시보드, 알림 규칙의 개수와 샘플, 그리고 현재 발생 중인 알림 수가 표시됩니다.

### 예시 프롬프트

```text
What are the slowest operations for the checkout service over the last hour?
Search ERROR logs from the last 30 minutes and group them by service
Review my SigNoz alert rules and flag any with no notification channel
```

## 문제 해결

<Accordion title="모든 요청이 404를 반환함">
**SIGNOZ_URL** 끝에 경로가 있습니다. `/api/v1` 없이 `https://<your-tenant>.signoz.cloud`처럼 기본 URL만 설정하세요.
</Accordion>

<Accordion title="401 Unauthorized">
키가 잘못되었거나, 만료되었거나, 취소되었습니다. Service Account의 **Keys** 탭에서 새 키를 만들고 **SIGNOZ_API_KEY**를 업데이트하세요.
</Accordion>

<Accordion title="403 Forbidden">
Service Account의 역할이 해당 작업을 허용하지 않습니다. SigNoz-Viewer 키는 모든 쓰기에서 이 오류를 반환합니다. SigNoz는 저장된 뷰와 알림 채널에 대한 Editor 접근을 문서화하지 않으므로, SigNoz-Editor 키는 이 쓰기에서 이 오류를 반환할 수 있습니다. 에이전트가 그 변경을 하게 하려면 SigNoz에서 역할을 변경하세요.
</Accordion>

<Accordion title="로그 또는 트레이스 검색 결과가 비어 있음">
검색한 범위에서 일치하는 항목이 없습니다. 최근 6시간처럼 더 넓은 범위를 요청하거나, 필터를 제거한 다음 한 절씩 다시 추가하세요.
</Accordion>

<Accordion title="429 또는 503 오류">
SigNoz 인스턴스가 속도 제한 중이거나 재시작 중입니다. 1분 정도 기다린 후 다시 요청하세요. 셀프 호스팅 SigNoz에서는 쿼리 서비스의 상태를 확인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **CloudThinker 전용 Service Account 하나**: 팀원의 키를 재사용하지 마세요. 전용 계정이 있으면 다른 사람의 접근에 영향을 주지 않고 CloudThinker의 접근을 취소할 수 있습니다.
- **키 만료일 설정**: 만료되기 전에 키를 교체하고 **SIGNOZ_API_KEY**를 업데이트하세요. 그렇지 않으면 연결이 401 오류로 중단됩니다.

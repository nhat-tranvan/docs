AppDynamics(Cisco) Controller를 연결하면 CloudThinker 에이전트가 애플리케이션, 티어, 노드, 비즈니스 트랜잭션을 나열하고, 가장 느리거나 오류가 많은 트랜잭션의 순위를 매기고, 활성 헬스 룰 위반을 분류하고, 느린 요청이 데이터베이스, 외부 호출, 큐, 또는 자체 코드 중 어디에서 시간을 썼는지 보여 줄 수 있습니다. 이 연결은 AppDynamics **API client**(OAuth2 클라이언트 자격 증명)로 로그인하며, 에이전트가 Controller에 실행하는 모든 명령은 읽기입니다.

## 사전 요구 사항

- 관심 있는 애플리케이션을 모니터링하는 AppDynamics Controller(SaaS 또는 온프레미스).
- API 클라이언트를 만들 수 있는 Controller 관리자 권한.
- Controller가 온프레미스라면: CloudThinker Cloud의 HTTPS를 허용해야 합니다. 이 문서에는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의하기](https://cloudthinker.io/contact)를 이용하세요. 다른 방법은 [사설 서비스에 접근하기](/ko/guide/connections/overview#비공개-서비스-접근)를 참고하세요.

## 설정

<Steps>
  <Step title="Controller URL과 계정 이름 기록">
    Controller에 로그인하여 기본 주소를 복사합니다. 예: `https://myaccount.saas.appdynamics.com`. `/controller` 같은 경로는 빼세요.

    SaaS에서 계정 이름은 보통 서브도메인입니다(예시에서는 `myaccount`). **Settings → License**에서도 찾을 수 있습니다.
  </Step>
  <Step title="API 클라이언트 생성">
    **Settings → Administration → API Clients**로 이동하여 **Create**를 클릭합니다.

    - **Client Name**: `cloudthinker`
    - **Description**: `Read-only access for CloudThinker agents`
    - **Roles**: 에이전트가 읽어야 할 애플리케이션을 볼 수 있는 보기 전용 역할

    시크릿을 생성하고 즉시 복사하세요. AppDynamics는 한 번만 표시합니다.

    토큰 만료는 기본값으로 두세요. CloudThinker는 필요할 때마다 새 단기 토큰을 요청하므로 이 설정은 연결에 영향을 주지 않습니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **AppDynamics**를 선택합니다. 네 필드를 모두 채웁니다.

    - **APPD_CONTROLLER_URL**: Controller 기본 URL
    - **APPD_ACCOUNT_NAME**: 계정 이름
    - **APPD_CLIENT_NAME**: `cloudthinker` 같은 클라이언트 이름만
    - **APPD_CLIENT_SECRET**: 복사한 시크릿

    **Connect**를 클릭합니다. CloudThinker가 이 자격 증명으로 Controller에 테스트 호출을 실행합니다.

    **성공 상태:** AppDynamics에 **Connected**가 표시됩니다. 아래 확인 프롬프트를 실행하여 클라이언트가 애플리케이션을 볼 수 있는지 확인하세요.
  </Step>
</Steps>

<Warning>
클라이언트 이름은 `@<account>` 없이 입력하세요. CloudThinker가 OAuth2 클라이언트 ID를 `<APPD_CLIENT_NAME>@<APPD_ACCOUNT_NAME>`으로 만들어 주므로, 이름 필드에 `cloudthinker@myaccount`를 넣으면 `cloudthinker@myaccount@myaccount`가 되어 401로 실패합니다.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **APPD_CONTROLLER_URL** | Controller 기본 URL, HTTPS | `https://myaccount.saas.appdynamics.com` |
| **APPD_ACCOUNT_NAME** | AppDynamics 계정 이름 | `myaccount` |
| **APPD_CLIENT_NAME** | 계정 접미사를 뺀 API 클라이언트 이름 | `cloudthinker` |
| **APPD_CLIENT_SECRET** | API 클라이언트 시크릿 | `<your-client-secret>` |

네 필드 모두 필수입니다. 워크스페이스에는 AppDynamics 연결이 하나만 있으므로 Controller 하나에 접근합니다.

## 필수 권한

API 클라이언트에 에이전트가 읽어야 할 애플리케이션으로 범위가 정해진 보기 전용 역할을 부여하세요. 에이전트가 볼 수 있어야 하는 것:

| 데이터 | 용도 |
|------|----------|
| 애플리케이션, 티어, 노드 | 탐색과 올바른 대상 지정 |
| 비즈니스 트랜잭션 | 느리고 오류가 나는 트랜잭션 순위 매기기 |
| 메트릭 | 응답 시간, 분당 호출 수, 분당 오류 수, 백엔드 및 외부 호출 지연, 노드 CPU |
| 헬스 룰과 위반 | 설정된 임계값과 현재 위반된 임계값 |
| 이벤트 | 애플리케이션의 최근 오류와 변경 |
| 스냅샷 | 데이터베이스, 외부, 큐 호출에 대한 요청 단위 드릴다운 |

에이전트는 AppDynamics 구성을 절대 변경하지 않으므로, 이 역할에서 모든 구성 및 관리 권한을 빼 두세요. 결과에서 애플리케이션이 빠져 있다면 역할이 그 애플리케이션을 볼 수 없는 것입니다.

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 | 승인 |
|------------|--------------------|----------|
| **Discovery** | Controller 요약: 애플리케이션, 티어, 노드, 열린 헬스 룰 위반 | 아니요 |
| **Application health** | 기간 동안 애플리케이션의 평균 응답 시간, 분당 호출 수, 분당 오류 수, 최종 사용자 응답 시간 조회 | 아니요 |
| **Transaction hotspots** | 응답 시간, 분당 오류 수 또는 느린 호출로 비즈니스 트랜잭션 순위 매기기 | 아니요 |
| **Violation triage** | 애플리케이션의 열린 위반을 최근 이벤트, 관련 티어와 함께 심각도로 필터링하여 나열 | 아니요 |
| **Bottleneck drilldown** | 느리거나 오류가 난 요청 스냅샷을 읽고 시간을 데이터베이스, 외부, 큐 또는 애플리케이션 코드로 구분 | 아니요 |
| **Health rules** | 현재 위반된 것과 별개로, 경보를 보내는 임계값 나열 | 아니요 |

에이전트는 최근 60분 같은 짧은 기간으로 시작하고, 신호가 없을 때만 넓힙니다. ID를 추측하지 않고 탐색에서 얻은 실제 애플리케이션, 티어, 트랜잭션 이름을 사용합니다.

### 연결 확인

```text
Run AppDynamics discovery and summarize applications, tiers, nodes, and any open health-rule violations
```

계정, 티어 및 노드 수와 함께 애플리케이션 목록, 그리고 열린 위반이 나와야 합니다. 애플리케이션 목록이 비어 있다면 보통 역할이 어떤 애플리케이션도 볼 수 없다는 뜻입니다.

### 예시 프롬프트

```text
Which AppDynamics business transactions in the checkout application were slowest in the last hour?
List open critical health-rule violations for the payments application and the events around them
Show response time and errors per minute for the checkout application over the last 24 hours
Where is the slow /api/orders request spending its time: database, external calls, or our code?
```

대규모 Controller에서는 모든 프롬프트에 애플리케이션 이름을 지정하세요. 그러면 각 요청이 적은 수의 호출로 끝납니다.

## 문제 해결

<Accordion title="Connect가 401로 실패합니다">
클라이언트 이름, 시크릿 또는 계정 이름이 잘못되었거나, 이름에 `@<account>`가 포함되어 있습니다. **APPD_CLIENT_NAME**이 순수한 이름인지, **APPD_ACCOUNT_NAME**이 Controller와 일치하는지 확인하세요. 시크릿을 잃어버렸거나 재생성했다면 **API Clients**에서 새로 생성한 뒤 연결을 편집하세요.
</Accordion>

<Accordion title="Connect가 시간 초과되거나 Controller에 연결할 수 없습니다">
**APPD_CONTROLLER_URL**을 확인하세요. 경로 없는 HTTPS 기본 주소여야 합니다. 온프레미스 Controller라면 CloudThinker의 egress IP에서 오는 HTTPS 트래픽을 허용하는지 확인하세요.
</Accordion>

<Accordion title="애플리케이션이나 메트릭이 반환되지 않습니다">
API 클라이언트의 역할이 해당 애플리케이션을 볼 수 없거나, Controller에 해당 기간의 데이터가 없습니다. 애플리케이션에 보기 권한을 부여한 뒤, 알려진 애플리케이션 이름과 최근 1시간으로 다시 시도하세요.
</Accordion>

<Accordion title="애플리케이션이나 트랜잭션을 찾을 수 없습니다 (404)">
이름에 오타가 있거나 애플리케이션 이름이 바뀌었습니다. 먼저 에이전트에게 애플리케이션이나 비즈니스 트랜잭션을 나열하라고 요청한 뒤 정확한 이름을 사용하세요.
</Accordion>

<Accordion title="요청이 429 또는 503을 반환합니다">
Controller가 속도를 제한하고 있거나 과부하 상태입니다. 1분 기다린 뒤 기간을 좁혀 다시 요청하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **설계상 읽기 전용**: 에이전트는 애플리케이션, 메트릭, 위반, 이벤트, 스냅샷만 읽습니다. Controller를 변경하는 명령은 없습니다.
- **전용 API 클라이언트**: CloudThinker만 사용하는 클라이언트를 만들어 다른 도구에 영향 없이 폐기할 수 있게 하세요.
- **HTTPS 전용**: 클라이언트 시크릿이 전송 중 보호되도록 항상 `https://` Controller URL을 사용하세요.

Azure를 연결하면 CloudThinker가 가상 머신, AKS 클러스터, 데이터베이스, 스토리지, 네트워킹의 인벤토리를 만들고, ID와 역할 할당을 검토하고, Azure Cost Management에서 지출을 읽을 수 있습니다. Azure는 **서비스 주체**(클라이언트 secret이 있는 Microsoft Entra ID의 앱 ID)로 인증하며, 그 역할 할당이 CloudThinker가 볼 수 있는 범위를 결정합니다.

## 사전 요구 사항

- 역할을 할당할 수 있도록 **Owner** 또는 **User Access Administrator** 권한이 있는 Azure 구독.
- Microsoft Entra ID에서 앱 등록을 만들 수 있는 권한: **Application Developer** 역할, 또는 Entra ID 사용자 설정에서 **Users can register applications**가 **Yes**로 설정되어 있어야 합니다.
- 계정에 등록된 다단계 인증. 보안 기본값은 다단계 인증 없이 앱 등록을 차단합니다.

### 먼저 알아야 할 제한

- **클라이언트 secret만.** 대화 상자는 클라이언트 secret을 받습니다. 인증서나 페더레이션 자격 증명을 위한 필드는 없습니다.
- **워크스페이스당 테넌트 하나.** 워크스페이스당 Azure 연결 하나를 가지며, 이 연결은 한 테넌트에서 서비스 주체가 읽을 수 있는 모든 구독을 다룹니다. 별도의 개발 테넌트 같은 두 번째 테넌트에는 자체 Rules와 채팅이 있는 별도 워크스페이스가 필요합니다.
- **규칙 집합 하나.** Azure는 단일 연결 서비스이므로 **Environment**는 **Not set**으로 유지됩니다. [승인 규칙](/guide/approvals/rules)은 어떤 경우에도 환경을 읽지 않습니다. Azure 쓰기를 다르게 처리하려면 [이 연결을 지정하는 Rule](/guide/approvals/rules#what-a-rule-contains)을 작성하세요.

        {

          "displayName": "cloudthinker",
          "password": "the-client-secret",
          "tenant": "00000000-0000-0000-0000-000000000000"
        }
        ```
      </Step>
      <Step title="비용 접근 권한 추가하기">

      </Step>
      <Step title="선택 사항: 더 많은 구독 포함하기">
        볼 수 있는 모든 구독에서 서비스 주체에 두 역할을 모두 주려면 반복문을 사용하세요. 명시적인 목록을 얻을 수 있으므로 권장하는 방법입니다:

            az role assignment create --assignee <appId> --role "$ROLE" --scope /subscriptions/$SUB

        done
        ```

        ```bash
        for ROLE in Reader "Cost Management Reader"; do

        done
        ```
      </Step>

### Microsoft Customer Agreement 청구

Microsoft Customer Agreement 구독에서 Optimize를 사용할 때만 필요합니다. 온라인으로 구매한 종량제 구독은 보통 Microsoft Customer Agreement(MCA)에 속합니다. Cost Management는 이런 구독의 구독 수준 쿼리를 `Given subscription doesn't have valid WebDirect/AIRS offer type`로 거부하므로, [Optimize](/ko/guide/cost-optimization/overview)는 대신 청구 프로필에서 지출을 읽습니다.

MCA인지 확인하려면 다음을 실행하세요. MCA라면 `MicrosoftCustomerAgreement`가 표시됩니다:

```bash
az billing account list --query "[].{name:displayName, type:agreementType}" -o table
```

청구 프로필 읽기를 허용하려면 **Cost Management + Billing → your billing account → Billing profiles → your profile → Access control (IAM) → Add**로 이동해 `cloudthinker` 앱에 **Billing profile reader**를 할당하세요. 구독 역할 할당은 청구 범위에 미치지 않습니다. 작동하는지 확인하려면 Optimize를 열고 Azure 지출이 로드되는지 확인하세요.

## 연결 세부 정보

| 필드 | 입력할 내용 | 예시 |
|-------|---------------|---------|
| **APP_ID** | 앱 등록의 Application (client) ID | `00000000-0000-0000-0000-000000000000` |
| **CLIENT_SECRET** | **Certificates & secrets**의 secret 값 | 해당 없음 |
| **TENANT_ID** | Microsoft Entra ID의 Directory (tenant) ID | `00000000-0000-0000-0000-000000000000` |
| **AZURE_DEFAULT_REGION** | Azure CLI 호출의 기본 리전. 표시 이름 목록에서 고릅니다. 기본값은 **East US**이며, Azure CLI에서는 `eastus`라고 부릅니다. | `East US` |

구독 필드는 없습니다. CloudThinker는 서비스 주체가 읽을 수 있는 모든 구독에서 작동합니다. 둘 이상 읽을 수 있으면 Optimize를 처음 열 때 **Choose an Azure billing scope**를 요청합니다.

## 필요한 권한

| 역할 | 범위 | 사용할 수 있게 되는 것 |
|------|-------|-----------------|
| **Reader** | 구독 | 리소스 인벤토리, 역할 및 정책 검토, 상태 확인, Azure Monitor 지표 |
| **Cost Management Reader** | 구독 | Optimize의 지출, 예측, 비용 발견 항목 |
| **Billing profile reader** | MCA 청구 프로필 | Microsoft Customer Agreement 구독의 Optimize |
| **Contributor** | 구독 또는 리소스 그룹 | 선택 사항. CloudThinker가 리소스를 변경할 수 있게 합니다. [쓰기 권한](#쓰기-권한)을 참고하세요. |

Reader만으로는 비용 데이터가 나오지 않습니다. Reader는 `*/read`를 부여하는데, Cost Management 쿼리는 `*/read`가 다루지 않는 POST 작업이기 때문입니다.

<Tip>
Reader와 Cost Management Reader로 시작하세요. 변경에는 구독 전체의 Contributor보다 리소스 그룹 하나로 범위를 정한 **Virtual Machine Contributor** 같은 좁은 기본 제공 역할을 선호하세요.
</Tip>

## 에이전트 기능

CloudThinker는 읽기 전용 Azure CLI 명령을 묻지 않고 실행합니다. 변경은 [쓰기 권한](#쓰기-권한) 모델을 따릅니다.

| 영역 | CloudThinker가 하는 일 |
|------|------------------------|
| **비용** | Cost Management에서 지출(세전, 통화 포함)을 읽고, 사용되지 않는 리소스와 활용도가 낮은 VM을 찾습니다 |
| **ID와 거버넌스** | Azure RBAC 역할 할당과 Azure Policy를 검토합니다. Reader는 Microsoft Entra 사용자, 그룹, 앱 등록을 다루지 않습니다. |
| **컴퓨팅과 컨테이너** | VM, App Service, AKS 클러스터를 살펴봅니다 |
| **데이터와 스토리지** | SQL 및 기타 데이터베이스, 스토리지 계정, 백업을 살펴봅니다 |
| **네트워킹** | 네트워크 경계, DNS 영역, 연결된 Log Analytics 워크스페이스를 검토합니다 |
| **모니터링** | VM CPU 같은 Azure Monitor 지표를 읽어 급증을 설명하거나 리소스 크기를 정합니다 |
| **변경** | **Allow writes**가 켜져 있고, 서비스 주체의 역할이 허용하고, 승인 설정이 허용할 때만 Azure CLI 쓰기를 실행합니다 |

```

답변에 실제 구독 이름과 ID가 나열됩니다.

```

## 쓰기 권한

연결 세부 정보 패널의 **Allow writes**는 에이전트가 Azure에서 무언가를 변경할 수 있는지 제어합니다. 기본적으로 켜져 있지만, Reader와 Cost Management Reader는 아무것도 변경할 수 없으므로 더 많은 권한을 부여하기 전까지 Azure가 모든 쓰기를 거부합니다.

| Azure 역할 | Allow writes | 결과 |
|---|---|---|
| 읽기 역할만 | 켜짐 또는 꺼짐 | 읽기 전용. Azure가 모든 변경을 거부합니다. |
| 쓰기 역할 부여 | 꺼짐 | 읽기 전용. CloudThinker가 Azure에 도달하기 전에 모든 변경을 거부합니다. |
| 쓰기 역할 부여 | 켜짐 | 에이전트가 변경을 제안할 수 있습니다. [Rules와 Approval mode](/guide/approvals/overview)가 각각을 결정합니다. |

CloudThinker에서도 쓰기를 잠그려면 **Settings → Workspace → Connections**에서 **Microsoft Azure**를 열고 세부 정보 패널의 **Allow writes** 스위치를 끄세요.

## 클라이언트 secret 교체

Azure는 단일 연결 서비스이므로 정상 상태일 때는 연필 아이콘이나 **Edit Instance** 대화 상자가 없습니다.

| 시점 | 방법 |
|---|---|
| secret이 만료되기 전 | 새 secret을 만든 다음 **Microsoft Azure** 세부 정보 패널에서 **Disconnect**를 클릭하고 새 값으로 다시 연결하세요. 이후 이전 secret을 삭제하세요. |
| 만료된 후(연결에 **Error** 표시) | 새 secret을 만든 다음 세부 정보 패널에서 **Replace credentials**를 클릭하고 새 값을 저장하세요. |

미리 교체하는 것은 만료된 secret을 교체하는 것보다 수고가 더 들지만, 그 수고를 아끼려고 secret을 만료시키지 마세요: 만료된 secret은 교체할 때까지 장애를 의미합니다. 한가한 시간에 미리 교체하세요. 다시 연결하면 새 연결이 시작됩니다:

- 연결을 해제한 뒤 다시 연결할 때까지 에이전트, automation, Optimize가 Azure를 사용할 수 없습니다.
- 새 연결과 마찬가지로 CloudThinker가 다시 **Turn on Optimize?**를 묻습니다.
- **Allow writes**가 다시 켜집니다. 꺼 두었다면 다시 끄세요.
- Azure 연결을 지정한 [Rules](/guide/approvals/rules)에 여전히 그 연결이 나열되는지 확인하세요.

새 secret을 만들려면 `az ad sp credential reset --id <appId> --append`를 실행하거나 **Microsoft Entra ID → App registrations → your app → Certificates & secrets**를 사용하세요. `--append` 없이 재설정하면 기존 secret이 삭제되어 연결이 즉시 끊어집니다.

## 문제 해결

<Accordion title="보안 기본값 때문에 로그인이 차단됩니다">
`az login` 또는 포털이 `AADSTS530035: Access has been blocked by security defaults`를 반환합니다. 보안 기본값은 앱을 등록하기 전에 다단계 인증을 요구합니다. [aka.ms/mfasetup](https://aka.ms/mfasetup)에서 방법을 등록하고 다시 로그인하세요. `--use-device-code`와 `--allow-no-subscriptions` 플래그로는 우회할 수 없습니다.
</Accordion>

<Accordion title="인증에 실패했습니다">
**원인:** 잘못된 APP_ID, CLIENT_SECRET, TENANT_ID, 만료된 secret, 또는 조건부 액세스 정책. Microsoft Entra 오류 코드로 어느 것인지 알 수 있습니다:

| 코드 | 의미 | 해결 |
|---|---|---|
| `AADSTS7000215` | 잘못된 클라이언트 secret | secret의 **Secret ID**가 아니라 **Value**를 붙여 넣거나, 새 secret을 만드세요 |
| `AADSTS700016` | 테넌트에서 앱을 찾을 수 없음 | **APP_ID**와, 입력한 테넌트에 앱이 등록되어 있는지 확인하세요 |
| `AADSTS90002` | 테넌트를 찾을 수 없음 | **TENANT_ID**를 확인하세요 |

**해결:** 값이 올바르다면 서비스 주체 로그인을 차단하는 조건부 액세스 정책이 없는지 확인하세요.
</Accordion>

<Accordion title="클라이언트 secret이 만료되었습니다">
**원인:** secret이 만료일(CLI 기본값으로 1년)에 도달했습니다.

**해결:** 새 secret을 만든 다음 **Microsoft Azure** 세부 정보 패널에서 **Replace credentials**를 클릭하고 저장하세요. [클라이언트 secret 교체](#클라이언트-secret-교체)를 참고하세요.
</Accordion>

<Accordion title="Optimize에 Azure Cost Management is not readable이 표시됩니다">
**원인:** 서비스 주체에 비용 접근 권한이 없습니다.

**해결:** 구독에 **Cost Management Reader**를 할당하세요. Microsoft Customer Agreement 구독이라면 청구 프로필에 **Billing profile reader**도 할당하세요. 역할 할당이 전파되는 데 몇 분이 걸리므로 그 후에 다시 시도하세요.
</Accordion>

<Accordion title="Cost Management가 429를 반환합니다">
**원인:** Cost Management는 새 구독을 강하게 제한하므로 쿼리가 `429 Too many requests`로 응답합니다. 잘못 구성된 것은 없습니다.

**해결:** 몇 분 기다린 뒤 Optimize를 다시 로드하세요.
</Accordion>

<Accordion title="리소스나 구독이 누락되었습니다">
**원인:** 서비스 주체가 해당 구독을 읽을 수 없습니다.

**해결:** 보길 기대하는 모든 구독에 **Reader**를 할당하세요. Azure CLI 탭의 선택적 반복문 단계로 한 번에 할 수 있습니다. 역할 할당이 적용되는 데 최대 약 10분이 걸릴 수 있으므로 기다린 뒤 다시 질문하세요.
</Accordion>

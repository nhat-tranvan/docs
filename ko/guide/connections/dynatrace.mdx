Dynatrace 환경을 연결하면 CloudThinker 에이전트가 열린 문제를 나열하고, Grail의 로그·메트릭·스팬·이벤트에 대해 DQL(Dynatrace Query Language)을 실행하고, 취약점을 검토하고, 문제가 영향을 주는 엔티티를 찾을 수 있습니다. 이 연결은 공식 Dynatrace MCP 서버를 사용하며, 하나의 환경에 대해 하나의 **platform token**으로 로그인합니다.

## 사전 요구 사항

- 에이전트가 읽을 데이터가 있는 Dynatrace Platform(Grail) 기반 Dynatrace SaaS 환경. Dynatrace Managed와 `apps.dynatrace.com` 주소가 없는 클래식 환경은 연결할 수 없습니다.
- 에이전트가 쿼리할 데이터를 읽을 수 있는, 해당 환경 계정의 Dynatrace 사용자(또는 서비스 사용자). 계정 구성원이라면 누구나 platform token을 만들 수 있지만, 토큰은 해당 사용자의 권한만 가집니다.
- Platform 형식의 환경 URL: `https://<environment-id>.apps.dynatrace.com`.

## 설정

<Steps>
  <Step title="환경 URL 확인">
    Dynatrace에 로그인하고 브라우저의 주소를 `.apps.dynatrace.com`까지 복사합니다(예: `https://abc12345.apps.dynatrace.com`).

    클래식 `live.dynatrace.com` 주소가 아니라 `apps.dynatrace.com` 주소를 사용합니다. MCP 서버는 Platform API와만 통신합니다.
  </Step>
  <Step title="Platform token 생성">
    Dynatrace 계정에서 **My platform tokens**([myaccount.dynatrace.com/platformTokens](https://myaccount.dynatrace.com/platformTokens))를 열고 **Platform token**을 선택합니다. 다음을 설정합니다:
    - **Token name**: `cloudthinker`
    - **Expiration date**: 교체 정책에 맞는 유효 기간
    - **Environments**: 토큰을 계정 전체에 적용하지 않는다면 이전 단계에서 확인한 환경
    - **Scopes**: `app-engine:apps:run`과 에이전트가 쿼리할 데이터의 읽기 범위([필요 권한](#필요-권한) 참조)

    **Generate**를 클릭하고 토큰을 복사합니다. Dynatrace는 토큰을 한 번만 표시합니다. 토큰은 해당 사용자에게 허용된 작업만 할 수 있으므로, 그 데이터를 읽을 수 있는 사용자(또는 서비스 사용자)로 토큰을 만듭니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **Dynatrace**를 선택합니다. 다음을 입력합니다:

    - **DT_ENVIRONMENT**: 환경 URL
    - **DT_PLATFORM_TOKEN**: 방금 만든 토큰

    **Connect**를 클릭합니다.

    **성공 상태:** Dynatrace가 **Connected**로 표시됩니다. 아래 검증 프롬프트를 실행하여 토큰이 환경을 읽을 수 있는지 확인합니다.
  </Step>
</Steps>

<Warning>
클래식 Dynatrace API 토큰이 아니라 **platform token**을 사용하세요. 클래식 API 토큰에는 MCP 서버에 필요한 Platform 범위가 없으므로 대부분의 요청이 401 또는 403으로 실패합니다.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **DT_ENVIRONMENT** | Dynatrace Platform 환경 URL | `https://abc12345.apps.dynatrace.com` |
| **DT_PLATFORM_TOKEN** | 해당 환경의 platform token | `<your-platform-token>` |

다른 환경에 접근하려면 자체 토큰으로 별도의 연결을 추가합니다.

## 필요 권한

`app-engine:apps:run`으로 시작하고, 에이전트가 쿼리할 데이터 유형의 읽기 범위만 추가합니다.

| 범위 | 가능해지는 작업 |
|-------|-----------------|
| `app-engine:apps:run` | 필수. Dynatrace MCP 도구를 실행합니다 |
| `storage:buckets:read` | 토큰이 읽을 수 있는 Grail 버킷 탐색 |
| `storage:logs:read` | DQL로 로그 쿼리 |
| `storage:metrics:read` | DQL로 메트릭 쿼리 |
| `storage:spans:read` | DQL로 트레이스 및 스팬 쿼리 |
| `storage:events:read` | DQL로 이벤트 쿼리 |
| `storage:entities:read` | DQL로 모니터링 엔티티 쿼리 |
| `storage:smartscape:read` | DQL로 Smartscape 토폴로지 쿼리 |
| `storage:security.events:read` | DQL로 보안 이벤트 쿼리 |
| `storage:bizevents:read` | DQL로 비즈니스 이벤트 쿼리 |
| `storage:user.events:read` | DQL로 사용자 이벤트 쿼리 |
| `storage:user.sessions:read` | DQL로 사용자 세션 쿼리 |
| `storage:system:read` | DQL로 시스템 데이터 쿼리 |
| `storage:files:read` | DQL `load` 문에서 조회 데이터 사용 |
| `document:documents:write` | 선택 사항. 에이전트가 Dynatrace 노트북을 만들 수 있게 합니다 |

선택적 도구에는 추가 범위가 필요합니다. 에이전트가 사용할 범위만 추가합니다:

| 도구 | 추가 범위 |
|------|--------------|
| Davis analyzers | 목록 조회는 `davis:analyzers:read`, 실행은 `davis:analyzers:execute` |
| DQL help | `davis-copilot:nl2dql:execute`(질문을 DQL로), `davis-copilot:dql2nl:execute`(쿼리 설명) |
| 이벤트 보내기 | `storage:events:write` |
| 이메일 보내기 | `email:emails:send` |

전체 목록은 [Dynatrace MCP server README](https://www.npmjs.com/package/@dynatrace-oss/dynatrace-mcp-server)에 있습니다.

<Tip>
DQL이 한 데이터 유형에서는 작동하고 다른 유형에서는 실패한다면, 토큰에 해당 유형의 `storage:*:read` 범위가 없는 것입니다. Dynatrace에서 범위를 추가하고 연결의 토큰을 업데이트하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 | 승인 |
|------------|--------------------|----------|
| **Environment check** | 연결을 확인하고 기본 환경 정보를 읽습니다 | 아니요 |
| **Problems** | 열린 문제와 최근 문제, 그리고 영향받는 서비스나 호스트를 나열합니다 | 아니요 |
| **Vulnerabilities** | 위험 점수(예: 7.0 이상)로 필터링하여 취약점을 나열합니다 | 아니요 |
| **Entities** | 이름으로 모니터링 엔티티를 찾습니다 | 아니요 |
| **DQL** | 쿼리를 검증한 다음 작은 레코드 제한으로 실행합니다 | 아니요 |
| **DQL help** | 일반 언어 질문을 DQL로 바꾸거나 기존 쿼리를 설명합니다(추가 범위 필요) | 아니요 |
| **Kubernetes events and exceptions** | 클러스터나 워크로드의 Kubernetes 이벤트와 최근 예외를 나열합니다 | 아니요 |
| **Davis analyzers** | 사용 가능한 Davis analyzer를 나열하고 시간 범위에 대해 하나를 실행합니다(추가 범위 필요) | 아니요 |
| **Notebooks** | 결과로 Dynatrace 노트북을 만듭니다 | 예 |
| **Notifications and events** | Dynatrace를 통해 이메일을 보내거나, 이벤트를 보내거나, 알림 워크플로를 만듭니다(추가 범위 필요) | 예 |

에이전트는 각 DQL 쿼리를 실행하기 전에 검증하고 50~100개 레코드로 시작합니다. 이는 비용에 중요합니다. DQL 쿼리는 Grail 데이터를 스캔하며, 이는 Dynatrace 사용량에 포함될 수 있습니다([Dynatrace pricing](https://www.dynatrace.com/pricing/) 참조). MCP 서버는 쿼리가 스캔한 데이터의 누적 합계인 **Grail query budget**도 관리하며, 예산을 다 쓰면 쿼리를 중지합니다. 모든 쓰기 작업은 [Approvals](/guide/approvals/overview)를 거치며, 거부된 호출은 다시 시도하지 않습니다.

### 연결 검증

```text
Run Dynatrace discovery and list open problems and high-risk vulnerabilities
```

환경 정보, 영향받는 엔티티가 포함된 열린 문제, 위험 점수 7.0 이상인 취약점이 표시됩니다. 토큰에 Davis 범위가 있으면 Davis analyzer 목록도 표시됩니다.

### 예시 프롬프트

```text
Which Dynatrace problems are open in production right now, and which services do they affect?
Query Dynatrace logs for errors from the checkout service in the last 30 minutes
List Dynatrace vulnerabilities with a risk score of 7 or higher on internet-facing services
Show the Kubernetes events for the payments workload in the last hour
```

큰 환경에서는 서비스, 엔티티 또는 버킷과 짧은 시간 범위를 지정합니다. 좁은 쿼리는 더 빨리 반환되고 Grail 예산을 덜 사용합니다.

## 문제 해결

<Accordion title="Connect가 실패하거나 모든 요청이 401을 반환함">
토큰이 없거나, 만료되었거나, 취소되었거나, 클래식 API 토큰입니다. `app-engine:apps:run`이 있는 새 platform token을 만들고, 연결을 편집하여 **DT_PLATFORM_TOKEN**에 붙여넣습니다. 또한 **DT_ENVIRONMENT**가 `live.dynatrace.com`이 아니라 `apps.dynatrace.com`을 사용하는지 확인합니다.
</Accordion>

<Accordion title="일부 쿼리가 403을 반환함">
토큰에 해당 데이터 유형의 범위가 없습니다. 예를 들어 로그 쿼리에는 `storage:logs:read`가 필요합니다. Dynatrace에서 범위를 추가하고 연결을 업데이트합니다.
</Accordion>

<Accordion title="DQL 쿼리가 행을 반환하지 않음">
쿼리가 토큰이 읽을 수 없는 버킷, 데이터가 없는 시간 범위, 또는 철자가 틀린 엔티티를 대상으로 할 수 있습니다. 먼저 에이전트에게 이름으로 엔티티를 찾게 한 다음, 알려진 서비스와 짧은 시간 범위로 쿼리를 다시 실행합니다.
</Accordion>

<Accordion title="요청이 429를 반환함">
Grail query budget을 다 썼습니다. 에이전트에게 예산을 재설정하도록 요청하고(재설정은 다른 쓰기와 마찬가지로 Approvals를 거칩니다), 다음 쿼리가 덜 스캔하도록 시간 범위와 레코드 제한을 좁힙니다.
</Accordion>

<Accordion title="엔티티 또는 문제를 찾을 수 없음(404)">
엔티티 이름이 바뀌었거나 ID가 잘못되었습니다. ID 대신 이름으로 찾아 달라고 에이전트에게 요청합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **Platform token, 읽기 범위부터**: 에이전트가 노트북을 만들거나 Dynatrace를 통해 메시지를 보내게 하려는 경우에만 `document:documents:write` 또는 알림 범위를 추가합니다.
- **연결마다 토큰 하나**: 다른 도구를 손상시키지 않고 취소할 수 있도록 CloudThinker 전용 토큰을 만듭니다.

New Relic을 연결하면 CloudThinker가 NRQL을 실행하고, 서비스의 골든 메트릭과 오류를 확인하고, 로그와 트레이스를 읽고, 열린 이슈와 알림 조건을 분류할 수 있습니다. CloudThinker는 User API 키(`NRAK-...`)로 인증된 New Relic MCP 서버를 통해 New Relic에 접근합니다.

## 사전 요구 사항

- **US** 또는 **EU** 리전의 New Relic 계정.
- 조직에서 **New Relic MCP Server** 기능이 켜져 있어야 합니다. New Relic은 기본적으로 이 기능을 켜 두지만, 조직 관리자가 기능 제어 관리자에서 끌 수 있으며, 꺼져 있는 동안에는 아무것도 작동하지 않습니다.
- 두 종류의 역할이 있는 그룹에 속한 New Relic 사용자: MCP 서버를 읽을 수 있는 조직 역할, 그리고 에이전트가 쿼리할 각 계정의 계정 역할. [필요 권한](#필요-권한)을 참조하세요.
- CloudThinker 워크스페이스에 연결을 추가할 수 있는 권한.

<Warning>
New Relic의 MCP 서버는 공개 프리뷰 상태이며, New Relic은 FedRAMP 또는 HIPAA 규제 대상 계정에서 이를 허용하지 않습니다. 해당 계정은 연결하지 마세요.
</Warning>

## 설정

<Steps>
  <Step title="User API 키 생성">
    New Relic의 사용자 메뉴에서 **API keys**를 열거나, `one.newrelic.com/api-keys`(EU: `one.eu.newrelic.com/api-keys`)로 이동합니다. **Create a key**를 클릭하고, **Key type**을 **User**로 설정하고, 이름을 `cloudthinker`로 지정한 다음 저장합니다.

    지금 전체 키를 복사합니다. 키는 `NRAK-`로 시작하며 New Relic은 한 번만 표시합니다.
  </Step>
  <Step title="연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭을 연 다음 **New Relic**을 선택합니다. 다음을 입력합니다:
    - **Alias**(선택 사항): `newrelic-prod` 같은 짧은 이름. 소문자, 숫자, 하이픈을 사용합니다.
    - **Description**(선택 사항): 어떤 계정 또는 환경인지. 에이전트는 이를 읽고 올바른 인스턴스를 선택합니다.
    - **NEWRELIC_API_KEY**: `NRAK-` 키.
    - **NEWRELIC_REGION**: 로그인하는 위치에 맞춰 **US (mcp.newrelic.com)** 또는 **EU (mcp.eu.newrelic.com)**.

    **Connect**를 클릭합니다. CloudThinker가 **Connecting**과 **Verifying**을 표시한 다음 **Connected** 상태를 표시합니다. **Verifying**은 해당 리전의 New Relic MCP 서버와 세션을 열고 도구 목록을 가져옵니다. 쿼리는 실행하지 않으므로, 누락된 계정 역할은 나중에 첫 질문에서 드러납니다. 검증에 실패하면 **Failed**가 표시되고 오류 메시지가 나타납니다. 메시지를 [문제 해결](#문제-해결)과 대조합니다.
  </Step>
</Steps>

<Warning>
License, ingest, browser 키는 여기서 작동하지 않습니다. **User** 키(`NRAK-...`)만 데이터를 쿼리할 수 있습니다. 가장 흔한 설정 실수입니다.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **NEWRELIC_API_KEY** | New Relic User API 키 | `NRAK-XXXXXXXXXXXXXXXXXXXX` |
| **NEWRELIC_REGION** | 계정의 데이터 센터. 기본값은 **US**입니다 | `EU (mcp.eu.newrelic.com)` |

`one.eu.newrelic.com`에서 로그인한다면 리전은 **EU**입니다. 그렇지 않으면 **US**입니다.

## 필요 권한

User API 키는 키를 소유한 사용자의 권한을 가집니다. 키별 범위가 없으므로 최소 권한은 사용자에서 결정됩니다. 사용자에게는 두 수준이 모두 필요합니다:

| 수준 | 역할 | 적합성 |
|-------|------|-----|
| 조직 | **Organization Read Only** | 권장. 사용자가 MCP 서버에 접근할 수 있게 합니다 |
| 조직 | **Organization Product Admin**, **Organization Manager** | 작동하지만 CloudThinker에 필요한 것보다 많은 권한을 부여합니다 |
| 조직 | 커스텀 조직 역할 | MCP 서버를 읽을 권한이 포함되어 있으면 작동합니다 |
| 계정(쿼리할 각 계정) | **Read Only** | 권장. NRQL, APM, 로그, 알림 읽기가 해당 계정의 데이터를 볼 수 있게 합니다 |

<Tip>
전용 New Relic 사용자와 그 사용자를 위한 그룹을 만드세요. New Relic **Access management**에서 그룹에 조직 수준의 **Organization Read Only**를 부여한 다음, 조사할 각 계정에 **Read Only**를 부여합니다. 해당 사용자로 키를 만듭니다. New Relic 사용자 유형은 결제에 영향을 줄 수 있으므로, 사용자가 어떤 유형을 받는지 확인하세요.
</Tip>

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 |
|------------|------------------------|
| **Discovery** | 계정을 나열한 다음 각 계정의 이벤트 유형, 대시보드, 알림 정책, 최근 이슈를 나열합니다 |
| **NRQL** | 작성한 NRQL이나, 질문으로부터 만든 NRQL(예: `SELECT percentile(duration, 95) FROM Transaction FACET name`)을 실행합니다 |
| **Entities** | 이름이나 태그로 서비스와 호스트를 찾고, 한 단계 떨어진 엔티티를 찾습니다 |
| **Service health** | 골든 메트릭(처리량, 응답 시간, 오류율, 포화도), 느린 트랜잭션, 오류 그룹을 읽습니다 |
| **Logs and traces** | 최근 로그, 로그 통계, 분산 트레이스 세부 정보를 읽습니다 |
| **Alerts and issues** | 열린 이슈, 알림 정책과 조건, 과거 인시던트를 나열합니다 |
| **Changes** | 애플리케이션의 배포 같은 변경 이벤트를 나열합니다 |
| **Synthetics** | 합성 모니터와 최근 결과를 나열합니다 |
| **Dashboards** | 대시보드를 나열하고 읽습니다 |

New Relic은 자연어 NRQL이나 배포 영향 보고서 같은 일부 AI 도구를 OAuth 로그인 전용으로 둡니다. 이는 New Relic의 제한입니다. User API 키로는 사용할 수 없으므로, CloudThinker가 NRQL을 직접 작성하고 변경 이벤트를 직접 읽습니다(위의 **Changes** 참조).

연결이 처음 **Connected**에 도달하면 CloudThinker가 계정을 읽기 전용으로 깊이 살펴보는 채팅을 엽니다. 다시 실행하려면 카드의 **More** 메뉴를 열고 **Try in chat**을 선택합니다.

### 연결 검증

```text
Run New Relic discovery and list my accounts, their dashboards and alert policies, and any open issues
```

정상적인 답변은 계정 ID를 하나 이상 제시하고, `Transaction`이나 `Log` 같은 이벤트 유형을 보여 줍니다.

### 예시 프롬프트

```text
Show golden metrics for the checkout service over the last hour and anything unusual
Which New Relic issues are open right now, and which alert condition opened each one?
Were there deployments to the checkout service today, and did error rate change after them?
```

## New Relic 알림을 Resolve로 보내기

Resolve에는 New Relic 프리셋이 없으므로, 워크플로 알림을 [커스텀 신호 소스](/guide/incident/webhook-integrations/custom-source)로 보냅니다.

<Steps>
  <Step title="CloudThinker에서 신호 생성">
    **Resolve → Triggers & Outcomes**로 이동하여 **Custom source**를 선택하고 **Add signal**을 클릭합니다. 이름을 `New Relic`으로 지정하고 **Create endpoint**를 클릭한 다음 **Webhook URL**과 비밀 키를 복사합니다. 시크릿은 한 번만 표시됩니다.
  </Step>
  <Step title="New Relic에 webhook 대상 추가">
    New Relic에서 **Webhook** 대상을 추가합니다. **Webhook URL**을 엔드포인트로 붙여넣고, 비밀 키로 bearer 토큰 인증을 설정하여 New Relic이 `Authorization: Bearer <your-secret-key>`를 보내도록 합니다.
  </Step>
  <Step title="워크플로에서 대상으로 알림 보내기">
    원하는 알림 정책을 다루는 워크플로에서 해당 대상으로 webhook 알림을 추가합니다. New Relic의 기본 페이로드 템플릿을 유지합니다.
  </Step>
  <Step title="테스트 이벤트 하나를 보내고 필드 매핑">
    워크플로에서 테스트 알림을 보냅니다. CloudThinker에 **Payload received**가 표시되면 **Map the fields**를 클릭하고, **Incident title**에는 이슈 제목 필드를, **Severity**에는 우선순위 필드를 선택한 다음 **Save mapping**을 클릭합니다. New Relic의 `CRITICAL`, `HIGH`, `MEDIUM`, `LOW` 우선순위는 그대로 인식됩니다.
  </Step>
</Steps>

**성공 상태:** 해당 워크플로의 다음 이슈가 [Resolve → Signals](/ko/guide/pulse/overview)에 표시되고, 에이전트가 이 연결을 통해 조사합니다.

## 문제 해결

<Accordion title="Verifying 단계 또는 첫 질문에서 401 Unauthorized">
- 키가 없거나, 삭제되었거나, User 키가 아닙니다. 키가 `NRAK-`로 시작하는지 확인하고, 필요하면 새 User 키를 만들어 연결의 세부 정보 패널에서 연결을 업데이트합니다.
- **NEWRELIC_REGION**이 계정과 일치하지 않습니다. `one.eu.newrelic.com`에서 로그인한다면 **EU**를 선택합니다.
</Accordion>

<Accordion title="유효한 키인데도 Verifying 단계 또는 모든 호출에서 실패함">
조직에서 **New Relic MCP Server** 기능이 꺼져 있습니다. 기본적으로 켜져 있으므로, 관리자가 New Relic의 기능 제어 관리자에서 끈 것입니다. 다시 켜 달라고 요청한 다음 연결을 다시 테스트합니다.
</Accordion>

<Accordion title="권한 오류 또는 계정 누락">
키 사용자에게 MCP 서버를 읽을 수 있는 역할이 없거나, 해당 계정의 계정 역할이 없습니다. 사용자의 그룹에 **Organization Read Only**와 해당 계정의 **Read Only**를 부여합니다.
</Accordion>

<Accordion title="엔티티 또는 서비스를 찾을 수 없음">
CloudThinker는 엔티티를 쿼리하기 전에 이름으로 확인합니다. New Relic에 표시되는 그대로 서비스 이름을 사용하거나, 태그로 엔티티를 검색해 달라고 요청합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **읽기 전용 사용자**: User 키에는 자체 범위가 없으므로, 쿼리할 계정에 대해 **Organization Read Only**와 **Read Only** 역할만 가진 사용자로 키를 만듭니다.
- **키는 한 번만 표시됨**: 키를 만들 때 시크릿 관리자에 저장합니다. 분실하면 새 키를 만들고 이전 키를 삭제합니다.

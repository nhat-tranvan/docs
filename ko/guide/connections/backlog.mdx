Nulab의 Backlog를 연결하면 CloudThinker [에이전트](/ko/guide/agents/overview)가 프로젝트, 이슈, 마일스톤, 위키, 풀 리퀘스트를 읽고, 요청할 때 이슈, 마일스톤, 위키 페이지를 만들거나 업데이트할 수 있습니다. Backlog는 API 키로 인증하며, 키는 그 키를 발급한 Backlog 사용자와 같은 프로젝트 접근 권한을 가집니다.

## 사전 요구 사항

- CloudThinker가 읽기를 원하는 모든 프로젝트에 속한 Backlog 사용자.
- 스페이스에서 API 접근이 켜져 있어야 합니다. 스페이스가 이를 제한한다면 스페이스 관리자가 먼저 활성화해야 합니다.
- 에이전트가 이슈, 마일스톤 또는 위키 페이지를 만들거나 업데이트하기를 원하는 경우에만, 해당 프로젝트에 대한 그 사용자의 쓰기 권한.
- CloudThinker 워크스페이스에서 연결을 관리할 수 있는 권한. Backlog는 모든 CloudThinker 플랜에서 작동합니다.

## 설정

<Steps>
  <Step title="Backlog에서 API 키 생성">
    Backlog에서 프로필 메뉴를 열고 **Personal Settings → API**로 이동합니다. `cloudthinker` 같은 메모를 입력하고 키를 등록한 뒤 복사합니다.

    CloudThinker가 가지기를 원하는 접근 권한을 가진 사용자로 키를 발급하세요. 키를 가진 사람은 누구나 그 사용자로 동작합니다.
  </Step>
  <Step title="CloudThinker에서 Backlog 열기">
    **Settings → Workspace → Connections**를 엽니다. **Discover** 탭에서 **Backlog**를 검색하고 **Connect**를 클릭합니다.
  </Step>
  <Step title="도메인과 키 입력">
    **BACKLOG_DOMAIN**에 `myorg.backlog.com` 또는 `myorg.backlog.jp` 같은 전체 스페이스 호스트를 입력합니다. **BACKLOG_API_KEY**에 키를 붙여넣고 **Connect**를 클릭합니다.

    **성공 상태:** CloudThinker가 키를 테스트하고 Backlog에 **Connected** 상태가 표시됩니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 입력할 내용 | 예시 |
|---|---|---|
| **BACKLOG_DOMAIN** | 스페이스 키만이 아닌 Backlog 스페이스의 전체 호스트 | `myorg.backlog.com` |
| **BACKLOG_API_KEY** | **Personal Settings → API**에서 만든 API 키 | (시크릿) |

## 필수 권한

Backlog에는 키별 스코프가 없습니다. 키는 그 사용자가 Backlog에서 할 수 있는 모든 것을 할 수 있습니다.

| 에이전트가 하게 하려면 | 키 사용자에게 필요한 것 |
|---|---|
| 프로젝트, 이슈, 마일스톤, 위키, 문서, 저장소, 풀 리퀘스트 읽기 | 해당 프로젝트의 멤버십 |
| 이슈, 댓글, 마일스톤 또는 위키 페이지 생성이나 업데이트 | 프로젝트의 쓰기 권한 |

읽기는 묻지 않고 실행됩니다. 쓰기는 [승인](/guide/approvals/overview)을 거칩니다. Rules가 먼저 결정하고, 어떤 Rule과도 일치하지 않는 쓰기는 Approval mode가 실행, 확인 요청, 거부 중 하나로 정합니다. 채팅에서 CloudThinker는 항목과 변경 내용을 지정할 때만 쓰기를 제안합니다. Resolve 후속 티켓은 예외로, [Resolve Triggers & Outcomes](/guide/incident/triggers-and-outcomes#outcomes)에서 켠 결과(outcome)에 따라 실행됩니다.

<Tip>
CloudThinker에게 필요한 프로젝트에만 속한 전용 Backlog 사용자로 키를 발급하세요. 에이전트가 티켓을 등록하거나 업데이트하기를 원하는 프로젝트에만 쓰기 권한을 주세요. 전용 사용자는 Backlog 플랜의 사용자 한도에 포함될 수 있습니다.
</Tip>

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 | 승인 |
|---|---|---|
| **Space discovery** | 스페이스, 연결된 사용자, 키가 있는 프로젝트, 우선순위, 해결 상태 나열 | 아니요 |
| **Issue tracking** | 이슈 검색, 읽기, 개수 세기 | 아니요 |
| **Milestones** | 마일스톤과 각각에 포함된 것 나열 | 아니요 |
| **Wikis and documents** | 프로젝트 위키와 문서 읽기 | 아니요 |
| **Git and pull requests** | 프로젝트의 저장소와 풀 리퀘스트 읽기 | 아니요 |
| **Ticket context in Review** | 머지 리퀘스트나 풀 리퀘스트가 참조하는 Backlog 이슈(예: `PROJ-123`)를 [Review](/ko/guide/code-review/overview)로 가져오기 | 아니요 |
| **Issue, milestone, and wiki changes** | 이슈, 마일스톤 또는 위키 페이지 생성이나 업데이트, 댓글 추가 | 예 |
| **Follow-up tickets in Resolve** | [Resolve Triggers & Outcomes](/guide/incident/triggers-and-outcomes#outcomes)에서 결과를 켜면 인시던트 후 후속 티켓 등록 및 업데이트 | 결과 설정에 따름 |

### 연결 확인

```text
List my Backlog projects with their keys, then show the five most recently updated open issues in one of them
```

`PLATFORM` 같은 키가 있는 프로젝트 이름과, Backlog에서 열 수 있는 `PLATFORM-42` 같은 이슈 키가 나와야 합니다.

### 예시 프롬프트

```text
Summarize the open issues in the PLATFORM project and flag anything past its due date
What does the 2.4 milestone in PLATFORM still have open, grouped by assignee?
Add a comment to PLATFORM-118 saying the fix is deployed to staging
```

세 번째 프롬프트는 쓰기이므로, CloudThinker가 댓글을 보여 주고 게시하기 전에 승인을 거칩니다.

## 문제 해결

<Accordion title="연결 테스트가 401 Unauthorized로 실패합니다">
키가 잘못되었거나 삭제되었거나, 스페이스에서 API 접근이 꺼져 있습니다. **Personal Settings → API**에서 새 키를 만들고, 스페이스 관리자에게 API 접근이 허용되어 있는지 확인한 뒤 연결의 **BACKLOG_API_KEY**를 업데이트하세요.
</Accordion>

<Accordion title="요청이 404를 반환하거나 잘못된 스페이스에 접근합니다">
**BACKLOG_DOMAIN**에 스페이스 키(`myorg`)만 있거나 리전이 잘못되었습니다. `myorg.backlog.com` 또는 `myorg.backlog.jp`처럼 브라우저에 표시되는 전체 호스트를 정확히 입력하고 다시 연결하세요.
</Accordion>

<Accordion title="연결은 작동하지만 프로젝트나 이슈가 빠져 있습니다">
키 사용자가 해당 프로젝트의 멤버가 아닙니다. Backlog에서 사용자를 프로젝트에 추가한 뒤 CloudThinker에게 프로젝트를 다시 나열해 달라고 요청하세요.
</Accordion>

<Accordion title="이슈 생성이나 업데이트가 권한 오류로 실패합니다">
키 사용자가 프로젝트를 읽을 수는 있지만 쓸 수는 없습니다. 그 사용자에게 프로젝트의 쓰기 권한을 주거나 권한이 있는 사용자로 키를 다시 발급한 뒤 작업을 다시 승인하세요.
</Accordion>

<Accordion title="큰 프로젝트에서 결과가 중간에 멈춥니다">
CloudThinker는 응답을 읽기 쉽게 유지하기 위해 Backlog 응답을 약 10,000 토큰으로 제한합니다. 요청을 프로젝트, 마일스톤, 상태 또는 담당자 하나로 좁히거나, 먼저 개수를 묻고 나서 세부 항목으로 들어가세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **키는 곧 사용자입니다.** 키는 발급한 Backlog 사용자의 모든 권한을 가지므로, 최소 권한의 전용 사용자로 발급하고 연결을 제거할 때 Backlog에서 키를 삭제하세요.
- **쓰기는 승인을 거칩니다.** 이슈, 위키, 마일스톤 변경은 [승인](/guide/approvals/overview)을 거치며, Approval mode가 각 변경을 결정합니다. 사람이 모든 변경을 확인해야 한다면 **Manual**을 선택하고, 키에는 그 변경에 필요한 것 이상의 쓰기 권한을 주지 마세요.

Coralogix 팀을 연결하면 CloudThinker 에이전트가 열린 인시던트를 분류하고, 로그와 트레이스를 검색하고, 메트릭을 쿼리하고, 알림과 대시보드를 검사하고, 데이터 파이프라인에서 비활성화된 파싱 규칙이나 잘못 구성된 커넥터를 확인할 수 있습니다. 연결은 Coralogix의 호스팅 MCP 서버를 사용하며, 하나의 **region**에 대한 하나의 **API key**로 로그인합니다. 리전을 선택하면 CloudThinker가 해당 Coralogix 엔드포인트로 라우팅하므로 URL을 입력할 필요가 없습니다.

## 사전 요구 사항

- 에이전트가 읽을 데이터가 있는 Coralogix 팀.
- 해당 팀의 API 키를 만들 수 있는 권한.
- 팀의 리전. 로그인 주소에서 확인합니다([리전 표](#연결-세부-정보) 참조).

## 설정

<Steps>
  <Step title="리전 찾기">
    Coralogix에 로그인하고 주소 표시줄을 [리전 표](#연결-세부-정보)와 비교합니다. 일부 리전은 주소에 이름이 나타나지 않습니다. `acme.coralogix.com`은 EU1이고 `acme.app.cx498.coralogix.com`은 US2입니다.
  </Step>
  <Step title="API 키 만들기">
    **Settings → API Keys**로 이동하여 새 키를 만듭니다.

    - **Name**: `cloudthinker`
    - **Type**: **Team key**. 개인 키는 한 사용자에게 묶여 있어 그 사용자의 접근이 끝나면 작동을 멈춥니다.
    - **Permissions**: 에이전트가 접근해야 할 데이터에 대한 읽기 권한([필수 권한](#필수-권한) 참조)

    키를 즉시 복사하세요. 분실하면 새 키가 필요합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **Coralogix**를 선택합니다. 다음을 입력합니다.

    - **CORALOGIX_API_KEY**: 만든 키
    - **CORALOGIX_REGION**: 목록에서 리전을 선택합니다(예: **EU2 (eu2.coralogix.com)**). 기본값은 **US2 (us2.coralogix.com)**이므로 팀이 다른 리전에 있다면 변경하세요.

    **Connect**를 클릭합니다.

    **성공 상태:** Coralogix에 **Connected**가 표시됩니다. 아래 확인 프롬프트를 실행하여 키와 리전이 일치하는지 확인하세요.
  </Step>
</Steps>

<Warning>
키는 생성된 리전에서만 작동합니다. 잘못된 리전은 **404 Not Found**로 나타나며, 데이터가 없는 것처럼 보입니다. 다른 것을 디버깅하기 전에 로그인 주소를 확인하세요.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **CORALOGIX_API_KEY** | Coralogix 팀 API 키 | `<your-api-key>` |
| **CORALOGIX_REGION** | 팀 로그인 주소와 일치하는 리전 | **EU2 (eu2.coralogix.com)** |

왼쪽 열에서 로그인 주소를 찾은 다음 오른쪽 옵션을 선택하세요.

| 로그인 주소 | **CORALOGIX_REGION**에서 선택 |
|---------------|------------------------------|
| `<team>.app.coralogix.us` | **US1 (us1.coralogix.com)** |
| `<team>.app.cx498.coralogix.com` | **US2 (us2.coralogix.com)**, 기본값 |
| `<team>.app.us3.coralogix.com` | **US3 (us3.coralogix.com)** |
| `<team>.coralogix.com` | **EU1 (eu1.coralogix.com)** |
| `<team>.app.eu2.coralogix.com` | **EU2 (eu2.coralogix.com)** |
| `<team>.app.coralogix.in` | **AP1 (ap1.coralogix.com)** |
| `<team>.app.coralogixsg.com` | **AP2 (ap2.coralogix.com)** |
| `<team>.app.ap3.coralogix.com` | **AP3 (ap3.coralogix.com)** |

다른 팀이나 리전에 접근하려면 자체 키를 사용하는 별도 연결로 추가하세요.

## 필수 권한

에이전트가 조사할 데이터에 대한 읽기 권한을 키에 부여하세요.

| 데이터 | 용도 |
|------|----------|
| Incidents | 인시던트 분류와 탐색 |
| Logs and traces | 오류 검색과 요청 추적 |
| Metrics | 메트릭 쿼리와 메트릭 카탈로그 |
| Alerts and dashboards | 알림 정의와 대시보드 검사 |
| Parsing rules, connectors, presets | 파이프라인 상태 점검 |

파싱 규칙 활성화처럼 에이전트가 Coralogix 리소스를 변경하기를 원하지 않는다면 키의 쓰기 권한은 꺼 두세요. 이 페이지의 모든 조사는 읽기 전용 키로 충분합니다.

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 | 승인 |
|------------|--------------------|----------|
| **탐색** | 열린 인시던트, 커넥터 수, 비활성화된 파싱 규칙, 프리셋, 메트릭 검색 작동 여부 요약 | 아니요 |
| **인시던트 분류** | 심각도, 상태, 타임스탬프와 함께 최근 및 열린 인시던트 나열 | 아니요 |
| **로그** | 시간 범위에 걸쳐 로그 검색 | 아니요 |
| **트레이스** | 분산 트레이스 검사 | 아니요 |
| **메트릭** | 메트릭 쿼리와 메트릭 카탈로그 검색 | 아니요 |
| **파이프라인 상태** | 비활성화되었거나 숨겨진 파싱 규칙을 찾고 커넥터와 프리셋 검토 | 아니요 |
| **알림과 대시보드** | 알림 정의와 대시보드 읽기 | 아니요 |
| **변경** | Coralogix 리소스 생성, 업데이트, 활성화, 비활성화 또는 삭제. 키에 쓰기 권한이 필요합니다 | 예 |

에이전트는 탐색, 분류, 상태 점검 중에는 아무것도 변경하지 않습니다. 변경은 대화에서 리소스와 변경 내용을 지정하여 요청할 때만 일어나며, [Approvals](/guide/approvals/overview)를 거칩니다. 에이전트는 큰 카탈로그가 답을 뒤덮지 않도록 기본적으로 샘플을 10개 항목으로 제한합니다.

### 연결 확인

```text
Run Coralogix discovery and summarize open incidents, connector count, disabled parsing rules, and whether metric search is healthy
```

인시던트, 커넥터, 파싱 규칙, 프리셋의 개수와 각각의 짧은 샘플이 표시되어야 합니다. 메트릭 점검에서 "No metrics matched"는 정상입니다. 탐색은 존재하지 않는 이름으로 확인합니다. 요약에 **degraded**가 표시되면 에이전트가 실패한 점검(incidents, connectors, parsing rules, presets, metrics)을 나열합니다. 점검이 실패하면 보통 키에 해당 데이터의 읽기 권한이 없다는 뜻입니다. 모든 점검이 실패하면 키와 리전을 먼저 확인하세요.

### 예시 프롬프트

```text
Triage open Coralogix incidents and flag anything affecting production
Search Coralogix logs for 5xx errors from the api-gateway service in the last hour
Check Coralogix pipeline health and list disabled parsing rules
Which Coralogix alerts fired for the payments service today?
```

서비스 이름과 짧은 시간 범위를 지정하세요. 좁은 쿼리가 더 빨리 돌아오고 읽기 쉽습니다.

## 문제 해결

<Accordion title="연결이 실패하거나 요청이 401을 반환함">
키가 없거나, 만료되었거나, 취소되었습니다. 새 팀 키를 만들고 연결을 편집하여 **CORALOGIX_API_KEY**에 붙여 넣으세요.
</Accordion>

<Accordion title="모든 것이 404를 반환함">
키가 다른 리전에 속해 있습니다. 로그인 주소를 확인하고 **CORALOGIX_REGION**을 그에 맞게 변경하세요.
</Accordion>

<Accordion title="일부 데이터 유형은 실패하고 나머지는 작동함">
키에 해당 데이터의 읽기 권한이 없습니다. Coralogix에서 권한을 추가한 다음 요청을 다시 실행하세요. 키 자체가 바뀌지 않았다면 다시 연결할 필요가 없습니다.
</Accordion>

<Accordion title="메트릭 쿼리가 아무것도 반환하지 않음">
해당 이름과 일치하는 메트릭이 없거나 팀이 메트릭을 보내지 않습니다. 에이전트는 이를 빈 결과로 처리합니다. 존재하는 것으로 알고 있는 메트릭 이름을 사용하거나, 인시던트와 로그로 계속 진행하세요.
</Accordion>

<Accordion title="요청이 429 또는 503을 반환함">
Coralogix가 속도 제한 중이거나 유지 관리 중입니다. 1분 기다렸다가 요청 범위를 좁혀 다시 요청하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **팀 키, 읽기 권한부터**: 에이전트가 제안할 수 있기를 원하는 변경에 대해서만 쓰기 권한을 추가하세요.
- **연결당 키 하나**: CloudThinker 전용 키를 만들어 다른 도구에 영향을 주지 않고 취소할 수 있게 하세요.

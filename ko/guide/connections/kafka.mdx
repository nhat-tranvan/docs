Confluent Cloud 또는 셀프 호스팅 Apache Kafka 클러스터를 연결하면 CloudThinker 에이전트가 토픽과 그 구성을 나열하고, 메시지를 샘플링하고, 처리량 메트릭을 쿼리하고, 스키마와 커넥터를 감사하고, Flink SQL 문을 진단할 수 있습니다. **JSON credentials file** 하나를 업로드하여 연결합니다. 이 파일에는 부트스트랩 주소와, 켜려는 범위마다 하나씩 Confluent API 키 쌍이 들어갑니다.

## 사전 요구 사항

- **Confluent Cloud**: Kafka 클러스터가 하나 이상 있는 환경과, 가급적 서비스 계정용으로 API 키를 만들 수 있는 권한.
- **셀프 호스팅 Kafka**: CloudThinker가 네트워크로 접근할 수 있는 부트스트랩 주소(기본 포트 `9092`)를 가진 브로커. 파일에는 SASL/SCRAM, mTLS, 클라이언트 인증서, 사용자 지정 CA 설정이 없으므로, 브로커가 이것들 없이 CloudThinker의 연결을 받아들여야 합니다. 이런 브로커를 인터넷에 공개하지 말고 CloudThinker의 egress IP로 제한하세요. 이 문서는 CloudThinker의 egress IP 목록을 공개하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의하기](https://cloudthinker.io/contact)를 이용하세요. 다른 방법은 [비공개 서비스 접근](/ko/guide/connections/overview#비공개-서비스-접근)을 참조하세요.
- JSON 파일을 작성할 텍스트 편집기.
- 연결을 추가하고 편집할 수 있는 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참조하세요.

## 범위 선택

Confluent Cloud에서는 각 API 키 쌍이 하나의 범위를 엽니다. Kafka 클러스터 범위로 시작하고, 나중에 [업데이트된 파일을 업로드](#나중에-파일-변경)하여 다른 범위를 추가하세요. 셀프 호스팅 Kafka에서는 `BOOTSTRAP_SERVERS`와 선택 사항인 `SCHEMA_REGISTRY_ENDPOINT`만 적용되며, 나머지 범위는 모두 Confluent Cloud 전용입니다.

| 범위 | 에이전트가 할 수 있는 작업 | 필드 |
|-------|----------------------------|--------|
| **Kafka cluster** (필수) | 토픽 나열, 토픽 구성 읽기, 메시지 샘플링과 생성, 토픽 생성 또는 삭제 | `BOOTSTRAP_SERVERS`(두 플랫폼 모두). Confluent Cloud 전용: `KAFKA_API_KEY`, `KAFKA_API_SECRET`, `KAFKA_REST_ENDPOINT`, `KAFKA_CLUSTER_ID`, `KAFKA_ENV_ID` |
| **Cloud resource management** | 환경과 클러스터 나열, 수신 바이트 같은 메트릭 쿼리, 청구 비용 나열, 커넥터와 토픽 태그 관리 | `CONFLUENT_CLOUD_API_KEY`, `CONFLUENT_CLOUD_API_SECRET` |
| **Schema Registry** | 스키마 subject와 버전 나열, 스키마 삭제 | `SCHEMA_REGISTRY_ENDPOINT`, `SCHEMA_REGISTRY_API_KEY`, `SCHEMA_REGISTRY_API_SECRET` |
| **Flink** | Flink SQL 문 실행과 검사, 카탈로그와 테이블 탐색, 문 상태 점검 실행 | `FLINK_API_KEY`, `FLINK_API_SECRET`, `FLINK_REST_ENDPOINT`, `FLINK_COMPUTE_POOL_ID`, `FLINK_ENV_ID`, `FLINK_ORG_ID`, 선택 사항 `FLINK_ENV_NAME`, `FLINK_DATABASE_NAME` |
| **Tableflow** | Tableflow 토픽과 카탈로그 통합 나열과 관리 | `TABLEFLOW_API_KEY`, `TABLEFLOW_API_SECRET` |

## 설정

<Tabs>
  <Tab title="Confluent Cloud">
    <Steps>
      <Step title="클러스터 필드 수집">
        [Confluent Cloud](https://confluent.cloud/home)에서 **Environments**를 열고 환경을 선택합니다. 환경 ID(`env-...`)가 `KAFKA_ENV_ID`입니다. 클러스터를 열고 부트스트랩 서버, REST 엔드포인트, 클러스터 ID(`lkc-...`)를 복사합니다.
      </Step>
      <Step title="범위마다 API 키 쌍 하나 만들기">
        **Settings → API keys**로 이동하여 **Add API key**를 클릭합니다. 프로덕션에서는 **Service account**를 선택합니다. 먼저 Kafka 클러스터 키를 만든 다음, 선택한 선택 범위마다 키를 하나씩 만듭니다. 만들 때마다 각 키와 시크릿을 저장합니다. 각 범위에 맞는 리소스를 선택하세요.

        | 범위 | 마법사에서 선택 | 그다음 선택 |
        |-------|----------------------|-------------|
        | Kafka cluster | **Kafka cluster** | 1단계의 클러스터 |
        | Cloud resource management | **Cloud resource management** | 더 선택할 것 없음. 조직 전체를 다룹니다 |
        | Schema Registry | **Schema Registry** | 1단계의 환경 |
        | Flink | **Flink region** | 컴퓨트 풀의 환경, 클라우드, 리전 |
        | Tableflow | **Tableflow** | 더 선택할 것 없음 |
      </Step>
      <Step title="선택 범위 필드 수집">
        - **Schema Registry**: 환경에서 **Stream Governance → Schema Registry**를 열고 엔드포인트를 복사합니다.
        - **Flink**: **Flink → Compute pools**를 열고 풀을 선택한 다음 ID(`lfcp-...`)를 복사합니다. REST 엔드포인트는 `https://flink.<region>.<provider>.confluent.cloud` 패턴을 따릅니다(예: `https://flink.us-east-1.aws.confluent.cloud`). `FLINK_ENV_ID`는 풀이 있는 환경의 `env-...` ID로, 보통 `KAFKA_ENV_ID`와 같은 값입니다. 조직 ID는 **Settings → Organizations**에 있습니다.
        - **선택 사항인 Flink 기본값**: `FLINK_ENV_NAME`은 환경의 표시 이름으로 기본 카탈로그로 사용됩니다. `FLINK_DATABASE_NAME`은 Kafka 클러스터의 표시 이름으로 기본 데이터베이스로 사용됩니다. 이를 설정하면 에이전트가 전체 `catalog.database.table` 경로 없이 테이블 이름을 지정할 수 있습니다.
      </Step>
      <Step title="JSON 파일 작성">
        `kafka.json` 같은 파일을 저장합니다. 키를 만든 범위만 남기고, 나머지 줄은 완전히 삭제합니다.

        ```json
        {
          "BOOTSTRAP_SERVERS": "pkc-xxxxx.us-east-1.aws.confluent.cloud:9092",
          "KAFKA_API_KEY": "<kafka-api-key>",
          "KAFKA_API_SECRET": "<kafka-api-secret>",
          "KAFKA_REST_ENDPOINT": "https://pkc-xxxxx.us-east-1.aws.confluent.cloud:443",
          "KAFKA_CLUSTER_ID": "lkc-xxxxx",
          "KAFKA_ENV_ID": "env-xxxxx",

          "CONFLUENT_CLOUD_API_KEY": "<cloud-api-key>",
          "CONFLUENT_CLOUD_API_SECRET": "<cloud-api-secret>",

          "SCHEMA_REGISTRY_ENDPOINT": "https://psrc-xxxxx.us-east-1.aws.confluent.cloud",
          "SCHEMA_REGISTRY_API_KEY": "<schema-registry-api-key>",
          "SCHEMA_REGISTRY_API_SECRET": "<schema-registry-api-secret>",

          "FLINK_API_KEY": "<flink-api-key>",
          "FLINK_API_SECRET": "<flink-api-secret>",
          "FLINK_REST_ENDPOINT": "https://flink.us-east-1.aws.confluent.cloud",
          "FLINK_COMPUTE_POOL_ID": "lfcp-xxxxx",
          "FLINK_ENV_ID": "env-xxxxx",
          "FLINK_ORG_ID": "<org-id>",

          "TABLEFLOW_API_KEY": "<tableflow-api-key>",
          "TABLEFLOW_API_SECRET": "<tableflow-api-secret>"
        }
        ```
      </Step>
      <Step title="CloudThinker에서 파일 업로드">
        **Settings → Workspace → Connections**를 열고 **Apache Kafka**를 선택합니다. 파일을 업로드 영역으로 끌어다 놓거나 **choose a JSON file**을 클릭합니다. **Connect**를 클릭합니다.

        **성공 상태:** 연결에 **Connected** 상태가 표시됩니다. 아래 확인 프롬프트를 실행하여 에이전트가 토픽을 볼 수 있는지 확인하세요.
      </Step>
    </Steps>
  </Tab>
  <Tab title="셀프 호스팅 Kafka">
    <Steps>
      <Step title="네트워크 접근 열기">
        CloudThinker가 브로커의 부트스트랩 주소(기본 포트 `9092`)에 접근할 수 있도록 허용합니다. `127.0.0.1`에만 바인딩된 브로커에는 접근할 수 없습니다.
      </Step>
      <Step title="JSON 파일 작성">
        부트스트랩 주소와, Schema Registry를 운영한다면 그 엔드포인트(보통 포트 `8081`)를 넣어 `kafka.json` 같은 파일을 저장합니다.

        ```json
        {
          "BOOTSTRAP_SERVERS": "kafka-1.example.com:9092",
          "SCHEMA_REGISTRY_ENDPOINT": "https://schema-registry.example.com:8081"
        }
        ```
      </Step>
      <Step title="CloudThinker에서 파일 업로드">
        **Settings → Workspace → Connections**를 열고 **Apache Kafka**를 선택합니다. 파일을 업로드하고 **Connect**를 클릭합니다.

        **성공 상태:** 연결에 **Connected** 상태가 표시됩니다.
      </Step>
    </Steps>

    셀프 호스팅 Kafka에서는 에이전트가 브로커 자체를 통해 작업합니다. 토픽 나열과 메시지 샘플링 또는 생성, 그리고 Schema Registry 엔드포인트를 설정한 경우 스키마 작업이 가능합니다. 메트릭, 청구, 커넥터, Flink, Tableflow는 Confluent Cloud API이므로 사용할 수 없습니다.
  </Tab>
</Tabs>

## 연결 세부 정보

양식에는 업로드 필드가 하나 있습니다. 파일은 문자열 값을 가진 하나의 JSON 객체여야 하며, [범위 선택](#범위-선택)에 나열된 키만 사용해야 합니다. 다른 키가 있거나 값이 문자열이 아닌 파일은 거부됩니다.

| 필드 | 필수 | 설명 |
|-------|----------|-------------|
| `BOOTSTRAP_SERVERS` | 예 | 브로커 부트스트랩 주소, `host:port` |
| `KAFKA_API_KEY` / `KAFKA_API_SECRET` | Confluent Cloud | Kafka 클러스터 키 쌍 |
| `KAFKA_REST_ENDPOINT`, `KAFKA_CLUSTER_ID`, `KAFKA_ENV_ID` | Confluent Cloud | 클러스터 REST 엔드포인트, 클러스터 ID, 환경 ID |
| `SCHEMA_REGISTRY_ENDPOINT` | 아니요 | 두 플랫폼 모두의 Schema Registry URL |
| 기타 범위 키 | 아니요 | [범위 선택](#범위-선택)을 참조하세요 |

## 필수 권한

**Confluent Cloud:** 서비스 계정용으로 키를 만들고, 그 계정에는 에이전트에게 필요한 것만 부여하세요.

- **Kafka cluster**: ACL을 에이전트가 읽어야 할 토픽으로 제한합니다. 메시지 샘플링은 컨슈머 그룹을 통해 읽으므로, 계정에 컨슈머 그룹에 대한 `READ`도 필요합니다.

  ```bash
  confluent kafka acl create --allow --service-account sa-xxxxx \
    --operations read,describe,describe-configs --topic orders --cluster lkc-xxxxx
  confluent kafka acl create --allow --service-account sa-xxxxx \
    --operations read --consumer-group "*" --cluster lkc-xxxxx
  ```

- **Cloud resource management**: 메트릭을 위해 최소 **MetricsViewer**.
- **Schema Registry**: 에이전트가 나열할 subject에 대한 **DeveloperRead**.
- **Flink**: 컴퓨트 풀이 있는 환경에서 **FlinkDeveloper**.

**셀프 호스팅 Kafka:** 연결에는 부트스트랩 주소만 필요합니다.

<Tip>
Kafka 클러스터 범위와 읽기 전용 ACL로 시작하세요. 에이전트가 메시지를 생성하거나 토픽을 만들게 하려는 경우가 아니라면 서비스 계정에 쓰기 ACL을 주지 마세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 | Approvals를 거침 |
|------------|--------------------|------------------------|
| **토픽 인벤토리** | 파티션 수와 함께 토픽 나열, 토픽 구성 읽기, 이름이나 태그로 토픽 검색 | 아니요 |
| **메시지 샘플링** | 정해진 수의 최근 메시지를 읽고, 구성된 경우 Schema Registry로 디코딩 | 아니요 |
| **메트릭과 청구** | 수신 바이트 같은 Confluent Cloud 메트릭 쿼리와 청구 비용 나열 | 아니요 |
| **스키마와 커넥터** | 스키마 subject와 버전 나열, 커넥터 나열과 읽기 | 아니요 |
| **Flink SQL 읽기** | 카탈로그와 테이블 탐색, 문과 그 예외 읽기, 상태 점검 실행 | 아니요 |
| **Flink SQL 문** | Flink SQL 문 실행 | 예 |
| **생성과 만들기** | 메시지 생성, 토픽 만들기 | 예 |
| **변경과 삭제** | 토픽, 스키마, 커넥터 또는 Flink 문 삭제, 토픽 구성 변경, 커넥터 생성, 태그 삭제, Tableflow 변경 | 예 |

**예**로 표시된 호출은 먼저 워크스페이스 [Approvals](/guide/approvals/overview)를 거칩니다.

<ApprovalDefault />

<Warning>
Flink 문은 읽기 이상을 할 수 있습니다. `INSERT INTO`는 토픽에 쓰고, 연속 실행 문은 누군가 삭제할 때까지 컴퓨트 풀에서 계속 실행되며 비용이 드는 용량을 사용합니다. 승인하기 전에 문을 읽어 보세요.
</Warning>

파티션 수는 토픽 구성으로 변경할 수 없습니다. Confluent Cloud UI를 사용하거나, 토픽을 삭제하고 다시 만드세요.

### 연결 확인

```text
List my Kafka topics with partition counts and replication factor
```

클러스터의 모든 토픽이 파티션 수와 복제 계수와 함께 표시되어야 합니다. cloud 범위가 있는 Confluent Cloud에서는 에이전트가 환경과 클러스터 이름도 알려 줄 수 있습니다.

### 예시 프롬프트

```text
Show the last 10 messages on the orders topic, decoded with Schema Registry
Chart received bytes per 5 minutes for my Kafka cluster over the last 6 hours
Why is my Flink statement order-enrichment failing?
```

## 나중에 파일 변경

범위를 추가하거나 키를 교체하려면 유지하려는 모든 범위를 담은 완전한 파일을 작성하세요. 연결을 열고 해당 행의 연필 아이콘을 클릭한 다음, **Edit Instance**에서 **Replace…**를 클릭합니다. 파일을 업로드하고 **Save and test**를 클릭합니다. 테스트가 실패하면 CloudThinker가 이전 자격 증명을 유지합니다. [자격 증명 교체](/ko/guide/connections/overview#자격-증명-교체)를 참조하세요.

## 문제 해결

<Accordion title="Connection refused 또는 시간 초과">
CloudThinker에서 브로커에 접근할 수 없습니다. 브로커가 실행 중인지, 방화벽에서 `9092`가 열려 있는지, `BOOTSTRAP_SERVERS`가 올바른지 확인하세요. `127.0.0.1`에만 바인딩된 브로커는 호스트 외부에서 접근할 수 없습니다.
</Accordion>

<Accordion title="일부만 채운 파일을 업로드한 후 검증 오류 발생">
범위 키가 빈 값으로 들어 있습니다. 사용하지 않는 범위의 키와 값을 통째로 삭제하세요. `"SCHEMA_REGISTRY_ENDPOINT": ""`는 실패하지만, 키를 빼면 작동합니다.
</Accordion>

<Accordion title="401 Unauthorized">
키 쌍이 잘못되었거나, 만료되었거나, 다른 범위에 사용되었습니다. 각 범위에는 자체 키 쌍이 필요합니다. Kafka 클러스터 키는 Schema Registry나 Flink에서 작동하지 않습니다. 해당 범위의 새 키 쌍을 만들고 [업데이트된 파일을 업로드](#나중에-파일-변경)하세요.
</Accordion>

<Accordion title="메트릭 또는 청구 질문이 실패함">
파일에 `CONFLUENT_CLOUD_API_KEY` 쌍이 없거나, 그 계정에 **MetricsViewer**가 없습니다. cloud 범위를 추가하고 [파일을 다시 업로드](#나중에-파일-변경)하세요. 셀프 호스팅 클러스터에서는 이 API를 사용할 수 없습니다.
</Accordion>

<Accordion title="Schema Registry가 실패함">
CloudThinker에서 `SCHEMA_REGISTRY_ENDPOINT`에 접근할 수 있는지 확인하세요. 셀프 호스팅에서는 포트 `8081`을 여세요. Confluent Cloud에서는 Schema Registry 키가 같은 환경에 속하는지 확인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **셀프 호스팅 Kafka는 자격 증명을 받지 않음**: 위의 읽기 전용 권장 사항은 Confluent Cloud 키에만 적용됩니다. 셀프 호스팅 브로커는 자체 구성이 허용하는 모든 것을 받아들이므로, 아래와 같이 네트워크 접근을 제한하고, 생성과 만들기 호출은 여전히 Approvals를 거친다는 점을 기억하세요.
- **범위마다 키 쌍 하나**: 서비스 계정에서 범위마다 별도의 키를 주면, Kafka 클러스터 키를 건드리지 않고 Flink나 Tableflow 접근을 취소할 수 있습니다.
- **네트워크 접근 제한**: 방화벽 규칙으로 부트스트랩과 REST 엔드포인트를 CloudThinker의 트래픽으로 제한하세요. 자격 증명이 없는 셀프 호스팅 브로커에서는 특히 중요합니다.
- **로컬 파일 삭제**: JSON 파일에는 모든 시크릿이 평문으로 들어 있습니다. 업로드한 후 삭제하거나 시크릿 관리자에만 보관하세요.
- **메시지를 민감 정보로 취급**: 샘플링된 메시지에는 프로듀서가 기록한 개인 데이터나 토큰이 포함될 수 있습니다. 에이전트가 봐야 할 토픽에만 `READ`를 부여하세요.

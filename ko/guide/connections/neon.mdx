Neon을 연결하면 CloudThinker 에이전트가 프로젝트, 브랜치, 컴퓨트를 나열하고, 테이블 스키마를 검사하고, 느린 쿼리를 찾을 수 있으며, 워크스페이스의 Approvals를 거쳐 SQL 실행, 브랜치 변경, 마이그레이션 적용도 할 수 있습니다. Neon은 Neon의 호스팅 MCP 서버(MCP는 에이전트가 서비스의 도구를 호출할 때 사용하는 프로토콜)를 통해 **OAuth**로 연결하므로, API 키를 만들거나 붙여 넣지 않습니다.

<Warning>
Neon의 승인 페이지에는 **Allow writes** 체크박스가 있습니다. 체크한 채로 두면 기본 Approval mode에서 AI가 브랜치 삭제나 재설정 같은 쓰기를 스스로 승인할 수 있습니다. 프로덕션 프로젝트가 있는 계정이라면 승인할 때 **Allow writes**의 체크를 해제하거나, **Manual**을 선택하여 모든 쓰기가 사람을 기다리게 하세요. [Ask first 또는 Deny Rule](#쓰기-권한)로 이 연결에만 같은 효과를 줄 수도 있습니다.
</Warning>

---

## 사전 요구 사항

- 조사할 프로젝트를 볼 수 있는 Neon 계정.
- 연결을 추가할 수 있는 CloudThinker의 워크스페이스 Admin 역할. [접근 권한이 작동하는 방식](/ko/guide/connections/overview#접근-권한이-작동하는-방식)을 참조하세요.
- 선택 사항: 느린 쿼리 분석을 원하는 데이터베이스의 `pg_stat_statements` 확장. Neon Console **SQL Editor**(또는 Postgres 클라이언트)에서 분석할 각 데이터베이스마다 한 번씩 `CREATE EXTENSION IF NOT EXISTS pg_stat_statements;`를 실행하세요.

## 설정

<Steps>
  <Step title="Neon 연결 열기">
    **Settings → Workspace → Connections**를 엽니다. **Discover** 탭에서 **Neon**을 검색하고 **Connect**를 클릭합니다.
  </Step>
  <Step title="Neon에서 CloudThinker 승인">
    CloudThinker가 새 창에서 Neon을 엽니다. 프로젝트를 소유하거나 접근할 수 있는 Neon 계정으로 로그인한 다음 접근을 승인합니다. 읽기 전용으로 연결하려면 Neon의 승인 페이지에서 **Allow writes**의 체크를 해제하세요. 그러면 에이전트는 프로젝트를 나열하고, 스키마를 읽고, 느린 쿼리를 나열할 수 있지만, 브랜치 변경, 마이그레이션 및 기타 쓰기는 제공되지 않습니다. SQL은 다릅니다. CloudThinker는 Neon의 SQL 도구를 통한 모든 문을 `SELECT`까지 포함해 변경으로 취급하므로, 체크박스를 어떻게 설정하든 각 문은 Approvals를 거칩니다. [쓰기 권한](#쓰기-권한)을 참조하세요. **Allow writes**를 체크하면 CloudThinker는 해당 계정과 같은 접근 권한을 받습니다.

    창이 열리지 않으면 브라우저가 팝업을 차단한 것입니다. CloudThinker가 대신 대화상자를 표시하므로, 그 안의 **Open Neon**을 클릭하세요.
  </Step>
  <Step title="CloudThinker로 돌아오기">
    CloudThinker 탭으로 다시 전환합니다. **Open Neon** 대화상자를 사용했다면 연결이 준비되면 스스로 닫힙니다.

    **성공 상태:** Neon에 **Connected** 상태가 표시됩니다.
  </Step>
  <Step title="확인 프롬프트 실행">
    [확인 프롬프트](#연결-확인)를 실행하여 승인한 계정이 예상한 프로젝트를 보는지 확인합니다.

    **성공 상태:** CloudThinker가 Neon 조직과 프로젝트를 브랜치 및 컴퓨트와 함께 나열합니다.
  </Step>
</Steps>

## 연결 세부 정보

Neon에는 입력할 필드가 없습니다. Neon이 승인 중에 OAuth 토큰을 발급하고 CloudThinker가 이를 저장합니다.

워크스페이스는 Neon 연결을 하나만 가질 수 있습니다. 다른 Neon 계정을 사용하려면 Neon 연결에서 **Disconnect**를 클릭한 다음, **Connect**를 클릭하고 다른 계정으로 로그인하세요.

---

## 필수 권한

CloudThinker는 승인한 Neon 계정의 접근 권한을 받으며, Neon의 승인 페이지에서 **Allow writes**의 체크를 해제했다면 읽기로 제한됩니다. 어느 쪽이든 계정을 신중하게 선택하세요.

| 에이전트가 할 수 있는 작업 | 필요한 것 |
|------------|-------|
| 프로젝트, 브랜치, 컴퓨트, 테이블 나열, 스키마 읽기 | Neon에서 프로젝트에 대한 접근 권한 |
| 느린 쿼리 분석 | 프로젝트에 대한 접근 권한과 데이터베이스에서 활성화된 `pg_stat_statements` |
| `SELECT`와 `EXPLAIN`을 포함한 SQL 실행 | 프로젝트에 대한 접근 권한과 문마다 [승인](/guide/approvals/overview) 통과. 스키마나 데이터를 변경하는 문에는 Neon의 쓰기 권한과 승인 시 체크한 **Allow writes**도 필요합니다 |
| 브랜치 생성 또는 삭제, 브랜치 재설정, 마이그레이션 적용, 쿼리 튜닝, Neon Auth 또는 Data API 설정 | Neon의 쓰기 권한, 승인 시 체크한 **Allow writes**, 그리고 [승인](/guide/approvals/overview) 통과 |

모든 Neon 조직 멤버는 그 조직의 모든 프로젝트를 봅니다. 에이전트가 접근하는 범위를 제한하려면 조직에 속하지 않은 별도의 Neon 계정으로 승인하고, 에이전트에게 필요한 프로젝트만 그 계정과 공유하세요. 그런 프로젝트는 공유 프로젝트로 표시됩니다. 프로덕션에서는 이것이 안전한 기본값입니다. 에이전트에게 필요한 프로젝트만 공유된 전용 계정을 사용하고, 연결하기 전에 **Manual**을 선택하여 사람이 모든 문을 승인하게 하세요.

## 에이전트 기능

| 기능 | 설명 |
|------------|-------------|
| **프로젝트 탐색** | 조직, 자신의 프로젝트와 공유 프로젝트, 브랜치 컴퓨트, 데이터베이스 테이블 나열 |
| **스키마 감사** | 프로젝트와 그 테이블의 스키마 설명 |
| **느린 쿼리 감사** | 가장 느린 쿼리를 나열한 다음 `SELECT` 문에 `EXPLAIN` 실행. 나열에는 승인이 필요 없습니다. `EXPLAIN`은 Neon의 SQL 도구로 실행되므로 다른 문과 마찬가지로 승인을 요청할 수 있습니다 |
| **SQL** | 문 또는 트랜잭션 실행. CloudThinker가 먼저 정확한 SQL을 보여 주고 스키마나 데이터를 변경하는지 알려 줍니다. |
| **브랜치** | 브랜치 생성, 삭제 또는 부모 브랜치로부터 재설정 |
| **마이그레이션과 튜닝** | 마이그레이션이나 쿼리 튜닝을 준비하고, 결과를 보여 준 다음, 별도의 승인된 단계로 완료 |
| **Neon Auth와 Data API** | [Neon Auth](https://neon.com/docs/neon-auth/overview)(데이터베이스에 저장되는 앱 사용자용 관리형 로그인)를 프로비저닝하고 구성하며, [Data API](https://neon.com/docs/data-api/get-started)(데이터베이스 테이블 위의 HTTP API)를 프로비저닝합니다. 둘 다 앱 사용자가 로그인하거나 데이터에 접근하는 방식을 바꾸는 쓰기이므로 승인을 거칩니다 |

0으로 축소된 컴퓨트에서 SQL이나 `EXPLAIN`을 실행하면 컴퓨트가 깨어나며, Neon은 실행되는 동안의 컴퓨트 시간을 청구합니다.

CloudThinker는 마이그레이션을 준비한 단계에서 바로 완료하지 않습니다. 무엇이든 적용되기 전에 무엇이 바뀌는지 확인할 수 있습니다.

<Tip>
Neon Auth와 Data API는 앱 사용자가 접근할 수 있는 범위를 바꿉니다. AI 판단에 맡기지 말고 **Manual**을 선택하여 사람이 각각을 승인하게 하세요. **Ask first** Rule로 이 두 가지만 따로 지정할 수도 있습니다.
</Tip>

### 연결 확인

```text
Check my Neon connection: list my organizations and projects with their branches and computes
```

**성공 상태:** CloudThinker가 Neon 조직과 프로젝트를 브랜치 및 컴퓨트와 함께 나열합니다.

### 예시 프롬프트

```text
Find the slowest queries on my production-db Neon project and suggest indexes
Describe the schema of the users table on the main branch of production-db
Prepare a migration on production-db that adds a last_login_at column to users, and show me the plan first
```

## 쓰기 권한

Neon의 읽기 전용 옵션은 승인 페이지의 **Allow writes** 체크박스입니다. 나중에 변경하려면 **Disconnect**를 클릭한 다음 다시 **Connect**를 클릭하고 체크박스를 설정하세요. 쓰기가 허용되면 각 SQL 문, 브랜치 변경, 마이그레이션은 변경으로 간주됩니다.

<ApprovalDefault />

각 선택이 무엇을 하는지는 [The two modes](/guide/approvals/approval-mode#the-two-modes)를 참조하세요.

- **모든 프로덕션 쓰기 승인**: **Manual**을 선택하여 사람이 모든 SQL 문, 브랜치 변경, 마이그레이션을 승인하게 합니다.
- **Neon 계정 자체가 변경할 수 있는 범위 제한**: **Allow writes**의 체크를 해제하고 다시 연결합니다. `SELECT`는 승인되면 여전히 실행되며, 프로젝트, 브랜치, 테이블 나열, 스키마 읽기, 느린 쿼리 목록은 계속 작동합니다.

Rule로 범위를 좁힐 수 있습니다.

- **Rule로 프로덕션 쓰기 승인**: Neon 연결에 **Ask first** Rule을 추가하여 사람이 모든 SQL 문과 마이그레이션을 승인하게 합니다.
- **연결 후 사실상 읽기 전용으로 만들기**: 모든 작업을 다루는 **Deny** Rule을 Neon 연결에 추가합니다. Neon의 SQL 도구를 통한 모든 문은 `SELECT`까지 포함해 변경으로 간주되므로, Deny는 모든 SQL을 막습니다. **Allow writes**의 체크 해제로는 이렇게 되지 않습니다.

두 Rule 중 하나를 만들려면:

<Steps>
  <Step title="Rule 요청">
    채팅에 `/creating-policy Ask first for every write on the Neon connection`을 입력합니다. 차단하려면 대신 **Deny** Rule을 요청하세요.
  </Step>
  <Step title="제안 확인">
    **Settings → Workspace → Autonomy → Rules**를 열고 **Needs review**로 전환한 다음 Rule을 엽니다. **Effect**가 **Ask first**(또는 **Deny**)인지, Rule에 **Every operation** 배지가 있는지, **Connections**에 Neon 연결이 지정되어 있는지 확인합니다. **What would change**에는 최근 Neon 쓰기가 먼저 묻는 것(또는 거부되는 것)으로 표시되어야 합니다.
  </Step>
  <Step title="수락">
    Rule을 선택하고 **Accept**를 클릭합니다.

    **성공 상태:** 토스트가 수락된 Rule을 확인해 주고, Rule이 **Active** 탭으로 이동합니다.
  </Step>
</Steps>

## 문제 해결

<Accordion title="승인 창이 닫히지만 Neon에 Connected가 표시되지 않음">
브라우저가 다른 Neon 계정에 로그인되어 있거나 팝업이 차단되었을 수 있습니다. 같은 브라우저에서 올바른 Neon 계정으로 로그인한 다음 **Connect**를 다시 클릭하세요.
</Accordion>

<Accordion title="에이전트가 예상한 프로젝트를 찾지 못함">
해당 프로젝트에 접근할 수 없는 Neon 계정으로 승인했습니다. **Disconnect**를 클릭한 다음, 그 프로젝트를 볼 수 있는 계정으로 **Connect**하세요. 공유받은 프로젝트는 공유 프로젝트로 표시됩니다.
</Accordion>

<Accordion title="느린 쿼리 분석이 아무것도 반환하지 않거나 실패함">
데이터베이스에 `pg_stat_statements`가 활성화되어 있지 않습니다. `CREATE EXTENSION IF NOT EXISTS pg_stat_statements;`를 실행하고, 트래픽을 어느 정도 발생시킨 다음 다시 요청하세요. 스키마 검사와 SQL은 이것 없이도 작동합니다.
</Accordion>

<Accordion title="조용한 기간 후 느린 쿼리 결과가 비어 있음">
Neon은 컴퓨트가 0으로 축소되면 `pg_stat_statements` 데이터를 유지하지 않으므로, 깨어날 때마다 기록이 처음부터 시작됩니다. 더 긴 기록이 필요하다면 조사하는 컴퓨트에서 scale to zero를 끄세요.
</Accordion>

<Accordion title="이전에 작동하던 Neon에 오류가 표시됨">
OAuth 승인이 만료되었거나 Neon에서 취소되었습니다. 연결의 오류 알림에서 **Connect**를 클릭하여 다시 승인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **기본적으로 연결 문자열 없음**: 에이전트는 요청하지 않는 한 데이터베이스 연결 문자열을 가져오지 않습니다. 연결 문자열에는 데이터베이스 비밀번호가 포함되고 채팅에 표시되므로, 대화를 읽을 수 있는 누구나 이를 읽을 수 있습니다.
- **데이터 경로**: 에이전트는 `https://mcp.neon.tech/mcp`에 있는 Neon의 호스팅 MCP 서버를 호출합니다. SQL, 브랜치, 마이그레이션 요청과 그 결과가 이 서버를 거치고, 결과는 채팅에 표시되므로 대화와 함께 보관됩니다. CloudThinker는 OAuth 토큰을 저장합니다.
- **접근 차단**: Neon 연결에서 **Disconnect**를 클릭하세요. 대신 Neon 쪽에서 권한 부여가 취소되면, 누군가 다시 승인할 때까지 연결에 오류가 표시됩니다.
- **거절은 최종적**: SQL 문이나 마이그레이션을 거절하면 CloudThinker는 다시 시도하지 않습니다. 어떻게 진행할지 묻습니다.

Pulumi Cloud를 연결하면 [CloudThinker](/ko/guide/agents/overview)가 스택을 나열하고, Pulumi가 관리하는 리소스를 찾고, 정책 위반을 분류할 수 있습니다. Pulumi의 OAuth 흐름으로 로그인하므로 Pulumi 액세스 토큰을 CloudThinker에 붙여넣을 필요가 없습니다.

## 사전 요구사항

- 스택을 보유한 조직에 속한 Pulumi Cloud 계정.
- CloudThinker 워크스페이스의 **Admin** 역할. 워크스페이스 Admin만 연결을 추가, 편집, 삭제할 수 있습니다. [Roles](/guide/security/roles)를 참고하세요.

<Info>
프롬프트에서 인증한 계정이 속한 다른 조직을 지정하지 않으면 CloudThinker는 인증한 계정의 기본 Pulumi 조직을 사용합니다.
</Info>

## 설정

<Steps>
  <Step title="Pulumi 연결 열기">
    **Settings → Workspace → Connections**를 열고 **Pulumi**를 선택한 뒤 **Connect**를 클릭합니다. 팝업으로 Pulumi 인증 페이지가 열립니다.
  </Step>
  <Step title="로그인 및 승인">
    스택을 볼 수 있는 Pulumi 계정으로 로그인한 뒤 접근을 승인합니다.
  </Step>
  <Step title="CloudThinker로 돌아오기">
    Pulumi가 CloudThinker로 돌려보내고, CloudThinker가 OAuth 토큰을 대신 저장합니다.

    **성공 상태:** Pulumi 연결에 **Connected** 상태가 표시됩니다.
  </Step>
</Steps>

입력할 필드는 없습니다. Pulumi가 인증 중에 OAuth 토큰을 발급하며, 엔드포인트는 `mcp.ai.pulumi.com`으로 고정되어 있습니다.

## 필요 권한

CloudThinker는 인증한 계정과 동일한 Pulumi 접근 권한을 얻습니다. 조직에 대한 읽기 권한으로 아래의 모든 읽기 기능을 사용할 수 있습니다.

Deploy to AWS와 Neo 작업도 해당 계정으로 실행되므로, 그 계정이 Pulumi에서 같은 작업을 할 수 있을 때만 동작합니다. 읽기 전용 계정이면 Pulumi가 거부합니다.

<Tip>
CloudThinker를 통해 배포할 계획이 아니라면, 조직을 읽을 수는 있지만 관리하지는 않는 계정으로 인증하세요.
</Tip>

## 에이전트 기능

| 기능 | CloudThinker가 하는 일 | Approvals 확인 |
|------------|------------------------|----------|
| **스택 인벤토리** | 스택을 프로젝트 및 마지막 업데이트와 함께 나열 | 아니요 |
| **리소스 검색** | Pulumi가 관리하는 리소스를 이름, 유형, 프로젝트, 스택으로 검색 | 아니요 |
| **정책 검토** | 정책 위반을 시행 수준별로 묶어 영향받는 스택과 함께 나열 | 아니요 |
| **Registry 조회** | Pulumi Registry에서 프로바이더 리소스 및 함수 스키마 읽기 | 아니요 |
| **조직 구성원** | 조직의 구성원 나열 | 아니요 |
| **Pulumi Neo 이력** | 과거 Pulumi Neo 작업 읽기 | 아니요 |
| **Deploy to AWS** | AWS에 리소스 프로비저닝 | 예 |
| **Pulumi Neo 구동** | Neo 작업을 시작하거나 계속하거나, Neo 대화를 초기화 | 예 |

Pulumi Neo는 Pulumi 자체의 AI 에이전트입니다. Neo 작업은 인프라를 배포하고 리포지토리를 변경할 수 있으므로, 작업을 시작하거나 계속할 때 Approvals를 거칩니다.

스택은 조직, 프로젝트, 스택 이름의 조합으로 식별되므로 CloudThinker는 세 가지를 모두 보고합니다. 스택 출력, 구성 값, 시크릿은 출력하지 않습니다.

### 연결 확인

```text
List my Pulumi stacks with their project and organization
```

스택 표가 나와야 합니다. 결과가 비어 있다면 연결이 끊어진 것이 아니라, 인증한 계정의 기본 조직에 스택이 없다는 뜻입니다.

### 예시 프롬프트

```text
Which Pulumi stacks have mandatory policy violations, and which policies fail most often?
Find every S3 bucket Pulumi manages and name the stack that owns each one
Read the aws:s3/bucket schema from the Pulumi Registry and list its required inputs
```

## 쓰기 권한

실제 상태를 바꾸는 도구는 네 개입니다. Deploy to AWS와 Pulumi Neo를 구동하는 세 도구입니다. 각 호출은 개별적으로 Approvals를 거치며, 한 호출을 승인해도 다음 호출이 승인되지는 않습니다.

<ApprovalDefault />

사람이 승인하기 전에 CloudThinker가 먼저 조직, 스택, 영향을 밝힙니다. 호출을 거부하면 CloudThinker는 다시 시도하지 않습니다. 마음이 바뀌면 새 메시지로 다시 요청하세요. 게이트 도구의 동작 방식은 [Approvals](/guide/approvals/overview)를 참고하세요.

<Warning>
스택을 확실히 알아볼 때만 배포를 승인하세요. Pulumi 배포는 실제 리소스를 만들고 클라우드 계정에 요금이 청구됩니다.
</Warning>

CloudThinker는 검토를 마친 Pulumi 도구 목록만 노출합니다. Pulumi가 나중에 추가한 도구는 검토되어 읽기 또는 쓰기로 지정될 때까지 숨겨집니다.

## 문제 해결

<Accordion title="OAuth 흐름이 완료되지 않음">
- **아무것도 열리지 않음:** 브라우저가 팝업을 차단했습니다. CloudThinker의 팝업을 허용한 뒤 **Connect**를 다시 클릭하세요.
- **잘못된 계정:** 브라우저가 다른 Pulumi 계정으로 로그인되어 있습니다. app.pulumi.com에서 올바른 계정으로 로그인한 뒤 **Connect**를 다시 클릭하세요.
- **접근을 거부함:** **Connect**를 다시 클릭하고 Pulumi 페이지에서 승인하세요.
</Accordion>

<Accordion title="CloudThinker가 스택이 없다고 보고함">
프롬프트에서 인증한 계정이 속한 다른 조직을 지정하지 않으면 CloudThinker는 인증한 계정의 기본 Pulumi 조직을 사용합니다. 스택을 보유한 조직을 지정하세요. 계정이 구성원이 아니라면 구성원인 계정으로 다시 연결하세요.
</Accordion>

<Accordion title="CloudThinker가 조직에 접근할 수 없다고 함">
연결은 인증한 Pulumi 사용자가 속한 조직에만 도달합니다. Pulumi에서 해당 사용자를 조직에 추가하거나, 연결을 해제하고 이미 그 조직에 속한 계정으로 인증하세요.
</Accordion>

<Accordion title="배포할 때마다 확인을 요청함">
이는 Approvals이며 호출마다 개별적으로 확인합니다. 계속하려면 대화에서 확인 요청에 응답하세요. 신뢰하는 스택에 대해 더 이상 묻지 않게 하려면 **Allow** [Rule](/guide/approvals/rules)로 해당 호출을 실행하도록 할 수 있습니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **게이트를 유지하세요.** 이 연결에서 클라우드나 리포지토리를 변경할 수 있는 도구는 Deploy to AWS와 Pulumi Neo 도구뿐입니다.
- **계정은 신중하게 바꾸세요.** 연결은 인증한 계정이 도달하는 모든 곳에 도달합니다. 계정을 바꾸려면 **Settings → Workspace → Connections**를 열고 **Pulumi**를 선택한 뒤 상세 패널에서 **Disconnect**를 클릭하고, 다른 계정으로 다시 연결하세요.

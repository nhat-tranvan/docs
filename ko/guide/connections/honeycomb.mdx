Honeycomb 팀을 연결하면 CloudThinker 에이전트가 실패한 스팬 기준으로 엔드포인트의 순위를 매기고, BubbleUp(실패한 이벤트를 정상 이벤트와 비교하는 Honeycomb 기능)을 실행하여 무엇이 바뀌었는지 찾고, 트레이스 워터폴을 열고, 트리거, SLO, 보드를 검토할 수 있습니다. OAuth로 Honeycomb에 한 번 로그인하면 됩니다. 만들거나 붙여 넣을 API 키가 없습니다.

## 사전 요구 사항

- 에이전트가 읽을 팀에 접근할 수 있는 Honeycomb 계정.
- 텔레메트리를 수신하는 데이터 세트가 있는 환경 하나 이상. 모든 쿼리에는 데이터 세트가 필요하므로, 데이터 세트가 없는 환경은 아무것도 답할 수 없습니다.
- Honeycomb US 리전의 팀. CloudThinker는 `https://mcp.honeycomb.io/mcp`에 연결하므로, Honeycomb EU 리전에만 있는 팀은 아직 연결할 수 없습니다. EU가 필요하다면 CloudThinker 담당자에게 문의하세요.
- 연결을 추가하고 편집할 수 있는 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참조하세요.

## 설정

<Steps>
  <Step title="연결 시작">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **Honeycomb**을 선택한 다음 **Connect**를 클릭합니다. CloudThinker가 Honeycomb의 승인 페이지를 엽니다.
  </Step>
  <Step title="CloudThinker 승인">
    팀에 접근할 수 있는 Honeycomb 계정으로 로그인한 다음 접근을 승인합니다. 브라우저가 이미 다른 Honeycomb 계정에 로그인되어 있다면 먼저 로그아웃하세요.
  </Step>
  <Step title="CloudThinker로 돌아오기">
    Honeycomb이 CloudThinker로 돌려보내며, CloudThinker는 토큰을 저장하고 스스로 갱신합니다.

    **성공 상태:** Honeycomb에 **Connected**가 표시됩니다. 아래 확인 프롬프트를 실행하여 어떤 팀을 연결했는지 확인하세요.
  </Step>
</Steps>

## 연결 세부 정보

입력할 필드가 없습니다.

| 항목 | 값 |
|------|-------|
| **Authentication** | OAuth. Honeycomb이 토큰을 발급하고 CloudThinker가 저장합니다 |
| **Endpoint** | `https://mcp.honeycomb.io/mcp`, Honeycomb의 호스팅 MCP 서버 |

## 필수 권한

에이전트는 승인한 Honeycomb 계정이 보는 것을 보며, CloudThinker는 그 권한 범위를 좁힐 수 없습니다. 에이전트가 접근하는 범위를 제한하려면, 사용할 팀과 환경에만 접근할 수 있는 CloudThinker 전용 Honeycomb 사용자로 승인하세요.

전용 사용자를 쓰면 사람들의 역할이 바뀌어도 연결이 유지됩니다. 승인한 사람이 팀을 떠나 접근을 잃으면, 누군가 다시 연결할 때까지 모든 호출이 실패합니다.

보드, 트리거, SLO, 마커 또는 수신자를 만들거나 업데이트하는 것은 쓰기입니다. 사용자에게 물을 때 에이전트는 효과를 설명하고, 정확한 입력값을 보여 주고, 답을 기다립니다.

<ApprovalDefault />

보드, 트리거, SLO, 마커, 수신자 쓰기가 모두 사람을 기다리게 하려면 **Manual**을 선택하세요. **Ask first** [Rule](/guide/approvals/rules)로 이러한 쓰기만 따로 지정할 수도 있습니다.

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 | 승인 |
|------------|--------------------|----------|
| **탐색** | 팀 이름을 확인하고, 환경과 데이터 세트를 나열하고, 트리거, 보드, 수신자가 있는지 보고 | 아니요 |
| **서비스 상태** | 오류율과 p95 지연 시간과 함께 실패한 스팬 수 기준으로 엔드포인트 순위 매기기 | 아니요 |
| **근본 원인** | BubbleUp을 실행하여 실패한 스팬과 정상 스팬을 구분하는 필드 찾기 | 아니요 |
| **트레이스** | 스팬을 나열하고, 스팬 세부 정보를 읽고, 전체 트레이스 워터폴 열기 | 아니요 |
| **쿼리** | 쿼리를 실행하고, 결과를 읽고, 열을 찾고, 저장된 쿼리 조회 | 아니요 |
| **알림 검토** | 트리거, 보드, 알림 수신자 읽기 | 아니요 |
| **변경** | 보드, 트리거 또는 SLO를 만들거나 업데이트하고, 마커나 수신자 만들기 | Approvals를 거침 |

에이전트는 오류율만이 아니라 실패한 스팬 수로 순위를 매기므로, 드물게 호출되지만 오류율이 100%인 엔드포인트가 실제로 사용자에게 피해를 주는 엔드포인트보다 앞서지 않습니다. BubbleUp 결과는 상관관계이며, 에이전트는 이를 증명된 원인이 아니라 상관관계로 보고합니다.

<Warning>
Honeycomb의 MCP 서버에는 삭제 기능이 없습니다. 에이전트가 만든 보드, 트리거, SLO, 마커, 수신자는 Honeycomb에서 직접 제거할 때까지 남아 있습니다. 해당 객체가 존재하기를 원할 때만 생성을 승인하세요.
</Warning>

### 연결 확인

```text
Summarize my Honeycomb setup: team, environments, datasets, and whether triggers exist
```

팀 이름, 각 환경의 데이터 세트 수, 그리고 트리거, 보드, 수신자가 설정되어 있는지가 표시되어야 합니다.

### 예시 프롬프트

```text
Which endpoint is in the worst shape right now?
Why is POST /checkout failing, and what changed? Run BubbleUp on the errors
Which datasets have no trigger watching them?
```

에이전트는 답변에 Honeycomb 쿼리와 트레이스의 퍼머링크를 공유하므로, Honeycomb에서 같은 화면을 열 수 있습니다.

## 문제 해결

<Accordion title="OAuth 흐름이 완료되지 않음">
브라우저가 다른 Honeycomb 계정에 로그인되어 있을 가능성이 높습니다. Honeycomb에서 올바른 계정으로 로그인한 다음 **Connect**를 다시 클릭하세요.
</Accordion>

<Accordion title="모든 호출이 인증 오류로 실패함">
저장된 토큰이 더 이상 유효하지 않습니다. 보통 Honeycomb에서 접근이 취소되었기 때문입니다. **Settings → Workspace → Connections**를 열고 **Honeycomb**을 선택한 다음, 오류 알림에서 **Connect**를 클릭하고 다시 승인하세요.
</Accordion>

<Accordion title="에이전트가 데이터 세트나 텔레메트리가 없다고 함">
환경에 데이터 세트가 없거나, 해당 시간 범위에 스팬 데이터가 없습니다. Honeycomb에서 환경이 이벤트를 수신하고 있는지 확인하거나, 더 넓은 범위를 요청하세요.
</Accordion>

<Accordion title="$activity-log$라는 환경을 건너뜀">
이는 Honeycomb 자체의 감사 환경입니다. 환경 목록에는 나타나지만 쿼리할 수 없으므로 에이전트가 의도적으로 건너뜁니다.
</Accordion>

<Accordion title="생성 또는 업데이트가 실행되지 않음">
거절했거나, 승인 요청에 답하지 않았거나, Rule이 거부했습니다. 에이전트는 거절된 쓰기를 다시 시도하지 않습니다. 원한다면 다시 요청하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **채팅에 서명된 결과 링크 없음**: Honeycomb의 원시 결과 다운로드 URL에는 데이터 접근 권한을 주는 토큰이 포함됩니다. 에이전트는 대신 퍼머링크를 공유하므로, 메시지를 복사해도 접근 권한이 유출되지 않습니다.
- **팀 전환**: Honeycomb 연결에서 **Disconnect**를 클릭한 다음 다른 Honeycomb 계정으로 다시 연결하세요.
- **Disconnect는 CloudThinker의 사본만 지움**: 저장된 토큰은 삭제하지만 Honeycomb의 권한 부여는 취소하지 않습니다. 정책상 필요하다면 Honeycomb 계정 설정에서도 CloudThinker의 접근을 제거하세요.

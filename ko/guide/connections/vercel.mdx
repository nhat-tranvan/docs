Vercel을 연결하면 CloudThinker 에이전트가 배포 실패 원인을 찾고, 런타임 로그를 읽고, 어떤 배포가 라이브인지 확인하고, 도메인을 감사할 수 있으며, [Approvals](/guide/approvals/overview)를 거쳐 배포를 취소하거나 프로젝트를 일시 중지할 수도 있습니다. 연결은 Vercel **access token** 하나를 사용하며, 토큰의 범위(개인 계정 또는 팀 하나)가 에이전트가 볼 수 있는 범위를 결정합니다.

---

## 사전 요구사항

- 조사하려는 팀과 프로젝트를 볼 수 있는 Vercel 계정.
- 해당 팀의 access token을 만들 수 있는 권한.
- 연결을 추가하는 데 필요한 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참고하세요.

---

## 설정

<Steps>
  <Step title="Vercel에서 access token 만들기">
    Vercel에서 아바타 메뉴를 열고 **Account Settings → Tokens**로 이동합니다([직접 링크](https://vercel.com/account/settings/tokens)). 토큰을 만듭니다.
    - **Name**: `cloudthinker`
    - **Scope**: CloudThinker가 접근할 팀 하나, 또는 개인 계정. 토큰은 해당 범위에만 접근하므로, 프로젝트가 여러 팀에 걸쳐 있다면 팀마다 토큰을 하나씩 만들어 각각 별도의 연결로 추가하세요.
    - **Expiration**: 날짜를 선택하고 교체 일정을 캘린더에 넣으세요

    지금 토큰을 복사하세요. Vercel은 토큰을 한 번만 보여줍니다.
  </Step>
  <Step title="CloudThinker에서 연결 추가">
    **Settings → Workspace → Connections**를 엽니다. **Discover** 탭에서 **Vercel**을 검색하고 토큰을 **VERCEL_TOKEN**에 붙여넣은 뒤 **Connect**를 클릭합니다.

    **성공 상태:** CloudThinker의 Vercel 카드에 **Connected**가 표시됩니다. Vercel의 경우 이는 토큰이 저장되었다는 뜻이지, 동작한다는 뜻은 아닙니다.
  </Step>
  <Step title="확인 프롬프트 실행">
    Vercel은 연결이 시작될 때 어떤 토큰이든 받아들이고, 첫 실제 호출에서만 검사합니다. 잘못 입력했거나 만료된 토큰도 **Connected**로 표시되므로, 사용하기 전에 [확인 프롬프트](#연결-확인)를 실행하세요.

    **성공 상태:** CloudThinker가 Vercel 사용자, 팀, 프로젝트를 반환합니다. 대신 `403 Not authorized (invalidToken)`이 반환되면 토큰이 잘못된 것입니다. [문제 해결](#문제-해결)을 참고하세요.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 설명 |
|-------|-------------|
| **VERCEL_TOKEN** | Vercel access token. CloudThinker가 토큰의 범위에서 팀과 프로젝트를 찾으므로 팀 ID를 입력할 필요가 없습니다. |

---

## 필요 권한

Vercel 토큰에는 읽기 전용 옵션이 없습니다. 범위가 주요 통제 수단입니다. 한 팀으로 범위가 지정된 토큰은 다른 팀의 프로젝트에 접근할 수 없습니다.

| 에이전트가 할 수 있는 일 | 필요한 것 |
|------------|-------|
| 프로젝트, 배포, 로그, 도메인, alias 읽기 | 해당 리소스를 소유한 팀으로 범위가 지정된 토큰 |
| 배포 취소, 프로젝트 일시 중지 또는 재개 | 같은 토큰과 Approvals 통과 |

<Tip>
토큰 범위를 팀 하나로 지정하고 만료일을 설정하세요. 이 연결에는 읽기 전용 모드가 없습니다. **Manual**을 선택해 모든 취소, 일시 중지, 재개를 사람이 승인하도록 하세요.

Rule로 범위를 좁힐 수 있습니다. 가장 빠른 방법은 [채팅에서 요청](/guide/approvals/rules#ask-for-one-rule-in-chat)하는 것입니다. `Propose a Deny Rule for cancelling deployments and pausing or unpausing projects on my Vercel connection`은 이 제어를 완전히 거부하고, `Propose an Ask first Rule before cancelling deployments or pausing projects in production on my Vercel connection`은 프로덕션 관련 제어를 사람에게 보냅니다.
</Tip>

## 에이전트 기능

| 기능 | 설명 |
|------------|-------------|
| **배포 분류** | 배포의 빌드 이벤트와 런타임 로그 오류를 읽고 실패 원인 설명 |
| **배포 상태** | 프로젝트별 배포 상태 집계, 연속 오류 발견, 30분 이상 멈춘 빌드 표시 |
| **프로덕션 상태** | alias를 라이브 배포에 매핑하고 롤백할 수 있는 이전 배포 제안 |
| **빌드 성능** | 기본적으로 최근 7일 동안 프로젝트별 빌드 시간(p50, p95, max)을 비교하고(프롬프트에서 다른 기간 지정 가능) 가장 느린 빌드 나열 |
| **도메인과 alias** | 도메인 구성 확인, 미확인 도메인 찾기, alias 나열 |
| **제어** | 배포 취소, 프로젝트 일시 중지 또는 재개. 각각 Approvals를 거침 |

롤백 제안은 조언일 뿐입니다. CloudThinker에는 Vercel에서 롤백하거나 재배포하는 도구가 없습니다.

### 연결 확인

```text
Check my Vercel connection: show the signed-in user, my teams, and my projects with their latest deployment state
```

### 예시 프롬프트

```text
Why did the latest production deployment of my web project fail? Show the build error and a fix
Which Vercel builds are stuck right now, and which are getting slower this week?
Audit my Vercel domains and list any that are unverified or misconfigured
```

계정에 프로젝트가 많다면 프롬프트에 팀이나 프로젝트를 지정하세요. 답이 더 빨리 오고 초점이 유지됩니다.

## 문제 해결

기존 연결의 토큰을 바꾸려면 연결을 열고 인스턴스의 편집 아이콘을 클릭한 뒤, **Edit Instance**에서 **Replace…**를 클릭하고 새 토큰을 붙여넣은 다음 **Save and test**를 클릭하세요. [Rotate a credential](/ko/guide/connections/overview#자격-증명-교체)을 참고하세요.

<Accordion title="모든 요청이 403 Not authorized (invalidToken)으로 실패함">
토큰이 잘못되었거나, 만료되었거나, 취소되었습니다. Vercel은 첫 호출에서만 토큰을 검사하므로 연결은 여전히 **Connected**로 표시되었습니다. 새 토큰을 만들어 연결에서 교체하세요.
</Accordion>

<Accordion title="특정 팀이나 프로젝트만 403 Forbidden으로 실패함">
다른 요청은 동작하지만 토큰의 범위에 해당 팀이 포함되지 않습니다. 올바른 팀으로 범위가 지정된 토큰을 만들어 연결에서 교체하세요.
</Accordion>

<Accordion title="프로젝트나 배포에 대해 404 Not Found">
이름이나 ID가 잘못되었거나, 토큰 범위 밖의 팀에 속해 있습니다. 먼저 CloudThinker에게 프로젝트 목록을 요청한 뒤 그 목록의 이름을 사용하세요.
</Accordion>

<Accordion title="취소나 일시 중지가 실행되지 않음">
제어는 먼저 [Approvals](/guide/approvals/overview)를 거치며, CloudThinker는 거부된 요청을 다시 시도하지 않습니다. **Manual**에서 사람이 거부했을 수 있습니다. Auto에서는 변경을 허용하는 것이 없을 때 Approval 모드가 **Refuse**로 설정되어 있을 수 있습니다. **Deny** Rule이 완전히 거부했을 수도 있습니다. 실행하고 싶을 때 다시 요청하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **읽기 전용 토큰 없음**: Vercel에는 읽기 전용 자격 증명이 없으므로 위의 읽기 전용 권장 사항은 여기에 적용되지 않습니다. 팀 범위 토큰을 사용하고 **Manual**을 선택해 모든 변경을 사람이 승인하도록 하며, **Deny** 또는 **Ask first** Rule을 함께 사용하세요.
- **교체 계획**: Vercel 토큰은 자동으로 교체되지 않습니다. 만들 때 만료일을 설정하고 그 전에 교체하세요.
- **런타임 로그 주의**: 앱이 자체 로그에 시크릿을 출력할 수 있습니다. CloudThinker는 모델이나 채팅이 보기 전에 도구 출력에서 자격 증명 형태의 값을 플레이스홀더로 바꾸지만([Data protection](/guide/security/data-protection) 참고), 특이한 형식의 시크릿은 빠져나갈 수 있습니다. 시크릿이 원천에서부터 로그에 남지 않게 하세요.

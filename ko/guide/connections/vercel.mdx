Vercel 계정을 연결하여 CloudThinker 에이전트가 프로젝트를 인벤토리하고, 배포 및 빌드 이벤트를 검사하고, 런타임 로그를 가져오고, 도메인 및 별칭을 감사하고, 중단된 배포 취소나 프로젝트 일시 중지와 같은 승인 게이트 작업을 실행할 수 있도록 합니다.

Vercel은 CloudThinker가 공식 Vercel MCP 서버(`@vercel/sdk`)에 전달하는 **액세스 토큰**으로 인증합니다. 토큰의 **범위** — 개인 계정 또는 특정 팀 — 가 에이전트가 접근할 수 있는 범위를 결정합니다. OAuth 플로우가 필요하지 않습니다.

---

## 사전 요구 사항

- 조사하려는 팀과 프로젝트에 접근할 수 있는 **Vercel 계정**.
- 올바른 팀으로 범위가 지정된 **액세스 토큰**.
- 해당 범위에 대한 토큰을 생성할 권한.

<Info>
CloudThinker가 필요한 팀으로만 토큰 범위를 제한하세요. 연결의 읽기 작업은 Vercel 리소스를 변경하지 않습니다 — 세 가지 승인 게이트 작업만 변경합니다.
</Info>

---

## 설정

<Steps>
  <Step title="액세스 토큰 생성">
    Vercel에서 **Settings → Tokens → Create Token**으로 이동하세요:
    - **Name**: `cloudthinker`
    - **Scope**: CloudThinker가 접근해야 할 **팀** (또는 개인 계정) 선택
    - **Expiration**: 유효 기간을 선택하고 교체 계획을 세우세요

    토큰을 즉시 복사하세요 — Vercel은 한 번만 표시합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Connections → Vercel**로 이동하여 다음을 입력하세요:
    - **Token**: 방금 생성한 액세스 토큰

    **Connect**를 클릭하세요. CloudThinker가 Vercel MCP 서버를 시작하고 **Connected** 상태를 표시합니다.
  </Step>
</Steps>

<Warning>
액세스 토큰을 생성 직후 복사하세요. 분실 시 새 토큰을 생성해야 합니다.
</Warning>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **VERCEL_TOKEN** | MCP 베어러 토큰으로 사용되는 Vercel 액세스 토큰 | — |

<Note>
CloudThinker가 토큰의 범위에서 팀과 프로젝트를 확인하므로, 수동으로 팀 ID나 URL을 설정할 필요가 없습니다.
</Note>

---

## 필요 권한

CloudThinker가 접근해야 할 프로젝트, 배포, 도메인, 로그가 있는 **팀**으로 토큰 범위를 제한하세요. 읽기 작업은 해당 리소스를 볼 수 있는 모든 토큰으로 작동합니다. 세 가지 제어 작업은 추가로 토큰 범위가 허용해야 하며 CloudThinker에서의 명시적 [승인](/ko/guide/approval)이 필요합니다.

<Tip>
최소 권한을 따르세요: 토큰 범위를 단일 팀으로 제한하고 만료 기간을 설정하세요. 제어 작업은 안전 장치를 제거하지 말고 승인 게이트를 유지하세요.
</Tip>

## 에이전트 기능

연결되면 에이전트가 Vercel 프로젝트 및 배포에 대한 읽기 접근 권한을 갖습니다.

| 기능 | 설명 |
|------------|-------------|
| **Teams & Projects** | 팀과 프로젝트 목록 조회 및 프로젝트 도메인 검사 |
| **Deployments** | 배포, 배포 이벤트, 빌드 출력 목록 조회 및 검사 |
| **Runtime Logs** | 오류 분류를 위한 런타임 로그 가져오기 |
| **Domains & Aliases** | 도메인, 도메인 설정, 별칭 감사 |
| **Account** | 인증된 Vercel 사용자 읽기 |
| **Deployment Control** | 배포 취소, 프로젝트 일시 중지 및 재개 — **승인 필요** |

<Info>
`Cancel deployment`, `Pause project`, `Unpause project`는 승인 게이트가 적용됩니다. CloudThinker는 실행 전에 확인을 요청합니다. 읽기 전용 작업은 승인 없이 실행됩니다.
</Info>

### 연결 검증

```text
@alex check the Vercel connection and list accessible teams and projects
```

### 예시 프롬프트

```text
@alex list all projects across my Vercel teams with their framework and latest deployment status and #report as a table
@alex the latest production deployment failed — pull the build events, find the error, and #recommend a fix
@alex show runtime error logs for my Vercel project over the last 6 hours and #alert on 5xx spikes
```

<Note>
프로젝트가 많은 계정의 경우, 에이전트가 집중된 결과를 반환하도록 단일 팀이나 프로젝트로 요청 범위를 제한하세요.
</Note>

## 문제 해결

<Accordion title="401 또는 403 Unauthorized">
토큰이 없거나 만료되었거나 취소되었습니다. 새 Vercel 토큰을 생성하고 Vercel 연결을 다시 연결하세요.
</Accordion>

<Accordion title="에이전트가 예상 팀이나 프로젝트를 볼 수 없음">
토큰의 범위에 해당 팀이 포함되지 않습니다. 올바른 팀으로 범위가 지정된 새 토큰을 생성하고 다시 연결하세요.
</Accordion>

<Accordion title="CloudThinker가 Vercel이 이미 연결되어 있다고 표시">
워크스페이스당 하나의 Vercel 연결만 허용됩니다. 기존 연결을 사용하거나 다시 연결하기 전에 제거하세요.
</Accordion>

<Accordion title="제어 작업이 실행되지 않음">
취소, 일시 중지, 재개는 해당 작업을 허용하는 토큰 범위와 CloudThinker에서의 명시적 승인이 모두 필요합니다. 메시지가 나타나면 작업을 승인하고 토큰의 범위가 허용하는지 확인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **토큰 만료 설정** — 토큰을 생성할 때 만료 기간을 선택하고 교체 계획을 세우세요. Vercel 토큰은 자동 순환되지 않습니다.
- **제어 작업 승인** — 취소, 일시 중지, 재개 작업은 안전 장치를 제거하지 말고 승인 게이트를 유지하세요.

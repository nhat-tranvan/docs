**dbt**를 연결하면 CloudThinker 에이전트가 아무것도 실행하지 않고 실패한 작업 실행을 설명하고, 모델 리니지를 추적하고, 모델 상태를 확인하고, 컴파일된 SQL을 읽을 수 있습니다. **Cloud** 탭은 액세스 토큰으로 dbt Cloud 계정을 연결하고, **Self-host** 탭은 Git 리포지토리와 읽기 전용 웨어하우스 사용자로 dbt Core 프로젝트를 연결합니다.

<Note>
**Self-host**는 dbt Core를 뜻하며, CloudThinker의 셀프 호스팅 배포를 뜻하지 않습니다.
</Note>

## 사전 요구 사항

- **Cloud**: Starter, Enterprise 또는 Enterprise+ 플랜의 dbt 계정과 프로덕션 환경. 메트릭 질문에는 [dbt Semantic Layer](https://docs.getdbt.com/docs/use-dbt-semantic-layer/dbt-sl) 설정도 필요합니다.
- **Self-host**: HTTPS로 제공되는 GitLab 또는 GitHub 리포지토리에 있고 **PostgreSQL**로 빌드되는 dbt Core 프로젝트. Self-host 탭이 지원하는 웨어하우스는 PostgreSQL뿐입니다.
- **Self-host 네트워크 접근**: CloudThinker가 인터넷에서 Git 호스트와 PostgreSQL 포트에 접근할 수 있어야 합니다. [비공개 서비스 접근](/ko/guide/connections/overview#비공개-서비스-접근)을 참조하세요.

## 설정

<Tabs>
  <Tab title="Cloud">
    <Steps>
      <Step title="Access URL 복사">
        dbt에서 **Account settings**를 열고 **Access URLs**를 찾습니다. `cloud.getdbt.com`이나 `ab123.us1.dbt.com`처럼 계정 URL의 호스트를 `https://` 없이 복사합니다.

        CloudThinker는 토큰을 `getdbt.com`과 `dbt.com` 호스트에만 보냅니다. 계정이 다른 도메인을 사용한다면 [CloudThinker에 문의](https://cloudthinker.io/contact)하세요.
      </Step>
      <Step title="액세스 토큰 만들기">
        만들 수 있는 토큰은 dbt 플랜에 따라 다릅니다.

        - **Enterprise 또는 Enterprise+**: **Account settings → Service Tokens**를 열고 **+ Create service token**을 클릭합니다. **Job Viewer**와 **Metadata Only** 권한 세트를 추가하고, 에이전트가 메트릭 질문에 답하게 하려면 **Semantic Layer Only**도 추가합니다. **Save**를 클릭하고 토큰을 복사합니다. dbt는 토큰을 한 번만 표시합니다.
        - **Starter**: **Account settings → API tokens → Personal tokens**를 열고 **Create personal access token**을 클릭합니다. 개인 토큰은 만든 사용자의 권한을 가지므로, 가능하면 읽기 전용 접근 권한을 가진 사용자로 만드세요.

        dbt의 [service tokens](https://docs.getdbt.com/docs/dbt-cloud-apis/service-tokens) 및 [personal access tokens](https://docs.getdbt.com/docs/dbt-cloud-apis/user-tokens) 가이드를 참조하세요.
      </Step>
      <Step title="프로덕션 환경 ID 복사">
        **Orchestration → Environments**로 이동하여 프로덕션 환경을 클릭합니다. 페이지 URL에서 `/environments/` 뒤의 숫자만 복사합니다.
      </Step>
      <Step title="CloudThinker에 연결 추가">
        **Settings → Workspace → Connections**를 열고 **dbt**를 선택한 다음 **Connect**를 클릭합니다. **Cloud**를 선택하고 [연결 세부 정보](#연결-세부-정보)의 필드를 입력한 다음 **Connect**를 클릭합니다.

        **성공 상태:** 연결에 **Connected** 상태가 표시됩니다.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Self-host">
    <Steps>
      <Step title="리포지토리 읽기 토큰 만들기">
        <Tabs>
          <Tab title="GitLab">
            프로젝트에서 **Settings → Repository**를 열고 **Deploy tokens**를 펼친 다음 **Add token**을 클릭합니다. `read_repository` 범위만 선택하고 **Create deploy token**을 클릭합니다. 생성된 사용자 이름(예: `gitlab+deploy-token-1`)과 토큰을 복사합니다. [GitLab deploy tokens](https://docs.gitlab.com/user/project/deploy_tokens/)를 참조하세요.
          </Tab>
          <Tab title="GitHub">
            **Settings → Developer settings → Personal access tokens → Fine-grained tokens**를 열고 **Generate new token**을 클릭합니다. **Repository access**에서 **Only select repositories**를 선택하고 dbt 리포지토리를 고른 다음, 토큰에 해당 리포지토리의 읽기 전용 접근 권한을 부여합니다. 이 토큰에는 GitHub 사용자 이름을 사용합니다. [GitHub fine-grained tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)를 참조하세요.
          </Tab>
        </Tabs>
      </Step>
      <Step title="읽기 전용 PostgreSQL 사용자 만들기">
        관리자로 접속하여 모델과 소스가 있는 스키마에 대한 읽기 권한을 사용자에게 부여합니다. 이 예시는 `analytics`를 사용합니다.

        ```sql
        CREATE ROLE cloudthinker_dbt WITH LOGIN PASSWORD '<secure-password>';
        GRANT CONNECT ON DATABASE your_database TO cloudthinker_dbt;
        GRANT USAGE ON SCHEMA analytics TO cloudthinker_dbt;
        GRANT SELECT ON ALL TABLES IN SCHEMA analytics TO cloudthinker_dbt;
        ```

        그 밖에는 아무것도 부여하지 마세요. dbt는 컴파일할 때 프로젝트의 훅을 실행하므로, 읽기 전용 사용자는 훅이 데이터를 변경하지 못하게 막습니다.
      </Step>
      <Step title="네트워크 접근 열기">
        CloudThinker가 HTTPS로 Git 호스트에, 그리고 PostgreSQL 포트(기본값 `5432`)에 접근할 수 있도록 허용합니다. 이 문서는 CloudThinker의 egress IP 목록을 공개하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의하기](https://cloudthinker.io/contact)를 이용하세요.
      </Step>
      <Step title="CloudThinker에 연결 추가">
        **Settings → Workspace → Connections**를 열고 **dbt**를 선택한 다음 **Connect**를 클릭합니다. **Self-host**를 선택하고 [연결 세부 정보](#연결-세부-정보)의 필드를 입력한 다음 **Connect**를 클릭합니다.

        **성공 상태:** 연결에 **Connected** 상태가 표시됩니다. 첫 연결은 CloudThinker가 리포지토리를 복제하고 프로젝트의 패키지를 설치하는 동안 약 2분이 걸릴 수 있습니다.
      </Step>
    </Steps>
  </Tab>
</Tabs>

저장된 연결을 편집해도 원래 유형은 유지됩니다. 다른 탭을 사용하려면 두 번째 연결을 추가하세요.

## 연결 세부 정보

| Cloud 필드 | 필수 | 입력할 내용 |
|---|---|---|
| **Access URL** | 예 | **Account settings → Access URLs**의 호스트(예: `cloud.getdbt.com`) |
| **Access token** | 예 | 만든 서비스 토큰 또는 개인 액세스 토큰 |
| **Production environment ID** | 예 | 프로덕션 환경 URL에서 `/environments/` 뒤의 숫자. 모델, 소스, 리니지, 메트릭 읽기에 사용됩니다 |

| Self-host 필드 | 필수 | 입력할 내용 |
|---|---|---|
| **Git repository URL** | 예 | 사용자 이름이나 토큰이 포함되지 않은 HTTPS 복제 URL(예: `https://gitlab.com/acme/analytics.git`) |
| **Repository username** | 예 | GitLab 배포 토큰의 사용자 이름 또는 GitHub 사용자 이름. 기본값은 `oauth2` |
| **Repository read token** | 예 | 배포 토큰 또는 fine-grained 토큰 |
| **Branch or tag** | 아니요 | 기본 브랜치를 읽으려면 비워 둡니다 |
| **Project folder** | 아니요 | 리포지토리 루트를 기준으로 `dbt_project.yml`이 있는 폴더. 루트에 있으면 비워 둡니다 |
| **Warehouse** | 예 | **PostgreSQL** |
| **Warehouse host** | 예 | 포트 없이 호스트 이름 또는 IP 주소 |
| **Warehouse port** | 예 | 기본값은 `5432` |
| **Database** | 예 | 프로젝트가 빌드되는 데이터베이스 |
| **Schema** | 예 | 프로덕션 모델이 빌드되는 스키마. 컴파일된 SQL과 미리보기는 이 스키마를 기준으로 `ref()`를 해석합니다 |
| **Warehouse user** | 예 | 읽기 전용 사용자 |
| **Warehouse password** | 예 | 해당 사용자의 비밀번호 |

## 필수 권한

| 탭 | 에이전트에게 맡길 작업 | 접근 권한 |
|---|---|---|
| **Cloud** | 작업, 실행, 로그, 실행 아티팩트 읽기 | 서비스 토큰의 **Job Viewer** |
| **Cloud** | 모델, 소스, exposure, 리니지 읽기 | 서비스 토큰의 **Metadata Only** |
| **Cloud** | 메트릭 질문에 답하기 | 서비스 토큰의 **Semantic Layer Only** |
| **Self-host** | 프로젝트 읽기 | GitLab 배포 토큰의 `read_repository`, 또는 GitHub fine-grained 토큰의 리포지토리 하나에 대한 읽기 권한 |
| **Self-host** | 모델 컴파일과 행 미리보기 | 스키마에 대한 `USAGE`와 테이블에 대한 `SELECT` |

개인 액세스 토큰은 이러한 권한 세트 대신 해당 사용자의 권한을 가집니다.

<Tip>
서비스 토큰에는 위의 권한 세트만, 웨어하우스 사용자에게는 `USAGE`와 `SELECT`만 부여하세요. 둘 다 쓰기나 관리자 권한이 필요하지 않습니다.
</Tip>

## 에이전트 기능

| 탭 | 에이전트가 할 수 있는 작업 | 제한 |
|---|---|---|
| **Cloud** | 프로젝트, 작업, 실행을 나열하고 실행의 상태, 오류, 로그, 아티팩트 읽기 | 읽기 전용 |
| **Cloud** | 모델, 소스, exposure, 매크로를 읽고, 리니지를 추적하고, 모델 상태와 실행 시간 확인 | 프로덕션 환경을 사용합니다 |
| **Cloud** | 메트릭, 디멘션, 저장된 쿼리를 나열하고, 메트릭의 SQL을 보여 주고, 메트릭 쿼리 | Semantic Layer가 필요합니다. 메트릭 쿼리는 웨어하우스에서 실행되며 그곳에서 비용이 청구됩니다 |
| **Self-host** | 프로젝트를 파싱하고 나열하며, 리니지를 추적하고, 노드 세부 정보 읽기 | 설정한 브랜치를 읽습니다. 실행 기록은 없습니다 |
| **Self-host** | 모델을 SQL로 컴파일하고 행 미리보기 | 미리보기당 최대 100행 |

### 연결 확인

```text
Show the upstream and downstream lineage of the orders model
```

`orders`에 데이터를 공급하는 모델과 소스, 그리고 `orders`로부터 빌드되는 모델이 표시되어야 합니다. 알 수 없는 모델 오류가 나오면 이름이 잘못되었거나, 모델이 프로덕션 환경 또는 설정한 브랜치에 없는 것입니다.

### 예시 프롬프트

```text
Why did the last run of the nightly job fail?
Is the customers model healthy, and how long do its runs take?
Show the compiled SQL for the orders model and preview 5 rows
```

## 쓰기 권한

dbt 연결은 읽기 전용입니다. 에이전트는 dbt Cloud 작업을 실행, 재시도, 취소할 수 없으며, dbt Core 프로젝트를 run, build, test, seed, snapshot할 수 없습니다. CloudThinker는 리포지토리에 절대 푸시하지 않습니다.

## 문제 해결

<Accordion title="The provider rejected these credentials">
dbt가 토큰을 거부했습니다. **Access URL**이 계정의 호스트인지, 토큰이 만료되거나 취소되지 않았는지, 서비스 토큰에 **Job Viewer**와 **Metadata Only**가 있는지 확인하세요. 새 토큰을 만들고 다시 연결하세요.
</Accordion>

<Accordion title="모델, 리니지 또는 메트릭 질문이 실패함">
**Production environment ID**가 잘못되었거나 숫자가 아닙니다. 프로덕션 환경 URL에서 `/environments/` 뒤의 숫자만 복사하세요.
</Accordion>

<Accordion title="메트릭 질문이 유용한 결과를 반환하지 않음">
계정에 Semantic Layer가 설정되어 있지 않거나, 토큰에 **Semantic Layer Only**가 없습니다. 작업, 모델, 리니지 질문은 이것 없이도 작동합니다.
</Accordion>

<Accordion title="could not clone the repository; check the URL, branch, username, and token">
CloudThinker가 리포지토리를 읽을 수 없었습니다. URL이 `https://`로 시작하는지, 브랜치나 태그가 존재하는지, 사용자 이름이 토큰과 일치하는지(GitLab 배포 토큰 자체의 사용자 이름 또는 GitHub 사용자 이름), 토큰이 해당 리포지토리를 읽을 수 있는지 확인하세요. URL에 사용자 이름이나 토큰이 포함되어 있다면 제거하고 **Repository username**과 **Repository read token** 필드를 사용하세요.
</Accordion>

<Accordion title="dbt_project.yml not found in the project folder">
**Project folder**를 리포지토리 루트 기준으로 `dbt_project.yml`이 있는 폴더(예: `analytics`)로 설정하세요. 파일이 루트에 있으면 비워 두세요.
</Accordion>

<Accordion title="The tools for this connection took too long to start">
첫 Self-host 연결은 리포지토리를 복제하고 패키지를 설치하므로 몇 분이 걸릴 수 있습니다. 1분 기다린 다음 다시 연결하세요.
</Accordion>

<Accordion title="컴파일 또는 미리보기가 데이터베이스 오류로 실패함">
CloudThinker가 PostgreSQL에 접근할 수 없거나 사용자에게 접근 권한이 없습니다. 호스트, 포트, 데이터베이스, 비밀번호를 확인하고, 방화벽이 CloudThinker를 허용하는지, 사용자에게 모델이 읽는 스키마에 대한 `USAGE`와 `SELECT`가 있는지 확인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **읽기 전용 웨어하우스 사용자 사용**: 미리보기는 이 사용자로 `SELECT` 쿼리를 실행하고, dbt는 컴파일할 때 프로젝트 훅을 실행합니다. `USAGE`와 `SELECT`만 부여하세요.
- **리포지토리 토큰 범위 제한**: dbt 리포지토리 하나만 읽을 수 있는 GitLab 배포 토큰이나 GitHub fine-grained 토큰을 사용하세요.

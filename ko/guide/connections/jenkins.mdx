Jenkins를 연결하면 CloudThinker 에이전트가 작업을 나열하고, 빌드 로그와 테스트 결과를 읽고, 빌드가 실패한 이유를 설명하고, 워크스페이스의 Approvals를 거쳐 빌드를 실행할 수 있습니다. CloudThinker는 서버의 **Jenkins MCP Server plugin**과 통신하며 **Jenkins 사용자 이름과 API 토큰**으로 로그인합니다.

## 사전 요구 사항

- CloudThinker가 인터넷에서 접근할 수 있고, 플러그인을 설치할 관리자 권한이 있는 Jenkins 서버. 방화벽 뒤의 서버라면 CloudThinker의 egress IP를 허용 목록에 추가합니다. 이 문서는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의](https://cloudthinker.io/contact)하세요. 다른 옵션은 [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참조하세요.
- [MCP Server plugin](https://plugins.jenkins.io/mcp-server/) 설치. 이 플러그인은 CloudThinker가 호출하는 엔드포인트를 `<your-jenkins-url>/mcp-server/mcp`에 추가합니다.
- [필요 권한](#필요-권한)의 권한이 있는 CloudThinker용 Jenkins 사용자.
- 연결을 추가하고 편집할 수 있는 CloudThinker 워크스페이스의 **Admin** 역할. [Roles](/guide/security/roles)를 참조하세요.

## 설정

<Steps>
  <Step title="MCP Server plugin 설치">
    Jenkins에서 **Manage Jenkins → Plugins → Available plugins**로 이동하여 **MCP Server**를 검색하고 설치한 다음, 요청하면 Jenkins를 다시 시작합니다.
  </Step>
  <Step title="Jenkins URL 설정">
    **Manage Jenkins → System**으로 이동하여 **Jenkins Location** 아래 **Jenkins URL**에 사람들이 Jenkins에 접속하는 주소(예: `https://jenkins.acme.com/`)를 입력합니다. **Save**를 클릭합니다.

    플러그인은 이 값으로 작업 및 빌드 링크를 만듭니다. 비어 있거나 `localhost`로 설정되어 있으면 에이전트가 깨진 링크를 받습니다.
  </Step>
  <Step title="API 토큰 생성">
    CloudThinker 사용자로 Jenkins에 로그인하고 `<your-jenkins-url>/user/<username>/security`를 엽니다(이전 Jenkins 버전에서는 `/user/<username>/configure`). **API Token** 아래에서 **Add new Token**을 클릭합니다. 이름을 `cloudthinker`로 지정하고 **Generate**를 클릭한 다음 토큰을 복사합니다. Jenkins는 토큰을 한 번만 표시합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 엽니다. **Discover** 탭에서 **Jenkins**를 검색하고 **Connect**를 클릭한 다음 [연결 세부 정보](#연결-세부-정보)의 필드를 입력합니다. **Connect**를 클릭합니다.

    CloudThinker는 사용자 이름과 토큰으로 MCP 엔드포인트를 호출하여 연결을 테스트합니다. URL이 잘못되었거나, 토큰이 거부되었거나, 플러그인이 없으면 **Connected** 대신 오류가 표시됩니다.

    **성공 상태:** **Connected** 탭에 Jenkins가 **Connected**로 표시됩니다.
  </Step>
</Steps>

<Note>
테스트는 사용자의 작업 권한을 확인하지 않습니다. 아래 검증 프롬프트를 실행하여 에이전트가 작업을 볼 수 있는지 확인하세요.
</Note>

## 연결 세부 정보

대화상자에는 필드가 정확히 다음 이름으로 표시됩니다.

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| `JENKINS_URL` | `/mcp-server/mcp`를 제외한 Jenkins 서버의 기본 URL. CloudThinker가 해당 경로를 추가합니다 | `https://jenkins.acme.com` |
| `JENKINS_USER` | 토큰이 속한 Jenkins 사용자 이름 | `cloudthinker` |
| `JENKINS_API_TOKEN` | 해당 사용자에 대해 생성한 API 토큰 | `<your-api-token>` |

스킴을 생략하면 CloudThinker는 `https://`를 사용합니다. 공개 주소에서는 `http://`를 입력하더라도 CloudThinker가 항상 HTTPS로 연결하므로, 서버에 유효한 TLS 인증서가 있어야 합니다.

## 필요 권한

Jenkins 권한 부여 전략(예: **Manage Jenkins → Security**의 **Matrix-based security**)에서 CloudThinker 사용자에게 다음 권한을 부여합니다:

| 권한 | 필요한 용도 |
|------------|------------|
| **Overall / Read** | 로그인 및 작업 나열 |
| **Job / Read** | 빌드, 로그, 테스트 결과, 변경 사항 읽기 |
| **Job / Discover** | 폴더와 뷰의 작업 보기 |
| **View / Read** | 뷰 읽기 |
| **Job / Build** | 선택 사항: 빌드 실행 |

토큰은 정확히 이 사용자의 권한으로 작동합니다. 읽기 전용 연결에서는 **Job / Build**를 제외합니다. 사용자에게 **Overall / Administer**는 필요하지 않으며, 어떤 에이전트 도구도 Jenkins 자격 증명이나 시크릿을 읽지 않습니다.

<Tip>
관리자 계정 대신 CloudThinker 전용 Jenkins 사용자를 사용하세요. 폴더 수준 권한을 사용한다면 에이전트가 볼 폴더에만 접근을 부여하세요.
</Tip>

## 에이전트 기능

읽기 작업은 묻지 않고 실행됩니다. 빌드 실행은 쓰기 작업이므로 먼저 Approvals를 거칩니다.

<ApprovalDefault />

| 기능 | 에이전트가 할 수 있는 일 |
|------------|--------------------|
| **Jobs** | 작업을 나열하고 각 작업의 마지막 빌드 상태를 보여 줍니다 |
| **Build logs** | 빌드 로그를 읽고 검색하여 실패한 단계를 찾습니다 |
| **Test results** | 테스트 결과를 읽고 실패한 테스트를 가리킵니다 |
| **Changes** | 빌드에 포함된 커밋과 SCM 변경 사항을 보여 줍니다 |
| **Trigger builds** | Rules와 Approval mode를 거쳐 빌드를 시작합니다. 에이전트는 요청에서 가져온 빌드 매개변수를 전달할 수 있습니다 |

### 연결 검증

```text
List the Jenkins jobs you can reach and the result of the last build for each
```

정상적인 연결은 실제 작업 이름과 결과를 반환합니다. 목록이 비어 있다면 대개 사용자에게 **Job / Read** 또는 **Job / Discover**가 없는 것입니다.

### 예시 프롬프트

```text
Why did the last build of payments-api fail? Show the failing step and the error from the log
Which tests failed in the last 5 builds of the main pipeline, and are any of them flaky?
Which commits went into the latest build of web-frontend?
```

## 문제 해결

<Accordion title="This connection did not respond in time. Try connecting again.">
CloudThinker가 Jenkins 서버에 접근할 수 없습니다. 네트워크 외부에서 URL이 열리는지, 방화벽이 CloudThinker의 egress IP에서 들어오는 HTTPS를 허용하는지 확인합니다. `localhost`나 네트워크 내부에서만 확인되는 주소는 사용하지 않습니다.
</Accordion>

<Accordion title="The provider rejected these credentials. Update them, then connect again.">
사용자 이름이나 토큰이 잘못되었거나, 토큰이 취소되었습니다. `JENKINS_USER`가 토큰을 생성한 사용자인지 확인하고, 필요하면 새 토큰을 생성합니다. 교체하려면 **Settings → Workspace → Connections**에서 **Jenkins**를 선택하고, 연필 아이콘을 클릭하고, **Credentials** 아래 **Replace…**를 클릭한 다음 **Save and test**를 클릭합니다.
</Accordion>

<Accordion title="The provider endpoint was not found. Check the connection settings.">
MCP Server plugin이 설치되지 않았거나 활성화되지 않았거나, `JENKINS_URL`이 잘못된 경로를 가리킵니다. 플러그인을 설치하고 기본 URL만 입력합니다. Jenkins가 `/jenkins` 같은 경로에서 실행된다면 이를 포함합니다: `https://ci.acme.com/jenkins`.
</Accordion>

<Accordion title="작업 목록이 비어 있거나 링크가 깨짐">
사용자에게 **Job / Read** 또는 **Job / Discover**가 없거나, **Jenkins URL**이 비어 있거나 `localhost`로 설정되어 있습니다. 권한을 수정하고, **Manage Jenkins → System**에서 **Jenkins URL**을 설정한 다음 다시 요청합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **네트워크 노출을 제한합니다.** 필요한 소스에서만 Jenkins로 들어오는 트래픽을 허용하고, Jenkins UI는 일반적인 접근 제어 뒤에 둡니다.
- **빌드를 승인 게이트로 유지합니다.** 에이전트가 빌드를 시작해야 할 때만 **Job / Build**를 부여하고, CloudThinker가 시작하는 모든 빌드를 사람이 확인해야 한다면 **Manual**을 선택합니다.

AWX를 연결하면 CloudThinker 에이전트가 실패한 작업을 찾아 출력을 읽고, 인벤토리, 호스트, 프로젝트를 검사하고, 승인을 거쳐 작업 템플릿을 실행할 수 있습니다. 이 연결은 AWX **access token** 하나로 로그인하며 서버에 대해 `awx` 명령줄 도구를 실행합니다.

## 사전 요구 사항

- CloudThinker에서 HTTPS로 접근할 수 있는 AWX 서버 또는 Ansible Automation Platform 컨트롤러. 사설 네트워크의 서버는 [사설 서비스에 접근하기](/ko/guide/connections/overview#비공개-서비스-접근)를 참고하세요.
- 에이전트가 접근해야 할 조직, 인벤토리, 템플릿에 접근할 수 있는 CloudThinker용 AWX 사용자.

## 설정

<Steps>
  <Step title="CloudThinker용 사용자 생성">
    AWX에서 `cloudthinker` 같은 사용자를 만들고, 에이전트에게 필요한 리소스에만 역할을 부여합니다([필수 권한](#필수-권한) 참고). 전용 사용자를 두면 토큰의 범위가 작게 유지되고 폐기하기 쉽습니다.
  </Step>
  <Step title="액세스 토큰 생성">
    그 사용자로 로그인합니다. 사용자 메뉴를 열고 **User Details**를 선택한 뒤 **Tokens** 탭으로 이동하여 **Add**를 클릭합니다.

    - **Application**: 비워 둡니다
    - **Scope**: 모니터링만 하려면 **Read**, 에이전트가 실행하고 변경해야 한다면 **Write**

    토큰을 복사하세요. AWX는 한 번만 표시합니다. 토큰은 AWX OAuth 2 설정에 지정된 기간이 지나면 만료되므로, 날짜를 기록해 두고 그 전에 새 토큰을 만드세요.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **AWX**를 선택합니다. 다음을 입력합니다.

    - **TOWER_HOST**: `https://awx.example.com` 같은 AWX 주소
    - **TOWER_OAUTH_TOKEN**: 복사한 토큰

    **Connect**를 클릭합니다. CloudThinker가 토큰으로 `awx me`를 실행하여 로그인할 수 있는지 확인합니다.

    **성공 상태:** 다이얼로그가 닫히고 연결에 **Connected**가 표시됩니다. 아래 확인 프롬프트를 실행하세요.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **TOWER_HOST** | AWX 서버의 기본 URL, HTTPS | `https://awx.example.com` |
| **TOWER_OAUTH_TOKEN** | CloudThinker 사용자의 AWX 개인 액세스 토큰. 필드 이름은 AWX의 이전 이름인 Tower를 유지합니다 | `<your-token>` |

## 필수 권한

에이전트가 할 수 있는 일은 토큰의 스코프와 AWX에서 사용자의 역할 두 가지가 정합니다. 토큰은 사용자 권한을 넘어설 수 없습니다. **Write** 토큰에서는 사용자의 역할이 상한이며, 그 안에서 각 작업은 승인이 결정합니다. CloudThinker에서도 모든 쓰기를 차단하려면 AWX 연결의 세부 정보 패널에서 **Allow writes** 스위치를 끄세요.

| 목표 | 토큰 스코프 | 사용자의 AWX 역할 |
|------|-------------|------------------------|
| 작업, 인벤토리, 프로젝트 모니터링 | **Read** | 감시할 조직 또는 리소스에 **Read** |
| 선택한 작업 템플릿 실행 | **Write** | 해당 작업 템플릿 또는 워크플로 템플릿에 **Execute** |
| 프로젝트 동기화 | **Write** | 해당 프로젝트에 **Update** |
| 호스트와 그룹 변경 | **Write** | 해당 인벤토리에 **Admin** |

<Tip>
Read 토큰으로 시작하세요. 에이전트가 실행하기를 원하는 템플릿에만 Write로 전환하고, 넓은 조직 역할 대신 템플릿별로 **Execute**를 부여하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 | 승인 |
|------------|--------------------|----------|
| **Discovery** | 로그인한 사용자, 조직, 인벤토리, 프로젝트, 작업 템플릿, 워크플로 템플릿, 최근 작업 요약 | 아니요 |
| **Jobs** | 상태별로 작업과 워크플로 작업 나열, 작업 세부 정보 읽기, 완료된 작업의 출력 읽기 | 아니요 |
| **Inventories** | 인벤토리, 호스트, 그룹 검사 | 아니요 |
| **Projects** | 프로젝트 소스 제어와 동기화 상태 확인 | 아니요 |
| **Templates and credentials** | 작업 템플릿, 워크플로 템플릿, 자격 증명 메타데이터 읽기. 자격 증명 시크릿은 절대 반환되지 않습니다 | 아니요 |
| **Launch** | 추가 변수와 함께 작업 템플릿 또는 워크플로 템플릿을 실행하고 완료까지 따라가기. 템플릿에서 **Variables**에 대해 **Prompt on launch**가 켜져 있어야 합니다 | 예 |
| **Control and sync** | 실행 중인 작업 취소, 또는 소스 제어에서 프로젝트 동기화 | 예 |
| **Change resources** | 호스트, 그룹, 기타 AWX 리소스 생성, 수정, 삭제 | 예 |

모든 쓰기는 [승인](/guide/approvals/overview)을 거치며, 거부된 요청은 재시도되지 않습니다. Read 토큰에서는 승인 후에도 AWX가 쓰기를 거부합니다.

### 연결 확인

```text
Run AWX discovery and summarize my organizations, inventories, job templates, and the last few jobs with their status
```

CloudThinker가 로그인한 사용자, 각 리소스 유형의 이름과 개수, 그리고 **successful** 또는 **failed** 같은 상태가 있는 최근 작업이 나와야 합니다.

### 예시 프롬프트

```text
List AWX jobs that failed in the last 24 hours and show the error from each job's output
Which AWX projects failed their last source control sync?
Launch the deploy-web job template with extra vars version=2.1.0 and tell me when it finishes
```

실제 템플릿, 인벤토리 또는 프로젝트 이름을 사용하세요. 에이전트는 먼저 이름을 조회하며 ID를 추측하지 않습니다.

## 문제 해결

<Accordion title="Connect가 Failed to connect to AWX로 실패합니다">
CloudThinker가 **TOWER_HOST**에 대해 `awx me`를 실행할 수 없었습니다. 다이얼로그는 서버에 연결할 수 없을 때와 토큰이 잘못되었을 때 같은 메시지를 표시하므로 둘 다 확인하세요. 먼저 네트워크 외부의 브라우저에서 **TOWER_HOST**를 여세요. HTTPS로 로드되어야 합니다. 로드된다면 토큰이 만료되었거나 폐기된 것입니다. 새 토큰을 만들고 연결을 편집하여 붙여넣으세요.
</Accordion>

<Accordion title="요청이 401을 반환합니다">
토큰이 없거나 만료되었거나 폐기되었습니다. CloudThinker 사용자의 새 토큰을 만들고 **TOWER_OAUTH_TOKEN**을 업데이트하세요.
</Accordion>

<Accordion title="실행 또는 동기화가 거부됩니다">
토큰의 스코프가 **Read**이거나, 사용자에게 템플릿의 **Execute** 또는 프로젝트의 **Update**가 없습니다. Write 토큰을 만들거나 AWX에서 역할을 부여한 뒤 다시 요청하세요.
</Accordion>

<Accordion title="목록이 비어 있습니다">
사용자가 해당 리소스를 볼 수 없습니다. 에이전트가 접근해야 할 조직이나 인벤토리에 **Read**를 부여하세요. 다시 연결할 필요는 없으며, 역할은 다음 요청부터 적용됩니다.
</Accordion>

<Accordion title="실행 시 추가 변수가 무시됩니다">
템플릿이 허용하지 않으면 AWX는 추가 변수를 버립니다. 작업 템플릿을 편집하여 **Variables**에 대해 **Prompt on launch**를 켜고 다시 실행하세요.
</Accordion>

<Accordion title="작업 출력이 비어 있습니다">
AWX는 작업이 끝난 뒤에만 출력을 반환합니다. 작업 상태가 **successful** 또는 **failed**가 되면 다시 요청하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **Read 스코프 우선**: 에이전트가 실행하거나 변경해야 할 때만 Write 토큰을 사용하고, 사용자의 역할을 해당 템플릿으로 한정하세요.
- **HTTPS 전용**: 항상 HTTPS **TOWER_HOST**를 사용하세요. 일반 HTTP는 토큰을 평문으로 보냅니다.

monday.com 계정을 연결하면 CloudThinker 에이전트가 보드를 검토하고, 진행이 멈춘 작업을 찾고, 아이템 논의를 읽고, 승인 후 아이템을 업데이트할 수 있습니다.

monday.com은 monday.com이 호스팅하는 MCP 서버를 통해 **OAuth**를 사용하므로 API 토큰을 만들거나 자격 증명을 CloudThinker에 붙여 넣을 필요가 없습니다.

---

## 사전 요구사항

- CloudThinker가 읽을 보드를 볼 수 있는 **monday.com 계정**.
- monday.com OAuth 흐름으로 CloudThinker를 인가할 수 있는 권한.
- monday.com이 아직 연결되지 않은 CloudThinker 워크스페이스.

<Info>
에이전트는 인가한 계정이 보는 것만 볼 수 있습니다. 그 계정이 열 수 없는 보드는 CloudThinker에도 보이지 않습니다.
</Info>

---

## 설정

<Steps>
  <Step title="CloudThinker 열기">
    CloudThinker 워크스페이스에서 **Connections → monday.com**으로 이동합니다.
  </Step>
  <Step title="OAuth 흐름 시작">
    **Connect**를 클릭하여 monday.com 인가 페이지를 엽니다.
  </Step>
  <Step title="CloudThinker 인가">
    사용할 보드에 접근할 수 있는 monday.com 계정으로 로그인한 후 접근을 승인합니다.
  </Step>
  <Step title="CloudThinker로 돌아가기">
    인가가 끝나면 CloudThinker가 OAuth 토큰을 저장하고 **Connected** 상태를 표시합니다.
  </Step>
</Steps>

---

## 연결 세부 정보

monday.com은 OAuth를 사용하므로 수동으로 입력할 연결 필드가 없습니다. CloudThinker는 인가 흐름이 완료된 후 토큰을 자동으로 저장합니다.

| 필드 | 설명 |
|-------|-------------|
| **OAuth 토큰** | monday.com이 발급하고 자동으로 저장됨; 수동 입력 불필요 |

---

## 필요 권한

CloudThinker는 OAuth 중에 부여된 monday.com 접근 권한을 상속합니다.

- **읽기 작업**은 인가한 계정이 이미 열 수 있는 워크스페이스, 보드, 아이템, 업데이트, 문서, 사용자, 팀, 자동화, 스프린트를 대상으로 합니다.
- 아이템 생성, 아이템 컬럼 값 변경, 업데이트 작성 등의 **쓰기 작업**은 일치하는 monday.com 권한 **및** CloudThinker의 명시적 [승인](/ko/guide/approval)이 필요합니다.

<Tip>
CloudThinker에 필요한 보드로만 제한된 계정으로 인가하세요. monday.com MCP 서버에는 삭제나 보관 도구가 없으므로 에이전트가 만든 항목은 monday.com에서 직접 제거해야 합니다.
</Tip>

## 에이전트 기능

연결이 완료되면 에이전트가 할 수 있는 작업:

| 기능 | 설명 |
|------------|-------------|
| **계정 검색** | 워크스페이스, 보드, 사용자, 팀 목록 조회 및 다른 요청에 필요한 보드 ID 반환 |
| **보드 검토** | 보드의 그룹과 컬럼, 상태 및 담당자별 작업 분포 요약 |
| **정체된 작업** | 지정한 기간 동안 움직이지 않은 아이템을 오래된 순으로 검색 |
| **아이템 컨텍스트** | 조치 전에 아이템 업데이트, 보드 활동, monday 문서 읽기 |
| **스프린트 보고** | monday dev 스프린트 보드, 스프린트 메타데이터, 스프린트 요약 조회 |
| **아이템 쓰기** | 아이템 생성, 컬럼 값 변경, 업데이트 작성 — 각 작업은 명시적 승인 후 실행 |

### 연결 확인

```text
@alex list my monday.com workspaces and boards
```

### 예시 프롬프트

```text
@alex review the Tasks board on monday.com and #report how work splits by status and owner
@alex find monday.com items that have not moved in 14 days and #recommend what to chase first
@alex read the updates on the checkout bug item and summarize what is blocking it
```

## 문제 해결

<Accordion title="OAuth 흐름이 완료되지 않음">
브라우저가 다른 monday.com 계정으로 로그인되어 있을 수 있습니다. 원하는 계정으로 로그인한 후 CloudThinker에서 연결 흐름을 다시 시도하세요.
</Accordion>

<Accordion title="에이전트가 보드를 비어 있다고 보고함">
monday.com은 존재하지 않거나 삭제되었거나 볼 수 없는 보드 ID에 대해 오류 대신 빈 레코드를 반환합니다. 먼저 워크스페이스와 보드 목록을 조회하게 한 뒤 그 목록에서 보드를 지정하세요.
</Accordion>

<Accordion title="본인은 볼 수 있는 보드를 에이전트가 찾지 못함">
해당 보드에 접근할 수 없는 계정으로 OAuth 흐름이 실행되었을 수 있습니다. 보드를 열 수 있는 계정으로 다시 연결하세요. 최근 방문한 보드는 전체 목록이 아닙니다. 보드는 워크스페이스에 속하므로 에이전트가 워크스페이스를 읽어야 목록을 만들 수 있습니다.
</Accordion>

<Accordion title="스프린트 요약을 사용할 수 없음">
스프린트 요약에는 sprint summary 컬럼이 있는 monday dev 보드가 필요합니다. 이 컬럼이 없는 보드는 요약을 반환하지 않으므로 스프린트 메타데이터나 보드 검토를 요청하세요.
</Accordion>

<Accordion title="에이전트가 아이템을 변경하기 전에 멈춤">
아이템 쓰기는 승인 게이트를 거칩니다. CloudThinker에서 대기 중인 작업을 승인하거나, 인가한 monday.com 계정에 해당 보드의 쓰기 권한이 있는지 확인하세요.
</Accordion>

---

## 보안

<ConnectionSecurity />

- **쓰기에 승인 필요** — 아이템 생성, 컬럼 변경, 업데이트 작성이 CloudThinker에서 승인 필요로 유지되도록 하세요.
- **되돌릴 방법 없음** — monday.com에는 삭제나 보관 도구가 없으므로 에이전트가 만든 항목은 monday.com에서 직접 제거하세요.

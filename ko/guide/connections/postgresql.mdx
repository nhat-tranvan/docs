PostgreSQL 데이터베이스를 연결하면 CloudThinker 에이전트가 스키마를 읽고, 느린 쿼리의 순위를 매기고, 인덱스를 추천하고, vacuum, 잠금, 복제 상태를 확인할 수 있습니다. 전용 읽기 전용 사용자의 연결 URL 하나를 CloudThinker에 제공하며, 연결은 제한 모드로 실행됩니다. 모든 쿼리가 읽기 전용이므로, 에이전트는 사용자가 승인해도 쓸 수 없습니다.

## 사전 요구 사항

- 셀프 호스팅 PostgreSQL, Amazon RDS 또는 Aurora, Cloud SQL, Azure Database for PostgreSQL처럼 CloudThinker가 인터넷에서 접근할 수 있는 PostgreSQL 엔드포인트. 에이전트는 CloudThinker Cloud에서 연결하므로, `localhost`와 사설 주소는 사용자의 네트워크가 아니라 CloudThinker Cloud 쪽에서 확인됩니다.
- 이 연결에는 아직 private link나 VPN 옵션이 없습니다. 데이터베이스가 비공개라면 CloudThinker의 egress IP로 제한된 엔드포인트를 공개하세요. 읽기 복제본을 공개하면 프라이머리를 비공개로 유지할 수 있지만, 그 쿼리 통계는 복제본 자체의 워크로드만 다룹니다. [비공개 서비스 접근](/ko/guide/connections/overview#비공개-서비스-접근)을 참조하세요.
- `CREATE ROLE`과 `GRANT`를 실행할 수 있는 관리자 계정.
- 느린 쿼리 순위와 워크로드 인덱스 조언을 원한다면 `pg_stat_statements` 확장. 그 밖의 모든 것은 이것 없이도 작동합니다.

## 설정

<Steps>
  <Step title="읽기 전용 사용자 만들기">
    관리자로 접속하여 CloudThinker용 로그인 역할을 만듭니다.

    ```sql
    CREATE ROLE cloudthinker_readonly WITH LOGIN PASSWORD '<secure-password>';
    ```
  </Step>
  <Step title="읽기 권한 부여">
    분석할 데이터베이스에서 다음을 실행합니다. 에이전트가 읽어야 할 `public` 이외의 모든 스키마에 대해 스키마 줄을 반복하세요.

    ```sql
    GRANT CONNECT ON DATABASE your_database TO cloudthinker_readonly;
    GRANT USAGE ON SCHEMA public TO cloudthinker_readonly;
    GRANT SELECT ON ALL TABLES IN SCHEMA public TO cloudthinker_readonly;
    ALTER DEFAULT PRIVILEGES FOR ROLE app_owner IN SCHEMA public GRANT SELECT ON TABLES TO cloudthinker_readonly;
    GRANT pg_monitor TO cloudthinker_readonly;
    ```

    `app_owner`를 애플리케이션의 테이블을 만드는 역할로 바꾸세요. 보통 마이그레이션을 실행하는 역할입니다. 기본 권한은 지정한 역할이 만든 테이블에만 적용되므로, 테이블을 만드는 역할마다 이 줄을 반복하세요.

    `pg_monitor`를 부여하면 에이전트가 자신의 것뿐 아니라 모든 세션, 잠금, 쿼리 통계를 볼 수 있습니다.
  </Step>
  <Step title="pg_stat_statements 켜기">
    많은 관리형 서비스가 이미 미리 로드하므로 먼저 확인하세요.

    ```sql
    SHOW shared_preload_libraries;
    ```

    `pg_stat_statements`가 없으면 `shared_preload_libraries`에 추가하고 PostgreSQL을 재시작합니다. RDS, Aurora, Cloud SQL에서는 파라미터 그룹이나 데이터베이스 플래그에서 설정하고 재부팅합니다. 이미 목록에 있다면 재시작을 건너뛰세요. 그런 다음 대상 데이터베이스에서 관리자로 실행합니다.

    ```sql
    CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
    ```

    **성공 상태:** `cloudthinker_readonly`로 로그인한 상태에서 `SELECT count(*) FROM pg_stat_statements;`가 오류 대신 숫자를 반환합니다. 이는 `pg_monitor` 권한 부여가 작동한다는 증명이기도 합니다.
  </Step>
  <Step title="네트워크 접근 열기">
    방화벽, 보안 그룹 또는 authorized networks 목록에서 CloudThinker의 egress IP로부터 PostgreSQL 포트(기본값 `5432`)로의 인바운드 연결을 허용합니다. 이 문서는 CloudThinker의 egress IP 목록을 공개하지 않습니다. CloudThinker 담당자에게 문의하거나 [문의하기](https://cloudthinker.io/contact)를 이용하세요.

    셀프 호스팅 PostgreSQL에서는 `pg_hba.conf`에서 `cloudthinker_readonly`가 그 주소들로부터 로그인할 수 있도록 IP마다 한 줄씩 허용하세요.

    ```text
    hostssl your_database cloudthinker_readonly <cloudthinker-ip>/32 scram-sha-256
    ```

    그런 다음 `SELECT pg_reload_conf();`로 구성을 다시 로드합니다. 관리형 서비스는 이를 대신 처리합니다.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Settings → Workspace → Connections**를 열고 **PostgreSQL**을 선택한 다음, 상세 패널에서 **Connect**를 클릭합니다. 대화상자에서 필요하면 **Alias**와 **Description**을 변경합니다(여러 데이터베이스를 연결할 때 에이전트는 설명을 읽고 올바른 데이터베이스를 고릅니다). **DATABASE_URI**에 URL을 붙여 넣고 **Connect**를 클릭합니다.

    ```text
    postgresql://cloudthinker_readonly:<secure-password>@db.example.com:5432/your_database?sslmode=require
    ```

    **성공 상태:** 연결에 **Connecting**과 **Verifying**이 표시된 다음 **Connected**가 표시됩니다. 그러면 CloudThinker가 에이전트가 데이터베이스를 탐색하는 [deep look](/ko/guide/connections/overview#연결한-다음에-일어나는-일) 채팅을 엽니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 설명 | 예시 |
|-------|----------|-------------|---------|
| **Alias** | 아니요 | 이 데이터베이스의 짧은 이름. `postgres-1`처럼 다음으로 사용 가능한 별칭이 미리 채워집니다 | `prod-db` |
| **Description** | 아니요 | 이 데이터베이스가 무엇인지. 에이전트가 인스턴스를 고를 때 읽습니다 | `Production orders database` |
| **DATABASE_URI** | 예 | 사용자, 비밀번호, 호스트, 포트, 데이터베이스, SSL 모드를 포함한 전체 연결 URL | `postgresql://cloudthinker_readonly:<password>@db.example.com:5432/shop?sslmode=require` |

양식에서 URL 필드의 레이블은 **DATABASE_URI**입니다. 각 연결은 URL에 지정된 데이터베이스 하나를 다룹니다. 다른 데이터베이스를 분석하려면 다른 **Alias**로 PostgreSQL 연결을 하나 더 추가하세요.

비밀번호에 `@`, `:`, `/`, `#`이 포함되어 있다면 URL 인코딩하세요(예: `@`는 `%40`이 됩니다). 그렇지 않으면 URL이 파싱되지 않습니다.

## 필수 권한

| 에이전트에게 맡길 작업 | 부여할 권한 |
|--------------------|-------|
| 스키마, 테이블, 인덱스 읽기와 읽기 전용 쿼리 실행 | 데이터베이스에 대한 `CONNECT`, 각 스키마에 대한 `USAGE`, 그 테이블에 대한 `SELECT` |
| 모든 세션, 잠금, 차단 쿼리 보기 | `pg_monitor` |
| 느린 쿼리 순위와 워크로드 인덱스 조언 | `pg_stat_statements` 확장과 `pg_monitor` |
| 인덱스를 만들지 않고 테스트 | 관리자가 설치한 `hypopg` 확장. 관리형 서비스마다 다르므로 공급자의 지원 확장 목록을 확인하세요 |

<Tip>
사용자를 읽기 전용으로 유지하세요. 제한 모드가 이미 에이전트의 쓰기를 차단하지만(쓰기가 Approvals를 거치는 [MySQL](/ko/guide/connections/mysql)과 다름), `SELECT` 전용 역할이면 두 계층 중 어느 쪽에서 실수가 있어도 데이터를 변경할 수 없습니다.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 작업 |
|------------|--------------------|
| **스키마 검사** | 스키마, 테이블, 뷰, 시퀀스를 나열하고 열 유형, 제약 조건, 인덱스 읽기 |
| **읽기 전용 SQL** | 데이터에 관한 질문에 답하기 위해 `SELECT` 쿼리 실행 |
| **느린 쿼리** | `pg_stat_statements`를 바탕으로 총 시간, 평균 시간 또는 전체 리소스 사용량 기준으로 문의 순위 매기기 |
| **쿼리 계획과 인덱스 조언** | 쿼리를 explain하고, 쿼리 하나 또는 전체 워크로드에 대한 인덱스를 추천하고, `hypopg`로 가상 인덱스 테스트 |
| **상태 점검** | 무효, 중복, 비대, 미사용 인덱스, 캐시 적중률, 한도에 가까운 시퀀스, 연결 사용량 찾기 |
| **Vacuum과 잠금** | 테이블 비대, 지연된 autovacuum, 트랜잭션 ID wraparound 위험, 차단 쿼리 보고 |
| **복제** | 복제본 지연과 복제 슬롯 상태 확인 |

### 연결 확인

```text
List the schemas and tables in the connected PostgreSQL database with their sizes
```

테이블 이름이 스키마별로 크기와 함께 표시되어야 합니다. `permission denied` 오류는 사용자가 읽을 수 없는 객체를 알려 줍니다.

### 예시 프롬프트

```text
Which 10 queries use the most resources on PostgreSQL, and what indexes would help them?
Run a health check on the database and list the indexes I can safely drop
Is anything blocking right now? Show the blocking and waiting queries
```

## 문제 해결

<Accordion title="Connection refused 또는 시간 초과">
CloudThinker가 호스트에 접근할 수 없습니다. **DATABASE_URI**의 호스트와 포트가 공개되어 있거나 접근 가능한지, 방화벽이나 보안 그룹이 CloudThinker를 허용하는지, `postgresql.conf`의 `listen_addresses`가 `localhost`가 아닌지 확인하세요. RDS에서는 인스턴스가 publicly accessible이거나 네트워크 설정을 통해 접근 가능해야 합니다.
</Accordion>

<Accordion title="Password authentication failed 또는 no pg_hba.conf entry">
사용자나 비밀번호가 잘못되었거나, `pg_hba.conf`가 CloudThinker의 주소에서 이 사용자를 허용하지 않습니다. **DATABASE_URI**에서 비밀번호가 URL 인코딩되었는지 확인하고, 사용자에 대한 `pg_hba.conf` 줄을 추가한 다음 PostgreSQL을 다시 로드하세요.
</Accordion>

<Accordion title="pg_stat_statements not found 또는 느린 쿼리 데이터 없음">
확장이 로드되지 않았거나 생성되지 않았습니다. `SHOW shared_preload_libraries;`에 `pg_stat_statements`가 포함되어 있는지 확인하고, 방금 추가했다면 재시작한 다음 대상 데이터베이스에서 `CREATE EXTENSION pg_stat_statements;`를 실행하세요. 통계는 마지막 초기화 시점부터 시작되므로, 새 서버에는 기록이 거의 없습니다.
</Accordion>

<Accordion title="테이블 또는 스키마에 대해 Permission denied">
사용자에게 스키마에 대한 `USAGE`나 테이블에 대한 `SELECT`가 없습니다. 권한 부여 이후에 만들어진 테이블에는 테이블을 만드는 역할을 지정한 `ALTER DEFAULT PRIVILEGES FOR ROLE` 줄이 필요합니다.
</Accordion>

<Accordion title="HypoPG not installed">
가상 인덱스 테스트에는 `hypopg` 확장이 필요합니다. 설치하거나, 테스트 없이 인덱스 추천을 요청하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **전송 중 암호화**: **DATABASE_URI**에 `sslmode=require`를 넣어 자격 증명과 결과가 평문으로 네트워크를 지나지 않게 하세요. `verify-full`은 CloudThinker 쪽에 서버의 CA 인증서도 필요한데, 연결에는 이를 제공할 필드가 없으므로 `require`를 사용하세요.
- **모든 쿼리에 제한 모드**: CloudThinker는 PostgreSQL 연결을 읽기 전용으로 실행하므로, 역할의 권한이 허용하더라도 에이전트는 쓸 수 없습니다.

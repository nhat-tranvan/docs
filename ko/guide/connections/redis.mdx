자체 호스팅 Redis, Upstash, Redis Cloud 같은 Redis 서버를 연결하면 CloudThinker 에이전트가 메모리와 축출(eviction)을 검사하고, 가장 큰 키와 TTL이 없는 키를 찾고, 클라이언트를 나열하고, 명령 지연 시간을 읽을 수 있습니다. CloudThinker에는 연결 URL 하나(`REDIS_URL`)만 제공합니다. 에이전트는 해당 사용자의 ACL이 허용하는 명령을 실행할 수 있으며, 연결의 쓰기 도구는 먼저 [Approvals](/guide/approvals/overview)를 거칩니다.

## 사전 요구사항

- CloudThinker가 인터넷에서 접근할 수 있는 Redis 엔드포인트. 에이전트는 CloudThinker Cloud에서 연결하므로 `localhost`와 사설 주소는 사용자의 네트워크가 아니라 CloudThinker 쪽에서 해석됩니다. 프라이빗 링크 옵션이 없으므로 Amazon ElastiCache, MemoryDB 같은 VPC 전용 서비스는 연결할 수 없습니다. [Reaching private services](/ko/guide/connections/overview#비공개-서비스-접근)를 참고하세요.
- 전용 ACL 사용자를 원한다면 Redis 6 이상. 이전 버전은 공유 비밀번호 하나만 지원합니다.
- `ACL SETUSER`를 실행하거나 관리형 프로바이더 콘솔에서 사용자를 만들 수 있는 관리자 권한.

## 설정

<Steps>
  <Step title="읽기 전용 사용자 만들기">
    <Tabs>
      <Tab title="자체 호스팅 Redis">
        키를 읽고 에이전트가 사용하는 진단 명령만 실행할 수 있는 사용자를 만듭니다.

        ```bash
        redis-cli --askpass ACL SETUSER cloudthinker-readonly on \
          '><readonly-password>' '~*' \
          -@all +@read +info +ping +select '+client|list' -keys
        ```

        | 부분 | 의미 |
        |------|---------|
        | `'><readonly-password>'` | 비밀번호를 설정합니다. `>`는 ACL 구문입니다 |
        | `'~*'` | 모든 키를 허용합니다. `'~app:*'`처럼 접두사로 좁히세요 |
        | `-@all +@read` | 아무 권한 없이 시작한 뒤 `GET`, `SCAN`, `TYPE`, `TTL` 같은 읽기 명령을 허용합니다 |
        | `+info +ping +select '+client\|list'` | 서버 통계, 상태 확인, 데이터베이스 인덱스 선택, 클라이언트 나열을 허용합니다 |
        | `-keys` | 대형 인스턴스를 멈추게 할 수 있는 `KEYS`를 차단합니다. 에이전트는 대신 `SCAN`을 사용합니다 |

        `--askpass`는 관리자 비밀번호를 입력받으므로 셸 기록에 남지 않습니다. `default`로 로그인하지 않는다면 `--user <admin-user>`를 추가하세요. `'+client|list'`의 따옴표는 유지하세요. 따옴표가 없으면 셸이 `|`를 파이프로 읽습니다.

        재시작 후에도 유지되도록 저장하세요. `aclfile`을 사용한다면 `ACL SAVE`를, 사용자가 `redis.conf`에 있다면 `CONFIG REWRITE`를 실행합니다.
      </Tab>
      <Tab title="관리형 Redis">
        모든 프로바이더가 같은 ACL 규칙을 받습니다. 콘솔 필드에는 따옴표 없이 붙여넣고, 셸에서는 `'+client|list'`의 따옴표를 유지하세요.

        ```text
        ~* -@all +@read +info +ping +select +client|list -keys
        ```

        - **Redis Cloud**: **Data Access Control**로 이동합니다. 위 규칙으로 Redis ACL을 추가하고, 이를 데이터베이스에 적용하는 역할을 만든 뒤, 그 역할로 사용자를 만듭니다.
        - **Azure Cache for Redis**: `rediss://`와 함께 TLS 포트 `6380`을 사용하고, 캐시의 방화벽 규칙에서 CloudThinker의 egress IP를 허용합니다.

        그런 다음 해당 사용자의 TCP 또는 Redis CLI 연결 URL을 복사합니다. REST 또는 SDK URL은 사용하지 마세요. CloudThinker는 Redis 프로토콜로 통신합니다.
      </Tab>
    </Tabs>
  </Step>
  <Step title="사용자가 읽기 전용인지 확인">
    ```bash
    redis-cli -u 'rediss://cloudthinker-readonly@redis.example.com:6379' --askpass SET probe 1
    redis-cli -u 'rediss://cloudthinker-readonly@redis.example.com:6379' --askpass INFO memory
    ```

    서버가 TLS를 사용하지 않을 때만 `redis://`를 사용하세요. 서버와 맞지 않는 스킴은 `NOPERM`이 아니라 연결 오류로 실패합니다.

    **성공 상태:** `SET`이 `NOPERM`으로 실패하고, `INFO memory`가 메모리 통계를 출력합니다.
  </Step>
  <Step title="네트워크 접근 열기">
    방화벽, 보안 그룹, 프로바이더 허용 목록에서 CloudThinker의 egress IP로부터 Redis 포트로 들어오는 연결을 허용합니다. 이 문서에는 CloudThinker의 egress IP 목록을 게시하지 않습니다. CloudThinker 담당자에게 문의하거나 [contact us](https://cloudthinker.io/contact)로 연락하세요. 포트는 기본 `6379`, Azure TLS는 `6380`이며, Redis Cloud에서는 데이터베이스마다 할당됩니다. 자체 호스팅 Redis에서는 `redis.conf`의 `bind`가 `127.0.0.1`만으로 되어 있지 않은지 확인하세요.
  </Step>
  <Step title="CloudThinker에서 연결 추가">
    **Settings → Workspace → Connections**를 열고 **Redis**를 선택한 뒤 상세 패널에서 **Connect**를 클릭합니다. 대화 상자에서 필요하면 **Alias**와 **Description**을 변경합니다. URL을 **REDIS_URL**에 붙여넣고 **Connect**를 클릭합니다.

    ```text
    rediss://cloudthinker-readonly:<readonly-password>@redis.example.com:6379/0
    ```

    **성공 상태:** 연결이 **Connecting**과 **Verifying**을 거쳐 **Connected**로 표시됩니다. 이후 CloudThinker가 [deep look](/ko/guide/connections/overview#연결한-다음에-일어나는-일) 채팅을 열고, 에이전트가 서버를 탐색합니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 필수 | 설명 | 예시 |
|-------|----------|-------------|---------|
| **Alias** | 아니요 | 이 서버의 짧은 이름. `redis-1`처럼 다음 사용 가능한 alias가 미리 채워집니다 | `prod-cache` |
| **Description** | 아니요 | 이 서버가 무엇인지. 에이전트가 인스턴스를 고를 때 읽습니다 | `Production session cache` |
| **REDIS_URL** | 예 | 스킴, 사용자, 비밀번호, 호스트, 포트, 선택적 데이터베이스 인덱스를 포함한 전체 URL | `rediss://cloudthinker-readonly:<password>@redis.example.com:6379/0` |

| URL 부분 | 값 |
|----------|--------|
| 스킴 | TLS는 `rediss://`(Upstash에서 필수), 일반 TCP는 `redis://` |
| 사용자 | ACL 사용자. Upstash와 비밀번호만 있는 Redis에서는 `default` 사용 |
| 포트 | 기본 `6379`, Azure TLS는 `6380`. Redis Cloud는 데이터베이스마다 포트를 할당하므로 콘솔에서 복사 |
| 데이터베이스 인덱스 | 끝에 `/0`부터 `/15`. `0`이면 생략 |

비밀번호의 특수 문자는 URL 인코딩하세요(`@`는 `%40`).

## 필요 권한

| 에이전트에게 허용할 작업 | 허용 항목 |
|--------------------|-------|
| 키, 유형, TTL, 크기, 키 개수 읽기 | `+@read`와 `~*` 같은 키 패턴 |
| 메모리, 축출, 적중률, 복제, 명령 통계 읽기 | `+info` |
| 연결된 클라이언트 보기 | `+client\|list` |
| `0` 이외의 데이터베이스 인덱스 사용 | `+select` |
| 키 변경 | `+@write` 같은 쓰기 카테고리. 권장하지 않습니다. [쓰기 권한](#쓰기-권한)을 참고하세요 |

<Tip>
사용자를 읽기 전용으로 유지하세요. 읽기 전용 ACL은 무엇이 승인되든 Redis에서 모든 쓰기를 막습니다.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 |
|------------|--------------------|
| **메모리와 축출** | 사용 메모리, 단편화 비율, `maxmemory` 정책, 축출 수, 적중률 읽기 |
| **키스페이스** | 데이터베이스별 키 개수 세기, `SCAN`으로 키 샘플링, 유형·크기·TTL 읽기 |
| **만료 감사** | 데이터베이스별로 TTL이 있는 키와 없는 키를 비교하고, 이를 `maxmemory` 정책과 대조 |
| **가장 큰 키** | 샘플링한 키를 크기(문자열 길이, 또는 리스트·해시·셋·정렬된 셋의 요소 수) 순으로 정렬. 기본 샘플은 `SCAN`으로 얻은 100개 키이므로 결과는 추정치이며, 스캔이 모든 키를 다루지 못했으면 답변에 그렇게 표시됩니다 |
| **클라이언트와 지연 시간** | 연결된 클라이언트를 나열하고 `INFO commandstats`에서 명령별 호출 수와 지연 시간 읽기 |
| **복제** | 역할, 연결된 레플리카, 복제 오프셋 읽기 |
| **모듈** | 서버에 해당 모듈이 로드되어 있으면 RediSearch 인덱스와 RedisJSON 문서 읽기 |

### 연결 확인

```text
Summarize Redis memory usage, connected clients, eviction policy, and key counts per database
```

사용 메모리와 최대치, 클라이언트 수, `maxmemory` 정책, 각 데이터베이스 인덱스의 키 개수가 나와야 합니다. `NOPERM` 오류에는 빠진 명령이 표시됩니다. `ACL SETUSER cloudthinker-readonly`로 추가한 뒤 다시 요청하세요.

### 예시 프롬프트

```text
Which sampled keys are the largest, and what share of keys in each database has no TTL?
Is Redis evicting keys? Show the eviction policy, evictions, and hit rate
Which commands have the highest average latency according to commandstats?
```

## 쓰기 권한

Redis 연결에는 쓰기 도구가 있습니다. ACL이 쓰기를 허용하면 각 도구는 먼저 [Approvals](/guide/approvals/overview)를 거치며, [rule](/guide/approvals/rules)로 먼저 묻게 하거나 거부할 수 있습니다.

<ApprovalDefault />

| 분류 | 도구 |
|---|---|
| Write | 값 설정, 만료 설정, 이름 변경, 게시, 리스트에서 꺼내기, 해시·리스트·셋·정렬된 셋·스트림·JSON 문서에 추가 |
| Destructive | 키 삭제, 또는 해시·리스트·셋·정렬된 셋·스트림·JSON 문서에서 항목 제거 |
| 명령에 따라 다름 | 원시 Redis 명령: `GET` 같은 읽기는 묻지 않고 실행되고, `DEL`이나 `FLUSHALL`은 destructive로, 그 밖의 명령은 write로 분류됩니다 |

## 문제 해결

<Accordion title="NOAUTH 또는 WRONGPASS">
사용자 또는 비밀번호가 틀렸거나 없습니다. **REDIS_URL**에서 URL 인코딩을 포함해 둘 다 확인하세요. Upstash에서는 사용자로 `default`를, 비밀번호로 데이터베이스 토큰을 사용합니다. 자체 호스팅 Redis에서는 `ACL LIST`를 실행해 사용자가 존재하고 `on` 상태인지 확인하세요.
</Accordion>

<Accordion title="연결이 닫히거나 Connected에 도달하지 않음">
대개 URL 형식이 잘못된 경우입니다. 스킴(TLS 엔드포인트에는 `rediss://`, Upstash는 필수), 호스트, 포트, 비밀번호 포함 여부를 확인하세요. 프로바이더의 REST 또는 SDK URL은 동작하지 않습니다. TCP 또는 Redis CLI URL을 사용하세요.
</Accordion>

<Accordion title="연결 거부 또는 시간 초과">
CloudThinker가 서버에 도달할 수 없습니다. 방화벽, 보안 그룹, 프로바이더 허용 목록과 `redis.conf`의 `bind`가 `127.0.0.1`만으로 되어 있지 않은지 확인하세요. 사설 네트워크의 서버는 먼저 도달 가능한 엔드포인트가 필요합니다.
</Accordion>

<Accordion title="INFO, CLIENT LIST, 또는 읽기 명령에서 NOPERM">
ACL에 명령이 빠져 있습니다. `ACL SETUSER cloudthinker-readonly ...`로 `+info`, `'+client|list'`, 또는 오류에 표시된 카테고리를 추가한 뒤 다시 요청하세요. 읽기 전용 사용자가 쓰기 명령에서 `NOPERM`을 받는 것은 정상입니다.
</Accordion>

<Accordion title="Command is not available: FT.* 또는 JSON.*">
서버에 RediSearch 또는 RedisJSON 모듈이 로드되어 있지 않습니다. 많은 호스팅 요금제가 이 모듈을 제공하지 않습니다. 나머지 기능은 모두 계속 동작합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **`rediss://`를 사용하세요**: 일반 `redis://`는 비밀번호와 모든 값을 암호화하지 않고 보냅니다. 서버나 프로바이더가 지원하면 항상 TLS를 사용하세요.
- **키 범위를 제한하세요**: `~*`를 `~cache:*`처럼 에이전트에게 필요한 접두사로 바꿔, 세션 토큰이나 기타 민감한 키에 접근하지 못하게 하세요.

Rollbar 프로젝트를 연결하면 CloudThinker 에이전트가 오류를 분류하고, 상위 이슈를 순위 매기고, 배포를 검토하고, 세션 리플레이 컨텍스트를 가져오고, 하나 또는 여러 프로젝트 전반의 항목을 업데이트할 수 있습니다. Rollbar는 **프로젝트 액세스 토큰**으로 인증합니다. 읽기 스코프 토큰은 조사를 위해 충분하며, 쓰기 스코프 토큰은 승인이 필요한 항목 업데이트를 추가합니다.

## 사전 요구 사항

- CloudThinker가 접근할 프로젝트에 접근 권한이 있는 **Rollbar 계정**.
- 각 프로젝트에 대한 **프로젝트 액세스 토큰** (조사에는 읽기 스코프로 충분).
- 에이전트가 항목 상태를 업데이트해야 하는 경우에만 **쓰기 스코프 토큰** (승인 필요).

<Info>
Rollbar 토큰은 **프로젝트 단위**로 스코프가 지정됩니다. CloudThinker는 하나의 연결에서 여러 프로젝트를 지원하므로 포함할 각 프로젝트에 대해 토큰을 하나씩 제공하세요.
</Info>

## 설정

<Steps>
  <Step title="프로젝트 액세스 토큰 생성">
    Rollbar에서 프로젝트를 열고 **읽기** 스코프로 **프로젝트 액세스 토큰**을 생성(또는 복사)합니다. 에이전트가 항목을 업데이트해야 하는 경우 **쓰기** 스코프 토큰도 추가합니다. 토큰 및 구성 세부 정보는 Rollbar의 [MCP Server Setup](https://docs.rollbar.com/docs/mcp-server-setup#configuration)을 참조하세요.
  </Step>
  <Step title="CloudThinker에 연결 추가">
    **Connections → Rollbar**로 이동하여 다음을 입력합니다.
    - **Project config (JSON)**: Rollbar 프로젝트당 하나의 항목이 있는 `projects` 배열로, 각 항목에는 `name`과 `token`이 포함됩니다.

    **Connect**를 클릭합니다. CloudThinker가 자격 증명을 검증하고 **Connected** 상태를 표시합니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **ROLLBAR_CONFIG_JSON** | 각 Rollbar 프로젝트를 액세스 토큰에 매핑하는 `projects` 배열. 각 항목에는 `name`과 `token`이 있습니다. | 아래 참조 |

```json
{
  "projects": [
    { "name": "backend",  "token": "tok_abc123" },
    { "name": "frontend", "token": "tok_xyz789" }
  ]
}
```

<Info>
토큰 필드는 `token`입니다 (`access_token`이 아님). `projects`는 배열입니다. 형식은 Rollbar의 [MCP 멀티 프로젝트 구성](https://docs.rollbar.com/docs/mcp-server-setup#configuration)과 일치합니다.
</Info>

## 필수 권한

읽기 작업(프로젝트 목록, 항목, 상위 오류, 배포, 버전, 리플레이)은 **읽기** 스코프 프로젝트 액세스 토큰으로 작동합니다. 항목 업데이트는 추가로 **쓰기** 스코프 토큰 **및** CloudThinker의 명시적인 [승인](/ko/guide/approval)이 필요합니다.

<Tip>
최소 권한 원칙을 따르세요. 조사에는 읽기 스코프 토큰을 사용하고, 에이전트가 항목 상태를 업데이트해야 하는 프로젝트에만 쓰기 스코프 토큰을 추가하세요.
</Tip>

## 에이전트 기능

연결 후 에이전트는 구성된 프로젝트 전반에서 오류를 조사하고 조치를 취할 수 있습니다.

### 읽기 기능

| 카테고리 | 에이전트가 할 수 있는 작업 |
|----------|----------------------|
| **프로젝트** | 구성된 Rollbar 프로젝트 목록 조회 및 단일 프로젝트로 자동 스코프 지정 |
| **오류 항목** | 현재 및 활성 항목 목록 조회, 항목 세부 정보 및 발생 신호 검사 |
| **상위 오류** | 가장 큰 영향을 미치는 오류와 현재 프로덕션 오류 현황 표시 |
| **배포** | 프로젝트별 최근 배포 검토 |
| **릴리스 및 버전** | 버전 컨텍스트 가져오기 및 릴리스와 오류 활동 연관 |
| **세션 리플레이** | 기록된 리플레이가 있는 항목의 리플레이 컨텍스트 가져오기 |

### 쓰기 기능

| 카테고리 | 에이전트가 할 수 있는 작업 |
|----------|----------------------|
| **항목 업데이트** | 항목 상태 변경 (예: 해결, 음소거) — **승인 필요** |

<Warning>
항목 업데이트는 실행 전 명시적인 사용자 승인이 필요하며, 프로젝트, 항목, 원하는 변경 사항을 지정해야 합니다.
</Warning>

### 연결 확인

```text
@alex list my Rollbar projects and show the current top errors
```

### 예시 프롬프트

```text
@alex triage current Rollbar items and rank them by impact #recommend
@alex show the top errors that appeared after the latest deployment
@alex review recent deployments and correlate them with new error activity
```

## 문제 해결

<Accordion title="인증 실패 또는 쿼리 결과 없음">
붙여넣은 프로젝트 구성이 유효하지 않은 JSON이거나, 요청된 프로젝트 이름이 포함되지 않았거나, 만료된 토큰에 프로젝트가 매핑되어 있습니다. 항목 또는 배포가 없는 것을 "데이터 없음"으로 처리하기 전에 먼저 구성된 프로젝트 목록을 조회하세요.
</Accordion>

<Accordion title="에이전트가 사용할 프로젝트를 묻는 경우">
여러 프로젝트가 구성된 경우 발생합니다. 에이전트가 쿼리 범위를 지정할 수 있도록 프롬프트에 프로젝트를 지정하세요 (예: "for my-app").
</Accordion>

<Accordion title="항목에 대한 리플레이 없음">
세션 리플레이 컨텍스트는 기록된 리플레이가 있는 항목에만 존재합니다. 리플레이가 없는 항목은 리플레이 데이터를 반환하지 않습니다. 이는 예상된 동작이며 오류가 아닙니다.
</Accordion>

<Accordion title="항목 업데이트가 차단됨">
업데이트는 승인이 필요하며 **쓰기** 스코프 토큰이 필요합니다. 해당 프로젝트의 토큰에 쓰기 스코프가 있는지 확인한 후 메시지가 표시될 때 작업을 승인하세요.
</Accordion>

## 보안

<ConnectionSecurity />

- **최소 권한 토큰** — 조사에는 읽기 스코프 프로젝트 토큰을 사용하고, 에이전트가 항목 상태를 업데이트해야 하는 경우에만 쓰기 스코프를 추가하세요.
- **교체** — 프로젝트 액세스 토큰을 정기적으로 교체하고 CloudThinker에서 업데이트하세요.

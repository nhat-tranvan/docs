Rollbar를 연결하면 CloudThinker 에이전트가 상위 오류의 순위를 매기고, 새 오류를 최근 배포 및 버전과 연관 짓고, 세션 리플레이 맥락을 가져오고, [Approvals](/guide/approvals/overview)를 거쳐 항목의 상태를 변경할 수 있습니다. 각 Rollbar 프로젝트를 해당 프로젝트 액세스 토큰에 매핑하는 JSON 구성 하나를 붙여넣으므로, 하나의 연결로 여러 프로젝트를 다룰 수 있습니다.

## 사전 요구 사항

- 에이전트가 읽을 각 프로젝트에 접근할 수 있는 Rollbar 계정.
- 해당 프로젝트마다 프로젝트 액세스 토큰. Rollbar 토큰은 프로젝트별이므로 하나의 토큰으로 두 프로젝트를 다룰 수 없습니다.

## 설정

<Steps>
  <Step title="프로젝트 액세스 토큰 생성">
    Rollbar에서 프로젝트를 열고 **Settings → Project Access Tokens**로 이동합니다. **Create new access token**을 클릭하고 **read**를 선택하며, 에이전트가 항목 상태를 변경하게 하려는 경우에만 **write**를 추가합니다. **post_server_item**과 **post_client_item**은 선택하지 않은 상태로 둡니다. 이들은 Rollbar로 오류를 보내는 권한이며, CloudThinker는 이를 하지 않습니다. 프로젝트마다 반복합니다.
  </Step>
  <Step title="프로젝트 구성 작성">
    프로젝트마다 항목이 하나씩 있는 `projects` 배열을 가진 JSON 객체를 만듭니다. 각 항목에는 `name`과 `token`이 있습니다. `name`은 프롬프트에서 쓰는 자체 레이블이므로 Rollbar 프로젝트 이름과 일치할 필요가 없습니다. `backend` 같은 짧은 이름이 입력하기 가장 쉽습니다.

    ```json
    {
      "projects": [
        { "name": "backend", "token": "<backend-project-token>" },
        { "name": "frontend", "token": "<frontend-project-token>" }
      ]
    }
    ```
  </Step>
  <Step title="연결 추가">
    **Settings → Workspace → Connections**를 열고 **Discover** 탭에서 **Rollbar**를 선택한 다음, JSON을 **ROLLBAR_CONFIG_JSON**에 붙여넣고 **Connect**를 클릭합니다.

    **성공 상태:** 연결이 **Connected**로 표시됩니다. Connect는 각 토큰으로 Rollbar를 호출하지 않으므로, 잘못된 토큰은 첫 요청에서야 드러납니다. 바로 새 채팅에서 [연결 검증](#연결-검증)의 프롬프트를 실행합니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 설명 | 예시 |
|-------|-------------|---------|
| **ROLLBAR_CONFIG_JSON** | `projects` 배열. 각 항목에는 `name`과 `token`이 있습니다. 키는 `access_token`이 아니라 `token`입니다 | `{"projects":[{"name":"backend","token":"..."}]}` |

형식은 Rollbar의 [MCP server multi-project configuration](https://docs.rollbar.com/docs/mcp-server-setup#configuration)과 같습니다.

## 필요 권한

| 토큰 범위 | 허용하는 작업 |
|-------------|----------------|
| **read** | 프로젝트, 항목, 상위 오류, 배포, 버전, 세션 리플레이 |
| **write** | 해결 또는 음소거처럼 항목의 상태 변경. 각 변경은 Approvals도 거칩니다 |

<Tip>
읽기 전용 토큰으로 시작하세요. 에이전트가 항목을 해결하거나 음소거하게 하려는 프로젝트에만 write 범위를 추가하세요.
</Tip>

## 에이전트 기능

| 기능 | 에이전트가 할 수 있는 일 |
|------------|--------------------|
| **Discovery** | 구성된 프로젝트를 나열하고, 프로젝트가 하나뿐이면 스스로 선택합니다 |
| **Error triage** | 현재 항목을 나열하고, 항목 세부 정보와 발생 횟수를 읽고, 상위 오류의 순위를 매깁니다 |
| **Release context** | 최근 배포를 검토하고 배포 리비전에서 버전 세부 정보를 가져옵니다 |
| **Session replay** | 기록된 리플레이가 있는 항목의 리플레이 맥락을 가져옵니다. Rollbar에서 프로젝트에 세션 리플레이가 설정되어 있어야 합니다 |
| **Item updates (checked each time)** | 하나의 항목 상태를 변경합니다. 프로젝트, 항목, 원하는 변경을 지정해야 합니다 |

에이전트는 분류, 배포 검토, 리플레이 읽기 중에는 항목을 변경하지 않습니다. 업데이트는 대화에서 요청할 때만 실행되며, Approvals를 거칩니다.

<ApprovalDefault />

### 연결 검증

새 채팅에서 CloudThinker에게 질문합니다:

```text
List my Rollbar projects and show the top errors in each
```

구성에 있는 모든 프로젝트 이름이 각각 영향이 가장 큰 항목, 수준, 발생 횟수와 함께 표시됩니다. 프로젝트가 없다면 붙여넣은 JSON에 해당 프로젝트가 없는 것입니다.

### 예시 프롬프트

```text
Which errors in backend first appeared after the latest deployment?
Rank the active items in frontend by impact and show replay context for the top one
Resolve item #1042 in backend
```

여러 프로젝트가 구성되어 있다면 프롬프트에서 프로젝트 이름을 지정합니다. 그렇지 않으면 에이전트가 어느 프로젝트를 사용할지 묻습니다. 항목 번호에는 Rollbar가 항목에 표시하는 `#` 번호를 사용합니다.

## 문제 해결

<Accordion title="호출이 401 Unauthorized로 실패하거나 빈 결과가 반환됨">
붙여넣은 구성이 유효하지 않은 JSON이거나, 지정한 프로젝트를 포함하지 않거나, Rollbar에서 취소·비활성화·속도 제한된 토큰을 담고 있습니다. 에이전트에게 구성된 프로젝트를 나열해 달라고 요청한 다음, 연결을 편집하여 JSON이나 토큰을 수정합니다.
</Accordion>

<Accordion title="에이전트가 어느 프로젝트를 사용할지 물음">
둘 이상의 프로젝트가 구성되어 있는데 프롬프트에서 프로젝트를 지정하지 않았습니다. 구성의 프로젝트 이름을 추가합니다(예: "in backend").
</Accordion>

<Accordion title="항목에 사용할 수 있는 리플레이가 없음">
리플레이 맥락은 세션 리플레이가 기록된 항목에만 있습니다. 리플레이가 없는 항목은 리플레이 데이터를 반환하지 않습니다. 이는 오류가 아니라 예상된 동작입니다.
</Accordion>

<Accordion title="항목 업데이트가 차단되거나 실패함">
해당 프로젝트의 토큰에 write 범위가 없거나, 승인을 거부했습니다. Rollbar에서 토큰에 write 범위를 추가하고, 연결을 업데이트한 다음 다시 요청합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **임시 구성 파일**: 토큰은 암호화되어 저장됩니다. 에이전트가 Rollbar를 사용할 때 Rollbar 프로세스는 해당 프로세스만 읽을 수 있는 임시 파일에서 토큰을 읽으며, 프로세스가 멈추면 파일이 삭제됩니다.
- **교체와 새 프로젝트**: 연결을 편집할 때 저장된 JSON은 표시되지 않습니다. 토큰을 교체하거나 프로젝트를 추가할 때마다 모든 프로젝트가 포함된 전체 JSON을 다시 붙여넣습니다.

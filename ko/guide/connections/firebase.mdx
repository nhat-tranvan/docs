Firebase를 연결하면 CloudThinker가 프로젝트와 앱을 나열하고, SDK 구성을 읽고, Firestore·Storage·Realtime Database 보안 규칙을 감사하고, 배포 상태를 확인할 수 있습니다. Firebase는 **Google Cloud 서비스 계정 키**(JSON 파일)로 인증하며, 서비스 계정의 IAM 역할이 CloudThinker가 접근할 수 있는 범위를 결정합니다.

## Firebase와 Google Cloud 중 선택

| 연결 | 다루는 범위 | 연결해야 할 때 |
|---|---|---|
| Firebase | `firebase-tools`를 통한 프로젝트, 앱, SDK 구성, 보안 규칙, 배포 | Firebase 앱을 감사하거나 배포하려는 경우 |
| [Google Cloud](/ko/guide/connections/gcp) | Google Cloud CLI를 통한 Compute, GKE, BigQuery, IAM, 비용 | 인프라, ID, 비용에 대한 답을 원하는 경우 |

두 연결은 별개입니다. 같은 프로젝트에 둘 다 연결할 수 있으며, 각각 자체 서비스 계정을 사용합니다.

## 사전 요구 사항

- CloudThinker가 검사할 Firebase 프로젝트.
- 해당 프로젝트의 Google Cloud에서 서비스 계정과 키를 만들고 IAM 역할을 할당할 수 있는 권한.
- 서비스 계정 키 생성이 허용되어 있어야 합니다. 조직이 `constraints/iam.disableServiceAccountKeyCreation`을 적용한다면(2024년 5월 이후 생성된 조직의 기본값), 먼저 조직 정책 관리자에게 이 프로젝트에 대한 예외를 요청합니다.

## 설정

먼저 여러 프로젝트를 어떻게 다룰지 정합니다. 대부분의 팀은 프로젝트마다 연결 하나를 사용합니다.

| 옵션 | 작동 방식 | 적합한 경우 |
|---|---|---|
| 프로젝트마다 연결 하나 | 각 프로젝트에 자체 서비스 계정, 키, 별칭, **Environment**가 있습니다. 전환이 필요 없습니다. | 여러 프로젝트를 자주 오가거나, 프로젝트마다 다른 승인 규칙을 원하는 경우 |
| 서비스 계정 하나, 여러 프로젝트 | 하나의 연결이 서비스 계정이 볼 수 있는 모든 프로젝트에 접근하지만, 한 번에 하나의 활성 프로젝트에서만 작업합니다. 전환할 때마다 승인 절차를 거칩니다. | 주로 한 프로젝트에서 작업하고 가끔 다른 프로젝트를 보는 경우 |

<Warning>
Firebase **Project settings**의 **Generate new private key**를 사용하지 마세요. 이 기능은 기본 `firebase-adminsdk-…@<project-id>.iam.gserviceaccount.com` 계정의 키를 만드는데, 이 계정은 광범위한 관리자 권한을 가지며 자체 앱이 이 계정에 의존할 수 있습니다. 해당 계정에서 역할을 제거하지도 마세요.
</Warning>

<Tabs>
  <Tab title="Google Cloud console">
    <Steps>
      <Step title="전용 서비스 계정 생성">
        [Google Cloud console](https://console.cloud.google.com/)에서 Firebase 프로젝트를 선택하고 **IAM & Admin → Service Accounts**로 이동합니다. **Create service account**를 클릭하고 이름을 `cloudthinker-firebase`로 지정한 다음 **Create and continue**를 클릭합니다.
      </Step>
      <Step title="읽기 전용 Firebase 역할 부여">
        **Firebase Viewer**(`roles/firebase.viewer`)를 추가하고 **Done**을 클릭합니다. CloudThinker가 승인 절차를 거쳐 앱을 만들거나 배포하게 하려는 경우에만 쓰기 역할을 추가합니다. [필요 권한](#필요-권한)을 참조하세요.
      </Step>
      <Step title="JSON 키 생성">
        서비스 계정을 열고 **Keys** 탭으로 이동하여 **Add key → Create new key**를 클릭합니다. **JSON**을 선택하고 **Create**를 클릭합니다.

        **성공 상태:** 브라우저가 `.json` 키 파일을 다운로드합니다.
      </Step>
    </Steps>
  </Tab>
  <Tab title="gcloud CLI">
    [Cloud Shell](https://shell.cloud.google.com/) 또는 Google Cloud에 로그인된 터미널에서 다음을 실행합니다.

    ```bash
    PROJECT_ID=your-firebase-project-id
    SA=cloudthinker-firebase@$PROJECT_ID.iam.gserviceaccount.com

    gcloud iam service-accounts create cloudthinker-firebase \
      --project="$PROJECT_ID" --display-name="CloudThinker Firebase"

    gcloud projects add-iam-policy-binding "$PROJECT_ID" \
      --member="serviceAccount:$SA" --role="roles/firebase.viewer"

    gcloud iam service-accounts keys create cloudthinker-firebase-key.json --iam-account="$SA"
    ```

    마지막 명령은 키를 `cloudthinker-firebase-key.json`에 씁니다. Cloud Shell에서는 `cloudshell download cloudthinker-firebase-key.json`으로 다운로드하고, CloudThinker에 업로드한 후 `rm cloudthinker-firebase-key.json`으로 Cloud Shell 사본을 삭제합니다. CloudThinker가 승인 절차를 거쳐 앱을 만들거나 배포하게 하려는 경우에만 쓰기 역할도 바인딩합니다. [필요 권한](#필요-권한)을 참조하세요.
  </Tab>
</Tabs>

그런 다음 CloudThinker에서 연결합니다:

<Steps>
  <Step title="연결 대화상자 열기">
    **Settings → Workspace → Connections**를 열고 **Firebase**를 선택한 다음 **Connect**를 클릭합니다.
  </Step>
  <Step title="연결 이름 지정">
    **Alias**(예: `prod-firebase`)와 **Description**(예: `Production Firebase project, mobile app`)을 입력합니다. 연결이 여러 개일 때 에이전트는 설명을 읽고 올바른 연결을 선택합니다.
  </Step>
  <Step title="키 업로드">
    `.json` 파일을 업로드 영역으로 끌어다 놓거나, **choose a JSON file**을 클릭하여 찾아봅니다. **Connect**를 클릭합니다.

    **성공 상태:** 연결이 **Connected**로 표시되고, 키의 `project_id`가 활성 프로젝트가 됩니다. 그런 다음 CloudThinker가 [deep look](/ko/guide/connections/overview#연결한-다음에-일어나는-일) 채팅을 열고, 에이전트가 프로젝트를 살펴봅니다.
  </Step>
  <Step title="환경 설정">
    **Settings → Workspace → Connections**에서 **Firebase**를 열고 연결 행의 연필 아이콘을 클릭한 다음 **Edit Instance**에서 **Environment**를 설정합니다. 이 값은 사람과 에이전트를 위해 연결에 레이블을 붙입니다.
  </Step>
</Steps>

## 연결 세부 정보

| 필드 | 입력할 내용 | 예시 |
|-------|---------------|---------|
| **Alias** | 이 연결의 짧은 이름. 비워 두면 자동으로 정해집니다. | `prod-firebase` |
| **Description** | 프로젝트가 무엇인지. 에이전트는 이를 사용해 연결 중에서 선택합니다. | `Production Firebase project` |
| **GOOGLE_SERVICE_ACCOUNT_KEY** | 업로드한 서비스 계정의 JSON 키 파일. 이 파일의 `project_id`가 활성 Firebase 프로젝트를 정합니다. | `cloudthinker-firebase-key.json` |

별도의 프로젝트 ID나 Firebase 구성 파일은 필요하지 않습니다. 여러 프로젝트를 다루려면 [설정](#설정)의 옵션을 참조하세요.

## 필요 권한

| 원하는 작업 | 서비스 계정의 IAM 역할 | CloudThinker 승인 |
|---------------|---------------------------------|--------------------------|
| 프로젝트와 앱 인벤토리, SDK 구성 읽기, 보안 규칙 감사 | Firebase Viewer(`roles/firebase.viewer`) | 아니요 |
| 활성 프로젝트 전환 | 대상 프로젝트에 대한 접근(예: 해당 프로젝트의 Firebase Viewer) | Approvals를 거침 |
| 배포 상태 확인 | Firebase Viewer(`roles/firebase.viewer`) | Approvals를 거침 |
| 프로젝트, 앱, Android SHA 키 생성, 기능 초기화, 배포 | Firebase Admin(`roles/firebase.admin`) 또는 Firebase Hosting Admin(`roles/firebasehosting.admin`), Firebase Rules Admin(`roles/firebaserules.admin`)처럼 한 제품에 한정된 역할 | Approvals를 거침 |

일부 배포에는 Google이 더 많은 역할을 요구합니다. 예를 들어 Cloud Functions 배포에는 Cloud Functions Developer(`roles/cloudfunctions.developer`)와 Service Account User(`roles/iam.serviceAccountUser`)도 필요합니다.

<Tip>
Firebase에는 **Allow writes** 스위치가 없습니다. 모든 변경은 [Approvals](/guide/approvals/overview)를 거치며, IAM 역할도 허용할 때만 실행됩니다. 감사용으로는 Firebase Viewer를 부여하세요.
</Tip>

## 에이전트 기능

CloudThinker는 이 연결을 통해 공식 Firebase CLI(`firebase-tools`) 도구 세트를 사용합니다.

| 기능 | CloudThinker가 하는 일 | 승인 |
|------------|------------------------|----------|
| **Projects and apps** | 접근 가능한 프로젝트를 나열하고, 활성 프로젝트를 검사하고, iOS·Android·웹 앱을 나열합니다 | 아니요 |
| **SDK configuration** | 앱의 Firebase SDK 구성을 읽습니다 | 아니요 |
| **Security rules audit** | Firestore, Storage, Realtime Database 규칙을 읽고 열려 있어 보이는 규칙을 표시합니다 | 아니요 |
| **Firebase docs** | Firebase 및 Google 개발자 문서를 검색합니다 | 아니요 |
| **Project and app controls** | 활성 프로젝트 전환, 프로젝트·앱·Android SHA 키 생성, 기능 초기화, 배포, 배포 상태 확인 | Approvals를 거침 |

이 연결은 `firebase-tools`가 제공하는 범위를 다룹니다. Firestore 문서, Authentication 사용자, Crashlytics, Remote Config는 읽지 않습니다.

### 연결 검증

```text
Show my Firebase environment and list the projects you can access
```

답변은 실제 `project_id`를 활성 프로젝트로 제시합니다.

### 예시 프롬프트

```text
Audit the Firestore and Storage security rules and flag anything that allows unauthenticated writes
List the apps registered in the active Firebase project as a table
Show the Firebase SDK config for my web app
```

## 문제 해결

<Accordion title="인증 실패 또는 자격 증명을 사용할 수 없음">
**원인:** 키 JSON이 유효하지 않거나, 불완전하거나, 삭제된 서비스 계정의 것입니다.

**해결:** 서비스 계정의 새 JSON 키를 만듭니다. **Settings → Workspace → Connections**에서 **Firebase**를 열고 연결 행의 연필 아이콘을 클릭한 다음, **Edit Instance**의 **Replace…**를 사용해 업로드합니다.
</Accordion>

<Accordion title="CloudThinker가 활성 프로젝트가 선택되지 않았다고 표시함">
**원인:** 오류에 `PRECONDITION_FAILED`가 표시되고 활성 프로젝트가 언급됩니다. CloudThinker는 연결이 시작될 때마다 키의 `project_id`로 활성 프로젝트를 설정합니다. 저장된 키를 파싱할 수 없으면(예: 업로드 전에 편집한 경우) 프로젝트가 선택되지 않습니다. 리소스가 없는 것은 아닙니다.

**해결:** 이번 프롬프트에서는 프로젝트 이름을 지정합니다. 활성 프로젝트 전환은 승인 절차를 거칩니다. 영구적으로 해결하려면 새 JSON 키를 만들고, 다운로드한 파일을 수정하지 않은 채 **Edit Instance**의 **Replace…**로 업로드합니다.
</Accordion>

<Accordion title="프로젝트, 규칙 또는 배포에서 권한 거부">
**원인:** 서비스 계정에 해당 Firebase 제품의 IAM 역할이 없거나, 프로젝트가 서비스 계정에 보이지 않습니다.

**해결:** **Google Cloud console → IAM**에서 읽기와 규칙에는 Firebase Viewer를, 생성과 배포에는 Firebase Admin(또는 [필요 권한](#필요-권한)의 더 좁은 역할)을 부여합니다. 그런 다음 다시 시도합니다.
</Accordion>

<Accordion title="프로젝트 목록에 프로젝트가 나타나지 않음">
**원인:** 서비스 계정에 해당 프로젝트의 역할이 없습니다.

**해결:** 해당 프로젝트의 **Google Cloud console → IAM**에서 서비스 계정에 Firebase Viewer(`roles/firebase.viewer`)를 부여한 다음 다시 요청합니다.
</Accordion>

<Accordion title="테스트에 Timed out이 표시됨">
**원인:** 테스트가 시간 안에 끝나지 않았습니다. Firebase 엔드포인트는 공개되어 있으므로 네트워크 문제인 경우는 드뭅니다.

**해결:** 다시 연결합니다. 계속 시간 초과되면 [문의](https://cloudthinker.io/contact)하세요.
</Accordion>

<Accordion title="생성 또는 배포 작업이 실행되지 않음">
**원인:** 쓰기 작업에는 이를 허용하는 IAM 역할과 CloudThinker의 승인이 모두 필요합니다. 요청을 거부했다면 CloudThinker는 다시 시도하지 않습니다.

**해결:** 서비스 계정의 역할을 확인한 다음 다시 요청합니다.
</Accordion>

## 보안

<ConnectionSecurity />

- **키 보호**: JSON 키는 서비스 계정의 완전한 자격 증명입니다. 업로드한 후 로컬 사본을 삭제하고, 커밋하거나 채팅에 붙여넣지 마세요.
- **최소 90일마다 키 교체**: 새 키를 만들고 **Edit Instance**의 **Replace…**로 업로드한 다음 이전 키를 삭제합니다. [Rotate a credential](/ko/guide/connections/overview#자격-증명-교체)을 참조하세요.

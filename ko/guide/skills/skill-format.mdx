모든 스킬은 `SKILL.md` 파일입니다. 스킬 이름과 사용 시점을 적은 짧은 YAML 헤더(frontmatter) 뒤에 Markdown 지침이 이어집니다. 이 페이지는 파일이 로드되기 위해 통과해야 하는 규칙과, 에이전트가 지침을 따르게 만드는 작성 패턴을 다룹니다.

## 최소한의 유효한 스킬

이것을 복사해 이름, 설명, 규칙을 바꾸면 로드됩니다.

```markdown
---
name: security-review-checklist
description: Enforce our SQL and secrets rules when reviewing code. Use for any pull request review or security question about code.
---

## SQL injection

- Flag SQL built with string concatenation or f-strings.
- Require parameterized queries or ORM methods.

## Secrets

- Flag hardcoded credentials, tokens, and API keys.
- Require secrets to come from a secrets manager or environment variables.
```

| 부분 | 필수 | 목적 |
|---|---|---|
| Frontmatter (`---` 줄 사이) | 예 | `name`과 `description`을 담습니다. 유효한 YAML이어야 합니다. |
| 지침 본문 | 예 | 에이전트가 스킬을 사용할 때 읽는 Markdown 규칙입니다. |
| 규칙 그룹마다 `##` 제목 하나 | 권장 | 사용자와 에이전트 모두 규칙을 쉽게 훑어볼 수 있습니다. |
| 좋은 예와 나쁜 예 | 권장 | 각 규칙을 구체적인 사례에 고정합니다. |

## Frontmatter 필드

| 필드 | 필수 | 규칙 |
|---|---|---|
| `name` | 예 | 문자나 숫자로 시작하고, 이후에는 문자, 숫자, `_` 또는 `-`. 대문자를 사용할 수 있습니다. 공백은 안 됩니다. 최대 255자. 이름은 대소문자를 구분하며, `/` 명령은 정확한 이름을 사용합니다. `pdf`, `docx`, `deep-research` 같은 CloudThinker 기본 제공 스킬과 같으면 안 됩니다. |
| `description` | 예 | 스킬이 하는 일과 사용 시점을 말하는 비어 있지 않은 문장. 에이전트는 설명을 읽고 작업에 맞는 스킬을 정하므로, 모호한 설명이면 스킬이 거의 선택되지 않습니다. 콜론이 들어 있으면 따옴표로 감싸세요: `description: "Use when: reviewing PRs"`. 최대 2,000자. |
| `argument-hint` | 아니요 | 채팅 `/` 메뉴에서 스킬을 실행할 때만 적용됩니다. 해당 메뉴에서 스킬 옆에 표시되는 텍스트(예: `<service-name>`)로, 명령 뒤에 무엇을 입력할지 알려 줍니다. 동작은 바뀌지 않습니다. `/skill-name` 뒤에 입력한 내용은 메시지의 일부로 에이전트에 전달됩니다. |

다른 도구용으로 작성된 SKILL.md 파일의 `license`나 `allowed-tools` 같은 기타 필드는 업로드를 막지 않으며, CloudThinker는 이를 사용하지 않습니다. 다른 도구에서 가져온 스킬도 `name`과 `description`만 있으면 로드됩니다.

이름 예시:

| 이름 | 유효? |
|---|---|
| `security-checklist` | 예 |
| `security_checklist` | 예 |
| `Security-Checklist` | 예 |
| `Security Checklist` | 아니요(공백) |
| `-checklist` | 아니요(문자나 숫자로 시작해야 함) |

<Note>
**Write skill instructions**로 스킬을 만들면 CloudThinker가 **Skill name**과 **Description** 필드로 frontmatter를 만들어 줍니다. frontmatter를 직접 작성하는 것은 `.zip`을 업로드하거나 `SKILL.md`를 직접 편집할 때뿐입니다.
</Note>

## Zip 패키지 구조

스킬에 보조 파일이 필요하거나 워크스페이스 간에 스킬을 옮길 때 `.zip`을 사용하세요. **Settings → Workspace → Skills → +** (**Search skills** 옆) **→ Upload zip file**에서 업로드합니다.

```text
security-review-checklist.zip
└── security-review-checklist/
    ├── SKILL.md            required
    ├── references/         optional: longer docs the skill points to
    ├── scripts/            optional: scripts the skill runs
    └── schemas/            optional: schemas the skill validates against
```

- `SKILL.md`는 zip의 루트나 최상위 폴더 하나 안에 두세요. 스킬 이름은 frontmatter의 `name`에서 가져오므로 폴더 이름은 일치하지 않아도 됩니다.
- zip 파일 이름은 대소문자를 포함해 frontmatter의 `name`과 정확히 같게 지으세요(예: `security-review-checklist.zip`). CloudThinker는 zip 파일 이름으로 기존 스킬을 찾아 **Replace**를 제안합니다. 둘이 다르면 **Replace**가 zip 이름과 일치하는 스킬을 삭제하고 다른 이름으로 스킬을 업로드할 수 있습니다. 일치하는 스킬이 없을 때 frontmatter `name`이 이미 사용 중이면 업로드가 **This skill name is already in use.**와 함께 실패합니다.
- `scripts/`, `schemas/`, `references/`만 보존됩니다. 다른 파일과 폴더는 무시됩니다.
- `SKILL.md`에서 보조 파일은 상대 경로로 참조하세요. 에이전트는 이를 자동으로 읽지 않으며, 지침이 가리킬 때 파일을 엽니다. 예:

  ```markdown
  For the escalation order, read references/escalation-matrix.md.
  ```

- 스크립트는 이름과 실행 시점을 적으세요. 예: "Run `scripts/check_tags.sh` with the account ID." 스크립트는 Bash 또는 TypeScript(`bun`으로 실행)일 수 있습니다. 에이전트는 다른 명령과 같은 명령 도구로 스크립트를 실행하므로, 스크립트가 하는 쓰기는 다른 명령처럼 [Approvals](/guide/approvals/overview)를 거칩니다.
- 스크립트는 워크스페이스 [Credentials](/guide/credentials)를 각 자격 증명의 **Key** 이름으로 된 환경 변수로 받습니다. 키가 `DATADOG_API_KEY`인 자격 증명은 스크립트에서 `$DATADOG_API_KEY`입니다.

<Note>
자격 증명은 스킬 스크립트 전용이 아닙니다. 에이전트가 실행하는 모든 명령은 스킬이나 프롬프트가 사용하는지와 관계없이 모든 워크스페이스 자격 증명을 받습니다. 자격 증명을 스킬 하나나 에이전트 하나로 한정할 수는 없습니다. 스킬에 필요한 키만 저장하고 읽기 전용 벤더 키를 우선 사용하세요. [에이전트가 자격 증명을 사용하는 방식](/guide/credentials#how-agents-use-credentials)을 참조하세요.
</Note>

## 제한

| 항목 | 제한 |
|---|---|
| 앱에서 만들거나 편집한 `SKILL.md` | 50,000자 |
| zip으로 업로드한 `SKILL.md` | 아래 zip 제한 외에는 제한이 없습니다. 50,000자가 넘는 파일은 앱 내 편집기에서 저장할 수 없습니다. |
| 설명 | 2,000자 |
| 스킬 이름 | 255자 |
| Zip 업로드 크기 | 5 MB |
| zip 안의 파일 수 | 1,024 |
| 압축 해제 후 zip 크기 | 50 MB. `references/`, `scripts/`, `schemas/` 파일에 대한 유일한 제한입니다 |

## 업로드 전 확인

- `SKILL.md` 이름이 대문자이고 zip 루트 또는 한 단계 아래 폴더에 있습니다.
- 파일 첫 줄이 `---`로 시작하고 frontmatter가 `---`로 닫힙니다.
- `name`이 문자나 숫자로 시작하고 문자, 숫자, `_`, `-`만 사용합니다.
- `name`이 `pdf`나 `deep-research` 같은 기본 제공 스킬 이름이 아닙니다.
- `description`이 채워져 있고, 콜론이 있으면 따옴표로 감싸져 있습니다.
- zip 파일 이름이 `name`과 정확히 일치합니다.
- 보조 파일이 `references/`, `scripts/`, `schemas/`에 있습니다.

## 에이전트가 따르는 지침 작성

**에이전트가 이미 모르는 것만 쓰세요.** 에이전트는 SQL 인젝션을 이미 이해합니다. 그에 관한 팀의 규칙은 모릅니다.

```markdown
<!-- Too general: the agent already knows this -->
SQL injection is a vulnerability where attackers run arbitrary SQL
through unsanitized input, so always be careful with queries...

<!-- Useful: your specific rules -->
## SQL injection
- Flag `execute()` calls that take f-strings or `.format()`.
- Require the `db.query(sql, params)` helper for every new query.
```

**원하는 자유도에 맞춰 규칙 스타일을 고르세요.**

| 자유도 | 스타일 | 용도 |
|---|---|---|
| 높음 | 원칙과 가이드라인 | 아키텍처 조언, 탐색적 리뷰 |
| 중간 | 예시가 있는 체크리스트 | 표준 리뷰, 보안 검사 |
| 낮음 | 정확한 템플릿과 고정 필드 | 출력 형식, 필수 섹션 |

**설명하지 말고 보여 주세요.** 예시 한 쌍이 문단 하나보다 낫습니다.

```markdown
## Naming
- `remaining_retries`, not `r`
- `is_authenticated`, not `auth`
- Booleans start with `is_`, `has_`, or `should_`.
```

**스킬 하나에 주제 하나를 유지하세요.** 보안 규칙과 성능 규칙을 분리하면 각각을 다른 곳에서 사용할 수 있게 지정할 수 있습니다. 스킬이 약 300줄을 넘으면 나누거나, 긴 참조 표를 `references/`로 옮기고 가리키세요. 이는 에이전트가 흐름을 유지하도록 돕는 조언이며, 50,000자 하드 제한보다 훨씬 낮은 수준입니다.

## 완전한 예시

조정해서 쓸 수 있는 풀 리퀘스트 표준 스킬:

````markdown
---
name: pr-review-standards
description: Enforce our pull request standards for size, tests, and docs. Use when reviewing any merge request or pull request.
argument-hint: <pull request link>
---

## Size

- Flag pull requests over 500 changed lines as "needs splitting" and suggest split points.
- Generated files (migrations, lockfiles) don't count toward the limit.

## Tests

- Require tests for every new public function.
- Flag deleted tests that have no matching feature removal.

## Docs

- Flag breaking API changes without a migration note.
- Require a README update when a new environment variable is added.

## Comment format

```text
**[severity]** Short title

What is wrong and why it matters.

**Suggestion:** How to fix it.
```

Severity is one of `critical`, `warning`, `suggestion`, `nitpick`. For example:

```text
**[warning]** New endpoint has no tests

`create_invoice()` is public and has no test, so a regression would reach production unnoticed.

**Suggestion:** Add a test in `tests/test_invoices.py` that covers the happy path and an invalid amount.
```
````

저장한 뒤 풀 리퀘스트 리뷰에 적용되도록 **Available in** 아래에서 **Review**를 체크하세요. 리뷰는 `argument-hint`를 사용하지 않습니다. 이는 채팅의 `/` 메뉴에서 스킬을 실행하는 사람에게만 도움이 됩니다. [커스텀 스킬](/ko/guide/skills/custom-skills#스킬을-적용할-곳-선택)을 참조하세요.

## 문제 해결

<AccordionGroup>
  <Accordion title="This skill file could not be saved">
    - **Frontmatter.** 없거나, YAML 오류가 있거나, `name` 또는 `description`이 비어 있습니다. `SKILL.md`가 `---`로 시작하는지, 헤더가 `---`로 닫히는지, 두 필드 모두 값이 있는지 확인하세요. 콜론이 들어 있는 설명은 따옴표로 감싸세요. `name`이 위의 이름 규칙을 따르는지도 확인하세요.
    - **CloudThinker가 찾는 위치에 `SKILL.md`가 없습니다.** zip 루트나 한 단계 아래 폴더에 있어야 하며, 파일 이름은 대소문자를 구분합니다. `skill.md`를 `SKILL.md`로 바꾸고 다시 압축하세요.
  </Accordion>
  <Accordion title="SKILL.md name must match the selected skill">
    기존 스킬을 직접 편집할 때는 frontmatter의 `name`이 정확히 그대로 유지되어야 합니다. 스킬 이름을 바꾸려면 다운로드해 이름을 바꾸고 새 스킬로 업로드하세요. 그런 다음 기존 스킬을 삭제하고, 새 스킬은 **Chat**만으로 시작하므로 **Available in**을 다시 체크하세요.
  </Accordion>
  <Accordion title="업로드 후 스크립트나 문서가 없음">
    `SKILL.md` 옆의 `scripts/`, `schemas/`, `references/` 안에 있는 파일만 보존됩니다. 다른 파일은 이 폴더 중 하나로 옮기세요.
  </Accordion>
  <Accordion title="스킬은 로드되지만 에이전트가 거의 사용하지 않음">
    사람들이 실제로 입력하는 단어("Use when reviewing a pull request")로 스킬 사용 시점을 말하도록 `description`을 다시 쓰세요. 그런 다음 규칙을 구체적으로 만들고 예시를 추가하세요.
  </Accordion>
</AccordionGroup>

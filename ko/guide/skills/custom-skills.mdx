커스텀 스킬은 리뷰 체크리스트, 에스컬레이션 순서, 태깅 규칙처럼 팀이 일을 처리하는 방식을 CloudThinker에 가르치는 작성된 지침 세트(`SKILL.md` 파일)입니다. **Settings → Workspace → Skills**에서 한 번 작성하면 에이전트가 사용 가능하도록 지정한 모든 곳에서 이를 적용하므로, 누구도 같은 규칙을 매 프롬프트에 다시 입력할 필요가 없습니다.

## 스킬을 작성해야 할 때

같은 지시를 반복하고 있다면 스킬을 작성하세요. 대표적인 예는 다음과 같습니다.

| 영역 | 스킬에 담을 수 있는 규칙 예시 |
|---|---|
| Review | "문자열 연결로 만든 SQL을 모두 표시하세요. 매개변수화된 쿼리를 요구하세요." |
| Incident | "애플리케이션 파드보다 로드 밸런서와 데이터베이스를 먼저 확인하세요." |
| 클라우드 운영 | "모든 리소스에는 `team`, `env`, `cost-center` 태그가 필요합니다." |
| 보고서 | "성과, 차단 요인, 다음 단계의 세 섹션으로 요약하세요." |

스킬은 에이전트에게 **행동하는 방법**을 알려 줍니다. [스킬을 사용해야 할 때](/ko/guide/skills/overview#스킬을-사용할-때)를 참조하세요.

## 사전 요구 사항

- 사용하는 방법에 맞는 역할. Developer와 Viewer는 스킬을 읽을 수 있지만 **+** 버튼이나 **New skill**은 보이지 않습니다. [역할](/guide/security/roles)을 참조하세요.

| 방법 | 사용할 수 있는 사람 |
|---|---|
| **Write skill instructions**, **Upload zip file**, 편집, 삭제 | 워크스페이스 Admin |
| 채팅의 `/creating-skill` (Admin은 메뉴에서 **Create with CloudThinker**도 볼 수 있음) | 채팅할 수 있는 모든 멤버(Admin 또는 Developer) |
| **Skills Hub** 설치 링크 | 모든 워크스페이스 멤버 |
- `SKILL.md`를 직접 작성하거나 패키지를 업로드하려면 [스킬 형식](/ko/guide/skills/skill-format)을 훑어보세요.

## 스킬 만들기

<Steps>
  <Step title="Skills 열기">
    **Settings → Workspace → Skills**로 이동합니다. 페이지 왼쪽에 워크스페이스의 스킬 목록이, 오른쪽에 선택한 스킬이 표시됩니다.
  </Step>
  <Step title="새 스킬 메뉴 열기">
    스킬 목록 상단의 **Search skills** 옆에 있는 **+** 버튼을 클릭합니다. (스킬이 아직 없으면 대신 **New skill** 버튼이 표시됩니다.) 메뉴에서 생성 방법 중 하나를 선택합니다. 선택한 방법은 아래 탭을 참조하세요.
  </Step>
  <Step title="스킬 만들기">
    <Tabs>
      <Tab title="Create with CloudThinker">
        첫 스킬에 가장 적합합니다. CloudThinker가 질문하며 파일 초안을 작성합니다.

        1. **Create with CloudThinker**를 클릭합니다. `/creating-skill` 명령이 입력된 채팅이 열립니다.
        2. 전송한 뒤 질문에 답합니다. 팀이 적용하는 구체적인 규칙 하나를 예시와 함께 설명하세요.
        3. CloudThinker가 제안하는 초안을 검토합니다. **Proceed with creating this skill?**라고 물으면 **Yes, create it**을 선택하거나, **Change something**을 선택하고 변경할 내용을 말합니다. 그런 다음 **Settings → Workspace → Skills**를 열어 스킬이 활성화되어 있고 **Chat**에서 사용 가능한지 확인합니다.

        어떤 채팅에서든 `/creating-skill`을 입력해 같은 흐름을 시작할 수 있습니다. 일반 채팅이므로 크레딧을 사용합니다. **Yes, create it**을 선택하기 전에는 아무것도 저장되지 않으므로, 중간에 나가도 반쯤 만들어진 스킬이 남지 않습니다.
      </Tab>
      <Tab title="Write skill instructions">
        정확한 규칙을 이미 알고 있을 때 가장 적합합니다.

        1. **Write skill instructions**를 클릭합니다.
        2. 양식을 채웁니다.

        | 필드 | 입력할 내용 |
        |---|---|
        | **Skill name** | 문자나 숫자로 시작하고, 이후에는 문자, 숫자, `_` 또는 `-`. 예: `weekly-status-report`. 최대 255자. |
        | **Description** (필수) | 에이전트가 스킬을 사용해야 할 때. 예: "Generate weekly status reports. Use when asked for updates or progress summaries." 항상 채우세요. 에이전트는 설명으로 스킬을 선택하며, CloudThinker는 설명이 없는 스킬을 저장할 수 없습니다. 최대 2,000자. |
        | **Instructions** | Markdown으로 작성한 규칙. 최대 50,000자. |

        3. **Create**를 클릭합니다.

        붙여 넣을 수 있는 완전한 예시이며, [스킬 테스트](#스킬-테스트)에서 다시 사용합니다.

        - **Skill name:** `weekly-status-report`
        - **Description:** `Generate weekly status reports. Use when asked for updates or progress summaries.`
        - **Instructions:**

        ```markdown
        # Weekly status report

        Write the report in exactly three sections, in this order:

        ## Wins
        What shipped or finished this week. One bullet per item, with the owner.

        ## Blockers
        What is stuck, why, and who can unblock it. Write "None" if nothing is blocked.

        ## Next steps
        What the team will do next week. One bullet per item, with the owner.

        Keep the whole report under 200 words. No other sections.
        ```
      </Tab>
      <Tab title="Upload zip file">
        리포지토리에 보관하거나 워크스페이스 간에 공유하는 스킬에 가장 적합합니다.

        1. **Upload zip file**을 클릭합니다.
        2. `SKILL.md`가 들어 있는 `.zip`을 끌어다 놓습니다. 폴더와 제한은 [zip 패키지 구조](/ko/guide/skills/skill-format#zip-패키지-구조)를 참조하세요.
        3. **Upload**를 클릭합니다.

        zip 파일 이름이 기존 스킬과 일치하면(예: `weekly-status-report.zip`) CloudThinker가 **Replace**할지 묻습니다. **Replace**는 기존 스킬을 삭제하고 새 스킬을 업로드하므로, 스위치가 다시 켜지고 **Available in**이 **Chat**만으로 초기화됩니다. 이후 다른 영역을 다시 체크하세요. Scale 이상에서는 [감사 로그](/guide/security/audit-logs)에 삭제와 업로드가 모두 남습니다. 어느 경우든 기존 파일과 설정은 사라집니다.

        일치 여부는 대소문자를 포함해 zip 파일 이름으로 정확히 판단합니다. zip 이름은 기존 스킬과 일치하지만 frontmatter의 `name`이 다르면, **Replace**는 일치한 스킬을 삭제한 뒤 새 스킬을 frontmatter 이름으로 업로드합니다.
      </Tab>
      <Tab title="Browse skills hub">
        허브는 별도의 사이트입니다. CloudThinker를 떠나 스킬을 고른 뒤 설치 링크로 돌아옵니다.

        1. **Browse skills hub**를 클릭합니다. 새 탭에서 공개 카탈로그가 열립니다.
        2. 원하는 스킬을 찾습니다.
        3. 설치 링크를 클릭합니다. CloudThinker가 워크스페이스에서 **Install Skill** 페이지를 엽니다.
        4. **Install**을 클릭합니다. 스킬이 스킬 목록에 추가되며 **Chat**에서만 활성화됩니다.

        설치된 허브 스킬은 허브 버전이 바뀌어도 업데이트되지 않습니다. 같은 이름의 스킬이 이미 워크스페이스에 있으면 **Skill already installed in this workspace**와 함께 설치가 실패합니다.
      </Tab>
    </Tabs>

    **완료 상태:** 스킬이 목록에 스위치가 켜진 상태로 표시되며 **Available in** 아래에 **Chat**이 체크되어 있습니다.
  </Step>
</Steps>

## 스킬을 적용할 곳 선택

새 스킬은 활성화된 상태로 Chat에서만 사용할 수 있게 시작합니다. 다른 영역은 직접 켜기 전까지 꺼져 있으므로, 테스트가 덜 된 규칙이 리뷰나 인시던트 작업을 바꿀 수 없습니다.

<Steps>
  <Step title="스킬 선택">
    **Settings → Workspace → Skills**에서 목록의 스킬을 클릭합니다.
  </Step>
  <Step title="Available in 아래 영역 체크">
    스킬을 적용할 각 위치를 체크합니다.

    | 옵션 | 에이전트가 사용하는 곳 |
    |---|---|
    | **Chat** | 워크스페이스 채팅, 그리고 Automations와 웹훅 |
    | **Review** | 이 워크스페이스에서 CloudThinker가 리뷰하는 모든 연결된 리포지토리의 모든 머지 리퀘스트와 풀 리퀘스트. 리뷰가 자동으로 시작되었든 `@cloudthinker-ai review` 댓글로 시작되었든 동일합니다. [Review](/ko/guide/code-review/overview)를 참조하세요. |
    | **Incident** | [Resolve](/ko/guide/incident/overview)의 인시던트 분석 및 근본 원인 조사 |
    | **Assessment** | Well-architected 및 보안 태세 평가 |

    스킬을 일시 중지하려면 모든 체크를 해제하지 말고 스위치를 사용하세요.

    <Warning>
    **Review**에는 리포지토리별 필터가 없습니다. 체크하면 모든 리포지토리의 다음 리뷰에 스킬이 적용됩니다. 먼저 **Chat**에서 스킬을 테스트한 뒤 [스킬 테스트](#스킬-테스트)의 Review 테스트를 따르세요.
    </Warning>
  </Step>
  <Step title="스위치가 켜져 있는지 확인">
    스킬 이름 옆의 스위치로 스킬을 활성화하거나 비활성화합니다. 비활성화된 스킬은 저장된 채로 남지만 어떤 에이전트도 사용하지 않습니다.
  </Step>
</Steps>

## 스킬 테스트

<Steps>
  <Step title="규칙이 중요한 작업 실행">
    두 가지 방식을 각각 새 채팅에서 시도하세요. **Write skill instructions** 탭의 `weekly-status-report` 예시의 경우:

    이름으로 실행합니다(`/`를 입력하고 메뉴에서 선택).

    ```text
    /weekly-status-report Notes: shipped the new login page (Ana). Billing export blocked on finance sign-off (Raj). Next week: start the search rewrite (Ana).
    ```

    이름을 지정하지 않고 실행합니다.

    ```text
    Write a status update for the platform team from these notes: shipped the new login page (Ana). Billing export blocked on finance sign-off (Raj). Next week: start the search rewrite (Ana).
    ```

    에이전트가 실제 내용을 갖도록 이와 같은 메모를 붙여 넣으세요. 메모나 연결된 트래커가 없으면 보고할 내용이 없어 대신 질문할 수 있습니다. **Wins**, **Blockers**, **Next steps**의 세 섹션이 각각 담당자가 있는 글머리표 하나와 함께 나와야 합니다.

    **완료 상태:** 에이전트 활동에 **Load Skill** 단계가 표시되고, 규칙을 다시 말하지 않아도 두 답변 모두 스킬(여기서는 성과, 차단 요인, 다음 단계 구성)을 따릅니다.
  </Step>
  <Step title="작동하면 범위 넓히기">
    Chat에서 좋은 결과가 몇 번 나오면 **Review**, **Incident**, **Assessment**를 체크하고 그곳의 다음 실행을 확인하세요. Review에는 샌드박스가 없으므로 다음과 같이 테스트합니다.

    1. **Review**를 체크합니다.
    2. Review가 다루는 테스트용 리포지토리에서 작은 풀 리퀘스트를 엽니다. 초안으로 열지 마세요. 초안은 준비 완료로 표시되기 전까지 리뷰되지 않습니다. 또는 기존 풀 리퀘스트에 `@cloudthinker-ai review` 댓글을 답니다.
    3. 리뷰가 스킬을 따르는지 확인합니다. 따르지 않으면 체크되어 있는 동안 모든 리포지토리가 스킬을 사용하므로 즉시 **Review** 체크를 해제하세요.

    CloudThinker 앱이 해당 리포지토리에 설치되어 있어야 합니다. [Review 설정](/ko/guide/code-review/setup)과 [멘션 명령](/ko/guide/code-review/mention-commands)을 참조하세요.
  </Step>
</Steps>

출력이 규칙을 무시하면 규칙을 더 구체적으로 만들고 좋은 예와 나쁜 예를 추가하세요. "우리 스타일을 따르라" 같은 모호한 지침은 결과를 거의 바꾸지 못합니다.

## 스킬 편집, 다운로드, 삭제

스킬을 선택한 뒤 **Available in** 옆의 아이콘 버튼을 사용합니다. 마우스를 올리면 이름이 표시됩니다.

| 작업 | 방법 | 참고 |
|---|---|---|
| CloudThinker로 편집 | 연필 아이콘(**Edit skill**) → **CloudThinker** | 스킬을 로드하고 다듬도록 돕는 채팅을 엽니다. |
| 직접 편집 | 연필 아이콘(**Edit skill**) → **Manual** | `SKILL.md`만 편집합니다. **Preview**로 렌더링을 확인한 뒤 **Save**합니다. frontmatter의 `name`은 그대로 유지해야 합니다. `references/`, `scripts/`, `schemas/`의 파일을 변경하려면 스킬을 다운로드해 편집한 뒤 **Replace**로 `.zip`을 업로드하세요. **Replace**는 **Available in**을 **Chat**만으로 초기화하므로 다른 영역을 다시 체크하세요. |
| 다운로드 | 다운로드 아이콘(**Download**) | 다른 워크스페이스에 업로드할 수 있는 `.zip`으로 스킬을 저장합니다. |
| 삭제 | 휴지통 아이콘(**Delete**) | 영구적입니다. |

<Warning>
스킬 삭제는 되돌릴 수 없으며, 편집을 되돌릴 버전 기록도 없습니다. 편집하거나 삭제하기 전에 `.zip`을 다운로드하거나, 다시 필요할 수 있다면 대신 스위치를 끄세요.
</Warning>

[감사 로그](/guide/security/audit-logs)는 **Settings → Workspace → Skills**에서 스킬을 만들고, 업로드하고, 편집하고, 범위를 바꾸고, 삭제한 사람을 기록합니다. 단, Scale과 Enterprise에서만 기록되며, 에이전트가 채팅에서 저장한 스킬은 기록되지 않습니다. 다른 플랜에서는 스킬 변경이 기록되지 않으므로, 모든 스킬의 `.zip`을 리포지토리에 보관하고 그곳에서 변경 사항을 업로드하세요.

## 문제 해결

<AccordionGroup>
  <Accordion title="This skill name is already in use">
    이 워크스페이스의 다른 스킬이 그 이름을 사용합니다. 다른 이름을 고르거나, `.zip`을 업로드하고 **Replace**를 선택해 기존 스킬을 덮어쓰세요.
  </Accordion>
  <Accordion title="This skill name is reserved">
    이름이 `pdf`, `docx`, `deep-research` 같은 CloudThinker 기본 제공 스킬과 일치합니다. 다른 이름을 고르세요.
  </Accordion>
  <Accordion title="Failed to create skill">
    양식에서는 **Description**을 비운 채 제출할 수 있지만, 그러면 저장이 이 오류로 실패합니다. 스킬을 사용할 때를 설명하는 문장 하나를 추가하고 **Create**를 다시 클릭하세요. 설명이 채워져 있다면 스킬 저장소가 파일을 받아들이지 않은 것이니 다시 시도하세요.
  </Accordion>
  <Accordion title="This skill file could not be saved">
    스킬 파일을 저장하는 서비스가 업로드를 거부했습니다. 대개 `SKILL.md` frontmatter가 없거나, 유효하지 않거나, `name` 또는 `description`이 빠져 있습니다. [스킬 형식 문제 해결](/ko/guide/skills/skill-format#문제-해결)을 참조하세요.
  </Accordion>
  <Accordion title="Only .zip files are accepted">
    업로드는 `.zip`만 받습니다. `SKILL.md`(그리고 `scripts/`, `schemas/`, `references/` 폴더)를 폴더에 넣어 압축한 뒤 zip을 업로드하세요.
  </Accordion>
  <Accordion title="No agent can load this skill">
    **Settings → Workspace → Skills**의 스킬 상세 패널에 알림으로 표시됩니다. 스킬의 `SKILL.md` frontmatter에 사용할 수 있는 `description`이 없습니다. 대개 직접 편집하다 `description:` 줄을 지우거나 망가뜨린 경우입니다. 직접 편집으로 `description:` 줄을 추가하고 **Save**를 클릭하세요. 그 전까지 스킬은 `/` 메뉴에 나타나지 않습니다.
  </Accordion>
  <Accordion title="Cannot preview this skill">
    스킬의 파일 내용을 불러올 수 없습니다. 짧은 인터뷰를 통해 CloudThinker로 `SKILL.md`를 다시 만들려면 **Recovery with AI**를, 보관해 둔 `.zip`(예: 이전에 다운로드한 파일)으로 복원하려면 **Re-upload**를 클릭하세요.
  </Accordion>
  <Accordion title="에이전트가 스킬을 무시함">
    - 스위치가 켜져 있는지 확인하세요.
    - **Available in** 아래에 올바른 영역이 체크되어 있는지 확인하세요(예: 풀 리퀘스트 리뷰에는 **Review**).
    - 지침을 구체적으로 만들고 예시를 추가하세요. 길고 광범위한 스킬은 짧은 스킬 여러 개로 나누세요.
  </Accordion>
</AccordionGroup>

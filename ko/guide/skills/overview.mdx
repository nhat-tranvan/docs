스킬은 `SKILL.md` 파일로 저장되는 작성된 절차 또는 규칙 모음으로, 에이전트는 눈앞의 작업이 스킬과 일치할 때 이를 따릅니다. 트리아지 단계, 리뷰 체크리스트, 명명 규칙을 한 번만 작성하면, 매 프롬프트마다 반복하지 않아도 에이전트가 적용합니다.

## 스킬을 사용할 때

에이전트가 단계별로 따라야 하는 모든 것에 스킬을 사용하세요. "CPU를 확인하고, 그다음 크레딧, 그다음 트래픽" 같은 트리아지 런북, 리뷰 체크리스트, 태깅 정책 등입니다. 스킬은 에이전트의 작업 방식을 바꿉니다. 스킬은 CloudThinker에서 작성하거나 `.zip`으로 업로드하는 `SKILL.md` 파일입니다.

스킬은 CloudThinker에 제공하는 컨텍스트를 담는 여러 공간 중 하나입니다. [Teach CloudThinker](/guide/teach-cloudthinker)에서 모두 비교합니다.

## 스킬이 사용되는 방식

스킬은 다음 세 가지가 모두 참일 때만 사용됩니다.

1. **활성화되어 있습니다.** 스킬의 스위치가 켜져 있습니다. 새 스킬은 활성화된 상태로 시작합니다.
2. **해당 공간에서 사용할 수 있습니다.** 작업이 일어나는 공간이 **Available in**에서 체크되어 있습니다(아래 표 참조). 새 스킬은 **Chat**만 체크된 상태로 시작합니다. `/`에도 적용됩니다. `/` 메뉴는 활성화된 모든 스킬을 나열하지만, **Chat**이 체크되지 않은 스킬은 채팅에서 사용할 수 없으며 에이전트는 그 스킬 없이 계속 진행합니다. 이름으로 실행할 스킬에는 **Chat**을 체크하세요.
3. **작업에 맞습니다.** Review를 포함한 모든 공간에서, 에이전트는 그 공간에서 사용 가능한 스킬만 보고 이름과 설명이 작업과 일치하는 스킬을 로드합니다. 하나의 작업에 여러 스킬을 로드할 수 있습니다. 따라서 설명은 요청에 쓰이는 단어로 작성하세요. 나쁜 예: "CPU stuff". 좋은 예: "Investigate high CPU or a slow EC2 instance".

| 공간 | 실행되는 곳 |
|---|---|
| **Chat** | 워크스페이스 채팅, 그리고 자동화나 웹훅처럼 자체 공간이 없는 실행 |
| **Review** | [Review](/ko/guide/code-review/overview)의 머지 리퀘스트 및 풀 리퀘스트 리뷰 |
| **Incident** | [Resolve](/ko/guide/incident/overview)의 인시던트 분석과 근본 원인 |
| **Assessment** | Well-architected 및 보안 태세 평가 |

스킬을 이름으로 실행할 수도 있습니다. 채팅 프롬프트 상자에 `/`를 입력하고 메뉴에서 고르세요. 에이전트가 스킬을 사용하면 활동에 **Load Skill** 단계가 표시됩니다.

CloudThinker는 [Skills Hub](https://www.cloudthinker.io/skills)에 바로 쓸 수 있는 스킬도 게시합니다. 설치한 허브 스킬은 직접 만든 스킬처럼 관리하는 워크스페이스 스킬이 되며, 허브 버전이 바뀌어도 변하지 않습니다. 설치 방법은 [커스텀 스킬](/ko/guide/skills/custom-skills#스킬-만들기)을 참조하세요.

새 워크스페이스의 스킬 목록은 비어 있는 상태로 시작합니다. `pdf`, `docx`, `pptx`, `xlsx`, `deep-research` 같은 CloudThinker 기본 제공 스킬은 설정 없이 동작합니다. 목록에 나타나지 않으므로 편집하거나 끌 수 없습니다. 이 이름들은 예약되어 있어 직접 만든 스킬에 사용할 수 없습니다.

## 역할별 권한

**Settings → Workspace → Skills**에서는 워크스페이스 **Admin**만 스킬을 만들고, 편집하고, 연결하고, 삭제할 수 있습니다. 스위치를 켜고 끄거나 **Available in**을 바꾸는 것도 포함됩니다. Developer는 스킬 목록을 보고 `/`로 스킬을 실행할 수 있습니다. Viewer는 스킬을 볼 수 있지만 채팅할 수 없으므로 실행할 수 없습니다. [역할](/guide/security/roles)을 참조하세요.

<Note>
Admin 없이 스킬을 추가하는 경로가 두 가지 있으며, 각각 모든 에이전트의 **Chat**에서 바로 적용됩니다.

- **채팅의 `/creating-skill`.** 채팅할 수 있는 모든 멤버가 실행할 수 있으며, 에이전트가 스킬을 직접 작성합니다.
- **[Learning Mode](/ko/guide/agents/customize#learning-mode).** **Auto** 또는 **Offer**로 설정된 커스텀 에이전트는 채팅에서 스킬을 저장합니다. [Audit Logs](/guide/security/audit-logs)에는 기록되지 않습니다. 모든 스킬이 Admin에게서 와야 한다면 **Off**로 설정하세요.

**Settings → Workspace → Skills**를 수시로 확인하세요. Admin은 그곳에서 이런 스킬을 끄거나, 범위를 다시 정하거나, 삭제할 수 있습니다.
</Note>

## 스킬을 만드는 방법

| 방법 | 적합한 경우 |
|---|---|
| **Create with CloudThinker** | 첫 스킬: CloudThinker가 인터뷰하고 파일 초안을 작성합니다 |
| **Write skill instructions** | 이미 알고 있는 규칙: 이름, 설명, 지침이 있는 양식 |
| **Upload zip file** | 저장소에서 관리하는 스킬, 또는 스크립트와 참조 파일이 있는 스킬 |
| **Browse skills hub** | CloudThinker의 바로 쓸 수 있는 스킬(셀프 호스팅 설치에서는 제공되지 않음) |

단계는 [커스텀 스킬](/ko/guide/skills/custom-skills)에 있습니다. 파일 자체는 [스킬 형식](/ko/guide/skills/skill-format)을 참조하세요.

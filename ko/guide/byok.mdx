Bring Your Own Key(BYOK)는 CloudThinker 뒤에서 실행되는 AI 모델 호출을 자체 공급자 계정에서 실행합니다. 토큰 비용은 공급자가 청구합니다. API 키를 사용하는 호출은 CloudThinker 모델 크레딧을 쓰지 않습니다. 플랫폼 모델로 대체된 호출은 평소처럼 크레딧을 씁니다. [사용량](/ko/guide/billing/usage)을 참고하세요.

<Warning>
BYOK는 실패 시 차단(fail closed)되지 않습니다. 키로 한 호출이 실패하거나 키가 일시 중지 또는 비활성 상태이면 해당 턴은 CloudThinker 플랫폼 모델에서 실행되며, 이를 끄는 설정은 없습니다. 데이터가 자체 공급자 계정에만 도달해야 한다면 **BYOK Credentials Error** 경보를 주시하고 [키가 작동을 멈출 때](#키가-작동을-멈출-때)를 참고하세요.
</Warning>

## 사전 요구 사항

- Scale 또는 Enterprise 플랜. 다른 플랜에서는 BYOK 페이지에 **Upgrade plan** 버튼이 표시됩니다. [가격](/ko/guide/billing/pricing)을 참고하세요.
- 조직 워크스페이스. 개인 워크스페이스에는 **No key in a personal workspace**가 표시됩니다.
- 설정하려는 키에 맞는 역할:

| 키 | 관리자 | 위치 |
|---|---|---|
| **Organization key**, 모든 워크스페이스의 기본값 | 조직 Owner. 조직 Admin은 키의 상태를 볼 수 있지만 자격 증명은 볼 수 없으며 변경할 수 없습니다. | **Settings → Organization → BYOK** |
| **Workspace key**, 하나의 워크스페이스 전용 | 워크스페이스 Admin | **Settings → Workspace → BYOK** |

다른 멤버는 키가 정상인지 여부만 보며, 자격 증명은 절대 보지 못합니다.

- 하나의 공급자 자격 증명:

| 공급자 | 필요한 것 |
|---|---|
| **AWS Bedrock** | CloudThinker가 맡을 수 있는 IAM 역할(권장) 또는 IAM 액세스 키. **Models**에 있는 모델에 대해 [Amazon Bedrock](https://console.aws.amazon.com/bedrock/)에서 모델 액세스가 켜져 있어야 하며, **Models**는 확인 전에 각 행의 기본값을 보여 줍니다. Anthropic 모델의 경우 AWS가 먼저 일회성 사용 사례 양식을 요청합니다. |
| **Anthropic** | Anthropic Console API 키. `sk-ant`로 시작합니다. |
| **FPT Cloud** | FPT Cloud Marketplace API 키. |
| **BytePlus** | BytePlus ModelArk API 키. 조직 및 워크스페이스 키만 해당합니다. |
| **OpenAI** | OpenAI API 키와 선택적 base URL 및 조직. |
| **Azure OpenAI** | Azure 리소스 엔드포인트, 해당 API 키, 기존 모델 배포. |
| **Google Vertex AI** | Google 서비스 계정 JSON 키, 프로젝트, 모델 위치. |
| **LiteLLM** | 프록시 URL과 가상 키. |
| **OpenAI-compatible endpoint** | 엔드포인트 base URL과, 엔드포인트가 요구하는 경우 API 키. |
| **Claude Code** | Claude Code를 포함하는 플랜의 Claude 계정. 계정 자체를 **Setup token**, **Browser sign-in**, 또는 Linux나 Windows 머신의 `~/.claude/.credentials.json` 업로드로 연결합니다. macOS에서는 Claude Code가 이 파일을 Keychain에 보관하므로 setup token을 대신 사용하세요. |
| **Codex** | Codex를 포함하는 플랜의 ChatGPT 계정. 계정 자체를 **Device code**, **Browser sign-in**, 또는 Codex CLI의 `~/.codex/auth.json` 업로드로 연결합니다. 업로드 후에는 해당 머신에서 Codex에서 로그아웃하세요. 그렇지 않으면 다음 토큰 갱신 시 두 사본이 서로를 무효화합니다. |

엔드포인트 필드, 모델 검색, Azure 배포 이름은 [엔드포인트 공급자 연결](/guide/byok-endpoint-providers)을 참고하세요.

## 키 연결

<Steps>
  <Step title="BYOK 설정 열기">
    Owner라면 **Settings → Organization → BYOK**로 이동합니다. 페이지에는 **This workspace**(현재 있는 워크스페이스)와 **Organization key** 두 섹션이 있습니다.

    워크스페이스 Admin이라면 **Settings → Workspace → BYOK**로 이동하여 **This workspace**를 **Workspace**로 설정합니다.
  </Step>
  <Step title="공급자 선택">
    **Add provider**를 클릭하고 공급자를 선택한 다음 **Next**를 클릭합니다. 키에 선택적으로 **Name**을 지정하고 다시 **Next**를 클릭합니다.
  </Step>
  <Step title="자격 증명 입력">
    **Credentials**를 채웁니다. OpenAI, Azure OpenAI, Vertex AI, LiteLLM 또는 다른 호환 엔드포인트는 [엔드포인트 공급자 필드 표](/guide/byok-endpoint-providers#provider-fields)를 사용하세요.

    **Claude Code**와 **Codex**에는 붙여넣을 자격 증명이 없습니다. **Connect** 단계에서 방법 탭을 고르고 로그인을 완료합니다. 자격 증명이 스스로 연결되므로 **Models** 단계와 **Verify and activate** 버튼이 없습니다. 이후 키 카드 아래의 **What runs on which credential** 표에서 어떤 행을 여기서 실행할지 선택하세요.

    <Tabs>
      <Tab title="Bedrock: IAM role">
        **Sign in with**를 **IAM role**(기본값)로 설정합니다. CloudThinker는 모든 호출에 이 역할을 맡으며 AWS 키를 저장하지 않습니다.

        1. **CloudThinker 신뢰.** AWS IAM에서 양식에 표시된 신뢰 정책으로 역할을 만듭니다. 정책은 아래와 같은 형태이며, 양식이 실제 CloudThinker principal과 이 키의 범위에 고유한 External ID를 채워 주므로 다른 워크스페이스가 아니라 양식에서 복사하세요.

        ```json
        {
          "Version": "2012-10-17",
          "Statement": [
            {
              "Effect": "Allow",
              "Principal": { "AWS": "<CloudThinker principal ARN from the form>" },
              "Action": "sts:AssumeRole",
              "Condition": {
                "StringEquals": { "sts:ExternalId": "<External ID from the form>" }
              }
            }
          ]
        }
        ```

        2. **Bedrock 허용.** 양식에 표시된 권한 정책을 연결합니다. 양식에도 자리 표시자 `111122223333`이 표시되므로 직접 AWS 계정 ID로 바꾸세요.

        ```json
        {
          "Version": "2012-10-17",
          "Statement": [
            {
              "Sid": "CloudThinkerInvokeModels",
              "Effect": "Allow",
              "Action": ["bedrock:InvokeModel*"],
              "Resource": [
                "arn:aws:bedrock:*:111122223333:inference-profile/*",
                "arn:aws:bedrock:*::foundation-model/*",
                "arn:aws:bedrock:::foundation-model/*"
              ]
            },
            {
              "Sid": "CloudThinkerListModels",
              "Effect": "Allow",
              "Action": ["bedrock:ListFoundationModels"],
              "Resource": "*"
            },
            {
              "Sid": "CloudThinkerInvokeMantle",
              "Effect": "Allow",
              "Action": ["bedrock-mantle:CreateInference"],
              "Resource": "arn:aws:bedrock-mantle:*:111122223333:project/*"
            }
          ]
        }
        ```

        두 `foundation-model` 리소스는 Bedrock이 기본 모델에 사용하는 리전 포함 및 미포함 두 가지 ARN 형식을 모두 다룹니다. `CloudThinkerListModels` 문은 CloudThinker가 키로 사용할 수 있는 모델을 나열하여 모델 선택기가 이를 제공할 수 있게 합니다. `bedrock-mantle` 문은 Bedrock에서 OpenAI 모델을 제공하는 Bedrock의 Mantle 추론 API를 다룹니다. 해당 모델을 키에서 사용하려면 유지하세요.

        3. **Role ARN.** 새 역할의 ARN을 붙여넣습니다.
        4. **Region.** **Global (recommended)**을 유지하거나 AWS 리전 하나를 고릅니다. [Bedrock 리전 선택](#bedrock-리전-선택)을 참고하세요.
      </Tab>
      <Tab title="Bedrock: access key">
        **Sign in with**를 **Access key**로 설정합니다. IAM 사용자를 만들고 **IAM role** 탭에 표시된 것과 같은 권한 정책을 연결한 뒤 액세스 키를 만듭니다.

        - **Access key ID**: 영구 키는 `AKIA...`, 임시 키는 `ASIA...`.
        - **Secret access key**: 해당 키의 시크릿.
        - **Session token**: 임시 `ASIA` 키에만 해당.
        - **Region**: **Global (recommended)**을 유지하거나 AWS 리전 하나를 고릅니다.

        IAM 역할을 권장합니다. 키를 꼭 사용해야 한다면 영구 `AKIA` 키를 사용하세요. CloudThinker가 이를 단기 세션 토큰으로 교환하고 갱신합니다. 임시 `ASIA` 키는 갱신할 수 없으며 만료되면 작동을 멈춥니다.
      </Tab>
      <Tab title="Anthropic">
        - **API key**: Anthropic Console 키, `sk-ant-...`.
        - **Base URL**: 키가 게이트웨이를 거치지 않는다면 비워 둡니다. 비워 두면 `https://api.anthropic.com`입니다.
      </Tab>
      <Tab title="FPT Cloud">
        - **API key**: FPT Cloud Marketplace API 키.
        - **Base URL**: 키가 게이트웨이를 거치지 않는다면 비워 둡니다. 비워 두면 `https://mkp-api.fptcloud.com/v1`입니다.
      </Tab>
      <Tab title="BytePlus">
        - **API key**: BytePlus ModelArk API 키.
        - **Base URL**: 키가 게이트웨이를 거치지 않는다면 비워 둡니다. 비워 두면 `https://ark.ap-southeast.bytepluses.com/api/v3`입니다.
      </Tab>
    </Tabs>
  </Step>
  <Step title="모델 선택">
    **Models**에는 작업 종류별로 키가 실행할 모델이 나열됩니다. 기본값을 유지하거나 **Customize models**를 클릭하여 행을 변경하거나 **CloudThinker credits**로 설정하세요. 최소 한 행은 키에서 실행되어야 하며, 그렇지 않으면 버튼이 **Pick a model for at least one row**와 함께 비활성 상태로 남습니다.
  </Step>
  <Step title="확인 및 활성화">
    **Verify and activate**를 클릭합니다. CloudThinker는 선택한 모델마다 짧은 요청 하나(출력 토큰 1개, 공급자가 청구)를 보낸 뒤 키를 저장하고 켭니다.

    **성공 상태:** 키 카드에 **Active**, 키 힌트, 리전(Bedrock), **verified** 시각이 표시됩니다. 채팅에서는 메시지 입력란 옆에 **Your key** 배지가 나타납니다. 직접 확인하려면 AWS CloudTrail에서 해당 역할의 `InvokeModel` 호출을 찾거나 Anthropic Console에서 사용량을 확인하세요.
  </Step>
</Steps>

CloudThinker는 저장된 자격 증명을 암호화하며, 저장된 시크릿을 브라우저로 다시 보내지 않습니다.

## 키에서 실행되는 것

**Models**의 각 행은 하나의 작업 종류입니다. **CloudThinker credits**로 설정한 행은 플랫폼에서 실행되며 평소처럼 청구됩니다.

| 행 | 대상 |
|---|---|
| **Light**, **Pro**, **Ultra** | 해당 모드의 채팅 턴 |
| **Review** | 풀 리퀘스트와 머지 리퀘스트의 [Review](/ko/guide/code-review/overview) |
| **Cyber** | [Cyber](/guide/security/cyber-overview) 테스트 실행, Cyber 채팅, Code Audit |
| **Resolve** | [Resolve](/ko/guide/incident/overview) 근본 원인 분석 |
| **Optimize** | [Optimize](/ko/guide/cost-optimization/overview). 기본값은 **Ultra** 행의 모델입니다. |
| **Background tasks** | 턴 뒤에서 실행되는 보조 작업. 기본값은 **Light** 행의 모델입니다. |

다른 행의 기본값은 현재 CloudThinker 릴리스가 공급자별로 정하므로, 모델이 출시되면 바뀝니다. **Models**는 확인 전에 각 기본값을 보여 주며, 이것이 Bedrock 모델 액세스에서 켜야 할 목록입니다.

모델 목록은 공급자에서 가져옵니다. 엔드포인트 공급자는 내장 카탈로그 밖의 나열된 모델도 실행할 수 있습니다. [엔드포인트 모델 선택](/guide/byok-endpoint-providers#choose-an-endpoint-model)을 참고하세요. 선택기는 공급자가 이 키와 리전에서 제공하는 모델만 보여 줍니다. 저장된 선택에 **Model retired, pick another**가 표시되면 해당 행에 새 모델을 고르세요.

## Bedrock 리전 선택

**Region**은 Bedrock이 요청을 처리할 수 있는 위치를 정합니다. 리전을 고르면 CloudThinker가 그에 맞는 Bedrock 교차 리전 추론 프로필(`us.`, `eu.`, `apac.`, `global.`)을 고릅니다.

| 선택 | 프로필 | Bedrock이 요청을 처리하는 곳 |
|---|---|---|
| **Global (recommended)** | `global.` | 모든 상용 AWS 리전. 모델 선택 폭이 가장 넓습니다. |
| `us-east-1` 같은 미국 또는 캐나다 리전 | `us.` | 미국 리전 |
| `eu-west-1` 같은 EU, 중동 또는 이스라엘 리전 | `eu.` | EU 리전 |
| `ap-southeast-1` 같은 아시아 태평양 리전 | `apac.` | 아시아 태평양 리전 |
| 남아메리카(상파울루) 같은 그 밖의 리전 | `global.` | Global과 동일하게 모든 상용 AWS 리전 |

<Warning>
남아메리카를 고르면 Global로 실행되므로 요청이 남아메리카를 벗어날 수 있습니다. 지역 리전을 고르면 모델 목록이 Bedrock이 해당 지역에서 제공하는 모델로 좁혀집니다. 데이터가 한 지역에 머물러야 한다면 지역 리전을 유지하고, 설정 후 모든 행이 여전히 키에서 실행되는지 확인하세요.
</Warning>

## 조직 키와 워크스페이스 키

**This workspace**는 워크스페이스가 어떤 키로 실행될지 정합니다.

| 선택 | 결과 |
|---|---|
| **Organization** | 턴이 조직 키로 실행됩니다. 조직 키가 활성 상태가 아니면 CloudThinker 크레딧을 씁니다. |
| **Workspace** | 턴이 이 워크스페이스 전용으로 설정된 키로 실행됩니다. |
| **Off** | 조직에 키가 있어도 턴이 CloudThinker 크레딧을 씁니다. |

선택 아래의 줄은 현재 적용 중인 내용을 알려 줍니다. 예: "Turns run on the organization's AWS Bedrock key." 모든 워크스페이스가 조직 키를 쓰도록 강제하려면 Owner가 **Organization key** 아래에서 **Require the organization key in every workspace**를 켭니다. 그러면 워크스페이스 Admin은 자체 키를 추가하거나 BYOK를 끌 수 없습니다.

## 키 관리

| 작업 | 동작 |
|---|---|
| 키 패널에서 새 자격 증명 입력 후 **Check and save** | 자격 증명을 교체합니다. CloudThinker가 새 자격 증명을 확인하고 모델 선택은 유지합니다. |
| 키 패널의 모델 스위치 | 이 키가 공급자의 어떤 모델을 제공할지 선택합니다. 각 모델은 **Offered to members** 또는 **Hidden from the picker** 아래에 있습니다. |
| **Check key** | 저장된 자격 증명을 다시 테스트합니다. |
| 키 행의 스위치 | 키에서의 호출을 중지하거나 다시 시작합니다. 일시 중지된 키는 자격 증명을 유지하며 **Saved, paused**로 표시됩니다. |
| **Remove** | 키를 삭제합니다. 모든 행이 CloudThinker 크레딧으로 돌아갑니다. |

어떤 모델이 실행될지는 서로 다른 두 설정이 정합니다.

| 설정 | 결정하는 것 | 변경 위치 |
|---|---|---|
| 허용된 모델 | 이 키가 공급자의 어떤 모델을 사용할 수 있는지 | 키 패널의 모델 스위치 |
| 행 지정 | 각 행(**Light**, **Review** 등)이 어떤 허용된 모델을 쓰는지 | 키 카드 아래의 **What runs on which credential** 표에서 변경 후 **Save**. 설정 중에는 **Models**의 **Customize models**가 같은 선택입니다. |

## 키가 작동을 멈출 때

키로 한 호출이 실패하면 CloudThinker는 작업이 끝나도록 플랫폼 모델로 대체합니다. 그 호출은 CloudThinker 크레딧을 씁니다. 공급자가 속도 제한한 호출도 포함되므로, 워크로드에 비해 Bedrock 할당량이 낮다면 AWS Service Quotas에서 할당량을 올려 턴이 키에서 실행되도록 하세요.

공급자가 자격 증명을 거부하면(토큰 만료, 키 폐기, 액세스 거부) CloudThinker는 키를 끕니다.

- 키 카드에 공급자의 오류 코드와 함께 **Disabled after error** 또는 **Key expired**가 표시됩니다.
- 호출이 실패한 워크스페이스로 **BYOK Credentials Error**라는 제목의 높은 심각도 [알림](/ko/guide/notifications)이 전송되며, 공급자와 오류 코드가 명시됩니다.
- 키를 고칠 때까지 턴은 CloudThinker 크레딧으로 계속 실행됩니다.

복구하려면 키를 열고 작동하는 자격 증명을 입력한 뒤 **Check and save**를 클릭하세요.

## 문제 해결

<AccordionGroup>
  <Accordion title="Verification failed">
    빨간색 **Verification failed** 상자에 공급자의 오류 텍스트가 그대로 표시됩니다.

    - **Bedrock 액세스 거부:** 역할 또는 사용자에게 **Allow Bedrock** 정책이 있는지, 신뢰 정책이 이 양식의 External ID를 사용하는지 확인하세요.
    - **모델을 사용할 수 없음:** Bedrock 콘솔에서 해당 모델의 모델 액세스를 켜거나, 해당 행에 다른 모델을 고르세요.
    - **한 행을 처리할 수 없음:** 해당 행을 **CloudThinker credits**로 설정하고 다시 확인하세요.
  </Accordion>
  <Accordion title="리전을 고른 뒤에만 액세스가 거부됩니다">
    Bedrock은 모든 지역에서 모든 모델을 제공하지 않습니다. **Region**을 **Global (recommended)**으로 바꾸거나 해당 지역에서 제공하는 모델을 고르세요.
  </Accordion>
  <Accordion title="키가 계속 스스로 꺼집니다">
    임시 `ASIA` 액세스 키는 만료되며 갱신할 수 없습니다. IAM 역할이나 영구 `AKIA` 키로 교체하세요.
  </Accordion>
  <Accordion title="채팅에 Your key 배지가 없습니다">
    - 키 카드가 **Saved, paused**가 아니라 **Active**로 표시되어야 합니다.
    - 워크스페이스의 **This workspace** 선택이 **Off**가 아니어야 합니다.
    - **Organization**을 선택했다면 조직 키 자체가 활성 상태여야 합니다.
  </Accordion>
  <Accordion title="워크스페이스 설정을 변경할 수 없습니다">
    워크스페이스 Admin이 아니거나, Owner가 **Require the organization key in every workspace**를 켰습니다. 페이지에 어느 쪽인지 표시됩니다.
  </Accordion>
</AccordionGroup>

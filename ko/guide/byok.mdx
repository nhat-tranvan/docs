자체 키 사용(BYOK)은 에이전트 응답 뒤의 AI 모델 호출을 플랫폼 크레딧 대신 자체 AWS Bedrock 또는 Anthropic 자격 증명으로 실행합니다. 조직 Owner가 **Admin Settings → BYOK**에서 한 번 설정하면 조직의 모든 워크스페이스가 이 키를 사용합니다.

## BYOK를 사용하는 이유

- **자체 비용.** 키로 실행한 모델 호출은 CloudThinker 크레딧이 아닌 AWS 또는 Anthropic 계정에 청구됩니다.
- **자체 할당량.** 플랫폼 크레딧 한도가 아닌 제공업체의 한도가 적용됩니다.
- **모델 선택.** 모드와 모듈마다 Claude 모델을 선택하거나 기본값을 유지합니다.
- **Bedrock 데이터 레지던시.** AWS 리전을 선택해 추론을 미국, EU 또는 아시아 태평양 안에 유지합니다.

## 사전 요구 사항

- Scale, Scale+ 또는 Enterprise 플랜. [가격 및 플랜](/ko/guide/billing/pricing)을 참조하세요.
- 조직의 Owner 역할. Admin과 다른 멤버는 키 상태를 볼 수 있지만 자격 증명은 볼 수 없습니다.
- 다음 자격 증명 중 하나:
  - Bedrock 호출 권한이 있는 AWS IAM 액세스 키. 아래 **AWS Bedrock 준비** 섹션을 참조하세요.
  - `sk-ant`로 시작하는 Anthropic Console API 키.

## 지원 모델

키로 다음 Claude 모델을 실행합니다. CloudThinker가 각 행의 기본값을 정하며, 직접 바꿀 수 있습니다.

| 모델 | Bedrock 모델 ID | Anthropic 모델 ID | 기본값 대상 |
|---|---|---|---|
| Claude Opus 5 | `anthropic.claude-opus-5` | `claude-opus-5` | Ultra, Review, Cyber |
| Claude Sonnet 5 | `anthropic.claude-sonnet-5` | `claude-sonnet-5` | Pro, Resolve |
| Claude Haiku 4.5 | `anthropic.claude-haiku-4-5-20251001-v1:0` | `claude-haiku-4-5-20251001` | Light |

모델은 여섯 행에서 선택합니다. **Light**, **Pro**, **Ultra** 채팅 모드와 **Review**, **Cyber**, **Resolve** 모듈입니다. Review conventions는 **Review** 행을, Cyber chat은 **Cyber** 행을 따릅니다. **CloudThinker credits**로 설정한 행은 키 대신 플랫폼에서 실행됩니다.

## AWS Bedrock 준비

Anthropic API 키를 사용한다면 이 섹션을 건너뛰세요.

<Steps>
  <Step title="Bedrock에서 Anthropic 모델 활성화">
    AWS Console에서 [Amazon Bedrock](https://console.aws.amazon.com/bedrock/)을 엽니다. Bedrock이 Anthropic 사용 사례 양식을 요청하면 AWS 계정당 한 번 제출하세요. [AWS 모델 액세스 문서](https://docs.aws.amazon.com/bedrock/latest/userguide/model-access.html)를 참조하세요.
  </Step>
  <Step title="IAM 사용자와 정책 생성">
    사용자를 만들고 Bedrock이 Claude 모델을 호출할 수 있게 하는 정책을 연결합니다.

    ```bash
    aws iam create-user --user-name bedrock-byok-user

    cat > bedrock-policy.json << 'EOF'
    {
      "Version": "2012-10-17",
      "Statement": [
        {
          "Effect": "Allow",
          "Action": [
            "bedrock:InvokeModel",
            "bedrock:InvokeModelWithResponseStream"
          ],
          "Resource": [
            "arn:aws:bedrock:*::foundation-model/anthropic.claude-*",
            "arn:aws:bedrock:*:*:inference-profile/*.anthropic.claude-*"
          ]
        },
        {
          "Effect": "Allow",
          "Action": ["sts:GetSessionToken"],
          "Resource": "*"
        }
      ]
    }
    EOF

    aws iam put-user-policy \
      --user-name bedrock-byok-user \
      --policy-name BedrockInvokePolicy \
      --policy-document file://bedrock-policy.json
    ```

    이 명령에는 `iam:CreateUser`와 `iam:PutUserPolicy` 권한이 있는 AWS 프로필이 필요합니다.
  </Step>
  <Step title="액세스 키 생성">
    ```bash
    aws iam create-access-key --user-name bedrock-byok-user
    ```

    출력의 `AccessKeyId`와 `SecretAccessKey`를 저장하세요. CloudThinker에 입력합니다.
  </Step>
</Steps>

<Tip>
`anthropic.claude-*` 와일드카드는 CloudThinker가 나중에 추가하는 모델도 포함합니다. 더 엄격한 정책이 필요하면 지원 모델 표의 모델 ID를 하나씩 나열하세요. `us.anthropic.claude-opus-5`처럼 각 추론 프로필도 추가하세요.
</Tip>

## 키 연결

<Steps>
  <Step title="BYOK 설정 열기">
    **Admin Settings → BYOK**로 이동합니다.
  </Step>
  <Step title="제공업체 선택">
    **Step 1 Provider**에서 **AWS Bedrock** 또는 **Anthropic**을 선택합니다.
  </Step>
  <Step title="자격 증명 입력">
    **Step 2 Credentials**를 채웁니다.

    <Tabs>
      <Tab title="AWS Bedrock">
        - **Access key ID**: 영구 키는 `AKIA`, 임시 키는 `ASIA`로 시작합니다.
        - **Secret access key**: 해당 키의 시크릿입니다.
        - **Session token**: 임시 `ASIA` 키에만 필요합니다.
        - **Region**: **Global (recommended)**을 유지하거나 AWS 리전 하나를 선택합니다. 아래 **Bedrock 리전 선택** 섹션을 참조하세요.
      </Tab>
      <Tab title="Anthropic">
        - **API key**: `sk-ant`로 시작하는 Anthropic Console 키입니다.
        - **Base URL**: 키가 게이트웨이를 거칠 때만 설정합니다. 공개 URL이어야 합니다.
      </Tab>
    </Tabs>
  </Step>
  <Step title="모델 검토">
    **Step 3 Models on your key**에 각 행의 모델이 표시됩니다. **Customize models**를 클릭해 행을 바꾸거나 **CloudThinker credits**로 설정합니다. 적어도 한 행은 키로 실행되어야 합니다.
  </Step>
  <Step title="검증 및 활성화">
    **Verify and activate**를 클릭합니다. CloudThinker가 선택한 각 모델에 짧은 테스트 호출을 보낸 뒤 키를 저장합니다.

    **성공 상태:** 키 카드에 **Active**, 키 힌트, 리전, 각 행의 모델이 표시됩니다.
  </Step>
</Steps>

CloudThinker는 자격 증명을 저장 시 암호화합니다. 브라우저는 저장된 시크릿을 다시 받지 않습니다.

## Bedrock 리전 선택

선택한 **Region**이 Bedrock 추론 프로필을 정합니다. Bedrock은 해당 프로필 안의 어느 AWS 리전에서든 요청을 처리할 수 있습니다.

| 선택한 리전 | 추론 프로필 | Bedrock이 요청을 처리하는 곳 |
|---|---|---|
| **Global (recommended)** | `global.` | 모든 상용 AWS 리전 |
| 미국 또는 캐나다 리전 (예: `us-east-1`) | `us.` | 미국 리전 |
| EU 리전 (예: `eu-west-1`) | `eu.` | EU 리전 |
| 아시아 태평양 리전 (예: `ap-southeast-1`) | `apac.` | 아시아 태평양 리전 |
| South America (Sao Paulo) | `global.` | 모든 상용 AWS 리전 |

데이터가 한 지역 안에 있어야 한다면 지역 리전을 선택하세요. Sao Paulo에는 지역 프로필이 없으므로 Global 프로필을 사용합니다.

## 키 관리

키 카드에는 제공업체, 상태, 키 힌트, 리전, 마지막 검증 시간이 표시됩니다.

| 작업 | 설명 |
|---|---|
| **Rotate key** | 자격 증명을 교체합니다. CloudThinker가 새 키를 검증하고, 모델 선택을 유지하며, 키를 활성화합니다. |
| **Edit models** | 각 행의 모델을 바꾼 뒤 **Verify and save**를 클릭합니다. |
| **Re-verify** | 저장된 키를 다시 테스트합니다. |
| **Pause** / **Activate** | 키로 실행하는 모델 호출을 중지하거나 다시 시작합니다. 일시 중지한 키도 자격 증명을 유지합니다. |
| **Remove** | 키를 삭제합니다. 모든 턴이 CloudThinker 크레딧으로 돌아갑니다. |

카드에는 **Active**, **Saved, paused**, **Key expired**, **Disabled after error** 중 하나의 상태가 표시됩니다. 한 번에 하나의 제공업체만 활성화됩니다. 제공업체를 바꾸려면 키를 삭제하고 다른 제공업체를 연결하세요.

## 작동 방식

- **조직당 하나의 키.** 모든 워크스페이스와 멤버가 Owner의 키를 사용합니다.
- **"Your key" 배지.** 채팅에서 **Your key** 배지는 키로 실행되어 크레딧을 쓰지 않는 턴을 표시합니다.
- **세션 토큰.** 영구 `AKIA` 키는 CloudThinker가 세션 토큰을 자동으로 갱신합니다. 임시 `ASIA` 키는 갱신할 수 없으므로 만료 전에 교체하세요.
- **폴백.** 키로 실행한 호출이 재시도 후에도 실패하면 CloudThinker가 플랫폼 자격 증명으로 플랫폼 모델에서 호출을 실행합니다. 폴백 호출은 플랫폼 크레딧을 사용합니다.
- **각 호출이 보내는 내용.** 호출은 에이전트의 시스템 프롬프트, 도구 정의, 대화 기록, 검색된 컨텍스트를 보냅니다. CloudThinker는 먼저 알려진 시크릿과 감지된 개인 식별 정보를 플레이스홀더로 바꿉니다.

## 자격 증명 오류 시 자동 비활성화

제공업체가 자격 증명을 거부하면 CloudThinker가 BYOK를 끕니다. 만료된 세션 토큰, 취소된 액세스 키, access denied 오류가 그 예입니다. 키를 복구할 때까지 에이전트 작업은 플랫폼 크레딧으로 계속됩니다.

**BYOK Credentials Error — AWS Bedrock Auto-Disabled** 또는 **BYOK Credentials Error — Anthropic Auto-Disabled**라는 높은 심각도의 [알림](/ko/guide/notifications)을 한 번 받습니다. 알림에는 제공업체 오류 코드가 있습니다. 키 카드에는 **Disabled after error**와 같은 코드가 표시됩니다. BYOK를 복구하려면 **Rotate key**를 클릭하고 유효한 자격 증명을 입력한 뒤 **Verify and save**를 클릭하세요.

## 문제 해결

<AccordionGroup>
  <Accordion title="검증 실패">
    - 버튼 아래의 오류를 읽으세요. 제공업체의 메시지와 실패한 모델이 표시됩니다.
    - Bedrock이라면 AWS 계정의 Anthropic 사용 사례 양식이 승인되었는지 확인하세요.
    - IAM 정책이 모델과 선택한 리전의 추론 프로필을 포함하는지 확인하세요.
    - 처리할 수 없는 행을 **CloudThinker credits**로 설정한 뒤 다시 검증하세요.
  </Accordion>

  <Accordion title="특정 리전에서 access denied">
    - 지역 리전은 `us.`, `eu.`, `apac.` 추론 프로필을 사용합니다.
    - IAM 정책이 `inference-profile/*.anthropic.claude-*` 또는 해당 프로필 이름을 허용하는지 확인하세요.
    - Bedrock이 그 지역에서 모델을 제공하는지 확인하거나, **Region**을 **Global (recommended)**로 바꾸세요.
  </Accordion>

  <Accordion title="행에 Model retired, pick another가 표시됨">
    - CloudThinker가 더 이상 키에서 해당 모델을 제공하지 않습니다.
    - **Edit models**를 클릭하고 행에 다른 모델을 선택한 뒤 **Verify and save**를 클릭하세요.
  </Accordion>

  <Accordion title="BYOK가 스스로 꺼짐">
    - 제공업체가 자격 증명을 거부했습니다. 위의 자동 비활성화 섹션을 참조하세요.
    - 키 카드나 알림의 오류 코드를 읽으세요.
    - **Rotate key**를 클릭하고 유효한 자격 증명을 입력하세요.
    - 임시 `ASIA` 키는 만료됩니다. 반복을 막으려면 영구 `AKIA` 키로 바꾸세요.
  </Accordion>

  <Accordion title="턴에 Your key 배지가 없음">
    - 키 카드가 **Saved, paused**가 아닌 **Active**인지 확인하세요.
    - 조직이 Scale, Scale+ 또는 Enterprise 플랜인지 확인하세요.
    - 모드나 모듈 행이 **CloudThinker credits**가 아닌 키로 실행되는지 확인하세요.
  </Accordion>
</AccordionGroup>

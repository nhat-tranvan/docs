조직은 CloudThinker의 최상위 계정입니다. 청구와 멤버 목록을 소유하며, 실제 작업이 이루어지는 하나 이상의 [워크스페이스](/ko/guide/workspaces)를 포함합니다.

## 사전 요구사항

- 이 페이지의 대부분의 작업에는 조직 **Owner** 또는 **Admin**이 필요합니다. Developer와 Viewer는 override로 워크스페이스의 Admin이더라도 **Settings → Organization**을 열 수 없습니다. 그런 워크스페이스 Admin이 그곳에서 열 수 있는 유일한 페이지는 직접 링크로 여는 **Guardrails**입니다. 워크스페이스 Admin은 자체 BYOK 키를 포함해 **Settings → Workspace**에서 해당 워크스페이스를 관리합니다.
- Owner를 제외한 누구나 [조직을 나갈](#조직-나가기) 수 있습니다.

## 조직과 워크스페이스의 관계

가입하면 CloudThinker가 이름을 딴 조직(예: "Jane's Organization")을 만들고 사용자를 Owner로 지정합니다. 그런 다음 온보딩에서 그 안에 첫 워크스페이스를 만듭니다.

| 조직에 있는 것 | 각 워크스페이스에 있는 것 |
|---|---|
| 요금제와 청구 | [Connections](/ko/guide/connections/overview)와 [credentials](/guide/credentials) |
| 멤버 목록과 조직 역할 | [Custom agents](/ko/guide/agents/customize), [skills](/ko/guide/skills/overview), [memory](/guide/memory) |
| [BYOK](/ko/guide/byok), [SSO 및 프로비저닝](/ko/guide/security/sso), [audit logs](/guide/security/audit-logs) | 대화, artifact, 모듈 데이터(Optimize, Review, Cyber, Resolve) |
| [Usage](/ko/guide/billing/usage)와 [credit limits](/guide/billing/credit-limits)(여기서 설정, 워크스페이스마다 상한 하나) | [Approvals](/guide/approvals/overview), [notifications](/ko/guide/notifications), 워크스페이스 멤버 |

Approvals는 각 워크스페이스 안에서 구성합니다. Credit limits는 Owner 또는 Admin이 **Settings → Organization → Billing**에서 워크스페이스마다 상한 하나씩 설정합니다. 한쪽에 더 엄격한 승인이나 더 빠듯한 예산이 필요하다면 프로덕션과 비프로덕션을 별도의 워크스페이스로 나누세요. [choose a layout](/ko/guide/workspaces#구성-방식-선택)을 참고하세요.

## 조직 설정 열기

조직 제어는 **Settings → Organization**에 있으며, 한 번에 워크스페이스 하나를 다루는 **Settings → Workspace**와는 별개입니다.

<Steps>
  <Step title="Settings 열기">
    사이드바 상단의 워크스페이스 메뉴를 클릭한 뒤 **Settings**를 클릭합니다. ⌘,(Windows와 Linux에서는 Ctrl+,)를 눌러도 됩니다.
  </Step>
  <Step title="Organization 탭 선택">
    Settings 상단에서 **Organization**을 클릭합니다.

    **성공 상태:** 측면 목록에 **General**, **Workspaces**, **Members**로 시작하는 조직 페이지가 표시됩니다.
  </Step>
</Steps>

[Organization settings](/guide/admin-settings)에 그곳의 모든 페이지, 각 페이지가 설정하는 것, 각각의 가이드가 나와 있습니다. 보이는 페이지는 조직 역할과 조직에서 활성화된 기능에 따라 다르며, [아래 역할 표](#조직-역할)에서 각 역할이 변경할 수 있는 것을 확인할 수 있습니다. 워크스페이스를 삭제할 수 있는 곳은 **Workspaces**뿐입니다.

## 멤버 초대

<Steps>
  <Step title="Members 열기">
    **Settings → Organization → Members**로 이동해 **Invite people**을 클릭합니다.
  </Step>
  <Step title="이메일 주소 추가">
    **Enter an email**에 주소를 입력하고 Enter를 눌러 추가합니다. 이번 일괄 초대에 필요한 만큼 추가하세요.
  </Step>
  <Step title="역할 선택">
    역할 메뉴에서 **Admin**, **Developer**, **Viewer** 중 하나를 고릅니다. 기본값은 Developer입니다. Owner로는 초대할 수 없습니다.

    한 일괄 초대의 모든 주소에는 하나의 역할이 적용됩니다. 서로 다른 역할로 초대하려면 별도로 일괄 초대를 보내세요.
  </Step>
  <Step title="보내기">
    **Invite**를 클릭합니다.

    **성공 상태:** 각 초대 대상이 멤버 목록 맨 위에 **Invited**와 만료일과 함께 나타나고, 초대 이메일을 받습니다. 초대는 7일 후 만료됩니다.
  </Step>
</Steps>

초대하면서 Developer와 Viewer의 워크스페이스를 고르려면 대신 사이드바 상단 워크스페이스 메뉴의 **Invite members**를 사용하세요. 그 대화 상자에는 **Select workspaces**가 있습니다. Admin은 모든 워크스페이스를 자동으로 받으므로 필요하지 않습니다.

<Warning>
워크스페이스를 선택하지 않고 Developer나 Viewer를 초대하면, 조직에는 가입하지만 접근 권한을 부여할 때까지 어떤 워크스페이스도 열 수 없습니다. [워크스페이스 멤버](/ko/guide/workspace-users)를 참고하세요.
</Warning>

**초대받은 사람이 할 일:** 이메일의 링크를 열고, 초대된 주소로 로그인하거나 가입합니다. 다른 주소는 거부됩니다. 이미 다른 조직에 속한 사람은 그 조직을 유지하며, 두 조직 모두 워크스페이스 메뉴에 표시됩니다.

## 조직 역할

모든 멤버는 조직 역할 하나를 가집니다. 조직 **Owner**는 가장 높은 역할이며 조직의 비용을 지불합니다. 조직 **Admin**은 [Roles](/guide/security/roles#organization-permissions)의 Owner 전용 행을 제외한 조직의 모든 것을 설정할 수 있습니다. Owner와 Admin은 모든 워크스페이스에서 Admin입니다. Developer와 Viewer는 조직 이름과 배정된 워크스페이스를 봅니다. 조직 멤버 목록은 보지 못하며, 각 워크스페이스의 **Members** 페이지에서 해당 워크스페이스의 멤버만 봅니다.

| 권한 | Owner | Admin | Developer | Viewer |
|---|:---:|:---:|:---:|:---:|
| 조직 이름과 설명 편집 | ✓ | ✓ | | |
| 멤버 초대 및 제거, 역할 변경 | ✓ | ✓† | | |
| 워크스페이스 생성 및 삭제 | ✓ | ✓ | | |
| 모든 워크스페이스에 대한 Admin 접근 | ✓ | ✓ | | |
| 사용량 보기, credit limits 설정 | ✓ | ✓ | | |
| 요금제와 청구 관리 | ✓ | | | |
| BYOK와 SSO 구성 | ✓ | | | |
| 모든 워크스페이스의 [capabilities](/guide/capabilities) 변경 | ✓ | | | |
| 소유권 이전 요청 | ✓ | | | |
| 배정된 워크스페이스에서 작업 | ✓ | ✓ | ✓ | 보기만* |

\*Viewer는 대화, 발견 항목, 대시보드를 열 수 있지만 에이전트와 채팅하거나, 스킬을 실행하거나, 무엇이든 변경할 수는 없습니다.

†Admin은 Developer와 Viewer의 역할만 변경하고 제거할 수 있습니다. Admin은 새 멤버를 Admin으로 초대할 수 있지만, 기존 멤버를 Admin으로 승격하거나, Admin의 역할을 바꾸거나, Admin을 제거하는 것은 Owner만 할 수 있습니다.

SSO just-in-time 로그인이나 SCIM으로 추가된 사람은 연결에 설정한 **Auto-assigned organization role**(기본값 Viewer)을 받습니다. SCIM에서는 IdP 그룹별로 역할을 설정할 수도 있습니다. [SSO](/ko/guide/security/sso)와 [SCIM group mapping](/ko/guide/security/scim#그룹을-워크스페이스에-매핑)을 참고하세요.

단일 워크스페이스 안에서 Developer나 Viewer의 역할을 올리거나 낮출 수 있습니다. [workspace roles](/ko/guide/workspace-users#워크스페이스-역할)를 참고하세요. "Member"는 레거시 역할 이름이며 Developer처럼 동작합니다.

## 멤버와 초대 관리

조직 이름은 **Settings → Organization → General**에서 바꿉니다. **Organization name** 옆의 **Edit**를 클릭하고 **Organization Name**(필요하면 **Description**도)을 변경한 뒤 **Save Changes**를 클릭합니다. 나머지는 모두 **Settings → Organization → Members**에 있으며, 각 사람은 작업 메뉴(**...**)가 있는 한 행입니다.

| 작업 | 방법 |
|---|---|
| 멤버의 역할 변경 | 해당 행의 역할 메뉴에서 새 값을 고릅니다 |
| Developer나 Viewer가 열 수 있는 워크스페이스 변경 | 행의 작업 메뉴에서 **Edit workspace access**를 클릭합니다 |
| 멤버 제거 | 행의 작업 메뉴에서 **Remove**를 클릭하고 확인합니다. 조직의 모든 워크스페이스에 대한 접근을 잃습니다 |
| 멤버 활성화 | **Inactive**로 표시된 행의 작업 메뉴에서 **Activate member**를 클릭합니다 |
| 초대 재전송 또는 취소 | 초대 행의 작업 메뉴를 열고 **Resend invitation** 또는 **Revoke invitation**을 클릭합니다 |

이전 좌석당 구독에서는 조직에 남은 좌석이 없을 때 (예: SSO를 통해) 프로비저닝된 멤버가 **Inactive**로 표시됩니다. Inactive 멤버는 좌석을 사용하지 않습니다. 활성화하면 좌석 하나를 사용합니다.

### 멤버를 제거하면 일어나는 일

| 항목 | 일어나는 일 |
|---|---|
| 워크스페이스 접근 | 조직의 모든 워크스페이스에서 제거됩니다. 해당 이메일로 보낸 대기 중인 워크스페이스 초대는 취소됩니다 |
| 소유한 [Automations](/guide/automation/automations) | 꺼집니다. 각각에 "Its owner no longer has access to this workspace."가 표시됩니다. 워크스페이스 Admin이 **Take ownership**을 클릭한 뒤 다시 켭니다. 그 후에는 새 소유자로, 새 소유자의 접근 권한으로 실행됩니다 |
| Approvals | 모든 승인자 그룹에서 빠지므로, 대기 중인 요청은 남은 승인자에게 갑니다 |
| 만든 워크스페이스 | 안의 모든 것과 함께 조직에 남습니다. Owner와 Admin은 접근 권한을 유지합니다 |
| 좌석(이전 좌석당 구독) | 해제됩니다 |

<Warning>
예약된 Automations를 소유한 사람을 제거하기 전에 누가 이를 넘겨받을지 정하세요. 그렇지 않으면 워크스페이스 Admin이 소유권을 가져갈 때까지 해당 실행이 조용히 멈춥니다.
</Warning>

## 좌석

Team, Scale, Enterprise에는 무제한 멤버가 포함됩니다. 멤버를 추가해도 요금제 가격이나 월간 크레딧이 늘지 않습니다. Team에는 워크스페이스 3개, Scale에는 10개가 포함됩니다. [요금제 및 가격](/ko/guide/billing/pricing)을 참고하세요.

<Note>
  좌석 관리는 좌석당 청구되는 이전 구독에만 적용됩니다. 그런 구독에서는 활성 멤버와 대기 중인 초대가 좌석을 차지합니다. 초대는 7일 후 만료됩니다. Owner는 **Settings → Organization → General**의 **Seats → Manage**에서 좌석을 관리합니다. 새 유료 요금제에서는 좌석을 구매할 필요가 없습니다.
</Note>

## 지출 관리

크레딧은 조직 수준에서 공유되며, **Settings → Organization → Billing**의 **Credit limits** 섹션에서 각 워크스페이스의 몫에 상한을 둡니다. 이 섹션은 조직에서 credit limits가 활성화된 경우에만 표시됩니다.

| 설정 | 동작 |
|---|---|
| **Default monthly limit per workspace** | 자체 override가 없는 모든 워크스페이스의 크레딧 상한, 또는 **Unlimited** |
| **Per-workspace limits** | 워크스페이스 하나에 대한 다른 상한이나 적용 모드 |
| **When a workspace hits its monthly limit** | **Throttle**은 해당 워크스페이스의 유료 크레딧 사용을 멈춥니다. Light 모델 채팅은 매일 무료 100크레딧으로 계속됩니다. [usage](/ko/guide/billing/usage)를 참고하세요. **Notify only**는 아무것도 막지 않습니다 |
| **Alert the owner at 80%** 및 **Alert the owner at 100%** | 두 개의 스위치로, 둘 중 하나 또는 둘 다 켤 수 있습니다. 알림은 Owner에게만 앱 내와 이메일로 갑니다 |

<Warning>
**Throttle**에서는 한도에 도달한 워크스페이스가 인시던트 중이든 아니든 유료 크레딧으로 에이전트를 실행하지 않습니다. 프로덕션은 **Notify only**로 두거나 높은 상한을 주고, **Throttle**은 샌드박스에 사용하세요.
</Warning>

사용량은 **Settings → Organization → Usage**에서 추적합니다. [credit limits](/guide/billing/credit-limits)와 [usage](/ko/guide/billing/usage)를 참고하세요.

## 소유권 이전

각 조직에는 Owner가 한 명 있습니다. 앱에는 이전 버튼이 없습니다. 소유권을 옮기려면 현재 Owner가 조직 이름과 새 Owner의 이메일을 적어 [support@cloudthinker.io](mailto:support@cloudthinker.io)로 이메일을 보내야 합니다.

- 새 Owner는 이미 조직의 활성 멤버여야 합니다.
- 이전 Owner는 Admin이 됩니다.

<Tip>
Owner가 회사를 떠나기 전, 아직 이메일을 보낼 수 있을 때 이전을 요청하세요.
</Tip>

## 조직 나가기

Admin, Developer, Viewer는 나갈 수 있습니다. 사이드바 상단의 워크스페이스 메뉴를 클릭하고, 조직의 워크스페이스 아래에 있는 **Leave organization**을 클릭한 뒤 확인합니다.

나가는 것은 제거되는 것과 같은 효과가 있습니다. [멤버를 제거하면 일어나는 일](#멤버를-제거하면-일어나는-일)을 참고하세요.

Owner는 나갈 수 없습니다. 먼저 [소유권을 이전](#소유권-이전)하세요. SCIM으로 프로비저닝된 멤버는 대신 ID 공급자에서 제거됩니다.

## 문제 해결

<AccordionGroup>
  <Accordion title="Settings → Organization에 Organization admin access required가 표시됨">
    **원인:** 조직 역할이 Developer 또는 Viewer입니다. override로 워크스페이스의 Admin이 되어도 조직 설정은 열리지 않습니다.

    **해결:** 조직 Owner나 Admin에게 역할 변경을 요청하세요. 워크스페이스 BYOK 키 같은 워크스페이스 설정은 대신 **Settings → Workspace**를 사용하세요.
  </Accordion>
  <Accordion title="초대 버튼에 Seats full이 표시됨">
    **원인:** 이전 좌석당 구독에서 활성 멤버와 대기 중인 초대가 모든 좌석을 사용했습니다. 새 유료 요금제에는 무제한 멤버가 포함됩니다.

    **해결:** 아무도 수락하지 않을 초대를 취소하거나, 떠난 멤버를 제거하거나, Owner에게 **Settings → Organization → General**의 **Seats → Manage**에서 좌석을 추가해 달라고 요청하세요.
  </Accordion>
  <Accordion title="멤버를 제거할 수 없음">
    **원인:** 다음 규칙 중 하나가 적용됩니다.

    - Admin은 다른 Admin이나 Owner를 제거할 수 없습니다.
    - 조직 Owner는 제거할 수 없습니다.
    - SCIM으로 프로비저닝된 멤버는 ID 공급자에서 제거해야 합니다. 오류 메시지는 "This member was provisioned via SCIM."입니다.

    **해결:** Owner에게 요청하거나, ID 공급자에서 사용자를 디프로비저닝하세요. [SCIM](/ko/guide/security/scim)을 참고하세요.
  </Accordion>
  <Accordion title="새 팀원이 로그인했지만 워크스페이스가 보이지 않음">
    **원인:** 워크스페이스가 배정되지 않은 Developer 또는 Viewer입니다.

    **해결:** **Settings → Organization → Members**로 이동해 해당 행의 작업 메뉴에서 **Edit workspace access**를 클릭하고, 워크스페이스를 선택한 뒤 **Save Changes**를 클릭하세요.
  </Accordion>
</AccordionGroup>

이 튜토리얼을 마치면 라이브 환경에서 역할별 프롬프트 하나를 실행하고 후속 질문으로 정제할 수 있습니다. **약 10분**을 허용하세요.

<Info>
**필요한 것:** 연결이 하나 이상 있는 워크스페이스 — 연결 없이는 CloudThinker가 실제 결과를 반환할 수 없습니다. 아직 설정하지 않았다면 [빠른 시작](/ko/quickstart)을 먼저 완료하세요.
</Info>

## 문법

<PromptSyntaxBasics />

<Steps>
  <Step title="채팅 열기">
    [app.cloudthinker.io](https://app.cloudthinker.io)에 로그인하고 왼쪽 사이드바에서 **New chat**을 클릭하세요.

    **성공 기준:** 빈 대화가 열립니다. 요청을 자연어로 입력하세요 — 멘션 없이도 CloudThinker가 답변합니다.
  </Step>

  <Step title="역할별 빠른 성과 실행">
    역할에 맞는 탭을 선택하고, 빠른 성과 프롬프트를 붙여넣은 후, 출력 형태를 확인한 뒤 후속 질문을 시도해보세요.

    <Tabs>
      <Tab title="SRE / On-call">
        **목표:** 알림에서 근본 원인까지의 시간을 단축하세요. 원시 로그가 아닌 구조화된 조사를 받으세요.

        **필요한 것:** [Pulse](/ko/guide/pulse/overview) 구성, 운영하는 시스템의 연결.

        **빠른 성과 — 활성 알림 조사:**

        ```text
        Investigate the current incident: pull related metrics, recent deploys, and topology, then propose the top 3 likely causes ranked by evidence
        ```

        CloudThinker가 작업을 [서브에이전트](/ko/guide/agents/overview#서브에이전트)로 나누어 증거를 병렬로 수집하고, 각 원인의 근거와 함께 가능성 높은 원인을 순위별로 반환합니다.

        **후속 질문:**

        ```text
        Draft a postmortem from this conversation
        Pull the matching runbook and walk me through the approval steps
        Check whether this pattern matches any past incident in memory
        ```
      </Tab>

      <Tab title="DevOps / Platform">
        **목표:** 사용하지 않는 클라우드 비용을 줄이세요. 1분 이내에 낭비가 어디에 있는지 파악하세요.

        **필요한 것:** [AWS](/ko/guide/connections/aws), [Azure](/ko/guide/connections/azure), 또는 [GCP](/ko/guide/connections/gcp) 연결.

        **빠른 성과 — 유휴 및 과잉 프로비저닝 리소스 찾기:**

        ```text
        Find EC2 instances with <20% CPU utilization over the last 30 days, plus any unattached EBS volumes and unused Elastic IPs
        ```

        CloudThinker가 클라우드 API를 조회하고 사용률 메트릭과 결합하여 예상 월간 절감액과 함께 순위별 목록을 반환합니다.

        **후속 질문:**

        ```text
        Right-sizing for the top 5 by waste
        Cost trend by service for this quarter
        Draft a reserved-instance plan for the stable workloads above
        ```
      </Tab>

      <Tab title="Security">
        **목표:** 감사자나 공격자보다 먼저 가장 위험한 잘못된 구성을 찾으세요.

        **필요한 것:** AWS, Azure, 또는 GCP 연결.

        **빠른 성과 — 민감한 포트의 공개 노출 탐지:**

        ```text
        List security groups with 0.0.0.0/0 access on database, SSH, or RDP ports across all regions
        ```

        CloudThinker가 문제가 있는 규칙을 리소스 소유자, 리전, 심각도 순위와 함께 반환합니다.

        **후속 질문:**

        ```text
        SOC 2 compliance status with prioritized remediation
        Audit IAM policies for privilege-escalation paths
        Check for IMDSv1 instances or unencrypted EBS volumes
        ```
      </Tab>

      <Tab title="Database">
        **목표:** 느리다고 생각하는 쿼리가 아닌 실제로 문제를 일으키는 쿼리를 찾으세요.

        **필요한 것:** [PostgreSQL](/ko/guide/connections/postgresql) 또는 [MySQL](/ko/guide/connections/mysql) 연결.

        **빠른 성과 — 최근 24시간의 가장 느린 쿼리:**

        ```text
        Show the top 10 queries by total time over the last 24 hours on production PostgreSQL, with execution count and P95 latency
        ```

        CloudThinker가 `pg_stat_statements`(또는 동등한 소스)에서 데이터를 가져와 영향도 순으로 정렬하고 비용이 집중된 곳을 표시합니다.

        **후속 질문:**

        ```text
        Suggest indexes for the top 3 queries above
        Explain why query #2 isn't using the existing index
        Query latency P95 trends by endpoint
        ```
      </Tab>

      <Tab title="Kubernetes">
        **목표:** 다음 OOMKill이나 예산 검토 전에 파드가 과잉 프로비저닝, 과소 프로비저닝, 또는 불균형한 상태인지 파악하세요.

        **필요한 것:** [Kubernetes 연결](/ko/guide/connections/kubernetes).

        **빠른 성과 — 클러스터 전체의 파드 리소스 낭비:**

        ```text
        Analyze pod resource usage vs requests across all namespaces and surface the largest over- and under-provisioned workloads
        ```

        CloudThinker가 요청/제한을 실제 사용량과 결합하여 노드 비용 영향도 순으로 차이를 정렬합니다.

        **후속 질문:**

        ```text
        HPA policies for the variable workloads above
        Find nodes with <30% utilization for consolidation
        Check for pods without resource limits or liveness probes
        ```
      </Tab>

      <Tab title="Engineering leader">
        **목표:** 회의 네 번을 잡지 않고도 비용, 보안, 성능, 안정성 전반을 하나의 뷰로 파악하세요.

        **필요한 것:** 커버하려는 영역의 연결.

        **빠른 성과 — 분기별 인프라 검토:**

        ```text
        Run a quarterly infrastructure review covering top cost savings, security and compliance gaps, database performance hotspots, and Kubernetes utilization risk. Consolidate it into an executive summary with prioritized actions.
        ```

        CloudThinker가 각 영역을 병렬로 처리하고 중복 발견 사항을 제거하여 네 개의 탭 대신 하나의 경영진 브리핑을 반환합니다.

        **후속 질문:**

        ```text
        Turn this into a quarterly business review slide deck
        Track the open actions from last quarter — what shipped, what slipped
        Draft a roadmap that aligns cost reduction with reliability work
        ```
      </Tab>
    </Tabs>

    **성공 기준:** CloudThinker가 일반적인 모범 사례가 아닌 실제 환경에서 알고 있는 리소스, 쿼리, 또는 규칙을 언급하며 응답합니다.
  </Step>

  <Step title="대화 정제">
    CloudThinker는 대화 컨텍스트를 유지하므로, 처음부터 다시 시작하는 대신 결과를 기반으로 발전시키세요:

    - **처음부터 구체적으로.** "지난 30일 us-east-1의 EC2 비용"이 "비용 보여줘"보다 낫습니다.
    - **재시작 말고 정제.** "위 항목에 대해 RDS로 드릴다운해줘"는 잘 작동합니다.
    - **원하는 형태를 요청하기.** 먼저 대시보드로 추세를 확인한 다음, 같은 주제에 대한 추천을 요청하세요.
    - **여러 영역을 한 번에 요청하기.** 비용, 보안, 데이터베이스, Kubernetes에 걸친 작업은 한 번만 요청하세요 — CloudThinker가 작업을 나누어 처리합니다.

    **성공 기준:** 후속 프롬프트가 이전 대화 내용을 반복하지 않아도 이전 항목을 참조하는 답변을 반환합니다.
  </Step>
</Steps>

## 완료 기준

- [x] 역할별 빠른 성과가 알고 있는 리소스나 쿼리를 언급하는 결과를 반환했습니다
- [x] 적어도 하나의 후속 프롬프트가 첫 번째 답변을 재설명 없이 기반으로 했습니다
- [x] 대시보드, 보고서, 추천을 자연어로 요청할 수 있습니다

모든 요청은 각 워크스페이스에 내장된 어시스턴트인 **CloudThinker**로 전달됩니다. CloudThinker는 직접 답변하고, 큰 작업은 임시 서브에이전트에 나누어 맡기며, 팀이 만든 커스텀 에이전트에게 작업을 넘깁니다.

## 하나의 어시스턴트를 사용하는 이유

- **질문할 곳은 한 곳.** 먼저 전문가를 고를 필요가 없습니다. 요청을 입력하면 CloudThinker가 필요한 연결과 스킬을 판단합니다.
- **필요할 때 병렬 작업.** CloudThinker는 단기 서브에이전트를 생성해 여러 항목을 동시에 확인한 뒤 결과를 하나로 합칩니다.
- **팀만의 전문가.** 커스텀 에이전트는 팀의 지침과 직접 추가한 연결만 가집니다.
- **어디서나 같은 가드레일.** 모든 에이전트의 쓰기 작업은 워크스페이스의 [Manual 또는 Auto](/ko/guide/auto-mode) 설정과 [Tool Permissions](/ko/guide/approval)를 따릅니다.

## CloudThinker 어시스턴트

CloudThinker는 항상 켜져 있습니다. 끌 수 없으며, 워크스페이스의 모든 [연결](/ko/guide/connections/overview)을 사용할 수 있습니다.

`@CloudThinker`를 멘션하거나 그냥 입력하세요. 다음 표는 메시지에 누가 답하는지 보여줍니다:

| 보내는 메시지 | 답하는 에이전트 |
|---|---|
| 멘션이 없는 메시지 | CloudThinker, 또는 마지막으로 답한 에이전트가 아직 활성 상태라면 그 에이전트 |
| 커스텀 에이전트를 멘션한 메시지 | 해당 커스텀 에이전트 |
| `@CloudThinker`를 멘션한 메시지 | CloudThinker |

**Mention an agent**라는 제목의 `@` 선택기에는 CloudThinker와 워크스페이스의 활성 커스텀 에이전트가 나열됩니다.

## 서브에이전트

인시던트 중 세 개의 서비스를 확인하는 것처럼 독립적인 부분이 여러 개인 작업에서는 CloudThinker가 병렬로 작동하는 임시 서브에이전트를 생성합니다. 각 서브에이전트가 결과를 보고하면 CloudThinker가 이를 하나의 답변으로 합칩니다.

| 표시되는 내용 | 의미 |
|---|---|
| 채팅의 **Spawn Subagents** | CloudThinker가 이 작업을 위해 병렬 서브에이전트를 시작했습니다 |
| **N agents still working** | 서브에이전트가 아직 실행 중입니다 |
| **1 agent needs you** | 서브에이전트가 사용자를 기다리고 있습니다. 해당 줄을 클릭하면 사이드 패널의 **Agents** 탭이 열립니다 |
| 서브에이전트의 **Needs approval** | 승인이 필요한 쓰기 작업을 실행하려고 합니다 |
| **Finish Subagent** | 서브에이전트가 결과를 보고했습니다 |

서브에이전트는 자신을 시작한 작업 동안에만 존재합니다. 에이전트 목록에는 나타나지 않습니다.

## 커스텀 에이전트

커스텀 에이전트는 워크스페이스가 정의하는 에이전트로, 자체 이름, `@mention`, 역할, 지침, 연결을 가집니다. 팀에 일관된 동작이 필요할 때 사용하세요 — 예를 들어 항상 팀의 명명 규칙을 따르는 데이터베이스 리뷰어가 있습니다.

**Settings → Agents**(**Agent Configuration** 그룹)에서 만드세요. **Create agent**를 클릭한 다음 **Create with AI** 또는 **Build with form**을 선택합니다. 각 커스텀 에이전트에는 다음 설정이 있습니다:

| 설정 | 제어 대상 |
|---|---|
| **Identity** | 아바타, 이름, `@mention`, 역할, 목표 |
| **Instructions** 및 **Language** | 에이전트의 작업 방식과 응답 언어 |
| **Model Tier** | 에이전트가 사용하는 모델 등급 |
| **Skill Learning** | **Auto**는 새 스킬을 저장하고, **Offer**는 먼저 묻고, **Off**는 저장하지 않습니다 |
| **Connections** | 이 에이전트가 사용할 수 있는 연결 |

커스텀 에이전트는 연결이 없으면 스스로 꺼집니다. 커스텀 에이전트 수는 플랜에 따라 다릅니다 — 전체 설정은 [에이전트 사용자 정의](/ko/guide/agents/customize)를 참고하세요.

## 모듈별 에이전트

| 모듈 | 작업 수행 주체 |
|---|---|
| [Resolve](/ko/guide/incident/overview) | CloudThinker가 각 인시던트를 조사하고 수정 방안을 제안합니다 |
| [Review](/ko/guide/code-review/overview) | 풀 리퀘스트 리뷰는 리뷰 봇이 게시합니다. `@cloudthinker-ai` [명령](/ko/guide/code-review/mention-commands)으로 답글을 다세요 |
| [Optimize](/ko/guide/cost-optimization/overview) | 발견 항목은 청구 데이터에서 나옵니다. 채팅에서 CloudThinker에게 어떤 항목이든 자세히 분석하도록 요청하세요 |
| [Cyber](/guide/security/cyber-overview) | 전용 보안 에이전트가 앱에 대한 각 침투 테스트를 실행합니다 |

각 모듈을 시작하기 전에 필요한 것은 [모듈](/ko/guide/modules)을 참고하세요.

## FAQ

  <Accordion title="Anna, Alex, Oliver, Tony, Kai는 어디로 갔나요?">
    이전 버전에는 이름이 있는 다섯 에이전트가 표시되었습니다. 이제 CloudThinker가 하나의 어시스턴트로서 이들의 작업을 처리하며, 작업에 병렬 전문성이 필요할 때 서브에이전트를 생성합니다. 전문가를 고르는 대신 CloudThinker에게 직접 질문하세요.
  </Accordion>
  <Accordion title="CloudThinker를 끌 수 있나요?">

  </Accordion>
  <Accordion title="커스텀 에이전트도 승인을 따르나요?">
    예. CloudThinker, 서브에이전트, 커스텀 에이전트 등 모든 에이전트의 쓰기 작업은 동일한 워크스페이스 승인 설정을 따릅니다.
  </Accordion>
</AccordionGroup>

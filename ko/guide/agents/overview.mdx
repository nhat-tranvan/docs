에이전트는 요청을 읽고, [연결](/ko/guide/connections/overview)을 사용해 정보를 조회한 뒤 답변하거나 작업을 수행하는 AI입니다. 모든 워크스페이스에는 내장 에이전트 **CloudThinker**가 하나 있으며, 이 에이전트는 큰 작업을 임시 서브에이전트에 나누어 맡길 수 있습니다. 여기에 팀이 만드는 커스텀 에이전트가 더해집니다. 모든 에이전트의 쓰기 작업은 워크스페이스의 [Approvals](/guide/approvals/overview)를 따릅니다.

## 에이전트와 대화하기

<PromptSyntaxBasics />

누가 답하는지는 멘션에 따라 달라집니다:

| 보내는 메시지 | 답하는 에이전트 |
|---|---|
| 멘션이 없는 메시지 | CloudThinker |
| `@CloudThinker`를 멘션한 메시지 | CloudThinker |
| `@db-reviewer`처럼 커스텀 에이전트를 멘션한 메시지 | 해당 커스텀 에이전트 |

채팅 입력란에 `@`를 입력하면 **Mention an agent** 선택기가 열립니다. 여기에는 CloudThinker와 워크스페이스의 활성 커스텀 에이전트가 나열됩니다.

첫 요청에는 멘션이 전혀 필요하지 않습니다:

```text
Which pods in the production namespace restarted more than 3 times in the last 24 hours, and why?
```

CloudThinker가 Kubernetes 연결을 선택하고 확인을 실행한 뒤, 해당 Pod, 재시작 횟수, 찾아낸 각 재시작의 원인을 답변합니다.

## CloudThinker 어시스턴트

CloudThinker는 항상 켜져 있습니다. 끌 수 없으며, 워크스페이스의 모든 연결을 사용할 수 있습니다. 질문, 조사, 보고서, 변경 작업(Approvals 설정에 따라 승인을 기다림) 등 어떤 용도로든 사용하세요.

## 서브에이전트

서브에이전트는 CloudThinker가 더 큰 작업의 한 부분을 위해 시작하는 단기 도우미입니다. 예를 들어 인시던트 중에는 세 서비스를 하나씩 차례로 확인하는 대신 동시에 확인할 수 있습니다. 각 서브에이전트가 결과를 보고하면 CloudThinker가 이를 하나의 답변으로 합칩니다.

서브에이전트는 채팅과 사이드 패널의 **Agents** 탭에 표시됩니다:

| 표시되는 내용 | 의미 |
|---|---|
| **Spawn Subagents** | CloudThinker가 이 작업을 위해 서브에이전트를 시작했습니다 |
| **N agents still working** | 서브에이전트가 아직 실행 중입니다 |
| **1 agent needs you** | 서브에이전트가 사용자를 기다리고 있습니다. 해당 줄을 클릭하면 **Agents** 탭이 열립니다 |
| **Finish Subagent** | 서브에이전트가 결과를 보고했습니다 |

**Agents** 탭의 각 서브에이전트에는 상태가 표시됩니다:

| 상태 | 해야 할 일 |
|---|---|
| **Waiting to start**, **Working**, **Waiting for background work** | 없습니다. 실행 중입니다 |
| **Needs approval** | 쓰기 작업을 실행하려고 합니다. **Approve** 또는 **Reject**를 클릭하세요. 이 패널에는 **Approve and draft rule**이 없습니다. **Reject**는 서브에이전트를 중지하지만, 채팅 카드의 **Decline**은 해당 작업 없이 에이전트가 계속 진행하게 합니다 |
| **Needs review** | 서브에이전트가 결과를 확인하기 전에 호출이 중단되어 변경이 일어났는지 알 수 없습니다. 대상 시스템을 확인한 다음 **Agents** 탭의 해당 서브에이전트에서 **I verified it completed** 또는 **I verified it did not complete**를 클릭하거나 **Stop this agent**를 클릭하세요. 서브에이전트가 그 호출을 스스로 다시 실행하는 일은 없습니다 |
| **Done**, **Failed**, **Stopped**, **Replaced** | 완료되었습니다. **Replaced**는 더 새로운 실행이 이어받았다는 뜻이며 오류가 아닙니다 |

서브에이전트는 자신을 시작한 작업 동안에만 존재합니다. 에이전트 목록에 나타나지 않으며 멘션할 수도 없습니다.

## 커스텀 에이전트

커스텀 에이전트는 워크스페이스가 정의하는 에이전트로, 자체 이름, `@mention`, 지침, 연결을 가집니다. 팀에 매번 같은 동작이 필요할 때 만드세요. 예를 들어 항상 팀의 명명 규칙을 적용하는 데이터베이스 리뷰어나 스테이징 클러스터만 다루는 온콜 도우미가 있습니다.

워크스페이스 Admin과 Developer는 **Settings → Workspace → Agents**에서 만들 수 있습니다. **Create agent**를 클릭한 다음 **Create with AI**(평이한 말로 설명) 또는 **Build with form**을 선택하세요. 커스텀 에이전트에는 자체 승인 모드가 없습니다. 쓰기 작업은 다른 모든 에이전트와 마찬가지로 워크스페이스의 Approvals를 따릅니다.

| 설정 | 제어 대상 |
|---|---|
| **Identity** | 아바타, 이름, `@mention`, 역할, 목표 |
| **Instructions** 및 **Language** | 에이전트의 작업 방식과 응답 언어 |
| **Model Tier** | **Light**(빠르고 경제적, 0.3x), **Pro**(균형, 1.0x), **Ultra**(최대 성능, 1.7x). 배수는 각 실행이 사용하는 크레딧에 곱해집니다. 채팅은 Pro로 시작합니다. [실행 비용을 높이는 요인](/ko/guide/billing/usage#실행-비용을-높이는-요인)을 참고하세요 |
| **Skill Learning** | **Auto**는 새 스킬을 저장하고, **Offer**는 저장 전에 묻고, **Off**는 저장하지 않습니다 |
| **Connections** | 이 에이전트가 사용할 수 있는 유일한 연결 |

<Note>
연결이 없는 커스텀 에이전트는 활성 상태로 남지만 작업에 쓸 도구가 없습니다. 멘션하기 전에 연결을 하나 이상 추가하세요. Team은 커스텀 에이전트를 최대 5개, Scale은 최대 10개까지 허용하며 Enterprise는 제한이 없습니다. [플랜별 AI 기능](/ko/guide/billing/pricing#플랜별-ai-기능)을 참고하세요.
</Note>

테스트 프롬프트와 예상 답변이 포함된 실습 예시는 [첫 커스텀 에이전트 만들기](/guide/agents/quickstart)를 참고하세요. 전체 설정은 [에이전트 사용자 정의](/ko/guide/agents/customize)에 있습니다.

## 제품별 에이전트

| 제품 | 작업 수행 주체 |
|---|---|
| [Resolve](/ko/guide/incident/overview) | CloudThinker가 각 인시던트를 조사하고 수정 방안을 제안합니다 |
| [Review](/ko/guide/code-review/overview) | 리뷰 봇이 풀 리퀘스트에 리뷰를 게시합니다. `@cloudthinker-ai` [명령](/ko/guide/code-review/mention-commands)으로 답글을 다세요 |
| [Optimize](/ko/guide/cost-optimization/overview) | 발견 항목은 청구 데이터에서 나옵니다. 채팅에서 CloudThinker에게 어떤 항목이든 자세히 분석하도록 요청하세요 |
| [Cyber](/guide/security/cyber-overview) | CloudThinker가 테스트 권한이 있는 실행 중인 앱에 동적 보안 테스트를 실행합니다 |

## FAQ

<AccordionGroup>
  <Accordion title="CloudThinker를 끌 수 있나요?">
    아니요. CloudThinker는 모든 워크스페이스에서 항상 활성 상태입니다. 커스텀 에이전트는 켜고 끌 수 있습니다.
  </Accordion>
  <Accordion title="커스텀 에이전트와 서브에이전트도 승인을 따르나요?">
    예. CloudThinker, 서브에이전트, 커스텀 에이전트의 쓰기 작업은 모두 동일한 워크스페이스 Approvals 설정을 따릅니다.
  </Accordion>
  <Accordion title="CloudThinker는 볼 수 있는 시스템을 커스텀 에이전트는 왜 볼 수 없나요?">
    커스텀 에이전트는 자신에게 추가된 연결만 사용합니다. **Settings → Workspace → Agents**에서 해당 에이전트를 열고 연결을 추가하세요.
  </Accordion>
  <Accordion title="예전 블로그 글이나 스크린샷에 이름이 있는 에이전트가 나옵니다. 어디로 갔나요?">
    이전 버전에는 이름이 있는 다섯 전문 에이전트가 있었습니다. 이제 CloudThinker가 하나의 어시스턴트로서 이들의 작업을 모두 처리하며, 작업에 병렬 작업이 필요할 때 서브에이전트를 생성합니다. CloudThinker에게 직접 질문하세요.
  </Accordion>
</AccordionGroup>

Code Review 분석은 저장소 전반의 리뷰 활동, 반복되는 발견, 증거에 기반한 추세를 보여줍니다.

내비게이션에서 **Code Review → Analytics**로 접근하세요.

## Analytics 탭

Analytics 섹션에는 두 개의 탭이 있습니다.

| 탭 | 표시 내용 |
|-----|--------------|
| **Review Patterns** | 확인된 Advanced Review 머지 리퀘스트에 영향을 주는 발견 도메인과 그 결과를 설명하는 발견 항목 |
| **Reports** | 준비가 완료된 저장소 단위 리뷰 리포트 |

Review Patterns가 기본으로 열립니다. 폐지된 탭을 가리키는 저장된 링크도 Review Patterns를 엽니다.

## Review Patterns

Review Patterns는 코칭 뷰입니다. 머지 리퀘스트의 실제 결과를 사용하며, 각 패턴을 해당 발견 증거에 연결합니다.

### 포함 조건

Review Patterns는 완료되고 초안이 아니며 유효한 Advanced Review 중 정확한 결과가 저장된 것만 포함합니다. Fast Review, 섀도 판정, 미완료 리뷰, 파이프라인 발견, 메인 에이전트 발견, 알 수 없는 스페셜리스트, 봇 작성자는 도메인 비율에 영향을 주지 않습니다.

정확한 결과가 없는 과거 레코드는 계속 제외됩니다. 읽기 경로는 타임스탬프나 발견의 존재 여부로 완료 상태나 발견의 소유를 추론하지 않습니다.

### 비율 읽기

이 뷰는 Security, Performance, Correctness, Patterns 네 개 도메인을 다룹니다. 각 도메인은 발견이 없는 머지 리퀘스트 비율과 그 분자, 분모를 그대로 보여줍니다.

도메인 비율은 다음과 같습니다.

```text
발견 없는 머지 리퀘스트 / 리뷰된 머지 리퀘스트
```

하나의 머지 리퀘스트는 선택한 기간에 한 번만 반영됩니다. 포함 가능한 결과가 여러 개이면 작성자와 기간은 가장 최근의 포함된 완료에서 가져오고, 포함된 모든 결과에 연결된 발견의 합집합이 도메인 비율에 영향을 줍니다. 한 도메인에 발견이 여러 개여도 해당 머지 리퀘스트는 한 번만 반영됩니다. 해결된 발견과 해결되지 않은 발견은 동일하게 계산됩니다.

포함 가능한 머지 리퀘스트가 세 개 미만인 개발자도 **Not enough data**와 리뷰 건수와 함께 계속 표시됩니다. 이들의 머지 리퀘스트는 팀 전체 비율에는 반영됩니다.

### 주요 코칭 우선순위

페이지는 팀 전체에서 영향을 받은 머지 리퀘스트 비율이 가장 높은 도메인을 앞세워 보여줍니다. 비율이 정확히 같으면 Critical과 High 발견 건수로 정하며, 그래도 동률인 도메인은 모두 표시합니다. 심각도가 비율에 가중치를 주는 일은 없습니다.

### 증거 확인

개발자-도메인 셀을 선택하면 선택한 주간 또는 월간 기간에 대해 해당 개발자와 팀 전체를 볼 수 있습니다. 확장된 뷰에는 관련 발견이 심각도, 해결 상태, 머지 리퀘스트 식별 정보, 리뷰 링크와 함께 나열됩니다.

해결된 발견도 과거 코칭 증거로 남습니다.

## 기간과 상태

주간과 월간 컨트롤이 Analytics의 유일한 컨트롤이며 Review Patterns에 적용됩니다. 데이터가 로드되는 동안이나 요청이 실패해도 뷰는 선택 항목을 유지합니다.

| 뷰 | 선택 가능한 기간 |
|------|-------------------|
| 주간 | 이번 주 또는 최근 4, 8, 12주 |
| 월간 | 최근 3, 6, 12개월 |

데이터가 적은 기간은 뷰가 다음과 같이 명시합니다.

- 확인된 Advanced Review가 없는 경우: 해당 기간에 대상 데이터가 없다고 페이지가 설명합니다.
- 대상 머지 리퀘스트가 한두 개인 경우: 백분율 없이 건수만 표시합니다.
- 추세 구간에 대상 머지 리퀘스트가 없는 경우: 차트가 **No data** 라벨과 함께 빈 구간을 표시합니다.
- 요약 또는 상세 요청이 실패한 경우: 해당 영역이 Retry를 제공하며 현재 기간이나 선택은 유지됩니다.

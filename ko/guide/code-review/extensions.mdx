Extensions를 사용하면 Review가 풀 리퀘스트(PR) 또는 머지 리퀘스트(MR) 뒤에 있는 티켓을 읽을 수 있습니다. 설명에 Jira 이슈, Confluence 페이지, Linear 또는 Backlog 이슈, GitHub 또는 GitLab 이슈가 링크되어 있으면 리뷰어가 이를 가져와 코드가 티켓의 요구대로 동작하는지 확인합니다. extension이 없으면 Review는 diff만 보고 판단하므로 수락 기준이 누락되었다는 사실을 알려줄 수 없습니다.

## 사용 가능한 extension

| Extension | 읽는 내용 | 필요한 것 |
|---|---|---|
| **Jira / Confluence** | 링크된 티켓(요약, 수락 기준, 링크된 페이지)과 Confluence 스펙 페이지 | [Atlassian 연결](/ko/guide/connections/atlassian) |
| **Linear** | 이슈 제목, 설명, 상태, 라벨, 이슈의 git 브랜치 이름. PR 브랜치 이름은 검사하지 않습니다 | [Linear 연결](/guide/connections/linear) |
| **Backlog** | 이슈 요약, 설명, 상태 | [Backlog 연결](/ko/guide/connections/backlog) |
| **GitHub Issues** | PR이 참조하는 이슈: 제목, 본문, 라벨, 코멘트 | GitHub에 설정된 Review. 같은 연결을 사용합니다 |
| **GitLab Issues** | MR이 참조하는 이슈: 제목, 설명, 라벨, 코멘트 | GitLab에 설정된 Review. 같은 연결을 사용합니다 |

GitHub Issues는 Review 제공자가 GitHub일 때만, GitLab Issues는 GitLab일 때만 표시됩니다.

**지원되지 않음:** Jira 및 Confluence Data Center 또는 Server(Atlassian 연결은 Atlassian Cloud에서만 작동합니다), 그리고 extension이 없는 Azure Boards. 이 경우 수락 기준을 PR 설명에 붙여 넣으세요: Review는 변경과 함께 설명을 읽습니다.

## 사전 요구 사항

- 하나 이상의 저장소에 연결된 Review. [Review 설정](/ko/guide/code-review/setup)을 참고하세요.
- 트래커를 연결하려면 워크스페이스 **Admin** 역할과 **Settings → Workspace → Connections** 접근 권한이 필요합니다. 다른 역할에는 타일에 **Connect** 대신 **View**가 표시됩니다. [역할](/guide/security/roles)을 참고하세요.
- 티켓이 있는 프로젝트를 읽을 수 있는 트래커 계정.

## extension 켜기

<Steps>
  <Step title="Extensions 섹션 열기">
    **Review → Settings**로 이동해 **Extensions**("Link tickets and specs so Review can check changes against them")까지 스크롤하세요. 각 트래커에는 상태가 표시된 타일이 있습니다.

    | 타일 상태 | 의미 |
    |---|---|
    | **Connected** | Review가 이미 티켓을 가져오고 있습니다 |
    | **Not connected** | 아직 연결이 없습니다. **Connect**를 클릭하세요 |
    | **Needs attention** | 연결이 오류를 보고합니다. **Settings → Workspace → Connections**에서 해결하세요 |
    | **Uses your GitHub connection**(또는 GitLab) | Review 제공자를 통해 작동합니다. 설정할 것이 없습니다 |
    | **Status unavailable** | 연결 목록이 로드되지 않았습니다. 페이지를 새로 고치세요 |
  </Step>
  <Step title="트래커 연결하기">
    타일에서 **Connect**를 클릭하세요. CloudThinker가 해당 연결의 양식이 준비된 **Settings → Workspace → Connections**를 엽니다. [Atlassian](/ko/guide/connections/atlassian), [Linear](/guide/connections/linear), [Backlog](/ko/guide/connections/backlog) 연결 가이드를 참고해 작성한 다음 저장하세요.

    **성공 상태:** **Review → Settings → Extensions**로 돌아오면 타일에 **Connected**가 표시됩니다.
  </Step>
  <Step title="PR 설명에 티켓 참조하기">
    PR 또는 MR 설명에 티켓 링크나 키를 넣으세요. 명령이나 설정은 필요 없습니다.

    | 트래커 | 설명에 쓸 내용 |
    |---|---|
    | Jira | `https://myorg.atlassian.net/browse/OPS-1234` 또는 `OPS-1234` |
    | Confluence | `https://myorg.atlassian.net/wiki/spaces/ENG/pages/123456/API-contract`. Confluence에는 짧은 키가 없으므로 페이지 URL을 사용하세요 |
    | Linear | `https://linear.app/myorg/issue/ENG-123/slug` 또는 `ENG-123` |
    | Backlog | `https://myspace.backlog.com/view/PROJ-123` 또는 `PROJ-123` |
    | GitHub 또는 GitLab 이슈 | PR 자체 저장소에는 `Closes #123`, `Fixes #456`, `#123`. 다른 저장소에는 `org/repo#123` 또는 이슈 URL |

    Jira, Linear, Backlog 키는 비슷하게 생겼습니다. 이 중 하나만 연결되어 있으면 `OPS-1234` 같은 단순 키는 그 트래커로 갑니다. 둘 이상 연결되어 있으면 리뷰어가 각각을 시도해야 하며, 두 트래커에 모두 있는 키는 엉뚱한 티켓과 일치할 수 있습니다.

    <Tip>
    키 기반 트래커가 둘 이상 연결되어 있으면 항상 전체 티켓 URL을 사용하세요.
    </Tip>
  </Step>
  <Step title="PR을 열고 리뷰 읽기">
    리뷰는 평소대로 실행됩니다. 이제 발견 항목은 코드 자체뿐 아니라 티켓 대비 누락된 부분도 다룹니다.

    **성공 상태:** 변경이 티켓의 일부를 놓치면 리뷰 발견 항목이 어느 부분인지 알려줍니다.
  </Step>
</Steps>

연결된 타일에서 **Manage**를, 다른 타일에서 **View**를 클릭하면 해당 extension이 읽는 내용과 인식하는 패턴을 볼 수 있습니다.

extension은 워크스페이스에 해당 연결이 있으면 항상 켜져 있으며, 채팅이나 다른 에이전트를 위해 처음 만든 연결도 포함됩니다. Review가 다루는 모든 저장소에 적용됩니다. 별도 스위치나 저장소별 설정은 없습니다.

<Warning>
Review가 트래커를 읽지 않게 하려면 **Settings → Workspace → Connections**에서 연결을 해제해야 합니다. 이렇게 하면 Review뿐 아니라 워크스페이스의 모든 에이전트와 채팅에서 연결이 제거됩니다.
</Warning>

## 예시

다음과 같은 PR 설명이 있다고 합시다:

```markdown
Add rate limiting to the login endpoint.

Implements OPS-1234. Spec: https://myorg.atlassian.net/wiki/spaces/ENG/pages/123456
```

OPS-1234가 "return 429 with a Retry-After header"를 수락 기준으로 나열하고 있고, diff는 헤더 없이 429를 반환한다고 가정합시다. Jira extension이 있으면 리뷰어는 그 기준을 보고 티켓 대비 누락된 헤더를 지적할 수 있습니다. 예: "The login endpoint returns 429 without the Retry-After header that OPS-1234 requires." extension이 없으면 같은 diff가 올바르게 보입니다.

[리뷰 워크스페이스](/guide/code-review/review-workspace)에서는 **Ticket compliance** 카드도 변경을 티켓 대비 **Fully compliant**, **Partially compliant**, **Not compliant**로 평가합니다. 모든 리뷰 모드에서 작동합니다. 이 카드는 Jira 또는 Linear 티켓이 정확히 하나 확인되었을 때 표시됩니다. 티켓이 여러 개이거나 Backlog 티켓 또는 Git 이슈라면, 대신 리뷰 요약 코멘트에 티켓별 판정이 담긴 표가 나옵니다.

## 읽는 범위

- **설명만.** Review는 PR 또는 MR 설명에서 링크와 키를 찾습니다.
- **코드는 아님.** 코드 블록이나 인라인 코드(`` `OPS-1234` ``) 안의 키는 무시되므로, 스니펫의 예시 ID가 조회를 일으키지 않습니다.
- **PR당 최대 20개 참조.** 설명의 처음 65,535자에서 가져옵니다. 가장 중요한 티켓을 먼저 두세요.
- **연결이 볼 수 있는 티켓.** Review는 연결된 계정의 접근 권한으로 읽으므로, 그 계정이 열 수 없는 프로젝트의 티켓은 리뷰에 사용할 수 없습니다.
- **워크스페이스에 표시됨.** 리뷰어가 티켓에서 가져온 내용은 발견 항목에 나타날 수 있습니다. 이는 PR의 리뷰 코멘트와 워크스페이스에서 Review에 접근할 수 있는 모든 사람에게 표시됩니다. 공개 저장소에서는 PR을 볼 수 있는 누구나 그 코멘트를 읽을 수 있으므로, 그곳에 링크하는 티켓에는 기밀 정보를 넣지 마세요. [데이터 보호](/guide/security/data-protection)를 참고하세요.

## 리뷰에 도움이 되는 티켓 작성하기

- **수락 기준을 별도 줄로 나열하세요.** 각 줄이 리뷰어가 확인할 수 있는 항목이 됩니다. "Works well"은 확인할 수 없지만 "returns 429 after 5 failed attempts in 1 minute"는 확인할 수 있습니다.
- **티켓만이 아니라 스펙도 링크하세요.** API 계약이 있는 Confluence 페이지는 리뷰어에게 정확한 필드 이름과 상태 코드를 알려줍니다.
- **PR이 닫는 모든 티켓을 참조하세요.** 버그 두 개를 고치는 PR은 둘 다 적어야 합니다.

## 문제 해결

<AccordionGroup>
  <Accordion title="리뷰에서 티켓을 언급하지 않습니다">
    **확인:** 참조가 브랜치 이름이나 커밋 메시지에만 있지 않고 설명에 있는지, 백틱이나 코드 블록 안에 있지 않은지 확인하세요. 타일에 **Connected**가 표시되는지 확인하세요.

    **해결:** 설명을 편집한 다음 PR에 `@cloudthinker-ai review`를 코멘트로 달아 리뷰를 다시 실행하고 새 설명을 읽게 하세요. AWS CodeCommit에서는 대신 PR의 소스 브랜치에 새 커밋을 푸시하세요. [멘션 명령](/ko/guide/code-review/mention-commands)을 참고하세요.
  </Accordion>
  <Accordion title="GitHub Issues나 GitLab Issues가 보이지 않습니다">
    이 타일은 일치하는 Review 제공자에서만 표시됩니다. Bitbucket, Azure DevOps, AWS CodeCommit에서는 대신 Jira, Linear, Backlog를 사용하세요.
  </Accordion>
  <Accordion title="타일에 Connect 대신 View가 표시됩니다">
    워크스페이스 Admin만 트래커를 연결할 수 있습니다. 워크스페이스 Admin에게 연결하거나 역할을 변경해 달라고 요청하세요. [역할](/guide/security/roles)을 참고하세요.
  </Accordion>
  <Accordion title="타일에 Connected가 표시되지만 티켓을 읽지 못합니다">
    연결된 계정이 그 티켓의 프로젝트를 열 수 없습니다. 트래커에서 접근 권한을 부여하거나, 권한이 있는 계정으로 다시 연결하세요.
  </Accordion>
</AccordionGroup>

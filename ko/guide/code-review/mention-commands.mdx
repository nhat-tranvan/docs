머지 리퀘스트 또는 풀 리퀘스트 코멘트에서 `@cloudthinker-ai`를 언급하여 명령어를 트리거하세요 — 발견 항목 자동 수정, 리뷰 질문, 도움 요청.

<Warning>
  Mention commands는 현재 **GitLab**과 **GitHub**에서만 사용 가능합니다. Bitbucket과 Azure DevOps 지원은 곧 제공될 예정입니다.
</Warning>

---

## 명령어

| 명령어 | 수행 내용 |
|---------|-------------|
| `@cloudthinker-ai help` | 사용 가능한 명령어를 코멘트로 표시합니다 |
| `@cloudthinker-ai autofix` | 소스 브랜치의 미해결 발견 항목을 수정합니다 |
| `@cloudthinker-ai autofix stacked pr` | 새 브랜치에서 발견 항목을 수정하고 현재 MR/PR에 푸시합니다 |
| `@cloudthinker-ai <question>` | 코드 리뷰에 대해 자유 형식 질문을 합니다 |

---

## autofix 동작 방식

<Steps>
  <Step title="코멘트 작성">
    MR/PR에 `@cloudthinker-ai autofix`(또는 `@cloudthinker-ai autofix stacked pr`)를 코멘트로 작성하세요
  </Step>
  <Step title="분석">
    CloudThinker가 리뷰에서 모든 미해결 발견 항목을 수집합니다
  </Step>
  <Step title="수정">
    에이전트가 코드베이스 컨벤션에 따라 각 발견 항목에 대한 수정 사항을 구현합니다
  </Step>
  <Step title="푸시">
    변경 사항이 커밋되어 브랜치에 푸시됩니다
  </Step>
</Steps>

### 직접 vs. 스택 PR

- **`@cloudthinker-ai autofix`** — MR/PR 소스 브랜치에 직접 커밋합니다. 수정 후 발견 항목이 해결됨으로 표시됩니다.
- **`@cloudthinker-ai autofix stacked pr`** — 새 브랜치를 생성하고 수정 사항을 현재 MR/PR의 소스 브랜치에 푸시합니다. 검토를 위해 발견 항목이 열린 상태로 유지됩니다.

## 자유 형식 질문

`@cloudthinker-ai`를 언급하고 질문을 이어서 코드 리뷰에 대해 무엇이든 물어보세요:

```text
@cloudthinker-ai why was this function flagged as a security risk?
@cloudthinker-ai can you explain the performance impact of this change?
@cloudthinker-ai what's the best way to refactor this?
```

### 스레드 인식 컨텍스트

- **발견 항목 스레드에서 답글** — 에이전트가 해당 발견 항목의 세부 정보만(심각도, 파일, 라인, 수정 제안) 확인하여 집중된 답변을 제공합니다.
- **최상위 코멘트** — 에이전트가 리뷰의 모든 미해결 발견 항목을 확인하여 더 넓은 관점의 답변을 제공합니다.

## 팁

- **한 번에 하나의 autofix** — MR/PR당 하나의 autofix만 실행할 수 있습니다. 다음 것을 시작하기 전에 현재 것이 완료될 때까지 기다리세요.
- **대화 컨텍스트 재사용** — 같은 스레드에서의 자유 형식 답글은 대화 컨텍스트를 재사용하므로 후속 질문이 이전 답변을 기반으로 합니다.
- **푸시에는 승인 필요** — Autofix 푸시는 변경 사항이 브랜치에 적용되기 전에 사람의 승인이 필요합니다.

머지 리퀘스트 또는 풀 리퀘스트(MR/PR) 코멘트에서 `@cloudthinker-ai`를 멘션하면 Git 제공자를 떠나지 않고 리뷰를 다시 실행하거나, 발견 항목을 수정하거나, 변경에 대해 질문할 수 있습니다. **발견 항목(finding)**은 리뷰가 사람이 살펴보도록 표시한 문제 하나입니다.

## 사전 요구 사항

- [Review 설정](/ko/guide/code-review/setup)에서 연결된 저장소의 열린 MR/PR.
- Git 제공자에서 해당 MR/PR에 코멘트를 달 수 있는 권한.

## 명령

명령은 코멘트 안에서 별도 줄에 일반 텍스트로 쓰세요. 봇 사용자 이름이 무엇이든 `@cloudthinker-ai`를 정확히 입력하세요. 제공자의 자동 완성이 제안하지 않을 수도 있지만 괜찮습니다.

| 명령 | 동작 |
|---|---|
| `@cloudthinker-ai` 또는 `@cloudthinker-ai help` | 제공자가 지원하는 명령 목록을 게시합니다 |
| `@cloudthinker-ai <question>` | 이 MR/PR에 대한 질문에 답합니다 |
| `@cloudthinker-ai review` | 첫 리뷰를 시작하거나, 마지막으로 리뷰한 커밋부터 다시 리뷰합니다. `review again`, `continue`, `continue review`도 같은 동작을 합니다 |
| `@cloudthinker-ai autofix` | 심각도와 관계없이 해결되지 않은 모든 발견 항목을 수정하고, 커밋을 이 MR/PR의 소스 브랜치에 푸시합니다 |
| `@cloudthinker-ai autofix stacked` | 해결되지 않은 모든 발견 항목을 새 브랜치에서 수정하고 별도 MR/PR을 엽니다. `autofix stacked pr`도 작동합니다 |

`review`는 한 줄 전체여야 합니다. `@cloudthinker-ai review this carefully`는 명령이 아니라 질문으로 처리됩니다. 코드 블록, 인라인 코드, 인용된 답글 안의 멘션도 명령으로 실행되지 않습니다.

## 명령 실행하기

<Steps>
  <Step title="제공자에서 MR/PR 열기">
    CloudThinker가 리뷰한 GitHub, GitLab, Bitbucket, Azure DevOps, AWS CodeCommit의 MR/PR을 사용하세요.
  </Step>
  <Step title="새 코멘트로 명령 게시하기">
    예를 들어 중간에 멈춘 리뷰를 다시 실행하려면:

    ```text
    @cloudthinker-ai review
    ```

    **성공 상태:** 봇이 **CloudThinker Review Started**로 답합니다. 실행이 끝나면 MR/PR에 새 리뷰 요약 코멘트가 나타납니다. Azure DevOps에서는 대신 리뷰가 끝났을 때 봇이 **CloudThinker Review Complete** 또는 **CloudThinker Review Did Not Finish**로 답합니다.
  </Step>
</Steps>

리뷰가 요약 전에 멈추면 봇이 진행 상황 코멘트를 **CloudThinker Review Did Not Finish**로 편집합니다. 이미 게시된 발견 항목은 그대로 유효합니다. 마지막으로 리뷰한 커밋부터 이어가려면 `@cloudthinker-ai review`를 코멘트로 다세요. AWS CodeCommit에서는 대신 소스 브랜치에 새 커밋을 푸시하세요.

## 질문하기

봇을 멘션하고 질문을 이어 쓰세요:

```text
@cloudthinker-ai does this change break any other caller of parseConfig?
@cloudthinker-ai what should I test before merging this?
```

어디에 질문하느냐에 따라 에이전트가 집중하는 대상이 달라집니다:

| 코멘트 위치 | 에이전트가 먼저 보는 것 |
|---|---|
| 발견 항목 스레드의 답글 | 해당 발견 항목과 그 파일, 그리고 부작용을 확인할 수 있도록 MR/PR의 나머지 부분 |
| 새 최상위 코멘트 | MR/PR 전체와 해결되지 않은 모든 발견 항목 |

같은 스레드의 후속 질문은 이전 답변을 바탕으로 합니다.

## 발견 항목에 반론하기

MR/PR 작성자이거나 담당자이고 발견 항목이 틀렸다고 생각한다면, 해당 발견 항목의 스레드에 답글을 다세요. 멘션은 필요 없습니다. 예를 들어 이유를 설명하세요:

```text
This is intentional. The retry is capped by the caller in client.go, so it can't loop forever.
```

CloudThinker는 현재 코드와 답글을 기준으로 발견 항목을 다시 확인한 다음, 세 가지 중 하나로 정리합니다:

| 결과 | 조건 | 일어나는 일 |
|---|---|---|
| 철회됨 | 발견 항목이 틀렸습니다 | 닫히며, 이후 저장소의 리뷰는 변경되지 않은 코드에서 이를 다시 제기하지 않도록 안내받습니다. 이는 엄지 아래 [투표](/guide/code-review/review-workspace#work-the-findings)와 같은 노트를 사용합니다: 각 리뷰는 최근 90일 동안의 저장소 노트 중 최신 20개를 받습니다 |
| 확인됨 | 코드가 의도된 것입니다 | 이 MR/PR에서 닫히며, 이유가 스레드에 게시됩니다 |
| 여전히 열림 | 발견 항목이 여전히 해당됩니다 | 열린 상태로 남고, 봇이 이유와 함께 답합니다 |

반론은 리뷰가 끝난 뒤에 작동하며, AWS CodeCommit을 제외한 모든 제공자에서 사용할 수 있습니다. 다른 사람도 봇을 멘션해 발견 항목에 대해 질문할 수 있지만, 그 답글로는 발견 항목이 정리되지 않습니다.

## autofix로 발견 항목 수정하기

수정 사항을 받을 방식을 고르세요:

| 명령 | 수정이 들어가는 곳 | 사용할 때 |
|---|---|---|
| `@cloudthinker-ai autofix` | 이 MR/PR 소스 브랜치의 새 커밋 | 수정을 신뢰하고 MR/PR 하나로 머지하고 싶을 때 |
| `@cloudthinker-ai autofix stacked` | 이 MR/PR의 소스 브랜치를 대상으로 하는 자체 MR/PR이 있는 새 브랜치 | 수정이 브랜치에 들어가기 전에 리뷰하고 싶을 때(GitHub 및 GitLab 전용) |

<Steps>
  <Step title="최상위 코멘트로 명령 게시하기">
    ```text
    @cloudthinker-ai autofix stacked
    ```
  </Step>
  <Step title="수정 실행 기다리기">
    CloudThinker는 제안된 수정이 있든 없든 해결되지 않은 각 발견 항목을 읽고, 코드를 바꾸고, 커밋하고, 푸시합니다. MR/PR당 한 번에 하나의 autofix만 실행됩니다. 실행 중에 두 번째 요청을 보내도 새로 시작되지 않습니다.

    CloudThinker는 테스트를 실행하지 않습니다. 아키텍처 결정이 필요하거나 명확한 수정이 없는 발견 항목은 건너뜁니다. 수정 실행은 에이전트 실행이므로 크레딧을 사용합니다.

    **성공 상태:** 소스 브랜치에 `fix: autofix findings from code review of ...`라는 제목의 커밋이 나타나거나, 그 브랜치를 대상으로 하는 새 MR/PR이 열립니다. 커밋 메시지에는 `Fixed:` 아래에 각 수정이, `Skipped:` 아래에 건너뛴 각 발견 항목과 그 이유가 나열됩니다.
  </Step>
</Steps>

GitHub와 GitLab에서는 발견 항목 하나의 스레드 안에서 답글로 `@cloudthinker-ai autofix`를 입력할 수도 있습니다. 그러면 CloudThinker는 그 발견 항목만 수정합니다.

<Warning>
  `@cloudthinker-ai autofix`는 별도의 승인 단계 없이 소스 브랜치에 푸시합니다. CloudThinker는 이를 MR/PR 작성자로 제한하지 않으며, 그렇게 하는 CloudThinker 설정도 없습니다: 코멘트를 달 수 있는 누구나 실행할 수 있습니다. 널리 공유된 저장소에서는 제공자에서 코멘트 권한을 제한하고, 먼저 변경 사항을 읽고 싶다면 `autofix stacked`를 사용하세요.
</Warning>

## 리뷰 건너뛰기

MR/PR 설명 어디든 다음을 넣으면 CloudThinker가 해당 MR/PR을 리뷰하지 않습니다:

```text
@cloudthinker:ignore
```

대소문자를 구분합니다. CloudThinker는 새 이벤트마다 설명을 읽으므로, 마커를 추가하면 다음 푸시부터 리뷰를 건너뛰고, 제거하면 다음 푸시가 리뷰됩니다. 이미 실행 중인 리뷰는 끝까지 진행됩니다. 끝내려면 [Review 워크스페이스](/guide/code-review/review-workspace#re-run-fix-and-merge)에서 **Stop review**를 사용하세요. 봇 의존성 업데이트처럼 MR/PR 그룹 전체를 건너뛰려면 대신 [Review 설정](/ko/guide/code-review/setup)의 저장소 필터를 사용하세요.

## 제공자 지원

| 제공자 | 최상위 질문 | 스레드 답글 | `review` | `autofix` | `autofix stacked` |
|---|---|---|---|---|---|
| GitHub | 예 | 예 | 예 | 예 | 예 |
| GitLab | 예 | 예 | 예 | 예 | 예 |
| Bitbucket Cloud | 예 | 일부 (1) | 예 | 일부 (2) | 아니요 |
| Azure DevOps | 예 | 일부 (1) | 예 | 일부 (2) | 아니요 |
| AWS CodeCommit | 예 | 아니요 | 아니요 | 아니요 | 아니요 |

1. 발견 항목 스레드에서는 MR/PR 작성자 또는 담당자의 답글만 읽습니다. 다른 사람의 스레드 답글은 질문을 포함해 답을 받지 못하며, 대신 최상위 코멘트로 질문할 수 있습니다.
2. 발견 항목 스레드 안이 아닌 최상위 코멘트에서만.

AWS CodeCommit에서도 자동 리뷰는 모든 새 PR과 소스 브랜치에 대한 모든 푸시에서 실행됩니다. 그곳에서는 `review`와 `autofix` 코멘트 명령이 지원되지 않으므로, CodeCommit PR을 다시 리뷰하려면 새 커밋을 푸시하세요.

제공자가 지원하지 않는 명령에는 지원되지 않는다는 점과 대신 할 일을 알려주는 짧은 답글이 달립니다.

## 문제 해결

<AccordionGroup>
  <Accordion title="봇이 코멘트에 답하지 않았습니다">
    **확인:**

    - 멘션이 백틱, 코드 블록, 인용 안이 아닌 일반 텍스트인지 확인하세요.
    - 제공자가 [위 표](#제공자-지원)의 명령을 지원하는지 확인하세요.
    - Azure DevOps에서는 [제공자 인증](/guide/code-review/provider-auth)에 설명된 대로 **Resource version**이 **2.0**으로 설정된 **Pull request commented on** 서비스 후크가 있는지 확인하세요.
    - 제공자의 webhook 전송 기록에서 코멘트 이벤트가 전송되고 수락되었는지 확인하세요.
  </Accordion>
  <Accordion title="명령이 질문으로 답변되었습니다">
    **원인:** `review`는 한 줄 전체여야 합니다. **해결:** 뒤에 아무것도 붙이지 않고 `@cloudthinker-ai review`를 게시하세요.
  </Accordion>
  <Accordion title="발견 항목 스레드의 답글로 발견 항목이 정리되지 않았습니다">
    **원인:** 답글로 발견 항목을 정리할 수 있는 사람은 MR/PR 작성자 또는 담당자뿐이며, 리뷰가 끝난 뒤에만 가능합니다. **해결:** 작성자에게 답글을 요청하거나, Review 워크스페이스에서 해결됨으로 표시하세요.
  </Accordion>
</AccordionGroup>

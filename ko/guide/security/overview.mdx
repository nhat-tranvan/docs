CloudThinker 에이전트는 사용자가 추가한 연결을 통해 클라우드 계정, 클러스터, 도구를 읽으며, Approvals가 허용할 때만 이를 변경할 수 있습니다. 이 페이지는 보안 검토자가 묻는 사실을 모았으며, 각 통제를 자세히 다루는 페이지 링크를 함께 제공합니다.

## CloudThinker가 처리하는 데이터

| 데이터 | CloudThinker가 보관하는 이유 | 보호 방식 |
|---|---|---|
| 연결 자격 증명(클라우드 키, 토큰, 데이터베이스 로그인) | 에이전트가 연결된 시스템을 조회할 수 있도록 | 저장 시 암호화됩니다. 명령이 실행될 때 관리형 샌드박스에 주입되며, environment로는 절대 전송되지 않습니다. |
| 워크스페이스 [자격 증명](/guide/credentials)(명령에 필요한 기타 API 키) | 누구도 키를 붙여 넣지 않고 명령이 벤더 API를 호출할 수 있도록 | 저장 시 암호화되며 브라우저로 다시 전송되지 않습니다. 채팅에는 키 이름만 표시됩니다. |
| 대화, 발견 사항, 보고서, 아티팩트 | 에이전트가 발견하고 수행한 내용의 기록 | 워크스페이스 범위로 한정되며 역할에 따라 볼 수 있습니다. 도구 출력의 시크릿과 보호된 식별자는 저장되기 전에 플레이스홀더로 대체됩니다. 워크스페이스 Admin은 제목 메뉴(**Delete Conversation**)에서 대화를 삭제할 수 있습니다. |

모델 호출은 조직이 [BYOK](/ko/guide/byok)를 사용하지 않는 한 CloudThinker의 LLM 제공자로 전송됩니다. BYOK를 사용하면 호출이 자체 AWS Bedrock, Anthropic, FPT Cloud, Claude Code 또는 Codex 계정을 통해 라우팅됩니다. BYOK에서는 이러한 호출이 해당 제공자와 맺은 자체 계약의 적용을 받습니다. 단, 실패한 호출이 CloudThinker 모델로 폴백되는 경우는 예외입니다([자세히](/ko/guide/byok#키가-작동을-멈출-때)).

<Warning>
명령 출력은 대화의 일부이므로, 연결의 자격 증명이 읽을 수 있는 모든 것은 모델에 도달할 수 있습니다. AWS `ReadOnlyAccess`의 경우 S3 객체 내용도 포함됩니다. 각 자격 증명의 정책을 에이전트에 필요한 계정, 리전, 서비스로 한정하세요.
</Warning>

## 에이전트가 실행되는 곳

모든 채팅과 Automation은 다음 두 곳 중 하나에서 실행됩니다.

- **CloudThinker Cloud.** 명령은 격리된 CloudThinker 관리형 샌드박스에서 실행됩니다. 연결 자격 증명은 명령을 위해 그곳에 주입되며 다시 출력되지 않습니다.
- **An Environment.** 노트북, 서버, CI 러너 등 사용자가 관리하는 머신이 지정한 폴더 하나에서 파일 도구와 셸 명령을 실행합니다. 연결 명령은 여전히 관리형 샌드박스에서 실행되므로 자격 증명은 클라우드에 남습니다. 셀프 호스팅 environment는 베타입니다.

실행은 environment에서 클라우드로 폴백되지 않습니다. environment를 사용할 수 없으면 실행이 오류를 보고합니다. [Environments](/guide/workers)를 참조하세요.

이 문서에는 송신(egress) IP 범위가 나와 있지 않습니다. 보안 그룹이나 방화벽에서 CloudThinker를 허용 목록에 추가해야 한다면 [문의하세요](https://cloudthinker.io/contact).

## 작업할 수 있는 사람

액세스는 두 단계로 작동합니다. 조직 역할은 모든 워크스페이스에 적용됩니다. 워크스페이스 역할은 멤버가 한 워크스페이스 안에서 할 수 있는 일을 정합니다.

| 워크스페이스 역할 | 할 수 있는 일 |
|---|---|
| **Admin** | 연결, 자격 증명, 멤버, Approvals, Guardrails, 설정을 관리하고 [Skills Hub](/ko/guide/skills/overview) 스킬을 설치합니다 |
| **Developer** | 에이전트와 채팅하고 발견 사항, 리뷰, 스캔을 처리합니다 |
| **Viewer** | 대시보드, 발견 사항, 인시던트를 봅니다. 에이전트와 채팅하거나 무엇이든 변경할 수 없습니다. |

조직 Owner와 Admin은 모든 워크스페이스에서 워크스페이스 Admin 권한을 가집니다. 전체 매트릭스: [역할](/guide/security/roles).

**쓰기를 승인할 수 있는 사람:** 기본적으로 실행을 시작한 사람을 포함해 워크스페이스의 모든 Developer 또는 Admin입니다. Viewer는 절대 승인할 수 없습니다. 자신의 실행을 스스로 승인하지 못하게 하려면 2인 규칙을 켜거나, Rule의 요청을 지정된 승인자 그룹으로 보내세요. [Approvers](/guide/approvals/approvers)를 참조하세요.

**Settings → Organization**은 조직 Owner와 Admin을 위한 조직 콘솔입니다. 조직 Admin이 아닌 워크스페이스 Admin은 이 페이지들을 보지 못하지만, 직접 링크로 두 페이지를 열 수 있습니다. 해당 워크스페이스의 설정을 보여 주는 **Guardrails**와, Owner만 조직 키를 변경할 수 있는 **BYOK**입니다.

### 로그인 통제

| 통제 | 위치 | 플랜 |
|---|---|---|
| 일회용 백업 코드가 있는 인증 앱(TOTP). 각자가 자신의 계정에서 켜며, 조직 전체의 2FA 요구 사항은 없습니다. | **Settings → Personal → Security**, **Two-factor sign-in** 섹션 | 전체 |
| SAML 2.0 또는 OIDC SSO, 도메인 확인, SSO 강제 | **Settings → Organization → Identity** | [Scale 및 Enterprise](/ko/guide/billing/pricing) |
| SCIM 사용자 및 그룹 동기화 | **Settings → Organization → Identity** | [Scale 및 Enterprise](/ko/guide/billing/pricing) |

[싱글 사인온](/ko/guide/security/sso)과 [SCIM](/ko/guide/security/scim)을 참조하세요.

## 에이전트 변경 승인 방식

**쓰기**는 서비스 재시작처럼 연결된 시스템을 변경하는 모든 에이전트 호출입니다. 읽기는 항상 실행됩니다. 각 쓰기는 다음 검사를 순서대로 통과합니다.

1. **Always blocked**: CloudTrail 로깅 중지, AWS 계정 해지, `kube-system` 네임스페이스 삭제처럼 절대 실행되지 않는 호출의 기본 제공 목록입니다. Rule, 사람, break-glass(Deny Rule이 거부한 호출 하나를 owner나 admin이 실행할 수 있게 하는 옵트인 긴급 재정의) 중 어느 것도 이를 무시할 수 없습니다.
2. 이름이 지정된 종류의 쓰기를 허용, 먼저 확인, 거부하는 **Rules**. 어떤 Rule에도 해당하지 않는 쓰기는 Approval mode로 넘어갑니다.
3. 아래에 설명한 실행의 **Approval mode**.
4. 승인하거나 거절하는 승인자.

Approval mode는 **Manual** 또는 **Auto**입니다. **Auto · Rules + AI · Ask me**와 같은 Auto 레이블은 모드 뒤에 두 가지 선택을 더 추가합니다.

| 부분 | 옵션 | 동작 |
|---|---|---|
| 모드 | **Manual** | 모든 쓰기에 대해 사람에게 묻습니다 |
| | **Auto** | 다음 부분이 허용하면 사람 없이 쓰기를 실행합니다 |
| 쓰기를 허용할 수 있는 것 | **Rules** | Allow Rules만 |
| | **Rules + AI** | Allow Rules와, 어떤 Rule도 다루지 않는 쓰기에 대한 AI 판단 |
| 나머지의 처리 | **Ask me** | 사람을 기다립니다 |
| | **Refuse** | 기다리지 않고 거부합니다 |

새 워크스페이스는 **Auto · Rules + AI · Ask me**로 시작합니다. Automations는 응답할 사람이 없을 수 있으므로 기본값이 **Auto · Rules + AI · Refuse**입니다. AI 판단이 하는 일은 다음과 같습니다.

| 쓰기 | 결과 |
|---|---|
| 요청한 내용과 일치하고 범위 안에 머무름 | 실행되며, 결정이 [감사 로그](/guide/security/audit-logs)에 기록됩니다 |
| 파괴적이거나 효과가 불분명함 | 모드의 마지막 부분으로 넘어갑니다. **Ask me**는 사람을 기다리고, **Refuse**는 기다리지 않고 거부합니다. 파괴적인 쓰기는 심각도 높음 알림도 발생시킵니다. |
| AI 판단이 검사를 마칠 수 없음 | 같은 폴백이 적용됩니다. 기본적으로 쓰기를 허용하는 일은 없습니다. |

쓰기는 연결이 이를 허용해야 합니다. **Settings → Workspace → Connections**의 연결 상세 패널에서 **Allow writes**가 꺼져 있거나 자격 증명이 읽기 전용이면, 모드와 관계없이 쓰기가 거부됩니다. 모든 쓰기에 사람이 필요하도록 하려면 워크스페이스를 **Manual**로 전환하세요. [Approvals](/guide/approvals/overview)와 [Approval mode](/guide/approvals/approval-mode)를 참조하세요.

## 감사 및 보존

**Settings → Organization → Audit log**는 모든 워크스페이스에 걸친 사용자, 에이전트, 시스템 작업을 하나의 타임라인으로 보여 줍니다. 연결 변경, 승인 결정, 자격 증명 변경, 멤버 변경, 모듈 활동이 포함됩니다. 각 항목에는 행위자, 워크스페이스, 결과가 기록됩니다.

| 항목 | 값 |
|---|---|
| 볼 수 있는 사람 | 조직 Owner 및 Admin |
| 플랜 | [Scale 및 Enterprise](/ko/guide/billing/pricing) |
| 보존 | 기본 365일 후 자동 삭제됩니다. 셀프 호스팅 설치에서는 기간을 변경할 수 있습니다. |
| 내보내기 | 현재 필터를 반영하는 **Export CSV**. SIEM으로의 스트리밍 피드는 없으므로, 더 긴 기록을 유지하려면 일정에 따라 내보내세요. |

자격 증명 항목에는 값이나 키 이름이 절대 포함되지 않습니다. [감사 로그](/guide/security/audit-logs)를 참조하세요.

Free 또는 Team에서는 자체 CloudTrail에서 에이전트가 AWS에서 수행한 작업을 감사하세요. CloudThinker용으로 만든 역할([설정 템플릿](/ko/guide/connections/aws)을 사용했다면 `CloudThinkerAccessRole`)로 이벤트를 필터링합니다.

## 암호화 및 세션

| 계층 | CloudThinker의 조치 |
|---|---|
| 전송 중 | 앱과 API는 HTTPS로 제공됩니다 |
| 저장된 시크릿 | 연결 자격 증명, 워크스페이스 자격 증명, BYOK 키, 통합 토큰은 Fernet(AES-128 및 HMAC-SHA256)으로 저장 시 암호화됩니다. 키는 CloudThinker가 관리합니다. 고객 관리형 암호화 키는 제공되지 않습니다. [BYOK](/ko/guide/byok)는 암호화 키가 아니라 LLM 자격 증명을 다룹니다. |
| 비밀번호 | 모든 계정 비밀번호는 bcrypt 해시로 저장됩니다 |
| 세션 | 액세스 토큰은 RS256으로 서명됩니다. 리프레시 토큰은 사용 시 교체되며 해시로 저장됩니다. |

## 프로덕션을 연결하기 전에

- 각 연결은 에이전트에 필요한 계정과 리전으로 한정된 읽기 전용 자격 증명으로 시작하세요.
- 프로덕션 워크스페이스는 **Manual**로 유지하거나, 사람이 승인해야 하는 프로덕션 쓰기에 대해 **Ask first** [Rule](/guide/approvals/rules)을 추가하세요.
- 모든 Owner와 Admin에게 2FA를 켜도록 요청하거나, 로그인이 아이덴티티 제공자의 MFA 정책을 따르도록 SSO를 강제하세요.
- 각 멤버에게 맞는 가장 낮은 역할을 부여하세요.
- **Settings → Organization → Guardrails**에서 기본 제공 보호 기능을 확인하고, 자체 ID 형식에 대한 패턴을 추가하세요.

보안 설문이나 전용 배포가 필요하면 [문의하세요](https://cloudthinker.io/contact).

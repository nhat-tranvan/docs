[Code Audit](/ko/guide/security/code-audit)의 **Libraries**는 수집된 종속성 버전과 권고문 증거를 표시합니다. 버전 일치, 앱 영향, 소스 항목 검증은 서로 다른 판정입니다.

## 사전 요구 사항

- Code Audit와 라이브러리 검사를 사용할 수 있는 환경.
- 지원되는 종속성 파일과 확인된 버전이 있는 저장소.
- 브랜치 모니터링을 위한 게시된 완전한 목록.

## 목록 확인

감사 보고서는 평가한 커밋의 목록을 유지합니다. 브랜치 페이지는 마지막 완전한 목록과 현재 권고문 결과를 표시합니다.

| 상태 | 의미 |
| --- | --- |
| **Complete extraction** | 지원되는 범위에서 수집이 완료되었습니다 |
| **Incomplete extraction** | 종속성 정보가 부족합니다 |
| **Stale inventory** | 오래된 완전한 목록을 사용합니다. 새 스캔으로 갱신하세요 |
| **Last successful advisory check** | 마지막으로 성공한 검사 시각 |
| **Advisory evidence as of** | 저장된 증거의 최신성 |

저장소 목록은 배포된 라이브러리를 증명하지 않습니다. 미확인 패키지나 불완전한 수집은 안전의 증거가 아닙니다.

## 증거와 영향 확인

라이브러리를 열어 버전, 사용 위치, 권고문을 확인합니다. 일치는 종속성이 영향을 받을 가능성을 나타냅니다. 앱 영향 평가는 소스에 근거한 증거를 추가합니다.

불확실한 평가에는 부족한 증거나 조건이 남습니다. 영향 없음 판정도 기존 버전 일치를 지우지 않습니다. 과거 링크는 당시 증거를 보존합니다. Download로 평가를 공유하세요.

## 모니터링 관리

완전한 목록이 게시되면 새 소스 감사 없이 새로 알려진 취약점을 검사할 수 있습니다. 라이브러리 모니터링은 소스 감사 일정과 별개입니다.

**Pause monitoring**은 증거를 유지하고 갱신을 멈춥니다. **Resume monitoring**으로 갱신을 재개합니다. 이후 소스 감사도 명시적 일시 중지 선택을 유지합니다.

마지막 성공 시각과 증거의 최신성을 확인하세요. 일시 중지, 지연, 오래된 목록 상태에서 새 경고가 없다는 것은 안전을 뜻하지 않습니다.

## 문제 해결

완전한 목록이 필요하면 지원되는 종속성 파일로 감사합니다. 목록이 오래되면 현재 리비전을 스캔합니다. 소스 감사가 작동해도 Libraries가 없으면 관리자에게 확인하세요. 두 기능은 별도로 켤 수 있습니다.

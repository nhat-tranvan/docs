[Code Audit](/ko/guide/security/code-audit) 저장소의 **Issues** 탭에는 코드 이슈 옆에 브랜치가 사용하는 라이브러리 중 공개된 취약점과 일치하는 라이브러리가 나열됩니다. 버전 일치와 그것이 코드에 미치는 영향은 같은 브랜치의 소스 이슈와 별도로 판단됩니다.

## 사전 요구 사항

- Code Audit이 읽을 수 있는 lock 파일이나 의존성 파일이 있고, Code Audit이 모니터링하는 저장소.
- 완료된 감사 한 번. 감사가 라이브러리를 수집하며, 새 권고(advisory) 확인에는 그 인벤토리가 필요합니다.
- **Run library scan now**와 **Open fix pull request**에는 Admin 또는 Developer 역할이 필요합니다. Viewer는 라이브러리와 보고서를 읽을 수 있습니다.

## 라이브러리 확인 방식

- 각 감사는 감사의 나머지 부분이 실패하더라도 고정된 커밋이 선언한 라이브러리를 수집합니다.
- 그 후 Code Audit은 다른 감사 없이도 스스로 인벤토리를 새로 공개된 권고와 계속 대조합니다. 일시 중지하거나 재개할 필요가 없습니다.
- 일치하는 각 권고에 대해 에이전트가 코드가 영향받는 동작을 사용하는지 평가합니다. 공개 웹에서 권고를 조사하며, 검색에 저장소의 내용을 보내지 않습니다.

인벤토리는 프로덕션에서 실행되는 것이 아니라 저장소가 선언한 것을 나열합니다. 비공개 패키지나 정확한 버전이 없는 패키지처럼 Code Audit이 확인할 수 없었던 라이브러리는 안전한 것이 아니라 확인되지 않은 것으로 표시됩니다.

## Issues 목록에서 라이브러리 찾기

**Code audit**에서 저장소를 열고 **Issues** 탭을 선택합니다. 라이브러리만 보려면 **Type** 필터를 **Libraries**로 설정하고, 코드 이슈와 함께 순위를 매기려면 **All types**를 유지하세요. 각 라이브러리 행에는 이름, 버전, 생태계가 약점 **A06**(취약한 구성 요소)과 함께 표시됩니다.

| 레이블 | 읽는 방법 |
| --- | --- |
| **Affected** | 권고 일치가 확인된 열린 라이브러리 |
| **Needs review** | 확인으로 아직 결론을 내지 못한 열린 라이브러리 |
| **Last checked** / **Next check** | 권고 확인이 마지막으로 실행된 시점과 다음 실행 시점으로, 목록 위에 표시됩니다 |
| **Collection is incomplete. A clean result cannot be established.** | 일부 의존성 파일을 읽을 수 없었으므로, 빈 목록이 안전하다는 증거가 아닙니다 |

## 라이브러리의 영향 읽기

라이브러리를 클릭하면 코드 이슈와 같은 이슈 페이지가 열립니다. 페이지에는 **CVE**, 생태계, 의존성과 사용 방식, **Matched advisories**, **Source trace**, **Source evidence**, 에이전트의 **Verification**이 표시됩니다.

일치하는 권고는 라이브러리가 영향받을 수 있다는 뜻입니다. 평가는 한 걸음 더 나아가 코드가 취약한 동작에 도달하는지 묻습니다. 이를 결론 낼 수 없으면 부족한 증거나 조건을 나열합니다.

영향 없음 평가가 권고 일치를 지우지는 않습니다. 소스 이슈, 라이브러리 증거, [Pentest](/ko/guide/security/security-testing) 증명은 서로 다른 세 가지 질문에 답합니다. 공유하려면 라이브러리의 작업에서 **Download Markdown**을 선택하세요.

## 지금 스캔하거나 라이브러리 수정하기

- 저장소의 **Issues** 목록 위에 있는 **Run library scan now**는 저장된 인벤토리를 현재 권고와 즉시 대조합니다. 모니터링되는 브랜치에서만 실행됩니다.
- 라이브러리 이슈 페이지의 **Open fix pull request**는 CloudThinker가 라이브러리를 업그레이드하거나 고정하고 검토할 pull request를 여는 채팅을 엽니다.
- **Retry library assessment**는 실패한 영향 평가를 다시 실행합니다.

수정 pull request는 저장된 증거를 바꾸지 않습니다. 다음 감사나 라이브러리 확인이 새 버전을 읽습니다.

모든 Cyber 문제를 한곳에서 보려면 [Cyber troubleshooting](/guide/security/cyber-troubleshooting)을 참조하세요.

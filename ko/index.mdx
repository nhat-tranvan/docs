## CloudThinker 동작 방식

모든 모듈은 동일한 에이전틱 루프를 따릅니다: **감지 → 분석 → 해결 → 검증**.

| 단계 | 수행 내용 |
|-------|--------------|
| **감지** | 에이전트가 연결된 소스의 신호를 모니터링합니다 — 메트릭, 비용 데이터, 풀 리퀘스트, 알림. |
| **분석** | 에이전트가 신호를 토폴로지, 히스토리, [팀 지식](/ko/guide/knowledge)과 연관지어 계획을 수립합니다. |
| **해결** | 계획이 설정한 자율 모드([Manual 또는 Auto](/ko/guide/auto-mode))에 따라 실행되며, 민감한 작업은 [승인](/ko/guide/approval)을 통해 제어됩니다. |
| **검증** | 에이전트가 결과를 확인하고, 다음 반복에서 더 나은 시작을 위해 메모리에 기록합니다. |

모든 단계가 아닌 루프 위에 머무르세요: 목표를 설정하고, 자율 모드를 선택하고, 판단이 필요할 때 개입하면 됩니다. [AgenticOps 필드 가이드](/ko/learn/aio/introduction)에서 루프의 기반이 되는 참조 아키텍처와 거버넌스 원칙을 확인할 수 있습니다.

## CloudThinker를 선택하는 이유

클라우드 운영은 Cost Explorer, Datadog, GitHub 등 분리된 콘솔 전반에 흩어져 있어 서로 상태를 공유하지 않습니다. 그래서 모든 인시던트, 비용 검토, 보안 수정은 사람이 직접 컨텍스트를 재조립하는 것에서 시작됩니다. CloudThinker는 이를 이미 컨텍스트를 보유한 에이전트 팀으로 대체합니다: 에이전트들은 환경을 지속적으로 모니터링하고, 정의된 가드레일 내에서 행동하며, 학습한 내용을 기록하여 다음 실행이 더 스마트하게 시작됩니다. 툴 난립 없이 더 큰 운영 팀의 레버리지를 얻을 수 있으며, 모든 작업은 감사 가능하고 승인 기반으로 진행됩니다. [빠른 시작](/ko/quickstart)부터 시작하거나, 플랫폼의 아키텍처와 도입 원칙에 대한 [AgenticOps 필드 가이드](/ko/learn/aio/introduction)를 읽어보세요.

## CloudThinker 동작 방식

모든 모듈은 동일한 에이전틱 루프를 따릅니다: **감지 → 분석 → 해결 → 검증**.

| 단계 | 수행 내용 |
|-------|--------------|
| **감지** | 에이전트가 연결된 소스의 신호를 모니터링합니다 — 메트릭, 비용 데이터, 풀 리퀘스트, 알림. |
| **분석** | 에이전트가 신호를 토폴로지, 히스토리, [팀 지식](/ko/guide/knowledge)과 연관지어 계획을 수립합니다. |
| **해결** | 계획이 설정한 자율 모드([Manual 또는 Auto](/ko/guide/auto-mode))에 따라 실행되며, 민감한 작업은 [승인](/ko/guide/approval)을 통해 제어됩니다. |
| **검증** | 에이전트가 결과를 확인하고, 다음 반복에서 더 나은 시작을 위해 메모리에 기록합니다. |

엔지니어는 모든 단계가 아닌 루프 위에 머뭅니다: 의도를 설정하고, 자율 모드를 선택하고, 판단이 필요한 수정 사항을 승인합니다. [AgenticOps 필드 가이드](/ko/learn/aio/introduction)에서 루프의 기반이 되는 참조 아키텍처와 거버넌스 원칙을 확인할 수 있습니다.

## CloudThinker를 선택하는 이유

인시던트 대응에서 엔지니어링 시간의 대부분은 조사에 쓰입니다: 누군가 수정 방안을 결정하기 전에 Datadog, CloudWatch, GitHub 등에서 컨텍스트를 다시 조립해야 하기 때문입니다. CloudThinker의 프론티어 조사 에이전트는 모든 문제에 대해 24시간 내내 이 작업을 수행하고, 근본 원인과 제안된 수정 방안을 엔지니어에게 전달해 승인을 받습니다. 모든 작업은 정책에 따라 감사 가능한 승인 기록과 함께 실행되며, 모든 실행 결과가 공유 메모리에 기록되어 다음 조사가 더 스마트하게 시작됩니다. 이것이 자가 치유 클라우드입니다. 동일한 에이전트가 그 조사 역량을 Review, Optimize, Cyber에도 발휘합니다. [하네스](/ko/guide/harness)에서 그 방식을 확인하거나, [빠른 시작](/ko/quickstart)부터 시작하세요.

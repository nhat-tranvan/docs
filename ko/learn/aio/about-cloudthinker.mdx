*CloudThinker는 Frontier Investigation Agents를 만듭니다. 클라우드 전반의 문제를 조사하고 수정을 제안하는 에이전트입니다. 쓰기 작업은 승인 정책에 따라서만 실행됩니다.*

이 페이지는 필드 가이드의 각 실천 방법을 제품 페이지에 대응시키므로, 파일럿을 실행하기 전에 모든 주장을 확인할 수 있습니다.

## CloudThinker란

모든 워크스페이스에는 역시 **CloudThinker**라고 불리는 기본 제공 어시스턴트가 하나 있습니다. 이 어시스턴트는 큰 작업을 병렬로 일하는 임시 서브에이전트에게 나누어 맡기며, 팀은 자체 시스템을 위한 [커스텀 에이전트](/ko/guide/agents/customize)를 추가할 수 있습니다. [에이전트 개요](/ko/guide/agents/overview)에서 이들이 어떻게 함께 동작하는지 설명합니다.

에이전트는 [연결](/ko/guide/connections/overview)을 통해 작업합니다. 연결은 CloudThinker가 시스템에 도달하기 위해 사용하는 저장된 자격 증명으로, AWS, Azure, Google Cloud, [GreenNode](/guide/connections/greennode)와 [FPT Cloud](/guide/connections/fptcloud) 같은 로컬 클라우드, Kubernetes, 데이터베이스, 관측성 도구 등이 있습니다. 온프레미스 시스템은 [VMware](/guide/connections/vmware), [OpenStack](/guide/connections/openstack), [SSH](/ko/guide/connections/ssh), 또는 [Environment](/guide/workers)를 통해 도달할 수 있습니다. Environment는 CloudThinker가 아웃바운드 연결로 파일을 읽고 명령을 실행하는, 자신의 머신에 있는 폴더입니다.

각 요청은 하나의 루프를 거칩니다. 문제를 감지하고, 근본 원인을 분석하고, 승인 정책에 따라 해결하고, 수정이 유지되는지 검증합니다([전체 설명](/ko)).

## 제품

| 제품 | 하는 일 | 시작하기 |
| :---- | :---- | :---- |
| **Resolve** | 인시던트를 조사하고, 근본 원인을 찾고, 승인되면 실행되는 수정을 제안합니다 | [Resolve 개요](/ko/guide/incident/overview) |
| **Review** | 모든 풀 리퀘스트나 머지 리퀘스트를 리뷰하고 발견 항목을 댓글로 게시합니다 | [Review 개요](/ko/guide/code-review/overview) |
| **Cyber** | 실행 중인 웹 앱과 API를 테스트하고 각 발견 항목을 증거로 증명합니다 | [Cyber 개요](/guide/security/cyber-overview) |
| **Optimize** | 클라우드 비용 낭비를 찾고 절감 방안을 권고합니다 | [Optimize 개요](/ko/guide/cost-optimization/overview) |
| **Customize** | 워크스페이스에서 에이전트가 일하는 방식을 정합니다: 커스텀 에이전트, 스킬, 자격 증명, 승인 | [Customize](/ko/guide/agents/customize) |
| **Automation** | 일정, 웹훅 호출, 저장소 이벤트 또는 프로브에 따라 에이전트 지침을 실행합니다 | [Automations](/guide/automation/automations) |

모든 제품이 같은 연결, 승인 정책, 감사 추적을 공유합니다.

## 필드 가이드의 통제가 있는 곳

| 이 가이드의 실천 방법 | CloudThinker 기능 |
| :---- | :---- |
| 한 단계씩 얻어 내는 자율성([챕터 7](/ko/learn/aio/chapter-7-humans-on-the-loop)) | [Approval mode](/guide/approvals/approval-mode): **Manual**(사람이 모든 쓰기를 승인) 또는 **Auto**(Rules 우선, 선택적 AI 판단, 그다음 사람에게 묻거나 거부) |
| 작업별 실행 정책([챕터 6](/ko/learn/aio/chapter-6-trust-governance)) | 특정 쓰기 작업을 허용, 먼저 묻기 또는 거부하는 [Approval Rules](/guide/approvals/rules) |
| 루프 위의 인간([챕터 7](/ko/learn/aio/chapter-7-humans-on-the-loop)) | 승인을 기다리는 작업을 검토하는 사람인 [Approvers](/guide/approvals/approvers) |
| 모델로부터 보호되는 민감한 데이터([§6.3](/ko/learn/aio/chapter-6-trust-governance)) | [Guardrails](/guide/security/custom-guardrails)는 이메일, 카드 번호, API 키, 자체 ID 패턴 대신 자리표시자를 에이전트에게 보여 줍니다 |
| 자신의 계정으로 하는 모델 호출 | [BYOK](/ko/guide/byok)(자체 LLM 자격 증명 사용) |
| 변경 관리를 위한 증거 | **Settings → Organization → Audit log**의 [Audit Logs](/guide/security/audit-logs) |
| 데이터 상주 | [배포 옵션](/ko/guide/deployment/overview): CloudThinker Cloud, 그리고 자신의 머신에서 실행해야 하는 작업을 위한 Cloud와 [Environments](/guide/workers)(베타). 전용, 셀프 호스팅, 에어갭 배포는 디자인 파트너 프로그램을 통한 얼리 액세스입니다. 호스팅 리전은 공개되어 있지 않으니 문의하세요. |
| 메모리 레이어([챕터 9](/ko/learn/aio/chapter-9-roadmap)) | [Memory](/guide/memory) |

## 90일 파일럿 실행

[챕터 9](/ko/learn/aio/chapter-9-roadmap)는 권고 전용으로 시작하고 증거를 바탕으로 자율성을 얻어 내라고 권합니다. CloudThinker에서 첫 주는 세 가지 조치로 이루어집니다.

<Note>
**사전 요구사항:** Approval mode를 바꾸려면 워크스페이스 Admin 역할이 필요합니다. 다른 역할에게는 선택기가 보기 전용으로 표시됩니다.
</Note>

<Steps>
  <Step title="워크스페이스를 Manual로 전환">
    새 워크스페이스는 **Auto · Rules + AI · Ask me**로 시작하므로, 무엇이든 연결하기 전에 바꾸세요. **Settings → Workspace → Autonomy → Rules**를 엽니다. **When no Rule matches**에서 **Workspace mode**를 **Manual**로 설정합니다.

    [Automations](/guide/automation/automations)를 실행할 계획이라면, 같은 섹션의 **Automations** 행에서 **Override**를 클릭하고 **Manual**도 선택하세요. 이 행의 기본값은 **Auto · Rules + AI · Refuse**이며 워크스페이스 모드를 따르지 않습니다.

    **성공 상태:** 선택기에 **Manual**이 표시되고, 모든 쓰기 작업이 사람을 기다립니다. 읽기는 계속 실행됩니다.
  </Step>
  <Step title="범위가 제한된 저위험 시스템 하나를 읽기 전용으로 연결">
    스테이징 Kubernetes 클러스터나 비프로덕션 AWS 계정 하나처럼 실험해도 괜찮은 것을 고르세요. [AWS](/ko/guide/connections/aws#필요한-권한), [Azure](/ko/guide/connections/azure), [Google Cloud](/ko/guide/connections/gcp) 설정처럼 읽기 전용 IAM 역할이나 서비스 계정을 사용합니다. [빠른 시작](/ko/quickstart)을 따라 연결에 추가하세요.

    **성공 상태:** 연결에 **Connected** 상태가 표시됩니다.
  </Step>
  <Step title="기준선을 기록하고 매달 비교">
    페이징 및 티켓 도구에서 최근 90일간의 평균 해결 시간(MTTR)과 주당 호출 수를 내보내고, 월간 클라우드 비용을 기록하세요. CloudThinker는 연결하기 전의 시간을 측정할 수 없습니다. [Resolve Insights](/guide/incident/insights)는 Resolve가 알림 소스에서 인시던트를 받기 시작하면 추적을 시작합니다. 어떤 지표를 고를지는 [챕터 8](/ko/learn/aio/chapter-8-measuring)에서 다룹니다.

    **성공 상태:** 30일, 60일, 90일에 **Resolve → Insights**와 비교할 날짜가 기록된 기준선이 있습니다.
  </Step>
</Steps>

이후 단계(Approvers, Allow Rules, **Auto**로 전환)는 [§9.6](/ko/learn/aio/chapter-9-roadmap)을 따르세요. Allow Rules는 **Auto**에서만 쓰기 작업을 단독으로 실행합니다. **Manual**은 모든 쓰기 작업을 사람을 위해 보류합니다.

평가에는 [§6.3](/ko/learn/aio/chapter-6-trust-governance)의 여덟 가지 데이터 통제 질문을 가져오세요. 프라이빗 배포나 조달 관련 질문은 [팀에 문의](https://cloudthinker.io/contact)하세요.

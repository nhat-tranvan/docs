신규 고객이 가장 많이 묻는 질문에 짧게 답하고, 자세한 내용은 해당 페이지로 연결합니다. 찾는 질문이 없다면 [문의하세요](https://cloudthinker.io/contact).

## 시작하기

<AccordionGroup>
  <Accordion title="CloudThinker란 무엇인가요?">
    CloudThinker는 프론티어 조사 에이전트(Frontier Investigation Agents)를 만듭니다. 이 AI [에이전트](/ko/guide/agents/overview)는 클라우드, 코드, 도구에 연결해 인시던트, 코드 위험, 비용 낭비, 보안 공백의 근본 원인을 찾아내고, 엔지니어가 승인할 수 있는 해결 방안을 제안합니다.

    CloudThinker에는 문제 유형별로 네 가지 제품이 있으며, 하나씩 도입할 수 있습니다.

    | 제품 | 하는 일 |
    |---|---|
    | [Resolve](/ko/guide/incident/overview) | 인시던트를 조사하고 근거와 함께 근본 원인을 찾습니다 |
    | [Review](/ko/guide/code-review/overview) | 풀 리퀘스트를 리뷰하고 인라인 코멘트와 수정 제안을 남깁니다 |
    | [Cyber](/guide/security/cyber-overview) | 테스트 권한이 있는 앱에 동적 보안 테스트를 실행하고 각 발견 사항을 추적합니다 |
    | [Optimize](/ko/guide/cost-optimization/overview) | 유휴 리소스, 과대 인스턴스, 비용 이상 징후를 우선순위별로 정리합니다 |

    세 가지 지원 영역은 직접 조사하지 않고 네 제품 전반에서 함께 작동합니다.

    | 영역 | 하는 일 |
    |---|---|
    | [Approvals](/guide/approvals/overview) | 어떤 에이전트 변경을 자동으로 실행하고, 사람의 확인을 기다리고, 거부할지 결정합니다 |
    | [Customize](/ko/guide/agents/customize) | 에이전트의 작동 방식을 정합니다: 커스텀 에이전트, 스킬, 지식 |
    | [Automation](/guide/automation/automations) | 일정에 따라, 웹훅이 발생할 때, 리포지토리 이벤트가 있을 때, 프로브 점검이 작동할 때 프롬프트를 실행합니다 |
  </Accordion>

  <Accordion title="첫 답변을 얻기까지 얼마나 걸리나요?">
    약 10분입니다. [빠른 시작](/ko/quickstart)에서 [app.cloudthinker.io](https://app.cloudthinker.io)에 로그인하고, 시스템 하나를 읽기 전용으로 연결한 뒤, 첫 질문을 하는 과정을 안내합니다.

    **성공 상태:** 답변에 사용 중인 환경에서 익숙한 서비스, 리전, 리소스가 나타납니다.
  </Accordion>

  <Accordion title="프로덕션을 위험에 빠뜨리지 않고 먼저 써볼 수 있나요?">
    네. 읽기 전용 역할로 스테이징 또는 샌드박스 계정을 연결하고, 연결에서 **Allow writes**를 꺼서 CloudThinker가 모든 변경을 거부하게 하세요. 에이전트는 볼 수만 있고 아무것도 변경할 수 없습니다. [빠른 시작](/ko/quickstart)을 참고하세요.
  </Accordion>

  <Accordion title="조직과 워크스페이스는 어떻게 다른가요?">
    **조직**은 계정 단위입니다. 플랜, 결제, 멤버 목록, SSO, BYOK, 감사 로그가 여기에 속하며, 역할은 Owner, Admin, Developer, Viewer입니다. **워크스페이스**는 조직 안에 있으며 실제 작업을 담습니다. 연결, 에이전트, 스킬, 대화, 승인이 여기에 속하며, 역할은 Admin, Developer, Viewer입니다.

    | 설정 영역 | 대상 | 여는 위치 |
    |---|---|---|
    | **Admin Settings** | 조직 (Owner와 Admin만) | 사이드바 하단의 아바타, 그다음 **Admin settings** |
    | **Workspace settings** | 현재 워크스페이스 | 사이드바의 **More → Workspace settings** |
    | **Account Settings** | 나 자신: 프로필, 2FA, 내 이메일 알림 | 아바타 메뉴 |

    [조직](/ko/guide/organization)과 [워크스페이스](/ko/guide/workspaces)를 참고하세요.
  </Accordion>

  <Accordion title="팀원은 어떻게 초대하나요?">
    조직 Owner 또는 Admin이 **Admin Settings → Organization**으로 이동해 **Invite Members**를 클릭합니다. 각 멤버에게 조직 역할이 부여되며, **More → Workspace settings → Members**에서 특정 워크스페이스에만 다른 역할을 줄 수도 있습니다. [멤버 추가](/ko/guide/organization#멤버-추가)와 [워크스페이스 멤버](/ko/guide/workspace-users)를 참고하세요.
  </Accordion>

  <Accordion title="CloudThinker는 어떤 시스템에 연결할 수 있나요?">
    AWS, Google Cloud, Azure 같은 클라우드와 Kubernetes, 데이터베이스, 관찰 가능성 도구, Git 공급자, CI/CD, 그리고 Jira, ServiceNow, PagerDuty 같은 티켓 도구에 연결할 수 있습니다. 각각은 하나의 서비스에 대한 자격 증명인 **연결**이며, **More → Workspace settings → Connections**에서 추가합니다.

    전체 목록은 [연결 카탈로그](/ko/guide/connections/overview)에 있습니다. 목록에 없는 도구라도 그 앞에서 MCP 서버를 운영한다면, 해당 서버를 [MCP 연결](/ko/guide/connections/mcp)로 추가해 에이전트가 그 도구를 호출하게 할 수 있습니다.
  </Accordion>

  <Accordion title="설치하거나 아키텍처를 바꿔야 하나요?">
    아니요. CloudThinker는 관리형 서비스로 실행되며, 사용자가 추가한 연결을 통해 부여한 자격 증명과 권한으로 시스템에 접근합니다.

    노트북이나 CI 러너처럼 직접 관리하는 머신에서 명령을 실행하고 싶다면 [Worker](/guide/workers)(베타)를 추가할 수 있습니다. 선택 사항입니다. 에이전트가 비공개 리포지토리나 내부 호스트에 접근해야 할 때 사용하세요. Worker는 HTTPS로 바깥쪽으로 연결하므로 인바운드 포트를 열 필요가 없습니다.

    이 문서에는 CloudThinker의 egress IP 주소가 게시되어 있지 않습니다. 방화벽에 허용 목록이 필요하다면 [문의하기](https://cloudthinker.io/contact)를 통해 요청하세요.
  </Accordion>

  <Accordion title="Slack이나 Teams에서 CloudThinker를 쓰려면 어떻게 하나요?">
    조직 Owner 또는 Admin이 **Admin Settings → Integrations**로 이동해 **Slack** 카드를 열고 **Connect with Slack**을 클릭합니다. 그다음 채널에 봇을 초대하세요. 채팅 앱은 Team 플랜 이상이 필요합니다. Slack과 Microsoft Teams에서는 승인이 필요한 쓰기 작업이 웹 앱 링크로 연결되며, 웹 앱에서 승인합니다. Google Chat은 카드에 **Approve**와 **Reject** 버튼이 바로 표시됩니다. [Slack](/ko/guide/slack-integration), [Microsoft Teams](/ko/guide/teams-integration), [Google Chat](/guide/google-chat-integration)을 참고하세요.
  </Accordion>

  <Accordion title="연결을 제거하거나 데이터를 삭제하려면 어떻게 하나요?">
    워크스페이스 Admin은 **More → Workspace settings → Connections**에서 연결을 삭제할 수 있습니다. 연결, 대화, 설정을 포함한 워크스페이스 전체를 제거하려면 조직 Owner 또는 Admin이 **Admin Settings → Workspaces**를 사용합니다. 복원은 불가능합니다. [워크스페이스](/ko/guide/workspaces)를 참고하세요.
  </Accordion>
</AccordionGroup>

## 에이전트와 안전

<AccordionGroup>
  <Accordion title="에이전트는 누구인가요?">
    모든 워크스페이스에는 기본 제공 에이전트 **CloudThinker**가 하나 있습니다. 항상 켜져 있으며, 큰 작업을 임시 서브에이전트에게 나눠 맡길 수 있습니다. 팀은 자체 지침과 스킬을 가진 커스텀 에이전트를 만들 수도 있습니다. [에이전트](/ko/guide/agents/overview)와 [Customize](/ko/guide/agents/customize)를 참고하세요.
  </Accordion>

  <Accordion title="특별한 명령어를 배워야 하나요?">
    아니요. 일상적인 말로 충분하며, 멘션이 없으면 CloudThinker가 답합니다. 선택 사항인 세 가지 기호로 요청을 더 정확하게 만들 수 있습니다.

    | 기호 | 선택 대상 | 예시 |
    |---|---|---|
    | `@` | 에이전트 | `@CloudThinker` |
    | `#` | 연결 또는 지식 베이스 | `#aws-prod` |
    | `/` | 스킬 또는 명령 | `/resource-rightsizing-analysis` |

    ```text
    Which EC2 instances in us-east-1 averaged under 5% CPU last week?
    @CloudThinker #aws-prod which RDS instances averaged over 80% CPU yesterday?
    Show last month's cost by service as a dashboard
    ```

    대시보드나 보고서 같은 출력 형태는 말로 요청하세요. 전체 문법: [명령어](/guide/commands).
  </Accordion>

  <Accordion title="에이전트가 프로덕션 시스템을 마음대로 변경할 수 있나요?">
    사용자가 정한 한도 안에서만 가능합니다. 읽기는 항상 실행됩니다. 모든 **쓰기**(서비스 재시작처럼 연결된 시스템을 변경하는 에이전트 호출)는 다음 점검을 순서대로 거칩니다.

    1. **항상 차단**: CloudTrail 로깅 중지나 `kube-system` 네임스페이스 삭제처럼 절대 실행되지 않는 기본 제공 호출 목록입니다. 어떤 설정도 이를 덮어쓸 수 없습니다.
    2. 사용자의 **Rules**: 특정 종류의 쓰기를 허용하거나, 먼저 묻거나, 거부합니다. **Manual**에서는 Allow Rule이 있어도 쓰기가 실행되지 않고 사람에게 전달됩니다. Rules는 CloudThinker가 워크스페이스에 Rule 적용을 켠 뒤에만 판단합니다. 기본값은 꺼짐이며, 그때까지 Rules는 내렸을 판정만 기록하고 Approval mode가 단독으로 결정합니다([자세히](/guide/approvals/rules#troubleshooting)).
    3. **Approval mode**: **Manual**은 모든 쓰기에 대해 사람에게 묻습니다. **Auto**는 AI 판단으로 안전한 쓰기를 허용하고, 나머지는 사람에게 묻거나 거부합니다.
    4. 승인자: 승인하거나 거절합니다.

    한 가지 예외가 있습니다. Review에서 **Apply fix**와 **Fix all findings**는 사람이 클릭하면 이 점검을 거치지 않고 풀 리퀘스트의 소스 브랜치에 커밋합니다.

    Approval mode 자체는 실시간으로 적용되며, 새 워크스페이스는 **Auto · Rules + AI · Ask me**로 시작합니다. 세 부분으로 읽으세요. 모드는 **Auto**이고, 쓰기는 **Rules + AI** 판단으로 결정되며, 여전히 허용되지 않은 것은 사람을 기다립니다(**Ask me**). 예를 들어 방금 질문한 스테이징 파드의 재시작은 실행될 수 있습니다. RDS 스냅샷 삭제는 파괴적이므로 먼저 묻습니다.

    쓰기가 대기 중이면 채팅에 **Approve**와 **Decline**이 있는 승인 카드가 표시됩니다. 기본적으로 워크스페이스의 모든 Developer 또는 Admin이 응답할 수 있습니다. [Approvers](/guide/approvals/approvers)에서 범위를 좁힐 수 있습니다. Slack이나 Microsoft Teams의 요청은 웹 앱으로 연결되며, 웹 앱에서 승인합니다. Google Chat에서는 카드에서 바로 승인하거나 거부할 수 있습니다.

    모든 쓰기에 사람이 필요하게 하려면 워크스페이스를 **Manual**로 전환하세요. 그다음 [Run types](/guide/approvals/approval-mode#set-a-mode-for-a-run-type)에서 **Automations**(및 변경한 다른 실행 유형)도 **Manual**로 재정의하세요. Automations 행의 기본값은 **Auto · Rules + AI · Refuse**이며 워크스페이스를 따르지 않습니다. Automation이나 채팅이 자체 모드를 선택할 수도 있습니다. [Approvals](/guide/approvals/overview)와 [Approval mode](/guide/approvals/approval-mode)를 참고하세요.
  </Accordion>

  <Accordion title="CloudThinker는 내 클라우드에서 어떤 권한이 필요한가요?">
    시작에는 읽기 전용이면 충분합니다. 두 가지 통제 수단이 에이전트가 할 수 있는 일을 정합니다.

    | 통제 수단 | 위치 | 결정하는 것 |
    |---|---|---|
    | 자격 증명 자체의 권한 | 사용 중인 공급자 (IAM 역할, 서비스 계정, API 토큰 범위) | 상한선. 에이전트는 이보다 더 많은 일을 하지 않습니다. |
    | **Allow writes** | 연결의 상세 패널 | 꺼짐: 모든 변경이 거부됩니다. 켜짐: 변경이 Rules와 Approval mode를 거칩니다. |

    권장하는 읽기 전용 시작 역할은 다음과 같습니다.

    | 클라우드 | 역할 | 설정 |
    |---|---|---|
    | AWS | CloudShell에서 실행하는 설정 스크립트가 만드는 관리형 `ReadOnlyAccess` 정책 | [AWS 설정](/ko/guide/connections/aws#설정) |
    | Google Cloud | **Viewer** (`roles/viewer`). Optimize에는 **BigQuery Data Viewer**와 **BigQuery Job User**를 추가하세요. | [Google Cloud](/ko/guide/connections/gcp) |
    | Azure | 구독의 **Reader**, 지출 확인용 **Cost Management Reader** 추가 | [Azure](/ko/guide/connections/azure) |

    **Allow writes**는 AWS, Google Cloud, Azure에서 기본적으로 켜져 있으므로 변경을 막는 것은 읽기 전용 자격 증명입니다. CloudThinker에서도 막으려면 연결의 상세 패널에서 스위치를 끄세요. 에이전트가 수행하길 원하는 특정 변경에 대해서만 쓰기 권한을 추가하세요. [연결](/ko/guide/connections/overview)을 참고하세요.
  </Accordion>
</AccordionGroup>

## 보안과 컴플라이언스

<AccordionGroup>
  <Accordion title="CloudThinker는 어떤 데이터를 저장하며 어떻게 보호하나요?">
    | 데이터 | 보호 방식 |
    |---|---|
    | 연결 자격 증명 | 저장 시 암호화됩니다. 명령이 실행될 때 CloudThinker 관리형 샌드박스에 주입되며, [Worker](/guide/workers)로는 절대 전송되지 않습니다. |
    | 대화, 발견 사항, 보고서 | 워크스페이스 범위로 제한되며 역할에 따라 볼 수 있습니다. 알려진 시크릿(연결 자격 증명, 워크스페이스 자격 증명, 채팅에서 저장한 값)은 저장되기 전에 플레이스홀더로 대체됩니다. |
    | 감사 로그 | 90일간 보관한 뒤 자동으로 삭제됩니다. 더 오래 보관하려면 CSV로 내보내세요 |
    | 계정 비밀번호 | bcrypt 해시로 저장됩니다 |

    앱과 API는 HTTPS로 제공됩니다. 조직이 [BYOK](/ko/guide/byok)(자체 LLM 자격 증명 사용)를 쓰지 않는 한 모델 호출은 CloudThinker의 LLM 공급자로 전달되며, BYOK를 쓰면 사용자의 AWS Bedrock, Anthropic, FPT Cloud, Claude Code 또는 Codex 계정을 통해 호출됩니다.

    이 문서는 호스팅 리전, 모델 공급자 이름과 데이터 약관, 학습 사용 여부, 대화 보관 기간을 다루지 않습니다. 벤더 검토를 시작할 때 [문의하기](https://cloudthinker.io/contact)를 통해 요청하세요. 자세한 내용: [보안과 신뢰](/ko/guide/security/overview).
  </Accordion>

  <Accordion title="누군가 채팅에 시크릿을 붙여넣으면 어떻게 되나요?">
    메시지가 전송되지 않습니다. CloudThinker가 API 키, 토큰, 비밀번호, 연결 문자열처럼 자격 증명으로 보이는 값을 검사하고 **Review detected secrets** 대화상자를 엽니다. 하나를 선택하세요.

    | 버튼 | 결과 |
    |---|---|
    | **Redact from message** | 각 값을 `[sensitive data removed]`로 대체합니다 |
    | **Save secrets** (워크스페이스 Admin만) | 각 값을 워크스페이스 자격 증명으로 저장하고 메시지를 `$KEY`로 다시 작성합니다 |

    오탐은 **Mark as not a secret**으로 표시하세요. 원본 값은 대화에 들어가지 않습니다. [데이터 보호](/guide/security/data-protection)를 참고하세요.
  </Accordion>

  <Accordion title="SSO를 쓰고, 2FA를 강제하고, 감사 추적을 남길 수 있나요?">
    | 통제 | 위치 | 플랜 |
    |---|---|---|
    | 인증 앱 (TOTP) | **Account Settings → 2FA** | 전체 |
    | SAML 2.0 또는 OIDC 기반 SSO, SCIM 동기화 | **Admin Settings → Identity and access** | Scale, Enterprise |
    | 감사 로그, 90일 보관, CSV 내보내기 | **Admin Settings → Audit Logs** | Scale, Enterprise |

    [싱글 사인온](/ko/guide/security/sso), [역할](/guide/security/roles), [감사 로그](/guide/security/audit-logs)를 참고하세요.
  </Accordion>

  <Accordion title="CloudThinker는 컴플라이언스 인증을 보유하고 있나요?">
    인증과 증명서는 이 문서에 게시되어 있지 않습니다. 최신 보고서, 보안 질문지, 데이터 처리 계약서가 필요하다면 [문의하세요](https://cloudthinker.io/contact). 팀이 제공 가능한 자료를 보내드립니다. 벤더 검토의 나머지 항목에 지금 답하려면 [보안과 신뢰](/ko/guide/security/overview)를 활용하세요.
  </Accordion>

  <Accordion title="CloudThinker를 우리 환경 안에서 실행할 수 있나요?">
    기본적으로 `app.cloudthinker.io`에서 관리형 서비스로 실행됩니다. [Worker](/guide/workers)는 셀프서비스이며 베타이고, 직접 관리하는 머신에서 파일 및 셸 작업을 실행합니다. 전용, 셀프 호스팅, 에어갭 배포는 디자인 파트너 프로그램을 통해 얼리 액세스로 제공됩니다. [배포](/ko/guide/deployment/overview)를 참고하세요.
  </Accordion>
</AccordionGroup>

## 요금제

<AccordionGroup>
  <Accordion title="CloudThinker 요금은 어떻게 책정되나요?">
    조직 전체에 월 고정 요금 하나이며 멤버는 무제한입니다. 각 유료 플랜은 에이전트 작업이 소비하는 단위인 **크레딧**을 월간 풀로 제공하고, 모든 워크스페이스가 이를 공유합니다. 플랜은 Free, Team, Scale, Enterprise입니다.

    | 플랜 | 월 요금 | 월간 크레딧 | 워크스페이스 |
    |---|---|---|---|
    | Free | 무료 | 없음 | — |
    | Team | $99 | 1,000 | 3 |
    | Scale | $499 | 5,000 | 10 |
    | Enterprise | 별도 견적 | Pay-As-You-Go | 무제한 |

    조직에는 Light 모델 채팅용 무료 크레딧도 매일 100개 제공됩니다. 매일 UTC 자정에 초기화됩니다.

    각 실행은 세 가지 모델 등급 중 하나를 사용하며, 등급에 따라 크레딧 차감량이 달라집니다. 빠른 질문에는 **Light**(0.3x), 일상적인 작업에는 **Pro**(1.0x, 기본값), 가장 어려운 문제에는 **Ultra**(1.7x)를 사용합니다.

    크레딧이 소진되면 더 많은 크레딧이 필요한 실행은 차단됩니다. Team 이상에서는 Owner가 [Pay-As-You-Go](/ko/guide/billing/usage#pay-as-you-go)를 켤 수 있습니다. 크레딧당 $0.10의 사용량 기반 충전이며, 직접 정한 월 한도까지 적용됩니다. 현재 요금과 한도: [요금제](/ko/guide/billing/pricing). 실행이 크레딧을 소비하는 방식: [사용량](/ko/guide/billing/usage).
  </Accordion>

  <Accordion title="Free 플랜에서는 무엇을 할 수 있나요?">
    Light 모델의 직접 채팅을 사용할 수 있습니다: 웹 채팅, Rooms(다른 사람과 공유하는 채팅), CLI의 [헤드리스 채팅](/ko/guide/cli/headless-chat). 대화형 [CLI 에이전트](/ko/guide/cli/overview)는 Team 이상이 필요합니다. Review, Resolve, Optimize, Cyber, Automation 같은 그 밖의 실행은 "The Free plan only supports direct chat."라는 메시지와 함께 거부됩니다. 이를 잠금 해제하고 Pro와 Ultra 모델을 쓰려면 Team 이상으로 업그레이드하세요.
  </Accordion>

  <Accordion title="무료 체험이 있나요?">
    조건을 충족하는 Free 조직은 **Admin Settings → Billing → Upgrade Plan**의 Team 카드에서 **Start 14-Day Free Trial**을 볼 수 있습니다. 14일 동안 Team 기능을 사용합니다. Pay-As-You-Go(풀이 소진된 뒤의 유료 충전 크레딧)는 체험 기간 동안 꺼져 있습니다.

    Team을 계속 쓰려면 Owner가 **Admin Settings → Billing → Upgrade Plan**을 열고 Team 카드에서 **Add payment method**를 클릭합니다.

    <Warning>
      체험이 끝나기 전에 결제 수단을 추가하지 않으면 조직이 Free로 돌아갑니다. 직접 채팅을 제외한 실행이 중단되고 Pro와 Ultra 모델이 잠깁니다.
    </Warning>
  </Accordion>

  <Accordion title="어떤 플랜이 필요한가요?">
    | 원하는 것 | 최소 플랜 |
    |---|---|
    | 비용 없이 채팅으로 CloudThinker 체험 | Free |
    | Review, Resolve, Optimize, Cyber 실행 또는 Slack, Teams, Google Chat에서 답변 받기 | Team |
    | SSO 사용, 감사 추적 유지, BYOK 사용, 워크스페이스별 지출 한도 설정 | Scale |
    | 자체 인프라에서 CloudThinker 실행 | Enterprise, 얼리 액세스 디자인 파트너 프로그램을 통해 |

    플랜은 조직 **Owner**만 변경할 수 있습니다. [요금제](/ko/guide/billing/pricing)를 참고하세요.
  </Accordion>
</AccordionGroup>

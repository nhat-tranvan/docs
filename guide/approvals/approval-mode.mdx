The Approval mode decides each agent write that no [Rule](/guide/approvals/rules) covers. Every run uses one of two modes, **Manual** or **Auto**: reads always run in both, and a run no person can answer refuses a write instead of hanging.

## The two modes

| Mode | What happens to a write that no Rule decides |
|------|----------------------------------------------|
| **Manual** | A person approves every write before it runs, also one that an **Allow** Rule covers. **Ask first** and **Deny** Rules still apply. |
| **Auto** | The write goes through three steps, in order, until one gives an answer |

Under **Auto**, each write goes through these steps:

1. **Your Rules** allow, ask, or deny the write. This step is always on.
2. **AI judgment** allows a safe write that no Rule covers. You can turn this step off.
3. **If still not allowed**, the write waits for a person (**Ask me**) or is refused (**Refuse**).

<Note>
Rules decide only when Rule enforcement is on for your workspace. It's off by default, and CloudThinker turns it on per workspace. If the **Rules** step on **Approvals** says **In preview**, Rules only record what they would decide, and the Approval mode alone decides each write. See [Rules in preview](/guide/approvals/rules#troubleshooting).
</Note>

That gives four Auto choices. The picker names each one by its steps:

| Choice | AI judgment | If still not allowed | Good for |
|--------|-------------|----------------------|----------|
| **Auto · Rules · Ask me** | Off | Asks a person | Teams that want only accepted Rules to run writes alone |
| **Auto · Rules · Refuse** | Off | Refused | Unattended runs with a tight, known set of writes |
| **Auto · Rules + AI · Ask me** | On | Asks a person | Most teams. This is the default for new workspaces. |
| **Auto · Rules + AI · Refuse** | On | Refused | Unattended runs. This is the built-in default for Automations. |

AI judgment allows a write that matches what you asked for and stays in its scope. A destructive write, or one with an unclear effect, goes to step 3. If AI judgment cannot finish its check, the write also goes to step 3.

## Set the workspace mode

<Steps>
  <Step title="Open the Approval mode tab">
    Open **Approvals** in the sidebar, then the **Approval mode** tab.
  </Step>
  <Step title="Pick the mode">
    Under **Workspace mode**, open the picker. Select **Manual**, or select **Auto** and set the **AI judgment** switch and **If still not allowed**.

    **Success state:** the picker shows your choice, such as **Auto · Rules + AI · Ask me**. It applies at once, with no confirm step.
  </Step>
</Steps>

You need the workspace Admin role to change a mode. Other roles see "View only. Ask a workspace admin to change these."

## Set a mode for a run type

A run type is where a run starts. Each one can use its own mode, also a looser one than the workspace.

<Steps>
  <Step title="Find the run type">
    On the **Approval mode** tab, go to **Run types**. Each row reads **Same as workspace** until you change it, except **Automations**, which shows its built-in **Auto · Rules + AI · Refuse** with a **Built-in** badge.
  </Step>
  <Step title="Override it">
    Click **Override** on the row (or the mode shown on **Automations**) and pick a mode. Click **Reset** later to follow the workspace again.

    **Success state:** the row shows the mode you picked instead of **Same as workspace**.
  </Step>
</Steps>

| Run type | Default | Can ask a person |
|----------|---------|------------------|
| **Chat** | Same as workspace | Yes |
| **Resolve** | Same as workspace | Yes |
| **Optimize** | Same as workspace | No |
| **Automations** | **Auto · Rules + AI · Refuse** (built in) | Yes |
| **Review** | Same as workspace | No |

No person can answer an Optimize or Review run, so **Ask me** becomes **Refuse** there. A Resolve ask, such as one from a webhook incident overnight, waits on its card until someone answers. Turn on **Agent approvals** in [Notifications](/guide/notifications) so someone sees it.

## Set a mode for one Automation or one chat

- **One Automation:** open the [Automation](/guide/automation/automations) and use its approval picker. **Default** follows the **Automations** run type.
- **One chat:** open the approval control in the chat prompt box, or type `/` and pick **Approval**. **Reset to default** follows the run type and workspace again.

Anyone who can chat in a conversation can change its mode. A chat pick never changes the workspace mode. Before the first message your pick is a draft, and the first message saves it. Each change posts a note in the chat, and the agent follows the new mode from its next step.

Under **Chat composer**, an admin can turn off **Let people pick AI judgment for one chat**. People can then pick only **Manual**, or **Auto** with AI judgment off, for a single chat.

## Which mode a run uses

The most specific mode that someone set wins, even when it is looser:

<Frame caption="The most specific mode that someone set wins, even when it is looser.">
  <img src="/images/approvals/diagram-mode-precedence-light.svg" alt="The chat pick wins over the Automation's mode, which wins over the run type's mode, which wins over the workspace mode." className="block dark:hidden" style={{width: '100%'}} />
  <img src="/images/approvals/diagram-mode-precedence-dark.svg" alt="The chat pick wins over the Automation's mode, which wins over the run type's mode, which wins over the workspace mode." className="hidden dark:block" style={{width: '100%'}} />
</Frame>

1. The mode picked for this chat
2. The mode of the Automation that started the run
3. The mode of the run type
4. The workspace mode

For example, a workspace in **Manual** with **Automations** on **Auto · Rules + AI · Refuse** runs a scheduled Automation in Auto.

<Warning>
A chat pick can loosen a **Manual** workspace, for example to **Auto · Rules · Ask me**. The only admin control over chat picks is **Let people pick AI judgment for one chat** under **Chat composer**. Turn that off and every mode a chat can still pick either asks a person or refuses the write — today that is what keeps a write from running without someone. Once Rule enforcement is on for your workspace, an **Ask first** or **Deny** Rule does the same in every mode (see the note above).
</Warning>

To let an Automation run a routine write every night, accept an **Allow** Rule for that exact operation and connection, scoped to **Automations** under **Runs from**. Then, with Rule enforcement on, the run never depends on AI judgment or on someone being online.

## FAQ

<AccordionGroup>
  <Accordion title="Does Manual turn my Rules off?">
    No. **Ask first** and **Deny** Rules still apply. Manual only stops an **Allow** Rule or AI judgment from running a write without a person.
  </Accordion>
  <Accordion title="Why was a scheduled Automation refused instead of asking?">
    Automations use **Auto · Rules + AI · Refuse** by default, because no one may be there to answer. Accept a Rule for that write, or set the Automation to an **Ask me** choice.
  </Accordion>
  <Accordion title="Why does Ask me show as disabled for Optimize or Review?">
    No person answers those runs, so a write that is still not allowed is refused. Use a Rule to let a specific write run.
  </Accordion>
  <Accordion title="I can't pick AI judgment in a chat">
    You see "An admin turned off AI judgment in conversations." Ask a workspace Admin to turn on **Let people pick AI judgment for one chat** under **Chat composer**.
  </Accordion>
  <Accordion title="A destructive write is waiting for me. Is anyone else told?">
    Yes. A destructive write that waits for a person also raises a High alert. It reaches every channel on the **Alerts** row in [Notifications](/guide/notifications) whose severity threshold is High or lower.
  </Accordion>
</AccordionGroup>

Tony is CloudThinker's Database Engineer, specializing in query optimization, performance tuning, backup strategies, and data analytics across SQL and NoSQL platforms.

## How Tony works

1. **Connects to your databases** via read access — `pg_stat_statements`, MySQL Performance Schema, RDS Performance Insights, Aurora, MongoDB profiler.
2. **Identifies slow queries** by analyzing execution times, call frequency, and resource consumption — finding the highest-impact targets automatically.
3. **Reads execution plans** — Tony interprets EXPLAIN ANALYZE output to understand table scans, index misses, and join inefficiencies.
4. **Recommends with precision** — specific `CREATE INDEX` statements, query rewrites, and configuration changes with before/after impact estimates.
5. **Understands tradeoffs** — the write overhead of new indexes, the memory implications of configuration changes, and the downtime requirements of schema changes.

Tony proposes changes under your workspace's autonomy mode — Manual or Auto. See [Auto Mode](/guide/auto-mode) and [Approval](/guide/approval).

## Tool usage

| Tool | Tony use case |
|------|---------------|
| `#dashboard` | Query latency (P50/P95/P99), connections, I/O, replication lag |
| `#report` | Performance analysis, optimization recommendations, capacity planning |
| `#recommend` | Index changes, configuration updates, query rewrites |
| `#alert` | Slow queries, connection pool exhaustion, replication lag |
| `#visualize` | Query trends, resource utilization, growth patterns |

## Example prompts

Query performance:

```text
@tony #report the 20 slowest queries on production PostgreSQL with execution plans
@tony #recommend index changes prioritized by impact
@tony #alert when P95 query latency exceeds 500ms
```

Health and capacity:

```text
@tony #dashboard database performance metrics for the production cluster
@tony #visualize database growth patterns over the last 6 months
@tony #recommend an archiving strategy based on growth trends
```

Operations:

```text
@tony #report backup status and recovery readiness for production databases
@tony #recommend connection pool settings for high-load periods
@tony #alert on replication lag above 30 seconds
```

## Connection requirements

Tony requires database connections with performance metrics access:

| Platform | Required access |
|----------|----------------|
| **PostgreSQL** | `pg_stat_statements`, query logs, performance schema |
| **MySQL** | Performance Schema, slow query log, status variables |
| **RDS/Aurora** | Enhanced Monitoring, Performance Insights |
| **MongoDB** | Profiler, `serverStatus`, operation logs |

**Works the way your team works.**

Customize is how you shape the Frontier Investigation Agents (the built-in assistant and any custom agents you create) to your team: which agents exist, what procedures they follow, what documents and secrets they can use, where alerts go, and which changes need a person first. Everything here is per workspace and lives in **Settings**.

<CustomizeScene />

The built-in assistant, [CloudThinker](/guide/agents/overview), works without any of this setup.

## How it works

Each piece answers one question about how an agent behaves. You can set them up in any order.

1. **Who answers.** A custom agent has its own name, `@mention`, instructions, reply language, and connections.
2. **How it works.** Skills hold your procedures and rules. Knowledge holds documents the agent looks things up in.
3. **What it can reach.** Connections give access to your systems. Credentials hold any other secret a command needs, such as a vendor API key for a CLI the agent runs where no connection exists for that tool.
4. **What it may change.** Approvals decide whether each write runs, waits for a person, or is refused.
5. **Who hears about it.** Notifications route alerts to email, Slack, Teams, or Google Chat.

Two optional extras sit next to these: **Memory** holds what agents remember between conversations, and **Commands** saves prompts you rerun with `/`.

Skills, Knowledge, and Approvals are workspace-wide. Every agent, built-in or custom, sees the same enabled skills, the same knowledge bases, and the same approval policy. You can't limit a custom agent to certain skills or knowledge bases; scope it through its instructions and connections instead (see [Custom agents at a glance](#custom-agents-at-a-glance)). For example:

```text
Use the ec2-high-cpu-runbook skill for performance questions. Look up procedures in the Payments runbooks knowledge base first.
```

Instructions steer the agent; they don't block anything. Connections are the hard limit: an agent reaches only the connections attached to it.

## Where each setting lives

Open **Settings** from the gear icon in the chat prompt box, or open the workspace switcher and click your current workspace. Both open the same workspace settings. The settings rail groups the pages like this:

| Group | Page | What you set there | Guide |
|-------|------|--------------------|-------|
| Agent Configuration | **Connections** | The cloud accounts, clusters, databases, and tools agents can reach | [Connections](/guide/connections/overview) |
| Agent Configuration | **Skills** | Reusable procedures, and where each one applies | [Skills](/guide/skills/overview) |
| Agent Configuration | **Memory** | What agents remember between conversations | [Memory](/guide/memory) |
| Agent Configuration | **Agents** | Custom agents: identity, instructions, model tier, connections | [Custom agent quickstart](/guide/agents/quickstart) |
| Agent Configuration | **Knowledge** | Documents and websites agents search | [Knowledge base](/guide/knowledge) |
| Agent Configuration | **Credentials** | Secrets agents receive when they run commands | [Credentials](/guide/credentials) |
| Workflow | **Commands** | Saved prompts you run with `/` | [Commands](/guide/commands) |
| Workflow | **Approvals** | Rules, the Approval mode, and approvers for writes | [Approvals](/guide/approvals/overview) |
| Integrations | **Notifications** | Which events reach email, Slack, Teams, or Google Chat | [Notifications](/guide/notifications) |

## What you can do

| Goal | What to set | Learn more |
|------|-------------|------------|
| Give a team its own specialist, such as a cost reviewer that answers in Vietnamese | Create a custom agent, set **Language**, attach only the connections it needs | [Custom agent quickstart](/guide/agents/quickstart) |
| Make agents follow your runbook every time | Write the runbook as a skill and attach it to **Chat** or **Incident** | [Custom skills](/guide/skills/custom-skills) |
| Apply your review standards to every pull request | Write a skill and attach it to **Review** | [Custom skills](/guide/skills/custom-skills#choose-where-the-skill-applies) |
| Let agents cite your architecture docs | Upload them to a knowledge base | [Knowledge base](/guide/knowledge) |
| Give agents an API token without pasting it into chat | Add it under **Credentials** | [Credentials](/guide/credentials) |
| Require a person before any production write | Add an **Ask first** Rule, or set the mode to **Manual** | [Approvals](/guide/approvals/overview) |

## Custom agents at a glance

| Item | Detail |
|------|--------|
| Create | **Settings → Agents**, then **Create agent**. Pick **Create with AI** (an interview in chat) or **Build with form** (a three-step dialog). |
| `@mention` | Lowercase letters, numbers, dots, underscores, and hyphens, starting with a letter, up to 63 characters. Set once, can't be changed later. |
| Instructions | Up to 4,000 characters of plain-language guidance |
| Model Tier | **Light** (0.3x credits, simple questions), **Pro** (1.0x, the default, everyday work), or **Ultra** (1.7x, hard problems). See [what makes a run cost more](/guide/billing/usage#what-makes-a-run-cost-more). |
| Learning Mode | Kicks in when the agent repeats the same tool call several times in one conversation. **Auto** (the form's default) saves the workflow as a skill on its own, **Offer** asks you in chat first (reply yes or no), **Off** never saves. A learned skill is saved as a workspace skill in **Settings → Skills**, available in **Chat**, so every agent can use it. Use **Offer** in shared workspaces. |
| Connections | Up to 64 per agent, from the **Builtin** and **MCP** tabs |
| Who can create and edit | Workspace Admins and Developers. Viewers can see agents but can't chat with or edit them. |

The number of custom agents depends on your plan:

| Plan | Custom agents |
|------|---------------|
| Free | 1 |
| Team | 5 |
| Scale and Scale+ | 10 |
| Enterprise | Unlimited |

When you reach the limit, **Create agent** is disabled, and hovering it shows **Custom agent limit reached.** with an **Upgrade plan** link. Deleting an agent frees its slot right away. The limit is checked only when you create an agent, so after a downgrade your existing agents keep working, but you can't add one until you're under the new limit. See [pricing](/guide/billing/pricing).

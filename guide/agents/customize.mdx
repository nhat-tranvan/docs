**Works the way your team works.**

Customize is how you shape your agents (the built-in assistant, CloudThinker, and any custom agents you create; see [Agents](/guide/agents/overview)) to your team: which agents exist, what procedures they follow, what documents and secrets they can use, where alerts go, and which changes need a person first. Everything here is per workspace and lives in **More → Workspace settings**.

CloudThinker works without any of this setup.

## How it works

Each piece answers one question about how an agent behaves. You can set them up in any order.

1. **Who answers.** A custom agent has its own name, `@mention`, instructions, reply language, and connections.
2. **How it works.** Skills hold your procedures and rules. Knowledge holds documents the agent looks things up in.
3. **What it can reach.** Connections give access to your systems. Credentials hold other secrets, such as a vendor API key for a CLI. Use them when no connection exists for that tool.
4. **What it may change.** Approvals decide whether each write runs, waits for a person, or is refused. There are two modes: **Manual** asks a person before every write, and **Auto** lets your Rules, then AI judgment, decide.
5. **Who hears about it.** Notifications route alerts to email, Slack, Teams, or Google Chat.

Two optional extras sit next to these: **Memory** holds what agents remember between conversations, and **Commands** saves prompts you rerun with `/`.

<Warning>
New workspaces start in **Auto · Rules + AI · Ask me**, where AI judgment can let a safe write run without asking. Before you connect production, switch to **Manual**, which asks a person before every write. **Ask first** Rules are the narrower control later: Rule enforcement is off by default, and while the **Rules** step says **In preview** they only record what they would decide. See [Approvals](/guide/approvals/overview#what-you-get-out-of-the-box).
</Warning>

## What's per agent and what's workspace-wide

| Set per custom agent | Shared by every agent in the workspace |
|---|---|
| Name and `@mention`, instructions, reply language, model tier, Learning Mode, connections | Skills, knowledge bases, credentials, memory, commands, notifications, Approval Rules and the workspace Approval mode |

A skill reaches every agent on each surface ticked under its **Available in**, such as Chat or Review. You can't limit a custom agent to certain skills or knowledge bases. Scope it through its instructions and connections instead. Instructions steer the agent; they don't block anything. Connections are the hard limit: an agent reaches only the connections attached to it.

In the sidebar, click **More**, then **Workspace settings**. The settings rail groups the pages like this:

| Group | Page | What you set there | Who can edit | Guide |
|-------|------|--------------------|--------------|-------|
| Agent Configuration | **Connections** | The cloud accounts, clusters, databases, and tools agents can reach | Admin | [Connections](/guide/connections/overview) |
| Agent Configuration | **Skills** | Reusable procedures, and where each one applies | Admin | [Skills](/guide/skills/overview) |
| Agent Configuration | **Memory** | What agents remember between conversations | Admin | [Memory](/guide/memory) |

| Agent Configuration | **Knowledge** | Documents and websites agents search | Admin | [Knowledge base](/guide/knowledge) |
| Agent Configuration | **Credentials** | Secrets agents receive when they run commands | Admin | [Credentials](/guide/credentials) |
| Workflow | **Commands** | Saved prompts you run with `/` | Admin and Developer | [Commands](/guide/commands) |
| Workflow | **Approvals** | Rules, the Approval mode, and approvers for writes | Admin | [Approvals](/guide/approvals/overview) |
| Integrations | **Notifications** | Which events reach email, Slack, Teams, or Google Chat | Admin | [Notifications](/guide/notifications) |

For every permission by role, see [roles](/guide/security/roles).

## What you can do

| Goal | What to set | Learn more |
|------|-------------|------------|
| Give a team its own specialist, such as a cost reviewer that answers in Vietnamese | Create a custom agent, set **Language**, attach only the connections it needs | [Custom agent quickstart](/guide/agents/quickstart) |
| Make agents follow your runbook every time | Write the runbook as a skill and attach it to **Chat** or **Incident** | [Custom skills](/guide/skills/custom-skills) |
| Apply your review standards to every pull request | Write a skill and attach it to **Review** | [Custom skills](/guide/skills/custom-skills#choose-where-the-skill-applies) |
| Let agents cite your architecture docs | Upload them to a knowledge base | [Knowledge base](/guide/knowledge) |
| Limit an agent to certain accounts or tools | Attach only those connections to the agent | [Custom agent quickstart](/guide/agents/quickstart#give-it-a-connection) |
| Give agents an API token without pasting it into chat | Add it under **Credentials** | [Credentials](/guide/credentials) |
| Require a person before any production write | Set the Approval mode to **Manual**, the control that holds today. An **Ask first** Rule narrows it to one write later, once CloudThinker turns on Rule enforcement — it's off by default | [Approvals](/guide/approvals/overview) |

To choose between skills, knowledge bases, memory, Learnings and runbook sources, see [Teach CloudThinker](/guide/teach-cloudthinker).

## Custom agents at a glance

| Item | Detail |
|------|--------|
| Create | **More → Workspace settings → Agents**, then **Create agent**. Pick **Create with AI** or **Build with form** (a three-step dialog: Identity, Configuration, Connect). |
| Create with AI | Opens a chat that asks for the name, `@mention`, role, goal, instructions, model tier, language, Learning Mode, avatar, and connections. It confirms the `@mention`, then creates the agent from the chat, with no form to review. It's a normal chat, so it uses credits. |
| `@mention` | Lowercase letters, numbers, dots, underscores, and hyphens, starting with a letter, up to 63 characters. Set once, can't be changed later. |
| Instructions | Up to 4,000 characters of plain-language guidance. Use them to point the agent at skills and knowledge, for example: `Use the ec2-high-cpu-runbook skill for performance questions. Look up procedures in the Payments runbooks knowledge base first.` |
| Model Tier | **Light** (0.3x the credits of Pro, simple questions), **Pro** (the default, everyday work), or **Ultra** (1.7x the credits of Pro, hard problems). The Free plan runs Light only, so pick **Light** there. See [what makes a run cost more](/guide/billing/usage#what-makes-a-run-cost-more). |
| Language | **Match the user** by default: the agent replies in the language of your latest message. Pick a language to pin every reply to it. |
| Learning Mode | Whether the agent saves repeated workflows as skills. See [Learning Mode](#learning-mode). |
| Connections | Up to 64 per agent, from the **Builtin** and **MCP** tabs |
| Who can create and edit | Workspace Admins and Developers. Viewers can see agents but can't chat with or edit them. |

The number of custom agents each workspace can have depends on your plan:

| Plan | Custom agents |
|------|---------------|
| Free | 1 |
| Team | 5 |
| Scale and Scale Plus | 10 |
| Enterprise | Unlimited |

The **Create Custom Agent** dialog shows how many slots you've used, for example **3 of 5 custom agents used**. The organization Owner sees the plan itself in **Admin Settings → Billing**.

When you reach the limit, **Create agent** is disabled, and hovering it shows **Custom agent limit reached.** with an **Upgrade plan** link. Deleting an agent frees its slot right away. The limit is checked only when you create an agent, so after a downgrade your existing agents keep working, but you can't add one until you're under the new limit. For the other per-plan limits, see [pricing](/guide/billing/pricing#ai-features-by-plan).

## Learning Mode

Learning Mode lets a custom agent turn a workflow it keeps repeating into a skill. It kicks in when the agent makes the same tool call on the same connection 3 times, in a conversation that has run at least 10 tool calls. You can't change these thresholds in workspace settings.

| Mode | What happens |
|---|---|
| **Auto** (the form's default) | The agent saves the workflow as a skill on its own. It doesn't when your request limits it to reading, such as "investigate only, don't change anything". |
| **Offer** | The agent asks in chat first, and whoever is in the chat can say yes. |
| **Off** | The agent never saves a skill. |

<Note>
Only Admins can create skills in **More → Workspace settings → Skills**, but Developers can create agents. A custom agent on **Auto** or **Offer** adds workspace skills without an Admin, and they go live in **Chat** for every agent. [Audit Logs](/guide/security/audit-logs) don't record them. Use **Off** for agents in production workspaces. No workspace setting enforces Off: an Admin sets it per agent in the agent's settings, and can edit, re-scope, or delete a learned skill in **More → Workspace settings → Skills**.
</Note>

Anna is CloudThinker's General Manager, specializing in multi-agent coordination, complex project management, executive reporting, and strategic operations that span multiple domains.

## How Anna works

1. **Receives a complex request** — a project, investigation, or reporting requirement that spans multiple domains.
2. **Breaks it into parallel sub-tasks** — Anna determines which agents need to contribute and what each should investigate.
3. **Coordinates agent execution** — Anna dispatches work to [Alex](/guide/agents/alex), [Oliver](/guide/agents/oliver), [Tony](/guide/agents/tony), and [Kai](/guide/agents/kai) concurrently, managing dependencies between them.
4. **Combines findings** — Anna collects results from all agents and connects them into a coherent cross-domain narrative.
5. **Produces the deliverable** — an executive summary, action plan, or remediation roadmap, ready to share.

When Anna hands part of a task to another agent, that agent works with its own attached connections: read-only checks run directly, and any change to your environment goes through the same approval as if you had asked that agent yourself, under your workspace's autonomy mode — Manual or Auto. See [Auto Mode](/guide/auto-mode) and [Approval](/guide/approval).

## Capabilities

| Domain | Capabilities |
|--------|-------------|
| **Agent coordination** | Directing Alex, Oliver, Tony, and Kai through complex operations |
| **Project management** | Multi-phase projects, dependencies, timelines, risk management |
| **Executive reporting** | Strategic summaries, KPI dashboards, board-level presentations |
| **Complex operations** | Cloud migrations, security transformations, infrastructure overhauls |

## When to use Anna

Use Anna when operations require:

- **Multiple agents** working on related aspects of a problem
- **Cross-domain expertise** — for example, security plus infrastructure plus databases
- **Executive-level visibility** or reporting
- **Project coordination** with dependencies and timelines

For single-domain tasks, mention the specialized agent directly. To steer who does what, name the agents in your request in plain language — for example, "have @oliver lead the assessment and @alex review the infrastructure impact".

## Tool usage

| Tool | Anna use case |
|------|---------------|
| `#dashboard` | Executive KPIs, project status, multi-domain metrics |
| `#report` | Strategic summaries, quarterly reviews, board presentations |
| `#recommend` | Strategic initiatives, investment priorities, project sequencing |
| `#alert` | Project milestones, risk thresholds, critical findings |
| `#visualize` | Trend analysis, comparative metrics, progress tracking |

## Example prompts

Coordination:

```text
@anna #report investigation summary of the production outage across infrastructure, database, and Kubernetes
@anna #recommend a remediation plan with an owner for each finding
@anna #dashboard migration progress and risk status
```

Executive reporting:

```text
@anna #report quarterly infrastructure review for the executive team
@anna #dashboard executive KPIs across cost, security, and reliability
@anna #visualize cost and incident trends for the last two quarters
```

Planning:

```text
@anna #recommend priority initiatives for next quarter ranked by impact
@anna #report capacity forecast for 3x growth with cost implications
@anna #alert when a coordinated project misses a milestone
```

## Connection requirements

Anna inherits access from the agents she coordinates, so her connections are managed for you — attach connections to the specialist agents instead:

| Agent | Inherited access |
|-------|-----------------|
| **Alex** | Cloud providers, cost data, infrastructure metrics |
| **Oliver** | Security services, compliance data, audit logs |
| **Tony** | Database connections, performance metrics |
| **Kai** | Kubernetes clusters, container metrics |

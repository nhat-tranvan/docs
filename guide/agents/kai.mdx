Kai is CloudThinker's Kubernetes Engineer, specializing in cluster management, workload optimization, autoscaling, and operational troubleshooting across EKS, GKE, AKS, and self-managed clusters.

## How Kai works

1. **Connects to the Kubernetes API** — Kai reads pods, nodes, deployments, services, events, and RBAC (role-based access control) configurations across all namespaces.
2. **Pulls metrics** — Kai correlates Kubernetes API state with metrics-server data: actual CPU and memory usage vs requested.
3. **Identifies inefficiency patterns** — OOMKill (out-of-memory kill) history, pending pods, underutilized nodes, misconfigured autoscaling policies.
4. **Generates specific recommendations** — exact resource request/limit values based on actual P95 utilization, HPA (Horizontal Pod Autoscaler) threshold adjustments, RBAC policy changes.
5. **Troubleshoots with context** — when a pod fails, Kai reads logs, events, and resource state together to identify the root cause.

Kai proposes changes under your workspace's autonomy mode — Manual or Auto. See [Auto Mode](/guide/auto-mode) and [Approval](/guide/approval).

## Capabilities

| Domain | Capabilities |
|--------|-------------|
| **Cluster management** | Health monitoring, node management, resource allocation, upgrades |
| **Workload optimization** | Pod right-sizing, resource requests/limits, scheduling efficiency |
| **Autoscaling** | HPA/VPA/Cluster Autoscaler optimization, scaling policies |
| **Security** | RBAC auditing, network policies, pod security, secrets management |
| **Troubleshooting** | Crash loops, OOMKills, scheduling failures, networking issues |

## Supported platforms

| Platform | Support level |

## Tool usage

| Tool | Kai use case |
|------|--------------|
| `#dashboard` | Cluster health, node status, resource utilization, pod metrics |
| `#report` | Optimization analysis, security audits, capacity planning |
| `#recommend` | Right-sizing, scaling policies, consolidation actions |
| `#alert` | OOMKills, node pressure, pod failures, resource thresholds |
| `#visualize` | Resource trends, scaling patterns, utilization over time |

## Example prompts

Cluster health:

```text
@kai #dashboard EKS cluster health with node and pod metrics
@kai #report pods experiencing OOMKilled events with recommended fixes
@kai #alert on pod OOMKilled events or node pressure conditions
```

Optimization:

```text
@kai #recommend resource requests and limits based on actual utilization
@kai #report nodes under 30% CPU utilization with a consolidation plan
@kai #visualize cluster resource utilization trends over the last 30 days
```

Security:

```text
@kai #report RBAC configuration audit against least-privilege principles
@kai #recommend network policy improvements between namespaces
@kai #alert on pods running with privileged security contexts
```

## Connection requirements

Kai requires Kubernetes cluster access with monitoring capabilities:

| Component | Required access |
|-----------|----------------|
| **Kubernetes API** | Read access to pods, nodes, deployments, services |
| **Metrics server** | Resource metrics for pods and nodes |
| **Events** | Cluster events for troubleshooting |
| **Logs** | Container logs for debugging |

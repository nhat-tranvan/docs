By the end of this page you have a custom agent, `@ec2-triage`, that investigates high CPU on your EC2 instances by following your team's runbook, and that asks you before it changes anything. It takes about 10 minutes.

<Info>
**What you'll need**

- The workspace **Admin** role for step 3 (adding a skill). Developers can do every other step, so a Developer can ask an Admin to add the skill and do the rest. Run the test in step 5 only after the skill appears in **Settings → Skills**; without it, the agent has no runbook to follow.
- An [AWS connection](/guide/connections/aws) that shows **Connected**. Its role needs to describe instances and read CloudWatch metrics; the `ReadOnlyAccess` policy the setup script attaches covers both (see [required permissions](/guide/connections/aws#required-permissions)). Any other connection works too: swap the names in the examples.
- A free custom agent slot on your plan (Free includes 1). See [Customize](/guide/agents/customize#custom-agents-at-a-glance).
</Info>

A custom agent is a named agent you create in your workspace. It sits next to the built-in assistant, [CloudThinker](/guide/agents/overview), with its own instructions and its own connections. You talk to it by typing its `@mention` in chat.

<Steps>
  <Step title="Create the agent">
    Open **Settings → Agents**, click **Create agent**, and pick **Build with form**. On the **Identity** step, fill in:

    | Field | Value |
    |-------|-------|
    | **Name** | `EC2 Triage` |
    | **@mention** | `ec2-triage` (set once, can't be changed later) |
    | **Role** | `AWS Compute Specialist` |
    | **Goal** | `Find why an EC2 instance is slow and recommend the safest fix` |

    **Role** and **Goal** go at the top of the agent's prompt, ahead of the **Instructions** you add next, so the agent reads them on every request. Keep them short and specific.

    <Frame>
      <img src="/images/agents/create-custom-agent-dialog-1.png" alt="Create Custom Agent dialog, Identity step, with Avatar, Name, @mention, Role, and Goal fields" style={{ maxWidth: '400px' }} />
    </Frame>

    Click **Next**. On the **Configuration** step, keep **Model Tier** on **Pro**, set **Learning Mode** to **Offer**, and paste these **Instructions**:

    ```text
    You investigate EC2 performance problems in our AWS account.
    Always start read-only: describe the instance, then check CloudWatch metrics for the last hour.
    Report findings as a short table: metric, value, what it means.
    Never stop, reboot, or resize an instance without saying why first.
    ```

    **Learning Mode: Offer** means that when the agent repeats the same tool call several times in a conversation, it asks you in chat before it saves that workflow as a new skill. Reply yes to save it or no to skip. The form defaults to **Auto**, which saves without asking. A saved skill lands in **Settings → Skills**, available in **Chat**, and every agent in the workspace can use it (see [Customize](/guide/agents/customize#custom-agents-at-a-glance)). Click **Next**.

    **Success state:** the dialog moves to the **Connect** step.
  </Step>
  <Step title="Give it a connection">
    On the **Connect** step, open the **Builtin** tab and click **Add** next to your AWS connection. **Builtin** lists the connected connections from **Settings → Connections**; **MCP** lists the [MCP servers](/guide/connections/mcp) you've added. Click **Create Agent**.

    <Frame>
      <img src="/images/agents/create-custom-agent-dialog-3.png" alt="Create Custom Agent dialog, Connect step, with Builtin and MCP tabs and a list of connections to attach" style={{ maxWidth: '500px' }} />
    </Frame>

    An agent reaches only the connections you attach, so attach only what its job needs. You can add more later on the agent's **Connections** tab.

    **Success state:** `EC2 Triage` appears under **Custom** in **Settings → Agents**, showing 1 connection.

    <Frame caption="Agents: each custom agent has a name, @mention, role, goal and model tier">
      <img src="/images/v2/agents-custom.webp" alt="Settings, Agents page listing custom agents with name, @mention, role, goal, and model tier" />
    </Frame>
  </Step>
  <Step title="Add your runbook as a skill">
    A skill is a set of instructions agents follow when the task matches. Open **Settings → Skills**, click **New Skill**, and pick **Write skill instructions**. Fill in:

    - **Skill name:** `ec2-high-cpu-runbook`
    - **Description:** `Steps to investigate an EC2 instance with high CPU`
    - **Instructions:**

    ```markdown
    # EC2 high CPU runbook

    Use this when someone reports a slow EC2 instance or high CPU.

    1. Check CPUUtilization for the last hour. Above 90% for 15 minutes or more counts as sustained.
    2. If the instance is a burstable type (t2, t3, t4g), check CPUCreditBalance. A balance near zero means the instance is throttled.
    3. Check NetworkIn and DiskReadOps for a traffic spike that started at the same time.
    4. Recommend one fix, in this order of preference: wait out a short spike, move a burstable instance to unlimited mode, then resize. Recommend only; don't apply it. Unlimited mode and resizing both change cost.
    5. Never reboot an instance tagged env=prod without a person approving it.
    ```

    Click **Create**. New skills start enabled and available in **Chat**, which is where you test next.

    Skills apply to every agent in the workspace, not only `@ec2-triage`, so CloudThinker also follows this runbook when a chat asks about high CPU. See [Customize](/guide/agents/customize#how-it-works).

    **Success state:** `ec2-high-cpu-runbook` appears in the skills list with its switch on and **Chat** checked under **Available in**.
  </Step>
  <Step title="Make it ask before any change">
    Approvals decide whether a write (any call that changes something) runs, waits for a person, or is refused. Reads always run. For this test, make every write wait for you.

    Start a new chat. The approval control sits next to the model picker in the chat prompt box and shows the chat's current mode, **Manual** or **Auto**. A new chat starts on the workspace mode (new workspaces default to **Auto**). Open the control, or type `/` and pick **Approval**, and select **Manual**.

    **Success state:** the approval control shows **Manual**. This applies to this chat only; your workspace mode doesn't change. Developers can do this step too.

    New chats start on the workspace mode again, and Automations use their own mode (**Auto · Rules + AI · Refuse** by default). To make prod changes always wait for a person, add an **Ask first** [Rule](/guide/approvals/rules).
  </Step>
  <Step title="Test the agent">
    In the same chat, mention the agent. Send one of these prompts.

    If you have an instance ID, replace the example one:

    ```text
    @ec2-triage Instance i-0abc1234def567890 feels slow. Investigate it.
    ```

    If you don't:

    ```text
    @ec2-triage List my running EC2 instances, pick the one with the highest CPU, and investigate it.
    ```

    The agent describes the instance, reads its CloudWatch metrics, and answers with a metric table and one recommended fix, in the order your runbook sets. A good answer has this shape (your values will differ):

    | Metric | Value | What it means |
    |---|---|---|
    | CPUUtilization | Above 90% for the last 40 minutes | Sustained high CPU |
    | CPUCreditBalance | Near zero | The burstable instance is throttled |

    Followed by one recommendation, such as moving the instance to unlimited mode, with the reason and no change applied.

    If the agent wants to change the instance, the chat shows an approval card with **Approve** and **Decline**. Click **Decline** if you only wanted the diagnosis.

    **Success state:** the agent's activity includes a **Load Skill** step (the summary reads "read 1 skill" or more), the answer follows your runbook steps without you restating them, and nothing changed in AWS without your approval.
  </Step>
</Steps>

## You're done when…

- `@ec2-triage` answers in chat, and its **Connections** tab in **Settings → Agents** lists only your AWS connection
- Its activity shows a **Load Skill** step and its answer follows the steps in `ec2-high-cpu-runbook`
- Any write it attempts shows an approval card before it runs

If this was only a trial, delete the agent in **Settings → Agents** (it frees the slot right away; Free includes one) and the skill in **Settings → Skills**.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Create agent is greyed out">
    Your workspace reached its custom agent limit. Hover the button: the tooltip says **Custom agent limit reached.** with an **Upgrade plan** link. Delete an unused agent in **Settings → Agents**, or see [plans](/guide/billing/pricing).
  </Accordion>
  <Accordion title="The @mention is rejected">
    It must start with a lowercase letter and use only lowercase letters, numbers, dots, underscores, and hyphens, up to 63 characters. It also can't match a name already in use or reserved by CloudThinker.
  </Accordion>
  <Accordion title="The @mention doesn't autocomplete">
    Check that `EC2 Triage` appears under **Custom** in **Settings → Agents**. If you created it in another tab, refresh the chat page, then type `@` again.
  </Accordion>
  <Accordion title="A change ran without an approval card">
    Check that the chat's approval control shows **Manual**. In Manual mode every write asks a person, even one an Allow Rule covers, so a missing card usually means the chat was on **Auto**. Reads (describe, list, metrics) never show a card. See [Approvals](/guide/approvals/overview).
  </Accordion>
  <Accordion title="The agent says it can't reach AWS">
    Open the agent in **Settings → Agents**, go to the **Connections** tab, and check that your AWS connection is attached. Then check the connection itself shows **Connected** on the [Connections](/guide/connections/overview) page.
  </Accordion>
  <Accordion title="The answer ignores the runbook">
    Open **Settings → Skills** and check that the skill's switch is on and **Chat** is checked. Then make the request match the skill's description, for example by saying "high CPU". Agents apply a skill only when it fits the task.
  </Accordion>
  <Accordion title="I don't see New Skill">
    Adding skills needs the workspace **Admin** role. Ask a workspace admin to add the skill or change your role.
  </Accordion>
</AccordionGroup>

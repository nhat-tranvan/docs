An agent is the AI that reads your request, uses your [connections](/guide/connections/overview) to look things up, and answers or acts. Every workspace has one built-in agent, **CloudThinker**, which can split big tasks across temporary subagents, plus any custom agents your team creates. Every write from any agent follows your workspace's [Approvals](/guide/approvals/overview).

## Talk to an agent

<PromptSyntaxBasics />

Who answers depends on the mention:

| You send | Who answers |
|---|---|
| A message with no mention | CloudThinker |
| A message that mentions `@CloudThinker` | CloudThinker |
| A message that mentions a custom agent, such as `@db-reviewer` | That custom agent |

Type `@` in the chat box to open the **Mention an agent** picker. It lists CloudThinker and your workspace's active custom agents.

A first request needs no mention at all:

```text
Which pods in the production namespace restarted more than 3 times in the last 24 hours, and why?
```

CloudThinker picks the Kubernetes connection, runs the checks, and replies with the pods, their restart counts, and the reason for each restart it found.

## The CloudThinker assistant

CloudThinker is always on. You can't turn it off, and it can use every connection in the workspace. Use it for anything: questions, investigations, reports, and changes (which wait for approval when your Approvals settings say so).

## Subagents

A subagent is a short-lived helper that CloudThinker starts for one part of a bigger task. During an incident, for example, it can check three services at once instead of one after another. Each subagent reports back, and CloudThinker combines the results into one answer.

You see subagents in the chat and in the **Agents** tab of the side panel:

| What you see | Meaning |
|---|---|
| **Spawn Subagents** | CloudThinker started subagents for this task |
| **N agents still working** | Subagents are still running |
| **1 agent needs you** | A subagent is waiting on you. Click the line to open the **Agents** tab |
| **Finish Subagent** | A subagent reported its results back |

Each subagent in the **Agents** tab shows a status:

| Status | What to do |
|---|---|
| **Waiting to start**, **Working**, **Waiting for background work** | Nothing. It's running |
| **Needs approval** | It wants to run a write action. Click **Approve** or **Reject**. The panel has no **Approve and draft rule**. **Reject** stops the subagent, while **Decline** on a chat card lets the agent carry on without that action |
| **Needs review** | A call was interrupted before the subagent learned its result, so the change may or may not have happened. Check the target system, then click **I verified it completed** or **I verified it did not complete** on the subagent in the **Agents** tab, or **Stop this agent**. It never runs that call again on its own |
| **Done**, **Failed**, **Stopped**, **Replaced** | Finished. **Replaced** means a newer run took over, not an error |

Subagents exist only for the task that started them. They don't appear in your agent list and you can't mention them.

## Custom agents

A custom agent is an agent your workspace defines, with its own name, `@mention`, instructions, and connections. Create one when a team needs the same behavior every time, such as a database reviewer that always applies your naming rules, or an on-call helper that only touches the staging cluster.

Workspace Admins and Developers can create one under **More → Workspace settings → Agents**: click **Create agent**, then choose **Create with AI** (describe it in plain words) or **Build with form**. A custom agent has no approval mode of its own. Its writes follow the workspace's Approvals like every other agent's.

| Setting | What it controls |
|---|---|
| **Identity** | Avatar, name, `@mention`, role, and goal |
| **Instructions** and **Language** | How the agent works and which language it replies in |
| **Model Tier** | **Light** (fast and economical, 0.3x), **Pro** (balanced, 1.0x), or **Ultra** (maximum capability, 1.7x). The multiplier scales the credits each run uses. Chat starts on Pro. See [What makes a run cost more](/guide/billing/usage#what-makes-a-run-cost-more) |
| **Skill Learning** | **Auto** saves new skills, **Offer** asks before saving, **Off** never saves |
| **Connections** | The only connections this agent can use |

<Note>
A custom agent turns itself off when it has no connection. Attach at least one before you mention it. Team allows up to 5 custom agents, Scale and Scale Plus up to 10, and Enterprise has no limit. See [AI features by plan](/guide/billing/pricing#ai-features-by-plan).
</Note>

For a worked example with a test prompt and its expected reply, see [Build your first custom agent](/guide/agents/quickstart). The full settings are in [Customize agents](/guide/agents/customize).

## Agents in each product

| Product | Who does the work |
|---|---|
| [Resolve](/guide/incident/overview) | CloudThinker investigates each incident and proposes a fix |
| [Review](/guide/code-review/overview) | A review bot posts reviews on pull requests. Reply to it with `@cloudthinker-ai` [commands](/guide/code-review/mention-commands) |
| [Optimize](/guide/cost-optimization/overview) | Findings come from your billing data. Ask CloudThinker in chat to dig into any of them |
| [Cyber](/guide/security/cyber-overview) | CloudThinker runs dynamic security tests on running apps you're authorized to test |

## FAQ

<AccordionGroup>
  <Accordion title="Can I turn CloudThinker off?">
    No. CloudThinker is always active in every workspace. You can turn custom agents on and off.
  </Accordion>
  <Accordion title="Do custom agents and subagents follow approvals?">
    Yes. Write actions from CloudThinker, a subagent, or a custom agent all follow the same workspace Approvals settings.
  </Accordion>
  <Accordion title="Why can't my custom agent see a system CloudThinker can?">
    A custom agent only uses the connections attached to it. Open it under **More → Workspace settings → Agents** and add the connection.
  </Accordion>
  <Accordion title="An old blog post or screenshot shows named agents. Where are they?">
    Older versions had five named specialist agents. CloudThinker now does all of their work as one assistant and spawns subagents when a task needs parallel work. Ask CloudThinker directly.
  </Accordion>
</AccordionGroup>

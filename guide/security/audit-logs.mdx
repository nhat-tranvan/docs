Audit Logs is one timeline of every user, agent and system action across all workspaces in your organization. Use it to answer "who did this, when, and from where" during a security review, an incident postmortem or a change investigation.

## Prerequisites

- An organization **Owner** or **Admin** role. Developers and Viewers don't see the page. See [Roles](/guide/security/roles).
- A **Scale**, **Scale+** or **Enterprise** plan. On other plans the page shows an **Unlock Audit Logs with the Scale plan** prompt and an **Upgrade Plan** button instead of the timeline. See [Subscription](/guide/billing/subscription).

When billing is turned off, which is typical for a self-hosted deployment, there's no plan check: Owners and Admins always see the timeline.

## Key terms

| Term | Meaning |
|---|---|
| **Event** | One recorded action, such as a connection update or an approval decision. Shown as one row. |
| **Actor** | Who performed the action. **User** is a person in your organization, **Agent** is an AI agent acting in a workspace, **System** is the CloudThinker platform itself. |
| **Category** | The area of the product the event came from, such as **Connection**, **Approval** or **Billing**. |
| **Severity** | How significant the action is: **Low**, **Medium**, **High** or **Critical**. |
| **Outcome** | Whether the action finished: **Success**, **Failure** or **Pending**. |

The timeline is read-only. Nobody, including Owners, can edit or delete an event from the app.

## Open the timeline

<Steps>
  <Step title="Go to Audit Logs">
    Open **Admin Settings → Audit Logs**.

    **Success state:** four summary tiles (**Total Events**, **Success**, **Failures**, **Agent Actions**) appear above a table of events, newest first.
  </Step>
  <Step title="Read the summary tiles">
    The tiles count the events that match your current filters. **Failures** shows **Needs attention** when the count is above zero and **All clear** when it's zero. **Agent Actions** counts events performed by agents.
  </Step>
</Steps>

Each row shows these columns:

| Column | Contents |
|---|---|
| **Timestamp** | Relative time, such as "5 minutes ago". Hover it for the exact date and time. |
| **Actor** | The user or agent name. Agent actions carry a bot badge with the agent's name. |
| **Category** | The product area, such as **Connection**, **Review** or **Optimize**. |
| **Event** | The action taken, such as **Connection Updated** (raw action `connection.updated`). |
| **Severity** | **Low**, **Medium**, **High** or **Critical**. |
| **Summary** | A one-line description of what happened. |
| **Workspace** | The workspace the action ran in, or `-` for organization-level events. |

## Find a specific event

Every filter narrows the table, the summary tiles and the CSV export at the same time. Filters combine, so **Actor Type: Agent** plus **Severity: High** shows only high-severity agent actions.

<Steps>
  <Step title="Search">
    Type into **Search**. It matches text in the event summary, the resource name and the actor name. Search runs as you type.
  </Step>
  <Step title="Filter by actor, category or severity">
    Pick values in **Actor Type**, **Category** and **Severity**. Each filter accepts several values at once.
  </Step>
  <Step title="Set a date range">
    Choose a start and end date in the date picker. The end date includes the whole day, up to 23:59:59.

    **Success state:** the summary tiles and the table update to show only matching events.
  </Step>
</Steps>

Available categories: Agent, Agent Policy, Alert, Approval, Artifact, Assessment, Billing, Chat, Command, Connection, Cyber, Incident, Keepers, Knowledge, Notification, Optimize, Plan, Recommendation, Resource, Review, Security, Skill, Task, Topology, User Mgmt, Webhook and Workspace.

### Common lookups

| Question | Filters |
|---|---|
| What did agents change this week? | **Actor Type:** Agent, date range: last 7 days |
| Who changed a connection? | **Category:** Connection, then search the connection name |
| Who approved or rejected an agent action? | **Category:** Approval |
| What went wrong recently? | **Severity:** High and Critical, then check the **Failures** tile |
| Who added or removed a member? | **Category:** User Mgmt |

## Inspect an event

Click any row to open its detail panel. It shows:

| Field | Contents |
|---|---|
| **Actor**, **Severity**, **Timestamp**, **Workspace**, **Summary** | Same as the row, with the full date and time. |
| **Resource Type**, **Resource Name**, **Resource ID** | The object the action touched. |
| **Incident ID** | The related [Resolve](/guide/incident/overview) incident, when there is one. |
| **IP Address** | Where a user action came from. |
| **Resource Changes** | A **Field / Before / After** table listing only the fields that changed. |
| **Metadata** | Extra context for the event, as JSON. |

Fields with no value are hidden, so a system event usually shows no IP address.

## Export to CSV

<Steps>
  <Step title="Filter first">
    Narrow the timeline to what the reviewer needs, for example one workspace's events in the last quarter. The export uses exactly the filters on screen.
  </Step>
  <Step title="Click Export CSV">
    Click **Export CSV** next to the filters. The button reads **Exporting...** while the file builds.

    **Success state:** your browser downloads `audit-trail.csv` and an **Audit trail exported successfully** message appears.
  </Step>
</Steps>

The file has one row per event with these columns: `timestamp`, `actor_type`, `actor_name`, `agent_name`, `action_category`, `action`, `severity`, `resource_type`, `resource_id`, `resource_name`, `summary`, `ip_address`, `changes`, `outcome`, `metadata`. The `changes` and `metadata` columns hold JSON.

<Warning>
One export holds at most the 10,000 most recent matching events. For a longer period, export in smaller date ranges so nothing is cut off.
</Warning>

## Retention

Events are kept for 90 days, then deleted automatically. If you need a record that lasts longer, export it to CSV before the 90 days are up and store it in your own system.

On self-hosted deployments the retention period is the **Audit Trail Retention Days** setting in **Instance configuration**, which defaults to 90. See [Deployment](/guide/deployment/overview).

## Troubleshooting

<AccordionGroup>
  <Accordion title="I don't see Audit Logs in Admin Settings">
    **Cause:** your organization role is Developer or Viewer.
    **Fix:** ask an organization Owner to make you an Admin. See [Roles](/guide/security/roles).
  </Accordion>
  <Accordion title="The page shows an upgrade prompt instead of events">
    **Cause:** your organization is on a plan without Audit Logs.
    **Fix:** click **Upgrade Plan** and move to Scale, Scale+ or Enterprise. See [Subscription](/guide/billing/subscription).
  </Accordion>
  <Accordion title="An event I expect is missing">
    **Check:** clear all filters and the date range, then search again. Search only matches the summary, resource name and actor name, not the event name or workspace.
    **Check:** the event may be older than 90 days and already deleted.
  </Accordion>
  <Accordion title="My CSV has fewer rows than the Total Events tile">
    **Cause:** an export stops at the 10,000 most recent matching events.
    **Fix:** split the export into shorter date ranges.
  </Accordion>
  <Accordion title="Failed to export audit trail">
    **Fix:** check your network connection and click **Export CSV** again. If it keeps failing, narrow the date range to make the file smaller.
  </Accordion>
</AccordionGroup>

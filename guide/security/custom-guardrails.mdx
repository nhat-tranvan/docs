Guardrails decides which sensitive values agents never see in the clear. When a protected value shows up in what an agent works with, such as a customer email in a log line, the agent reads a placeholder instead. You manage it in **Admin Settings → Guardrails**: turn built-in identifiers on or off, and add patterns for ID formats only your team uses.

## Prerequisites

- The **Admin** role in the workspace, to change settings for that workspace.
- The organization **Owner** or **Admin** role, to set the organization baseline, lock a rule, or move a pattern to the organization.
- A regular expression for any custom ID format you want to hide. You don't need sample values.

## What agents see

Each row in the table is a built-in identifier or a custom pattern. Click a built-in row to see its description and an example of what the agent sees.

| Identifier | Default | Raw value | What the agent sees |
|---|---|---|---|
| Email | On | `ops@mail.example.com` | `ct:pii:v3:email:4c1f0a9e27b3 [op***@ma***.com]` |
| Phone | On | `(012) 345-6789` | `ct:pii:v3:phone:8e25b0d4c7a1 [***-***-**89]` |
| Credit card | On | `4111 1111 1111 1111` | `ct:pii:v3:creditcard:0a1b2c3d4e5f` |
| IBAN | On | `GB82WEST12345698765432` | `ct:pii:v3:iban:b7e3915c0d2a` |
| MAC address | On | `00:00:5E:00:53:01` | `ct:pii:v3:mac:5f08a2c9e1d4` |
| API keys | On | `sk-…` | `ct:secret:v3:openai-api-key:2d9c4e7a0b16` |
| Cloud credentials | On | `AIza…` | `ct:secret:v3:gcp-api-key:9a4e1c7b3f20` |
| IP addresses | Off | `203.0.113.7` | `ct:pii:v3:ip:6c3a8f1e0b95 [203.0.***.7]` |
| Public keys | Off | `ssh-ed25519 AAAA…` | `ct:pii:v3:publickey:e1b6d3a09c42` |
| Cloud account IDs | Off | `arn:aws:iam::123456789012:role/ops` | `arn:aws:iam::ct:pii:v3:account:3b0f7d2e9a61 [**********12]:role/ops` |

Defaults that are on start at the **Organization** scope. A few details from the built-in rules:

- **Email** skips addresses at `example.com`, `.net`, and `.org`. **Phone** skips the reserved 555-0100 to 555-0199 range.
- **Credit card** and **IBAN** only match numbers that pass their checksum, so random digit strings stay visible.
- **Cloud credentials** hides secret keys and service account keys. A bare `AKIA…` key ID stays visible.

<Tip>
Turn on **IP addresses** or **Cloud account IDs** only if you need them hidden. Agents investigating network or IAM issues often need to read them.
</Tip>

## Set where a protection runs

The **Scope** column has three positions for every row.

| Scope | Effect |
|---|---|
| **Off** | Doesn't run in this workspace |
| **Workspace** | Runs in this workspace only |
| **Organization** | Runs in every workspace in the organization. Owners and Admins of the organization set it. |

<Steps>
  <Step title="Open Guardrails">
    Go to **Admin Settings → Guardrails**. Use **Search identifiers**, or filter by scope and by type (**Built-in** or **Custom**).
  </Step>
  <Step title="Pick a scope">
    Click **Off**, **Workspace**, or **Organization** on the row. The change saves on click. There's no Save bar.

    **Success state:** the row shows the new scope.
  </Step>
  <Step title="Lock it (optional, organization Admins)">
    Click the padlock in the **Actions** column to keep a built-in rule on for every workspace.

    **Success state:** workspace Admins can no longer turn the rule **Off**. Click the padlock again to unlock it.
  </Step>
</Steps>

A workspace Admin can turn off an organization rule for their workspace only while it's unlocked. Custom patterns can't be locked.

## Add a custom pattern

Use a custom pattern for a structured ID that the built-in rules don't cover, such as a customer account number. Write the format as a regular expression. Don't enter real values.

<Steps>
  <Step title="Start a pattern">
    In **Admin Settings → Guardrails**, click **Add pattern**. A new pattern starts at the **Workspace** scope.
  </Step>
  <Step title="Name it">
    Enter a **Name** your team will recognize, such as `Customer account ID`.
  </Step>
  <Step title="Pick a category">
    Choose a **Category** from the list or type your own, such as `customer-id`. Agents see the category in the placeholder, for example `ct:pii:v3:customer-id:<hash>`. Categories that built-in rules use, such as `email`, are reserved.
  </Step>
  <Step title="Enter the pattern and save">
    Enter the regular expression in **Pattern**, for example `ACC-\d{6}` for `ACC-` followed by six digits. Click **Save**.

    **Success state:** the pattern appears in the table as **Custom**, at the **Workspace** scope. CloudThinker checks the pattern on save, and an invalid or too-broad pattern shows an error instead (see [Troubleshooting](#troubleshooting)).
  </Step>
</Steps>

There's no match preview, so make the pattern specific. A broad pattern, such as any UUID, can hide values agents need to do their work.

### Limits

| Item | Limit |
|---|---|
| Custom patterns per workspace | 5, counting the workspace's own patterns and organization patterns that apply to it |
| Name | 200 characters |
| Pattern | 512 characters |
| Category | 32 characters, lowercase letters, numbers, and hyphens |

To use a pattern across the organization, an organization Owner or Admin moves it to **Organization** with its scope control. It then shows in every workspace's table, and only organization Admins can edit, move, or delete it. Moving a pattern doesn't use another slot.

## Change or remove a pattern

| Action | How | Note |
|---|---|---|
| Edit | Click the pattern's row to change its name or pattern | The category is fixed. For a new category, add a new pattern. |
| Pause | Set its scope to **Off** | It stays saved and keeps its slot |
| Delete | Click **Delete** in the **Actions** column and confirm | Can't be undone. Agents see matching values again unless another rule catches them. |

## Troubleshooting

<AccordionGroup>
  <Accordion title="The pattern won't save">
    The error message tells you which check failed.

    | Message says | Fix |
    |---|---|
    | It couldn't read the pattern | Check the regex syntax, especially brackets and escapes |
    | It can match empty text | Make every part required, for example `\d{6}` instead of `\d*` |
    | A simpler pattern, or fewer repetitions | Cap repeats, for example `{1,32}`, and cut alternatives |
    | The category is used by a built-in protection | Pick another category |
    | All 5 slots are in use | Delete a pattern. Turning one **Off** doesn't free its slot. |
  </Accordion>
  <Accordion title="I can't turn a rule off">
    An organization Admin locked it. Ask them to unlock it, or keep it on.
  </Accordion>
  <Accordion title="I can't edit or delete a pattern">
    It's an organization pattern. Only organization Owners and Admins can change it.
  </Accordion>
  <Accordion title="Guardrails isn't in Admin Settings">
    You need the workspace **Admin** role. If you have it and still don't see the page, Guardrails may not be enabled for your deployment. Contact your organization Admin.
  </Accordion>
</AccordionGroup>

Cyber tests running applications with **Pentest**. Review the evidence, track remediation, and retest after changes.


<CyberScene />

## How it works

1. **Choose the starting point.** Choose an application you are authorized to test.
2. **Set the boundaries.** Verify domain ownership and configure scope, test users, and optional source context.
3. **Run the checks.** CloudThinker tests the application within your saved scope. Missing access and incomplete checks remain visible as limitations.
4. **Review the evidence.** Read the attack path and proof before deciding what to fix. A candidate that still needs review is not a confirmed vulnerability.
5. **Reassess after a fix.** Run another pentest against the changed application. Creating a ticket or merging a fix does not establish a new verdict.

  Cyber is in beta.
</Note>

## Read the workspace overview

Open **Cyber** from the navigation menu. Choose an app from **Pentest**, or from **Overview** if the app list appears there.

When the app list appears on **Overview**, that page also shows the workspace verdict, fix progress, a trend of open findings, and recent runs. An app with no completed scan has no assessed security verdict. An app whose last completed scan is more than 30 days old is marked stale.

Each Pentest app keeps its findings and run history across scans. Its header links the overview, runs, findings, reports, and settings. Coverage describes what the selected OWASP framework could assess; missing inputs do not become clean results.

## Key concepts

| Concept | Meaning |
| --- | --- |
| Pentest app | One saved application target, its access configuration, findings, and run history |
| Access level | Black-box for public access, gray-box with test users, or white-box with source context |
| Intensity | Safe uses a read-only approach; Aggressive allows active testing; Full and Deep dive allow destructive testing. Deep dive investigates complex vulnerabilities and connected attack paths |
| Pentest triage | Your work stage, separate from the assessment of whether a vulnerability is present or fixed |

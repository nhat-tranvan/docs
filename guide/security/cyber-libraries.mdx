The **Libraries** tab of a [Code Audit](/guide/security/code-audit) repository lists the libraries your branch uses that match a published vulnerability. A version match and its impact on your own code are judged separately from the source findings on the same branch.

## Prerequisites

- A repository monitored by Code Audit, with lock or dependency files Code Audit can read.
- One finished audit. The audit collects the libraries; checks for new advisories need that inventory.
- **Run library scan now** and **Open fix pull request** need the Admin or Developer role. Viewers can read libraries and reports.

## How library checks work

- Each audit collects the libraries the pinned commit declares, even when the rest of the audit fails.
- After that, Code Audit keeps checking the inventory for newly disclosed advisories on its own, without another audit. You don't pause or resume it.
- For each matched advisory, an agent assesses whether your code uses the affected behavior. It researches the advisory on the public web, and it never sends your repository's content in a search.

An inventory lists what the repository declares, not what runs in production. A library Code Audit couldn't confirm, such as a private package or one with no exact version, is marked as not checked, not as safe.

## Read the Libraries tab

Open the repository and select **Libraries**. Filter by **Git target**, search by name, or filter by severity.

| Column or label | How to read it |
| --- | --- |
| **Severity** | The highest severity of the matched advisories. **Needs review** when no severity is known |
| **CVEs** | The advisories that match this version |
| **Last checked** / **Next check** | When advisory checks last ran and run next |
| **Library data is out of date** | The saved inventory is older than the branch. Run a scan or an audit to refresh it |
| **Collection is incomplete. A clean result cannot be established.** | Some dependency files couldn't be read, so an empty list is not proof of safety |

## Read a library's impact

Select a library to open its page. It shows the version match, the ecosystem, where the library is defined and used, the **Matched advisories**, and the agent's **Assessment** with its **Source evidence**.

A matching advisory says the library may be affected. The assessment goes further and asks whether your code reaches the vulnerable behavior. When that can't be settled, it lists the evidence or conditions it's missing.

A not-affected assessment doesn't erase the advisory match. Source findings, library evidence, and [Pentest](/guide/security/security-testing) proof answer three different questions. Click **Download** on the assessment to share it as Markdown.

## Scan now or fix a library

- **Run library scan now** on the **Libraries** tab checks the saved inventory against current advisories right away. It runs on monitored branches only.
- **Open fix pull request** on a library page opens a chat where CloudThinker upgrades or pins the library and opens a pull request for you to review.
- **Retry library assessment** reruns a failed impact assessment.

A fix pull request doesn't change the saved evidence. The next audit or library check reads the new version.

## Troubleshooting

For every Cyber problem in one place, see [Cyber troubleshooting](/guide/security/cyber-troubleshooting).

<AccordionGroup>
  <Accordion title="No libraries collected">
    Code Audit found no dependency files it can read at the audited commit. Check that the branch commits its lock files, then run an audit.
  </Accordion>
  <Accordion title="Library checks paused">
    A check failed in a way retrying won't fix, and you get one notification. Fix the source or inventory problem the tab shows, then run a new audit to resume checks.
  </Accordion>
  <Accordion title="Run library scan now is disabled">
    Hover the button to read why. Scans run on monitored branches only, need the Admin or Developer role, and wait while checks are paused.
  </Accordion>
  <Accordion title="Library checks are turned off">
    Library checks can be off while source auditing still works. Ask CloudThinker support, or whoever runs CloudThinker for your company. Saved libraries stay readable, but they don't tell you about today.
  </Accordion>
</AccordionGroup>

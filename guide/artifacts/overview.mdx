An artifact is a saved, versioned output that CloudThinker builds in a conversation: a report, a dashboard, or a generated file. You ask in plain language, CloudThinker queries your [connections](/guide/connections/overview), and the result lands in the **Artifacts** gallery where your workspace can open, download, and share it.

## Prerequisites

- At least one [connection](/guide/connections/overview) with the data you want in the artifact (for example AWS for cost, a database for query performance)
- A paid [plan](/guide/billing/pricing) if you want live data (**Go live**, **Refresh**). On the Free plan, artifacts show their published snapshot only.
- A [workspace role](/guide/workspace-users) that allows what you want to do:

| Action | Admin | Developer | Viewer |
|---|---|---|---|
| Create an artifact in a conversation | Yes | Yes | No |
| Open artifacts and download them | Yes | Yes | Yes |
| Run live data (**Go live**, **Refresh**) | Yes | Yes | No |
| Create or revoke a share link | Yes | Yes | No |

Every member of the workspace sees every artifact in the gallery. **Private** in the **Sharing** filter means the artifact has no public share link.

## Artifact types

| Type | What it is | Where it shows |
|---|---|---|
| **Report** | A written analysis with tables, charts, findings, and recommendations | **Visuals** tab |
| **Dashboard** | A view of related metrics and charts on one page | **Visuals** tab |
| **File** | A file CloudThinker generated in a conversation (for example a CSV or script) that you chose to keep | **Files** tab |

Every report and dashboard is stored as versions. When CloudThinker updates one, it publishes a new version and the old ones stay unchanged.

## Create an artifact

<Steps>
  <Step title="Ask for the output shape in words">
    Start a conversation and say what you want and in which form. You don't need any special syntax.

    ```text
    Build a dashboard of AWS spend by service for the last 30 days, with the top 10 cost drivers and month-over-month change.
    ```

    ```text
    Write a report on Aurora cluster prod-aurora: p50, p95 and p99 query latency over the past 7 days, split by reads and writes, with queries over 200 ms called out.
    ```

    To pin the request to one account, type `#` and pick the connection:

    ```text
    #aws-production Build a dashboard of EC2 and RDS spend for the last 30 days.
    ```

    **Success state:** CloudThinker replies with an artifact card in the conversation. Click it to open the artifact panel in the conversation (**View fullscreen** enlarges it). While CloudThinker is still writing, the card's actions show **Available after this artifact finishes**.
  </Step>
  <Step title="Refine it in the same conversation">
    Ask for changes as follow-ups, such as "add a breakdown by the `team` tag" or "compare against the previous 30 days".

    **Success state:** CloudThinker publishes a new version. If you already have the artifact open, a **Version N is available** notice appears with a **Show vN** button. The view never switches versions on its own.
  </Step>
  <Step title="Keep a generated file (optional)">
    When CloudThinker produces a file in the conversation, click **Save to artifacts** on its file card. Click it again (**Remove from artifacts**) to take it back out.

    **Success state:** the file appears under the **Files** tab in the gallery.
  </Step>
</Steps>

<Tip>
Name the time range, the grouping (service, account, tag), and the comparison period. Whatever you leave out, CloudThinker picks for you, so you may need a follow-up to get the exact cut.
</Tip>

## Versions

The version picker (**v1**, **v2**, and so on) sits at the top right of the artifact page. Pick any version to read it. Older versions show their published snapshot only, and live data runs on the current version.

There's no restore button. To bring an older cut back, ask CloudThinker in the same conversation, and it publishes that as a new version.

## Find artifacts in the gallery

Click **Artifacts** in the left sidebar, or go to [app.cloudthinker.io/artifacts](https://app.cloudthinker.io/artifacts). **More → Workspace settings → Artifacts** opens the same gallery. It has three tabs, each with a count.

| Control | Options |
|---|---|
| Tabs | **All**, **Visuals** (reports and dashboards), **Files** |
| Search | **Search artifacts** filters the list as you type |
| Filter | **Sharing** (**Shared** or **Private**) and **Category** |
| Sort | **Newest**, **Recently updated**, **Name A–Z** |
| View | Grid view or table view |

CloudThinker picks a short category label when it builds an artifact. There's no fixed list, so the **Category** filter shows only the labels in use in your workspace. To group artifacts your way, name the category in your request. Click the category tag on a card to filter by it.

Open any card to see the artifact on its own page. Reports and dashboards both have **Download PDF** at the top of the page and in the **More actions** (⋯) menu, next to **Open conversation**, which takes you back to the chat that built it. For a saved file, click the **Download** icon on its card in the **Files** tab.

## Manage artifacts

The gallery has no rename or delete control, and older versions stay readable in the version picker. If an artifact holds data that shouldn't be out, revoke its [share link](/guide/sharing#revoke-a-link) first, then ask CloudThinker for a version without that data. To take a saved file out of the gallery, click **Remove from artifacts** on its card in the **Files** tab. That doesn't revoke the file's share link, so revoke it before you remove the file. For how CloudThinker handles sensitive data, see [Data protection](/guide/security/data-protection).

## Snapshot and live data

A report or dashboard is published with a snapshot: the data as of the moment that version was published. The pill at the top of the artifact page tells you which data you're seeing.

| Pill | Meaning | What you can do |
|---|---|---|
| **Snapshot** | You see the published data, with its "Data from" time | Click **Go live**, or change a filter, to run the artifact's queries against current data |
| **Live** | The queries ran against your connections just now | Click **Refresh** to run them again |
| **Paused** | Live data stopped polling after a stretch with no activity on the page (15 minutes) | Click **Resume** |
| **Refresh failed** | The last run failed, so you see the last good data | Click **Retry** |

Live data runs the artifact's read-only queries against the connections it was published with, using your own access to those connections. The page names the connections before it starts. It needs a paid [plan](/guide/billing/pricing) and a role that can run live data. Each run is recorded in [Audit Logs](/guide/security/audit-logs).

An artifact is snapshot-only when you're on an older version, or when the version has no stored queries (for example, one built only from uploaded files or pasted data). The message under the pill then reads **This artifact shows its published snapshot only.**

## Share an artifact

Click **Share** on the artifact's card or page, then **Create share link**. Anyone with the link can view it without signing in. [Sharing](/guide/sharing) covers what viewers see and how to revoke a link.

<Warning>
The link is public, and every later version CloudThinker publishes shows up at the same URL. Read the [warning on Sharing](/guide/sharing#what-viewers-see) before you send it.
</Warning>

## Rerun on a schedule

An [automation](/guide/automation/automations) can run the same request on a schedule. Each run is a new conversation, so by default it builds a new artifact each time, and a link you already shared won't update. CloudThinker can find any artifact in the workspace, so to keep one URL current for stakeholders, name the existing artifact in the automation's request (for example, "update the AWS spend by service dashboard"). Each run then publishes a new version of it.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The artifact is missing data or shows an empty chart">
    **Cause:** CloudThinker couldn't read that source. **Check:** the connection exists and is **Connected** in [Connections](/guide/connections/overview), and the time range has data. **Fix:** reconnect or widen the range, then ask CloudThinker to update the artifact.
  </Accordion>
  <Accordion title="Go live doesn't appear or the pill stays on Snapshot">
    **Cause:** the workspace is on the Free plan, your role is **Viewer**, you're on an older version, or the version has no stored connections. **Check:** the message under the pill names the reason. **Fix:** upgrade the [plan](/guide/billing/pricing), ask an Admin about your role, or switch to the latest version in the version picker.
  </Accordion>
  <Accordion title="Live data says you don't have access to a connection">
    **Cause:** the message reads **You do not have access to** followed by a connection name. That connection was deleted, or your account can't see it. Live data only uses the connections stored with that version. **Fix:** ask CloudThinker in the artifact's conversation to rebuild it on a current connection. The new version runs live on that one.
  </Accordion>
  <Accordion title="A generated file isn't in the gallery">
    **Cause:** generated files stay in the conversation until you keep them. **Fix:** open the conversation and click **Save to artifacts** on the file card.
  </Accordion>
  <Accordion title="Download PDF fails">
    **Cause:** a print error, or more PDF requests than the per-minute limit (10 per user). **Fix:** wait a minute, then click **Retry** next to **Print failed** at the top of the page, or **Print failed. Retry** in the **More actions** menu.
  </Accordion>
</AccordionGroup>

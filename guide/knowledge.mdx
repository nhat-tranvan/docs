A knowledge base is a collection of your documents (files or crawled web pages) that CloudThinker searches when it answers. Add your runbooks and architecture docs once, and answers in chat and incident investigations cite your procedures instead of generic advice.

## How it works

1. You create a knowledge base and add files or a website URL.
2. CloudThinker indexes each document in the background. Each one shows a status: **Pending**, **Processing**, **Completed**, or **Failed**.
3. When a question needs workspace knowledge, CloudThinker searches the completed documents by meaning, not exact keywords, and answers from the passages it finds. [Resolve](/guide/incident/overview) can also use them as evidence during incident triage.

CloudThinker sees each knowledge base's title and description and searches all of them by default. Name a specific knowledge base in your request to search only that one.

Knowledge bases belong to one workspace. Everyone in the workspace can read and use them; agents in other workspaces can't.

| Use a knowledge base for | Use a [skill](/guide/skills/custom-skills) for |
|---|---|
| Facts and documents to look up: runbooks, architecture docs, policies, vendor manuals | Rules agents follow every time: review checklists, naming conventions, report formats |

## Prerequisites

- A CloudThinker workspace.
- The workspace **Admin** role to create knowledge bases and add or delete documents. Developers and Viewers can browse them and ask questions. See [roles](/guide/security/roles).

<Note>
If **Knowledge** is missing from **Settings**, the knowledge base module is turned off for your deployment. Ask your CloudThinker administrator to turn it on.
</Note>

## Create a knowledge base

<Steps>
  <Step title="Open Knowledge">
    Go to **Settings → Knowledge**.
  </Step>
  <Step title="Click Create KB">
    The **Create Knowledge Base** dialog opens.
  </Step>
  <Step title="Fill in the details and click Create">
    | Field | What to enter |
    |---|---|
    | **Title** | A name people will use in prompts, such as `Payments runbooks`. Up to 255 characters. |
    | **Description** | What's inside and when to use it, such as "On-call runbooks for the payments API, queue workers, and Postgres." CloudThinker reads this to pick the right collection. Up to 1,000 characters. |
    | **Tags** | Optional labels to filter the list, such as `oncall` or `payments`. |

    **Success state:** the new knowledge base appears in the list with 0 documents.
  </Step>
</Steps>

## Add documents

Open the knowledge base, click **Add Documents**, and choose a tab.

<Tabs>
  <Tab title="Files">
    1. Drag files onto the drop area, or click it to select them.
    2. Click **Upload N files**.

    | Limit | Value |
    |---|---|
    | Formats | PDF, DOC, DOCX, TXT, MD, CSV, XLSX, XLS, ODS |
    | Size per file | 10 MB |
    | Files per upload | 10 |

    Uploads also count toward your workspace's storage quota.
  </Tab>
  <Tab title="Website">
    1. Enter the **Website URL**, for example `https://docs.example.com/runbooks`.
    2. Turn on **Deep Crawl** to also import every linked page on the same domain. Leave it off to import only that page.
    3. Click **Add Website**.

    The URL must be public `http` or `https`. Internal addresses and URLs with a username or password in them are rejected.
  </Tab>
</Tabs>

**Success state:** every document in the list shows **Completed**. Only completed documents are searchable. Large files and deep crawls take longer.

## Ask questions from your documents

Ask in plain language. Ask about the content you need, not the document's title, because CloudThinker searches by meaning. Name the knowledge base when you want to search only that one:

```text
What's the escalation path for a Sev 1 on the payments API?
Using the Payments runbooks knowledge base, how do I fail over the primary Postgres?
Summarize the backup and restore procedure for our Redis clusters
```

**Success state:** the answer follows your document's steps and wording, and the chat shows that CloudThinker searched the knowledge base.

## Keep it accurate

- **Replace, don't stack.** When a runbook changes, delete the old document and upload the new one. CloudThinker can't tell which of two copies is current.
- **Use clear headings and short sections.** Search returns passages, so a focused section makes a better answer than a long wall of text.
- **Start small.** Load the ten documents your team opens most during incidents, then add more as questions come up.

To delete a document, use **Delete** in its row. To delete a whole knowledge base, use **Delete** from its row in the list.

<Warning>
Deleting a knowledge base permanently deletes every document in it. This can't be undone.
</Warning>

## Troubleshooting

<AccordionGroup>
  <Accordion title="CloudThinker doesn't use my documents">
    - Check the document status. Only **Completed** documents are searchable.
    - Ask a specific question about the content, and name the knowledge base to narrow the search.
    - Make sure you're chatting in the workspace that owns the knowledge base.
    - Give the knowledge base a description that says what's inside.
  </Accordion>
  <Accordion title="A document shows Failed">
    Delete it and upload it again. If it fails again, export it to a simpler format (for example PDF or TXT) and retry.
  </Accordion>
  <Accordion title="Files won't upload">
    - Each file must be 10 MB or smaller, with at most 10 files per upload.
    - The format must be one of PDF, DOC, DOCX, TXT, MD, CSV, XLSX, XLS, ODS.
    - "Storage quota exceeded. Cannot ingest more documents." means the workspace is out of knowledge base storage. Delete documents you no longer need, or check your plan in [usage](/guide/billing/usage).
  </Accordion>
  <Accordion title="A website import returns nothing">
    - Open the URL in a private browser window. If it needs a login or VPN, CloudThinker can't reach it.
    - Some sites block crawlers. Try a different starting page.
    - Turn off **Deep Crawl** and import one page first to confirm the site can be read.
  </Accordion>
  <Accordion title="I can't see Create KB or Add Documents">
    You need the workspace **Admin** role. Ask a workspace admin to add the documents or change your role.
  </Accordion>
</AccordionGroup>

A skill is a written procedure or set of rules, stored as a `SKILL.md` file, that agents follow when the task in front of them matches it. Write your triage steps, review checklist, or naming convention once, and agents apply it without you repeating it in every prompt.

## When to use a skill

Use a skill when you repeat the same instruction across prompts. Use the [knowledge base](/guide/knowledge) when agents need facts to look up rather than steps to follow.

The rule for runbooks: a runbook written as steps the agent must follow is a skill. A long reference document the agent should look things up in is knowledge.

| | Skill | Knowledge base |
|---|---|---|
| Holds | Procedures and rules agents follow | Documents and websites agents search |
| Examples | Step-by-step triage runbook, review checklist, tagging policy | Architecture docs, vendor manuals, past postmortems |
| Changes | How the agent works | What the agent knows |
| Format | A `SKILL.md` file, written in CloudThinker or uploaded in a `.zip` | Uploaded files or crawled websites |

A skill can point agents at a knowledge base document, so the two work well together.

## How a skill gets used

A skill is used only when all three are true:

1. **It is enabled.** The switch on the skill is on. New skills start enabled.
2. **It is available on the surface.** Under **Available in**, the surface where the work happens is checked: **Chat**, **Review** (merge and pull requests), **Incident** (incident analysis and root cause in [Resolve](/guide/incident/overview)), or **Assessment** (well-architected and posture assessments). New skills start with **Chat** only. Runs with no surface of their own, such as automations and webhooks, use the **Chat** set.
3. **It fits the task.** On every surface, including Review, the agent sees only the skills available there and loads the ones whose name and description match the work. It can load several skills for one task. So write the description in the words of the request.

You can also run a skill by name: type `/` in the chat prompt box and pick it from the menu. The menu lists every enabled skill, but in chat an agent can load only skills with **Chat** checked, so keep **Chat** ticked on any skill you want to run this way. When an agent uses a skill, its activity shows a **Load Skill** step.

CloudThinker also ships public skills in the [Skills Hub](https://www.cloudthinker.io/skills). A hub skill's install link opens an **Install Skill** page in CloudThinker, where **Install** adds it to your workspace. An installed hub skill becomes a skill in your workspace that you manage like your own, and it doesn't change when the hub version does. Hub skill names are reserved, so your own skills can't reuse them; the hub is the list to check.

## Who can do what

Only workspace **Admins** can create, edit, attach, or delete skills, including turning the switch on or off and changing **Available in**. Developers can see the skills list and run skills with `/`. Viewers can see skills but can't chat, so they can't run them. See [roles](/guide/security/roles).

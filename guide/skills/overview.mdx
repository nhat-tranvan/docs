A skill is a written procedure or set of rules, stored as a `SKILL.md` file, that agents follow when the task in front of them matches it. Write your runbook, review checklist, or naming convention once, and agents apply it without you repeating it in every prompt.

## When to use a skill

Use a skill when you find yourself typing the same instruction into more than two prompts. Use the [knowledge base](/guide/knowledge) when agents need facts to look up rather than steps to follow.

| | Skill | Knowledge base |
|---|---|---|
| Holds | Rules and procedures agents follow | Documents and websites agents search |
| Examples | Incident runbook, review checklist, tagging policy | Architecture docs, vendor manuals, past postmortems |
| Changes | How the agent works | What the agent knows |
| Format | A `SKILL.md` file, written in CloudThinker or uploaded in a `.zip` | Uploaded files or crawled websites |

A skill can point agents at a knowledge base document, so the two work well together.

## How a skill gets used

A skill is used only when all three are true:

1. **It is enabled.** The switch on the skill is on. New skills start enabled.
2. **It is available on the surface.** Under **Available in**, the surface where the work happens is checked: **Chat**, **Review** (merge and pull requests), **Incident** (incident analysis and root cause), or **Assessment** (well-architected and posture assessments). New skills start with **Chat** only.
3. **It fits the task.** In Chat, Incident, and Assessment, the agent picks the skills whose name and description match the work. Review applies attached skills during pull request analysis.

You can also run a skill by name: type `/` in the chat prompt box and pick it from the menu.

CloudThinker also ships public skills in the [Skills Hub](https://www.cloudthinker.io/skills). Their names are reserved, so your workspace skills can't reuse them.

## Prerequisites

- The workspace **Admin** role. Without it, **New Skill** and the edit controls are hidden.
- For a skill attached to Review, a connected repository. See [Review setup](/guide/code-review/setup).

## Create a skill

<Steps>
  <Step title="Open Skills">
    Open **Settings → Skills**. The page lists every workspace skill on the left and the selected skill's content on the right.
  </Step>
  <Step title="Pick how to create it">
    Click **New Skill** and pick one option:

    | Option | Best for | What happens |
    |--------|----------|--------------|
    | **Create with CloudThinker** | Your first skill, or turning a rough idea into a structured one | A chat opens with `/create-skill`. CloudThinker asks what the skill should do and drafts the `SKILL.md`. |
    | **Write skill instructions** | A procedure you already have written down | A form with **Skill name**, **Description**, and **Instructions** (Markdown). Click **Create**. |
    | **Upload zip file** | A skill you keep in Git or share between workspaces | Drop a `.zip` of up to 5 MB that contains a `SKILL.md`. Click **Upload**. |
    | **Browse Skills Hub** | Seeing what public skills look like | Opens the public catalog in a new tab |

    **Skill name** accepts letters, numbers, hyphens, and underscores, and must start with a letter or number, for example `ec2-high-cpu-runbook`.
  </Step>
  <Step title="Write a description that matches real requests">
    Agents choose a skill by its name and description, so describe when to use it in the words people actually type. For example:

    ```text
    Steps to investigate an EC2 instance with high CPU or a slow instance report
    ```

    **Success state:** the new skill appears in the list with its switch on and **Chat** checked.
  </Step>
  <Step title="Attach it where it belongs">
    Select the skill. Under **Available in**, check each surface where it should apply, and uncheck the rest. Hover a surface to see what it covers.

    Start with **Chat** only, test it, then add **Review**, **Incident**, or **Assessment**.
  </Step>
  <Step title="Test it">
    Ask for work the skill should change, without restating the rule. For a runbook skill:

    ```text
    Instance i-0abc1234def567890 feels slow. Investigate it.
    ```

    **Success state:** the answer follows the skill's steps. If it doesn't, sharpen the description and add a concrete example to the instructions, then ask again.
  </Step>
</Steps>

For the `SKILL.md` structure, frontmatter fields, and a complete example, see [Skill format](/guide/skills/skill-format).

## Manage a skill

Select a skill in **Settings → Skills** to see its file tree and rendered content.

| Action | How |
|--------|-----|
| Turn it off without deleting it | Use the switch next to the skill name. A disabled skill stays saved but isn't used anywhere. |
| Edit with AI | Click **Edit skill**, then **CloudThinker**. A chat opens that loads the skill and helps you refine it. |
| Edit by hand | Click **Edit skill**, then **Manual**. The `name` in the frontmatter must stay the same as the skill name. |
| Download | Click **Download** to save the skill package |
| Delete | Click **Delete skill** |

<Warning>
Deleting a skill can't be undone. Turn it off instead if you might need it again.
</Warning>

## Troubleshooting

<AccordionGroup>
  <Accordion title="This skill name is already in use">
    Another skill in this workspace has that name. Pick a different name, or edit the existing skill.
  </Accordion>
  <Accordion title="This skill name is reserved">
    The name matches a public skill CloudThinker ships. Pick a different name, for example by adding your team's prefix.
  </Accordion>
  <Accordion title="Only .zip files are accepted">
    Put your `SKILL.md` in a folder, zip the folder, and upload the `.zip`. The file must be 5 MB or smaller.
  </Accordion>
  <Accordion title="The agent ignores my skill">
    Check three things in order: the switch is on, the right surface is checked under **Available in**, and the description uses the words your request uses. One skill per topic also helps: a skill that mixes security and cost rules matches neither well.
  </Accordion>
  <Accordion title="I can't see New Skill">
    You need the workspace **Admin** role. Ask a workspace admin to add the skill or change your role.
  </Accordion>
</AccordionGroup>

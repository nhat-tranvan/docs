A custom skill is a set of written instructions (a `SKILL.md` file) that teaches CloudThinker your team's way of doing a job, such as a review checklist, an escalation order, or a tagging convention. You write it once in **Settings → Skills**, and agents apply it wherever you make it available, so nobody retypes the same rule into every prompt.

## When to write a skill

Write a skill when you catch yourself repeating the same instruction. Some typical ones:

| Area | Example rule a skill can carry |
|---|---|
| Review | "Flag any SQL built with string concatenation. Require parameterized queries." |
| Incident | "Check the load balancer and the database before the application pods." |
| Cloud operations | "Every resource needs `team`, `env`, and `cost-center` tags." |
| Reports | "Summarize in three sections: wins, blockers, next steps." |

A skill tells agents **how to act**. For facts and documents agents should look up (runbooks, architecture docs, policies), use the [knowledge base](/guide/knowledge) instead.

## Prerequisites

- A CloudThinker workspace.
- The workspace **Admin** role. Developers and Viewers can read skills but don't see **New Skill**. See [roles](/guide/security/roles).
- If you plan to write `SKILL.md` by hand or upload a package, skim [skill format](/guide/skills/skill-format).

## Create a skill

<Steps>
  <Step title="Open Skills">
    Go to **Settings → Skills**. The page lists your workspace's skills on the left and shows the selected skill on the right.
  </Step>
  <Step title="Click New Skill">
    Pick one of the creation methods from the **New Skill** menu. Use the tabs below for the one you chose.
  </Step>
  <Step title="Create the skill">
    <Tabs>
      <Tab title="Create with CloudThinker">
        Best for a first skill. CloudThinker interviews you and drafts the file.

        1. Click **Create with CloudThinker**. A chat opens with the `/create-skill` command filled in.
        2. Send it, then answer the questions. Describe one concrete rule your team applies, with an example.
        3. Review the draft CloudThinker proposes and confirm it.

        You can start the same flow from any chat by typing `/create-skill`.
      </Tab>
      <Tab title="Write skill instructions">
        Best when you already know the exact rules.

        1. Click **Write skill instructions**.
        2. Fill in the form:

        | Field | What to enter |
        |---|---|
        | **Skill name** | Starts with a letter or digit; then letters, digits, `_`, or `-`. Example: `weekly-status-report`. Up to 255 characters. |
        | **Description** | When agents should use the skill. Example: "Generate weekly status reports. Use when asked for updates or progress summaries." The form marks it optional, but fill it in: a skill without a description fails to save. Up to 2,000 characters. |
        | **Instructions** | The rules, in Markdown. Up to 50,000 characters. |

        3. Click **Create**.
      </Tab>
      <Tab title="Upload zip file">
        Best for skills you keep in a repository or share between workspaces.

        1. Click **Upload zip file**.
        2. Drop a `.zip` (5 MB maximum) that contains `SKILL.md`. Optional folders: `scripts/`, `schemas/`, `references/`.
        3. Click **Upload**.

        `SKILL.md` must start with frontmatter that has both `name` and `description`. If a skill with the same name exists, CloudThinker asks whether to **Replace** it. See [skill format](/guide/skills/skill-format) for the package layout.
      </Tab>
      <Tab title="Browse Skills Hub">
        Click **Browse Skills Hub** to open the public catalog of skills CloudThinker publishes, in a new tab. Use it for ideas and ready-made patterns.
      </Tab>
    </Tabs>

    **Success state:** the skill appears in the list with its switch on and **Chat** checked under **Available in**.
  </Step>
</Steps>

## Choose where the skill applies

A new skill starts enabled and available in Chat only. The other areas stay off until you turn them on, so a half-tested rule can't change your reviews or incident work.

<Steps>
  <Step title="Select the skill">
    In **Settings → Skills**, click the skill in the list.
  </Step>
  <Step title="Check the areas under Available in">
    Tick each place the skill should apply:

    | Option | Where agents use it |
    |---|---|
    | **Chat** | Workspace chat |
    | **Review** | Reviewing merge requests and pull requests in [Review](/guide/code-review/overview) |
    | **Incident** | Incident analysis and root cause investigation in [Resolve](/guide/incident/overview) |
    | **Assessment** | Well-architected and posture assessments |

    Clear every box to hide the skill everywhere while keeping it saved.
  </Step>
  <Step title="Confirm the switch is on">
    The switch next to the skill name enables or disables it. A disabled skill stays saved but no agent uses it.
  </Step>
</Steps>

## Test the skill

<Steps>
  <Step title="Run a task where the rule matters">
    In chat, type `/` and pick your skill by name, or ask for work the skill covers without naming it. For a skill called `weekly-status-report`:

    ```text
    /weekly-status-report for the platform team this week
    Write a status update on what the platform team shipped this week
    ```

    **Success state:** both answers follow the skill (here, the wins, blockers, next steps layout) without you restating the rule.
  </Step>
  <Step title="Widen it once it works">
    After a few good results in Chat, tick **Review**, **Incident**, or **Assessment** and check the next run there.
  </Step>
</Steps>

If the output ignores the rule, make the rule more specific and add a good and a bad example. Vague guidance such as "follow our style" rarely changes results.

## Edit, download, or delete a skill

Select the skill, then use the buttons next to **Available in**:

| Action | How | Notes |
|---|---|---|
| Edit with CloudThinker | Pencil icon → **CloudThinker** | Opens a chat that loads the skill and helps you refine it. |
| Edit by hand | Pencil icon → **Manual** | Edits `SKILL.md` directly. Use **Preview** to check rendering, then **Save**. The `name` in the frontmatter must stay the same. |
| Download | Download icon | Saves the skill as a `.zip` you can upload to another workspace. |
| Delete | Trash icon | Permanent. |

<Warning>
Deleting a skill can't be undone. Turn the switch off instead if you might need it again, or download it first.
</Warning>

## Troubleshooting

<AccordionGroup>
  <Accordion title="This skill name is already in use">
    Another skill in this workspace has that name. Pick a different name, or upload a `.zip` and choose **Replace** to overwrite the existing one.
  </Accordion>
  <Accordion title="This skill name is reserved">
    The name matches a skill CloudThinker ships in its public catalog. Pick a different name.
  </Accordion>
  <Accordion title="Failed to create skill">
    The usual cause is an empty **Description**. Add one sentence saying when to use the skill and click **Create** again.
  </Accordion>
  <Accordion title="Failed to upload skill to executor">
    Usually the `SKILL.md` frontmatter is missing, invalid, or lacks a `name` or `description`. See [skill format troubleshooting](/guide/skills/skill-format#troubleshooting).
  </Accordion>
  <Accordion title="Only .zip files are accepted">
    The upload accepts `.zip` only. Put `SKILL.md` (and any `scripts/`, `schemas/`, or `references/` folders) in a folder, zip it, and upload the zip.
  </Accordion>
  <Accordion title="No agent can load this skill">
    The skill's `SKILL.md` frontmatter has no usable `description`. Edit it by hand, add a `description:` line, and click **Save**. Until then the skill doesn't appear in the `/` menu.
  </Accordion>
  <Accordion title="Cannot preview this skill">
    The skill's file content can't be loaded. Click **Recovery with AI** to rebuild the `SKILL.md` with CloudThinker through a short interview, or click **Re-upload** to restore it from a `.zip` you kept (for example one you downloaded earlier).
  </Accordion>
  <Accordion title="The agent ignores the skill">
    - Check that the switch is on.
    - Check that the right area is ticked under **Available in** (for example **Review** for pull request reviews).
    - Make the instructions concrete and add examples. Split a long, broad skill into several short ones.
  </Accordion>
</AccordionGroup>

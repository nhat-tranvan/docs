Deleting the stack removes the cluster, nodes, load balancer, and network gateways. It keeps your data on purpose, so a mistaken delete never loses it.

<Warning>
**Kept resources keep costing money.** The Aurora cluster, S3 bucket, KMS key, and secrets stay billed until you delete them yourself.
</Warning>

## Delete the stack

<Steps>
  <Step title="Take a final snapshot">
    Check your backups, or take a manual snapshot of the Aurora cluster, if you might need the data later. See [Backup and restore](/guide/deployment/aws-marketplace/backup-and-restore).
  </Step>
  <Step title="Note the kept resources">
    Open the nested stack, whose name contains `-Enterprise-`, and copy `KeptResources` from its **Outputs** tab. It lists what stays after the delete.
  </Step>
  <Step title="Delete the top-level stack">
    In the CloudFormation console, select the top-level stack, the one you named at launch, and choose **Delete**. CloudFormation deletes the nested stack with it. Never delete the nested stack on its own. The managed address is released.
  </Step>
  <Step title="Retry if it stops on a dependency">
    If the delete stops with `DependencyViolation` on a subnet or security group, wait about 15 minutes and delete again. AWS removes the installer's network interfaces a few minutes after the function is gone.
  </Step>
</Steps>

## Remove the kept resources

Only do this when you are sure you no longer need the data. Retained resources carry the tag `aws:cloudformation:stack-name` with the nested stack's name, which helps you find them.

| Order | Resource | How to remove it |
|---|---|---|
| 1 | Aurora cluster and instance | RDS console: modify the cluster to turn off deletion protection, delete the instance, then delete the cluster. Deleting the cluster also deletes its automated backups. A final snapshot is optional, and it keeps costing money too. |
| 2 | Pre-upgrade snapshots | RDS console, **Snapshots**, **Manual** tab: the snapshots taken before each upgrade. Delete the ones you no longer need. |
| 3 | S3 bucket | Empty the bucket, including old versions, then delete it. |
| 4 | Secrets Manager secrets | Delete the database, app database, and app keys secrets, the AWS Marketplace deployment secret, and your SMTP password secret if you made one. |
| 5 | DB subnet group and cluster parameter group | RDS console, **Subnet groups** and **Parameter groups** |
| 6 | Security groups | The database security group, and any group the stack left behind |
| 7 | VPC and data subnets | Delete the data subnets, then the VPC. |
| 8 | SES identities | SES console, **Identities**: the sender and administrator identities, if nothing else uses them |
| 9 | CloudWatch log groups | The installer's log groups, if you do not need the logs |
| 10 | KMS key | Last. Schedule the key's deletion (7 to 30 days). After that, any backup encrypted with it can never be read. |

If you keep any snapshot or backup, keep the KMS key and the app keys secret too. Without both, the data in it can't be read.

## Cancel the subscription

Deleting the stack does not end the contract. Manage the subscription in the AWS Marketplace console, under **Manage subscriptions**. See [Contract and billing](/guide/deployment/aws-marketplace/contract-and-billing).

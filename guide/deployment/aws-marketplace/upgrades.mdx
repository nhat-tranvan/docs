CloudThinker Enterprise upgrades itself inside your account. You choose whether each release installs on its own, waits for an administrator, or waits until you change the setting.

## How releases arrive

An upgrader runs in your cluster. It checks the CloudThinker billing endpoint for new releases and pulls the software from AWS Marketplace. Nothing from CloudThinker connects into your account.

Administrators manage upgrades on the **License** page in CloudThinker settings. The page shows the current version, the next release, and the update settings. Changes to the settings reach the upgrader within 5 minutes.

## Update mode

| Mode | What happens |
|---|---|
| **Auto** | Upgrades run on their own in the update window. |
| **Approve** | An administrator approves each release. It runs in the next window, or right away with **Upgrade now**. |
| **Manual** | Pinned. Nothing upgrades until you switch to Approve or Auto. |

## Release channel

| Channel | When a release reaches you |
|---|---|
| **Stable** | As soon as CloudThinker publishes it |
| **Delayed** | 14 days after it reaches Stable |

## Update window and Upgrade now

The update window sets the days, start time, length, and time zone when upgrades may run. By default it opens every day at 02:00 for 4 hours.

**Upgrade now** starts the next release within 5 minutes, outside the window, in Auto or Approve mode. A release with database changes that cannot be undone still waits for the window.

## Before each upgrade

The release card shows whether the release changes the database, the expected downtime, the health check timeout, and whether it is a security release. Use **Copy as change request** to paste these details into your own change process.

When a release changes the database, the upgrader takes an Aurora snapshot first. The 3 most recent pre-upgrade snapshots are kept. See [Backup and restore](/guide/deployment/aws-marketplace/backup-and-restore).

## Rollback

After an upgrade, the upgrader runs a health check. If it fails, the upgrader rolls back to the previous version on its own.

<Warning>
Some releases change data in a way that cannot be undone. The release card says so. Those releases have no automatic rollback: if one fails, upgrades stop and you need CloudThinker's help to restore from the pre-upgrade snapshot.
</Warning>

## Banners on the License page

| Banner | What it means | What to do |
|---|---|---|
| **Upgrade stuck** | The last upgrade failed and could not roll back. Automatic upgrades are paused. | [Contact CloudThinker](https://cloudthinker.io/contact). Once the cause is fixed, choose **Upgrade now**. |
| **Needs a stack update** | The next release changes cluster-wide objects, so the stack needs a new template version first. The upgrader waits until then. | Contact CloudThinker for the new template version and update the top-level stack with it. Never update the nested stack. |
| **Outside the support window** | Only the two newest minor releases get fixes. | Upgrade to a supported release. |

## Security releases

A release that fixes a security issue is marked **Security release** on the release card. Approve or schedule it promptly, especially in Approve or Manual mode, where it does not install on its own.

Check these items in the AWS account and Region where CloudThinker Enterprise will run. A short quota or a missing permission makes the stack roll back partway through.

## Account quotas

Open [Service Quotas](https://console.aws.amazon.com/servicequotas/home) in the Region you plan to use and compare each quota with what is already in use.

| Quota | Service | The stack needs |
|---|---|---|
| Running On-Demand Standard (A, C, D, H, I, M, R, T, Z) instances | Amazon EC2 | 16 vCPUs for the default four `m7i.xlarge` nodes. Ask for at least 20, so a node upgrade can add a temporary node. |
| EC2-VPC Elastic IPs | Amazon EC2 | 1 |
| NAT gateways per Availability Zone | Amazon VPC | 1 |
| VPCs per Region | Amazon VPC | 1 |
| Clusters | Amazon EKS | 1 |

A new AWS account often starts at 16 vCPUs or less. Quota increases can take from minutes to a few days, so request them before you launch.

## Deployment permissions

The person or role that launches the stack needs two IAM permission policies. Both are required.

| Policy | What it covers |
|---|---|
| **Core** | Shown with the template on the AWS Marketplace **Configure and launch** page. Covers CloudFormation, the network, EKS, Aurora, ElastiCache, Lambda, certificates, and logs. |
| **Supplemental** | Provided with the launch instructions. Covers the remaining actions: attaching policies to the stack's roles, the cluster's identity provider, KMS key use, reading the deployment secret, and code signing for the installer. |

Both policies are scoped to what the template creates. IAM actions reach only the roles this stack names, and service-linked roles only for the services the stack uses. An administrator with the `AdministratorAccess` managed policy already has everything and needs neither.

<Warning>
Whoever can launch or update this stack can change the permissions of the roles it creates. Give the deployment policies only to people you trust with the whole install.
</Warning>

## Marketplace deployment role

The first time you use **Launch template**, AWS Marketplace asks you to **Enable integration**. This creates the AWS service-linked role `AWSServiceRoleForMarketplaceDeployment`, which lets Marketplace store the install's deployment settings in AWS Secrets Manager in your account. Your account needs the right to create that role once.

## Information to have ready

- The administrator's email address. This person signs in first.
- How the app sends email: none for now (set it up later), Amazon SES in your account, or your own SMTP server. See [Email](/guide/deployment/aws-marketplace/email).
- Who should reach the app: your private network only, or the internet limited to your IP ranges. See [Network access](/guide/deployment/aws-marketplace/network-access).

## How long it takes

| Stage | Typical time |
|---|---|
| Stack create, from launch to complete | about 17 minutes |
| App usable at `<your-install-address>` | about 23 minutes after launch |

All CloudThinker Enterprise data lives in your AWS account: the Aurora PostgreSQL database and the S3 bucket. AWS features you already know protect both.

## What is backed up

| Data | Protection | Kept for |
|---|---|---|
| Aurora PostgreSQL database | Automated backups with point-in-time restore. Deletion protection on. | 7 days |
| Aurora snapshots before upgrades | A manual snapshot is taken before each CloudThinker release upgrade. | Until you delete it |
| S3 bucket (files, attachments, images) | Versioning on. A deleted or overwritten file keeps its previous version. | Old versions for 30 days |
| App keys and database passwords | AWS Secrets Manager, encrypted with the stack's KMS key | Kept when the stack is deleted |

The cache holds only short-lived data and is not backed up.

To keep backups longer or copy them to another Region or account, add the Aurora cluster and the bucket to your own [AWS Backup](https://docs.aws.amazon.com/aws-backup/latest/devguide/whatisbackup.html) plan.

## Take a manual snapshot

Before a risky change, take a snapshot in the RDS console: select the Aurora cluster, then **Actions → Take snapshot**. Manual snapshots stay until you delete them.

## Restore to a new stack

<Warning>
**Verify before relying on it.** This restore path has not been tested end to end. Rehearse it in a test account, and contact CloudThinker before you restore a production install.
</Warning>

The data is readable only with the same KMS key and the same app keys secret. Never delete either while you might restore.

1. Restore the Aurora cluster to a point in time, or restore a snapshot, as a new cluster encrypted with the original KMS key.
2. Keep the original S3 bucket, or copy its objects to a new bucket encrypted with the same key.
3. Contact CloudThinker with the restored cluster, bucket, and secrets. CloudThinker helps you launch a new stack that uses them.
4. Sign in and check recent conversations, files, and connections before you switch users over.

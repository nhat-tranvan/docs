CloudThinker runs as a hosted service at [app.cloudthinker.io](https://app.cloudthinker.io), and most teams never need anything else. When some work has to happen inside your network, you have two options: Workers for individual folders and hosts, or a private deployment of the whole platform.

## Pick a model

| Model | Where it runs | Use it when | How to get it |
|---|---|---|---|
| **CloudThinker Cloud** | Shared service managed by CloudThinker | You want to start today with no infrastructure to run. | [Sign up](/quickstart) |
| **CloudThinker Cloud + Workers** (Beta) | Platform in the cloud. File and shell work runs on machines you control. | The agent must work in a private repository or reach an internal host, but connection credentials can stay in the cloud. | [Set up a Worker](/guide/workers) |
| **Dedicated cloud** | Single-tenant instance hosted by CloudThinker in a region you choose | You need tenant isolation or a specific region. Available regions are confirmed during onboarding. | [Contact sales](https://cloudthinker.io/contact) |
| **Bring your own cloud** (self-hosted or air-gapped) | Inside your own cloud account or data center, offline if needed | Policy says data can't leave your perimeter. | [Contact sales](https://cloudthinker.io/contact) |

<Note>
**Early access.** Dedicated, self-hosted, and air-gapped deployments are offered through a design-partner program. System requirements, supported topologies, pricing, upgrade paths, who runs operations, and how the model is provided without internet access are confirmed during onboarding, not published here.
</Note>

## Try Workers before a private deployment

Workers are in beta: CLI command names and flags may change before general availability. A Worker often covers the need that prompts a self-hosting request, with nothing to install beyond the CLI. It's a folder on your machine where CloudThinker reads files and runs commands, connecting outward over HTTPS with no inbound port. Your firewall only needs to allow outbound HTTPS (port 443) to `app.cloudthinker.io`, directly or through an `HTTPS_PROXY`. If the proxy re-signs HTTPS, set `SSL_CERT_FILE` to your company CA bundle. Installing and updating the CLI also reaches `cloudthinker.io` and `github.com`.

| Your requirement | Covered by a Worker? |
|---|---|
| The agent edits code in a private repository | Yes. File tools stay inside the folder you serve. |
| The agent runs your internal CLIs or scripts | Yes. Shell commands run on the machine as your OS account. |
| Workspace connection credentials (AWS, Kubernetes, and more) never touch your hosts | Yes. Connection commands run in CloudThinker Cloud. Credentials already on the host can still be used by shell commands. |
| File contents and command output stay on the host | No. What the agent reads and the output it gets go to CloudThinker Cloud and the model. |
| Conversations, [memory](/guide/memory), and Skills stay inside your perimeter | No. These stay in CloudThinker Cloud. You need a private deployment. |
| Every component runs with no internet access | No. A Worker needs outbound HTTPS. You need an air-gapped deployment. |

If every row you care about says yes, start with [Workers](/guide/workers).

## Request a private deployment

<Steps>
  <Step title="Collect your requirements">
    Put these in your first message so the reply can be specific:

    - Region or data residency rules
    - Whether your hosts have internet access
    - The identity provider you use for sign-in
    - Roughly how many people will use CloudThinker
    - The clouds and accounts you plan to connect
    - The LLM provider you want to use, if you have one (see [BYOK](/guide/byok))
    - Any compliance frameworks your review checks against
  </Step>
  <Step title="Contact CloudThinker">
    Send those requirements through [cloudthinker.io/contact](https://cloudthinker.io/contact) and ask for a dedicated, self-hosted, or air-gapped deployment.

    **Success state:** you have a reply that says whether your environment fits the program and what onboarding needs from you.
  </Step>
  <Step title="Evaluate in the hosted cloud meanwhile">
    While you wait, connect a non-production account in CloudThinker Cloud to test the agents on real work. See the [Quickstart](/quickstart).
  </Step>
</Steps>

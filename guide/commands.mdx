You talk to CloudThinker in plain language, and three optional symbols make a request more precise: `@` picks an agent, `#` picks a connection, and `/` runs a skill, command, or chat action. A command is a saved prompt: type `/` plus its name and CloudThinker sends the full instruction for you.

## Prerequisites

- Developers and Admins can run commands. Commands run in the chat box, and Viewers can't chat with CloudThinker, so a Viewer can't run one.
- To create, edit, import, or delete commands, you need the **Developer** or **Admin** [workspace role](/guide/workspace-users).

Commands belong to the workspace, not to the person who made them. Every member sees them in the `/` menu, and any Developer or Admin can edit or delete any command that isn't built in.

## Prompt syntax

```text
@agent #connection your request
```

| Part | Required | What it does | Example |
| --- | --- | --- | --- |
| `@agent` | No | Sends the request to one of your workspace's [custom agents](/guide/agents/customize). Leave it out and CloudThinker, the built-in assistant, answers. Type `@` to pick from your workspace's agents. A name that matches no agent stays plain text, and CloudThinker answers | `@finops-reviewer` |
| `#connection` | No | Points CloudThinker at one connected system, such as an AWS account or a Kubernetes cluster. The `#` picker also lists your [knowledge bases](/guide/knowledge) | `#prod-aws` |
| `/name` | No | Runs a skill, a command, or a chat action from the `/` menu | `/security-configuration-audit` |
| Your request | Yes | What you need, in your own words. Add scope, time range, and the output shape you want | `top 5 cost drivers this month as a table` |

A plain sentence with none of the symbols works. Add `#connection` when the workspace has several accounts and the answer depends on which one CloudThinker reads.

```text
What changed in our AWS bill this week?
#prod-aws Which EC2 instances ran under 10% CPU for the last 14 days?
Summarize open critical findings for production as a dashboard
```

Ask for an output shape, such as a dashboard, a report, or a table, in words. The `#` picker selects connections and knowledge bases only, not output types.

## What the / menu shows

Type `/` in the CloudThinker chat box to open the menu. It has two groups, and typing after the `/` filters both.

| Group | What it contains |
| --- | --- |
| **Actions** | Controls for the current chat, listed below |
| **Skills and commands** | Your enabled [skills](/guide/skills/overview) (packaged procedures an agent follows) and every command in the workspace. Items you used recently sort first |

| Action | What it does |
| --- | --- |
| **Compact** | Summarizes the chat to free context. The summary is a model call, so it uses [credits](/guide/billing/usage) |
| **Side chat** | Asks a quick side question while this chat keeps running. It's a model call, so it uses credits too |
| **Context** | Shows how full the context window is |
| **Model** | Switches the model for this chat. The model's tier sets its [credit multiplier](/guide/billing/usage#what-makes-a-run-cost-more) |
| **Approval** | Sets the [approval mode](/guide/approvals/approval-mode) for this chat |
| **Attach files** | Adds files or images to the message |
| **Connection** | Opens a list of your connections and inserts the one you pick as a `#connection` token in your message. Same result as typing `#` |
| **Resume chat** | Continues a recent chat |
| **New chat** | Starts a fresh conversation. Shown inside an existing chat |
| **Rename** | Renames this chat |
| **Stop** | Stops the running reply. Shown while CloudThinker is answering |

## Built-in commands

Every workspace includes these commands. You can run and view them, but you can't edit or delete them.

### Setup helpers

These interview you or check your setup, then create or propose something.

| Command | What it does |
| --- | --- |
| `/create-agent` | Interviews you and helps design a new custom agent |
| `/create-skill` | Interviews you and helps create a new custom skill |
| `/create-automation` | Clarifies the trigger and the prompt, then creates an [automation](/guide/automation/automations) |
| `/create-custom-section` | Adds one custom section to [Review](/guide/code-review/overview) summaries on pull requests and merge requests |
| `/create-policy` | Checks your current approval setup and proposes a rule for you to accept |
| `/find-rules` | Reads your connections and approval history, then proposes the [approval rules](/guide/approvals/rules) this workspace needs |

`/create-policy` and `/find-rules` appear only where CloudThinker can write [approval rules](/guide/approvals/rules) for you. A rule you accept there only records what it would decide until CloudThinker turns on Rule enforcement for your workspace, which is off by default, so set the [Approval mode](/guide/approvals/approval-mode) for the behavior you need today. If the commands are missing from your `/` menu, contact CloudThinker support, or whoever runs CloudThinker for your company. See [Rules troubleshooting](/guide/approvals/rules#troubleshooting).

### Cloud analysis prompts

These are saved prompts with no fixed output format. CloudThinker runs them against the workspace's connected cloud accounts, so connect at least one first, and add `#connection` when you want one account.

| Command | What it does |
| --- | --- |
| `/resource-rightsizing-analysis` | Finds underused resources by CPU, memory, and storage usage |
| `/automated-backup-strategy` | Reviews backup schedules and retention for coverage and cost |
| `/monitoring-alerting-setup` | Sets up monitoring and alerts for utilization, performance, and cost anomalies |
| `/security-configuration-audit` | Audits access controls, encryption settings, and security practices |
| `/cost-allocation-tagging` | Plans consistent resource tags for cost allocation |

## Create a command

<Steps>
  <Step title="Open the Commands page">
    Switch to the right workspace in the workspace switcher at the top of the sidebar, then go to **More → Workspace settings → Commands**. The page lists only this workspace's commands. Tabs split the list into **All**, **Your Commands** (the ones your workspace created), and **CloudThinker's Commands** (built in), and **Search commands...** filters by name.
  </Step>
  <Step title="Click New Command">
    The **Create Command** dialog opens. Fill in the three fields:

    | Field | What to enter |
    | --- | --- |
    | **Title** | A readable name, such as `Weekly cost review` |
    | **Slug** | The name people type after `/`. CloudThinker fills it from the title. Use lowercase letters, numbers, hyphens, and underscores; other characters are dropped and long slugs are cut to 100 characters. If the slug is taken in this workspace, CloudThinker adds a number, such as `weekly-cost-review-1`. Avoid a slug that matches an enabled skill's name: the skill wins |
    | **Prompt** | The full instruction CloudThinker sends when the command runs. Up to 1,000 characters |
  </Step>
  <Step title="Click Create Command">
    **Success state:** the command appears under **Your Commands**, and typing `/` plus the first letters of its slug in any chat in the workspace shows it.
  </Step>
</Steps>

<Warning>
Check the slug on the new command's card before you share it. If CloudThinker added a number because the slug was taken, your team will type the wrong name. Rename it with **Edit** if needed.
</Warning>

<Tip>
Keep the stable part of the instruction in the command and type the variable part when you run it. A prompt such as `Review last week's spend for the account below, list the top 5 changes with their cost impact, and suggest one fix for each:` lets each run name its own account.
</Tip>

## Run a command

<Steps>
  <Step title="Type / and pick the command">
    Type `/` in the chat box, keep typing to filter, and select the command. The `/slug` token stays in your message.
  </Step>
  <Step title="Add context and send">
    Type anything extra after the token, then send:

    ```text
    /security-configuration-audit focus on the production AWS account
    ```

    CloudThinker replaces `/security-configuration-audit` with the command's full prompt before the agent reads your message. Slugs match without regard to case.

    **Success state:** the reply answers the saved instruction plus your added context, not the literal slug text.
  </Step>
</Steps>

## Edit or delete a command

On **More → Workspace settings → Commands**, hover over the command's card and click the **...** menu (**Open actions**).

- **Edit** opens the **Edit Command** dialog. Change the fields and click **Update Command**.
- **Delete** asks you to confirm in a **Delete Command** dialog. The slug stops expanding at once.

Built-in commands show **View** instead, because you can't change them.

Commands expand in the web app chat, inside the prompt of a [scheduled automation](/guide/automation/automations), and in a [headless CLI prompt](/guide/cli/headless-chat) (`cloudthinker chat -p`), so one saved instruction can serve chat, schedules, and scripts.

## Move commands between workspaces

Commands belong to one workspace. To reuse a set in another workspace:

<Steps>
  <Step title="Export from the source workspace">
    On **More → Workspace settings → Commands**, click **Export File**. CloudThinker downloads `shortcuts-export-<date>.json` with every command under **Your Commands**. Built-in commands are left out, and the active tab and search don't limit the export.

    ```json
    {
      "version": "1.0",
      "exported_at": "2026-10-25T09:00:00+00:00",
      "shortcuts": [
        {
          "title": "Weekly cost review",
          "slug": "weekly-cost-review",
          "content": "Review last week's spend and list the top 5 changes.",
          "category": null
        }
      ]
    }
    ```

    The file uses the product's older internal names:

    | Key | What it holds |
    | --- | --- |
    | `shortcuts` | The list of commands, up to 100 per import |
    | `title` | The command's **Title** |
    | `slug` | The command's **Slug**. Imports clean and de-duplicate it the same way the dialog does |
    | `content` | The command's **Prompt**. Imports enforce the same 1,000-character limit |
    | `category` | An optional label, up to 255 characters, or `null`. The **Create Command** dialog doesn't set it |
  </Step>
  <Step title="Import into the target workspace">
    Switch to the other workspace, open **More → Workspace settings → Commands**, click **Upload File**, and pick the JSON file. One file imports up to 100 commands.

    **Success state:** the commands appear under **Your Commands**. A command whose slug is already taken in that workspace gets a new slug automatically, so check the list before you share the names.
  </Step>
</Steps>

## Troubleshooting

<AccordionGroup>
  <Accordion title="A command doesn't expand when I send it">
    An enabled skill whose name matches the slug, ignoring case, wins the slug. The menu hides the command, and `/name` invokes the skill instead. Rename the command's slug on **More → Workspace settings → Commands**, or turn off the skill if you meant the command.
  </Accordion>
  <Accordion title="The / menu shows Nothing matches">
    No skill or command matches the text after the `/`, so **Enter** sends your message as typed. Clear the filter, or check the slug's spelling on **More → Workspace settings → Commands**.
  </Accordion>
  <Accordion title="I don't see New Command or Upload File">
    Your workspace role is **Viewer**. Ask a workspace Admin to give you the **Developer** role, or ask a Developer to create the command.
  </Accordion>
  <Accordion title="The prompt won't save">
    The **Prompt** field holds up to 1,000 characters, and **Title**, **Slug**, and **Prompt** are all required. For longer procedures, build a [custom skill](/guide/skills/custom-skills) instead.
  </Accordion>
</AccordionGroup>

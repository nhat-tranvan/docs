Workspace settings shape how CloudThinker works inside one [workspace](/guide/workspaces): what it can reach, how agents behave, and which changes need a person. Open them from **More → Workspace settings** at the bottom of the sidebar's top menu.

What you can change in each tab depends on your workspace role; see [Roles](/guide/security/roles).

## Every tab

The settings rail groups the tabs into four sections, in this order.

| Group | Tab | What you set there | Learn more |
|---|---|---|---|
| Workspace | **General** | The workspace name and description, plus the **Capabilities** switches for Advisor, Blind Spot and Conversation recaps | [Workspaces](/guide/workspaces), [Capabilities](/guide/capabilities) |
| Workspace | **Members** | Who is in the workspace and their workspace role | [Workspace members](/guide/workspace-users) |
| Workspace | **Branding** | Your logo, company name and color palette on PDF exports and artifact charts | [Branding](/guide/workspace-branding) |
| Workspace | **BYOK** | Your own LLM credentials for this workspace | [BYOK](/guide/byok) |
| Agent Configuration | **Connections** | The cloud accounts, clusters, repositories and tools agents can use | [Connections](/guide/connections/overview) |
| Agent Configuration | **Skills** | Procedures and runbooks agents follow, written as `/skill-name` | [Skills](/guide/skills/overview) |
| Agent Configuration | **Memory** | What agents remember from past work in this workspace | [Memory](/guide/memory) |
| Agent Configuration | **Agents** | Custom agents with their own role, goal and connections | [Customize](/guide/agents/customize) |
| Agent Configuration | **Knowledge** | Documents agents can search when they answer | [Knowledge](/guide/knowledge) |
| Agent Configuration | **Credentials** | Secrets agents can use by name, without seeing the value | [Credentials](/guide/credentials) |
| Workflow | **Artifacts** | Dashboards and reports agents created | [Artifacts](/guide/artifacts/overview) |
| Workflow | **Commands** | Saved prompts your team runs with `/` | [Commands and prompts](/guide/commands) |
| Workflow | **Approvals** | Which agent changes run on their own, wait for a person, or are refused | [Approvals](/guide/approvals/overview) |
| Integrations | **Notifications** | Which events reach email, Slack, Teams or Google Chat | [Notifications](/guide/notifications) |

**Automations** has no tab here. It gets a row of its own in the sidebar, because each automation opens its own page. See [Automations](/guide/automation/automations).

Every role sees every tab except **BYOK**, which only workspace Admins see. Developers and Viewers can open the rest but can't save most changes, and **Credentials** opens locked with "Credentials are restricted" so stored values stay hidden. **Knowledge** is hidden when the Knowledge Base module is turned off for your workspace.

Organization-wide settings, such as billing, SSO and audit logs, live in [Admin Settings](/guide/admin-settings) instead.

## Set up a new workspace

A workspace is ready for real work after these four tabs. Do them in this order:

1. **Connections:** connect the systems agents should investigate, read-only first.
2. **Approvals:** choose how changes are approved before you allow any writes.
3. **Members:** invite the people who will work here.
4. **Notifications:** send findings and approval requests where your team already looks.

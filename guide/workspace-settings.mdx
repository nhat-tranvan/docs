Workspace settings shape how CloudThinker works inside one [workspace](/guide/workspaces): what it can reach, how agents behave, and which changes need a person. Open them from **More → Workspace settings** at the bottom of the sidebar's top menu.

What you can change in each tab depends on your workspace role; see [Roles](/guide/security/roles).

## Every tab

| Tab | What you set there | Learn more |
|---|---|---|
| **General** | The workspace name and other general details | [Workspaces](/guide/workspaces) |
| **Members** | Who is in the workspace and their workspace role | [Workspace members](/guide/workspace-users) |
| **Branding** | Your logo, company name and color palette on PDF exports and artifact charts | [Branding](/guide/workspace-branding) |
| **BYOK** | Your own LLM credentials for this workspace | [BYOK](/guide/byok) |
| **Connections** | The cloud accounts, clusters, repositories and tools agents can use | [Connections](/guide/connections/overview) |
| **Skills** | Procedures and runbooks agents follow, written as `/skill-name` | [Skills](/guide/skills/overview) |
| **Agents** | Custom agents with their own role, goal and connections | [Customize](/guide/agents/customize) |
| **Knowledge** | Documents agents can search when they answer | [Knowledge](/guide/knowledge) |
| **Credentials** | Secrets agents can use by name, without seeing the value | [Credentials](/guide/credentials) |
| **Automations** | Agent work that runs on a schedule or an event | [Automations](/guide/automation/automations) |
| **Artifacts** | Dashboards and reports agents created | [Artifacts](/guide/artifacts/overview) |
| **Commands** | Saved prompts your team runs with `/` | [Commands and prompts](/guide/commands) |
| **Approvals** | Which agent changes run on their own, wait for a person, or are refused | [Approvals](/guide/approvals/overview) |
| **Notifications** | Which events reach email, Slack, Teams or Google Chat | [Notifications](/guide/notifications) |
| **Memory** | What agents remember from past work in this workspace | [Memory](/guide/memory) |

Organization-wide settings, such as billing, SSO and audit logs, live in [Admin Settings](/guide/admin-settings) instead.

## Set up a new workspace

A workspace is ready for real work after these four tabs. Do them in this order:

1. **Connections:** connect the systems agents should investigate, read-only first.
2. **Approvals:** choose how changes are approved before you allow any writes.
3. **Members:** invite the people who will work here.
4. **Notifications:** send findings and approval requests where your team already looks.

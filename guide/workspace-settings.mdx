Workspace settings shape how CloudThinker works inside one [workspace](/guide/workspaces): what it can reach, how agents behave, and which changes need a person. What you can change on each page depends on your workspace role; see [Roles](/guide/security/roles).

## Open Settings

Settings is one screen with three tabs at the top: **Personal**, **Workspace**, and **Organization**. Open it in any of these ways:

- Click the workspace menu at the top of the sidebar, then **Settings**. Settings opens on the **Workspace** tab.
- Click your account menu at the bottom of the sidebar, then **Settings**. Settings opens on the **Personal** tab.
- Press ⌘, on macOS, or Ctrl+, on Windows and Linux.

These docs write a page's location as a path, such as **Settings → Workspace → Connections**.

## Every page

The **Workspace** tab groups its pages into four sections, in this order.

| Group | Page | What you set there | Learn more |
|---|---|---|---|
| Overview | **General** | The workspace name and description, plus the **Branding** section: your logo, company name, and color palette on PDF exports and charts | [Workspaces](/guide/workspaces), [Branding](/guide/workspace-branding) |
| Overview | **Members** | Who is in the workspace and their workspace role | [Workspace members](/guide/workspace-users) |
| Overview | **Connections** | The cloud accounts, clusters, repositories, and tools agents can use | [Connections](/guide/connections/overview) |
| Overview | **Notifications** | Which events reach email, Slack, Teams, or Google Chat | [Notifications](/guide/notifications) |
| Agents & context | **Agents** | Custom agents with their own role, goal, and connections | [Customize](/guide/agents/customize) |
| Agents & context | **Skills** | Procedures and runbooks agents follow, run as `/skill-name` | [Skills](/guide/skills/overview) |
| Agents & context | **Memory** | What agents remember from past work in this workspace | [Memory](/guide/memory) |
| Agents & context | **Capabilities** | The switches for Advisor and Blind Spot | [Capabilities](/guide/capabilities) |
| Access & keys | **Environments** | Where agent commands run in this workspace | [Environments](/guide/workers) |
| Access & keys | **Credentials** | Secrets agents can use by name, without seeing the value | [Credentials](/guide/credentials) |
| Access & keys | **BYOK** | Your own LLM credentials for this workspace | [BYOK](/guide/byok) |
| Autonomy | **Rules** | Which agent writes run on their own, wait for a person, or are refused, and what happens when no Rule matches | [Rules](/guide/approvals/rules), [Approval mode](/guide/approvals/approval-mode) |
| Autonomy | **Approvers** | Who answers approval requests | [Approvers](/guide/approvals/approvers) |
| Autonomy | **Runbooks** | Fix procedures Resolve can propose during an incident | [Runbooks](/guide/incident/runbooks) |

**Automations** has no page here. It gets a row of its own in the sidebar, because each automation opens its own page. See [Automations](/guide/automation/automations). Dashboards and reports agents built live in **More → Library** in the sidebar.

Every role sees every page except **BYOK**, which only workspace Admins see. Developers and Viewers can open the rest but can't save most changes. On **Credentials** they see "Ask a workspace admin for edit access to view and manage stored credentials." instead of the list.

Organization-wide settings, such as billing, SSO, and audit logs, live on the **Organization** tab instead. See [Organization settings](/guide/admin-settings).

## Set up a new workspace

A workspace is ready for real work after these four pages. Do them in this order:

1. **Connections:** connect the systems agents should investigate, read-only first.
2. **Autonomy → Rules:** choose how changes are approved before you allow any writes.
3. **Members:** invite the people who will work here.
4. **Notifications:** send findings and approval requests where your team already looks.

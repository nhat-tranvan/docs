A custom source connects a system that has no preset in Resolve: an in-house uptime checker, a cron job, a deploy script, or a vendor CloudThinker doesn't list yet. If it can send an HTTP POST with a JSON body, its events can open incidents and trigger a root cause analysis (RCA).

## How it works

You create an endpoint, send it one real event, then click the fields in that event to tell Resolve which one is the title, severity, and so on. Because you pick from a payload your system really sent, every mapping you save points at a field that exists.

Each event becomes a **signal** in [Pulse](/guide/pulse/overview), where it's filtered, grouped with related signals, and routed into an incident when it's actionable.

<Note>
A custom source isn't the same as a conversation webhook. A custom source feeds Pulse and opens incidents. If you want an event to start a chat with CloudThinker instead, use [webhooks](/guide/webhooks/overview).
</Note>

## Prerequisites

- Permission to manage Resolve integrations.
- A system that can send `POST` requests with a JSON object body and a custom `Authorization` header.
- A way to fire one representative event on demand, such as a test button or a `curl` command.

## Create the source

Go to **Resolve → Integrations** and select **Custom source**. Click **Add signal**. One card holds every custom source you create.

<Steps>
  <Step title="Name the source">
    Enter a **Source name** your team will recognize, for example `Acme uptime`, and click **Create endpoint**.
  </Step>
  <Step title="Copy the URL and secret">
    The dialog shows the **Webhook URL** and the secret key. Copy both into your system now.

    The secret is shown only once. If you lose it, you have to regenerate it and update every sender.
  </Step>
  <Step title="Send one real event">
    Trigger the event from your system. The dialog waits and updates itself when the event arrives.

    Send a representative event, not an empty test body. You can only map fields that this event contains.
  </Step>
  <Step title="Map the fields">
    When the dialog says **Payload received**, click **Map the fields**. Every field in the captured JSON is listed with its value. Pick the one for **Incident title**, then any of **Severity**, **Service**, **Resource**, and **Description**. Click **Save mapping**.
  </Step>
</Steps>

**Success state:** the dialog closes and the source appears under **Signals to Resolve** on the Custom source card. The next event arrives in Pulse with the title you mapped.

## Send events

Authenticate with a bearer token: put the secret key in the `Authorization` header. Here's a complete example:

```bash
curl -X POST "<your-webhook-url>" \
  -H "Authorization: Bearer <your-secret-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "event": {
      "data": {
        "title": "Checkout latency above 2s",
        "priority": "critical",
        "service": "checkout-api",
        "host": "web-03",
        "summary": "p95 latency 2.4s for 5 minutes"
      }
    }
  }'
```

Mapped to this payload, the fields look like this:

| Field | Path you'd pick | Required | What it does |
|---|---|---|---|
| **Incident title** | `event.data.title` | Yes | Names the signal and the incident. |
| **Severity** | `event.data.priority` | No | Feeds routing and the automatic RCA threshold. |
| **Service** | `event.data.service` | No | Helps Pulse group related events. |
| **Resource** | `event.data.host` | No | Identifies the affected host, cluster, or component. |
| **Description** | `event.data.summary` | No | Gives responders and CloudThinker the symptom in your system's words. |

## Rules for payloads and paths

| Rule | What it means for you |
|---|---|
| Send a JSON object | A JSON array, a plain value, or `{}` can't be mapped. The dialog tells you when an event arrived but had no readable fields. |
| Paths are dotted | `event.data.title` reads `title` inside `data` inside `event`. A list index is `[0]`, as in `alerts[0].labels.severity`. |
| At most 8 segments | A path deeper than 8 levels is rejected. Send a flatter body if your value is nested deeper. |
| JSONPath prefix is optional | A leading `$.` is accepted and removed, so `$.event.data.title` works too. |
| Severity values | `critical`, `high`, `medium`, `low`, and `info` are understood as-is. Map other values (like `P1` or `sev2`) in **Severity Mapping**, or they're treated as Medium. |

## Verify the whole path

A successful HTTP response only proves delivery. Open **Resolve → Pulse** and confirm the signal, its title, and its severity. If **Auto-investigate** is on and the severity clears its minimum, the incident shows **AI is handling** on **Resolve → Investigation**.

## Change the mapping later

Open **Resolve → Integrations → Custom source**, find the source under **Signals to Resolve**, and choose **Edit** from its menu. The edit view has every mapping field (including **Resource ID Path** and **Timestamp Path**), **Severity Mapping**, and **Auto-investigate** with its minimum severity.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The dialog keeps waiting for the first payload">
    Check that your system posts to the exact **Webhook URL** and sends `Authorization: Bearer <secret>`. Click **Check again** after you resend.
  </Accordion>
  <Accordion title="The event arrived but no fields can be mapped">
    The body wasn't a JSON object with values in it. Send an object such as `{"title": "..."}`, not an array or an empty body, then click **Check again**.
  </Accordion>
  <Accordion title="Signals are titled 'Webhook signal'">
    Events that arrive before you save a mapping still become signals. Resolve uses a top-level `title` key if there is one, and otherwise falls back to `Webhook signal`. Save a mapping to fix new events.
  </Accordion>
  <Accordion title="There's no payload to pick from when editing">
    The picker shows the last stored event, and stored event bodies expire after 90 days. Fire the source once more, then map.
  </Accordion>
  <Accordion title="Everything arrives as Medium severity">
    Your system sends severity values Resolve doesn't recognize. Add rows to **Severity Mapping**, for example `p1` → critical.
  </Accordion>
</AccordionGroup>

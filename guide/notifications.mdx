The Notifications page decides which workspace events CloudThinker sends outside the app, such as an agent waiting for approval or a failed automation, and where each one goes. Every notification also lands in the in-app notification center, which is always on and has no switch.

## Prerequisites

- The workspace **Admin** role to change settings. Developers and Viewers can open the page but can't edit it. See [workspace roles](/guide/workspace-users).
- For Slack, Microsoft Teams, or Google Chat delivery: a **Team** plan or above (see [pricing](/guide/billing/pricing)), and the integration set up:
  - [Slack integration](/guide/slack-integration) connected.
  - [Teams integration](/guide/teams-integration) connected, with the bot installed and the workspace mapped.
  - [Google Chat integration](/guide/google-chat-integration) set up, with a Google Chat space mapped to this workspace by an organization admin.

## Set up delivery channels

A delivery channel is where notifications go. Email is ready by default. The chat channels each post to one channel or space that you pick.

<Steps>
  <Step title="Open Notifications">
    Go to **Workspace Settings → Notifications**. The page has two sections: **Delivery channels** and **What to notify me about**.
  </Step>
  <Step title="Choose email recipients">
    On the **Email** card, open **Manage email recipients**. Workspace members receive email by default. To include someone outside the workspace, such as a team alias, type the address and click **Add email**.

    **Success state:** the card shows **Workspace members**, or **Members + 2 more** after you add two addresses.
  </Step>
  <Step title="Pick a Slack channel, Teams channel, or Google Chat space">
    On the **Slack**, **Teams**, or **Google Chat** card, click **Pick a channel** (or **Pick a space** for Google Chat), then search and select one. Posting to a shared channel lets the whole team see alerts, and people opt in by joining it.

    **Success state:** the card shows the channel or space name. A card that says **Set up**, **Finish setup**, or **Upgrade to enable** isn't delivering yet. See [Troubleshooting](#troubleshooting).
  </Step>
</Steps>

## Choose which events to send

<Steps>
  <Step title="Open a module group">
    Under **What to notify me about**, events are grouped by module, such as Resolve, Review, Optimize, and Agents & Tasks. Click a group to expand it.
  </Step>
  <Step title="Turn channels on per event">
    Each row is one event, and each column is a delivery channel. Turn on the cells for the channels that event should reach. A dash means that channel isn't available for the event.
  </Step>
  <Step title="Set a severity threshold where offered">
    The **Alerts** and **CloudKeepers** rows show a severity picker once a channel is on. Pick the lowest severity that should reach that channel:

    | Threshold | Sends |
    |---|---|
    | **Low** | Everything |
    | **Medium** | Medium and above |
    | **High** | High and Critical |
    | **Critical** | Critical only |

    Each channel has its own threshold. For example, send Medium and above to Slack, and only Critical to email.
  </Step>
</Steps>

**Success state:** changes save as you make them. The next matching event posts to the channels you turned on.

## Events you can route

The "Email on by default" column shows which events send email before anyone changes a setting.

| Module | Event | Sent when | Email on by default |
|---|---|---|---|
| Agents & Tasks | Agent approvals | An agent needs [approval](/guide/approvals/overview) to run a write, and when it's approved or rejected | Yes |
| Agents & Tasks | Rule proposals | A run with no person in it proposes Rules that wait for your review | No |
| Agents & Tasks | Automation run failed | An [automation](/guide/automation/automations) fails a run for the first time after a success | Yes |
| Agents & Tasks | Automation turned off | An automation is turned off after repeated failures or a plan change | Yes |
| Agents & Tasks | Watched condition met | An automation reports that the condition it watches is met | Yes |
| Agents & Tasks | Agent reduced its monitoring | An agent running an automation on its own removes or pauses one of its triggers, or checks less often | Yes |
| Agents & Tasks | Automation resource missing | An automation can't run because a resource it needs was deleted | Yes |
| Resolve | Incident created | A new [incident](/guide/incident/overview) is created, manually or by webhook | Yes |
| Resolve | Awaiting approval | An incident action needs your approval | Yes |
| Resolve | Runbook approvals | A runbook execution needs approval | Yes |
| Resolve | RCA completed | Root cause analysis finishes for an incident | No |
| Resolve | Incident resolved | An incident is marked resolved | No |
| Resolve | Postmortem ready | The incident postmortem is ready for review | No |
| Resolve | Runbook draft generated | CloudThinker drafts a [runbook](/guide/incident/runbooks) for an incident | No |
| Review | Review findings | A [Review](/guide/code-review/overview) run finishes on a pull or merge request | Yes |
| Review | Pipeline analysis | Pipeline analysis finds issues in a failed pipeline | Yes |
| Review | Reports ready | Repository-level Review report PDFs finish generating | No |
| Cyber | Dependency risk changes | A monitored library becomes vulnerable, its risk increases, or monitoring pauses | Yes |
| Cyber | Pentest run blocked | A pentest run is blocked because the saved login no longer works | Yes |
| Optimize | Optimize refresh paused | A connection needs attention before [Optimize](/guide/cost-optimization/overview) can refresh cost data | Yes |
| Optimize | Optimize report ready | A scheduled [cost report](/guide/cost-optimization/reports) is ready to read | No |
| Optimize | Optimize weekly digest | Monday summary of Cost Health, new findings, expiring commitments, and reviewed anomalies | No |
| Optimize | Optimize monthly digest | Last month's spend, new findings, anomalies, and Cost Health, sent on the 2nd | Yes |
| Recommendations | Recommendation assignments | A recommendation is assigned to you, or you're unassigned | Yes |
| Recommendations | Replies | Someone replies to one of your comments | Yes |
| Recommendations | Resolved discussions | A discussion you're in is marked resolved | No |
| Connections | Connection needs attention | A [connection's](/guide/connections/overview) credentials stop working, for example an expired or revoked key | Yes |
| Rooms | Mentions | Someone mentions you in a room. Email only. | Yes |

Three groups sit above the table as single rows with their own settings: **Alerts** (new alerts an agent creates, with a severity threshold), **CloudKeepers** (findings and auto-run completions, with a severity threshold), and **Well-Architected Assessment** (an assessment finishes).

<Tip>
Start with approvals, incidents, and connection health on a shared channel. Add digests and lower-severity events once the team knows what normal volume looks like.
</Tip>

## Workspace settings vs. your own email

This page sets what the workspace sends. Each member can still mute their own copy of an email from **Account Settings → Notifications**, without changing it for anyone else.

<Note>
An [Agent CLI](/guide/cli/agent) session doesn't send approval notifications on its own, because the approval card is already in your terminal and browser. Run `/cloudthinker notify` in the session to alert the workspace approvers once.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="A chat card says Upgrade to enable">
    Slack, Teams, and Google Chat delivery need a Team plan or above. Email and in-app notifications work on every plan. See [Subscription](/guide/billing/subscription).
  </Accordion>
  <Accordion title="A chat card says Set up or Finish setup">
    **Set up** means the integration isn't connected yet. For Teams, **Finish setup** means the bot isn't installed or the workspace isn't mapped. For Google Chat, an organization admin must map a space to this workspace. Follow the integration guide linked in [Prerequisites](#prerequisites).
  </Accordion>
  <Accordion title="My Slack channel isn't in the list">
    The picker searches as you type and matches partial names. If the channel still doesn't show, check that the CloudThinker app can see it in Slack, then search again.
  </Accordion>
  <Accordion title="The toggles are locked">
    Changing notification settings needs the workspace **Admin** role. Ask a workspace admin to change them, or to change your role.
  </Accordion>
  <Accordion title="An event is on but nobody got an email">
    Check that the email cell is on for that event, that its severity threshold isn't higher than the event, and that the recipient hasn't muted their own copy in **Account Settings → Notifications**. The in-app notification center always has the record.
  </Accordion>
</AccordionGroup>

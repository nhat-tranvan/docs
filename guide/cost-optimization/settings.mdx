**Optimize → Settings** holds the billing source, the refresh health, and the notification link for one cloud account. It's the one Optimize page that still opens when billing data can't be read, so you can fix the problem from it.

## Prerequisites

- A cloud account connected to Optimize. See the [Optimize quickstart](/guide/cost-optimization/quickstart).
- Any workspace role can read Settings. Choosing a billing source, checking it again, and retrying a refresh need Developer or higher. See [Roles](/guide/security/roles).

## Open Settings

Settings isn't in the sidebar. Open it in one of two ways:

- On **Overview** or **Cost Health**, select **Open Settings** on the notice that says a capability is not measured.
- Add `/costops/settings` to your CloudThinker address, then pick the account next to the page title.

The **Updated** button and the **Daily refresh** switch stay in the page header, the same as on every Optimize page. Select **Updated** to see how far behind the provider publishes billing data and to turn the daily refresh on or off.

## Billing source

GCP and Azure accounts show where Optimize reads spend from. AWS accounts don't show this section, because Optimize always reads AWS Cost Explorer.

| Provider | Billing source | Picker |
|---|---|---|
| GCP | The Cloud Billing Standard export in BigQuery | **GCP billing export table** |
| Azure | Azure Cost Management on a subscription or billing scope | **Azure billing scope** |

When the source is readable, the section says **Connected and readable** with the table or scope Optimize reads, and when it was last checked. Select **Check again** after you change permissions or the export.

If the source isn't ready, the section shows what's wrong:

| Title | What to do |
|---|---|
| **GCP billing export is required** | Turn on the Standard export in BigQuery for this project, then select **Check again** |
| **Choose a GCP billing export** | Optimize found more than one Standard export table. Pick one under **GCP billing export table**, then select **Use this export** |
| **GCP billing export is not readable** | Give the service account **BigQuery Data Viewer** and **BigQuery Job User** on the project that holds the export |
| **An Azure billing scope is required** | The credential reaches no subscription or billing profile yet. Grant it access to one |
| **Choose an Azure billing scope** | Pick a subscription under **Azure billing scope**, then select **Use this scope** |
| **Azure Cost Management is not readable** | Grant **Cost Management Reader** on the subscription. On a Microsoft Customer Agreement, also grant **Billing profile reader** on the billing profile |

**GCP billing export is connected** or **Azure billing scope is connected** with no spend means the source works but the provider hasn't published rows yet. Optimize shows spend once it does.

## Refresh health

Refresh health says whether the daily read of billing data still runs. **Refresh is running normally** means nothing needs your attention.

When a refresh fails, the section shows one of three alerts:

| Alert | Meaning |
|---|---|
| **Optimize is missing a permission** | The provider denied an action. The alert names it under **Denied action** and can show a policy to add |
| **Optimize refresh is paused** | Refreshes stopped after repeated failures |
| **Optimize data may be stale** | The latest refresh didn't complete |

Your last good billing data stays readable in every case. To fix it:

<Steps>
  <Step title="Grant what's missing">
    If the alert shows a policy, select **Copy policy** and add it to the role, service account, or service principal. Select **Check connection** to review the credentials.
  </Step>
  <Step title="Retry">
    Select **Retry refresh**. A missing permission also retries on its own at the next daily refresh.

    **Success state:** the section reads **Refresh is running normally**.
  </Step>
</Steps>

## Notifications

Select **Open notification preferences** to choose who hears about a paused refresh or a finished scheduled report. Each person sets their own preferences.

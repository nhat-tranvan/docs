**Optimize → Reports** turns the cost data Optimize has already saved into a written report, such as monthly spend or ranked savings. CloudThinker, the built-in assistant, writes each report in a new conversation and saves it as a report [artifact](/guide/artifacts/overview) you can reopen and share.

## Prerequisites

- At least one Optimize connection with billing data. See the [Optimize quickstart](/guide/cost-optimization/quickstart).
- Workspace role Developer or higher to generate reports and manage schedules. Viewers can see the schedule list but not generate. See [Roles](/guide/security/roles).

## Choose a report

| Report | What it summarizes | Use it for |
|---|---|---|
| Monthly spend | Spend by account and service, with month-over-month change | A monthly finance or engineering review |
| Savings opportunities | Open findings ranked by potential monthly savings | Planning which [findings](/guide/cost-optimization/recommendations) to work next |
| Cost allocation readiness | Tagged and untagged spend coverage from Cost Health | Checking whether spend can be charged back to teams |
| Spend forecast | Current-month forecast from your stored spend trend | Spotting a month that will finish over plan |
| Commitment coverage | Measured coverage and utilization from Cost Health | Reviewing Savings Plans, reservations, or committed use |
| Anomaly review log | Detected impact and review outcomes from the last 30 days | Showing that [cost spikes](/guide/cost-optimization/anomalies) were reviewed |

Reports only use evidence Optimize already stores. Generating one doesn't call the cloud provider for fresh data, and missing data is reported as a gap, never as zero.

## Choose the scope

Use the selector above the report cards.

| Scope | What it includes |
|---|---|
| Selected account | The cloud account currently selected in the Optimize page header |
| All accounts | Every Optimize account connected at the moment you generate the report or create the schedule |

Each account gets its own section, and Optimize never adds different currencies together. A schedule keeps the accounts it captured: an account you connect later isn't added, and a captured account that is later disconnected shows up as a gap in the report.

## Generate a report now

<Steps>
  <Step title="Open Reports">
    In the sidebar, select **Optimize → Reports**.
  </Step>
  <Step title="Set the scope">
    Choose **Selected account** or **All accounts**.
  </Step>
  <Step title="Select a report card">
    Select the card for the report you want, for example **Savings opportunities**.

    **Success state:** a new conversation opens and CloudThinker starts writing. When it finishes, the report appears in the conversation as an artifact.
  </Step>
  <Step title="Refine it in the conversation">
    Ask follow-ups in the same conversation. CloudThinker answers from the same saved data.

    ```text
    Turn the top five savings opportunities into a checklist with an owner column for the platform team.
    Which account changed the most month over month, and which services drove it?
    ```
  </Step>
</Steps>

A one-off report doesn't send a notification, since you're already in the conversation.

## Schedule a recurring report

<Steps>
  <Step title="Set the scope first">
    On **Optimize → Reports**, choose **Selected account** or **All accounts**. The schedule captures this scope.
  </Step>
  <Step title="Add the schedule">
    Under **Scheduled reports**, select **Add schedule** and pick the report type.
  </Step>
  <Step title="Name it and pick a cadence">
    Edit the **Title** if you like, then set **Schedule** to **Daily**, **Weekly**, **Monthly**, or **Custom** (a cron expression such as `0 9 * * 1-5`). Optionally check **Set expiration date** so the schedule stops after a date.
  </Step>
  <Step title="Save">
    Select **Schedule report**.

    **Success state:** the schedule appears under **Scheduled reports** with its accounts, cadence, and **Next** run time. Its status reads **Not run** until the first run.
  </Step>
</Steps>

Every scheduled run opens a new conversation and must produce exactly one report artifact to count as succeeded. After a successful run, the schedule owner gets a report-ready notification that links to the conversation. A failed run sends no ready notification, so check the status on the list.

## Manage schedules

Each row under **Scheduled reports** shows the last run status (**Running**, **Succeeded**, or **Failed**) and gives you these controls:

| Control | What it does |
|---|---|
| Switch | Turns the schedule on or off without deleting it |
| **Open last report** | Opens the conversation from the latest successful run |
| Trash icon | Deletes the schedule after you confirm. Past report conversations stay. |

To change a schedule's scope or cadence, delete it and create a new one.

## What a report won't claim

CloudThinker gets one fixed snapshot of saved Optimize data per report. The report states how fresh the data is and names any partial coverage or missing accounts. It doesn't claim realized savings or ROI, budget variance, purchase advice, or a root cause the data can't support.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Add schedule is locked or a report card does nothing">
    **Cause:** generating and scheduling reports need workspace role Developer or higher. The tooltip says "You don't have permission to schedule reports." **Fix:** ask a workspace Admin to change your role in [Workspace users](/guide/workspace-users).
  </Accordion>
  <Accordion title="A report says data is missing or stale">
    **Cause:** the account's billing refresh failed or hasn't run yet. **Fix:** open **Optimize → Overview** for the account, follow the refresh alert, then generate the report again.
  </Accordion>
  <Accordion title="A scheduled run shows Failed">
    **Cause:** the run ended without a report artifact. **Fix:** generate the same report now from its card to see the error in the conversation. If it succeeds, the next scheduled run should too.
  </Accordion>
  <Accordion title="A new account isn't in my All accounts schedule">
    **Cause:** schedules keep the accounts captured when they were created. **Fix:** delete the schedule and create it again with **All accounts** selected.
  </Accordion>
</AccordionGroup>

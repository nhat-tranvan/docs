CloudThinker agents can work without a live prompt: automations run on triggers, and [Pulse](/guide/pulse/overview) watches your monitoring feeds continuously. [Approvals](/guide/approvals/overview) bounds everything they do, whichever surface started it.

## Why autonomous operations

- **Routine work runs itself.** [Automations](/guide/automation/automations) run recurring checks, react to webhook calls and repository events, or run once at a future time — without someone remembering.
- **Noise becomes signal.** Pulse suppresses duplicate monitoring events and ranks the clusters that remain.
- **You set the boundary.** Rules and the Approval mode decide what an agent may do on its own, for a scheduled run and a live chat alike.
- **Everything is recorded.** Every autonomous run keeps its conversation, so you can open any run and read exactly what the agent did.

## Manual and Auto

Each run uses one Approval mode:

<AutonomyModes />

Automations use **Auto · Rules + AI · Refuse** by default, because no person may be there to answer. Change it for all Automations, or for one Automation, on the [Approval mode](/guide/approvals/approval-mode) page.

<Tip>
Accept [Rules](/guide/approvals/rules) for the writes your Automations make often. A Rule decides the same way in every mode, so a scheduled run does not depend on AI judgment.
</Tip>

## What runs autonomously

Two surfaces run work without a live prompt. Configure each one on its own page.

| Surface | What it does on its own | Learn more |
|---------|------------------------|------------|
| **Automations** | Run stored agent instructions on a schedule, when a webhook call arrives, or when a repository event lands | [Automations](/guide/automation/automations) |
| **Pulse** | Collects events from sources like CloudTrail, GuardDuty, and Datadog, suppresses noise, and surfaces ranked clusters that can escalate to [incidents](/guide/incident/overview) | [How Pulse Works](/guide/pulse/overview) |

## How autonomous work is bounded

Whichever surface starts the work, [Approvals](/guide/approvals/overview) decides each call to a connection:

| The agent wants to | What decides |
|--------------------|--------------|
| Read data | Nothing. Reads always run. |
| Make a write that a Rule covers | The Rule: **Allow** runs it, **Ask first** waits for a person, **Deny** refuses it |
| Make a write that no Rule covers | The run's Approval mode: Manual asks a person; Auto can let AI judgment allow it, then asks or refuses |
| Make a call that is **Always blocked** | Nothing. It never runs. |

A run that waits for a person shows **Required Approval** in the automation's Runs view until a person decides, so autonomous work never silently waits.

## Examples

- **A daily cost report.** An Automation summarizes cost every morning. It only reads billing data, so it finishes without waking anyone; the report waits in the run's conversation and in [notifications](/guide/notifications).
- **A reaction to a repository event.** A merge request lands, and the run needs to comment on it. An Allow Rule for that comment lets it run. With no Rule, the Automation's **Refuse** mode refuses the comment unless AI judgment allows it.

## Stay informed

Every autonomous run is logged in the workspace, and each run's conversation holds its full output. Notifications deliver findings, errors, and approval requests to Slack, Teams, or email. Review run history regularly and adjust your Rules, the Approval mode, or the automation's instructions when the work changes.

A credential is a secret, such as an API key or a service token, that you save once in a workspace. CloudThinker encrypts it and passes it to agents as an environment variable every time they run a command, so the value never appears in chat.

## Credentials, connections, or BYOK?

CloudThinker keeps secrets in three places. Pick the one that matches what you're storing.

| You want to give agents | Use | Where |
|---|---|---|
| Access to a cloud account, database, or monitoring tool | [Connections](/guide/connections/overview) | **Workspace Settings → Connections** |
| Any other secret a command needs, such as a vendor API key or a webhook secret | **Credentials** (this page) | **Workspace Settings → Credentials** |
| Your own LLM provider keys for model inference | [BYOK](/guide/byok) | **Admin Settings → BYOK** |

## Prerequisites

- The **Admin** role in the workspace. Developers and Viewers see a "Credentials are restricted" card instead of the list. See [workspace roles](/guide/workspace-users).

## Add a credential

<Steps>
  <Step title="Open the Credentials page">
    Go to **Workspace Settings → Credentials**. The list shows each credential's key, description, who added it, and when it was last updated. Values are never shown.
  </Step>
  <Step title="Click Add Credential">
    Fill in the form:

    | Field | What to enter |
    |---|---|
    | **Key** | The environment variable name agents see, for example `STRIPE_API_KEY`. Uppercase letters, digits, and underscores only, and it can't start with a digit. Up to 255 characters. |
    | **Value** | The secret itself. |
    | **Description** | Optional, up to 1,024 characters. Say what the secret is for and where it came from, so the next admin knows whether it's safe to rotate. |
  </Step>
  <Step title="Click Save">
    **Success state:** the credential appears in the list with its key and description. Agents get it on their next command.
  </Step>
</Steps>

<Note>
Some keys are reserved and the form rejects them: anything starting with `AWS_`, `GOOGLE_`, or `AZURE_`, plus `KUBECONFIG`, `GITHUB_TOKEN`, `GITLAB_TOKEN`, `BITBUCKET_TOKEN`, and the login keys Cyber manages (such as `CYBER_AUTH` and `CYBER_COOKIE`). Cloud and Git access comes from [Connections](/guide/connections/overview).
</Note>

## Import a .env file

Use this when you already keep secrets in a dotenv file. The file is parsed in your browser, and only the rows you select are sent.

<Steps>
  <Step title="Open the import dialog">
    On **Workspace Settings → Credentials**, click **Import .env**.
  </Step>
  <Step title="Add your file">
    Choose **Paste** and paste the contents, or choose **Upload a file** and pick a `.env`, `.env.local`, or other `.env.*` file. One import takes a file of 64 KiB or smaller with at most 50 keys. Click **Review credentials**.
  </Step>
  <Step title="Pick the rows to save">
    Rows are split into two groups:

    | Group | What selecting a row does |
    |---|---|
    | **New** | Creates the credential. |
    | **Already in this workspace** | Overwrites the stored value. Leave it unselected to keep the current value. |

    Rows with a reserved key are marked "This key is managed by the platform." and can't be imported.
  </Step>
  <Step title="Click Import">
    The button shows how many rows you selected, for example **Import 3**.

    **Success state:** the imported keys appear in the list.
  </Step>
</Steps>

## Use a credential in chat

Type `$` in the chat box to open the credential picker, then pick a key. It's inserted as `$KEY`, so you can point an agent at a secret without pasting it.

```text
Summarize this month's failed payments from the Stripe API using $STRIPE_API_KEY
```

The agent reads the value from its environment and reports back by key name only. The `$` picker shows only for members who can manage credentials. See [Commands and syntax](/guide/commands) for the other tokens you can type.

## How agents use credentials

| Behavior | What it means for you |
|---|---|
| Every credential is available to every command | Agents get all workspace credentials as environment variables, whether or not your prompt mentions them. Keep only secrets you're comfortable any agent in the workspace using. |
| Agents can ask for a missing secret | If a task needs a key the workspace doesn't have, the agent shows a secure form in chat. What you submit is saved as a workspace credential, and the list shows "Added by" with the agent's name. |
| Values stay out of chat | Agents never print a value. Chat, agent output, and the Credentials list show key names only. |

<Warning>
If an agent asks for a key that already exists, submitting the form replaces the stored value. Check the list first when the key might be used by another automation.
</Warning>

## Edit or delete a credential

- **Edit:** click the pencil icon on the credential's row (tooltip **Edit credential**). Change the description, or enter a new value to replace the secret. Leave the value blank to keep the stored secret.
- **Delete:** click the trash icon (tooltip **Delete credential**) and confirm. Every agent that reads this credential loses access on its next command. This can't be undone.

## Security

- Values are encrypted at rest and are never sent back to the browser.
- Each create, update, and delete is recorded in [Audit Logs](/guide/security/audit-logs) under the Security category. The entry leaves out both the key name and the value, because more people can read audit logs than can manage credentials.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The form says 'Uppercase letters, digits, and underscores only'">
    The key has a lowercase letter, a dash, a space, or starts with a digit. Rename it, for example `stripe-key` becomes `STRIPE_KEY`.
  </Accordion>
  <Accordion title="The key 'uses reserved prefix'">
    The key starts with a reserved name such as `AWS_` or `GITHUB_TOKEN`. Add that access as a [connection](/guide/connections/overview) instead, or rename the key if it's for a different service.
  </Accordion>
  <Accordion title="'A credential named ... already exists'">
    **Add Credential** never overwrites. Edit the existing credential to change its value, or use **Import .env** and select the row under **Already in this workspace**.
  </Accordion>
  <Accordion title="I can't see the Credentials list or the $ picker">
    Both need the workspace **Admin** role. Ask a workspace admin to add the secret, or to change your role.
  </Accordion>
</AccordionGroup>

Release Risk tells your team whether a release can ship. Pick a release, and CloudThinker reads every change since the last release and gives one verdict, with the reason behind every blocker.

## Why use it

- **Know before you deploy.** Each release reads **Blocked** or **Clear to ship**, with the reason behind every blocker.
- **One decision for the whole team.** Everyone reads the same report, and can download it as a PDF.
- **Fixes come with the report.** CloudThinker can fix a blocker, or review a change nobody reviewed.

## Prerequisites

- A repository turned on in [Review setup](/guide/code-review/setup), on GitHub, GitLab, Bitbucket or Azure DevOps.
- The workspace **Admin** role to analyze, fix or ship anyway. Everyone else can read reports and download the PDF. See [roles](/guide/security/roles).

## Analyze a release

To check a release, click **Analyze release** on **Review → Releases** and choose the repository. **Next release** is preselected when the default branch has unreleased changes; you can also pick a tag from the list. CloudThinker compares it with the previous release. Click **Analyze**. The report is ready in about 5 minutes, and you can leave the page.

## Check new tags automatically

Go to **Review → Settings → General**:

- Turn on **Analyze new release tags** to start a report each time a tag is pushed. Each report is one CloudThinker run. Your Git provider must send tag events ([Configure webhooks](/guide/code-review/provider-auth#configure-webhooks)).
- Turn on **Deploy gate** to add a `cloudthinker/release` check to the tag. Have your deploy job wait until that check passes. It stays closed while the release is **Blocked** and opens once it is **Clear to ship** or **Shipped anyway**. Some code hosts cannot show a check on a tag, and the setting says so.
- Pick a channel under **Post results to** to post the verdict and the first blocker in Slack.

## Read the verdict

**Review → Releases** opens on the **Blocked** tab, beside **Clear to ship** and **All**. Each release shows one status:

| Status | What it means |
|---|---|
| Analyzing | CloudThinker is checking the release |
| Blocked | At least one blocker is open |
| Clear to ship | No blocker is open |
| Shipped anyway | An Admin shipped past an open blocker, with a note |
| Analysis failed | The analysis stopped before it finished |
| Replaced | A newer report on the same release replaced this one. Read the newer report |

Open a release for its report:

- **Blockers**: what to fix before you ship, plus items **To watch** during rollout.
- **Findings**: the open review findings of the release's merge requests.
- **What's shipping**: release notes and every merge request, grouped by area of the codebase.

## Fix or ship

Each open blocker carries one main action:

| Action | What happens |
|---|---|
| **Check** | CloudThinker reviews a merge request nobody reviewed, then checks the release again |
| **Fix** | CloudThinker fixes that blocker. Follow it in Chat |
| **Mark resolved** | Record that you dealt with it. **Reopen** undoes it |

**Fix all blockers** works through every open blocker at once. When the last blocker is resolved, the release turns **Clear to ship**. A blocker for an unreviewed change also clears on its own once that change is reviewed.

To ship anyway, open the **⋯** menu and click **Ship anyway**. Answer **Why is it safe to ship?** and confirm. The release shows who shipped it and why. The same menu holds **Download PDF**.

## How it works

1. **You pick a release.** Click **Analyze release** and choose **Next release** or a tag.
2. **CloudThinker reads the release.** It compares it with the previous release and reads the real diff and each merge request's review.
3. **One verdict lands.** The report lists blockers and items to watch, with the evidence and how to fix each one.

## Troubleshooting

<AccordionGroup>
  <Accordion title="A new tag has no report">
    Check that **Analyze new release tags** is on in **Review → Settings → General**, that the repository is turned on in Review, and that your provider sends tag events ([Configure webhooks](/guide/code-review/provider-auth#configure-webhooks)). To check that tag now, click **Analyze release** and pick it.
  </Accordion>
  <Accordion title="The release shows Analysis failed">
    The analysis stopped before it finished. Open the release and click **Analyze again**.
  </Accordion>
</AccordionGroup>

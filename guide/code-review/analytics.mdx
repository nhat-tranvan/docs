The Analytics section gives your team a data layer on top of every code review Oliver has run — surfacing where quality is improving, where findings cluster, and how individual contributors are trending over time.

Access it from **Code Review → Insights** in the navigation.

## Analytics tabs

The Analytics page has four tabs. Summary cards appear above the tabs for the Leaderboard and Details views. The Details and Review Patterns tabs are hidden for the single-week range, which has no trend to plot.

| Tab | What it shows |
|-----|--------------|
| **Leaderboard** | Developer scores ranked by contribution and code quality — see [Leaderboard](/guide/code-review/leaderboard) |
| **Details** | A selected metric by developer across weekly or monthly periods, with a period data table |
| **Review Patterns** | Evidence-backed patterns across Security, Performance, Correctness, and Patterns |
| **Reports** | Generated repository reports |

## Summary cards

Above the analytics tabs, the selected period shows four summary cards:

| Card | Description |
|------|-------------|
| Active Authors | Number of developers with review data in the selected period |
| Total PRs/MRs | Total reviewed pull requests or merge requests in the selected period |
| Total Findings | Sum of findings, with a severity breakdown |
| Team Quality Score | Average team quality score on a 1–10 scale |

## Details tab

Details replaces the former Author Performance view. It compares a selected metric by developer across the chosen weekly or monthly period and shows the matching period data table.

Choose one of these metrics in Details:

| Metric |
|--------|
| Contribution Score |
| Quality Score |
| MR/PR Count |
| Total Impact |

## Time range

Use the control above the tabs to select weekly or monthly reporting:

| View | Available periods |
|------|-------------------|
| Weekly | This week, or the last 4, 8, or 12 weeks |
| Monthly | Last 3, 6, or 12 months |

## Review Patterns tab

Review Patterns uses completed, non-draft Advanced Review outcomes. It shows the clean MR rate and finding evidence for Security, Performance, Correctness, and Patterns. Developers with fewer than three reviewed MRs remain visible with an insufficient-sample state instead of a misleading rate.

Infra shows where your live cloud no longer matches your Terraform. Someone opens a port in the AWS console, and CloudThinker lists the change, who made it, and what to do about it.

## Why use it

- **Terraform decides what drifted.** CloudThinker runs `terraform plan` on your code and state, so defaults and computed values never show up as differences.
- **You see who and when.** Each difference names who changed it, from CloudTrail, or **Not known** when there is no evidence.
- **Your pipeline does the changing.** CloudThinker never gets a role that can write to your cloud account. Revert and Keep change both open a merge request, and your pipeline applies it.

## Prerequisites

- A Terraform or OpenTofu state in S3, and an [AWS connection](/guide/connections/aws) that can read it.
- A repository connection for the code that writes the state. Checks with Terraform and the two actions need it.
- The workspace **Developer** role to run an action, **Viewer** to read. See [roles](/guide/security/roles).

## Add a Terraform state

<Steps>
  <Step title="Open Infra">
    Go to **Review → Infra** and click **Terraform state**.
  </Step>
  <Step title="Add the state">
    Click **Add Terraform state**. Pick the AWS connection, paste the state URL (`s3://bucket/path/terraform.tfstate`) and link the repository.
  </Step>
  <Step title="Wait for the first check">
    CloudThinker checks the state at once. Click **Check now** to run it again.
  </Step>
</Steps>

**Success state:** the Open tab lists each difference, or says nothing differs.

## How a check works

CloudThinker clones the default branch of your repository in a sandbox, runs `terraform plan -refresh-only` with read access, and lists what changed in your account since the last apply. Each difference is one changed attribute on one resource, or a resource that no longer exists.

A check runs when you click **Check now**, after a change that CloudTrail reports, and once a week. Anything it could not read is listed under **Not checked** with the reason, for example a missing variable or a locked state.

## Handle a difference

Open a difference to see the Terraform value, the live value, who changed it and where the code sets it.

| Action | What CloudThinker does | What you do |
|---|---|---|
| **Revert** | Plans the change that brings live back to your code, asks you to approve it, and opens a merge request. | Merge it and run your pipeline's apply. |
| **Keep change** | Writes the live value into your code and opens a merge request. | Merge it and let your pipeline apply it. |
| **Dismiss on this resource** | Hides the difference and ignores this attribute on the resource. | Remove the ignore any time in **Ignored attributes**. |

After the merge, CloudThinker waits for your pipeline to change the state, checks that one resource, and closes the difference as **Reverted** or **Kept**. If the resource still differs, it checks again, up to three times.

<Note>
CloudThinker only reads your cloud account. It never applies a change itself.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="A state shows Not checked">
    Open the reason. Missing variables, module or provider access, and a locked state are the usual causes. Fix it in your repository or in Terraform, then click **Check now**.
  </Accordion>
  <Accordion title="Revert or Keep change is greyed out">
    The state needs a linked repository, and Keep change is not offered when a remote module sets the value. The page names the reason.
  </Accordion>
  <Accordion title="The difference stays open after the merge">
    Your pipeline must apply the merged change. Run the apply, then click **Check now**. CloudThinker stops waiting after 7 days.
  </Accordion>
</AccordionGroup>

Mention `@cloudthinker-ai` in any merge request or pull request comment to trigger commands — restart a review, autofix findings, ask questions, or get help.

<Note>
  GitLab and GitHub support every command. Bitbucket, Azure DevOps, and AWS CodeCommit support a subset — see [provider support](#provider-support).
</Note>

## Commands

| Command | What it does |
|---------|-------------|
| `@cloudthinker-ai help` | Shows available commands as a comment |
| `@cloudthinker-ai review` | Restarts the review from the last reviewed commit — use it to request a re-review. `review again`, `continue`, and `continue review` work too |
| `@cloudthinker-ai autofix` | Fixes unresolved findings and pushes the result to the original source branch |
| `@cloudthinker-ai autofix stacked pr` | Fixes findings on a separate branch, then opens a follow-up MR/PR |
| `@cloudthinker-ai <question>` | Ask a free-form question about the code review |

A command only runs as plain comment text. A mention inside a code block, inline code, or a quoted reply is treated as quoted text, not as a command.

## How autofix works

1. Post `@cloudthinker-ai autofix` (or `@cloudthinker-ai autofix stacked pr`) as a comment on the MR/PR.
2. CloudThinker picks up all unresolved findings from the review.
3. An agent implements fixes for each finding, following your codebase conventions.
4. CloudThinker commits and pushes the changes — direct autofix to the original source branch, stacked autofix to a separate branch with a follow-up MR/PR.

<Warning>
  `@cloudthinker-ai autofix` commits and pushes to your source branch without pausing for approval. Use `autofix stacked pr` when you want to review the changes in a separate MR/PR first. CloudThinker never pushes to protected branches.
</Warning>

### Direct vs. stacked PR

- **`@cloudthinker-ai autofix`** — Commits and pushes directly to the original MR/PR source branch. Findings are marked resolved after fixing.
- **`@cloudthinker-ai autofix stacked pr`** — Creates and pushes a separate branch, then opens a follow-up MR/PR targeting the original source branch. Findings stay open for your review.

## Skip a review

Add the marker `@cloudthinker:ignore` anywhere in the MR/PR description to skip reviews for that MR/PR. The marker is case-sensitive and must match exactly.

Skipping works on GitLab, GitHub, Bitbucket, and Azure DevOps. To skip whole categories of PRs — by label, author, or branch — use [filters](/guide/code-review/setup#filter-configuration) instead.

## Free-form questions

Ask anything about the code review by mentioning `@cloudthinker-ai` followed by your question:

```text
@cloudthinker-ai why was this function flagged as a security risk?
@cloudthinker-ai can you explain the performance impact of this change?
@cloudthinker-ai what's the best way to refactor this?
```

### Thread-aware context

- **Reply in a finding's thread** — The agent sees only that specific finding's details (severity, file, line, suggested fix), giving you a focused answer.
- **Top-level comment** — The agent sees all unresolved findings from the review, giving you a broader perspective.

## Provider support

| Provider | Questions and help | `review` | `autofix` |
|----------|--------------------|----------|-----------|
| GitLab | Yes | Yes | Yes |
| GitHub | Yes | Yes | Yes |
| Azure DevOps | Yes | Yes | No |
| Bitbucket | Replies in finding threads only | Yes | No |
| AWS CodeCommit | Top-level comments only | No | No |

## Tips

- **One autofix at a time** — Only one autofix can run per MR/PR. Wait for the current one to finish before starting another.
- **Reuse conversation context** — Free-form replies in the same thread reuse the conversation context, so follow-up questions build on previous answers.

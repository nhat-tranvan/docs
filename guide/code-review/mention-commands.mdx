Mention `@cloudthinker-ai` in a merge request or pull request (MR/PR) comment to re-run a review, fix its findings, or ask about the change, all without leaving your Git provider. A **finding** is one issue the review flagged for a human to look at.

## Prerequisites

- An open MR/PR in a repository connected in [Review setup](/guide/code-review/setup).
- Comment access on that MR/PR in your Git provider.

## Commands

Write the command as plain text on its own line in a comment. Type `@cloudthinker-ai` exactly, whatever your bot user is called. Your provider's autocomplete may not suggest it, and that's fine.

| Command | What it does |
|---|---|
| `@cloudthinker-ai` or `@cloudthinker-ai help` | Posts the list of commands your provider supports |
| `@cloudthinker-ai <question>` | Answers a question about this MR/PR |
| `@cloudthinker-ai review` | Starts the first review, or reviews again from the last reviewed commit. `review again`, `continue`, and `continue review` do the same |
| `@cloudthinker-ai review ultra` | Runs one deeper Ultra review of the latest commit, if Ultra review is turned on for your CloudThinker instance |
| `@cloudthinker-ai autofix` | Fixes every unresolved finding, of any severity, and pushes the commits to this MR/PR's source branch |
| `@cloudthinker-ai autofix stacked` | Fixes every unresolved finding on a new branch and opens a separate MR/PR for them. `autofix stacked pr` also works |

`review` and `review ultra` must be the whole line. `@cloudthinker-ai review this carefully` is treated as a question, not a command. A mention inside a code block, inline code, or a quoted reply is also never run as a command.

## Run a command

<Steps>
  <Step title="Open the MR/PR on your provider">
    Use the MR/PR on GitHub, GitLab, Bitbucket, Azure DevOps, or AWS CodeCommit that CloudThinker reviewed.
  </Step>
  <Step title="Post the command as a new comment">
    For example, to re-run a review that stopped part way:

    ```text
    @cloudthinker-ai review
    ```

    **Success state:** the bot replies **CloudThinker Review Started**. When the run finishes, a new review summary comment appears on the MR/PR.
  </Step>
</Steps>

If a review stops before its summary, the bot edits its progress comment to **CloudThinker Review Did Not Finish**. Findings it already posted stay valid. Comment `@cloudthinker-ai review` to continue from the last reviewed commit. On AWS CodeCommit, push a new commit to the source branch instead.

## Ask a question

Mention the bot followed by your question:

```text
@cloudthinker-ai does this change break any other caller of parseConfig?
@cloudthinker-ai what should I test before merging this?
```

Where you ask changes what the agent focuses on:

| Where you comment | What the agent looks at first |
|---|---|
| Reply in a finding's thread | That finding and its file, plus the rest of the MR/PR so it can check side effects |
| New top-level comment | The whole MR/PR and all its unresolved findings |

Follow-up questions in the same thread build on earlier answers.

## Push back on a finding

If you're the MR/PR author or an assignee and you think a finding is wrong, reply in that finding's thread. No mention is needed. Explain why, for example:

```text
This is intentional. The retry is capped by the caller in client.go, so it can't loop forever.
```

CloudThinker re-checks the finding against the current code and your reply, then settles it one of three ways:

| Outcome | When | What happens |
|---|---|---|
| Withdrawn | The finding was wrong | It closes, and later reviews of the repository are told not to raise it again on unchanged code. This uses the same notes as a thumbs-down [vote](/guide/code-review/review-workspace#work-the-findings): each review gets the repository's newest 20 from the last 90 days |
| Acknowledged | The code is intentional | It closes for this MR/PR, with your reason posted in the thread |
| Still open | The finding still applies | It stays open, and the bot replies with why |

Pushing back works once the review has finished, on every provider except AWS CodeCommit. Other people can still ask about a finding by mentioning the bot, but their reply doesn't settle it.

## Fix findings with autofix

Pick how you want the fixes delivered:

| Command | Where the fixes land | Use it when |
|---|---|---|
| `@cloudthinker-ai autofix` | New commits on this MR/PR's source branch | You trust the fixes and want one MR/PR to merge |
| `@cloudthinker-ai autofix stacked` | A new branch with its own MR/PR that targets this MR/PR's source branch | You want to review the fixes before they reach your branch (GitHub and GitLab only) |

<Steps>
  <Step title="Post the command as a top-level comment">
    ```text
    @cloudthinker-ai autofix stacked
    ```
  </Step>
  <Step title="Wait for the fix run">
    CloudThinker reads each unresolved finding, whether or not it has a suggested fix, changes the code, commits, and pushes. Only one autofix runs per MR/PR at a time. A second request while one runs doesn't start another.

    CloudThinker doesn't run your tests. It skips a finding that needs an architectural decision or has no clear fix. The fix run is an agent run and uses credits.

    **Success state:** a commit titled `fix: autofix findings from code review of ...` appears on your source branch, or a new MR/PR opens that targets it. The commit message lists each fix under `Fixed:` and each skipped finding, with its reason, under `Skipped:`.
  </Step>
</Steps>

On GitHub and GitLab you can also type `@cloudthinker-ai autofix` as a reply inside one finding's thread. CloudThinker then fixes only that finding.

<Warning>
  `@cloudthinker-ai autofix` pushes to your source branch without a separate approval step. CloudThinker doesn't limit it to the MR/PR author, and there's no CloudThinker setting that does: anyone who can comment can run it. On a widely shared repository, limit who can comment in your provider, and use `autofix stacked` when you want to read the changes first.
</Warning>

## Skip a review

Put this anywhere in the MR/PR description to stop CloudThinker reviewing that MR/PR:

```text
@cloudthinker:ignore
```

It's case-sensitive. CloudThinker reads the description on every new event, so adding the marker skips reviews from the next push, and removing it lets the next push be reviewed. A review that's already running finishes; to end it, use **Stop review** in the [Review workspace](/guide/code-review/review-workspace#re-run-fix-and-merge). To skip whole groups of MR/PRs, such as bot dependency bumps, use repository filters in [Review setup](/guide/code-review/setup) instead.

## Run an Ultra review

Ultra is a deeper, slower review that uses more credits than a normal one. It runs the code to check each finding before it posts, and takes about 10 minutes. It's available only when Ultra review is turned on for your CloudThinker instance. It isn't a workspace setting, so there's no switch for it in **Review → Settings**.

- **Once:** comment `@cloudthinker-ai review ultra`. Only the MR/PR author or an assignee can start it this way. The next push gets your normal review.
- **On every push:** put `@cloudthinker-ai review ultra` on its own line in the MR/PR description. If the description also has the skip marker, the skip wins.

If Ultra is off, the bot replies **Ultra review is turned off for this installation. Ask an admin to turn on Ultra review.** No workspace Admin can change it, so ask CloudThinker support to enable it.

## Provider support

| Provider | Top-level questions | Thread replies | `review` | `autofix` | `autofix stacked` |
|---|---|---|---|---|---|
| GitHub | Yes | Yes | Yes | Yes | Yes |
| GitLab | Yes | Yes | Yes | Yes | Yes |
| Bitbucket Cloud | Yes | Partial (1) | Yes | Partial (2) | No |
| Azure DevOps | Yes | Partial (1) | Yes | Partial (2) | No |
| AWS CodeCommit | Yes | No | No | No | No |

1. Only the MR/PR author's or an assignee's replies in a finding's thread are read. Anyone else's thread reply, a question included, gets no answer; they can ask in a top-level comment instead.
2. Top-level comments only, not inside a finding's thread.

`review` covers `review ultra` too. On AWS CodeCommit, automatic reviews still run on every new PR and on every push to its source branch. The `review` and `autofix` comment commands aren't supported there, so push a new commit to review a CodeCommit PR again.

A command your provider doesn't support is ignored without a reply.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The bot didn't reply to my comment">
    **Check:**

    - The mention is plain text, not inside backticks, a code block, or a quote.
    - Your provider supports the command in the [table above](#provider-support).
    - On Azure DevOps, the **Pull request commented on** service hook exists with **Resource version** set to **2.0**, as described in [Provider authentication](/guide/code-review/provider-auth).
    - Your provider's webhook delivery history shows the comment event was delivered and accepted.
  </Accordion>
  <Accordion title="My command was answered as a question">
    **Cause:** `review` and `review ultra` must be the whole line. **Fix:** post `@cloudthinker-ai review` with nothing after it.
  </Accordion>
  <Accordion title="Ultra review won't start from a comment">
    **Cause:** only the MR/PR author or an assignee can start Ultra from a comment, or Ultra is turned off for your CloudThinker instance. **Fix:** ask the author to comment. Or, as a Developer or Admin, open the review in the [Review workspace](/guide/code-review/review-workspace#re-run-fix-and-merge) and click **More actions (⋯) → Run Ultra review**.
  </Accordion>
  <Accordion title="My reply in a finding thread didn't settle the finding">
    **Cause:** only the MR/PR author or an assignee can settle a finding by replying, and only after the review has finished. **Fix:** ask the author to reply, or mark it resolved in the Review workspace.
  </Accordion>
</AccordionGroup>

Codebase Atlas connects your repository's structure to its merged changes. Use it to find the areas that changed, inspect their dependencies, and see who contributed.

## Prerequisites

- A repository connected through [Review setup](/guide/code-review/setup), with its initial setup finished.
- Review view permission in the workspace to read an Atlas.
- Review edit permission to build an Atlas or change its settings. Ask a workspace Admin if these controls are unavailable.

## Build your first Atlas

<Steps>
  <Step title="Choose a repository">
    Open **Review → Codebase Atlas**. Select a repository from the picker at the top.

    Only repositories with finished setup can start their first map. If the page says **Connect a repository first**, open **Review settings** and finish setup there.
  </Step>
  <Step title="Choose the branch and build">
    In **Build your Codebase Atlas**, select **Branch**, then click **Build Atlas**.

    If the page instead offers **Run initial assessment**, mapping is already enabled. Click it to start the first assessment.

    The page shows **Assessment queued**, then **Building your Codebase Atlas** while CloudThinker reads the repository and merged changes. It updates when the result is ready.

    **Success state:** the repository has a published Atlas, and you can explore its components and changes.
  </Step>
  <Step title="Check ongoing updates">
    Atlas updates daily while it is enabled. The setup card shows the update time.

    To manage mapping for other repositories, open **More actions → Manage repositories**. See [repository management](/guide/code-review/repository-management).
  </Step>
</Steps>

An Atlas that was built before can offer **Turn on daily updates** instead of **Build Atlas**. This resumes updates for that repository.

## Explore a period

<Steps>
  <Step title="Select the repository and dates">
    Use the repository picker to switch repositories. Open the period picker for **Today**, **Yesterday**, **This week**, **Last week**, or **Custom range**.

    Use the previous and next arrows to move between periods. The selected period controls the changes and contributions you inspect.
  </Step>
  <Step title="Open the map">
    If view buttons appear, choose **Map**. Otherwise, the map is already open. Click a component or group to open its panel.

    Use **Zoom in**, **Zoom out**, or **Fit to screen** to navigate a larger map. The legend identifies merged changes, share of Impact, the most active areas, and critical components.

    Impact describes the size of changes, not their business value. See [Review Insights](/guide/code-review/analytics#how-the-scores-are-built) for the scoring definition.
  </Step>
  <Step title="Follow a change">
    Select a component with changes in your chosen period. In its panel, open **Changes** and select a change to inspect it. Use **People** to see its contributors when that tab is available.

    The **Overview** tab shows the component's activity and related components. Click a related component to follow the connection.

    **Success state:** you can connect a changed area to the merged change and contributor behind it.
  </Step>
</Steps>

The map describes repository structure. A component can still exist on the map when it has no changes in your selected period.

From a panel, use **Analyze in Chat** to open a conversation with that area's context ready. Review the prepared question before sending it.

When available, **Copy changelog** copies the selected scope's changes, and **Open in Insights** opens the workspace's Insights page.

## Explore people

Choose **People** to compare contributors across mapped areas. Select a person or a cell to inspect their activity and the changes behind it.

Use this view to answer questions such as who changed an area or where one person's work landed. It is a contribution view, not a performance rating.

People appears when contributor information is available for the selected period. Bot changes are reported separately and do not count in the people table.

## Share a view

Open **More actions → Copy link** to share the Atlas. Recipients still need access to the workspace and permission to view Review.

## Limits and empty states

| What you see | What it means |
|---|---|
| A component with no activity | No changes mapped to it in the selected period; the component can still be part of the repository |
| No merged changes in a period | Choose another period or check that changes merged into the branch Atlas tracks |
| No **People** view | Contributor information is unavailable for that period, or the view is unavailable in your deployment |
| A building state | The initial assessment or an update has not finished |

Atlas helps you understand merged work. Use the [Review workspace](/guide/code-review/review-workspace) to triage open changes, settle findings, and apply fixes.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Connect a repository first">
    Atlas needs a connected repository with finished setup. Open **Review settings**, check the repository's setup status, and finish or retry setup.
  </Accordion>
  <Accordion title="Ask an admin to build the Atlas">
    Your account can view Review but cannot change Atlas settings. Ask a workspace Admin to build it or check your permissions.
  </Accordion>
  <Accordion title="Could not build the Atlas">
    Read the error on the setup card. Check that the selected repository and branch are still available, then try **Build Atlas** again.
  </Accordion>
  <Accordion title="Your assessment needs another try">
    The first assessment did not finish. Read the error, check provider access and the selected branch, then click **Retry assessment**.
  </Accordion>
  <Accordion title="The page stopped updating while building">
    Click **Refresh** when the page offers it. A paused page refresh does not by itself mean the assessment failed.
  </Accordion>
  <Accordion title="A shared repository link no longer works">
    If the page says the repository is no longer available, choose a connected repository from the picker. Check workspace access with an Admin.
  </Accordion>
</AccordionGroup>

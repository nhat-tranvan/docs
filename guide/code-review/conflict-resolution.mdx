CloudThinker detects when a reviewed MR/PR can no longer merge into its base branch and — when Auto-Resolve is enabled — opens a follow-up MR/PR that resolves the conflict for you, preserving the intent of the original change.

---

## Conflict detection

Every reviewed MR/PR carries a merge-conflict status: **conflict**, **clean**, or **unknown** (the provider is still computing mergeability). Detection is proactive — conflicts are caught as soon as they appear, not only when the MR/PR is opened:

| Trigger | What happens |
|---------|--------------|
| MR/PR opened or updated | Conflict status is recorded as part of the review |
| Base branch changes | A push to the base branch re-checks open MRs/PRs, prioritizing those that touch overlapping files |
| Review list viewed | Statuses refresh when you open the code review list |
| MR/PR approved | Status is re-checked before the approval is processed |

Conflicting MRs/PRs show a red **Conflict** badge on the **MR / PR** list. Hover the badge to see the provider's raw merge status.

## Auto-Resolve

Auto-Resolve is **opt-in per workspace**. When enabled, CloudThinker responds to a detected conflict by opening a follow-up MR/PR that resolves it:

<Steps>
  <Step title="Conflict detected">
    A reviewed MR/PR becomes unmergeable because the base branch moved. CloudThinker posts a progress comment on the original MR/PR: *Conflict Resolution In Progress*.
  </Step>
  <Step title="Agent resolves the conflict">
    The resolution agent merges the base branch into the MR/PR's branch in an isolated workspace and resolves each conflict marker while preserving what both sides intended — it does not blindly pick one side.
  </Step>
  <Step title="Follow-up MR/PR opened">
    The resolved merge is pushed to a `cloudthinker/` branch and opened as a follow-up MR/PR **targeting the original MR/PR's branch**. The original MR/PR gets a comment linking to it, and the **MR / PR** list shows a **Resolution MR** link next to the item.
  </Step>
  <Step title="You merge the follow-up">
    Review and merge the follow-up into your branch — the original MR/PR becomes mergeable again. The follow-up itself is not code-reviewed and never triggers another resolution.
  </Step>
</Steps>

### Re-conflicts refresh, not duplicate

If the base branch moves again and the same MR/PR re-conflicts, CloudThinker **refreshes the existing follow-up** with a new resolution instead of opening a duplicate.

### If resolution fails

When a resolution run fails (for example, a transient network error), the progress comment flips to *Conflict Resolution Failed* so you're not left waiting. CloudThinker retries automatically on the next update to the base branch.

## Setup

<Steps>
  <Step title="Open the Repositories page">
    Go to **Code Review** > **Repositories** for your workspace.
  </Step>
  <Step title="Enable Auto-Resolve Conflicts">
    In the setup header, turn on the **Auto-Resolve Conflicts** toggle — "Open a follow-up PR to resolve base-branch conflicts automatically". Editing requires code review edit permission.
  </Step>
</Steps>

  <img src="/images/code-review/02-auto-resolve-conflicts-toggle.png" alt="Repositories page with the Auto-Resolve Conflicts toggle enabled in the setup header" />

</Note>

## Known limitations

- **Retargeting an open MR/PR** to a different base branch does not immediately re-run conflict detection. The status catches up on the next base-branch push or when the review list is viewed.
- **A mergeable MR/PR can briefly show an unknown status** if the provider computes mergeability asynchronously without sending a webhook. Viewing the review list refreshes it.

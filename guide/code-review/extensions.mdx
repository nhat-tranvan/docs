Extensions let Review read the ticket behind a pull request (PR) or merge request (MR). When the PR description links a Jira issue, a Confluence page, a Linear or Backlog issue, or a GitHub or GitLab issue, the reviewer fetches it and checks whether the code does what the ticket asks. Without an extension, Review judges the diff on its own and can't tell you that an acceptance criterion was missed.

## Available extensions

| Extension | Reads | Needs |
|---|---|---|
| **Jira / Confluence** | The linked ticket (summary, acceptance criteria, linked pages) and Confluence spec pages | An [Atlassian connection](/guide/connections/atlassian) |
| **Linear** | Issue title, description, status, labels and git branch | A [Linear connection](/guide/connections/linear) |
| **Backlog** | Issue summary, description and status | A [Backlog connection](/guide/connections/backlog) |
| **GitHub Issues** | Issues the PR references: title, body, labels and comments | Review set up on GitHub. Uses that same connection |
| **GitLab Issues** | Issues the MR references: title, description, labels and comments | Review set up on GitLab. Uses that same connection |

GitHub Issues appears only when your Review provider is GitHub, and GitLab Issues only when it's GitLab.

## Prerequisites

- Review connected to at least one repository. See [Review setup](/guide/code-review/setup).
- To connect a tracker: edit permission for Review and access to **Workspace Settings → Connections**. Without edit permission, tiles show **View** instead of **Connect**.
- An account on the tracker that can read the projects your tickets live in.

## Turn on an extension

<Steps>
  <Step title="Open the Extensions section">
    Go to **Review → Settings** and scroll to **Extensions** ("Link tickets and specs so Review can check changes against them"). Each tracker has a tile with its status.

    | Tile status | Meaning |
    |---|---|
    | **Connected** | Review already fetches tickets from it |
    | **Not connected** | No connection yet. Click **Connect** |
    | **Uses your GitHub connection** (or GitLab) | Works through your Review provider. Nothing to set up |
    | **Status unavailable** | The connection list didn't load. Refresh the page |
  </Step>
  <Step title="Connect the tracker">
    Click **Connect** on the tile. CloudThinker opens **Workspace Settings → Connections** with that connection's form ready. Fill it in using the connection guide for [Atlassian](/guide/connections/atlassian), [Linear](/guide/connections/linear) or [Backlog](/guide/connections/backlog), then save.

    **Success state:** back in **Review → Settings → Extensions**, the tile shows **Connected**.
  </Step>
  <Step title="Reference the ticket in the PR description">
    Put the ticket link or key in the PR or MR description. No command or setting is needed.

    | Tracker | Write this in the description |
    |---|---|
    | Jira | `https://myorg.atlassian.net/browse/OPS-1234` or `OPS-1234` |
    | Confluence | `https://myorg.atlassian.net/wiki/spaces/...` |
    | Linear | `https://linear.app/myorg/issue/ENG-123/slug` or `ENG-123` |
    | Backlog | `https://myspace.backlog.com/view/PROJ-123` or `PROJ-123` |
    | GitHub or GitLab issues | `Closes #123`, `Fixes #456` or `#123` |
  </Step>
  <Step title="Open the PR and read the review">
    The review runs as usual. Findings now cover gaps against the ticket as well as the code itself.

    **Success state:** when the change misses part of the ticket, the review findings say which part.
  </Step>
</Steps>

Click **Manage** on a connected tile, or **View** on any other, to see what that extension reads and the patterns it recognizes.

## Example

A PR description like this:

```markdown
Add rate limiting to the login endpoint.

Implements OPS-1234. Spec: https://myorg.atlassian.net/wiki/spaces/ENG/pages/123456
```

Say OPS-1234 lists "return 429 with a Retry-After header" as an acceptance criterion, and the diff returns 429 without the header. With the Jira extension, the reviewer has that criterion in front of it and can flag the missing header against the ticket. Without it, the same diff looks correct.

## What gets read

- **The description only.** Review scans the PR or MR description for links and keys.
- **Not code.** A key inside a code block or inline code (`` `OPS-1234` ``) is ignored, so example IDs in snippets don't trigger lookups.
- **Up to 20 references per PR**, taken from the first 65,535 characters of the description. Put the ticket that matters most first.
- **Tickets your connection can see.** Review reads with the connected account's access, so a ticket in a project that account can't open isn't available to the review.

## Write tickets that help the review

- **List acceptance criteria as separate lines.** Each one becomes something the reviewer can check. "Works well" can't be checked; "returns 429 after 5 failed attempts in 1 minute" can.
- **Link the spec, not just the ticket.** A Confluence page with the API contract gives the reviewer the exact field names and status codes.
- **Reference every ticket the PR closes.** A PR that fixes two bugs should name both.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The review doesn't mention the ticket">
    **Check:** the reference is in the description, not only the branch name or commit message, and not inside backticks or a code block. Confirm the tile shows **Connected**.

    **Fix:** edit the description, then comment `@cloudthinker-ai review` on the PR to run the review again. See [mention commands](/guide/code-review/mention-commands).
  </Accordion>
  <Accordion title="I don't see GitHub Issues or GitLab Issues">
    Those tiles appear only for the matching Review provider. On Bitbucket, Azure DevOps or AWS CodeCommit, use Jira, Linear or Backlog instead.
  </Accordion>
  <Accordion title="Tiles show View instead of Connect">
    Your role can't change Review settings. Ask a workspace Admin to connect the tracker, or to update your role in [workspace users](/guide/workspace-users).
  </Accordion>
  <Accordion title="The tile says Connected but a ticket isn't read">
    The connected account can't open that ticket's project. Grant it access in the tracker, or reconnect with an account that has it.
  </Accordion>
</AccordionGroup>

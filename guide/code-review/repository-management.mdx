Use **Review → Settings → Repositories** to choose what runs on each repository. Search your connected repositories, adjust individual features, or apply one change to a selection.

## Prerequisites

- [Review is set up](/guide/code-review/setup), and your Git connection can access the repositories you want to manage.
- You're a workspace **Admin** to change repository settings. Developers and Viewers can inspect the list. See [roles and permissions](/guide/security/roles).
- Codebase Atlas and Learnings controls appear when those features are available for your instance and provider.

## Find a repository

Open **Review → Settings** and find **Repositories**. Search by repository name, then choose a filter:

| Filter | Repositories shown |
|---|---|
| **All** | Every configured repository matching the search |
| **Review** | Repositories with Review on |
| **Codebase Atlas** | Repositories with the daily map on |
| **Learnings** | Repositories with Review on and a Learnings schedule |
| **needs attention** | Repositories with failed setup or lost provider access; the button includes a count |

If nothing matches, click **Show all repositories** to clear the search and filter. Use the page controls to browse a longer list.

## Add a repository

<Steps>
  <Step title="Open the repository picker">
    Click **Add repository** in **Review → Settings → Repositories**.
  </Step>
  <Step title="Choose a repository your connection can access">
    Select one or more repositories, then click **Add**, which shows your selection count. Already configured repositories are marked **Added**.

    If a repository is missing, check the Git connection's access first. See [provider authentication](/guide/code-review/provider-auth).
  </Step>
  <Step title="Wait for setup">
    The repository shows **Cloning**, and its Review control says **Setting up**. Wait for setup to finish before changing its features.

    **Success state:** the repository appears in the table with an available Review switch.
  </Step>
</Steps>

Repositories created later in your Git provider need to be added here too. Adding a repository to the provider alone does not add it to Review.

## Choose what runs

Each ready repository has controls for its available features. Changes save when you use the control; there is no separate page-wide save action.

| Control | Choices and behavior |
|---|---|
| **Review** | Turn automatic reviews on or off for the repository |
| **Codebase Atlas** | Select a branch for the daily map, or choose **Off** |
| **Learnings** | Choose **Off**, **Weekly** or **Monthly** for learning from resolved findings |

The Codebase Atlas column shows the selected branch. Open its picker to choose another branch. This branch setting controls the daily map; [review filters](/guide/code-review/setup#filter-which-prs-get-reviewed) separately decide which pull or merge requests get reviewed.

To open an enabled map, use the repository's actions menu (⋯) and choose **Open Codebase Atlas**. See [Codebase Atlas](/guide/code-review/codebase-atlas) to read its results.

<Note>
  Codebase Atlas needs Review to be on. Turning Review off also turns off its daily Atlas map. Turning Review back on does not restore the map automatically: select a branch again.
</Note>

[Learnings](/guide/code-review/convention-rules) keeps its selected schedule while Review is off, but runs pause until Review is on again. Choose **Off** in the Learnings column to stop its schedule.

## Update several repositories

<Steps>
  <Step title="Select the repositories">
    Tick the checkboxes beside the repositories you want to change. The table's header checkbox selects the repositories on the current page.

    Your selection can include repositories from several pages, up to 200 at a time. Check the **selected** count before applying a change. Click **Clear** to start again.
  </Step>
  <Step title="Apply a shared setting">
    Choose **Turn on Review** or **Turn off Review**. Turning off Review opens a confirmation describing the affected maps and Learnings.

    To schedule other features, open **Schedule** and choose **Map daily** or **Learnings weekly**, when available.
  </Step>
  <Step title="Check the result">
    Inspect the repository rows after the update. If all updates succeed, the selection clears. If some fail, those repositories stay selected so you can review and retry them.

    **Success state:** the requested setting appears on each successfully updated repository.
  </Step>
</Steps>

The Codebase Atlas column also has a menu labeled **Map all or none on this page**. **Map all** enables daily maps for eligible repositories on that page; **Map none** disables maps on that page. These actions do not change every repository in the workspace.

## Use repository actions

Open a repository's actions menu (⋯) for these tasks:

| Action | What to do |
|---|---|
| **Configure filters** | Include or exclude pull requests by author, target branch or label. Follow [review filters](/guide/code-review/setup#filter-which-prs-get-reviewed) |
| **Learning sources** | Inspect convention files Review reads. See [convention files](/guide/code-review/convention-rules#add-your-own-convention-files) |
| **Customize for this repository** | Open its summary layout settings. See [Review Customizations](/guide/code-review/customizations) |
| **Run Code Audit** | Open a source security audit for this repository, when available and permitted. See [Code Audit](/guide/security/code-audit) |
| **Remove repository** | Remove it from this Review setup; confirm with **Remove**. You can add it again later |

Some actions appear only after repository setup finishes. To pause reviews while keeping the repository configured, use its Review switch.

## Troubleshooting

<AccordionGroup>
  <Accordion title="A feature says Setting up or Not set up">
    **Cause:** the repository has not finished cloning, or setup failed or was cancelled.

    **Check:** inspect its setup status. Hover **Setup failed** or **Setup cancelled** for the clone error.

    **Fix:** correct provider access if needed, then click **Retry**. For a clone that remains on **Cloning**, click **Cancel**, confirm **Cancel clone**, then retry.
  </Accordion>
  <Accordion title="A repository shows No access">
    **Cause:** the provider connection no longer has access to it.

    **Check:** confirm the repository is still granted to your connected account or app.

    **Fix:** restore provider access. Use **Update token** when offered if the token expired or changed. See [authentication problems](/guide/code-review/troubleshooting).
  </Accordion>
  <Accordion title="Codebase Atlas says Needs Review">
    **Cause:** Review is off for this repository.

    **Fix:** turn Review on, then choose the branch in the Codebase Atlas column. A previous daily map does not resume automatically.
  </Accordion>
  <Accordion title="Some repositories did not accept a bulk update">
    **Check:** failed repositories stay selected. Inspect their setup status and provider access before retrying.

    **Fix:** complete setup or restore access, then apply the setting again to the remaining selection.
  </Accordion>
</AccordionGroup>

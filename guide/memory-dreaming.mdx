Dreaming is a nightly run that keeps [workspace memory](/guide/memory) short, current, and consistent. It reads conversations from the activity window (the last 24 hours by default), adds what is new, merges duplicates, and removes memory and [custom skills](/guide/skills/custom-skills) that no longer hold.

Agents save facts as they work, so overlaps and contradictions pile up. Dreaming cleans them up without anyone tending memory by hand, while [connections](/guide/connections/overview) stay read-only and conversation and connection notes are never changed. Conversation notes are older per-conversation summaries that CloudThinker no longer writes; connection notes are described on [Workspace Memory](/guide/memory#what-cloudthinker-remembers).

## Prerequisites

- The workspace Admin role to change settings or click **Run now**. Other members see the settings read-only.
- Credits in the workspace. Dreaming runs on the Pro tier, the default model tier, billed at 1.0x the base credit rate. It can't use daily credits, the free allowance that only pays for chat on the Light tier. Cost depends on how many conversations it reads, so a busy workspace pays more per night than a quiet one. CloudThinker doesn't show a per-run estimate. Check spending on [Usage](/guide/billing/usage).

## Turn Dreaming on or off

<Note>
Dreaming is on by default for every workspace and uses credits each night it has conversations to read. Consider turning it off if your credits are tight, or if your team curates memory and custom skills by hand and doesn't want them merged or deleted.
</Note>

<Steps>
  <Step title="Open Memory settings">
    Go to **More → Workspace settings → Memory**.
  </Step>
  <Step title="Set the switch">
    Turn **Consolidate memory nightly (Dreaming)** on or off.
  </Step>
</Steps>

**Success state:** the card shows **Next run** with a date and time in your browser's local time, followed by "Runs start within 45 minutes of that time." When the switch is off, **Next run** is hidden, the card shows "Turn on Dreaming to run it.", and **Run now** is disabled.

## How a run works

Runs start at 00:30 UTC, spread over the next 45 minutes across workspaces. Only one run per workspace happens at a time. A workspace can't change the schedule; use **Run now** for an extra run.

1. **Gather.** Dreaming lists every conversation updated in the activity window, plus any the previous run didn't finish.
2. **Read.** Sub-agents that can only read go through batches of conversations in parallel and report what is worth keeping.
3. **Consolidate.** Dreaming compares the sub-agents' reports from step 2 with existing memory and custom skills, then adds, edits, merges, or deletes.
4. **Finalize.** Dreaming writes a summary to **Run history**. Near the time limit it stops reading and finalizes with what it has.
5. **Carry over.** Conversations it didn't read to the end go first on the next run (see [Limits](#limits) for the cap).

### What Dreaming reads and changes

| Area | What Dreaming does |
|---|---|
| Chats, rooms (shared team chats), Memory chats, [headless chats](/guide/cli/headless-chat) from the CLI, and [deep dive](/guide/security/pentest-deep-dive) pentests | Reads every one updated in the activity window, from every member. A conversation can't be excluded; deleted conversations aren't read |
| Scheduled tasks and [autonomous agent](/guide/automation/autonomous-agents) runs | Reads them when **Include automated conversations** is on |
| Memory items | Adds, edits, merges, and deletes |
| Custom skills | Creates, updates, and merges. Deletes up to 10 per run when allowed |
| Conversation notes and connection notes | Never changes them. A run that touches them is rolled back, saves no changes to memory, and shows as **Failed** in **Run history** |
| Connections | Reads only |

## Customize Dreaming

Expand **Customize** on the Dreaming card.

<Warning>
Skill deletion is on by default and a deleted skill can't be restored. On a new workspace, turn off **Allow Dreaming to delete redundant custom skills** before the first nightly run, and turn it back on once a few run summaries look right.
</Warning>

| Option | Default | What it does |
|---|---|---|
| **Activity window** | **Last 24 hours** | How far back Dreaming reads: **Last 24 hours**, **Last 3 days**, or **Last 7 days** |
| **Include automated conversations** | On | Also reads scheduled tasks and [autonomous agent](/guide/automation/autonomous-agents) runs, not only chats |
| **Allow Dreaming to delete redundant custom skills** | On | Off keeps every skill. Dreaming can still create and update them. A deleted skill can't be restored, so turn this off until you trust the results |
| **Focus instructions** | Empty | Up to 1,000 characters on what to watch for. Click **Save focus** to apply |

The window and switches save as soon as you change them. Every change applies from the next run.

<Frame>
  <img src="/images/memory/06-dreaming-customize.jpg" alt="Customize section with the activity window choices, the automated conversations and skill deletion switches, and the Focus instructions box" />
</Frame>

A focus instruction that works well names a topic and an outcome:

```text
Track cost-saving decisions and name the owner.
Keep one item per AWS account with its region and exemptions.
```

Focus instructions are guidance the run follows on a best-effort basis, not enforced rules. They never override the safety rules: connections stay read-only and protected notes stay untouched.

## Run Dreaming now

Use this after a big import or a busy day, instead of waiting for the night.

<Steps>
  <Step title="Start the run">
    On the Dreaming card, click **Run now**.
  </Step>
  <Step title="Confirm the cost">
    Click **Run at Pro rate**. The dialog states the rate only, with no cost estimate. The run uses workspace credits at the Pro rate, the same as the nightly run.
  </Step>
</Steps>

**Success state:** the button shows **Running…**, and the run appears in **Run history** as **Manual by** your name when it finishes. The run happens on the server, so you can leave the page. It stops after one hour at most.

If the run doesn't start, the dialog shows **Dreaming did not start** with one of these reasons:

| Message | Fix |
|---|---|
| Dreaming is already running for this workspace. | Wait for the current run to finish |
| There are no conversations in the activity window, so there is nothing to consolidate. Widen the window under Customize, or chat first. | Widen **Activity window** under **Customize**, or chat first |
| This workspace has no credits left to run Dreaming. | Add credits. Daily credits don't count |
| Nightly consolidation is off for this workspace. Turn it on to run it. | Turn the switch on first |
| Dreaming is turned off for this instance. An instance admin can turn it on. | Ask your instance admin (whoever runs a self-hosted CloudThinker install). On CloudThinker cloud, email [support@cloudthinker.io](mailto:support@cloudthinker.io) |

## Read the run history

**Run history** lists the latest 20 runs with status, start time, trigger (**Scheduled** or **Manual**), and duration. Click a run to expand it.

<Frame>
  <img src="/images/memory/07-run-history.jpg" alt="Run history with succeeded, skipped, and failed runs, one expanded to show conversations read and the run summary" />
</Frame>

| Status | Meaning |
|---|---|
| **Succeeded** | Finished. Shows conversations read, the number of skills deleted, and the summary. The summary names the memory items it wrote, merged, or deleted, and the skills it created, updated, or deleted |
| **Skipped** | Didn't start work. The reason is shown, for example **No conversations in the activity window** or **Another run was already going** |
| **Failed** | Stopped early. Edits already made are kept; skill deletes are not applied. Expand the row: the failure message ends with the run ID. No email or notification is sent, so check **Run history**. On CloudThinker cloud, email the run ID to [support@cloudthinker.io](mailto:support@cloudthinker.io); on a self-hosted instance, your instance admin finds the cause in the server logs |
| **Queued** or **Running** | Waiting or in progress |

## Undo a run

There's no per-run undo, bulk undo, or dry run. To reverse a bad run:

1. Expand the run in **Run history** and read the summary. It names each memory item and skill the run changed.
2. Ask in chat to restore each item from its revision history, for example "Restore the payments-ownership memory item to its version before the Dreaming run on 2026-10-24."
3. Re-create any deleted skill by hand. Deleted skills can't be recovered.
4. Turn off Dreaming or skill deletion until you've found the cause.

## Limits

| Item | Value |
|---|---|
| Time limit | One hour per run |
| Billing | Pro tier (1.0x), from workspace credits. Daily credits don't apply |
| Carry-over | Up to 200 unread conversations, kept for up to 7 days. People's chats and newer conversations are kept first. Conversations past the cap or older than 7 days are dropped without being read, and **Run history** doesn't show it |
| Failed runs | Not retried. The next night picks up from the carry-over |

## Troubleshooting

<AccordionGroup>
  <Accordion title="A run says Succeeded but memory didn't change">
    Dreaming only edits memory when conversations add something new. A quiet day can end with no edits, and the run summary says so.
  </Accordion>
  <Accordion title="An item I edited by hand was merged or deleted">
    Dreaming can merge or delete any item, including one you edited, when a newer conversation shows it's outdated. Items can't be locked. A focus instruction that names it, for example "Keep the payments-ownership item as is," lowers the chance, but it's best-effort and not guaranteed. To get a deleted item back, ask CloudThinker in chat to restore it from its revision history. See [Workspace Memory](/guide/memory#edit-or-delete-an-item).
  </Accordion>
  <Accordion title="Dreaming deleted a custom skill we need">
    Deleted skills can't be restored. The run's summary names the skills it deleted. Re-create the skill, then turn off **Allow Dreaming to delete redundant custom skills** under **Customize**.
  </Accordion>
  <Accordion title="The card says an instance admin turned off Dreaming">
    Dreaming or workspace memory is switched off for the whole instance. The switch and **Run now** stay locked until an instance admin turns it back on. On CloudThinker cloud, email [support@cloudthinker.io](mailto:support@cloudthinker.io).
  </Accordion>
  <Accordion title="Run now is greyed out">
    Either you aren't a workspace Admin, the nightly switch is off, a run is already in progress, or an instance admin turned off Dreaming or workspace memory. If the button works but the run doesn't start, the dialog gives the reason, such as no credits.
  </Accordion>
</AccordionGroup>

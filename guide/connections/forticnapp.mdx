Connect FortiCNAPP so CloudThinker can investigate alerts and host or container vulnerability findings. The connection uses an API key ID and secret for the selected FortiCNAPP account.

## Prerequisites

- Access to the FortiCNAPP account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your FortiCNAPP administrator for an API key ID and API secret authorized for read access. Keep the account URL from that same FortiCNAPP account with the key pair. If your organization uses FortiCloud access, ask the administrator to confirm the credentials are compatible with the account API.

    See the [provider documentation](https://docs.fortinet.com/document/forticnapp/latest/administration-guide/155000/api-keys) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **FortiCNAPP**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Account URL** | The account’s HTTPS address. | https://acme.lacework.net |
| **API key ID** | The identifier from the account API-key credentials. | Copy from the API-key file |
| **API secret** | The secret paired with the API key ID. | Enter in the connection form |

## Required permissions

Use credentials with read access to alerts and host and container vulnerability findings. Account and user permissions constrain the available data. CloudThinker does not need alert-change or vulnerability-exception rights for these investigations.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Alerts** | Read alerts, severity, and status over a selected time window. |
| **Host vulnerabilities** | Review vulnerable packages, affected hosts, and severity. |
| **Container vulnerabilities** | Inspect findings for container images and packages. |

This connection is read-only. It cannot comment on or close alerts or add vulnerability exceptions. Failed reads are reported as failures rather than zero findings; a sample cannot establish account-wide compliance.

### Verify the connection

```text
Summarize FortiCNAPP alerts and host and container vulnerability findings, separating successful reads from permission errors
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Show the most severe open FortiCNAPP alerts in the last day
Review critical container vulnerabilities and identify affected image references
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="The API key cannot obtain access">
Confirm the Account URL, API key ID, and API secret belong to one account. Ask the administrator to check that the key is active and has access to the requested data.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

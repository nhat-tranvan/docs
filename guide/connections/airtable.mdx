Connect Airtable so CloudThinker can browse bases, table schemas, views, and a sample of records. The connection uses a personal access token.

## Prerequisites

- Access to the Airtable account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Open Airtable’s **Builder hub → Personal access tokens** and create a token. Add `data.records:read` and `schema.bases:read`, then explicitly select the bases this connection may access. Copy the token when Airtable displays it.

    See the [provider documentation](https://support.airtable.com/articles/9934989703-creating-personal-access-tokens) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Airtable**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Personal access token** | Airtable personal access token with the two read scopes and access to the intended bases. | Copy from Airtable |

## Required permissions

The token needs both `schema.bases:read` for base structure and `data.records:read` for records. Its base access list and the creating user’s permissions both constrain results. A scope alone does not grant access to every base.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Base inventory** | List accessible bases and inspect their tables and views. |
| **Table structure** | Read field names, types, and view identifiers. |
| **Records** | Read a bounded sample from one table or view. |

This connection is read-only: it does not create, update, or delete records, fields, or tables. Record samples are not table totals, and missing permissions do not mean a base is empty.

### Verify the connection

```text
List the Airtable bases this connection can read, then show the tables and views in one base
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Show the schema of the selected Airtable base and identify tables with no views
Show a sample of records from the selected table and flag stalled status values
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="A base is missing or returns 403/404">
Add that base to the token’s access list and check both read scopes. Confirm the token’s user can open it in Airtable; do not assume the base was deleted.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

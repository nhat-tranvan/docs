Connect OpenObserve so CloudThinker can review alerts, failed evaluations, and firing history. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing OpenObserve account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain a dedicated user's email and password or service-account token for your OpenObserve organization. See the [vendor's authentication documentation](https://openobserve.ai/docs/reference/api/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **OpenObserve**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the correct organization ID. For Cloud, the default API address is `https://api.openobserve.ai`.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **OpenObserve URL** | Yes | The HTTPS address you open OpenObserve at. Keep https://api.openobserve.ai for OpenObserve Cloud. Default: `https://api.openobserve.ai`. |
| **Organization ID** | Yes | The organization ID shown in the OpenObserve URL, such as default. Default: `default`. |
| **User email** | Yes | The email of a service account or user. With an alert editor role the agent can enable or disable alerts after you approve. |
| **Password or token** | Yes | The service account token, or the user's password or token. |
| **CA certificate (optional)** | No | PEM of a private CA or TLS-inspecting proxy. Leave empty to use public trust. The certificate and hostname are always checked. |

## Required permissions

Read alerts, evaluation failures, and firing history. Enabling or disabling an alert needs alert editing permission.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Alert inventory | Read alert definitions. |
| Evaluation health | Inspect failed evaluations and firing history. |
| Alert control | Enable or disable one existing alert after approval. |

The only supported change enables or disables one existing alert. Creating or deleting alert definitions, destinations, and templates is excluded.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my OpenObserve connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use OpenObserve to review alerts, failed evaluations, and firing history.
Summarize the highest-priority items visible through my OpenObserve connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in OpenObserve. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in OpenObserve when access is no longer needed, and update the connection after rotation.

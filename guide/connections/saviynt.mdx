Connect Saviynt Identity Cloud so CloudThinker can audit inactive users, orphan accounts, endpoint health, and pending access requests. The connection uses a Saviynt service account.

## Prerequisites

- Access to the Saviynt Identity Cloud account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your Saviynt administrator for a dedicated service account authorized to read users, accounts, access details, endpoints, and its pending request queue. Obtain the tenant’s HTTPS origin and the account credentials. Your administrator must permit the account’s API sign-in method.

    See the [provider documentation](https://saviynt.com/es/api-reference) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Saviynt Identity Cloud**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Tenant URL** | HTTPS origin of the Saviynt tenant, without /ECM. | https://acme.saviyntcloud.com |
| **Service account username** | User permitted to perform the intended audit reads. | Your service account |
| **Password** | Password of that service account. | Enter in the connection form |

## Required permissions

The service account’s SAV role must permit the required user, account, access, endpoint, and pending-request web services. Grant only the necessary reads. The pending approval queue is the service account’s queue; it is not every open request in the tenant.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Identity hygiene** | Review inactive users, missing managers, and orphan accounts. |
| **Access review** | Inspect a selected user’s privileged and critical access. |
| **Approval queue** | Review visible pending requests, age, due dates, and separation-of-duties conflicts. |

This connection is read-only. It cannot approve or reject requests, certify access, provision accounts, or update users. Summaries can cover bounded samples, so incomplete inventories must remain labeled as such.

### Verify the connection

```text
Summarize inactive users, orphan accounts, endpoint status, and the connected account’s pending approval queue in Saviynt
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Review the selected user’s access and identify privileged or critical entitlements
Show overdue pending requests and any recorded separation-of-duties conflicts
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="The approval queue differs from another administrator’s queue">
Requests are scoped to the service account’s visible queue. Confirm the intended account and permissions rather than treating another user’s queue as missing data.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

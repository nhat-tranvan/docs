Connect NetBox to let CloudThinker search devices, sites, IP addresses, and prefixes. The connection uses **a NetBox API token**.

## Prerequisites

- An account with access to the NetBox resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in NetBox">
    Create a dedicated NetBox user with view permissions for the inventory you want investigated. Under that user’s profile, open the API tokens page and create a token. Store the complete token when it is displayed. Use your NetBox instance URL; the NetBox Cloud management API is a different service.

    Follow the [vendor’s credential and authentication guidance](https://netboxlabs.com/docs/netbox/integrations/rest-api/) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **NetBox**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **NetBox URL** | Yes | The address you open NetBox at, such as https://netbox.example.com or https://example.com/netbox. |
| **API token** | Yes | The API token for the account described in Setup. |
| **CA certificate (optional)** | Optional | PEM of the private CA that issued the NetBox certificate. Leave empty to use public trust. The certificate and hostname are always checked. |

For read-only use, also disable write access on the token where your NetBox version offers that setting.

## Required permissions

View access to devices, sites, IP addresses, and prefixes. Device status changes, journal creation, and reserving addresses also need the relevant change or add permissions. Keep the user and token read-only unless those workflows are intended.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Search devices and sites |
| Investigation | Inspect IP addresses and prefixes |
| Changes | Reserve an IP address or update device metadata when authorized |

### Verify the connection

```text
Discover NetBox sites and devices and summarize IP address and prefix inventory without changes. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Discover NetBox sites and devices and summarize IP address and prefix inventory without changes
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. The user’s object permissions limit which inventory is visible. Token-format compatibility varies by NetBox version; if a new token is refused, confirm supported authentication with your administrator rather than weakening access controls.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

Connect GitHub and CloudThinker agents can read your repositories, pull requests, issues, and GitHub Actions runs, and [Review](/guide/code-review/overview) can post AI code reviews on pull requests. You connect by installing the CloudThinker **GitHub App** on an account or organization, so there's no token to create or paste.

## Prerequisites

- Access to the GitHub repositories you want agents to read.
- To install on a GitHub organization: the **Owner** role in that organization, or an owner willing to approve the install.
- The **Admin** role in your CloudThinker workspace, which can add and edit connections. See [Roles](/guide/security/roles).
- A GitHub.com account or organization. Setup installs the app from GitHub.com and has no field for a GitHub Enterprise Server URL.

## Setup

<Steps>
  <Step title="Open GitHub in CloudThinker">
    In the sidebar, click **More → Workspace settings → Connections**. On the **Builtin Connections** tab, search for **GitHub** and click **Connect**.

    The **Connect GitHub** dialog lists what the app requests: access to the repositories you select, read and write permissions for pull requests, and webhook events for code review.
  </Step>
  <Step title="Install the GitHub App">
    Click **Install GitHub App**. GitHub opens and asks where to install it. Pick the account or organization, then choose **All repositories** or **Only select repositories**.

    Pick only the repositories agents need. You can add more later from GitHub.
  </Step>
  <Step title="Approve and return">
    Click **Install** on GitHub. GitHub sends you back to CloudThinker, which shows **Processing GitHub App installation...** and then **Successfully installed!**

    **Success state:** GitHub shows **Connected** on the **Builtin Connections** tab.
  </Step>
</Steps>

The app registers its own webhooks (event notifications GitHub sends when a pull request changes), so GitHub needs no webhook setup for Review.

## Connection details

GitHub has no fields to fill in. CloudThinker stores the GitHub App installation when you approve it.

| Item | Where it comes from |
|------|---------------------|
| **GitHub App installation** | Created on GitHub during setup and saved automatically |
| **Repositories** | The repositories you granted to the app on GitHub |

## Required permissions

The app's permissions are fixed. You decide its reach by choosing which repositories it's installed on. The **Connect GitHub** dialog summarizes what the app requests:

| Request | Why CloudThinker needs it |
|---------|---------------------------|
| Access to the repositories you select | Read code, issues, and Actions runs |
| Read and write on pull requests | Read pull requests and post review comments |
| Webhook events | Start a review when a pull request opens or changes |

GitHub's install screen lists every permission by its GitHub name, with its access level. Check it there before you click **Install**.

<Tip>
Install the app on **Only select repositories** and start with the ones you want reviewed or investigated. To change the list later on GitHub, go to **Organization settings → GitHub Apps** (or **Settings → Applications → Installed GitHub Apps** for a personal account), click **Configure** next to the CloudThinker app, and edit GitHub's **Repository access**.
</Tip>

## Control access in CloudThinker

Two settings on the connection's detail panel narrow what agents do with the installation. Open **Connections**, select **GitHub**, and look under **Settings**.

| Setting | Options | What it does |
|---------|---------|--------------|
| **Repository access** (CloudThinker) | **All** or **Selected** | **All** lets agents read every repository the installation covers, including new ones. **Selected** limits agents to the repositories you pick, and new repositories stay excluded until you add them. |
| **Allow writes** | On (default) or off | On: agents can propose changes, and your [Rules and Approval mode](/guide/approvals/overview) decide each one. Off: agents can only read, and every change is refused. |

With the default Approval mode for new workspaces, a write that a Rule allows runs, and a write no Rule covers goes to AI judgment, which runs it or asks a person. To make every GitHub write wait for you, add a [Rule](/guide/approvals/rules) or turn **Allow writes** off.

These settings only narrow what GitHub already grants. Choosing which repositories Review runs on is a separate step in [Review setup](/guide/code-review/setup).

## Agent capabilities

Agents work through the GitHub CLI (`gh`). Reads run without asking. Writes need **Allow writes** on and pass through your Rules and Approval mode first. Comments and pull requests appear on GitHub as the app's bot account, `cloudthinker-ai[bot]`.

| Capability | What agents can do |
|------------|--------------------|
| **Repositories** | List repositories the connection reaches and read their code and history |
| **Pull requests** | Summarize open pull requests, their review status, and discussion |
| **Actions runs** | Find failing workflow runs and read their logs to explain the failure |
| **Issues** | Read issues for triage and delivery context |
| **Changes** | Create branches, comment, or open pull requests, after approval |

### Verify the connection

```text
List the GitHub repositories you can reach and how many open pull requests each one has
```

A working connection names your real repositories and counts. A generic answer about GitHub means the connection isn't being used. Check GitHub's **Repository access** on the app install, then CloudThinker's **Repository access** setting.

### Example prompts

```text
Which open pull requests in our GitHub repositories have had no review for more than 3 days?
Why did the latest GitHub Actions run on main fail in the payments repository?
Summarize the pull requests merged into api this week
```

## Troubleshooting

<Accordion title="Installation failed">
The redirect back from GitHub was interrupted, or you approved the install from a different GitHub account. Sign in to the right account, return to **Connections → GitHub**, and click **Connect** again.
</Accordion>

<Accordion title="You can't install on your organization">
Only organization owners can install apps on a GitHub organization. When a member picks the organization, GitHub offers to send the owners a request instead of installing. Nothing is installed until an owner approves it. After approval, click **Connect** again and pick the organization.
</Accordion>

<Accordion title="An agent can't find a repository">
Check both layers. On GitHub, the app install's **Repository access** must include that repository. In CloudThinker, the connection's **Repository access** setting must be **All**, or **Selected** with that repository in the list.
</Accordion>

<Accordion title="Reconnect GitHub to renew its App installation credentials.">
CloudThinker could no longer use the installation, often because the app was uninstalled or suspended on GitHub. Open the connection and click **Connect** to install the app again.
</Accordion>

<Accordion title="An agent says it can't make changes">
**Allow writes** is off on the connection, or a Rule refused the action. Turn on **Allow writes** if you want agents to propose changes, then check your [approval rules](/guide/approvals/rules).
</Accordion>

## Security

<ConnectionSecurity />

- **Scope the installation.** The app reaches only the repositories you grant it on GitHub, and you can narrow that list at any time.
- **Uninstall to revoke.** On the app's **Configure** page on GitHub, click **Uninstall**. Access to every repository stops, and the connection then shows [Reconnect GitHub to renew its App installation credentials.](#troubleshooting)

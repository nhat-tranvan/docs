Connect UptimeRobot and ask [CloudThinker](/guide/agents/overview) which monitors are down right now, what a monitor's uptime was last week, or which incidents hit yesterday. [UptimeRobot](https://uptimerobot.com) checks whether your websites and endpoints respond. The connection uses UptimeRobot's **Read-only API key**, which can't create, change, or pause monitors, so CloudThinker can only look.

## What CloudThinker can do

CloudThinker allows three UptimeRobot reads on this connection: list monitors, get monitor stats, and list incidents. CloudThinker combines them into these answers:

| Capability | What you get |
|------------|--------------|
| **Account health** | Monitors that are down or paused, plus recent incidents, for a time window |
| **Monitor inventory** | Your monitors with their status and overall health |
| **Uptime and response time** | Uptime statistics and response-time values over a time range |
| **Incident summary** | Recent incidents with their status and timing |

By default CloudThinker looks at the last 24 hours and return up to 10 items, and you can ask for up to 25. When a list is cut short, CloudThinker says so.

CloudThinker leaves out monitor settings, custom headers, incident logs, alert contacts, and integration details. It can't read incident details or your integrations list, because those can expose contacts and webhook URLs.

## Before you start

- An UptimeRobot account that owns the monitors you want CloudThinker to read.
- The **Admin** role in the CloudThinker workspace, which you need to add connections. See [Roles](/guide/security/roles).

<Warning>
Use the **Read-only API key**, never the **Main API key**. The Main key has the same permissions as your UptimeRobot account. CloudThinker doesn't check which key you paste. With a Main key it still runs only the three reads above, but the stored key could change your account if it ever leaked.
</Warning>

## Connect UptimeRobot

<Steps>
  <Step title="Open Integrations & API">
    Sign in to UptimeRobot and go to **Integrations & API**.
  </Step>
  <Step title="Copy the Read-only API key">
    Copy the **Read-only API Key**. Skip the Main API Key on the same page. If no Read-only key exists yet, create one there first, then copy it.
  </Step>
  <Step title="Add the connection in CloudThinker">
    In the sidebar, click **More → Workspace settings → Connections**, stay on the **Builtin Connections** tab, and select **UptimeRobot**. Paste the key into **UPTIMEROBOT_READ_ONLY_API_KEY**, and click **Connect**. There's no region or URL to enter.

    **Success state:** the UptimeRobot card shows **Connected**.
  </Step>
</Steps>

## Verify the connection

Ask CloudThinker in chat:

```text
Check UptimeRobot for the last 24 hours and summarize monitors that are down or paused and any recent incidents
```

**Success state:** you get a short health summary that matches your UptimeRobot dashboard. An empty incident list is a valid answer, not an error.

## Troubleshooting

<Accordion title="The key is rejected">
The key is wrong or has extra characters. Check for spaces around the pasted value and confirm you copied the **Read-only API Key** from **Integrations & API**. If it still fails, generate a new Read-only key in UptimeRobot and update the connection.
</Accordion>

<Accordion title="Health shows as unavailable">
The uptime statistics read failed, so CloudThinker reports health as unavailable instead of guessing. Ask again. If UptimeRobot returned a 429, wait at least 60 seconds first.
</Accordion>

<Accordion title="I pasted the Main API key">
Replace it. Copy the **Read-only API Key** from **Integrations & API**, open the UptimeRobot connection in **More → Workspace settings → Connections**, and update the key. To be safe, regenerate the Main key in UptimeRobot afterward.
</Accordion>

<Accordion title="429 Too Many Requests">
UptimeRobot limits requests per rolling 60-second window, based on your plan. Every tool using your account's API shares that limit. Wait 60 seconds, then ask a narrower question.
</Accordion>

<Accordion title="CloudThinker can't pause or change a monitor">
That's by design. The Read-only key can't make changes, and CloudThinker doesn't try. Make the change in UptimeRobot.
</Accordion>

## Security

<ConnectionSecurity />

- **Never use the Main API key**: it carries the same permissions as your UptimeRobot account.
- **Shared rate limit**: other tools on the same account draw from the same request quota.

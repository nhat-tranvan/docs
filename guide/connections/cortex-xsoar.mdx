Connect Cortex XSOAR so CloudThinker can review incidents, ownership, severity, and threat-intelligence indicators. The connection uses a Standard API key for an XSOAR 6 server or XSOAR 8 tenant.

## Prerequisites

- Access to the Cortex XSOAR account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to the provider API. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services). Access through your browser or local SSH tunnel alone is insufficient.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your XSOAR administrator for a Standard API key associated with a read-only role. For XSOAR 8, obtain both the key ID and the API URL from the tenant’s API-key settings. For XSOAR 6, use the server’s HTTPS URL and leave the XSOAR 8 key-ID field empty.

    See the [provider documentation](https://xsoar.pan.dev/docs/reference/integrations/core-rest-api) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Cortex XSOAR**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **API URL** | XSOAR server URL, or the API URL shown by an XSOAR 8 tenant. | https://xsoar.example.com |
| **API key** | Standard key for incident and indicator reads. | Copy from XSOAR |
| **API key ID (XSOAR 8)** | The key ID for XSOAR 8; leave empty for XSOAR 6. | Your XSOAR 8 key ID |

## Required permissions

Use a role permitted to read the incidents and indicators under investigation. Broader administrative or playbook-execution rights are unnecessary for this connection. The connected role determines which incidents appear, so an empty list does not establish that the tenant has no incidents.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Incidents** | List or inspect incidents with severity, status, owner, and type. |
| **Response gaps** | Find open urgent incidents without owners or playbooks. |
| **Indicators** | Review indicators and recent malicious verdicts. |

This connection is read-only. It does not run playbooks, assign or close incidents, execute War Room commands, or edit indicators. Make those changes in XSOAR after reviewing the investigation.

### Verify the connection

```text
Summarize open XSOAR incidents by severity and show recent malicious indicators, identifying any permission failures
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Find high-severity open XSOAR incidents with no owner
Inspect the selected indicator and show its current verdict and related context
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="XSOAR 8 authentication fails">
Check that API URL and API key ID come from the same tenant and Standard API key. Do not substitute the browser console address for the API URL.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

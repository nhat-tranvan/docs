Connect HAProxy so CloudThinker can operate load balancers, server pools, and traffic. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing HAProxy account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain a Data Plane API username and password for your HAProxy deployment. Enter them together as `username:password`. See the [vendor's authentication documentation](https://www.haproxy.com/documentation/haproxy-data-plane-api/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **HAProxy**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the HTTPS origin of Data Plane API v3.4 without `/v3`; the API must reach HAProxy's runtime socket.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Data Plane API URL** | Yes | HTTPS origin of your HAProxy Data Plane API v3.4, without /v3. The API must reach HAProxy's runtime socket. |
| **API credentials** | Yes | Enter username:password for the Data Plane API user. A password may contain colons; the username cannot. The user's permissions govern reads and approved writes. |
| **CA certificate (optional)** | No | PEM of the issuing private CA for this self-hosted API. Leave empty for public trust. Hostname and certificate verification remain enabled. |

## Required permissions

Read backend, server, runtime, and traffic state. Configuration changes require an API identity permitted to make the requested change.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Traffic health | Inspect backend, server, and traffic statistics. |
| Runtime state | Review active runtime configuration. |
| Load-balancer changes | Make supported runtime or configuration changes after approval. |

Drain, maintenance, weight, address, and deletion operations can interrupt traffic. Runtime changes can be replaced by a reload.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my HAProxy connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use HAProxy to operate load balancers, server pools, and traffic.
Summarize the highest-priority items visible through my HAProxy connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in HAProxy. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in HAProxy when access is no longer needed, and update the connection after rotation.

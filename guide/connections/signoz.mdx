Connect SigNoz Cloud or a self-hosted SigNoz instance to let CloudThinker agents rank a service's slowest operations, search and group logs, open a full trace waterfall, query metrics, and review alert rules and their history. You give CloudThinker two values: your SigNoz base URL and a Service Account API key. The setup is the same for SigNoz Cloud and self-hosted.

## Prerequisites

- A SigNoz Cloud or self-hosted SigNoz instance with at least one instrumented service sending telemetry. SigNoz creates services from your applications' telemetry, so agents can't create one for you.
- A SigNoz user with the SigNoz-Admin role, who can create a Service Account and its API key.
- Your SigNoz base URL: `https://<your-tenant>.signoz.cloud` for SigNoz Cloud, or the address you open SigNoz at for self-hosted, such as `https://signoz.internal.example.com`.
- For self-hosted SigNoz: the instance must accept connections from CloudThinker Cloud. To allowlist CloudThinker's egress IPs, ask your CloudThinker contact for the current list. See [Reaching private services](/guide/connections/overview#reaching-private-services) for other options.
- The **Admin** role in the CloudThinker workspace, which you need to add connections. See [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Create a Service Account">
    In SigNoz, open **Settings → Service Accounts**, click **New Service Account**, and name it something you'll recognize later, such as `cloudthinker`. The steps are the same on SigNoz Cloud and self-hosted.
  </Step>
  <Step title="Pick its role">
    On the account's **Overview** tab, pick the narrowest role from the **Roles** dropdown:

    | You want agents to | Role |
    |--------------------|------|
    | Investigate services, logs, traces, metrics, dashboards, and alerts | **SigNoz-Viewer** |
    | Also create, update, or delete dashboards and alerts | **SigNoz-Editor** |
    | Also manage saved views and notification channels | **SigNoz-Admin** |

    Click **Save** before you create a key. SigNoz-Admin can also manage users, roles, and service accounts, so pick it only when you need it.
  </Step>
  <Step title="Create an API key">
    Open the account's **Keys** tab, click **Add Key**, name it (for example `cloudthinker-key`), set an expiration if your policy needs one, and copy the key. SigNoz shows it only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    In the sidebar, click **More → Workspace settings → Connections**, stay on the **Builtin Connections** tab, and select **SigNoz**. Fill in:

    - **SIGNOZ_URL**: the base URL only, for example `https://<your-tenant>.signoz.cloud`. Don't add `/api/v1` or any other path.
    - **SIGNOZ_API_KEY**: the key you copied.
    - **LOG_LEVEL**: leave it at **Info**. It sets how much detail the connection writes to CloudThinker's diagnostic logs, which support uses when troubleshooting.

    Click **Connect**.

    **Success state:** SigNoz shows **Connected**.
  </Step>
</Steps>

## Connection details

| Field | Required | Description | Example |
|-------|----------|-------------|---------|
| **SIGNOZ_URL** | Yes | Base URL of your instance, with no path | `https://<your-tenant>.signoz.cloud` |
| **SIGNOZ_API_KEY** | Yes | Service Account API key | From the account's **Keys** tab |
| **LOG_LEVEL** | No | Detail level for CloudThinker's internal connection logs, used by support. Default **Info** | **Info** |

## Required permissions

Agents can do exactly what the Service Account's role allows, and SigNoz enforces it.

- **SigNoz-Viewer** covers every read in the capability table below.
- **SigNoz-Editor** adds dashboard and alert writes. SigNoz doesn't document Editor access to saved views or notification channels, so use SigNoz-Admin for those.
- **SigNoz-Admin** adds every write, plus user, role, and service account management in SigNoz.

<ApprovalDefault />

A [Rule](/guide/approvals/rules) can make CloudThinker ask first for a write, or refuse it outright.

<Tip>
Start with SigNoz-Viewer. Move to SigNoz-Editor for dashboard and alert changes, or SigNoz-Admin only when you want agents to manage saved views or channels for you.
</Tip>

## Agent capabilities

| Capability | What agents can do | Approval |
|------------|--------------------|----------|
| **Services** | List instrumented services and rank a service's top operations by latency | No |
| **Logs** | Search logs with filters such as severity, and aggregate them by a field such as service | No |
| **Traces** | Search and aggregate traces, and open a full trace waterfall by trace ID | No |
| **Metrics** | List metrics and run time-series queries | No |
| **Dashboards** | List dashboards and templates, and read a dashboard's full definition | No |
| **Alerts** | List alert rules with their state, and read a rule's state-change history | No |
| **Saved views and channels** | Read saved query views and notification channels | No |
| **Writes** | Create, update, or delete alerts, dashboards, saved views, and notification channels, and import a dashboard from JSON. Needs SigNoz-Editor (dashboards, alerts) or SigNoz-Admin (saved views, channels) | Goes through Approvals |

Log, trace, and metric searches always run over a time window. Agents start with the last 15 minutes and widen it when nothing comes back, so name a window in your prompt if you care about a specific period.

<Warning>
A SigNoz delete can't be undone: a deleted alert loses its history, and deleting a notification channel leaves its routed alerts with nowhere to send. Agents show you the current record before an update or delete, so read it before you approve.
</Warning>

### Verify the connection

```text
List my SigNoz services, dashboards, and alert rules, and tell me which alerts are firing
```

Expect a count and sample of services, dashboards, and alert rules, plus how many alerts are firing now.

### Example prompts

```text
What are the slowest operations for the checkout service over the last hour?
Search ERROR logs from the last 30 minutes and group them by service
Review my SigNoz alert rules and flag any with no notification channel
```

## Troubleshooting

<Accordion title="Every request returns 404">
**SIGNOZ_URL** has a path on the end. Set it to the base URL only, such as `https://<your-tenant>.signoz.cloud`, with no `/api/v1`.
</Accordion>

<Accordion title="401 Unauthorized">
The key is wrong, expired, or revoked. Create a new key on the Service Account's **Keys** tab and update **SIGNOZ_API_KEY**.
</Accordion>

<Accordion title="403 Forbidden">
The Service Account's role doesn't allow the action. A SigNoz-Viewer key returns this on any write. A SigNoz-Editor key may return it on saved view and notification channel writes, since SigNoz doesn't document Editor access to those. Change the role in SigNoz if you want agents to make that change.
</Accordion>

<Accordion title="A log or trace search comes back empty">
Nothing matched in the window searched. Ask for a wider window, such as the last 6 hours, or drop the filter and add it back one clause at a time.
</Accordion>

<Accordion title="429 or 503 errors">
Your SigNoz instance is rate limiting or restarting. Wait a minute and ask again. On self-hosted SigNoz, check the query service's health.
</Accordion>

## Security

<ConnectionSecurity />

- **One Service Account for CloudThinker**: don't reuse a teammate's key. A dedicated account lets you revoke CloudThinker's access without touching anyone else's.
- **Set a key expiration**: rotate the key and update **SIGNOZ_API_KEY** before it lapses, or the connection stops with 401 errors.

Connect FPT Cloud to let CloudThinker agents inspect the VMs, disks, networks, backups, tags, and activity in your VPCs, and change them after approval. The connection uses one **personal access token** and reaches every VPC that the token's user can see, so you don't enter a VPC or an organization.

## Prerequisites

- An FPT Cloud account that signs in to [console.fptcloud.com](https://console.fptcloud.com) with **FPT ID** or your organization's **SSO**.
- At least one VPC assigned to that user. An organization admin assigns VPCs in **IAM**.

<Info>
The token carries the permissions of the user who creates it, in every VPC that user can see. To limit what agents can reach, create the token from a user who has only the VPCs and permissions you want to share. A dedicated FPT Cloud user for CloudThinker works best, so the connection doesn't depend on one person's account.
</Info>

## Setup

<Steps>
  <Step title="Create a personal access token">
    Sign in to the FPT Cloud console and open [**Token**](https://console.fptcloud.com/tokens), near the bottom of the left navigation bar.

    1. Click **Create**.
    2. Enter a **Name**, such as `cloudthinker`.
    3. Select an **Expiration**.
    4. Click **Create**, then copy the full token value.

    FPT Cloud shows the token value only once. If you lose it, delete the token and create a new one.

    When the token expires, the connection switches to **Error**. To swap in a new token, follow [Rotate a credential](/guide/connections/overview#rotate-a-credential).
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar, select **FPT Cloud**, and enter:

    - **Alias**: a short name such as `production`. Leave it blank to use the suggested alias.
    - **Description**: what this connection is for. It defaults to the provider name.
    - **FPT Cloud personal access token**: the token you copied.

    Click **Connect**.

    **Success state:** the connection shows **Connecting** and **Verifying**, then a **Connected** status with a message such as `FPT Cloud connection verified. VPCs: 3.`
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|-------|----------|---------------|
| **Alias** | No | Name for this connection, in lowercase letters, digits, and hyphens (up to 63 characters). Use a different alias for each FPT Cloud connection. |
| **Description** | No | What the connection is for. Defaults to **FPT Cloud**. |
| **FPT Cloud personal access token** | Yes | The token from the FPT Cloud **Token** page. Letters, digits, `.`, `_`, and `-` only, with no spaces or line breaks. |

You can add more than one FPT Cloud connection to a workspace, for example one token per organization. When several are attached, agents pick the connection by its alias.

## Required permissions

A token is not bound to a VPC or an organization. It carries the user's permissions across the FPT Cloud API.

| You want agents to | The token's user needs |
|--------------------|------------------------|
| Pass the connection test | Sign-in access and at least one assigned VPC |
| Read inventory | Access to each VPC you want inspected |
| Make approved changes | The matching permission codes in the table below |

For read-only use, give the token's user a role in **IAM → Roles** that holds only read codes: `instance:List`, `instance:Detail`, `instance:ListSnapshot`, `storage:List`, and `network:List`. The built-in **ORG Super Admin** and **VPC Super Admin** roles grant full administrative rights. Add write codes only for the changes you want agents to make:

| Change | FPT Cloud permission code |
|--------|---------------------------|
| Create a VM | `instance:Create` |
| Power a VM on or off | `instance:StartAndStop` |
| Delete a VM | `instance:Terminate` |
| Create or delete a snapshot | `instance:CreateSnapshot`, `instance:DeleteSnapshot` |
| Resize, attach, detach, or delete a disk | `storage:Resize`, `storage:Attach`, `storage:Detach`, `storage:Delete` |
| Create or delete a network | `network:Create`, `network:Delete` |

These are the codes agents can check. Other reads and changes on this page, such as tags, activity, backups, reboot, rename, clone, NICs, and schedules, follow the rest of the user's role. If an agent reports a permission error on one of them, ask your organization admin to widen the role.

<Tip>
To see what the token holds before you widen it, ask: `Which FPT Cloud permissions does my token have in the production VPC?` Agents check the codes through FPT Cloud IAM.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **VPC discovery** | List the VPCs the token can see, with organization, region, and platform (OpenStack or VMware) |
| **Find a resource** | Look up an IP address or a name across every organization and VPC the token can see |
| **Account-wide scans** | Find stopped VMs, VMs with a public IP, and unattached disks or public IPs across all VPCs in one pass |
| **VMs** | Inventory and detail, flavors, images, storage policies, NICs, and flavors a VM can resize to |
| **Networks** | Subnets, NICs, floating IPs, load balancer backends, and the security groups attached to each VM |
| **Storage and backup** | Disks, volumes, snapshots, snapshot schedules, backup coverage, and restore points |
| **Tags** | Tags, tag coverage, untagged resources, and tag policies |
| **Activity** | Who changed a resource and when, from the VPC activity log |
| **Cost estimates** | List-price estimates from FPT Cloud's unit prices for vCPU, RAM, and disk |
| **Approved changes** | Create, power, reboot, rename, resize, clone, or delete a VM, and manage its disks, NICs, snapshots, schedules, and tags |

Every change goes through [Approvals](/guide/approvals/overview) first, and agents name the exact VM ID and name they will touch. When the token can see several VPCs, the agent asks which one to use instead of guessing.

<Note>
Agents can't create Kubernetes clusters or databases, can't read security group rules or ports, and have no historical CPU or memory usage to right-size from. Cost figures are list-price estimates, not invoice amounts. FPT Cloud's price list states no currency, so agents show the figure without one and name the unit prices they used: vCPU, RAM per GB, and disk per GB, with monthly figures at 720 hours. Read it in the currency of your FPT Cloud invoice.
</Note>

### Verify the connection

```text
List the VPCs my FPT Cloud token can see, with the number of VMs in each
```

Expect each VPC with its organization, region, platform, and VM count.

### Example prompts

```text
Which FPT Cloud VMs have a public IP, and which security groups do they use?
List unattached disks and public IPs across all my VPCs with their estimated monthly list price
Reboot the VM web-01 in the production VPC, and show me the exact VM ID first
```

## Troubleshooting

<Accordion title="FPT Cloud personal access token is required">
The token field is empty, or the pasted value has a space, a line break, or another unsupported character. Copy the full token again, then test the connection.
</Accordion>

<Accordion title="FPT Cloud rejected the personal access token">
The token expired, was deleted, or was not copied in full. On the FPT Cloud **Token** page, check that the token is **Active**. If not, create a new token and update the connection.
</Accordion>

<Accordion title="FPT Cloud token lacks permission to list its VPCs">
FPT Cloud refused to list the user's VPCs. Ask your organization admin to check the user's role in **IAM**, then test again.
</Accordion>

<Accordion title="FPT Cloud token has no assigned VPC">
The token's user has no VPC. Ask an organization admin to assign one in **IAM**, or create the token from a user who has one.
</Accordion>

<Accordion title="FPT Cloud rate limit reached, or FPT Cloud is temporarily unavailable">
FPT Cloud is limiting requests or returned a server error. Wait a few minutes, then test the connection again.
</Accordion>

<Accordion title="FPT Cloud could not be reached from the executor">
The executor is the CloudThinker cloud runner that sends requests to FPT Cloud, and it could not open a connection. Retry. If it keeps failing and your FPT Cloud setup restricts API access by IP, allowlist CloudThinker's egress IPs. See [Reaching private services](/guide/connections/overview#reaching-private-services).
</Accordion>

<Accordion title="The agent says a change is pending">
FPT Cloud accepted the request, but a fresh read hasn't confirmed the result yet. Ask the agent to check the VM's current state before you retry, so the change doesn't run twice.
</Accordion>

## Security

<ConnectionSecurity />

- **Set a short expiration**: pick the shortest **Expiration** that fits, and create a new token before the old one expires.
- **Delete the token to revoke access**: deleting it on the FPT Cloud **Token** page stops all access through this connection.

Connect Check Point so CloudThinker can review gateways, policy packages, and access rules. The connection uses a dedicated API credential, with access limited by the account behind it.

## Prerequisites

- Access to the Check Point account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create an administrator account with API key authentication in SmartConsole. Copy its API key and enter the management server address, with the domain or Smart-1 context when applicable.

    See the [Check Point documentation](https://sc1.checkpoint.com/documents/R81.20/WebAdminGuides/EN/CP_R81.20_SecurityManagement_AdminGuide/Content/Topics-SECMG/Configuring_Authentication_through_an_API_Key.htm) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Check Point**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Management server URL** | Yes | Use the management server url prepared in the credential step. |
| **Smart-1 Cloud context** | Yes | Smart-1 Cloud only: the path segment before /web_api in the API URL shown in the Infinity Portal. Leave empty for an on-premises server. |
| **API key** | Yes | Use the api key prepared in the credential step. |
| **Domain** | Yes | Multi-Domain Server only: the domain name to read. Leave empty for a single-domain server or Smart-1 Cloud. |
| **TLS certificate** | Yes | Enter the tls certificate for this connection. Options: Verify SSL certificate, Skip SSL verification. Default: true. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

Use a read-only management permission profile for gateways, packages, objects, and rules. Do not grant policy-install or object-write privileges for inspection.

<Tip>
Start with read access to the smallest useful scope. This guide covers investigation; broad administrative or write access is unnecessary for these reads.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Gateways and management servers** | Review gateways, policy packages, and access rules. |
| **Access rules and policy packages** | Inspect access rules and policy packages within the connected account’s scope. |
| **Rule configuration and hit information** | Inspect rule configuration and hit information within the connected account’s scope. |

Smart-1 Cloud needs its service context. Multi-Domain Server needs the intended domain; those values are not interchangeable.

The connection reads the supported information without changing it. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Check Point connection, summarize its account or service scope and gateways and management servers. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize gateways and management servers in Check Point and highlight items needing attention.
Review access rules and policy packages and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

<ConnectionSecurity />

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

Connect MuleSoft Anypoint Platform so CloudThinker can inspect apps, deployments, logs, and API policies. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing MuleSoft Anypoint Platform account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Register an Anypoint Connected App that acts on its own behalf, using the client credentials grant. See the [vendor's authentication documentation](https://docs.mulesoft.com/access-management/connected-apps-overview) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **MuleSoft Anypoint Platform**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Select the Anypoint region that hosts your account. The client ID and secret must belong to the same Connected App.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Region** | Yes | Select the region where your account is hosted. Options: **US**, **EU**, **Government Cloud**. Default: `https://anypoint.mulesoft.com`. |
| **Connected App client ID** | Yes | A Connected App acting on its own behalf. Grant organization and Connected App reads, Runtime Manager reads and actions, and API Manager reads in the required business groups and environments. |
| **Connected App client secret** | Yes | The secret of that Connected App. Recovery actions require approval through the connection's write tool. |

## Required permissions

Grant organization and Connected App reads, Runtime Manager access, and API Manager reads in the intended business groups and environments.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Deployment review | Inspect applications and deployments. |
| Operational context | Read logs and API policies. |
| Recovery actions | Request supported application actions after approval. |

Application recovery actions can affect service availability or capacity. Reads precede every requested action and changes require approval.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my MuleSoft Anypoint Platform connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use MuleSoft Anypoint Platform to inspect apps, deployments, logs, and API policies.
Summarize the highest-priority items visible through my MuleSoft Anypoint Platform connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in MuleSoft Anypoint Platform. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in MuleSoft Anypoint Platform when access is no longer needed, and update the connection after rotation.

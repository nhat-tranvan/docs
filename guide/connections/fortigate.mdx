Connect a FortiGate firewall and CloudThinker agents can report device health, license expiry, and interface traffic, review policies and routes, and make configuration changes you approve. The connection uses a FortiGate **REST API token** (a token tied to a dedicated API administrator), and CloudThinker must be able to reach the FortiGate's management interface over HTTPS.

## Prerequisites

- A FortiGate whose HTTPS management interface CloudThinker can reach from the internet, or through a firewall rule you open for it.
- A FortiGate administrator with the **super_admin** profile. Only that profile can create a REST API administrator.
- Edit permission on connections in your CloudThinker workspace.

## Setup

<Steps>
  <Step title="Create an administrator profile">
    In FortiGate, go to **System → Admin Profiles** and click **Create New**. Name it `cloudthinker` and set every permission to **Read**.

    Set **Read/Write** only on the areas you want agents to change, such as **Firewall**. See [Required permissions](#required-permissions).
  </Step>
  <Step title="Create a REST API administrator">
    Go to **System → Administrators** and click **Create New → REST API Admin**. Fill in:
    - **Username**: `cloudthinker`
    - **Administrator Profile**: the `cloudthinker` profile
    - **PKI Group**: leave empty
    - **Trusted Hosts**: optional. To restrict the token to CloudThinker, add CloudThinker's egress IP addresses (ask your CloudThinker contact for the current list).

    Click **OK** and copy the token. FortiGate shows it only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    In the sidebar, click **More → Workspace settings → Connections**. On the **Builtin Connections** tab, search for **FortiGate** and click **Connect**. Fill in the fields from [Connection details](#connection-details) and click **Connect**.

    CloudThinker tests the token by reading the FortiGate's system status.

    **Success state:** the test message reads `FortiGate connection verified` and the connection shows **Connected**.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **FORTIGATE_HOST** | FortiGate address or hostname, without `https://` or a port | `fw.example.com` |
| **FORTIGATE_PORT** | HTTPS management port. Default `443` | `443` |
| **FORTIGATE_API_TOKEN** | The REST API administrator token | `<your-api-token>` |
| **FORTIGATE_VDOM** | Virtual domain (VDOM) agents work in. Default `root` | `root` |
| **FORTIGATE_VERIFY_SSL** | **Skip SSL verification** (default, for FortiGate's built-in self-signed certificate) or **Verify SSL certificate** (for a trusted CA-signed certificate) | **Verify SSL certificate** |

Agents only see the VDOM you enter. To cover several VDOMs, add one connection per VDOM.

## Required permissions

The token has exactly the permissions of its administrator profile.

| Goal | Profile access |
|------|----------------|
| Read device health, licenses, traffic, and configuration | **Read** on every area |
| Change configuration objects, such as firewall addresses or policies | **Read/Write** on only those areas |

<Tip>
Start with **Read** everywhere. Add **Read/Write** to one area when a workflow needs it, and leave **System** and **Network** read-only so agents can't touch administrator or interface settings.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **Device overview** | Report hostname, model, serial number, firmware version, and uptime |
| **License health** | Show license and subscription status and expiry dates |
| **Interface traffic** | Rank interfaces by transmitted and received traffic, with bandwidth |
| **Configuration review** | Read firewall policies, addresses, routes, VPN settings, and other configuration |
| **Configuration changes** | Create, update, or delete one configuration object per request |

Reads run without asking. Every configuration change is a write that needs approval: the agent states the exact object and change, and you approve each object on its own before it runs. See [Approvals](/guide/approvals/overview). Agents can only write configuration objects, never run commands on the device.

<Warning>
Changing administrator or interface settings can lock you out of the FortiGate or open the firewall. Read the exact object and change in the approval card before you approve it.
</Warning>

### Verify the connection

```text
Summarize my FortiGate: model, firmware version, license status, and the five busiest interfaces
```

A working connection returns your device's model and serial number and lists named interfaces such as `wan1`. A `401` error means the token was rejected: see Troubleshooting.

### Example prompts

```text
Check which FortiGate licenses and subscriptions expire in the next 90 days
Show interface traffic on the FortiGate and flag any interface close to saturation
List the firewall address objects on the FortiGate and flag any that no policy uses
Create a firewall address object named blocklist-203.0.113.7 for 203.0.113.7/32
```

## Troubleshooting

<Accordion title='The test fails with "returned error: 401"'>
The token was rejected. Check that you copied the whole token, that **PKI Group** is empty on the REST API administrator, and that **Trusted Hosts** (if set) includes CloudThinker's addresses.
</Accordion>

<Accordion title='The test fails with "Failed to connect" or "Could not resolve host"'>
CloudThinker couldn't reach the FortiGate. Check **FORTIGATE_HOST** and **FORTIGATE_PORT**, and that the management interface accepts HTTPS from CloudThinker.
</Accordion>

<Accordion title="SSL certificate problem">
The FortiGate's certificate isn't trusted. Install a CA-signed certificate on the FortiGate, or set **FORTIGATE_VERIFY_SSL** to **Skip SSL verification**.
</Accordion>

<Accordion title="Invalid FortiGate connection configuration">
**FORTIGATE_HOST** or **FORTIGATE_API_TOKEN** is empty. Fill in both and connect again.
</Accordion>

<Accordion title="Connected, but objects are missing">
Agents only see the VDOM in **FORTIGATE_VDOM**. Set it to the VDOM that holds the objects, or add a second connection for that VDOM.
</Accordion>

<Accordion title="A configuration change fails with HTTP 403">
The administrator profile doesn't allow that change. Give the profile **Read/Write** on that area, or make the change in FortiGate yourself.
</Accordion>

## Security

<ConnectionSecurity />

- **Restrict trusted hosts.** Limit the REST API administrator to CloudThinker's egress addresses so a leaked token is useless elsewhere.
- **Verify the certificate.** Use **Verify SSL certificate** once the FortiGate has a trusted certificate.
- **Token stays redacted.** CloudThinker injects the token at run time and redacts it from command output, so it doesn't appear in chat.

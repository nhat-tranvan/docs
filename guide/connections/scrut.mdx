Connect Scrut so CloudThinker can track framework progress, failing tests, and controls. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Scrut account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    As an Org Admin, create a Scrut API credential in the Developer Console with Read Only access. Copy its client ID and client secret. See the [vendor's authentication documentation](https://developer.scrut.io/authentication-and-access-tokens) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Scrut**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose the API region matching your Scrut organization. Token requests and data requests use that same region.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Region** | Yes | Match the app URL you sign in to: app.scrut.io is India, app.us.scrut.io is US. Options: **India**, **United States**, **Europe**, **Australia**. Default: `https://api.scrut.io`. |
| **Client ID** | Yes | Enter client id. |
| **Client secret** | Yes | Enter client secret. |

## Required permissions

Read frameworks, tests, controls, and their mapped compliance data.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Framework readiness | Inspect framework progress. |
| Test review | Read failing tests. |
| Control context | Inspect mapped controls and compliance data. |

The connection is read-only. It cannot remediate tests, upload evidence, or update vulnerabilities.

This connection is read-only. Make changes in Scrut.

### Verify the connection

```text
Inspect my Scrut connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Scrut to track framework progress, failing tests, and controls.
Summarize the highest-priority items visible through my Scrut connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Scrut. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Scrut when access is no longer needed, and update the connection after rotation.

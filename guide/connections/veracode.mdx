Connect Veracode so CloudThinker can review applications, policy status, and scan findings. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Veracode account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create Veracode HMAC credentials for an API service account and save its API ID and secret key. See the [vendor's authentication documentation](https://docs.veracode.com/r/c_api_credentials3) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Veracode**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Select the Veracode region where the credentials were created. The connection signs API requests with the HMAC key.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Veracode region** | Yes | Options: **Commercial (US)**, **European (EU)**, **US Federal (FedRAMP)**. Default: `api.veracode.com`. |
| **API ID** | Yes | Enter api id. |
| **API secret key** | Yes | Shown once with the API ID. The account needs the Results API role. |

## Required permissions

The account needs access to application results through the Results API.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Application inventory | Read application profiles and scan history. |
| Policy status | Inspect policy compliance. |
| Finding triage | Read application findings. |

The connection is read-only. It cannot submit mitigation proposals, add comments, edit policy, or start scans.

This connection is read-only. Make changes in Veracode.

### Verify the connection

```text
Inspect my Veracode connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Veracode to review applications, policy status, and scan findings.
Summarize the highest-priority items visible through my Veracode connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Veracode. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Veracode when access is no longer needed, and update the connection after rotation.

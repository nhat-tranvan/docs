Connect Firebase so CloudThinker can list your projects and apps, read SDK configuration, audit Firestore, Storage, and Realtime Database security rules, and check deploy state. Firebase authenticates with a **Google Cloud service-account key** (a JSON file), and the service account's IAM roles decide what CloudThinker can reach.

## Prerequisites

- A Firebase project you want CloudThinker to inspect.
- Permission in that project's Google Cloud to create service-account keys and assign IAM roles.

## Setup

<Steps>
  <Step title="Generate a service-account key">
    In the [Firebase console](https://console.firebase.google.com), open your project and click the gear icon to open **Project settings**. On the **Service accounts** tab, click **Generate new private key**, then **Generate key**.

    **Success state:** your browser downloads a `.json` key file.
  </Step>
  <Step title="Trim the service account's roles">
    In **Google Cloud console → IAM**, give the service account only what you need: a viewer-level Firebase role for inventory and rule audits. Add a Firebase admin role only if you want CloudThinker to create apps or deploy after your approval.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Go to **Connections → Firebase**. Drag the `.json` file onto the upload area, or click the link in the upload area to browse for it. Click **Connect**.

    **Success state:** the connection shows **Connecting** and **Verifying**, then a **Connected** status. CloudThinker reads `project_id` from the key and makes that the active project.
  </Step>
</Steps>

<Warning>
The JSON key is a full credential for the service account. Store it in a secret manager and delete the local copy once it's uploaded.
</Warning>

## Connection details

| Field | What to enter | Example |
|-------|---------------|---------|
| **GOOGLE_SERVICE_ACCOUNT_KEY** | The full service-account key JSON. Its `project_id` sets the active Firebase project. | `{ "type": "service_account", "project_id": "my-app", ... }` |

You don't need a separate project ID or a Firebase config file.

## Required permissions

| What you want | IAM role on the service account | Approval in CloudThinker |
|---------------|---------------------------------|--------------------------|
| Inventory projects and apps, read SDK config, audit security rules | Viewer-level Firebase role | Not needed |
| Switch the active project, create projects, apps, or Android SHA keys, initialize features, deploy, check deploy status | A Firebase role that allows the action | Required for every call |

<Tip>
Grant a read-only role for audits and keep the [Approvals](/guide/approvals/overview) guardrail on for writes. An action only runs when the IAM role allows it and you approve it.
</Tip>

## Agent capabilities

CloudThinker uses the official Firebase CLI (`firebase-tools`) toolset through this connection.

| Capability | What CloudThinker does | Approval |
|------------|------------------------|----------|
| **Projects and apps** | Lists accessible projects, inspects the active project, lists iOS, Android, and web apps | No |
| **SDK configuration** | Reads the Firebase SDK config for an app | No |
| **Security rules audit** | Reads Firestore, Storage, and Realtime Database rules and flags rules that look open | No |
| **Firebase docs** | Searches Firebase and Google developer documentation | No |
| **Project and app controls** | Switches the active project, creates projects, apps, and Android SHA keys, initializes features, deploys, checks deploy status | Yes |

The connection covers what `firebase-tools` exposes. It doesn't read Firestore documents, Authentication users, Crashlytics, or Remote Config.

### Verify the connection

```text
Show my Firebase environment and list the projects you can access
```

### Example prompts

```text
Audit the Firestore and Storage security rules and flag anything that allows unauthenticated writes
List the apps registered in the active Firebase project as a table
Show the Firebase SDK config for my web app
```

## Troubleshooting

<Accordion title="Authentication failed or credentials unavailable">
The key JSON is invalid, incomplete, or belongs to a deleted service account. Generate a new private key in the Firebase console, upload it on the connection, and test again.
</Accordion>

<Accordion title="CloudThinker says no active project is selected">
The error reads `PRECONDITION_FAILED` and mentions the active project. It means no project is selected, not that the resource is missing. Name the project in your prompt. Switching the active project asks for your approval.
</Accordion>

<Accordion title="Permission denied on a project, rules, or deploy">
The service account lacks the IAM role for that Firebase product, or the project isn't visible to it. Grant the role in **Google Cloud console → IAM** and retry.
</Accordion>

<Accordion title="A create or deploy action didn't run">
Writes need both an IAM role that allows them and your approval in CloudThinker. If you rejected the request, CloudThinker won't retry it. Ask again when you're ready, and check the service account's roles.
</Accordion>

## Security

<ConnectionSecurity />

- **Keep writes approval-gated**: create, initialize, and deploy actions should stay behind approval rather than lose the guardrail.
- **Protect the key**: never commit the service-account JSON to source control or paste it into chat.

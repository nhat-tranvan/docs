Connect your Flespi account so [CloudThinker](/guide/agents/overview) can answer questions about your telematics fleet: which devices stopped reporting, what a device sent in the last day, whether a channel is receiving data, and whether streams are delivering it. Flespi is a telematics backend that receives data from GPS trackers and other IoT devices. CloudThinker talks to Flespi's own hosted MCP server, signed in with one **Flespi token** you create.

## Supported platforms

| Platform | Supported | Notes |
|----------|-----------|-------|
| **Flespi cloud** (flespi.io) | Yes | CloudThinker calls Flespi's hosted MCP server at `https://flespi.io/ai/mcp/develop`. The address is fixed, so your data flows from Flespi's MCP server to CloudThinker, and no other Flespi endpoint can be set |

## Prerequisites

- A Flespi account with access to the Flespi panel at [flespi.io](https://flespi.io/#/).
- Permission to create tokens in that account.

## Choose a token type

| Token type | Access | Use it for |
|------------|--------|------------|
| **ACL** | Nothing until you grant it, per module and method | Production. Recommended |
| **Standard** | Full read and write on your telematics entities | Short-lived testing only |
| **Master** | Full account administration | Never with CloudThinker |

For a read-only ACL token, grant **GET** on each module agents should see:

| ACL module | Method | Unlocks |
|------------|--------|---------|
| `gw/devices` | GET | Devices and Telemetry: device list, last report time, and device messages |
| `gw/channels` | GET | Channels: settings, protocols, and incoming data |
| `gw/streams` | GET | Streams: status and delivery |
| `gw/geofences` | GET | Geofences |
| `gw/calcs` | GET | Calculators, such as trip detection |

Leave out any module agents don't need. Grant write methods (POST, PUT, DELETE) only if you want agents to change things. See [Write access](#write-access).

<Info>
ACL tokens deny by default, and permissions don't imply each other. Write access on devices doesn't include read on devices unless you grant read too.
</Info>

## Setup

<Steps>
  <Step title="Create a token in Flespi">
    In the Flespi panel, open **Tokens** in the left menu and click **+**. Set:

    - **Name**: `CloudThinker`
    - **Type**: **ACL**. In the ACL editor, add one entry per module from the [ACL table](#choose-a-token-type) and allow the **GET** method on each
    - **Expiration**: Flespi requires every token to have a TTL or an expiration date. Use a 90-day inactivity TTL. It resets on every call, so a token in active use stays valid, and an idle one is cleaned up

    Save the token and copy its value.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **More → Workspace settings → Connections**, stay on the **Builtin Connections** tab, and select **Flespi**. Paste the token into **FLESPI_TOKEN**. Paste only the token value, without a `FlespiToken` prefix. CloudThinker adds that header itself.

    Click **Connect**.

    **Success state:** the connection shows **Connecting** and **Verifying**, then **Connected**. If verification fails, it shows **Failed** and an error message appears. Match the message to [Troubleshooting](#troubleshooting).
  </Step>
</Steps>

## Connection details

| Field | Required | Description |
|-------|----------|-------------|
| **FLESPI_TOKEN** | Yes | A Flespi ACL or Standard token. CloudThinker sends it to Flespi's MCP server as `Authorization: FlespiToken <token>` |

## Agent capabilities

What agents can do depends on what the token allows:

| Capability | What agents can do | Needs ACL |
|------------|--------------------|-----------|
| **Devices** | List devices, check when each last reported, and read a device's recent messages | `gw/devices` GET |
| **Telemetry** | Pull position, speed, and sensor values from device messages over a time range | `gw/devices` GET |
| **Channels** | Inspect channel settings and protocols, and whether a channel is receiving data | `gw/channels` GET |
| **Streams** | Check stream status and delivery to your downstream systems | `gw/streams` GET |
| **Geofences and calculators** | Read geofence zones and calculator setups such as trip detection | `gw/geofences` GET, `gw/calcs` GET |

Some of Flespi's AI-assisted tools, such as searching Flespi documentation, draw on your Flespi account's AI usage allowance. Check the **AI** tile in the Flespi panel if you rely on them. Plain device, channel, and stream reads don't.

### Verify the connection

```text
List my Flespi devices and when each one last reported
```

Expect a list of device names or IDs with a last-message time for each. A device the token can't read won't appear.

### Example prompts

```text
Which Flespi devices haven't sent a message in the last 6 hours?
Show the messages from device 12345 over the last 24 hours and flag any gaps
Are all my Flespi streams delivering, and which ones have errors?
```

## Write access

A read-only ACL token is the recommended setup, and Flespi refuses any write it doesn't permit. If you grant write methods, each write an agent attempts goes through [Approvals](/guide/approvals/overview). Your Rules and Approval mode decide whether it runs, waits for a person, or is refused. Reads never need approval.

## Troubleshooting

<Accordion title="Invalid or expired token">
Flespi deletes a token when it expires. Check the token's TTL in the Flespi panel, create a new one if it's gone, and update **FLESPI_TOKEN** on the connection.
</Accordion>

<Accordion title="Action is not permitted by ACL">
The ACL token lacks the module and method for that request. Add the permission to the token in the Flespi panel. Remember that read and write are granted separately.
</Accordion>

<Accordion title="Using token from unauthorized location">
The token has an IP allowlist that doesn't include CloudThinker. Add CloudThinker's egress IPs to the token's IP whitelist in the Flespi panel (ask your CloudThinker contact for the current list), or remove the restriction.
</Accordion>

<Accordion title="HTTP 429 rate limit">
Flespi limits usage per minute across API, MQTT, and traffic on your account. Ask for narrower ranges or fewer devices at once, or wait a minute and retry.
</Accordion>

<Accordion title="AI-assisted lookups are refused">
Your Flespi AI allowance for the month is used up. Device, channel, and stream reads keep working. Check the **AI** tile in the Flespi panel for your usage.
</Accordion>

## Security

<ConnectionSecurity />

- **One token for CloudThinker**: don't share it with other integrations, so you can revoke it on its own.
- **Never a Master token**: use ACL with only the modules and methods agents need.
- **Keep the 90-day inactivity TTL**: a token in use stays valid. If the connection sits idle that long, Flespi deletes the token and you'll need a new one. Rotate it on your usual credential schedule as well.

Connect Automox so CloudThinker can check device patch status, pending patches, and policies. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Automox account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create an Automox API key for a user who can view the target organization's devices and policies. See the [vendor's authentication documentation](https://docs.automox.com/product/Developer/Developer_LP.htm) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Automox**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Copy the numeric organization ID from the `o=` parameter of the Automox console URL.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Automox console** | Yes | Options: **console.automox.com**. Default: `https://console.automox.com`. |
| **API key** | Yes | The key acts as its user, so that user must see devices and policies in this organization. |
| **Organization ID** | Yes | The number after o= in the console URL, for example 1234 in https://console.automox.com/dashboard?o=1234. |

## Required permissions

Read device inventory, pending patches, policy schedules, and compliance in the specified organization.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Device inventory | Read devices and last-seen information. |
| Pending patches | Inspect patches for a selected device. |
| Policy coverage | Review schedules and compliance. |

The connection is read-only. It cannot patch, reboot, execute policies, or modify device groups.

This connection is read-only. Make changes in Automox.

### Verify the connection

```text
Inspect my Automox connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Automox to check device patch status, pending patches, and policies.
Summarize the highest-priority items visible through my Automox connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Automox. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Automox when access is no longer needed, and update the connection after rotation.

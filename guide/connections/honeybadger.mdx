Connect Honeybadger so CloudThinker can investigate faults, uptime outages, check-ins, and deploys. Authorize your account with OAuth.

## Prerequisites

- An existing Honeybadger account or deployment containing the resources you want to inspect.
- Permission to authorize an integration for the account you want CloudThinker to use.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Open the connection">
    Open **Settings → Connections**, find **Honeybadger**, and click **Connect**.
  </Step>
  <Step title="Authorize the account">
    Authorize your Honeybadger account in CloudThinker's sign-in window. There is no API key field. Sign in with the account whose resources CloudThinker should reach and review the access request.
  </Step>
  <Step title="Verify access">
    Return to CloudThinker and wait for the connection check. This connector uses the US Honeybadger endpoint; EU accounts are not supported by this connection.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check the resources it can read.
  </Step>
</Steps>

## Connection details

There are no credentials to paste. CloudThinker stores the authorization returned when you connect. Reconnect to replace that authorization.

## Required permissions

The OAuth account must be allowed to read the chosen projects. Choose read-write access only if you need supported changes.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Fault triage | Inspect faults, notices, comments, and deploy context. |
| Monitor health | Read uptime, check-ins, and Insights alarms. |
| Response changes | Update supported fault and monitor records after approval. |

Read-only authorization hides write tools. Changing faults, comments, check-ins, uptime sites, alarms, and dashboards requires write access and approval.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Honeybadger connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Honeybadger to investigate faults, uptime outages, check-ins, and deploys.
Summarize the highest-priority items visible through my Honeybadger connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. For OAuth, repeat authorization with the intended account. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Honeybadger. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. If authorization does not open, allow the sign-in window and reconnect with the intended account.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Honeybadger when access is no longer needed, and update the connection after rotation.

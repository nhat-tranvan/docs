Connect Varonis so CloudThinker can investigate data-security alerts, threat models, and associated events. The connection uses a Varonis SaaS API key.

## Prerequisites

- Access to the Varonis account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your Varonis administrator for a dedicated SaaS API key permitted to read the threat models and alerts you want investigated. Obtain the exact HTTPS address of that Varonis SaaS console. Keep the key within the connection form; do not paste it into a conversation.

    See the [provider documentation](https://help.varonis.com/) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Varonis**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Varonis URL** | Address of the Varonis SaaS console. | https://acme.varonis.io |
| **API key** | Dedicated API key with the intended alert permissions. | Enter in the connection form |

## Required permissions

Start with read access to alerts, associated events, and threat models. Alert updates and notes need the corresponding additional permissions. Your Varonis administrator should confirm the key’s available operations for your tenant; do not assume every API key can update alerts.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Alert queue** | Review open alerts by severity, threat model, and status. |
| **Alert evidence** | Inspect one alert’s associated events and user, device, or asset context. |
| **Threat models** | Review the visible threat models behind the alert queue. |

The connection cannot change threat models, policies, permissions, or remediation settings. Search results are bounded. An incomplete or failed search does not mean no alerts exist, and an uncertain update must be checked before retrying.

Supported alert status changes, closing or reopening, and notes go through [Approvals](/guide/approvals/overview). Identify the exact alert and desired action. A submitted note may be accepted without being readable afterward; report it as accepted rather than independently verified.

### Verify the connection

```text
Summarize visible Varonis threat models and open alerts, reporting the search window and any incomplete reads
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Investigate the selected high-severity Varonis alert and summarize its associated events
Group recent open alerts by threat model and identify affected users or assets
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="The key is accepted but some alerts cannot be read">
Ask the Varonis administrator to confirm alert, event, and threat-model access for the key. Reduce the investigation window if a large search takes too long to complete.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

Connect Anchore Enterprise so CloudThinker can review container image analysis, vulnerabilities, and scan subscriptions. The connection uses an API key for an Anchore account user.

## Prerequisites

- Access to the Anchore Enterprise account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to the provider API. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services). Access through your browser or local SSH tunnel alone is insufficient.

## Setup

<Steps>
  <Step title="Prepare access">
    Sign in as the dedicated Anchore user. Open the top-right account menu, select **API Keys**, and choose **Create New API Key**. Give the key a name and expiry, save it, and copy the displayed value. Keep the Enterprise address and any private CA certificate with it.

    See the [provider documentation](https://docs.anchore.com/current/docs/configuration/user_management/ui/) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Anchore Enterprise**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Enterprise URL** | HTTPS address of Anchore Enterprise, without /v2. | https://anchore.example.com |
| **API key** | Key for the dedicated Anchore user. | Copy from Anchore |
| **CA certificate (optional)** | PEM of the private issuing CA; leave empty for public trust. | Leave empty for public trust |

## Required permissions

Give the user access to read images, analysis, vulnerability findings, and subscriptions in the intended account. Add rights to submit analysis and manage subscriptions only if those operations are needed. Account visibility limits what the connection can report.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Image analysis** | List images, analysis states, and timestamps. |
| **Vulnerabilities** | Investigate findings for a known image digest. |
| **Subscriptions** | Inspect targets and active states. |

Incomplete analysis does not mean an image has no vulnerabilities. Results are bounded samples. Policy administration, image deletion, and registry credential management are not part of this connection.

Agents can submit image analysis and create, activate, deactivate, or delete scan subscriptions through [Approvals](/guide/approvals/overview). Name the exact image or subscription and requested change. Submitted analysis is queued work, not proof that a scan completed.

### Verify the connection

```text
Summarize Anchore image analysis states and inactive scan subscriptions, identifying any failed reads
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Show the highest-severity vulnerabilities for the selected Anchore image digest
List inactive subscriptions and their exact image targets
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Private certificate is rejected">
Check Enterprise URL uses the certificate’s hostname. Paste the complete issuing CA certificate into CA certificate (optional); do not replace it with an API key or disable verification.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

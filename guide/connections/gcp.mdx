CloudThinker runs the Google Cloud CLI against your projects to answer questions about compute, GKE, BigQuery, storage, identity, and cost. You connect with a service account's JSON key, and that service account's IAM roles decide what agents can reach.

## Prerequisites

- A Google Cloud project where you can create service accounts and grant IAM roles.
- Permission to create service account keys. If your organization enforces the `iam.disableServiceAccountKeyCreation` policy, ask an organization admin for an exception on this project first.
- For cost questions and [Optimize](/guide/cost-optimization/overview): a Cloud Billing **Standard usage cost** export to BigQuery. The export dataset must be in the same project as the service account, because Optimize only reads billing tables in the connected project.

## Setup

Create the service account in Google Cloud first, then upload its key to CloudThinker.

<Tabs>
  <Tab title="Google Cloud console">
    <Steps>
      <Step title="Create the service account">
        In the [Google Cloud console](https://console.cloud.google.com/), select the project and go to **IAM & Admin → Service Accounts**. Click **Create service account**, name it `cloudthinker-readonly`, and click **Create and continue**.
      </Step>
      <Step title="Grant read-only roles">
        Add **Viewer** (`roles/viewer`). For Optimize, also add **BigQuery Data Viewer** (`roles/bigquery.dataViewer`) and **BigQuery Job User** (`roles/bigquery.jobUser`). Click **Done**.
      </Step>
      <Step title="Create a JSON key">
        Open the service account, go to the **Keys** tab, and click **Add key → Create new key**. Choose **JSON** and click **Create**. The key file downloads once and can't be downloaded again.
      </Step>
    </Steps>
  </Tab>
  <Tab title="gcloud CLI">
    Run these in [Cloud Shell](https://shell.cloud.google.com/) or any terminal signed in to Google Cloud. Replace `PROJECT_ID` with your project ID.

    ```bash
    PROJECT_ID=your-project-id
    SA=cloudthinker-readonly@$PROJECT_ID.iam.gserviceaccount.com

    gcloud iam service-accounts create cloudthinker-readonly \
      --project="$PROJECT_ID" --display-name="CloudThinker read-only"

    for ROLE in roles/viewer roles/bigquery.dataViewer roles/bigquery.jobUser; do
      gcloud projects add-iam-policy-binding "$PROJECT_ID" \
        --member="serviceAccount:$SA" --role="$ROLE"
    done

    gcloud iam service-accounts keys create cloudthinker-key.json --iam-account="$SA"
    ```

    The last command writes the key to `cloudthinker-key.json`. Drop the two BigQuery roles if you don't use Optimize.
  </Tab>
</Tabs>

Then connect it in CloudThinker:

<Steps>
  <Step title="Open the connect dialog">
    In the sidebar, click **More → Workspace settings → Connections**, select **Google Cloud Platform**, and click **Connect**.
  </Step>
  <Step title="Name the project">
    Fill in **Alias** (for example `prod-gcp`) and **Description** (for example `Production GCP project, GKE workloads`). Agents read the description to pick the right connection when you have several.
  </Step>
  <Step title="Upload the key and pick a region">
    Drag the JSON key file into **GOOGLE_SERVICE_ACCOUNT_KEY**, or click to browse for it. Pick your main region in **GCP_DEFAULT_REGION**, for example `us-central1`. Click **Connect**.

    **Success state:** the status moves through **Connecting** and **Verifying**, and the project shows a **Connected** status.
  </Step>
</Steps>

### Connect more projects

You have two options:

| Option | How | Best when |
|---|---|---|
| One service account, many projects | Grant the same roles to the service account in each project, or once on a folder or the organization | You want one connection that can look across projects |
| One connection per project | Repeat the setup in each project and click **Connect** again on **Google Cloud Platform** with a new alias | Projects belong to different teams, or each has its own billing export |

Optimize reads billing only from the project the key belongs to (its `project_id`), whichever option you pick.

## Connection details

| Field | Description | Example |
|---|---|---|
| **Alias** | Short name for this connection. Blank picks one for you. | `prod-gcp` |
| **Description** | What the project is. Agents use it to choose between connections. | `Production GCP project` |
| **GOOGLE_SERVICE_ACCOUNT_KEY** | The service account's JSON key file, uploaded | `cloudthinker-key.json` |
| **GCP_DEFAULT_REGION** | Starting region for agent commands | `us-central1` |

The key file is JSON with fields such as `type`, `project_id`, `private_key`, and `client_email`. Upload it unchanged.

After connecting, set **Environment** (**Production**, **Staging**, **Development**, or **Not set**) in **Edit Instance** so [approval rules](/guide/approvals/rules) can treat projects differently. **Not set** counts as production.

## Required permissions

| You want | Role | Grant on |
|---|---|---|
| Inventory, health, and IAM questions | Viewer (`roles/viewer`) | Each project, or a folder or organization |
| Optimize cost data | BigQuery Data Viewer (`roles/bigquery.dataViewer`) | The billing export dataset (or the project) |
| Optimize cost queries | BigQuery Job User (`roles/bigquery.jobUser`) | The connected project |
| Agents to make specific changes | Only the narrow roles for those changes | Where the change happens. See [Write access](#write-access). |

<Tip>
**Viewer** can't change anything, so it's a safe starting point. Granting BigQuery Data Viewer on the billing export dataset instead of the whole project keeps agents out of your other BigQuery data.
</Tip>

## Agent capabilities

| Area | What CloudThinker does |
|---|---|
| **Inventory** | Lists and describes Compute Engine, GKE, Cloud Storage, BigQuery, and other resources across the projects the service account can see |
| **Identity** | Reviews IAM bindings and service accounts for broad or unused access |
| **Containers** | Checks GKE cluster and node pool configuration and health |
| **Cost** | Reads your BigQuery billing export to break down spend by project, service, and label. Feeds [Optimize](/guide/cost-optimization/overview). |
| **Changes** | Runs Google Cloud CLI writes only when **Allow writes** is on, the service account permits them, and your approval settings allow them |

### Verify the connection

```text
Which Google Cloud projects can you reach through my GCP connection, and which services are enabled in each?
```

The answer lists your real project IDs.

### Example prompts

```text
List Compute Engine instances that have been stopped for more than 30 days and the disks still attached to them
Find service accounts with the Owner or Editor role in my projects
Break down last month's Google Cloud spend by project and service
```

## Write access

**Allow writes** on the connection's detail panel controls whether agents may change anything in Google Cloud. It's on by default, but a service account with only **Viewer** and the BigQuery read roles can't change anything, so Google Cloud refuses every write until you grant more.

| IAM roles | Allow writes | Result |
|---|---|---|
| Read-only roles only | On or off | Read-only. Google Cloud rejects any change. |
| Extra write roles granted | Off | Read-only. CloudThinker refuses every change before it reaches Google Cloud. |
| Extra write roles granted | On | Agents can propose changes. Your [Rules and Approval mode](/guide/approvals/overview) decide each one. |

## Troubleshooting

<Accordion title="You can't create a key: key creation is disabled">
**Cause:** the organization policy `iam.disableServiceAccountKeyCreation` is enforced.

**Fix:** ask an organization policy admin to allow key creation for this project, or to create the key for you.
</Accordion>

<Accordion title="The upload is rejected or the test fails right away">
**Cause:** the file isn't the original JSON key. Common cases are a P12 key, a copied snippet, or a file that was edited and lost its `private_key` line breaks.

**Fix:** create a new JSON key and upload the downloaded file unchanged.
</Accordion>

<Accordion title="Agents get PERMISSION_DENIED or 'API not enabled'">
**Check:** the service account has a role on the project you asked about, and the API for that service (for example Compute Engine or Kubernetes Engine) is enabled in that project.

**Fix:** grant **Viewer** on the project or its folder, or enable the API under **APIs & Services**. No reconnect needed: the next request uses the new access.
</Accordion>

<Accordion title="Optimize says no billing export was found">
**Cause:** Optimize needs a Cloud Billing Standard usage cost export table (named `gcp_billing_export_v1_...`) in the connected project.

**Fix:** turn on the Standard usage cost export in **Billing → Billing export**, pointing at a dataset in the same project as the service account. If Optimize says the table is outside the connected project, move the export or create the service account in the project that holds it. If it asks you to select a table, pick the one you want Optimize to use.
</Accordion>

<Accordion title="The connection shows Error">
**Cause:** the key was deleted, disabled, or expired in Google Cloud.

**Fix:** create a new key, then open the connection and click **Replace credentials** to upload it. Scheduled work resumes once the status is **Connected**.
</Accordion>

## Security

<ConnectionSecurity />

- **Delete local copies of the key.** After you upload the JSON file, delete it from your downloads folder or store it in a secret manager. It grants the service account's access to anyone who holds it.
- **Rotate by replacing.** Create a new key, upload it with **Replace…** in **Edit Instance**, then delete the old key under the service account's **Keys** tab.

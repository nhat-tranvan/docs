Connect Oracle Cloud Infrastructure so CloudThinker can explore compartments, resources, and Cloud Guard problems. The connection uses a dedicated API credential, with access limited by the account behind it.

## Prerequisites

- Access to the Oracle Cloud Infrastructure account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create an API signing key for a dedicated OCI user and register its public key. Copy the user OCID, tenancy OCID, fingerprint, and corresponding private key.

    See the [Oracle Cloud Infrastructure documentation](https://docs.oracle.com/en-us/iaas/Content/API/Concepts/apisigningkey.htm) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Oracle Cloud Infrastructure**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Region** | Yes | The region identifier, for example us-ashburn-1. Use your Cloud Guard reporting region to read problems. Default: us-ashburn-1. |
| **Tenancy OCID** | Yes | Use the tenancy ocid prepared in the credential step. |
| **User OCID** | Yes | The OCID of a user in a group with read policies, starting ocid1.user.oc1.. |
| **API key fingerprint** | Yes | The fingerprint OCI shows after you add the API signing key to the user. |
| **API private key (PEM)** | Yes | The unencrypted private key of that API signing key, including the BEGIN and END lines. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

Give the user’s IAM group read policies for the services and compartments you want to inspect. Choose the Cloud Guard reporting region for Cloud Guard problems.

<Tip>
Start with read access to the smallest useful scope. This guide covers investigation; broad administrative or write access is unnecessary for these reads.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Compute and database inventory** | Explore compartments, resources, and Cloud Guard problems. |
| **Cloud Guard problems** | Inspect cloud Guard problems within the connected account’s scope. |
| **Resource and compartment context** | Inspect resource and compartment context within the connected account’s scope. |

The fingerprint must match the public key registered for the entered user. Use the matching unencrypted PEM private key, not an SSH key.

The connection reads the supported information without changing it. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Oracle Cloud Infrastructure connection, summarize its account or service scope and compute and database inventory. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize compute and database inventory in Oracle Cloud Infrastructure and highlight items needing attention.
Review cloud guard problems and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

<ConnectionSecurity />

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

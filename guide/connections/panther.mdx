Connect Panther so CloudThinker can investigate alerts, detection errors, and detection-rule configuration. The connection uses a Panther API token.

## Prerequisites

- Access to the Panther account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    In Panther, open **Settings → Developer Tools → API Tokens** and create a dedicated token. Grant the read permissions needed for alerts and rules. Copy the API URL shown with the token; enter the origin without appending the GraphQL path.

    See the [provider documentation](https://docs.panther.com/panther-developer-workflows/api) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Panther**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **API URL** | Panther API address shown in Developer Tools, without /public/graphql. | https://api.acme.runpanther.net |
| **API token** | Dedicated token permitted to read alerts and rules. | Copy from Panther |

## Required permissions

Grant Read Alerts and View Rules for the data being investigated. No write permission is required for this connection. Use the API URL for the same Panther installation as the token, and limit access to the operational scope you intend to share.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Alerts** | Review alert severity, status, and associated detection information. |
| **Detection errors** | Identify detections with recent execution errors. |
| **Rules** | Inspect detection configuration and relevant rule context. |

This connection is read-only. It does not change alert status, edit rules, or deploy detections. A rule that returned no alerts is not necessarily healthy; check detection errors and the investigation time window separately.

### Verify the connection

```text
Summarize recent Panther alerts and detection errors, identifying any data this token cannot read
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Investigate recent high-severity Panther alerts and identify their detections
Show detection rules with errors and explain which reads support that result
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Requests fail despite a valid token">
Compare API URL with the address in Panther’s API Tokens page. Remove /public/graphql from the field and confirm the token has both alert and rule read permissions.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

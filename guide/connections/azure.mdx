Connect Azure so CloudThinker can inventory virtual machines, AKS clusters, databases, storage, and networking, review identity and role assignments, and read spend from Azure Cost Management. Azure authenticates with a **service principal** (an app identity in Microsoft Entra ID with a client secret), and its role assignments decide what CloudThinker can see.

## Prerequisites

- An Azure subscription where you hold **Owner** or **User Access Administrator**, so you can assign roles.
- Permission to create app registrations in Microsoft Entra ID.
- Multi-factor authentication registered on your account. Security defaults block app registration without it.

## Setup

<Tabs>
  <Tab title="Azure CLI">
    <Steps>
      <Step title="Select the subscription">
        ```bash
        az login
        az account set --subscription <subscription-id>
        ```
      </Step>
      <Step title="Create the service principal with Reader">
        ```bash
        az ad sp create-for-rbac --name cloudthinker \
          --role Reader \
          --scopes /subscriptions/<subscription-id>
        ```

        Copy the output now. Azure shows the `password` only once.

        ```json
        {
          "appId": "00000000-0000-0000-0000-000000000000",
          "displayName": "cloudthinker",
          "password": "the-client-secret",
          "tenant": "00000000-0000-0000-0000-000000000000"
        }
        ```
      </Step>
      <Step title="Add cost access">
        ```bash
        az role assignment create --assignee <appId> \
          --role "Cost Management Reader" \
          --scope /subscriptions/<subscription-id>
        ```
      </Step>
      <Step title="Add the connection in CloudThinker">
        Go to **Connections → Microsoft Azure** and enter `appId` as **APP_ID**, `password` as **CLIENT_SECRET**, and `tenant` as **TENANT_ID**. Pick an **AZURE_DEFAULT_REGION**, then click **Connect**.

        **Success state:** the connection shows **Connecting** and **Verifying**, then a **Connected** status.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Azure portal">
    <Steps>
      <Step title="Register an application">
        In the [Azure portal](https://portal.azure.com/), go to **Microsoft Entra ID → App registrations → New registration**. Name it `cloudthinker`, keep the default account type, and click **Register**.
      </Step>
      <Step title="Copy the identifiers">
        On the app's overview page, copy the **Application (client) ID** and the **Directory (tenant) ID**.
      </Step>
      <Step title="Create a client secret">
        Go to **Certificates & secrets → New client secret**, set an expiration, and click **Add**. Copy the secret **Value** right away. Azure never shows it again.
      </Step>
      <Step title="Assign the roles">
        Go to **Subscriptions → your subscription → Access control (IAM) → Add role assignment**. Assign **Reader** to the `cloudthinker` app, then repeat for **Cost Management Reader**.
      </Step>
      <Step title="Add the connection in CloudThinker">
        Go to **Connections → Microsoft Azure** and enter the client ID as **APP_ID**, the secret value as **CLIENT_SECRET**, and the directory ID as **TENANT_ID**. Pick an **AZURE_DEFAULT_REGION**, then click **Connect**.

        **Success state:** the connection shows **Connecting** and **Verifying**, then a **Connected** status.
      </Step>
    </Steps>
  </Tab>
</Tabs>

### Microsoft Customer Agreement billing

Pay-as-you-go subscriptions bought online usually sit on a Microsoft Customer Agreement (MCA). Cost Management rejects subscription-level queries for these with `Given subscription doesn't have valid WebDirect/AIRS offer type`, so [Optimize](/guide/cost-optimization/overview) reads spend at the billing profile instead.

To allow that, go to **Cost Management + Billing → your billing account → Billing profiles → your profile → Access control (IAM) → Add** and assign **Billing profile reader** to the `cloudthinker` app. Subscription role assignments don't reach billing scopes.

## Connection details

| Field | What to enter | Example |
|-------|---------------|---------|
| **APP_ID** | Application (client) ID of the app registration | `00000000-0000-0000-0000-000000000000` |
| **CLIENT_SECRET** | Secret value from **Certificates & secrets** | n/a |
| **TENANT_ID** | Directory (tenant) ID of your Microsoft Entra ID | `00000000-0000-0000-0000-000000000000` |
| **AZURE_DEFAULT_REGION** | Default region for Azure CLI calls | `East US` |

There's no subscription field. CloudThinker works with every subscription the service principal can read. If it can read more than one, Optimize asks you to **Choose an Azure billing scope** the first time you open it.

## Required permissions

| Role | Scope | What it unlocks |
|------|-------|-----------------|
| **Reader** | Subscription | Resource inventory, role and policy reviews, health and performance checks |
| **Cost Management Reader** | Subscription | Spend, forecasts, and cost findings in Optimize |
| **Billing profile reader** | MCA billing profile | Optimize on a Microsoft Customer Agreement subscription |
| **Contributor** | Subscription | Optional. Lets CloudThinker change resources after you approve |

Reader alone returns no cost data. Reader grants `*/read`, and a Cost Management query is a POST action that `*/read` doesn't cover.

<Tip>
Start with Reader and Cost Management Reader. Add Contributor only when you want CloudThinker to make changes, and every change still goes through [Approvals](/guide/approvals/overview).
</Tip>

## Agent capabilities

CloudThinker runs bounded, read-only Azure CLI commands by default. Any command that changes a resource needs your approval first.

| Area | What CloudThinker does |
|------|------------------------|
| **Cost** | Reads spend from Cost Management (pretax, with currency), finds unused resources and underused VMs |
| **Identity and governance** | Reviews role assignments, RBAC, and Azure Policy |
| **Compute and containers** | Inspects VMs, App Service, and AKS clusters |
| **Data and storage** | Inspects SQL and other databases, storage accounts, and backups |
| **Networking** | Reviews network boundaries, DNS zones, and connected Log Analytics workspaces |

## Troubleshooting

<Accordion title="Sign-in blocked by security defaults">
`az login` or the portal returns `AADSTS530035: Access has been blocked by security defaults`. Security defaults require multi-factor authentication before you can register an app. Register a method at [aka.ms/mfasetup](https://aka.ms/mfasetup) and sign in again. The `--use-device-code` and `--allow-no-subscriptions` flags don't get around this.
</Accordion>

<Accordion title="Authentication failed">
Check APP_ID, CLIENT_SECRET, and TENANT_ID. Make sure the secret hasn't expired and the app registration lives in the tenant you entered. Confirm no conditional access policy blocks service principal sign-in.
</Accordion>

<Accordion title="Client secret expired">
Run `az ad sp credential reset --id <appId>`, or create a new secret under **Microsoft Entra ID → App registrations → your app → Certificates & secrets**. Update CLIENT_SECRET on the connection and test it again.
</Accordion>

<Accordion title="Optimize says Azure Cost Management is not readable">
Assign **Cost Management Reader** on the subscription. For a Microsoft Customer Agreement subscription, also assign **Billing profile reader** on the billing profile. Role assignments take a few minutes to propagate, so retry after that.
</Accordion>

<Accordion title="Cost Management returns 429">
New subscriptions are heavily throttled by Cost Management, and queries answer `429 Too many requests`. Nothing is misconfigured and no permission change is needed. Wait a few minutes and reload Optimize.
</Accordion>

<Accordion title="Resources or a subscription are missing">
Assign **Reader** on every subscription you expect to see. CloudThinker never sees resources in a subscription the service principal can't read.
</Accordion>

## Security

<ConnectionSecurity />

- **Expire and rotate secrets**: always set an expiration on the client secret and rotate it before it lapses.
- **Scope the roles**: assign roles on the subscriptions CloudThinker needs, not at management group level by default.

Connect Microsoft Defender XDR to let CloudThinker investigate incidents, alerts, and their evidence. The connection uses **a Microsoft Entra application**.

## Prerequisites

- An account with access to the Microsoft Defender XDR resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Microsoft Defender XDR">
    Register an application in **Microsoft Entra ID → App registrations** and keep its directory and application IDs. Add a client secret and copy its value. Add the Microsoft Graph application permissions **SecurityIncident.Read.All** and **SecurityAlert.Read.All**, then have an administrator grant consent. Use the tenant’s matching Microsoft cloud.

    Follow the [vendor’s credential and authentication guidance](https://learn.microsoft.com/en-us/graph/api/security-list-incidents?view=graph-rest-1.0) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Microsoft Defender XDR**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Directory (tenant) ID** | Yes | Microsoft Entra ID &gt; App registrations &gt; your app &gt; Overview. |
| **Application (client) ID** | Yes | The Application (client) ID for the account described in Setup. |
| **Client secret** | Yes | A secret of the app. Grant it the Microsoft Graph application permissions SecurityIncident.Read.All and SecurityAlert.Read.All, with admin consent. |
| **Cloud** | Yes | The Microsoft cloud that hosts your tenant. Choose **Global**, **US Government L4 and L5**, **China, 21Vianet**. Default: **Global**. |

Microsoft documents that these security APIs are unavailable in China operated by 21Vianet, although the connection form lists that cloud. Use a supported tenant cloud for incident and alert investigations.

Use an application permission grant, not a delegated sign-in token. Confirm admin consent after adding or changing permissions.

## Required permissions

Microsoft Graph application permissions SecurityIncident.Read.All and SecurityAlert.Read.All, with admin consent in the intended tenant. This connection reads incidents, alerts, and evidence; it does not isolate devices or update incidents.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | List Defender incidents |
| Investigation | Inspect incident alerts and evidence |
| Investigation | Filter investigations by status and severity |

### Verify the connection

```text
Review Microsoft Defender XDR incidents and alerts and summarize the most urgent unresolved investigations. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Review Microsoft Defender XDR incidents and alerts and summarize the most urgent unresolved investigations
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. Use Microsoft Graph permissions, not similarly named permissions from a different Defender API. Supply the secret value, not its identifier.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

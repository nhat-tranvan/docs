Connect TOPdesk so CloudThinker can review service tickets, ownership, progress, and overdue work. The connection uses an operator username and application token.

## Prerequisites

- Access to the TOPdesk account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to the provider API. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services). Access through your browser or local SSH tunnel alone is insufficient.

## Setup

<Steps>
  <Step title="Prepare access">
    Sign in as the intended TOPdesk operator. Open the user menu, choose **My settings**, and create an application token under **Application tokens**. Give it a descriptive name and expiry, then copy it. Ask the administrator to grant the required Incident Management API permissions to that operator.

    See the [provider documentation](https://docs.topdesk.com/en/api-account.html) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **TOPdesk**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **TOPdesk URL** | HTTPS origin of the instance, without /tas/api. | https://acme.topdesk.net |
| **API operator username** | Operator associated with the application token. | Your API operator |
| **Application token** | Application token rather than the operator’s interactive password. | Copy from TOPdesk |
| **CA certificate (optional)** | Private issuing CA certificate; empty uses public trust. | Leave empty for public trust |

## Required permissions

The operator needs Incident Management API access, permission to use application tokens, and read access to the intended tickets and lookups. Creating tickets, assigning ownership, changing status, or adding progress requires the corresponding additional permissions.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Backlog** | Review incomplete tickets, target dates, and missing ownership. |
| **Ticket detail** | Read one ticket and bounded request and action history. |
| **Assignments** | Resolve current operator, group, status, and priority choices. |

Instance-specific required fields and transition rules still apply. The connection does not delete tickets or manage other TOPdesk modules. Returned pages and action histories are samples rather than a full tenant export.

Creating tickets, changing assignments or supported ticket fields, and adding progress comments go through [Approvals](/guide/approvals/overview). Comments may be visible to callers and can send notifications. Review the precise ticket and message before approval.

### Verify the connection

```text
Summarize the visible TOPdesk backlog and identify overdue tickets or tickets with no owner
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Inspect the selected ticket and summarize its current owner and recent progress
List incomplete tickets assigned to the selected operator group
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Interactive password is rejected">
Use the operator’s application token in Application token. Confirm it has not expired and the operator’s permission group allows application-token use and the required incident operations.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

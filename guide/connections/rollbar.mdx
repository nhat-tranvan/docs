Connect Rollbar to let CloudThinker agents rank your top errors, tie new errors to recent deployments and versions, pull session replay context, and change an item's status after you approve it. You paste one JSON config that maps each Rollbar project to its project access token, so one connection can cover many projects.

## Prerequisites

- A Rollbar account with access to each project you want agents to read.
- A project access token for each of those projects. Rollbar tokens are per project, so one token can't cover two projects.

## Setup

<Steps>
  <Step title="Create a project access token">
    In Rollbar, open the project, go to its settings, and create a **project access token** with the **read** scope. Add the **write** scope too only if you want agents to change item status. Repeat for each project.
  </Step>
  <Step title="Write the project config">
    Build a JSON object with a `projects` array, one entry per project. Each entry has a `name` (the label you'll use in prompts) and a `token`.

    ```json
    {
      "projects": [
        { "name": "backend", "token": "<backend-project-token>" },
        { "name": "frontend", "token": "<frontend-project-token>" }
      ]
    }
    ```
  </Step>
  <Step title="Add the connection">
    Open **Connections** in the sidebar, select **Rollbar**, paste the JSON into **ROLLBAR_CONFIG_JSON**, and click **Connect**.

    **Success state:** the connection shows **Connected**.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **ROLLBAR_CONFIG_JSON** | A `projects` array. Each entry has a `name` and a `token`. The key is `token`, not `access_token` | `{"projects":[{"name":"backend","token":"..."}]}` |

The format matches Rollbar's [MCP server multi-project configuration](https://docs.rollbar.com/docs/mcp-server-setup#configuration).

## Required permissions

| Token scope | What it allows |
|-------------|----------------|
| **read** | Projects, items, top errors, deployments, versions, and session replay |
| **write** | Changing an item's status, such as resolving or muting it. Each change also needs your approval |

<Tip>
Start with read-only tokens. Add the write scope only on the projects where you want agents to resolve or mute items.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **Discovery** | List configured projects and pick the project on their own when there's only one |
| **Error triage** | List current items, read item details and occurrence counts, and rank the top errors |
| **Release context** | Review recent deployments and pull version details from deploy revisions |
| **Session replay** | Fetch replay context for items that have a recorded replay |
| **Item updates (approval each time)** | Change one item's status. You must name the project, the item, and the change you want |

Agents never change an item while triaging, reviewing deploys, or reading replays. An update runs only when you ask for it in the conversation and approve it.

### Verify the connection

```text
List my Rollbar projects and show the top errors in each
```

Expect every project name from your config, each with its highest-impact items, their level, and occurrence counts. A missing project means it isn't in the JSON you pasted.

### Example prompts

```text
Which errors in backend first appeared after the latest deployment?
Rank the active items in frontend by impact and show replay context for the top one
Resolve item 1042 in backend
```

With several projects configured, name the project in your prompt. Otherwise the agent asks you which one to use.

## Troubleshooting

<Accordion title="Calls fail with 401 Unauthorized, or come back empty">
The pasted config is invalid JSON, doesn't include the project you named, or holds an expired token. Ask the agent to list your configured projects, then edit the connection and fix the JSON or token.
</Accordion>

<Accordion title="The agent asks which project to use">
More than one project is configured and your prompt didn't name one. Add the project name from your config, for example "in backend".
</Accordion>

<Accordion title="No replay is available for an item">
Replay context exists only for items with a recorded session replay. Items without one return no replay data. That's expected, not an error.
</Accordion>

<Accordion title="An item update is blocked or fails">
The token for that project lacks the write scope, or you declined the approval. Add write scope to the token in Rollbar, update the connection, and ask again.
</Accordion>

## Security

<ConnectionSecurity />

- **Short-lived config file**: CloudThinker writes your config to a temporary file only your session can read, and deletes it when the Rollbar server stops.
- **Rotation**: when you rotate a project token in Rollbar, edit the connection and paste the updated JSON.

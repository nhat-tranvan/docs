Connect Catchpoint so CloudThinker can inspect synthetic tests, recent alerts, and performance failures. The connection uses a Catchpoint REST API consumer key.

## Prerequisites

- Access to the Catchpoint account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    In the Catchpoint portal, open **Settings → Integrations → REST API**. Select **Add Consumer**, enter a name, choose the intended contact, and select **Add Consumer & Show Key**. Copy that key; the selected contact and account access determine the available scope.

    See the [provider documentation](https://docs.catchpoint.com/docs/rest-api-v2-guide) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Catchpoint**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **REST API key** | The Catchpoint REST API consumer key. | Copy from Catchpoint |

## Required permissions

Use a consumer with access to the tests and alerts CloudThinker should investigate. Add test-management and alert-change rights only if approved changes are required. Ask your Catchpoint administrator to confirm the consumer’s client or division coverage before connecting.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Tests** | Inspect visible tests and one test’s configuration summary. |
| **Performance** | Review recent metrics and error records for a selected test. |
| **Alerts** | Read recent alerts and affected test identifiers. |

Pausing alerts changes notifications, not test execution. Results describe returned pages and time windows. A submitted assignment or drop needs confirmation in Catchpoint when the final state cannot be read back.

Through [Approvals](/guide/approvals/overview), agents can acknowledge, assign, or drop an alert; pause or resume test alerts; and create, edit, delete, or rerun a test. Test reruns consume provider capacity. Dropping alerts and deleting tests need explicit approval for that irreversible action.

### Verify the connection

```text
List visible Catchpoint tests and recent alerts, including the time window and any unreadable sections
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Investigate the latest performance errors for the selected Catchpoint test
Show recent alerts for the selected test and identify which are still unacknowledged
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Expected tests are missing">
Confirm the API consumer belongs to the correct client or division and its contact can see those tests. Returned pages are not an account-wide inventory.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

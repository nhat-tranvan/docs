Connect Mixpanel so CloudThinker can explore event activity, trends, and property breakdowns for one project. The connection uses a Mixpanel service account.

## Prerequisites

- Access to the Mixpanel account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    In Mixpanel **Organization settings → Service Accounts**, create a dedicated account and grant it the intended project. Save its username and secret when shown. Find the project ID in the project settings, and confirm the project’s data residency before choosing the matching option in CloudThinker.

    See the [provider documentation](https://docs.mixpanel.com/reference/service-accounts) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Mixpanel**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Data residency** | Region in which the project resides; the default is the US Mixpanel domain. | US, EU, or India |
| **Project ID** | ID of the project to investigate. | Your project ID |
| **Service account username** | Username of the account granted access to this project. | Copy from Mixpanel |
| **Service account secret** | Secret paired with the service account. | Enter in the connection form |
| **Workspace ID (data views only)** | Data-view workspace identifier; leave empty when data views are not used. | Your data-view workspace ID |

## Required permissions

Grant the service account access to the project and its event-analysis data. Use the narrowest project role that permits the required reports; the connection’s setup guidance uses Consumer access. Do not use a project ingestion token as a substitute for service account credentials.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Event discovery** | Read top events and the available event properties. |
| **Trends** | Compare an event over a specified date range. |
| **Breakdowns** | Group a selected event by one of its properties. |

This connection is read-only. It does not ingest events, change project settings, or edit reports. Event names and properties must exist in the connected project, and the selected date range affects every result.

### Verify the connection

```text
Show the top events and available event properties for the connected Mixpanel project
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Compare the selected event’s daily trend over the last seven days
Break down the selected event by its country property and show the largest groups
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="The project is unavailable or results come from the wrong region">
Check Project ID, the service account’s project membership, and Data residency. Choose EU or India only for a project enrolled in that residency.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

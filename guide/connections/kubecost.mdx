Connect KubeCost so CloudThinker can break Kubernetes cost down by namespace, controller, or pod. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing KubeCost account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain the address of your Kubecost endpoint and the credentials used by its access proxy, if any. See the [vendor's authentication documentation](https://www.ibm.com/docs/en/kubecost) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **KubeCost**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose None, Bearer Token, or Basic Auth to match the endpoint. Do not expose an unauthenticated endpoint publicly.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **KUBECOST_URL** | Yes | The Kubecost endpoint address reachable from CloudThinker. |
| **KUBECOST_AUTH_TYPE** | Yes | Options: **None**, **Bearer Token**, **Basic Auth**. Default: `none`. |
| **KUBECOST_TOKEN** | For bearer | The bearer token accepted by your access proxy. Shown when **KUBECOST_AUTH_TYPE** is `bearer`. |
| **KUBECOST_USERNAME** | For basic | The username for your endpoint access proxy. Shown when **KUBECOST_AUTH_TYPE** is `basic`. |
| **KUBECOST_PASSWORD** | For basic | The password for that username. Shown when **KUBECOST_AUTH_TYPE** is `basic`. |
| **KUBECOST_API_PREFIX** | Yes | Default: `/model`. |

## Required permissions

Read allocation, asset, efficiency, and right-sizing APIs. Cluster mutation and billing writes are not used.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Cost allocation | Break costs down by namespace or workload. |
| Cost trends | Inspect costs over an allocation window. |
| Efficiency | Review utilization and right-sizing recommendations. |

All supported tools are read-only. Available cost data depends on the endpoint's configured data sources and allocation window.

This connection is read-only. Make changes in KubeCost.

### Verify the connection

```text
Inspect my KubeCost connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use KubeCost to break Kubernetes cost down by namespace, controller, or pod.
Summarize the highest-priority items visible through my KubeCost connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in KubeCost. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in KubeCost when access is no longer needed, and update the connection after rotation.

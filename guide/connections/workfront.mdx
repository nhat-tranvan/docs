Connect Adobe Workfront so CloudThinker can review projects at risk, late tasks, open issues, and ownership. The connection uses a Workfront API key acting as one user.

<Note>
Adobe still supports API keys but recommends Adobe Developer Console authentication for new integrations. This CloudThinker connection currently uses an API key; browser OAuth or Developer Console credentials do not replace this field.
</Note>

## Prerequisites

- Access to the Adobe Workfront account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your Workfront administrator for a dedicated user API key with access to the projects to investigate. The administrator controls under **Setup → System → Customer Info → API Key Settings** generate the administrator’s own key, which grants broader access than ordinary project reads need. Record the Workfront domain for that account and confirm which projects the key’s user can read.

    See the [provider documentation](https://experienceleague.adobe.com/en/docs/workfront/using/administration-and-setup/manage-wf/security/manage-api-keys) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Adobe Workfront**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Workfront URL** | The HTTPS domain of your Workfront instance. | https://acme.my.workfront.com |
| **API key** | Key associated with the user whose project access should apply. | Enter in the connection form |

## Required permissions

The API key acts as its Workfront user. Grant that user read access to the relevant projects, tasks, issues, and ownership information. Broad administrator access is unnecessary for the read-only investigations supported here.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Project risk** | Review current projects marked at risk or in trouble and compare planned versus projected completion. |
| **Late work** | Find incomplete tasks whose planned completion date has passed. |
| **Open issues** | Review unresolved issues and their assignees within a selected project. |

This connection is read-only. It cannot change statuses, assignments, dates, or project conditions. Results reflect the key user’s access; unavailable projects must not be treated as complete or healthy.

### Verify the connection

```text
Summarize the Workfront projects this user can read, highlighting at-risk projects, late tasks, and open issues
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Inspect the selected Workfront project and list its late tasks and open issues
Show incomplete work assigned to the selected person and its planned completion dates
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="A project is visible in your browser but missing here">
Check which user owns API key and whether that user has access to the project. Your browser’s signed-in user can have different permissions.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

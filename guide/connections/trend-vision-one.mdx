Connect Trend Micro Vision One to let CloudThinker review workbench alerts and observed attack techniques. The connection uses **a Trend Micro Vision One API key**.

## Prerequisites

- An account with access to the Trend Micro Vision One resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Trend Micro Vision One">
    Create an API key in the Vision One console for a role that can view Workbench alerts and Observed Attack Techniques. Select the data center that hosts your account and retain the key securely. Use the vendor’s current API-key instructions for your console version.

    Follow the [vendor’s credential and authentication guidance](https://docs.trendmicro.com/en-us/documentation/article/trend-vision-one-automation-center-authentication) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Trend Micro Vision One**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Region** | Yes | The data center of your Vision One console. Choose **United States**, **Europe**, **Japan**, **Australia**, **Singapore**, **India**, **Middle East and Africa**. Default: **United States**. |
| **API key** | Yes | The API key for the account described in Setup. |

Use an API key for the selected data center. A Cloud Accounts onboarding key is not a substitute for the investigation permissions.

## Required permissions

View access to Workbench and Observed Attack Techniques. These are investigations only; this connection does not isolate endpoints, quarantine files, or close alerts.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Review Workbench alerts and impact scope |
| Investigation | Inspect high-risk observed attack techniques |
| Investigation | Relate alert indicators to affected endpoints and accounts |

### Verify the connection

```text
Review Vision One Workbench alerts and observed attack techniques, prioritizing open high-risk alerts. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Review Vision One Workbench alerts and observed attack techniques, prioritizing open high-risk alerts
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. Use an API key for the selected data center. A Cloud Accounts onboarding key is not a substitute for the investigation permissions.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

Connect AWS CodeCommit to let CloudThinker agents list and read your repositories, and to run [Review](/guide/code-review/setup) (automated AI code review) on their pull requests. The connection signs in with an **IAM role** (recommended) or **IAM user access keys**, and covers one AWS Region.

## Prerequisites

- An AWS account that holds the CodeCommit repositories you want to connect.
- Permission to create an IAM role or IAM user in that account, and to open [AWS CloudShell](https://docs.aws.amazon.com/cloudshell/latest/userguide/getting-started.html). The `AWSCloudShellFullAccess` managed policy grants CloudShell access.
- The AWS Region where the repositories live, for example `us-east-1`.

<Info>
A workspace holds one AWS CodeCommit connection, and that connection covers one Region. Repositories in other Regions aren't reachable through it.
</Info>

## Setup

In the sidebar, click **More → Workspace settings → Connections**, stay on the **Builtin Connections** tab, and select **AWS CodeCommit**. Choose the **AWS Region**, then pick a tab.

<Tabs>
  <Tab title="IAM role (recommended)">
    <Steps>
      <Step title="Open AWS CloudShell">
        On the **IAM Role** tab, open AWS CloudShell from the **Open AWS CloudShell** step. It runs in your browser, so there's nothing to install.
      </Step>
      <Step title="Run the setup script">
        In **Run Setup Script**, copy the script, paste it into CloudShell, and run it. It creates the role `CloudThinkerCodeCommitAccessRole` with a trust policy that includes your workspace's External ID, then prints the role ARN.

        Check first that no role with that name already exists in the account. The wizard also lists the same steps as manual commands.
      </Step>
      <Step title="Paste the Role ARN">
        Paste the ARN into **Role ARN** and click **Connect**.

        **Success state:** the dialog shows **Connected** with the number of repositories CloudThinker can reach.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Access keys">
    <Steps>
      <Step title="Run the setup script">
        On the **Access Keys** tab, open AWS CloudShell, copy the script from **Run Setup Script**, and run it. It creates the IAM user `CloudThinkerCodeCommitUser`, attaches the CodeCommit permissions, and prints an access key pair.
      </Step>
      <Step title="Paste the keys">
        Paste the values into **Access Key ID** and **Secret Access Key**, then click **Connect**.

        **Success state:** the dialog shows **Connected** with the number of repositories CloudThinker can reach.
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Warning>
AWS shows a secret access key only once. Copy it from the script output before you close CloudShell.
</Warning>

Review also needs pull request events from AWS. After you connect, finish the [webhook step](/guide/code-review/provider-auth#configure-webhooks), which links Amazon EventBridge to CloudThinker.

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **AWS Region** | Region that holds your repositories | `us-east-1` |
| **Role ARN** | IAM role CloudThinker assumes (IAM role method) | `arn:aws:iam::<your-account-id>:role/CloudThinkerCodeCommitAccessRole` |
| **Access Key ID** | Access key for the dedicated IAM user (access keys method) | `<your-access-key-id>` |
| **Secret Access Key** | Secret for that access key (access keys method) | `<your-secret-access-key>` |

## Required permissions

The setup script attaches an inline policy with these CodeCommit actions:

| Purpose | Actions |
|---------|---------|
| Find repositories | `ListRepositories`, `GetRepository` |
| Read pull requests | `ListPullRequests`, `GetPullRequest`, `GetDifferences`, `GetCommentsForPullRequest`, `GetCommentReactions` |
| Read code | `GetBlob`, `GetFile`, `GetFolder`, `GitPull` |
| Write review comments | `PostCommentForPullRequest`, `PostCommentReply`, `UpdateComment` |

The policy also lets CloudThinker manage Amazon EventBridge rules whose names start with `CloudThinker-CodeCommit-`, so pull request events can reach Review.

<Tip>
Keep the policy exactly as the script attaches it and add nothing broader. The IAM role method stores no long-lived key, so prefer it.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **Repositories** | List repositories in the connection's Region and clone one to read its code |
| **Pull requests** | Read a pull request's changes and comments during a review |
| **Review comments** | Post review summaries, findings, and replies as pull request comments |

CodeCommit supports fewer [mention commands](/guide/code-review/mention-commands) than other providers: questions in top-level comments only, with no `review` or `autofix`.

### Verify the connection

```text
List the AWS CodeCommit repositories CloudThinker can reach
```

Expect the repository names in the connection's Region. The count should match the one the dialog showed when you connected.

### Example prompts

```text
Clone the payments repository from AWS CodeCommit and summarize how it's structured
Which AWS CodeCommit pull requests did Review flag with high-severity findings this week?
```

## Troubleshooting

<Accordion title="Failed to connect to AWS CodeCommit. Please verify your credentials.">
CloudThinker couldn't use the credentials. For the IAM role method, the role's trust policy must include the External ID the wizard shows, so re-run the script if you changed it. For access keys, check the key pair and that the user can list repositories. Also confirm the **AWS Region** is valid and the workspace doesn't already have an AWS CodeCommit connection.
</Accordion>

<Accordion title="Failed to connect to AWS CodeCommit. Please try again.">
An unexpected error stopped the check. Try again. If it repeats, contact support.
</Accordion>

<Accordion title="Connected, but no repositories found yet">
The credentials work, but the chosen Region has no repositories the role or user can list. Confirm the **AWS Region** and that the permissions above are attached.
</Accordion>

<Accordion title="An expected repository is missing">
It lives in another Region. A connection only sees the Region it was set up for.
</Accordion>

<Accordion title="Review doesn't start on new pull requests">
AWS sends no pull request events until the webhook step is done. Run the webhook script from the wizard, then click **Mark as Configured**. See [provider authentication](/guide/code-review/provider-auth#configure-webhooks).
</Accordion>

## Security

<ConnectionSecurity />

- **External ID**: the role's trust policy requires it, which stops another AWS account from tricking CloudThinker into using your role (the confused deputy problem). AWS doesn't treat an External ID as a secret.
- **Dedicated identity**: use the role or user the script creates only for CloudThinker, so you can revoke it without touching anything else.

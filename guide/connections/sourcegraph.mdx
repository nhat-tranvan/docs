Connect Sourcegraph so CloudThinker can search code, repositories, and code host sync health. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Sourcegraph account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain a Sourcegraph access token from the account that should perform searches. See the [vendor's authentication documentation](https://sourcegraph.com/docs/api) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Sourcegraph**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use your Sourcegraph instance URL. Keep TLS verification enabled when its certificate is trusted.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Sourcegraph URL** | Yes | Your instance, such as https://sourcegraph.example.com, or https://sourcegraph.com. Default: `https://sourcegraph.com`. |
| **Access token** | Yes | A site admin token also shows code host sync health. |
| **TLS certificate** | Yes | Options: **Verify (recommended)**, **Skip SSL verification (self-signed)**. Default: `true`. |

## Required permissions

Read repositories and code accessible to that account. Code-host sync health additionally requires a site administrator token.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Code search | Search accessible repositories. |
| Repository context | Inspect repository metadata. |
| Sync health | Read code-host sync health when permitted. |

The connection is read-only. It cannot change code-host settings, run batch changes, or edit site settings.

This connection is read-only. Make changes in Sourcegraph.

### Verify the connection

```text
Inspect my Sourcegraph connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Sourcegraph to search code, repositories, and code host sync health.
Summarize the highest-priority items visible through my Sourcegraph connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Sourcegraph. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Sourcegraph when access is no longer needed, and update the connection after rotation.

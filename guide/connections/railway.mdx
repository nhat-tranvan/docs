Connect Railway so CloudThinker can inspect accessible projects, services, and feature flags. The connection uses browser-based authorization with your Railway account.

## Prerequisites

- Access to the Railway account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Choose the Railway account and workspace that contain the intended projects. Check that the account can view those projects and services. This connection signs in through Railway’s hosted authorization flow; project API tokens and a local Railway CLI login do not authenticate it.

    See the [provider documentation](https://docs.railway.com/ai/mcp-server) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Railway**, and choose **Connect**. Select **Connect**, sign in to Railway in the browser, and review the requested access. Complete authorization and return to CloudThinker. No manually entered API token is required.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Authorization** | Sign in to Railway and authorize the intended workspace scope in the browser. | Your Railway account |

## Required permissions

The authorized account and workspace selection determine project visibility. Grant access only to the workspaces needed for the investigation. CloudThinker restricts this connection to account identity, project and service listings, and feature-flag reads.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Account and projects** | Identify the connected account and list accessible projects. |
| **Services** | List services within one selected project. |
| **Feature flags** | Read feature flags and inspect one flag’s current configuration. |

This connection is read-only. Deployments, logs, variable changes, resource creation, and Railway Agent actions are not available through it. A visible service inventory does not prove that every deployment is healthy.

### Verify the connection

```text
Identify the connected Railway account and list its accessible projects and a small sample of services
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
List the services belonging to the selected Railway project
Review feature flags for the selected project and show their current settings
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Authorization expired or was revoked">
Reconnect Railway and complete browser authorization with the intended account. Confirm that account still has access to the required organization or workspace.
</Accordion>

<Accordion title="Sign-in succeeds but no projects appear">
Reconnect and select the intended workspace or project scope. Confirm the same account can view those projects in Railway before interpreting an empty list.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

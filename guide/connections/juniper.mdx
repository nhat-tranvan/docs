Connect Juniper Junos to let CloudThinker inspect interfaces, BGP peers, and chassis alarms. The connection uses **a Junos login for the HTTPS REST API**.

## Prerequisites

- An account with access to the Juniper Junos resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Juniper Junos">
    Ask the device administrator for an enabled HTTPS REST API endpoint and a dedicated Junos login. Assign a login class that permits the operational reads you need. Enter the REST API address in CloudThinker; this connection does not take an SSH or NETCONF address.

    Follow the [vendor’s credential and authentication guidance](https://www.juniper.net/documentation/us/en/software/junos/rest-api/topics/concept/rest-api-overview.html) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Juniper Junos**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Junos REST API URL** | Yes | The HTTPS address of the device's REST API service, such as https://router1.example.com:3443. |
| **Username** | Yes | A Junos login. Use a class with view permissions; add configure and interface-control only to allow approved interface changes. |
| **Password** | Yes | The password of that login. |
| **CA certificate (optional)** | Optional | PEM of the private CA that issued the device certificate. Leave empty to use public trust. The certificate and hostname are always checked. |

The connection uses HTTPS REST with a username and password. Enabling SSH or NETCONF alone does not enable the REST API.

## Required permissions

View permissions for interface, routing, and chassis health reads. Interface configuration edits need both configure and interface-control permissions; counter clears need the appropriate clear-command permission. These actions also go through the workspace’s approval policy.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Inspect interfaces, errors, and counters |
| Investigation | Review BGP peers and routing health |
| Investigation | Inspect chassis alarms |
| Changes | Change a named interface or clear its counters when authorized |

### Verify the connection

```text
Inspect Juniper interfaces, BGP peers, and chassis alarms without changing device configuration. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Inspect Juniper interfaces, BGP peers, and chassis alarms without changing device configuration
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

Disabling an interface can interrupt traffic and drop active sessions. Administrative state changes use a five-minute confirmed commit; if the connection cannot verify the read-back, Junos rolls the change back. Read the device again before retrying an unverified change. Clearing counters resets diagnostic measurements without changing configuration.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. The connection uses HTTPS REST with a username and password. Enabling SSH or NETCONF alone does not enable the REST API.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

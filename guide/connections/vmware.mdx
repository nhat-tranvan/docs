Connect vCenter Server so CloudThinker can inventory your VMs, hosts, clusters, and datastores, find oversized VMs and stale snapshots, and make VM changes after you approve them. The connection signs in with a **vCenter user name and password**, and the vSphere role you give that user decides what agents can see and change.

## Prerequisites

- A **vCenter Server** that CloudThinker can reach over HTTPS by hostname or IP address. The default port is `443`.
- Permission in the vSphere Client to create a user and assign a global permission.
- A CloudThinker workspace with no VMware vCenter connection yet.

<Info>
A workspace holds **one** VMware vCenter connection. Commands run in the CloudThinker cloud, so a vCenter on a private network that CloudThinker cannot reach fails the connection test.
</Info>

## Setup

<Steps>
  <Step title="Create a vCenter user">
    In the vSphere Client, open **Administration → Single Sign On → Users and Groups**. Select the `vsphere.local` domain, open the **Users** tab, click **Add**, and create a user such as `cloudthinker` with a strong password. A new user starts with no privileges.
  </Step>
  <Step title="Give the user the Read-only role">
    Open **Administration → Access Control → Global Permissions** and click **Add**. Choose the domain, search for the user, select the **Read-only** role, and tick **Propagate to children**. Click **OK**.

    **Success state:** the user appears in the global permissions list with the **Read-only** role.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar and select **VMware vCenter**. Fill in the fields from [Connection details](#connection-details): the host, `cloudthinker@vsphere.local` as the user name, the password, and the port. Leave **Verify SSL certificate** selected. Click **Connect**.

    **Success state:** the connection shows **Connecting** and **Verifying**, then a **Connected** status. CloudThinker signs in to vCenter and reads its version to prove the credentials work.
  </Step>
</Steps>

<Note>
Without **Propagate to children**, the user sees only the root object and agents report an empty inventory. To share less, assign the role on just the datacenters, clusters, or folders you want agents to see instead of using a global permission.
</Note>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **VMWARE_HOST** | vCenter hostname, IPv4 address, or IPv6 address in brackets. No `https://` and no path | `vcenter.example.com` |
| **VMWARE_USERNAME** | vCenter user name, including the domain | `cloudthinker@vsphere.local` |
| **VMWARE_PASSWORD** | Password of that user | |
| **VMWARE_PORT** | Port vCenter listens on. Defaults to `443` | `443` |
| **VMWARE_VERIFY_SSL** | **Verify SSL certificate** (default) or **Skip SSL verification** | **Verify SSL certificate** |

There is no field for a custom certificate authority. If vCenter uses a self-signed certificate (common on default installs and labs), **Skip SSL verification** is the only way to connect. It also removes protection against a server impersonating your vCenter, so use it for lab systems and give production vCenter a certificate from a trusted authority.

## Required permissions

Start with the built-in **Read-only** role. vSphere lets users with this role view the state and details of an object, and blocks every action in the menus and toolbars. It covers every read capability below.

<Tip>
Keep the CloudThinker user on **Read-only** until you want agents to make changes. If a question fails with a permission error, add only the privilege vCenter names, on as few objects as you can.
</Tip>

## Write access

To let agents power, reconfigure, migrate, snapshot, or delete VMs, give the user a custom role that holds those privileges on the objects in scope. Each change still pauses for your approval in CloudThinker before it runs. See [Approvals](/guide/approvals/overview) for who approves and how rules apply.

## Agent capabilities

| Capability | What agents do |
|------------|----------------|
| **Inventory** | List datacenters, clusters, hosts, VMs, datastores, and networks, and inspect one object in detail |
| **Tags** | Read tag categories and the objects they are attached to |
| **Right-sizing** | Find oversized and idle powered-on VMs from CPU usage history |
| **Snapshots** | List snapshots by VM and flag old ones |
| **Datastore capacity** | Show used and free space and flag datastores running low |
| **Drift** | Compare host settings (NTP, syslog, SSH service, lockdown mode) and flag risky port group security options such as promiscuous mode |
| **Changes** | Power, reconfigure, migrate, snapshot, or delete VMs. Each change **requires approval** |

Answers cover only what the user's role can see.

### Verify the connection

```text
Summarize my vCenter inventory: datacenters, clusters, hosts, VMs, and datastores
```

You get counts per object type and a short list of clusters and hosts. An empty inventory on a **Connected** status points to a missing **Propagate to children**.

### Example prompts

```text
Which powered-on VMs have used under 15% CPU recently and have 8 or more vCPUs?
List snapshots older than 7 days, grouped by VM
Which datastores are above 85% full?
```

## Troubleshooting

<Accordion title="Failed to connect to VMware vCenter">
CloudThinker could not sign in. Check that the user name includes its domain (`cloudthinker@vsphere.local`), the password is current, and the host and port are reachable from the internet. A self-signed certificate also fails here unless **Skip SSL verification** is selected.
</Accordion>

<Accordion title="VMWARE_HOST must be a DNS hostname, IPv4, or bracketed IPv6">
The host field has a scheme, a path, or an unbracketed IPv6 address. Enter only the host, such as `vcenter.example.com`, `192.0.2.10`, or `[2001:db8::10]`.
</Accordion>

<Accordion title="VMWARE_PORT must be an integer between 1 and 65535">
The port has letters or is out of range. Enter a number such as `443`.
</Accordion>

<Accordion title="Invalid VMware connection configuration">
The host field is empty. Enter your vCenter hostname or IP address and connect again.
</Accordion>

<Accordion title="Connection 'vmware' already exists. Only one instance is allowed.">
This workspace already has a VMware vCenter connection. Edit that connection or disconnect it first.
</Accordion>

<Accordion title="An agent cannot see a VM, host, or datastore">
The user's role does not cover that object. Check that the global permission has **Propagate to children** ticked, or assign the role on the object's parent folder or cluster.
</Accordion>

## Security

<ConnectionSecurity />

- **Use a dedicated user.** A separate vCenter user keeps CloudThinker's access visible in vCenter events and lets you revoke it without touching anyone's account.
- **Keep certificate checks on.** Reserve **Skip SSL verification** for lab systems with self-signed certificates.

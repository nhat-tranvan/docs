Connect Vanta so CloudThinker can track frameworks, failing tests, and vulnerabilities. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Vanta account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create a dedicated Vanta API application and copy its client ID and secret. See the [vendor's authentication documentation](https://developer.vanta.com/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Vanta**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose the commercial or Vanta Gov instance to match the application.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Vanta instance** | Yes | Vanta Gov is for FedRAMP customers. Options: **Vanta**, **Vanta Gov (FedRAMP)**. Default: `api.vanta.com`. |
| **Client ID** | Yes | Use a dedicated app: each new token revokes the app's previous one. |
| **Client secret** | Yes | Enter client secret. |

## Required permissions

Read the framework, test, and vulnerability data you want investigated.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Framework readiness | Review framework state. |
| Test review | Inspect failing tests. |
| Vulnerability context | Read available vulnerability data. |

The connection is read-only. It cannot remediate tests, assign owners, deactivate tests, or upload documents.

This connection is read-only. Make changes in Vanta.

### Verify the connection

```text
Inspect my Vanta connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Vanta to track frameworks, failing tests, and vulnerabilities.
Summarize the highest-priority items visible through my Vanta connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Vanta. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Vanta when access is no longer needed, and update the connection after rotation.

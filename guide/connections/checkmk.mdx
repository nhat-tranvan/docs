Connect Checkmk to let CloudThinker check hosts and services, then acknowledge or set downtime. The connection uses **a Checkmk automation user and automation secret**.

## Prerequisites

- An account with access to the Checkmk resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Checkmk">
    In Checkmk, go to **Setup → Users → Users** and create a dedicated automation user with an automation secret. Assign a role that can view the relevant hosts and services. Use the full HTTPS site URL, including the site name.

    Follow the [vendor’s credential and authentication guidance](https://docs.checkmk.com/latest/en/rest_api.html) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Checkmk**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Site URL** | Yes | The address of your Checkmk site, including the site name, such as https://monitor.example.com/mysite. |
| **Automation user** | Yes | The Automation user for the account described in Setup. |
| **Automation secret** | Yes | The automation secret of that user. |
| **CA certificate (optional)** | Optional | PEM of the private CA that issued the Checkmk certificate. Leave empty to use public trust. The certificate and hostname are always checked. |

A Checkmk site URL includes its site name. A server hostname without that path can return a missing-route error.

## Required permissions

Host and service view permissions for investigations. Acknowledging problems and creating or ending downtimes need the corresponding command permissions; leave them out for a read-only connection.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Find hosts that are down and services in a problem state |
| Investigation | Inspect one host and its services |
| Changes | Acknowledge a problem or manage a named downtime when permitted |

### Verify the connection

```text
Review Checkmk hosts and services that are not healthy, without acknowledging or changing anything. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Review Checkmk hosts and services that are not healthy, without acknowledging or changing anything
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

A host-level downtime also silences notifications for its services. Confirm the host or exact service and time window before scheduling or ending a downtime.

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. A Checkmk site URL includes its site name. A server hostname without that path can return a missing-route error.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

PagerDuty connects to CloudThinker through a webhook: PagerDuty sends each incident event to [Resolve](/guide/incident/overview), which can open an incident and start a root cause analysis (RCA). The webhook is signed with a secret that PagerDuty generates, so Resolve can prove each event came from your account.

<Note>
This is a one-way feed. There's no PagerDuty API connection today, so agents can't read on-call schedules, escalation policies, or services in PagerDuty, and can't acknowledge or resolve PagerDuty incidents.
</Note>

## Prerequisites

- The **Admin** role in your CloudThinker workspace. Only workspace Admins can create or edit webhooks.
- Permission in PagerDuty to add a webhook under **Integrations → Generic Webhooks (v3)**.
- A PagerDuty service you can trigger a test incident on.
- [Connections](/guide/connections/overview) to the systems behind your services, such as AWS or Datadog, if you want the RCA to query them.

## Setup

<Steps>
  <Step title="Create the webhook in CloudThinker">
    Go to **Resolve → Integrations** and select **PagerDuty**. Under **Signals to Resolve**, click **Add signal**. The **Create Webhook** dialog opens with the PagerDuty preset.

    On **Basic Info**, keep or change **Webhook Name** and click **Next**. On **Configure**, change **Service Path** to `event.data.service.summary`, which is where PagerDuty v3 events carry the service name. Leave the rest of **Field Mapping** and **Severity Mapping** as they are and click **Next**.
  </Step>
  <Step title="Keep the PagerDuty signature settings">
    On **Advanced**, **Auth Method** is already **HMAC Signature** with **HMAC Signature Header** set to `X-PagerDuty-Signature`. Leave both. Leave **Provider signing secret** blank for now. Keep **Auto-investigate** on for your first test, so the test incident gets an RCA, and click **Create**.

    Copy the **Webhook URL** from the dialog that opens. You don't need the secret it shows, because PagerDuty signs with its own.
  </Step>
  <Step title="Add the webhook in PagerDuty">
    In PagerDuty, go to **Integrations → Generic Webhooks (v3)** and click **New Webhook**. Paste the CloudThinker **Webhook URL**. Set **Scope Type** to **Service** (or **Account**) and pick the **Scope** whose incidents you want to send. Then select these events:

    - `incident.triggered`
    - `incident.acknowledged`
    - `incident.resolved`

    Save the webhook, then copy the signing secret PagerDuty shows. PagerDuty shows it only once, so copy it before you close the dialog.
  </Step>
  <Step title="Paste the PagerDuty secret into CloudThinker">
    Back on **Resolve → Integrations → PagerDuty**, find your webhook under **Signals to Resolve**. Open its menu (**⋯**), click **Edit**, paste the secret into **Provider signing secret**, and click **Save**.

    **Success state:** the webhook is listed under **Signals to Resolve**, and Resolve now verifies every PagerDuty event with your PagerDuty secret.
  </Step>
</Steps>

<Warning>
Until you paste the PagerDuty secret, every PagerDuty event fails the signature check and is rejected. If you regenerate the secret in PagerDuty later, paste the new one the same way.
</Warning>

## Connection details

The PagerDuty preset maps these fields from PagerDuty's v3 webhook payload:

| Field | Path | What it fills in |
|-------|------|------------------|
| **Title Path** | `event.data.title` | The incident title |
| **Description Path** | `event.data.html_url` | A link back to the PagerDuty incident |
| **Severity Path** | `event.data.priority.summary` | The severity, translated by **Severity Mapping** |
| **Service Path** | `event.data.service.name` in the preset. Change it to `event.data.service.summary` in setup. | The affected service, used by [Pulse](/guide/pulse/overview) to group related alerts |

**Severity Mapping** translates the values PagerDuty sends into CloudThinker's five levels. Incident events carry the incident priority (`P1` to `P5`) in `priority.summary`. The `critical`, `error`, `warning`, and `info` rows only match if you point **Severity Path** at a field that holds those values.

| PagerDuty value | CloudThinker severity |
|-----------------|-----------------------|
| `P1`, `critical` | critical |
| `P2`, `error` | high |
| `P3`, `warning` | medium |
| `P4` | low |
| `P5`, `info` | info |

Matching ignores case, so `P1` and `p1` both map to critical. An incident with no priority set arrives as **medium**. Priority names are set per PagerDuty account, so if yours aren't `P1` to `P5`, add them to **Severity Mapping**.

## Required permissions

CloudThinker needs nothing from PagerDuty except the signed events. There's no API key to store.

| Setting | Use |
|---------|-----|
| **HMAC Signature** on `X-PagerDuty-Signature` | Recommended. Resolve checks each event against your PagerDuty secret. A signed triggered or acknowledged event opens in Resolve as an incident that's already declared, because PagerDuty declared it. |
| **No Authentication** | A quick test only. Anyone with the URL can send events. Each one arrives as an ordinary alert that Pulse groups and that opens an incident only if its group is actionable. |

<Tip>
Scope the PagerDuty webhook to the services you want investigated, not the whole account. Fewer, relevant events make each RCA faster to read.
</Tip>

## What CloudThinker does with the events

| Step | What happens |
|------|--------------|
| **Receive** | Resolve accepts the event and returns `202 Accepted` to PagerDuty |
| **Group** | Pulse drops noise and groups related signals, so repeat events for one incident stay together |
| **Open** | An actionable group becomes an incident on **Resolve → Investigation** |
| **Investigate** | With **Auto-investigate** on and **On duty** on, CloudThinker starts an RCA using your other connections |

By event type:

| PagerDuty event | What Resolve does |
|-----------------|-------------------|
| `incident.triggered` | Opens a declared incident (signed webhook) and can start an RCA |
| `incident.acknowledged` | Treated like a triggered event and grouped with it, so the same incident stays together |
| `incident.resolved` | Received and grouped as a signal. It doesn't close the Resolve incident, so close that in Resolve. |

See [Webhook signals](/guide/incident/webhook-integrations/overview) for every **Auto-investigate** option, including a minimum severity.

### Verify the connection

Trigger a test incident on a non-production PagerDuty service, then check two places:

1. **Resolve → Pulse** shows a signal with the PagerDuty incident title, the right severity, and the service.
2. **Resolve → Investigation** shows the incident. With **Auto-investigate** and **On duty** both on, it shows **AI is handling**.

**Success state:** both appear within a minute or two. Resolve the test incident in PagerDuty when you're done.

## Troubleshooting

<Accordion title="PagerDuty reports failed deliveries with 401 or 403">
The signature check failed. **Check:** that you pasted the PagerDuty signing secret into **Provider signing secret**, not the CloudThinker secret, and that **HMAC Signature Header** is `X-PagerDuty-Signature`. **Fix:** copy the secret from the PagerDuty webhook again, edit the CloudThinker webhook, paste it, and click **Save**.
</Accordion>

<Accordion title="Every PagerDuty incident arrives as medium">
The incident has no priority, or the value isn't in **Severity Mapping**. **Fix:** set priorities in PagerDuty, or edit the webhook and add a mapping row for the value PagerDuty sends.
</Accordion>

<Accordion title="Signals arrive without a service">
**Service Path** still has the preset value `event.data.service.name`, which PagerDuty v3 events don't carry. **Fix:** edit the webhook and set **Service Path** to `event.data.service.summary`.
</Accordion>

<Accordion title="The signal is in Pulse but no RCA started">
**Auto-investigate** is off, the severity is below its minimum, or **On duty** shows **Paused**. **Fix:** check all three, or start the investigation by hand. See [Resolve settings](/guide/incident/settings).
</Accordion>

## Security

- **Signed events only.** Keep **HMAC Signature** on so Resolve rejects any event that isn't signed with your PagerDuty secret.
- **Rotate both sides.** When you regenerate the signing secret in PagerDuty, paste the new value into **Provider signing secret** right away. Events fail until you do.
- **Delete when done.** Delete the webhook in PagerDuty and in **Resolve → Integrations** when you stop using it. Deleting only the CloudThinker side leaves PagerDuty sending events that fail.

Connect Glean so CloudThinker can search company documents and people, then read one. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Glean account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create a Glean Client API token using the vendor's token administration procedure. See the [vendor's authentication documentation](https://docs.glean.com/administration/developer/api-tokens) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Glean**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Enter the instance name before `-be.glean.com`. A global token also needs an Act as user whose permissions should apply.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Instance name** | Yes | The part before -be.glean.com in your Glean API address, for example acme. |
| **Client API token** | Yes | Enter client api token. |
| **Act as (global tokens only)** | No | For a global token, the email of the user whose permissions results follow. Leave empty for a user token. |

## Required permissions

The token needs search, document, and entity access. Results follow the token's user permissions.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Document search | Search connected company content. |
| Document access | Read a selected document. |
| People search | Find people visible to the acting user. |

The connection is read-only. It does not create, edit, pin, or share source documents.

This connection is read-only. Make changes in Glean.

### Verify the connection

```text
Inspect my Glean connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Glean to search company documents and people, then read one.
Summarize the highest-priority items visible through my Glean connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Glean. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Glean when access is no longer needed, and update the connection after rotation.

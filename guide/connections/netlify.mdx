Connect Netlify to let CloudThinker agents list your teams and projects, find failed or stale deploys, audit Netlify Forms, and read extensions, plus start a deploy or change project settings after you approve. The connection uses one Netlify **personal access token**, which carries the same access as the user who created it.

---

## Prerequisites

- A Netlify account that belongs to the teams you want to investigate.
- Access to that account's Netlify user settings, to create a token.

---

## Setup

<Steps>
  <Step title="Create a personal access token in Netlify">
    In Netlify, open your **User settings** and go to **OAuth applications → Personal access tokens**. Create a token:
    - **Description**: `cloudthinker`
    - **Expiration**: pick a date and put the rotation on your calendar

    Copy the token now. Netlify shows it only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Go to **Connections → Netlify**, paste the token into **Personal access token**, and click **Connect**. CloudThinker checks the token with Netlify before it saves the connection.

    **Success state:** Netlify shows a **Connected** status with the message `Netlify account verified. Sites: <count>.`
  </Step>
</Steps>

---

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Personal access token** | Netlify personal access token for the team whose projects CloudThinker should inspect | Secret, not shown |

---

## Required permissions

Netlify tokens have no scopes. A token can do everything its user can do, in every team that user belongs to. Least privilege comes from the account you create the token with.

| Agents can | Needs |
|------------|-------|
| Read teams, projects, deploys, forms, and extensions | A user who belongs to those teams |
| Start deploys, create projects, change settings, form submissions, environment variables, or extensions | A user whose team role allows it, plus your approval in CloudThinker |

<Tip>
Create the token from a dedicated Netlify user that belongs only to the teams CloudThinker needs, with the lowest team role that can read projects and deploys. Avoid using an Owner account.
</Tip>

## Agent capabilities

| Capability | Description |
|------------|-------------|
| **Account and teams** | Read the signed-in user, list teams, and inspect one team |
| **Projects** | List projects and read a project's settings, URL, and current deploy |
| **Deploy health** | Find failed, stale, and unhealthy deploys, and show which deploy is live in production |
| **Forms** | List the forms on each project and what they collect |
| **Extensions** | List extensions and read their details |
| **Changes** | Upload and start deploys, create projects, change project settings, manage form submissions and environment variables, and change extension state, each with approval |

Any Netlify call that isn't a read waits for approval. Before it runs, CloudThinker states the effect and the exact inputs.

### Verify the connection

```text
Check my Netlify connection: list my teams and projects with each project's current deploy state
```

### Example prompts

```text
Which Netlify projects have a failed or stale production deploy, and what should I fix first?
Audit Netlify Forms across my projects and tell me which ones collect submissions
Show the build settings and current deploy for my marketing site on Netlify
```

## Troubleshooting

<Accordion title="Netlify personal access token is invalid or expired.">
Netlify rejected the token while CloudThinker was saving the connection. Create a new token in **User settings → OAuth applications** and connect again.
</Accordion>

<Accordion title="Failed to get Netlify token (during an agent run)">
The connection no longer holds a working token, for example because it expired. Create a new token and update the connection.
</Accordion>

<Accordion title="404 for a project or deploy">
The ID is wrong, or the token's user can't see that project. Ask CloudThinker to list your projects first. If the project is missing, add the user to the team that owns it, or create the token from a user who already belongs to it.
</Accordion>

<Accordion title="Netlify API rate limit reached. Retry later.">
Netlify throttled the requests. Wait a few minutes, then ask about one team or project at a time so each run makes fewer calls.
</Accordion>

<Accordion title="A change was requested but never ran">
Changes wait for your approval. If you rejected it, CloudThinker won't retry. Ask again when you want it to run.
</Accordion>

## Security

<ConnectionSecurity />

- **Plan rotation**: Netlify tokens don't rotate on their own. Set an expiration when you create one and replace it before that date.
- **Review environment variable changes**: approving one can expose or overwrite a secret. Read the variable name and value before you approve.

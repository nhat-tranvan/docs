Connect Netlify to let CloudThinker agents list your teams and projects, find failed or stale deploys, audit Netlify Forms, and read extensions, plus start a deploy or change project settings through your [Approvals](/guide/approvals/overview). The connection uses one Netlify **personal access token**, which carries the same access as the user who created it. Netlify now calls sites **projects**, so this page does too.

---

## Prerequisites

- A Netlify account that belongs to the teams you want to investigate.
- Access to that account's Netlify user settings, to create a token.
- A CloudThinker workspace where you can add connections.

---

## Setup

<Steps>
  <Step title="Create a personal access token in Netlify">
    In Netlify, go to **User settings → Applications → Personal access tokens** ([direct link](https://app.netlify.com/user/applications#personal-access-tokens)). Create a token:
    - **Description**: `cloudthinker`
    - **Expiration**: a fixed lifetime, such as 90 days, rather than no expiration. Put the rotation on your calendar.

    Copy the token now. Netlify shows it only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    In the sidebar, click **More → Workspace settings → Connections**. On the **Builtin Connections** tab, search for **Netlify**, paste the token into **Personal access token**, and click **Connect**. CloudThinker checks the token with Netlify before it saves the connection.

    **Success state:** the Netlify card shows **Connected** with the message `Netlify account verified. Sites: <count>.` Netlify renamed sites to projects, so the count is your projects.
  </Step>
  <Step title="Run the verify prompt (optional)">
    Run the [verify prompt](#verify-the-connection) in a new chat.

    **Success state:** CloudThinker lists your teams and projects with each project's current deploy state.
  </Step>
</Steps>

## Connection details

| Field | Description |
|-------|-------------|
| **Personal access token** | Netlify personal access token. It reaches every team its user belongs to. |

---

## Required permissions

Netlify tokens have no scopes. A token can do everything its user can do, in every team that user belongs to. Least privilege comes from the account you create the token with.

| Agents can | Needs |
|------------|-------|
| Read teams, projects, deploys, forms, and extensions | A user who belongs to those teams |
| Start deploys, create projects, change settings, form submissions, environment variables, or extensions | A user whose team role allows it, plus a pass through your Approvals in CloudThinker |

<Tip>
Create the token from a dedicated Netlify user that belongs only to the teams CloudThinker needs, with the lowest team role that can read projects and deploys. Avoid using an Owner account.
</Tip>

## Agent capabilities

| Capability | What CloudThinker does | Checked by Approvals |
|------------|------------------------|----------------|
| **Account and teams** | Reads the signed-in user, lists teams, and inspects one team | No |
| **Projects** | Lists projects and reads a project's settings, URL, and current deploy | No |
| **Deploy health** | Finds failed, stale, and unhealthy deploys, and shows which deploy is live in production | No |
| **Forms** | Lists the forms on each project and what they collect | No |
| **Extensions** | Lists extensions and reads their details | No |
| **Deploys** | Starts a deploy | Yes |
| **New projects** | Creates a project | Yes |
| **Project settings** | Changes a project's settings | Yes |
| **Form submissions** | Manages a form's submissions. This can change or remove submission data. | Yes |
| **Environment variables** | Sets or changes a project's environment variables. This can overwrite a secret. | Yes |
| **Extension state** | Changes an extension's state | Yes |

Any Netlify call that isn't a read goes through Approvals.

<ApprovalDefault />

When a person approves, CloudThinker states the effect and the exact inputs first. Read them closely for form submissions and environment variables, since those changes can lose data.

### Verify the connection

```text
Check my Netlify connection: list my teams and projects with each project's current deploy state
```

### Example prompts

```text
Which Netlify projects have a failed or stale production deploy, and what should I fix first?
Audit Netlify Forms across my projects and tell me which ones collect submissions
Show the build settings and current deploy for my marketing site on Netlify
```

## Troubleshooting

<Accordion title="Netlify personal access token is invalid or expired.">
Netlify rejected the token while CloudThinker was saving the connection. Create a new token in **User settings → Applications → Personal access tokens** and connect again.
</Accordion>

<Accordion title="Failed to get Netlify token (during an agent run)">
The connection no longer holds a working token, for example because it expired. Create a new token, then open the connection, click the edit icon on the instance, click **Replace…** in **Edit Instance**, paste the token, and click **Save and test**. See [Rotate a credential](/guide/connections/overview#rotate-a-credential).
</Accordion>

<Accordion title="404 for a project or deploy">
The ID is wrong, or the token's user can't see that project. Ask CloudThinker to list your projects first. If the project is missing, add the user to the team that owns it, or create the token from a user who already belongs to it.
</Accordion>

<Accordion title="Netlify API rate limit reached. Retry later.">
Netlify throttled the requests. Wait a few minutes, then ask about one team or project at a time so each run makes fewer calls.
</Accordion>

<Accordion title="A change was requested but never ran">
Changes go through your Approvals. If a person rejected one, CloudThinker won't retry. Ask again when you want it to run.
</Accordion>

## Security

<ConnectionSecurity />

- **Plan rotation**: Netlify tokens don't rotate on their own. Set an expiration when you create one and replace it before that date.
- **Review environment variable changes**: approving one can expose or overwrite a secret. Read the variable name and value before you approve.
- **Treat form data as sensitive**: form submissions often hold personal data, so treat what agents report about them the same way.

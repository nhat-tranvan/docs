Connect Monte Carlo so CloudThinker can investigate data alerts, tables, lineage, and monitors. The connection uses the credentials described below, with access limited by the account behind it.

## Prerequisites

- Access to the Monte Carlo account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    In Monte Carlo, open Settings → API Keys → Add. Choose the MCP server key type and copy both Key ID and Key secret.

    See the [Monte Carlo documentation](https://docs.getmontecarlo.com/docs/mcp-server) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Monte Carlo**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Key ID** | Yes | Use the key id prepared in the credential step. |
| **Key secret** | Yes | Shown once when the MCP server key is created. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

Use an account whose Monte Carlo permissions reach the datasets and monitors you need. MCP server keys are distinct from standard API keys.

<Tip>
Start with read access to the smallest useful scope. Read access is sufficient for investigation. Add only the permissions needed for alert status or ownership changes if you intend to approve those actions.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Data incidents and monitors** | Investigate data alerts, tables, lineage, and monitors. |
| **Dataset health and lineage** | Inspect dataset health and lineage within the connected account’s scope. |
| **Data-quality investigation** | Inspect data-quality investigation within the connected account’s scope. |

A standard Monte Carlo API key does not work with this connection. Create an MCP server key even if you already have another API key.

Read workflows inspect alerts and their context. Updating an alert status or assigning its owner changes Monte Carlo and follows your [Approvals](/guide/approvals/overview) settings. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Monte Carlo connection, summarize its account or service scope and data incidents and monitors. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize data incidents and monitors in Monte Carlo and highlight items needing attention.
Review dataset health and lineage and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

<ConnectionSecurity />

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

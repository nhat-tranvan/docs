Connect Microsoft Sentinel so CloudThinker can review incidents, alerts, and entities; run hunting queries. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Microsoft Sentinel account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create a Microsoft Entra app registration and client secret for the Azure workspace containing Sentinel. See the [vendor's authentication documentation](https://learn.microsoft.com/en-us/azure/sentinel/roles) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Microsoft Sentinel**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Supply the subscription, resource group, and Log Analytics workspace name, and choose the matching Azure cloud.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Directory (tenant) ID** | Yes | Enter directory (tenant) id. |
| **Application (client) ID** | Yes | Enter application (client) id. |
| **Client secret** | Yes | A secret of an Entra app registration. Grant the app Microsoft Sentinel Reader, or Microsoft Sentinel Responder to update incidents, plus Log Analytics Reader on the workspace. |
| **Subscription ID** | Yes | The Azure subscription that holds the workspace. |
| **Resource group** | Yes | The resource group that holds the workspace. |
| **Log Analytics workspace name** | Yes | The workspace where Microsoft Sentinel is enabled. |
| **Cloud** | Yes | The Azure cloud that hosts your tenant. Options: **Azure public**, **Azure US Government**, **Azure China, 21Vianet**. Default: `AzureCloud`. |

## Required permissions

Assign Microsoft Sentinel Reader plus Log Analytics Reader for investigation. Incident changes require Microsoft Sentinel Responder.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Incident triage | Read incidents, alerts, and entities. |
| Hunting | Run bounded read-only KQL queries. |
| Incident actions | Change supported incident fields or add a comment after approval. |

Incident actions and comments are supported after approval. Playbook execution, rule changes, connector changes, and incident deletion are excluded.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Microsoft Sentinel connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Microsoft Sentinel to review incidents, alerts, and entities; run hunting queries.
Summarize the highest-priority items visible through my Microsoft Sentinel connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Microsoft Sentinel. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Microsoft Sentinel when access is no longer needed, and update the connection after rotation.

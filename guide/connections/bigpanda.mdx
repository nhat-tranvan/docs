Connect BigPanda to let CloudThinker explore environments, correlated incidents, and alerts. The connection uses **a BigPanda bearer token**.

## Prerequisites

- An account with access to the BigPanda resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in BigPanda">
    Ask your BigPanda administrator for the token type required by the incident and environment APIs in your account. BigPanda supports organization tokens and user API keys; their endpoint support differs. Use the official authentication guide to choose the credential, and select the account’s region.

    Follow the [vendor’s credential and authentication guidance](https://docs.bigpanda.io/en/authentication-and-headers) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **BigPanda**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **BIGPANDA_API_TOKEN** | Yes | Use the value supplied for this connection. |
| **BIGPANDA_REGION** | Yes | Use the value supplied for this connection. Choose **US (api.bigpanda.io)**, **EU (eu-api.bigpanda.io)**. Default: **US (api.bigpanda.io)**. |
| **BIGPANDA_ENVIRONMENT_ID** | Optional | Use the value supplied for this connection. |

Use the same region as the account. If the environment filter is empty, discovery uses the scope available to the credential.

## Required permissions

Read access to the environments, incidents, and correlated alerts being investigated. The connector’s investigations are read-only. An environment filter narrows investigation scope; it does not grant permission to that environment.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | List environments and active incidents |
| Investigation | Inspect correlated alerts for an incident |
| Investigation | Read an incident timeline and affected services |

### Verify the connection

```text
Discover BigPanda environments and summarize open incidents with their correlated alerts. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Discover BigPanda environments and summarize open incidents with their correlated alerts
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. Use the same region as the account. If the environment filter is empty, discovery uses the scope available to the credential.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

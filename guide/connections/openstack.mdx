Connect your OpenStack cloud to let CloudThinker agents inventory servers, volumes, networks, images, flavors, and quotas, flag waste and open security groups, and make changes after approval. The connection signs in to Keystone (the OpenStack Identity service) with a **user name and password**, scoped to one project in one region.

## Prerequisites

- An OpenStack cloud whose Keystone v3 address CloudThinker can reach over the network. Use an `https` address.
- A **dedicated Keystone user** with a role on the project you want inspected. See [Required permissions](#required-permissions).
- The project name, the domain names of the user and the project, and the region.

<Info>
A workspace holds one OpenStack connection, and it covers one project in one region. The connection uses a user name and password. Federated sign-in and application credentials are not supported.
</Info>

## Setup

<Steps>
  <Step title="Find your sign-in values">
    Download the **openrc** file for your project from the OpenStack dashboard, or ask your cloud administrator. It lists the auth URL, project name, user name, domain names, and region, using the same `OS_*` names as the CloudThinker form.
  </Step>
  <Step title="Create or choose a Keystone user">
    Use a dedicated user for CloudThinker and give it the `reader` role on the project. You can widen the role later if you want agents to make changes.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar, select **OpenStack**, and fill in the fields from [Connection details](#connection-details). Leave the five endpoint override fields blank unless your service catalog is incomplete. Click **Connect**.

    **Success state:** the connection shows **Testing**, then a **Connected** status. CloudThinker requests a token from Keystone to prove the credentials work.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **OS_AUTH_URL** | Keystone v3 address. The path ends in `/v3` | `https://openstack.example.com:5000/v3` |
| **OS_USERNAME** | Keystone user name | `cloudthinker` |
| **OS_PASSWORD** | Password of that user | |
| **OS_PROJECT_NAME** | Project every request is scoped to | `production` |
| **OS_USER_DOMAIN_NAME** | Domain that holds the user. Defaults to `Default` | `Default` |
| **OS_PROJECT_DOMAIN_NAME** | Domain that holds the project. Defaults to `Default` | `Default` |
| **OS_REGION_NAME** | Region in your service catalog. Letters, digits, `_`, and `-`, up to 64 characters. Defaults to `RegionOne` | `RegionOne` |
| **OS_INTERFACE** | **Public endpoint** (default), **Internal endpoint**, or **Admin endpoint** | **Public endpoint** |
| **OS_VERIFY_SSL** | **Verify SSL certificate** (default) or **Skip SSL verification** | **Verify SSL certificate** |

Five optional fields bypass the Keystone catalog for one service each: **OS_IMAGE_ENDPOINT_OVERRIDE** (Glance), **OS_COMPUTE_ENDPOINT_OVERRIDE** (Nova), **OS_NETWORK_ENDPOINT_OVERRIDE** (Neutron), **OS_VOLUMEV3_ENDPOINT_OVERRIDE** (Cinder), and **OS_PLACEMENT_ENDPOINT_OVERRIDE** (Placement). Each takes a full `http` or `https` URL.

<Warning>
There is no field for a custom certificate authority. For a cloud with a self-signed certificate, **Skip SSL verification** is the only way to connect, and it removes protection against someone impersonating your cloud. Use it for lab clouds only. **Internal endpoint** works only if CloudThinker can reach your control-plane network.
</Warning>

## Required permissions

Keystone ships three default roles: `admin`, `member`, and `reader`. OpenStack describes `reader` as read-only access within a project, and `member` includes `reader`.

| You want agents to | Role on the project |
|--------------------|---------------------|
| Inventory and audit the project | `reader` |
| Stop, reboot, resize, or delete resources | `member`, or the narrowest role your cloud's policies accept |
| Answer questions across all projects | Usually `admin`. Without it, OpenStack returns `403 Forbidden` |

<Tip>
Start with `reader`. Default policies may hide some sensitive details from it, so check what your cloud returns before you rely on it for an audit.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **Inventory** | List servers, volumes, networks, subnets, images, flavors, projects, and the service catalog, and inspect one in detail |
| **Idle and unused** | Find under-used servers worth right-sizing and unattached volumes |
| **Quotas** | Show quota use for instances, cores, RAM, volumes, gigabytes, and networks, and flag anything above 80% |
| **Capacity** | Review flavors and, where your role allows, hypervisors |
| **Network drift** | Flag security group rules open to `0.0.0.0/0` |
| **Approved changes** | Stop, reboot, resize, or delete servers, and delete volumes, images, or networks |

Reads run without asking. Every change goes through [Approvals](/guide/approvals/overview) first.

### Verify the connection

```text
Summarize my OpenStack project: servers, volumes, networks, images, and quota use
```

Expect counts for each resource type and quota use for the project, with any quota above 80% called out.

### Example prompts

```text
Which volumes are unattached, and how large is each one?
Which security group rules allow traffic from 0.0.0.0/0?
Which quotas in my project are above 80% used?
```

## Troubleshooting

<Accordion title="Failed to connect to OpenStack">
Keystone did not issue a token. Check the user name, password, project name, and both domain names. Confirm the address is reachable from CloudThinker and the user has a role on the project. A certificate CloudThinker doesn't trust also fails here unless **Skip SSL verification** is selected.
</Accordion>

<Accordion title="OS_AUTH_URL must be a Keystone v3 URL">
The address doesn't end in `/v3`, or it contains credentials, a query string, or a fragment. Copy `OS_AUTH_URL` from your openrc file.
</Accordion>

<Accordion title="OS_REGION_NAME must contain only letters, digits, '_', '-' (max 64 chars)">
The region has a space or another character. Copy the region name exactly as it appears in your service catalog.
</Accordion>

<Accordion title="An endpoint override must be an http(s) URL with a host">
An optional override field holds something other than a full URL. The message names the field. Enter a URL such as `https://image.example.com`, or clear the field.
</Accordion>

<Accordion title="Invalid OpenStack connection configuration">
**OS_AUTH_URL** is empty. Enter your Keystone v3 address and connect again.
</Accordion>

<Accordion title="403 Forbidden on a question across projects">
Cross-project questions usually need the `admin` role. Ask about your own project, or grant the user that role.
</Accordion>

## Security

<ConnectionSecurity />

- **Use an https address**: CloudThinker accepts an `http` Keystone address, but your password then travels unencrypted.
- **Keep certificate checks on**: reserve **Skip SSL verification** for lab clouds with self-signed certificates.

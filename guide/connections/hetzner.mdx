Connect Hetzner Cloud so CloudThinker can review servers, volumes, resource usage, and potential idle cloud spend. The connection uses a project-scoped API token.

## Prerequisites

- Access to the Hetzner Cloud account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Open the intended project in Hetzner Console, then **Security → API tokens**. Generate a token with **Read** permission for investigations. Choose **Read & Write** only when you intend to let CloudThinker change resource delete protection. Copy the token after creating it.

    See the [provider documentation](https://docs.hetzner.com/cloud/api/getting-started/generating-api-token/) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Hetzner Cloud**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **API token** | Token from the intended Hetzner Cloud project. | Copy from Hetzner Console |

## Required permissions

Read permission covers project inventory and investigations. The token is tied to one project; create separate CloudThinker connections for other projects. Read & Write is required only for the supported protection changes and is broader than the read-only investigation needs.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Project inventory** | Review servers and related volumes and network resources. |
| **Idle candidates** | Identify stopped or apparently idle resources for further review. |
| **Protection** | Inspect delete-protection settings before proposing changes. |

An idle candidate is a review suggestion, not proof that deleting it is safe. The investigation covers the connected project. The connection does not turn a resource inventory into a complete billing statement.

With a Read & Write token, agents can change the supported resource delete-protection setting through [Approvals](/guide/approvals/overview). Confirm the exact resource and desired protection value before approving.

### Verify the connection

```text
List the Hetzner servers and volumes in this project and identify which inventory reads succeeded
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Find stopped Hetzner servers and explain which resources still need a cost review
Show delete-protection settings for the selected server without changing them
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Resources from another project are missing">
Hetzner API tokens are project-scoped. Select a connection for the correct project or create a separate connection with that project’s token.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

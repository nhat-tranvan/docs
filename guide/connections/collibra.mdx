Connect Collibra so CloudThinker can search governed assets, domains, and data issues. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Collibra account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain a Collibra OAuth client ID and secret for an integration permitted to view the catalog. See the [vendor's authentication documentation](https://developer.collibra.com/api) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Collibra**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use your Collibra environment URL, not a link to a particular asset.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Collibra URL** | Yes | Your environment address, for example https://acme.collibra.com. |
| **OAuth client ID** | Yes | Enter oauth client id. |
| **OAuth client secret** | Yes | Enter oauth client secret. |

## Required permissions

View the assets, domains, and data issues CloudThinker should inspect.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Asset search | Search governed catalog assets. |
| Domain context | Inspect domains. |
| Data issues | Review catalog issues without resolving them. |

The connection is read-only. It cannot edit assets, update statuses, or resolve issues.

This connection is read-only. Make changes in Collibra.

### Verify the connection

```text
Inspect my Collibra connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Collibra to search governed assets, domains, and data issues.
Summarize the highest-priority items visible through my Collibra connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Collibra. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Collibra when access is no longer needed, and update the connection after rotation.

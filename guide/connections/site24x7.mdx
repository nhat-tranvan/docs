Connect Site24x7 so CloudThinker can review monitor status, outages, and scheduled maintenance. The connection uses Zoho OAuth client credentials and a refresh token.

## Prerequisites

- Access to the Site24x7 account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Create a **Self Client** in the Zoho API Console for the same data center as the Site24x7 account. Follow Site24x7’s OAuth instructions to obtain a refresh token for `Site24x7.Reports.Read` and `Site24x7.Admin.Read`. Keep the matching client ID and client secret; an access token alone is not a refresh token.

    See the [provider documentation](https://www.site24x7.com/help/api/) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Site24x7**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Data center** | Location of the Site24x7 account. The default is us. | us, eu, in, au, cn, jp, ca, uk, ae, or sa |
| **Client ID** | ID of the matching Zoho Self Client. | Copy from Zoho API Console |
| **Client secret** | Secret of that same client. | Enter in the connection form |
| **Refresh token** | OAuth refresh token with the intended Site24x7 scopes. | Copy after OAuth authorization |

## Required permissions

Read investigations need `Site24x7.Reports.Read` and `Site24x7.Admin.Read`. Add `Site24x7.Admin.All` only if agents should suspend monitors or schedule maintenance after approval. The client, refresh token, and data center must belong together.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Monitor health** | Review monitor status and availability summaries. |
| **Outages** | Inspect recent outage details for one monitor. |
| **Maintenance** | Review maintenance context before a requested change. |

A returned monitor list is a bounded selection. A failed read is not an empty account or a healthy monitor. Before repeating an uncertain maintenance change, inspect the current provider state.

Suspending a monitor and scheduling supported maintenance require the matching OAuth permission and [Approvals](/guide/approvals/overview). State the monitor or maintenance target and intended duration before approving.

### Verify the connection

```text
Summarize Site24x7 monitor status and recent outages, including any failed reads or permission gaps
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Investigate the latest outage for the selected Site24x7 monitor
Show monitors currently unavailable and their most recent outage details
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Refresh token cannot obtain access">
Check Data center, Client ID, Client secret, and Refresh token were issued together. Regenerate authorization for the same data center if the token was revoked or its scopes are insufficient.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

Connect Zscaler so CloudThinker can review internet-access policy and private-access connector health. The connection uses a ZIdentity API client.

## Prerequisites

- Access to the Zscaler account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your Zscaler administrator to create a ZIdentity API client with read access to the intended ZIA and, optionally, ZPA resources. Obtain its client ID and secret, the ZIdentity vanity name, and the ZPA customer ID if private-access inspection is needed.

    See the [provider documentation](https://github.com/zscaler/zscaler-mcp-server/blob/master/README.md) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Zscaler**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **ZIdentity vanity name** | Name before .zslogin.net in the organization’s sign-in address. | acme |
| **API client ID** | Identifier of the dedicated ZIdentity API client. | Copy from ZIdentity |
| **API client secret** | Secret paired with that client ID. | Enter in the connection form |
| **ZPA customer ID (optional)** | Customer identifier for ZPA; leave empty to inspect ZIA only. | Your ZPA customer ID |

## Required permissions

Grant read-only ZIA permissions for URL filtering, firewall rules, activation state, and locations. Add read-only ZPA access only for App Connectors, connector groups, and applications. The client needs the matching product entitlement as well as an appropriate product role.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Internet-access policy** | Read URL-filtering and firewall rules in evaluation order. |
| **Activation state** | Identify pending ZIA changes without activating them. |
| **Private-access health** | Review App Connector connection state, versions, and connector groups. |

This connection is read-only. It never edits policies, locations, or connectors and never activates pending changes. Omitting the ZPA customer ID skips ZPA inspection; it does not establish that the account has no connectors.

### Verify the connection

```text
Summarize ZIA policy and pending activation, then review ZPA connector health if a customer ID is configured
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Find overly permissive rules and disabled rules in the current ZIA policy
Review ZPA App Connectors that are disconnected or behind the expected version
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="ZIA works but ZPA is skipped or denied">
Enter ZPA customer ID (optional) to enable ZPA inspection. Confirm the API client has a read-only ZPA product role and entitlement for that customer.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

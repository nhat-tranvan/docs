Connect Akeyless so CloudThinker can audit secret inventory, rotation, and auth method expiry. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Akeyless account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    In Akeyless, create an API Key authentication method under Administration → Users & Auth Methods. Save its Access ID and Access Key. See the [vendor's authentication documentation](https://docs.akeyless.io/docs/auth-with-api-key) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Akeyless**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the Akeyless API endpoint or your gateway API address.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **API URL** | Yes | https://api.akeyless.io, or your gateway API address such as https://gw.example.com:8081. Default: `https://api.akeyless.io`. |
| **Access ID** | Yes | An API Key auth method (p-...) whose role can list items and auth methods. |
| **Access key** | Yes | The access key shown once when you create the API Key auth method. |

## Required permissions

The authentication method needs a role that can list items and authentication methods. Secret-value access is not required for inventory checks.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Secret inventory | List metadata without reading secret values. |
| Rotation health | Identify rotation failures and expiring certificates. |
| Authentication methods | Inspect access-method expiry and target metadata. |

This connection inspects metadata and expiry. It does not retrieve secret values or rotate credentials.

This connection does not provide mutation tools. Make changes in Akeyless.

### Verify the connection

```text
Inspect my Akeyless connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Akeyless to audit secret inventory, rotation, and auth method expiry.
Summarize the highest-priority items visible through my Akeyless connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Akeyless. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Akeyless advises against API-key authentication for production. This connection uses that method; check your organization's policy before connecting.
- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Akeyless when access is no longer needed, and update the connection after rotation.

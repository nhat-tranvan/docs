Connect a MySQL database to let CloudThinker agents inspect schemas, indexes, table health, and slow queries by running SQL against it. You give CloudThinker one connection URL (`MYSQL_URL`) for a dedicated database user, and agents can do exactly what that user's grants allow.

## Prerequisites

- A MySQL endpoint CloudThinker can reach over the network, such as self-hosted MySQL, Amazon RDS for MySQL, or Cloud SQL for MySQL. Agents connect from CloudThinker's managed sandbox, so `localhost` and private addresses resolve there, not on your network.
- An admin account that can run `CREATE USER` and `GRANT`.
- Performance Schema turned on if you want slow-query analysis. It's on by default in MySQL 5.7 and later.

## Setup

<Steps>
  <Step title="Create a dedicated user">
    Connect as an admin and create a user for CloudThinker. Replace `%` with the address range CloudThinker connects from if you want to pin it down.

    ```sql
    CREATE USER 'cloudthinker_readonly'@'%' IDENTIFIED BY '<secure-password>';
    ```
  </Step>
  <Step title="Grant read access">
    Grant read access to the database you want analyzed, plus the monitoring privileges agents need for sessions and query statistics:

    ```sql
    GRANT SELECT, SHOW VIEW ON your_database.* TO 'cloudthinker_readonly'@'%';
    GRANT PROCESS ON *.* TO 'cloudthinker_readonly'@'%';
    GRANT SELECT ON performance_schema.* TO 'cloudthinker_readonly'@'%';
    ```

    `GRANT` takes effect right away, so you don't need `FLUSH PRIVILEGES`. See [Required permissions](#required-permissions) to add replication checks.
  </Step>
  <Step title="Check Performance Schema">
    ```sql
    SHOW VARIABLES LIKE 'performance_schema';
    ```

    **Success state:** the value is `ON`. If it's `OFF`, set `performance_schema = ON` under `[mysqld]` in `my.cnf` and restart MySQL. On RDS or Cloud SQL, change it in the parameter group or database flags and reboot.
  </Step>
  <Step title="Open network access">
    Allow inbound connections on the MySQL port (default `3306`) from CloudThinker in your firewall, security group, or authorized networks list. A database that only listens on a private network needs a reachable endpoint first.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar, select **MySQL**, and click **Connect**. Paste the URL into **MYSQL_URL** and click **Connect**:

    ```text
    mysql://cloudthinker_readonly:<secure-password>@db.example.com:3306/your_database
    ```

    **Success state:** the connection shows **Testing**, then **Connected**. CloudThinker then runs a one-time, read-only [discovery](/guide/connections/overview) of the database.
  </Step>
</Steps>

## Connection details

| Field | Required | Description | Example |
|-------|----------|-------------|---------|
| **MYSQL_URL** | Yes | Full connection URL: user, password, host, port, and database | `mysql://cloudthinker_readonly:<password>@db.example.com:3306/shop` |

If the password contains `@`, `:`, `/`, or `#`, URL-encode it (for example, `@` becomes `%40`), or the URL won't parse.

## Required permissions

Grant only the rows you need.

| You want agents to | Grant |
|--------------------|-------|
| Read schemas, tables, and indexes | `SELECT, SHOW VIEW ON your_database.*` |
| See active sessions and running queries | `PROCESS ON *.*` |
| Find slow queries and index usage | `SELECT ON performance_schema.*` |
| Check replica status and lag | `REPLICATION CLIENT ON *.*` |

<Tip>
Keep the user read-only. Never grant `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, or `ALL PRIVILEGES` unless you have a workflow that needs writes. Even then, write statements go through [Approvals](/guide/approvals/overview), and a [rule](/guide/approvals/rules) can ask first or refuse them.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **Schema inspection** | List databases and tables, and read column types, keys, and table sizes |
| **Index review** | Find missing, unused, and redundant indexes |
| **Slow queries** | Rank statements by total and average latency from Performance Schema |
| **Table health** | Check row counts, data and index size, and free space per table |
| **Sessions and replication** | List running sessions and long queries, and check replica lag (needs `REPLICATION CLIENT`) |

### Verify the connection

```text
List the tables in the connected MySQL database with their row counts and sizes
```

Expect a table of names, approximate row counts, and data and index sizes. An error that names a missing privilege tells you which grant to add.

### Example prompts

```text
Which 10 queries spend the most total time on MySQL, and which indexes would help them?
Find indexes that haven't been used since the last restart
Is anything blocking right now? Show long-running sessions and what they're waiting on
```

## Troubleshooting

<Accordion title="Connection refused or timed out">
CloudThinker can't reach the host. Check that the host and port in **MYSQL_URL** are public or otherwise reachable, that your firewall or security group allows CloudThinker, and that `bind-address` in `my.cnf` isn't `127.0.0.1`. On RDS, the instance must be publicly accessible or reachable through your network setup.
</Accordion>

<Accordion title="Access denied for user">
The user, password, or host part doesn't match. A user created as `'cloudthinker_readonly'@'localhost'` can't sign in remotely, so create it with `'%'` or CloudThinker's address range. Also check the password is URL-encoded in **MYSQL_URL**.
</Accordion>

<Accordion title="SELECT command denied, or no slow-query data">
The user lacks a grant for what the agent tried. For slow queries, grant `SELECT ON performance_schema.*` and confirm `SHOW VARIABLES LIKE 'performance_schema'` returns `ON`. Performance Schema statistics reset on restart, so a freshly restarted server has little history.
</Accordion>

<Accordion title="Unknown database">
The database name at the end of **MYSQL_URL** doesn't exist or the user can't see it. Run `SHOW DATABASES;` as that user and fix the name.
</Accordion>

## Security

<ConnectionSecurity />

- **Scope grants to one database**: grant `SELECT` on `your_database.*`, not `*.*`, so agents can't read the `mysql` system schema or other apps' data.
- **Require TLS on the server**: set `REQUIRE SSL` on the user (`ALTER USER ... REQUIRE SSL`) when your server supports it, so credentials and results are encrypted in transit.

Connect Chef Infra so CloudThinker can check node convergence, cookbook pins, and environments. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Chef Infra account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain an existing Chef client or user identity and its PEM private key. Requests are signed with the key. See the [vendor's authentication documentation](https://docs.chef.io/server/api_chef_server/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Chef Infra**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the organization-specific Chef Server URL, including `/organizations/<organization>` when applicable.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Chef Server URL** | Yes | The chef_server_url from knife config, for example https://chef.example.com/organizations/acme |
| **Client name** | Yes | A Chef client or user that can read nodes, environments, cookbooks, and roles. |
| **Client key** | Yes | The PEM private key of that client. Requests are signed with it; it is never sent. |

## Required permissions

Read nodes, environments, cookbooks, and roles in the selected Chef organization.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Node convergence | Inspect node health and run-list context. |
| Cookbook pins | Review cookbook versions. |
| Environment context | Read environments and roles. |

The connection is read-only. It cannot edit a run list or trigger a chef-client run.

This connection is read-only. Make changes in Chef Infra.

### Verify the connection

```text
Inspect my Chef Infra connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Chef Infra to check node convergence, cookbook pins, and environments.
Summarize the highest-priority items visible through my Chef Infra connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Chef Infra. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Chef Infra when access is no longer needed, and update the connection after rotation.

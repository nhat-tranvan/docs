Connect Microsoft Defender for Cloud so CloudThinker can review secure score, recommendations, and security alerts. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Microsoft Defender for Cloud account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create or select a Microsoft Entra app registration. Copy its tenant ID and application ID, and create a client secret. See the [vendor's authentication documentation](https://learn.microsoft.com/en-us/azure/defender-for-cloud/permissions) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Microsoft Defender for Cloud**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose the Azure cloud matching your tenant. Use the secret's value rather than its identifier.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Directory (tenant) ID** | Yes | Enter directory (tenant) id. |
| **Application (client) ID** | Yes | An app registration with the Security Reader role on each subscription or management group. |
| **Client secret** | Yes | Enter client secret. |
| **Cloud** | Yes | Options: **Azure (global)**, **Azure US Government**, **Azure China**. Default: `AzureCloud`. |

## Required permissions

Assign the app Security Reader on the subscriptions or management groups to inspect.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Security posture | Review secure score and plan coverage. |
| Recommendations | Read unhealthy assessments. |
| Alert context | Review security alerts and resource associations. |

The connection is read-only. It cannot remediate recommendations, dismiss alerts, or change Defender plans.

This connection is read-only. Make changes in Microsoft Defender for Cloud.

### Verify the connection

```text
Inspect my Microsoft Defender for Cloud connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Microsoft Defender for Cloud to review secure score, recommendations, and security alerts.
Summarize the highest-priority items visible through my Microsoft Defender for Cloud connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Microsoft Defender for Cloud. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Microsoft Defender for Cloud when access is no longer needed, and update the connection after rotation.

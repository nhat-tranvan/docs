Connect Cisco IOS XE and NX-OS so CloudThinker can inspect interfaces, BGP peers, and CDP neighbors. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Cisco IOS XE and NX-OS account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Use a dedicated device login. Ask your network administrator to enable RESTCONF for IOS XE or NX-API for NX-OS before connecting. See the [vendor's authentication documentation](https://developer.cisco.com/docs/ios-xe/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Cisco IOS XE and NX-OS**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose the actual device platform. Use the HTTPS origin of the device and a trusted CA certificate.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Platform** | Yes | Options: **IOS XE**, **NX-OS**. Default: `ios-xe`. |
| **Device URL** | Yes | The HTTPS address of the device, such as https://switch1.example.com. RESTCONF (IOS XE) or NX-API (NX-OS) must be enabled. |
| **Username** | Yes | A device login. Read-only roles can inspect; changing an interface needs a role that can configure it. |
| **Password** | Yes | The password of that login. |
| **CA certificate (optional)** | No | PEM of the private CA that issued the device certificate. Leave empty to use public trust. The certificate and hostname are always checked. |

## Required permissions

Read interface, BGP, and neighbor state. Interface changes need device configuration permission in addition to CloudThinker approval.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Interface health | Inspect administrative state, links, errors, and descriptions. |
| Neighbor context | Read BGP and CDP relationships. |
| Interface changes | Change the state or description of one supported interface after approval. |

Changes affect running configuration only. Shutting an interface can interrupt traffic; saving startup configuration and device reloads are excluded.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Cisco IOS XE and NX-OS connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Cisco IOS XE and NX-OS to inspect interfaces, BGP peers, and CDP neighbors.
Summarize the highest-priority items visible through my Cisco IOS XE and NX-OS connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Cisco IOS XE and NX-OS. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Cisco IOS XE and NX-OS when access is no longer needed, and update the connection after rotation.

Connect Sonatype Nexus IQ Server so CloudThinker can review application policy results, violations, and risky software components. The connection uses a user token code and passcode, or dedicated-user credentials.

## Prerequisites

- Access to the Sonatype Nexus IQ Server account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to the provider API. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services). Access through your browser or local SSH tunnel alone is insufficient.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your IQ Server administrator to grant a dedicated user read access to the intended organizations and applications. Generate a user token for that user and copy its code and passcode. Record the full IQ Server URL, including an application path if your installation uses one.

    See the [provider documentation](https://help.sonatype.com/en/iq-server-user-tokens.html) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Sonatype Nexus IQ Server**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **IQ Server URL** | The server’s HTTPS address, including its application path when present. | https://iq.example.com |
| **User token code** | Code from the user token, or the dedicated username. | Copy from IQ Server |
| **User token passcode** | Passcode paired with the user token, or that user’s password. | Enter in the connection form |
| **CA certificate (optional)** | Private issuing CA certificate; empty uses public trust. | Leave empty for public trust |

## Required permissions

Give the user only View IQ Elements for the organizations being reviewed. Read access is sufficient for application and policy-result investigation. A token inherits its user’s visibility; applications outside that user’s scope will not appear.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Applications** | List applications and their available policy evaluation results. |
| **Policy violations** | Investigate violations for one application. |
| **Component risk** | Review risky package references and associated policy context. |

This connection is read-only. It does not waive violations, change policies, alter organization access, or trigger remediation. Evaluation results describe the scans available in IQ Server, not a new scan of the application.

### Verify the connection

```text
List the IQ Server applications this connection can read and show the latest available policy evaluation for one application
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Show critical policy violations for the selected IQ Server application
Identify the packages associated with the selected application’s highest-risk violations
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="User token is rejected">
The code and passcode must come from the same active user token. Ask the administrator to check expiry and regenerate the token if needed, then update both fields.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

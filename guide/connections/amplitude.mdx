Connect Amplitude so CloudThinker can track active users, event volumes, and trends. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Amplitude account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain the API key and secret key for the Amplitude project you want to investigate. See the [vendor's authentication documentation](https://amplitude.com/docs/apis/analytics/dashboard-rest) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Amplitude**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose the data region that owns your project; US and EU use different API hosts.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Data region** | Yes | Options: **US (amplitude.com)**, **EU (analytics.eu.amplitude.com)**. Default: `us`. |
| **API key** | Yes | Enter api key. |
| **Secret key** | Yes | Shown beside the API key on the same page. |

## Required permissions

Access to the selected project's analytics data. The connection uses the project's key pair.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Active users | Read project activity over a bounded window. |
| Event trends | Compare event counts and trends. |
| Project scope | Keep analysis within the connected project and region. |

The connection is read-only. It does not edit charts, cohorts, dashboards, or event taxonomy.

This connection is read-only. Make changes in Amplitude.

### Verify the connection

```text
Inspect my Amplitude connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Amplitude to track active users, event volumes, and trends.
Summarize the highest-priority items visible through my Amplitude connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Amplitude. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Amplitude when access is no longer needed, and update the connection after rotation.

Connect Splunk Enterprise Security so CloudThinker can investigate notable events, entity risk, and correlation searches. The connection uses a Splunk authentication token.

## Prerequisites

- Access to the Splunk Enterprise Security account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to the provider API. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services). Access through your browser or local SSH tunnel alone is insufficient.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your Splunk administrator for an authentication token associated with an Enterprise Security analyst account. Confirm the search head’s management hostname and port; they can differ from the Splunk Web address. Use the host running Enterprise Security rather than a generic ingestion endpoint.

    See the [provider documentation](https://help.splunk.com/en/splunk-enterprise-security-7/install/7.2/installation/configure-users-and-roles) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Splunk Enterprise Security**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Management host** | Search-head management hostname without scheme or port. | splunk.example.com |
| **Management port** | Management service port; default 8089. | 8089 |
| **Authentication token** | Token for the intended analyst account. | Enter in the connection form |
| **TLS certificate** | Whether to verify the certificate presented by Splunk. Keep verification enabled for trusted certificates. | true |

## Required permissions

The account needs access to Enterprise Security notable events, risk data, and correlation searches. The standard `ess_analyst` role is the usual starting point. Updating notable events additionally needs the `edit_notable_events` capability. Restrict index access to the investigation scope.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Notable events** | Review urgency, status, owner, and event context. |
| **Entity risk** | Inspect risk scores and contributing risk records. |
| **Detection context** | Review correlation-search context for an investigation. |

Splunk Web commonly uses a different port from the management service. Results describe the selected search window and visible indexes. A missing event can reflect index access or time-range selection rather than deletion.

Supported notable-event updates go through [Approvals](/guide/approvals/overview). Identify the notable event and exact status, owner, or other supported change before approving. Investigation reads do not alter event state.

### Verify the connection

```text
Summarize recent Splunk Enterprise Security notable events and entity risk, identifying unreadable indexes or searches
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Triage recent high-urgency notable events and show their owners and current statuses
Review risk records for the selected entity and summarize their contributing detections
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Splunk Web works but the connection cannot reach Splunk">
Check Management host and Management port with your administrator. The default management port is 8089, not the browser’s usual 8000 port. Confirm the network route permits that management service.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

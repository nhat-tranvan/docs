Connect Supabase to let CloudThinker agents review your projects, tables, migrations, branches, logs, and performance advisors, plus run SQL, apply migrations, and deploy Edge Functions after approval. Supabase connects with **OAuth** through Supabase's hosted MCP server (MCP is the protocol agents use to call a service's tools), so you don't create or paste an access token.

---

## Prerequisites

- A Supabase account that can see the organization and projects you want to investigate.
- The workspace Admin role in CloudThinker to add the connection. See [How access works](/guide/connections/overview#how-access-works).

---

## Setup

<Steps>
  <Step title="Open the Supabase connection">
    In CloudThinker, go to **Connections → Supabase** and click **Connect**.
  </Step>
  <Step title="Authorize CloudThinker in Supabase">
    CloudThinker opens Supabase in a new window. Sign in with the Supabase account that can access your projects, then approve access. If Supabase asks you to pick an organization, pick the one that owns the projects you want agents to reach. A wrong pick shows up later as a project agents can't find.

    If the window doesn't open, your browser blocked the pop-up. Click **Open Supabase** in the dialog instead.
  </Step>
  <Step title="Return to CloudThinker">
    The dialog closes on its own once the connection is ready.

    **Success state:** Supabase shows a **Connected** status.
  </Step>
  <Step title="Run the verify prompt">
    Run the [verify prompt](#verify-the-connection) to confirm the authorized account sees the projects you expect.

    **Success state:** CloudThinker lists your organizations and projects with their tables and migrations.
  </Step>
</Steps>

---

## Connection details

Supabase has no fields to fill in. Supabase issues OAuth tokens during authorization and CloudThinker stores them for you.

A workspace holds one Supabase connection. To use a different Supabase account, click **Disconnect** on the Supabase connection, then click **Connect** and sign in with the other account.

---

## Required permissions

CloudThinker gets the same access as the Supabase account you authorize, across every project that account can see. Supabase's own project scoping and read-only mode aren't available on this connection. To get close, authorize with an account that belongs only to the organizations agents should reach, and use Rules to block writes.

| Agents can | Needs |
|------------|-------|
| List organizations and projects; read tables, extensions, migrations, branches, logs, advisors, Edge Functions, and storage buckets | Access to the project in Supabase |
| Run SQL, apply migrations, deploy Edge Functions, manage branches, pause or restore a project, change storage settings | Write access in Supabase, plus a pass through [approvals](/guide/approvals/overview) |

### How writes are approved

Each change goes through your [Rules](/guide/approvals/rules) first, then your [Approval mode](/guide/approvals/approval-mode). New workspaces start on **Auto · Rules + AI · Ask me**, so a write no Rule covers is judged by AI, and anything it isn't sure about waits for a person. Pausing a project, deploying an Edge Function, and applying a migration to production are high-impact, so don't leave them to the mode:

- **Approve production writes**: add an **Ask first** Rule on the Supabase connection so a person reviews every SQL statement, migration, and deploy.
- **Make it effectively read-only**: add a **Deny** Rule on the Supabase connection that covers every operation. Rules never match reads, so reads keep working. Check **What would change** before you accept it.

## Agent capabilities

| Capability | Description |
|------------|-------------|
| **Project discovery** | List organizations and projects, get project details, and read current billing costs |
| **Database review** | List tables, installed Postgres extensions, and migrations |
| **Logs and advisors** | Read project logs and Supabase's performance advisors to trace errors and slow spots |
| **Branches** | List branches, and create, delete, merge, reset, or rebase one. Supabase branching needs a paid Supabase plan |
| **Edge Functions** | List and read Edge Functions, and deploy a new version |
| **Storage** | List storage buckets and read or update the storage configuration |
| **Types and keys** | Generate TypeScript types from the schema, and read the project API URL and publishable keys |
| **SQL and migrations** | Run a SQL query or apply a migration. CloudThinker shows the statement before it runs. |

Every change goes through [approvals](#how-writes-are-approved). If you decline, CloudThinker doesn't retry.

### Verify the connection

```text
Check my Supabase connection: list my organizations and projects with their tables and latest migrations
```

### Example prompts

```text
Show the errors in my production Supabase project logs from the last 24 hours and what's causing them
What do the performance advisors flag on my staging project, and which fixes matter most?
Compare the tables and migrations on my staging branch with production and list what differs
```

## Troubleshooting

<Accordion title="The authorization window closes but Supabase never shows Connected">
Your browser may be signed in to a different Supabase account, or the pop-up was blocked. Sign in to the right account in the same browser, then click **Connect** again.
</Accordion>

<Accordion title="Agents can't find a project you expect">
You authorized a Supabase account without access to that project, or the project is in another organization. Click **Disconnect**, then **Connect** with an account that can see it.
</Accordion>

<Accordion title="401 errors or an error status after it worked before">
The OAuth authorization expired or was revoked in Supabase. Click **Connect** in the error alert on the connection to authorize again.
</Accordion>

<Accordion title="A SQL statement or migration fails on a paused project">
Supabase pauses inactive projects on its free plan, and a paused project answers no SQL. Restore it in the Supabase dashboard, or ask CloudThinker to restore it (that's a change, so it needs approval), then run the statement again.
</Accordion>

<Accordion title="Permission denied on the auth or storage schema">
Supabase manages the `auth` and `storage` schemas itself, so a statement that alters their tables can fail with `permission denied`. Put your own tables and functions in `public` or a schema you create.
</Accordion>

## Security

<ConnectionSecurity />

- **Account-wide reach**: the connection reaches every project the authorizing account can see, including production. Your Supabase memberships are the real boundary.
- **Keys in answers**: agents can read a project's publishable keys and logs, and an app can print secrets into its own logs. Treat those answers as sensitive.

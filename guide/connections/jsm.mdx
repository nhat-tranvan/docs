Connect Jira Service Management (JSM) Operations to let CloudThinker agents triage alerts, see who's on call, and acknowledge, note, or escalate alerts during an incident. Operations is JSM's alerting and on-call product (formerly Opsgenie), and the connection signs in with an **Atlassian API token** plus the email of the account that owns it.

## Prerequisites

- A CloudThinker workspace on the **Scale** plan or above. On lower plans the button reads **Upgrade to Connect**.
- A JSM site with **Operations** turned on.
- An Atlassian account that can open Operations on that site, and its API token.
- Permission to manage connections in your CloudThinker workspace.

<Info>
This is separate from the [Atlassian](/guide/connections/atlassian) connection, which covers Jira issues and Confluence over OAuth. Atlassian only exposes Operations through an API token, so you need both connections for tickets and alerts.
</Info>

## Setup

<Steps>
  <Step title="Check that the account can open Operations">
    Sign in to your site with the account agents will use and confirm **Operations** appears in the JSM sidebar. Without it the connection fails, whatever the token can do.
  </Step>
  <Step title="Create an API token">
    Signed in as that account, go to [id.atlassian.com → Security → API tokens](https://id.atlassian.com/manage-profile/security/api-tokens), click **Create API token**, and label it `cloudthinker`. Copy it right away. Atlassian won't show it again.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Workspace Settings → Connections**, stay on the **Builtin Connections** tab, and select **Jira Service Management**. Fill in:

    - **Site URL**: your Atlassian site, such as `https://acme.atlassian.net`
    - **Account email**: the account that created the token
    - **API token**: the token you copied

    Click **Connect**.

    **Success state:** Jira Service Management shows a **Connected** status. Run the verify prompt below to confirm alerts come back.
  </Step>
</Steps>

<Warning>
An API token carries everything its account can do. Create it under a dedicated account on only the teams CloudThinker should touch, never under a site admin.
</Warning>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Site URL** | Your Atlassian site. A pasted project or board URL works too. | `https://acme.atlassian.net` |
| **Account email** | The Atlassian account the API token belongs to | `ops-bot@acme.com` |
| **API token** | Atlassian API token, not the account password | `<api-token>` |

## Required permissions

JSM scopes alerts and schedules by team, and the token inherits the account's access.

- **To read**: add the account to every team whose alerts and schedules agents should see.
- **To act**: the account needs permission in JSM to acknowledge, assign, add notes to, close, and escalate alerts on those teams.

<Tip>
Start with an account on just one or two teams. Widen it once you've seen how agents handle alerts there.
</Tip>

## Agent capabilities

| Capability | What agents can do | Approval |
|------------|--------------------|----------|
| **Alert triage** | List open alerts, read an alert's timeline, notes, and responders | No |
| **On-call** | See who's on call now across schedules and spot uncovered schedules | No |
| **Linked incident** | Read the JSM incident issue behind an alert | No |
| **Alert lifecycle** | Acknowledge, assign, add a note, or add a responder | Yes |
| **Close or escalate** | Close an alert, or escalate it to the next level | Yes, never approved by AI |

Closing can't be undone from CloudThinker, and escalating pages people. AI judgment never approves either one, so both wait for a person unless one of your [rules](/guide/approvals/rules) decides first. Other actions follow your [Approvals](/guide/approvals/overview) settings.

JSM actions are queued: Atlassian accepts them, then applies them a moment later. Agents wait for the result and never resend an action, so you won't get a double page.

### Use it with Resolve

Under **Resolve → Integrations → Jira Service Management**, JSM can send alerts to [Resolve](/guide/incident/overview) as a signal and run the **Keep the provider alert in step** outcome. With that outcome on, Resolve acknowledges the alert it's working, adds what it finds as alert notes, and pulls in a responder when nobody is on call. Closing or escalating still asks you first. See [Resolve integrations](/guide/incident/integrations).

### Verify the connection

```text
List open JSM alerts by priority and tell me who is on call right now
```

Expect a short list of alerts and the current on-call person for each schedule. An empty on-call list is a real answer: that schedule has no one covering it right now.

### Example prompts

```text
Which JSM alerts fired most often this week, and which teams own them?
Show the timeline of the open checkout-latency alert and who has touched it
Acknowledge the checkout-latency alert and add a note with the deploy that preceded it
```

The last prompt changes the alert, so it waits for approval first.

## Troubleshooting

<Accordion title="Account does not have access to Opsgenie">
The token works, but Operations isn't turned on for the site or the account can't open it. It isn't a token scope problem. Confirm **Operations** appears in the JSM sidebar for that account, then connect again.
</Accordion>

<Accordion title="Authentication failed (401)">
The token is wrong or revoked, or the email belongs to a different account. The email must be the account that created the token. Create a new token and edit the connection.
</Accordion>

<Accordion title="The site URL doesn't resolve">
Enter the Atlassian site address, such as `https://acme.atlassian.net`. A custom domain that doesn't point at an Atlassian site fails.
</Accordion>

<Accordion title="Some alerts are missing">
The account isn't on the team that owns them. Add it to that team in JSM, then ask again.
</Accordion>

<Accordion title="The button says Upgrade to Connect">
Your CloudThinker plan doesn't include Atlassian connections. They need the Scale plan or above. See [Pricing](/guide/billing/pricing).
</Accordion>

## Security

<ConnectionSecurity />

- **Dedicated account**: issue the token from an account made for CloudThinker, so revoking it never locks a person out.
- **Team scoping**: keep that account on only the teams agents should see and act on. The token can reach everything the account can.

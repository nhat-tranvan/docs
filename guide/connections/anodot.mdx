Connect Anodot Cloud Cost so CloudThinker can explore cloud cost, savings recommendations, and anomalies. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Anodot Cloud Cost account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Ask your Umbrella Cost administrator for a dedicated API user's username and password for the accounts you need to inspect. See the [vendor's authentication documentation](https://support.anodot.com/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Anodot Cloud Cost**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    This connector targets Umbrella Cost, formerly Anodot Cloud Cost. Use a password-enabled API user rather than an SSO-only login.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **API username** | Yes | The email of an Umbrella Cost (formerly Anodot Cloud Cost) user that signs in with a password, ideally a dedicated API user with read access to the accounts you want to analyze. |
| **Password** | Yes | That user's password. CloudThinker only reads costs, recommendations, and anomalies. |
| **Account ID** | No | Only when the user reaches several cloud accounts and you want one by default, for example 932213950603. Leave empty otherwise. |

## Required permissions

Read access to cloud accounts, cost data, recommendations, and anomalies.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Cloud spend | Inspect account cost data. |
| Recommendations | Read potential savings. |
| Anomalies | Review unexpected cost changes. |

The connection is read-only. It does not change budgets, alerts, anomalies, or recommendation statuses.

This connection is read-only. Make changes in Anodot Cloud Cost.

### Verify the connection

```text
Inspect my Anodot Cloud Cost connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Anodot Cloud Cost to explore cloud cost, savings recommendations, and anomalies.
Summarize the highest-priority items visible through my Anodot Cloud Cost connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Anodot Cloud Cost. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Anodot Cloud Cost when access is no longer needed, and update the connection after rotation.

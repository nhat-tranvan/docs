Connect Netskope so CloudThinker can review security alerts, user activity, and URL lists. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Netskope account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Open Settings → Administration → Administrators & Roles → Administrators and create a Service Account token for the required REST API v2 resources. See the [vendor's authentication documentation](https://docs.netskope.com/en/rest-api-v2-overview-312207) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Netskope**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the tenant origin. If IP allowlisting is enabled, include CloudThinker's approved source addresses.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Tenant URL** | Yes | Your tenant address, for example https://acme.goskope.com or https://acme.de.goskope.com. |
| **API token** | Yes | Grant read on /api/v2/events/data/alert, /api/v2/events/data/application, and /api/v2/policy/urllist. |

## Required permissions

Read `/api/v2/events/data/alert`, `/api/v2/events/data/application`, and `/api/v2/policy/urllist`.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Security alerts | Read tenant security alerts. |
| Activity context | Inspect application and user activity. |
| URL-list review | Read configured lists without changing them. |

The connection is read-only. It cannot deploy URL lists, change policies, or update DLP incidents.

This connection is read-only. Make changes in Netskope.

### Verify the connection

```text
Inspect my Netskope connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Netskope to review security alerts, user activity, and URL lists.
Summarize the highest-priority items visible through my Netskope connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Netskope. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Netskope when access is no longer needed, and update the connection after rotation.

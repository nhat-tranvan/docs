Connect Reco so CloudThinker can investigate SaaS alerts, risky accounts, and OAuth grants. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Reco account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Ask your Reco administrator for an API key for the tenant you want to inspect. See the [vendor's authentication documentation](https://docs.reco.ai/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Reco**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Enter the tenant host without `https://`, such as `acme.reco.ai`.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Tenant host** | Yes | The address of your Reco console without https://, for example acme.reco.ai. |
| **API key** | Yes | Reco shows the key once. CloudThinker only reads alerts, accounts, posture issues, and connected apps. |

## Required permissions

Read SaaS alerts, accounts, posture issues, and connected applications.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| SaaS alerts | Inspect security alerts. |
| Account risk | Review risky accounts and OAuth grants. |
| Posture context | Read issues and connected applications. |

The connection is read-only. It cannot revoke grants, change policies, add comments, or update alert statuses.

This connection is read-only. Make changes in Reco.

### Verify the connection

```text
Inspect my Reco connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Reco to investigate SaaS alerts, risky accounts, and OAuth grants.
Summarize the highest-priority items visible through my Reco connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Reco. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Reco when access is no longer needed, and update the connection after rotation.

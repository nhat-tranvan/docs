Connect Prometheus so CloudThinker can run PromQL queries, list metrics and labels, check scrape-target health, and read active alerts and alert rules. The connection is read-only and authenticates with no auth, a bearer token, or HTTP Basic auth.

## Prerequisites

- A Prometheus HTTP API reachable from CloudThinker over the internet. CloudThinker connects from its cloud, not from inside your network.
- The API served at the root of its address, so `<your URL>/api/v1/query` answers. Self-hosted Prometheus and a Thanos Querier work this way.
- A bearer token or a username and password, if a proxy or gateway in front of Prometheus requires one.
- Permission to add connections in your CloudThinker workspace.

<Warning>
The URL can't include a path. An endpoint that only answers under a prefix, such as `https://metrics.example.com/prometheus/api/v1`, fails the connection test. Expose the API at the root of a hostname instead.
</Warning>

## Setup

<Steps>
  <Step title="Find the base URL">
    Use the address you'd put in front of `/api/v1`, with no path and no trailing slash, for example `https://prometheus.example.com` or `http://prometheus.example.com:9090`.

    Check it from a terminal before you connect:

    ```bash
    curl -s "https://prometheus.example.com/api/v1/query?query=count(up)"
    ```

    **Success state:** the response starts with `{"status":"success","data":{"resultType":"vector"`.
  </Step>
  <Step title="Pick an auth mode">
    | Mode | Use it when | Fields that appear |
    |------|-------------|--------------------|
    | **None** | The endpoint is open or limited by network rules | URL only |
    | **Bearer Token** | A proxy expects `Authorization: Bearer <token>` | **PROMETHEUS_TOKEN** |
    | **Basic Auth** | A proxy expects a username and password | **PROMETHEUS_USERNAME**, **PROMETHEUS_PASSWORD** |
  </Step>
  <Step title="Add the connection">
    In CloudThinker, go to **Connections**, find **Prometheus**, and click **Connect**. Fill in:
    - **Alias** (optional): a short name such as `prod-metrics`. Lowercase letters, numbers, and hyphens.
    - **Description** (optional): what this Prometheus covers. Agents read it to pick the right instance when you connect more than one.
    - **PROMETHEUS_URL**: the base URL from step 1.
    - **PROMETHEUS_AUTH_TYPE**: **None**, **Bearer Token**, or **Basic Auth**, then the credential fields that appear.

    Click **Connect**. CloudThinker runs `count(up)` against the endpoint, shows **Testing**, then a **Connected** status.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **PROMETHEUS_URL** | Base URL of the Prometheus HTTP API, no path | `https://prometheus.example.com` |
| **PROMETHEUS_AUTH_TYPE** | **None** (default), **Bearer Token**, or **Basic Auth** | `Bearer Token` |
| **PROMETHEUS_TOKEN** | Token sent as `Authorization: Bearer`. Bearer Token mode only | `eyJhbGci...` |
| **PROMETHEUS_USERNAME** | HTTP Basic username. Basic Auth mode only | `cloudthinker` |
| **PROMETHEUS_PASSWORD** | HTTP Basic password. Basic Auth mode only | |
| **LOG_LEVEL** | Connector log detail. Leave at **Info** unless support asks | `Info` |

## Required permissions

Prometheus has no built-in user permissions, so access is whatever your proxy or gateway allows. CloudThinker needs read (`GET`) access under `/api/v1/` for:

| Area | Used for |
|------|----------|
| Query API | Instant and range PromQL queries, series lookups |
| Metadata | Metric names, label names, type and help text |
| Targets | Scrape-target health |
| Alerts and rules | Active alerts and alert rule definitions |
| Status config | Reading the loaded configuration, only when you ask |

<Tip>
If your proxy supports it, give CloudThinker its own token limited to `GET` requests under `/api/v1/`. Nothing in the connection writes to Prometheus.
</Tip>

## Agent capabilities

| Capability | What CloudThinker does |
|------------|------------------------|
| **Discovery** | Counts scrape targets (up and down), firing alerts, alert rules and their health, metrics, and labels such as `job`, `instance`, and `namespace` |
| **Instant queries** | Evaluates a PromQL expression at one point in time |
| **Range queries** | Evaluates PromQL over a window with a step. Starts at the last 15 minutes and widens if empty |
| **Metric and label discovery** | Lists metric names, type and help text, and label names, so queries use real names |
| **Target health** | Lists scrape targets and which ones are down |
| **Alerts** | Lists firing and pending alerts and the configured alert rules |
| **Configuration** | Reads the loaded config on request and redacts credential values in its answer |

When a connection first reaches **Connected**, CloudThinker runs a read-only [discovery](/guide/connections/overview#what-happens-after-you-connect) of the endpoint and saves what it learns for later chats.

### Verify the connection

```text
Run Prometheus discovery and tell me how many scrape targets are up and down, and how many alerts are firing
```

A healthy answer gives target counts by state, a firing-alert count, and a few sample metric names from your endpoint.

### Example prompts

```text
Which scrape targets are down right now, and which jobs do they belong to?
Show 5xx rate by service from http_requests_total over the last hour and flag anything above 1%
List firing alerts and the alert rule behind each one
```

Name the metric and the labels you care about. CloudThinker can list label names, so a prompt like "split by `namespace`" gets an accurate selector faster.

To route Prometheus alerts into Resolve so incidents open automatically, set up a [webhook integration](/guide/incident/webhook-integrations/overview).

## Troubleshooting

<Accordion title="Prometheus rejected the credentials">
The endpoint returned 401 or 403. Check that **PROMETHEUS_AUTH_TYPE** matches what your proxy expects, then re-enter the token or username and password. A token revoked at the proxy fails the same way.
</Accordion>

<Accordion title="Prometheus has no query API at that URL">
The endpoint returned 404. The URL most likely has a path, such as `/api/v1` or `/prometheus`. Enter only the scheme, host, and port. If your API only answers under a prefix, it isn't supported.
</Accordion>

<Accordion title="That URL answered, but not as a Prometheus query API">
Something in front of Prometheus answered instead, usually a login page or an SSO proxy. Point the URL at the API itself, or use a bearer token or Basic auth that the proxy accepts without a browser login.
</Accordion>

<Accordion title="Prometheus is unreachable or didn't answer in time">
CloudThinker couldn't open a connection. Check the hostname, port, and TLS certificate, and that the endpoint accepts traffic from the internet. A private address such as `10.0.0.5` can't be reached from CloudThinker.
</Accordion>

<Accordion title="A query returns no data">
Ask CloudThinker to list metrics matching a name first, so it confirms the metric exists. Then widen the time window, since range queries start at 15 minutes.
</Accordion>

## Security

<ConnectionSecurity />

- **No writes**: the connection only reads the Prometheus HTTP API, so a token limited to `GET` requests is enough.
- **Config holds secrets**: `/api/v1/status/config` can include scrape credentials and internal hostnames. Block that path at your proxy if you don't want it readable.

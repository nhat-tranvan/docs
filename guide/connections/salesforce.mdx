Connect Salesforce so CloudThinker can review open pipeline, support cases, and API limits. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Salesforce account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain the consumer key and secret of a Salesforce connected app configured for the client credentials flow. See the [vendor's authentication documentation](https://help.salesforce.com/s/articleView?id=sf.connected_app_client_credentials_setup.htm&type=5) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Salesforce**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Enter the org's My Domain URL. Use the sandbox My Domain address for a sandbox org.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **My Domain URL** | Yes | Your org's My Domain address, for example https://acme.my.salesforce.com (sandbox: https://acme--dev.sandbox.my.salesforce.com). |
| **Consumer key** | Yes | Enable the client credentials flow and set a read-only Run As user. |
| **Consumer secret** | Yes | The consumer secret of the same connected app. The Run As user needs API Enabled and read access to Opportunity and Case. |

## Required permissions

The app's Run As user needs API Enabled and read access to Opportunity and Case.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Pipeline review | Read open opportunity data. |
| Support context | Inspect cases. |
| API usage | Review API limit information. |

The connection is read-only. It cannot edit records, close deals, change cases, or run Apex and flows.

This connection is read-only. Make changes in Salesforce.

### Verify the connection

```text
Inspect my Salesforce connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Salesforce to review open pipeline, support cases, and API limits.
Summarize the highest-priority items visible through my Salesforce connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Salesforce. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Salesforce when access is no longer needed, and update the connection after rotation.

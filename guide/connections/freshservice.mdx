Connect Freshservice so [CloudThinker](/guide/agents/overview) can find urgent and past-due tickets, review planned and emergency changes, and list recent problems. The connection uses the **API key** of a Freshservice agent and only reads.

## Prerequisites

- A Freshservice agent who can view tickets, changes, and problems. The API key carries that agent's access.
- Your helpdesk address on `freshservice.com`, such as `acme.freshservice.com`.
- The **Admin** role in your CloudThinker workspace. See [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Copy the API key in Freshservice">
    Sign in to Freshservice as the agent CloudThinker should use. Click your profile picture in the top right corner and open **Profile settings**. Your API key is on the right side of that page. Copy it. See [Freshservice's API key instructions](https://support.freshservice.com/support/solutions/articles/50000000306-where-do-i-find-my-api-key-).
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, open the **Discover** tab, and select **Freshservice**. Click **Connect**, fill in the fields below, then click **Connect** in the dialog. CloudThinker reads one ticket to check the key.

    **Success state:** the connection shows a **Connected** status and the message `Freshservice connected; the key can read tickets.` CloudThinker then opens a chat that takes a read-only deep look at the connection ("Often takes about 15 min. You can leave the chat."). To run it again later, open the card's **More** menu and choose **Try in chat**.
  </Step>
</Steps>

## Connection details

| Field | Required | Description |
|---|---|---|
| **Helpdesk domain** | Yes | Your Freshservice address, for example `acme.freshservice.com`. A leading `https://` is fine. Use the `freshservice.com` address, not a custom domain |
| **API key** | Yes | The key from **Profile settings**, of an agent who can view tickets, changes, and problems |

## Required permissions

Freshservice API keys have no scopes of their own. The key can reach what its agent's role allows, so least privilege comes from the agent you choose.

| Agent access | Used for |
|---|---|
| View tickets | Ticket lists, urgent and past-due counts, and one ticket's replies |
| View changes | Planned, risky, and emergency changes |
| View problems | Recent problems |

<Tip>
Create a dedicated agent whose role can only view tickets, changes, and problems. The connection never writes, so the agent needs no rights to reply, assign, or approve.
</Tip>

## Agent capabilities

| Capability | What agents can read |
|---|---|
| **Helpdesk overview** | Open tickets, open urgent tickets, and open tickets past their due date, with totals, plus the latest changes and problems |
| **Tickets** | Tickets by status, priority, or group, or only past-due ones, with agent, due date, and an overdue flag |
| **Ticket detail** | One ticket's description and its latest 5 replies |
| **Changes** | Changes planned in the next days, high-risk or emergency changes, with risk, type, approval, and planned window |
| **Problems** | The latest problems in the helpdesk |

Ticket totals come from Freshservice's filter, so they cover every match. The change and problem sections read only the latest records, and agents say so. A section that failed is unavailable data, not an empty list.

Agents can't reply to, assign, approve, or close anything. Do that in Freshservice.

### Verify the connection

```text
Summarize my Freshservice helpdesk: open urgent tickets, open tickets past due, and changes planned this week.
```

### Example prompts

```text
Which open Freshservice tickets are past due, by group, oldest first?
Show high-risk and emergency changes planned in the next 7 days, with their approval status
What happened on ticket 4512? Summarize its latest replies
```

## Troubleshooting

<Accordion title="Freshservice rejected the API key. Copy it again from Profile settings.">
The key is wrong or was reset. Copy it again from **Profile settings**, then edit the connection and paste it.
</Accordion>

<Accordion title="The API key works, but the agent cannot view tickets. Use an agent with ticket access.">
The agent's role can't view tickets. Give the role ticket access, or use another agent's key. During an investigation, HTTP 403 on changes or problems means the role can't view that module.
</Accordion>

<Accordion title="That helpdesk domain does not exist. Check the domain.">
Check the spelling of the **Helpdesk domain**. It's the address you sign in at, such as `acme.freshservice.com`.
</Accordion>

<Accordion title="Enter your helpdesk domain, for example acme.freshservice.com.">
The domain isn't a `freshservice.com` address, or it holds a path. Enter only the host, such as `acme.freshservice.com`.
</Accordion>

<Accordion title="Freshservice is rate-limiting this credential. Try again in a minute.">
Freshservice limits API calls per minute across the whole account, so other tools share the limit. Wait a minute, then ask about one area at a time. See [Freshservice rate limits](https://api.freshservice.com/).
</Accordion>

## Security

<ConnectionSecurity />

- Use a dedicated agent with a view-only role, so the key can't reply to or change tickets even if it leaks.
- When the agent leaves or its key changes, update the connection with a key from another view-only agent.

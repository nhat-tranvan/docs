Connect OVHcloud so CloudThinker can explore Public Cloud projects, instances, and bills. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing OVHcloud account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create an OVHcloud API application and consumer key for the account you want to inspect. See the [vendor's authentication documentation](https://api.ovh.com/) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **OVHcloud**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Save the application key, application secret, and consumer key together. Select the API endpoint for the account's region.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **API endpoint** | Yes | The OVHcloud API of your account's region. Options: **OVHcloud Europe**, **OVHcloud Canada**, **OVHcloud US**. Default: `https://eu.api.ovh.com`. |
| **Application key** | Yes | From the API token page (eu.api.ovh.com/createToken). Grant GET on /me, /me/*, and /cloud/*. |
| **Application secret** | Yes | Enter application secret. |
| **Consumer key** | Yes | Enter consumer key. |

## Required permissions

Allow GET on `/me`, `/me/*`, and `/cloud/*` for read-only account, billing, and Public Cloud inspection.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Project inventory | Read Public Cloud projects. |
| Compute context | Inspect instances. |
| Billing context | Review account billing data. |

The connection is read-only. It cannot provision, stop, resize, or delete instances or pay bills.

This connection is read-only. Make changes in OVHcloud.

### Verify the connection

```text
Inspect my OVHcloud connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use OVHcloud to explore Public Cloud projects, instances, and bills.
Summarize the highest-priority items visible through my OVHcloud connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in OVHcloud. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in OVHcloud when access is no longer needed, and update the connection after rotation.

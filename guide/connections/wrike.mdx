Connect Wrike so CloudThinker can review projects, overdue tasks, and workload. The connection uses a dedicated API credential, with access limited by the account behind it.

## Prerequisites

- Access to the Wrike account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Open your Wrike API application settings and generate a permanent token. Use the account’s own Wrike address and a user with access to the projects you need.

    See the [Wrike documentation](https://developers.wrike.com/docs/oauth-20-authorization) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Wrike**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Wrike URL** | Yes | The address you sign in at, for example https://www.wrike.com, https://app-eu.wrike.com, or https://app-us2.wrike.com. |
| **Permanent token** | Yes | Use the permanent token prepared in the credential step. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

The token acts on behalf of its user. Share only the folders, projects, and tasks that should be visible to this connection.

<Tip>
Start with read access to the smallest useful scope. This guide covers investigation; broad administrative or write access is unnecessary for these reads.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Projects at risk** | Review projects, overdue tasks, and workload. |
| **Overdue and upcoming tasks** | Inspect overdue and upcoming tasks within the connected account’s scope. |
| **Assignee workload** | Inspect assignee workload within the connected account’s scope. |

A permanent token does not override folder sharing. The account host matters, including EU and other regional hosts.

The connection reads the supported information without changing it. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Wrike connection, summarize its account or service scope and projects at risk. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize projects at risk in Wrike and highlight items needing attention.
Review overdue and upcoming tasks and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

<ConnectionSecurity />

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

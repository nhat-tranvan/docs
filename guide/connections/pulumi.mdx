Connect Pulumi Cloud so [CloudThinker](/guide/agents/overview) can list your stacks, find the resources Pulumi manages, and triage policy violations. You sign in with Pulumi's OAuth flow, so you never paste a Pulumi access token into CloudThinker.

## Prerequisites

- A Pulumi Cloud account that belongs to the organization holding your stacks.
- The **Admin** role in the CloudThinker workspace. Only workspace Admins can add, edit, or remove connections. See [Roles](/guide/security/roles).

<Info>
CloudThinker uses the authorizing account's default Pulumi organization unless you name another organization that account belongs to in your prompt.
</Info>

## Setup

<Steps>
  <Step title="Open the Pulumi connection">
    Open **Connections**, select **Pulumi**, and click **Connect**. A Pulumi authorization page opens in a pop-up.
  </Step>
  <Step title="Sign in and authorize">
    Sign in to the Pulumi account that can see your stacks, then approve access.
  </Step>
  <Step title="Return to CloudThinker">
    Pulumi sends you back to CloudThinker, which stores the OAuth tokens for you.

    **Success state:** the Pulumi connection shows a **Connected** status.
  </Step>
</Steps>

There are no fields to fill in. Pulumi issues the OAuth tokens during authorization, and the endpoint is fixed at `mcp.ai.pulumi.com`.

## Required permissions

CloudThinker gets the same Pulumi access as the account that authorized it. Read access to the organization covers every read capability below.

Deploy to AWS and Neo tasks also run as that account, so they work only if the account is allowed to do the same thing in Pulumi. With a read-only account, Pulumi refuses them.

<Tip>
Authorize with an account that can read the organization but doesn't administer it, unless you plan to deploy through CloudThinker.
</Tip>

## Agent capabilities

| Capability | What CloudThinker does | Approval |
|------------|------------------------|----------|
| **Stack inventory** | Lists stacks with their project and last update | No |
| **Resource search** | Finds Pulumi-managed resources by name, type, project, or stack | No |
| **Policy review** | Lists policy violations grouped by enforcement level, with the stacks they hit | No |
| **Registry lookup** | Reads provider resource and function schemas from the Pulumi Registry | No |
| **Organization members** | Lists the organization's members | No |
| **Pulumi Neo history** | Reads past Pulumi Neo tasks | No |
| **Deploy to AWS** | Provisions resources in AWS | Yes |
| **Drive Pulumi Neo** | Starts or continues a Neo task, or resets a Neo conversation | Yes |

Pulumi Neo is Pulumi's own AI agent. A Neo task can deploy infrastructure and change a repository, which is why starting or continuing one asks you first.

A stack is identified by organization, project, and stack name together, so CloudThinker reports all three. It doesn't print stack outputs, configuration values, or secrets.

### Verify the connection

```text
List my Pulumi stacks with their project and organization
```

Expect a table of stacks. An empty result means the authorizing account's default organization has no stacks, not that the connection is broken.

### Example prompts

```text
Which Pulumi stacks have mandatory policy violations, and which policies fail most often?
Find every S3 bucket Pulumi manages and name the stack that owns each one
Read the aws:s3/bucket schema from the Pulumi Registry and list its required inputs
```

## Write access

Four tools change real state: deploy to AWS, plus the three tools that drive Pulumi Neo. Before each call, CloudThinker names the organization, stack, and effect, then waits for your answer. Approving one call never approves the next. If you reject a call, CloudThinker doesn't retry it. Ask again in a new message if you change your mind. See [Approvals](/guide/approvals/overview) for how gated tools work.

<Warning>
Approve a deployment only when you recognize the stack. A Pulumi deployment creates real resources and bills your cloud account.
</Warning>

CloudThinker exposes a reviewed list of Pulumi tools. A tool Pulumi adds later stays hidden until it has been reviewed and marked as a read or a write.

## Troubleshooting

<Accordion title="The OAuth flow doesn't complete">
- **Nothing opens:** your browser blocked the pop-up. Allow pop-ups for CloudThinker, then click **Connect** again.
- **Wrong account:** your browser is signed in to a different Pulumi account. Sign in to the right one at app.pulumi.com, then click **Connect** again.
- **You declined access:** click **Connect** again and approve on the Pulumi page.
</Accordion>

<Accordion title="CloudThinker reports no stacks">
CloudThinker uses the authorizing account's default Pulumi organization unless you name another organization that account belongs to in your prompt. Name the organization that holds the stacks. If the account isn't a member, reconnect with one that is.
</Accordion>

<Accordion title="CloudThinker says it can't reach an organization">
The connection reaches only organizations the authorizing Pulumi user belongs to. Add the user to the organization in Pulumi, or disconnect and authorize with an account that already belongs to it.
</Accordion>

<Accordion title="A deployment keeps asking for confirmation">
That's the approval gate, and it applies to each call. Answer the prompt in the conversation to continue.
</Accordion>

## Security

<ConnectionSecurity />

- **Keep the gate on.** Deploy to AWS and the Pulumi Neo tools are the only tools on this connection that can change your cloud or a repository.
- **Switch accounts deliberately.** The connection reaches whatever the authorizing account reaches. To change accounts, open **Connections**, select **Pulumi**, click the trash icon (**Disconnect**) on the connection, then connect again with the other account.

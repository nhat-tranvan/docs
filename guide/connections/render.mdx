Connect Render so CloudThinker can explain why a deploy failed, read build and runtime logs, check service metrics, and review your Render Postgres and Key Value instances. The connection uses a Render API key, and anything that changes your services (a deploy, an environment-variable update, a new resource) goes through your workspace's Approvals first.

---

## Prerequisites

- A Render account that can see the workspace you want CloudThinker to investigate.
- Permission to create an API key on that account.
- A CloudThinker workspace where you can add connections.

---

## Setup

<Steps>
  <Step title="Create a Render API key">
    In the Render Dashboard, open **Account Settings → API Keys** ([direct link](https://dashboard.render.com/u/settings#api-keys)) and create a key named `cloudthinker`.

    Copy the key right away. Render shows the full value only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    In the sidebar, click **More → Workspace settings → Connections**. On the **Builtin Connections** tab, search for **Render**, paste the key into **RENDER_API_KEY**, and click **Connect**.

    **Success state:** the Render card shows a **Connected** status.
  </Step>
  <Step title="Run the verify prompt">
    Ask the prompt in [Verify the connection](#verify-the-connection) in a new chat. Don't skip this: Render accepts the connection handshake even with a bad key, so a wrong key only shows up when the first request runs.

    **Success state:** CloudThinker lists your Render workspaces and services by name.
  </Step>
</Steps>

## Connection details

| Field | What to enter |
|-------|---------------|
| **RENDER_API_KEY** | The API key from **Account Settings → API Keys** in the Render Dashboard |

---

## Required permissions

Render API keys aren't scoped. A key acts as the account that created it and reaches every workspace and service that account can see.

<Tip>
For least privilege, create the key from an account that belongs only to the workspace CloudThinker should investigate, not from an owner account that sees everything you host.
</Tip>

## Agent capabilities

| Capability | What CloudThinker does | Checked by Approvals |
|------------|------------------------|----------------|
| **Service inventory** | Lists workspaces, services, URLs, and plans | No |
| **Deploy history** | Reads deploys per service and flags failed or stuck builds | No |
| **Logs** | Reads build, runtime, and request logs and groups errors by message. It sees only logs Render still keeps, which depends on your plan ([Render's logging docs](https://render.com/docs/logging)). | No |
| **Metrics** | Reads CPU, memory, instance count, and HTTP latency for a service | No |
| **Datastores** | Reviews Render Postgres and Key Value instances | No |
| **Postgres queries** | Runs bounded, read-only SQL against Render Postgres and shows you the SQL first | No |
| **Deploys** | Triggers a deploy of a service | Yes |
| **Environment variables** | Updates a service's environment variables, showing the full resulting set before you approve | Yes |
| **New resources** | Creates a web service, static site, cron job, Postgres instance, or Key Value instance | Yes |

<ApprovalDefault />

<Note>
Postgres queries run on Render's side: Render hosts the server CloudThinker calls (an MCP server, the standard way AI agents call a service's tools), and it runs the SQL with your API key. CloudThinker never holds database credentials. Because a query is a read, no Rule can switch it off. To keep a database out of reach, create the key from an account that can't see it.
</Note>

<Warning>
A deploy ships code to live traffic, and an environment-variable update can restart the service. Read the proposed change in the [approval](/guide/approvals/overview) request before you accept it. An environment-variable request lists the full resulting set, values included, so treat that chat as sensitive.
</Warning>

### Verify the connection

```text
List my Render workspaces and services with their current status
```

### Example prompts

```text
Why did the last deploy of my api service on Render fail? Quote the build log lines that matter.
Show CPU, memory, and HTTP latency for my Render web services over the last 24 hours
List my Render Postgres instances with their plans and status
```

## Troubleshooting

<Accordion title="Connected, but the first prompt returns 401">
The key is wrong or revoked. Render's handshake succeeds without a valid key, so the error appears at the first request. Create a new key in **Account Settings → API Keys**. Then open the connection, click the edit icon on the instance, click **Replace…** in **Edit Instance**, paste the key, and click **Save and test**.
</Accordion>

<Accordion title="403, or expected services are missing">
The key's account isn't a member of that workspace. Ask CloudThinker to list your Render workspaces to see what the key reaches, then create the key from an account in the right workspace.
</Accordion>

<Accordion title="404 for a service or database">
The service or database was renamed or deleted, or the name doesn't match. Ask CloudThinker to list your Render services, then refer to the service by the name in that list.
</Accordion>

<Accordion title="429 rate limit">
Render is throttling requests. Wait a minute and retry with a narrower request, such as one service or a shorter log window.
</Accordion>

<Accordion title="A deploy or change didn't happen">
Deploys, environment-variable updates, and new resources go through Approvals, and some wait for a person. Check the chat for a pending approval request and answer it before asking again.
</Accordion>

## Security

<ConnectionSecurity />

- **One-time key display:** Render shows the API key in full only at creation, so store it in your password manager before you leave the page.
- **Set a rotation schedule:** Render API keys don't expire, so replace the key on a fixed schedule and revoke the old one.
- **Account-wide reach:** because a key reaches every workspace its account can see, revoke it in Render (**Account Settings → API Keys**, then delete the key) as soon as you delete the connection.

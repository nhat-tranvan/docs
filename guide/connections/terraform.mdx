Connect HCP Terraform so [CloudThinker](/guide/agents/overview) can list your workspaces, report recent run statuses, and make approved workspace changes such as locking or renaming. The connection uses one organization name and that organization's API token.

## Prerequisites

- An HCP Terraform organization on app.terraform.io. Terraform Enterprise isn't supported.
- You, or someone helping you, must be an owner of that organization, because only owners can create or revoke the organization token.
- The **Admin** role in the CloudThinker workspace, which you need to add connections. See [Roles](/guide/security/roles).

<Info>
An organization token has authority across the whole organization. CloudThinker limits itself to the actions on this page, but treat the token as an organization-wide secret.
</Info>

## Setup

<Steps>
  <Step title="Copy your organization name">
    Sign in to [HCP Terraform](https://app.terraform.io/), select the organization, and copy its name exactly as shown, for example `platform-team`.
  </Step>
  <Step title="Create the organization token">
    Open **Organization settings → API Tokens → Organization Tokens**, set an expiration (the shortest your policy allows, and note the date), generate the token, and copy it right away. HCP Terraform shows it only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections**, select **HCP Terraform**, enter the **Organization name** and **Organization token**, and click **Connect**. CloudThinker checks that the token belongs to that organization.

    **Success state:** the connection shows a **Connected** status.
  </Step>
</Steps>

<Warning>
An organization has one organization token at a time. Generating a new one can break other automations that use the current token, so check with the organization owners first.
</Warning>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Organization name** | The name shown in app.terraform.io. Not the URL or the HCP organization ID | `platform-team` |
| **Organization token** | From **Organization settings → API Tokens → Organization Tokens** | Hidden |

Each CloudThinker workspace holds one HCP Terraform connection, so it covers one organization. To cover a second organization, connect it in another CloudThinker workspace.

## Required permissions

Use the **organization token**, not a user or team token. HCP Terraform organization tokens can manage workspaces but can't start runs or upload configuration versions, which matches what this connection does.

<Tip>
If another integration already uses the organization token, generating a new one breaks it. You can reuse the current token only if you can copy its value from your secret store, since HCP Terraform never shows it again. The trade-off: revoking it later breaks every integration that shares it.
</Tip>

## Agent capabilities

| Capability | What CloudThinker does | Approval |
|------------|------------------------|----------|
| **Workspace inventory** | Lists workspaces with lock state, execution mode, auto-apply, and other settings. Reads the first 100 workspaces, in the order HCP Terraform's API returns them | No |
| **Recent run status** | Counts run statuses and lists recent runs. Reads the first 100 runs in the organization | No |
| **Workspace changes** | Creates, renames, locks, unlocks, or safely deletes a workspace | Yes |

CloudThinker states the scope it read in every answer. Changes address a workspace by name, so you can lock or rename one outside the first 100 by naming it. Run status describes Terraform runs, not the health of your infrastructure.

### What this connection can't do

It can't start plans, applies, or runs. It can't upload or download configuration or state, change variables, show sensitive outputs, force-unlock or force-delete a workspace, delete an organization, manage teams or tokens, or connect to Terraform Enterprise endpoints. Ask for a run and CloudThinker reports current run state, says it changed nothing, and stops.

### Verify the connection

```text
List my HCP Terraform workspaces with their lock state and execution mode
```

Expect a table of workspaces with a line such as `Scope: first 100 workspaces`.

### Example prompts

```text
Summarize recent HCP Terraform run statuses and list the runs that errored
Which HCP Terraform workspaces are locked right now?
Lock the HCP Terraform workspace named prod-network
```

## Write access

Before any workspace change, CloudThinker names the organization, workspace, action, and expected effect, then waits for your [approval](/guide/approvals/overview). Asking for the change in your prompt doesn't count as approval.

HCP Terraform records each change under the organization token, not a person. A lock carries the reason `CloudThinker approved workspace lock`.

Safe delete uses HCP Terraform's own safe-delete action, which refuses a workspace that still manages resources. CloudThinker never force-deletes.

## Troubleshooting

<Accordion title="&quot;Invalid HCP Terraform organization name&quot;">
Enter the name exactly as shown in HCP Terraform. Don't paste the organization URL or an HCP organization ID.
</Accordion>

<Accordion title="&quot;HCP Terraform organization token is invalid or expired&quot;">
Create a replacement organization token, update **Organization token**, and reconnect. Coordinate with the owners first, because the old token stops working.
</Accordion>

<Accordion title="&quot;HCP Terraform organization was not found or the token cannot access it&quot;">
**Organization name** and **Organization token** must come from the same organization. Fix whichever is wrong and reconnect.
</Accordion>

<Accordion title="&quot;HCP Terraform token resolved a different organization&quot;">
The token belongs to another organization. Enter that organization's name, or use the token from the organization you entered.
</Accordion>

<Accordion title="&quot;HCP Terraform API rate limit reached. Retry later&quot;">
Wait a few minutes, then reconnect once. Repeated retries keep you rate limited.
</Accordion>

<Accordion title="&quot;HCP Terraform API is temporarily unavailable. Retry later&quot;">
HCP Terraform couldn't complete the check. Retry later. CloudThinker doesn't treat this as a passing check.
</Accordion>

<Accordion title="Safe delete refused a workspace">
The workspace still manages resources. Remove that infrastructure through your normal Terraform workflow first, then ask again.
</Accordion>

## Security

<ConnectionSecurity />

- **Track expiration.** Replace the token before the expiration date you set in setup.
- **Coordinate rotation.** Only one organization token is valid at a time. Confirm which integrations use it before you generate or revoke one.

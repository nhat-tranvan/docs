Connect Tanium so CloudThinker can operate endpoints, actions, groups, and scheduled tasks. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Tanium account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create a Tanium API token authorized for the Gateway API and the content sets needed for your investigation. See the [vendor's authentication documentation](https://help.tanium.com/bundle/gateway_heretto_cloud/page/gateway/gateway_examples.html) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Tanium**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the HTTPS Gateway origin without `/plugin/products/gateway/graphql`.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Gateway origin** | Yes | HTTPS origin that serves Tanium Gateway, such as https://example-api.cloud.tanium.com. Omit /plugin/products/gateway/graphql. |
| **API token** | Yes | Create an API token in Tanium. Gateway queries and approved mutations use this token's roles and content sets. Grant only the endpoint, group and action permissions you need. |
| **Private CA (optional)** | No | PEM of the issuing private CA. Leave empty for public trust. Hostname and certificate verification remain enabled. |

## Required permissions

Read endpoints, computer groups, actions, and schedules. Requested endpoint actions need the corresponding mutation permissions.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Endpoint inventory | Read endpoints and computer groups. |
| Action review | Inspect actions and schedules. |
| Endpoint actions | Submit supported targeted actions after approval. |

An action can affect every endpoint in a selected group. Submission is not completion; stopping an action does not undo work already executed.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Tanium connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Tanium to operate endpoints, actions, groups, and scheduled tasks.
Summarize the highest-priority items visible through my Tanium connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Tanium. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Tanium when access is no longer needed, and update the connection after rotation.

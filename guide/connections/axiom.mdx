Connect Axiom so CloudThinker agents can query your logs, traces, and metrics, find what is failing, and check which monitors fired, plus create or change monitors and dashboards through your [Approvals](/guide/approvals/overview). The connection uses one Axiom **API token** or **personal access token** and reaches one Axiom organization through Axiom's hosted MCP server.

## Prerequisites

- An Axiom organization with the datasets you want agents to read.
- Access to **Settings → API tokens** in Axiom, to create a token.
- A CloudThinker workspace where you can add connections.

## Setup

<Steps>
  <Step title="Create the credential in Axiom">
    In Axiom, click **Settings → API tokens**, then **New API token**. Name it `cloudthinker`, and set an expiration date if your policy needs one. Under **Token permissions**, click **Advanced**, then **Custom**:
    - Allow querying the datasets agents should read.
    - Allow reading monitors and dashboards.
    - Allow updating monitors and dashboards only if CloudThinker may edit them.

    Click **Create** and copy the token now. Axiom shows it only once. API tokens start with `xaat-`. See [Axiom's token instructions](https://axiom.co/docs/reference/tokens).

    You can use a personal access token (it starts with `xapt-`) instead, but it has full control of your Axiom account. Prefer an API token.
  </Step>
  <Step title="Find your organization ID">
    In Axiom, click **Settings** and copy the ID at the top right. It is also the first part of your Axiom URL: in `https://app.axiom.co/acme-a1b2/datasets`, the ID is `acme-a1b2`.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, open the **Discover** tab, and select **Axiom**. Click **Connect**, fill in the fields below, then click **Connect** in the dialog.

    **Success state:** the connection shows a **Connected** status. CloudThinker then opens a chat that takes a deep look at the connection ("Often takes about 15 min. You can leave the chat."). To run it again later, open the card's **More** menu and choose **Try in chat**.
  </Step>
</Steps>

## Connection details

| Field | Required | Description |
|---|---|---|
| **Token** | Yes | An Axiom API token (starts with `xaat-`) or personal access token (starts with `xapt-`) |
| **Organization ID** | Yes | The organization ID from Axiom **Settings**, also the first segment of `app.axiom.co` URLs |
| **Region** | Yes | Where query results pass through: **US (mcp.axiom.co)**, the default, or **EU (mcp.eu.axiom.co)**. EU keeps them in EU data centers. Both reach every Axiom organization |

One connection reads one Axiom organization. To read another organization, add a second connection with its own token and ID.

## Required permissions

| Axiom permission | Used for |
|---|---|
| Query on each dataset | Logs, traces, and metrics queries, field lists, and error triage |
| Read monitors and notifiers | Monitor health, alert history, and notifier coverage |
| Read dashboards | Listing and reading dashboards |
| Update monitors and dashboards (optional) | Approved creates, edits, and deletes |

<Tip>
Give the token query access only to the datasets agents need, and leave out update rights until you want CloudThinker to edit monitors or dashboards. You can't change a token's permissions after you create it, so create a new token to widen them.
</Tip>

## Agent capabilities

| Capability | What CloudThinker does | Checked by Approvals |
|---|---|---|
| **Datasets** | Lists datasets and their fields, and runs APL queries on events and traces | No |
| **Error triage** | Shows the failure trend, top failing groups, fields that differ in failures, and error rate before and after deploy markers | No |
| **Spotlight** | Compares a slice of events with the rest to find what stands out | No |
| **Metrics** | Lists metrics and tags, and runs MPL queries on metrics datasets | No |
| **Monitors** | Checks monitors, reads alert history, and flags monitors with no notifier | No |
| **Dashboards and saved queries** | Lists and reads dashboards, saved queries, annotations, and labels | No |
| **Service map** | Reads the service map, its changes, and the history of each edge | No |
| **Monitor changes** | Creates, updates, or deletes a monitor | Yes |
| **Dashboard changes** | Creates, updates, or deletes a dashboard or one of its charts | Yes |

<ApprovalDefault />

Before a change, CloudThinker states its effect and shows the exact monitor or dashboard JSON. A delete is permanent. Integration dashboards are read-only in Axiom.

### Verify the connection

```text
Check my Axiom connection: list my datasets, monitors, and dashboards, and flag monitors that notify no one
```

### Example prompts

```text
What is failing in my traces dataset in the last hour, and did it start after a deploy?
Which Axiom monitors fired in the last 24 hours, and why did the checkout monitor fire?
Create an Axiom monitor that alerts when 5xx errors in my http-logs dataset exceed 50 in 5 minutes
```

## Troubleshooting

<Accordion title="The provider rejected these credentials. Update them, then connect again.">
Axiom refused the token while CloudThinker was connecting. Check that you pasted the whole token and the matching **Organization ID**, then edit the connection and connect again.
</Accordion>

<Accordion title="This access token is not valid for this server">
The token or organization ID is wrong, or someone revoked the token. Create a new token in **Settings → API tokens**, then edit the connection and paste it.
</Accordion>

<Accordion title="requires a personal access token">
Axiom allows that action only with a personal access token, and the connection uses an API token. Use another way to get the answer, or replace the token with a personal access token if your policy allows it.
</Accordion>

<Accordion title="unable to find dataset">
The dataset name is wrong or the token can't query it. Ask CloudThinker to list your datasets first. If the dataset is missing, create a token with query access to it.
</Accordion>

<Accordion title="feature not enabled">
Your Axiom plan does not include that feature, so CloudThinker can't use it.
</Accordion>

<Accordion title="A dataset shows no failures">
If the dataset received no events in the window, CloudThinker says so rather than calling it healthy. Check that data still reaches the dataset, or ask about a longer window.
</Accordion>

## Security

<ConnectionSecurity />

- Prefer an API token over a personal access token. A personal access token acts as your whole user account.
- A token with an expiration date can't be regenerated. Create a new token before it expires and update the connection.

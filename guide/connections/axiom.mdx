Connect Axiom so CloudThinker can query logs, traces, and metrics and review monitors and dashboards. The connection uses an Axiom API token or personal access token.

## Prerequisites

- Access to the Axiom account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    In Axiom, open **Settings → API tokens → New API token**. Use an advanced token with query access to the required datasets and read access to monitors and dashboards. A basic ingest-only token cannot perform these investigations. Copy the organization ID from Settings and choose where query results should pass through.

    See the [provider documentation](https://axiom.co/docs/reference/tokens) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Axiom**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Token** | API token or personal access token. Prefer a token limited to the required operations. | Copy from Axiom |
| **Organization ID** | The organization ID shown in Axiom Settings. | Your organization ID |
| **Region** | US is the default. EU keeps query-result handling in EU data centers; both reach every organization. | US or EU |

## Required permissions

Grant dataset query access and read access to the monitors, notifiers, and dashboards being investigated. Add monitor or dashboard update permissions only for intended changes. Personal access tokens act with the user’s full permissions; prefer a narrower API token where possible.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Failure analysis** | Compare event trends, failure groups, and deployment annotations in one dataset. |
| **Alert health** | Read monitors, notifiers, and alert history. |
| **Metrics and dashboards** | Query metrics and inspect dashboard definitions. |

An empty time window is not proof of service health. Specify a dataset and time range. Change correlation identifies events that occur together; it does not establish causation.

Creating, updating, or deleting a monitor or editable dashboard goes through [Approvals](/guide/approvals/overview). Integration-managed dashboards remain read-only. Review the exact proposed change before approval.

### Verify the connection

```text
List the Axiom datasets, monitors, and dashboards this connection can read and report any permission gaps
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Investigate error trends in the selected dataset over the last hour and compare deployment annotations
Find monitors with no notifier and show the affected monitor names
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Token can ingest but cannot query">
Replace an ingest-only token with an advanced token permitted to query the selected datasets. A permission change requires a token with the new permissions.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.
- Review the exact resource and proposed change before approving a write. An uncertain result needs a fresh read before retrying.

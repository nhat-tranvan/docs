Connect GreenNode to let CloudThinker agents read and operate your GreenNode resources, such as vServer instances, VKS clusters, load balancers, databases, and storage. The connection signs in with a **service account** (a client ID and client secret) and runs the official GreenNode CLI, `grn`, in one region.

## Prerequisites

- Access to [GreenNode IAM](https://iam.console.greennode.ai/service-accounts) with permission to create a service account.
- The GreenNode region that holds your resources: **HCM-3** (Ho Chi Minh City) or **HAN** (Hanoi).
- For vServer work, the **Project ID** of the project you want agents to use. GreenNode does not pick a project for you.

## Setup

<Steps>
  <Step title="Create a GreenNode service account">
    Open [GreenNode IAM → Service accounts](https://iam.console.greennode.ai/service-accounts), then:

    1. Click **Create a Service account**.
    2. Enter a name, such as `cloudthinker`.
    3. In the scope picker, select only the scopes for the services you want agents to use. See [Required permissions](#required-permissions).
    4. Click **Create Service account**.
    5. Copy the **Client ID** and **Client secret**.
  </Step>
  <Step title="Copy your Project ID (for vServer)">
    In the [GreenNode dashboard](https://dashboard.console.greennode.ai/), open **vServer → Limit** and copy **User Project ID** for the project you want agents to use. Skip this step if you only need VKS or other services that are not project-scoped.
  </Step>
  <Step title="Copy your Portal user ID (optional)">
    In the GreenNode dashboard, click your avatar in the upper-right corner and hover over the **Currently signed in as** card. Copy the numeric **Account ID**, such as `123456`. Do not use the account email.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar, select **GreenNode**, and fill in the fields from [Connection details](#connection-details). Click **Connect**.

    **Success state:** the connection shows **Testing**, then a **Connected** status. CloudThinker verifies the credentials by reading the service account's identity from GreenNode IAM.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|-------|----------|---------------|
| **Client ID** | Yes | The service account's client ID. |
| **Client secret** | Yes | The service account's client secret. |
| **Portal user ID** | No | Your numeric GreenNode Account ID. Must be a positive whole number. Some vServer and block-volume commands use it. |
| **Default region** | Yes | **HCM-3** (default) or **HAN**. One connection covers one region. |
| **Project ID** | No | The project agents work in. Required for vServer commands, not used for VKS. |

## Required permissions

The service account's scopes decide everything agents can see and change. CloudThinker adds no access of its own.

- The connection test reads the service account's identity through GreenNode IAM, so the account must be able to do that.
- For each service you want agents to inspect, grant its read scopes only.
- Add write scopes for a service only when you want agents to change it, for example starting or stopping vServer instances.

<Tip>
Start with read scopes for the one or two services you care about, such as vServer and VKS. If an agent reports a permission error, add the scope GreenNode names and test again.
</Tip>

## Agent capabilities

Agents use the GreenNode CLI and read its built-in help before each command, so they only run operations the CLI actually offers. The CLI covers 13 service groups:

| Service group | What agents can work with |
|---------------|---------------------------|
| `vserver` | Virtual servers and their volumes |
| `vks` | VKS Kubernetes clusters |
| `vlb` | Load balancers |
| `vdb` | Managed databases |
| `vstorage`, `vstorage-gateway` | Storage and storage gateways |
| `vbackup` | Backups |
| `vcr` | Container registry |
| `vmonitor`, `vmonitor-log` | Metrics and logs |
| `iam` | Identity and access |
| `saas-ai`, `agentbase` | GreenNode AI services |

Reads run without asking. Any create, update, delete, start, stop, resize, attach, restore, or other change goes through [Approvals](/guide/approvals/overview) first. If the CLI has no command for what you ask, the agent tells you instead of working around it. For example, VKS can register and unregister a fleet but has no command to delete one.

### Verify the connection

```text
Who am I signed in as on GreenNode, and which VKS clusters exist in my region?
```

Expect the service account identity, then a list of VKS clusters, or a clear statement that the region has none.

### Example prompts

```text
List my GreenNode vServer instances with their status and flavor
List my VKS clusters with their status and Kubernetes version
Stop the vServer instance web-01, and show me the exact change before you run it
```

## Troubleshooting

<Accordion title="GreenNode requires GRN_ACCESS_KEY_ID and GRN_SECRET_ACCESS_KEY">
**Client ID** or **Client secret** is empty. Enter both values from the service account, then test again.
</Accordion>

<Accordion title="GreenNode region must be HCM-3 or HAN">
Select **HCM-3** or **HAN** in **Default region**, then test again.
</Accordion>

<Accordion title="GreenNode portal user ID must be a positive numeric value">
**Portal user ID** holds an email or other text. Enter the numeric **Account ID** from the **Currently signed in as** card, or clear the field.
</Accordion>

<Accordion title="GreenNode project ID contains unsupported characters">
**Project ID** has a space or a character GreenNode does not use. Copy **User Project ID** again from **vServer → Limit**, without extra characters.
</Accordion>

<Accordion title="GreenNode rejected the credentials or they lack the required read permission">
The client ID or secret is wrong, the service account was deleted, or it cannot read its own IAM identity. Check the service account in GreenNode IAM, create a new secret if needed, and update the connection.
</Accordion>

<Accordion title="GreenNode did not answer before the connection test timeout">
GreenNode was slow or unreachable. Wait a few minutes, then test the connection again.
</Accordion>

<Accordion title="vServer questions fail but VKS works">
vServer commands need **Project ID**. Add it, and add **Portal user ID** if the agent reports it missing, then test again.
</Accordion>

## Security

<ConnectionSecurity />

- **Credentials stay out of commands**: CloudThinker passes the client ID and secret to the CLI as environment values, and agents cannot print them, override the GreenNode endpoint, or turn off certificate checks.
- **Revoke at the source**: delete the service account in GreenNode IAM to stop all access through this connection at once.

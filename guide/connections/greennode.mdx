Connect GreenNode to let CloudThinker agents read and operate your GreenNode resources, such as vServer instances, VKS clusters, load balancers, databases, and storage. The connection signs in with a **service account** (a client ID and client secret) and runs the official GreenNode CLI, `grn`, in one region.

## Prerequisites

- Access to [GreenNode IAM](https://iam.console.greennode.ai/service-accounts) with permission to create a service account.
- The GreenNode region that holds your resources: **HCM-3** (Ho Chi Minh City) or **HAN** (Hanoi).
- For vServer work, the **Project ID** of the project you want agents to use, and your numeric **Account ID**. GreenNode does not pick a project for you.

<Info>
A workspace holds **one** GreenNode connection, for one region and one project. To cover both HCM-3 and HAN, or a second project, [create a separate workspace](/guide/workspaces#create-a-workspace) for each, with its own members and Approvals settings.
</Info>

<Warning>
Copy the **Client secret** as soon as you create the service account, and store it somewhere safe. If you lose it, you create a new service account and swap in its values with [Rotate a credential](/guide/connections/overview#rotate-a-credential).
</Warning>

## Setup

<Steps>
  <Step title="Create a GreenNode service account">
    Open [GreenNode IAM → Service accounts](https://iam.console.greennode.ai/service-accounts), then:

    1. Click **Create a Service account**.
    2. Enter a name, such as `cloudthinker`.
    3. In the scope picker, select only the scopes for the services you want agents to use. See [Required permissions](#required-permissions).
    4. Click **Create Service account**.
    5. Copy the **Client ID** and **Client secret**.
  </Step>
  <Step title="vServer only: copy your Project ID and Account ID">
    Skip this step if agents won't work with vServer.

    1. In the [GreenNode dashboard](https://dashboard.console.greennode.ai/), open **vServer → Limit** and copy **User Project ID** for the project you want agents to use.
    2. Click your avatar in the upper-right corner and hover over the **Currently signed in as** card. Copy the numeric **Account ID**, such as `123456`. Do not use the account email. The CloudThinker form calls this value **Portal user ID**.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar, select **GreenNode**, and fill in the fields from [Connection details](#connection-details). For vServer, enter the User Project ID in **Project ID** and the Account ID in **Portal user ID**. Otherwise leave both blank. Click **Connect**.

    **Success state:** the connection shows **Connecting** and **Verifying**, then a **Connected** status. CloudThinker verifies the credentials by reading the service account's identity from GreenNode IAM.

    If the test fails, the connection shows **Error** with **Retry** (test the saved values again) and **Replace credentials** (enter new ones). To change values on a working connection, follow [Rotate a credential](/guide/connections/overview#rotate-a-credential).
  </Step>
</Steps>

## Connection details

The form has these five fields and no others.

| Field | Required | What to enter |
|-------|----------|---------------|
| **Client ID** | Yes | The service account's client ID. CloudThinker passes it to the CLI as `GRN_ACCESS_KEY_ID`. |
| **Client secret** | Yes | The service account's client secret. CloudThinker passes it as `GRN_SECRET_ACCESS_KEY`. |
| **Portal user ID** | For vServer | Your numeric GreenNode **Account ID** (same value, different label). Must be a positive whole number. Leave blank if you don't use vServer. |
| **Default region** | Yes | **HCM-3** (preselected) or **HAN**. Despite the label, this is the only region the connection covers, so agents can't reach the other one. To cover both, use a second workspace. |
| **Project ID** | For vServer | The project agents work in. vServer commands fail without it. VKS doesn't use it. |

## Required permissions

The service account's scopes decide everything agents can see and change. CloudThinker adds no access of its own.

- **Required for the connection test:** the scope that lets the service account read its own IAM identity. CloudThinker runs `grn iam whoami` to test the connection, and it fails without that scope.
- For each service you want agents to inspect, grant its read scopes only.
- Add write scopes for a service only when you want agents to change it, for example starting or stopping vServer instances.

<Tip>
Start with read scopes for the one or two services you care about, such as vServer and VKS. If an agent reports a permission error, add the scope GreenNode names and test again.
</Tip>

## Agent capabilities

Agents use the GreenNode CLI and read its built-in help before each command, so they only run operations the CLI actually offers. The CLI covers 13 service groups:

| Service group | What agents can work with |
|---------------|---------------------------|
| `vserver` | Virtual servers and their volumes |
| `vks` | VKS Kubernetes clusters |
| `vlb` | Load balancers |
| `vdb` | Managed databases |
| `vstorage`, `vstorage-gateway` | Storage and storage gateways |
| `vbackup` | Backups |
| `vcr` | Container registry |
| `vmonitor`, `vmonitor-log` | Metrics and logs |
| `iam` | Identity and access |
| `saas-ai`, `agentbase` | GreenNode AI platform services |

Reads run without asking. Any create, update, delete, start, stop, resize, attach, restore, or other change goes through [Approvals](/guide/approvals/overview) first. If the CLI has no command for what you ask, the agent tells you instead of working around it, and names the closest actions the CLI does offer.

### Verify the connection

```text
Who am I signed in as on GreenNode, and which VKS clusters exist in my region?
```

Expect the service account identity, then a list of VKS clusters, or a clear statement that the region has none.

### Example prompts

```text
List my GreenNode vServer instances with their status and flavor
List my VKS clusters with their status and Kubernetes version
Stop the vServer instance web-01, and show me the exact change before you run it
```

## Troubleshooting

<Accordion title="GreenNode requires GRN_ACCESS_KEY_ID and GRN_SECRET_ACCESS_KEY">
`GRN_ACCESS_KEY_ID` is the **Client ID** field and `GRN_SECRET_ACCESS_KEY` is the **Client secret** field. One of them is empty. Enter both values from the service account, then test again.
</Accordion>

<Accordion title="GreenNode region must be HCM-3 or HAN">
Select **HCM-3** or **HAN** in **Default region**, then test again.
</Accordion>

<Accordion title="GreenNode portal user ID must be a positive numeric value">
**Portal user ID** holds an email or other text. Enter the numeric **Account ID** from the **Currently signed in as** card, or clear the field.
</Accordion>

<Accordion title="GreenNode project ID contains unsupported characters">
**Project ID** has a space or a character GreenNode does not use. Copy **User Project ID** again from **vServer → Limit**, without extra characters.
</Accordion>

<Accordion title="GreenNode rejected the credentials or they lack the required read permission">
The client ID or secret is wrong, the service account was deleted, or it cannot read its own IAM identity. Check the service account in GreenNode IAM. To enter new values, click **Replace credentials** on the errored connection, or follow [Rotate a credential](/guide/connections/overview#rotate-a-credential).
</Accordion>

<Accordion title="GreenNode did not answer before the connection test timeout">
GreenNode didn't answer within the test window, which is 60 seconds. Wait a few minutes, then test the connection again.
</Accordion>

<Accordion title="Connection 'greennode' already exists. Only one instance is allowed.">
This workspace already has a GreenNode connection. Edit that connection, or disconnect it first.
</Accordion>

<Accordion title="vServer questions fail but VKS works">
vServer commands need **Project ID**, and some also need **Portal user ID**. Add both, then test again.
</Accordion>

## Security

<ConnectionSecurity />

- **Credentials stay out of commands**: CloudThinker passes the client ID and secret to the CLI as environment values, and agents cannot print them, override the GreenNode endpoint, or turn off certificate checks.
- **Rotate the secret**: to swap in a new client ID and secret, follow [Rotate a credential](/guide/connections/overview#rotate-a-credential).
- **Revoke at the source**: delete the service account in GreenNode IAM to stop all access through this connection at once.

Connect Secureframe to let CloudThinker track failing tests, framework progress, and vendor risk. The connection uses **a Secureframe API key and secret**.

## Prerequisites

- An account with access to the Secureframe resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Secureframe">
    In Secureframe, open your profile, then **Company Settings → API Keys → Create API Key**. A **Super Admin** must create the key. Assign the intended owner, enter a key name, and generate it. Keep the key and secret together and choose the region that matches your login domain.

    Follow the [vendor’s credential and authentication guidance](https://support.secureframe.com/en/articles/15111555-secureframe-developer-portal-api) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Secureframe**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **API key** | Yes | The API key for the account described in Setup. |
| **API secret** | Yes | Secret value paired with the credential above. |
| **Region** | Yes | app.secureframe.com is US; app-uk.secureframe.com is UK. Choose **US (api.secureframe.com)**, **UK (api-uk.secureframe.com)**. Default: **US (api.secureframe.com)**. |

US and UK accounts use different API hosts. A valid key and secret for one region do not authorize requests to the other.

## Required permissions

The key owner must be able to read the frameworks, tests, integrations, people, devices, policies, and vendor-risk data to be investigated. Key creation requires Super Admin; do not confuse the creation role with the access needed for each later request.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Review framework readiness and failing tests |
| Investigation | Inspect disconnected integrations |
| Investigation | Review personnel and device readiness |
| Investigation | Inspect vendor-risk information |

### Verify the connection

```text
Review Secureframe framework progress, failing tests, disconnected integrations, and personnel readiness. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Review Secureframe framework progress, failing tests, disconnected integrations, and personnel readiness
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. US and UK accounts use different API hosts. A valid key and secret for one region do not authorize requests to the other.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

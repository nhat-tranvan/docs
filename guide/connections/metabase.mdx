Connect Metabase so CloudThinker can search dashboards and saved questions, then read results. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Metabase account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    In Metabase, open Admin → Settings → Authentication → API Keys → Manage and create an API key. Assign it to a group with view access. See the [vendor's authentication documentation](https://www.metabase.com/docs/latest/people-and-groups/api-keys) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Metabase**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Copy the generated key when it is displayed and enter your Metabase URL.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Metabase URL** | Yes | The address of your Metabase, for example https://metabase.example.com |
| **API key** | Yes | Put the key in a group with view access only. |

## Required permissions

The API key inherits its selected group's collection and data permissions.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Content search | Find dashboards and saved questions. |
| Question review | Read a saved question's definition. |
| Question results | Run an existing saved question when you request its data. |

The connection reads dashboards, saved questions, and results. It does not modify questions, dashboards, or database permissions.

Running a saved question can load its database. Ask to see the definition first, then request its results; the connection does not edit dashboards, questions, or collections.

### Verify the connection

```text
Inspect my Metabase connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Metabase to search dashboards and saved questions, then read results.
Summarize the highest-priority items visible through my Metabase connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Metabase. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Metabase when access is no longer needed, and update the connection after rotation.

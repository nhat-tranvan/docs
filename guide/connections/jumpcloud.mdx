Connect JumpCloud so CloudThinker can review users, MFA, lockouts, and managed devices. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing JumpCloud account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain an API key from an administrator assigned the Read Only role. See the [vendor's authentication documentation](https://docs.jumpcloud.com/api/1.0/index.html) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **JumpCloud**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Select the correct US or EU region. The current connection form requires Organization ID. Ask your JumpCloud administrator for the target organization ID; for an MSP key this selects the organization to inspect.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Region** | Yes | The data region of your JumpCloud organization. Options: **United States**, **Europe**. Default: `https://console.jumpcloud.com`. |
| **API key** | Yes | Enter api key. |
| **Organization ID (MSP only)** | Yes (current form) | The target organization ID. This is required by the current form, including when the label identifies MSP use. |

## Required permissions

Read users, authentication status, and managed device inventory in the target organization.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| User inventory | Read users and access context. |
| Authentication health | Review MFA and lockout information. |
| Device inventory | Inspect managed devices. |

The connection is read-only. It cannot unlock users, reset MFA, or lock or erase devices.

This connection is read-only. Make changes in JumpCloud.

### Verify the connection

```text
Inspect my JumpCloud connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use JumpCloud to review users, MFA, lockouts, and managed devices.
Summarize the highest-priority items visible through my JumpCloud connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in JumpCloud. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in JumpCloud when access is no longer needed, and update the connection after rotation.

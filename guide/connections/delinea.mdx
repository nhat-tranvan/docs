Connect Delinea Secret Server so CloudThinker can audit secret metadata, failed heartbeats, rotation state, checkouts, and access history. The connection uses a local application account.

## Prerequisites

- Access to the Delinea Secret Server account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to the provider API. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services). Access through your browser or local SSH tunnel alone is insufficient.

## Setup

<Steps>
  <Step title="Prepare access">
    Ask your Secret Server administrator for a dedicated local application account permitted to use the REST API. Give it View access to only the folders that should be reviewed. Record the exact Secret Server address, including its application path on an on-premises installation.

    See the [provider documentation](https://docs.delinea.com/online-help/secret-server/api-scripting/rest-api/index.htm) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Delinea Secret Server**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Secret Server URL** | Exact cloud or on-premises application URL, including /SecretServer when present. | https://pam.example.com/SecretServer |
| **Application account username** | Dedicated account used for API access. | Your application account |
| **Password** | Password of that application account. | Enter in the connection form |

## Required permissions

The account needs View on the folders and secrets being audited and access to their metadata and audit history. It does not need permission to expose secret values, rotate passwords, or check out secrets. Your administrator must also permit the account’s API sign-in method.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Secret hygiene** | Find heartbeat failures, out-of-sync passwords, and disabled automatic changes. |
| **Expiry and checkouts** | Review upcoming expiry and checked-out secret metadata. |
| **Access history** | Read audit entries for one identified secret. |

CloudThinker never reads, reveals, or exports secret values through this connection. It does not check out, change, or rotate secrets. Hygiene summaries cover a bounded inventory and say when that inventory is incomplete.

### Verify the connection

```text
Review Secret Server metadata for heartbeat failures, out-of-sync passwords, and upcoming expiry without reading secret values
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Show checked-out secrets and their folder names without revealing any values
Review the access history of the selected secret and identify unusual access times
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Sign-in address returns not found">
An on-premises Secret Server can live beneath /SecretServer. Enter the application’s exact address, including that path, rather than only its hostname.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

Connect a LangSmith workspace and ask CloudThinker why an LLM run failed, which runs cost the most yesterday, or how two experiments compare on latency, cost, and feedback. [LangSmith](https://www.langchain.com/langsmith) is LangChain's platform for tracing and evaluating LLM apps. You need three values: an API key, a workspace ID, and your region's API URL.

## What agents can do

| Capability | What you get |
|------------|--------------|
| **Projects and runs** | Failed, slow, or costly runs in a named project, ranked by errors, latency, or cost |
| **Traces and threads** | One trace, or the message history of a conversation thread |
| **Datasets and examples** | Your datasets and the examples inside one dataset |
| **Experiments** | Experiment results for a dataset, including latency, cost, and feedback |
| **Prompts** | Your prompts and one prompt's template |

Agents summarize what they find. They don't print full run inputs, outputs, or message bodies. Billing usage is turned off on this connection.

<Note>
Agents read by default. They won't push a prompt, edit a dataset, or start an experiment unless you ask for that exact change by name in the conversation. To rule out writes entirely, use a key with a read-only role (see [Choose a key](#choose-a-key)).
</Note>

## Before you start

- A LangSmith account with access to the workspace you want agents to read.
- Permission to create an API key in LangSmith. Only organization admins can create service keys.
- Permission to add connections in your CloudThinker workspace.

## Choose a key

| Key type | Who it acts as | Use it when |
|----------|----------------|-------------|
| **Personal access token** | The user who created it, with all of that user's access | You're testing on your own |
| **Service key, workspace-scoped** | Only the workspaces you pick | Recommended for a shared CloudThinker workspace |
| **Service key, organization-scoped** | Every workspace in the organization | Avoid unless agents need every workspace |

<Tip>
Create a workspace-scoped service key for the one workspace agents should read. On LangSmith Enterprise, give it the **Workspace Viewer** role for read-only access.
</Tip>

## Connect LangSmith

<Steps>
  <Step title="Create an API key">
    In LangSmith, open **Settings → API Keys**. Pick the key type from the table above. For a workspace-scoped service key, select the workspace. Set an expiration, then click **Create API Key**.
  </Step>
  <Step title="Copy the key">
    Copy the key now. LangSmith shows it only once.
  </Step>
  <Step title="Copy the workspace ID">
    On the **Settings** page, copy the **Workspace ID** under **General**.
  </Step>
  <Step title="Pick your API URL">
    Use the URL for the region your workspace lives in:

    | Region | API URL |
    |--------|---------|
    | GCP US (default) | `https://api.smith.langchain.com` |
    | GCP EU | `https://eu.api.smith.langchain.com` |
    | GCP APAC | `https://apac.api.smith.langchain.com` |
    | AWS US | `https://aws.api.smith.langchain.com` |

    For a self-hosted LangSmith, use that deployment's API URL.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Go to **Connections → LangSmith**, fill in all three fields, and click **Connect**.

    **Success state:** the LangSmith card shows **Connected**. That means CloudThinker saved the connection. Run the verify prompt below to confirm LangSmith accepts the key, workspace, and URL together.
  </Step>
</Steps>

| Field | What to enter | Example |
|-------|---------------|---------|
| **LANGSMITH_API_KEY** | Personal access token or service key | `<your-api-key>` |
| **LANGSMITH_WORKSPACE_ID** | The workspace ID from **Settings → General** | `<your-workspace-id>` |
| **LANGSMITH_ENDPOINT** | Your region's API URL | `https://api.smith.langchain.com` |

All three fields are required. LangSmith needs the workspace ID when a key covers more than one workspace, and it does no harm for a single-workspace key.

## Verify the connection

Ask CloudThinker in chat:

```text
List my LangSmith projects and datasets
```

**Success state:** you get project and dataset names that match your workspace in LangSmith. An empty list with no error is still a working connection: the workspace may just be empty.

## Example prompts

Name the exact project or dataset. Ranking runs needs a project name, and experiments and examples need a dataset name.

```text
Show the five most expensive runs in the support-bot project from the last day and what drove their cost
```

```text
Find failed runs in the support-bot project and group them by error
```

```text
Compare the latest experiments on the support-eval dataset by latency, cost, and feedback
```

```text
Show me the template of the support-triage prompt
```

## Troubleshooting

<Accordion title="401 Unauthorized">
The key is missing, mistyped, expired, or deleted. Expired LangSmith keys can't be reactivated. Create a new key, then open **Connections → LangSmith** and replace **LANGSMITH_API_KEY**.
</Accordion>

<Accordion title="403 Forbidden">
The key can't read that workspace. An organization-scoped key needs the right **LANGSMITH_WORKSPACE_ID**, and a workspace-scoped key only works for the workspaces you picked. Check both, plus the key's role.
</Accordion>

<Accordion title="Nothing is found, or the wrong data comes back">
**LANGSMITH_ENDPOINT** doesn't match your workspace's region. Set it to the URL from the region table above.
</Accordion>

<Accordion title="404, or a project or dataset isn't found">
The name doesn't exist in this workspace. Ask the agent to list your projects or datasets first, then use an exact name.
</Accordion>

<Accordion title="429 Too Many Requests">
LangSmith limits how many requests a key can make per minute. Wait a minute, then ask a narrower question, for example one project and a shorter time window.
</Accordion>

## Security

<ConnectionSecurity />

- **Workspace-scoped key**: limit the key to one workspace so others stay out of reach.
- **Expiration**: set one on the key and replace the key before it lapses.

Connect ilert so CloudThinker can inspect alerts, incidents, and on-call coverage. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing ilert account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create a user API key in ilert and copy it for the connection. See the [vendor's authentication documentation](https://docs.ilert.com/rest-api) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **ilert**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Choose a user whose service and team access matches what CloudThinker should reach.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **User API key** | Yes | The Connection inherits that user's permissions. |

## Required permissions

The connection inherits the API key user's permissions for alerts, incidents, schedules, and on-call resources.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Alert triage | Inspect alerts and incident context. |
| On-call coverage | Read schedules and responders. |
| Response actions | Make supported response or maintenance changes after approval. |

Escalation can page responders; maintenance can suppress notifications. Such changes need a specific target and approval.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my ilert connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use ilert to inspect alerts, incidents, and on-call coverage.
Summarize the highest-priority items visible through my ilert connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in ilert. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in ilert when access is no longer needed, and update the connection after rotation.

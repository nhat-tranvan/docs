Connect Cisco Secure Firewall to let CloudThinker review access rules, managed devices, and deploy state. The connection uses **a dedicated Firewall Management Center API user**.

## Prerequisites

- An account with access to the Cisco Secure Firewall resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Cisco Secure Firewall">
    Have your Firewall Management Center administrator create a dedicated API user with read access to the intended management domain. Do not reuse your interactive login: Cisco documents that simultaneous REST API and GUI sessions with the same user can log one another out. Record the HTTPS management address.

    Follow the [vendor’s credential and authentication guidance](https://www.cisco.com/c/en/us/support/docs/security/firepower-management-center/215918-how-to-generate-authentication-token-for.html) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Cisco Secure Firewall**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Management Center URL** | Yes | The https address of your Firewall Management Center, for example https://fmc.example.com. It needs a certificate the connection trusts. |
| **Username** | Yes | A dedicated FMC API user with a read-only role. API sessions log other sessions of the same user out. |
| **Password** | Yes | That user's password. |
| **Domain UUID (optional)** | No | Leave empty for the Global domain, or enter a domain UUID to read a subdomain. |

Leave Domain UUID empty for Global; specify the actual subdomain UUID when investigating a subdomain.

## Required permissions

Read access to managed devices, access policies and rules, and deployment status in the target domain. The connection does not deploy policy or change firewall rules.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Inspect managed device health |
| Investigation | Review access policy rules and logging settings |
| Investigation | Identify pending deployments |

### Verify the connection

```text
Inspect Cisco Secure Firewall devices and access rules, and report unhealthy devices or pending deployments. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Inspect Cisco Secure Firewall devices and access rules, and report unhealthy devices or pending deployments
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. Leave Domain UUID empty for Global; specify the actual subdomain UUID when investigating a subdomain.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

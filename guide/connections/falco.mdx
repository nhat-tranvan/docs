Connect Falco so CloudThinker can inspect runtime detections and verify event ingestion. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Falco account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain the username and password configured for your Falcosidekick UI. Enter them as one `username:password` value. See the [vendor's authentication documentation](https://github.com/falcosecurity/falcosidekick-ui) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Falco**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use your Falcosidekick UI HTTPS origin without `/api/v1`; this does not connect directly to every Falco sensor.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Falcosidekick UI URL** | Yes | The HTTPS origin of your Falcosidekick UI, without /api/v1. |
| **Credentials** | Yes | The username:password pair configured for Falcosidekick UI, kept together as one secret. |
| **CA certificate (optional)** | No | PEM of the private CA that issued your self-hosted UI certificate. Leave empty for public trust. |

## Required permissions

Read retained Falcosidekick UI events, counts, and output metadata. The optional ingestion check also needs access to the selected receiver.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Runtime events | Read retained Falcosidekick UI events. |
| Event counts | Inspect the counts and filters exposed by that UI. |
| Ingestion verification | Create a marked synthetic event after approval. |

The optional ingestion check creates a clearly marked synthetic event. It verifies UI ingestion, not detector rules or downstream routing.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Falco connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Falco to inspect runtime detections and verify event ingestion.
Summarize the highest-priority items visible through my Falco connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Falco. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Falco when access is no longer needed, and update the connection after rotation.

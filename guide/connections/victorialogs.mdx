Connect VictoriaLogs to let CloudThinker search log lines, counts over time, streams, and fields. The connection uses **an HTTPS VictoriaLogs endpoint, optionally with a bearer token**.

## Prerequisites

- An account with access to the VictoriaLogs resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in VictoriaLogs">
    Ask your VictoriaLogs administrator for a search endpoint protected by your approved access controls. For a bearer-protected endpoint, obtain a token restricted to the intended tenant and search paths. Record AccountID:ProjectID only when your deployment uses explicit tenant routing.

    Follow the [vendor’s credential and authentication guidance](https://docs.victoriametrics.com/victorialogs/security-and-lb/) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **VictoriaLogs**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **VictoriaLogs URL** | Yes | The address of VictoriaLogs or the vmauth in front of it, such as https://logs.example.com. |
| **Bearer token (optional)** | Optional | A VictoriaMetrics Cloud access token or a vmauth bearer token. Leave empty when the endpoint needs no authentication. |
| **Tenant (optional)** | Optional | AccountID:ProjectID for a multitenant VictoriaLogs, such as 12:0. Leave empty for the default tenant. |
| **CA certificate (optional)** | Optional | PEM of the private CA that issued the VictoriaLogs certificate. Leave empty to use public trust. The certificate and hostname are always checked. |

Keep VictoriaLogs behind a protected network and authenticated HTTPS proxy as the vendor recommends. Leave the token empty only when the endpoint’s existing access policy explicitly permits that connection.

## Required permissions

Search access to the intended log tenant and streams. This connector reads logs, stream fields, and query statistics; it does not ingest or delete logs. A tenant field selects a tenant but does not grant permission to it.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Search log lines with LogsQL |
| Investigation | Count errors over a time window |
| Investigation | Inspect streams and field names |

### Verify the connection

```text
Inspect VictoriaLogs streams and count errors over the last hour, showing the LogsQL query and time window. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Inspect VictoriaLogs streams and count errors over the last hour, showing the LogsQL query and time window
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. Keep VictoriaLogs behind a protected network and authenticated HTTPS proxy as the vendor recommends. Leave the token empty only when the endpoint’s existing access policy explicitly permits that connection.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

Connect your Braintrust organization and ask CloudThinker how an experiment scored against its baseline, what a saved monitor view shows, or how a project is configured, without opening Braintrust. [Braintrust](https://www.braintrust.dev) is an evaluation and observability platform for LLM apps. The connection uses one API key and is read-only: agents can look, never change.

## What agents can do

CloudThinker allows exactly six Braintrust actions on this connection. Everything else Braintrust offers is blocked.

| Capability | What you get |
|------------|--------------|
| **Recent objects** | Up to 10 recent projects, experiments, datasets, prompts, or functions of one type |
| **Experiment summary** | One experiment's scores and metrics, optionally compared with a baseline experiment |
| **Object lookup** | Resolve a name, ID, or Braintrust URL to the object it points to |
| **Share link** | A Braintrust link to one resolved object, ready to paste into a ticket or chat |
| **Monitor view** | One saved monitor view and its charts, by exact name |
| **Project settings** | One project's settings, including its default preprocessor |

Agents report names and counts. They show an object ID only when you ask for one.

<Warning>
Agents cannot run SQL over your logs, list automations, browse all monitor views, or create, edit, or run anything in Braintrust. Do those in Braintrust itself.
</Warning>

## Before you start

- A Braintrust organization on Braintrust's US data plane. CloudThinker always connects to `api.braintrust.dev`, so EU data plane and self-hosted Braintrust deployments are not supported.
- Permission to create an API key in that organization.
- Permission to add connections in your CloudThinker workspace.

## Choose the account that creates the key

A Braintrust API key carries the permissions of the user who created it, and it cannot be scoped below that user. The key's reach is the account's reach.

<Tip>
Create the key from an account that only needs to read. If your Braintrust plan offers permission groups, put that account in the **Viewers** group, which gives read access to the organization's projects. A key created by an owner works, but carries owner access.
</Tip>

## Connect Braintrust

<Steps>
  <Step title="Open API keys in Braintrust">
    Sign in to Braintrust with the account you picked above and go to **Settings → API keys**.
  </Step>
  <Step title="Create the key">
    Click **+ API key**, name it `cloudthinker`, and choose an expiration. Note the date: the expiration can't be changed later. Click **Create**.
  </Step>
  <Step title="Copy the key">
    Copy the key now. Braintrust shows it only once. If you lose it, create a new one.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Go to **Connections → Braintrust**, paste the key into **BRAINTRUST_API_KEY**, and click **Connect**.

    **Success state:** the Braintrust card shows **Connected**.
  </Step>
</Steps>

| Field | What to enter | Example |
|-------|---------------|---------|
| **BRAINTRUST_API_KEY** | The API key you just created | `<your-api-key>` |

## Verify the connection

Ask CloudThinker in chat:

```text
List my 5 most recent Braintrust projects and report their names only
```

**Success state:** you get a short list of project names that match what you see in Braintrust. A 401 error means the key is wrong or expired; see [Troubleshooting](#troubleshooting).

## Example prompts

Use exact names from Braintrust. The agent looks up the object you name; it doesn't guess.

```text
How did the latest support-bot experiment score compared with the baseline experiment?
```

```text
Show the saved monitor view called production-latency and list its charts
```

```text
What are the settings of the support-bot project, including its default preprocessor?
```

```text
Give me a Braintrust link to the support-bot-v2 experiment so I can share it
```

## Troubleshooting

<Accordion title="Every request fails with 401 Unauthorized">
Braintrust didn't accept the key. It may be mistyped, deleted, or expired. Create a new key, then open **Connections → Braintrust** and replace the value.
</Accordion>

<Accordion title="403 Forbidden, or a project or experiment isn't found">
The key only sees what its creator's account sees. Check that account's access to the project or experiment in Braintrust, and check the exact name you used.
</Accordion>

<Accordion title="It worked for months, then every request started failing">
The key expired. Braintrust keys can't be renewed, so create a new key and update the connection. Set a calendar reminder before the next expiration.
</Accordion>

<Accordion title="My organization uses the EU data plane or self-hosts Braintrust">
This connection only talks to `api.braintrust.dev`. It can't reach EU data plane or self-hosted deployments.
</Accordion>

<Accordion title="The agent won't run a query or change something">
That's by design. The connection allows only the six read actions listed in [What agents can do](#what-agents-can-do).
</Accordion>

## Security

<ConnectionSecurity />

- **Account scope**: the key acts as its creator, so create it from an account with read-only access.
- **Expiration**: pick an expiration you'll track, and rotate the key before it lapses.

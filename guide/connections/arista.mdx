Connect Arista EOS so CloudThinker can inspect interfaces, BGP peers, MLAG, and LLDP neighbors. The connection uses the credentials described below, with access limited by the account behind it.

## Prerequisites

- Access to the Arista EOS account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Ask the switch administrator for an EOS account with read access through the switch’s HTTPS eAPI. Obtain the issuing CA certificate if the switch uses a private certificate.

    See the [Arista EOS documentation](https://anta.arista.com/stable/api/device/) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Arista EOS**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Switch URL** | Yes | The HTTPS address of the switch's eAPI, such as https://leaf1.example.com. Enable it with management api http-commands. |
| **Username** | Yes | An EOS login. A read-only role can inspect; changing an interface needs a role that can configure it. |
| **Password** | Yes | The password of that login. |
| **CA certificate (optional)** | Optional | PEM of the private CA that issued the switch certificate. Leave empty to use public trust. The certificate and hostname are always checked. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

A read-only EOS role is enough for interface, BGP, MLAG, and LLDP inspection. Interface changes require a role with the corresponding configuration permissions.

<Tip>
Start with read access to the smallest useful scope. Add write permissions only when you want a supported change, and review the exact target before approving it.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Interface health and errors** | Inspect interfaces, BGP peers, MLAG, and LLDP neighbors. |
| **BGP and LLDP neighbors** | Inspect bGP and LLDP neighbors within the connected account’s scope. |
| **MLAG peer health** | Inspect mLAG peer health within the connected account’s scope. |

Changes are limited to supported interface state and description operations. Management interfaces and the interface carrying the connection are protected from state changes.

Supported changes follow your [Approvals](/guide/approvals/overview) settings. A provider permission and a CloudThinker approval are separate requirements. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Arista EOS connection, summarize its account or service scope and interface health and errors. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize interface health and errors in Arista EOS and highlight items needing attention.
Review bgp and lldp neighbors and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

Connect a Grafana instance so [CloudThinker](/guide/agents/overview) can work from the dashboards, data sources, and alert rules your team already has. Agents can find the right dashboard, run Prometheus or Loki queries through Grafana, and tell you which alerts are firing, without you copying panels into chat. The connection signs in with a **service account token**, a non-human Grafana identity you create and scope to the **Viewer** role.

## Supported platforms

| Platform | Supported |
|----------|-----------|
| **Grafana OSS** | Yes, on versions with service accounts |
| **Grafana Enterprise** | Yes |
| **Grafana Cloud** | Yes |

## Prerequisites

- A Grafana instance reachable from CloudThinker over HTTPS.
- Grafana admin access to create a service account.

## Setup

<Steps>
  <Step title="Create a Viewer service account">
    In Grafana, go to **Administration → Users and access → Service accounts** and click **Add service account**. Set:

    - **Display name**: `cloudthinker-readonly`
    - **Role**: **Viewer**

    Click **Create**.
  </Step>
  <Step title="Generate a token">
    On the new service account's page, click **Add service account token**, name it (for example `cloudthinker`), set an expiration, and click **Generate token**.

    Copy the token now. It starts with `glsa_`, and Grafana won't show it again.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Workspace Settings → Connections**, stay on the **Builtin Connections** tab, and select **Grafana**. Fill in:

    - **GRAFANA_URL**: your instance's base URL, such as `https://grafana.example.com` or `https://your-stack.grafana.net`
    - **GRAFANA_SERVICE_ACCOUNT_TOKEN**: the `glsa_` token

    Click **Connect**.

    **Success state:** the connection shows **Testing**, then **Connected**.
  </Step>
</Steps>

## Connection details

| Field | Required | Example | Description |
|-------|----------|---------|-------------|
| **GRAFANA_URL** | Yes | `https://grafana.example.com` | Base URL of the instance, the address you open in a browser |
| **GRAFANA_SERVICE_ACCOUNT_TOKEN** | Yes | `glsa_...` | Token for the service account agents act as |

## Required permissions

| Role | What agents get | Use it when |
|------|-----------------|-------------|
| **Viewer** | Search and read dashboards and folders, query data sources, read alert rules and annotations | Investigation. Recommended |
| **Editor** | Viewer, plus changing dashboards, annotations, and alert rules | Only if you want agents to make those changes |

Agents see only what the service account can see. If a dashboard folder has restricted permissions, add the service account to that folder or agents won't find its dashboards.

<Tip>
Keep the service account on **Viewer**. Grafana then refuses any change on its side, whatever an agent asks for.
</Tip>

## Agent capabilities

| Capability | What agents can do |
|------------|--------------------|
| **Dashboards and folders** | Search by name or tag, read a dashboard's panels and queries, and run a panel's query |
| **Metrics** | Run PromQL against Prometheus data sources, with label and metric discovery |
| **Logs** | Run LogQL against Loki data sources, and search logs across supported data sources |
| **Other data sources** | Query Elasticsearch, CloudWatch, and ClickHouse data sources configured in Grafana |
| **Alerting** | List alert rules and their state, and show which are firing |
| **Annotations** | Read annotations, such as deploy markers, for the time around an issue |
| **Grafana Cloud features** | Where your stack has them: Grafana Incident, OnCall schedules, Sift investigations, and Pyroscope profiles |

Agents query through Grafana, so a data source only works if it's configured in your Grafana instance and the service account can use it.

When Grafana is connected, [Resolve](/guide/incident/overview) can also read your alert rules and query metric ranges while it investigates an incident. Sending Grafana alerts into Resolve is a separate webhook setup: see [Webhook integrations](/guide/incident/webhook-integrations/overview).

### Verify the connection

```text
List the Grafana alert rules that are firing right now, and the data sources configured in Grafana
```

Expect the names and states of firing rules (or a note that none are firing), then each data source with its type, such as Prometheus or Loki.

### Example prompts

```text
Find the Grafana dashboard for the checkout service and summarize what its panels show for the last hour
Using Grafana's Prometheus data source, which pods restarted most in the last 24 hours?
Search Loki through Grafana for errors from the payments app since 09:00 and group them by message
```

## Write access

The connection can call Grafana tools that change things, such as editing a dashboard, adding an annotation, or changing an alert rule. Any call that changes something goes through [Approvals](/guide/approvals/overview), and Grafana only allows it if the service account's role does. With **Viewer**, Grafana refuses all of them.

## Troubleshooting

<Accordion title="Connection failed">
- Open **GRAFANA_URL** from a browser outside your network to check it's reachable from the internet, or allow CloudThinker through your firewall.
- Check that the TLS certificate is valid and not self-signed.
- Use the base URL only, without a dashboard path.
</Accordion>

<Accordion title="Authentication failed or 401">
- Recheck the token. Copy it again if a character was lost.
- Check that the token hasn't expired and the service account is enabled in **Administration → Users and access → Service accounts**.
</Accordion>

<Accordion title="Token expired">
Open the service account in Grafana, generate a new token, and paste it into **GRAFANA_SERVICE_ACCOUNT_TOKEN** on the connection. Delete the old token in Grafana.
</Accordion>

<Accordion title="Agents can't find a dashboard you can see">
The dashboard sits in a folder the service account can't view. Grant the service account **View** on that folder.
</Accordion>

<Accordion title="A data source query fails">
Confirm the data source works in Grafana's **Explore** view, and that the service account has query access to it. Agents can only query data sources that Grafana itself can query.
</Accordion>

<Accordion title="Incident, OnCall, or Sift requests fail">
Those are Grafana Cloud features. They work only if your stack has them turned on.
</Accordion>

## Security

<ConnectionSecurity />

- **Viewer only**: give the CloudThinker service account **Viewer**, never **Admin**.
- **Expiring tokens**: set an expiration on every token and rotate it on your normal schedule.

Connect Heroku to let CloudThinker agents list your apps, read dyno formation and recent logs, review add-ons and their plans, and show which pipeline stage each app sits in. The connection is **read-only** and uses one Heroku **API token**, which can reach every app and team its user can.

---

## Prerequisites

- A Heroku account that belongs to the apps, teams, and pipelines you want to investigate.
- The Heroku CLI, signed in as that account.

---

## Setup

<Steps>
  <Step title="Create an API token">
    Run this in the Heroku CLI, signed in as the account CloudThinker should use:

    ```bash
    heroku authorizations:create -d cloudthinker
    ```

    Copy the value shown as `Token`. It starts with `HRKU-`. Keep the default `global` scope; see [Required permissions](#required-permissions) for why.

    The token doesn't expire unless you add `--expires-in <seconds>`. To cancel it later, run `heroku authorizations:revoke <id>`.

    You can also create an authorization in the Heroku Dashboard under **Account settings → Applications**.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Go to **Connections → Heroku**, paste the token into **API token**, and click **Connect**.

    **Success state:** Heroku shows a **Connected** status.
  </Step>
  <Step title="Run the verify prompt">
    Run the [verify prompt](#verify-the-connection) to confirm the token can read your account.

    **Success state:** CloudThinker returns your apps with their dyno formation.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **API token** | Authorization token from `heroku authorizations:create`. It inherits the account's access to every app and team it can reach. | `HRKU-...` |

## Required permissions

A Heroku token can't be limited to some apps. It can reach whatever its user can, so least privilege comes from the account you create it with.

- **Use the `global` scope.** The narrower scopes (`read`, `write`, `read-protected`, `write-protected`) can't read the token's own account. Without that, Heroku can't work out which apps and pipelines the token owns, so those lists fail.
- **Use a dedicated account.** Add it only to the teams and apps CloudThinker needs.
- **If you sign in with SSO**, Heroku may not let that account create a long-lived token. Use a separate non-SSO user for the integration.

<Tip>
CloudThinker exposes only 12 read tools for Heroku, so agents can't restart, scale, or change apps through this connection, whatever the token allows.
</Tip>

## Agent capabilities

| Capability | Description |
|------------|-------------|
| **Apps** | List apps and read one app's stack, region, and maintenance state |
| **Logs** | Read an app's recent application log lines, without router noise |
| **Dynos** | Show the dyno formation: type, size, quantity, and state of each process |
| **Add-ons** | List add-ons per app or across the account, and browse add-on services and plans |
| **Teams and private spaces** | List the teams and private spaces the account can reach |
| **Pipelines** | List pipelines and show the apps in each stage |

Agents never read config vars, environment values, or database credentials. For queries against a Heroku Postgres database, add a separate [PostgreSQL connection](/guide/connections/postgresql).

### Verify the connection

```text
Check my Heroku connection and list my apps with their dyno formation
```

### Example prompts

```text
My checkout app on Heroku is throwing errors. Read its recent logs and dynos, and tell me what's wrong
List the add-on plans attached to each of my Heroku apps as a table
Which stage of the web pipeline is each app in, and is any app in maintenance mode?
```

Name the app or pipeline in your prompt when the account has many apps. The answer stays focused on it.

## Troubleshooting

<Accordion title="401 Unauthorized">
The token is wrong, expired, or revoked. Create a new one with `heroku authorizations:create` and update the connection.
</Accordion>

<Accordion title="403 Forbidden on an app or team">
The token's account isn't a member of that app or team. Add the account in Heroku, then ask again.
</Accordion>

<Accordion title="404 Couldn't find that user">
The token can't read its own account, which is what a narrow scope looks like. Add-ons and teams still list, but apps and pipelines fail. Create a new authorization with the default `global` scope and update the connection.
</Accordion>

<Accordion title="404 for a named app, add-on, or pipeline">
The name is wrong, or it belongs to an account the token can't see. Ask CloudThinker to list your apps or pipelines, then use a name from that list.
</Accordion>

<Accordion title="429 Too Many Requests">
Heroku throttled the account. Wait a few minutes, then ask about one app at a time so each run makes fewer calls.
</Accordion>

<Accordion title="No private spaces are listed">
Private spaces exist only on some Heroku plans. If your account has none, an empty list is the correct answer.
</Accordion>

## Security

<ConnectionSecurity />

- **Plan rotation**: pass `--expires-in` when you create the token, and run `heroku authorizations:revoke <id>` when you no longer need it.
- **Treat logs as sensitive**: an app can print secrets into its own logs. CloudThinker avoids quoting lines that look like tokens or passwords, but don't rely on that alone.

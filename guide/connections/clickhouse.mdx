Connect ClickHouse to let CloudThinker list databases and tables, check part counts and table sizes, rank slow queries from `system.query_log`, and answer questions with analytical SQL. CloudThinker signs in as a ClickHouse user over the HTTP interface, and a new connection is read-only until you change **Write access**.

---

## Prerequisites

- A ClickHouse server reachable from CloudThinker on its **HTTP interface**: `8443` with TLS, `8123` without. ClickHouse Cloud and self-hosted clusters both work. The native TCP port (`9000`) is not used.
- An admin login on ClickHouse to create a dedicated user.

---

## Setup

<Steps>
  <Step title="Create a dedicated user with read access">
    Connect as an admin and run:
    ```sql
    CREATE USER cloudthinker IDENTIFIED BY 'your-secure-password';
    GRANT SELECT ON your_database.* TO cloudthinker;
    GRANT SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT SELECT ON system.tables TO cloudthinker;
    GRANT SELECT ON system.columns TO cloudthinker;
    GRANT SELECT ON system.parts TO cloudthinker;
    GRANT SELECT ON system.query_log TO cloudthinker;
    ```
    The `system.*` grants power table health and slow-query answers. Skip them and those questions fail while schema questions still work.
  </Step>
  <Step title="Lock the user to read-only at the server (recommended)">
    Skip this step if you plan to turn **Write access** on. Otherwise, add a settings profile so ClickHouse itself refuses writes, whatever any client asks for:
    ```sql
    CREATE SETTINGS PROFILE cloudthinker_readonly SETTINGS readonly = 1 READONLY;
    ALTER USER cloudthinker SETTINGS PROFILE cloudthinker_readonly;
    ```
  </Step>
  <Step title="Open network access">
    - **ClickHouse Cloud**: add CloudThinker to the service's IP access list under the service **Settings → Security**.
    - **Self-hosted**: allow inbound `8443` (or `8123`) from CloudThinker in your firewall or security group.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Go to **Connections → ClickHouse**, fill in the fields from [Connection details](#connection-details), leave **Write access** on **Read-only (default)**, and click **Connect**.

    CloudThinker runs one `SELECT version()` as that user.

    **Success state:** ClickHouse shows a **Connected** status, and the message reads `ClickHouse <version> reachable as cloudthinker`.
  </Step>
</Steps>

## Connection details

| Field | Required | Description | Default |
|-------|----------|-------------|---------|
| **Host** | Yes | Hostname only, no `https://` and no port. ClickHouse Cloud looks like `abc123.ap-southeast-1.aws.clickhouse.cloud` | |
| **Port** | Yes | HTTP interface port: `8443` with TLS, `8123` without | `8443` |
| **Username** | Yes | The dedicated user, for example `cloudthinker` | |
| **Password** | Yes | That user's password | |
| **Use TLS** | No | HTTPS instead of plain HTTP | **Yes** |
| **Verify the TLS certificate** | No | Set to **No** only for a self-signed or internal-CA certificate. Shown only when TLS is on | **Yes (default)** |
| **Default database** | No | Database used when a query doesn't name one. Blank uses the server default | Blank |
| **Write access** | No | **Read-only (default)** or **Full access** | **Read-only (default)** |
| **Allow DROP and TRUNCATE** | No | **Blocked (default)** or **Allowed**. Shown only with **Full access** | **Blocked (default)** |

<Tip>
Change **Port** and **Use TLS** together. `8443` goes with TLS on, `8123` with TLS off. A mismatch fails at connect time.
</Tip>

## Required permissions

The Setup grants cover everything read-only. Add write grants only if you set **Write access** to **Full access**, and only on the databases the agent should change:

```sql
GRANT INSERT, ALTER, CREATE TABLE, CREATE VIEW ON your_database.* TO cloudthinker;
-- Only if the agent should remove tables:
GRANT DROP TABLE, TRUNCATE ON your_database.* TO cloudthinker;
```

<Tip>
Never grant writes on `*.*`. The ClickHouse grants are the real boundary: the **Write access** field only decides whether CloudThinker sends `readonly=1`, and it can't give the user a privilege ClickHouse didn't grant.
</Tip>

## Agent capabilities

| Capability | Description |
|------------|-------------|
| **Schema discovery** | List databases and tables with engine, sorting key, row count, and column types |
| **Analytical queries** | Run SQL with aggregates, joins, and window functions |
| **Table health** | Check part counts, compressed and uncompressed size, and index granularity from `system.parts` |
| **Query investigation** | Rank slow or expensive queries from `system.query_log` |
| **Changes** | With **Full access** only: insert rows, alter tables, and create tables and views |

### Verify the connection

```text
List the ClickHouse databases and the tables in each one
```

**Success state:** CloudThinker returns your databases with their tables, engines, and row counts.

### Example prompts

```text
Which ClickHouse tables grew the most in the last week?
Show the 10 slowest queries from system.query_log in the last 24 hours, with the user and table for each
Suggest a better sorting key for our largest MergeTree table, based on the queries that hit it
```

## Write access

| Write access | Allow DROP and TRUNCATE | What the agent can do |
|--------------|-------------------------|------------------------|
| **Read-only (default)** | Hidden | `SELECT` only. ClickHouse refuses anything else with error `164` (`READONLY`) |
| **Full access** | **Blocked (default)** | `INSERT`, `ALTER`, and `CREATE`. `DROP TABLE` and `TRUNCATE` are refused |
| **Full access** | **Allowed** | Everything above, plus dropping tables and databases |

Before you choose **Full access**:

- **Blocked protects the table, not the rows.** `ALTER TABLE ... DELETE`, `DROP PARTITION`, and `DROP COLUMN` still run and still remove data. Treat **Full access** as "the agent can destroy data".
- **Nothing rolls back.** ClickHouse has no transactions, so recovery means restoring from a backup.

To change **Write access** on an existing connection, click **Disconnect**, then **Connect** again with the new value.

<Warning>
ClickHouse runs every query through one tool, so CloudThinker can't ask for approval on writes separately from reads. With **Full access**, a write runs without a per-query confirmation. Try it on a staging cluster before the one your dashboards read from.
</Warning>

## Troubleshooting

<Accordion title="ClickHouse rejected the username or password">
Check the user exists with `SHOW USERS;`, then retype the password instead of pasting it. A value with a line break is rejected before CloudThinker contacts the server. On ClickHouse Cloud, create a database user rather than reusing a console sign-in.
</Accordion>

<Accordion title="ClickHouse is unreachable, or rejected the request path">
- **Port** and **Use TLS** must agree: `8443` with TLS, `8123` without. `9000` is the native TCP port, not the HTTP interface.
- **Host** must have no `https://` prefix and no `:port` suffix.
- On ClickHouse Cloud, add CloudThinker to the service IP access list. Self-hosted, check the firewall and that `<listen_host>` covers the exposed interface.
</Accordion>

<Accordion title="ClickHouse did not answer in time">
On ClickHouse Cloud, an idle service suspends and connections time out until it wakes. Wake the service in the ClickHouse Cloud console, then connect again.
</Accordion>

<Accordion title="ClickHouse has no database named ...">
The **Default database** doesn't exist. Names are case-sensitive. Fix the spelling or leave the field blank.
</Accordion>

<Accordion title="Cannot execute query in readonly mode">
The connection is read-only, which is the default. If the agent should write, reconnect with **Write access** set to **Full access**. If it still fails, the limit is on the server: run `SHOW CREATE USER cloudthinker;` and look for a `readonly` settings profile or missing write grants.
</Accordion>

<Accordion title="The table list is empty">
The user needs `SHOW TABLES` and `SELECT` on the database, not only on single tables, plus `SELECT` on `system.tables`.
</Accordion>

## Security

<ConnectionSecurity />

- **Grants over switches**: the privileges on the ClickHouse user decide what's possible. **Write access** only decides what CloudThinker asks for.
- **Server-side read-only**: for a connection that must never write, keep the `READONLY` settings profile from Setup step 2. No client can lift it.

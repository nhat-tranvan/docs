Connect a Pinecone project to let CloudThinker agents list indexes, read record counts per namespace, search records by text, and create indexes or upsert records after you approve. The connection signs in with one Pinecone **project API key**, so it reaches the indexes of that one project only.

## Prerequisites

- A Pinecone project with the indexes you want agents to reach.
- Permission to create API keys in that project.
- For search and writes: indexes created with **integrated embedding**, meaning Pinecone generates the vectors from text using a hosted embedding model. Indexes built from vectors you embedded yourself can be listed and described, but not searched or written through this connection.

## Setup

<Steps>
  <Step title="Create an API key">
    In the Pinecone console, open the project agents should read and go to **API keys**. Click **Create API key**, name it `cloudthinker`, and pick the narrowest permissions your plan allows (see [Required permissions](#required-permissions)). Click **Create key**.
  </Step>
  <Step title="Copy the key">
    Copy the key right away. Pinecone shows it only once.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **Connections** in the sidebar and select **Pinecone**. Paste the key into **PINECONE_API_KEY** and click **Connect**.

    **Success state:** the connection shows a **Connected** status. Run the verify prompt below to confirm the key works against your project.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **PINECONE_API_KEY** | API key for one Pinecone project | `<your-api-key>` |

To reach indexes in another project, add a key from that project as a separate connection.

## Required permissions

| You want agents to | Key needs |
|--------------------|-----------|
| List indexes, read stats, search, and rerank | Read access |
| Create an index or upsert records | Write access |

<Tip>
Start with a read-only key if your Pinecone plan lets you narrow API key permissions. Some plans only offer full access, in which case approvals in CloudThinker are what stop unwanted writes.
</Tip>

## Agent capabilities

| Capability | What agents can do | Approval |
|------------|--------------------|----------|
| **Index inventory** | List indexes, read each index's configuration, dimensions, record counts, and namespaces | No |
| **Search** | Search one integrated-embedding index by text, or search several at once with deduplicated, reranked results | No |
| **Rerank** | Rerank a list of documents you supply, without an index | No |
| **Create an index** | Create a new integrated-embedding index | Yes |
| **Upsert records** | Insert or update records in a namespace of an integrated-embedding index | Yes |

Before a write, the agent shows you the exact index name, namespace, embedding model, and records, then waits for your confirmation in the conversation.

### Verify the connection

```text
List my Pinecone indexes with each one's record count and namespaces
```

Expect every index in the project with its dimension, record count, and namespaces such as `__default__`.

### Example prompts

```text
Which Pinecone indexes use integrated embedding, and how many records does each namespace hold?
Search the docs-search index for "refund policy" and show the five best matches with scores
Upsert these three FAQ records into the faq namespace of docs-search
```

## Troubleshooting

<Accordion title="Every request fails with 401">
The key is missing, mistyped, deleted, or from a different project. Create a new key in the right project, then edit the connection and paste it into **PINECONE_API_KEY**.
</Accordion>

<Accordion title="Search returns nothing, or an index can't be searched">
The index doesn't use integrated embedding, or the namespace is wrong. Ask the agent which indexes use integrated embedding. If you didn't name a namespace, records usually live in `__default__`.
</Accordion>

<Accordion title="The agent finds no indexes">
The project has no indexes yet, or the key belongs to a different project. Check the project in the Pinecone console, or ask the agent to create an integrated-embedding index.
</Accordion>

<Accordion title="A write fails after I approved it">
The key lacks write access, or the target index doesn't use integrated embedding. Check the key's permissions in the Pinecone console.
</Accordion>

<Accordion title="Requests return 429">
Pinecone is rate-limiting the project. Wait a moment, then ask again, and avoid running several large searches at once.
</Accordion>

## Security

<ConnectionSecurity />

- **One project per key**: create the key in the single project agents should reach, and delete it in Pinecone when you remove the connection.
- **Read-only where your plan allows it**: a key without write access can't create indexes or upsert, whatever gets approved.

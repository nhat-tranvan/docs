Connect Cribl Stream so CloudThinker can check sources, destinations, routes, and worker health. The connection uses the credentials described below, with access limited by the account behind it.

## Prerequisites

- Access to the Cribl Stream account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    For Cribl.Cloud, obtain an API client ID and secret from your organization administrator. For self-managed Cribl Stream, use a dedicated user’s username and password.

    See the [Cribl Stream documentation](https://docs.cribl.io/cribl-as-code/4.1/) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Cribl Stream**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Leader URL** | Yes | Cribl.Cloud workspace address such as https://main-acme.cribl.cloud, or your self-managed leader https address. |
| **Sign-in** | Yes | Enter the sign-in for this connection. Options: Cribl.Cloud API credential, Self-managed username and password. Default: cloud. |
| **Client ID or username** | Yes | The Cribl.Cloud client ID, or the self-managed username. |
| **Client secret or password** | Yes | The Cribl.Cloud client secret, or the self-managed password. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

Grant access to the worker groups, pipelines, routes, sources, and destinations you need.

<Tip>
Start with read access to the smallest useful scope. This connection is read-only; adding write permissions does not enable configuration or record updates.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Worker groups and pipeline health** | Check sources, destinations, routes, and worker health. |
| **Routes, sources, and destinations** | Inspect routes, sources, and destinations within the connected account’s scope. |
| **Configuration review** | Read pipeline and route configuration; no edits, commits, or deployments. |

Choose the sign-in mode matching your deployment. A Cribl.Cloud client secret and a self-managed user password are different credential types.

This connection is read-only. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Cribl Stream connection, summarize its account or service scope and worker groups and pipeline health. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize worker groups and pipeline health in Cribl Stream and highlight items needing attention.
Review routes, sources, and destinations and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

<ConnectionSecurity />

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

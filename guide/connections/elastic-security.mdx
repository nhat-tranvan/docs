Connect Elastic Security so CloudThinker can review detection alerts, cases, and detection rules. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Elastic Security account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create an Elasticsearch API key for access to Kibana APIs and copy its encoded value. See the [vendor's authentication documentation](https://www.elastic.co/docs/deploy-manage/api-keys) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Elastic Security**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Enter the Kibana URL, not the Elasticsearch URL. Select the space containing your detection rules and cases.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Kibana URL** | Yes | The Kibana address, for example https://kibana.example.internal:5601. Use the Kibana URL, not the Elasticsearch one. |
| **API key** | Yes | Paste the encoded value. Its role needs Security and Cases privileges in Kibana and read on the alerts index. |
| **Kibana space** | Yes | The space ID that holds your Security rules and alerts. Leave default unless you use another space. Default: `default`. |
| **TLS certificate** | Yes | Options: **Verify SSL certificate**, **Skip SSL verification**. Default: `true`. |

## Required permissions

Read the Security alerts and Cases data for the selected Kibana space and alerts indexes. Changes require the corresponding additional write privileges.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| Detection alerts | Read alerts and rule context. |
| Case review | Inspect cases and attached alert context. |
| Response updates | Change alert status or case status and assignment after approval. |

Supported changes cover alert status and case status or assignment. Rule edits, exceptions, timelines, and case deletion are excluded.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Elastic Security connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Elastic Security to review detection alerts, cases, and detection rules.
Summarize the highest-priority items visible through my Elastic Security connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Elastic Security. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Elastic Security when access is no longer needed, and update the connection after rotation.

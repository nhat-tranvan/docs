Connect Kong Konnect so CloudThinker can inspect control planes, gateway configuration, and traffic. The connection uses a dedicated API credential, with access limited by the account behind it.

## Prerequisites

- Access to the Kong Konnect account or service containing the records you want to investigate.
- Permission to prepare the credential below, or an administrator who can prepare it for you.
- The **Admin** role in your CloudThinker workspace to add a connection. See [Roles](/guide/security/roles).
- A network path from CloudThinker to the service. For private services, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Create a Konnect personal access token for the intended user, then choose the region containing the control planes you want to inspect.

    See the [Kong Konnect documentation](https://developer.konghq.com/konnect-api/) for the provider’s credential and access controls. Keep secrets out of chat messages.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Workspace → Connections**, find **Kong Konnect**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), then click **Connect**.

    **Success state:** the connection shows a **Connected** status. Use the verification prompt below to check that it reaches the intended account and records.
  </Step>
  <Step title="Check the scope">
    Open a conversation, select the new connection with **#**, and ask for a read-only summary. Check the account, region, and resources in the answer before using it for an investigation.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Kong Konnect access token** | Yes | Enter the kong konnect access token for this connection. |
| **Kong Konnect region** | Yes | Enter the kong konnect region for this connection. Options: United States, Europe, Australia, India. Default: us. |

Use the address and credential from the same account or deployment. Keep any region, organization, or page selection aligned with that account.

## Required permissions

The token inherits the user’s current Konnect role assignments. Limit those assignments to the required control planes and services.

<Tip>
Start with read access to the smallest useful scope. Add write permissions only when you want a supported change, and review the exact target before approving it.
</Tip>

## Agent capabilities

| Capability | What you can ask for |
|---|---|
| **Control planes and gateway configuration** | Inspect control planes, gateway configuration, and traffic. |
| **Traffic and service context** | Inspect traffic and service context within the connected account’s scope. |
| **Approved operations** | Inspect approved operations within the connected account’s scope. |

This is the Kong Konnect connection. A self-managed Kong Gateway Admin API address is not a substitute for Konnect credentials.

All Kong connection operations, including discovery and other reads, use an approval-gated execution tool and follow your [Approvals](/guide/approvals/overview) settings. A provider permission and a CloudThinker approval are separate requirements. A permission error is not an empty result; ask which checks failed when the answer is incomplete.

### Verify the connection

```text
Using this Kong Konnect connection, summarize its account or service scope and control planes and gateway configuration. Report any access failures without changing anything.
```

Check that the answer names the expected service and returns current records, or explains why a read failed. An empty collection alone is not proof that the entire service is healthy.

### Example prompts

```text
Summarize control planes and gateway configuration in Kong Konnect and highlight items needing attention.
Review traffic and service context and explain the limits of the data you could read.
```

## Troubleshooting

<Accordion title="Authentication fails">
  Check that the credential belongs to the account or deployment selected in the form. Replace a revoked or expired credential in the connection; do not paste it into the conversation.
</Accordion>
<Accordion title="Some records are missing or access is denied">
  Check the credential’s role and resource scope against [Required permissions](#required-permissions). Ask CloudThinker to name the failed check. Do not interpret a denied read as an empty collection.
</Accordion>
<Accordion title="The service cannot be reached">
  Check the service address, region, and network allowlist. If the form accepts a CA certificate, supply the CA that issued the service’s certificate. For private services, check the network route from CloudThinker.
</Accordion>

## Security

- Keep the credential scoped to the resources this workspace needs. Replace it in CloudThinker when you rotate or revoke it at the provider.

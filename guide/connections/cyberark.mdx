Connect CyberArk to let CloudThinker audit safes, safe members, and privileged accounts. The connection uses **a dedicated CyberArk user**.

## Prerequisites

- An account with access to the CyberArk resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in CyberArk">
    Choose the deployment your administrator provides. Privilege Cloud needs the PVWA address, Identity address, and a service user configured for that authentication flow. A self-hosted PAM connection uses either a CyberArk Vault user or LDAP user. Obtain the supported account configuration from your CyberArk administrator; an interactive MFA-only account is not a substitute.

    Follow the [vendor’s credential and authentication guidance](https://docs.cyberark.com/privilege-cloud-shared-services/latest/en/content/webservices/authentication.htm) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **CyberArk**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Deployment** | Yes | Use the value supplied for this connection. Choose **Privilege Cloud**, **Self-hosted PAM, CyberArk user**, **Self-hosted PAM, LDAP user**. Default: **Privilege Cloud**. |
| **PVWA URL** | Yes | Privilege Cloud: https://&lt;subdomain&gt;.privilegecloud.cyberark.cloud. Self-hosted: your PVWA address, without /PasswordVault. |
| **Identity URL (Privilege Cloud)** | Privilege Cloud only | Privilege Cloud only: https://&lt;tenant&gt;.id.cyberark.cloud. Leave empty for self-hosted. |
| **Username** | Yes | Privilege Cloud: an OAuth2 confidential client service user. Self-hosted: a user that is a member of the safes to audit, with List accounts and View Safe members. |
| **Password** | Yes | The service user's password or the Vault or LDAP user's password. |
| **TLS certificate** | Yes | Use the value supplied for this connection. Choose **Verify SSL certificate**, **Skip SSL verification**. Default: **Verify SSL certificate**. |

The Identity URL is required only for Privilege Cloud. For a self-hosted Vault or LDAP deployment, leave it empty.

## Required permissions

Membership of only the safes being audited, with permission to list accounts and view safe membership. This connector audits account metadata and rotation health; it does not retrieve stored passwords.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | List safes and inspect membership |
| Investigation | Review privileged account metadata |
| Investigation | Find unmanaged accounts and rotation failures |

### Verify the connection

```text
Audit CyberArk safe memberships and account rotation health without retrieving passwords. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Audit CyberArk safe memberships and account rotation health without retrieving passwords
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. Privilege Cloud requires Identity URL. Self-hosted Vault and LDAP modes do not. Keep certificate verification enabled with a trusted server certificate.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

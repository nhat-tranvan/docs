Connect Tenable One so CloudThinker can review vulnerability findings, affected assets, and scan health. The connection uses a Tenable access-key and secret-key pair.

## Prerequisites

- Access to the Tenable One account or installation containing the data you want to investigate.
- A workspace role that can add connections. See [Roles](/guide/security/roles).
- Permission to authorize the account or obtain the credentials described below.

## Setup

<Steps>
  <Step title="Prepare access">
    In Tenable, open **Settings → My Account → API Keys** and generate a key pair for the dedicated investigation user. Save both keys when displayed. Confirm whether your tenant uses the commercial or FedRAMP cloud before selecting Tenable cloud in CloudThinker.

    See the [provider documentation](https://docs.tenable.com/vulnerability-management/Content/Settings/my-account/GenerateAPIKey.htm) for its current access requirements.
  </Step>
  <Step title="Add the connection">
    Open **Connections**, find **Tenable One**, and choose **Connect**. Enter the fields in [Connection details](#connection-details), then click **Connect**. Enter credentials only in the connection form; do not include them in a chat message.

    **Success state:** the connection shows **Connected**. This confirms the connection was established; run the verification prompt below to check the data access needed for an investigation.
  </Step>
  <Step title="Check the intended scope">
    Run the verification prompt below. Confirm the returned account, project, or resource names belong to the intended scope before asking for a deeper investigation. If a section fails, check its permissions rather than interpreting the failure as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **Tenable cloud** | Cloud containing your tenant; defaults to the commercial cloud. | Commercial or FedRAMP |
| **Access key** | Access key of the dedicated Tenable user. | Copy from Tenable |
| **Secret key** | Secret key generated with that access key. | Enter in the connection form |

## Required permissions

A Basic user with permission to view the relevant scans can perform vulnerability investigations. Scanner-health reads need Scan Manager access. Keys inherit their user’s permissions and licensed-product access, so use a dedicated account with the minimum required scope.

## Agent capabilities

| Capability | What CloudThinker can do |
|------------|-------------------------|
| **Vulnerabilities** | Review findings by severity and vulnerability details. |
| **Assets** | Identify assets affected by the selected findings. |
| **Scan health** | Inspect scan runs and, when permitted, scanner availability. |

This connection is read-only. It does not launch scans, change scan settings, accept risk, or remediate hosts. Findings describe the available scan data; they do not prove that an asset was scanned recently.

### Verify the connection

```text
Summarize Tenable vulnerabilities and recent scan health, separating scanner permission failures from successful reads
```

Expect named resources or a clear empty result for each successful read. Keep any permission errors separate from the resources that were successfully inspected.

### Example prompts

```text
Show critical vulnerabilities and the assets affected by the selected finding
Find scans with recent failed runs and explain their current state
```

Use a resource returned by the verification step and a short time range where relevant. Narrow requests are easier to verify than account-wide conclusions.

## Troubleshooting

<Accordion title="Credentials are rejected">
Check the credential fields belong to the same account and have not expired or been revoked. Replace credentials in the connection form, then rerun the verification prompt.
</Accordion>

<Accordion title="Vulnerabilities work but scanner health is denied">
Scanner reads require additional permissions. Ask the Tenable administrator whether Scan Manager access is appropriate; do not broaden the account if vulnerability investigation alone meets your needs.
</Accordion>

<Accordion title="Requests fail or results are incomplete">
Check the provider’s availability, the selected resource scope, and any returned permission or rate-limit message. Narrow the request before retrying. For a private API, confirm the network route from CloudThinker itself, not only from your workstation.
</Accordion>

## Security

<ConnectionSecurity />

- Keep access limited to the intended account and resources. Replace or revoke credentials when the connection is no longer needed.

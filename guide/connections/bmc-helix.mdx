Connect BMC Helix ITSM, formerly BMC Remedy, so [CloudThinker](/guide/agents/overview) can investigate open incidents and their work logs, changes that start near an incident, and open problems. The connection signs in to the AR System REST API with the username and password of a Helix account, and it only reads.

## Prerequisites

- The AR System REST address of your Helix tenant. On BMC Helix SaaS it's often `https://<tenant>-restapi.onbmc.com`, which differs from the address you open in the browser. Ask your Helix administrator if you're not sure.
- A Helix account that can sign in to the REST API and read the Incident, Change, and Problem forms.
- An address CloudThinker can reach over HTTPS. For an on-premises server, follow [Reaching private services](/guide/connections/overview#reaching-private-services).
- The **Admin** role in your CloudThinker workspace. See [Roles](/guide/security/roles).

## Setup

<Steps>
  <Step title="Create the account in BMC Helix">
    Ask your Helix administrator for a dedicated account, such as `cloudthinker`, with read access to incidents and their work logs, changes, and problems, and no rights to create or edit records. Every REST API request runs as an AR System user, and Helix checks that user's permissions on each form. See [BMC's REST API authentication guide](https://docs.helixops.ai/bin/Service-Management/Innovation-Suite/BMC-Helix-Innovation-Suite/is253/Developing-an-API-program/Integrating-AR-System-forms-with-a-third-party-application-by-using-the-REST-API/Access-and-authentication-for-the-REST-API/).
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, open the **Discover** tab, and select **BMC Helix ITSM**. Click **Connect**, fill in the fields below, then click **Connect** in the dialog. CloudThinker signs in, counts open incidents, and signs out.

    **Success state:** the connection shows a **Connected** status and the message `Connected to BMC Helix; <count> open incidents visible.` A `+` after the count means 500 or more. CloudThinker then opens a chat that takes a read-only deep look at the connection ("Often takes about 15 min. You can leave the chat."). To run it again later, open the card's **More** menu and choose **Try in chat**.
  </Step>
</Steps>

## Connection details

| Field | Required | Description |
|---|---|---|
| **REST URL** | Yes | The AR System REST address, for example `https://acme-restapi.onbmc.com`. Use `https://` and no path |
| **Username** | Yes | A Helix account with read access to Incident, Change, and Problem |
| **Password** | Yes | The account password. Each agent task signs out when it ends |

CloudThinker refuses redirects, so enter the exact address the REST API answers at.

## Required permissions

| Helix access | Used for |
|---|---|
| REST API sign-in | Getting a session for each task |
| Read on incidents and work logs | Open incidents and one incident's history |
| Read on changes | Changes scheduled before or after an incident |
| Read on problems | The open problem backlog |

<Tip>
Use a dedicated account that can only read. The connection never writes, but a read-only account keeps the password harmless if it leaks.
</Tip>

## Agent capabilities

| Capability | What agents can read |
|---|---|
| **Backlog overview** | Open incidents by priority, changes that start in the next 7 days by risk, and open problems by priority |
| **Incidents** | Incidents filtered by status, priority, support group, and age, with impact, urgency, group, and assignee |
| **Incident history** | One incident's details and its latest work log entries |
| **Changes** | Changes starting soon or that ran in past days, with status, risk level, and scheduled window |
| **Problems** | Open problems with status, priority, and assigned group |

Each list reads a bounded number of records, and Helix gives no total, so agents say when a list may be incomplete. A section that failed is unavailable data, not an empty list.

Agents can't create, update, assign, or resolve records, or add work notes. Make those changes in BMC Helix.

### Verify the connection

```text
Summarize my BMC Helix backlog: open incidents by priority, changes starting this week by risk, and open problems.
```

### Example prompts

```text
Which critical and high incidents are open for the Network Support group, and what does the latest work log say?
Which changes ran in the 2 days before INC000000123456 was opened?
List the open BMC Helix problems with the highest priority and their assigned groups
```

## Troubleshooting

<Accordion title="BMC Helix rejected the username or password.">
Check both values, then edit the connection and connect again.
</Accordion>

<Accordion title="BMC Helix refused the sign-in for this account. Check that it may use the REST API.">
The password is correct, but Helix doesn't let this account use the REST API. Ask your Helix administrator to allow it, then connect again.
</Accordion>

<Accordion title="The account cannot read incidents. Give it read access to the Incident form.">
The account signed in but can't read incidents. Give it read access to incidents, then connect again. During an investigation, HTTP 403 on changes or problems means it lacks read access to that area.
</Accordion>

<Accordion title="That address has no AR System REST sign-in. Use the REST address, often https://<tenant>-restapi.onbmc.com.">
The **REST URL** points to the Helix web interface or another service. Enter the REST address of your tenant instead.
</Accordion>

<Accordion title="That address answered, but not as the AR System REST API. Use the REST address, often https://<tenant>-restapi.onbmc.com.">
Something answered at that address, but not the AR System REST API. Check the address with your Helix administrator.
</Accordion>

<Accordion title="Enter the REST URL without a path, for example https://acme-restapi.onbmc.com.">
Remove any path, query, or credentials from **REST URL**. The URL must also start with `https://`.
</Accordion>

<Accordion title="Could not reach BMC Helix over HTTPS. Check the REST address and the network path.">
CloudThinker couldn't open a connection to that address. Check the address and that your firewall lets CloudThinker reach it.
</Accordion>

## Security

<ConnectionSecurity />

- Use an account that can only read, and keep it out of groups that can edit incidents or changes.
- CloudThinker signs in for each task and signs out when the task ends, so no session stays open.

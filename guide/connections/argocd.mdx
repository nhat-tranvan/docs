Connect Argo CD to let CloudThinker agents list your applications, explain why one is out of sync or degraded, read its Kubernetes events and pod logs, and sync it once you approve. The connection signs in with one Argo CD **API token** and works with self-hosted Argo CD and the Akuity Platform.

## Prerequisites

- An Argo CD server reachable from CloudThinker over HTTPS. A `localhost` or cluster-internal address won't work.
- Admin access to Argo CD, so you can create a local account and generate a token for it.
- The [Argo CD CLI](https://argo-cd.readthedocs.io/en/stable/cli_installation/) on your machine to generate the token.
- Self-hosted only: `kubectl` access to the `argocd` namespace, to edit the `argocd-cm` and `argocd-rbac-cm` ConfigMaps.

If your server is on a private network, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

Create a dedicated `cloudthinker` account instead of using `admin`. Its token then carries only the RBAC permissions you grant it, and you can revoke it without touching anyone else.

<Tabs>
  <Tab title="Self-hosted Argo CD">
    <Steps>
      <Step title="Create a local account with API key access">
        Add a `cloudthinker` account that can only use API keys, not the web login:

        ```bash
        kubectl -n argocd patch configmap argocd-cm --type merge \
          -p '{"data":{"accounts.cloudthinker":"apiKey"}}'
        ```
      </Step>
      <Step title="Generate a token">
        Sign in as an admin, then generate a token for the new account:

        ```bash
        argocd login argocd.example.com --username admin
        argocd account generate-token --account cloudthinker --expires-in 90d
        ```

        Copy the token. Add `--insecure` to both commands only if the server uses a self-signed certificate. Without `--expires-in`, the token never expires, so set a lifetime and generate a new one before it lapses.

        **Success state:** the second command prints a long token string.
      </Step>
      <Step title="Grant the account read access">
        Run `kubectl -n argocd edit configmap argocd-rbac-cm` and add these lines to the existing `policy.csv`:

        ```csv
        p, role:cloudthinker, applications, get, */*, allow
        p, role:cloudthinker, logs, get, */*, allow
        g, cloudthinker, role:cloudthinker
        ```

        Edit the ConfigMap rather than applying a new one. `kubectl apply` with a fresh `argocd-rbac-cm` replaces your whole policy and can lock other users out. To let agents change things, add the lines in [Required permissions](#required-permissions).
      </Step>
      <Step title="Add the connection in CloudThinker">
        Open **Workspace Settings → Connections**, stay on the **Builtin Connections** tab, and select **ArgoCD**. Fill in:

        - **ARGOCD_BASE_URL**: your server address, such as `https://argocd.example.com`
        - **ARGOCD_API_TOKEN**: the token you copied
        - **NODE_TLS_REJECT_UNAUTHORIZED** (TLS verification): **Verify TLS (default)**, or **Skip TLS verification** for a self-signed certificate
        - **READ_ONLY**: change it to **Read-only**. The form defaults to **Full access**.

        Click **Connect**.

        **Success state:** the dialog closes and the connection shows **Connected**. That status doesn't prove the token or RBAC works, so run the verify prompt below.
      </Step>
    </Steps>
  </Tab>
  <Tab title="Akuity Platform">
    <Steps>
      <Step title="Create a system account">
        In the [Akuity Portal](https://akuity.cloud), open your Argo CD instance, go to **Settings → System Accounts**, and add an account named `cloudthinker` with the **apiKey** capability.
      </Step>
      <Step title="Generate a token">
        Sign in to the instance as an admin and generate a token for the new account:

        ```bash
        argocd login <instance-id>.cd.akuity.cloud --grpc-web --username admin
        argocd account generate-token --account cloudthinker --grpc-web --expires-in 90d
        ```

        Copy the token.
      </Step>
      <Step title="Grant the account read access">
        Add these lines to the instance's RBAC policy in the Akuity Portal:

        ```csv
        p, role:cloudthinker, applications, get, */*, allow
        p, role:cloudthinker, logs, get, */*, allow
        g, cloudthinker, role:cloudthinker
        ```
      </Step>
      <Step title="Add the connection in CloudThinker">
        Open **Workspace Settings → Connections**, stay on the **Builtin Connections** tab, and select **ArgoCD**. Fill in:

        - **ARGOCD_BASE_URL**: `https://<instance-id>.cd.akuity.cloud`
        - **ARGOCD_API_TOKEN**: the token you copied
        - **NODE_TLS_REJECT_UNAUTHORIZED** (TLS verification): **Verify TLS (default)**
        - **READ_ONLY**: change it to **Read-only**. The form defaults to **Full access**.

        Click **Connect**.

        **Success state:** the dialog closes and the connection shows **Connected**. Run the verify prompt below to confirm the token and RBAC work.
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Connection details

| Field | Description | Default |
|-------|-------------|---------|
| **ARGOCD_BASE_URL** | Argo CD server address, HTTPS | none |
| **ARGOCD_API_TOKEN** | Token for the account CloudThinker uses | none |
| **NODE_TLS_REJECT_UNAUTHORIZED** | TLS verification. **Verify TLS (default)** checks the server certificate. **Skip TLS verification** accepts self-signed certificates; use it only for local or dev servers | Verify TLS |
| **READ_ONLY** | **Read-only** turns off the sync, create, update, delete, and resource action tools. **Full access** keeps them on | Full access |

<Warning>
**READ_ONLY** defaults to **Full access**. Switch it to **Read-only** unless you want agents to propose syncs and changes. RBAC still blocks anything the account isn't granted.
</Warning>

## Required permissions

The read lines from setup cover every read: `applications, get` covers application status, resource trees, managed resources, and events, and `logs, get` lets agents read pod logs. Add a line for each change you want agents to propose:

| Capability | Policy line |
|------------|-------------|
| Sync | `p, role:cloudthinker, applications, sync, */*, allow` |
| Change applications | `p, role:cloudthinker, applications, create, */*, allow`<br />`p, role:cloudthinker, applications, update, */*, allow`<br />`p, role:cloudthinker, applications, delete, */*, allow` |
| Resource actions | `p, role:cloudthinker, applications, action/*, */*, allow` |

## Agent capabilities

| Capability | What agents can do | Approval |
|------------|--------------------|----------|
| **Discovery** | List applications with sync status, health, repo, path, and namespace, plus resource trees and recent events for the unhealthy or out-of-sync ones | No |
| **Application detail** | Read one app's spec, managed resources, and the live versus desired diff | No |
| **Events and logs** | Read Kubernetes events for an app or resource, and pod logs from its workloads | No |
| **Sync** | Trigger a sync of one application | Yes, and off in Read-only |
| **Change applications** | Create, update, or delete an application | Yes, and off in Read-only |
| **Resource actions** | Run an action such as a restart on a managed resource | Yes, and off in Read-only |

Every change goes through [Approvals](/guide/approvals/overview), and a rejected request isn't retried. To let agents sync, set **READ_ONLY** to **Full access** and add the `applications, sync` permission. Leave either one out and agents can only read.

### Verify the connection

```text
List my Argo CD applications with their sync status and health, and call out any that are OutOfSync or Degraded
```

Expect a table of application names with a sync status such as **Synced** or **OutOfSync** and a health status such as **Healthy** or **Degraded**, plus counts at the end.

### Example prompts

```text
Why is the checkout app Degraded? Check its resource tree, recent events, and pod logs
Which resources in payments-api differ from Git, and what changed?
Sync the payments-api app and tell me when it's Healthy
```

Name the application. Agents use real names from the application list and won't guess one. The sync prompt needs **Full access** and the `applications, sync` permission.

## Troubleshooting

<Accordion title="Connect fails with fetch failed">
CloudThinker can't reach **ARGOCD_BASE_URL**, or the server's certificate was rejected. Check that the address is public HTTPS, not `localhost` or a cluster-internal name. For a self-signed certificate, set **NODE_TLS_REJECT_UNAUTHORIZED** to **Skip TLS verification**.
</Accordion>

<Accordion title="Requests return 401">
The token is missing, expired, or was generated for a different account. Run `argocd account generate-token --account cloudthinker --expires-in 90d` again, edit the connection, and paste the new token.
</Accordion>

<Accordion title="Permission denied (code 7)">
The account's RBAC role doesn't allow that action. Check the `policy.csv` lines in [Required permissions](#required-permissions): logs need `logs, get` and syncs need `applications, sync`.
</Accordion>

<Accordion title="The application list is empty">
The role grants no access to those projects. The `*/*` pattern in the policy covers every project; if you narrowed it, add the projects agents should see.
</Accordion>

<Accordion title="Sync, create, update, or delete is unavailable">
**READ_ONLY** is set to **Read-only**. Edit the connection and switch to **Full access** if you want agents to propose those changes.
</Accordion>

<Accordion title="Generating a token fails">
The account doesn't have the `apiKey` capability. Run `argocd account get --account cloudthinker` to check, then repeat the first setup step.
</Accordion>

## Security

<ConnectionSecurity />

- **Dedicated account**: give CloudThinker its own `cloudthinker` account with API key access only, never the `admin` token.
- **Keep TLS verification on in production**: skip it only for a local or dev server with a self-signed certificate.

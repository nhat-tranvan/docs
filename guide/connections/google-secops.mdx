Connect Google SecOps to let CloudThinker review detections, detection rules, and SOAR cases. The connection uses **a Google service account JSON key**.

## Prerequisites

- An account with access to the Google SecOps resources you intend to investigate.
- The **Admin** role in your CloudThinker workspace to add and manage the connection. See [Roles](/guide/security/roles).
- The credentials described below and a network route from CloudThinker to the service. For a private endpoint, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare access in Google SecOps">
    Use a dedicated service account in the Google Cloud project linked to the SecOps instance. Grant **Chronicle API Viewer** for read-only work and create a JSON key using your organization’s permitted key-management procedure. Record the linked project ID, customer ID, and region from your SecOps instance. Paste the complete JSON document into the connection’s key field.

    Follow the [vendor’s credential and authentication guidance](https://docs.cloud.google.com/chronicle/docs/reference/authentication) for your account.
  </Step>
  <Step title="Connect in CloudThinker">
    Open **Settings → Workspace → Connections**, find **Google SecOps**, and click **Connect**. Fill in the fields in [Connection details](#connection-details), check the account and region, and click **Connect**.

    **Success state:** the connection shows **Connected**. Run the verification prompt below to check what the account can actually read.
  </Step>
  <Step title="Verify the scope">
    Run the [verification prompt](#verify-the-connection). Compare the returned organization, projects, or resource names with the account you intended to connect. Keep a denied request visible as an access problem; do not interpret it as an empty result.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **SecOps region** | Yes | Use the value supplied for this connection. Choose **US multi-region (us)**, **EU multi-region (eu)**, **Europe (europe)**, **Johannesburg (africa-south1)**, **Taiwan (asia-east1)**, **Tokyo (asia-northeast1)**, **Seoul (asia-northeast3)**, **Mumbai (asia-south1)**, **Singapore (asia-southeast1)**, **Jakarta (asia-southeast2)**, **Sydney (australia-southeast1)**, **Warsaw (europe-central2)**, **Turin (europe-west12)**, **London (europe-west2)**, **Frankfurt (europe-west3)**, **Zurich (europe-west6)**, **Paris (europe-west9)**, **Doha (me-central1)**, **Dammam (me-central2)**, **Tel Aviv (me-west1)**, **Toronto (northamerica-northeast2)**, **Sao Paulo (southamerica-east1)**. Default: **US multi-region (us)**. |
| **Google Cloud project ID** | Yes | The project linked to your SecOps instance. SecOps &gt; SIEM Settings &gt; Profile shows it. |
| **Customer ID** | Yes | SecOps &gt; SIEM Settings &gt; Profile &gt; Customer ID, a UUID. |
| **Service account JSON key** | Yes | The Service account JSON key for the account described in Setup. |

An ingestion API key cannot replace the service account credential used for these investigations.

## Required permissions

Chronicle API Viewer on the linked project for detections, rules, and case reads that the account is authorized to access. Changing case priority requires the relevant write permissions, such as Chronicle API Editor; do not grant them for investigations alone.

<Tip>
Start with read access to the smallest useful scope. Adding a connection does not grant permissions that the provider account lacks. For supported changes, [Approvals](/guide/approvals/overview) decides whether CloudThinker may proceed; provider permissions still apply.
</Tip>

## Agent capabilities

| Workflow | What agents can do |
|---|---|
| Discovery | Review detections and detection rules |
| Investigation | Inspect SOAR case status and priority |
| Changes | Change a named case priority when authorized |

### Verify the connection

```text
Review Google SecOps detections and open cases, showing the region and instance scope without changing anything. Report any denied or unavailable checks separately.
```

Expect current resource names or a clear access error. No matching records is a valid outcome only when the request succeeded and its account, filters, and time window match your question.

### Example prompts

```text
Review Google SecOps detections and open cases, showing the region and instance scope without changing anything
Use this connection to inspect one resource from the results and explain its current state with supporting evidence
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential is active, belongs to the intended account, and matches the selected region or endpoint. Replace an expired or revoked credential in CloudThinker. Do not paste it into chat or include it in a support screenshot.
  </Accordion>
  <Accordion title="Connected, but some resources are missing">
    Compare the provider account’s access, selected organization, and investigation filters. A successful sign-in does not prove access to every resource. An ingestion API key cannot replace the service account credential used for these investigations.
  </Accordion>
  <Accordion title="Requests are denied or cannot reach the service">
    A permission denial needs a provider access change for the specific read, not a broader account by default. For a timeout or certificate error, confirm the HTTPS endpoint, network route, and trusted CA with the service administrator. For throttling, narrow the investigation and retry after the provider’s indicated wait.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep the connection restricted to the account and resources intended for this workspace.
- Rotate credentials through the provider and replace the saved value in CloudThinker; never send secrets in a conversation.

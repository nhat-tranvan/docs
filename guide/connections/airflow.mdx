Connect Apache Airflow so CloudThinker can inspect DAG runs and manage workflow execution. Use a dedicated credential with access only to the resources you want to inspect.

## Prerequisites

- An existing Apache Airflow account or deployment containing the resources you want to inspect.
- Permission to create or obtain the credential described below.
- A CloudThinker workspace role that can add connections; see [Roles](/guide/security/roles).
- An HTTPS route from CloudThinker to your service. For a private service, see [Reaching private services](/guide/connections/overview#reaching-private-services).

## Setup

<Steps>
  <Step title="Prepare the credential">
    Obtain a JWT bearer token from your Airflow 3 auth manager. Follow its token procedure; the request format depends on the configured auth manager. See the [vendor's authentication documentation](https://airflow.apache.org/docs/apache-airflow/stable/security/api.html) for the procedure that applies to your account.
  </Step>
  <Step title="Add the connection">
    Open **Settings → Connections**, find **Apache Airflow**, and click **Connect**. Enter the values in [Connection details](#connection-details).

    Use the Airflow 3 API server address without `/api/v2`. Airflow 2 is unsupported by this connection.
  </Step>
  <Step title="Check the result">
    Click **Connect** and wait for the connection check.

    **Success state:** the connection shows **Connected**. Run the verification prompt below and confirm that the expected resources appear.
  </Step>
</Steps>

## Connection details

| Field | Required | What to enter |
|---|---|---|
| **Airflow URL** | Yes | HTTPS address of your Airflow 3 API server, without /api/v2. Airflow 2 is not supported. |
| **Bearer token** | Yes | An Airflow 3 API bearer token. Give the account permission to read DAGs, runs, task instances and HITL details; pause and trigger operations also need DAG edit and run create permissions. Renew expired tokens here. |
| **CA certificate (optional)** | No | PEM of the private CA that issued the server certificate. Leave empty for public trust. Certificate and hostname checks stay enabled. |

## Required permissions

Read DAGs, DAG runs, task instances, and human-in-the-loop details. DAG edits and run creation are needed only for requested workflow changes.

<Tip>
Start with the smallest resource scope that answers your investigation. Verify a known resource before expanding access. A successful sign-in does not prove access to every project or account.
</Tip>

## Agent capabilities

| Task | What CloudThinker can do |
|---|---|
| DAG health | Inspect schedules and paused state. |
| Run triage | Read DAG runs and task instance state. |
| Workflow actions | Pause schedules, trigger or retry runs, set run state, and add run notes after approval. |

Triggering or retrying a run executes workflow code and can repeat downstream changes. Marking a run successful changes its status without executing tasks.

Supported changes require the corresponding provider permission and go through [Approvals](/guide/approvals/overview). Ask for a specific target and change.

### Verify the connection

```text
Inspect my Apache Airflow connection. Identify the accessible account or resource scope and show a small sample without changing anything.
```

Confirm that the returned scope matches the credential you intended to connect. An empty result can mean missing data or restricted access; it is not proof that the service is healthy.

### Example prompts

```text
Use Apache Airflow to inspect DAG runs and manage workflow execution.
Summarize the highest-priority items visible through my Apache Airflow connection and cite their identifiers.
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication fails">
    Check that the credential belongs to the same account, region, or tenant entered in the form. Replace an expired or revoked credential, then reconnect. Do not paste credentials into chat.
  </Accordion>
  <Accordion title="A resource is missing or access is denied">
    Check the credential's access to that specific project, organization, or resource in Apache Airflow. Grant the missing read permission only for the intended scope, then try the same read again.
  </Accordion>
  <Accordion title="The service cannot be reached">
    Verify the service address and a route from CloudThinker. For a private endpoint, check your allowlist and trusted certificate chain. Keep certificate verification enabled when using a trusted certificate.
  </Accordion>
</AccordionGroup>

## Security

<ConnectionSecurity />

- Keep this integration's credential separate from personal daily-use credentials where your provider supports it.
- Revoke or rotate it in Apache Airflow when access is no longer needed, and update the connection after rotation.

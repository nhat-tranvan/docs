Connect a Coralogix team to let CloudThinker agents triage open incidents, search logs and traces, query metrics, inspect alerts and dashboards, and check your data pipeline for disabled parsing rules or misconfigured connectors. The connection uses Coralogix's hosted MCP server, signed in with one **API key** for one **region**. You pick the region and CloudThinker routes to the matching Coralogix endpoint, so there's no URL to type.

## Prerequisites

- A Coralogix team with the data you want agents to read.
- Permission to create API keys for that team.
- Your team's region, which you read from your login address (see [the region table](#connection-details)).

## Setup

<Steps>
  <Step title="Find your region">
    Sign in to Coralogix and match the address bar to the [region table](#connection-details). Some regions don't put their name in the address: `acme.coralogix.com` is EU1 and `acme.app.cx498.coralogix.com` is US2.
  </Step>
  <Step title="Create an API key">
    Go to **Settings → API Keys** and create a new key:

    - **Name**: `cloudthinker`
    - **Type**: **Team key**. A personal key is tied to one user and stops working when their access ends.
    - **Permissions**: read access to the data agents should reach (see [Required permissions](#required-permissions))

    Copy the key right away. You'll need a new key if you lose it.
  </Step>
  <Step title="Add the connection in CloudThinker">
    Open **More → Workspace settings → Connections**, stay on the **Builtin Connections** tab, and select **Coralogix**. Fill in:

    - **CORALOGIX_API_KEY**: the key you created
    - **CORALOGIX_REGION**: pick your region from the list, for example **EU2 (eu2.coralogix.com)**. The default is **US2 (us2.coralogix.com)**, so change it if your team lives elsewhere.

    Click **Connect**.

    **Success state:** Coralogix shows **Connected**. Run the verify prompt below to confirm the key and region match.
  </Step>
</Steps>

<Warning>
A key only works in the region it was created in. A wrong region shows up as **404 Not Found**, which looks like missing data. Check the login address before you debug anything else.
</Warning>

## Connection details

| Field | Description | Example |
|-------|-------------|---------|
| **CORALOGIX_API_KEY** | Coralogix team API key | `<your-api-key>` |
| **CORALOGIX_REGION** | Region that matches your team login address | **EU2 (eu2.coralogix.com)** |

Find your login address in the left column, then pick the option on the right:

| Login address | Pick in **CORALOGIX_REGION** |
|---------------|------------------------------|
| `<team>.app.coralogix.us` | **US1 (us1.coralogix.com)** |
| `<team>.app.cx498.coralogix.com` | **US2 (us2.coralogix.com)**, the default |
| `<team>.app.us3.coralogix.com` | **US3 (us3.coralogix.com)** |
| `<team>.coralogix.com` | **EU1 (eu1.coralogix.com)** |
| `<team>.app.eu2.coralogix.com` | **EU2 (eu2.coralogix.com)** |
| `<team>.app.coralogix.in` | **AP1 (ap1.coralogix.com)** |
| `<team>.app.coralogixsg.com` | **AP2 (ap2.coralogix.com)** |
| `<team>.app.ap3.coralogix.com` | **AP3 (ap3.coralogix.com)** |

To reach another team or region, add it as a separate connection with its own key.

## Required permissions

Grant the key read access to the data agents should investigate:

| Data | Used for |
|------|----------|
| Incidents | Incident triage and discovery |
| Logs and traces | Searching errors and following requests |
| Metrics | Metric queries and the metric catalog |
| Alerts and dashboards | Inspecting alert definitions and dashboards |
| Parsing rules, connectors, presets | Pipeline health checks |

Leave write permissions off the key unless you want agents to change Coralogix resources, such as enabling a parsing rule. A read-only key covers every investigation on this page.

## Agent capabilities

| Capability | What agents can do | Approval |
|------------|--------------------|----------|
| **Discovery** | Summarize open incidents, connector count, disabled parsing rules, presets, and whether metric search works | No |
| **Incident triage** | List recent and open incidents with severity, status, and timestamps | No |
| **Logs** | Search logs over a time window | No |
| **Traces** | Inspect distributed traces | No |
| **Metrics** | Query metrics and search the metric catalog | No |
| **Pipeline health** | Find disabled or hidden parsing rules and review connectors and presets | No |
| **Alerts and dashboards** | Read alert definitions and dashboards | No |
| **Changes** | Create, update, enable, disable, or delete a Coralogix resource. Needs write permissions on the key | Yes |

Agents never change anything during discovery, triage, or health checks. A change only happens when you ask for it in the conversation and name the resource and the change, and it goes through [Approvals](/guide/approvals/overview). Agents cap samples at 10 items by default so large catalogs don't flood the answer.

### Verify the connection

```text
Run Coralogix discovery and summarize open incidents, connector count, disabled parsing rules, and whether metric search is healthy
```

Expect counts for incidents, connectors, parsing rules, and presets, plus a short sample of each. "No metrics matched" in the metric check is normal: discovery probes with a name that doesn't exist. If the summary says **degraded**, the agent lists which checks failed: incidents, connectors, parsing rules, presets, or metrics. A failed check usually means the key lacks read permission for that data. If every check fails, check the key and the region first.

### Example prompts

```text
Triage open Coralogix incidents and flag anything affecting production
Search Coralogix logs for 5xx errors from the api-gateway service in the last hour
Check Coralogix pipeline health and list disabled parsing rules
Which Coralogix alerts fired for the payments service today?
```

Give a service name and a short time window. Narrow queries come back faster and stay readable.

## Troubleshooting

<Accordion title="Connect fails or requests return 401">
The key is missing, expired, or revoked. Create a new team key, edit the connection, and paste it into **CORALOGIX_API_KEY**.
</Accordion>

<Accordion title="Everything returns 404">
The key belongs to a different region. Check your login address and change **CORALOGIX_REGION** to match.
</Accordion>

<Accordion title="Some data types fail and others work">
The key lacks read permission for that data. Add it in Coralogix, then rerun the request. No need to reconnect if the key itself didn't change.
</Accordion>

<Accordion title="A metric query returns nothing">
No metric matches that name, or the team sends no metrics. The agent treats it as an empty result. Try a metric name you know exists, or continue with incidents and logs.
</Accordion>

<Accordion title="Requests return 429 or 503">
Coralogix is rate limiting or in maintenance. Wait a minute, narrow the request, and ask again.
</Accordion>

## Security

<ConnectionSecurity />

- **Team key, read access first**: add write permissions only for changes you want agents to be able to propose.
- **One key per connection**: create a key used only by CloudThinker so you can revoke it without breaking other tools.

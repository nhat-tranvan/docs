Add CloudThinker to Google Chat so your team can ask questions, approve actions, and receive incident updates without opening the web app. Each Google Chat space or direct message maps to one CloudThinker workspace, the project that holds your connections and conversations.

<Note>
**Early access.** Google Chat is turned on for selected organizations. [Contact us](https://cloudthinker.io/contact) if **Admin Settings → Integrations** does not list it. Google Chat is an integration, not a [connection](/guide/connections/overview): adding CloudThinker gives it no access to Gmail, Drive, or other Google Workspace data.
</Note>

## What you get

| In Google Chat you can | Example |
| --- | --- |
| Ask questions that run against the mapped workspace's connections | `@CloudThinker Why did our AWS bill go up this week?` |
| Approve or reject a paused action without opening the web app | Click **Approve** on the approval card in the thread |
| Receive incident updates and other workspace events in a shared space | Pick the space in the [notification matrix](/guide/notifications) |

## Prerequisites

- Both of these: a [messaging-eligible plan](/guide/billing/pricing#ai-features-by-plan) (Team, Scale, Scale+, or Enterprise) **and** Google Chat listed under **Admin Settings → Integrations**. Early access does not replace the plan requirement.
- A Google Workspace administrator who can install apps in the Google Admin console. They do this once for your organization.
- A CloudThinker organization Owner or Admin to map shared spaces. A workspace member with chat access can map their own direct message.

## Install CloudThinker

<Steps>
  <Step title="Open the setup page">
    Sign in to CloudThinker as an organization Owner or Admin. Go to **Admin Settings → Integrations → Google Chat**.

    The page walks through three steps: **Install CloudThinker**, **Add CloudThinker to a space**, and picking a notification space for each workspace.
  </Step>
  <Step title="Turn on Chat apps in Google Admin">
    Your Google Workspace administrator opens Google Chat settings in the Google Admin console, opens **Chat apps**, and sets **Allow users to install Chat apps** to **On**. The setup page links straight to this screen with **Open Google Chat settings**.
  </Step>
  <Step title="Install CloudThinker for your organization">
    In the Google Admin console, open the Google Workspace Marketplace apps list (**Open the Apps list** on the setup page) and install CloudThinker for everyone who should reach it.

    **Success state:** CloudThinker appears when people search for apps in Google Chat.
  </Step>
</Steps>

## Map a space to a workspace

Do this once for each shared space, and once for each person who wants a direct message with CloudThinker.

<Steps>
  <Step title="Add CloudThinker in Google Chat">
    Add CloudThinker to a shared space, or start a direct message with it.

    If CloudThinker is already in your direct message, remove it and add it again. Google sends the setup event only on a fresh add.
  </Step>
  <Step title="Open the configuration link">
    CloudThinker replies with a personal configuration link. It expires after 15 minutes and must be opened with the Google account that messaged CloudThinker.

    For a shared space that is not mapped yet, an organization Owner or Admin must open the link.
  </Step>
  <Step title="Choose a workspace and confirm your Google account">
    Pick the CloudThinker workspace this space should use under **Workspace**. Then click **Continue with Google** and choose that same Google account.

    **Success state:** the page shows **Google Chat is ready**. Back on **Admin Settings → Integrations → Google Chat**, the space appears under **Mapped spaces**.
  </Step>
  <Step title="Send a first request">
    Return to Google Chat and mention CloudThinker again with a question:

    ```text
    @CloudThinker Why did our AWS bill go up this week?
    ```

    **Success state:** CloudThinker answers in the same thread, using the mapped workspace's connections.
  </Step>
</Steps>

## Work with CloudThinker in chat

Write requests in plain language. Name a connection or ask for an output shape in words when it matters. See [CloudThinker Language](/guide/commands) for the full syntax.

```text
@CloudThinker Investigate the latest high-severity incident
@CloudThinker Summarize the open findings for production
@CloudThinker Compare this month's EC2 spend with last month as a dashboard
```

- **Mentions:** in a shared space, mention `@CloudThinker` so Google sends it the message. In a direct message, just type your request.
- **Threads:** reply in the same thread to continue the conversation. A new top-level message starts a new conversation.
- **Long runs:** CloudThinker posts a **Working…** message in the thread and updates it with the current step, then posts the answer in the same thread. If someone else sends a message while a run is going, CloudThinker queues it and starts it as that person when the run finishes.
- **Files:** upload up to 5 files to your Google Chat message, 20 MB in total. Oversized images are resized; other oversized files are refused with a reply. Supported types include PDF, Word, text and Markdown, CSV and Excel, PowerPoint, JSON and YAML, common images, and code files. Google Drive files are not read, because adding CloudThinker grants no Drive access: upload a copy or paste the part CloudThinker should read.
- **Approvals:** when an action needs sign-off under your [approval rules](/guide/approvals/overview), CloudThinker posts a **CloudThinker needs your approval** card with **Approve**, **Approve with reason** (opens a dialog for your note), and **Reject**. These chat labels differ from the web app card. Use **Open in CloudThinker** to see the full context first.

### Who can approve from chat

Being a member of the space is not enough. Each click is checked against the clicker's linked CloudThinker account, with the same approver checks as the web app:

| Clicker | What happens |
| --- | --- |
| Google account not linked to CloudThinker | CloudThinker privately sends a link: **Link your CloudThinker account to continue** |
| Linked, but can't run agents in this workspace | Private reply: **Your linked CloudThinker account cannot run agents in this Workspace.** |
| Linked, not a designated approver (or not in the approver group) | Can still **Reject**. **Approve** gets a private reply naming who can approve |
| Started the run that needs approval | Another approver must approve. They can still reject it |
| Allowed approver | The decision applies and the card updates to show it |

If the approval was already decided, in chat or in the web app, the clicker sees **This approval was already decided.**

## Security and permissions

| Question | Answer |
| --- | --- |
| Google API scopes | `chat.bot` to receive mentions and post replies and cards. `chat.app.messages.readonly` lets CloudThinker read earlier messages in a thread; a Google Workspace admin must approve it, and until then CloudThinker says so instead of reading the thread |
| Google sign-in | **Continue with Google** only confirms which Google account you are. It requests no Gmail, Drive, or Calendar access |
| Identity mapping | Each Google account links to one CloudThinker user per organization. Every message and click runs as that user, with that user's workspace role |
| What CloudThinker stores | Messages you send to CloudThinker and its replies, saved as a conversation in the mapped workspace, plus files you upload to those messages. In a shared space, Google sends CloudThinker only the messages that mention it; with the message-reading scope approved, it can also read earlier messages in its own thread |
| Approvals | Chat clicks go through the same approval path as the web app, so the decision shows on the conversation in CloudThinker |

## Send notifications to a space

A mapped shared space can receive workspace notifications, such as incident updates, approval requests, and Review results. Choose which events go where in the [notification matrix](/guide/notifications), the grid that maps each event type to a destination.

Direct messages never receive notifications, so they don't appear as destinations. If a space is missing from the list, check that it is a shared space mapped to the current workspace.

## Manage mapped spaces

Go to **Admin Settings → Integrations → Google Chat** to see every mapped space and the workspace it uses.

Open the actions menu (**...**) on a space row:

| Action | What happens |
| --- | --- |
| **Make notification default** | The space becomes the default notification destination for its workspace. The row shows a **Notification default** badge |
| **Change Workspace** | Moves the space to another workspace in the same organization. New messages start fresh conversations there; earlier conversations stay in the original workspace |
| **Remove** | Removes the space's mapping to its workspace |

To stop using the integration for the whole organization, click **Disconnect Google Chat** at the bottom of the page.

Only organization Owners and Admins can change mappings or disconnect.

## Troubleshooting

<AccordionGroup>
  <Accordion title="CloudThinker does not send a configuration link">
    Mention CloudThinker again in the same conversation. In a direct message where CloudThinker was added before, remove it and add it again so Google sends a fresh setup event.
  </Accordion>
  <Accordion title="This Google Chat link expired or is invalid">
    The link timed out or was opened with a different Google account (see [step 2](#map-a-space-to-a-workspace)). Mention CloudThinker again to get a new one.
  </Accordion>
  <Accordion title="An organization Admin must connect this space">
    Only an organization Owner or Admin can map a shared space. Ask one to mention CloudThinker in the same space and open the new link.
  </Accordion>
  <Accordion title="You cannot run CloudThinker in this Workspace">
    Ask a workspace Admin to give you chat access. Then mention CloudThinker again for a new link.
  </Accordion>
  <Accordion title="Google Chat requires a Team plan">
    Your organization is on the Free plan. Ask your billing owner to [upgrade](/guide/billing/subscription), then open the link again.
  </Accordion>
  <Accordion title="Google Sign-In did not load">
    Your browser or an extension blocked `accounts.google.com`. Allow it for the CloudThinker site, then reload the page.
  </Accordion>
  <Accordion title="A Google Chat space needs to be reconnected">
    Google Chat refused CloudThinker's messages to that space, so CloudThinker stopped sending there. In Google Chat, remove CloudThinker from the space and add it again.
  </Accordion>
</AccordionGroup>

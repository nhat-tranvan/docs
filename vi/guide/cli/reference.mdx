Mọi lệnh trong file nhị phân `cloudthinker`, kèm cờ và mã thoát của từng lệnh. Mới dùng CLI? Hãy bắt đầu từ [tổng quan CLI](/vi/guide/cli/overview).

```bash
cloudthinker [--url <URL>] [--workspace <ID or NAME>] <command> [flags]
```

Chạy `cloudthinker <command> --help` để xem cú pháp chính xác của phiên bản bạn đang cài.

## Tùy chọn toàn cục

Đặt tùy chọn toàn cục trước tên lệnh.

| Tùy chọn | Mô tả |
|---|---|
| `--url <URL>` | Địa chỉ CloudThinker. Mặc định là địa chỉ của lần `login --url` gần nhất, nếu không có thì là `https://app.cloudthinker.io`. Truyền origin trần, không kèm đường dẫn hay dấu gạch chéo cuối: `--url https://ct.example.com` |
| `--workspace <ID or NAME>` | Dùng thông tin đăng nhập đã lưu của workspace này. Không dùng chung được với `CLOUDTHINKER_TOKEN`, trừ trên `review setup` và `doctor` (mã thoát 2) |
| `--tui-mode <MODE>` | Chỉ áp dụng cho `cloudthinker` chạy trơn: `fullscreen` (mặc định) hoặc `regular`, giữ cuộc chat trong lịch sử cuộn của terminal. Với `cloudthinker agent`, hãy đặt tùy chọn này sau `agent` |
| `-y`, `--yes` | Chạy một lệnh vốn hỏi trước, chẳng hạn thao tác xóa hoặc `connections disconnect`, mà không hỏi. Bắt buộc khi không có terminal nào để trả lời, chẳng hạn trong script và CI |
| `--skill [MODULE]` | In hướng dẫn vận hành CLI dành cho AI coding agent rồi thoát. Không cần đăng nhập. Không truyền giá trị thì in mục lục; các module gồm `api`, `auth`, `chat`, `cloud`, `connections`, `policy`, `review`, `cyber`, `cyber-scan`, `cyber-verify`, `cyber-report`, `worker` và `remote` |
| `-h`, `--help` | In trợ giúp |
| `-V`, `--version` | In phiên bản CLI |

## Lệnh đăng nhập

| Lệnh | Mô tả |
|---|---|
| `login` | Đăng nhập qua trình duyệt. Khi chạy qua SSH hoặc máy không có màn hình, lệnh hiển thị một mã ngắn |
| `login --device-auth` | Luôn dùng luồng mã ngắn |
| `login --no-browser` | In URL đăng nhập mà không mở trình duyệt |
| `login --token` | Đọc personal API token (`ct_pat_`) từ stdin, kiểm tra với server, rồi lưu cho từng workspace mà token bao phủ: `cloudthinker login --token < token.txt`. Trên terminal không có input được pipe vào, lệnh thoát với mã 2 |
| `logout` | Xóa thông tin đăng nhập của workspace đang chọn hoặc đang hoạt động |
| `logout --all` | Xóa mọi thông tin đăng nhập đã lưu cho host này |
| `whoami [--json]` | Hiển thị tài khoản và workspace đứng sau thông tin đăng nhập, kiểm tra trực tiếp với server |
| `auth status [--json]` | Liệt kê các lần đăng nhập workspace đã lưu trên máy này và đánh dấu lần đang hoạt động |
| `auth switch <WORKSPACE>` | Chuyển một lần đăng nhập đã lưu thành lần đang hoạt động |
| `auth token` | In access token hiện tại ra stdout. Đây là thông tin bí mật |
| `workspace ls [--json]` | Liệt kê trực tiếp các workspace bạn truy cập được trong tổ chức của lần đăng nhập hiện tại, kèm vai trò của bạn. Lệnh đánh dấu workspace đang chọn và cho biết máy này có lưu thông tin đăng nhập cho từng workspace hay không. Việc liệt kê không bao giờ thay đổi lần đăng nhập đang hoạt động |
| `doctor [--json]` | Chẩn đoán máy này: địa chỉ server và nguồn của nó, đăng nhập, quyền truy cập API, các lần kiểm tra Connection đã ghi lại, agent và skill của agent, bản phát hành mới nhất, khả năng hỗ trợ của terminal, `AGENTS.md` hoặc `CLAUDE.md` trong thư mục này, và đường dẫn cài đặt. In một dòng khi mọi thứ ổn, nếu không thì in một hàng cho mỗi vấn đề kèm cách sửa. Lệnh không bắt đầu kiểm tra, sửa chữa hay đăng nhập nào |

Chi tiết và mẫu dùng cho CI: [xác thực CLI](/vi/guide/cli/authentication).

## Agent

`cloudthinker` không kèm lệnh, hoặc `cloudthinker agent`, khởi động [CloudThinker Agent](/vi/guide/cli/agent) trong thư mục hiện tại. Mọi tham số sau `agent` được chuyển nguyên vẹn cho agent.

Các cờ dưới đây cần lệnh `agent`. Chạy `cloudthinker agent --session <id>` để mở lại một phiên; CLI từ chối `cloudthinker --session <id>`. CLI 0.11.0 trở về trước in ra dạng bị từ chối đó khi thoát, nên hãy cập nhật bằng `cloudthinker update`.

| Cờ | Mô tả |
|---|---|
| `-p`, `--print <PROMPT>` | Chạy headless: trả lời, in ra rồi thoát |
| `--mode json` | Dùng với `-p` để stream sự kiện dưới dạng các dòng JSON |
| `-c`, `--continue` | Tiếp tục phiên gần nhất trong thư mục này |
| `-r`, `--resume` | Chọn một phiên để tiếp tục |
| `--session <ID>` | Mở một phiên theo ID hoặc theo file |
| `-n`, `--name <NAME>` | Đặt tên cho phiên này |
| `--model <MODE>` | Chế độ agent: `light`, `pro` hoặc `ultra` |
| `--list-models` | Liệt kê các chế độ agent mà workspace của bạn cung cấp |
| `--add-dir <PATH>` | Cho phép agent đọc và sửa thêm thư mục này. Lặp lại để thêm nhiều thư mục |
| `--max-turns <N>` | Khi dùng `-p`, dừng sau N lượt của model và thoát với lỗi |
| `--tools <NAMES>` | Chỉ cho phép các công cụ cục bộ này, phân tách bằng dấu phẩy |
| `--exclude-tools <NAMES>` | Tắt các công cụ cục bộ này, phân tách bằng dấu phẩy |
| `--tui-mode <MODE>` | `fullscreen` (mặc định) hoặc `regular`. Giống tùy chọn toàn cục khi chạy `cloudthinker` trơn |
| `-a`, `--approve` | Tin cậy các file cục bộ của project này trong lượt chạy này |
| `-na`, `--no-approve` | Bỏ qua các file cục bộ của project này trong lượt chạy này. Cờ viết với một dấu gạch và hai chữ cái |

Đặt tùy chọn của chính CLI trước `agent`. Mọi thứ sau `--` được chuyển cho agent mà CLI không đọc:

```bash
cloudthinker --workspace Production agent    # start the agent in the Production workspace
cloudthinker agent --help                    # the CLI's summary of agent flags
cloudthinker agent -- --help                 # the agent's own, full help
```

`agent` chuyển quyền điều khiển cho tiến trình agent, nên `agent -p` trả về mã thoát của chính agent, không phải các mã trong [Mã thoát](#mã-thoát).

### Agent từ xa

`remote [TARGET]` chạy agent trên một máy khác qua SSH và giữ agent chạy tiếp khi kết nối rớt hoặc laptop của bạn ngủ. CLI trên máy từ xa giữ agent trong một tiến trình nền, nên bạn không cần `tmux`. `TARGET` là một host trong `~/.ssh/config`, `user@host`, `user@host:port` hoặc `ssh://user@host:port`, mặc định là máy bạn dùng lần trước. Lần đầu tiên, hãy chỉ định máy: không có target và chưa từng dùng máy nào thì lệnh thoát với mã 2 kèm thông báo `Which machine? Run: cloudthinker remote <ssh-host>`. Cả hai máy đều cần CLI trên macOS hoặc Linux. Khi một máy Linux chưa có CLI, hoặc có bản quá cũ không tự cập nhật được, laptop của bạn sẽ đề nghị sao chép bản build tương ứng qua cùng lần đăng nhập SSH; máy đó chỉ cần `tar`.

| Cờ | Mô tả |
|---|---|
| `--cwd <DIR>` | Thư mục trên máy từ xa, thay cho việc chọn thủ công |
| `--name <NAME>` | Gắn vào hoặc khởi động agent có tên này |
| `--detach` | Khởi động agent mà không gắn vào, rồi in cách quay lại agent. Hoạt động cả khi không có terminal |
| `--via <COMMAND>` | Truy cập máy bằng một lệnh khác, chẳng hạn `ssh -J`. Lệnh này được lưu cùng máy |
| `-- <AGENT_ARGS>` | Tham số truyền cho agent khi khởi động |

`remote ls` liệt kê các máy đã lưu, `remote ls <MACHINE> [--json]` liệt kê các agent đang chạy trên máy đó, và `remote forget <MACHINE>` xóa một máy đã lưu.

Agent từ xa chạy `cloudthinker` của chính máy từ xa, nên dùng thông tin đăng nhập và workspace của máy đó. Hãy chạy `cloudthinker login` trên máy đó trước; qua SSH, lệnh hiển thị một mã ngắn.

<Note>
Trong `cloudthinker remote`, Ctrl+Z tách khỏi phiên và để agent tiếp tục chạy trên máy từ xa. Phím này không tạm dừng tác vụ cục bộ nào. Chạy lại `cloudthinker remote` để quay lại agent.
</Note>

## Chat

| Lệnh | Mô tả |
|---|---|
| `chat -p <PROMPT>` | Gửi prompt cho CloudThinker và chờ câu trả lời. `-p -` đọc prompt từ stdin |
| `chat -p … --continue <UUID>` | Tiếp tục một cuộc hội thoại, theo run ID hoặc conversation ID |
| `chat -p … --agent <UUID or ALIAS>` | Để một custom agent trả lời lượt này |
| `chat -p … --no-wait` | Trả về ngay khi lượt chạy được xếp hàng |
| `chat -p … --timeout <SECS>` | Ngừng chờ sau số giây này. Mặc định 2400. Lượt chạy vẫn tiếp tục |
| `chat -p … --json` | In một đối tượng JSON thay cho câu trả lời dạng văn bản |
| `chat status <RUN_ID> [--wait] [--timeout <SECS>] [--json]` | Hiển thị trạng thái và câu trả lời của một lượt chạy; `--wait` thăm dò cho tới khi lượt chạy xong |
| `chat ls [--conversation <UUID>] [--limit <N>] [--json]` | Liệt kê các lượt chạy headless gần đây, mới nhất trước. `--limit` từ 1 đến 50, mặc định 10 |
| `chat search <QUERY> [--regex \| --fuzzy [--min-score <SCORE>]] [--json]` | Tìm trong các cuộc hội thoại trước đây mà bạn được xem. Mặc định truy vấn là văn bản nguyên văn, tối đa 200 ký tự; `--regex` đọc nó như một biểu thức chính quy, còn `--fuzzy` tìm các kết quả gần đúng như lỗi gõ (`--min-score` từ 60 đến 100, mặc định 85). Lệnh tìm trong tiêu đề, nội dung tin nhắn, tên công cụ, đầu vào và đầu ra của công cụ, và tên file đính kèm, nhưng không tìm trong phần suy nghĩ hay nội dung file đính kèm. Mỗi kết quả hiện tiêu đề, UUID của cuộc hội thoại, một đoạn trích đã ẩn bí mật, và một đường dẫn. Thu hẹp bằng `--since`, `--until`, `--time-field` và `--type` (lặp lại để thêm, chẳng hạn `chat`, `headless` hoặc `rca`); `--limit` từ 1 đến 50, mặc định 10. Một lượt tìm chưa trọn vẹn sẽ in `--cursor` để tìm tiếp, và một lượt tìm chưa trọn vẹn không có kết quả sẽ thoát với mã 1. Lệnh không khởi động lượt chạy agent nào và không dùng model |
| `chat trace <CONVERSATION_ID> [--limit <N>] [--json]` | Hiển thị các tin nhắn gần đây, tên công cụ, lỗi và mức sử dụng của một cuộc hội thoại. Tham số công cụ, đầu ra công cụ và phần suy nghĩ bị lược bỏ, còn các tin nhắn cũ hơn bị giới hạn, nên đây không phải bản ghi đầy đủ. Nhận ID cuộc hội thoại, không phải ID lượt chạy. Chưa hỗ trợ phiên của agent CLI |

Khi không có `--json`, stdout chỉ chứa câu trả lời; tiến trình và dòng `continue_with=` đi ra stderr. Xem [Chat headless](/vi/guide/cli/headless-chat).

## Review

Review các thay đổi Git cục bộ của bạn, hoặc đọc một lượt [Review](/vi/guide/code-review/overview) mà CloudThinker đã chạy trên merge request hoặc pull request.

| Lệnh | Mô tả |
|---|---|
| `review` | Review các thay đổi đã stage, chưa stage và chưa theo dõi so với `HEAD` |
| `review --base <REF>` | Review diff của nhánh tính từ merge base với `REF`, gồm cả các chỉnh sửa chưa commit |
| `review status <MR_URL>` | Tóm tắt: nhà cung cấp, tiêu đề, trạng thái, kết luận và số phát hiện |
| `review findings <MR_URL>` | Liệt kê các phát hiện, mức nghiêm trọng cao nhất trước |
| `review findings <FINDING_ID>` | Đọc một phát hiện |
| `review --no-upload` | Giữ các phát hiện của lượt review cục bộ trên máy này thay vì gửi chúng tới CloudThinker |
| `review setup`, `review doctor` | Chuẩn bị Loupe trên một Worker dùng chung, hoặc kiểm tra các điều kiện tiên quyết của Worker |
| `review watch <MR_URL>` | Thăm dò cho tới khi review xong |

Mọi lệnh review đều nhận `--json`. `review` và `review watch` còn nhận `--timeout <SECS>` (mặc định 2400; với `review` cục bộ, đây là tổng thời gian cho mọi phần của một diff lớn) và `--fail-on <low|medium|high|critical>`, thoát với mã 6 khi có phát hiện ở mức nghiêm trọng đó hoặc cao hơn.

Lệnh `review` cục bộ đọc bản checkout của bạn bằng công cụ chỉ đọc và in phát hiện ra terminal. Lệnh không đăng bình luận, không áp dụng bản sửa, không thay đổi Git index hay working tree của bạn. Sau khi xong, lệnh gửi các phát hiện tới CloudThinker, để lượt Review đầu tiên của pull request cho nhánh này ghi nhận chúng; `--no-upload` giữ chúng trên máy bạn. Lệnh chạy trên model Code Review của workspace, nên diff và mọi file lệnh đọc sẽ được gửi tới model gateway của CloudThinker, và lệnh dùng credit của workspace. Xem [Dữ liệu nào rời khỏi máy bạn](/vi/guide/cli/agent#dữ-liệu-nào-rời-khỏi-máy-bạn).

```bash
cloudthinker review --base origin/main --fail-on high
cloudthinker review findings https://github.com/acme/api/pull/412 --json
```

| Trường | Giá trị |
|---|---|
| Trạng thái review | `queued`, `in review`, `review complete`, `filtered`, `failed`, `stopped` |
| Kết luận review | `in review`, `approved`, `review suggested`, `changes requested`, `filtered`, `failed`, `stopped` |

`filtered` nghĩa là bộ lọc repository đã bỏ qua merge request, nên không có review nào chạy. `review suggested` nghĩa là có phát hiện đáng xem nhưng không có gì chặn merge. Mã thoát: review kết thúc mà không chạm ngưỡng `--fail-on` thoát với mã 0, review `filtered` hoặc `stopped` cũng vậy. Review `failed`, hoặc URL MR chưa có review, thoát với mã 1. Lượt chờ vượt quá `--timeout` thoát với mã 4.

## Sự cố và khuyến nghị

| Lệnh | Mô tả |
|---|---|
| `incident ls [--status <STATUS>] [--limit <N>] [--json]` | Liệt kê các [sự cố](/vi/guide/incident/overview), mới nhất trước. `--limit` từ 1 đến 100, mặc định 25 |
| `incident status <ID> [--wait] [--timeout <SECS>] [--json]` | Hiển thị một sự cố; `--wait` chờ cho tới khi sự cố đóng |
| `recommendations ls [--status <STATUS>] [--limit <N>] [--json]` | Liệt kê các [khuyến nghị chi phí](/vi/guide/cost-optimization/recommendations) kèm khoản tiết kiệm hằng tháng. `--limit` từ 1 đến 100, mặc định 25 |

Trạng thái sự cố: `open`, `acknowledged`, `investigating`, `identified`, `on-hold`, `not-found`, `false-alarm`, `resolved`, `auto-resolved`. `not-found` là một trạng thái, không phải lỗi tra cứu: cuộc điều tra không tìm được nguyên nhân gốc nào có bằng chứng hỗ trợ. `incident status --wait` thoát với mã 0 khi sự cố ở trạng thái `resolved`, `auto-resolved`, `false-alarm` hoặc `not-found`. Nếu hết `--timeout` trước, lệnh thoát với mã 4.

Trạng thái khuyến nghị: `pending`, `in-progress`, `implemented`, `ignored`.

## Cyber

Để chạy kiểm thử bảo mật, hãy khởi động agent và yêu cầu bằng ngôn ngữ tự nhiên, ví dụ "Test http://localhost:3000 for security issues". Các lệnh dưới đây dùng để kiểm tra kết quả. Xem [Cyber](/vi/guide/security/cyber-overview).

| Lệnh | Mô tả |
|---|---|
| `cyber app ls` | Liệt kê các ứng dụng workspace này kiểm thử |
| `cyber domain ls` | Liệt kê các domain của workspace và bằng chứng sở hữu của từng domain |
| `cyber domain add <DOMAIN>` | Thêm một domain cần chứng minh quyền sở hữu bằng bản ghi DNS TXT. Xem [Đăng ký ứng dụng](/vi/guide/security/security-testing#đăng-ký-ứng-dụng) |
| `cyber domain verify <ID>` | Kiểm tra lại bằng chứng sở hữu của một domain |
| `cyber run status <RUN_ID> [--wait]` | Hiển thị trạng thái và số phát hiện của một lượt chạy. Không có lệnh nào liệt kê lượt chạy: run ID nằm trong đầu ra của agent khi agent bắt đầu một lượt kiểm thử |
| `cyber run cancel <RUN_ID>` | Dừng một lượt kiểm thử đang chạy |
| `cyber finding ls <APP_ID>` | Liệt kê phát hiện của một ứng dụng. Bộ lọc: `--severity`, `--status`, `--triage`. Phân trang: `--page` (từ 1, mặc định 1) và `--take` (số mục mỗi trang, mặc định 50) |
| `cyber finding get <FINDING_ID>` | Hiển thị một phát hiện |
| `cyber finding export <APP_ID> [--finding-id <ID>]` | Xuất phát hiện thành báo cáo PDF. Lệnh không ghi file cục bộ: lệnh in ra `filename` và một `download_url` để bạn tải về |
| `cyber config show`, `get <KEY>`, `set <KEY> <VALUE> [--user]` | Đọc hoặc thay đổi cài đặt Cyber cho project này, hoặc làm mặc định của bạn |
| `cyber doctor [--fix]` | Kiểm tra máy này có chạy được kiểm thử Cyber cục bộ không; `--fix` cài các công cụ còn thiếu |

Mọi lệnh Cyber đều nhận `--json`.

Giá trị bộ lọc của `finding ls`: `--severity` là `critical`, `high`, `medium`, `low` hoặc `info`. `--status` là `open`, `resolved`, `dismissed` hoặc `needs-verification`. `--triage` là `none`, `in-progress` hoặc `awaiting-retest`.

`cyber doctor --fix` cài các phiên bản cố định của `httpx` và `katana` vào `~/.cloudthinker/tools/` trong thư mục home, nên không cần `sudo`. Lệnh báo thiếu `curl` nhưng không tự cài.

`cyber config` đọc `.cloudthinker/config.toml` trong project và `~/.cloudthinker/config.toml` cho giá trị mặc định của bạn (`--user`). Giá trị bạn tự đặt được ưu tiên hơn giá trị suy ra. `cyber config show` liệt kê cả hai.

| Khóa | Ý nghĩa |
|---|---|
| `app` | Ứng dụng mà project này kiểm thử |
| `repo_path` | Thư mục gốc của repository. Suy ra từ Git khi chưa đặt |
| `auth.<role>` | Tên biến môi trường chứa auth header của danh tính kiểm thử đó, không bao giờ là chính giá trị bí mật. Trong file của project, tên này phải là `CYBER_<ROLE>_AUTH` |
| `context.<name>` | Đường dẫn hoặc URL tới ngữ cảnh cho bài kiểm thử, như OpenAPI spec, Postman collection hoặc file HAR |

## Public API

| Lệnh | Mô tả |
|---|---|
| `api <module>.<resource>.<verb> [IDS…] [--<param> <VALUE>]` | Gọi một thao tác Public API và in JSON của nó. Tham số query trở thành cờ |
| `api … --all` | Lần theo mọi trang và in tất cả mục, tối đa 10.000 |
| `api … --body <JSON or @FILE or ->` | Gửi body của request trực tiếp, từ file hoặc từ stdin |
| `api … --set <KEY=VALUE>` | Đặt một trường trong body |
| `api … --key <KEY>` | `Idempotency-Key`. Nếu bạn bỏ trống, một key mới sẽ được gửi |
| `api … --etag <ETAG>` | Giá trị `If-Match` cho một thao tác cập nhật. Các thao tác đọc in `ETag: …` ra stderr |
| `api <METHOD> <PATH> [--query <NAME=VALUE>]` | Gọi thao tác khớp với method và path. `--query` chỉ truyền tham số query ở dạng này; lặp lại để truyền thêm |
| `api … --yes` | Bỏ qua câu hỏi trên thao tác cần hỏi trước; bắt buộc khi không có terminal |
| `api --list [--json]` | Liệt kê mọi thao tác kèm lệnh, tên, method và scope |
| `<module> <resource> <verb>` | Cùng lệnh gọi ở dạng module, chẳng hạn `review reviews list` |

Xem [CLI cho Public API](/guide/cli/api).

## Connections, agent và Policy

TARGET là ID, alias hoặc prefix của một connection lấy từ `connections list`.

| Lệnh | Mô tả |
|---|---|
| `connections list [--json]` (alias `ls`) | Liệt kê các [Connection](/vi/guide/connections/overview) đã thêm vào workspace đang chọn |
| `connections show <TARGET> [--json]` | Hiển thị một Connection: loại, trạng thái và nơi nó trỏ tới. Không in thông tin xác thực nào |
| `connections status <TARGET> [--wait] [--timeout <SECS>] [--json]` | Hiển thị lần kiểm tra gần nhất; `--wait` chờ cho tới khi kiểm tra kết thúc và thoát với mã 1 khi thất bại |
| `connections retry <TARGET> [--wait] [--timeout <SECS>] [--json]` | Kiểm tra lại một Connection có sẵn bằng thông tin xác thực đã lưu (admin của workspace) |
| `connections disconnect <TARGET> [--json]` | Xóa một Connection cùng thông tin xác thực đã lưu (admin của workspace). Lệnh hỏi trước; `--yes` bỏ qua câu hỏi và bắt buộc khi không có terminal |
| `connections connect-url <PREFIX> [--wait] [--timeout <SECS>] [--json]` | In trang dùng để thêm một Connection, chẳng hạn `aws` hoặc `github`, và mở trang đó trên máy desktop. Thông tin xác thực ở lại trong trình duyệt. `--wait` theo dõi lần kiểm tra đầu tiên của Connection mới |
| `agents ls [--json]` | Liệt kê các agent của workspace và cho biết từng agent có chọn được bằng `chat --agent` hay không |
| `agents show <UUID_OR_ALIAS> [--json]` | Hiển thị danh tính, mô tả của một agent và cho biết agent đó có chọn được cho chat hay không. Alias khớp chính xác, không phân biệt hoa thường |
| `policy export [--output <PATH>]` | In Policy của workspace dưới dạng YAML, hoặc ghi vào một file riêng tư mới |
| `policy import <PATH> [--apply] [--prune] [--activate] [--json]` | Xem trước việc nhập một file Policy YAML hoặc JSON. Chỉ `--apply` mới ghi. `--prune` loại bỏ các Rule không còn trong file và xóa các override bị bỏ qua; `--activate` bật các Allow Rule được nhập |

## Environment

`worker` biến máy này thành một environment, để một cuộc chat hoặc automation có thể làm việc trong một thư mục trên máy. Hướng dẫn đầy đủ: [Environment](/vi/guide/workers).

| Lệnh | Mô tả |
|---|---|
| `worker outpost create <NAME> [--shared]`, `ls`, `archive <OUTPOST>` | Đăng ký, liệt kê hoặc ngừng dùng environment |
| `worker start --outpost <OUTPOST> --workdir <DIR>` | Phục vụ một thư mục cho tới khi bị ngắt. `--background` giữ environment chạy sau khi đóng terminal |
| `worker service install`, `uninstall`, `status`, `start`, `stop` | Chạy environment dưới systemd (Linux) hoặc launchd (macOS). `install --system --user <ACCOUNT>` (chạy với quyền root) cài một service cho toàn máy |
| `worker status --outpost <OUTPOST>` | Hiển thị tình trạng sẵn sàng của một environment theo góc nhìn của workspace |
| `worker doctor` | Kiểm tra máy này có chạy được environment không, kèm một cách sửa cho mỗi vấn đề |
| `worker worktrees ls`, `prune` | Liệt kê hoặc dọn dẹp các Git worktree tạo cho các cuộc hội thoại |

## Cập nhật và tự hoàn thành lệnh

| Lệnh | Mô tả |
|---|---|
| `update` | Cài bản phát hành mới nhất của CLI và agent cùng lúc |
| `update --force` | Cài lại kể cả khi đã là bản mới nhất |
| `update --version <VERSION>` | Cài bản phát hành đó thay cho bản mới nhất, cũ hơn hay mới hơn đều được, ví dụ `0.12.2`, để cố định phiên bản trên các host hoặc quay về bản cũ. Phiên bản chưa từng phát hành sẽ thoát với mã 2 |
| `update --json` | In kết quả dưới dạng JSON |
| `completion <bash\|zsh\|fish\|…>` | In script tự hoàn thành lệnh cho shell |

Trên terminal tương tác, CLI cũng đề nghị cập nhật khi có bản phát hành mới hơn, tối đa 20 giờ một lần. `update` chỉ hoạt động với bản cài do trình cài đặt của CLI tạo ra. Với bản cài khác, lệnh từ chối và in lệnh cài lại: `curl -fsSL https://cloudthinker.io/install.sh | sh`. Xem [tổng quan CLI](/vi/guide/cli/overview).

```bash
cloudthinker completion zsh > "${fpath[1]}/_cloudthinker"
cloudthinker completion bash > ~/.local/share/bash-completion/completions/cloudthinker
cloudthinker completion fish > ~/.config/fish/completions/cloudthinker.fish
```

Nếu không ghi được vào `${fpath[1]}`, hãy lưu file zsh vào một thư mục của riêng bạn và thêm thư mục đó vào `fpath` trong `~/.zshrc`, trước `compinit`.

## Biến môi trường

| Biến | Tác dụng |
|---|---|
| `CLOUDTHINKER_URL` | Tương đương `--url` |
| `CLOUDTHINKER_WORKSPACE` | Tương đương `--workspace` |
| `CLOUDTHINKER_TOKEN` | Một [API token](/guide/api/tokens) cá nhân (`ct_pat_`) hoặc của service account (`ct_sat_`), hoặc token lấy từ `auth token`, dùng thay cho thông tin đăng nhập đã lưu. API token dành cho `chat`, `incident ls` và `incident status`, các lệnh public API và `api`; hầu hết lệnh khác cần đăng nhập hoặc token từ `auth token`. Không dùng chung được với `--workspace` hoặc `CLOUDTHINKER_WORKSPACE`, trừ trên `review setup` và `doctor` |
| `CLOUDTHINKER_LOGIN` | `browser` hoặc `device` buộc máy này dùng luồng đăng nhập tương ứng |
| `CLOUDTHINKER_NO_UPDATE_CHECK` | Đặt `1` để tắt lời đề nghị cập nhật |
| `CLOUDTHINKER_OUTPOST_ID` | Environment mặc định cho các lệnh `worker` |
| `CLOUDTHINKER_CONFIG_DIR` | Giữ thông tin xác thực và trạng thái worker trong thư mục này thay vì thư mục cấu hình của nền tảng, để những người dùng chung một tài khoản hệ điều hành có thể giữ thông tin đăng nhập riêng |
| `CLOUDTHINKER_RELEASE_URL` | Cài agent từ một mirror `https`, một URL `file://`, hoặc một thư mục cục bộ có cấu trúc `<base>/v<version>/<asset>`, với cùng các bước kiểm tra checksum |
| `CLOUDTHINKER_REMOTE` | Đặt `0` để chạy `cloudthinker` trơn qua SSH trong shell hiện tại, thay vì một agent nền vẫn sống khi kết nối rớt |
| `CLOUDTHINKER_AUTO_BACKGROUND_SECONDS` | Số giây trước khi agent chuyển một lệnh shell chạy lâu xuống nền. Mặc định 10; `0` để tắt |
| `NO_COLOR` | Tắt màu trên stderr. Màu cũng tắt khi stderr không phải terminal |
| `HTTPS_PROXY`, `ALL_PROXY` | Định tuyến lưu lượng của CLI qua proxy này. Các host trong `NO_PROXY` đi thẳng |
| `SSL_CERT_FILE`, `SSL_CERT_DIR` | Tin cậy CA bundle hoặc thư mục này, dùng cho proxy ký lại HTTPS. Khi không đặt, CLI dùng kho chứng chỉ tin cậy của hệ điều hành |

## Mã thoát

| Mã | Ý nghĩa |
|---|---|
| 0 | Thành công |
| 1 | Công việc thất bại: lượt chạy thất bại, lượt chạy hoặc review không tồn tại, lỗi server như xung đột hoặc giới hạn tần suất, hoặc đã hết lượt thử lại kết nối |
| 2 | Dùng sai cách, hoặc server từ chối yêu cầu vì không hợp lệ (HTTP 422) |
| 3 | Chưa đăng nhập, thông tin xác thực đã hết hạn, hoặc bị từ chối truy cập |
| 4 | CLI ngừng chờ. Công việc vẫn tiếp tục trên server |
| 5 | Lượt chạy tạm dừng để chờ phê duyệt trên trình duyệt |
| 6 | Review tìm thấy vấn đề ở mức `--fail-on` hoặc cao hơn |
| 130 | Ctrl-C đã dừng lượt chờ `chat`, `incident status --wait` hoặc `login`. Lượt chạy hoặc sự cố vẫn tiếp tục trên server |

## Tập tin

| Đường dẫn | Nội dung |
|---|---|
| `~/.local/bin/cloudthinker` | File nhị phân mà trình cài đặt đặt vào `PATH` của bạn |
| `~/Library/Application Support/cloudthinker/credentials.json` (macOS), `$XDG_CONFIG_HOME/cloudthinker/credentials.json` hoặc `~/.config/cloudthinker/credentials.json` (Linux), hoặc `$CLOUDTHINKER_CONFIG_DIR/credentials.json` khi được đặt | Một lần đăng nhập cho mỗi workspace trên từng host |
| `~/.cloudthinker/agent/` | Cấu hình agent, gồm cả `settings.json` |
| `~/.cloudthinker/agent/bin/<version>/` | Bản build agent cho phiên bản CLI đó |
| `~/.cloudthinker/agent/sessions/` | Bản ghi các phiên agent cục bộ |
| `~/.cloudthinker/tools/` | Các công cụ do `cyber doctor --fix` cài |
| `.cloudthinker/config.toml` | Cài đặt Cyber đã lưu cho một project, nằm trong thư mục của project đó |
| `~/.cloudthinker/config.toml` | Cài đặt Cyber mặc định của bạn, từ `cyber config set --user` |

`credentials.json` là file JSON thuần với quyền `0600` trong thư mục `0700`, nên chỉ user của bạn đọc được. CLI không dùng keychain của hệ điều hành. Các bản trước 0.5.3 có dùng, và lượt chạy đầu tiên của bản mới hơn sẽ chuyển các lần đăng nhập đó vào file rồi xóa mục trong keychain. Trên máy có nhiều người đăng nhập, hãy cấp cho mỗi người một tài khoản hệ điều hành riêng, và chạy `cloudthinker logout --all` khi dùng xong.

### Gỡ cài đặt

1. Nếu máy này chạy environment dưới dạng service, hãy chạy `cloudthinker worker service uninstall`.
2. Chạy `cloudthinker logout --all` một lần cho mỗi host bạn đã đăng nhập, thêm `--url` cho mọi host khác host mặc định. Hoặc xóa `credentials.json`.
3. Xóa file nhị phân `~/.local/bin/cloudthinker`.
4. Xóa thư mục `~/.cloudthinker` và mọi script tự hoàn thành bạn đã lưu, như `"${fpath[1]}/_cloudthinker"`.
5. Tùy chọn: xóa các thư mục `.cloudthinker/` trong project của bạn.

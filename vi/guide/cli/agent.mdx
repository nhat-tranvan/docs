`cloudthinker agent` chạy agent lập trình ngay nơi code của bạn đang nằm. Nó đọc, sửa file và chạy lệnh trên máy bạn, còn model, bộ nhớ workspace và các [kết nối](/vi/guide/connections/overview) vẫn ở trong CloudThinker.

## Vì sao chạy cục bộ

- **Repository của bạn, không phải bản upload.** Agent làm việc trong thư mục hiện tại thay vì một bản sao trong sandbox của người khác.
- **Shell của bạn.** Nó chạy đúng những lệnh bạn sẽ chạy, với công cụ và credential vốn có trên máy đó.
- **Cùng một workspace.** Phiên làm việc tính phí, ghi nhớ và suy luận trên cùng workspace với ứng dụng web.

## Bắt đầu một phiên

<Steps>
  <Step title="Vào thư mục repository">
    ```bash
    cd ~/code/payments-api
    ```
  </Step>

  <Step title="Khởi động agent">
    ```bash
    cloudthinker
    ```

    `cloudthinker` trống chính là `cloudthinker agent`. Nó kiểm tra đăng nhập trước, và tự mở đăng nhập trình duyệt khi chưa có, nên một bản cài mới chỉ cần một lệnh là vào được phiên.

    **Trạng thái thành công:** agent mở phiên tương tác trong thư mục hiện tại. Lần chạy đầu tiên in `downloading cloudthinker-agent <version>` trong lúc tải bản agent tương ứng.
  </Step>

  <Step title="Yêu cầu thay đổi bạn muốn">
    Hãy mô tả kết quả mong muốn, không cần liệt kê file. Agent tự khám phá repository, đề xuất chỉnh sửa và chạy các lệnh cần thiết để tự kiểm chứng.
  </Step>
</Steps>

## Chạy một lần và chạy tiếp

Agent có bộ tùy chọn riêng, và mọi tham số sau `agent` được truyền thẳng cho nó:

```bash
cloudthinker agent -p "Add a health check endpoint to the API"   # không tương tác, xong là thoát
cloudthinker agent -c                                            # tiếp tục phiên trước
cloudthinker agent --model <pattern>                             # chọn model cho phiên này
cloudthinker agent -- --help                                     # xem tùy chọn của chính agent
```

Tùy chọn của bản thân CLI phải đứng trước `agent`:

```bash
cloudthinker --workspace Production agent
```

Dùng `--` khi một tùy chọn của agent trùng tên với tùy chọn của CLI, ví dụ `cloudthinker agent -- --url http://localhost:3000`. Mọi thứ sau `--` thuộc về agent.

## Bản agent được cài như thế nào

Agent đi kèm dưới dạng bundle trong cùng bản phát hành với CLI, không phải một bản tải riêng bạn phải tự quản lý.

1. Lần chạy `cloudthinker agent` đầu tiên sau khi cài hoặc cập nhật sẽ tải bundle cho nền tảng của bạn.
2. CLI đối chiếu với file SHA-256 đi kèm bản phát hành trước khi giải nén.
3. Bundle được cài vào `~/.cloudthinker/agent/bin/<version>/` và tái sử dụng ở các lần sau.
4. Khi CLI cập nhật, bundle tương ứng được cài ở lần chạy kế tiếp và bản cũ bị dọn đi.

Phiên bản CLI và agent luôn đi cùng nhau, nên `cloudthinker update` là bước duy nhất để nâng cả hai.

## Nền tảng hỗ trợ

Agent cục bộ chạy trên macOS (Apple Silicon và Intel) và Linux (x86_64 và arm64). Trên nền tảng khác, CLI báo rằng không có bản agent cho nền tảng đó thay vì tự thay thế bằng thứ khác.

## Xử lý sự cố

<AccordionGroup>
  <Accordion title="Lần nào cũng bắt đăng nhập lại">
    Có thứ gì đó đang ghi đè credential đã lưu, thường là một `CLOUDTHINKER_TOKEN` còn sót trong shell. Bỏ biến đó rồi chạy `cloudthinker login` một lần. Xem [Xác thực](/vi/guide/cli/authentication).
  </Accordion>

  <Accordion title="Agent khởi động sai workspace">
    Agent kế thừa workspace mà CLI đã phân giải. Kiểm tra bằng `cloudthinker whoami`, và ghim cho một phiên bằng `cloudthinker --workspace <name> agent`.
  </Accordion>

  <Accordion title="Cảnh báo nhắc tới CLOUDTHINKER_AGENT_BIN">
    Biến đó trỏ CLI tới một bản agent cục bộ thay vì bản phát hành đã cài. Bỏ biến đi để quay lại bundle chính thức.
  </Accordion>
</AccordionGroup>

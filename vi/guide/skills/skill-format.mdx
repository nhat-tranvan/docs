Mỗi skill là một file `SKILL.md`: một header YAML ngắn (frontmatter) đặt tên skill và cho biết khi nào dùng, tiếp theo là phần hướng dẫn viết bằng Markdown. Trang này trình bày các quy tắc mà file phải đáp ứng để tải được, và các cách viết giúp agent làm theo.

## Skill hợp lệ tối thiểu

Sao chép đoạn này, đổi tên, mô tả và quy tắc, là skill sẽ tải được:

```markdown
---
name: security-review-checklist
description: Enforce our SQL and secrets rules when reviewing code. Use for any pull request review or security question about code.
---

## SQL injection

- Flag SQL built with string concatenation or f-strings.
- Require parameterized queries or ORM methods.

## Secrets

- Flag hardcoded credentials, tokens, and API keys.
- Require secrets to come from a secrets manager or environment variables.
```

| Phần | Bắt buộc | Mục đích |
|---|---|---|
| Frontmatter (giữa hai dòng `---`) | Có | Chứa `name` và `description`. Phải là YAML hợp lệ. |
| Phần thân hướng dẫn | Có | Các quy tắc Markdown mà agent đọc khi dùng skill. |
| Mỗi nhóm quy tắc một heading `##` | Khuyến nghị | Giúp bạn và agent dễ lướt qua các quy tắc. |
| Ví dụ tốt và xấu | Khuyến nghị | Gắn mỗi quy tắc với một trường hợp cụ thể. |

## Các trường frontmatter

| Trường | Bắt buộc | Quy tắc |
|---|---|---|
| `name` | Có | Bắt đầu bằng chữ cái hoặc chữ số, sau đó là chữ cái, chữ số, `_` hoặc `-`. Được dùng chữ hoa. Không có khoảng trắng. Tối đa 255 ký tự. Tên phân biệt chữ hoa chữ thường, và lệnh `/` dùng đúng tên này. Không được trùng với skill tích hợp sẵn của CloudThinker, như `pdf`, `docx` hay `deep-research`. |
| `description` | Có | Một câu không rỗng nói skill làm gì và khi nào dùng. Agent đọc mô tả để quyết định skill nào hợp với tác vụ, nên mô tả mơ hồ khiến skill hiếm khi được chọn. Đặt trong dấu ngoặc kép nếu có dấu hai chấm: `description: "Use when: reviewing PRs"`. Tối đa 2.000 ký tự. |
| `argument-hint` | Không | Chỉ áp dụng khi ai đó chạy skill từ menu `/` trong chat. Đoạn text hiển thị cạnh skill trong menu đó, như `<service-name>`, để cho người dùng biết cần gõ gì sau lệnh. Trường này không thay đổi hành vi. Bất cứ gì người dùng gõ sau `/skill-name` đều tới agent như một phần tin nhắn của họ. |

Các trường khác, như `license` hay `allowed-tools` trong các file SKILL.md viết cho công cụ khác, không chặn việc tải lên, và CloudThinker không dùng chúng. Skill chuyển từ công cụ khác sang vẫn tải được, miễn là có `name` và `description`.

Ví dụ về tên:

| Tên | Hợp lệ? |
|---|---|
| `security-checklist` | Có |
| `security_checklist` | Có |
| `Security-Checklist` | Có |
| `Security Checklist` | Không (có khoảng trắng) |
| `-checklist` | Không (phải bắt đầu bằng chữ cái hoặc chữ số) |

<Note>
Khi bạn tạo skill bằng **Write skill instructions**, CloudThinker tự dựng frontmatter từ các trường **Skill name** và **Description**. Bạn chỉ tự viết frontmatter khi tải lên file `.zip` hoặc sửa `SKILL.md` bằng tay.
</Note>

## Cấu trúc gói zip

Dùng `.zip` khi skill cần file hỗ trợ, hoặc để chuyển skill giữa các workspace. Tải lên từ **More → Workspace settings → Skills → +** (cạnh **Search skills**) **→ Upload zip file**.

```text
security-review-checklist.zip
└── security-review-checklist/
    ├── SKILL.md            required
    ├── references/         optional: longer docs the skill points to
    ├── scripts/            optional: scripts the skill runs
    └── schemas/            optional: schemas the skill validates against
```

- Đặt `SKILL.md` ở thư mục gốc của zip hoặc bên trong một thư mục cấp cao nhất. Skill lấy tên từ `name` trong frontmatter, nên tên thư mục không cần khớp.
- Đặt tên file zip đúng bằng `name` trong frontmatter, kể cả chữ hoa chữ thường (ví dụ `security-review-checklist.zip`). CloudThinker dùng tên file zip để nhận ra skill đã có và đề xuất **Replace**. Nếu hai tên khác nhau, **Replace** có thể xóa skill trùng với tên zip và tải lên một skill dưới tên khác. Khi không có skill nào trùng, lần tải lên có `name` trong frontmatter đã bị dùng sẽ thất bại với **This skill name is already in use.**
- Chỉ `scripts/`, `schemas/` và `references/` được giữ lại. Các file và thư mục khác bị bỏ qua.
- Tham chiếu file hỗ trợ từ `SKILL.md` bằng đường dẫn tương đối. Agent không tự đọc các file này: agent chỉ mở file khi hướng dẫn trỏ tới, ví dụ:

  ```markdown
  For the escalation order, read references/escalation-matrix.md.
  ```

- Với script, hãy nêu tên và nói khi nào chạy, ví dụ "Run `scripts/check_tags.sh` with the account ID." Script có thể là Bash hoặc TypeScript (chạy bằng `bun`). Agent chạy script bằng chính công cụ lệnh dùng cho mọi lệnh khác, nên mọi thao tác ghi của script đều đi qua [Approvals](/vi/guide/approvals/overview) như các lệnh khác.
- Script nhận [Credentials](/vi/guide/credentials) của workspace dưới dạng biến môi trường, đặt tên theo **Key** của từng credential. Credential có key `DATADOG_API_KEY` sẽ là `$DATADOG_API_KEY` trong script.

<Note>
Credential không dành riêng cho script của skill: mọi lệnh agent chạy đều nhận mọi credential của workspace, dù skill hay prompt có dùng tới hay không. Bạn không thể giới hạn một credential cho riêng một skill hay agent. Chỉ lưu những key mà skill cần và ưu tiên key chỉ đọc của nhà cung cấp. Xem [cách agent dùng credential](/vi/guide/credentials#cách-agent-dùng-credential).
</Note>

## Giới hạn

| Mục | Giới hạn |
|---|---|
| `SKILL.md` tạo hoặc sửa trong ứng dụng | 50.000 ký tự |
| `SKILL.md` tải lên trong zip | Không giới hạn ngoài các giới hạn zip bên dưới. File dài hơn 50.000 ký tự không lưu được từ trình soạn thảo trong ứng dụng. |
| Mô tả | 2.000 ký tự |
| Tên skill | 255 ký tự |
| Dung lượng zip tải lên | 5 MB |
| Số file trong zip | 1.024 |
| Dung lượng zip sau khi giải nén | 50 MB, là giới hạn duy nhất cho các file trong `references/`, `scripts/` và `schemas/` |

## Kiểm tra trước khi tải lên

- `SKILL.md` được viết hoa và nằm ở thư mục gốc của zip hoặc sâu một thư mục.
- File bắt đầu bằng `---` ở dòng đầu tiên, và frontmatter đóng lại bằng `---`.
- `name` bắt đầu bằng chữ cái hoặc chữ số và chỉ dùng chữ cái, chữ số, `_` và `-`.
- `name` không trùng tên skill tích hợp sẵn, như `pdf` hay `deep-research`.
- `description` đã được điền, và nằm trong ngoặc kép nếu có dấu hai chấm.
- Tên file zip khớp chính xác với `name`.
- File hỗ trợ nằm trong `references/`, `scripts/` hoặc `schemas/`.

## Viết hướng dẫn mà agent làm theo

**Chỉ viết những gì agent chưa biết.** Agent đã hiểu SQL injection. Agent chưa biết quy tắc riêng của bạn về nó.

```markdown
<!-- Too general: the agent already knows this -->
SQL injection is a vulnerability where attackers run arbitrary SQL
through unsanitized input, so always be careful with queries...

<!-- Useful: your specific rules -->
## SQL injection
- Flag `execute()` calls that take f-strings or `.format()`.
- Require the `db.query(sql, params)` helper for every new query.
```

**Chọn kiểu quy tắc theo mức tự do bạn muốn cho agent:**

| Mức tự do | Kiểu | Dùng cho |
|---|---|---|
| Cao | Nguyên tắc và định hướng | Tư vấn kiến trúc, review mang tính khám phá |
| Trung bình | Checklist kèm ví dụ | Review tiêu chuẩn, kiểm tra bảo mật |
| Thấp | Template chính xác và trường cố định | Định dạng output, các phần bắt buộc |

**Cho thấy, đừng mô tả.** Một cặp ví dụ hiệu quả hơn một đoạn văn:

```markdown
## Naming
- `remaining_retries`, not `r`
- `is_authenticated`, not `auth`
- Booleans start with `is_`, `has_`, or `should_`.
```

**Mỗi skill một chủ đề.** Tách quy tắc bảo mật khỏi quy tắc hiệu năng để bạn có thể bật từng skill ở những nơi khác nhau. Nếu skill dài quá khoảng 300 dòng, hãy tách ra, hoặc chuyển các bảng tham chiếu dài vào `references/` và trỏ tới đó. Đây là lời khuyên để agent đi đúng hướng, thấp hơn nhiều so với giới hạn cứng 50.000 ký tự.

## Ví dụ đầy đủ

Một skill về tiêu chuẩn pull request mà bạn có thể điều chỉnh:

````markdown
---
name: pr-review-standards
description: Enforce our pull request standards for size, tests, and docs. Use when reviewing any merge request or pull request.
argument-hint: <pull request link>
---

## Size

- Flag pull requests over 500 changed lines as "needs splitting" and suggest split points.
- Generated files (migrations, lockfiles) don't count toward the limit.

## Tests

- Require tests for every new public function.
- Flag deleted tests that have no matching feature removal.

## Docs

- Flag breaking API changes without a migration note.
- Require a README update when a new environment variable is added.

## Comment format

```text
**[severity]** Short title

What is wrong and why it matters.

**Suggestion:** How to fix it.
```

Severity is one of `critical`, `warning`, `suggestion`, `nitpick`. For example:

```text
**[warning]** New endpoint has no tests

`create_invoice()` is public and has no test, so a regression would reach production unnoticed.

**Suggestion:** Add a test in `tests/test_invoices.py` that covers the happy path and an invalid amount.
```
````

Sau khi lưu, hãy tick **Review** trong **Available in** để skill áp dụng cho review pull request. Review không bao giờ dùng `argument-hint`; trường này chỉ giúp người chạy skill từ menu `/` trong chat. Xem [custom skill](/vi/guide/skills/custom-skills#chọn-nơi-áp-dụng-skill).

Kết nối một cluster Elasticsearch để agent CloudThinker liệt kê index, đọc field mapping, chạy truy vấn DSL và ES|QL, và kiểm tra phân bổ shard trong lúc điều tra sự cố. Kết nối đăng nhập bằng **API key** hoặc **username và password**, và mọi công cụ kết nối cung cấp đều chỉ đọc.

## Điều kiện tiên quyết

- Một cluster Elasticsearch có endpoint HTTPS mà CloudThinker truy cập được qua mạng, như một deployment Elastic Cloud hoặc một tên DNS công khai. CloudThinker Cloud không truy cập được `localhost` và các địa chỉ private.
- Nếu tường lửa hoặc traffic filter của Elastic Cloud bảo vệ cluster, hãy cho phép các egress IP của CloudThinker. Tài liệu này không công bố danh sách egress IP của CloudThinker: hãy hỏi đầu mối liên hệ CloudThinker của bạn, hoặc [liên hệ với chúng tôi](https://cloudthinker.io/contact). Xem [Truy cập dịch vụ private](/vi/guide/connections/overview#truy-cập-dịch-vụ-nội-bộ) để biết các lựa chọn khác.
- Quyền tạo API key (Kibana **Stack Management → Security → API keys**, hoặc API `_security/api_key`) hoặc tạo một user riêng.
- Các index pattern mà agent cần đọc, như `logs-*` hoặc `filebeat-*`.

## Thiết lập

<Steps>
  <Step title="Tạo API key chỉ đọc">
    Trong Kibana, mở **Dev Tools** và chạy request bên dưới. Thay `logs-*` bằng index pattern của bạn.

    ```http
    POST /_security/api_key
    {
      "name": "cloudthinker",
      "expiration": "90d",
      "role_descriptors": {
        "cloudthinker_read": {
          "cluster": ["monitor"],
          "indices": [
            {
              "names": ["logs-*"],
              "privileges": ["read", "view_index_metadata", "monitor"]
            }
          ]
        }
      }
    }
    ```

    Sao chép giá trị `encoded` trong response. Elasticsearch chỉ hiển thị giá trị này một lần.

    Bạn cũng có thể tạo key trong **Stack Management → Security → API keys**: nhấn **Create API key**, bật **Control security privileges**, rồi dán cùng đối tượng `role_descriptors` ở trên.
  </Step>
  <Step title="Sao chép endpoint của cluster">
    Dùng URL đầy đủ kèm scheme và port, như `https://elasticsearch.example.com:9200`. Trên Elastic Cloud, sao chép Elasticsearch endpoint từ trang deployment.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Mở **More → Workspace settings → Connections** và chọn **Elasticsearch**. Nhập endpoint vào **ES_URL**, chọn **API key** trong **Authentication**, rồi dán key đã mã hóa. Giữ **TLS certificate** ở **Verify** trừ khi cluster dùng chứng chỉ tự ký. Nhấn **Connect**.

    **Trạng thái thành công:** kết nối hiển thị **Connecting** và **Verifying**, rồi **Connected**. Nếu kiểm tra thất bại, kết nối hiển thị lỗi kèm thông báo mà cluster trả về. Đối chiếu thông báo đó với mục [Khắc phục sự cố](#khắc-phục-sự-cố).
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Bắt buộc | Mô tả | Ví dụ |
|-------|----------|-------------|---------|
| **ES_URL** | Có | Endpoint của cluster, gồm scheme và port | `https://elasticsearch.example.com:9200` |
| **Authentication** | Có | **API key** (mặc định) hoặc **Username & password** | **API key** |
| **API key** | Chỉ với API key | Giá trị `encoded` trong response khi tạo key | `VnVhQ2ZHY0JDZGJr...` |
| **Username** | Chỉ với Username & password | Một user Elasticsearch dành riêng | `cloudthinker` |
| **Password** | Chỉ với Username & password | Password của user đó | |
| **TLS certificate** | Không | **Verify** (mặc định) hoặc **Allow self-signed** | **Verify** |

Chỉ điền một phương thức. Nếu bạn nhập cả API key lẫn username hoặc password, kết nối bị từ chối với thông báo "Choose either an API key or username and password."

## Quyền yêu cầu

| Agent cần | Cấp quyền |
|----------------|-------|
| Kiểm tra sức khỏe cluster | Cluster privilege `monitor` |
| Liệt kê index và đọc phân bổ shard | Index privilege `monitor` trên các pattern của bạn |
| Đọc field mapping | Index privilege `view_index_metadata` trên các pattern của bạn |
| Chạy truy vấn DSL và ES\|QL | Index privilege `read` trên các pattern của bạn |

Nếu dùng **Username & password**, hãy tạo một role có cùng các quyền trên và một user giữ role đó. Chạy từng request riêng trong **Dev Tools**:

```http
POST /_security/role/cloudthinker_read
{
  "cluster": ["monitor"],
  "indices": [
    {
      "names": ["logs-*"],
      "privileges": ["read", "view_index_metadata", "monitor"]
    }
  ]
}
```

```http
POST /_security/user/cloudthinker
{
  "password": "<a long random password>",
  "roles": ["cloudthinker_read"]
}
```

<Tip>
Liệt kê đúng các index pattern agent cần thay vì dùng `*`. Key giới hạn trong `logs-*` không đọc được index `customers`, kể cả khi truy vấn yêu cầu.
</Tip>

## Khả năng của agent

| Khả năng | Agent làm được gì |
|------------|--------------------|
| **Danh mục index** | Liệt kê index kèm trạng thái và số document, nhận ra các mẫu đặt tên như `logs-app-*` |
| **Mapping** | Đọc tên và kiểu của field trước khi lọc, để truy vấn chỉ dùng field có thật |
| **Tìm kiếm** | Chạy truy vấn DSL có giới hạn khoảng thời gian, thứ tự sắp xếp và số kết quả |
| **ES\|QL** | Tổng hợp bằng ES\|QL, như đếm lỗi theo từng service, luôn kèm `LIMIT` |
| **Shard và sức khỏe** | Tìm shard chưa được phân bổ và báo sức khỏe cluster là green, yellow hoặc red |

Kết nối không có công cụ nào ghi, xóa hay thay đổi cài đặt cluster.

### Xác minh kết nối

```text
Check Elasticsearch cluster health and list the five largest indices by document count
```

Kết quả mong đợi: trạng thái sức khỏe, số shard kèm các shard chưa phân bổ (nếu có), và tên năm index cùng số document.

### Ví dụ prompt

```text
Count ERROR log lines per service in logs-app-* over the last hour
Search logs-* for authentication failures in the last 24 hours and group them by source IP
Why is the cluster yellow? List the unassigned shards and the indices they belong to
```

## Khắc phục sự cố

<Accordion title="Kết nối thất bại do timeout hoặc connection refused">
**ES_URL** trỏ tới địa chỉ mà CloudThinker không truy cập được. Hãy dùng endpoint công khai, kèm scheme và port, và kiểm tra tường lửa hoặc traffic filter của Elastic Cloud có cho phép egress IP của CloudThinker (xem [Điều kiện tiên quyết](#điều-kiện-tiên-quyết)).
</Accordion>

<Accordion title="401 Unauthorized">
API key sai, đã hết hạn hoặc đã bị vô hiệu hóa, hoặc password đã đổi. Hãy tạo key mới và [thay thông tin xác thực](/vi/guide/connections/overview#xoay-vòng-thông-tin-xác-thực) bằng giá trị `encoded` của key, không dùng riêng trường `id` hay `api_key`.
</Accordion>

<Accordion title="security_exception trên một index">
Key hoặc user không có quyền trên index đó. Thêm pattern của index vào `names` trong một key mới, rồi [thay thông tin xác thực](/vi/guide/connections/overview#xoay-vòng-thông-tin-xác-thực) trên kết nối.
</Accordion>

<Accordion title="Lỗi chứng chỉ trên cluster tự host">
Cluster dùng chứng chỉ tự ký. Chỉ đặt **TLS certificate** thành **Allow self-signed** khi bạn tin cậy cluster đó.
</Accordion>

<Accordion title="Truy vấn không trả về kết quả">
Index pattern không khớp, tên field khác với tên prompt giả định, hoặc khoảng thời gian không có dữ liệu. Hãy yêu cầu agent liệt kê index và đọc mapping của index trước.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Đặt thời hạn cho key**: một `expiration` như `90d` giới hạn thời gian key bị lộ còn dùng được. Tạo key mới trước khi key cũ hết hạn, sau đó mở kết nối, nhấn biểu tượng bút chì trên dòng của kết nối, và trong **Edit Instance** nhấn **Replace…**. Dán key mới và nhấn **Save and test**. Nếu kiểm tra thất bại, CloudThinker giữ key cũ, nên agent không mất quyền truy cập trong lúc đổi key.
- **Coi nội dung đã index là dữ liệu nhạy cảm**: log có thể chứa token hoặc dữ liệu cá nhân mà ứng dụng đã ghi ra. Hãy giới hạn key trong các index bạn muốn agent đọc.

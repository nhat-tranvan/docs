Kết nối một cluster Kubernetes để CloudThinker tìm các pod bị crash-loop hoặc kẹt ở trạng thái pending, đọc log và event, kiểm tra áp lực node, rà soát RBAC và network policy. Bạn tải lên một **file kubeconfig** đăng nhập bằng service account chỉ đọc dành riêng; các thay đổi như rollout restart đi qua Approvals của workspace và chỉ chạy khi bạn cấp RBAC ghi (xem [Quyền ghi](#quyền-ghi)).

## Điều kiện tiên quyết

- Một cluster có API server mà CloudThinker truy cập được qua internet. Lệnh chạy trên cloud của CloudThinker, nên endpoint chỉ riêng tư sẽ làm bài kiểm tra kết nối thất bại. Nếu bạn giới hạn truy cập API (public access CIDR của EKS, authorized network của GKE, authorized IP range của AKS), hãy thêm egress IP của CloudThinker thay vì mở cho `0.0.0.0/0`. Tài liệu này không công bố danh sách egress IP của CloudThinker: hãy hỏi đầu mối CloudThinker của bạn, hoặc [liên hệ chúng tôi](https://cloudthinker.io/contact). Xem [Truy cập dịch vụ riêng tư](/vi/guide/connections/overview#truy-cập-dịch-vụ-nội-bộ) để biết các phương án khác.
- Quyền `kubectl` vào cluster đó, đủ để tạo namespace, ClusterRole và ClusterRoleBinding.
- Cluster managed (EKS, GKE, AKS) cấp kubeconfig đăng nhập qua exec plugin `aws`, `gcloud` hoặc `az`, và các plugin này không chạy được trong CloudThinker. Bước 2 tạo một kubeconfig dùng được. Kubernetes tự kiểm tra token của service account, nên bạn không cần ánh xạ token trong IAM của cloud (ví dụ không cần EKS access entry).
- Tùy chọn: [Metrics Server](https://github.com/kubernetes-sigs/metrics-server) trong cluster. Không có Metrics Server, agent vẫn báo cáo trạng thái pod và điều kiện node, nhưng không có mức dùng CPU và bộ nhớ theo thời gian thực.
- Vai trò **Admin** trong workspace CloudThinker, vai trò có thể thêm và sửa kết nối. Xem [Vai trò](/vi/guide/security/roles).

<Info>
Mỗi workspace có **một** kết nối Kubernetes, và agent làm việc trong **current context** của kubeconfig. Hãy tải lên kubeconfig cho đúng một cluster bạn muốn kiểm tra. Với nhiều cluster, dùng [mỗi cluster một workspace](/vi/guide/workspaces#tạo-workspace), hoặc thêm [kết nối Rancher](/vi/guide/connections/rancher) để xem inventory và sức khỏe của các cluster mà Rancher quản lý.
</Info>

## Thiết lập

<Steps>
  <Step title="Tạo service account chỉ đọc">
    Lưu manifest này thành `cloudthinker-reader.yaml`. Manifest cũng tạo một Secret là token của service account, và chỉ bạn đọc Secret này ở bước 2. Phần [Quyền yêu cầu](#quyền-yêu-cầu) giải thích role cho phép những gì.

    <Accordion title="cloudthinker-reader.yaml">
      ```yaml
      apiVersion: v1
      kind: Namespace
      metadata:
        name: cloudthinker
      ---
      apiVersion: v1
      kind: ServiceAccount
      metadata:
        name: cloudthinker-reader
        namespace: cloudthinker
      ---
      apiVersion: rbac.authorization.k8s.io/v1
      kind: ClusterRole
      metadata:
        name: cloudthinker-reader
      rules:
      - apiGroups: [""]
        resources: ["pods", "pods/log", "nodes", "namespaces", "services", "endpoints", "events", "configmaps", "persistentvolumeclaims", "persistentvolumes", "resourcequotas", "limitranges", "serviceaccounts", "replicationcontrollers"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["apps"]
        resources: ["deployments", "replicasets", "statefulsets", "daemonsets"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["batch"]
        resources: ["jobs", "cronjobs"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["autoscaling"]
        resources: ["horizontalpodautoscalers"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["networking.k8s.io"]
        resources: ["ingresses", "networkpolicies"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["policy"]
        resources: ["poddisruptionbudgets"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["storage.k8s.io"]
        resources: ["storageclasses"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["rbac.authorization.k8s.io"]
        resources: ["roles", "rolebindings", "clusterroles", "clusterrolebindings"]
        verbs: ["get", "list", "watch"]
      - apiGroups: ["metrics.k8s.io"]
        resources: ["pods", "nodes"]
        verbs: ["get", "list"]
      ---
      apiVersion: rbac.authorization.k8s.io/v1
      kind: ClusterRoleBinding
      metadata:
        name: cloudthinker-reader
      roleRef:
        apiGroup: rbac.authorization.k8s.io
        kind: ClusterRole
        name: cloudthinker-reader
      subjects:
      - kind: ServiceAccount
        name: cloudthinker-reader
        namespace: cloudthinker
      ---
      apiVersion: v1
      kind: Secret
      metadata:
        name: cloudthinker-reader-token
        namespace: cloudthinker
        annotations:
          kubernetes.io/service-account.name: cloudthinker-reader
      type: kubernetes.io/service-account-token
      ```
    </Accordion>

    Áp dụng manifest:

    ```bash
    kubectl apply -f cloudthinker-reader.yaml
    ```

    Lệnh này tạo namespace `cloudthinker`, service account `cloudthinker-reader`, một ClusterRole chỉ đọc gắn với service account đó và một Secret chứa token dài hạn.

    **Trạng thái thành công:** `kubectl get secret cloudthinker-reader-token -n cloudthinker` liệt kê Secret với số `DATA` là 3. Kubernetes điền token vài giây sau khi bạn áp dụng, nên nếu `DATA` hiện 0, hãy đợi rồi chạy lại lệnh.
  </Step>
  <Step title="Tạo kubeconfig cho service account đó">
    Chạy từ shell có context `kubectl` hiện tại là cluster đích. Trước tiên, đọc và kiểm tra địa chỉ API server:

    ```bash
    SERVER=$(kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}')
    echo $SERVER
    ```

    Kết quả phải là hostname hoặc IP public. Nếu thấy `127.0.0.1`, `localhost` hoặc địa chỉ riêng như `10.x` hay `192.168.x` (thường gặp với kind, minikube, k3d hoặc khi đi qua proxy cục bộ), CloudThinker không truy cập được, nên hãy dừng lại và xử lý quyền truy cập trước.

    Sau đó, trong cùng shell, tạo file `cloudthinker-kubeconfig.yaml` có nhúng sẵn token và chứng chỉ CA:

    ```bash
    CA=$(kubectl get secret cloudthinker-reader-token -n cloudthinker -o jsonpath='{.data.ca\.crt}')
    TOKEN=$(kubectl get secret cloudthinker-reader-token -n cloudthinker -o jsonpath='{.data.token}' | base64 --decode)

    cat > cloudthinker-kubeconfig.yaml <<EOF
    apiVersion: v1
    kind: Config
    clusters:
    - name: target
      cluster:
        server: ${SERVER}
        certificate-authority-data: ${CA}
    users:
    - name: cloudthinker-reader
      user:
        token: ${TOKEN}
    contexts:
    - name: cloudthinker
      context:
        cluster: target
        user: cloudthinker-reader
    current-context: cloudthinker
    EOF
    ```

    Trên các bản macOS cũ, thay `base64 --decode` bằng `base64 -D`, và giữ dòng `EOF` kết thúc ở ngay đầu dòng.

    **Trạng thái thành công:** `kubectl --kubeconfig cloudthinker-kubeconfig.yaml get nodes` liệt kê các node của bạn. Đây cũng là lệnh CloudThinker chạy để kiểm tra kết nối.
  </Step>
  <Step title="Tải kubeconfig lên CloudThinker">
    Mở **More → Workspace settings → Connections**, chọn **Kubernetes** và tải `cloudthinker-kubeconfig.yaml` lên trường **KUBECONFIG**. Nhấn **Connect**.

    **Trạng thái thành công:** kết nối hiển thị **Connecting** và **Verifying**, rồi chuyển sang trạng thái **Connected**.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Bắt buộc | Mô tả | Ví dụ |
|-------|----------|-------------|---------|
| **KUBECONFIG** | Có | File kubeconfig. Bộ chọn file chỉ nhận đuôi `.yaml`, nên không chọn được file `.yml`. Hãy đổi đuôi thành `.yaml` trước. CloudThinker dùng current context của file | `cloudthinker-kubeconfig.yaml` |

Nhúng mọi thứ vào file. Kubeconfig trỏ đến file chứng chỉ cục bộ, hoặc đăng nhập qua plugin `exec`, cần những file và công cụ mà CloudThinker không có. File dùng token ở bước 2 tránh được cả hai.

## Quyền yêu cầu

Manifest ở [bước 1](#thiết-lập) cấp quyền đọc (`get`, `list`, `watch`) cho các tài nguyên agent cần kiểm tra, cùng log pod và metrics. Manifest này không đọc được Secret.

Quyền đọc áp dụng trên toàn cluster, kể cả `kube-system`, vì ClusterRoleBinding cấp role trong mọi namespace. Để chỉ bao phủ một số namespace, thay ClusterRoleBinding bằng một RoleBinding tới cùng ClusterRole đó trong từng namespace. Khi đó, các tài nguyên cấp cluster như node, namespace và persistent volume sẽ không xuất hiện trong câu trả lời, vì RoleBinding không cấp được chúng.

Custom resource không nằm trong role, nên agent không thấy các đối tượng dựa trên CRD như application của Argo CD hay virtual service của Istio. Để agent thấy được, hãy thêm vào ClusterRole một rule với API group của từng resource.

<Tip>
Rút gọn role đến đúng mức bạn cần. Bỏ `configmaps` nếu ConfigMap của bạn chứa giá trị nhạy cảm, và bỏ rule `rbac.authorization.k8s.io` nếu bạn không muốn rà soát RBAC. Lỗi `403` trong câu trả lời nêu tên tài nguyên mà role còn thiếu.
</Tip>

## Quyền ghi

Agent chỉ chạy thay đổi như `scale`, `rollout restart`, `cordon`, `drain` hoặc `apply` khi bạn yêu cầu trong cuộc hội thoại, và role chỉ đọc ở trên khiến các thay đổi này thất bại với `403`. **Allow writes** trên bảng chi tiết của kết nối là lớp kiểm soát thứ hai. Công tắc này bật theo mặc định, nhưng không thể nới rộng những gì role cho phép.

| RBAC trên service account `cloudthinker-reader` | Allow writes | Kết quả |
|---|---|---|
| Chỉ có rule đọc | Bật hoặc tắt | Chỉ đọc. Kubernetes từ chối mọi thay đổi với `403`. |
| Đã cấp rule ghi | Tắt | Chỉ đọc. CloudThinker từ chối mọi thay đổi trước khi đến cluster. |
| Đã cấp rule ghi | Bật | Agent có thể đề xuất thay đổi. [Rules và Approval mode](/vi/guide/approvals/overview) của bạn quyết định từng thay đổi. |

Để khóa cả thao tác ghi trong CloudThinker, mở **More → Workspace settings → Connections**, chọn **Kubernetes** và tắt công tắc **Allow writes** trên bảng chi tiết.

<ApprovalDefault />

Để cho phép một thay đổi cụ thể, chỉ cấp đúng những gì thay đổi đó cần:

- **Scale và rollout restart** tác động lên workload trong namespace. Dùng một Role trong từng namespace liên quan, với `patch` trên `deployments` và `get` cùng `patch` trên `deployments/scale`. Với StatefulSet, thêm tương tự cho `statefulsets` và `statefulsets/scale`. Với DaemonSet, thêm `daemonsets` (chỉ restart, vì DaemonSet không scale).
- **Apply** cần `get`, `create` và `patch` trên từng loại tài nguyên trong manifest bạn áp dụng, ở các namespace mà manifest nhắm tới.
- **Cordon và drain** tác động lên node, vốn là tài nguyên cấp cluster, nên Role trong namespace không cho phép được. Dùng ClusterRole với `patch` trên `nodes` và `create` trên `pods/eviction`. Role đọc đã có sẵn `get` và `list` trên pod và DaemonSet mà drain cần.

Các quyền ghi gắn vào cùng service account `cloudthinker-reader`, nên một kubeconfig bao phủ cả đọc lẫn thay đổi. Nếu bạn định cấp quyền ghi ngay từ đầu, hãy đổi tên account (ví dụ `cloudthinker-agent`) trong cả hai manifest và ở bước 2.

Ví dụ sau cho phép scale deployment trong một namespace, cùng cordon và drain. Thay `payments` bằng namespace của bạn, lưu thành `cloudthinker-write.yaml` và chạy `kubectl apply -f cloudthinker-write.yaml`.

```yaml
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: cloudthinker-scale
  namespace: payments
rules:
- apiGroups: ["apps"]
  resources: ["deployments"]
  verbs: ["patch"]
- apiGroups: ["apps"]
  resources: ["deployments/scale"]
  verbs: ["get", "patch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: cloudthinker-scale
  namespace: payments
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: cloudthinker-scale
subjects:
- kind: ServiceAccount
  name: cloudthinker-reader
  namespace: cloudthinker
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: cloudthinker-node-ops
rules:
- apiGroups: [""]
  resources: ["nodes"]
  verbs: ["patch"]
- apiGroups: [""]
  resources: ["pods/eviction"]
  verbs: ["create"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: cloudthinker-node-ops
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: cloudthinker-node-ops
subjects:
- kind: ServiceAccount
  name: cloudthinker-reader
  namespace: cloudthinker
```

**Trạng thái thành công:** `kubectl auth can-i patch deployments/scale -n payments --as=system:serviceaccount:cloudthinker:cloudthinker-reader` in ra `yes`.

## Khả năng của agent

| Khả năng | Agent làm gì |
|------------|----------------|
| **Phân loại workload** | Tìm pod bị crash-loop, pending hoặc khởi động lại liên tục, deployment suy giảm và event cảnh báo, rồi đọc log để giải thích nguyên nhân |
| **Áp lực node** | Báo cáo điều kiện node, capacity, tài nguyên allocatable, và những đối tượng dùng nhiều CPU, bộ nhớ nhất khi đã cài Metrics Server |
| **Capacity và lập lịch** | So sánh request và limit với mức sử dụng, và giải thích vì sao pod không được lập lịch |
| **Bảo mật và RBAC** | Rà soát role binding, service account, network policy và workload đặc quyền |
| **Cấu hình** | Kiểm tra ingress, service, storage, autoscaler và image trên các namespace. Custom resource cần thêm rule vào role |
| **Thay đổi** | Scale, restart, cordon, drain hoặc apply. Mỗi thay đổi đi qua Approvals |

### Xác minh kết nối

```text
Check the Kubernetes connection: list the namespaces, the node count, and any nodes that are not Ready
```

Bạn nhận được danh sách namespace, số node và trạng thái node. Nếu thiếu số liệu sử dụng, câu trả lời sẽ cho biết Metrics Server chưa được cài.

```text
Which pods in the payments namespace are crash-looping, and what do their logs say?

```

## Xoay vòng token

Kubernetes là dịch vụ chỉ cho một kết nối, nên khi kết nối đang hoạt động tốt sẽ không có biểu tượng bút chì hay hộp thoại **Edit Instance**. Hãy tạo token mới trước và xóa Secret cũ sau cùng: xóa trước sẽ cắt kết nối tới cluster khi bạn chưa có token thay thế hoạt động được.

<Steps>
  <Step title="Tạo Secret token thứ hai">
    Lưu nội dung sau thành `cloudthinker-reader-token-2.yaml`: một token thứ hai cho cùng service account, để cả hai cùng dùng được trong lúc bạn hoán đổi.

    ```yaml
    apiVersion: v1
    kind: Secret
    metadata:
      name: cloudthinker-reader-token-2
      namespace: cloudthinker
      annotations:
        kubernetes.io/service-account.name: cloudthinker-reader
    type: kubernetes.io/service-account-token
    ```

    Áp dụng file:

    ```bash
    kubectl apply -f cloudthinker-reader-token-2.yaml
    ```

    **Trạng thái thành công:** `kubectl get secret cloudthinker-reader-token-2 -n cloudthinker` liệt kê Secret với số `DATA` là 3.
  </Step>
  <Step title="Tạo kubeconfig từ token mới">
    Lặp lại bước 2 của phần [Thiết lập](#thiết-lập), dùng `cloudthinker-reader-token-2` thay cho `cloudthinker-reader-token`.

    **Trạng thái thành công:** `kubectl --kubeconfig cloudthinker-kubeconfig.yaml get nodes` liệt kê các node của bạn.
  </Step>
  <Step title="Hoán đổi trong CloudThinker">
    Khi kết nối đang hiển thị **Connected**, nhấn **Disconnect** trên bảng chi tiết **Kubernetes**, rồi kết nối lại và tải lên kubeconfig mới. Khi kết nối hiển thị **Error**, nhấn **Replace credentials** trên bảng chi tiết và tải kubeconfig mới lên, không cần ngắt kết nối.

    **Trạng thái thành công:** kết nối hiển thị **Connected**.
  </Step>
  <Step title="Xóa Secret cũ">
    Đến lúc này mới xóa token đã được thay thế:

    ```bash
    kubectl delete secret cloudthinker-reader-token -n cloudthinker
    ```
  </Step>
</Steps>

Ngắt kết nối rồi kết nối lại sẽ tạo một kết nối mới:

- Agent và các [automation](/vi/guide/automation/automations) theo lịch không dùng được cluster trong khoảng giữa lúc ngắt và lúc kết nối lại.
- Quá trình khám phá chạy lại và tiêu tốn credit.
- **Allow writes** trở về trạng thái bật. Hãy tắt lại nếu trước đó bạn đã tắt.
- Kiểm tra các [Rule](/vi/guide/approvals/rules) có nêu tên kết nối Kubernetes vẫn còn liệt kê kết nối này.

Nếu chính sách của bạn cấm thông tin xác thực dài hạn, hãy bỏ qua Secret và tạo kubeconfig bằng token ngắn hạn từ `kubectl create token cloudthinker-reader -n cloudthinker --duration=<time>`. Kết nối sẽ hỏng khi token đó hết hạn, nên mỗi lần như vậy bạn phải tạo và tải lên lại kubeconfig.

## Khắc phục sự cố

Khi kiểm tra thất bại, CloudThinker hiển thị `Failed to connect to Kubernetes:` kèm dòng lỗi đầu tiên của `kubectl get nodes`. Đối chiếu dòng đó với các mục dưới đây.

<Accordion title="Unable to connect to the server">
CloudThinker không truy cập được API server trong kubeconfig. Kiểm tra địa chỉ `server` truy cập được từ internet, không chỉ từ VPN của bạn, và allowlist của API server (nếu có) cho phép truy cập từ bên ngoài. Chạy `kubectl --kubeconfig cloudthinker-kubeconfig.yaml get nodes` từ một máy bên ngoài mạng của bạn để xác nhận.
</Accordion>

<Accordion title="error: You must be logged in to the server (Unauthorized)">
Token sai, đã hết hạn hoặc đã bị thu hồi. Kiểm tra Secret `cloudthinker-reader-token` vẫn tồn tại, rồi tạo lại kubeconfig từ bước 2 và tải lên theo hướng dẫn [Xoay vòng token](#xoay-vòng-token).
</Accordion>

<Accordion title="Error from server (Forbidden) trong câu trả lời">
ClusterRole không bao phủ tài nguyên đó. Xác nhận ClusterRoleBinding đã được áp dụng, rồi thêm tài nguyên vào role.
</Accordion>

<Accordion title="getting credentials: exec, hoặc no such file or directory">
Kubeconfig phụ thuộc vào một lệnh hoặc đường dẫn file cục bộ. Thay bằng kubeconfig dùng token ở bước 2.
</Accordion>

<Accordion title="Câu trả lời không có mức dùng CPU hoặc bộ nhớ">
Metrics Server chưa được cài hoặc chưa sẵn sàng. Chạy `kubectl top nodes` để kiểm tra. Trạng thái pod, event và điều kiện node vẫn hoạt động khi không có Metrics Server.
</Accordion>

<Accordion title="Connection 'k8s' already exists. Only one instance is allowed.">
`k8s` là kết nối Kubernetes, và mỗi workspace chỉ có một kết nối này. Không có biểu tượng bút chì để sửa, nên để trỏ CloudThinker sang cluster khác, hãy nhấn **Disconnect** trên bảng chi tiết **Kubernetes** rồi kết nối lại bằng kubeconfig kia.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Giữ Secret ngoài role.** Manifest ở trên không bao giờ cấp quyền đọc Secret, nên agent không đọc được đối tượng Secret. Log pod và ConfigMap thì đọc được, nên hãy bỏ `pods/log` hoặc `configmaps` khỏi role nếu chúng chứa dữ liệu nhạy cảm. Giá trị env đặt trực tiếp trong pod spec đọc được qua `pods`, nên hãy chuyển các giá trị nhạy cảm vào Secret.
- **Xoay vòng token.** Secret token không tự hết hạn, nên hãy xoay vòng theo lịch thông thường của bạn. Xem [Xoay vòng token](#xoay-vòng-token).
- **Thu hồi bằng một lệnh.** Xóa Secret token để cắt quyền truy cập ngay, hoặc xóa namespace `cloudthinker` cùng ClusterRole và binding để gỡ bỏ toàn bộ.

Kết nối một Redis server, như Redis tự host, Upstash hoặc Redis Cloud, để agent CloudThinker kiểm tra bộ nhớ và eviction, tìm các key lớn nhất và các key không có TTL, liệt kê client và đọc độ trễ lệnh. Bạn cung cấp cho CloudThinker một URL kết nối (`REDIS_URL`): agent chạy được các lệnh mà ACL của user đó cho phép, và các công cụ ghi của kết nối luôn đi qua [Approvals](/vi/guide/approvals/overview) trước.

## Điều kiện tiên quyết

- Một Redis endpoint mà CloudThinker truy cập được từ internet. Agent kết nối từ CloudThinker Cloud, nên `localhost` và địa chỉ private được phân giải ở phía CloudThinker, không phải trong mạng của bạn. Không có tùy chọn private link, nên các dịch vụ chỉ chạy trong VPC như Amazon ElastiCache và MemoryDB không kết nối được. Xem [Truy cập dịch vụ private](/vi/guide/connections/overview#truy-cập-dịch-vụ-nội-bộ).
- Redis 6 trở lên nếu bạn muốn dùng một ACL user riêng. Các phiên bản cũ hơn chỉ hỗ trợ một password dùng chung.
- Quyền admin để chạy `ACL SETUSER`, hoặc để tạo user trong console của nhà cung cấp dịch vụ managed.

## Thiết lập

<Steps>
  <Step title="Tạo user chỉ đọc">
    <Tabs>
      <Tab title="Redis tự host">
        Tạo một user chỉ đọc được key và chạy các lệnh chẩn đoán mà agent dùng, ngoài ra không gì khác:

        ```bash
        redis-cli --askpass ACL SETUSER cloudthinker-readonly on \
          '><readonly-password>' '~*' \
          -@all +@read +info +ping +select '+client|list' -keys
        ```

        | Thành phần | Ý nghĩa |
        |------|---------|
        | `'><readonly-password>'` | Đặt password. Dấu `>` là cú pháp ACL |
        | `'~*'` | Cho phép mọi key. Thu hẹp về một prefix, như `'~app:*'` |
        | `-@all +@read` | Bắt đầu từ con số không, rồi cho phép các lệnh đọc như `GET`, `SCAN`, `TYPE` và `TTL` |
        | `+info +ping +select '+client\|list'` | Cho phép đọc thống kê server, kiểm tra sức khỏe, chọn database index và liệt kê client |
        | `-keys` | Chặn `KEYS`, lệnh có thể làm treo một instance lớn. Agent dùng `SCAN` thay thế |

        `--askpass` hỏi password admin qua prompt, nên password không nằm trong lịch sử shell. Thêm `--user <admin-user>` nếu bạn không đăng nhập bằng `default`. Giữ dấu nháy quanh `'+client|list'`: thiếu dấu nháy, shell sẽ hiểu `|` là pipe.

        Lưu cấu hình để giữ lại sau khi khởi động lại: chạy `ACL SAVE` nếu bạn dùng `aclfile`, hoặc `CONFIG REWRITE` nếu user nằm trong `redis.conf`.
      </Tab>
      <Tab title="Redis managed">
        Nhà cung cấp nào cũng nhận cùng một ACL rule. Dán rule không kèm dấu nháy vào trường trên console, còn trong shell thì giữ dấu nháy quanh `'+client|list'`:

        ```text
        ~* -@all +@read +info +ping +select +client|list -keys
        ```

        - **Redis Cloud**: vào **Data Access Control**. Thêm một Redis ACL với rule ở trên, tạo một role áp dụng ACL đó cho database của bạn, rồi tạo một user có role đó.
        - **Azure Cache for Redis**: dùng port TLS `6380` với `rediss://`, và cho phép egress IP của CloudThinker trong firewall rule của cache.

        Sau đó sao chép URL kết nối TCP hoặc Redis CLI của user đó. Đừng dùng URL REST hay SDK: CloudThinker giao tiếp bằng giao thức Redis.
      </Tab>
    </Tabs>
  </Step>
  <Step title="Kiểm tra user là chỉ đọc">
    ```bash
    redis-cli -u 'rediss://cloudthinker-readonly@redis.example.com:6379' --askpass SET probe 1
    redis-cli -u 'rediss://cloudthinker-readonly@redis.example.com:6379' --askpass INFO memory
    ```

    Chỉ dùng `redis://` nếu server của bạn không dùng TLS. Scheme không khớp với server sẽ báo lỗi kết nối, không phải `NOPERM`.

    **Trạng thái thành công:** `SET` thất bại với `NOPERM`, còn `INFO memory` in ra thống kê bộ nhớ.
  </Step>
  <Step title="Mở quyền truy cập mạng">
    Cho phép kết nối vào port Redis từ egress IP của CloudThinker trong tường lửa, security group hoặc allowlist của nhà cung cấp. Tài liệu này không công bố danh sách egress IP của CloudThinker: hãy hỏi đầu mối liên hệ CloudThinker của bạn, hoặc [liên hệ với chúng tôi](https://cloudthinker.io/contact). Port mặc định là `6379`, `6380` với Azure TLS, còn trên Redis Cloud thì mỗi database được cấp một port riêng. Với Redis tự host, hãy đảm bảo `bind` trong `redis.conf` không chỉ có `127.0.0.1`.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Mở **More → Workspace settings → Connections**, chọn **Redis**, rồi nhấn **Connect** trên bảng chi tiết. Trong hộp thoại, bạn có thể đổi **Alias** và **Description** nếu muốn. Dán URL vào **REDIS_URL** và nhấn **Connect**:

    ```text
    rediss://cloudthinker-readonly:<readonly-password>@redis.example.com:6379/0
    ```

    **Trạng thái thành công:** kết nối hiển thị **Connecting** và **Verifying**, rồi **Connected**. Sau đó CloudThinker chạy [Discovery](/vi/guide/connections/overview#điều-gì-xảy-ra-sau-khi-kết-nối) một lần: một lượt xem chỉ đọc trên server, kết quả hiện trong mục **Discovery** của bảng chi tiết kết nối.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Bắt buộc | Mô tả | Ví dụ |
|-------|----------|-------------|---------|
| **Alias** | Không | Tên ngắn cho server này. Được điền sẵn alias trống tiếp theo, như `redis-1` | `prod-cache` |
| **Description** | Không | Server này là gì. Agent đọc trường này để chọn giữa các instance | `Production session cache` |
| **REDIS_URL** | Có | URL đầy đủ: scheme, user, password, host, port và database index (tùy chọn) | `rediss://cloudthinker-readonly:<password>@redis.example.com:6379/0` |

| Thành phần URL | Giá trị |
|----------|--------|
| Scheme | `rediss://` cho TLS (bắt buộc với Upstash), `redis://` cho TCP thường |
| User | ACL user của bạn. Trên Upstash và trên Redis chỉ dùng password, hãy dùng `default` |
| Port | Mặc định `6379`, `6380` với Azure TLS. Redis Cloud cấp port riêng cho từng database, nên hãy sao chép từ console |
| Database index | `/0` tới `/15` ở cuối URL. Bỏ trống nếu là `0` |

Mã hóa URL các ký tự đặc biệt trong password (`@` thành `%40`).

## Quyền yêu cầu

| Bạn muốn agent | Cho phép |
|--------------------|-------|
| Đọc key, kiểu, TTL, kích thước và số lượng key | `+@read` và một key pattern như `~*` |
| Đọc bộ nhớ, eviction, hit rate, replication và thống kê lệnh | `+info` |
| Xem các client đang kết nối | `+client\|list` |
| Dùng database index khác `0` | `+select` |
| Thay đổi key | Các nhóm lệnh ghi như `+@write`. Không khuyến nghị. Xem [Quyền ghi](#quyền-ghi) |

<Tip>
Giữ user ở chế độ chỉ đọc. ACL chỉ đọc chặn mọi thao tác ghi ngay tại Redis, bất kể thao tác đó đã được phê duyệt hay chưa.
</Tip>

## Khả năng của agent

| Khả năng | Agent làm được gì |
|------------|--------------------|
| **Bộ nhớ và eviction** | Đọc bộ nhớ đã dùng, tỷ lệ phân mảnh, chính sách `maxmemory`, số eviction và hit rate |
| **Keyspace** | Đếm key theo database, lấy mẫu key bằng `SCAN`, đọc kiểu, kích thước và TTL |
| **Kiểm tra thời hạn** | So sánh key có và không có TTL trong từng database, đối chiếu với chính sách `maxmemory` |
| **Key lớn nhất** | Xếp hạng các key lấy mẫu theo kích thước: độ dài chuỗi, hoặc số phần tử với list, hash, set và sorted set. Mẫu mặc định là 100 key từ `SCAN`, nên kết quả là ước lượng, và câu trả lời sẽ nói rõ khi lượt quét không phủ hết mọi key |
| **Client và độ trễ** | Liệt kê client đang kết nối, đọc số lần gọi và độ trễ theo từng lệnh từ `INFO commandstats` |
| **Replication** | Đọc vai trò, số replica đang kết nối và replication offset |
| **Module** | Đọc index RediSearch và document RedisJSON, khi server đã nạp các module đó |

### Xác minh kết nối

```text
Summarize Redis memory usage, connected clients, eviction policy, and key counts per database
```

Kết quả mong đợi: bộ nhớ đã dùng và mức đỉnh, số client, chính sách `maxmemory`, và số key của từng database index. Lỗi `NOPERM` sẽ nêu tên lệnh còn thiếu. Thêm lệnh đó bằng `ACL SETUSER cloudthinker-readonly`, rồi hỏi lại.

### Ví dụ prompt

```text
Which sampled keys are the largest, and what share of keys in each database has no TTL?
Is Redis evicting keys? Show the eviction policy, evictions, and hit rate
Which commands have the highest average latency according to commandstats?
```

## Quyền ghi

Kết nối Redis có công cụ ghi. Nếu ACL cho phép ghi, mỗi thao tác ghi đều đi qua [Approvals](/vi/guide/approvals/overview) trước, và một [rule](/vi/guide/approvals/rules) có thể yêu cầu hỏi trước hoặc từ chối thao tác đó.

<ApprovalDefault />

| Loại | Công cụ |
|---|---|
| Ghi | Set, đặt thời hạn, đổi tên, publish, pop khỏi list, và thêm vào hash, list, set, sorted set, stream và document JSON |
| Phá hủy | Xóa một key, hoặc xóa phần tử khỏi hash, list, set, sorted set, stream hoặc document JSON |
| Tùy theo lệnh | Một lệnh Redis thô: lệnh đọc như `GET` chạy mà không cần hỏi, `DEL` hoặc `FLUSHALL` được tính là phá hủy, mọi lệnh khác được tính là ghi |

## Khắc phục sự cố

<Accordion title="NOAUTH hoặc WRONGPASS">
User hoặc password sai hoặc bị thiếu. Kiểm tra cả hai trong **REDIS_URL**, kể cả phần mã hóa URL. Trên Upstash, dùng `default` làm user và database token làm password. Trên Redis tự host, chạy `ACL LIST` để xác nhận user tồn tại và đang `on`.
</Accordion>

<Accordion title="Kết nối bị đóng, hoặc kết nối không bao giờ đạt Connected">
Thường do URL sai định dạng. Kiểm tra scheme (`rediss://` cho endpoint TLS, Upstash bắt buộc dùng), host, port, và URL có kèm password. URL REST hoặc SDK của nhà cung cấp sẽ không hoạt động: hãy dùng URL TCP hoặc Redis CLI.
</Accordion>

<Accordion title="Connection refused hoặc timeout">
CloudThinker không truy cập được server. Kiểm tra tường lửa, security group hoặc allowlist của nhà cung cấp, và đảm bảo `bind` trong `redis.conf` không chỉ có `127.0.0.1`. Server trong mạng private cần có một endpoint truy cập được trước.
</Accordion>

<Accordion title="NOPERM với INFO, CLIENT LIST hoặc một lệnh đọc">
ACL thiếu một lệnh. Thêm `+info`, `'+client|list'` hoặc nhóm lệnh mà thông báo lỗi nêu tên bằng `ACL SETUSER cloudthinker-readonly ...`, rồi hỏi lại. `NOPERM` với lệnh ghi là điều bình thường đối với user chỉ đọc.
</Accordion>

<Accordion title="Command is not available: FT.* or JSON.*">
Server chưa nạp module RediSearch hoặc RedisJSON. Nhiều gói hosted không đi kèm các module này. Mọi chức năng khác vẫn hoạt động bình thường.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Dùng `rediss://`**: `redis://` thường gửi password và mọi giá trị dưới dạng không mã hóa. Hãy dùng TLS bất cứ khi nào server hoặc nhà cung cấp hỗ trợ.
- **Giới hạn phạm vi key**: thay `~*` bằng các prefix agent cần, như `~cache:*`, để session token và các key nhạy cảm khác nằm ngoài tầm với.

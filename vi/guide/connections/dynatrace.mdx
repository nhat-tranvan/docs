Kết nối môi trường Dynatrace để agent CloudThinker liệt kê các problem đang mở, chạy DQL (Dynatrace Query Language) trên log, metric, span và sự kiện trong Grail, xem xét lỗ hổng và tìm các thực thể mà một problem ảnh hưởng tới. Kết nối dùng Dynatrace MCP server chính thức, đăng nhập bằng một **platform token** cho một môi trường.

## Điều kiện tiên quyết

- Một môi trường Dynatrace SaaS trên Dynatrace Platform (Grail), chứa dữ liệu bạn muốn agent đọc. Dynatrace Managed và các môi trường classic không có địa chỉ `apps.dynatrace.com` không thể kết nối.
- Một người dùng Dynatrace (hoặc service user) trong tài khoản của môi trường đó, có quyền đọc dữ liệu agent cần truy vấn. Mọi thành viên tài khoản đều tạo được platform token, nhưng token chỉ có đúng quyền của người dùng đó.
- URL môi trường theo định dạng Platform: `https://<environment-id>.apps.dynatrace.com`.

## Thiết lập

<Steps>
  <Step title="Tìm URL môi trường">
    Đăng nhập Dynatrace và sao chép địa chỉ trên trình duyệt đến hết `.apps.dynatrace.com`, ví dụ `https://abc12345.apps.dynatrace.com`.

    Dùng địa chỉ `apps.dynatrace.com`, không dùng địa chỉ classic `live.dynatrace.com`. MCP server chỉ làm việc với Platform API.
  </Step>
  <Step title="Tạo platform token">
    Mở **My platform tokens** trong tài khoản Dynatrace ([myaccount.dynatrace.com/platformTokens](https://myaccount.dynatrace.com/platformTokens)) và chọn **Platform token**. Thiết lập:
    - **Token name**: `cloudthinker`
    - **Expiration date**: thời hạn phù hợp với chính sách xoay vòng của bạn
    - **Environments**: môi trường bạn tìm được ở bước trước, trừ khi bạn áp dụng token cho toàn bộ tài khoản
    - **Scopes**: `app-engine:apps:run` cùng các scope đọc cho loại dữ liệu bạn muốn agent truy vấn (xem [Quyền yêu cầu](#quyền-yêu-cầu))

    Nhấn **Generate** và sao chép token. Dynatrace chỉ hiển thị token một lần. Token chỉ làm được những gì người dùng của nó được phép, nên hãy tạo token bằng một người dùng (hoặc service user) có quyền đọc dữ liệu đó.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Mở **More → Workspace settings → Connections**, giữ nguyên tab **Builtin Connections** và chọn **Dynatrace**. Điền:

    - **DT_ENVIRONMENT**: URL môi trường của bạn
    - **DT_PLATFORM_TOKEN**: token bạn vừa tạo

    Nhấn **Connect**.

    **Trạng thái thành công:** Dynatrace hiển thị **Connected**. Chạy prompt xác minh bên dưới để chắc chắn token đọc được môi trường của bạn.
  </Step>
</Steps>

<Warning>
Dùng **platform token**, không dùng API token classic của Dynatrace. API token classic không có các Platform scope mà MCP server cần, nên hầu hết yêu cầu sẽ thất bại với lỗi 401 hoặc 403.
</Warning>

## Chi tiết kết nối

| Trường | Mô tả | Ví dụ |
|-------|-------------|---------|
| **DT_ENVIRONMENT** | URL môi trường Dynatrace Platform | `https://abc12345.apps.dynatrace.com` |
| **DT_PLATFORM_TOKEN** | Platform token cho môi trường đó | `<your-platform-token>` |

Để truy cập môi trường khác, hãy thêm môi trường đó thành một kết nối riêng với token riêng.

## Quyền yêu cầu

Bắt đầu với `app-engine:apps:run` và chỉ thêm các scope đọc cho những loại dữ liệu agent cần truy vấn.

| Scope | Cho phép |
|-------|-----------------|
| `app-engine:apps:run` | Bắt buộc. Chạy các công cụ Dynatrace MCP |
| `storage:buckets:read` | Tìm các bucket Grail mà token đọc được |
| `storage:logs:read` | Truy vấn log bằng DQL |
| `storage:metrics:read` | Truy vấn metric bằng DQL |
| `storage:spans:read` | Truy vấn trace và span bằng DQL |
| `storage:events:read` | Truy vấn sự kiện bằng DQL |
| `storage:entities:read` | Truy vấn các thực thể được giám sát bằng DQL |
| `storage:smartscape:read` | Truy vấn topology Smartscape bằng DQL |
| `storage:security.events:read` | Truy vấn sự kiện bảo mật bằng DQL |
| `storage:bizevents:read` | Truy vấn business event bằng DQL |
| `storage:user.events:read` | Truy vấn user event bằng DQL |
| `storage:user.sessions:read` | Truy vấn user session bằng DQL |
| `storage:system:read` | Truy vấn dữ liệu hệ thống bằng DQL |
| `storage:files:read` | Dùng dữ liệu tra cứu trong câu lệnh `load` của DQL |
| `document:documents:write` | Tùy chọn. Cho phép agent tạo notebook Dynatrace |

Các công cụ tùy chọn cần thêm scope. Chỉ thêm những scope cho công cụ bạn muốn agent dùng:

| Công cụ | Scope bổ sung |
|------|--------------|
| Davis analyzers | `davis:analyzers:read` để liệt kê, `davis:analyzers:execute` để chạy một analyzer |
| Hỗ trợ DQL | `davis-copilot:nl2dql:execute` (chuyển câu hỏi thành DQL), `davis-copilot:dql2nl:execute` (giải thích một truy vấn) |
| Gửi sự kiện | `storage:events:write` |
| Gửi email | `email:emails:send` |

Danh sách đầy đủ có trong [README của Dynatrace MCP server](https://www.npmjs.com/package/@dynatrace-oss/dynatrace-mcp-server).

<Tip>
Nếu DQL chạy được với loại dữ liệu này nhưng thất bại với loại khác, token đang thiếu scope `storage:*:read` của loại đó. Thêm scope trong Dynatrace và cập nhật token trong kết nối.
</Tip>

## Khả năng của agent

| Khả năng | Agent có thể làm gì | Phê duyệt |
|------------|--------------------|----------|
| **Kiểm tra môi trường** | Xác nhận kết nối và đọc thông tin cơ bản của môi trường | Không |
| **Problem** | Liệt kê các problem đang mở và gần đây cùng các dịch vụ hoặc host bị ảnh hưởng | Không |
| **Lỗ hổng** | Liệt kê lỗ hổng, lọc theo điểm rủi ro, ví dụ từ 7.0 trở lên | Không |
| **Thực thể** | Tìm thực thể được giám sát theo tên | Không |
| **DQL** | Kiểm tra truy vấn hợp lệ rồi chạy với giới hạn bản ghi nhỏ | Không |
| **Hỗ trợ DQL** | Chuyển câu hỏi thông thường thành DQL hoặc giải thích một truy vấn có sẵn (cần thêm scope) | Không |
| **Sự kiện và exception Kubernetes** | Liệt kê sự kiện Kubernetes của một cluster hoặc workload, và các exception gần đây | Không |
| **Davis analyzers** | Liệt kê các Davis analyzer có sẵn và chạy một analyzer trên một khoảng thời gian (cần thêm scope) | Không |
| **Notebook** | Tạo notebook Dynatrace chứa các phát hiện | Có |
| **Thông báo và sự kiện** | Gửi email qua Dynatrace, gửi sự kiện hoặc tạo workflow thông báo (cần thêm scope) | Có |

Agent kiểm tra từng truy vấn DQL trước khi chạy và bắt đầu với 50 đến 100 bản ghi. Điều này quan trọng về chi phí: truy vấn DQL quét dữ liệu Grail, có thể được tính vào mức tiêu thụ Dynatrace của bạn (xem [bảng giá Dynatrace](https://www.dynatrace.com/pricing/)). MCP server cũng giữ một **Grail query budget**, tức tổng lượng dữ liệu mà các truy vấn đã quét, và dừng truy vấn khi dùng hết. Mọi thao tác ghi đều đi qua [Approvals](/vi/guide/approvals/overview), và lệnh gọi bị từ chối sẽ không được thử lại.

### Xác minh kết nối

```text
Run Dynatrace discovery and list open problems and high-risk vulnerabilities
```

Bạn sẽ thấy thông tin môi trường, các problem đang mở cùng thực thể bị ảnh hưởng, và các lỗ hổng có điểm rủi ro từ 7.0 trở lên. Nếu token có các scope Davis, danh sách Davis analyzer cũng xuất hiện.

### Ví dụ prompt

```text
Which Dynatrace problems are open in production right now, and which services do they affect?
Query Dynatrace logs for errors from the checkout service in the last 30 minutes
List Dynatrace vulnerabilities with a risk score of 7 or higher on internet-facing services
Show the Kubernetes events for the payments workload in the last hour
```

Với môi trường lớn, hãy nêu tên dịch vụ, thực thể hoặc bucket và một khoảng thời gian ngắn. Truy vấn hẹp trả kết quả nhanh hơn và tốn ít Grail budget hơn.

## Khắc phục sự cố

<Accordion title="Kết nối thất bại hoặc mọi yêu cầu trả về 401">
Token bị thiếu, hết hạn, bị thu hồi hoặc là API token classic. Tạo platform token mới có `app-engine:apps:run`, sửa kết nối và dán token vào **DT_PLATFORM_TOKEN**. Đồng thời kiểm tra **DT_ENVIRONMENT** dùng `apps.dynatrace.com`, không phải `live.dynatrace.com`.
</Accordion>

<Accordion title="Một số truy vấn trả về 403">
Token thiếu scope cho loại dữ liệu đó. Ví dụ, truy vấn log cần `storage:logs:read`. Thêm scope trong Dynatrace và cập nhật kết nối.
</Accordion>

<Accordion title="Truy vấn DQL không trả về dòng nào">
Truy vấn có thể nhắm vào bucket mà token không đọc được, khoảng thời gian không có dữ liệu, hoặc tên thực thể bị viết sai. Yêu cầu agent tìm thực thể theo tên trước, rồi chạy lại truy vấn trên một dịch vụ đã biết với khoảng thời gian ngắn.
</Accordion>

<Accordion title="Yêu cầu trả về 429">
Grail query budget đã dùng hết. Yêu cầu agent đặt lại budget (thao tác đặt lại đi qua Approvals như mọi thao tác ghi), rồi thu hẹp khoảng thời gian và giới hạn bản ghi để các truy vấn tiếp theo quét ít dữ liệu hơn.
</Accordion>

<Accordion title="Không tìm thấy thực thể hoặc problem (404)">
Thực thể đã được đổi tên hoặc id bị sai. Yêu cầu agent tìm theo tên thay vì theo id.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Platform token, ưu tiên scope đọc**: chỉ thêm `document:documents:write` hoặc scope thông báo khi bạn muốn agent tạo notebook hoặc gửi tin nhắn qua Dynatrace.
- **Mỗi kết nối một token**: tạo token chỉ dành cho CloudThinker để bạn có thể thu hồi mà không làm hỏng các công cụ khác.

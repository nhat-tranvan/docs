Kết nối SonarQube để các agent CloudThinker cho bạn biết vì sao quality gate thất bại, liệt kê các issue mức blocker và high đứng sau, xem lại các security hotspot đang mở, và tìm những file có độ phủ test thấp nhất. Kết nối đăng nhập bằng một **user token** của SonarQube và chạy MCP server chính thức của SonarSource, nên hoạt động với cả SonarQube Cloud lẫn SonarQube Server tự host.

## Điều kiện tiên quyết

- Một organization SonarQube Cloud, hoặc một instance SonarQube Server hay Community Build mà CloudThinker truy cập được qua HTTPS. Với instance nội bộ, xem [Truy cập dịch vụ nội bộ](/vi/guide/connections/overview#truy-cập-dịch-vụ-nội-bộ).
- Một tài khoản SonarQube dành cho CloudThinker, có quyền **Browse** trên các project agent cần đọc (xem [Quyền yêu cầu](#quyền-yêu-cầu)).
- Vai trò **Admin** trong workspace CloudThinker, vai trò cần có để thêm kết nối. Xem [Vai trò](/vi/guide/security/roles).

## Thiết lập

<Tabs>
  <Tab title="SonarQube Cloud">
    <Steps>
      <Step title="Tạo user token">
        Đăng nhập [SonarQube Cloud](https://sonarcloud.io) bằng tài khoản CloudThinker sẽ dùng. Vào **My Account → Security**, nhập tên như `cloudthinker`, đặt ngày hết hạn, rồi nhấn **Generate Token**.

        Sao chép token. SonarQube chỉ hiển thị token một lần.
      </Step>
      <Step title="Tìm organization key">
        Mở organization của bạn. Key là phần cuối của URL: `https://sonarcloud.io/organizations/<org-key>`.
      </Step>
      <Step title="Cấp quyền Browse trên các project">
        Với mỗi project agent cần đọc, mở project, vào **Administration → Permissions**, và cấp quyền **Browse** cho tài khoản CloudThinker. Thiếu quyền này, prompt xác minh sẽ trả về kết quả rỗng.
      </Step>
      <Step title="Thêm kết nối trong CloudThinker">
        Trên thanh bên, nhấn **More → Workspace settings → Connections**, giữ nguyên tab **Builtin Connections**, rồi chọn **SonarQube**. Điền:

        - **SONARQUBE_TOKEN**: token bạn vừa sao chép
        - **SONARQUBE_DEPLOYMENT_TYPE**: **SonarQube Cloud**
        - **SONARQUBE_ORG**: organization key của bạn

        Nhấn **Connect**.

        **Trạng thái thành công:** hộp thoại **Connect SonarQube** đóng lại mà không báo lỗi. Chạy prompt xác minh bên dưới.
      </Step>
    </Steps>
  </Tab>
  <Tab title="SonarQube Server">
    <Steps>
      <Step title="Tạo user token">
        Đăng nhập instance SonarQube bằng tài khoản CloudThinker sẽ dùng. Vào **My Account → Security**, nhập tên như `cloudthinker`, chọn loại **User Token**, đặt ngày hết hạn, rồi nhấn **Generate**.

        Sao chép token. SonarQube chỉ hiển thị token một lần.
      </Step>
      <Step title="Cấp quyền Browse trên các project">
        Với mỗi project agent cần đọc, mở project, vào **Project Settings → Permissions**, và cấp quyền **Browse** cho tài khoản CloudThinker. Permission template giúp cấp quyền tương tự cho nhiều project cùng lúc. Thiếu quyền này, prompt xác minh sẽ trả về kết quả rỗng.
      </Step>
      <Step title="Thêm kết nối trong CloudThinker">
        Trên thanh bên, nhấn **More → Workspace settings → Connections**, giữ nguyên tab **Builtin Connections**, rồi chọn **SonarQube**. Điền:

        - **SONARQUBE_TOKEN**: token bạn vừa sao chép
        - **SONARQUBE_DEPLOYMENT_TYPE**: **SonarQube Server**
        - **SONARQUBE_URL**: địa chỉ instance của bạn, chẳng hạn `https://sonarqube.example.com`

        Nhấn **Connect**.

        **Trạng thái thành công:** hộp thoại **Connect SonarQube** đóng lại mà không báo lỗi. Chạy prompt xác minh bên dưới.
      </Step>
    </Steps>

## Chi tiết kết nối

Form hiển thị **SONARQUBE_ORG** hoặc **SONARQUBE_URL** tùy theo loại triển khai bạn chọn. Tùy chọn **SonarQube Cloud** kết nối tới `sonarcloud.io`. Không có trường region.

| Trường | Mô tả | Ví dụ |
|-------|-------------|---------|
| **SONARQUBE_TOKEN** | User token của tài khoản CloudThinker | `squ_...` |
| **SONARQUBE_DEPLOYMENT_TYPE** | **SonarQube Cloud** (mặc định) cho organization trên Cloud, hoặc **SonarQube Server** cho instance Server hay Community Build tự host | SonarQube Cloud |
| **SONARQUBE_ORG** | Organization key. Chỉ dùng cho Cloud | `my-org` |
| **SONARQUBE_URL** | Địa chỉ instance, dùng HTTPS. Chỉ dùng cho Server | `https://sonarqube.example.com` |

## Quyền yêu cầu

User token hoạt động với quyền của tài khoản đã tạo ra nó. Cấp quyền project cho tài khoản đó trong SonarQube, theo từng project hoặc qua permission template.

| Mục tiêu | Quyền SonarQube |
|------|----------------------|
| Đọc project, quality gate, issue, measure, độ phủ, code trùng lặp và hotspot | **Browse** |
| Đổi trạng thái issue, chẳng hạn đánh dấu false positive | **Administer Issues** |
| Review security hotspot và đặt trạng thái cho hotspot | **Administer Security Hotspots** |

<Tip>
Hãy bắt đầu chỉ với **Browse**. Với quyền này, agent đã giải thích được mọi gate và issue. Chỉ thêm hai quyền Administer trên những project mà bạn muốn agent đề xuất thay đổi trạng thái.
</Tip>

## Khả năng của agent

| Khả năng | Agent làm được gì | Phê duyệt |
|------------|--------------------|----------|
| **Khám phá** | Liệt kê project kèm trạng thái quality gate (**OK** hoặc **ERROR**) và số issue theo mức độ nghiêm trọng | Không |
| **Quality gate** | Kiểm tra trạng thái gate của một project hoặc pull request, và các điều kiện bị trượt | Không |
| **Issue** | Tìm issue theo project, pull request, mức độ nghiêm trọng và trạng thái, đồng thời hiển thị rule đứng sau issue kèm hướng dẫn sửa | Không |
| **Security hotspot** | Liệt kê hotspot cần review và hiển thị đoạn code cùng rủi ro của từng hotspot | Không |
| **Measure, độ phủ và code trùng lặp** | Đọc số dòng code, độ phủ, bug, lỗ hổng, code smell và số dòng trùng lặp, và tìm các file dưới ngưỡng độ phủ | Không |
| **Đổi trạng thái** | Đổi trạng thái issue hoặc review một hotspot | Qua Approvals |

Tên mức độ nghiêm trọng tuân theo chế độ của instance. Chế độ Multi-Quality Rule báo **BLOCKER**, **HIGH**, **MEDIUM**, **LOW** và **INFO**. Chế độ Standard Experience báo **BLOCKER**, **CRITICAL**, **MAJOR**, **MINOR** và **INFO**.

<ApprovalDefault />

Yêu cầu bị từ chối sẽ không được thử lại. Để tự quyết định từng thay đổi trạng thái, chẳng hạn đánh dấu một issue là false positive, hãy chọn **Manual** để người duyệt phê duyệt mọi thay đổi. Khi CloudThinker bật [Rule enforcement](/vi/guide/approvals/rules#khắc-phục-sự-cố) cho workspace của bạn, một [Rule](/vi/guide/approvals/rules) **Ask first** có thể thu hẹp việc này về riêng kết nối SonarQube. Một số tool phụ thuộc vào phiên bản SonarQube: dependency risk cần giấy phép Advanced Security, còn các tool kiểm tra tình trạng hệ thống chỉ hoạt động trên SonarQube Server.

Agent báo cáo số liệu của từng project như hiện tại. SonarQube trả về measure hiện hành, nên agent sẽ không khẳng định xu hướng nào trừ khi bạn yêu cầu so sánh các branch hoặc pull request.

### Xác minh kết nối

```text
List my SonarQube projects with their quality gate status and issue counts by severity
```

Kết quả mong đợi là một bảng gồm key và tên project, trạng thái gate **OK** hoặc **ERROR** cho từng project, và số issue theo mức độ nghiêm trọng, chẳng hạn **BLOCKER**.

### Ví dụ prompt

```text
Why did the quality gate fail on payments-api? List the failed conditions and the blocker issues behind them
Show the security hotspots still to review in payments-api, highest risk first
Which files in payments-api have under 50% coverage?
```

Hãy dùng đúng project key thật. Agent tra key từ danh sách project và không đoán key.

## Khắc phục sự cố

<Accordion title="Request trả về 401">
Token sai, đã hết hạn hoặc bị thu hồi. Tạo user token mới, sửa kết nối và dán token vào **SONARQUBE_TOKEN**.
</Accordion>

<Accordion title="Kết nối tới SonarQube Server thất bại">
CloudThinker không truy cập được **SONARQUBE_URL**. Kiểm tra địa chỉ dùng HTTPS và truy cập được từ internet, không phải `localhost` hay hostname nội bộ, và service SonarQube đang chạy.
</Accordion>

<Accordion title="Không có project nào được trả về (Cloud)">
**SONARQUBE_ORG** sai, hoặc tài khoản của token không phải thành viên của organization đó. Sao chép key từ URL của organization và xác nhận tư cách thành viên.
</Accordion>

<Accordion title="Thiếu một số project">
Tài khoản của token thiếu quyền **Browse** trên các project đó. Cấp quyền **Browse** trên các project này trong SonarQube. Không cần kết nối lại; quyền có hiệu lực từ request tiếp theo.
</Accordion>

<Accordion title="Đổi trạng thái trả về 403">
Tài khoản thiếu quyền **Administer Issues** hoặc **Administer Security Hotspots** trên project đó. Cấp quyền trong SonarQube, rồi yêu cầu lại.
</Accordion>

<Accordion title="Không có dependency risk hoặc tình trạng hệ thống">
Phiên bản của bạn không có các tool đó. Dependency risk cần giấy phép Advanced Security, còn các tool kiểm tra tình trạng hệ thống chỉ có trên SonarQube Server.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Dùng user token**: trên SonarQube Server, chọn loại **User Token**, không chọn Global Analysis Token, để quyền truy cập tuân theo quyền project của một tài khoản.
- **Đặt ngày hết hạn**: đặt ngày hết hạn cho token và xoay vòng trước khi token hết hạn.

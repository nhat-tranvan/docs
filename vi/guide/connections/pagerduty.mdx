Kết nối tài khoản PagerDuty của bạn để cho phép các agent CloudThinker quản lý sự cố, xem lịch on-call, giám sát dịch vụ và xử lý chính sách leo thang. PagerDuty xác thực bằng **User API Token** được giới hạn phạm vi theo quyền của người dùng tạo ra nó.

---

## Nền tảng được hỗ trợ

| Nền tảng | Hỗ trợ |
|----------|---------|
| **PagerDuty** | Tất cả gói (Free, Professional, Business, Digital Operations) |

---

## Điều kiện tiên quyết

- Một **tài khoản PagerDuty** trên bất kỳ gói nào.
- Một **User API Token** từ **My Profile → User Settings → API Access**.

<Info>
Sử dụng **User API Token**, không phải General Access REST API Key. Token người dùng giới hạn quyền truy cập theo những gì người dùng có thể thấy, tạo ra ranh giới bảo mật tốt hơn.
</Info>

---

## Thiết lập

<Steps>
  <Step title="Mở PagerDuty">
    Đăng nhập vào tài khoản PagerDuty của bạn tại [app.pagerduty.com](https://app.pagerduty.com).
  </Step>
  <Step title="Tạo User API Key">
    Nhấp vào **User Icon → My Profile**, sau đó cuộn xuống **User Settings → API Access** và nhấp **Create API User Token**:
    - **Description**: `cloudthinker`
    - Nhấp **Create Key**

    Sao chép khóa ngay lập tức — sẽ không được hiển thị lại.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Điều hướng đến **Connections → PagerDuty** và nhập:
    - **User API Key**: token bạn vừa tạo

    Nhấp **Connect**. CloudThinker xác minh thông tin xác thực và hiển thị trạng thái **Connected**.
  </Step>
</Steps>

<Warning>
Sao chép API token ngay sau khi tạo. PagerDuty sẽ không hiển thị lại, và bạn cần tạo token mới nếu bị mất.
</Warning>

## Quyền hạn cần thiết

### Tối thiểu (chỉ đọc)

Người dùng có vai trò **Observer** hoặc **Responder** cung cấp:
- Xem sự cố, dịch vụ và chính sách leo thang
- Xem lịch on-call
- Xem team và người dùng

### Khuyến nghị (toàn bộ thao tác)

Người dùng có vai trò **Responder** hoặc **Manager** cung cấp:
- Tất cả quyền đọc
- Xác nhận và giải quyết sự cố
- Tạo sự cố và cập nhật trạng thái
- Quản lý on-call override

<Tip>
Tuân thủ nguyên tắc đặc quyền tối thiểu: chỉ định vai trò Observer để giám sát chỉ đọc. Nâng lên Responder hoặc Manager chỉ khi cần thao tác ghi trên sự cố.
</Tip>

## Khả năng của agent

Sau khi kết nối, các agent có thể truy vấn và hành động trên dữ liệu PagerDuty.

| Khả năng | Mô tả |
|------------|-------------|
| **Phân loại sự cố** | Liệt kê các sự cố đã kích hoạt và được xác nhận, xác định các mẫu |
| **Lịch on-call** | Xem ai đang on-call và lịch luân phiên sắp tới |
| **Sức khỏe dịch vụ** | Giám sát trạng thái dịch vụ và số lượng sự cố đang hoạt động |
| **Chính sách leo thang** | Xem chuỗi leo thang và quy tắc thông báo |
| **Hành động sự cố** | Xác nhận, giải quyết và thêm ghi chú vào sự cố |
| **Quản lý lịch** | Xem lịch và xác định các khoảng trống trong lịch trực |

## Xử lý sự cố

<Accordion title="Xác thực thất bại">
Token không chính xác, đã hết hạn hoặc bị thu hồi. Xác minh User API Token, đảm bảo bạn đang sử dụng **User Token** (không phải REST API Key) và tạo token mới nếu cần.
</Accordion>

<Accordion title="Quyền truy cập bị từ chối">
Người dùng có quyền vai trò không đủ hoặc hạn chế quyền truy cập ở cấp team. Đối với các thao tác ghi, đảm bảo người dùng có vai trò Responder hoặc Manager.
</Accordion>

<Accordion title="Thiếu dịch vụ hoặc sự cố">
Người dùng không có quyền truy cập vào các team liên quan. Xác minh tư cách thành viên team bao gồm các dịch vụ bạn muốn giám sát.
</Accordion>

<Accordion title="Token bị thu hồi">
Điều hướng đến **My Profile → User Settings** trong PagerDuty, tạo API User Token mới và cập nhật token trong cài đặt kết nối CloudThinker.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **User token** — sử dụng User API Token được giới hạn phạm vi cho người dùng PagerDuty chuyên dụng thay vì General Access REST API Key.
- **Giới hạn theo team** — hạn chế tư cách thành viên team của người dùng chuyên dụng chỉ đến các dịch vụ CloudThinker cần giám sát.

Kết nối Buildkite để các agent CloudThinker đo sức khỏe pipeline, tìm nguyên nhân build lỗi từ log và annotation, và kiểm tra năng lực của agent Buildkite. Kết nối dùng API access token của Buildkite, và các scope bạn cấp cho token là giới hạn cứng cho những gì agent làm được.

## Điều kiện tiên quyết

- Tài khoản Buildkite có quyền truy cập tổ chức bạn muốn agent giám sát.
- Quyền tạo API access token cho tổ chức đó.

## Thiết lập

<Steps>
  <Step title="Tạo API access token">
    Trong Buildkite, vào **Personal Settings → API Access Tokens → New API Access Token** ([buildkite.com/user/api-access-tokens/new](https://buildkite.com/user/api-access-tokens/new)) và đặt:
    - **Description**: `cloudthinker`
    - **Organization access**: tổ chức mà CloudThinker cần truy cập
    - **REST API scopes**: `read_organizations`, `read_pipelines`, `read_builds`, `read_build_logs`, `read_artifacts`, `read_agents`, `read_clusters` và `read_user`. Chỉ thêm `write_builds` nếu bạn muốn agent retry, unblock, rebuild hoặc cancel.

    Sao chép token ngay. Buildkite chỉ hiện token một lần.
  </Step>
  <Step title="Thêm kết nối">
    Mở **More → Workspace settings → Connections**, giữ nguyên tab **Builtin Connections**, rồi chọn **Buildkite**. Dán token vào **BUILDKITE_API_TOKEN** và nhấn **Connect**.

    **Trạng thái thành công:** hộp thoại đóng lại và kết nối hiện **Connected**.
  </Step>
  <Step title="Xác nhận token hoạt động">
    Chạy prompt trong [Xác minh kết nối](#xác-minh-kết-nối). Buildkite chấp nhận kết nối kể cả khi token sai và chỉ từ chối khi agent gọi lần đầu, nên trạng thái **Connected** chưa đủ để chứng minh token hợp lệ.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Mô tả |
|-------|-------------|
| **BUILDKITE_API_TOKEN** | API access token của Buildkite. Các scope của token quyết định thao tác nào thành công |

Bạn không cần nhập organization slug. Agent tự xác định slug từ token. CloudThinker gửi token tới máy chủ MCP do Buildkite vận hành tại `https://mcp.buildkite.com/direct`, máy chủ này chuyển token tới REST API của Buildkite. Buildkite vận hành máy chủ đó, không phải CloudThinker.

## Quyền yêu cầu

| Scope | Bắt buộc | Cho phép |
|-------|----------|---------|
| `read_organizations` | Có | Xác định tổ chức mà token truy cập được |
| `read_pipelines` | Có | Danh sách và chi tiết pipeline |
| `read_builds` | Có | Build, job, annotation và tóm tắt lỗi |
| `read_build_logs` | Có | Đọc, tìm kiếm và theo dõi log của job |
| `read_artifacts` | Có | Artifact của build và job |
| `read_agents` | Có | Trạng thái kết nối và năng lực của agent Buildkite |
| `read_clusters` | Có | Cluster và cluster queue |
| `read_user` | Có | Tra cứu user sở hữu token |
| `write_builds` | Không | Retry job, unblock job, rebuild và cancel |

<Tip>
Bỏ `write_builds` nếu kết nối chỉ dùng để giám sát. Agent vẫn đọc được mọi thứ, và chính Buildkite từ chối mọi thay đổi, nên bạn không phải trông cậy hoàn toàn vào phê duyệt.
</Tip>

## Khả năng của agent

| Khả năng | Agent làm được gì |
|------------|--------------------|
| **Khám phá** | Liệt kê pipeline, build gần đây, agent Buildkite và cluster trong tổ chức |
| **Sức khỏe pipeline** | Báo tỷ lệ pass, chuỗi lỗi liên tiếp, và build bị kẹt lâu hơn ngưỡng bạn nêu trong prompt, chẳng hạn "stuck for more than 30 minutes" |
| **Phân tích build lỗi** | Đối chiếu tóm tắt lỗi của Buildkite với log job, annotation và test lỗi |
| **Log và artifact** | Đọc, tìm kiếm và theo dõi log của job; liệt kê và tải artifact của build và job |
| **Năng lực** | Hiện trạng thái kết nối của agent Buildkite, cluster và cluster queue |
| **Điều khiển build** | Retry job, unblock job, rebuild build, cancel build. **Mỗi thao tác đều đi qua Approvals** |

Build đang chờ một block step thủ công được Buildkite API báo là `passed`. Agent kiểm tra cổng này, nêu tên block step, và không tính build đó vào tỷ lệ pass, nên một lần deploy đang bị giữ không bao giờ hiện thành pipeline xanh. Trước khi unblock, agent trích nhãn của block step và annotation của build để bạn biết mình đang mở cổng nào.

Agent không tạo hoặc sửa được pipeline, cluster, queue hay lịch chạy, và không đọc biến môi trường của job. Dữ liệu Buildkite Test Engine không có trong kết nối này.

<ApprovalDefault />

Để luôn được hỏi, chọn **Manual** làm [Approval mode](/vi/guide/approvals/approval-mode), khi đó mọi thay đổi đều cần một người phê duyệt. Khi CloudThinker đã bật [Rule enforcement](/vi/guide/approvals/rules#khắc-phục-sự-cố) cho workspace của bạn, một [Rule](/vi/guide/approvals/rules) **Ask first** có thể thu hẹp yêu cầu đó về riêng kết nối này.

### Xác minh kết nối

```text
List my Buildkite pipelines and show the latest build status for each
```

Kết quả mong đợi là từng pipeline theo slug, kèm trạng thái của build mới nhất. Lỗi 401 ở bước này nghĩa là token không hợp lệ, dù kết nối hiện **Connected**.

### Ví dụ prompt

```text
Which Buildkite pipelines are failing right now, and how long is each failure streak?
Build 42 of the web pipeline failed. Pull the logs and annotations and tell me the cause
Show Buildkite agent capacity and any builds stuck for more than an hour
```

## Khắc phục sự cố

<Accordion title="Đã Connected nhưng mọi request đều trả về 401">
Token không hợp lệ, đã hết hạn hoặc đã bị thu hồi. Tạo API access token mới và cập nhật **BUILDKITE_API_TOKEN** trên kết nối.
</Accordion>

<Accordion title="Lỗi 403 khi đọc">
Token thiếu một scope đọc. Đối chiếu với [Quyền yêu cầu](#quyền-yêu-cầu) và sửa scope của token trong Buildkite. Bạn không cần tạo token mới.
</Accordion>

<Accordion title="Retry, unblock, rebuild hoặc cancel báo lỗi quyền">
Token không có `write_builds`. Thêm scope này trong Buildkite, hoặc giữ kết nối ở chế độ chỉ đọc và tự thực hiện thao tác trong Buildkite.
</Accordion>

<Accordion title="Trạng thái cổng hiện là unknown">
Bước kiểm tra block step thủ công bị lỗi, thường do giới hạn tốc độ. Agent coi build là chưa xong và không tính vào tỷ lệ pass. Unknown không bao giờ có nghĩa là không có cổng. Hỏi lại sau một phút.
</Accordion>

<Accordion title="Lỗi 404 với pipeline có tồn tại">
Tên pipeline đã được dùng ở chỗ Buildkite cần slug. Yêu cầu agent liệt kê pipeline và dùng slug trong danh sách đó.
</Accordion>

<Accordion title="429 rate limited">
Request bao quá nhiều pipeline hoặc build. Thu hẹp câu hỏi về một pipeline, hoặc yêu cầu ít build gần đây hơn.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Giới hạn scope của token, không chỉ dựa vào phê duyệt**: Buildkite thực thi scope của token. Token không có `write_builds` hoàn toàn không thay đổi được trạng thái CI.
- **Coi unblock là một lần phát hành**: block step thường là cổng deploy mà ai đó cố ý thêm vào. Chỉ phê duyệt unblock sau khi đọc nhãn mà agent trích ra.

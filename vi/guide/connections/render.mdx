Kết nối Render để CloudThinker có thể giải thích vì sao một deploy thất bại, đọc log build và runtime, kiểm tra số liệu service, và xem xét các instance Render Postgres và Key Value của bạn. Kết nối dùng Render API key, và mọi thao tác thay đổi service của bạn (deploy, cập nhật biến môi trường, tạo tài nguyên mới) đều phải qua Approvals của workspace trước.

---

## Điều kiện tiên quyết

- Một tài khoản Render thấy được workspace bạn muốn CloudThinker điều tra.
- Quyền tạo API key trên tài khoản đó.
- Một workspace CloudThinker nơi bạn có thể thêm kết nối.

---

## Thiết lập

<Steps>
  <Step title="Tạo Render API key">
    Trong Render Dashboard, mở **Account Settings → API Keys** ([liên kết trực tiếp](https://dashboard.render.com/u/settings#api-keys)) và tạo một key tên `cloudthinker`.

    Sao chép key ngay. Render chỉ hiển thị giá trị đầy đủ một lần.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Trên thanh bên, nhấn **More → Workspace settings → Connections**. Ở tab **Builtin Connections**, tìm **Render**, dán key vào **RENDER_API_KEY** và nhấn **Connect**.

    **Trạng thái thành công:** thẻ Render hiển thị trạng thái **Connected**.
  </Step>
  <Step title="Chạy prompt xác minh">
    Gửi prompt trong [Xác minh kết nối](#xác-minh-kết-nối) ở một chat mới. Đừng bỏ qua bước này: Render vẫn chấp nhận bước bắt tay kết nối kể cả khi key sai, nên key sai chỉ lộ ra khi yêu cầu đầu tiên chạy.

    **Trạng thái thành công:** CloudThinker liệt kê các workspace và service Render của bạn theo tên.
  </Step>
</Steps>

---

## Chi tiết kết nối

| Trường | Giá trị cần nhập |
|-------|---------------|
| **RENDER_API_KEY** | API key từ **Account Settings → API Keys** trong Render Dashboard |

---

## Quyền yêu cầu

Render API key không có scope. Key hoạt động với tư cách tài khoản đã tạo ra key và truy cập mọi workspace và service mà tài khoản đó thấy được.

<Tip>
Để đảm bảo quyền tối thiểu, hãy tạo key từ một tài khoản chỉ thuộc workspace mà CloudThinker cần điều tra, không phải từ tài khoản owner thấy mọi thứ bạn host.
</Tip>

## Khả năng của agent

| Khả năng | CloudThinker làm gì | Qua Approvals kiểm tra |
|------------|------------------------|----------------|
| **Kiểm kê service** | Liệt kê workspace, service, URL và gói | Không |
| **Lịch sử deploy** | Đọc deploy theo từng service và chỉ ra các build thất bại hoặc bị kẹt | Không |
| **Log** | Đọc log build, runtime và request, và nhóm lỗi theo thông báo. Chỉ thấy những log Render còn lưu giữ, tùy theo gói của bạn ([tài liệu logging của Render](https://render.com/docs/logging)). | Không |
| **Số liệu** | Đọc CPU, bộ nhớ, số instance và độ trễ HTTP của một service | Không |
| **Datastore** | Xem xét các instance Render Postgres và Key Value | Không |
| **Truy vấn Postgres** | Chạy SQL chỉ đọc có giới hạn trên Render Postgres và hiển thị SQL cho bạn trước | Không |
| **Deploy** | Kích hoạt deploy một service | Có |
| **Biến môi trường** | Cập nhật biến môi trường của một service, hiển thị toàn bộ tập kết quả trước khi bạn phê duyệt | Có |
| **Tài nguyên mới** | Tạo web service, static site, cron job, instance Postgres hoặc instance Key Value | Có |

<ApprovalDefault />

<Note>
Truy vấn Postgres chạy ở phía Render: Render host server mà CloudThinker gọi (một MCP server, cách tiêu chuẩn để AI agent gọi các công cụ của một dịch vụ), và chạy SQL bằng API key của bạn. CloudThinker không bao giờ giữ thông tin xác thực cơ sở dữ liệu. Vì truy vấn là thao tác đọc, không Rule nào có thể tắt được. Để CloudThinker không chạm tới một cơ sở dữ liệu, hãy tạo key từ tài khoản không thấy cơ sở dữ liệu đó.
</Note>

<Warning>
Deploy đưa mã ra phục vụ lưu lượng thật, và cập nhật biến môi trường có thể khởi động lại service. Đọc thay đổi được đề xuất trong yêu cầu [phê duyệt](/vi/guide/approvals/overview) trước khi chấp nhận. Yêu cầu thay đổi biến môi trường liệt kê toàn bộ tập kết quả, bao gồm cả giá trị, nên hãy coi cuộc chat đó là nhạy cảm.
</Warning>

### Xác minh kết nối

```text
List my Render workspaces and services with their current status
```

### Ví dụ prompt

```text
Why did the last deploy of my api service on Render fail? Quote the build log lines that matter.
Show CPU, memory, and HTTP latency for my Render web services over the last 24 hours
List my Render Postgres instances with their plans and status
```

## Khắc phục sự cố

<Accordion title="Đã kết nối, nhưng prompt đầu tiên trả về 401">
Key sai hoặc đã bị thu hồi. Bước bắt tay của Render vẫn thành công khi key không hợp lệ, nên lỗi xuất hiện ở yêu cầu đầu tiên. Tạo key mới trong **Account Settings → API Keys**. Sau đó mở kết nối, nhấn biểu tượng chỉnh sửa trên instance, nhấn **Replace…** trong **Edit Instance**, dán key và nhấn **Save and test**.
</Accordion>

<Accordion title="403, hoặc thiếu các service dự kiến">
Tài khoản của key không phải thành viên của workspace đó. Yêu cầu CloudThinker liệt kê các workspace Render để xem key truy cập được những gì, rồi tạo key từ tài khoản thuộc đúng workspace.
</Accordion>

<Accordion title="404 cho một service hoặc cơ sở dữ liệu">
Service hoặc cơ sở dữ liệu đã bị đổi tên hoặc xóa, hoặc tên không khớp. Yêu cầu CloudThinker liệt kê các service Render, rồi gọi service theo tên trong danh sách đó.
</Accordion>

<Accordion title="429 rate limit">
Render đang giới hạn tốc độ yêu cầu. Đợi một phút và thử lại với yêu cầu hẹp hơn, chẳng hạn một service hoặc khoảng thời gian log ngắn hơn.
</Accordion>

<Accordion title="Deploy hoặc thay đổi không diễn ra">
Deploy, cập nhật biến môi trường và tài nguyên mới đi qua Approvals, và một số chờ người duyệt. Kiểm tra chat xem có yêu cầu phê duyệt đang chờ không và trả lời trước khi yêu cầu lại.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Key chỉ hiển thị một lần:** Render chỉ hiển thị đầy đủ API key khi tạo, nên hãy lưu vào trình quản lý mật khẩu trước khi rời trang.
- **Đặt lịch xoay vòng:** Render API key không hết hạn, nên hãy thay key theo lịch cố định và thu hồi key cũ.
- **Phạm vi toàn tài khoản:** vì key truy cập mọi workspace mà tài khoản tạo key thấy được, hãy thu hồi key trong Render (**Account Settings → API Keys**, rồi xóa key) ngay khi bạn xóa kết nối.

Kết nối ClickHouse để CloudThinker liệt kê database và bảng, kiểm tra số part và kích thước bảng, xếp hạng truy vấn chậm từ `system.query_log`, và trả lời câu hỏi bằng SQL phân tích. CloudThinker đăng nhập bằng một user ClickHouse qua HTTP interface, và kết nối mới luôn ở chế độ chỉ đọc.

<Warning>
Approvals không áp dụng cho ClickHouse. Nếu bạn đặt **Write access** thành **Full access**, thao tác ghi sẽ chạy mà không hỏi ai. Xem [Quyền ghi](#quyền-ghi).
</Warning>

---

## Điều kiện tiên quyết

- Server ClickHouse mà CloudThinker truy cập được qua **HTTP interface**: `8443` có TLS, `8123` không TLS. Cả ClickHouse Cloud và cluster tự host đều dùng được. Cổng TCP native (`9000`) không được dùng.
- Tài khoản admin trên ClickHouse để tạo user riêng. Trên ClickHouse Cloud, chạy đoạn SQL ở phần Thiết lập trong **SQL console** của service bằng user `default`.
- Vai trò workspace Admin trong CloudThinker để thêm kết nối. Xem [Cách hoạt động của quyền truy cập](/vi/guide/connections/overview#cách-quyền-truy-cập-hoạt-động).

## Thiết lập

<Steps>
  <Step title="Tạo user riêng với quyền đọc">
    Kết nối bằng tài khoản admin và chạy:
    ```sql
    CREATE USER cloudthinker IDENTIFIED BY 'your-secure-password';
    GRANT SELECT ON your_database.* TO cloudthinker;
    GRANT SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT SELECT ON system.tables TO cloudthinker;
    GRANT SELECT ON system.columns TO cloudthinker;
    GRANT SELECT ON system.parts TO cloudthinker;
    GRANT SELECT ON system.query_log TO cloudthinker;
    ```
    Trên ClickHouse Cloud, mật khẩu phải đáp ứng quy tắc độ phức tạp của service (độ dài, chữ hoa và chữ thường, một chữ số và một ký tự đặc biệt), nếu không `CREATE USER` sẽ thất bại.

    Các grant `system.*` phục vụ câu trả lời về sức khỏe bảng và truy vấn chậm. Bỏ qua chúng thì các câu hỏi đó thất bại, còn câu hỏi về schema vẫn chạy.

    <Warning>
    `system.query_log` chứa toàn văn truy vấn của mọi user, kể cả giá trị literal trong mệnh đề `WHERE`, vốn có thể chứa dữ liệu cá nhân. Cấp grant này cho phép agent đọc các truy vấn đó và trích dẫn chúng trong chat. Nếu bạn lo ngại, hãy bỏ grant này: khi đó câu trả lời về truy vấn chậm sẽ thất bại.
    </Warning>

    Trên cluster tự host có nhiều node, user tạo theo cách này chỉ tồn tại trên node bạn chạy lệnh, trừ khi cluster replicate access storage. Hãy chạy phiên bản sau, kèm tên cluster của bạn:
    ```sql
    CREATE USER cloudthinker ON CLUSTER '<cluster>' IDENTIFIED BY 'your-secure-password';
    GRANT ON CLUSTER '<cluster>' SELECT ON your_database.* TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.tables TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.columns TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.parts TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.query_log TO cloudthinker;
    ```
    Kiểm tra user có trên mọi node bằng `SELECT name FROM clusterAllReplicas('<cluster>', system.users) WHERE name = 'cloudthinker'`.
  </Step>
  <Step title="Khóa user ở chế độ chỉ đọc phía server (khuyến nghị)">
    Bỏ qua bước này nếu bạn định bật **Write access**. Nếu không, hãy thêm một settings profile để chính ClickHouse từ chối thao tác ghi, bất kể client nào yêu cầu:
    ```sql
    CREATE SETTINGS PROFILE cloudthinker_readonly SETTINGS readonly = 1 READONLY;
    ALTER USER cloudthinker SETTINGS PROFILE cloudthinker_readonly;
    ```
    Profile này không làm hỏng CloudThinker. Thao tác đọc chạy bình thường, và chính ClickHouse từ chối mọi thao tác ghi.
  </Step>
  <Step title="Mở truy cập mạng">
    Tài liệu này không công bố danh sách IP egress của CloudThinker: hãy hỏi đầu mối CloudThinker của bạn, hoặc [liên hệ chúng tôi](https://cloudthinker.io/contact). Sau đó:
    - **ClickHouse Cloud**: thêm các IP đó vào IP access list của service tại **Settings → Security** của service.
    - **Tự host**: cho phép inbound `8443` (hoặc `8123`) từ các IP đó trong firewall hoặc security group.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Vào **More → Workspace settings → Connections**, chọn **ClickHouse**, điền các trường trong [Chi tiết kết nối](#chi-tiết-kết-nối), giữ **Write access** ở **Read-only (default)**, rồi nhấn **Connect**.

    CloudThinker chạy một lệnh `SELECT version()` bằng user đó.

    **Trạng thái thành công:** ClickHouse hiển thị trạng thái **Connected**, và thông báo ghi `ClickHouse <version> reachable as cloudthinker`.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Bắt buộc | Mô tả | Mặc định |
|-------|----------|-------------|---------|
| **Host** | Có | Chỉ hostname, không có `https://` và không có port. Với ClickHouse Cloud có dạng `abc123.ap-southeast-1.aws.clickhouse.cloud` | |
| **Port** | Có | Cổng HTTP interface: `8443` có TLS, `8123` không TLS | `8443` |
| **Username** | Có | User riêng, ví dụ `cloudthinker` | |
| **Password** | Có | Mật khẩu của user đó | |
| **Use TLS** | Không | Dùng HTTPS thay vì HTTP thường. Tùy chọn: **Yes**, **No** | **Yes** |
| **Verify the TLS certificate** | Không | Chỉ đặt **No** khi chứng chỉ là self-signed hoặc do CA nội bộ cấp. Chỉ hiển thị khi TLS bật. Tùy chọn: **Yes (default)**, **No** | **Yes (default)** |
| **Default database** | Không | Database được dùng khi truy vấn không chỉ định database. Để trống thì dùng mặc định của server | Trống |
| **Write access** | Không | CloudThinker có được ghi hay không. Tùy chọn: **Read-only (default)**, **Full access** | **Read-only (default)** |
| **Allow DROP and TRUNCATE** | Không | Chỉ hiển thị khi chọn **Full access**. Tùy chọn: **Blocked (default)**, **Allowed** | **Blocked (default)** |

<Tip>
Đổi **Port** và **Use TLS** cùng lúc. `8443` đi với TLS bật, `8123` đi với TLS tắt. Nếu không khớp, kết nối thất bại ngay khi connect.
</Tip>

## Quyền yêu cầu

Các grant ở phần Thiết lập đã đủ cho mọi thao tác chỉ đọc. Chỉ thêm grant ghi nếu bạn đặt **Write access** thành **Full access**, và chỉ trên những database mà agent được phép thay đổi:

```sql
-- ALTER includes ALTER ... DELETE, DROP PARTITION, and DROP COLUMN, which remove data.
-- See "Blocked protects the table, not the rows" under Write access.
GRANT INSERT, ALTER, CREATE TABLE, CREATE VIEW ON your_database.* TO cloudthinker;
-- Only if the agent should remove tables:
GRANT DROP TABLE, TRUNCATE ON your_database.* TO cloudthinker;
```

<Tip>
Không bao giờ cấp quyền ghi trên `*.*`. Grant của ClickHouse mới là ranh giới thực sự: trường **Write access** chỉ quyết định CloudThinker có gửi `readonly=1` hay không, và không thể trao cho user một đặc quyền mà ClickHouse chưa cấp.
</Tip>

## Khả năng của agent

| Khả năng | Mô tả |
|------------|-------------|
| **Khám phá schema** | Liệt kê database và bảng kèm engine, sorting key, số dòng và kiểu cột |
| **Truy vấn phân tích** | Chạy SQL với aggregate, join và window function |
| **Sức khỏe bảng** | Kiểm tra số part, kích thước nén và chưa nén, và index granularity từ `system.parts` |
| **Điều tra truy vấn** | Xếp hạng truy vấn chậm hoặc tốn kém từ `system.query_log` |
| **Thay đổi** | Chỉ khi có **Full access**: chèn dòng, alter bảng, tạo bảng và view |

`system.query_log` và `system.parts` được lưu riêng trên từng node. Trên cluster có nhiều replica, câu trả lời chỉ bao gồm node đã nhận truy vấn. Để bao gồm mọi node, hãy yêu cầu rõ trong prompt:

- **Tự host**: "use `clusterAllReplicas('<cluster>', system.query_log)`"
- **ClickHouse Cloud**: "use `clusterAllReplicas('default', system.query_log)`"

### Xác minh kết nối

```text
List the ClickHouse databases and the tables in each one
```

**Trạng thái thành công:** CloudThinker trả về các database cùng bảng, engine và số dòng của chúng.

### Ví dụ prompt

```text
Which ClickHouse tables are the largest by compressed size, and how many parts does each have?
Show the 10 slowest queries from system.query_log in the last 24 hours, with the user and table for each
Suggest a better sorting key for our largest MergeTree table, based on the queries that hit it
```

## Quyền ghi

| Write access | Allow DROP and TRUNCATE | Agent làm được gì |
|--------------|-------------------------|------------------------|
| **Read-only (default)** | Ẩn | Chỉ `SELECT`. ClickHouse từ chối mọi thứ khác với lỗi `164` (`READONLY`) |
| **Full access** | **Blocked (default)** | `INSERT`, `ALTER` và `CREATE`, không qua bước phê duyệt. `DROP TABLE` và `TRUNCATE` bị từ chối |
| **Full access** | **Allowed** | Mọi thứ ở trên, thêm `DROP TABLE` và `TRUNCATE`. `DROP DATABASE` cũng chạy nếu user có grant đó, vốn không nằm trong phần Quyền yêu cầu |

Trước khi chọn **Full access**:

- **Blocked bảo vệ bảng, không bảo vệ dữ liệu trong bảng.** `ALTER TABLE ... DELETE`, `DROP PARTITION` và `DROP COLUMN` vẫn chạy và vẫn xóa dữ liệu. Hãy coi **Full access** là "agent có thể phá hủy dữ liệu".
- **Không có gì rollback được.** ClickHouse không có transaction, nên khôi phục đồng nghĩa với restore từ bản backup.

**Write access** bị khóa sau khi bạn kết nối. Trong **Edit Instance**, **Replace…** mở các trường đã lưu để sửa, nhưng **Write access** vẫn bị mờ với dòng "To change this, disconnect and connect again." Để đổi, hãy [ngắt kết nối](/vi/guide/connections/overview#ngắt-kết-nối) ClickHouse, rồi thêm lại với **Write access** mới.

Khi **Full access** đang bật, bạn vẫn có thể đổi **Allow DROP and TRUNCATE** tại chỗ: mở **More → Workspace settings → Connections**, chọn **ClickHouse**, nhấn biểu tượng bút chì trên dòng của instance, rồi trong **Edit Instance** nhấn **Replace…**, chọn tùy chọn, để trống **Password** để giữ mật khẩu đã lưu, và nhấn **Save and test**. Nếu kiểm tra thất bại, kết nối giữ nguyên cài đặt trước đó.

Nếu bạn đã áp dụng profile `READONLY` ở bước 2 phần Thiết lập, hãy gỡ profile trước, nếu không ClickHouse vẫn tiếp tục từ chối thao tác ghi:

```sql
ALTER USER cloudthinker SETTINGS PROFILE default;
DROP SETTINGS PROFILE cloudthinker_readonly;
```

Vì sao Approvals không áp dụng: ClickHouse chạy mọi truy vấn qua một công cụ duy nhất, nên CloudThinker không thể hỏi riêng về thao tác ghi tách khỏi thao tác đọc. Rules và Approval mode không bao giờ thấy thao tác ghi vào ClickHouse. Hãy thử **Full access** trên cluster staging trước khi dùng cho cluster mà các dashboard của bạn đang đọc.

## Xoay vòng mật khẩu

1. Đặt mật khẩu mới cho user ClickHouse:
   ```sql
   ALTER USER cloudthinker IDENTIFIED BY 'new-secure-password';
   ```
   Mật khẩu cũ ngừng hoạt động ngay lập tức, nên truy vấn của CloudThinker sẽ thất bại cho tới khi bạn làm xong bước 2. Hãy làm cả hai bước liền nhau.
2. Mở **More → Workspace settings → Connections**, chọn **ClickHouse**, nhấn biểu tượng bút chì trên dòng của instance, rồi trong **Edit Instance** nhấn **Replace…**. Nhập **Password** mới và nhấn **Save and test**.

**Trạng thái thành công:** kiểm tra thành công và kết nối vẫn ở trạng thái **Connected**. Nếu kiểm tra thất bại, CloudThinker giữ cài đặt trước đó và hiển thị lỗi.

## Khắc phục sự cố

Bốn tiêu đề đầu tiên khớp với thông báo của bước kiểm tra kết nối, nên bạn có thể tìm đúng thông báo mình gặp trên trang này. Tiêu đề thứ năm là thông báo lỗi của chính ClickHouse, và tiêu đề thứ sáu là triệu chứng bạn thấy trong chat.

<Accordion title="ClickHouse rejected the username or password">
Kiểm tra user tồn tại bằng `SHOW USERS;`, rồi gõ lại mật khẩu thay vì dán. Giá trị có ký tự xuống dòng bị từ chối trước khi CloudThinker liên hệ server. Trên ClickHouse Cloud, hãy tạo một database user thay vì dùng lại tài khoản đăng nhập console.
</Accordion>

<Accordion title="ClickHouse is unreachable, or rejected the request path">
- **Port** và **Use TLS** phải khớp nhau: `8443` có TLS, `8123` không TLS. `9000` là cổng TCP native, không phải HTTP interface.
- **Host** không được có tiền tố `https://` hay hậu tố `:port`.
- Trên ClickHouse Cloud, thêm IP egress của CloudThinker vào IP access list của service. Với bản tự host, kiểm tra firewall và đảm bảo `<listen_host>` bao gồm interface được mở.
</Accordion>

<Accordion title="ClickHouse did not answer in time">
Trên ClickHouse Cloud, service nhàn rỗi sẽ bị tạm dừng và kết nối bị timeout cho tới khi service hoạt động lại. Đánh thức service trong ClickHouse Cloud console, rồi kết nối lại.
</Accordion>

<Accordion title="ClickHouse has no database named ...">
**Default database** không tồn tại. Tên phân biệt chữ hoa chữ thường. Sửa chính tả hoặc để trống trường này.
</Accordion>

<Accordion title="Cannot execute query in readonly mode">
Kết nối đang ở chế độ chỉ đọc, là mặc định. Nếu agent cần ghi, hãy kết nối lại với **Write access** đặt thành **Full access** (xem [Quyền ghi](#quyền-ghi)). Nếu vẫn thất bại, giới hạn nằm ở phía server: chạy `SHOW CREATE USER cloudthinker;` và tìm settings profile `readonly` hoặc grant ghi còn thiếu.
</Accordion>

<Accordion title="Danh sách bảng trống">
User cần `SHOW TABLES` và `SELECT` trên database, không chỉ trên từng bảng, cùng `SELECT` trên `system.tables`.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Grant quan trọng hơn công tắc**: đặc quyền trên user ClickHouse quyết định điều gì khả thi. **Write access** chỉ quyết định CloudThinker yêu cầu gì.
- **Chỉ đọc phía server**: với kết nối không bao giờ được ghi, hãy giữ settings profile `READONLY` ở bước 2 phần Thiết lập. Không client nào gỡ được profile đó.

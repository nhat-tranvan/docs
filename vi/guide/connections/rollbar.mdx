Kết nối Rollbar để agent CloudThinker xếp hạng các lỗi hàng đầu, gắn lỗi mới với các lần deploy và phiên bản gần đây, lấy ngữ cảnh session replay, và đổi trạng thái item qua [Approvals](/vi/guide/approvals/overview) của bạn. Bạn dán một cấu hình JSON ánh xạ mỗi project Rollbar với project access token của nó, nên một kết nối có thể bao quát nhiều project.

## Điều kiện tiên quyết

- Tài khoản Rollbar có quyền truy cập từng project bạn muốn agent đọc.
- Một project access token cho mỗi project đó. Token của Rollbar gắn với từng project, nên một token không dùng được cho hai project.

## Thiết lập

<Steps>
  <Step title="Tạo project access token">
    Trong Rollbar, mở project và vào **Settings → Project Access Tokens**. Nhấn **Create new access token**, đánh dấu **read**, và chỉ thêm **write** nếu bạn muốn agent đổi trạng thái item. Để trống **post_server_item** và **post_client_item**: hai scope này dùng để gửi lỗi vào Rollbar, việc CloudThinker không bao giờ làm. Lặp lại cho từng project.
  </Step>
  <Step title="Viết cấu hình project">
    Tạo một object JSON có mảng `projects`, mỗi project một phần tử. Mỗi phần tử có `name` và `token`. `name` là nhãn riêng của bạn để dùng trong prompt, nên không cần trùng với tên project trên Rollbar. Tên ngắn như `backend` là dễ gõ nhất.

    ```json
    {
      "projects": [
        { "name": "backend", "token": "<backend-project-token>" },
        { "name": "frontend", "token": "<frontend-project-token>" }
      ]
    }
    ```
  </Step>
  <Step title="Thêm kết nối">
    Ở thanh bên, nhấn **More → Workspace settings → Connections**, rồi trên tab **Builtin Connections** chọn **Rollbar**, dán JSON vào **ROLLBAR_CONFIG_JSON** và nhấn **Connect**.

    **Trạng thái thành công:** kết nối hiển thị **Connected**. Bước Connect không gọi Rollbar bằng từng token, nên token sai chỉ lộ ra ở yêu cầu đầu tiên. Hãy chạy ngay prompt trong [Xác minh kết nối](#xác-minh-kết-nối) ở một chat mới.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Mô tả | Ví dụ |
|-------|-------------|---------|
| **ROLLBAR_CONFIG_JSON** | Mảng `projects`. Mỗi phần tử có `name` và `token`. Khóa là `token`, không phải `access_token` | `{"projects":[{"name":"backend","token":"..."}]}` |

Định dạng này giống [cấu hình đa project cho MCP server](https://docs.rollbar.com/docs/mcp-server-setup#configuration) của Rollbar.

## Quyền yêu cầu

| Scope của token | Cho phép |
|-------------|----------------|
| **read** | Project, item, lỗi hàng đầu, deployment, phiên bản và session replay |
| **write** | Đổi trạng thái item, ví dụ resolve hoặc mute. Mỗi thay đổi còn đi qua Approvals của bạn |

<Tip>
Bắt đầu với token chỉ đọc. Chỉ thêm scope write trên những project mà bạn muốn agent resolve hoặc mute item.
</Tip>

## Khả năng của agent

| Khả năng | Agent có thể làm gì |
|------------|--------------------|
| **Khám phá** | Liệt kê các project đã cấu hình và tự chọn project khi chỉ có một |
| **Phân loại lỗi** | Liệt kê item hiện tại, đọc chi tiết item và số lần xuất hiện, và xếp hạng lỗi hàng đầu |
| **Ngữ cảnh phát hành** | Xem các deployment gần đây và lấy chi tiết phiên bản từ revision của lần deploy |
| **Session replay** | Lấy ngữ cảnh replay cho item có replay đã ghi. Cần thiết lập session replay cho project trong Rollbar |
| **Cập nhật item (kiểm tra từng lần)** | Đổi trạng thái của một item. Bạn phải nêu rõ project, item và thay đổi mong muốn |

Agent không bao giờ thay đổi item khi đang phân loại, xem deploy hay đọc replay. Cập nhật chỉ chạy khi bạn yêu cầu trong cuộc hội thoại, và đi qua Approvals của bạn.

### Xác minh kết nối

Hỏi CloudThinker trong một chat mới:

```text
List my Rollbar projects and show the top errors in each
```

Kết quả mong đợi gồm mọi tên project trong cấu hình, mỗi project kèm các item ảnh hưởng lớn nhất, level và số lần xuất hiện. Nếu thiếu project nào, project đó không có trong JSON bạn đã dán.

### Ví dụ prompt

```text
Which errors in backend first appeared after the latest deployment?
Rank the active items in frontend by impact and show replay context for the top one
Resolve item #1042 in backend
```

Khi cấu hình nhiều project, hãy nêu tên project trong prompt. Nếu không, agent sẽ hỏi bạn dùng project nào. Với số item, dùng số `#` mà Rollbar hiển thị trên item.

## Khắc phục sự cố

<Accordion title="Lời gọi thất bại với 401 Unauthorized, hoặc trả về trống">
Cấu hình đã dán không phải JSON hợp lệ, không chứa project bạn nêu tên, hoặc chứa token đã bị thu hồi, vô hiệu hóa hoặc giới hạn tần suất trong Rollbar. Yêu cầu agent liệt kê các project đã cấu hình, rồi sửa kết nối và chỉnh lại JSON hoặc token.
</Accordion>

<Accordion title="Agent hỏi nên dùng project nào">
Có nhiều hơn một project được cấu hình và prompt của bạn không nêu tên project. Thêm tên project trong cấu hình, ví dụ "in backend".
</Accordion>

<Accordion title="Item không có replay">
Ngữ cảnh replay chỉ có với item có session replay đã ghi. Item không có replay sẽ không trả về dữ liệu replay. Đây là hành vi bình thường, không phải lỗi.
</Accordion>

<Accordion title="Cập nhật item bị chặn hoặc thất bại">
Token của project đó thiếu scope write, hoặc bạn đã từ chối phê duyệt. Thêm scope write cho token trong Rollbar, cập nhật kết nối rồi hỏi lại.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **File cấu hình tạm**: token được lưu dưới dạng mã hóa. Khi agent dùng Rollbar, tiến trình Rollbar của agent đọc token từ một file tạm mà chỉ tiến trình đó đọc được, và file bị xóa khi tiến trình dừng.
- **Xoay vòng token và thêm project**: JSON đã lưu không hiển thị khi bạn sửa kết nối. Dán lại toàn bộ JSON, với mọi project, mỗi khi bạn xoay vòng token hoặc thêm project.

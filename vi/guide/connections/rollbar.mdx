Kết nối các project Rollbar của bạn để cho phép các agent CloudThinker phân loại lỗi, xếp hạng các vấn đề hàng đầu, xem xét deployment, lấy ngữ cảnh session replay và cập nhật item trên một hoặc nhiều project. Rollbar xác thực bằng **project access token** — token có phạm vi đọc đủ cho điều tra; token có phạm vi ghi bổ sung các cập nhật item được kiểm soát bởi phê duyệt.

## Điều kiện tiên quyết

- Một **tài khoản Rollbar** với quyền truy cập vào các project bạn muốn CloudThinker xem.
- Một **project access token** cho mỗi project (phạm vi đọc là đủ để điều tra).
- Một **token có phạm vi ghi** chỉ khi bạn muốn agent cập nhật trạng thái item (được kiểm soát bởi phê duyệt).

<Info>
Token Rollbar được giới hạn phạm vi **theo project**. CloudThinker hỗ trợ nhiều project trong một kết nối — cung cấp một token cho mỗi project bạn muốn đưa vào.
</Info>

## Thiết lập

<Steps>
  <Step title="Tạo project access token">
    Trong Rollbar, mở project và tạo (hoặc sao chép) một **project access token** với phạm vi **read**. Thêm token có phạm vi **write** nếu bạn muốn agent cập nhật item. Xem [MCP Server Setup](https://docs.rollbar.com/docs/mcp-server-setup#configuration) của Rollbar để biết chi tiết về token và cấu hình.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Điều hướng đến **Connections → Rollbar** và nhập:
    - **Project config (JSON)**: một mảng `projects`, một mục cho mỗi project Rollbar, mỗi mục gồm `name` và `token`.

    Nhấn **Connect**. CloudThinker xác minh thông tin xác thực và hiển thị trạng thái **Connected**.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Mô tả | Ví dụ |
|--------|-------|-------|
| **ROLLBAR_CONFIG_JSON** | Một mảng `projects` ánh xạ mỗi project Rollbar với access token của nó. Mỗi mục có `name` và `token`. | xem bên dưới |

```json
{
  "projects": [
    { "name": "backend",  "token": "tok_abc123" },
    { "name": "frontend", "token": "tok_xyz789" }
  ]
}
```

<Info>
Trường token là `token` (không phải `access_token`), và `projects` là một mảng. Định dạng khớp với [cấu hình multi-project MCP](https://docs.rollbar.com/docs/mcp-server-setup#configuration) của Rollbar.
</Info>

## Quyền yêu cầu

Các thao tác đọc (danh sách project, item, lỗi hàng đầu, deployment, phiên bản, replay) hoạt động với **project access token** có phạm vi **read**. Cập nhật item bổ sung yêu cầu token có phạm vi **write** **và** [phê duyệt](/vi/guide/approval) rõ ràng trong CloudThinker.

<Tip>
Tuân theo nguyên tắc ít quyền nhất: dùng token có phạm vi đọc để điều tra, và chỉ thêm token có phạm vi ghi cho các project mà agent cần cập nhật item.
</Tip>

## Khả năng của agent

Sau khi kết nối, các agent có thể điều tra và xử lý lỗi trên các project đã cấu hình của bạn.

### Khả năng đọc

| Danh mục | Chức năng của agent |
|----------|---------------------|
| **Project** | Liệt kê các project Rollbar đã cấu hình và tự động giới hạn phạm vi theo một project |
| **Error item** | Liệt kê các item hiện tại và đang hoạt động, kiểm tra chi tiết item và tín hiệu xảy ra |
| **Lỗi hàng đầu** | Hiển thị các lỗi có tác động cao nhất và tình trạng lỗi production hiện tại |
| **Deployment** | Xem xét các deployment gần đây theo project |
| **Release & phiên bản** | Lấy ngữ cảnh phiên bản và tương quan release với hoạt động lỗi |
| **Session replay** | Lấy ngữ cảnh replay cho các item có replay được ghi |

### Khả năng ghi

| Danh mục | Chức năng của agent |
|----------|---------------------|
| **Cập nhật item** | Thay đổi trạng thái của item (ví dụ giải quyết, tắt tiếng) — **yêu cầu phê duyệt** |

<Warning>
Cập nhật item yêu cầu phê duyệt rõ ràng từ người dùng trước khi thực thi, và bạn phải nêu tên project, item và thay đổi mong muốn.
</Warning>

### Xác minh kết nối

```text
@alex list my Rollbar projects and show the current top errors
```

### Ví dụ lệnh

```text
@alex triage current Rollbar items and rank them by impact #recommend
@alex show the top errors that appeared after the latest deployment
@alex review recent deployments and correlate them with new error activity
```

## Khắc phục sự cố

<Accordion title="Xác thực thất bại hoặc truy vấn trả về trống">
JSON cấu hình project đã dán không hợp lệ, không bao gồm tên project được yêu cầu, hoặc ánh xạ project với token đã hết hạn. Hãy liệt kê các project đã cấu hình trước khi coi item hoặc deployment bị thiếu là "không có dữ liệu".
</Accordion>

<Accordion title="Agent hỏi nên dùng project nào">
Điều này xảy ra khi nhiều project được cấu hình. Hãy nêu tên project trong lệnh (ví dụ "for my-app") để agent có thể giới hạn phạm vi truy vấn.
</Accordion>

<Accordion title="Không có replay cho một item">
Ngữ cảnh session replay chỉ tồn tại cho các item có replay được ghi. Các item không có replay sẽ không trả về dữ liệu replay — đây là điều bình thường, không phải lỗi.
</Accordion>

<Accordion title="Cập nhật item bị chặn">
Các cập nhật được kiểm soát bởi phê duyệt và cần token có phạm vi **write**. Xác nhận token cho project đó có phạm vi ghi, rồi phê duyệt hành động khi được nhắc.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Token ít quyền nhất** — dùng token project có phạm vi đọc để điều tra; chỉ thêm phạm vi ghi khi agent cần cập nhật trạng thái item.
- **Xoay vòng** — xoay vòng project access token thường xuyên và cập nhật trong CloudThinker.

Kết nối tài khoản Datadog của bạn để cho phép các agent CloudThinker tìm kiếm log, truy vấn metric, giám sát hạ tầng và điều tra sự cố trên toàn bộ stack. Datadog xác thực bằng cặp **API key** và **Application key có phạm vi**.

---

## Nền tảng hỗ trợ

| Site | URL |
|------|-----|
| **US1** | `app.datadoghq.com` |
| **US3** | `us3.datadoghq.com` |
| **US5** | `us5.datadoghq.com` |
| **EU1** | `app.datadoghq.eu` |
| **AP1** | `ap1.datadoghq.com` |
| **AP2** | `ap2.datadoghq.com` |

<Warning>
GovCloud (US1-FED) không được Datadog MCP server hỗ trợ.
</Warning>

---

## Điều kiện tiên quyết

Bạn cần có **Datadog API key** và **Application key có phạm vi**.

**Tạo API key:**

1. Vào **Organization Settings → API Keys** trong tài khoản Datadog của bạn.
2. Nhấn **+ New Key**, đặt tên (ví dụ: `CloudThinker`) và lưu.
3. Sao chép giá trị key.

**Tạo Application key có phạm vi:**

1. Vào **Organization Settings → Application Keys**.
2. Nhấn **+ New Key**, đặt tên (ví dụ: `CloudThinker`).
3. Trong **Scopes**, chọn các quyền được liệt kê trong [Quyền yêu cầu](#required-permissions).
4. Lưu và sao chép giá trị key.

<Tip>
Luôn dùng Application key có phạm vi thay vì không có phạm vi. Key không có phạm vi kế thừa tất cả quyền từ người dùng đã tạo nó.
</Tip>

## Thiết lập

<Steps>
  <Step title="Mở CloudThinker">
    Điều hướng đến **Connections → Datadog** trong workspace CloudThinker của bạn.
  </Step>
  <Step title="Chọn Datadog site của bạn">
    Chọn Datadog site phù hợp với tài khoản của bạn (ví dụ: US1 cho `datadoghq.com`, EU1 cho `datadoghq.eu`).
  </Step>
  <Step title="Nhập API key của bạn">
    Dán **API key** Datadog của bạn.
  </Step>
  <Step title="Nhập Application key của bạn">
    Dán **Application key** Datadog của bạn.
  </Step>
  <Step title="Kết nối">
    Nhấn **Connect**. CloudThinker xác minh thông tin xác thực và hiển thị trạng thái **Connected**.
  </Step>
</Steps>

## Quyền yêu cầu

Chọn các phạm vi này khi tạo Application key. Các phạm vi đọc bao gồm tất cả công cụ điều tra; `notebooks_write` là tùy chọn và cho phép tạo notebook.

| Phạm vi | Tính năng cho phép |
|---------|-------------------|
| `logs_read_data`, `logs_read_index_data` | Tìm kiếm và phân tích log |
| `metrics_read`, `timeseries_query` | Truy vấn metric và dữ liệu time-series |
| `monitors_read` | Tìm kiếm monitor theo trạng thái và tag |
| `incidents_read` | Tìm kiếm sự cố và lấy chi tiết |
| `dashboards_read` | Kiểm tra cấu hình dashboard |
| `hosts_read` | Liệt kê và kiểm tra host hạ tầng |
| `apm_read` | Lấy trace và tìm kiếm APM span |
| `apm_service_catalog_read` | Liệt kê dịch vụ và ánh xạ phụ thuộc |
| `events_read` | Tìm kiếm sự kiện platform và tùy chỉnh |
| `notebooks_read` | Tìm kiếm và lấy notebook điều tra |
| `rum_apps_read` | Tìm kiếm dữ liệu Real User Monitoring |
| `notebooks_write` | Tạo và chỉnh sửa notebook điều tra (tùy chọn) |

<Tip>
Bắt đầu chỉ với các phạm vi đọc. Thêm `notebooks_write` chỉ khi workflow cần agent tạo notebook điều tra.
</Tip>

## Khả năng của agent

Sau khi kết nối, các agent có thể thực hiện thao tác đọc và ghi trên môi trường Datadog của bạn.

| Khả năng | Những gì agent có thể làm |
|----------|--------------------------|
| **Log** | Tìm kiếm log trên các dịch vụ và môi trường, phân tích mẫu và xu hướng |
| **Metric** | Tìm kiếm metric có sẵn, truy vấn dữ liệu time-series, lấy metadata metric |
| **Monitor** | Tìm monitor theo trạng thái, tên hoặc tag |
| **Sự cố** | Tìm kiếm sự cố đang hoạt động và đã giải quyết, lấy chi tiết đầy đủ |
| **Dashboard** | Tìm kiếm và kiểm tra cấu hình dashboard |
| **Hạ tầng** | Liệt kê và kiểm tra host trên hạ tầng của bạn |
| **APM** | Lấy distributed trace, tìm kiếm span để phân tích latency |
| **Service catalog** | Liệt kê dịch vụ và ánh xạ quan hệ phụ thuộc dịch vụ |
| **Sự kiện** | Tìm kiếm sự kiện platform và tùy chỉnh |
| **Notebook** | Tìm kiếm, lấy, tạo và chỉnh sửa notebook điều tra |
| **RUM** | Tìm kiếm dữ liệu Real User Monitoring |
| **Sức khỏe kết nối** | Xác nhận kết nối Datadog đang hoạt động |

<Warning>
Các thao tác ghi notebook yêu cầu phê duyệt của người dùng trước khi thực thi.
</Warning>

### Xác minh kết nối

```text
@alex run the Datadog connection health check and summarize active monitors and host count
```

### Ví dụ prompt

```text
@alex search for error logs in the production environment from the last 15 minutes
@alex check for active Datadog incidents and investigate root causes
@alex analyze APM traces for the checkout service and identify latency bottlenecks
```

## Xử lý sự cố

<Accordion title="Kiểm tra kết nối thất bại với 403">
Xác minh API key hợp lệ và chưa bị thu hồi. Xác nhận Application key có đúng phạm vi và cả hai key thuộc cùng tổ chức Datadog.
</Accordion>

<Accordion title="Thiếu dữ liệu sau khi kết nối">
Kiểm tra phạm vi Application key bao gồm loại dữ liệu bạn đang truy vấn (ví dụ: `logs_read_data` cho log). Xác minh cài đặt retention của Datadog và xác nhận dịch vụ hoặc host đang tích cực gửi dữ liệu.
</Accordion>

<Accordion title="Chọn sai Datadog site">
Nếu truy vấn trả về kết quả rỗng, bạn có thể đã chọn sai site. Kiểm tra URL Datadog của bạn — `app.datadoghq.com` là US1, `us3.datadoghq.com` là US3, `app.datadoghq.eu` là EU1. Ngắt kết nối và kết nối lại với site đúng.
</Accordion>

<Accordion title="Nhầm lẫn giữa API key và Application key">
Cả hai key đều cần thiết và phục vụ các vai trò khác nhau. **API key** xác thực yêu cầu. **Application key** kiểm soát tính năng và dữ liệu Datadog nào agent có thể truy cập. Một mình không đủ.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Application key có phạm vi** — luôn chỉ định phạm vi rõ ràng; key không có phạm vi kế thừa đầy đủ quyền của người dùng tạo ra nó.
- **Key riêng cho mỗi tích hợp** — tạo API key và Application key riêng cho CloudThinker để bạn có thể thu hồi chúng độc lập.

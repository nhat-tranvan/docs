Kết nối Datadog để CloudThinker phân loại các monitor đang cảnh báo, tìm kiếm log, truy vấn metric, lần theo trace, và đọc sự cố, host và dashboard. CloudThinker truy cập Datadog qua Datadog MCP server, xác thực bằng một API key cùng một application key chỉ được cấp scope đọc.

Datadog có hai phần thiết lập riêng biệt. Muốn phân tích nguyên nhân gốc tự động cho cảnh báo Datadog, bạn cần cả hai.

| Thiết lập | Tác dụng | Khi nào cần |
|---|---|---|
| Điều tra (kết nối này) | Cho agent đọc log, metric, trace và monitor | Luôn cần. Thiếu kết nối này, agent không xem được dữ liệu bên trong Datadog. |
| Nhận cảnh báo (webhook) | Mở một sự cố Resolve khi monitor kích hoạt | Khi bạn muốn sự cố tự mở. Xem [Gửi cảnh báo Datadog tới Resolve](#gửi-cảnh-báo-datadog-tới-resolve). |

## Điều kiện tiên quyết

- Một Datadog organization trên một trong các site: **US1**, **US3**, **US5**, **EU1**, **AP1** hoặc **AP2**. Datadog MCP server không hỗ trợ các site dành cho chính phủ (`ddog-gov.com`).
- **MCP Access** đã được bật trong **Organization Settings** của Datadog. Admin Datadog chỉ cần bật một lần cho mỗi organization.
- Quyền tạo API key và application key trong Datadog.
- Quyền thêm kết nối trong workspace CloudThinker.

## Thiết lập

<Steps>
  <Step title="Xác định site">
    Xem thanh địa chỉ khi bạn đã đăng nhập Datadog:

    | URL Datadog của bạn | Chọn trong CloudThinker |
    |------------------|----------------------|
    | `app.datadoghq.com` | **US1 (datadoghq.com)** |
    | `us3.datadoghq.com` | **US3 (us3.datadoghq.com)** |
    | `us5.datadoghq.com` | **US5 (us5.datadoghq.com)** |
    | `app.datadoghq.eu` | **EU1 (datadoghq.eu)** |
    | `ap1.datadoghq.com` | **AP1 (ap1.datadoghq.com)** |
    | `ap2.datadoghq.com` | **AP2 (ap2.datadoghq.com)** |
  </Step>
  <Step title="Tạo API key">
    Trong Datadog, vào **Organization Settings → API Keys**, nhấn **New Key**, đặt tên `cloudthinker` và sao chép giá trị.
  </Step>
  <Step title="Tạo application key giới hạn scope">
    **Khuyến nghị:** tạo key trên một service account của Datadog có **Datadog Read Only Role**, để key không phụ thuộc vào quyền của một cá nhân. Vào **Organization Settings → Service Accounts**, tạo `cloudthinker` với role đó, rồi thêm application key cho service account này.

    Nếu không, vào **Organization Settings → Application Keys** và nhấn **New Key**.

    Dù chọn cách nào, hãy đặt tên key là `cloudthinker` và chọn các scope trong [Quyền yêu cầu](#quyền-yêu-cầu). Lưu và sao chép key ngay.

    <Warning>
    Application key không có scope sẽ thừa hưởng mọi quyền của người sở hữu, kể cả quyền ghi. Luôn chọn scope.
    </Warning>

    **Trạng thái thành công:** danh sách scope của key chỉ có quyền đọc, không có mục `_write` nào.
  </Step>
  <Step title="Thêm kết nối">
    Mở **More → Workspace settings → Connections**, giữ nguyên tab **Builtin Connections**, rồi chọn **Datadog**. Điền:
    - **Alias** (không bắt buộc): tên ngắn như `datadog-prod`. Chỉ gồm chữ thường, số và dấu gạch ngang.
    - **Description** (không bắt buộc): organization hoặc môi trường của kết nối này. Agent đọc mô tả để chọn đúng instance.
    - **DD_API_KEY**: API key.
    - **DD_APPLICATION_KEY**: application key.
    - **DD_SITE**: site bạn xác định ở bước 1.

    Nhấn **Connect**. CloudThinker hiển thị **Connecting** và **Verifying**, rồi chuyển sang trạng thái **Connected**. Ở bước **Verifying**, CloudThinker mở một phiên với Datadog MCP server của site bạn chọn và liệt kê các tool của server. Bước này không chạy truy vấn dữ liệu, nên một scope bị thiếu chỉ lộ ra về sau dưới dạng lỗi 403 khi bạn hỏi về loại dữ liệu đó. Nếu xác minh thất bại, kết nối hiển thị **Failed** kèm thông báo lỗi. Đối chiếu thông báo với phần [Khắc phục sự cố](#khắc-phục-sự-cố).
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Mô tả | Ví dụ |
|-------|-------------|---------|
| **DD_API_KEY** | API key Datadog của organization | |
| **DD_APPLICATION_KEY** | Application key Datadog đã giới hạn scope. Scope của key quyết định CloudThinker đọc được gì | |
| **DD_SITE** | Site Datadog của organization. Mặc định là **US1** | `EU1 (datadoghq.eu)` |

Bạn cần cả hai key. CloudThinker gửi chúng tới Datadog MCP server của site bạn trong mọi lệnh gọi.

## Quyền yêu cầu

Datadog MCP server kiểm tra quyền của chính Datadog trong mọi lệnh gọi. Chọn các hàng tương ứng với dữ liệu bạn muốn CloudThinker xem.

| Scope ID | Tên trong Datadog | Mở khóa |
|----------|--------------------------|-----------------|
| `mcp_read` | `mcp_read` | Mọi thao tác với Datadog MCP server. Bắt buộc |
| `monitors_read` | Monitors Read | Tìm monitor và phân loại cảnh báo |
| `logs_read_data`, `logs_read_index_data` | Logs Read Data, Logs Read Index Data | Tìm kiếm log |
| `timeseries_query` | Timeseries | Phân tích log, metric của host, event |
| `metrics_read` | Metrics | Tìm và truy vấn metric |
| `hosts_read` | Hosts Read | Danh sách host |
| `incident_read` | Incidents Read | Sự cố Datadog |
| `dashboards_read`, `user_access_read` | Dashboards Read, User Access Read | Tìm dashboard |
| `apm_read` | APM Read | Span và trace |
| `events_read` | Events | Tìm event |
| `notebooks_read` | Notebooks Read | Tìm notebook |

<Tip>
Bỏ qua `mcp_write` và mọi scope `_write`. Các cuộc điều tra Datadog của CloudThinker chỉ đọc dữ liệu.
</Tip>

## Khả năng của agent

| Khả năng | CloudThinker làm gì |
|------------|------------------------|
| **Khám phá** | Tóm tắt monitor theo trạng thái (OK, Alert, Warn, No Data), host, sự cố đang diễn ra, dashboard và service |
| **Monitor** | Tìm monitor theo trạng thái, tên hoặc tag, và giải thích cái gì đang cảnh báo |
| **Log** | Tìm kiếm và nhóm log bằng cú pháp truy vấn của Datadog, chẳng hạn `service:web status:error`, bắt đầu từ 15 phút gần nhất |
| **Metric** | Tìm metric và truy vấn kèm phép tổng hợp, chẳng hạn `avg:system.cpu.user{host:web-1}` |
| **Trace** | Tìm span theo service và thời lượng, rồi mở toàn bộ trace |
| **Sự cố** | Liệt kê sự cố Datadog và đọc chi tiết |
| **Hạ tầng** | Liệt kê host kèm ứng dụng, trạng thái mute và các metric hệ thống chính |
| **Service** | Liệt kê service trong catalog và vẽ sơ đồ phụ thuộc |
| **Dashboard, event, notebook** | Tìm và đọc để lấy thêm ngữ cảnh |

Khi kết nối lần đầu đạt trạng thái **Connected**, CloudThinker chạy một lượt [khám phá](/vi/guide/connections/overview#điều-gì-xảy-ra-sau-khi-kết-nối) chỉ đọc và lưu kết quả cho các cuộc trò chuyện sau.

### Xác minh kết nối

```text
Run Datadog discovery and list monitors by state, the number of hosts, and any active incidents
```

Câu trả lời đúng sẽ đếm số monitor ở các trạng thái OK, Alert, Warn và No Data, và nêu tên những monitor đang cảnh báo.

### Ví dụ prompt

```text
Which Datadog monitors are alerting right now, and what do the error logs for those services show in the last 15 minutes?
Find the slowest checkout spans in the last hour and walk me through one trace
Which hosts have the highest CPU right now, and do any have muted monitors?
```

## Gửi cảnh báo Datadog tới Resolve

Resolve có sẵn preset cho Datadog, nên **Resolve → Integrations** điền sẵn phần ánh xạ trường và mức độ nghiêm trọng cho bạn. [Webhook Signals](/vi/guide/incident/webhook-integrations/overview) giải thích đầy đủ hộp thoại này; các bước dưới đây là phần riêng cho Datadog. Với công cụ không có preset, xem [Kết nối nguồn cảnh báo](/vi/guide/incident/connect-alert-sources).

<Steps>
  <Step title="Tạo webhook trong CloudThinker">
    Vào **Resolve → Integrations**, chọn **Datadog**, rồi trong **Signals to Resolve** nhấn **Add signal**. Lần lượt qua **Basic Info**, **Configure** và **Advanced**, rồi nhấn **Create**. Sao chép **Webhook URL** và **Secret Key**. Secret Key chỉ hiển thị một lần.
  </Step>
  <Step title="Trỏ phần ánh xạ tới một service">
    Preset đọc `title`, `body` và `alert_type`, nhưng **Service Path** mặc định là `tags`, vốn trỏ tới một danh sách nên không ánh xạ ra giá trị nào. Trong **Field Mapping**, đổi **Service Path** thành `service`, rồi gửi key đó trong payload bên dưới. Xem [Ánh xạ các trường](/vi/guide/incident/webhook-integrations/overview#ánh-xạ-các-trường).
  </Step>
  <Step title="Thêm các hàng mức độ nghiêm trọng mà monitor gửi">
    **Severity Mapping** của preset gồm `alert`, `warn`, `ok` và `no data`, trong khi `$ALERT_TYPE` của Datadog gửi `error`, `warning`, `info` hoặc `success`. Trong **Severity Mapping**, nhấn **Customize**, rồi nhấn **Add Mapping** cho từng giá trị mà monitor của bạn gửi. Giá trị chưa được ánh xạ sẽ nhận mức **medium**.
  </Step>
  <Step title="Thêm webhook trong Datadog">
    Trong Datadog, mở **Integrations → Webhooks** và thêm một webhook tên `CloudThinker`. Dán **Webhook URL** vào **URL**, và điền nội dung sau vào ô **Custom Headers**: `{"Authorization": "Bearer <your-secret-key>"}`. Dùng payload như sau:

    ```json
    {
      "title": "$EVENT_TITLE",
      "body": "$EVENT_MSG",
      "alert_type": "$ALERT_TYPE",
      "service": "web-api"
    }
    ```

    Giá trị `service` cố định sẽ áp dụng cho mọi monitor gửi thông báo tới webhook này. Secret được lưu trong cấu hình webhook của Datadog, nên ai quản lý được integration đó cũng đọc được secret. Hãy giới hạn quyền truy cập này, và dùng **Regenerate credentials** trên hàng webhook trong Resolve nếu secret bị lộ.
  </Step>
  <Step title="Cho monitor gửi thông báo tới webhook">
    Thêm `@webhook-CloudThinker` vào message của từng monitor cần mở sự cố. Để chỉ gửi cảnh báo mà không gửi thông báo phục hồi, đặt mention trong điều kiện alert của Datadog:

    ```text
    {{#is_alert}}@webhook-CloudThinker{{/is_alert}}
    ```
  </Step>
  <Step title="Gửi một event thử">
    Nhấn **Test Notifications** trên một monitor, hoặc dùng tab **cURL** trong **Integration Examples** của hộp thoại webhook.
  </Step>
</Steps>

**Trạng thái thành công:** cảnh báo tiếp theo từ monitor đó xuất hiện trong [Pulse](/vi/guide/pulse/overview), luồng cảnh báo của Resolve, với tiêu đề của monitor, và agent điều tra cảnh báo qua kết nối này.

## Khắc phục sự cố

<Accordion title="401 hoặc 403 ở bước Verifying hoặc ở mọi lệnh gọi">
- **DD_SITE** không khớp với organization. Key Datadog chỉ hoạt động trên site của chính nó, nên hãy so sánh với URL Datadog theo bảng ở bước 1, rồi sửa kết nối.
- Một trong hai key sai, đã bị thu hồi hoặc thuộc một Datadog organization khác. Tạo key mới trong cùng organization và cập nhật kết nối từ bảng chi tiết của nó.
- **MCP Access** đang tắt cho organization, hoặc application key thiếu `mcp_read`.
</Accordion>

<Accordion title="403 Forbidden ở một số câu hỏi nhưng không phải tất cả">
Application key thiếu scope cho loại dữ liệu đó, ví dụ thiếu `apm_read` khi hỏi về trace. Thêm scope trong **Organization Settings → Application Keys**.
</Accordion>

<Accordion title="Không tìm thấy metric hoặc service">
CloudThinker tìm tên metric và service trước khi truy vấn. Hãy yêu cầu liệt kê các metric khớp với một tên, rồi dùng đúng tên mà CloudThinker trả về.
</Accordion>

<Accordion title="429 Too Many Requests">
Datadog đang giới hạn tần suất request của các key. Hãy hỏi hẹp hơn với khoảng thời gian ngắn hơn, hoặc thử lại sau một phút.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Giới hạn scope cho application key**: key không có scope mang toàn bộ quyền của người tạo, kể cả quyền ghi.
- **Key riêng**: tạo key chỉ dành cho CloudThinker để bạn có thể thu hồi mà không ảnh hưởng tới các integration khác.

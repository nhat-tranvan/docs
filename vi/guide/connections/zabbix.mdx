Kết nối Zabbix để agent của CloudThinker phân loại các problem đang hoạt động, đọc metric và log item của host, xem trigger, template và dashboard, và nếu bạn cho phép, xác nhận event hoặc lên lịch bảo trì. Kết nối đăng nhập vào Zabbix API bằng API token hoặc username và password, và agent chỉ làm được những gì người dùng Zabbix đó được phép làm.

## Điều kiện tiên quyết

- Zabbix frontend mà CloudThinker truy cập được qua internet, ví dụ `https://zabbix.example.com`. Nếu frontend nằm sau tường lửa hoặc phải giữ ở mạng riêng, xem [Truy cập dịch vụ riêng](/vi/guide/connections/overview#truy-cập-dịch-vụ-nội-bộ).
- Một Super admin của Zabbix có quyền tạo user, user group và API token.
- Zabbix 5.4 trở lên nếu bạn muốn dùng API token. Các phiên bản cũ hơn dùng username và password.
- Vai trò **Admin** trong workspace CloudThinker, vai trò cần để thêm kết nối. Xem [Vai trò](/vi/guide/security/roles).

## Thiết lập

<Steps>
  <Step title="Tạo role có quyền truy cập API">
    Vào **Users → User roles** (trong Zabbix 6.x là **Administration → User roles**) và nhấn **Create user role**. Đặt tên `CloudThinker`, đặt **User type** là **User** (hoặc **Admin** nếu cần ghi, xem [Quyền yêu cầu](#quyền-yêu-cầu)), bảo đảm **Access to API** đang bật, rồi nhấn **Add**.
  </Step>
  <Step title="Tạo user group có quyền vào host group">
    Vào **Users → User groups** (trong 6.x là **Administration → User groups**) và nhấn **Create user group**. Đặt tên `CloudThinker`. Trên tab **Host permissions** (trong 6.x là **Permissions**), chọn các host group mà agent cần thấy, chọn **Read**, rồi nhấn **Add**.
  </Step>
  <Step title="Tạo user">
    Vào **Users → Users** (trong 6.x là **Administration → Users**) và tạo user tên `cloudthinker` trong group `CloudThinker`. Trên tab **Permissions**, chọn role `CloudThinker`, rồi nhấn **Add**.
  </Step>
  <Step title="Tạo API token (Zabbix 5.4+)">
    Vào **Users → API tokens** (trong Zabbix 5.4 đến 6.x là **Administration → General → API tokens**) và nhấn **Create API token**. Chọn user `cloudthinker`, đặt **Expires at** khớp với lịch xoay vòng của bạn, rồi nhấn **Add**. Sao chép token. Zabbix chỉ hiển thị token một lần.

    Với phiên bản cũ hơn 5.4, bỏ qua bước này và dùng password của user.
  </Step>
  <Step title="Thêm kết nối trong CloudThinker">
    Ở thanh bên, nhấn **More → Workspace settings → Connections**, chọn **Zabbix**, rồi điền:

    - **ZABBIX_URL**: URL của Zabbix frontend, ví dụ `https://zabbix.example.com`.
    - **ZABBIX_AUTH_TYPE**: chuyển sang **API Token**. Mặc định là **Username & Password**, nhưng token có thể hết hạn và bị thu hồi mà không cần đổi password.
    - **ZABBIX_TOKEN**, hoặc **ZABBIX_USERNAME** và **ZABBIX_PASSWORD**: thông tin xác thực từ các bước trên. CloudThinker chỉ hiển thị các trường của kiểu xác thực bạn đã chọn.

    Nhấn **Connect**. CloudThinker đăng nhập và liệt kê host để kiểm tra thông tin xác thực.

    **Trạng thái thành công:** kết nối hiển thị trạng thái **Connected**. Trạng thái này chỉ chứng minh việc đăng nhập, vì vậy hãy chạy prompt trong mục [Xác minh kết nối](#xác-minh-kết-nối) ở một cuộc chat mới để kiểm tra các host bạn mong đợi đều hiển thị.
  </Step>
</Steps>

## Chi tiết kết nối

Biểu mẫu hiển thị tên các trường đúng như viết dưới đây.

| Trường | Mô tả | Ví dụ |
|-------|-------------|---------|
| **ZABBIX_URL** | URL của Zabbix frontend | `https://zabbix.example.com` |
| **ZABBIX_AUTH_TYPE** | **Username & Password** (mặc định) hoặc **API Token** | **API Token** |
| **ZABBIX_TOKEN** | API token của Zabbix. Hiện khi chọn **API Token** | Lấy từ **API tokens** |
| **ZABBIX_USERNAME** | Username của Zabbix. Hiện khi chọn **Username & Password** | `cloudthinker` |
| **ZABBIX_PASSWORD** | Password của user đó. Hiện khi chọn **Username & Password** | |

## Quyền yêu cầu

Zabbix quyết định quyền truy cập ở hai nơi: role của user (user thuộc loại nào, và có dùng được API không) và user group của user (đọc hoặc thay đổi được những host group nào). Agent chỉ thấy host trong các host group mà user group đọc được.

| Bạn muốn agent | Role | Quyền trên host group |
|--------------------|------|-----------------------|
| Điều tra problem, metric, log, trigger, template và dashboard | Loại **User**, bật quyền API | **Read** |
| Đồng thời xác nhận event, bật hoặc tắt host và trigger, liên kết template, và tạo maintenance window | Loại **Admin**, bật quyền API | **Read-write** |
| Đồng thời tạo host group hoặc user | Loại **Super admin** | Tất cả |

<Warning>
Tránh dùng Super admin. Super admin bỏ qua quyền trên host group và có thể tạo, thay đổi user, nên chỉ một lần phê duyệt nhầm, dù do người hay do AI đánh giá, cũng có thể chạm tới mọi host và tài khoản. Nếu bắt buộc phải dùng, hãy chọn **Manual** để có người phê duyệt mọi thay đổi. Khi CloudThinker bật [Rule enforcement](/vi/guide/approvals/rules#khắc-phục-sự-cố) cho workspace của bạn, một [Rule](/vi/guide/approvals/rules) **Deny** cho thao tác tạo user trên Zabbix có thể chặn hẳn thao tác đó.
</Warning>

<Tip>
Hãy bắt đầu với role loại User và quyền Read trên các host group bạn quan tâm. Mọi thao tác ghi vẫn đi qua [Approvals](/vi/guide/approvals/overview), nhưng với người dùng Zabbix chỉ đọc, không lần phê duyệt nào, dù nhầm hay tự động, có thể thay đổi được gì.
</Tip>

## Khả năng của agent

| Khả năng | Agent có thể làm gì |
|------------|--------------------|
| **Khám phá** | Báo cáo phiên bản Zabbix, host, host group, problem đang hoạt động và template |
| **Problem và event** | Liệt kê problem đang hoạt động theo mức độ nghiêm trọng, host hoặc host group, và đọc lịch sử event |
| **Metric và log** | Liệt kê item của một host, đọc giá trị gần đây và theo dõi log item |
| **Cấu hình** | Đọc trigger, template, action, maintenance window, dashboard và user, và export cấu hình host hoặc template |
| **Ghi (qua Approvals)** | Xác nhận event; tạo, cập nhật, bật, tắt hoặc xóa host; bật hoặc tắt trigger và action; liên kết hoặc gỡ liên kết template; tạo hoặc xóa maintenance window; tạo host group và user; import cấu hình |

Agent dùng thang mức độ nghiêm trọng của Zabbix: Not classified, Information, Warning, Average, High, Disaster.

<ApprovalDefault />

Vì vậy, ở chế độ mặc định, agent có thể tạo maintenance window, xóa host hoặc tạo user mà không ai thấy. Hãy chọn **Manual** để có người phê duyệt mọi thay đổi, đó là biện pháp kiểm soát hoạt động được ngay hôm nay. Khi CloudThinker bật [Rule enforcement](/vi/guide/approvals/rules#khắc-phục-sự-cố) cho workspace của bạn, một [Rule](/vi/guide/approvals/rules) **Ask first** có thể thu hẹp việc chờ duyệt về đúng các thao tác đó: trong cuộc chat, gõ `/create-policy Ask first for maintenance windows, host deletes and user creation on the Zabbix connection`, rồi chấp nhận Rule trong **Approvals → Rules → Needs review**.

<Warning>
Maintenance window do agent tạo bắt đầu ngay lập tức, và cảnh báo của các host đó bị chặn cho đến khi window kết thúc. Bạn không thể đặt thời điểm bắt đầu trong tương lai, nên hãy yêu cầu đúng lúc công việc bắt đầu. Kiểm tra danh sách host và thời lượng trong yêu cầu phê duyệt trước khi duyệt. Xóa host hoặc gỡ liên kết template kèm dữ liệu là không thể hoàn tác.
</Warning>

### Xác minh kết nối

Hỏi CloudThinker trong một cuộc chat mới:

```text
Run Zabbix discovery and summarize the version, host count, host groups, and active problems by severity
```

Bạn sẽ nhận được phiên bản Zabbix server, số host kèm một vài host mẫu, các host group, và problem đang hoạt động nhóm theo mức độ nghiêm trọng. Nếu thiếu host, group của user không đọc được host group chứa các host đó.

### Ví dụ prompt

```text
List active Zabbix problems at High or Disaster and tell me which hosts they're on
Is db-prod-01 running out of disk? Show the trend from its recent disk values
Schedule a 2-hour Zabbix maintenance window for the hosts in Database servers
```

Prompt cuối cần role loại Admin với quyền **Read-write** trên host group đó, và phải đi qua [Approvals](/vi/guide/approvals/overview) trước. Ở chế độ **Manual**, yêu cầu chờ người duyệt; ở chế độ Auto mặc định, AI có thể đánh giá và cho chạy mà không hỏi.

## Khắc phục sự cố

<Accordion title="Failed to connect to Zabbix">
CloudThinker không đăng nhập hoặc không liệt kê được host. Kiểm tra **ZABBIX_URL** là địa chỉ frontend và CloudThinker truy cập được, **ZABBIX_AUTH_TYPE** khớp với thông tin xác thực bạn đã nhập, và role của user đã bật quyền truy cập API.
</Accordion>

<Accordion title="Lỗi 401, hoặc phiên đăng nhập hết hạn">
Token đã hết hạn hoặc bị xóa, hoặc password đã thay đổi. Tạo token mới trong **API tokens** và cập nhật **ZABBIX_TOKEN**, hoặc cập nhật password.
</Accordion>

<Accordion title="Thiếu host hoặc problem">
Group của user không có quyền trên host group đó, nên Zabbix bỏ các host đó ra. Cấp quyền **Read** trên host group trong phần quyền của user group.
</Accordion>

<Accordion title="Thao tác ghi thất bại với lỗi quyền (403)">
User có role loại User hoặc chỉ có quyền **Read** trên host group. Đổi role sang loại Admin và cấp **Read-write** nếu bạn muốn agent thực hiện thay đổi đó.
</Accordion>

<Accordion title="Lỗi 429, 500 hoặc 503">
Zabbix API đang giới hạn tần suất, gặp lỗi, hoặc đang bảo trì. Chờ một phút, rồi đặt câu hỏi hẹp hơn, giới hạn trong một host hoặc host group.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Ưu tiên API token**: token thuộc về một user, có thời hạn riêng, và có thể thu hồi mà không cần đổi password.
- **Giới hạn theo host group**: chỉ cấp quyền cho user group của CloudThinker trên các host group mà agent cần.

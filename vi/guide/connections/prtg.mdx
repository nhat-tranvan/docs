Kết nối PRTG Network Monitor bằng API key để điều tra sensor, alarm, device và lịch sử. Khi được cấp quyền, CloudThinker cũng có thể thay đổi một đối tượng giám sát thông qua [Approvals](/vi/guide/approvals/overview).

## Điều kiện tiên quyết

- PRTG web server mà CloudThinker truy cập được qua HTTPS, với chứng chỉ được tin cậy. Xem [Truy cập dịch vụ riêng](/vi/guide/connections/overview#truy-cập-dịch-vụ-nội-bộ).
- Tài khoản PRTG đọc được các đối tượng giám sát bạn muốn điều tra.
- Quyền thêm kết nối trong workspace CloudThinker của bạn.

## Thiết lập

<Steps>
  <Step title="Tạo API key">
    Trong PRTG, mở **Setup → Account Settings → API Keys**. Di chuột lên biểu tượng thêm và chọn **Add API Key**. Đặt tên cho key và chọn **Read access** để dùng cho điều tra. Sao chép key trước khi nhấn **OK**, vì PRTG sẽ không hiển thị lại. Xem [hướng dẫn API key của Paessler](https://www.paessler.com/manuals/prtg/api_keys).
  </Step>
  <Step title="Thêm kết nối">
    Trong CloudThinker, mở **More → Workspace settings → Connections** và chọn **PRTG Network Monitor**. Nhập địa chỉ gốc HTTPS của server vào **Server URL**, không kèm đường dẫn hay query. Dán key vào **API key** rồi nhấn **Connect**.

    **Trạng thái thành công:** kết nối hiển thị **Connected**. CloudThinker kiểm tra trạng thái của PRTG server.
  </Step>
</Steps>

## Chi tiết kết nối

| Trường | Mô tả |
|-------|-------------|
| **Server URL** | Địa chỉ HTTPS của PRTG web server, không kèm đường dẫn hay query |
| **API key** | Key đã tạo trong PRTG |

## Quyền yêu cầu

Bắt đầu với **Read access** trên API key và một user đọc được các đối tượng giám sát bạn muốn điều tra. PRTG giới hạn những gì user nhìn thấy theo quyền truy cập của user đó. Xem [hướng dẫn quyền truy cập của Paessler](https://www.paessler.com/manuals/prtg/access_rights_management).

Để cho phép thay đổi, key và user của key phải có đủ quyền cần thiết trong PRTG, đồng thời công cụ ghi của kết nối phải được bật. Hãy xem lại [Approval mode](/vi/guide/approvals/approval-mode) trước khi cho phép thay đổi.

## Khả năng của agent

| Khả năng | CloudThinker làm gì |
|------------|---------------------------|
| **Khám phá** | Tóm tắt server, sensor, alarm và device |
| **Điều tra alarm** | Đọc các sensor ở trạng thái down, acknowledged, warning và log gần đây |
| **Lịch sử sensor** | Đọc lịch sử gần đây và giá trị channel của một sensor |
| **Thay đổi** | Tạm dừng, tiếp tục, acknowledge, quét, đổi tên hoặc đổi mức ưu tiên của một đối tượng được hỗ trợ |

Tạm dừng một device hoặc group cũng tạm dừng các sensor bên trong. Kết nối này không hỗ trợ xóa, nhân bản đối tượng hay thay đổi các thiết lập khác.

### Xác minh kết nối

```text
Summarize my PRTG sensor and device counts and show the current down and warning sensors
```

Đối chiếu câu trả lời với PRTG. Bài kiểm tra kết nối thành công chỉ xác nhận trạng thái server, nên hãy kiểm tra thêm rằng CloudThinker nhìn thấy đúng các đối tượng giám sát bạn mong đợi.

### Ví dụ prompt

```text
Which PRTG sensors are down, and what are their latest messages?
Show the last 24 hours of history for this sensor
```

## Khắc phục sự cố

<Accordion title="PRTG rejected the API key">
Kiểm tra key còn hiệu lực và được sao chép đúng. Nếu cần, tạo key mới trong PRTG rồi cập nhật kết nối.
</Accordion>

<Accordion title="PRTG answered with a redirect">
Dùng đúng địa chỉ HTTPS của PRTG web server, không kèm đường dẫn. Kiểm tra cả API key.
</Accordion>

<Accordion title="Could not reach the PRTG server">
Kiểm tra địa chỉ server, quyền truy cập mạng và chứng chỉ. CloudThinker yêu cầu chứng chỉ được tin cậy.
</Accordion>

<Accordion title="The API key's user cannot read the server status">
Kiểm tra quyền của user PRTG và quyền truy cập vào server cùng các đối tượng giám sát.
</Accordion>

## Bảo mật

<ConnectionSecurity />

- **Bắt đầu với quyền đọc**: dùng key và tài khoản chỉ giới hạn ở những đối tượng CloudThinker cần.
- **Xem xét thay đổi**: dùng thiết lập Approval và quyền trong PRTG để kiểm soát các thao tác.

*The terms this edition uses with a specific meaning, grouped by the chapter that introduces them. For CloudThinker product terms such as workspace, connection and finding, see the [product glossary](/guide/glossary).*

## The agent loop

| Term | Definition |
|---|---|
| Agentic loop | The four outer stages an agent runs for one problem: Detect, Analyze, Resolve, Validate. The [Leadership Edition](/learn/aio/chapter-4-architecture) introduces it. |
| Step | One pass of the loop inside a stage: assemble context, reason, call a tool or take an action, observe the result. |
| Trajectory | The ordered sequence of steps for one task. It's the unit you replay and evaluate. |
| Agent behavior | The observable decisions, tool calls, evidence use and outcome of the whole agent system on one concrete problem. Source code, prompts or isolated tool tests alone don't establish it. |
| Model-visible context | The exact instructions, messages, tool schemas and tool results sent to a model for one step. It's an input to agent behavior, not proof of it. |
| Determinism boundary | The deliberate line between generative reasoning (selecting, judging) and deterministic code (executing, verifying). The pattern is called "deterministic rails, generative core": the model chooses, code executes. |
| Soak window | A fixed period after a fix during which the agent watches independent signals. When it ends, the agent either declares success with evidence or escalates with a rollback ready. |

See [Chapter 1](/learn/aio-engineer/chapter-1-agent-anatomy).

## Context

| Term | Definition |
|---|---|
| Context budget | How the context window is split across the system core, the task frame, retrieved knowledge and the working set. |
| Compaction | The agent summarizing its own trajectory, with pointers back to the evidence, so context stays small and still auditable. |
| Provenance | A record of where a piece of context or a remembered fact came from, so a person can check it or correct it. |

See [Chapter 2](/learn/aio-engineer/chapter-2-context-engineering).

## Tools, orchestration and economics

| Term | Definition |
|---|---|
| Skill | A reusable, versioned unit of operational know-how, such as "rotate credentials for X". The model picks the skill and fills in its parameters; the skill's tested steps do the work. |
| MCP (Model Context Protocol) | An open standard for exposing tools and data to AI agents, so tools and agents from different vendors work together. |
| Two-engine design | A cheap, always-on sensing engine that filters signals, paired with an expensive resolver engine that investigates only what the sensing engine promotes. |
| Promotion (seam) | The sensing engine's decision to wake the resolver engine for an event. The promotion rate drives fleet cost. |
| Bundle | The versioned unit you deploy for an agent system: prompts, tools, skills, policy, retrieval configuration and model pins. |
| Canary lane | A small slice of production traffic that runs a changed bundle or model first, so you compare it with the current one before a full rollout. |

See [Chapter 3](/learn/aio-engineer/chapter-3-tools-skills-protocol), [Chapter 4](/learn/aio-engineer/chapter-4-orchestration-economics) and [Chapter 9](/learn/aio-engineer/chapter-9-agentops-day-2).

## Security

| Term | Definition |
|---|---|
| Indirect prompt injection | Adversarial instructions planted in content the agent reads (logs, tickets, tool metadata) rather than sent to it directly. |
| Confused deputy | An authorized agent tricked into using its legitimate credentials for an attacker's goal. |
| Taint tagging | Labels that mark where each piece of context came from (system, human, telemetry, third party), enforced through prompting and structure. |
| Ambient credentials | Credentials an executed command can pick up from its environment without asking for them. A sandbox for agent commands should have none. |
| Default-deny egress | Network policy that blocks every outbound destination except an allowlist, and alerts when an agent tries a new one. |
| Tokenization boundary | The point where PII and secrets are replaced with tokens before content reaches a model. Real values are restored only inside your trust boundary, under policy, with an audit event. |

See [Chapter 5](/learn/aio-engineer/chapter-5-threat-model).

## Policy and approvals

| Term | Definition |
|---|---|
| Action class | A category of actions with known properties, such as "restart a stateless pod". Policy applies to classes, not to individual commands. |
| Reversibility | How cleanly and how fast an action can be undone. One of the two axes for classifying actions. |
| Blast radius | How much of the estate, and which tiers of it, an action can touch. The other classification axis. |
| Policy-as-code | Versioned, reviewed rules that decide which action classes need approval, per environment and per agent. |
| Circuit breaker | An automatic halt and escalation when an agent repeats a failing action or the fleet exceeds a change-rate ceiling. |
| Kill switch | A single, drilled action that halts all autonomous execution across the fleet while investigation continues. |
| Trust ladder | Granting an agent more autonomy one action class at a time, based on measured evidence. See [Field Guide §7.3](/learn/aio/chapter-7-humans-on-the-loop). |

See [Chapter 6](/learn/aio-engineer/chapter-6-policy-approvals). In CloudThinker, the approval side of these terms maps to [Approvals](/guide/approvals/overview): Rules decide which agent writes run on their own, wait for a person, or never run.

## Evaluation

| Term | Definition |
|---|---|
| Golden set | A versioned set of replayable evaluation scenarios harvested from real incidents, each with a known answer and an oracle. |
| Replay harness | The tooling that reruns a golden-set scenario against a new prompt, tool, policy or model and scores the result. |
| State-based oracle | A success check that probes actual system state (is the defect still present?) rather than symptoms. It resists false wins where the alert clears but the fault remains. |
| Reward hacking | An agent meeting the measured objective while defeating its intent, for example disabling the fault injector or restart-looping until alerts clear. |
| Diagnosis-mitigation gap | The measured drop between correctly naming a root cause and safely fixing it. Score the two separately. |
| Judge | A model that scores agent outputs against a rubric. It needs calibration against human grades. |
| Evidence integrity | The requirement that every claim in a conclusion traces to data the agent actually retrieved. |
| Regression gate | A check that blocks a prompt, tool, policy or model change when its golden-set scores drop for any incident class. |

See [Chapter 7](/learn/aio-engineer/chapter-7-evaluating-agents).

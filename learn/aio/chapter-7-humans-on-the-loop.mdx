*Agentic operations is a people change wearing a technology costume.*

This chapter covers the shift from doing operations work to supervising it, how each operations role changes, and the four-step trust ladder for handing work to agents. Section 7.5 maps each step of the ladder to CloudThinker settings.

## 7.1 From executor to supervisor

"Human in the loop" means a person sits inside the execution path: every step waits for them. "Human on the loop" means a person supervises: they set intent and policy, approve consequential actions, audit outcomes, and step in by exception.

| | Human in the loop | Human on the loop |
| :---- | :---- | :---- |
| Who runs each step | The engineer | The agent |
| What the engineer does | Triage, run commands, write the fix | Set policy, approve high-impact writes, review outcomes |
| When the engineer is needed | Every step | Novel failures and consequential decisions |
| What limits throughput | Engineer hours | How much autonomy policy allows |

Think of a pilot hand-flying a plane versus a pilot managing the autopilot. The second pilot isn't less important. They're responsible for more of the aircraft with less manual work, and they take the controls when judgment matters most.

Teams that do well redesign roles on purpose. Teams that don't end up with engineers who rubber-stamp approvals they no longer understand.

## 7.2 How roles change

| Role today | What shrinks | What grows |
| :---- | :---- | :---- |
| SRE or on-call engineer | Manual triage, digging through logs, 3 a.m. mechanical fixes | Policy design, agent supervision, engineering for novel failures, reliability architecture |
| DevOps or platform engineer | Ticket-driven provisioning, repeated pipeline fixes | Agent enablement: connections, context and runbooks, golden paths, evaluation |
| Ops manager or IT operations leader | Headcount-based capacity planning, war-room coordination | Autonomy governance, managing which work agents own, outcome-based vendor management |
| Security engineer | Manual hunts for misconfigurations, collecting compliance screenshots | Guardrail design, agent permission design, continuous compliance checks |

Two new jobs appear. Treat both as career paths, not side duties.

- **Agent operations engineer.** Owns the health of the agents themselves: instructions, connections, skills, memory, evaluations, and cost.
- **Autonomy policy owner.** Often a senior SRE or engineering manager. Decides which kinds of action move up the trust ladder, and settles disputes when an agent and a person disagree.

## 7.3 Trust is built in increments

Engineers come to trust an agent in a predictable order. Skipping a step backfires.

| Step | What the agent does | What people do | Move on when |
| :---- | :---- | :---- | :---- |
| **1. Watch it investigate** | Investigates and recommends. Makes no changes. | Compare the agent's root-cause analysis against their own. | Its findings match yours on real incidents. |
| **2. Approve its actions** | Proposes a complete fix and waits. | Approve or reject each write. Every decision is a labeled data point on the agent's judgment. | A kind of action is approved consistently and rolls back cleanly. |
| **3. Pre-approve the routine** | Runs those proven actions alone. | Get notified, and review the record afterward. | A whole domain runs without surprises. |
| **4. Delegate a domain** | Owns a bounded domain end to end, such as idle-resource cleanup, cache management, or certificate rotation. | Audit outcomes on a schedule instead of approving each action. | You keep this level, and review it after any incident. |

The failure mode is consistent: skip steps and you ship an agent that is confidently wrong at 3 a.m. One such incident can set an agentic program back by months. Take the steps in order and autonomy compounds.

A practical test for step 1: give the agent an incident your team has already closed, and compare answers.

```text
Investigate why checkout-api returned 5xx errors between 14:00 and 14:20 UTC yesterday. Give the root cause, the evidence for it, and the fix you would propose. Don't change anything.
```

If its root cause and evidence match your postmortem on several past incidents, you have grounds to move to step 2.

## 7.4 The talent dividend

Framed correctly, agents answer the operations skills shortage instead of threatening the team. The real choice isn't agents versus engineers. It's engineers with agents versus engineers without them.

The payoff of the supervisor model is where senior engineers spend their time: architecture, prevention, and performance instead of interrupt-driven toil. Nobody's career goal is restarting pods at 3 a.m.

## 7.5 The trust ladder in CloudThinker

In CloudThinker, reads always run and every write passes through [Approvals](/guide/approvals/overview). Each step of the ladder is a setting you can see and change.

| Step | How to set it up | Where |
| :---- | :---- | :---- |
| **1. Watch it investigate** | Ask for investigations and say "don't change anything". Set the [Approval mode](/guide/approvals/approval-mode) to **Manual** so any write still waits for a person. | **Workspace Settings → Approvals → Approval mode** |
| **2. Approve its actions** | Answer each approval card in chat. Choose who may answer with [Approvers](/guide/approvals/approvers) groups, and add the two-person rule for the riskiest writes. | **Workspace Settings → Approvals → Approvers** |
| **3. Pre-approve the routine** | Accept an **Allow** [Rule](/guide/approvals/rules) for one operation on one connection that you've approved by hand several times. Agents propose Rules as they work, and **Find rules** proposes more. Nothing changes until an admin accepts. | **Workspace Settings → Approvals → Rules** |
| **4. Delegate a domain** | Run the domain as an [Automation](/guide/automation/automations). Automations default to **Auto · Rules + AI · Refuse**, so a write no Rule allows is refused instead of waiting for someone who isn't there. Review **Activity** on a schedule. | **Workspace Settings → Approvals → Activity** |

Most teams sit between steps 2 and 3: new workspaces start on **Auto · Rules + AI · Ask me**, which runs accepted Rules and asks a person about everything else.

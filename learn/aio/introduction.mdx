This is the CloudThinker field guide to AgenticOps, *Agentic Infrastructure Operations, Leadership Edition* (June 2026). Use it to decide whether, where, and how fast to let AI agents do operational work in your environment.

> *Engineers on the loop, not in the loop.*

## Who this guide is for

It's written for the people who carry the pager and the people who set the budget: SREs, DevOps and platform engineers, infrastructure leaders, CTOs, and CIOs. Regulated industries get extra attention, because there autonomy has to be earned, evidenced, and audited.

Each chapter hands you something to use: a definition to hold vendors to, an architecture checklist, a governance model, a set of KPIs, or a 90-day plan.

## Terms you'll see everywhere

| Term | Meaning |
|---|---|
| **AgenticOps** (agentic infrastructure operations) | AI agents that run the whole operational loop under explicit policy: detect a problem, analyze it, resolve it, and validate the fix. The guide calls this loop DARV (Detect → Analyze → Resolve → Validate). |
| **In the loop** | A person executes every step. The agent, if there is one, only suggests. |
| **On the loop** | A person sets intent, approves consequential actions, and reviews outcomes. Agents do the execution. |
| **Autonomy level (L0 to L4)** | The guide's vendor-neutral scale for how much an agent may do on its own, from observe-only (L0) to fully delegated (L4). Defined in [Chapter 3](/learn/aio/chapter-3-what-is-aio). |
| **Agent washing** | Selling a chatbot, a script runner, or an alert summarizer as an autonomous agent. [Chapter 3](/learn/aio/chapter-3-what-is-aio) gives you five questions to catch it. |
| **MCP** (Model Context Protocol) | An open standard that lets an agent call tools and read data from other systems through one interface. |
| **Toil** | Manual, repetitive operational work that scales with system size and adds no lasting value. |

*備えるべき 5 つの変化、タイミングが重要な理由、そして 2026 年のすべての購入者が直面する 1 つのアーキテクチャの選択: クラウドごとの純正のエージェントか、すべてにまたがる 1 つのプラットフォームか。*

この章では、備えるべき 5 つの変化、ハイパースケーラー純正のエージェントとクラウドをまたぐ 1 つのプラットフォームの選び方、そして最初に何をするかを説明します。各プラクティスの CloudThinker での対応は、[CloudThinker について](/ja/learn/aio/about-cloudthinker)にあります。

## 10.1 近い将来の 5 つの変化

各行は、変化と、今四半期にできる 1 つのことを組み合わせています。

| 変化 | 変わること | 今すべきこと |
| :---- | :---- | :---- |
| **対応から予防へ** | エージェントが過去のインシデントを記憶するようになると、労力はインシデントの修正から防止へと移ります: デプロイ前のリスクチェック、急増前のキャパシティの調整、環境全体のパターンから引き出す設計のアドバイス。 | メモリの層に意図的に情報を与えます: トポロジー、規約、過去のインシデント（[§9.3](/ja/learn/aio/chapter-9-roadmap)）。 |
| **エージェント間のオペレーション** | オペレーションのエージェントは、クラウドプロバイダーのサポートエージェントなど、ベンダーのエージェントに作業を引き渡すようになります。MCP（Model Context Protocol）はすでにエージェントをツールにつないでいます。現在 Linux Foundation の下にある A2A（Agent2Agent）プロトコルは、企業の境界を越えたエージェント間のメッセージを扱います。AWS DevOps Agent は、すでに調査を添付して AWS Support にエスカレーションしています。 | MCP と A2A を話すプラットフォームを選びます。CloudThinker では、[MCP 接続](/ja/guide/connections/mcp)が後から追加するツールに到達し、[A2A API](/guide/api/a2a) によって ServiceNow などの外部のシステムが CloudThinker のエージェントに質問できます（Scale プラン）。 |
| **ガバナンスが法律になる** | AI のガバナンスは、EU AI Act を先頭に、一部の業界で任意のプラクティスから法的な要件へと移りつつあります。規制産業では、監査の証拠を出せないプラットフォームは調達を通過しません。 | 規制当局に求められる前に、[第 6 章](/ja/learn/aio/chapter-6-trust-governance)の制御を構築します。 |
| **自律性が段階的に上がる** | 証拠が積み重なるにつれて、より多くの操作のクラスが承認から事前承認へと移り、エージェントは範囲が限定された領域でワークフロー全体を担うようになります。 | 測定された結果に基づき、操作のクラスを 1 つずつ自律性を上げます（[§7.3](/ja/learn/aio/chapter-7-humans-on-the-loop)）。 |
| **運用モデルがプロダクトになる** | モデルが交換可能になるにつれ、ベンダー間の違いは、オーケストレーション、領域の深さ、蓄積されたコンテキスト、信頼の制御へと移ります。 | どのモデルを使っているかではなく、その 4 つでベンダーを判断します。 |

## 10.2 戦略的な機会

Gartner の 2 つの予測は、矛盾しているように見えます。

- 2026 年末までに、[エンタープライズアプリケーションの 40% にタスク特化型のエージェント](https://www.gartner.com/en/newsroom/press-releases/2025-08-26-gartner-predicts-40-percent-of-enterprise-apps-will-feature-task-specific-ai-agents-by-2026-up-from-less-than-5-percent-in-2025)（2025 年の 5% 未満から増加）。
- 2027 年末までに、[エージェント型 AI のプロジェクトの 40% 以上が中止](https://www.gartner.com/en/newsroom/press-releases/2025-06-25-gartner-predicts-over-40-percent-of-agentic-ai-projects-will-be-canceled-by-end-of-2027)（[§9.4](/ja/learn/aio/chapter-9-roadmap)）。

両者は矛盾しません。合わせると、組織は 2 つのグループに分かれます。段階的な自律性、実際のガバナンス、誠実な測定によって実験から本番へ移る組織と、停滞する組織です。

早く本番に到達すると、効果が積み重なります。

- 解決したインシデントが増えるごとに、エージェントがシステムについて知っていることが増えます。
- 取り除いた労力の 1 時間ごとに、エンジニアリングの作業に戻ります。
- 運用コストが、環境の規模に比例して増えなくなります。

## 10.3 ハイパースケーラーのエージェントか、クラウドをまたぐ 1 つのプラットフォームか

本書で扱ったハイパースケーラーのエージェント（AWS DevOps Agent、Azure SRE Agent、Gemini Cloud Assist）は、作られた目的に対しては優れています。それぞれが自社のクラウドで最も深く、ベンダーの料金モデルに従い、調査に注力しており、自動の修正はよりゆっくりと提供されつつあります。

単一のクラウドを運用しているなら、純正のエージェントは強力なデフォルトです。しかし、ほとんどのエンタープライズはそうではありません。東南アジアの金融業界の多くを含む多くの規制下の環境は、ハイパースケーラーと、ローカルまたはソブリンのクラウド、オンプレミスのシステムを組み合わせています。単一のクラウドのエージェントが 3 つあれば、コンソールが 3 つ、ガバナンスのモデルが 3 つ、監査証跡が 3 つになります。本書が反対している「回転椅子」の問題が、1 つ上の層で起きるのです。

| 観点 | ハイパースケーラー純正のエージェント | クラウドをまたぐ 1 つのプラットフォーム |
| :---- | :---- | :---- |
| カバー範囲 | 自社のクラウドで最も深く、それ以外は部分的 | ローカルクラウドとオンプレミスのシステムを含め、運用するすべてのクラウド |
| 範囲 | まず調査、修正は徐々に提供 | 1 つのポリシーの下での、検出、分析、解決、検証のループ全体 |
| ガバナンス | ベンダーごとに別々の制御と監査証跡 | 1 つの承認ポリシー、1 つの監査証跡、承認する場所は 1 つ |
| データの制御 | ベンダーのクラウドでの処理、制御はさまざま | 識別子のマスキング、自社のモデルのアカウント、プライベートデプロイの選択肢 |
| インセンティブ | ベンダーのエコシステムの中で最適化 | ベンダーの請求を減らす判断も含め、クラウドに中立 |
| 単一のクラウドでの深さ | 最も深い: そのクラウド自身のチームが構築 | 通常、どのクラウドでも、そのクラウド自身のエージェントより浅い |
| セットアップの労力 | 自社のクラウドでは少なく、すでにあるアカウントとベンダーの中で完結 | クラウドごとの接続と認証情報に加え、審査する新しいベンダー |

### 列を選ぶ

4 つの質問に答えてください。

1. 現在、クラウド、ローカルクラウド、オンプレミスの環境をいくつ運用しており、2 年後にはいくつ運用しているか?
2. 規制当局やセキュリティチームは、そのすべてにまたがる 1 つの監査証跡を必要としているか?
3. データを特定の国の中、または自社の境界の中にとどめる必要があるか?
4. 承認の下で修正を実行する必要があるか、それとも今は調査で十分か?

1 つのクラウドを超える、または調査を超えることを示す回答を数えます。

- **0 個:** 純正のエージェントから始めます。
- **1 個:** 純正のエージェントから始めます。ただし、その回答が、1 つの国にとどめる必要があるデータなどの絶対的な要件である場合は、2 個として扱います。
- **2 個以上:** クラウドをまたいで動作するプラットフォームを候補に挙げ、それぞれを [§6.3](/ja/learn/aio/chapter-6-trust-governance) の 8 つのデータ制御の質問と、[§3.3](/ja/learn/aio/chapter-3-what-is-aio) の 5 つの質問のベンダーテストで試します。

このフィールドガイドは、2 列目の側で構築している CloudThinker が発行しています。私たちはその利害を証拠から遠ざけました。ベンチマークには出典を示し、ハイパースケーラーのエージェントは最も強い状態で示し、フレームワークの章はどのプラットフォームを選んでも当てはまります。

上の一覧の同じ 2 つのテストで、私たちを評価してください。[CloudThinker について](/ja/learn/aio/about-cloudthinker)では、このガイドの各プラクティスを、確認できるプロダクトのページに対応付けています。

## 10.4 月曜日にすること

1. **ベースラインを記録する。** ページングとチケットのツールから、90 日分の MTTR、アラートの件数、ページ数をエクスポートします（[§8.2](/ja/learn/aio/chapter-8-measuring)）。
2. **範囲が限定された領域を 1 つ選ぶ。** 頻繁で、繰り返し起き、元に戻せるインシデントがある領域です（[§9.2](/ja/learn/aio/chapter-9-roadmap)）。
3. **すべての書き込みを承認から始める。** CloudThinker では、何かを接続する前に Approval mode を **Manual** に設定し、[実行タイプの行](/guide/approvals/approval-mode#set-a-mode-for-a-run-type)で **Automations** も **Manual** にオーバーライドします。チャットは独自のモードを選べるため、そこでも確認してください。
4. **パイロットを始める前に、自律性のポリシーのオーナーを決める**（[§7.2](/ja/learn/aio/chapter-7-humans-on-the-loop)）。

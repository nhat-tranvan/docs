これは CloudThinker の AgenticOps フィールドガイド *Agentic Infrastructure Operations, Leadership Edition*（2026年6月版、2026年10月最終レビュー）です。自社の環境で、AI エージェントに運用業務を任せるかどうか、どこで任せるか、どれくらいの速さで任せるかを判断するために使ってください。

## このガイドの対象読者

このガイドは、呼び出しを受ける人と予算を決める人のために書かれています。SRE、DevOps とプラットフォームのエンジニア、インフラのリーダー、CTO、CIO です。規制業界には特に重点を置いています。そこでは自律性を獲得し、証拠を示し、監査を受ける必要があるからです。モデルに渡す前のデータのマスキングについては [4.4](/ja/learn/aio/chapter-4-architecture#44-パイプライン内のデータ保護) を、データの所在と監査証跡については[第6章](/ja/learn/aio/chapter-6-trust-governance)を参照してください。

各章では、すぐに使えるものを提供します。ベンダーに守らせる定義、アーキテクチャのチェックリスト、ガバナンスモデル、一連の KPI、または90日間の計画です。

## 主張の要約

1. **[危機](/ja/learn/aio/chapter-1-complexity-crisis)。** インフラの複雑さはヘッドカウントより速く増大し、人、スクリプト、ダッシュボードを増やしても、人間は実行パスに置かれたままです。
2. **[自動化から自律へ](/ja/learn/aio/chapter-2-automation-to-autonomy)。** エージェントは運用ツールの第4世代です。IaC、アラート、スクリプトを再利用し、それらのツールが開けたままにしていたループを閉じます。
3. **[定義](/ja/learn/aio/chapter-3-what-is-aio)。** 本物のエージェントは、目標を持ち、知覚し、推論し、ツールを使い、自己検証します。自律性はアクションクラスと環境ごとに設定するダイヤル（L0〜L4）です。
4. **[アーキテクチャ](/ja/learn/aio/chapter-4-architecture)。** 1つのオーケストレーター、スコープを絞った少数のスペシャリスト、検証を組み込んだ閉じたループ、高コストな推論層の前に置く低コストな検知層、そしてモデルに渡す前にマスクされる機密データです。
5. **[エージェントチーム](/ja/learn/aio/chapter-5-agent-team)。** 各エージェントに安定したスコープと最小権限のアクセスを与え、推論を示しながらチャットでエンジニアと向き合います。
6. **[信頼とガバナンス](/ja/learn/aio/chapter-6-trust-governance)。** エージェントが本番環境に書き込む前に、ガードレール、データ管理、エクスポート可能な監査証跡を整えます。
7. **[Humans on the loop](/ja/learn/aio/chapter-7-humans-on-the-loop)。** エンジニアは作業をする立場から監督する立場へと移り、証明された段階を1つずつ踏んで自律性を委ねます。
8. **[測定](/ja/learn/aio/chapter-8-measuring)。** MTTR、自律解決率、ロールバック率を中心とする8つの KPI で、プログラムがより多くの自律性を獲得するかどうかを決めます。
9. **[ロードマップ](/ja/learn/aio/chapter-9-roadmap)。** 5つの準備の基盤を確認し、終了基準を備えた90日間のパイロットを実施し、その後12か月かけて拡大します。
10. **[今後の展望](/ja/learn/aio/chapter-10-road-ahead)。** 近い将来の5つの変化に備え、クラウドごとのネイティブエージェントか、すべてのクラウドにまたがる単一プラットフォームかを決めます。

## よく出てくる用語

| 用語 | 意味 |
|---|---|
| **AgenticOps**（エージェント型インフラ運用） | 明示的なポリシーのもとで、AI エージェントが運用ループ全体を実行すること。問題を検出し、分析し、解決し、修正を検証します。このガイドではこのループを DARV（Detect → Analyze → Resolve → Validate）と呼びます。 |
| **In the loop** | 人がすべての手順を実行します。エージェントがいる場合でも、提案するだけです。 |
| **On the loop** | 人が意図を設定し、影響の大きいアクションを承認し、結果をレビューします。実行はエージェントが行います。 |
| **自律性のレベル（L0〜L4）** | エージェントが単独でどこまで行ってよいかを示す、このガイド独自のベンダー非依存の尺度です。観察のみ（L0）から完全な委任（L4）まであります。[第3章](/ja/learn/aio/chapter-3-what-is-aio)で定義しています。 |
| **エージェントウォッシング** | チャットボット、スクリプト実行ツール、アラート要約ツールを自律エージェントとして売り込むこと。[第3章](/ja/learn/aio/chapter-3-what-is-aio)では、それを見抜く5つの質問を紹介しています。 |
| **MCP**（Model Context Protocol） | エージェントが1つのインターフェースを通じて、ほかのシステムのツールを呼び出し、データを読み取れるようにするオープン標準です。 |
| **トイル** | システムの規模に比例して増え、永続的な価値を生まない、手作業で繰り返される運用業務です。 |
| **オーケストレーター** | 作業を分割し、スペシャリストに振り分け、人にエスカレーションする調整役のエージェントです。CloudThinker では組み込みの [CloudThinker](/ja/guide/agents/overview) アシスタントがこれにあたり、一時的なサブエージェントを生成します。 |
| **検知層** | シグナルを監視し、どれが本格的な調査に値するかを判断する、低コストで常時稼働のレイヤーです。CloudThinker では [Signals](/ja/guide/pulse/overview) がこれにあたります。 |
| **アクションクラス** | 「Pod を再起動する」や「デプロイをロールバックする」など、エージェントが行える変更の1つの種類です。自律性はアクションクラスごとに設定します。 |
| **影響範囲（Blast radius）** | アクションが失敗した場合に、どれだけのものが壊れるか。影響範囲の小さいアクションから先に自律性が拡大されます。 |
| **BYOC**（bring your own cloud） | ベンダーのプラットフォームを自社のクラウドアカウント内で実行し、データを自社の境界内にとどめることです。 |
| **SLO**（service level objective） | 「チェックアウトのリクエストの99.9%を300ms未満にする」のような、サービスの目標値です。 |
| **MTTR**（mean time to resolve） | インシデントの開始（影響の発生）から解決までの平均時間です。Resolve の Insights も同じ方法で測定します。 |

CloudThinker 独自の製品用語については、[用語集](/guide/glossary)を参照してください。

*CloudThinker は Frontier Investigation Agents を構築しています。クラウド全体で問題を調査し、修正を提案するエージェントです。書き込みは、あなたの承認ポリシーの下でのみ実行されます。*

このページでは、フィールドガイドの各プラクティスをプロダクトのページに対応付けているため、パイロットを実行する前にすべての主張を確認できます。

## CloudThinker とは

すべてのワークスペースには、同じく **CloudThinker** という名前の組み込みのアシスタントが 1 つあります。大きなタスクを、並行して作業する一時的なサブエージェントに分割し、チームは自社のシステムのために[カスタムエージェント](/ja/guide/agents/customize)を追加できます。それらがどう組み合わさるかは、[エージェントの概要](/ja/guide/agents/overview)で説明しています。

エージェントは[接続](/ja/guide/connections/overview)を通じて作業します。接続とは、CloudThinker がシステムに到達するために使う保存された認証情報で、AWS、Azure、Google Cloud、[GreenNode](/guide/connections/greennode) や [FPT Cloud](/guide/connections/fptcloud) などのローカルクラウド、Kubernetes、データベース、オブザーバビリティのツールなどがあります。オンプレミスのシステムには、[VMware](/guide/connections/vmware)、[OpenStack](/guide/connections/openstack)、[SSH](/ja/guide/connections/ssh)、または [Environment](/guide/workers)（CloudThinker が外向きの接続でファイルを読みコマンドを実行する、自社のマシン上のフォルダー）を通じて到達できます。

各リクエストは 1 つのループで実行されます。問題を検出し、根本原因を分析し、承認ポリシーの下で解決し、修正が持続したことを検証します（[詳しい説明](/ja)）。

## プロダクト

| プロダクト | すること | はじめに |
| :---- | :---- | :---- |
| **Resolve** | インシデントを調査し、根本原因を見つけ、承認されると実行される修正を提案します | [Resolve の概要](/ja/guide/incident/overview) |
| **Review** | すべてのプルリクエストやマージリクエストをレビューし、検出事項をコメントとして投稿します | [Review の概要](/ja/guide/code-review/overview) |
| **Cyber** | 稼働中の Web アプリと API をテストし、各検出事項を証拠で証明します | [Cyber の概要](/guide/security/cyber-overview) |
| **Optimize** | クラウドのコストの無駄を見つけ、削減を推奨します | [Optimize の概要](/ja/guide/cost-optimization/overview) |
| **Customize** | ワークスペースでのエージェントの作業方法を形作ります: カスタムエージェント、スキル、認証情報、承認 | [Customize](/ja/guide/agents/customize) |
| **Automation** | スケジュール、Webhook の呼び出し、リポジトリのイベント、プローブでエージェントの指示を実行します | [Automations](/guide/automation/automations) |

これらはすべて、同じ接続、承認ポリシー、監査証跡を共有します。

## フィールドガイドの制御がある場所

| このガイドのプラクティス | CloudThinker の機能 |
| :---- | :---- |
| 自律性は一歩ずつ獲得する（[第 7 章](/ja/learn/aio/chapter-7-humans-on-the-loop)） | [Approval mode](/guide/approvals/approval-mode): **Manual**（すべての書き込みを人が承認）または **Auto**（まず Rules、任意で AI の判断、その後人に確認するか拒否） |
| 操作ごとのアクションポリシー（[第 6 章](/ja/learn/aio/chapter-6-trust-governance)） | 特定の書き込みを許可、先に確認、拒否する [Approval Rules](/guide/approvals/rules) |
| Humans on the loop（[第 7 章](/ja/learn/aio/chapter-7-humans-on-the-loop)） | 承認待ちの操作を確認する人である [Approvers](/guide/approvals/approvers) |
| 機密データをモデルから遠ざける（[§6.3](/ja/learn/aio/chapter-6-trust-governance)） | [Guardrails](/guide/security/custom-guardrails) は、メールアドレス、カード番号、API キー、独自の ID のパターンの代わりに、エージェントにプレースホルダーを見せます |
| 自社のアカウントでのモデルの呼び出し | [BYOK](/ja/guide/byok)（独自の LLM の認証情報を使う） |
| 変更管理のための証拠 | **Settings → Organization → Audit log** の [Audit Logs](/guide/security/audit-logs) |
| データの所在地 | [デプロイの選択肢](/ja/guide/deployment/overview): CloudThinker Cloud と、マシン上で実行する必要がある作業のための Cloud と [Environments](/guide/workers)（ベータ）。Dedicated、セルフホスト、エアギャップのデプロイは、デザインパートナープログラムを通じたアーリーアクセスです。ホスティングのリージョンは公開していないため、お問い合わせください。 |
| メモリの層（[第 9 章](/ja/learn/aio/chapter-9-roadmap)） | [Memory](/guide/memory) |

## 90 日間のパイロットを実行する

[第 9 章](/ja/learn/aio/chapter-9-roadmap)では、推奨のみから始め、証拠に基づいて自律性を獲得することを勧めています。CloudThinker では、最初の週は 3 つの手順です。

<Note>
**前提条件:** Approval mode の変更には、ワークスペースの Admin ロールが必要です。他のロールでは、選択は閲覧のみとして表示されます。
</Note>

<Steps>
  <Step title="ワークスペースを Manual に切り替える">
    新しいワークスペースは **Auto · Rules + AI · Ask me** で始まるため、何かを接続する前に変更してください。**Settings → Workspace → Autonomy → Rules** を開きます。**When no Rule matches** で、**Workspace mode** を **Manual** に設定します。

    [Automations](/guide/automation/automations) を実行する予定がある場合は、同じセクションの **Automations** の行で **Override** もクリックし、**Manual** を選びます。その行はデフォルトで **Auto · Rules + AI · Refuse** で、ワークスペースのモードには従いません。

    **成功時の状態:** 選択に **Manual** と表示され、すべての書き込みが人を待ちます。読み取りは引き続き実行されます。
  </Step>
  <Step title="範囲が限定されたリスクの低いシステムを 1 つ、読み取り専用のアクセスで接続する">
    ステージングの Kubernetes クラスターや、非本番の AWS アカウント 1 つなど、試しても問題のないものを選びます。[AWS](/ja/guide/connections/aws#必要な権限)、[Azure](/ja/guide/connections/azure)、[Google Cloud](/ja/guide/connections/gcp) のセットアップのように、読み取り専用の IAM ロールやサービスアカウントを使ってください。[クイックスタート](/ja/quickstart)に従って、接続に追加します。

    **成功時の状態:** 接続に **Connected** のステータスが表示されます。
  </Step>
  <Step title="ベースラインを記録し、毎月比較する">
    ページングとチケットのツールから、過去 90 日間の平均解決時間（MTTR）と週あたりのページ数をエクスポートし、月次のクラウドのコストを書き留めます。CloudThinker は、接続する前の時間を測定できません。[Resolve Insights](/guide/incident/insights) は、Resolve がアラートのソースからインシデントを受け取り始めると追跡を開始します。どのメトリクスを選ぶかは[第 8 章](/ja/learn/aio/chapter-8-measuring)で説明しています。

    **成功時の状態:** 30 日目、60 日目、90 日目に **Resolve → Insights** と比較するための、日付付きのベースラインがあります。
  </Step>
</Steps>

後の段階（Approvers、Allow Rules、**Auto** への切り替え）については、[§9.6](/ja/learn/aio/chapter-9-roadmap) に従ってください。Allow Rules が書き込みを単独で実行するのは **Auto** の下だけです。**Manual** はすべての書き込みを人のために保留します。

評価には、[§6.3](/ja/learn/aio/chapter-6-trust-governance) の 8 つのデータ制御の質問を持ち込んでください。プライベートデプロイや調達に関する質問は、[チームにお問い合わせ](https://cloudthinker.io/contact)ください。

## はじめに

<AccordionGroup>
  <Accordion title="CloudThinker とは何ですか？">
    CloudThinker はフロンティア調査エージェントを提供しています。これらの AI [エージェント](/ja/guide/agents/overview)がクラウド、コード、ツールに接続し、インシデント、コードリスク、コストの無駄、セキュリティ上の隙の根本原因を突き止め、エンジニアが承認できる修復案を提示します。

    CloudThinker には、課題の種類ごとに 4 つのプロダクトがあります。1 つずつ導入することもできます。

    | プロダクト | できること |
    |---|---|
    | [Resolve](/ja/guide/incident/overview) | インシデントを調査し、根拠とともに根本原因を特定します |
    | [Review](/ja/guide/code-review/overview) | プルリクエストをレビューし、インラインコメントと修正案を提示します |
    | [Cyber](/guide/security/cyber-overview) | テスト権限のあるアプリに動的セキュリティテストを実行し、検出結果を 1 件ずつ追跡します |
    | [Optimize](/ja/guide/cost-optimization/overview) | アイドル状態のリソース、過大なインスタンス、コストの異常をランク付けします |

    さらに 3 つのサポート領域が 4 つのプロダクトすべてにまたがって機能します。これらは自分で調査を行うものではありません。

    | 領域 | できること |
    |---|---|
    | [Approvals](/guide/approvals/overview) | エージェントの変更を、自動実行・人の承認待ち・拒否のいずれにするか判定します |
    | [Customize](/ja/guide/agents/customize) | カスタムエージェント、スキル、ナレッジなど、エージェントの動作を調整します |
    | [Automation](/guide/automation/automations) | スケジュール、Webhook の発火、リポジトリイベント、プローブチェックの発火のタイミングでプロンプトを実行します |
  </Accordion>

  <Accordion title="最初の回答を得るまでどのくらいかかりますか？">
    約 10 分です。[クイックスタート](/ja/quickstart)では、[app.cloudthinker.io](https://app.cloudthinker.io) へのサインイン、1 つのシステムの読み取り専用接続、最初の質問までを案内します。

    **成功の目安:** 回答に、お使いの環境で見覚えのあるサービス、リージョン、リソースが挙がっていること。
  </Accordion>

  <Accordion title="本番環境を危険にさらさずに試せますか？">
    はい。ステージングまたはサンドボックスのアカウントを読み取り専用ロールで接続し、接続の **Allow writes** をオフにすると、CloudThinker はあらゆる変更を拒否します。エージェントは参照のみで、何も変更できません。[クイックスタート](/ja/quickstart)をご覧ください。
  </Accordion>

  <Accordion title="組織とワークスペースの違いは何ですか？">
    **組織**はアカウント全体の単位で、プラン、請求、メンバー一覧、SSO、BYOK、監査ログを扱います。ロールは Owner、Admin、Developer、Viewer です。**ワークスペース**は組織の内側にあり、接続、エージェント、スキル、会話、承認といった実際の作業を扱います。ロールは Admin、Developer、Viewer です。

    | 設定領域 | 対象 | 開き方 |
    |---|---|---|
    | **Admin Settings** | 組織（Owner と Admin のみ） | サイドバー下部のアバター、次に **Admin settings** |
    | **Workspace settings** | 現在のワークスペース | サイドバーの **More → Workspace settings** |
    | **Account Settings** | 自分自身: プロフィール、2FA、自分宛てのメール通知 | アバターメニュー |

    [組織](/ja/guide/organization)と[ワークスペース](/ja/guide/workspaces)をご覧ください。
  </Accordion>

  <Accordion title="チームメンバーを招待するには？">
    組織の Owner または Admin が **Admin Settings → Organization** を開き、**Invite Members** をクリックします。各メンバーに組織ロールが付与され、**More → Workspace settings → Members** から特定のワークスペースだけ別のロールを割り当てることもできます。[メンバーの招待](/ja/guide/organization#invite-members)と[ワークスペースメンバー](/ja/guide/workspace-users)をご覧ください。
  </Accordion>

  <Accordion title="CloudThinker はどのシステムに接続できますか？">
    AWS、Google Cloud、Azure などのクラウドに加え、Kubernetes、データベース、オブザーバビリティツール、Git プロバイダー、CI/CD、Jira・ServiceNow・PagerDuty などのチケット管理ツールに接続できます。それぞれが**接続**であり、1 つのサービス用の認証情報として **More → Workspace settings → Connections** で追加します。

    全一覧は[接続カタログ](/ja/guide/connections/overview#connection-catalog)にあります。一覧にないツールでも、その前段で MCP サーバーを運用していれば、そのサーバーを [MCP 接続](/ja/guide/connections/mcp)として追加することで、エージェントがそのツールを呼び出せます。
  </Accordion>

  <Accordion title="何かをインストールしたり、アーキテクチャを変更したりする必要はありますか？">
    いいえ。CloudThinker はマネージドサービスとして動作し、お客様が追加した接続を通じて、付与された認証情報と権限の範囲でシステムにアクセスします。

    ノート PC や CI ランナーなど、お客様が管理するマシンでコマンドを実行したい場合は、[Environment](/guide/workers)（ベータ）を追加できます。これは任意です。エージェントがプライベートリポジトリや社内ホストにアクセスする必要があるときに使います。Environment は HTTPS で外向きに接続するため、受信ポートを開ける必要はありません。

    これらのドキュメントでは、CloudThinker の送信元 IP アドレスは公開していません。ファイアウォールで許可リストが必要な場合は、[お問い合わせ](https://cloudthinker.io/contact)からご相談ください。
  </Accordion>

  <Accordion title="Slack や Teams から CloudThinker を使うには？">
    組織の Owner または Admin が **Admin Settings → Integrations** を開き、**Slack** カードを開いて **Connect with Slack** をクリックします。その後、ボットをチャンネルに招待します。チャットアプリには Team プラン以上が必要です。Slack と Microsoft Teams では、承認が必要な書き込みは Web アプリへのリンクが表示され、そこで承認します。Google Chat では、カード上に **Approve** と **Reject** ボタンが表示されます。[Slack](/ja/guide/slack-integration)、[Microsoft Teams](/ja/guide/teams-integration)、[Google Chat](/guide/google-chat-integration) をご覧ください。
  </Accordion>

  <Accordion title="接続の削除やデータの削除はどうすればよいですか？">
    ワークスペースの Admin は **More → Workspace settings → Connections** から接続を削除できます。接続、会話、設定を含むワークスペース全体を削除するには、組織の Owner または Admin が **Admin Settings → Workspaces** を使います。復元はできません。[ワークスペースの削除](/ja/guide/workspaces#delete-a-workspace)をご覧ください。
  </Accordion>
</AccordionGroup>

## エージェントと安全性

<AccordionGroup>
  <Accordion title="エージェントとは誰ですか？">
    すべてのワークスペースには、組み込みエージェントが 1 つあります。**CloudThinker** です。常に稼働しており、大きなタスクを一時的なサブエージェントに分担させることもできます。チームは、独自の指示とスキルを持つカスタムエージェントを作成することもできます。[エージェント](/ja/guide/agents/overview)と [Customize](/ja/guide/agents/customize) をご覧ください。
  </Accordion>

  <Accordion title="特別なコマンドを覚える必要はありますか？">
    いいえ。普通の言葉で十分で、メンションがなければ CloudThinker が回答します。3 つの任意の記号を使うと、依頼をより正確にできます。

    | 記号 | 指定するもの | 例 |
    |---|---|---|
    | `@` | エージェント | `@CloudThinker` |
    | `#` | 接続またはナレッジベース | `#aws-prod` |
    | `/` | スキルまたはコマンド | `/resource-rightsizing-analysis` |

    ```text
    Which EC2 instances in us-east-1 averaged under 5% CPU last week?
    @CloudThinker #aws-prod which RDS instances averaged over 80% CPU yesterday?
    Show last month's cost by service as a dashboard
    ```

    ダッシュボードやレポートなど、出力の形式は言葉で依頼してください。構文の全容は[コマンド](/guide/commands)をご覧ください。
  </Accordion>

  <Accordion title="エージェントは本番システムを勝手に変更できますか？">
    設定した範囲内でのみ可能です。読み取りは常に実行されます。すべての**書き込み**（サービスの再起動など、接続先システムを変更するエージェントの呼び出し）は、次のチェックを順に通ります。

    1. **常にブロック**: CloudTrail のログ停止や `kube-system` ネームスペースの削除など、決して実行されない組み込みのリストです。これを上書きするものはありません。
    2. **Rules**: 特定の種類の書き込みを、許可、事前確認、拒否のいずれかにします。**Manual** では、Allow ルールがあっても書き込みは実行されず、人の確認に回ります。Rules が判定を下すのは、CloudThinker がお客様のワークスペースで Rule enforcement を有効にした後だけです。デフォルトではオフで、それまでは Rules は下すはずだった判定を記録するだけで、承認モードのみが判断します（[詳細](/guide/approvals/rules#troubleshooting)）。
    3. **承認モード**: **Manual** はすべての書き込みで人に確認します。**Auto** は AI の判断で安全な書き込みを許可でき、残りは人に確認するか拒否します。
    4. 承認者: 承認または却下します。

    例外が 1 つあります。Review では、**Apply fix** と **Fix all findings** は、人がクリックするとプルリクエストのソースブランチにコミットされ、これらのチェックは経由しません。

    承認モード自体は現在有効で、新しいワークスペースは **Auto · Rules + AI · Ask me** で始まります。3 つに分けて読みます。モードは **Auto**、書き込みは **Rules + AI** の判断で決まり、それでも許可されないものは人の確認を待ちます（**Ask me**）。たとえば、先ほど質問したステージングの Pod の再起動は実行できます。RDS スナップショットの削除は破壊的なため、確認を求められます。

    書き込みが待機状態になると、チャットに **Approve** と **Decline** のある承認カードが表示されます。デフォルトでは、ワークスペースの Developer または Admin なら誰でも応答できます。[承認者](/guide/approvals/approvers)で絞り込めます。Slack や Microsoft Teams からのリクエストは Web アプリへのリンクが表示され、そこで承認します。Google Chat ではカード上で承認または拒否できます。

    すべての書き込みで人の確認を必須にするには、ワークスペースを **Manual** に切り替えます。さらに、[実行タイプ](/guide/approvals/approval-mode#set-a-mode-for-a-run-type)で **Automations**（および変更した他の実行タイプ）も **Manual** に上書きしてください。Automations の行のデフォルトは **Auto · Rules + AI · Refuse** で、ワークスペースの設定には従いません。Automation やチャットが独自のモードを選ぶこともできます。[Approvals](/guide/approvals/overview) と[承認モード](/guide/approvals/approval-mode)をご覧ください。
  </Accordion>

  <Accordion title="CloudThinker にはクラウドでどのような権限が必要ですか？">
    開始時は読み取り専用で十分です。エージェントにできることは 2 つの制御で決まります。

    | 制御 | 場所 | 決まること |
    |---|---|---|
    | 認証情報自体の権限 | お使いのプロバイダー（IAM ロール、サービスアカウント、API トークンのスコープ） | 上限です。エージェントはそれ以上のことはできません。 |
    | **Allow writes** | 接続の詳細パネル | オフ: すべての変更が拒否されます。オン: 変更は Rules と承認モードを通ります。 |

    読み取り専用で始める際に推奨するロールは次のとおりです。

    | クラウド | ロール | セットアップ |
    |---|---|---|
    | AWS | マネージドの `ReadOnlyAccess` ポリシー。CloudShell で実行するセットアップスクリプトが作成します | [AWS セットアップ](/ja/guide/connections/aws#setup) |
    | Google Cloud | **Viewer**（`roles/viewer`）。Optimize では **BigQuery Data Viewer** と **BigQuery Job User** を追加します。 | [Google Cloud](/ja/guide/connections/gcp) |
    | Azure | サブスクリプションの **Reader**。費用の参照には **Cost Management Reader** も付与します | [Azure](/ja/guide/connections/azure) |

    **Allow writes** は AWS、Google Cloud、Azure ではデフォルトでオンのため、変更を防ぐのは読み取り専用の認証情報です。CloudThinker 側でも変更を防ぐには、接続の詳細パネルでスイッチをオフにします。書き込み権限は、エージェントに行わせたい特定の変更に限って追加してください。[接続](/ja/guide/connections/overview)をご覧ください。
  </Accordion>
</AccordionGroup>

## セキュリティとコンプライアンス

<AccordionGroup>
  <Accordion title="CloudThinker はどのようなデータを保存し、どのように保護していますか？">
    | データ | 保護方法 |
    |---|---|
    | 接続の認証情報 | 保存時に暗号化されます。コマンド実行時に CloudThinker のマネージドサンドボックスへ注入され、[Environment](/guide/workers) には送信されません。 |
    | 会話、検出結果、レポート | ワークスペース単位にスコープされ、ロールに応じて閲覧できます。既知のシークレット（接続の認証情報、ワークスペースの認証情報、チャットから保存した値）は、保存前にプレースホルダーに置き換えられます。 |
    | 監査ログ | 90 日間保持され、その後自動的に削除されます。CSV にエクスポートすれば、より長く保管できます |
    | アカウントのパスワード | bcrypt ハッシュとして保存されます |

    アプリと API は HTTPS で提供されます。モデル呼び出しは、組織が [BYOK](/ja/guide/byok)（独自の LLM 認証情報の持ち込み）を使わない限り CloudThinker の LLM プロバイダーに送られます。BYOK を使うと、お客様自身の AWS Bedrock、Anthropic、FPT Cloud、Claude Code、Codex アカウント経由でルーティングされます。

    これらのドキュメントでは、ホスティングリージョン、モデルプロバイダーの名称とデータ条件、学習への利用、会話の保持期間については扱っていません。ベンダーレビューを開始する際に、[お問い合わせ](https://cloudthinker.io/contact)からご確認ください。詳細: [セキュリティとトラスト](/ja/guide/security/overview)。
  </Accordion>

  <Accordion title="チャットにシークレットを貼り付けてしまったらどうなりますか？">
    メッセージは送信されません。CloudThinker が API キー、トークン、パスワード、接続文字列など、認証情報らしい値をスキャンし、**Review detected secrets** ダイアログを開きます。次のいずれかを選びます。

    | ボタン | 結果 |
    |---|---|
    | **Redact from message** | 各値を `[sensitive data removed]` に置き換えます |
    | **Save secrets**（ワークスペースの Admin のみ） | 各値をワークスペースの認証情報として保存し、メッセージを `$KEY` を使う形に書き換えます |

    誤検出は **Mark as not a secret** で除外できます。生の値が会話に入ることはありません。[データ保護](/guide/security/data-protection)をご覧ください。
  </Accordion>

  <Accordion title="SSO や 2FA の強制、監査証跡は利用できますか？">
    | 制御 | 場所 | プラン |
    |---|---|---|
    | 認証アプリ（TOTP） | **Account Settings → 2FA** | すべて |
    | SAML 2.0 または OIDC による SSO、SCIM 同期 | **Admin Settings → Identity and access** | Scale、Enterprise |
    | 監査ログ（90 日間保持、CSV エクスポート） | **Admin Settings → Audit Logs** | Scale、Enterprise |

    [シングルサインオン](/ja/guide/security/sso)、[ロール](/guide/security/roles)、[監査ログ](/guide/security/audit-logs)をご覧ください。
  </Accordion>

  <Accordion title="CloudThinker はコンプライアンス認証を取得していますか？">
    認証や証明は、これらのドキュメントでは公開していません。最新のレポート、セキュリティ質問票、データ処理契約については、[お問い合わせ](https://cloudthinker.io/contact)いただければ、提供可能な資料をお送りします。ベンダーレビューのそれ以外の項目には、今すぐ[セキュリティとトラスト](/ja/guide/security/overview)でお答えできます。
  </Accordion>

  <Accordion title="CloudThinker を自社環境内で実行できますか？">
    デフォルトでは、`app.cloudthinker.io` のマネージドサービスとして動作します。[Environment](/guide/workers) はセルフサービスのベータ版で、お客様が管理するマシンでファイル操作やシェル処理を実行します。専用環境、セルフホスト、エアギャップ環境でのデプロイは、デザインパートナープログラムによるアーリーアクセスで提供しています。[デプロイ](/ja/guide/deployment/overview)をご覧ください。
  </Accordion>
</AccordionGroup>

## 料金とプラン

<AccordionGroup>
  <Accordion title="CloudThinker の料金体系は？">
    組織単位の月額固定料金で、メンバー数は無制限です。各有料プランには、エージェントの作業で消費される単位である**クレジット**が毎月プールとして付与され、すべてのワークスペースで共有します。プランは Free、Team、Scale、Enterprise です。

    | プラン | 月額料金 | 月間クレジット | ワークスペース |
    |---|---|---|---|
    | Free | 無料 | なし | — |
    | Team | $99 | 1,000 | 3 |
    | Scale | $499 | 5,000 | 10 |
    | Enterprise | 個別見積もり | Pay-As-You-Go | 無制限 |

    組織には、Light モデルでのチャット用に毎日 100 クレジットの無料クレジットも付与されます。UTC の午前 0 時にリセットされます。

    各実行は 3 つのモデルティアのいずれかを使い、クレジットの消費量に倍率がかかります。**Light**（0.3x）は簡単な質問向け、**Pro**（1.0x、デフォルト）は日常の作業向け、**Ultra**（1.7x）は最も難しい問題向けです。

    クレジットが尽きると、追加のクレジットが必要な実行はブロックされます。Team 以上では、Owner が [Pay-As-You-Go](/ja/guide/billing/usage#pay-as-you-go) を有効にできます。これは 1 クレジットあたり $0.10 の従量課金によるチャージで、設定した月間上限まで利用できます。現在の料金と上限は[料金プラン](/ja/guide/billing/pricing)、実行によるクレジットの消費は[使用状況](/ja/guide/billing/usage)をご覧ください。
  </Accordion>

  <Accordion title="Free プランでは何ができますか？">
    Light モデルでの直接チャットです。Web チャット、Rooms（他の人と共有するチャット）、CLI からの[ヘッドレスチャット](/ja/guide/cli/headless-chat)が使えます。対話型の [CLI エージェント](/ja/guide/cli/overview)には Team 以上が必要です。Review、Resolve、Optimize、Cyber、Automation など、それ以外の実行は "The Free plan only supports direct chat." というメッセージで拒否されます。これらと Pro・Ultra モデルを利用するには、Team 以上にアップグレードしてください。
  </Accordion>

  <Accordion title="無料トライアルはありますか？">
    対象となる Free 組織では、**Admin Settings → Billing → Upgrade Plan** の Team カードに **Start 14-Day Free Trial** が表示されます。14 日間、Team の機能を利用できます。Pay-As-You-Go（プールを使い切った後の有料チャージクレジット）は、トライアル中はオフのままです。

    Team を継続するには、Owner が **Admin Settings → Billing → Upgrade Plan** を開き、Team カードの **Add payment method** をクリックします。

    <Warning>
      トライアル終了までに支払い方法を追加しないと、組織は Free に戻ります。直接チャット以外の実行は停止し、Pro と Ultra モデルはロックされます。
    </Warning>
  </Accordion>

  <Accordion title="どのプランが必要ですか？">
    | やりたいこと | 最低限必要なプラン |
    |---|---|
    | 無料でチャットから CloudThinker を試す | Free |
    | Review、Resolve、Optimize、Cyber を実行する、または Slack・Teams・Google Chat から回答する | Team |
    | SSO を使う、監査証跡を残す、BYOK を使う、またはワークスペースごとに支出に上限を設ける | Scale |
    | 自社のインフラで CloudThinker を実行する | Enterprise（アーリーアクセスのデザインパートナープログラム経由） |

    プランを変更できるのは、組織の **Owner** のみです。[料金プラン](/ja/guide/billing/pricing)をご覧ください。
  </Accordion>
</AccordionGroup>

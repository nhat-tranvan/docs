**Runbook** とは、「checkout の Pod を再起動する」「データベースをフェイルオーバーする」など、既知の問題を修正するための文書化された手順です。Runbook を Resolve に接続すると、CloudThinker は根本原因分析 (RCA) の間にそれを読み込み、その場で修正を考え出す代わりに、該当する修正を提案します。

<Note>
**Legacy.** Runbooks には、サイドバーとページ上部の名前の横に **Legacy** ラベルが付いています。ここで説明するとおりに機能し、後継機能や削除日は発表されていません。接続したソースは Confluence、GitHub、GitLab に残るため、このページがどうなっても手順は引き続き使えます。どの程度投資するかを検討している場合は、[support@cloudthinker.io](mailto:support@cloudthinker.io) にお問い合わせください。
</Note>

## 仕組み

1. **Runbook ソース** を追加します。Confluence のスペース、GitHub または GitLab のリポジトリ、またはアップロードした Markdown ファイルです。
2. [根本原因分析](/ja/guide/incident/root-cause-analysis) の間に、CloudThinker は有効なソースから、見つけた問題に合う手順を検索します。
3. 手順に何かを変更するコマンドが含まれる場合、各変更は他のエージェントの書き込みと同じく、ワークスペースの [Approvals](/guide/approvals/overview) を通ります。人の判断が必要な場合、実行は承認を待ち、インシデントは **Resolve → Issues** の **Approval needed** フィルターに一致します。
4. すべての試行は、ポリシーの判定、承認、結果とともに **Execution history** タブに記録されます。

<ApprovalDefault />

読み取り専用のコマンド (`kubectl get pods` のように確認するだけのもの) は、アップロードでも接続ソースでも、Runbook の承認を待つことはありません。`kubectl rollout restart` のようにインフラを変更するコマンドは Approvals を通ります。Runbook 独自の効果がどう関わるかは [コマンドの効果を制御する](#コマンドの効果を制御する) で説明しています。

## CloudThinker が Runbook を見つける方法

CloudThinker は、見つけた問題の説明を使って、有効な各ソースを検索します。

| ソース | 検索方法 |
|---|---|
| **Confluence** | 設定したスペースとラベル内のページを全文検索します。影響を受けたサービスに言及しているページが上位になります。 |
| **GitHub**、**GitLab** | ブランチ (既定は `main`) 上で **Path Prefix** の下にあり **File Patterns** に一致するファイルを一覧表示して読み込み、それぞれの関連性を判断します。影響を受けたサービスに言及しているファイルが上位になります。 |
| **Upload** | 選ぶ際に、各アップロードの最初の 200 文字を参照します |

CloudThinker は有効なすべてのソースから候補を集め、修正を計画する前に最も一致するものを読み込みます。

そのため、Runbook はアラートの文面に合わせて書いてください。タイトルと最初の数行に症状とサービス名を入れます。たとえば `# Procedure 7` ではなく `# checkout-api pods in CrashLoopBackOff` とします。アップロードの場合、CloudThinker が選ぶ際に参照するのはほぼ最初の数行だけです。1 ページまたは 1 ファイルにつき 1 つの手順にしてください。

## コマンドが実行される場所

Runbook のコマンドは他のエージェントのコマンドと同じく、対象システムの [connection](/ja/guide/connections/overview) を通じて、その接続の認証情報と権限で実行されます。範囲は認証情報で決まります。読み取り専用の認証情報では、Runbook に何が書かれていても書き込みはできず、**Allow writes** がオフの接続も書き込みを拒否します。すべての書き込みは、決して実行されない呼び出しの一覧も含めて、[Approvals](/guide/approvals/overview#how-a-write-is-decided) も通ります。コマンドが実行されるマシンについては [エージェントが実行される場所](/ja/guide/security/overview#エージェントが実行される場所) を参照してください。

## 前提条件

- ソースを追加、編集、公開、削除するには、ワークスペースの **Admin** ロールが必要です。Developer と Viewer はソースと **Execution history** を閲覧できます。[Roles](/guide/security/roles) を参照してください。
- Runbook アクションの承認者は、Admin ロールではなく Approvals の設定に従います。[approvers](/guide/approvals/approvers) を参照してください。
- Confluence、GitHub、GitLab の場合: Runbook を読み取れる、動作中の接続が必要です。接続がないとソースのフォームを保存できません。
  - Confluence: [Atlassian 接続](/ja/guide/connections/atlassian#必要な権限) を認可したアカウントがそのスペースを開けること。
  - GitHub: CloudThinker アプリが [リポジトリにインストールされている](/guide/connections/github#required-permissions) こと。
  - GitLab: サインインしたユーザーまたはアクセストークンがプロジェクトを読み取れること。[GitLab の権限](/guide/connections/gitlab#required-permissions) を参照してください。
- アップロードの場合: コマンドをフェンス付きコードブロックに入れた `.md` ファイルの手順。

## ソースの種類を選ぶ

| ソースの種類 | 最適な場合 | 絞り込める項目 |
|---|---|---|
| **Confluence** | Runbook が Wiki のスペースにある場合。 | **Confluence Space Key** (空の場合はすべてのスペースを検索) と **Labels** |
| **GitHub** | Runbook がリポジトリ内のファイルである場合。 | **Repository**、**Branch**、**Path Prefix**、**File Patterns** |
| **GitLab** | GitHub と同じで、GitLab 上にある場合。 | **Repository**、**Branch**、**Path Prefix**、**File Patterns** |
| **Upload a runbook** | 手順が少なく、それを置く Wiki やリポジトリがない場合。 | 絞り込む項目はありません。CloudThinker がファイルをワークスペースに保存します |

接続したソースは元のシステムに残ります。CloudThinker は RCA の時点でそれを読み込むため、Confluence での編集や Git でマージされた変更は、再同期なしで次の調査に反映されます。

ソースを追加する前に、その手順の置き場所として Runbook ソースが適切か確認してください。[Teach CloudThinker](/guide/teach-cloudthinker) では、Runbook ソースと CloudThinker に教える他の方法を比較しています。

## Confluence、GitHub、GitLab のソースを接続する

<Steps>
  <Step title="Runbooks を開く">
    サイドバーで **Resolve → Runbooks** (**Configuration** の下) を開きます。ページには **Runbook sources** と **Execution history** の 2 つのタブがあります。まだソースがない場合、ページには各ソースの種類が一覧表示されます。接続済みのものには接続名が、未接続のものには **Connect first** が表示されます。
  </Step>
  <Step title="ソースを追加する">
    **Add source** (または空の状態に表示されるソースの種類) をクリックします。**Add Runbook Source** で **Source Name** (たとえば `SRE Runbooks`) を入力し、**Source Type** を選び、接続を選択します。
  </Step>
  <Step title="CloudThinker の検索範囲を絞り込む">
    Confluence の場合は、`SRE` などの **Confluence Space Key** と、必要に応じて **Labels** を設定します。GitHub または GitLab の場合は **Repository** を選び、必要に応じて **Branch**、`docs/runbooks` などの **Path Prefix**、`*.md` などの **File Patterns** を設定します。**Add Source** をクリックします。
  </Step>
</Steps>

**成功時の状態:** ソースが種類と範囲 (たとえば `GitHub · acme/runbooks · docs/runbooks`) とともに一覧に表示され、トグルがオンになっています。

接続したページについては、アップロードの場合のようにコマンドを抽出したり分類したりはしません。フォームの注記には、ソースのすべてのコマンドに承認が必要と表示されます。実際には、変更を伴うすべてのコマンドが対象です。読み取り専用のコマンドは Runbook の承認なしで実行され、変更はワークスペースの Approvals を通ります。これらのソースには、コマンドごとに設定する効果はありません。

## Markdown の Runbook をアップロードする

<Steps>
  <Step title="アップロードのダイアログを開く">
    **Resolve → Runbooks** で **Upload runbook** (または空の状態では **Upload a runbook**) をクリックします。
  </Step>
  <Step title="ファイルを追加する">
    `.md` ファイルを最大 20 個、各 5 MB までドラッグします。各ファイルには **Runbook name** が付き、アップロード前に編集できます。
  </Step>
  <Step title="アップロードする">
    **Upload** をクリックします。CloudThinker がコードブロックからコマンドを取り出す間、各ファイルには **Uploading...**、続いて **Extracting commands...** と表示されます。
  </Step>
</Steps>

**成功時の状態:** 各ファイルが個別のソースとして一覧に表示され、すぐに公開され検索可能になります。アップロードが下書きとして作成されることはありません。行の本のアイコンをクリックすると読み取り専用のプレビューが開き、元の Markdown をダウンロードする **Download** ボタンがあります。

次のように書かれた Runbook は、CloudThinker に明確で切り分けやすいコマンドを渡します。

````md
# Checkout pods in CrashLoopBackOff

## Check
```bash
kubectl get pods -n checkout
kubectl logs deploy/checkout-api -n checkout --tail=200
```

## Fix
```bash
kubectl rollout restart deploy/checkout-api -n checkout
```
````

このファイルから、CloudThinker は `kubectl rollout restart` を承認が必要な、変更を伴うコマンドとして記録します。2 つの読み取り専用コマンドは記録されず、CloudThinker は RCA の間に Runbook の承認なしでそれらを実行できます。

アップロード時に、CloudThinker のバックエンドが呼び出す AI モデルがフェンス付きコードブロックを読み、何かを変更するコマンドだけを残します。パイプラインは、どこか一部でも書き込みを行えば変更を伴うものとして数えます。残す各コマンドはコードブロック内にある必要があるため、本文の文章からは何も記録されません。モデルのステップが失敗した場合は、確認専用のコマンドの固定リスト (`kubectl get`、`kubectl logs`、`cat`、`grep` など) で判定し、リストにないものはすべて変更を伴うものとして扱います。モデルの呼び出し先については [CloudThinker が扱うデータ](/ja/guide/security/overview#cloudthinker-が扱うデータ) を参照してください。

誤って分類されたコマンドが承認を回避することはありません。モデルが見逃した書き込みも、他のエージェントの書き込みと同じく、接続の認証情報と **Allow writes** の設定、そして [Approvals](/guide/approvals/overview) を通って実行されます ([コマンドが実行される場所](#コマンドが実行される場所) を参照)。ワークスペースで Runbook のコマンド効果が有効な場合は、記録されたコマンドをレビューできます。[コマンドの効果を制御する](#コマンドの効果を制御する) を参照してください。

アップロードした Runbook を変更するには、そのソースを削除して新しいバージョンをアップロードします。アップロードをその場で編集する方法はありません。古い **Execution history** の行には Runbook のタイトルが残りますが、削除されたソースとの関連付けはなくなります。

<Warning>
新しいアップロードには新しいポリシーが割り当てられるため、すべてのコマンドが再び **Require Approval** から始まります。古いアップロードで設定した **Allow** や **Deny** は失われます。
</Warning>

## コマンドの効果を制御する

**効果 (effect)** とは、変更を伴うコマンドに対する Runbook 独自のルールです。ワークスペースの [Approvals](/guide/approvals/overview) のモードもすべての変更に適用されます。Runbook のコマンド効果がオフの場合 (ほとんどのデプロイメントがこれに該当します)、効果は適用されず、Approvals だけが判定します。既定の **Auto · Rules + AI · Ask me** モードでは、AI の判断によって確認なしで変更が実行されることがあり、Allow の [Rule](/guide/approvals/rules) でも同様です。すべての Runbook の変更で人を待たせるには **Manual** を選びます。使える効果はソースの種類によって異なります。

| ソースの種類 | 効果 | 既定値 |
|---|---|---|
| Confluence、GitHub、GitLab | 常に **Require Approval** | Require Approval |
| Upload | Runbook のコマンド効果が有効な場合のみ、コマンドごとに **Allow**、**Require Approval**、**Deny**。ほとんどのデプロイメントでは **Require Approval** のみ。 | Require Approval |

| 効果 | 何が起きるか |
|---|---|
| **Allow** | 確認なしで実行します |
| **Require Approval** | 人が承認または拒否するまで待ちます |
| **Deny** | 実行しません |

各アップロードには `Manual Runbook: <runbook name>` という名前の独自のポリシーが割り当てられ、抽出されたコマンドごとに 1 つのステートメントがあります。Runbook のコマンド効果は、ほとんどのデプロイメントでオフです。オンの場合は **Settings → Workspace → Autonomy → Runbooks** にあり、そこでポリシーを開いてコマンドの効果を変更できます。たとえば、頻繁に実行する安全な再起動を **Allow** にできます。この機能がない場合、すべてのコマンドはポリシー上 **Require Approval** のままで、変更が待機するかどうかは Approvals のモードが決めます。お使いのデプロイメントで有効にできるか問い合わせるには、[support@cloudthinker.io](mailto:support@cloudthinker.io) にメールしてください。

## Runbook アクションを承認する

インシデント中に CloudThinker が変更を伴うコマンドを実行しようとすると、インシデントは承認を待ち、**Resolve → Issues** の **Approval needed** フィルターに一致します。

<Steps>
  <Step title="会話を開く">
    インシデントで **More actions** を開き、**Open AI Conversation** をクリックします。
  </Step>
  <Step title="判断する">
    承認カードで提案されたコマンドを読み、**Approve** または **Decline** をクリックします。承認すると実行が続行されます。拒否するとそのアクションは停止します。カードにはコマンドを編集する欄はありません。別のことを実行させたい場合は、拒否してから会話で希望を伝えてください。
  </Step>
</Steps>

**成功時の状態:** インシデントが **Approval needed** に一致しなくなり、**Execution history** タブで実行に **Approved** と表示されます。拒否したアクションはそこに **Rejected** と表示されます。

誰かが判断するまで、実行はそのステップで待機します。承認できる人はワークスペースの承認設定に従います。[approvers](/guide/approvals/approvers) を参照してください。承認できない場合、カードには承認者を待っていると表示されます。会話を開始した人には **Notify approvers** ボタンも表示されます。承認リクエストをメールやチャットで受け取るには、[Notifications](/ja/guide/notifications) で **Agent approvals** をオンにします。

## 実行内容をレビューする

**Resolve → Runbooks** の **Execution history** タブを開きます。各行が 1 つの Runbook アクションです。

| 列 | 値 | 分かること |
|---|---|---|
| **Runbook** | Runbook のタイトル (ソースへのリンク付き) | CloudThinker が使った手順 |
| **Policy** | Auto Execute、Requires Approval、Denied、Per Command | 誰かに確認する前にポリシーが何を決めたか: **Auto Execute** はアクションを許可し、**Requires Approval** は人に回し、**Denied** はブロックしました。**Per Command** はアップロードした Runbook を示し、各コマンドは実行時にそれぞれの効果と照合されます。 |
| **Approval** | Pending、Approved、Rejected | 確認を求められた場合に、人が何を決めたか |
| **Status** | 下の表を参照 | 実行時に何が起きたか |
| **Created** | タイムスタンプ | CloudThinker が提案した日時 |

| Status | 意味 |
|---|---|
| 空 | 何も実行されていません。アクションが人を待っているか、拒否されたか、ポリシーで拒否されました |
| **Not Started** | 承認済み、またはポリシーで許可されています。実行中を示す別のステータスはないため、キューに入っているか、まだ実行中の可能性があります。更新すると **Completed** または **Failed** が表示されます。このままの場合は、インシデントを開き、**More actions** → **Open AI Conversation** でコマンドがまだ実行中か確認してください。 |
| **Completed** | コマンドが実行され、完了しました |
| **Failed** | コマンドが実行され、エラーを返しました。再試行する前に結果を読んでください。 |

インシデントをクローズする前に **Status** を確認してください。**Approved** は人が許可したことを意味します。コマンドが実行されたことを意味するのは **Completed** だけです。

## ソースを管理する

ソースの行にカーソルを合わせると、アクションが表示されます。

| アクション | 内容 |
|---|---|
| トグル | 削除せずにソースをオフにします。CloudThinker は無効なソースを検索しません。 |
| Edit | 接続ソースの名前または範囲を変更します。 |
| Preview (本のアイコン) | アップロードした Runbook の内容を表示します。 |
| Publish | まだ **Draft** と表示されている古いアップロードのソースにのみ表示されます。新しいアップロードは常に公開されます。Admin が公開するまで、CloudThinker は下書きを検索しません。 |
| Delete | 確認のあとにソースを削除します。 |

## トラブルシューティング

<AccordionGroup>
  <Accordion title="ソースの種類がグレー表示になっている、または Connect first と表示される">
    ソースのフォームには、そのプラットフォームの接続が必要です。行をクリックして接続するか、[Connections](/ja/guide/connections/overview) から追加し、戻って **Add source** をクリックしてください。
  </Accordion>
  <Accordion title="RCA の間に CloudThinker が Runbook を使わなかった">
    ソースのトグルがオンで、**Draft** と表示されていないことを確認してください。次に範囲を確認します。**Confluence Space Key**、**Path Prefix**、**File Patterns** の値が誤っていると、ファイルが見えなくなります。Runbook には症状とサービスを示すタイトルを付けてください。[CloudThinker が Runbook を見つける方法](#cloudthinker-が-runbook-を見つける方法) を参照してください。
  </Accordion>
  <Accordion title="アップロードが拒否された">
    受け付けるのは 5 MB までの `.md` ファイルだけで、1 回のアップロードにつき最大 20 個です。大きな Runbook は手順ごとに 1 ファイルに分割してください。
  </Accordion>
  <Accordion title="アップロードからコマンドが取り込まれなかった">
    コマンドはフェンス付きコードブロック内にある必要があります。通常の段落内のコマンドや、読み取り専用のコマンドだけの場合、承認対象は何も生成されません。
  </Accordion>
  <Accordion title="インシデントが待機したまま進まない">
    Runbook アクションが保留中です。インシデントを開き、**More actions** → **Open AI Conversation** をクリックして、**Approve** または **Decline** をクリックしてください。
  </Accordion>
</AccordionGroup>

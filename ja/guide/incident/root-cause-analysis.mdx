根本原因分析（RCA）は、CloudThinker がインシデントが起きた理由を突き止めるステップです。インシデント、その背後にあるアラート、接続されたシステムを読み、考えられる説明を検証し、文章の判定、障害がどう展開したかを示す図、修正の提案の一覧を渡します。あなたはそれを確認し、次に何をするかを決めます。

RCA は [Resolve](/ja/guide/incident/overview) の Investigate の段階です。すでにセットアップした[接続](/ja/guide/connections/overview)を通じて、ログ、メトリクス、トレース、最近の変更、依存関係を読み、それらの接続が到達できるものにしか到達できません。調査は読み取りのみです。変更はすべて [runbook](/ja/guide/incident/runbooks) と [Approvals](/guide/approvals/overview) の設定を経由します。モデルが何を見るか、シークレットがどう扱われるかは、[Data protection](/guide/security/data-protection) を参照してください。

## 始める前に

- クラウドアカウント、Kubernetes クラスター、モニタリングツールなど、関係するシステムへの[接続](/ja/guide/connections/overview)が少なくとも 1 つ。RCA は読めるものしか確認できません。
- 調査の開始、提案の決着、インシデントのステータスの変更（クローズを含む）には、ワークスペースの **Admin** ロール。Developer と Viewer は結果を読めます。[Roles](/guide/security/roles) を参照してください。
- クレジット。各調査はエージェントの作業で、自動で開始されるものも含め、他の実行と同様にクレジットで課金されます。[使用量](/ja/guide/billing/usage)で支出を確認し、[クレジット上限](/guide/billing/credit-limits)でワークスペースに上限を設定してください。自動の実行を止めるには、Webhook の **Auto-investigate** をオフにするか、**AI auto-investigate** をオフにします。[What starts an investigation](/guide/incident/settings#what-starts-an-investigation) を参照してください。

## 調査が開始される方法

| インシデントの出所 | RCA が開始されるタイミング |
|---|---|
| [Signals](/ja/guide/pulse/overview)（アラートのソース） | **AI auto-investigate** がオンで、Webhook のオプションが許可している間、トリアージがインシデントを開いたり再オープンしたりしたときに自動で。完全なルールは [What starts an investigation](/guide/incident/settings#what-starts-an-investigation) にあります。 |
| [Log Incident](/ja/guide/incident/manual-logging)（人） | フォームを送信した直後。**AI auto-investigate** がオフでも開始されます。 |
| まだ調査のないインシデント。**Not started** で待機します。 | **Investigate** をクリックしたとき。 |
| 一度も調査されていないのに **Investigating** に設定されたインシデント（誰かがステータスバッジから **Investigating** を選んだ場合など）。**Not started** で待機します。 | **Investigate** をクリックしたとき。 |

## 調査を実行する

<Steps>
  <Step title="インシデントを開く">
    **Resolve → Issues** に移動し、キューからインシデントを選びます。
  </Step>
  <Step title="開始していなければ RCA を開始する">
    インシデントが一度も調査されていない場合は、インシデントのヘッダーの **Investigate** をクリックします。

    **成功時の状態:** インシデントが **AI is handling** に移り、インシデントのページに **CloudThinker is investigating** と **Watch live** ボタンが表示されます。
  </Step>
  <Step title="経過を追う（任意）">
    **Watch live** をクリックすると、CloudThinker が作業している会話が開きます。実行される各チェックをその場で確認できます。検出事項は保存されるたびにインシデントのページにも表示されます。
  </Step>
  <Step title="判定を読む">
    分析が完了すると、インシデントは **Needs you** に移ります。ステータスが **Identified** のインシデントでは、結果の見出しが **Root cause** になります。すべてのステータスとその行き先は[調査の結果](#調査の結果)に一覧があります。ページの各セクションは[結果を読む](#結果を読む)で説明しています。

    新しい検出事項が表示されず、**Watch live** に動きがない場合は、[Investigation stuck](/guide/incident/troubleshooting#investigation-stuck) を参照してください。
  </Step>
  <Step title="各提案を決着させる">
    **Actions** の各項目を、完了または却下としてマークします。[修復の各提案を決着させる](#修復の各提案を決着させる)を参照してください。
  </Step>
  <Step title="インシデントをクローズする">
    インシデントのヘッダーのステータスバッジをクリックし、**Resolved** または **False alarm** を選んで、**Change Status** で確定します。ステータスを変更できるのはワークスペースの Admin だけです。他のロールにはメニューのないバッジが表示されます。

    | 現在のステータス | メニューのクローズの選択肢 |
    |---|---|
    | **Open**、**Acknowledged**、**Investigating**、**Identified** | **Resolved** または **False alarm** |
    | **On hold** | **Resolved** のみ。**False alarm** にするには、まず **Investigating** に移します。 |
    | **Not found** | どちらもありません。メニューには **Investigating** しかありません。クローズするには、**Investigating** を選んでから再度バッジを開き、**Resolved** または **False alarm** を選びます。 |

    **成功時の状態:** インシデントが **Resolved** または **Dismissed** のグループに移ります。
  </Step>
</Steps>

## 調査のキュー

**Resolve → Issues** は、インシデントをあなたに求めることでグループ化します。

| グループ | 含まれるもの |
|---|---|
| **AI is handling** | 調査が実行中 |
| **Needs you** | 判定ができている、調査が入力待ちで一時停止している、またはチェックの結果が決定的でない |
| **Not started** | まだ調査が実行されていないか、キューに入っている。**Investigate** をクリックして開始します。 |
| **Resolved** | **Resolved** または **Auto-resolved** としてクローズ済み |
| **Dismissed** | **False alarm** としてクローズ済み |
| **Triaged** | トリアージがアラートを確認し、対応は開始されなかった（アラートに対応が不要と判断した場合など） |

## 結果を読む

インシデントのページは、答えを最初に、裏付けとなる資料をその下に置きます。

答えの見出しは、調査がどの段階にあるかを示します: **Triage**、**Working theory**、**Root cause**、**On hold**、**No root cause found**、**False alarm**、**Resolution**。その横の証拠のラベル（下記）が証拠の強さを示し、セッションの実行中は **Running** が表示されます。判定の下にある **Impact**、**Cause**、**Fix**、**Risk and undo**、**Confidence** などの短い行がそれを要約し、根本原因を見つけるまでにかかった時間も示します。

答えの下の各セクションは、クリックすると開きます。

| セクション | 示す内容 |
|---|---|
| **How it happened** | 最初の障害から目に見える影響までの因果グラフ |
| **Actions** | 修正の提案。それぞれに優先度があります: **Critical**、**High**、**Medium**、**Low**。**Critical** から順に取り組んでください。 |
| **What happened** | インシデントのタイムライン |
| **Evidence** | 判定の根拠となる検出事項 |
| **Full analysis** | 一覧にする検出事項がない場合の、完全な文章の分析 |
| **Investigation trail** | 一覧にする検出事項がない場合の、CloudThinker が行ったすべてのステップ |
| **Affected services** | 関係するサービスと依存関係 |
| **Duplicate webhooks** | 同じアラートの重複した配信（ある場合）。重複が多い場合は、再試行するソースを示しています。ツールの再試行の設定、または [Limits and responses](/ja/guide/incident/webhook-integrations/overview#制限とレスポンス) で Pulse が重複の検出に使うフィールドを確認してください。 |
| **Was Resolve's diagnosis right?** | 判定へのサムズアップまたはダウン。これらの回答は **Accuracy and trust** タブに反映されます。[Mark a diagnosis right or wrong](/guide/incident/insights#mark-a-diagnosis-right-or-wrong) を参照してください。 |

CloudThinker が重大度が誤っていると考える場合、インシデントの **More actions** メニューに、提案されたレベルとともに **AI suggests** が表示されます。クリックすると現在のレベルと提案されたレベルが表示されるので、提案されたレベルを **Apply** するか、現在のレベルを **Keep** します。

短い結果は、たとえば次のようになります。

```text
Root cause                                     Strong evidence
checkout-api pods ran out of memory after payment-client v2.3 doubled
its connection pool. Restarts cleared it for minutes at a time.

Actions
High    Roll back payment-client to v2.2 on prod-eu
Medium  Set a pool size limit in the payment-client config
```

### 証拠のラベル

見出しの横のラベルは、CloudThinker が自身の証拠をどれだけ強いと評価しているかを示します。

| ラベル | 意味 | 扱い方 |
|---|---|---|
| **Strong evidence** | システムのデータと照合して確認済みで、**Evidence** に示されています | 根拠となる検出事項を確認してから対応します。変更は引き続き runbook と Approvals の設定を経由します。 |
| **Probable** | 証拠から推論したもので、直接は確認されていません | 対応する前に証拠を確認します |
| **Possible** | 判定が仮定に基づいています | 手がかりとして扱います。アクセスやコンテキストを追加し、[再調査](#再調査)します。 |

**Possible** は裏付けの弱い判定です。**Not found** は、判定がまったくないことを意味するステータスです。

### 修復の各提案を決着させる

**Actions** の提案にカーソルを合わせ、その **More remediation actions** メニューを開いて選びます。

| 操作 | 使う場面 | メモに書く内容 |
|---|---|---|
| **Mark as Done** | チームが作業を行った | 実際に行ったこと |
| **Dismiss** | 当てはまらない、または行う価値がない | その理由 |

メモは任意で、インシデントを確認する人のために提案に残ります。決着は最終的です。提案をマークするとメニューが消え、元に戻すことはできません。後の調査のセッションで上書きされることもありません。

## 調査の結果

各ステータスはキューのグループに対応します。

| ステータス | 意味 | キューのグループ |
|---|---|---|
| **Open**、**Acknowledged** | まだ結果がない。**Acknowledged** は対応者が担当していることを意味します。 | 調査の前は **Not started**、調査の完了後は **Needs you** |
| **Identified** | 根本原因が見つかった | **Needs you** |
| **On hold** | 人からの情報、アクセス、判断を待っている | **Needs you** |
| **Not found** | 利用できる証拠では根本原因を裏付けられなかった | なし。キューには表示されません。 |
| **False alarm** | アラートは実際の問題ではなかった | **Dismissed** |
| **Resolved** | 人が関与して修正・クローズされた | **Resolved** |
| **Auto-resolved** | 誰も関与せず、エージェントが修正・クローズした | **Resolved** |

インシデントは、次のいずれかの理由で **Needs you** にとどまることもあります。

| 表示 | 意味 | 対応 |
|---|---|---|
| 結果はあるが、ステータスが **Open**、**Acknowledged**、**Investigating** のまま | 調査がステータスを動かさずに完了した | 結果を読み、自分でステータスを設定します |
| 行に **Failed** と表示され、インシデントのページに調査が停止したと表示される | セッションが失敗したか、キャンセルされた | **Retry investigation** をクリックします |
| トリアージのメモはあるが、判定がない | トリアージがアラートに対応が必要かを判断できなかった | **View origin** で元のアラートを読み、自分でステータスを設定します |

<Warning>
既知の制限: **Not found** のインシデントはキューから外れます。どのキューのグループやフィルターにも表示されません。そのページを離れる前に、先に進めるか URL をコピーしてください。

- 作業を続けるには、不足している[接続](/ja/guide/connections/overview)を追加し、ステータスバッジをクリックして **Investigating** を選びます。以前に調査されたインシデントは **Not started** ではなく **Needs you** に戻り、そこで[再調査](#再調査)できます。
- 取り下げるには、**Investigating** を選んでから再度バッジを開き、**Resolved** または **False alarm** を選びます。
- 後で戻るには、インシデントの URL をブックマークします。それが戻る唯一の方法です。
</Warning>

## 再調査

インシデントには 1 つの調査記録があります。セッションとは 1 つの調査の会話です。その会話で再度依頼しても、同じセッションのままです。トリアージが新しいアラートをインシデントに対応付けると、後のセッションが開始されることがあります。

**Investigate** ボタンは最初の調査の前にしか表示されません。新しいアクセスやコンテキストで再調査するには:

<Steps>
  <Step title="不足していたものを追加する">
    不足している[接続](/ja/guide/connections/overview)を追加するか、CloudThinker に使わせたいコンテキストを書き留めます。
  </Step>
  <Step title="会話を開く">
    インシデントのヘッダーで、**More actions → Open AI Conversation** を開きます。
  </Step>
  <Step title="もう一度調べるよう依頼する">
    何が変わったかを伝えます。例: `I've connected the prod-eu Datadog account. Re-check the root cause.`

    **成功時の状態:** 記録された検出事項がインシデントのページに表示され、根本原因が変われば上部の答えが更新されます。何も変わらない場合、その返信でインシデントは変わっていません。
  </Step>
</Steps>

セッションが失敗した場合（キューの行に **Failed** と表示されます）、インシデントのページに調査が停止したと表示されます。そこで **Retry investigation** をクリックします。Admin のみです。

## 相関するインシデント

複数のアラートが同じ原因を持つ可能性が高い場合、Resolve はそれらを 1 つの親インシデントの下にまとめ、そこで 1 つの RCA を実行します。まとめられたアラートを開くと、**Part of a Correlated Group** カードが表示されます。

| 選択肢 | 動作 |
|---|---|
| **View Parent Analysis** | 調査を持つ親インシデントを開きます |
| **Promote to Standalone** | アラートを切り離して独立したインシデントにします。確定後、今すぐ RCA を開始するか、後に残すかを選びます。Admin のみです。 |

グループ化は Pulse で始まります。関連するアラートが正しくまとまるよう、各 Webhook で **Resource ID Path** を対応付けて 1 つの障害の繰り返しがまとまるようにし、**Service Path** を 1 つのサービス名に対応付けて 1 つのサービスに関する異なるアラートが合流できるようにしてください。[How signals join a cluster](/ja/guide/pulse/clusters#シグナルがクラスターに合流する仕組み) を参照してください。

## 結果を共有・エクスポートする

インシデントの **More actions** メニューから:

- **Download analysis PDF** は分析を PDF として保存します。
- **Open AI Conversation** は調査の会話全体を開き、そこでフォローアップの質問ができます。
- **View origin** はインシデントの元になったアラートと Pulse のデータを表示します。

## トラブルシューティング

| 問題 | 対処 |
|---|---|
| **Investigate** ボタンがない | インシデントにすでに調査がある（[再調査](#再調査)を参照）、セッションが実行中、または相関するグループの一部です（**View Parent Analysis** を使います）。Admin ロールも必要です。 |
| アラートが調査されたインシデントにならなかった | **AI auto-investigate**、Webhook の **Auto-investigate** と最低の重大度を、[What starts an investigation](/guide/incident/settings#what-starts-an-investigation) と照合してください。今すぐ開始するには、**Resolve → Signals** でそのクラスターの **Open incident** と **Send to triage** をクリックします。 |
| インシデントが **Not started** のまま | **Investigate** をクリックします。 |
| 判定が **Possible**、またはステータスが **Not found** | RCA が十分に読めませんでした。不足している[接続](/ja/guide/connections/overview)を追加してから、会話で再度依頼してください。**Not found** のインシデントは、まず **Investigating** に戻す必要があります。[Not found の警告](#調査の結果)と[再調査](#再調査)を参照してください。 |
| **On hold** のまま進まない | **Open AI Conversation** で会話を開き、CloudThinker が求めたことに答えてください。 |

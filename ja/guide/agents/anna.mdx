Anna は CloudThinker のコーディネーション専門家であり、複数のドメインにまたがるマルチエージェントオーケストレーション、複雑なプロジェクト管理、エグゼクティブレポーティング、戦略的オペレーションを専門としています。

---

## Anna が解決する問題

複雑なクラウドオペレーションは複数のドメインにまたがります — クラウド移行にはインフラ（AWS）、セキュリティ要件（IAM、コンプライアンス）、データベース戦略（移行、レプリケーション）、コンテナオーケストレーション（Kubernetes）が関与します。しかし、専門エージェントとツールはサイロ化されています。Cost Explorer は Security Hub と連携せず、Security Hub はデータベース監視と連携せず、データベース監視は Kubernetes ツールと連携しません。

本番インシデントや大規模プロジェクトにクロスドメインのコーディネーションが必要なとき、その作業はシニアエンジニアに手動で押し付けられます：
- ダッシュボードとツールを行き来して各ドメインからデータを収集する
- 検出結果を整合性のある全体像に統合する
- ステータスレポート、エグゼクティブサマリー、取締役会向けプレゼンを作成する
- 異なるツールチェーンを持つチーム間で依存関係とタイムラインを追跡する

このコーディネーションのオーバーヘッドこそが、大規模な取り組み（クラウド移行、セキュリティ修復、四半期レビュー）が数日ではなく数週間かかる理由です。

## 他のツールが見逃すこと

| ツール | できること | 不足していること |
|------|-------------|----------------|
| **Jira / Linear** | プロジェクトトラッキングとチケット管理 | タスクを追跡するが、調査・分析・検出結果の統合はできない |
| **ServiceNow** | ITSM ワークフローとインシデント管理 | プロセス重視、低速、ドメインをまたぐ AI 分析なし |
| **Confluence / Notion** | ドキュメンテーションと知識管理 | 受動的なドキュメンテーション、手動データ入力が必要 |
| **スプレッドシート + スライド** | 手動のコーディネーションとレポーティング | 完全に手動、ライブインフラデータとの接続なし |
| **シングルエージェント AI ツール** | ドメインごとに 1 つの AI | コスト + セキュリティ + データベース + K8s を 1 つのワークフローで調整できない |

Anna は、マルチドメインオペレーションをオーケストレーションし、[Alex](/ja/guide/agents/alex)、[Oliver](/ja/guide/agents/oliver)、[Tony](/ja/guide/agents/tony)、[Kai](/ja/guide/agents/kai) からの検出結果を同時に統合し、エグゼクティブレディな成果物を — すべて 1 つのプロンプトから — 生成できる唯一のエージェントです。

---

## Anna の仕組み

1. **複雑なリクエストを受信** — 複数のドメインにまたがるプロジェクト、調査、またはレポーティング要件
2. **並列サブタスクへの分解** — どのエージェントが貢献する必要があるか、各エージェントが何を調査すべきかを決定
3. **エージェント実行のコーディネーション** — [Alex](/ja/guide/agents/alex)、[Oliver](/ja/guide/agents/oliver)、[Tony](/ja/guide/agents/tony)、[Kai](/ja/guide/agents/kai) へのタスクを並行して配信し、依存関係を自動管理
4. **検出結果の統合** — すべてのエージェントから結果を収集し、クロスドメインのインサイトをつなぐ整合性のある説明を構築
5. **成果物の作成** — エグゼクティブサマリー、アクションプラン、取締役会向けプレゼンテーション、修復ロードマップ — 手動編集なしで共有可能な状態で提供

|--------|-------------|

| **複雑なオペレーション** | クラウド移行、セキュリティ変革、インフラ刷新 |

## Anna を使うべき場面

以下のオペレーションには Anna を使用してください：

- **複数のエージェント**が問題の関連する側面に取り組む場合
- **クロスドメインの専門知識**（例：セキュリティ + インフラ + データベース）が必要な場合
- **エグゼクティブレベルの可視性**またはレポーティングが必要な場合
- **依存関係とタイムラインを持つプロジェクトコーディネーション**が必要な場合

単一ドメインのタスクには、直接専門エージェントを使用してください。

## プロンプトパターン

### マルチエージェントコーディネーション

```text
# 並列調査
@anna coordinate investigation of production outage:
  - @alex: infrastructure and resource issues
  - @tony: database performance and connections
  - @kai: pod health and networking

# プロジェクトオーケストレーション
@anna manage AWS to Azure migration:
  - @alex: infrastructure planning and cost analysis
  - @oliver: security requirements and compliance
  - @tony: database migration strategy
  - @kai: container workload transition

# クロスファンクショナル分析
@anna coordinate quarterly infrastructure review:
  - @alex: cost and performance
  - @oliver: security posture
  - @tony: database health
  - @kai: Kubernetes efficiency
```

### 複雑なオペレーション

```text
# クラウド移行
@anna orchestrate multi-cloud migration project with timeline and risk assessment

# セキュリティ変革
@anna coordinate enterprise security remediation with @oliver leading

# インフラのモダナイゼーション
@anna manage Kubernetes adoption across all environments

# コスト最適化イニシアチブ
@anna coordinate company-wide cost reduction targeting 30% savings
```

### エグゼクティブレポーティング

```text
# 戦略的サマリー
@anna #report quarterly infrastructure status for executive team

# 取締役会向けプレゼンテーション
@anna prepare board-level cloud transformation summary

# KPI ダッシュボード
@anna #dashboard executive infrastructure KPIs

# ROI 分析
@anna analyze ROI of cloud optimization initiatives
```

### 戦略的計画

```text
# テクノロジーロードマップ
@anna create 12-month infrastructure modernization roadmap

# キャパシティプランニング
@anna forecast infrastructure needs for 3x growth

# リスク評価
@anna assess risks of current infrastructure with mitigation plan

# 投資分析
@anna evaluate cloud investment options with cost-benefit analysis
```

## ツールの使い方

| ツール | Anna のユースケース |
|------|---------------|
| `#dashboard` | エグゼクティブ KPI、プロジェクトステータス、マルチドメインメトリクス |
| `#report` | 戦略的サマリー、四半期レビュー、取締役会向けプレゼンテーション |
| `#recommend` | 戦略的イニシアチブ、投資優先度、プロジェクトシーケンス |
| `#alert` | プロジェクトのマイルストーン、リスクしきい値、重大な検出結果 |
| `#chart` | トレンド分析、比較メトリクス、進捗トラッキング |

### ツールを使った例

```text
@anna #dashboard executive infrastructure overview
@anna #report quarterly review with findings from all agents
@anna #recommend priority initiatives for next quarter
@anna #schedule monthly executive infrastructure summary
```

## 効果的なプロンプト

**ヒント：エージェントの役割を定義する**

```text
# 良い例
@anna coordinate security audit:
@oliver leads assessment
@alex reviews infrastructure impact
@kai checks container security

# 避けるべき例
@anna do a security check
```

**ヒント：成果物を指定する**

```text
# 良い例
@anna #report quarterly review:
- Executive summary
- Cost trends and savings
- Security posture
- Recommendations

# 避けるべき例
@anna summarize things
```

| エージェント | 継承するアクセス |

## 代表的なワークフロー

### インシデントコーディネーション

```text
# Step 1: 並列調査
@anna coordinate investigation:
  @alex check infrastructure and load balancers
  @tony analyze database performance
  @kai review pod health and networking

# Step 2: 検出結果の統合
@anna summarize findings and identify root cause

# Step 3: 修復計画
@anna #recommend remediation actions with owner assignment

# Step 4: インシデント後
@anna #report incident analysis with prevention measures
```

### 四半期レビュー

```text
# Step 1: データ収集
@anna compile infrastructure metrics from @alex @oliver @tony @kai

# Step 2: 分析
@anna identify trends, risks, and opportunities

# Step 3: レポート
@anna #report quarterly infrastructure review for executives

# Step 4: 計画
@anna #recommend priorities for next quarter
```

### クラウド移行

```text
# Step 1: 評価
@anna coordinate migration assessment:
  @alex: current state and target architecture
  @oliver: security and compliance requirements
  @tony: data migration strategy
  @kai: container migration plan

# Step 2: 計画
@anna create phased migration plan with dependencies

# Step 3: 実行トラッキング
@anna #dashboard migration progress and risk status

# Step 4: 検証
@anna coordinate post-migration validation across all domains
```

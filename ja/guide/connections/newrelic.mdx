New Relic を接続すると、CloudThinker は NRQL の実行、サービスのゴールデンメトリクスとエラーの確認、ログとトレースの閲覧、未解決の issue とアラート条件のトリアージができます。CloudThinker は New Relic MCP サーバーを通じて New Relic にアクセスし、User API キー（`NRAK-...`）で認証します。

## 前提条件

- **US** または **EU** リージョンの New Relic アカウント。
- 組織で **New Relic MCP Server** 機能がオンのままになっていること。New Relic ではデフォルトでオンですが、組織の管理者が機能コントロールマネージャーでオフにでき、オフの間は何も動作しません。
- 2 種類のロールを持つグループに属する New Relic ユーザー。MCP サーバーを読める組織ロールと、エージェントにクエリさせる各アカウントでのアカウントロールです。[必要な権限](#必要な権限)を参照してください。
- CloudThinker ワークスペースで接続を追加する権限。

<Warning>
New Relic の MCP サーバーはパブリックプレビュー段階で、New Relic は FedRAMP や HIPAA の規制対象アカウントでの利用を認めていません。そうしたアカウントは接続しないでください。
</Warning>

## セットアップ

<Steps>
  <Step title="User API キーを作成する">
    New Relic のユーザーメニューから **API keys** を開くか、`one.newrelic.com/api-keys`（EU: `one.eu.newrelic.com/api-keys`）を開きます。**Create a key** をクリックし、**Key type** を **User** にして、名前を `cloudthinker` にして保存します。

    今すぐキー全体をコピーしてください。キーは `NRAK-` で始まり、New Relic は一度しか表示しません。
  </Step>
  <Step title="接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **New Relic** を選択します。次を入力します。
    - **Alias**（任意）: `newrelic-prod` などの短い名前。小文字の英字、数字、ハイフンが使えます。
    - **Description**（任意）: どのアカウントまたは環境か。エージェントはこれを読んで適切なインスタンスを選びます。
    - **NEWRELIC_API_KEY**: `NRAK-` キー。
    - **NEWRELIC_REGION**: サインインする場所に合わせて、**US (mcp.newrelic.com)** または **EU (mcp.eu.newrelic.com)**。

    **Connect** をクリックします。CloudThinker に **Connecting**、**Verifying** と表示され、その後 **Connected** ステータスになります。**Verifying** では、リージョンの New Relic MCP サーバーとセッションを開き、そのツールを一覧表示します。クエリは実行しないため、アカウントロールの不足は後で、最初の質問のときに現れます。検証に失敗すると **Failed** と表示され、エラーメッセージが出ます。メッセージを[トラブルシューティング](#トラブルシューティング)と照らし合わせてください。
  </Step>
</Steps>

<Warning>
ライセンスキー、インジェストキー、ブラウザキーはここでは使えません。データをクエリできるのは **User** キー（`NRAK-...`）だけです。これはセットアップで最もよくある間違いです。
</Warning>

## 接続の詳細

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **NEWRELIC_API_KEY** | New Relic の User API キー | `NRAK-XXXXXXXXXXXXXXXXXXXX` |
| **NEWRELIC_REGION** | アカウントのデータセンター。デフォルトは **US** です | `EU (mcp.eu.newrelic.com)` |

`one.eu.newrelic.com` でサインインしている場合、リージョンは **EU** です。それ以外は **US** です。

## 必要な権限

User API キーは、それを所有するユーザーの権限を持ちます。キーごとのスコープはないため、最小権限はユーザーで実現します。ユーザーには両方のレベルが必要です。

| レベル | ロール | 適合度 |
|-------|------|-----|
| 組織 | **Organization Read Only** | 推奨。ユーザーが MCP サーバーにアクセスできます |
| 組織 | **Organization Product Admin**、**Organization Manager** | 動作しますが、CloudThinker に必要な範囲を超えて付与されます |
| 組織 | カスタムの組織ロール | MCP サーバーを読む権限を含んでいれば動作します |
| アカウント（クエリする各アカウント） | **Read Only** | 推奨。NRQL、APM、ログ、アラートの読み取りで、そのアカウントのデータを見られます |

<Tip>
専用の New Relic ユーザーと、そのためのグループを作成してください。New Relic の **Access management** で、グループに組織レベルの **Organization Read Only** を付与し、続いて調査させたい各アカウントで **Read Only** を付与します。キーはそのユーザーで作成します。New Relic のユーザータイプは請求に影響することがあるため、ユーザーがどのタイプになるかを確認してください。
</Tip>

## エージェントの機能

| 機能 | CloudThinker が行うこと |
|------------|------------------------|
| **Discovery** | アカウントを一覧表示し、続いて各アカウントのイベントタイプ、ダッシュボード、アラートポリシー、最近の issue を一覧表示します |
| **NRQL** | あなたが書いた NRQL、または質問から組み立てた NRQL（例: `SELECT percentile(duration, 95) FROM Transaction FACET name`）を実行します |
| **Entities** | 名前やタグでサービスとホストを見つけ、1 ホップ先のエンティティも見つけます |
| **Service health** | ゴールデンメトリクス（スループット、レスポンスタイム、エラー率、飽和度）、遅いトランザクション、エラーグループを読みます |
| **Logs and traces** | 最近のログ、ログの統計、分散トレースの詳細を読みます |
| **Alerts and issues** | 未解決の issue、アラートポリシーと条件、過去のインシデントを一覧表示します |
| **Changes** | アプリケーションのデプロイなどの変更イベントを一覧表示します |
| **Synthetics** | Synthetic モニターとその最近の結果を一覧表示します |
| **Dashboards** | ダッシュボードを一覧表示し、内容を読みます |

自然言語による NRQL やデプロイの影響レポートなど、New Relic の一部の AI ツールは OAuth サインイン専用です。これは New Relic 側の制限です。User API キーではそれらを使えないため、CloudThinker は NRQL を自分で書き、変更イベントを直接読みます（上の **Changes** を参照）。

接続が初めて **Connected** になると、CloudThinker がチャットを開き、アカウントを読み取り専用で詳しく調べます。もう一度実行するには、カードの **More** メニューを開いて **Try in chat** を選びます。

### 接続を確認する

```text
Run New Relic discovery and list my accounts, their dashboards and alert policies, and any open issues
```

正常な回答には、少なくとも 1 つのアカウント ID と、`Transaction` や `Log` などのイベントタイプが含まれます。

### プロンプト例

```text
Show golden metrics for the checkout service over the last hour and anything unusual
Which New Relic issues are open right now, and which alert condition opened each one?
Were there deployments to the checkout service today, and did error rate change after them?
```

## New Relic のアラートを Resolve に送る

Resolve には New Relic のプリセットがないため、ワークフローの通知を[カスタムシグナルソース](/guide/incident/webhook-integrations/custom-source)に送ります。

<Steps>
  <Step title="CloudThinker でシグナルを作成する">
    **Resolve → Triggers & Outcomes** を開き、**Custom source** を選択して **Add signal** をクリックします。名前を `New Relic` にして **Create endpoint** をクリックし、**Webhook URL** とシークレットキーをコピーします。シークレットは一度しか表示されません。
  </Step>
  <Step title="New Relic で Webhook の送信先を追加する">
    New Relic で **Webhook** の送信先を追加します。エンドポイントに **Webhook URL** を貼り付け、シークレットキーで Bearer トークン認可を設定します。これで New Relic は `Authorization: Bearer <your-secret-key>` を送ります。
  </Step>
  <Step title="ワークフローから送信先に通知する">
    対象にしたいアラートポリシーをカバーするワークフローで、その送信先への Webhook 通知を追加します。New Relic のデフォルトのペイロードテンプレートはそのままにしてください。
  </Step>
  <Step title="テストイベントを 1 件送り、フィールドをマッピングする">
    ワークフローからテスト通知を送ります。CloudThinker に **Payload received** と表示されたら **Map the fields** をクリックし、**Incident title** に issue のタイトルのフィールドを、**Severity** に優先度のフィールドを選んで、**Save mapping** をクリックします。New Relic の `CRITICAL`、`HIGH`、`MEDIUM`、`LOW` の優先度はそのまま解釈されます。
  </Step>
</Steps>

**成功状態:** そのワークフローからの次の issue が [Resolve → Signals](/ja/guide/pulse/overview) に表示され、エージェントがこの接続を通じて調査します。

## トラブルシューティング

<Accordion title="Verifying の段階や最初の質問で 401 Unauthorized になる">
- キーがない、削除されている、または User キーではありません。`NRAK-` で始まることを確認し、必要なら新しい User キーを作成して、接続の詳細パネルから接続を更新してください。
- **NEWRELIC_REGION** がアカウントと一致していません。`one.eu.newrelic.com` でサインインしている場合は **EU** を選んでください。
</Accordion>

<Accordion title="キーが有効なのに、Verifying の段階やすべての呼び出しで失敗する">
組織で **New Relic MCP Server** 機能がオフになっています。デフォルトはオンなので、管理者が New Relic の機能コントロールマネージャーでオフにしています。オンに戻してもらってから、接続を再テストしてください。
</Accordion>

<Accordion title="権限エラー、またはアカウントが見つからない">
キーのユーザーに MCP サーバーを読めるロールがないか、そのアカウントでのアカウントロールがありません。ユーザーのグループに **Organization Read Only** と、そのアカウントでの **Read Only** を付与してください。
</Accordion>

<Accordion title="エンティティやサービスが見つからない">
CloudThinker はクエリの前に名前でエンティティを解決します。New Relic に表示されているとおりのサービス名を使うか、タグでエンティティを検索するよう依頼してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **読み取り専用ユーザー**: User キーには独自のスコープがないため、**Organization Read Only** とクエリするアカウントでの **Read Only** だけを持つユーザーでキーを作成してください。
- **キーは一度しか表示されない**: 作成したときにシークレットマネージャーに保管してください。紛失した場合は、新しいキーを作成して古いキーを削除してください。

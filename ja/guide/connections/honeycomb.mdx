Honeycomb のチームを接続すると、CloudThinker のエージェントが失敗しているスパンの数でエンドポイントをランク付けし、BubbleUp（失敗したイベントと正常なイベントを比較する Honeycomb の機能）を実行して何が変わったかを見つけ、トレースのウォーターフォールを開き、トリガー、SLO、ボードを確認できるようになります。Honeycomb へのサインインは OAuth で一度行うだけです。API キーを作成したり貼り付けたりする必要はありません。

## 前提条件

- エージェントに読ませたいチームに到達できる Honeycomb アカウント。
- テレメトリーを受信しているデータセットを持つ環境が少なくとも 1 つ。すべてのクエリにはデータセットが必要なため、データセットのない環境では何も答えられません。
- Honeycomb の US リージョンにあるチーム。CloudThinker は `https://mcp.honeycomb.io/mcp` に接続するため、Honeycomb の EU リージョンにしかないチームはまだ接続できません。EU が必要な場合は、CloudThinker の担当者にお問い合わせください。
- 接続を追加・編集できる、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Steps>
  <Step title="接続を開始する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Honeycomb** を選び、**Connect** をクリックします。CloudThinker が Honeycomb の認可ページを開きます。
  </Step>
  <Step title="CloudThinker を認可する">
    チームに到達できる Honeycomb アカウントでサインインし、アクセスを承認します。ブラウザがすでに別の Honeycomb アカウントにサインインしている場合は、先にサインアウトしてください。
  </Step>
  <Step title="CloudThinker に戻る">
    Honeycomb から CloudThinker に戻り、CloudThinker がトークンを保存して自動で更新します。

    **成功時の状態:** Honeycomb に **Connected** と表示されます。下の確認用プロンプトを実行して、どのチームに接続したかを確認してください。
  </Step>
</Steps>

## 接続の詳細

入力するフィールドはありません。

| 項目 | 値 |
|------|-------|
| **Authentication** | OAuth。Honeycomb がトークンを発行し、CloudThinker が保存します |
| **Endpoint** | `https://mcp.honeycomb.io/mcp`（Honeycomb がホストする MCP サーバー） |

## 必要な権限

エージェントには認可した Honeycomb アカウントが見られるものが見え、CloudThinker はその権限を絞り込めません。エージェントの到達範囲を制限するには、使わせたいチームと環境だけにアクセスできる、CloudThinker 専用の Honeycomb ユーザーで認可してください。

専用ユーザーを使えば、人の役割が変わっても接続が維持されます。認可した人がチームを離れてアクセスを失うと、誰かが再接続するまですべての呼び出しが失敗し始めます。

ボード、トリガー、SLO、マーカー、受信者の作成や更新は書き込みです。確認が求められると、エージェントは効果を説明し、正確な入力を示して、あなたの回答を待ちます。

<ApprovalDefault />

ボード、トリガー、SLO、マーカー、受信者のすべての書き込みを人の判断待ちにするには、**Manual** を選びます。**Ask first** の [Rule](/guide/approvals/rules) を使えば、それらの書き込みだけを対象にできます。

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **Discovery** | チーム名を示し、環境とデータセットを一覧表示し、トリガー、ボード、受信者が存在するかを報告します | 不要 |
| **Service health** | 失敗しているスパンの数でエンドポイントをランク付けし、エラー率と p95 レイテンシーを示します | 不要 |
| **Root cause** | BubbleUp を実行し、失敗したスパンと正常なスパンを分けるフィールドを見つけます | 不要 |
| **Traces** | スパンを一覧表示し、スパンの詳細を読み、トレース全体のウォーターフォールを開きます | 不要 |
| **Queries** | クエリを実行し、結果を読み、カラムを見つけ、保存されたクエリを調べます | 不要 |
| **Alerting review** | トリガー、ボード、通知の受信者を読みます | 不要 |
| **Changes** | ボード、トリガー、SLO の作成・更新、マーカーや受信者の作成を行います | Approvals を経由 |

エージェントはエラー率だけでなく失敗しているスパンの数でランク付けするため、まれにしか呼ばれずエラー率 100% のエンドポイントが、実際にユーザーに影響を与えているエンドポイントより上位になることはありません。BubbleUp の結果は相関であり、エージェントはそれを証明された原因ではなく相関として報告します。

<Warning>
Honeycomb の MCP サーバーには削除がありません。エージェントが作成したボード、トリガー、SLO、マーカー、受信者は、Honeycomb で削除するまで残ります。そのオブジェクトが存在してほしい場合にのみ、作成を承認してください。
</Warning>

### 接続を確認する

```text
Summarize my Honeycomb setup: team, environments, datasets, and whether triggers exist
```

チーム名、データセット数付きの環境、トリガー、ボード、受信者がセットアップされているかが返されることを確認します。

### プロンプトの例

```text
Which endpoint is in the worst shape right now?
Why is POST /checkout failing, and what changed? Run BubbleUp on the errors
Which datasets have no trigger watching them?
```

エージェントは回答に Honeycomb のクエリとトレースのパーマリンクを含めるため、Honeycomb で同じビューを開けます。

## トラブルシューティング

<Accordion title="OAuth フローが完了しない">
ブラウザが別の Honeycomb アカウントにサインインしている可能性があります。Honeycomb で正しいアカウントにサインインしてから、もう一度 **Connect** をクリックしてください。
</Accordion>

<Accordion title="すべての呼び出しが認証エラーで失敗する">
保存されたトークンが無効になっています。通常は Honeycomb でアクセスが取り消されたためです。**Settings → Workspace → Connections** を開き、**Honeycomb** を選んで、エラー通知の **Connect** をクリックし、再度認可してください。
</Accordion>

<Accordion title="エージェントがデータセットやテレメトリーがないと言う">
環境にデータセットがないか、その期間にスパンのデータがありません。Honeycomb で環境がイベントを受信していることを確認するか、より広い期間で依頼してください。
</Accordion>

<Accordion title="$activity-log$ という環境がスキップされる">
これは Honeycomb 自身の監査用の環境です。環境の一覧には表示されますがクエリできないため、エージェントは意図的にスキップします。
</Accordion>

<Accordion title="作成や更新が実行されなかった">
あなたが却下した、承認のプロンプトに回答しなかった、または Rule が拒否しました。エージェントは却下された書き込みを再試行しません。必要であれば、もう一度依頼してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **チャットに署名付きの結果リンクを載せない**: Honeycomb の生の結果ダウンロード URL には、データへのアクセスを許可するトークンが含まれています。エージェントは代わりにパーマリンクを共有するため、コピーされたメッセージからアクセスが漏れることはありません。
- **チームの切り替え**: Honeycomb の接続で **Disconnect** をクリックしてから、別の Honeycomb アカウントで再度接続します。
- **Disconnect で消えるのは CloudThinker のコピーだけ**: 保存されたトークンは削除されますが、Honeycomb での許可は取り消されません。ポリシーで必要な場合は、Honeycomb のアカウント設定でも CloudThinker のアクセスを削除してください。

SigNoz Cloud またはセルフホストの SigNoz インスタンスを接続すると、CloudThinker エージェントはサービスの最も遅いオペレーションをランク付けし、ログを検索してグループ化し、トレースのウォーターフォール全体を開き、メトリクスをクエリし、アラートルールとその履歴を確認できます。CloudThinker に渡す値は、SigNoz のベース URL と Service Account API キーの 2 つです。セットアップは SigNoz Cloud とセルフホストで同じです。

## 前提条件

- テレメトリを送信しているインスツルメント済みサービスが 1 つ以上ある SigNoz Cloud またはセルフホストの SigNoz インスタンス。SigNoz はアプリケーションのテレメトリからサービスを作成するため、エージェントがサービスを作成することはできません。
- Service Account とその API キーを作成できる、SigNoz-Admin ロールを持つ SigNoz ユーザー。
- SigNoz のベース URL: SigNoz Cloud では `https://<your-tenant>.signoz.cloud`、セルフホストでは SigNoz を開くアドレス（例: `https://signoz.internal.example.com`）。
- セルフホストの SigNoz の場合: インスタンスが CloudThinker Cloud からの接続を受け付ける必要があります。CloudThinker の送信元 IP を許可リストに追加するには、最新の一覧が必要です。このドキュメントでは CloudThinker の送信元 IP 一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その他の方法は [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- 接続を追加するために必要な、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Steps>
  <Step title="Service Account を作成する">
    SigNoz で **Settings → Service Accounts** を開き、**New Service Account** をクリックして、後で見分けがつく名前（例: `cloudthinker`）を付けます。手順は SigNoz Cloud とセルフホストで同じです。
  </Step>
  <Step title="ロールを選ぶ">
    アカウントの **Overview** タブで、**Roles** ドロップダウンから最も狭いロールを選びます:

    | エージェントにさせたいこと | ロール |
    |--------------------|------|
    | サービス、ログ、トレース、メトリクス、ダッシュボード、アラートの調査 | **SigNoz-Viewer** |
    | さらにダッシュボードとアラートの作成、更新、削除 | **SigNoz-Editor** |
    | さらに保存済みビューと通知チャンネルの管理 | **SigNoz-Admin** |

    キーを作成する前に **Save** をクリックします。SigNoz-Admin はユーザー、ロール、Service Account も管理できるため、必要な場合にのみ選んでください。
  </Step>
  <Step title="API キーを作成する">
    アカウントの **Keys** タブを開き、**Add Key** をクリックして名前を付け（例: `cloudthinker-key`）、ポリシー上必要なら有効期限を設定して、キーをコピーします。SigNoz がキーを表示するのは一度だけです。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **SigNoz** を選択します。次を入力します:

    - **SIGNOZ_URL**: ベース URL のみ（例: `https://<your-tenant>.signoz.cloud`）。`/api/v1` などのパスは付けないでください。
    - **SIGNOZ_API_KEY**: コピーしたキー。
    - **LOG_LEVEL**: **Info** のままにします。接続が CloudThinker の診断ログにどれだけ詳しく書き込むかを設定するもので、サポートがトラブルシューティングに使います。

    **Connect** をクリックします。

    **成功の状態:** SigNoz に **Connected** と表示されます。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **SIGNOZ_URL** | はい | インスタンスのベース URL（パスなし） | `https://<your-tenant>.signoz.cloud` |
| **SIGNOZ_API_KEY** | はい | Service Account の API キー | アカウントの **Keys** タブから |
| **LOG_LEVEL** | いいえ | サポートが使う、CloudThinker 内部の接続ログの詳しさ。デフォルトは **Info** | **Info** |

## 必要な権限

エージェントができることは Service Account のロールが許可する範囲とまったく同じで、SigNoz がそれを強制します。

- **SigNoz-Viewer** は、下の機能表にあるすべての読み取りをカバーします。
- **SigNoz-Editor** は、ダッシュボードとアラートの書き込みを追加します。SigNoz は保存済みビューや通知チャンネルへの Editor のアクセスを文書化していないため、それらには SigNoz-Admin を使ってください。
- **SigNoz-Admin** は、すべての書き込みに加え、SigNoz のユーザー、ロール、Service Account の管理を追加します。

<ApprovalDefault />

[Rule](/guide/approvals/rules) を使うと、書き込みの前に CloudThinker に確認させたり、書き込みを完全に拒否したりできます。

<Tip>
まずは SigNoz-Viewer で始めてください。ダッシュボードとアラートの変更には SigNoz-Editor に、保存済みビューやチャンネルをエージェントに管理させたい場合にのみ SigNoz-Admin に変更します。
</Tip>

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **Services** | インスツルメント済みサービスを一覧表示し、サービスの上位オペレーションをレイテンシでランク付けします | 不要 |
| **Logs** | 重大度などのフィルターでログを検索し、サービスなどのフィールドで集計します | 不要 |
| **Traces** | トレースを検索・集計し、トレース ID でトレースのウォーターフォール全体を開きます | 不要 |
| **Metrics** | メトリクスを一覧表示し、時系列クエリを実行します | 不要 |
| **Dashboards** | ダッシュボードとテンプレートを一覧表示し、ダッシュボードの完全な定義を読みます | 不要 |
| **Alerts** | アラートルールとその状態を一覧表示し、ルールの状態変化の履歴を読みます | 不要 |
| **Saved views and channels** | 保存済みクエリビューと通知チャンネルを読みます | 不要 |
| **Writes** | アラート、ダッシュボード、保存済みビュー、通知チャンネルの作成、更新、削除と、JSON からのダッシュボードのインポート。SigNoz-Editor（ダッシュボード、アラート）または SigNoz-Admin（保存済みビュー、チャンネル）が必要です | Approvals を通ります |

ログ、トレース、メトリクスの検索は常に時間範囲を指定して実行されます。エージェントは直近 15 分から始め、何も返らない場合は範囲を広げます。特定の期間が重要な場合は、プロンプトで範囲を指定してください。

<Warning>
SigNoz での削除は元に戻せません。削除したアラートは履歴を失い、通知チャンネルを削除すると、そこに振り分けられていたアラートの送信先がなくなります。エージェントは更新や削除の前に現在のレコードを表示するので、承認する前に確認してください。
</Warning>

### 接続を確認する

```text
List my SigNoz services, dashboards, and alert rules, and tell me which alerts are firing
```

サービス、ダッシュボード、アラートルールの件数とサンプルに加え、現在発火しているアラートの数が返るはずです。

### プロンプト例

```text
What are the slowest operations for the checkout service over the last hour?
Search ERROR logs from the last 30 minutes and group them by service
Review my SigNoz alert rules and flag any with no notification channel
```

## トラブルシューティング

<Accordion title="すべてのリクエストが 404 を返す">
**SIGNOZ_URL** の末尾にパスが付いています。`https://<your-tenant>.signoz.cloud` のようなベース URL のみに設定し、`/api/v1` は付けないでください。
</Accordion>

<Accordion title="401 Unauthorized">
キーが間違っているか、期限切れか、取り消されています。Service Account の **Keys** タブで新しいキーを作成し、**SIGNOZ_API_KEY** を更新してください。
</Accordion>

<Accordion title="403 Forbidden">
Service Account のロールがその操作を許可していません。SigNoz-Viewer のキーは、どの書き込みでもこれを返します。SigNoz-Editor のキーは、保存済みビューと通知チャンネルの書き込みでこれを返すことがあります。SigNoz がそれらへの Editor のアクセスを文書化していないためです。エージェントにその変更をさせたい場合は、SigNoz でロールを変更してください。
</Accordion>

<Accordion title="ログやトレースの検索結果が空になる">
検索した範囲で一致するものがありませんでした。直近 6 時間などの広い範囲を依頼するか、フィルターを外して条件を 1 つずつ戻してください。
</Accordion>

<Accordion title="429 または 503 エラー">
SigNoz インスタンスがレート制限中か、再起動中です。1 分待ってからもう一度依頼してください。セルフホストの SigNoz では、クエリサービスの健全性を確認してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **CloudThinker 専用の Service Account を 1 つ使う**: チームメイトのキーを再利用しないでください。専用のアカウントなら、他の人のアクセスに触れずに CloudThinker のアクセスを取り消せます。
- **キーの有効期限を設定する**: 期限が切れる前にキーをローテーションして **SIGNOZ_API_KEY** を更新してください。そうしないと、接続は 401 エラーで停止します。

CircleCI を接続すると、CloudThinker のエージェントがパイプラインのステータスを読み、ビルドとテストのログを取得して実行が失敗した理由を突き止め、不安定なテストを見つけ、`.circleci/config.yml` を検証できるようになります。接続には CircleCI の個人 API トークンを使うため、エージェントはトークンのユーザーが見られるプロジェクトに限って到達します。

## 前提条件

- エージェントに調査させたい組織とプロジェクトを閲覧できる CircleCI アカウント。
- そのアカウントがフォローしているプロジェクトが少なくとも 1 つ。エージェントはフォロー中の一覧からプロジェクトを見つけます。フォローするには、トークンのユーザーとして CircleCI にサインインし、**Projects** を開いて、各リポジトリの横の **Follow Project** をクリックします。
- 不安定なテストとジョブのテスト結果の場合: ジョブが `store_test_results` で JUnit の結果をアップロードしている必要があります。これがないと、CircleCI は返すテストデータを持ちません。
- エージェントにパイプラインの開始や再実行をさせる場合: 同じアカウントに、それらのプロジェクトでパイプラインをトリガーする権限が必要です。
- セルフホストの CircleCI Server の場合: CloudThinker から HTTPS でサーバーに到達できる必要があります。[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。

## セットアップ

<Steps>
  <Step title="個人 API トークンを作成する">
    CircleCI で **User Settings → Personal API Tokens**（[app.circleci.com/settings/user/tokens](https://app.circleci.com/settings/user/tokens)）を開き、**Create New Token** をクリックします。名前は `cloudthinker` にします。

    トークンはすぐにコピーしてください。CircleCI は一度しか表示しません。
  </Step>
  <Step title="接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **CircleCI** を選びます。次を入力します。
    - **CIRCLECI_TOKEN**: 作成したトークン。
    - **CIRCLECI_BASE_URL**: CircleCI クラウドでは `https://circleci.com` のままにします。セルフホストの CircleCI Server の場合にのみ変更します。

    **Connect** をクリックします。

    **成功時の状態:** ダイアログが閉じ、接続に **Connected** と表示されます。
  </Step>
  <Step title="トークンが機能することを確認する">
    [接続を確認する](#接続を確認する)のプロンプトを実行します。CloudThinker は接続時に CircleCI でトークンを確認しないため、**Connected** のステータスだけではトークンが有効であることは証明されません。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **CIRCLECI_TOKEN** | はい | 個人 API トークン。作成したユーザーのアクセス権を持ちます | `CCIPAT_...` |
| **CIRCLECI_BASE_URL** | いいえ | CircleCI のインストール先のホスト。ホストのみで、末尾のパスは付けません | `https://circleci.com` |

組織やプロジェクトの ID を入力する必要はありません。エージェントがトークンのフォロー中のプロジェクトから解決します。

## 必要な権限

個人 API トークンは、作成した CircleCI ユーザーと同じアクセス権を持ちます。そのユーザーのプロジェクトへのアクセス権が、エージェントが読み取り・変更できる範囲の上限です。

| エージェントにさせたいこと | トークンのユーザーに必要なもの |
|----------------------------|-----------------------------|
| ステータス、ログ、テスト結果、成果物を読む | プロジェクトへの読み取りアクセス |
| パイプラインの開始、ワークフローの再実行、評価テストの実行 | プロジェクトでパイプラインをトリガーする権限 |
| デプロイのロールバック | CircleCI の **Deploys** でプロジェクトに設定されたロールバックパイプラインと、それをトリガーする権限 |

**評価テスト**は CircleCI のプロンプトテンプレートのテストで、エージェントは CircleCI 上のパイプラインとして実行します。

<Tip>
トークンは、調査させたいプロジェクトだけに所属する専用の CircleCI ユーザーで作成してください。そのユーザーは GitHub または Bitbucket の組織のメンバーである必要があるため、VCS のマシンユーザーを使うのが一般的です。CircleCI のプランでユーザーとしてカウントされるかを確認してください。書き込み操作は引き続き [Approvals](/guide/approvals/overview) を経由するため、トークンが上限を決め、Approvals が各操作を判断します。
</Tip>

## エージェントの機能

| 機能 | エージェントができること |
|------------|--------------------|
| **Project discovery** | フォロー中のプロジェクトとその組織を一覧表示します |
| **Pipeline status** | プロジェクトとブランチの最新のパイプラインのステータスを読みます |
| **Failure triage** | ビルドの失敗ログとジョブのテスト結果を取得し、失敗しているステップを見つけます |
| **Flaky tests** | 同じコードで成功と失敗を繰り返すテストを見つけます |
| **Config validation** | `.circleci/config.yml` を確認し、エラーを説明します |
| **Artifacts** | ジョブが生成した成果物を一覧表示します |
| **Usage review** | 使用量データをダウンロードし、使用率の低いリソースクラスを指摘します（有料プランのみ） |
| **Pipeline controls** | パイプラインの実行、ワークフローの再実行、評価テストの実行、デプロイのロールバック。**それぞれ Approvals を経由します** |

書き込みの前に、エージェントは何が起こるか（例: 「`gh/acme/api` のブランチ `main` でパイプラインを開始します」）を伝え、正確な入力を示します。ロールバックでは現在のバージョンと対象のバージョンも示し、対象の確認を求めます。

<ApprovalDefault />

毎回確認されるようにするには、[Approval mode](/guide/approvals/approval-mode) で **Manual** を選び、すべての変更を人が承認するようにします。**Ask first** の [Rule](/guide/approvals/rules) を使えば、それをこの接続だけに絞り込めます。

### 接続を確認する

```text
List my followed CircleCI projects and show the latest pipeline status for each
```

フォロー中の各プロジェクトがスラッグ（`gh/acme/api` など）と最新のパイプラインのステータスとともに表示されることを確認します。期待したプロジェクトが表示されない場合、トークンのユーザーはそれをフォローしていません。

### プロンプトの例

```text
The main branch of gh/acme/api failed on CircleCI. Pull the failure logs and tell me which step broke and why
Which tests in gh/acme/api are flaky, and how often does each one fail?
```

## トラブルシューティング

<Accordion title="すべてのリクエストが 401 Unauthorized を返す">
トークンがない、期限切れ、または取り消されています。新しい個人 API トークンを作成し、接続の **CIRCLECI_TOKEN** フィールドを更新してください。
</Accordion>

<Accordion title="読み取りは機能するが、パイプラインの開始や再実行で権限エラーが返る">
トークンのユーザーはプロジェクトを読めますが、パイプラインをトリガーできません。そのプロジェクトでトリガー権限を持つユーザーでトークンを作成し、接続を更新してください。
</Accordion>

<Accordion title="接続は Connected なのにプロジェクトが表示されない">
トークンのユーザーがプロジェクトを 1 つもフォローしていません。CircleCI で少なくとも 1 つのプロジェクトをフォローしてから、もう一度質問してください。
</Accordion>

<Accordion title="不安定なテストやジョブのテスト結果が空で返る">
ジョブがテスト結果をアップロードしていません。JUnit XML の出力を指す `store_test_results` ステップを追加し、何回かパイプラインを実行してから、もう一度質問してください。
</Accordion>

<Accordion title="プロジェクトが 404 を返す">
プロジェクトのスラッグには VCS のプレフィックスが必要です。GitHub では `gh/<org>/<repo>`、Bitbucket では `bb/<org>/<repo>` です。フォロー中のプロジェクトを一覧表示するようエージェントに依頼し、その一覧のスラッグを使ってください。
</Accordion>

<Accordion title="使用量の分析で組織 ID を求められる">
使用量データには組織の UUID が必要ですが、それを返す CircleCI API の呼び出しはありません。CircleCI の **Organization Settings → Overview → Organization ID** からコピーし、チャットに貼り付けてください。使用量 API は有料プラン限定で、1 回のリクエストで最大 32 日分をカバーします。
</Accordion>

<Accordion title="セルフホストのインストールが 404 や認証エラーを返す">
**CIRCLECI_BASE_URL** が `https://circleci.com` のままか、パスが含まれています。`https://circleci.example.com` のように、CircleCI Server のホストだけを設定してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **専用ユーザーを使う**: CircleCI の個人トークンには独自のスコープがないため、到達範囲を制限する唯一の方法は、トークンのユーザーのプロジェクトメンバーシップです。
- **操作は承認付きのままにする**: パイプラインの実行はコンピューティングに課金され、デプロイを行うこともあります。これらの操作は自動承認せず、[Approval mode](/guide/approvals/approval-mode) の背後に置いてください。

CloudThinkerはプロジェクトに対してGoogle Cloud CLIを実行し、コンピュート、GKE、BigQuery、ストレージ、ID、コストに関する質問に答えます。接続にはサービスアカウントのJSONキーを使い、そのサービスアカウントのIAMロールがエージェントの到達範囲を決めます。

<Warning>
この接続が受け付けるのはサービスアカウントのJSONキーだけです。Workload Identity Federationとなりすまし（impersonation）には対応していません。
</Warning>

## 前提条件

- サービスアカウントを作成し、IAMロールを付与できるGoogle Cloudプロジェクト。
- サービスアカウントキーを作成する権限。組織で`constraints/iam.disableServiceAccountKeyCreation`が適用されている場合（2024年5月以降に作成された組織ではこれがデフォルトです）、始める前に組織のポリシー管理者にこのプロジェクトの例外を依頼してください。ポリシーの変更が反映されるまで数分かかることがあります。
- 回答を得たいサービスのAPIが、接続の対象とするすべてのプロジェクトで有効になっていること。無効なサービスについては、エージェントに`API not enabled`が返ります。APIを有効にするには、プロジェクトで**Service Usage Admin**（`roles/serviceusage.serviceUsageAdmin`）またはOwnerが必要です。プロジェクト、インベントリ、GKE、BigQuery、IAMレビュー、メトリクス、ログ、Cloud Storageをカバーする一般的なセットは次のとおりです。

  ```bash
  APIS="cloudresourcemanager.googleapis.com serviceusage.googleapis.com \
    compute.googleapis.com container.googleapis.com bigquery.googleapis.com \
    iam.googleapis.com monitoring.googleapis.com logging.googleapis.com storage.googleapis.com"

  # One project
  gcloud services enable $APIS --project=PROJECT_ID

  # Every project you can see, for a folder or organization grant
  for P in $(gcloud projects list --format="value(projectId)"); do
    gcloud services enable $APIS --project="$P"
  done
  ```
- CloudThinkerワークスペースでの**Admin**ロール。接続の追加と編集ができます。[Roles](/guide/security/roles)を参照してください。
- コストに関する質問と[Optimize](/ja/guide/cost-optimization/overview)には、BigQueryへのCloud Billing **Standard usage cost**エクスポートが必要です。Optimizeは接続先プロジェクト内の課金テーブルしか読まないため、エクスポートのデータセットはサービスアカウントと同じプロジェクトに置く必要があります。作成するには、**Billing Account Administrator**が**Billing → Billing export → BigQuery export**を開き、**Standard usage cost**の下で**Edit settings**をクリックします。[Googleのセットアップガイド](https://cloud.google.com/billing/docs/how-to/export-data-bigquery-setup)を参照してください。新しいエクスポートは最初の行が現れるまで数時間かかることがあるため、初日はOptimizeが空に見える場合があります。

## セットアップ

まずGoogle Cloudでサービスアカウントを作成し、そのキーをCloudThinkerにアップロードします。

<Tabs>
  <Tab title="Google Cloud console">
    <Steps>
      <Step title="サービスアカウントを作成する">
        [Google Cloud console](https://console.cloud.google.com/)でプロジェクトを選択し、**IAM & Admin → Service Accounts**を開きます。**Create service account**をクリックし、名前を`cloudthinker-readonly`にして、**Create and continue**をクリックします。
      </Step>
      <Step title="読み取り専用ロールを付与する">
        **Viewer**（`roles/viewer`）を追加します。Optimizeを使う場合は**BigQuery Job User**（`roles/bigquery.jobUser`）も追加します。**Done**をクリックします。組織でViewerなどの基本ロールが禁止されている場合は、代わりに[必要な権限](#必要な権限)にある事前定義ロールを使ってください。
      </Step>
      <Step title="Optimizeの場合: 課金データセットを共有する">
        **BigQuery**を開き、課金エクスポートのデータセットを選択して、**Sharing → Permissions → Add principal**をクリックします。サービスアカウントのメールアドレスを入力し、**BigQuery Data Viewer**を選んで**Save**をクリックします。Optimizeを使わない場合はこの手順を省略してください。
      </Step>
      <Step title="JSONキーを作成する">
        サービスアカウントを開き、**Keys**タブで**Add key → Create new key**をクリックします。**JSON**を選んで**Create**をクリックします。キーファイルは一度だけダウンロードされ、再ダウンロードはできません。
      </Step>
    </Steps>
  </Tab>
  <Tab title="gcloud CLI">
    [Cloud Shell](https://shell.cloud.google.com/)、またはGoogle Cloudにサインイン済みの任意のターミナルで次を実行します。`PROJECT_ID`はプロジェクトIDに置き換えてください。

    ```bash
    PROJECT_ID=your-project-id
    SA=cloudthinker-readonly@$PROJECT_ID.iam.gserviceaccount.com

    gcloud iam service-accounts create cloudthinker-readonly \
      --project="$PROJECT_ID" --display-name="CloudThinker read-only"

    gcloud projects add-iam-policy-binding "$PROJECT_ID" \
      --member="serviceAccount:$SA" --role="roles/viewer"

    # Optimize only: skip these two commands if you don't use Optimize.
    # Replace BILLING_DATASET with the billing export dataset's name
    # and DATASET_LOCATION with its location, for example US or EU.
    gcloud projects add-iam-policy-binding "$PROJECT_ID" \
      --member="serviceAccount:$SA" --role="roles/bigquery.jobUser"
    bq query --project_id="$PROJECT_ID" --location=DATASET_LOCATION --use_legacy_sql=false \
      "GRANT \`roles/bigquery.dataViewer\` ON SCHEMA \`$PROJECT_ID.BILLING_DATASET\` TO 'serviceAccount:$SA'"

    gcloud iam service-accounts keys create cloudthinker-key.json --iam-account="$SA"
    ```

    最後のコマンドはキーを`cloudthinker-key.json`に書き出します。Cloud Shellでは`cloudshell download cloudthinker-key.json`でパソコンにダウンロードし、CloudThinkerにアップロードしたら`rm cloudthinker-key.json`でCloud Shell上のコピーを削除してください。
  </Tab>
</Tabs>

次に、CloudThinkerで接続します。

<Steps>
  <Step title="接続ダイアログを開く">
    **Settings → Workspace → Connections**を開き、**Google Cloud Platform**を選択して**Connect**をクリックします。
  </Step>
  <Step title="プロジェクトに名前を付ける">
    **Alias**（例: `prod-gcp`）と**Description**（例: `Production GCP project, GKE workloads`）を入力します。接続が複数あるとき、エージェントは説明を読んで適切な接続を選びます。
  </Step>
  <Step title="キーをアップロードしてリージョンを選ぶ">
    JSONキーファイルを**GOOGLE_SERVICE_ACCOUNT_KEY**にドラッグするか、クリックしてファイルを選びます。**GCP_DEFAULT_REGION**の一覧からメインのリージョンを選びます。デフォルトは`us-central1`です。**Connect**をクリックします。

    **成功状態:** ステータスが**Connecting**、**Verifying**と進み、プロジェクトに**Connected**ステータスが表示されます。このプロジェクトで Optimize がまだオンになっていない場合、CloudThinker は詳細調査を開始する代わりに **Turn on Optimize?** と尋ねます。**Turn on Optimize** をクリックして最初のコストスキャンを開始するか、**Not now** をクリックしてください。エージェントにプロジェクトを探索させるには、カードの **More** メニューを開き、**Try in chat** を選択します。[What happens after you connect](/ja/guide/connections/overview#接続した後に起こること) を参照してください。
  </Step>
  <Step title="環境を設定する">
    **Settings → Workspace → Connections**で**Google Cloud Platform**を開き、プロジェクトの行の鉛筆アイコンをクリックして、**Edit Instance**で**Environment**を設定します。これは人とエージェントのためにプロジェクトにラベルを付けるものです。
  </Step>
  <Step title="確認の質問をする">
    チャットを開き、[確認の質問](#接続を確認する)をします。回答には実際のプロジェクトIDが並ぶはずです。
  </Step>
</Steps>

### さらにプロジェクトを接続する

| 方法 | やり方 | 向いているケース |
|---|---|---|
| 1つのサービスアカウントで複数プロジェクト | 各プロジェクトでサービスアカウントに同じロールを付与するか、フォルダーまたは組織で一度だけ付与する | プロジェクトをまたいで見られる接続を1つにしたい |
| プロジェクトごとに1つの接続 | 各プロジェクトでセットアップを繰り返し、**Google Cloud Platform**で新しいエイリアスを付けて再度**Connect**をクリックする | プロジェクトがチームごとに分かれている、または別々の課金アカウントにあり、それぞれのエクスポートが接続先プロジェクトにある |

<Warning>
[承認ルール](/guide/approvals/rules)は接続全体に適用されます。そのため、本番と開発のプロジェクトが混在するフォルダーに付与した場合、すべてのプロジェクトに同じルールが適用されます。プロジェクトごとに異なる承認ルールが必要な場合は、プロジェクトごとに1つの接続を使ってください。
</Warning>

どちらの方法を選んでも、Optimizeはキーが属するプロジェクト（キーの`project_id`）からのみ課金を読みます。課金エクスポートを持たないプロジェクトへのプロジェクト単位の接続では、Optimizeのコストデータは得られません。課金エクスポートはその課金アカウント上のすべてのプロジェクトをカバーするため、エクスポートを持つプロジェクトにサービスアカウントを置き、フォルダーまたは組織で**Viewer**を付与して、一度だけ接続してください。フォルダーで付与するには**Folder IAM Admin**（`roles/resourcemanager.folderIamAdmin`）が必要です。組織で付与するには**Organization Administrator**（`roles/resourcemanager.organizationAdmin`）が必要です。

```bash
BILLING_PROJECT=your-billing-project-id
SA=cloudthinker-readonly@$BILLING_PROJECT.iam.gserviceaccount.com

# Find the organization ID, then the folder ID
gcloud organizations list
gcloud resource-manager folders list --organization=ORGANIZATION_ID

# Grant on one folder
gcloud resource-manager folders add-iam-policy-binding FOLDER_ID \
  --member="serviceAccount:$SA" --role="roles/viewer"

# Or grant on the whole organization
gcloud organizations add-iam-policy-binding ORGANIZATION_ID \
  --member="serviceAccount:$SA" --role="roles/viewer"
```

## 接続の詳細

| フィールド | 説明 | 例 |
|---|---|---|
| **Alias** | この接続の短い名前。空欄の場合は自動で付けられます。 | `prod-gcp` |
| **Description** | プロジェクトの内容。エージェントが接続を選ぶときに使います。 | `Production GCP project` |
| **GOOGLE_SERVICE_ACCOUNT_KEY** | アップロードするサービスアカウントのJSONキーファイル | `cloudthinker-key.json` |
| **GCP_DEFAULT_REGION** | エージェントのコマンドの開始リージョン。検索できる一覧から選びます。デフォルトは`us-central1`です。 | `us-central1` |

キーファイルは`type`、`project_id`、`private_key`、`client_email`などのフィールドを持つJSONです。変更せずにそのままアップロードしてください。

**Environment**（**Production**、**Staging**、**Development**、または**Not set**）は接続ダイアログにはありません。セットアップ手順のとおり、接続後に設定します。これは人とエージェントのためにプロジェクトにラベルを付けるものです。承認ルールはこれを読まないため、1つのプロジェクトだけを対象にするルールでは、その接続を指定します。

## 必要な権限

| 目的 | ロール | 付与先 |
|---|---|---|
| インベントリ、ヘルス、IAMに関する質問 | Viewer（`roles/viewer`） | 各プロジェクト、またはフォルダーや組織 |
| Optimizeのコストデータ | BigQuery Data Viewer（`roles/bigquery.dataViewer`） | 課金エクスポートのデータセット（またはプロジェクト） |
| Optimizeのコストクエリ | BigQuery Job User（`roles/bigquery.jobUser`） | 接続先プロジェクト |
| エージェントに特定の変更をさせる | その変更に必要な最小限のロールのみ | 変更が行われる場所。[書き込みアクセス](#書き込みアクセス)を参照してください。 |

組織で基本ロールが禁止されている場合は、Viewerの代わりに、必要な領域の事前定義された読み取りロールを付与してください。

| 領域 | ロール |
|---|---|
| プロジェクトとフォルダーの一覧 | Browser（`roles/browser`） |
| Compute Engine | Compute Viewer（`roles/compute.viewer`） |
| GKE | Kubernetes Engine Viewer（`roles/container.viewer`） |
| IAMレビュー | Security Reviewer（`roles/iam.securityReviewer`） |
| メトリクス | Monitoring Viewer（`roles/monitoring.viewer`） |
| ログ | Logs Viewer（`roles/logging.viewer`） |

<Tip>
**Viewer**は何も変更できないため、安全な出発点です。ただし設定だけでなくデータも読みます。BigQueryでは、デフォルトのプロジェクトレベルの読み取りアクセスを残しているすべてのデータセットをViewerが読めます。機密性の高いデータセットにエージェントを近づけないには、そのデータセットからデフォルトのアクセスを外すか、Viewerの代わりにカスタムロールを使ってください。
</Tip>

## エージェントの機能

| 領域 | CloudThinkerが行うこと |
|---|---|
| **Inventory** | サービスアカウントが見られるプロジェクト全体で、Compute Engine、GKE、Cloud Storage、BigQueryなどのリソースを一覧表示し、内容を説明します |
| **Identity** | IAMバインディングとサービスアカウントを確認し、広すぎるアクセスや使われていないアクセスを見つけます |
| **Containers** | GKEクラスターとノードプールの設定とヘルスを確認します |
| **Cost** | BigQueryの課金エクスポートを読み、プロジェクト、サービス、ラベルごとに支出を分析します。[Optimize](/ja/guide/cost-optimization/overview)に使われます。 |
| **Changes** | **Allow writes**がオンで、サービスアカウントが許可し、承認設定でも許可されている場合にのみ、Google Cloud CLIの書き込みを実行します |

### 接続を確認する

```text
Which Google Cloud projects can you reach through my GCP connection, and which services are enabled in each?
```

回答には実際のプロジェクトIDが並びます。フォルダーまたは組織で付与した場合は、その配下のすべてのプロジェクトが表示されるはずです。

### プロンプト例

```text
List Compute Engine instances that have been stopped for more than 30 days and the disks still attached to them
Find service accounts with the Owner or Editor role in my projects
Break down last month's Google Cloud spend by project and service
```

## 書き込みアクセス

接続の詳細パネルにある**Allow writes**は、エージェントがGoogle Cloudで何かを変更してよいかを制御します。デフォルトはオンですが、**Viewer**とBigQueryの読み取りロールしか持たないサービスアカウントは何も変更できないため、権限を追加するまでGoogle Cloudはすべての書き込みを拒否します。

| IAMロール | Allow writes | 結果 |
|---|---|---|
| 読み取り専用ロールのみ | オンまたはオフ | 読み取り専用。Google Cloudがあらゆる変更を拒否します。 |
| 追加の書き込みロールを付与 | オフ | 読み取り専用。変更がGoogle Cloudに届く前にCloudThinkerがすべて拒否します。 |
| 追加の書き込みロールを付与 | オン | エージェントが変更を提案できます。各変更は[ルールと承認モード](/guide/approvals/overview)で判断されます。 |

CloudThinker側でも書き込みを止めるには、**Settings → Workspace → Connections**を開き、**Google Cloud Platform**を選択して、詳細パネルの**Allow writes**スイッチをオフにします。

## トラブルシューティング

<Accordion title="キーを作成できない: キーの作成が無効になっている">
**原因:** 組織ポリシー`constraints/iam.disableServiceAccountKeyCreation`が適用されています。

**対処:** 組織のポリシー管理者に、このプロジェクトでのキー作成を許可してもらうか、キーを作成してもらいます。例外がすでに付与されている場合は数分待ってください。ポリシーの変更は反映に時間がかかります。また、プロジェクトやそのフォルダーなど下位で設定されたポリシーが、まだこの制約を適用していないかも確認してください。
</Accordion>

<Accordion title="アップロードが拒否される、またはテストがすぐに失敗する">
**原因:** ファイルが元のJSONキーではありません。よくあるのは、P12キー、コピーした断片、または編集されて`private_key`の改行が失われたファイルです。

**対処:** 新しいJSONキーを作成し、ダウンロードしたファイルを変更せずにアップロードしてください。
</Accordion>

<Accordion title="エージェントにPERMISSION_DENIEDまたは'API not enabled'が返る">
**確認:** 質問したプロジェクトでサービスアカウントにロールがあること、そしてそのサービス（例: Compute EngineやKubernetes Engine）のAPIがそのプロジェクトで有効になっていること。

**対処:** プロジェクトまたはそのフォルダーで**Viewer**を付与するか、**APIs & Services**でAPIを有効にします。再接続は不要です。次のリクエストから新しいアクセスが使われます。
</Accordion>

<Accordion title="Optimizeで課金エクスポートが見つからないと表示される">
**原因:** Optimizeには、接続先プロジェクト内にCloud BillingのStandard usage costエクスポートテーブル（名前は`gcp_billing_export_v1_...`）が必要です。

**対処:** **Billing → Billing export**でStandard usage costエクスポートをオンにし、サービスアカウントと同じプロジェクトのデータセットを指定します。テーブルが接続先プロジェクトの外にあるとOptimizeに表示された場合は、エクスポートを移動するか、エクスポートを持つプロジェクトでサービスアカウントを作成してください。テーブルを選ぶよう求められた場合は、Optimizeに使わせたいテーブルを選びます。
</Accordion>

<Accordion title="テストでTimed outと表示される">
**原因:** テストが時間内に終わりませんでした。Google Cloudのエンドポイントは公開されているため、ネットワークが原因であることはまれです。

**対処:** もう一度接続してください。タイムアウトが続く場合は、[お問い合わせ](https://cloudthinker.io/contact)ください。
</Accordion>

<Accordion title="接続にErrorと表示される">
**原因:** キーが削除または無効化されたか、組織ポリシー（`constraints/iam.serviceAccountKeyExpiryHours`）によって期限切れになりました。

**対処:** 新しいキーを作成し、接続を開いて**Replace credentials**をクリックしてアップロードします。これで**Replace…**と同じダイアログである**Edit Instance**が開きます。ステータスが**Connected**になると、スケジュールされた作業が再開します。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **キーのローカルコピーを削除してください。** JSONファイルをアップロードしたら、ダウンロードフォルダーから削除するか、シークレットマネージャーに保管してください。キーを持つ人は誰でもサービスアカウントのアクセス権を使えます。
- **少なくとも90日ごとにローテーションしてください。** [`constraints/iam.serviceAccountKeyExpiryHours`](https://cloud.google.com/resource-manager/docs/organization-policy/restricting-service-accounts#limit_key_expiry)ポリシーでキーの有効期間を制限します。ローテーションするには、新しいキーを作成し、プロジェクトの行の鉛筆アイコンをクリックして、**Edit Instance**の**Replace…**でアップロードしてから、サービスアカウントの**Keys**タブで古いキーを削除します。[認証情報をローテーションする](/ja/guide/connections/overview#認証情報をローテーションする)を参照してください。

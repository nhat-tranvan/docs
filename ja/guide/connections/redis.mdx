セルフホストの Redis、Upstash、Redis Cloud などの Redis サーバーを接続すると、CloudThinker のエージェントがメモリとエビクションを調べ、最大のキーと TTL のないキーを見つけ、クライアントを一覧表示し、コマンドのレイテンシーを読めるようになります。接続 URL（`REDIS_URL`）を 1 つ CloudThinker に渡します。エージェントはそのユーザーの ACL が許可するコマンドを実行でき、接続の書き込みツールはまず [Approvals](/guide/approvals/overview) を経由します。

## 前提条件

- CloudThinker がインターネットから到達できる Redis のエンドポイント。エージェントは CloudThinker Cloud から接続するため、`localhost` やプライベートアドレスはあなたのネットワークではなく CloudThinker 側で解決されます。プライベートリンクの選択肢はないため、Amazon ElastiCache や MemoryDB などの VPC 専用のサービスは接続できません。[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- 専用の ACL ユーザーが必要な場合は Redis 6 以降。それより古いバージョンは、共有のパスワード 1 つにしか対応していません。
- `ACL SETUSER` を実行する、またはマネージドプロバイダーのコンソールでユーザーを作成するための管理者アクセス。

## セットアップ

<Steps>
  <Step title="読み取り専用のユーザーを作成する">
    <Tabs>
      <Tab title="Self-hosted Redis">
        キーを読み、エージェントが使う診断コマンドを実行でき、それ以外は何もできないユーザーを作成します。

        ```bash
        redis-cli --askpass ACL SETUSER cloudthinker-readonly on \
          '><readonly-password>' '~*' \
          -@all +@read +info +ping +select '+client|list' -keys
        ```

        | 部分 | 意味 |
        |------|---------|
        | `'><readonly-password>'` | パスワードを設定します。`>` は ACL の構文です |
        | `'~*'` | すべてのキーを許可します。`'~app:*'` のようにプレフィックスに絞り込めます |
        | `-@all +@read` | 何もない状態から始め、`GET`、`SCAN`、`TYPE`、`TTL` などの読み取りコマンドを許可します |
        | `+info +ping +select '+client\|list'` | サーバーの統計、ヘルスチェック、データベースインデックスの選択、クライアントの一覧表示を許可します |
        | `-keys` | 大きなインスタンスを停止させる可能性がある `KEYS` をブロックします。エージェントは代わりに `SCAN` を使います |

        `--askpass` は管理者のパスワードを入力させるため、シェルの履歴に残りません。`default` としてサインインしない場合は `--user <admin-user>` を追加します。`'+client|list'` の引用符は残してください。引用符がないと、シェルは `|` をパイプとして解釈します。

        再起動後も残るよう保存します。`aclfile` を使っている場合は `ACL SAVE` を、ユーザーが `redis.conf` にある場合は `CONFIG REWRITE` を実行します。
      </Tab>
      <Tab title="Managed Redis">
        どのプロバイダーでも同じ ACL ルールを使います。コンソールのフィールドには引用符なしで貼り付け、シェルでは `'+client|list'` の引用符を残してください。

        ```text
        ~* -@all +@read +info +ping +select +client|list -keys
        ```

        - **Redis Cloud**: **Data Access Control** に移動します。上記のルールで Redis ACL を追加し、それをデータベースに適用するロールを作成してから、そのロールを持つユーザーを作成します。
        - **Azure Cache for Redis**: `rediss://` で TLS ポート `6380` を使い、キャッシュのファイアウォールのルールで CloudThinker の送信元 IP を許可します。

        その後、そのユーザーの TCP または Redis CLI の接続 URL をコピーします。REST や SDK の URL は使わないでください。CloudThinker は Redis プロトコルで通信します。
      </Tab>
    </Tabs>
  </Step>
  <Step title="ユーザーが読み取り専用であることを確認する">
    ```bash
    redis-cli -u 'rediss://cloudthinker-readonly@redis.example.com:6379' --askpass SET probe 1
    redis-cli -u 'rediss://cloudthinker-readonly@redis.example.com:6379' --askpass INFO memory
    ```

    `redis://` は、サーバーが TLS を使っていない場合にのみ使ってください。サーバーと一致しないスキームは、`NOPERM` ではなく接続エラーで失敗します。

    **成功時の状態:** `SET` が `NOPERM` で失敗し、`INFO memory` がメモリの統計を出力します。
  </Step>
  <Step title="ネットワークアクセスを開く">
    ファイアウォール、セキュリティグループ、またはプロバイダーの許可リストで、CloudThinker の送信元 IP からの Redis のポートへの受信接続を許可します。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。ポートはデフォルトで `6379`、Azure の TLS では `6380`、Redis Cloud ではデータベースごとに割り当てられます。セルフホストの Redis では、`redis.conf` の `bind` が `127.0.0.1` だけになっていないことを確認してください。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Redis** を選んで、詳細パネルの **Connect** をクリックします。ダイアログで必要に応じて **Alias** と **Description** を変更します。**REDIS_URL** に URL を貼り付け、**Connect** をクリックします。

    ```text
    rediss://cloudthinker-readonly:<readonly-password>@redis.example.com:6379/0
    ```

    **成功時の状態:** 接続に **Connecting** と **Verifying** が表示され、その後 **Connected** になります。その後、CloudThinker が[詳細調査](/ja/guide/connections/overview#接続した後に起こること)のチャットを開き、エージェントがサーバーを探索します。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **Alias** | いいえ | このサーバーの短い名前。`redis-1` など、次に空いているエイリアスが入力済みです | `prod-cache` |
| **Description** | いいえ | このサーバーの内容。エージェントはこれを読んでインスタンスを選びます | `Production session cache` |
| **REDIS_URL** | はい | 完全な URL: スキーム、ユーザー、パスワード、ホスト、ポート、任意のデータベースインデックス | `rediss://cloudthinker-readonly:<password>@redis.example.com:6379/0` |

| URL の部分 | 値 |
|----------|--------|
| スキーム | TLS には `rediss://`（Upstash では必須）、プレーンな TCP には `redis://` |
| ユーザー | ACL のユーザー。Upstash とパスワードだけの Redis では `default` を使います |
| ポート | デフォルトは `6379`、Azure の TLS では `6380`。Redis Cloud はデータベースごとにポートを割り当てるため、コンソールからコピーします |
| データベースインデックス | 末尾に `/0` から `/15`。`0` の場合は省略します |

パスワードの特殊文字は URL エンコードしてください（`@` は `%40` になります）。

## 必要な権限

| エージェントにさせたいこと | 許可するもの |
|--------------------|-------|
| キー、型、TTL、サイズ、キー数を読む | `+@read` と `~*` などのキーパターン |
| メモリ、エビクション、ヒット率、レプリケーション、コマンドの統計を読む | `+info` |
| 接続中のクライアントを見る | `+client\|list` |
| `0` 以外のデータベースインデックスを使う | `+select` |
| キーを変更する | `+@write` などの書き込みカテゴリ。推奨しません。[書き込みアクセス](#書き込みアクセス)を参照してください |

<Tip>
ユーザーは読み取り専用のままにしてください。読み取り専用の ACL は、何が承認されても、すべての書き込みを Redis で止めます。
</Tip>

## エージェントの機能

| 機能 | エージェントができること |
|------------|--------------------|
| **Memory and eviction** | 使用メモリ、断片化率、`maxmemory` のポリシー、エビクション、ヒット率を読みます |
| **Keyspace** | データベースごとのキー数を数え、`SCAN` でキーをサンプリングし、型、サイズ、TTL を読みます |
| **Expiration audit** | 各データベースで TTL のあるキーとないキーを比較し、それらに対して `maxmemory` のポリシーを確認します |
| **Largest keys** | サンプリングしたキーをサイズでランク付けします。文字列は長さ、リスト、ハッシュ、セット、ソート済みセットは要素数です。デフォルトのサンプルは `SCAN` による 100 キーのため結果は推定値で、スキャンがすべてのキーをカバーしなかった場合は回答にそう示されます |
| **Clients and latency** | 接続中のクライアントを一覧表示し、`INFO commandstats` からコマンドごとの呼び出し回数とレイテンシーを読みます |
| **Replication** | ロール、接続中のレプリカ、レプリケーションのオフセットを読みます |
| **Modules** | サーバーに RediSearch や RedisJSON のモジュールが読み込まれている場合、RediSearch のインデックスと RedisJSON のドキュメントを読みます |

### 接続を確認する

```text
Summarize Redis memory usage, connected clients, eviction policy, and key counts per database
```

使用メモリとピーク、クライアント数、`maxmemory` のポリシー、各データベースインデックスのキー数が返されることを確認します。`NOPERM` のエラーには、不足しているコマンドが示されます。`ACL SETUSER cloudthinker-readonly` で追加してから、もう一度質問してください。

### プロンプトの例

```text
Which sampled keys are the largest, and what share of keys in each database has no TTL?
Is Redis evicting keys? Show the eviction policy, evictions, and hit rate
Which commands have the highest average latency according to commandstats?
```

## 書き込みアクセス

Redis の接続には書き込みツールがあります。ACL が書き込みを許可している場合、それぞれがまず [Approvals](/guide/approvals/overview) を経由し、[rule](/guide/approvals/rules) で事前確認や拒否を設定できます。

<ApprovalDefault />

| 分類 | ツール |
|---|---|
| 書き込み | set、expire、rename、publish、リストからの pop、ハッシュ、リスト、セット、ソート済みセット、ストリーム、JSON ドキュメントへの追加 |
| 破壊的 | キーの削除、またはハッシュ、リスト、セット、ソート済みセット、ストリーム、JSON ドキュメントからの項目の削除 |
| コマンドによる | 生の Redis コマンド: `GET` などの読み取りは確認なしで実行され、`DEL` や `FLUSHALL` は破壊的とみなされ、それ以外は書き込みとみなされます |

## トラブルシューティング

<Accordion title="NOAUTH または WRONGPASS">
ユーザーまたはパスワードが誤っているか、ありません。URL エンコードも含め、**REDIS_URL** の両方を確認してください。Upstash では、ユーザーに `default` を、パスワードにデータベースのトークンを使います。セルフホストの Redis では、`ACL LIST` を実行してユーザーが存在し `on` であることを確認します。
</Accordion>

<Accordion title="接続が閉じられる、または Connected にならない">
通常は URL の形式の誤りです。スキーム（Upstash が必須とする TLS のエンドポイントでは `rediss://`）、ホスト、ポート、パスワードがあることを確認してください。プロバイダーの REST や SDK の URL は機能しません。TCP または Redis CLI のものを使ってください。
</Accordion>

<Accordion title="Connection refused またはタイムアウト">
CloudThinker がサーバーに到達できません。ファイアウォール、セキュリティグループ、またはプロバイダーの許可リストと、`redis.conf` の `bind` が `127.0.0.1` だけになっていないことを確認してください。プライベートネットワーク上のサーバーには、まず到達可能なエンドポイントが必要です。
</Accordion>

<Accordion title="INFO、CLIENT LIST、または読み取りコマンドで NOPERM が出る">
ACL にコマンドが不足しています。`ACL SETUSER cloudthinker-readonly ...` で `+info`、`'+client|list'`、またはエラーが示すカテゴリを追加してから、もう一度質問してください。書き込みコマンドでの `NOPERM` は、読み取り専用のユーザーでは想定どおりです。
</Accordion>

<Accordion title="Command is not available: FT.* or JSON.*">
サーバーに RediSearch または RedisJSON のモジュールが読み込まれていません。多くのホスト型のプランにはこれらが含まれていません。それ以外はすべて引き続き機能します。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **`rediss://` を使う**: プレーンな `redis://` では、パスワードとすべての値が暗号化されずに送信されます。サーバーやプロバイダーが対応している場合は常に TLS を使ってください。
- **キーの範囲を限定する**: `~*` を、`~cache:*` のようにエージェントが必要とするプレフィックスに置き換え、セッショントークンやその他の機密のキーに手が届かないようにしてください。

Dynatrace 環境を接続すると、CloudThinker エージェントが未解決の問題を一覧表示し、Grail のログ、メトリクス、スパン、イベントに対して DQL（Dynatrace Query Language）を実行し、脆弱性を確認し、問題が影響するエンティティを見つけられるようになります。この接続は公式の Dynatrace MCP サーバーを使い、1 つの環境に対して 1 つの **platform token** でサインインします。

## 前提条件

- エージェントに読ませたいデータを持つ、Dynatrace Platform（Grail）上の Dynatrace SaaS 環境。Dynatrace Managed や、`apps.dynatrace.com` のアドレスを持たないクラシック環境は接続できません。
- エージェントにクエリさせるデータを読み取れる、その環境のアカウントの Dynatrace ユーザー（またはサービスユーザー）。アカウントのメンバーなら誰でも platform token を作成できますが、トークンにはそのユーザーの権限しか与えられません。
- Platform 形式の環境 URL: `https://<environment-id>.apps.dynatrace.com`。

## セットアップ

<Steps>
  <Step title="環境 URL を確認する">
    Dynatrace にサインインし、ブラウザのアドレスを `.apps.dynatrace.com` までコピーします（例: `https://abc12345.apps.dynatrace.com`）。

    クラシックの `live.dynatrace.com` ではなく、`apps.dynatrace.com` のアドレスを使ってください。MCP サーバーは Platform API とのみ通信します。
  </Step>
  <Step title="platform token を作成する">
    Dynatrace アカウントで **My platform tokens**（[myaccount.dynatrace.com/platformTokens](https://myaccount.dynatrace.com/platformTokens)）を開き、**Platform token** を選択します。次を設定します。
    - **Token name**: `cloudthinker`
    - **Expiration date**: ローテーションポリシーに合った有効期間
    - **Environments**: トークンをアカウント全体に適用する場合を除き、前のステップで確認した環境
    - **Scopes**: `app-engine:apps:run` と、エージェントにクエリさせたいデータの読み取りスコープ（[必要な権限](#必要な権限)を参照）

    **Generate** をクリックしてトークンをコピーします。Dynatrace は一度しか表示しません。トークンはそのユーザーに許可されたことしかできないため、そのデータを読み取れるユーザー（またはサービスユーザー）として作成してください。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Dynatrace** を選択します。次を入力します。

    - **DT_ENVIRONMENT**: 環境 URL
    - **DT_PLATFORM_TOKEN**: 作成したトークン

    **Connect** をクリックします。

    **成功時の状態:** Dynatrace に **Connected** と表示されます。下の確認用プロンプトを実行して、トークンで環境を読み取れることを確認してください。
  </Step>
</Steps>

<Warning>
クラシックの Dynatrace API トークンではなく、**platform token** を使ってください。クラシックの API トークンには MCP サーバーが必要とする Platform スコープがないため、ほとんどのリクエストが 401 または 403 で失敗します。
</Warning>

## 接続の詳細

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **DT_ENVIRONMENT** | Dynatrace Platform の環境 URL | `https://abc12345.apps.dynatrace.com` |
| **DT_PLATFORM_TOKEN** | その環境の platform token | `<your-platform-token>` |

別の環境に接続するには、専用のトークンを持つ別の接続として追加してください。

## 必要な権限

`app-engine:apps:run` から始め、エージェントにクエリさせるデータタイプの読み取りスコープだけを追加してください。

| スコープ | 有効になるもの |
|-------|-----------------|
| `app-engine:apps:run` | 必須。Dynatrace MCP ツールを実行します |
| `storage:buckets:read` | トークンが読み取れる Grail バケットの検出 |
| `storage:logs:read` | DQL によるログのクエリ |
| `storage:metrics:read` | DQL によるメトリクスのクエリ |
| `storage:spans:read` | DQL によるトレースとスパンのクエリ |
| `storage:events:read` | DQL によるイベントのクエリ |
| `storage:entities:read` | DQL による監視対象エンティティのクエリ |
| `storage:smartscape:read` | DQL による Smartscape トポロジーのクエリ |
| `storage:security.events:read` | DQL によるセキュリティイベントのクエリ |
| `storage:bizevents:read` | DQL によるビジネスイベントのクエリ |
| `storage:user.events:read` | DQL によるユーザーイベントのクエリ |
| `storage:user.sessions:read` | DQL によるユーザーセッションのクエリ |
| `storage:system:read` | DQL によるシステムデータのクエリ |
| `storage:files:read` | DQL の `load` ステートメントでのルックアップデータの使用 |
| `document:documents:write` | 任意。エージェントが Dynatrace ノートブックを作成できるようにします |

任意のツールには追加のスコープが必要です。エージェントに使わせたいものだけを追加してください。

| ツール | 追加のスコープ |
|------|--------------|
| Davis analyzers | 一覧表示には `davis:analyzers:read`、実行には `davis:analyzers:execute` |
| DQL help | `davis-copilot:nl2dql:execute`（質問を DQL に変換）、`davis-copilot:dql2nl:execute`（クエリを説明） |
| Send an event | `storage:events:write` |
| Send an email | `email:emails:send` |

完全な一覧は [Dynatrace MCP server README](https://www.npmjs.com/package/@dynatrace-oss/dynatrace-mcp-server) にあります。

<Tip>
あるデータタイプでは DQL が動作し、別のデータタイプでは失敗する場合、トークンにそのタイプの `storage:*:read` スコープがありません。Dynatrace でスコープを追加し、接続のトークンを更新してください。
</Tip>

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **Environment check** | 接続を確認し、基本的な環境情報を読む | 不要 |
| **Problems** | 未解決および最近の問題と、それが影響するサービスやホストを一覧表示する | 不要 |
| **Vulnerabilities** | リスクスコア（例: 7.0 以上）で絞り込んで脆弱性を一覧表示する | 不要 |
| **Entities** | 名前で監視対象エンティティを見つける | 不要 |
| **DQL** | クエリを検証してから、少ないレコード上限で実行する | 不要 |
| **DQL help** | 自然言語の質問を DQL に変換する、または既存のクエリを説明する（追加のスコープが必要） | 不要 |
| **Kubernetes events and exceptions** | クラスターやワークロードの Kubernetes イベントと、最近の例外を一覧表示する | 不要 |
| **Davis analyzers** | 利用可能な Davis アナライザーを一覧表示し、期間を指定して実行する（追加のスコープが必要） | 不要 |
| **Notebooks** | 調査結果を含む Dynatrace ノートブックを作成する | 必要 |
| **Notifications and events** | Dynatrace 経由でメールを送信する、イベントを送信する、または通知ワークフローを作成する（追加のスコープが必要） | 必要 |

エージェントは各 DQL クエリを実行前に検証し、50〜100 件のレコードから始めます。これはコストの面で重要です。DQL クエリは Grail のデータをスキャンし、Dynatrace の消費量にカウントされる場合があります（[Dynatrace pricing](https://www.dynatrace.com/pricing/) を参照）。MCP サーバーは **Grail query budget**（クエリがスキャンしたデータの累計）も保持しており、使い切るとクエリを停止します。すべての書き込みは [Approvals](/guide/approvals/overview) を経由し、却下された呼び出しは再試行されません。

### 接続の確認

```text
Run Dynatrace discovery and list open problems and high-risk vulnerabilities
```

環境情報、影響を受けるエンティティ付きの未解決の問題、リスクスコア 7.0 以上の脆弱性が表示されるはずです。トークンに Davis のスコープがある場合は、Davis アナライザーの一覧も表示されます。

### プロンプト例

```text
Which Dynatrace problems are open in production right now, and which services do they affect?
Query Dynatrace logs for errors from the checkout service in the last 30 minutes
List Dynatrace vulnerabilities with a risk score of 7 or higher on internet-facing services
Show the Kubernetes events for the payments workload in the last hour
```

大規模な環境では、サービス、エンティティ、バケットと短い期間を指定してください。範囲を絞ったクエリほど速く返り、Grail の予算の消費も少なくなります。

## トラブルシューティング

<Accordion title="Connect が失敗する、またはすべてのリクエストが 401 を返す">
トークンがない、期限切れ、取り消された、またはクラシックの API トークンです。`app-engine:apps:run` を持つ新しい platform token を作成し、接続を編集して **DT_PLATFORM_TOKEN** に貼り付けてください。また、**DT_ENVIRONMENT** が `live.dynatrace.com` ではなく `apps.dynatrace.com` を使っていることも確認してください。
</Accordion>

<Accordion title="一部のクエリが 403 を返す">
トークンにそのデータタイプのスコープがありません。たとえば、ログのクエリには `storage:logs:read` が必要です。Dynatrace でスコープを追加し、接続を更新してください。
</Accordion>

<Accordion title="DQL クエリが 0 行を返す">
クエリが、トークンで読み取れないバケット、データのない時間範囲、またはスペルミスのあるエンティティを対象にしている可能性があります。まずエージェントに名前でエンティティを見つけさせ、既知のサービスと短い期間でクエリを再実行してください。
</Accordion>

<Accordion title="リクエストが 429 を返す">
Grail query budget を使い切りました。エージェントにリセットを依頼し（リセットは他の書き込みと同様に Approvals を経由します）、次のクエリのスキャン量が減るよう期間とレコード上限を絞ってください。
</Accordion>

<Accordion title="エンティティや問題が見つからない（404）">
エンティティの名前が変更されたか、ID が間違っています。ID ではなく名前で検索するようエージェントに依頼してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **platform token、まず読み取りスコープ**: `document:documents:write` や通知用のスコープは、エージェントに Dynatrace 経由でノートブックを作成させたり、メッセージを送信させたりしたい場合にのみ追加してください。
- **接続ごとに 1 つのトークン**: CloudThinker 専用のトークンを作成すれば、他のツールに影響を与えずに取り消せます。

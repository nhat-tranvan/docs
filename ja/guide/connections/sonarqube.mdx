SonarQube を接続すると、CloudThinker エージェントは品質ゲートが失敗した理由を説明し、その原因となっている blocker と高重大度の issue を一覧表示し、未対応のセキュリティホットスポットを確認し、テストカバレッジが最も低いファイルを見つけられます。この接続は SonarQube の**ユーザートークン** 1 つでサインインし、公式の SonarSource MCP サーバーを実行するため、SonarQube Cloud とセルフホストの SonarQube Server の両方で使えます。

## 前提条件

- SonarQube Cloud の組織、または CloudThinker から HTTPS で到達できる SonarQube Server か Community Build のインスタンス。プライベートなインスタンスについては [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- エージェントに読ませたいプロジェクトで **Browse** 権限を持つ、CloudThinker 用の SonarQube アカウント（[必要な権限](#必要な権限)を参照）。
- 接続を追加するために必要な、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Tabs>
  <Tab title="SonarQube Cloud">
    <Steps>
      <Step title="ユーザートークンを生成する">
        CloudThinker が使うアカウントで [SonarQube Cloud](https://sonarcloud.io) にサインインします。**My Account → Security** に移動し、`cloudthinker` などの名前を入力して有効期限を設定し、**Generate Token** をクリックします。

        トークンをコピーします。SonarQube がトークンを表示するのは一度だけです。
      </Step>
      <Step title="組織キーを確認する">
        組織を開きます。キーは URL の最後の部分です: `https://sonarcloud.io/organizations/<org-key>`。
      </Step>
      <Step title="プロジェクトに Browse を付与する">
        エージェントに読ませたい各プロジェクトについて、プロジェクトを開き、**Administration → Permissions** に移動して、CloudThinker のアカウントに **Browse** を付与します。これがないと、確認用のプロンプトは空で返ります。
      </Step>
      <Step title="CloudThinker で接続を追加する">
        **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **SonarQube** を選択します。次を入力します:

        - **SONARQUBE_TOKEN**: コピーしたトークン
        - **SONARQUBE_DEPLOYMENT_TYPE**: **SonarQube Cloud**
        - **SONARQUBE_ORG**: 組織キー

        **Connect** をクリックします。

        **成功の状態:** **Connect SonarQube** ダイアログがエラーなしで閉じます。下の確認用プロンプトを実行してください。
      </Step>
    </Steps>
  </Tab>
  <Tab title="SonarQube Server">
    <Steps>
      <Step title="ユーザートークンを生成する">
        CloudThinker が使うアカウントで SonarQube インスタンスにサインインします。**My Account → Security** に移動し、`cloudthinker` などの名前を入力し、**User Token** タイプを選んで有効期限を設定し、**Generate** をクリックします。

        トークンをコピーします。SonarQube がトークンを表示するのは一度だけです。
      </Step>
      <Step title="プロジェクトに Browse を付与する">
        エージェントに読ませたい各プロジェクトについて、プロジェクトを開き、**Project Settings → Permissions** に移動して、CloudThinker のアカウントに **Browse** を付与します。権限テンプレートを使うと、多くのプロジェクトに一度に同じ設定ができます。これがないと、確認用のプロンプトは空で返ります。
      </Step>
      <Step title="CloudThinker で接続を追加する">
        **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **SonarQube** を選択します。次を入力します:

        - **SONARQUBE_TOKEN**: コピーしたトークン
        - **SONARQUBE_DEPLOYMENT_TYPE**: **SonarQube Server**
        - **SONARQUBE_URL**: インスタンスのアドレス（例: `https://sonarqube.example.com`）

        **Connect** をクリックします。

        **成功の状態:** **Connect SonarQube** ダイアログがエラーなしで閉じます。下の確認用プロンプトを実行してください。
      </Step>
    </Steps>
  </Tab>
</Tabs>

## 接続の詳細

フォームには、選んだデプロイタイプに応じて **SONARQUBE_ORG** または **SONARQUBE_URL** が表示されます。**SonarQube Cloud** を選ぶと `sonarcloud.io` に接続します。リージョンのフィールドはありません。

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **SONARQUBE_TOKEN** | CloudThinker のアカウントのユーザートークン | `squ_...` |
| **SONARQUBE_DEPLOYMENT_TYPE** | Cloud の組織には **SonarQube Cloud**（デフォルト）、セルフホストの Server または Community Build のインスタンスには **SonarQube Server** | SonarQube Cloud |
| **SONARQUBE_ORG** | 組織キー。Cloud のみ | `my-org` |
| **SONARQUBE_URL** | インスタンスのアドレス（HTTPS）。Server のみ | `https://sonarqube.example.com` |

## 必要な権限

ユーザートークンは、それを作成したアカウントの権限で動作します。SonarQube で、プロジェクトごとまたは権限テンプレートを通じて、そのアカウントにプロジェクトの権限を付与してください。

| 目的 | SonarQube の権限 |
|------|----------------------|
| プロジェクト、品質ゲート、issue、メジャー、カバレッジ、重複、ホットスポットの読み取り | **Browse** |
| issue の状態の変更（false positive としてマークするなど） | **Administer Issues** |
| セキュリティホットスポットのレビューと状態の設定 | **Administer Security Hotspots** |

<Tip>
まずは **Browse** だけで始めてください。これだけでエージェントはすべてのゲートと issue を説明できます。2 つの Administer 権限は、エージェントに状態の変更を提案させたいプロジェクトにだけ追加してください。
</Tip>

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **検出** | プロジェクトを、品質ゲートの状態（**OK** または **ERROR**）と重大度別の issue 数とともに一覧表示します | 不要 |
| **品質ゲート** | プロジェクトまたはプルリクエストのゲートの状態と、失敗した条件を確認します | 不要 |
| **Issues** | プロジェクト、プルリクエスト、重大度、状態で issue を検索し、issue の原因となるルールと修正ガイダンスを表示します | 不要 |
| **セキュリティホットスポット** | レビュー対象のホットスポットを一覧表示し、それぞれのコードとリスクを表示します | 不要 |
| **メジャー、カバレッジ、重複** | コード行数、カバレッジ、バグ、脆弱性、コードスメル、重複行を読み、カバレッジがしきい値を下回るファイルを見つけます | 不要 |
| **状態の変更** | issue の状態を変更する、またはホットスポットをレビューします | Approvals を通ります |

重大度の名前はインスタンスのモードに従います。Multi-Quality Rule モードでは **BLOCKER**、**HIGH**、**MEDIUM**、**LOW**、**INFO** を報告します。Standard Experience では **BLOCKER**、**CRITICAL**、**MAJOR**、**MINOR**、**INFO** を報告します。

<ApprovalDefault />

拒否されたリクエストは再試行されません。issue を false positive としてマークするなど、各状態の変更を自分で決めたい場合は、**Manual** を選んですべての変更を人が承認するようにしてください。**Ask first** の [Rule](/guide/approvals/rules) を使うと、それを SonarQube の接続だけに絞れます。一部のツールは SonarQube のエディションに依存します。依存関係のリスクには Advanced Security ライセンスが必要で、システムヘルスのツールは SonarQube Server でのみ動作します。

エージェントは各プロジェクトの数値を現時点のものとして報告します。SonarQube は現在のメジャーを返すため、ブランチやプルリクエストの比較を依頼しない限り、エージェントが傾向を主張することはありません。

### 接続を確認する

```text
List my SonarQube projects with their quality gate status and issue counts by severity
```

プロジェクトキーと名前の表に、それぞれのゲートの状態 **OK** または **ERROR** と、**BLOCKER** などの重大度別の issue 数が返るはずです。

### プロンプト例

```text
Why did the quality gate fail on payments-api? List the failed conditions and the blocker issues behind them
Show the security hotspots still to review in payments-api, highest risk first
Which files in payments-api have under 50% coverage?
```

実際のプロジェクトキーを使ってください。エージェントはプロジェクト一覧からキーを調べ、推測はしません。

## トラブルシューティング

<Accordion title="リクエストが 401 を返す">
トークンが間違っているか、期限切れか、取り消されています。新しいユーザートークンを生成し、接続を編集して **SONARQUBE_TOKEN** に貼り付けてください。
</Accordion>

<Accordion title="SonarQube Server で Connect が失敗する">
CloudThinker が **SONARQUBE_URL** に到達できません。アドレスが HTTPS で、`localhost` やプライベートなホスト名ではなくインターネットから到達できること、そして SonarQube サービスが動作していることを確認してください。
</Accordion>

<Accordion title="プロジェクトが 1 つも返らない（Cloud）">
**SONARQUBE_ORG** が間違っているか、トークンのアカウントがその組織のメンバーではありません。組織の URL からキーをコピーし、メンバーであることを確認してください。
</Accordion>

<Accordion title="一部のプロジェクトが表示されない">
トークンのアカウントにそれらのプロジェクトの **Browse** がありません。SonarQube でそれらのプロジェクトに **Browse** を付与してください。再接続は不要で、権限は次のリクエストから適用されます。
</Accordion>

<Accordion title="状態の変更で 403 が返る">
アカウントにそのプロジェクトの **Administer Issues** または **Administer Security Hotspots** がありません。SonarQube で権限を付与してから、もう一度依頼してください。
</Accordion>

<Accordion title="依存関係のリスクやシステムヘルスが使えない">
ご利用のエディションにそれらのツールが含まれていません。依存関係のリスクには Advanced Security ライセンスが必要で、システムヘルスのツールは SonarQube Server にのみあります。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **ユーザートークンを使う**: SonarQube Server では、Global Analysis Token ではなく **User Token** タイプを選んでください。そうすればアクセスは 1 つのアカウントのプロジェクト権限に従います。
- **有効期限を設定する**: トークンに有効期限を設定し、期限切れになる前にローテーションしてください。

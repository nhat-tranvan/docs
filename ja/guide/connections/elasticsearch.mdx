Elasticsearch クラスターを接続すると、CloudThinker のエージェントがインシデントの調査中に、インデックスの一覧表示、フィールドマッピングの読み取り、DSL 検索と ES|QL クエリの実行、シャードの割り当ての確認を行えるようになります。接続は **API キー** または **ユーザー名とパスワード** でサインインし、公開されるツールはすべて読み取りです。

## 前提条件

- CloudThinker がネットワーク経由で到達できる HTTPS エンドポイントを持つ Elasticsearch クラスター（Elastic Cloud のデプロイや公開 DNS 名など）。`localhost` やプライベートアドレスには CloudThinker Cloud から到達できません。
- ファイアウォールや Elastic Cloud のトラフィックフィルターがクラスターを保護している場合は、CloudThinker の送信元 IP を許可してください。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その他の選択肢は [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- API キー（Kibana の **Stack Management → Security → API keys**、または `_security/api_key` API）または専用ユーザーを作成する権限。
- エージェントに読ませるインデックスパターン（`logs-*` や `filebeat-*` など）。

## セットアップ

<Steps>
  <Step title="読み取り専用の API キーを作成する">
    Kibana で **Dev Tools** を開き、下のリクエストを実行します。`logs-*` は自分のインデックスパターンに置き換えてください。

    ```http
    POST /_security/api_key
    {
      "name": "cloudthinker",
      "expiration": "90d",
      "role_descriptors": {
        "cloudthinker_read": {
          "cluster": ["monitor"],
          "indices": [
            {
              "names": ["logs-*"],
              "privileges": ["read", "view_index_metadata", "monitor"]
            }
          ]
        }
      }
    }
    ```

    レスポンスの `encoded` の値をコピーします。Elasticsearch は一度しか表示しません。

    **Stack Management → Security → API keys** で **Create API key** をクリックし、**Control security privileges** をオンにして同じ `role_descriptors` オブジェクトを貼り付けて、キーを作成することもできます。
  </Step>
  <Step title="クラスターのエンドポイントをコピーする">
    `https://elasticsearch.example.com:9200` のように、スキームとポートを含む完全な URL を使います。Elastic Cloud では、デプロイのページから Elasticsearch のエンドポイントをコピーします。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Elasticsearch** を選びます。**ES_URL** にエンドポイントを入力し、**Authentication** で **API key** を選んで、encoded のキーを貼り付けます。クラスターが自己署名証明書を使っている場合を除き、**TLS certificate** は **Verify** のままにします。**Connect** をクリックします。

    **成功時の状態:** 接続に **Connecting** と **Verifying** が表示され、その後 **Connected** になります。テストが失敗すると、クラスターが返したメッセージとともにエラーが表示されます。[トラブルシューティング](#トラブルシューティング)と照合してください。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **ES_URL** | はい | スキームとポートを含むクラスターのエンドポイント | `https://elasticsearch.example.com:9200` |
| **Authentication** | はい | **API key**（デフォルト）または **Username & password** | **API key** |
| **API key** | API key の場合のみ | 作成時のレスポンスの `encoded` の値 | `VnVhQ2ZHY0JDZGJr...` |
| **Username** | Username & password の場合のみ | 専用の Elasticsearch ユーザー | `cloudthinker` |
| **Password** | Username & password の場合のみ | そのユーザーのパスワード | |
| **TLS certificate** | いいえ | **Verify**（デフォルト）または **Allow self-signed** | **Verify** |

方式は 1 つだけ入力してください。API キーとユーザー名またはパスワードの両方を入力すると、"Choose either an API key or username and password." というメッセージで接続が拒否されます。

## 必要な権限

| エージェントに必要なこと | 付与するもの |
|----------------|-------|
| クラスターのヘルスを確認する | クラスター権限 `monitor` |
| インデックスを一覧表示し、シャードの割り当てを読む | パターンに対するインデックス権限 `monitor` |
| フィールドマッピングを読む | パターンに対するインデックス権限 `view_index_metadata` |
| DSL 検索と ES\|QL クエリを実行する | パターンに対するインデックス権限 `read` |

**Username & password** を使う場合は、同じ権限を持つロールと、そのロールを持つユーザーを作成します。各リクエストは **Dev Tools** で個別に実行してください。

```http
POST /_security/role/cloudthinker_read
{
  "cluster": ["monitor"],
  "indices": [
    {
      "names": ["logs-*"],
      "privileges": ["read", "view_index_metadata", "monitor"]
    }
  ]
}
```

```http
POST /_security/user/cloudthinker
{
  "password": "<a long random password>",
  "roles": ["cloudthinker_read"]
}
```

<Tip>
`*` ではなく、エージェントが必要とするインデックスパターンを列挙してください。`logs-*` にスコープを限定したキーは、検索で求められても `customers` インデックスを読めません。
</Tip>

## エージェントの機能

| 機能 | エージェントができること |
|------------|--------------------|
| **Index inventory** | インデックスをステータスとドキュメント数とともに一覧表示し、`logs-app-*` などの命名パターンを見つけます |
| **Mappings** | 絞り込む前にフィールド名と型を読み、存在するフィールドをクエリで使うようにします |
| **Search** | 期間、並べ替え、結果サイズを指定した範囲付きの DSL クエリを実行します |
| **ES\|QL** | サービスごとのエラー数など、ES\|QL で集計します。常に `LIMIT` を付けます |
| **Shards and health** | 未割り当てのシャードを見つけ、クラスターのヘルスを green、yellow、red で報告します |

この接続には、書き込み、削除、クラスター設定の変更を行うツールはありません。

### 接続を確認する

```text
Check Elasticsearch cluster health and list the five largest indices by document count
```

ヘルスのステータス、未割り当てのシャードを含むシャード数、ドキュメント数付きの 5 つのインデックス名が返されることを確認します。

### プロンプトの例

```text
Count ERROR log lines per service in logs-app-* over the last hour
Search logs-* for authentication failures in the last 24 hours and group them by source IP
Why is the cluster yellow? List the unassigned shards and the indices they belong to
```

## トラブルシューティング

<Accordion title="接続がタイムアウトまたは connection refused で失敗する">
**ES_URL** が、CloudThinker が到達できないアドレスを指しています。公開エンドポイントを使い、スキームとポートを含め、ファイアウォールや Elastic Cloud のトラフィックフィルターが CloudThinker の送信元 IP を許可していることを確認してください（[前提条件](#前提条件)を参照）。
</Accordion>

<Accordion title="401 Unauthorized">
API キーが誤っている、期限切れ、または無効化されているか、パスワードが変更されています。新しいキーを作成し、`id` や `api_key` フィールドだけではなく `encoded` の値で[認証情報を置き換え](/ja/guide/connections/overview#認証情報をローテーションする)てください。
</Accordion>

<Accordion title="1 つのインデックスで security_exception が発生する">
キーまたはユーザーに、そのインデックスへの権限がありません。新しいキーの `names` にそのパターンを追加してから、接続の[認証情報を置き換え](/ja/guide/connections/overview#認証情報をローテーションする)てください。
</Accordion>

<Accordion title="セルフホストのクラスターで証明書エラーが発生する">
クラスターが自己署名証明書を使っています。そのクラスターを信頼できる場合にのみ、**TLS certificate** を **Allow self-signed** に設定してください。
</Accordion>

<Accordion title="検索が何も返さない">
インデックスパターンが一致しない、フィールド名がプロンプトの想定と異なる、または期間にデータがありません。まずインデックスを一覧表示し、そのインデックスのマッピングを読むようエージェントに依頼してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **キーに有効期限を設定する**: `90d` などの `expiration` により、漏洩したキーが使える期間を制限できます。期限切れになる前に新しいキーを作成し、接続を開いて行の鉛筆アイコンをクリックし、**Edit Instance** で **Replace…** をクリックします。新しいキーを貼り付けて **Save and test** をクリックします。テストが失敗した場合、CloudThinker は古いキーを保持するため、切り替え中にエージェントがアクセスを失うことはありません。
- **インデックスされた内容は機密として扱う**: ログには、アプリケーションが書き込んだトークンや個人データが含まれていることがあります。キーは、エージェントに読ませたいインデックスにスコープを限定してください。

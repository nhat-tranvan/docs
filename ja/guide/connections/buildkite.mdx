Buildkite を接続すると、CloudThinker エージェントがパイプラインの健全性を測定し、ログとアノテーションからビルドの失敗原因を見つけ、エージェントのキャパシティを確認できるようになります。この接続は Buildkite の API アクセストークンを使い、付与したスコープがエージェントにできることの厳格な上限になります。

## 前提条件

- エージェントに監視させたい組織にアクセスできる Buildkite アカウント。
- その組織の API アクセストークンを作成する権限。

## セットアップ

<Steps>
  <Step title="API アクセストークンを作成する">
    Buildkite で **Personal Settings → API Access Tokens → New API Access Token**（[buildkite.com/user/api-access-tokens/new](https://buildkite.com/user/api-access-tokens/new)）に移動し、次を設定します。
    - **Description**: `cloudthinker`
    - **Organization access**: CloudThinker にアクセスさせる組織
    - **REST API scopes**: `read_organizations`、`read_pipelines`、`read_builds`、`read_build_logs`、`read_artifacts`、`read_agents`、`read_clusters`、`read_user`。エージェントに再試行、ブロック解除、再ビルド、キャンセルをさせたい場合のみ `write_builds` を追加します。

    トークンをすぐにコピーしてください。Buildkite は一度しか表示しません。
  </Step>
  <Step title="接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Buildkite** を選択します。**BUILDKITE_API_TOKEN** にトークンを貼り付け、**Connect** をクリックします。

    **成功時の状態:** ダイアログが閉じ、接続に **Connected** と表示されます。
  </Step>
  <Step title="トークンが機能することを確認する">
    [接続の確認](#接続の確認)のプロンプトを実行します。Buildkite は不正なトークンでも接続を受け付け、エージェントが最初に呼び出したときに初めて拒否するため、**Connected** ステータスだけではトークンが有効であることの証明になりません。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 説明 |
|-------|-------------|
| **BUILDKITE_API_TOKEN** | Buildkite の API アクセストークン。そのスコープによって、どの操作が成功するかが決まります |

入力する組織スラッグはありません。エージェントがトークンから解決します。CloudThinker はトークンを Buildkite がホストする MCP サーバー `https://mcp.buildkite.com/direct` に送信し、そのサーバーがトークンを Buildkite REST API に渡します。このサーバーを運用しているのは CloudThinker ではなく Buildkite です。

## 必要な権限

| スコープ | 必須 | 有効になるもの |
|-------|----------|---------|
| `read_organizations` | はい | トークンがアクセスできる組織の解決 |
| `read_pipelines` | はい | パイプラインの一覧と詳細 |
| `read_builds` | はい | ビルド、ジョブ、アノテーション、失敗サマリー |
| `read_build_logs` | はい | ジョブログの閲覧、検索、末尾追跡 |
| `read_artifacts` | はい | ビルドとジョブのアーティファクト |
| `read_agents` | はい | エージェントの接続状態とキャパシティ |
| `read_clusters` | はい | クラスターとクラスターキュー |
| `read_user` | はい | トークン自身のユーザーの参照 |
| `write_builds` | いいえ | ジョブの再試行、ジョブのブロック解除、再ビルド、キャンセル |

<Tip>
監視専用の接続では `write_builds` を付与しないでください。エージェントはすべての読み取りを維持し、Buildkite 自体があらゆる変更を拒否するため、承認だけに頼らずに済みます。
</Tip>

## エージェントの機能

| 機能 | エージェントができること |
|------------|--------------------|
| **Discovery** | 組織内のパイプライン、最近のビルド、エージェント、クラスターを一覧表示する |
| **Pipeline health** | 成功率、連続失敗回数、プロンプトで指定したしきい値（例: 「30 分以上止まっている」）より長く止まっているビルドを報告する |
| **Failed-build triage** | Buildkite の失敗サマリーをジョブログ、アノテーション、失敗したテストと照合する |
| **Logs and artifacts** | ジョブのログを閲覧、検索、末尾追跡し、ビルドとジョブのアーティファクトを一覧表示・取得する |
| **Capacity** | エージェントの接続状態、クラスター、クラスターキューを表示する |
| **Build controls** | ジョブの再試行、ジョブのブロック解除、ビルドの再ビルド、ビルドのキャンセル。**いずれも Approvals を経由します** |

手動のブロックステップで待機中のビルドは、Buildkite API で `passed` と報告されます。エージェントはゲートの有無を確認し、ブロックステップの名前を示し、そのビルドを成功率から除外するため、保留中のデプロイが緑のパイプラインとして表示されることはありません。ブロック解除の前に、エージェントはブロックステップのラベルとビルドのアノテーションを引用するので、どのゲートを解放するのかがわかります。

エージェントはパイプライン、クラスター、キュー、スケジュールの作成や編集はできず、ジョブの環境変数も読みません。Buildkite Test Engine のデータはこの接続では利用できません。

<ApprovalDefault />

毎回確認を求めるようにするには、[Approval mode](/guide/approvals/approval-mode) で **Manual** を選び、すべての変更を人が承認するようにします。**Ask first** の [Rule](/guide/approvals/rules) を使えば、この接続だけに絞ることもできます。

### 接続の確認

```text
List my Buildkite pipelines and show the latest build status for each
```

各パイプラインがスラッグごとに、最新のビルド状態とともに表示されるはずです。ここで 401 が返る場合は、接続に **Connected** と表示されていてもトークンは無効です。

### プロンプト例

```text
Which Buildkite pipelines are failing right now, and how long is each failure streak?
Build 42 of the web pipeline failed. Pull the logs and annotations and tell me the cause
Show Buildkite agent capacity and any builds stuck for more than an hour
```

## トラブルシューティング

<Accordion title="Connected だが、すべてのリクエストが 401 を返す">
トークンが無効、期限切れ、または取り消されています。新しい API アクセストークンを作成し、接続の **BUILDKITE_API_TOKEN** を更新してください。
</Accordion>

<Accordion title="読み取りで 403 になる">
トークンに読み取りスコープが不足しています。[必要な権限](#必要な権限)と照らし合わせ、Buildkite でトークンのスコープを編集してください。新しいトークンは不要です。
</Accordion>

<Accordion title="再試行、ブロック解除、再ビルド、キャンセルが権限エラーで失敗する">
トークンに `write_builds` がありません。Buildkite でスコープを追加するか、接続を読み取り専用のままにして、操作は Buildkite でご自身で実行してください。
</Accordion>

<Accordion title="ゲートの状態が unknown と表示される">
手動ブロックステップの確認が、通常はレート制限のために失敗しました。エージェントはそのビルドを未完了として扱い、成功率から除外します。unknown はゲートがないという意味ではありません。1 分後にもう一度依頼してください。
</Accordion>

<Accordion title="存在するパイプラインで 404 になる">
Buildkite がスラッグを期待している箇所でパイプライン名が使われました。エージェントにパイプラインを一覧表示させ、その一覧のスラッグを使ってください。
</Accordion>

<Accordion title="429 rate limited">
リクエストの対象となるパイプラインやビルドが多すぎました。質問を 1 つのパイプラインに絞るか、取得する最近のビルドの数を減らしてください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **承認だけでなくトークンのスコープを絞る**: Buildkite はトークンのスコープを強制します。`write_builds` のないトークンは CI の状態を一切変更できません。
- **ブロック解除はリリースとして扱う**: ブロックステップは通常、誰かが意図的に追加したデプロイゲートです。エージェントが引用したラベルを読んでからブロック解除を承認してください。

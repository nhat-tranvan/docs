ServiceNow インスタンスを接続すると、CloudThinker のエージェントがオープン中のインシデント、変更リクエスト、問題、CMDB の構成アイテムを確認し、[Approvals](/guide/approvals/overview) を経て更新を行えるようになります。接続は ServiceNow ユーザー（できれば専用のサービスアカウント）の **ユーザー名とパスワード** でサインインします。

## 前提条件

- ServiceNow インスタンスと、`https://<instance>.service-now.com` 形式のその URL。
- そのインスタンスでユーザーを作成しロールを割り当てる権限、またはそれを代わりに行える管理者。
- ServiceNow のローカルパスワードでサインインできるサービスアカウント。インスタンスが SSO を経由させる、または MFA を必要とする場合でも、このアカウントは API 呼び出しのために自身のパスワードで認証できる必要があります。
- 接続の追加に必要な、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Steps>
  <Step title="サービスアカウントを作成する">
    ServiceNow で **User Administration → Users** を開き、**New** をクリックします。

    - **User ID**: `cloudthinker`
    - **Password**: 強力で一意のパスワード
    - **Active**: チェックを入れる

    インスタンスに **Web service access only** が表示される場合はオンにします。これにより、アカウントは API を呼び出せますが、ServiceNow の UI にはサインインできません。
  </Step>
  <Step title="ロールを割り当てる">
    ユーザーレコードに、[必要な権限](#必要な権限)のロールを追加します。まず `itil` と `cmdb_read` から始めます。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **ServiceNow** を選びます。フォームには、フィールド名が下記のとおりに表示されます。次を入力します。

    - **SERVICENOW_INSTANCE_URL**: `https://acme.service-now.com` などのインスタンスの URL
    - **SERVICENOW_USERNAME**: `cloudthinker`
    - **SERVICENOW_PASSWORD**: 設定したパスワード

    **Connect** をクリックします。

    **成功時の状態:** Connect が接続テストを実行し、ServiceNow に **Connected** のステータスが表示されます。テストが失敗した場合は、代わりに理由とともにエラーが表示されます。下の確認用プロンプトを実行して、アカウント自体がレコードを読めることを確認してください。
  </Step>
</Steps>

<Tip>
個人の開発者インスタンスでテストしていますか？手早く試すなら、その管理者アカウントで機能します。本番のインスタンスを接続する前に、専用のアカウントに切り替えてください。
</Tip>

## 接続の詳細

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **SERVICENOW_INSTANCE_URL** | インスタンスのアドレス。末尾のパスは付けません | `https://acme.service-now.com` |
| **SERVICENOW_USERNAME** | サービスアカウントの User ID | `cloudthinker` |
| **SERVICENOW_PASSWORD** | そのユーザーのパスワード | `<password>` |

サブプロダクションなど別のインスタンスに到達するには、別の接続として追加してください。

## 必要な権限

ServiceNow は、ロールとテーブルのアクセスルール（ACL）によってアカウントが見られるものを決めます。エージェントは、アカウントができることだけを読み取り・変更できます。

| ロール | エージェントに与えるもの |
|------|--------------|
| `itil` | インシデント、変更リクエスト、問題の読み取りと更新 |
| `cmdb_read` | CMDB の構成アイテムとその関係の読み取り |

<Tip>
読み取り専用で使う場合は、`itil` の代わりに、`incident`、`change_request`、`problem`、`sys_user`、`sys_user_group`、`cmdb_ci` の各テーブルへの読み取りアクセスを持つカスタムロールを ServiceNow の管理者に依頼してください。エージェントは引き続き調査でき、書き込みはすべて ServiceNow で失敗します。エージェントにクエリやスキーマの読み取りをさせたい他のテーブルにも読み取りアクセスを追加してください。そうしないと、それらの読み取りも失敗します。
</Tip>

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **Incidents** | 状態、優先度、クエリでインシデントを一覧表示・読み取ります | 不要 |
| **Changes and problems** | 変更リクエストとアクティブな問題を一覧表示します | 不要 |
| **CMDB** | 構成アイテムを一覧表示し、その依存関係をたどります | 不要 |
| **Users and groups** | ユーザー、グループ、割り当てを調べます | 不要 |
| **Any table** | テーブルをクエリし、そのスキーマを読み、平易な言葉でテーブルをまたいで検索します | 不要 |
| **Incident updates** | インシデントの作成、割り当て、解決、クローズ。コメントや作業メモの追加 | Approvals を経由 |
| **Change and problem updates** | 変更リクエストの割り当てや承認、問題へのコメント、問題のクローズ | Approvals を経由 |
| **Record updates** | アカウントが書き込める任意のテーブルで、レコードを作成・更新します | Approvals を経由 |

読み取りは確認なしで実行されます。

<ApprovalDefault />

<Warning>
**Any table** の読み取りは事前に確認しないため、エージェントはアカウントが読めるすべてのテーブル（人事やユーザーのレコードを含む）を読めます。機密のテーブルは、アカウントのロールと ACL から外してください。
</Warning>

変更リクエストを承認するには、アカウントが ServiceNow でその変更の承認者になっている必要もあります。`itil` ロールだけでは承認者にはなりません。

### Resolve と組み合わせて使う

ServiceNow は [Resolve](/guide/incident/triggers-and-outcomes#outcomes) と連携します。**Resolve → Triggers & Outcomes → ServiceNow** で、**Create follow-up tickets** のアウトカムは、インシデントの対応が終わったときに残りの作業のための ServiceNow のレコードを登録します。**Assignment group**（例: `Cloud Operations`）を設定してください。ServiceNow は [Webhook シグナル](/ja/guide/incident/webhook-integrations/overview)としてインシデントを Resolve に送ることもできます。

### 接続を確認する

```text
List open P1 and P2 incidents in ServiceNow with their number, assignment group, and state
```

インシデントの短い表、または「オープン中のインシデントはありません」という明確な回答が返されることを確認します。権限エラーは、アカウントに `itil` またはテーブルの読み取りアクセスがないことを意味します。

### プロンプトの例

```text
Which ServiceNow change requests scheduled this week touch production, and which are still waiting for approval?
Find ServiceNow problems with more than three linked incidents in the last 30 days
Map what depends on the CMDB item payments-db-01 before we patch it
```

サービス、CI、または期間を指定してください。ServiceNow のテーブルには数百万行が含まれることがあるため、絞り込んだ依頼のほうが早く返ります。

## トラブルシューティング

<Accordion title="Connect が失敗する、またはリクエストが 401 を返す">
ユーザー名またはパスワードが誤っているか、ユーザーが非アクティブであるか、アカウントがロックされています。管理者として ServiceNow にサインインし、ユーザーレコードを確認し、必要に応じてパスワードをリセットして、接続を編集してください。

パスワードが正しい場合は、SSO や MFA がこのアカウントのパスワードによるサインインをブロックしていないか確認してください。アカウントには、API 呼び出しで機能するローカルパスワードが必要です。
</Accordion>

<Accordion title="一部のテーブルで権限エラーが返る">
アカウントに、そのテーブルのロールまたは ACL がありません。CMDB の読み取りには `cmdb_read` が、インシデント、変更、問題の読み取りには `itil` または同等のカスタムロールが必要です。ServiceNow でロールを追加して、もう一度質問してください。再接続は不要です。
</Accordion>

<Accordion title="リクエストがタイムアウトする、または 503 を返す">
インスタンスがメンテナンス中か、休止しています。個人の開発者インスタンスはアイドル時に休止するため、ServiceNow の開発者ポータルから起動してから再試行してください。また、インスタンスが IP アクセスルールで CloudThinker をブロックしていないことも確認してください。CloudThinker を許可するには、そのルールに CloudThinker の送信元 IP を追加します。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。
</Accordion>

<Accordion title="番号でレコードが見つからない">
エージェントは、`INC0012345` のような番号ではなく `sys_id` でレコードを検索します。検索が失敗した場合は、代わりに番号での検索を依頼してください。

```text
Search ServiceNow incidents for number INC0012345 and show its state and assignment group
```

インスタンスの URL が誤っている場合も「not found」と表示されるため、ブラウザのアドレスと一致していることを確認してください。
</Accordion>

<Accordion title="リクエストが 429 を返す">
インスタンスが API 呼び出しをレート制限しています。1 分待ち、より絞り込んだ質問をして、もう一度試してください。ServiceNow の管理者がインスタンスのレート制限のルールを確認できます。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **専用のサービスアカウント**: **Web service access only** をオンにした CloudThinker 専用のアカウントを使えば、人に影響を与えずにローテーションや無効化ができます。
- **admin ではなくロールを使う**: 本番のインスタンスを `admin` ロールで接続しないでください。`itil` と `cmdb_read` で、インシデント、変更、問題、CMDB の作業をカバーできます。変更を承認するにはアカウントを承認者に設定する必要もあり、**Any table** の読み取りには各テーブルへの読み取りアクセスが必要です。

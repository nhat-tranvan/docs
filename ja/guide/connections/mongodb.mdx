MongoDB のデプロイまたは MongoDB Atlas のクラスターを接続すると、CloudThinker のエージェントがデータベース、コレクション、インデックス、クエリプランを調べられるようになります。専用のデータベースユーザーの接続文字列を 1 つ CloudThinker に渡し、接続は常に読み取り専用モードで実行されます。エージェントはクエリと explain はできますが、挿入、更新、削除（drop）、インデックスの作成はできません。

## 前提条件

- CloudThinker がインターネットから到達できる MongoDB のデプロイまたは Atlas のクラスター。エージェントは CloudThinker Cloud から接続するため、`localhost` やプライベートアドレスはあなたのネットワークではなく CloudThinker 側で解決されます。Atlas のプライベートエンドポイントと VPC ピアリングには対応していません。[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- データベースユーザーを作成する権限: セルフホストの MongoDB では `admin` の `userAdmin`、Atlas では **Project Database Access Admin**（またはそれ以上）。

## セットアップ

<Steps>
  <Step title="読み取り専用のユーザーを作成する">
    <Tabs>
      <Tab title="Self-hosted MongoDB">
        管理者として `mongosh` で接続し、`admin` データベースにユーザーを作成します。

        ```javascript
        use admin
        db.createUser({
          user: "cloudthinker_readonly",
          pwd: "<secure-password>",
          roles: [
            { role: "readAnyDatabase", db: "admin" },  // or { role: "read", db: "shop" } for one database
            { role: "clusterMonitor", db: "admin" }
          ]
        })
        ```
      </Tab>
      <Tab title="MongoDB Atlas">
        Atlas で **Security → Database Access** を開き、**Add New Database User** をクリックします。**Password** 認証を選び、`cloudthinker_readonly` と強力なパスワードを入力して、**Database User Privileges** で組み込みロールの **Only read any database** を選びます。エージェントを 1 つのデータベースに限定するには、代わりに **Specific Privileges** で `read@shop` を追加します。**Add User** をクリックします。

        サーバーのステータス、ログ、レプリカの遅延には、**Specific Privileges** で **clusterMonitor** ロールも追加します。
      </Tab>
    </Tabs>
  </Step>
  <Step title="ネットワークアクセスを開く">
    CloudThinker の送信元 IP がデプロイに到達できるようにします。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。セルフホストの MongoDB では、ファイアウォールまたはセキュリティグループでポート `27017` への受信接続を許可し、`mongod.conf` の `bindIp` が `127.0.0.1` だけになっていないことを確認します。Atlas では、**Security → Network Access → IP Access List** で IP ごとにエントリを 1 つ追加します。
  </Step>
  <Step title="接続文字列を作成する">
    <Tabs>
      <Tab title="Self-hosted MongoDB">
        レプリカセットの場合は、すべてのメンバーを列挙し、セット名を指定します。

        ```text
        mongodb://cloudthinker_readonly:<secure-password>@h1.example.com:27017,h2.example.com:27017,h3.example.com:27017/?replicaSet=rs0&authSource=admin&tls=true&readPreference=secondaryPreferred&appName=CloudThinker
        ```

        単一サーバーの場合は、ホストを 1 つにして `replicaSet` を削除します。`tls=true` を削除するのは、サーバーが TLS に対応していない場合だけにしてください。
      </Tab>
      <Tab title="MongoDB Atlas">
        クラスターで **Connect** をクリックし、**Drivers** を選んで `mongodb+srv://` の文字列をコピーします。ステップ 1 のユーザーとパスワードを入れます。

        ```text
        mongodb+srv://cloudthinker_readonly:<secure-password>@cluster0.abcde.mongodb.net/?readPreference=secondaryPreferred&appName=CloudThinker
        ```

        Atlas は `mongodb+srv://` の文字列で TLS を自動的にオンにします。
      </Tab>
    </Tabs>

    `readPreference=secondaryPreferred` はエージェントの読み取りをセカンダリに送るため、本番のプライマリに負荷がかかりません。利用可能なセカンダリがない場合はプライマリにフォールバックします。`appName=CloudThinker` は MongoDB のログで接続にラベルを付けます。パスワードの特殊文字は URL エンコードしてください（`@` は `%40` になります）。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**MongoDB** を選んで、詳細パネルの **Connect** をクリックします。ダイアログで必要に応じて **Alias** と **Description** を変更します。**MDB_MCP_CONNECTION_STRING** というラベルの接続文字列のフィールドに文字列を貼り付け、**Connect** をクリックします。

    **成功時の状態:** 接続に **Connecting** と **Verifying** が表示され、その後 **Connected** になります。その後、CloudThinker が接続を読み取り専用で詳しく調べるチャットを開きます（"Often takes about 15 min. You can leave the chat."）。後で再実行するには、カードの **More** メニューを開いて **Try in chat** を選びます。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **Alias** | いいえ | このデプロイの短い名前。`mongodb-1` など、次に空いているエイリアスが入力済みです | `prod-atlas` |
| **Description** | いいえ | このデプロイの内容。エージェントはこれを読んでインスタンスを選びます | `Production Atlas cluster` |
| **MDB_MCP_CONNECTION_STRING** | はい | ユーザー、パスワード、ホスト、オプションを含む完全な MongoDB URI | `mongodb+srv://cloudthinker_readonly:<password>@cluster0.abcde.mongodb.net/` |

文字列で役立つオプション:

| オプション | 使う場面 |
|--------|-------------|
| `authSource=admin` | ユーザーが `admin` データベースにあり、文字列が別のデータベースを指定している場合 |
| `tls=true` | サーバーが TLS に対応していて、スキームが `mongodb://` の場合 |
| `readPreference=secondaryPreferred` | 本番環境で推奨: エージェントの読み取りがセカンダリに送られ、プライマリに負荷がかかりません |
| `appName=CloudThinker` | ログや `currentOp` で CloudThinker のセッションを見分けたい場合 |

## 必要な権限

| ロール | 利用可能になるもの |
|------|-----------------|
| `readAnyDatabase` | データベースとコレクションの一覧表示、ドキュメントのサンプリング、`find`、`aggregate`、`count` の実行、インデックスとクエリプランの読み取り |
| `clusterMonitor` | サーバーのステータス、レプリカセットのステータスと遅延、最近のサーバーログ |

<Tip>
エージェントを 1 つのデータベースに限定するには、ステップ 1 のとおり、`readAnyDatabase` の代わりにそのデータベースの `read` を付与します。`readWrite`、`dbAdmin`、`root` は決して付与しないでください。接続はいずれにせよ読み取り専用なので、余分なロールは機能を増やさずにリスクだけを増やします。
</Tip>

## エージェントの機能

| 機能 | エージェントができること |
|------------|--------------------|
| **Inventory** | データベースとコレクションを、ドキュメント数とストレージサイズとともに一覧表示します |
| **Schema** | サンプリングしたドキュメントから、フィールド名と型を推測します |
| **Queries** | `find`、`aggregate`、`count` のクエリを実行して、データに関する質問に答えます |
| **Index review** | コレクションごとにインデックスを一覧表示し、`explain` でクエリがインデックスを使っているかを確認します |
| **Server health** | サーバーのログ、接続、レプリカのステータスを読みます（`clusterMonitor` が必要） |

エージェントは書き込めません。この接続では挿入、更新、削除、drop、インデックス作成のツールがオフになっているため、「sessions コレクションを drop して」のような依頼は実行できません。エージェントは、あなたが作成すべきインデックスを推奨することはできます。

スキーマの推測とクエリは実際のドキュメントを返すため、個人データが含まれることがあります。エージェントにプレースホルダーとしてしか見せない識別子は [Guardrails](/guide/security/custom-guardrails) が決めます。メールアドレスと電話番号はデフォルトでオンです。

### 接続を確認する

```text
List the MongoDB databases with their collection counts and storage size
```

各データベース名とそのコレクションおよびサイズが返されることを確認します。Atlas では、Atlas がアクセスをブロックしているため、`local` と `config` のシステムデータベースはスキップされます。

### プロンプトの例

```text
Which queries on the orders collection scan the whole collection, and what index would fix them?
Show the indexes on every collection in the shop database and flag ones that look redundant
What does a typical document in users look like? List its fields and types
```

## トラブルシューティング

<Accordion title="Authentication failed">
ユーザー、パスワード、または認証データベースが誤っています。`admin` にユーザーを作成し、文字列が別のデータベースを指定している場合は、`authSource=admin` を追加してください。Atlas では、**Database Access** にユーザーが存在すること、パスワードの特殊文字が URL エンコードされていることを確認してください。
</Accordion>

<Accordion title="Server selection timed out、または connection refused">
CloudThinker がデプロイに到達できません。Atlas では **IP Access List** を確認してください。セルフホストの MongoDB では、ファイアウォールと、`bindIp` が `127.0.0.1` だけになっていないことを確認してください。プライベートネットワーク上のデプロイには、まず到達可能なエンドポイントが必要です。
</Accordion>

<Accordion title="not authorized on admin to execute command (serverStatus, replSetGetStatus, getLog)">
ユーザーに `clusterMonitor` がありません。`admin` データベースで追加してから、もう一度エージェントに質問してください。データへのクエリは、それがなくても引き続き機能します。
</Accordion>

<Accordion title="エージェントが書き込みは読み取り専用モードでブロックされていると言う">
これは想定どおりです。MongoDB の接続は読み取り専用です。変更は自分で行うか、実行すべき正確なコマンドをエージェントに尋ねてください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **2 層の読み取り専用**: 接続自体が書き込めず、`read` または `readAnyDatabase` しか持たないユーザーも、文字列が漏洩したとしても書き込めません。
- **TLS を使う**: Atlas では `mongodb+srv://` を、セルフホストの MongoDB では `tls=true` を使い、認証情報とクエリの結果が転送中に暗号化されるようにしてください。

Prometheus を接続すると、CloudThinker は PromQL クエリの実行、メトリクスとラベルの一覧表示、スクレイプターゲットのヘルスの確認、アクティブなアラートとアラートルールの閲覧ができます。接続は読み取り専用で、認証なし、Bearer トークン、または HTTP Basic 認証で認証します。

## 対応プラットフォーム

条件: エンドポイントが、アドレスのルートで `<your URL>/api/v1/query` に応答すること。認証は、なし、Bearer トークン、または HTTP Basic 認証です。

| プラットフォーム | 対応 | 備考 |
|----------|-----------|-------|
| **Self-hosted Prometheus** | はい | |
| **Thanos Querier** | はい | |
| **Grafana Mimir, Cortex, Grafana Cloud metrics** | いいえ | クエリ API が `/prometheus` や `/api/prom` などのパスプレフィックスの下にあります。Grafana Cloud の場合は、代わりに [Grafana の接続](/ja/guide/connections/grafana)を使ってください |
| **Amazon Managed Service for Prometheus** | いいえ | AWS SigV4 によるリクエスト署名が必要です |
| **Google Cloud Managed Service for Prometheus** | いいえ | Google Cloud の認証が必要です |

## 前提条件

- インターネットから到達できる Prometheus HTTP API。接続はネットワーク内からではなく、CloudThinker Cloud から実行されます。
- URL が HTTPS を使う場合は、公的に信頼された TLS 証明書。プライベート CA を追加するフィールドはありません。
- Prometheus の前にあるプロキシやゲートウェイが求める場合は、Bearer トークン、またはユーザー名とパスワード。
- CloudThinker ワークスペースで接続を追加する権限。

<Tip>
Prometheus が Kubernetes 内のプライベートアドレスにある場合は、TLS 付きのイングレスと、Bearer トークンまたは Basic 認証を確認する認証プロキシを通じて公開し、CloudThinker の送信元 IP を許可リストに追加してください。このドキュメントでは CloudThinker の送信元 IP 一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その他の方法は [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
</Tip>

<Warning>
URL にパスは含められません。`https://metrics.example.com/prometheus/api/v1` のように、プレフィックスの下でしか応答しないエンドポイントは接続テストに失敗します。代わりに、ホスト名のルートで API を公開してください。
</Warning>

## セットアップ

<Steps>
  <Step title="ベース URL を確認する">
    `/api/v1` の前に付けるアドレスを、パスも末尾のスラッシュもなしで使います。例: `https://prometheus.example.com`、`http://prometheus.example.com:9090`。

    接続する前に、ターミナルで確認します。

    ```bash
    # No auth
    curl -s "https://prometheus.example.com/api/v1/query?query=count(up)"
    # Bearer token
    curl -s -H "Authorization: Bearer <token>" "https://prometheus.example.com/api/v1/query?query=count(up)"
    # Basic auth
    curl -s -u <user>:<password> "https://prometheus.example.com/api/v1/query?query=count(up)"
    ```

    ネットワークの外にあるマシンから、CloudThinker に渡すのと同じ認証情報で実行してください。

    **成功状態:** レスポンスが `{"status":"success","data":{"resultType":"vector"` で始まります。
  </Step>
  <Step title="認証モードを選ぶ">
    | モード | 使う場面 | 表示されるフィールド |
    |------|-------------|--------------------|
    | **None** | エンドポイントが公開されているか、ネットワークルールで制限されている | URL のみ |
    | **Bearer Token** | プロキシが `Authorization: Bearer <token>` を求める | **PROMETHEUS_TOKEN** |
    | **Basic Auth** | プロキシがユーザー名とパスワードを求める | **PROMETHEUS_USERNAME**、**PROMETHEUS_PASSWORD** |

    <Warning>
    Prometheus は、到達できる人なら誰にでも、読み込んだ設定、内部のホスト名、ターゲットのアドレスを公開します。**None** は、CloudThinker の送信元 IP だけを許可するファイアウォールルールの内側でのみ使ってください。インターネット全体に公開されたエンドポイントで **None** を使ってはいけません。
    </Warning>
  </Step>
  <Step title="接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Prometheus** を選択します。次を入力します。
    - **Alias**（任意）: `prod-metrics` などの短い名前。小文字の英字、数字、ハイフンが使えます。
    - **Description**（任意）: この Prometheus が対象とする範囲。複数接続している場合、エージェントはこれを読んで適切なインスタンスを選びます。
    - **PROMETHEUS_URL**: ステップ 1 のベース URL。
    - **PROMETHEUS_AUTH_TYPE**: **None**、**Bearer Token**、または **Basic Auth**。続いて表示される認証情報のフィールドを入力します。
    - **LOG_LEVEL**: **Info** のままにします。

    **Connect** をクリックします。CloudThinker はエンドポイントに対して `count(up)` を実行し、**Connecting**、**Verifying** と表示してから **Connected** ステータスにします。検証に失敗すると **Failed** と表示され、エラーメッセージが出ます。メッセージを[トラブルシューティング](#トラブルシューティング)と照らし合わせてください。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | デフォルト | 説明 |
|-------|----------|---------|-------------|
| **Alias** | いいえ | 自動で付けられます | `prod-metrics` などの短い名前。小文字の英字、数字、ハイフン |
| **Description** | いいえ | `Prometheus` | このエンドポイントが対象とする範囲。エージェントはこれを読んで適切なインスタンスを選びます |
| **PROMETHEUS_URL** | はい | なし | Prometheus HTTP API のベース URL。パスは含めません。例: `https://prometheus.example.com` |
| **PROMETHEUS_AUTH_TYPE** | はい | **None** | **None**、**Bearer Token**、または **Basic Auth** |
| **PROMETHEUS_TOKEN** | Bearer Token モード | なし | `Authorization: Bearer` として送られるトークン |
| **PROMETHEUS_USERNAME** | Basic Auth モード | なし | HTTP Basic のユーザー名 |
| **PROMETHEUS_PASSWORD** | Basic Auth モード | なし | HTTP Basic のパスワード |
| **LOG_LEVEL** | いいえ | **Info** | コネクターのログの詳細度。サポートから依頼がない限り **Info** のままにします |

## 必要な権限

Prometheus には組み込みのユーザー権限がないため、アクセスはプロキシやゲートウェイが許可する範囲になります。CloudThinker には、`/api/v1/` の下で次の読み取り（`GET`）アクセスが必要です。

| 領域 | 用途 |
|------|----------|
| Query API | インスタントクエリとレンジクエリの PromQL、系列の検索 |
| Metadata | メトリクス名、ラベル名、タイプとヘルプテキスト |
| Targets | スクレイプターゲットのヘルス |
| Alerts and rules | アクティブなアラートとアラートルールの定義 |
| Status config | 読み込まれた設定の閲覧。依頼したときのみ |

<Tip>
プロキシが対応していれば、`/api/v1/` の下の `GET` リクエストに限定した CloudThinker 専用のトークンを発行してください。この接続が Prometheus に書き込むことはありません。
</Tip>

## エージェントの機能

| 機能 | CloudThinker が行うこと |
|------------|------------------------|
| **Discovery** | スクレイプターゲット（up と down）、発火中のアラート、アラートルールとそのヘルス、メトリクス、`job`、`instance`、`namespace` などのラベルを数えます |
| **Instant queries** | ある時点で PromQL 式を評価します |
| **Range queries** | 期間とステップを指定して PromQL を評価します。直近 15 分から始め、空なら範囲を広げます |
| **Metric and label discovery** | メトリクス名、タイプとヘルプテキスト、ラベル名を一覧表示し、クエリで実際の名前を使えるようにします |
| **Target health** | スクレイプターゲットと、そのうちダウンしているものを一覧表示します |
| **Alerts** | 発火中と保留中のアラート、設定済みのアラートルールを一覧表示します |
| **Configuration** | 依頼に応じて読み込まれた設定を読み、回答では認証情報の値を伏せます |

接続が初めて **Connected** になると、CloudThinker が[詳しく調べる](/ja/guide/connections/overview#接続した後に起こること)チャットを開き、エージェントがエンドポイントを探索します。

### 接続を確認する

```text
Run Prometheus discovery and tell me how many scrape targets are up and down, and how many alerts are firing
```

正常な回答には、状態ごとのターゲット数、発火中のアラート数、エンドポイントのメトリクス名のサンプルがいくつか含まれます。

### プロンプト例

```text
Which scrape targets are down right now, and which jobs do they belong to?
Show 5xx rate by service from http_requests_total over the last hour and flag anything above 1%
List firing alerts and the alert rule behind each one
```

対象のメトリクスとラベルを指定してください。CloudThinker はラベル名を一覧表示できるため、「`namespace` で分けて」のようなプロンプトなら、正確なセレクターに早くたどり着きます。

Prometheus のアラートを Resolve に送り、インシデントが自動で開かれるようにするには、[Webhook 連携](/ja/guide/incident/webhook-integrations/overview)を設定してください。

## トラブルシューティング

<Accordion title="Prometheus rejected the credentials">
エンドポイントが 401 または 403 を返しました。**PROMETHEUS_AUTH_TYPE** がプロキシの求めるものと一致していることを確認し、トークン、またはユーザー名とパスワードを入力し直してください。プロキシ側で取り消されたトークンも同じように失敗します。
</Accordion>

<Accordion title="Prometheus has no query API at that URL">
エンドポイントが 404 を返しました。URL に `/api/v1` や `/prometheus` などのパスが含まれている可能性が高いです。スキーム、ホスト、ポートだけを入力してください。API がプレフィックスの下でしか応答しない場合は対応していません。
</Accordion>

<Accordion title="That URL answered, but not as a Prometheus query API">
Prometheus の前にある何か、たいていはログインページや SSO プロキシが代わりに応答しました。URL を API そのものに向けるか、ブラウザでのログインなしでプロキシが受け付ける Bearer トークンまたは Basic 認証を使ってください。
</Accordion>

<Accordion title="Prometheus is unreachable or didn't answer in time">
CloudThinker が接続を開けませんでした。ホスト名、ポート、TLS 証明書を確認し、エンドポイントがインターネットからのトラフィックを受け付けることを確認してください。`10.0.0.5` のようなプライベートアドレスには CloudThinker から到達できません。
</Accordion>

<Accordion title="クエリでデータが返らない">
まず CloudThinker に名前が一致するメトリクスを一覧表示させ、メトリクスが存在することを確認してください。次に、レンジクエリは 15 分から始まるため、期間を広げてください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **書き込みなし**: 接続は Prometheus HTTP API を読むだけなので、`GET` リクエストに限定したトークンで十分です。
- **設定にはシークレットが含まれる**: `/api/v1/status/config` にはスクレイプ用の認証情報や内部のホスト名が含まれることがあります。読まれたくない場合は、プロキシでそのパスをブロックしてください。

Argo CD を接続すると、CloudThinker のエージェントがアプリケーションを一覧表示し、同期ずれや劣化の理由を説明し、Kubernetes のイベントと Pod のログを読み、承認を経てアプリを同期できるようになります。接続は 1 つの Argo CD **API token** でサインインし、セルフホストの Argo CD と Akuity Platform の両方で動作します。

## 前提条件

- CloudThinker から HTTPS で到達できる Argo CD サーバー。`localhost` やクラスター内部のアドレスは使えません。
- ローカルアカウントを作成しトークンを生成できる、Argo CD の管理者アクセス。
- トークンを生成するための、マシン上の [Argo CD CLI](https://argo-cd.readthedocs.io/en/stable/cli_installation/)。
- セルフホストの場合のみ: `argocd-cm` と `argocd-rbac-cm` の ConfigMap を編集するための、`argocd` 名前空間への `kubectl` アクセス。

サーバーがプライベートネットワーク上にある場合は、[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。

## セットアップ

`admin` を使う代わりに、専用の `cloudthinker` アカウントを作成します。そうすれば、そのトークンには付与した RBAC 権限だけが含まれ、他の人に影響を与えずに取り消せます。

<Tabs>
  <Tab title="Self-hosted Argo CD">
    <Steps>
      <Step title="API キーアクセスを持つローカルアカウントを作成する">
        Web ログインではなく API キーのみを使える `cloudthinker` アカウントを追加します。

        ```bash
        kubectl -n argocd patch configmap argocd-cm --type merge \
          -p '{"data":{"accounts.cloudthinker":"apiKey"}}'
        ```
      </Step>
      <Step title="トークンを生成する">
        管理者としてサインインし、新しいアカウントのトークンを生成します。

        ```bash
        argocd login argocd.example.com --username admin
        argocd account generate-token --account cloudthinker --expires-in 90d
        ```

        トークンをコピーします。サーバーが自己署名証明書を使っている場合に限り、両方のコマンドに `--insecure` を追加します。`--expires-in` を付けないとトークンは無期限になるため、有効期間を設定し、期限切れになる前に新しいトークンを生成してください。

        **成功時の状態:** 2 つ目のコマンドが長いトークン文字列を出力します。
      </Step>
      <Step title="アカウントに読み取りアクセスを付与する">
        `kubectl -n argocd edit configmap argocd-rbac-cm` を実行し、既存の `policy.csv` に次の行を追加します。

        ```csv
        p, role:cloudthinker, applications, get, */*, allow
        p, role:cloudthinker, logs, get, */*, allow
        g, cloudthinker, role:cloudthinker
        ```

        新しい ConfigMap を適用するのではなく、既存の ConfigMap を編集してください。新しい `argocd-rbac-cm` を `kubectl apply` するとポリシー全体が置き換わり、他のユーザーが締め出される可能性があります。エージェントに変更を許可するには、[Required permissions](#必要な権限) の行を追加します。
      </Step>
      <Step title="CloudThinker で接続を追加する">
        **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **ArgoCD** を選びます。次を入力します。

        - **ARGOCD_BASE_URL**: `https://argocd.example.com` などのサーバーアドレス
        - **ARGOCD_API_TOKEN**: コピーしたトークン
        - **NODE_TLS_REJECT_UNAUTHORIZED**（TLS 検証）: **Verify TLS (default)**、または自己署名証明書の場合は **Skip TLS verification**
        - **READ_ONLY**: **Read-only** に変更します。フォームのデフォルトは **Full access (default)** です。

        **Connect** をクリックします。

        **成功時の状態:** ダイアログが閉じ、接続に **Connected** と表示されます。このステータスはトークンや RBAC が機能することを証明するものではないため、下の確認用プロンプトを実行してください。
      </Step>
    </Steps>
  </Tab>
  <Tab title="Akuity Platform">
    <Steps>
      <Step title="システムアカウントを作成する">
        [Akuity Portal](https://akuity.cloud) で Argo CD インスタンスを開き、**Settings → System Accounts** に移動して、**apiKey** の機能を持つ `cloudthinker` という名前のアカウントを追加します。
      </Step>
      <Step title="トークンを生成する">
        管理者としてインスタンスにサインインし、新しいアカウントのトークンを生成します。

        ```bash
        argocd login <instance-id>.cd.akuity.cloud --grpc-web --username admin
        argocd account generate-token --account cloudthinker --grpc-web --expires-in 90d
        ```

        トークンをコピーします。
      </Step>
      <Step title="アカウントに読み取りアクセスを付与する">
        Akuity Portal で、インスタンスの RBAC ポリシーに次の行を追加します。

        ```csv
        p, role:cloudthinker, applications, get, */*, allow
        p, role:cloudthinker, logs, get, */*, allow
        g, cloudthinker, role:cloudthinker
        ```
      </Step>
      <Step title="CloudThinker で接続を追加する">
        **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **ArgoCD** を選びます。次を入力します。

        - **ARGOCD_BASE_URL**: `https://<instance-id>.cd.akuity.cloud`
        - **ARGOCD_API_TOKEN**: コピーしたトークン
        - **NODE_TLS_REJECT_UNAUTHORIZED**（TLS 検証）: **Verify TLS (default)**
        - **READ_ONLY**: **Read-only** に変更します。フォームのデフォルトは **Full access (default)** です。

        **Connect** をクリックします。

        **成功時の状態:** ダイアログが閉じ、接続に **Connected** と表示されます。下の確認用プロンプトを実行して、トークンと RBAC が機能することを確認してください。
      </Step>
    </Steps>
  </Tab>
</Tabs>

## 接続の詳細

| フィールド | 説明 | デフォルト |
|-------|-------------|---------|
| **ARGOCD_BASE_URL** | Argo CD サーバーのアドレス（HTTPS） | なし |
| **ARGOCD_API_TOKEN** | CloudThinker が使うアカウントのトークン | なし |
| **NODE_TLS_REJECT_UNAUTHORIZED** | TLS 検証。**Verify TLS (default)** はサーバー証明書を確認します。**Skip TLS verification** は自己署名証明書を受け入れます。ローカルまたは開発用のサーバーでのみ使ってください | Verify TLS |
| **READ_ONLY** | **Read-only** は、同期、作成、更新、削除、リソースアクションのツールをオフにします。**Full access (default)** はそれらをオンのままにします | Full access |

<Warning>
**READ_ONLY** のデフォルトは **Full access (default)** です。エージェントに同期や変更を提案させたい場合を除き、**Read-only** に切り替えてください。アカウントに付与されていない操作は、RBAC が引き続きブロックします。
</Warning>

## 必要な権限

セットアップの読み取り用の行で、すべての読み取りをカバーします。`applications, get` はアプリケーションのステータス、リソースツリー、管理対象リソース、イベントを、`logs, get` は Pod のログの読み取りをカバーします。エージェントに提案させたい変更ごとに行を追加します。

| 機能 | ポリシーの行 |
|------------|-------------|
| 同期 | `p, role:cloudthinker, applications, sync, */*, allow` |
| アプリケーションの変更 | `p, role:cloudthinker, applications, create, */*, allow`<br />`p, role:cloudthinker, applications, update, */*, allow`<br />`p, role:cloudthinker, applications, delete, */*, allow` |
| リソースアクション | `p, role:cloudthinker, applications, action/*, */*, allow` |

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **Discovery** | アプリケーションを、同期ステータス、ヘルス、リポジトリ、パス、名前空間とともに一覧表示し、異常または同期ずれのものについてはリソースツリーと最近のイベントも示します | 不要 |
| **Application detail** | 1 つのアプリの spec、管理対象リソース、実際の状態と期待する状態の差分を読みます | 不要 |
| **Events and logs** | アプリやリソースの Kubernetes イベントと、そのワークロードの Pod のログを読みます | 不要 |
| **Sync** | 1 つのアプリケーションの同期をトリガーします | 必要。Read-only ではオフ |
| **Change applications** | アプリケーションを作成、更新、削除します | 必要。Read-only ではオフ |
| **Resource actions** | 管理対象リソースで再起動などのアクションを実行します | 必要。Read-only ではオフ |

すべての変更は [Approvals](/guide/approvals/overview) を経由し、却下されたリクエストは再試行されません。エージェントに同期させるには、**READ_ONLY** を **Full access (default)** に設定し、`applications, sync` の権限を追加します。どちらかが欠けていると、エージェントは読み取りしかできません。

### 接続を確認する

```text
List my Argo CD applications with their sync status and health, and call out any that are OutOfSync or Degraded
```

アプリケーション名と、**Synced** や **OutOfSync** などの同期ステータス、**Healthy** や **Degraded** などのヘルスステータスの表が返され、最後に件数が示されることを確認します。

### プロンプトの例

```text
Why is the checkout app Degraded? Check its resource tree, recent events, and pod logs
Which resources in payments-api differ from Git, and what changed?
Sync the payments-api app and tell me when it's Healthy
```

アプリケーション名を指定してください。エージェントはアプリケーション一覧の実際の名前を使い、推測はしません。同期のプロンプトには **Full access (default)** と `applications, sync` の権限が必要です。

## トラブルシューティング

<Accordion title="Connect が fetch failed で失敗する">
CloudThinker が **ARGOCD_BASE_URL** に到達できないか、サーバーの証明書が拒否されました。アドレスが `localhost` やクラスター内部の名前ではなく、公開された HTTPS であることを確認してください。自己署名証明書の場合は、**NODE_TLS_REJECT_UNAUTHORIZED** を **Skip TLS verification** に設定します。
</Accordion>

<Accordion title="リクエストが 401 を返す">
トークンがない、期限切れ、または別のアカウント用に生成されています。`argocd account generate-token --account cloudthinker --expires-in 90d` を再実行し、接続を編集して新しいトークンを貼り付けます。
</Accordion>

<Accordion title="Permission denied (code 7)">
アカウントの RBAC ロールがその操作を許可していません。[Required permissions](#必要な権限) の `policy.csv` の行を確認してください。ログには `logs, get`、同期には `applications, sync` が必要です。
</Accordion>

<Accordion title="アプリケーション一覧が空になる">
ロールがそれらのプロジェクトへのアクセスを付与していません。ポリシーの `*/*` パターンはすべてのプロジェクトをカバーします。範囲を絞った場合は、エージェントに見せたいプロジェクトを追加してください。
</Accordion>

<Accordion title="同期、作成、更新、削除が利用できない">
**READ_ONLY** が **Read-only** に設定されています。エージェントにそれらの変更を提案させたい場合は、接続を編集して **Full access (default)** に切り替えます。
</Accordion>

<Accordion title="トークンの生成が失敗する">
アカウントに `apiKey` の機能がありません。`argocd account get --account cloudthinker` で確認してから、セットアップの最初のステップを繰り返します。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **専用アカウント**: CloudThinker には、API キーアクセスのみを持つ専用の `cloudthinker` アカウントを与え、`admin` のトークンは決して使わないでください。
- **本番環境では TLS 検証をオンのままにする**: スキップするのは、自己署名証明書を使うローカルまたは開発用のサーバーだけにしてください。

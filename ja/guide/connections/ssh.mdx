SSH でサーバーを接続すると、[CloudThinker](/ja/guide/agents/overview) がそこでシェルコマンドを実行できるようになります。ディスクとメモリの確認、ログの読み取り、プロセスとサービスの調査などです。秘密鍵でサインインし、CloudThinker は初回接続時にサーバーのホスト鍵を固定するため、ID の変化を検出できます。

## 前提条件

- SSH ポートで CloudThinker からの受信 SSH を受け付けるサーバー。CloudThinker は **Host** に直接接続し、ジャンプホストや踏み台のフィールドはありません。ファイアウォールの背後にあるサーバーや公開アドレスのないサーバーについては、Environment の選択肢を [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) で確認してください。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。
- シェルアクセスを持ち、`sshd` で公開鍵認証が有効になっているログインユーザー。
- 公開鍵がそのユーザーの `~/.ssh/authorized_keys` にある鍵ペア。
- 接続の追加に必要な、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Steps>
  <Step title="専用の鍵ペアを作成する">
    CloudThinker だけが使う鍵を生成すれば、他に影響を与えずに取り消せます。

    ```bash
    ssh-keygen -t ed25519 -C "cloudthinker" -f ./cloudthinker_key
    ```

    `cloudthinker_key`（秘密鍵）と `cloudthinker_key.pub`（公開鍵）が書き出されます。OpenSSH または PEM 形式の既存の RSA や ECDSA の鍵も使えます。
  </Step>
  <Step title="サーバーで公開鍵を許可する">
    ```bash
    ssh-copy-id -i ./cloudthinker_key.pub ubuntu@server.example.com
    ```

    または、`cloudthinker_key.pub` の内容をユーザーの `~/.ssh/authorized_keys` に手動で追記します。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**SSH** を選んで **Connect** をクリックし、**Host**、**User**、**Port**、**Private key** を入力します。鍵にパスフレーズがある場合にのみ **Passphrase** を追加します。**Connect** をクリックします。

    CloudThinker が接続し、サーバーのホスト鍵を記録して、テストを実行します。テストは通常 30 秒以内に終わり、45 秒でタイムアウトします。

    **成功時の状態:** ダイアログに **Connected** と "SSH connection verified and saved." が表示されます。
  </Step>
</Steps>

各サーバーはそれぞれ独立した SSH 接続です。CloudThinker に到達させたいサーバーごとに、最後のステップを繰り返してください。プロンプトを 1 つのサーバーに向けるには、プロンプトボックスで `#` を使ってその接続を選びます。

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **Host** | はい | ホスト名または IP アドレス | `server.example.com` または `203.0.113.10` |
| **User** | はい | シェルアクセスを持つログインユーザー | `ubuntu` |
| **Port** | いいえ | SSH のポート。デフォルトは `22` | `22` |
| **Private key** | はい | `BEGIN` と `END` の行を含む鍵全体 | `-----BEGIN OPENSSH PRIVATE KEY-----` |
| **Passphrase** | いいえ | 暗号化された鍵の場合のみ。それ以外は空欄にします | 非表示 |

## 必要な権限

コマンドはログインユーザーとして、そのユーザーの権限のとおりに実行されます。そのユーザーの権限が、CloudThinker がサーバーでできることの実際の境界です。

<Tip>
CloudThinker 用に、必要なログとパスへの読み取りアクセスを持ち、本番のパスへの書き込みアクセスを持たない、root 以外のユーザーを作成してください。ほとんどのヘルスチェックとログの読み取りには、それ以上は必要ありません。
</Tip>

コマンドはターミナルなしで実行されるため、`sudo` のパスワードのプロンプトには応答できません。CloudThinker に特権コマンドを実行させたい場合は、`/etc/sudoers.d/` でそのコマンドだけをパスワードなしで許可します。

```text
cloudthinker ALL=(root) NOPASSWD: /usr/bin/systemctl restart nginx
```

## エージェントの機能

| 機能 | CloudThinker が行うこと | 承認 |
|------------|------------------------|----------|
| **System inspection** | ディスク、メモリ、CPU、稼働時間、プロセス、サービスのステータスを確認します | 不要 |
| **Log analysis** | アプリケーションとシステムのログを読み、検索します | 不要 |
| **Diagnostics** | ホスト上の障害、接続性、設定を調査します | 不要 |
| **Changes** | サービスの再起動など、サーバーを変更するコマンドを実行します | 必要 |

### 接続を確認する

```text
Show uptime, disk usage per filesystem, and the top 5 processes by memory on the server
```

稼働時間、ファイルシステムとその使用量の表、メモリ使用量付きの 5 つのプロセスが返されることを確認します。

### プロンプトの例

```text
Flag any filesystem above 80% full and list the largest directories on it
Summarize the last 100 lines of /var/log/app/error.log and group them by error type
Is nginx running, and when did it last restart?
```

## 書き込みアクセス

読み取りコマンドは確認なしで実行されます。サーバーを変更するコマンドは Approvals を経由し、CloudThinker はリクエストにそのコマンドを表示します。

<ApprovalDefault />

シェルコマンドは自由形式で、どれが変更にあたるかは CloudThinker が判断します。承認のステップは二重のチェックとして扱い、CloudThinker に決してさせてはならないことのブロックは、ログインユーザーの権限に頼ってください。

## ホスト鍵の検証

初回接続時、CloudThinker はサーバーのホスト鍵を信頼して記録します。それ以降のすべての接続で、鍵が引き続き一致することを確認します。CloudThinker はフィンガープリントを表示しないため、初回接続で正しいサーバーに到達していることを確認してください。

鍵が変わると接続は停止し、**Host key changed** と表示されます。これはサーバーの再構築やホスト鍵のローテーションの後には想定どおりです。新しい鍵を受け入れるには、サーバーの横のシールドアイコン（**Trust new host key**）をクリックし、**Trust** で確定します。

<Warning>
予期していない新しいホスト鍵は信頼しないでください。予期しない変更は、誰かが接続を傍受していることを意味する場合があります。まず、信頼できるコンソールからサーバーでフィンガープリントを確認してください。

```bash
for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done
```
</Warning>

## トラブルシューティング

<Accordion title="Authentication failed">
- 公開鍵がログインユーザーの `~/.ssh/authorized_keys` にあることを確認します。
- **User** が、鍵が許可されているアカウントであることを確認します。
- `BEGIN` と `END` の行を含め、秘密鍵全体を貼り付けます。
- 鍵にパスフレーズがある場合は **Passphrase** を入力します。
</Accordion>

<Accordion title="Could not reach the host">
- **Host** と **Port** を確認します。
- ファイアウォール、セキュリティグループ、または許可リストで、CloudThinker からの受信 SSH を許可します。
- `sshd` が稼働していて、そのポートで待ち受けていることを確認します。
- 45 秒を超えて実行されたテストは、これと同じアドバイスとともにタイムアウトします。
</Accordion>

<Accordion title="Host key changed">
再構築や鍵のローテーションの後であれば想定どおりです。サーバーでフィンガープリントを確認してから、**Trust new host key** を選んでください。予期していなかった場合は、信頼する前に調査してください。
</Accordion>

<Accordion title="リモートコマンドが 0 以外のコードで終了した">
SSH は機能しましたが、サーバーでコマンドが失敗しました。コマンド、パス、ログインユーザーにそれを実行する権限があるかを確認してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **専用の鍵を使う。** CloudThinker だけが使う鍵は、他の人に影響を与えずに `authorized_keys` から削除できます。
- **鍵をローテーションする。** 新しい鍵ペアを生成し、新しい公開鍵を `authorized_keys` に追加します。**Settings → Workspace → Connections** を開き、**SSH** を選んで、サーバーの横の鉛筆アイコンをクリックし、**Edit SSH Connection** の **Rotate private key** に新しい鍵を貼り付けて、**Save** をクリックします。確認用のプロンプトを実行し、機能したら古い公開鍵をサーバーから削除します。
- **再信頼する前に確認する。** フィンガープリントを確認するまでは、すべてのホスト鍵の変更を疑わしいものとして扱ってください。

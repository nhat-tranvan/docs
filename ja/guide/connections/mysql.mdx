MySQL データベースを接続すると、CloudThinker のエージェントは SQL を実行して、スキーマ、インデックス、テーブルの状態、スロークエリを調べられます。CloudThinker には、専用のデータベースユーザー用の接続 URL（`MYSQL_URL`）を 1 つ渡します。エージェントはそのユーザーの権限で許される操作ができ、すべての書き込みはまず [Approvals](/guide/approvals/overview) を通ります。

## 前提条件

- CloudThinker がインターネットから到達できる MySQL エンドポイント。例: セルフホストの MySQL、Amazon RDS for MySQL、Cloud SQL for MySQL。エージェントは CloudThinker Cloud から接続するため、`localhost` やプライベートアドレスはあなたのネットワークではなく CloudThinker Cloud 側で解決されます。[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- `CREATE USER` と `GRANT` を実行できる管理者アカウント。
- スロークエリ分析をしたい場合は、Performance Schema がオンになっていること。セルフホストの MySQL 5.7 以降ではデフォルトでオンです。Amazon RDS では、パラメーターグループの `performance_schema` パラメーターによって決まります。

## セットアップ

<Steps>
  <Step title="専用ユーザーを作成する">
    管理者として接続し、CloudThinker 用のユーザーを作成します。`%` を使うと、ユーザーはどのホストからでもサインインできます。CloudThinker に限定するには、代わりに送信元 IP ごとに 1 つずつ（例: `'cloudthinker_readonly'@'203.0.113.10'`）作成し、それぞれに下の権限付与を実行します。このドキュメントでは CloudThinker の送信元 IP 一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。

    ```sql
    CREATE USER 'cloudthinker_readonly'@'%' IDENTIFIED BY '<secure-password>';
    ```
  </Step>
  <Step title="読み取りアクセスを付与する">
    分析したいデータベースへの読み取りアクセスと、セッションとクエリ統計のためにエージェントが必要とする監視権限を付与します。

    ```sql
    GRANT SELECT, SHOW VIEW ON your_database.* TO 'cloudthinker_readonly'@'%';
    GRANT PROCESS ON *.* TO 'cloudthinker_readonly'@'%';
    GRANT SELECT ON performance_schema.* TO 'cloudthinker_readonly'@'%';
    ```

    `GRANT` はすぐに反映されるため、`FLUSH PRIVILEGES` は不要です。レプリケーションの確認を追加するには[必要な権限](#必要な権限)を参照してください。
  </Step>
  <Step title="Performance Schema を確認する">
    ```sql
    SHOW VARIABLES LIKE 'performance_schema';
    ```

    **成功状態:** 値が `ON` です。`OFF` の場合は、`my.cnf` の `[mysqld]` の下で `performance_schema = ON` を設定し、MySQL を再起動します。RDS や Cloud SQL では、パラメーターグループまたはデータベースフラグで変更します。このパラメーターは静的なので、再起動後にのみ反映されます。
  </Step>
  <Step title="ネットワークアクセスを開く">
    ファイアウォール、セキュリティグループ、または承認済みネットワークの一覧で、CloudThinker の送信元 IP から MySQL のポート（デフォルトは `3306`）への受信接続を許可します。この接続にはプライベートリンクの選択肢がないため、プライベートネットワークでしか待ち受けていないデータベースには、まず到達できるエンドポイントが必要です。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**MySQL** を選択して、詳細パネルの **Connect** をクリックします。ダイアログでは、必要に応じて **Alias** と **Description** を変更します（複数接続している場合、エージェントは説明を読んで適切なデータベースを選びます）。**MYSQL_URL** に URL を貼り付け、**Connect** をクリックします。

    ```text
    mysql://cloudthinker_readonly:<secure-password>@db.example.com:3306/your_database
    ```

    **成功状態:** 接続に **Connecting**、**Verifying** と表示され、その後 **Connected** になります。続いて CloudThinker がチャットを開き、接続を読み取り専用で詳しく調べます（"Often takes about 15 min. You can leave the chat."）。後でもう一度実行するには、カードの **More** メニューを開いて **Try in chat** を選びます。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | 例 |
|-------|----------|-------------|---------|
| **Alias** | いいえ | このデータベースの短い名前。`mysql-1` など、次に空いているエイリアスがあらかじめ入っています | `prod-db` |
| **Description** | いいえ | このデータベースの内容。エージェントはこれを読んでインスタンスを選びます | `Production orders database` |
| **MYSQL_URL** | はい | ユーザー、パスワード、ホスト、ポート、データベースを含む完全な接続 URL | `mysql://cloudthinker_readonly:<password>@db.example.com:3306/shop` |

パスワードに `@`、`:`、`/`、`#` が含まれる場合は URL エンコードしてください（例: `@` は `%40` になります）。そうしないと URL を解析できません。

## 必要な権限

使いたい機能に必要な権限だけを付与してください。

| エージェントにさせたいこと | 付与する権限 |
|--------------------|-------|
| スキーマ、テーブル、インデックスを読む | `SELECT, SHOW VIEW ON your_database.*` |
| アクティブなセッションと実行中のクエリを見る | `PROCESS ON *.*` |
| スロークエリとインデックスの使用状況を見つける | `SELECT ON performance_schema.*` |
| レプリカの状態と遅延を確認する | `REPLICATION CLIENT ON *.*` |

<Tip>
ユーザーは読み取り専用にしておいてください。書き込みが必要なワークフローがない限り、`INSERT`、`UPDATE`、`DELETE`、`DROP`、`ALTER`、`ALL PRIVILEGES` は決して付与しないでください。[書き込みアクセス](#書き込みアクセス)を参照してください。
</Tip>

## エージェントの機能

| 機能 | エージェントができること |
|------------|--------------------|
| **Schema inspection** | データベースとテーブルを一覧表示し、列の型、キー、テーブルサイズを読みます |
| **Index review** | 不足している、使われていない、重複しているインデックスを見つけます |
| **Slow queries** | Performance Schema をもとに、合計レイテンシーと平均レイテンシーでステートメントを順位付けします |
| **Table health** | テーブルごとの行数、データとインデックスのサイズ、空き容量を確認します |
| **Sessions and replication** | 実行中のセッションと長時間のクエリを一覧表示し、レプリカの遅延を確認します（`REPLICATION CLIENT` が必要） |

### 接続を確認する

```text
List the tables in the connected MySQL database with their row counts and sizes
```

テーブル名、おおよその行数、データとインデックスのサイズの表が返ってきます。不足している権限を示すエラーが出た場合は、どの権限を追加すればよいかがわかります。

### プロンプト例

```text
Which 10 queries spend the most total time on MySQL, and which indexes would help them?
Find indexes that haven't been used since the last restart
Is anything blocking right now? Show long-running sessions and what they're waiting on
```

## 書き込みアクセス

CloudThinker は、エージェントが送る各 SQL ステートメントを実行前に分類します。

- `SELECT`、`SHOW`、`DESCRIBE`、`EXPLAIN`、および読み取り専用の `WITH` ステートメントは確認なしで実行されます。
- `INSERT`、`UPDATE`、`ALTER` など、その他のステートメントは書き込みとして扱われ、[Approvals](/guide/approvals/overview) を通ります。
- `DELETE`、`DROP`、`TRUNCATE` は破壊的な操作として扱われます。[ルール](/guide/approvals/rules)で、先に確認するか拒否するかを設定できます。
- 承認されたステートメントでも、ユーザーの権限で許されていなければ失敗します。読み取り専用ユーザーが最後の歯止めです。

## トラブルシューティング

<Accordion title="接続が拒否される、またはタイムアウトする">
CloudThinker がホストに到達できません。**MYSQL_URL** のホストとポートが公開されているか、その他の方法で到達できること、ファイアウォールやセキュリティグループが CloudThinker を許可していること、`my.cnf` の `bind-address` が `127.0.0.1` になっていないことを確認してください。RDS では、インスタンスがパブリックにアクセス可能であるか、ネットワーク構成を通じて到達できる必要があります。
</Accordion>

<Accordion title="Access denied for user">
ユーザー、パスワード、またはホストの部分が一致していません。`'cloudthinker_readonly'@'localhost'` として作成したユーザーはリモートからサインインできないため、`'%'` または CloudThinker のアドレス範囲で作成してください。また、**MYSQL_URL** でパスワードが URL エンコードされていることも確認してください。
</Accordion>

<Accordion title="SELECT command denied、またはスロークエリのデータがない">
エージェントが試した操作に必要な権限がユーザーにありません。スロークエリについては、`SELECT ON performance_schema.*` を付与し、`SHOW VARIABLES LIKE 'performance_schema'` が `ON` を返すことを確認してください。Performance Schema の統計は再起動でリセットされるため、再起動したばかりのサーバーには履歴がほとんどありません。
</Accordion>

<Accordion title="Unknown database">
**MYSQL_URL** の末尾のデータベース名が存在しないか、ユーザーがそれを見られません。そのユーザーで `SHOW DATABASES;` を実行し、名前を修正してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **権限を 1 つのデータベースに絞る**: `SELECT` は `*.*` ではなく `your_database.*` に付与してください。そうすれば、エージェントは `mysql` システムスキーマや他のアプリのデータを読めません。
- **サーバーで TLS を必須にする**: サーバーが対応していれば、ユーザーに `REQUIRE SSL` を設定してください（`ALTER USER ... REQUIRE SSL`）。認証情報と結果が通信中に暗号化されます。

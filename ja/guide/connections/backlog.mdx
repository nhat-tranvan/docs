Nulab の Backlog を接続すると、CloudThinker の[エージェント](/ja/guide/agents/overview)がプロジェクト、課題、マイルストーン、Wiki、プルリクエストを読み、依頼に応じて課題、マイルストーン、Wiki ページを作成・更新できるようになります。Backlog は API キーで認証し、キーには発行した Backlog ユーザーと同じプロジェクトアクセス権があります。

## 前提条件

- CloudThinker に読ませたいすべてのプロジェクトに所属している Backlog ユーザー。
- スペースで API アクセスが有効になっていること。スペースで制限されている場合は、先にスペース管理者が有効にする必要があります。
- エージェントに課題、マイルストーン、Wiki ページを作成・更新させたい場合のみ、そのプロジェクトでのユーザーの書き込み権限。
- CloudThinker ワークスペースで接続を管理する権限。Backlog はすべての CloudThinker プランで利用できます。

## セットアップ

<Steps>
  <Step title="Backlog で API キーを作成する">
    Backlog でプロフィールメニューを開き、**Personal Settings → API** に移動します。`cloudthinker` などのメモを入力してキーを登録し、コピーします。

    キーは、CloudThinker に持たせたいアクセス権を持つユーザーで発行してください。キーを持つ人は誰でもそのユーザーとして操作できます。
  </Step>
  <Step title="CloudThinker で Backlog を開く">
    **Settings → Workspace → Connections** を開きます。**Discover** タブで **Backlog** を検索し、**Connect** をクリックします。
  </Step>
  <Step title="ドメインとキーを入力する">
    **BACKLOG_DOMAIN** にスペースのホスト全体（例: `myorg.backlog.com` または `myorg.backlog.jp`）を入力します。**BACKLOG_API_KEY** にキーを貼り付け、**Connect** をクリックします。

    **成功時の状態:** CloudThinker がキーをテストし、Backlog に **Connected** ステータスが表示されます。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 入力内容 | 例 |
|---|---|---|
| **BACKLOG_DOMAIN** | スペースキーだけでなく、Backlog スペースのホスト全体 | `myorg.backlog.com` |
| **BACKLOG_API_KEY** | **Personal Settings → API** で発行した API キー | （シークレット） |

## 必要な権限

Backlog にはキーごとのスコープがありません。キーはそのユーザーが Backlog でできることをすべて実行できます。

| エージェントにさせたいこと | キーのユーザーに必要なもの |
|---|---|
| プロジェクト、課題、マイルストーン、Wiki、ドキュメント、リポジトリ、プルリクエストの読み取り | それらのプロジェクトへの参加 |
| 課題、コメント、マイルストーン、Wiki ページの作成・更新 | プロジェクトでの書き込み権限 |

読み取りは確認なしで実行されます。書き込みは [Approvals](/guide/approvals/overview) を経由します。まず Rules が判断し、どの Rule にも一致しない書き込みについては、Approval mode によって CloudThinker が実行するか、確認を求めるか、拒否するかが決まります。チャットでは、項目と変更内容を指定した場合にのみ CloudThinker が書き込みを提案します。例外は Resolve のフォローアップチケットで、[Resolve Triggers & Outcomes](/guide/incident/triggers-and-outcomes#outcomes) で有効にしたアウトカムに従って実行されます。

<Tip>
キーは、CloudThinker に必要なプロジェクトだけに所属する専用の Backlog ユーザーで発行してください。書き込み権限は、エージェントにチケットを登録・更新させたいプロジェクトにのみ付与してください。専用ユーザーは Backlog プランのユーザー数上限にカウントされる場合があります。
</Tip>

## エージェントの機能

| 機能 | CloudThinker が行うこと | 承認 |
|---|---|---|
| **Space discovery** | スペース、接続ユーザー、キー付きのプロジェクト、優先度、完了理由を一覧表示する | 不要 |
| **Issue tracking** | 課題を検索、閲覧、集計する | 不要 |
| **Milestones** | マイルストーンとそれぞれの内容を一覧表示する | 不要 |
| **Wikis and documents** | プロジェクトの Wiki とドキュメントを読む | 不要 |
| **Git and pull requests** | プロジェクト内のリポジトリとプルリクエストを読む | 不要 |
| **Ticket context in Review** | マージリクエストやプルリクエストが参照している Backlog 課題（例: `PROJ-123`）を [Review](/ja/guide/code-review/overview) に取り込む | 不要 |
| **Issue, milestone, and wiki changes** | 課題、マイルストーン、Wiki ページを作成・更新する、またはコメントを追加する | 必要 |
| **Follow-up tickets in Resolve** | [Resolve Triggers & Outcomes](/guide/incident/triggers-and-outcomes#outcomes) でアウトカムを有効にすると、インシデント後にフォローアップチケットを登録・更新する | アウトカムの設定による |

### 接続の確認

```text
List my Backlog projects with their keys, then show the five most recently updated open issues in one of them
```

`PLATFORM` のようなキー付きのプロジェクト名と、Backlog で開ける `PLATFORM-42` のような課題キーが表示されるはずです。

### プロンプト例

```text
Summarize the open issues in the PLATFORM project and flag anything past its due date
What does the 2.4 milestone in PLATFORM still have open, grouped by assignee?
Add a comment to PLATFORM-118 saying the fix is deployed to staging
```

3 つ目のプロンプトは書き込みなので、CloudThinker はコメントを表示し、投稿前に承認に回します。

## トラブルシューティング

<Accordion title="接続テストが 401 Unauthorized で失敗する">
キーが間違っている、削除された、またはスペースで API アクセスがオフになっています。**Personal Settings → API** で新しいキーを作成し、スペース管理者に API アクセスが許可されていることを確認してから、接続の **BACKLOG_API_KEY** を更新してください。
</Accordion>

<Accordion title="リクエストが 404 を返す、または別のスペースに到達する">
**BACKLOG_DOMAIN** にスペースキー（`myorg`）だけが入っているか、リージョンが間違っています。`myorg.backlog.com` や `myorg.backlog.jp` のように、ブラウザに表示されるホスト全体をそのまま入力し、再接続してください。
</Accordion>

<Accordion title="接続は動作するが、プロジェクトや課題が表示されない">
キーのユーザーがそれらのプロジェクトのメンバーではありません。Backlog でユーザーをプロジェクトに追加してから、CloudThinker にもう一度プロジェクトを一覧表示させてください。
</Accordion>

<Accordion title="課題の作成・更新が権限エラーで失敗する">
キーのユーザーはプロジェクトを読み取れますが、書き込めません。そのユーザーにプロジェクトの書き込み権限を付与するか、権限を持つユーザーでキーを再発行してから、もう一度操作を承認してください。
</Accordion>

<Accordion title="大規模なプロジェクトで結果が途中で止まる">
返答を読みやすく保つため、CloudThinker は Backlog の各レスポンスを約 10,000 トークンに制限しています。リクエストを 1 つのプロジェクト、マイルストーン、ステータス、担当者に絞るか、先に件数を尋ねてから詳しく掘り下げてください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **キーはユーザーそのものです。** キーは発行した Backlog ユーザーのすべての権限を持つため、最小権限の専用ユーザーで発行し、接続を削除したら Backlog でキーも削除してください。
- **書き込みは Approvals を経由します。** 課題、Wiki、マイルストーンの変更は [Approvals](/guide/approvals/overview) を経由し、Approval mode が各変更を判断します。すべての変更を人が確認すべき場合は **Manual** を選び、キーにはそれらの変更に必要な分を超える書き込み権限を与えないでください。

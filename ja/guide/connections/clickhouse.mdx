ClickHouse を接続すると、CloudThinker がデータベースとテーブルを一覧表示し、パーツ数とテーブルサイズを確認し、`system.query_log` から遅いクエリをランク付けし、分析 SQL で質問に答えられるようになります。CloudThinker は HTTP インターフェース経由で ClickHouse ユーザーとしてサインインし、新しい接続は読み取り専用です。

<Warning>
ClickHouse には Approvals が適用されません。**Write access** を **Full access** に設定すると、書き込みは誰にも確認せずに実行されます。[書き込みアクセス](#書き込みアクセス)を参照してください。
</Warning>

---

## 前提条件

- CloudThinker から **HTTP インターフェース**で到達できる ClickHouse サーバー: TLS ありは `8443`、TLS なしは `8123`。ClickHouse Cloud とセルフホストのクラスターのどちらにも対応します。ネイティブ TCP ポート（`9000`）は使用しません。
- 専用ユーザーを作成するための ClickHouse の管理者ログイン。ClickHouse Cloud では、サービスの **SQL console** で `default` ユーザーとしてセットアップの SQL を実行します。
- 接続を追加するための CloudThinker のワークスペース Admin ロール。[How access works](/ja/guide/connections/overview#アクセスの仕組み) を参照してください。

## セットアップ

<Steps>
  <Step title="読み取りアクセスを持つ専用ユーザーを作成する">
    管理者として接続し、次を実行します。
    ```sql
    CREATE USER cloudthinker IDENTIFIED BY 'your-secure-password';
    GRANT SELECT ON your_database.* TO cloudthinker;
    GRANT SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT SELECT ON system.tables TO cloudthinker;
    GRANT SELECT ON system.columns TO cloudthinker;
    GRANT SELECT ON system.parts TO cloudthinker;
    GRANT SELECT ON system.query_log TO cloudthinker;
    ```
    ClickHouse Cloud では、パスワードがサービスの複雑さのルール（長さ、大文字と小文字の混在、数字、特殊文字）を満たしていないと `CREATE USER` が失敗します。

    `system.*` の権限は、テーブルの健全性と遅いクエリに関する回答に使われます。これらを省略するとそれらの質問は失敗しますが、スキーマに関する質問は引き続き動作します。

    <Warning>
    `system.query_log` には、`WHERE` 句のリテラルを含むすべてのユーザーのクエリの全文が保存されており、個人データが含まれる可能性があります。この権限を付与すると、エージェントがそれらのクエリを読み、チャットで引用できるようになります。懸念がある場合はこの権限を省略してください。その場合、遅いクエリに関する回答は失敗します。
    </Warning>

    複数ノードのセルフホストクラスターでは、クラスターがアクセスストレージを複製していない限り、この方法で作成したユーザーは実行したノードにしか存在しません。代わりに、クラスター名を指定した次のバージョンを実行してください。
    ```sql
    CREATE USER cloudthinker ON CLUSTER '<cluster>' IDENTIFIED BY 'your-secure-password';
    GRANT ON CLUSTER '<cluster>' SELECT ON your_database.* TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SHOW DATABASES, SHOW TABLES, SHOW COLUMNS ON *.* TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.tables TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.columns TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.parts TO cloudthinker;
    GRANT ON CLUSTER '<cluster>' SELECT ON system.query_log TO cloudthinker;
    ```
    `SELECT name FROM clusterAllReplicas('<cluster>', system.users) WHERE name = 'cloudthinker'` で、すべてのノードにユーザーが存在することを確認してください。
  </Step>
  <Step title="サーバー側でユーザーを読み取り専用に固定する（推奨）">
    **Write access** をオンにする予定がある場合は、このステップを省略してください。それ以外の場合は、設定プロファイルを追加して、どのクライアントが何を要求しても ClickHouse 自体が書き込みを拒否するようにします。
    ```sql
    CREATE SETTINGS PROFILE cloudthinker_readonly SETTINGS readonly = 1 READONLY;
    ALTER USER cloudthinker SETTINGS PROFILE cloudthinker_readonly;
    ```
    このプロファイルで CloudThinker が動かなくなることはありません。読み取りは通常どおり動作し、ClickHouse 自体がすべての書き込みを拒否します。
  </Step>
  <Step title="ネットワークアクセスを開放する">
    このドキュメントでは CloudThinker の送信元 IP リストを公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その後、次を行います。
    - **ClickHouse Cloud**: サービスの **Settings → Security** にある IP アクセスリストに追加します。
    - **セルフホスト**: ファイアウォールまたはセキュリティグループで、それらの IP からのインバウンド `8443`（または `8123`）を許可します。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** に移動して **ClickHouse** を選択し、[接続の詳細](#接続の詳細)のフィールドを入力します。**Write access** は **Read-only (default)** のままにして、**Connect** をクリックします。

    CloudThinker はそのユーザーとして `SELECT version()` を 1 回実行します。

    **成功時の状態:** ClickHouse に **Connected** ステータスが表示され、メッセージは `ClickHouse <version> reachable as cloudthinker` となります。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 必須 | 説明 | デフォルト |
|-------|----------|-------------|---------|
| **Host** | はい | ホスト名のみ。`https://` もポートも含めません。ClickHouse Cloud では `abc123.ap-southeast-1.aws.clickhouse.cloud` のような形式です | |
| **Port** | はい | HTTP インターフェースのポート: TLS ありは `8443`、TLS なしは `8123` | `8443` |
| **Username** | はい | 専用ユーザー（例: `cloudthinker`） | |
| **Password** | はい | そのユーザーのパスワード | |
| **Use TLS** | いいえ | プレーンな HTTP ではなく HTTPS を使います。選択肢: **Yes**、**No** | **Yes** |
| **Verify the TLS certificate** | いいえ | 自己署名証明書または社内 CA の証明書の場合のみ **No** に設定します。TLS がオンの場合のみ表示されます。選択肢: **Yes (default)**、**No** | **Yes (default)** |
| **Default database** | いいえ | クエリでデータベースを指定しない場合に使うデータベース。空欄の場合はサーバーのデフォルトを使います | 空欄 |
| **Write access** | いいえ | CloudThinker に書き込みを許可するかどうか。選択肢: **Read-only (default)**、**Full access** | **Read-only (default)** |
| **Allow DROP and TRUNCATE** | いいえ | **Full access** の場合のみ表示されます。選択肢: **Blocked (default)**、**Allowed** | **Blocked (default)** |

<Tip>
**Port** と **Use TLS** はセットで変更してください。`8443` は TLS オン、`8123` は TLS オフに対応します。組み合わせが合わないと接続時に失敗します。
</Tip>

## 必要な権限

セットアップの権限で読み取り専用の操作はすべてカバーされます。書き込み権限は、**Write access** を **Full access** に設定する場合にのみ、エージェントに変更させるデータベースに限って追加してください。

```sql
-- ALTER includes ALTER ... DELETE, DROP PARTITION, and DROP COLUMN, which remove data.
-- See "Blocked protects the table, not the rows" under Write access.
GRANT INSERT, ALTER, CREATE TABLE, CREATE VIEW ON your_database.* TO cloudthinker;
-- Only if the agent should remove tables:
GRANT DROP TABLE, TRUNCATE ON your_database.* TO cloudthinker;
```

<Tip>
`*.*` に書き込み権限を付与しないでください。実際の境界は ClickHouse の権限です。**Write access** フィールドは CloudThinker が `readonly=1` を送信するかどうかを決めるだけで、ClickHouse が付与していない権限をユーザーに与えることはできません。
</Tip>

## エージェントの機能

| 機能 | 説明 |
|------------|-------------|
| **Schema discovery** | データベースとテーブルを、エンジン、ソートキー、行数、列の型とともに一覧表示する |
| **Analytical queries** | 集計、結合、ウィンドウ関数を使った SQL を実行する |
| **Table health** | `system.parts` からパーツ数、圧縮後と圧縮前のサイズ、インデックスの粒度を確認する |
| **Query investigation** | `system.query_log` から遅いクエリや高コストのクエリをランク付けする |
| **Changes** | **Full access** の場合のみ: 行の挿入、テーブルの変更、テーブルとビューの作成 |

`system.query_log` と `system.parts` はノードごとに保持されます。複数のレプリカを持つクラスターでは、回答はクエリを受けたノードの分だけになります。すべてのノードを対象にするには、プロンプトで次のように指定してください。

- **セルフホスト**: "use `clusterAllReplicas('<cluster>', system.query_log)`"
- **ClickHouse Cloud**: "use `clusterAllReplicas('default', system.query_log)`"

### 接続の確認

```text
List the ClickHouse databases and the tables in each one
```

**成功時の状態:** CloudThinker がデータベースを、そのテーブル、エンジン、行数とともに返します。

### プロンプト例

```text
Which ClickHouse tables are the largest by compressed size, and how many parts does each have?
Show the 10 slowest queries from system.query_log in the last 24 hours, with the user and table for each
Suggest a better sorting key for our largest MergeTree table, based on the queries that hit it
```

## 書き込みアクセス

| Write access | Allow DROP and TRUNCATE | エージェントができること |
|--------------|-------------------------|------------------------|
| **Read-only (default)** | 非表示 | `SELECT` のみ。それ以外は ClickHouse がエラー `164`（`READONLY`）で拒否します |
| **Full access** | **Blocked (default)** | 承認ステップなしで `INSERT`、`ALTER`、`CREATE`。`DROP TABLE` と `TRUNCATE` は拒否されます |
| **Full access** | **Allowed** | 上記のすべてに加えて `DROP TABLE` と `TRUNCATE`。ユーザーがその権限を持っていれば `DROP DATABASE` も実行されます（必要な権限では付与していません） |

**Full access** を選ぶ前に:

- **Blocked が守るのはテーブルであり、行ではありません。** `ALTER TABLE ... DELETE`、`DROP PARTITION`、`DROP COLUMN` は引き続き実行され、データを削除します。**Full access** は「エージェントがデータを破壊できる」ものとして扱ってください。
- **ロールバックはできません。** ClickHouse にはトランザクションがないため、復旧はバックアップからの復元になります。

**Write access** は接続後にロックされます。**Edit Instance** で **Replace…** を押すと保存済みのフィールドを編集できますが、**Write access** と **Use TLS** は「Reconnect to change.」と表示されてグレーアウトしたままです。変更するには、ClickHouse 接続を[切断](/ja/guide/connections/overview#接続を切断する)してから、新しい **Write access** で再度追加してください。

**Full access** がオンの場合、**Allow DROP and TRUNCATE** はその場で切り替えられます。**Settings → Workspace → Connections** を開いて **ClickHouse** を選択し、インスタンスの行の鉛筆アイコンをクリックします。**Edit Instance** で **Replace…** をクリックし、オプションを選び、保存済みのパスワードを維持するために **Password** を空欄のままにして、**Save and test** をクリックします。テストが失敗した場合、接続は以前の設定を維持します。

セットアップのステップ 2 で `READONLY` プロファイルを適用した場合は、先にそれを解除してください。解除しないと ClickHouse が書き込みを拒否し続けます。

```sql
ALTER USER cloudthinker SETTINGS PROFILE default;
DROP SETTINGS PROFILE cloudthinker_readonly;
```

承認が適用されない理由: ClickHouse はすべてのクエリを 1 つのツールで実行するため、CloudThinker は書き込みを読み取りと区別して確認できません。Rules と Approval mode が ClickHouse の書き込みを検知することはありません。ダッシュボードが読み取っているクラスターより先に、ステージングクラスターで **Full access** を試してください。

## パスワードのローテーション

1. ClickHouse ユーザーに新しいパスワードを設定します。
   ```sql
   ALTER USER cloudthinker IDENTIFIED BY 'new-secure-password';
   ```
   古いパスワードはすぐに使えなくなるため、ステップ 2 を完了するまで CloudThinker のクエリは失敗します。両方のステップを続けて行ってください。
2. **Settings → Workspace → Connections** を開いて **ClickHouse** を選択し、インスタンスの行の鉛筆アイコンをクリックし、**Edit Instance** で **Replace…** をクリックします。新しい **Password** を入力し、**Save and test** をクリックします。

**成功時の状態:** テストが成功し、接続は **Connected** のままです。テストが失敗した場合、CloudThinker は以前の設定を維持してエラーを表示します。

## トラブルシューティング

最初の 4 つのタイトルは接続テストのメッセージと一致しているため、表示されたメッセージでこのページを検索できます。5 つ目は ClickHouse 自身のエラーテキスト、6 つ目はチャットで見られる症状です。

<Accordion title="ClickHouse rejected the username or password">
`SHOW USERS;` でユーザーが存在することを確認し、パスワードは貼り付けではなく入力し直してください。改行を含む値は、CloudThinker がサーバーに接続する前に拒否されます。ClickHouse Cloud では、コンソールのサインインを流用せず、データベースユーザーを作成してください。
</Accordion>

<Accordion title="ClickHouse is unreachable, or rejected the request path">
- **Port** と **Use TLS** を一致させる必要があります: TLS ありは `8443`、TLS なしは `8123`。`9000` はネイティブ TCP ポートであり、HTTP インターフェースではありません。
- **Host** には `https://` プレフィックスも `:port` サフィックスも付けないでください。
- ClickHouse Cloud では、CloudThinker の送信元 IP をサービスの IP アクセスリストに追加してください。セルフホストでは、ファイアウォールと、`<listen_host>` が公開しているインターフェースをカバーしていることを確認してください。
</Accordion>

<Accordion title="ClickHouse did not answer in time">
ClickHouse Cloud では、アイドル状態のサービスは一時停止し、起動するまで接続がタイムアウトします。ClickHouse Cloud コンソールでサービスを起動してから、もう一度接続してください。
</Accordion>

<Accordion title="ClickHouse has no database named ...">
**Default database** が存在しません。名前は大文字と小文字を区別します。スペルを修正するか、フィールドを空欄にしてください。
</Accordion>

<Accordion title="Cannot execute query in readonly mode">
接続が読み取り専用（デフォルト）です。エージェントに書き込ませる場合は、**Write access** を **Full access** にして再接続してください（[書き込みアクセス](#書き込みアクセス)を参照）。それでも失敗する場合、制限はサーバー側にあります。`SHOW CREATE USER cloudthinker;` を実行し、`readonly` 設定プロファイルや不足している書き込み権限がないか確認してください。
</Accordion>

<Accordion title="テーブル一覧が空">
ユーザーには、個々のテーブルだけでなくデータベースに対する `SHOW TABLES` と `SELECT`、さらに `system.tables` に対する `SELECT` が必要です。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **スイッチより権限**: 何ができるかを決めるのは ClickHouse ユーザーの権限です。**Write access** は CloudThinker が何を要求するかを決めるだけです。
- **サーバー側の読み取り専用**: 書き込みを絶対に行ってはならない接続では、セットアップのステップ 2 の `READONLY` 設定プロファイルを維持してください。どのクライアントも解除できません。

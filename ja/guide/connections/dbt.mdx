**dbt** を接続すると、CloudThinker のエージェントが、何も実行することなく、失敗したジョブ実行の説明、モデルのリネージの追跡、モデルのヘルスチェック、コンパイル済み SQL の読み取りを行えるようになります。**Cloud** タブはアクセストークンで dbt Cloud アカウントを接続し、**Self-host** タブは Git リポジトリと読み取り専用のウェアハウスユーザーで dbt Core プロジェクトを接続します。

<Note>
**Self-host** は dbt Core を意味し、CloudThinker のセルフホストのデプロイではありません。
</Note>

## 前提条件

- **Cloud**: Starter、Enterprise、または Enterprise+ プランの dbt アカウントと、本番環境。メトリクスに関する質問には、[dbt Semantic Layer](https://docs.getdbt.com/docs/use-dbt-semantic-layer/dbt-sl) のセットアップも必要です。
- **Self-host**: HTTPS で提供される GitLab または GitHub リポジトリにあり、**PostgreSQL** にビルドする dbt Core プロジェクト。Self-host タブが対応するウェアハウスは PostgreSQL だけです。
- **Self-host のネットワークアクセス**: CloudThinker がインターネットから Git ホストと PostgreSQL のポートに到達できる必要があります。[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。

## セットアップ

<Tabs>
  <Tab title="Cloud">
    <Steps>
      <Step title="Access URL をコピーする">
        dbt で **Account settings** を開き、**Access URLs** を見つけます。アカウントの URL のホスト（`cloud.getdbt.com` や `ab123.us1.dbt.com` など）を、`https://` を付けずにコピーします。

        CloudThinker がトークンを送信するのは `getdbt.com` と `dbt.com` のホストだけです。アカウントが別のドメインを使っている場合は、[CloudThinker にお問い合わせ](https://cloudthinker.io/contact)ください。
      </Step>
      <Step title="アクセストークンを作成する">
        作成できるトークンは dbt のプランによって異なります。

        - **Enterprise または Enterprise+**: **Account settings → Service Tokens** を開き、**+ Create service token** をクリックします。**Job Viewer** と **Metadata Only** の権限セットを追加し、エージェントにメトリクスの質問に答えさせる場合は **Semantic Layer Only** も追加します。**Save** をクリックしてトークンをコピーします。dbt は一度しか表示しません。
        - **Starter**: **Account settings → API tokens → Personal tokens** を開き、**Create personal access token** をクリックします。個人トークンは作成したユーザーの権限を持つため、可能であれば読み取り専用のアクセス権を持つユーザーとして作成してください。

        dbt の [service tokens](https://docs.getdbt.com/docs/dbt-cloud-apis/service-tokens) と [personal access tokens](https://docs.getdbt.com/docs/dbt-cloud-apis/user-tokens) のガイドを参照してください。
      </Step>
      <Step title="本番環境の ID をコピーする">
        **Orchestration → Environments** に移動し、本番環境をクリックします。ページ URL の `/environments/` の後の数字だけをコピーします。
      </Step>
      <Step title="CloudThinker で接続を追加する">
        **Settings → Workspace → Connections** を開き、**dbt** を選んで **Connect** をクリックします。**Cloud** を選び、[接続の詳細](#接続の詳細)のフィールドに入力して、**Connect** をクリックします。

        **成功時の状態:** 接続に **Connected** のステータスが表示されます。
      </Step>
    </Steps>
  </Tab>
  <Tab title="Self-host">
    <Steps>
      <Step title="リポジトリの読み取りトークンを作成する">
        <Tabs>
          <Tab title="GitLab">
            プロジェクトで **Settings → Repository** を開き、**Deploy tokens** を展開して **Add token** をクリックします。`read_repository` スコープだけを選び、**Create deploy token** をクリックします。生成されたユーザー名（`gitlab+deploy-token-1` など）とトークンをコピーします。[GitLab deploy tokens](https://docs.gitlab.com/user/project/deploy_tokens/) を参照してください。
          </Tab>
          <Tab title="GitHub">
            **Settings → Developer settings → Personal access tokens → Fine-grained tokens** を開き、**Generate new token** をクリックします。**Repository access** で **Only select repositories** を選んで dbt リポジトリを選び、トークンにそのリポジトリへの読み取り専用アクセスを付与します。このトークンには GitHub のユーザー名を使います。[GitHub fine-grained tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) を参照してください。
          </Tab>
        </Tabs>
      </Step>
      <Step title="読み取り専用の PostgreSQL ユーザーを作成する">
        管理者として接続し、モデルとソースがあるスキーマへの読み取りアクセスをユーザーに付与します。この例では `analytics` を使います。

        ```sql
        CREATE ROLE cloudthinker_dbt WITH LOGIN PASSWORD '<secure-password>';
        GRANT CONNECT ON DATABASE your_database TO cloudthinker_dbt;
        GRANT USAGE ON SCHEMA analytics TO cloudthinker_dbt;
        GRANT SELECT ON ALL TABLES IN SCHEMA analytics TO cloudthinker_dbt;
        ```

        他には何も付与しないでください。dbt はコンパイル時にプロジェクトのフックを実行するため、読み取り専用のユーザーであればフックがデータを変更するのを防げます。
      </Step>
      <Step title="ネットワークアクセスを開く">
        CloudThinker が HTTPS で Git ホストに、また PostgreSQL のポート（デフォルト `5432`）に到達できるようにします。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。
      </Step>
      <Step title="CloudThinker で接続を追加する">
        **Settings → Workspace → Connections** を開き、**dbt** を選んで **Connect** をクリックします。**Self-host** を選び、[接続の詳細](#接続の詳細)のフィールドに入力して、**Connect** をクリックします。

        **成功時の状態:** 接続に **Connected** のステータスが表示されます。最初の接続では、CloudThinker がリポジトリをクローンしプロジェクトのパッケージをインストールするため、約 2 分かかることがあります。
      </Step>
    </Steps>
  </Tab>
</Tabs>

保存した接続を編集しても、元の種類は保持されます。もう一方のタブを使うには、2 つ目の接続を追加してください。

## 接続の詳細

| Cloud のフィールド | 必須 | 入力する内容 |
|---|---|---|
| **Access URL** | はい | **Account settings → Access URLs** のホスト（`cloud.getdbt.com` など） |
| **Access token** | はい | 作成したサービストークンまたは個人アクセストークン |
| **Production environment ID** | はい | 本番環境の URL の `/environments/` の後の数字。モデル、ソース、リネージ、メトリクスの読み取りに使われます |

| Self-host のフィールド | 必須 | 入力する内容 |
|---|---|---|
| **Git repository URL** | はい | `https://gitlab.com/acme/analytics.git` のような HTTPS のクローン URL。ユーザー名やトークンは含めません |
| **Repository username** | はい | GitLab のデプロイトークンのユーザー名、または GitHub のユーザー名。デフォルトは `oauth2` |
| **Repository read token** | はい | デプロイトークンまたは fine-grained トークン |
| **Branch or tag** | いいえ | 空欄にするとデフォルトブランチを読み取ります |
| **Project folder** | いいえ | `dbt_project.yml` を含むフォルダー（リポジトリのルートからの相対パス）。ルートにある場合は空欄にします |
| **Warehouse** | はい | **PostgreSQL** |
| **Warehouse host** | はい | ホスト名または IP アドレス。ポートは付けません |
| **Warehouse port** | はい | デフォルトは `5432` |
| **Database** | はい | プロジェクトがビルドするデータベース |
| **Schema** | はい | 本番モデルがビルドされるスキーマ。コンパイル済み SQL とプレビューは、これに対して `ref()` を解決します |
| **Warehouse user** | はい | 読み取り専用のユーザー |
| **Warehouse password** | はい | そのユーザーのパスワード |

## 必要な権限

| タブ | エージェントにさせたいこと | アクセス |
|---|---|---|
| **Cloud** | ジョブ、実行、ログ、実行の成果物を読む | サービストークンの **Job Viewer** |
| **Cloud** | モデル、ソース、エクスポージャー、リネージを読む | サービストークンの **Metadata Only** |
| **Cloud** | メトリクスの質問に答える | サービストークンの **Semantic Layer Only** |
| **Self-host** | プロジェクトを読む | GitLab のデプロイトークンの `read_repository`、または GitHub の fine-grained トークンでの 1 つのリポジトリへの読み取りアクセス |
| **Self-host** | モデルのコンパイルと行のプレビュー | スキーマへの `USAGE` とテーブルへの `SELECT` |

個人アクセストークンは、これらのセットではなく、そのユーザーの権限を持ちます。

<Tip>
サービストークンには上記の権限セットだけを、ウェアハウスのユーザーには `USAGE` と `SELECT` だけを付与してください。どちらも書き込みや管理者のアクセス権は不要です。
</Tip>

## エージェントの機能

| タブ | エージェントができること | 制限 |
|---|---|---|
| **Cloud** | プロジェクト、ジョブ、実行を一覧表示し、実行のステータス、エラー、ログ、成果物を読みます | 読み取り専用 |
| **Cloud** | モデル、ソース、エクスポージャー、マクロを読み、リネージを追跡し、モデルのヘルスと実行時間を確認します | 本番環境を使います |
| **Cloud** | メトリクス、ディメンション、保存されたクエリを一覧表示し、メトリクスの SQL を示し、メトリクスをクエリします | Semantic Layer が必要です。メトリクスのクエリはウェアハウスで実行され、そこで課金されます |
| **Self-host** | プロジェクトを解析・一覧表示し、リネージを追跡し、ノードの詳細を読みます | 設定したブランチを読みます。実行履歴はありません |
| **Self-host** | モデルを SQL にコンパイルし、行をプレビューします | プレビューあたり最大 100 行 |

### 接続を確認する

```text
Show the upstream and downstream lineage of the orders model
```

`orders` にデータを供給するモデルとソース、およびそこからビルドされるモデルが返されることを確認します。不明なモデルのエラーは、名前が誤っているか、モデルが本番環境または設定したブランチにないことを意味します。

### プロンプトの例

```text
Why did the last run of the nightly job fail?
Is the customers model healthy, and how long do its runs take?
Show the compiled SQL for the orders model and preview 5 rows
```

## 書き込みアクセス

dbt の接続は読み取り専用です。エージェントは dbt Cloud のジョブを実行、再試行、キャンセルできず、dbt Core プロジェクトの run、build、test、seed、snapshot もできません。CloudThinker がリポジトリにプッシュすることはありません。

## トラブルシューティング

<Accordion title="The provider rejected these credentials">
dbt がトークンを拒否しました。**Access URL** がアカウントのホストであること、トークンが期限切れや取り消しになっていないこと、サービストークンに **Job Viewer** と **Metadata Only** があることを確認してください。新しいトークンを作成し、再度接続します。
</Accordion>

<Accordion title="モデル、リネージ、メトリクスの質問が失敗する">
**Production environment ID** が誤っているか、数字ではありません。本番環境の URL から `/environments/` の後の数字だけをコピーしてください。
</Accordion>

<Accordion title="メトリクスの質問で役立つ結果が返らない">
アカウントに Semantic Layer がセットアップされていないか、トークンに **Semantic Layer Only** がありません。ジョブ、モデル、リネージの質問はそれがなくても機能します。
</Accordion>

<Accordion title="could not clone the repository; check the URL, branch, username, and token">
CloudThinker がリポジトリを読み取れませんでした。URL が `https://` で始まること、ブランチまたはタグが存在すること、ユーザー名がトークンと一致すること（GitLab のデプロイトークン自身のユーザー名、または GitHub のユーザー名）、トークンがそのリポジトリを読めることを確認してください。URL にユーザー名やトークンが含まれている場合は削除し、**Repository username** と **Repository read token** のフィールドを使ってください。
</Accordion>

<Accordion title="dbt_project.yml not found in the project folder">
**Project folder** を、`dbt_project.yml` を含むフォルダー（リポジトリのルートからの相対パス、例: `analytics`）に設定します。ファイルがルートにある場合は空欄にします。
</Accordion>

<Accordion title="The tools for this connection took too long to start">
最初の Self-host 接続ではリポジトリのクローンとパッケージのインストールが行われるため、数分かかることがあります。1 分待ってから、もう一度接続してください。
</Accordion>

<Accordion title="コンパイルやプレビューがデータベースエラーで失敗する">
CloudThinker が PostgreSQL に到達できないか、ユーザーにアクセス権がありません。ホスト、ポート、データベース、パスワード、ファイアウォールが CloudThinker を許可していること、ユーザーがモデルの読み取るスキーマに `USAGE` と `SELECT` を持っていることを確認してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **読み取り専用のウェアハウスユーザーを使う**: プレビューはこのユーザーとして `SELECT` クエリを実行し、dbt はコンパイル時にプロジェクトのフックを実行します。`USAGE` と `SELECT` だけを付与してください。
- **リポジトリのトークンの範囲を限定する**: 1 つの dbt リポジトリだけを読める GitLab のデプロイトークンまたは GitHub の fine-grained トークンを使ってください。

Langfuse のプロジェクトを接続すると、[CloudThinker](/ja/guide/agents/overview) は LLM 呼び出しが失敗した理由、トレースにかかったコスト、プロンプトのバージョンのスコアを教えてくれます。接続にはプロジェクト単位の API キーペア（パブリックキーとシークレットキー）を使い、Langfuse Cloud とセルフホストの Langfuse の両方で動作します。

## 前提条件

- アプリケーションからトレースを受け取っている Langfuse Cloud またはセルフホストのプロジェクト。
- そのプロジェクトで API キーを作成する権限。
- Langfuse のホスト: サインインするベース URL。例: `https://cloud.langfuse.com`（EU）、`https://us.cloud.langfuse.com`（US）、またはセルフホストのドメイン。
- セルフホストの Langfuse の場合: インスタンスが HTTPS で `/api/public/mcp` を提供し、インターネットからの接続を受け付けること。ファイアウォールの内側にある場合は、CloudThinker の送信元 IP を許可してください。このドキュメントでは CloudThinker の送信元 IP 一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その他の方法は [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。CloudThinker は平文の `http://` ホストを拒否します。
- CloudThinker ワークスペースでの **Admin** ロール。接続の追加と編集ができます。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Steps>
  <Step title="Langfuse で API キーペアを作成する">
    Langfuse にサインインし、CloudThinker に読ませたいプロジェクトを開いて、**Project → Settings → API Keys** を開きます。**Create new API keys** をクリックします。

    Langfuse に **Public Key**（`pk-lf-` で始まる）と **Secret Key**（`sk-lf-` で始まる）が表示されます。今すぐ両方をコピーしてください。シークレットキーは一度しか表示されません。
  </Step>
  <Step title="CloudThinker で Langfuse の接続を開く">
    CloudThinker で **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Langfuse** を選択します。
  </Step>
  <Step title="ホストとキーを入力する">
    | フィールド | 入力する内容 | 例 |
    |-------|---------------|---------|
    | **LANGFUSE_HOST** | プロジェクトがある Langfuse インスタンスのベース URL。パスは含めません。`https://` のないホストには自動で付けられます。 | `https://cloud.langfuse.com` |
    | **LANGFUSE_PUBLIC_KEY** | プロジェクトのパブリックキー | `pk-lf-...` |
    | **LANGFUSE_SECRET_KEY** | プロジェクトのシークレットキー | `sk-lf-...` |

    キーペアは、それを発行したホストとプロジェクトでしか使えません。2 つ目のプロジェクトを読むには、そのプロジェクトのキーで 2 つ目の Langfuse 接続を追加してください。
  </Step>
  <Step title="接続する">
    **Connect** をクリックします。CloudThinker は `/api/public/mcp` にある Langfuse の MCP サーバーとセッションを開いて接続をテストします。

    **成功状態:** Langfuse の接続に **Connected** ステータスが表示されます。下の確認用プロンプトを実行し、キーでプロジェクトを読めることを確かめてください。
  </Step>
</Steps>

## 接続を確認する

```text
Summarize my Langfuse project: recent traces, error count, models in use, and prompts
```

**成功状態:** CloudThinker が、このプロジェクトの過去 7 日間のトレースのサンプル、最近のオブザベーション、プロンプト、データセットを一覧表示します。トレースのないプロジェクトではエラーではなく空の一覧が返ります。401 はキーが誤っていることを意味します。[トラブルシューティング](#トラブルシューティング)を参照してください。

## 必要な権限

Langfuse のキーペアは 1 つのプロジェクトに属し、そのプロジェクトのトレース、スコア、データセット、プロンプトにアクセスします。CloudThinker が見られる範囲は、プロジェクトの選び方で制限します。

キーペアはそのプロジェクトへの書き込み（スコア、コメント、アノテーションキューのアイテムなど）もできます。CloudThinker が書き込むのは、具体的な変更を依頼したときだけで、すべての書き込みは [Approvals](/guide/approvals/overview) を通ります。

<ApprovalDefault />

<Tip>
SDK がトレースを送るためのキーとは別に、CloudThinker 専用のキーペアを作成してください。そうすれば、取り込みを止めずにそのキーを取り消せます。
</Tip>

## エージェントの機能

| 機能 | CloudThinker が行うこと |
|------------|------------------------|
| **Trace investigation** | 最近の失敗した、または遅いオブザベーションを順位付けし、エラー、レイテンシー、モデルの使用状況を関連付けます |
| **Conversation tracing** | 1 つの会話またはセッションを、モデルとツールの呼び出しの順序付きフローとして再構成し、エラーに印を付けます |
| **Usage reports** | 期間内のトークン、コスト、レイテンシーを合計し、モデルとセッションごとに内訳を出します |
| **Quality review** | スコア、データセット、アノテーションキュー、コメント、プロンプトのバージョンを確認し、評価の抜けを指摘します |
| **Changes on request** | スコアやコメントの追加、アノテーションキューのアイテムの変更などの書き込みを、対象と変更内容を指定した場合にのみ行います。調査、レポート、レビューの最中に書き込むことはありません。呼び出しは [Approvals](/guide/approvals/overview) を通ります。 |

## プロンプト例

```text
Which Langfuse traces failed in the last hour, and what do the errors have in common?
Break down LLM cost and latency by model for the last 24 hours in Langfuse
Which prompt versions have the lowest evaluation scores this week?
```

依頼ごとに期間を指定してください。トレースと使用状況のクエリには範囲の上限があり、短い期間のほうが焦点の合った回答が早く返ります。

## トラブルシューティング

<Accordion title="401 Unauthorized">
パブリックキーかシークレットキーが誤っているか、削除されているか、2 つのキーが別々のプロジェクトのものです。同じプロジェクトから両方のキーをもう一度コピーし、余分なスペースがないか確認して、接続を更新してください。
</Accordion>

<Accordion title="Langfuse Cloud への接続が失敗する">
Langfuse Cloud のリージョンはそれぞれデータを分けて保持しているため、キーペアはそれを発行したホストでしか使えません。**LANGFUSE_HOST** には、サインインするベース URL を設定してください。例: EU は `https://cloud.langfuse.com`、US は `https://us.cloud.langfuse.com`。
</Accordion>

<Accordion title="すべてのリクエストが 404 を返す">
**LANGFUSE_HOST** のドメインの後ろにパスが付いています。ベース URL だけを設定してください。1 つのトレースやデータセットでの 404 は、その ID がこのプロジェクトに存在しないことを意味します。
</Accordion>

<Accordion title="セルフホストの Langfuse が 503 を返す、または応答しない">
インスタンスが HTTPS で `/api/public/mcp` を提供していること、プロキシが公開用の `Host` ヘッダーを保持していること、そしてファイアウォールが CloudThinker からホストへのアクセスをブロックしていないことを確認してください。CloudThinker を許可リストに追加するには、[Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
</Accordion>

<Accordion title="検索で何も返らない">
空の回答は接続の故障ではありません。期間を段階的に広げ、プロジェクトがアプリケーションからトレースを受け取っていることを確認してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **キーペアごとに 1 プロジェクト**: キーペアはプロジェクト全体にアクセスするため、CloudThinker に読ませるプロジェクトだけを接続してください。
- **HTTPS のみ**: CloudThinker は HTTPS でないホストを拒否するため、キーが平文で送られることはありません。

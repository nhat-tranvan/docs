GitGuardian のワークスペースを接続すると、CloudThinker のエージェントがシークレットのインシデントを一覧表示・トリアージし、漏洩した各認証情報をそのソースと出現箇所まで追跡し、ハニートークンを確認できるようになります。接続は GitGuardian の **Personal Access Token（PAT）** とダッシュボードの URL でサインインするため、同じセットアップが US、EU、セルフホストのインスタンスで機能します。

## 前提条件

- エージェントに読ませたいインシデントを持つ GitGuardian ワークスペース。
- そのワークスペースで Personal Access Token を作成する権限。
- 接続を追加・編集できる、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。
- ダッシュボードの URL。サインインしているアドレスを使います。

| インスタンス | GitGuardian の URL |
|----------|-----------------|
| US（SaaS） | `https://dashboard.gitguardian.com` |
| EU（SaaS） | `https://dashboard.eu1.gitguardian.com` |
| セルフホスト | インスタンスの URL（例: `https://gitguardian.example.com`） |

## セットアップ

<Steps>
  <Step title="Personal Access Token を作成する">
    GitGuardian にサインインします。サイドバーで **Settings → API → Personal Access Tokens** を開き、**Create token** をクリックします。

    - **Name**: `cloudthinker`
    - **Expiration**: ローテーションのポリシーに合った日付を選びます
    - **Scopes**: `incidents`、`secrets`、`sources` の読み取り用（例: `incidents:read`）にチェックを入れます。これで確認用とプロンプト例のプロンプトをカバーできます。必要な場合にのみ、[必要な権限](#必要な権限)の他のスコープを追加します。

    トークンはすぐにコピーしてください。GitGuardian は一度しか表示しません。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **GitGuardian** を選びます。次を入力します。

    - **GITGUARDIAN_URL**: 上の表のダッシュボードまたはインスタンスの URL
    - **GITGUARDIAN_PERSONAL_ACCESS_TOKEN**: 作成したトークン

    **Connect** をクリックします。

    **成功時の状態:** Connections の一覧で GitGuardian に **Connected** と表示されます。その後、新しいチャットを開いて[確認用のプロンプト](#接続を確認する)を送り、トークンのスコープを確認します。
  </Step>
</Steps>

<Warning>
トークンを紛失すると、再表示できません。GitGuardian で新しいトークンを作成し、接続に貼り付けてください。
</Warning>

## 接続の詳細

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **GITGUARDIAN_URL** | ダッシュボードまたはセルフホストのインスタンスの URL。CloudThinker がそこから API のエンドポイントを導き出します。 | `https://dashboard.eu1.gitguardian.com` |
| **GITGUARDIAN_PERSONAL_ACCESS_TOKEN** | ワークスペースの Personal Access Token | `<your-token>` |

2 つ目の GitGuardian ワークスペースに到達するには、独自のトークンを持つ別の接続として追加してください。

## 必要な権限

PAT の各スコープが、エージェントの機能のグループを 1 つずつ利用可能にします。GitGuardian が `:read` と `:write` の両方を提供している場合は、`:read` を選んでください。エージェントが何かをできないと言う場合、たいていトークンにそのスコープがありません。

| スコープ | 利用可能になるもの |
|-------|---------|
| `incidents` | シークレットのインシデントの一覧表示、調査、トリアージ。最低限のセット。 |
| `secrets` | 検出されたシークレットと、それぞれの出現箇所の読み取り。最低限のセット。 |
| `sources` | 監視対象のソース（リポジトリ）の一覧表示と調査。最低限のセット。 |
| `scan` | 依頼に応じてコンテンツのシークレットをスキャン |
| `honeytokens` | 読み取りでハニートークンを一覧表示。書き込みで作成。 |
| `custom_tags` | カスタムタグの読み取りと管理 |
| `audit_logs` | ワークスペースの監査ログの読み取り |

<Tip>
PAT は、作成した人のワークスペースロールも継承します。必要なアクセス権を持つ中で最も権限の小さいメンバーから作成し、スコープに読み取りがある場合は常に読み取りを選んでください。
</Tip>

## エージェントの機能

| 機能 | エージェントができること | 必要なスコープ | 承認 |
|------------|--------------------|--------------|----------|
| **Incident triage** | シークレットのインシデントを、ステータスと重大度とともに一覧表示・調査します | `incidents` | 不要 |
| **Incident investigation** | 漏洩した認証情報の背後にあるソースと出現箇所を示します | `incidents`、`secrets`、`sources` | 不要 |
| **Token inspection** | 接続されたトークンが持つスコープを報告します | 任意 | 不要 |
| **Honeytokens** | ハニートークンとそのステータスを一覧表示します | `honeytokens` の読み取り | 不要 |
| **Honeytoken creation** | 新しいハニートークンを作成します | `honeytokens` の書き込み | Approvals を経由 |

読み取りは確認なしで実行されます。ハニートークンの作成には `honeytokens:write` と **Manager** が作成したトークンが必要で、あなたが依頼した場合にのみ行われます。

<ApprovalDefault />

ハニートークンを作成するたびに確認されるようにするには、**Manual** を選びます。**Ask first** の [Rule](/guide/approvals/rules) を使えば、ハニートークンの作成だけを対象にできます。

### 接続を確認する

```text
Check the GitGuardian connection, list the scopes on the token, and count open secret incidents
```

トークンのスコープの一覧と、オープン中のインシデント（**Triggered** または **Assigned** のステータスのインシデント）の件数が返されることを確認します。期待したスコープが表示されない場合は、トークンの更新が必要です。

### プロンプトの例

```text
List open GitGuardian incidents sorted by severity, with the repository for each one
Investigate the newest GitGuardian incident and summarize the exposed credential and its sources
```

## トラブルシューティング

<Accordion title="Connect が失敗する、またはリクエストが 401 を返す">
トークンが誤っている、期限切れ、または取り消されています。新しい Personal Access Token を作成します。**Settings → Workspace → Connections** で **GitGuardian** を開き、接続の行の鉛筆アイコンをクリックし、**Replace…** をクリックしてトークンを **GITGUARDIAN_PERSONAL_ACCESS_TOKEN** に貼り付け、**Save and test** をクリックします。
</Accordion>

<Accordion title="リクエストが 403 を返す">
トークンにそのリクエストのスコープがないか、作成者のワークスペースロールが不十分です。GitGuardian でスコープを追加し（ハニートークンの作成には **Manager** が必要です）、新しいトークンで接続を更新してください。
</Accordion>

<Accordion title="エージェントが機能を利用できないと言う">
トークンに対応するスコープがありません。リクエストを[必要な権限](#必要な権限)と照合し、そのスコープを持つトークンを作成して、接続を更新してください。
</Accordion>

<Accordion title="インシデントがない、またはエンドポイントに到達できない">
**GITGUARDIAN_URL** が誤ったリージョンまたはインスタンスを指しています。US のトークンは EU のダッシュボードでは機能しません。サインインしている正確なアドレスを使ってください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **まず読み取りスコープから**: `honeytokens:write` や Manager ロールのトークンは、エージェントにハニートークンを作成させたい場合にのみ追加してください。
- **専用のトークン**: `cloudthinker` という名前にすれば、他のツールを壊さずに GitGuardian で取り消せます。

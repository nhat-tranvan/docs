Coralogix のチームを接続すると、CloudThinker のエージェントがオープン中のインシデントをトリアージし、ログとトレースを検索し、メトリクスをクエリし、アラートとダッシュボードを調べ、データパイプラインに無効化されたパースルールや設定の誤ったコネクターがないかを確認できるようになります。接続は Coralogix がホストする MCP サーバーを使い、1 つの **リージョン** に対して 1 つの **API キー** でサインインします。リージョンを選ぶと CloudThinker が対応する Coralogix のエンドポイントにルーティングするため、URL を入力する必要はありません。

## 前提条件

- エージェントに読ませたいデータを持つ Coralogix のチーム。
- そのチームで API キーを作成する権限。
- チームのリージョン。ログインアドレスから読み取ります（[リージョンの表](#接続の詳細)を参照）。

## セットアップ

<Steps>
  <Step title="リージョンを確認する">
    Coralogix にサインインし、アドレスバーを[リージョンの表](#接続の詳細)と照合します。アドレスにリージョン名が含まれないリージョンもあります。`acme.coralogix.com` は EU1、`acme.app.cx498.coralogix.com` は US2 です。
  </Step>
  <Step title="API キーを作成する">
    **Settings → API Keys** に移動し、新しいキーを作成します。

    - **Name**: `cloudthinker`
    - **Type**: **Team key**。個人キーは 1 人のユーザーに紐づき、そのユーザーのアクセスが終了すると使えなくなります。
    - **Permissions**: エージェントに到達させたいデータへの読み取りアクセス（[必要な権限](#必要な権限)を参照）

    キーはすぐにコピーしてください。紛失した場合は新しいキーが必要になります。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Coralogix** を選びます。次を入力します。

    - **CORALOGIX_API_KEY**: 作成したキー
    - **CORALOGIX_REGION**: 一覧からリージョンを選びます（例: **EU2 (eu2.coralogix.com)**）。デフォルトは **US2 (us2.coralogix.com)** なので、チームが別のリージョンにある場合は変更してください。

    **Connect** をクリックします。

    **成功時の状態:** Coralogix に **Connected** と表示されます。下の確認用プロンプトを実行して、キーとリージョンが一致していることを確認してください。
  </Step>
</Steps>

<Warning>
キーは作成されたリージョンでのみ機能します。リージョンが誤っていると **404 Not Found** になり、データがないように見えます。他のことをデバッグする前に、ログインアドレスを確認してください。
</Warning>

## 接続の詳細

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **CORALOGIX_API_KEY** | Coralogix のチーム API キー | `<your-api-key>` |
| **CORALOGIX_REGION** | チームのログインアドレスに対応するリージョン | **EU2 (eu2.coralogix.com)** |

左の列でログインアドレスを見つけ、右のオプションを選びます。

| ログインアドレス | **CORALOGIX_REGION** で選ぶもの |
|---------------|------------------------------|
| `<team>.app.coralogix.us` | **US1 (us1.coralogix.com)** |
| `<team>.app.cx498.coralogix.com` | **US2 (us2.coralogix.com)**（デフォルト） |
| `<team>.app.us3.coralogix.com` | **US3 (us3.coralogix.com)** |
| `<team>.coralogix.com` | **EU1 (eu1.coralogix.com)** |
| `<team>.app.eu2.coralogix.com` | **EU2 (eu2.coralogix.com)** |
| `<team>.app.coralogix.in` | **AP1 (ap1.coralogix.com)** |
| `<team>.app.coralogixsg.com` | **AP2 (ap2.coralogix.com)** |
| `<team>.app.ap3.coralogix.com` | **AP3 (ap3.coralogix.com)** |

別のチームやリージョンに到達するには、独自のキーを持つ別の接続として追加してください。

## 必要な権限

エージェントに調査させたいデータへの読み取りアクセスをキーに付与します。

| データ | 用途 |
|------|----------|
| Incidents | インシデントのトリアージと Discovery |
| Logs and traces | エラーの検索とリクエストの追跡 |
| Metrics | メトリクスのクエリとメトリクスカタログ |
| Alerts and dashboards | アラート定義とダッシュボードの調査 |
| Parsing rules, connectors, presets | パイプラインのヘルスチェック |

パースルールの有効化など、エージェントに Coralogix のリソースを変更させたい場合を除き、キーの書き込み権限はオフのままにしてください。このページのすべての調査は、読み取り専用のキーでカバーできます。

## エージェントの機能

| 機能 | エージェントができること | 承認 |
|------------|--------------------|----------|
| **Discovery** | オープン中のインシデント、コネクターの数、無効化されたパースルール、プリセット、メトリクス検索が機能するかを要約します | 不要 |
| **Incident triage** | 最近のインシデントとオープン中のインシデントを、重大度、ステータス、タイムスタンプとともに一覧表示します | 不要 |
| **Logs** | 期間を指定してログを検索します | 不要 |
| **Traces** | 分散トレースを調べます | 不要 |
| **Metrics** | メトリクスをクエリし、メトリクスカタログを検索します | 不要 |
| **Pipeline health** | 無効化または非表示のパースルールを見つけ、コネクターとプリセットを確認します | 不要 |
| **Alerts and dashboards** | アラート定義とダッシュボードを読みます | 不要 |
| **Changes** | Coralogix のリソースを作成、更新、有効化、無効化、削除します。キーに書き込み権限が必要です | 必要 |

Discovery、トリアージ、ヘルスチェックの間、エージェントは何も変更しません。変更が行われるのは、会話の中であなたがリソースと変更内容を指定して依頼した場合だけで、それも [Approvals](/guide/approvals/overview) を経由します。大きなカタログで回答があふれないよう、エージェントはデフォルトでサンプルを 10 件に制限します。

### 接続を確認する

```text
Run Coralogix discovery and summarize open incidents, connector count, disabled parsing rules, and whether metric search is healthy
```

インシデント、コネクター、パースルール、プリセットの件数と、それぞれの短いサンプルが返されることを確認します。メトリクスのチェックでの「No metrics matched」は正常です。Discovery は存在しない名前で検証するためです。要約に **degraded** と表示された場合、エージェントはインシデント、コネクター、パースルール、プリセット、メトリクスのうち、どのチェックが失敗したかを一覧表示します。チェックの失敗は通常、そのデータへの読み取り権限がキーにないことを意味します。すべてのチェックが失敗する場合は、まずキーとリージョンを確認してください。

### プロンプトの例

```text
Triage open Coralogix incidents and flag anything affecting production
Search Coralogix logs for 5xx errors from the api-gateway service in the last hour
Check Coralogix pipeline health and list disabled parsing rules
Which Coralogix alerts fired for the payments service today?
```

サービス名と短い期間を指定してください。絞り込んだクエリのほうが早く返り、読みやすくなります。

## トラブルシューティング

<Accordion title="Connect が失敗する、またはリクエストが 401 を返す">
キーがない、期限切れ、または取り消されています。新しいチームキーを作成し、接続を編集して **CORALOGIX_API_KEY** に貼り付けてください。
</Accordion>

<Accordion title="すべてが 404 を返す">
キーが別のリージョンのものです。ログインアドレスを確認し、**CORALOGIX_REGION** を一致するものに変更してください。
</Accordion>

<Accordion title="一部のデータの種類だけが失敗する">
キーにそのデータへの読み取り権限がありません。Coralogix で追加してから、リクエストを再実行してください。キー自体が変わっていなければ、再接続は不要です。
</Accordion>

<Accordion title="メトリクスのクエリが何も返さない">
その名前に一致するメトリクスがないか、チームがメトリクスを送信していません。エージェントはこれを空の結果として扱います。存在すると分かっているメトリクス名を試すか、インシデントとログで調査を続けてください。
</Accordion>

<Accordion title="リクエストが 429 または 503 を返す">
Coralogix がレート制限中かメンテナンス中です。1 分待ち、リクエストを絞り込んでから、もう一度質問してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **チームキーで、まず読み取りアクセスから**: 書き込み権限は、エージェントに提案させたい変更に限って追加してください。
- **接続ごとに 1 つのキー**: CloudThinker 専用のキーを作成すれば、他のツールを壊さずに取り消せます。

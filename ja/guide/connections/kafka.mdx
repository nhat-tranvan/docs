Confluent Cloud またはセルフホストの Apache Kafka クラスターを接続すると、CloudThinker のエージェントがトピックとその設定を一覧表示し、メッセージをサンプリングし、スループットのメトリクスをクエリし、スキーマとコネクターを監査し、Flink SQL のステートメントを診断できるようになります。接続には **JSON の認証情報ファイル** を 1 つアップロードします。内容は、ブートストラップアドレスと、オンにしたいスコープごとに 1 組の Confluent API キーです。

## 前提条件

- **Confluent Cloud**: Kafka クラスターが少なくとも 1 つある環境と、API キー（できればサービスアカウント用）を作成する権限。
- **セルフホストの Kafka**: CloudThinker がネットワーク経由でブートストラップアドレス（デフォルトはポート `9092`）に到達できるブローカー。ファイルには SASL/SCRAM、mTLS、クライアント証明書、カスタム CA の設定がないため、ブローカーはそれらなしで CloudThinker の接続を受け入れる必要があります。そのようなブローカーをインターネットに公開せず、CloudThinker の送信元 IP に制限してください。このドキュメントでは CloudThinker の送信元 IP の一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その他の選択肢は [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- JSON ファイルを書くためのテキストエディター。
- 接続を追加・編集できる、CloudThinker ワークスペースの **Admin** ロール。[Roles](/guide/security/roles) を参照してください。

## スコープを選ぶ

Confluent Cloud では、API キーの各組が 1 つのスコープを利用可能にします。まず Kafka クラスターのスコープから始め、後で[更新したファイルをアップロード](#後でファイルを変更する)して他を追加します。セルフホストの Kafka では `BOOTSTRAP_SERVERS` と任意の `SCHEMA_REGISTRY_ENDPOINT` だけが適用され、他のスコープはすべて Confluent Cloud 専用です。

| スコープ | エージェントができること | フィールド |
|-------|----------------------------|--------|
| **Kafka cluster**（必須） | トピックの一覧表示、トピック設定の読み取り、メッセージのサンプリングと送信、トピックの作成・削除 | `BOOTSTRAP_SERVERS`（両方のプラットフォーム）。Confluent Cloud のみ: `KAFKA_API_KEY`、`KAFKA_API_SECRET`、`KAFKA_REST_ENDPOINT`、`KAFKA_CLUSTER_ID`、`KAFKA_ENV_ID` |
| **Cloud resource management** | 環境とクラスターの一覧表示、受信バイト数などのメトリクスのクエリ、請求コストの一覧表示、コネクターとトピックタグの管理 | `CONFLUENT_CLOUD_API_KEY`、`CONFLUENT_CLOUD_API_SECRET` |
| **Schema Registry** | スキーマのサブジェクトとバージョンの一覧表示、スキーマの削除 | `SCHEMA_REGISTRY_ENDPOINT`、`SCHEMA_REGISTRY_API_KEY`、`SCHEMA_REGISTRY_API_SECRET` |
| **Flink** | Flink SQL ステートメントの実行と調査、カタログとテーブルの閲覧、ステートメントのヘルスチェック | `FLINK_API_KEY`、`FLINK_API_SECRET`、`FLINK_REST_ENDPOINT`、`FLINK_COMPUTE_POOL_ID`、`FLINK_ENV_ID`、`FLINK_ORG_ID`、任意の `FLINK_ENV_NAME`、`FLINK_DATABASE_NAME` |
| **Tableflow** | Tableflow のトピックとカタログ連携の一覧表示と管理 | `TABLEFLOW_API_KEY`、`TABLEFLOW_API_SECRET` |

## セットアップ

<Tabs>
  <Tab title="Confluent Cloud">
    <Steps>
      <Step title="クラスターのフィールドを集める">
        [Confluent Cloud](https://confluent.cloud/home) で **Environments** を開き、環境を選びます。その ID（`env-...`）が `KAFKA_ENV_ID` です。クラスターを開き、ブートストラップサーバー、REST エンドポイント、クラスター ID（`lkc-...`）をコピーします。
      </Step>
      <Step title="スコープごとに API キーの組を作成する">
        **Settings → API keys** に移動し、**Add API key** をクリックします。本番環境では **Service account** を選びます。まず Kafka クラスターのキーを作成し、次に選んだ任意のスコープごとにキーを 1 つずつ作成します。作成するたびに各キーとシークレットを保存してください。各スコープに対応するリソースを選びます。

        | スコープ | ウィザードで選ぶもの | 次に選ぶもの |
        |-------|----------------------|-------------|
        | Kafka cluster | **Kafka cluster** | ステップ 1 のクラスター |
        | Cloud resource management | **Cloud resource management** | なし。組織全体が対象です |
        | Schema Registry | **Schema Registry** | ステップ 1 の環境 |
        | Flink | **Flink region** | コンピュートプールの環境、クラウド、リージョン |
        | Tableflow | **Tableflow** | なし |
      </Step>
      <Step title="任意のスコープのフィールドを集める">
        - **Schema Registry**: 環境で **Stream Governance → Schema Registry** を開き、エンドポイントをコピーします。
        - **Flink**: **Flink → Compute pools** を開き、プールを選んでその ID（`lfcp-...`）をコピーします。REST エンドポイントは `https://flink.<region>.<provider>.confluent.cloud` のパターンに従います（例: `https://flink.us-east-1.aws.confluent.cloud`）。`FLINK_ENV_ID` はプールを含む環境の `env-...` の ID で、通常は `KAFKA_ENV_ID` と同じ値です。組織 ID は **Settings → Organizations** にあります。
        - **任意の Flink のデフォルト**: `FLINK_ENV_NAME` は環境の表示名で、デフォルトのカタログとして使われます。`FLINK_DATABASE_NAME` は Kafka クラスターの表示名で、デフォルトのデータベースとして使われます。これらを設定すると、エージェントは `catalog.database.table` の完全なパスなしでテーブルを指定できます。
      </Step>
      <Step title="JSON ファイルを書く">
        `kafka.json` などのファイルを保存します。キーを作成したスコープだけを残し、他の行は完全に削除してください。

        ```json
        {
          "BOOTSTRAP_SERVERS": "pkc-xxxxx.us-east-1.aws.confluent.cloud:9092",
          "KAFKA_API_KEY": "<kafka-api-key>",
          "KAFKA_API_SECRET": "<kafka-api-secret>",
          "KAFKA_REST_ENDPOINT": "https://pkc-xxxxx.us-east-1.aws.confluent.cloud:443",
          "KAFKA_CLUSTER_ID": "lkc-xxxxx",
          "KAFKA_ENV_ID": "env-xxxxx",

          "CONFLUENT_CLOUD_API_KEY": "<cloud-api-key>",
          "CONFLUENT_CLOUD_API_SECRET": "<cloud-api-secret>",

          "SCHEMA_REGISTRY_ENDPOINT": "https://psrc-xxxxx.us-east-1.aws.confluent.cloud",
          "SCHEMA_REGISTRY_API_KEY": "<schema-registry-api-key>",
          "SCHEMA_REGISTRY_API_SECRET": "<schema-registry-api-secret>",

          "FLINK_API_KEY": "<flink-api-key>",
          "FLINK_API_SECRET": "<flink-api-secret>",
          "FLINK_REST_ENDPOINT": "https://flink.us-east-1.aws.confluent.cloud",
          "FLINK_COMPUTE_POOL_ID": "lfcp-xxxxx",
          "FLINK_ENV_ID": "env-xxxxx",
          "FLINK_ORG_ID": "<org-id>",

          "TABLEFLOW_API_KEY": "<tableflow-api-key>",
          "TABLEFLOW_API_SECRET": "<tableflow-api-secret>"
        }
        ```
      </Step>
      <Step title="CloudThinker でファイルをアップロードする">
        **Settings → Workspace → Connections** を開き、**Apache Kafka** を選びます。ファイルをアップロード領域にドラッグするか、**choose a JSON file** をクリックします。**Connect** をクリックします。

        **成功時の状態:** 接続に **Connected** のステータスが表示されます。下の確認用プロンプトを実行して、エージェントがトピックを見られることを確認してください。
      </Step>
    </Steps>
  </Tab>
  <Tab title="Self-hosted Kafka">
    <Steps>
      <Step title="ネットワークアクセスを開く">
        CloudThinker がブローカーのブートストラップアドレス（デフォルトはポート `9092`）に到達できるようにします。`127.0.0.1` にのみバインドされたブローカーには到達できません。
      </Step>
      <Step title="JSON ファイルを書く">
        ブートストラップアドレスと、Schema Registry を運用している場合はそのエンドポイント（多くの場合ポート `8081`）を含む、`kafka.json` などのファイルを保存します。

        ```json
        {
          "BOOTSTRAP_SERVERS": "kafka-1.example.com:9092",
          "SCHEMA_REGISTRY_ENDPOINT": "https://schema-registry.example.com:8081"
        }
        ```
      </Step>
      <Step title="CloudThinker でファイルをアップロードする">
        **Settings → Workspace → Connections** を開き、**Apache Kafka** を選びます。ファイルをアップロードし、**Connect** をクリックします。

        **成功時の状態:** 接続に **Connected** のステータスが表示されます。
      </Step>
    </Steps>

    セルフホストの Kafka では、エージェントはブローカー自体を通じて作業します。トピックの一覧表示とメッセージのサンプリング・送信、さらに Schema Registry のエンドポイントを設定した場合はスキーマも扱えます。メトリクス、請求、コネクター、Flink、Tableflow は Confluent Cloud の API のため、利用できません。
  </Tab>
</Tabs>

## 接続の詳細

フォームにはアップロードのフィールドが 1 つあります。ファイルは文字列の値を持つ 1 つの JSON オブジェクトでなければならず、[スコープを選ぶ](#スコープを選ぶ)に記載されたキーだけを使えます。それ以外のキーがあるファイルや、文字列でない値を持つファイルは拒否されます。

| フィールド | 必須 | 説明 |
|-------|----------|-------------|
| `BOOTSTRAP_SERVERS` | はい | ブローカーのブートストラップアドレス（`host:port`） |
| `KAFKA_API_KEY` / `KAFKA_API_SECRET` | Confluent Cloud | Kafka クラスターのキーの組 |
| `KAFKA_REST_ENDPOINT`、`KAFKA_CLUSTER_ID`、`KAFKA_ENV_ID` | Confluent Cloud | クラスターの REST エンドポイント、クラスター ID、環境 ID |
| `SCHEMA_REGISTRY_ENDPOINT` | いいえ | Schema Registry の URL（どちらのプラットフォームでも） |
| その他のスコープのキー | いいえ | [スコープを選ぶ](#スコープを選ぶ)を参照 |

## 必要な権限

**Confluent Cloud:** サービスアカウント用のキーを作成し、そのアカウントにはエージェントが必要とするものだけを付与します。

- **Kafka cluster**: ACL をエージェントに読ませるトピックに制限します。メッセージのサンプリングはコンシューマーグループを通じて読み取るため、アカウントにはコンシューマーグループへの `READ` も必要です。

  ```bash
  confluent kafka acl create --allow --service-account sa-xxxxx \
    --operations read,describe,describe-configs --topic orders --cluster lkc-xxxxx
  confluent kafka acl create --allow --service-account sa-xxxxx \
    --operations read --consumer-group "*" --cluster lkc-xxxxx
  ```

- **Cloud resource management**: メトリクスには少なくとも **MetricsViewer**。
- **Schema Registry**: エージェントに一覧表示させるサブジェクトへの **DeveloperRead**。
- **Flink**: コンピュートプールを含む環境での **FlinkDeveloper**。

**セルフホストの Kafka:** 接続にはブートストラップアドレスだけが必要です。

<Tip>
Kafka クラスターのスコープと読み取り専用の ACL から始めてください。エージェントにメッセージの送信やトピックの作成をさせたい場合を除き、サービスアカウントの書き込み ACL はオフのままにしてください。
</Tip>

## エージェントの機能

| 機能 | エージェントができること | Approvals を経由するか |
|------------|--------------------|------------------------|
| **Topic inventory** | パーティション数付きでトピックを一覧表示し、トピック設定を読み、名前やタグでトピックを検索します | いいえ |
| **Message sampling** | 最近のメッセージを件数を限って読み、設定されていれば Schema Registry でデコードします | いいえ |
| **Metrics and billing** | 受信バイト数などの Confluent Cloud のメトリクスをクエリし、請求コストを一覧表示します | いいえ |
| **Schemas and connectors** | スキーマのサブジェクトとバージョンを一覧表示し、コネクターを一覧表示・読み取ります | いいえ |
| **Flink SQL reads** | カタログとテーブルを閲覧し、ステートメントとその例外を読み、ヘルスチェックを実行します | いいえ |
| **Flink SQL statements** | Flink SQL ステートメントを実行します | はい |
| **Produce and create** | メッセージを送信し、トピックを作成します | はい |
| **Changes and deletions** | トピック、スキーマ、コネクター、Flink ステートメントの削除。トピック設定の変更。コネクターの作成。タグの削除。Tableflow の変更 | はい |

**はい** の呼び出しは、まずワークスペースの [Approvals](/guide/approvals/overview) を経由します。

<ApprovalDefault />

<Warning>
Flink のステートメントは読み取り以上のことができます。`INSERT INTO` はトピックに書き込み、継続的なステートメントは誰かが削除するまで、あなたが料金を支払うコンピュートプールの容量を使って実行され続けます。承認する前にステートメントを読んでください。
</Warning>

パーティション数はトピック設定では変更できません。Confluent Cloud の UI を使うか、トピックを削除して再作成してください。

### 接続を確認する

```text
List my Kafka topics with partition counts and replication factor
```

クラスター内のすべてのトピックが、パーティション数とレプリケーション係数とともに返されることを確認します。Confluent Cloud でクラウドのスコープがある場合、エージェントは環境とクラスターの名前も示せます。

### プロンプトの例

```text
Show the last 10 messages on the orders topic, decoded with Schema Registry
Chart received bytes per 5 minutes for my Kafka cluster over the last 6 hours
Why is my Flink statement order-enrichment failing?
```

## 後でファイルを変更する

スコープを追加したりキーをローテーションしたりするには、残したいすべてのスコープを含む完全なファイルを書きます。接続を開き、行の鉛筆アイコンをクリックし、**Edit Instance** で **Replace…** をクリックします。ファイルをアップロードし、**Save and test** をクリックします。テストが失敗した場合、CloudThinker は以前の認証情報を保持します。[Rotate a credential](/ja/guide/connections/overview#認証情報をローテーションする) を参照してください。

## トラブルシューティング

<Accordion title="Connection refused またはタイムアウト">
CloudThinker からブローカーに到達できません。ブローカーが稼働していること、ファイアウォールで `9092` が開いていること、`BOOTSTRAP_SERVERS` が正しいことを確認してください。`127.0.0.1` にのみバインドされたブローカーには、そのホストの外から到達できません。
</Accordion>

<Accordion title="一部だけのファイルをアップロードした後に検証エラーが出る">
スコープのキーが空の値で存在しています。使わないスコープは、キーと値を丸ごと削除してください。`"SCHEMA_REGISTRY_ENDPOINT": ""` は失敗しますが、キーを省けば機能します。
</Accordion>

<Accordion title="401 Unauthorized">
キーの組が誤っている、期限切れ、または誤ったスコープに使われています。各スコープには専用の組が必要で、Kafka クラスターのキーは Schema Registry や Flink では機能しません。そのスコープ用の新しい組を作成し、[更新したファイルをアップロード](#後でファイルを変更する)してください。
</Accordion>

<Accordion title="メトリクスや請求の質問が失敗する">
ファイルに `CONFLUENT_CLOUD_API_KEY` の組がないか、そのアカウントに **MetricsViewer** がありません。クラウドのスコープを追加し、[ファイルを再アップロード](#後でファイルを変更する)してください。セルフホストのクラスターでは、これらの API は利用できません。
</Accordion>

<Accordion title="Schema Registry が失敗する">
`SCHEMA_REGISTRY_ENDPOINT` に CloudThinker から到達できることを確認してください。セルフホストの場合はポート `8081` を開きます。Confluent Cloud の場合は、Schema Registry のキーが同じ環境に属していることを確認します。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **セルフホストの Kafka は認証情報を受け取らない**: 上記の読み取り専用のアドバイスは Confluent Cloud のキーにのみ適用されます。セルフホストのブローカーは自身の設定が許可するものを何でも受け入れるため、下記のとおりネットワークアクセスを制限してください。また、送信や作成の呼び出しは引き続き Approvals を経由することを覚えておいてください。
- **スコープごとに 1 組のキー**: 各スコープにサービスアカウントの専用キーを与えれば、Kafka クラスターのキーに触れずに Flink や Tableflow のアクセスを取り消せます。
- **ネットワークアクセスを制限する**: 特に認証情報のないセルフホストのブローカーでは、ファイアウォールのルールでブートストラップと REST のエンドポイントを CloudThinker のトラフィックに限定してください。
- **ローカルのファイルを削除する**: JSON ファイルにはすべてのシークレットが平文で含まれています。アップロード後に削除するか、シークレットマネージャーにだけ保管してください。
- **メッセージは機密として扱う**: サンプリングされたメッセージには、プロデューサーが書き込んだ個人データやトークンが含まれていることがあります。トピックの `READ` は、エージェントに見せるべき場所にだけ付与してください。

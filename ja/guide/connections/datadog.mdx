Datadog を接続すると、CloudThinker がアラート中のモニターをトリアージし、ログを検索し、メトリクスをクエリし、トレースを追跡し、インシデント、ホスト、ダッシュボードを読めるようになります。CloudThinker は Datadog MCP server を通じて Datadog にアクセスし、API キーと、読み取り権限にスコープを限定したアプリケーションキーで認証します。

Datadog には 2 つの別々のセットアップがあります。Datadog アラートに対して自動で根本原因分析を行うには、両方が必要です。

| セットアップ | 役割 | 必要になる場合 |
|---|---|---|
| 調査（この接続） | エージェントがログ、メトリクス、トレース、モニターを読めるようにする | 常に必要。これがないと、エージェントは Datadog の中を見られません。 |
| アラートの受信（Webhook） | モニターが発火したときに Resolve インシデントを開く | インシデントを自動で開きたい場合。[Datadog アラートを Resolve に送信する](#datadog-アラートを-resolve-に送信する)を参照してください。 |

## 前提条件

- 次のいずれかのサイトにある Datadog 組織: **US1**、**US3**、**US5**、**EU1**、**AP1**、**AP2**。政府向けサイト（`ddog-gov.com`）は Datadog MCP server でサポートされていません。
- Datadog の **Organization Settings** で **MCP Access** がオンになっていること。これは Datadog の管理者が組織ごとに 1 回行います。
- API キーとアプリケーションキーを作成する Datadog の権限。
- CloudThinker ワークスペースで接続を追加する権限。

## セットアップ

<Steps>
  <Step title="サイトを確認する">
    Datadog にサインインしているときのアドレスバーを確認します。

    | Datadog の URL | CloudThinker で選ぶもの |
    |------------------|----------------------|
    | `app.datadoghq.com` | **US1 (datadoghq.com)** |
    | `us3.datadoghq.com` | **US3 (us3.datadoghq.com)** |
    | `us5.datadoghq.com` | **US5 (us5.datadoghq.com)** |
    | `app.datadoghq.eu` | **EU1 (datadoghq.eu)** |
    | `ap1.datadoghq.com` | **AP1 (ap1.datadoghq.com)** |
    | `ap2.datadoghq.com` | **AP2 (ap2.datadoghq.com)** |
  </Step>
  <Step title="API キーを作成する">
    Datadog で **Organization Settings → API Keys** に移動し、**New Key** をクリックして `cloudthinker` という名前を付け、値をコピーします。
  </Step>
  <Step title="スコープを限定したアプリケーションキーを作成する">
    **推奨:** 個人の権限に結び付かないよう、**Datadog Read Only Role** を持つ Datadog サービスアカウントでキーを作成してください。**Organization Settings → Service Accounts** に移動し、そのロールで `cloudthinker` を作成して、アプリケーションキーを追加します。

    それ以外の場合は、**Organization Settings → Application Keys** に移動して **New Key** をクリックします。

    どちらの場合も、キーに `cloudthinker` という名前を付け、[必要な権限](#必要な権限)のスコープを選択します。保存して、すぐにキーをコピーしてください。

    <Warning>
    スコープのないアプリケーションキーは、書き込みを含む所有者のすべての権限を継承します。必ずスコープを選択してください。
    </Warning>

    **成功時の状態:** キーのスコープ一覧に読み取り権限のみが表示され、`_write` の項目はありません。
  </Step>
  <Step title="接続を追加する">
    **Settings → Workspace → Connections** を開き、**Discover** タブを開いて **Datadog** を選択します。次を入力します。
    - **Alias**（任意）: `datadog-prod` などの短い名前。小文字、数字、ハイフンが使えます。
    - **Description**（任意）: どの組織または環境か。エージェントはこれを読んで正しいインスタンスを選びます。
    - **DD_API_KEY**: API キー。
    - **DD_APPLICATION_KEY**: アプリケーションキー。
    - **DD_SITE**: ステップ 1 で確認したサイト。

    **Connect** をクリックします。CloudThinker に **Connecting** と **Verifying** が表示され、その後 **Connected** ステータスになります。**Verifying** では、サイトの Datadog MCP server とのセッションを開いてツールを一覧表示します。データクエリは実行しないため、スコープの不足は後でその種類の質問に対する 403 として現れます。検証に失敗した場合は **Failed** と表示され、エラーメッセージが表示されます。メッセージを[トラブルシューティング](#トラブルシューティング)と照らし合わせてください。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| **DD_API_KEY** | 組織の Datadog API キー | |
| **DD_APPLICATION_KEY** | スコープを限定した Datadog アプリケーションキー。そのスコープによって CloudThinker が読める範囲が決まります | |
| **DD_SITE** | 組織の Datadog サイト。デフォルトは **US1** | `EU1 (datadoghq.eu)` |

両方のキーが必要です。CloudThinker は呼び出しのたびに、サイトの Datadog MCP server にそれらを送信します。

## 必要な権限

Datadog MCP server は、呼び出しのたびに Datadog 自身の権限をチェックします。CloudThinker に参照させたいデータの行を選んでください。

| Scope ID | Datadog での名前 | 有効になるもの |
|----------|--------------------------|-----------------|
| `mcp_read` | `mcp_read` | Datadog MCP server のあらゆる利用。必須 |
| `monitors_read` | Monitors Read | モニターの検索とアラートのトリアージ |
| `logs_read_data`, `logs_read_index_data` | Logs Read Data, Logs Read Index Data | ログの検索 |
| `timeseries_query` | Timeseries | ログ分析、ホストメトリクス、イベント |
| `metrics_read` | Metrics | メトリクスの検索とクエリ |
| `hosts_read` | Hosts Read | ホストのインベントリ |
| `incident_read` | Incidents Read | Datadog インシデント |
| `dashboards_read`, `user_access_read` | Dashboards Read, User Access Read | ダッシュボードの検索 |
| `apm_read` | APM Read | スパンとトレース |
| `events_read` | Events | イベントの検索 |
| `notebooks_read` | Notebooks Read | ノートブックの検索 |

<Tip>
`mcp_write` とすべての `_write` スコープは付与しないでください。CloudThinker の Datadog 調査は読み取りのみです。
</Tip>

## エージェントの機能

| 機能 | CloudThinker が行うこと |
|------------|------------------------|
| **Discovery** | 状態別（OK、Alert、Warn、No Data）のモニター、ホスト、アクティブなインシデント、ダッシュボード、サービスの概要をまとめる |
| **Monitors** | 状態、名前、タグでモニターを見つけ、何がアラート中かを説明する |
| **Logs** | `service:web status:error` などの Datadog クエリ構文でログを検索・グループ化する。直近 15 分から開始します |
| **Metrics** | メトリクスを見つけ、`avg:system.cpu.user{host:web-1}` などの集計でクエリする |
| **Traces** | サービスと所要時間でスパンを検索し、トレース全体を開く |
| **Incidents** | Datadog インシデントを一覧表示し、詳細を読む |
| **Infrastructure** | ホストを、そのアプリ、ミュート状態、主要なシステムメトリクスとともに一覧表示する |
| **Services** | カタログのサービスを一覧表示し、依存関係をマッピングする |
| **Dashboards, events, notebooks** | コンテキストとして検索して読む |

接続が初めて **Connected** になると、CloudThinker は[詳細調査](/ja/guide/connections/overview#接続した後に起こること)のチャットを開き、エージェントがアカウントを探索します。

### 接続の確認

```text
Run Datadog discovery and list monitors by state, the number of hosts, and any active incidents
```

正常な回答では、OK、Alert、Warn、No Data のモニター数が示され、アラート中のモニターの名前が挙げられます。

### プロンプト例

```text
Which Datadog monitors are alerting right now, and what do the error logs for those services show in the last 15 minutes?
Find the slowest checkout spans in the last hour and walk me through one trace
Which hosts have the highest CPU right now, and do any have muted monitors?
```

## Datadog アラートを Resolve に送信する

Resolve には Datadog のプリセットが用意されているため、**Resolve → Triggers & Outcomes** でフィールドと重大度のマッピングが事前入力されます。ダイアログの詳細は [Webhook Signals](/ja/guide/incident/webhook-integrations/overview) で説明しています。以下は Datadog 固有の手順です。プリセットのないツールについては、[Connect alert sources](/guide/incident/connect-alert-sources) を参照してください。

<Steps>
  <Step title="CloudThinker で Webhook を作成する">
    **Resolve → Triggers & Outcomes** に移動し、**Datadog** を選択して、**Signals to Resolve** の下にある **Add signal** をクリックします。**Basic Info**、**Configure**、**Advanced** を順に進め、**Create** をクリックします。**Webhook URL** と **Secret Key** をコピーしてください。キーは一度しか表示されません。
  </Step>
  <Step title="マッピングをサービスに向ける">
    プリセットは `title`、`body`、`alert_type` を読み取りますが、**Service Path** のデフォルトは `tags` で、これはリストを指すため何にもマッピングされません。**Field Mapping** で **Service Path** を `service` に変更し、下のペイロードでそのキーを送信してください。[Map the fields](/ja/guide/incident/webhook-integrations/overview#フィールドをマッピングする) を参照してください。
  </Step>
  <Step title="モニターが送信する重大度の行を追加する">
    プリセットの **Severity Mapping** は `alert`、`warn`、`ok`、`no data` をカバーしていますが、Datadog の `$ALERT_TYPE` は `error`、`warning`、`info`、`success` のいずれかを送信します。**Severity Mapping** で **Customize** をクリックし、モニターが送信する値ごとに **Add Mapping** をクリックします。マッピングされていない値は **medium** になります。
  </Step>
  <Step title="Datadog で Webhook を追加する">
    Datadog で **Integrations → Webhooks** を開き、`CloudThinker` という名前の Webhook を追加します。**URL** に **Webhook URL** を貼り付け、**Custom Headers** ボックスに `{"Authorization": "Bearer <your-secret-key>"}` を入力します。ペイロードは次のようにします。

    ```json
    {
      "title": "$EVENT_TITLE",
      "body": "$EVENT_MSG",
      "alert_type": "$ALERT_TYPE",
      "service": "web-api"
    }
    ```

    固定の `service` 値は、この Webhook に通知するすべてのモニターに適用されます。シークレットは Datadog の Webhook 設定に保存されるため、そのインテグレーションを管理できる人は誰でも読めます。そのアクセスを制限し、漏洩した場合は Resolve の Webhook 行で **Regenerate credentials** を使ってください。
  </Step>
  <Step title="モニターから Webhook に通知する">
    インシデントを開くべき各モニターのメッセージに `@webhook-CloudThinker` を追加します。アラートは送信して回復は送信しないようにするには、メンションを Datadog のアラート条件で囲みます。

    ```text
    {{#is_alert}}@webhook-CloudThinker{{/is_alert}}
    ```
  </Step>
  <Step title="テストイベントを 1 件送信する">
    モニターで **Test Notifications** をクリックするか、Webhook ダイアログの **Integration Examples** にある **cURL** タブを使います。
  </Step>
</Steps>

**成功時の状態:** そのモニターからの次のアラートが、モニターのタイトル付きで [Resolve → Signals](/ja/guide/pulse/overview) に表示され、エージェントがこの接続を通じて調査します。

## トラブルシューティング

<Accordion title="Verifying の段階、またはすべての呼び出しで 401 や 403 になる">
- **DD_SITE** が組織と一致していません。Datadog のキーは自身のサイトでのみ機能するため、ステップ 1 の表を使って Datadog の URL と比較し、接続を編集してください。
- いずれかのキーが間違っている、取り消された、または別の Datadog 組織のものです。同じ組織で新しいキーを作成し、詳細パネルから接続を更新してください。
- 組織で **MCP Access** がオフになっているか、アプリケーションキーに `mcp_read` がありません。
</Accordion>

<Accordion title="一部の質問だけで 403 Forbidden になる">
アプリケーションキーに、そのデータ用のスコープ（例: トレースの場合は `apm_read`）がありません。**Organization Settings → Application Keys** でスコープを追加してください。
</Accordion>

<Accordion title="メトリクスやサービスが見つからない">
CloudThinker はクエリの前にメトリクス名とサービス名を検索します。名前に一致するメトリクスを一覧表示させ、返された正確な名前を使ってください。
</Accordion>

<Accordion title="429 Too Many Requests">
Datadog がキーをレート制限しています。より短い期間で範囲を絞った質問をするか、1 分後に再試行してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **アプリケーションキーのスコープを限定する**: スコープのないキーは、書き込みを含む作成者のすべての権限を持ちます。
- **専用キー**: CloudThinker 専用のキーを作成すれば、他のインテグレーションに影響を与えずに取り消せます。

Jenkins を接続すると、CloudThinker のエージェントはジョブの一覧表示、ビルドログとテスト結果の読み取り、ビルドが失敗した理由の説明、ワークスペースの Approvals を通じたビルドのトリガーができます。CloudThinker はサーバー上の **Jenkins MCP Server plugin** と通信し、**Jenkins のユーザー名と API トークン**でサインインします。

## 前提条件

- CloudThinker がインターネットから到達でき、プラグインをインストールできる管理者アクセスがある Jenkins サーバー。ファイアウォールの内側にあるサーバーの場合は、CloudThinker の送信元 IP を許可リストに追加してください。このドキュメントでは CloudThinker の送信元 IP 一覧を公開していません。CloudThinker の担当者に問い合わせるか、[お問い合わせ](https://cloudthinker.io/contact)ください。その他の方法は [Reaching private services](/ja/guide/connections/overview#プライベートサービスへの到達) を参照してください。
- [MCP Server plugin](https://plugins.jenkins.io/mcp-server/) がインストールされていること。このプラグインは、CloudThinker が呼び出すエンドポイントを `<your-jenkins-url>/mcp-server/mcp` に追加します。
- [必要な権限](#必要な権限)にある権限を持つ、CloudThinker 用の Jenkins ユーザー。
- CloudThinker ワークスペースでの **Admin** ロール。接続の追加と編集ができます。[Roles](/guide/security/roles) を参照してください。

## セットアップ

<Steps>
  <Step title="MCP Server plugin をインストールする">
    Jenkins で **Manage Jenkins → Plugins → Available plugins** を開き、**MCP Server** を検索してインストールし、求められたら Jenkins を再起動します。
  </Step>
  <Step title="Jenkins URL を設定する">
    **Manage Jenkins → System** を開き、**Jenkins Location** の下の **Jenkins URL** に、利用者が Jenkins にアクセスするアドレス（例: `https://jenkins.acme.com/`）を入力します。**Save** をクリックします。

    プラグインはこの値からジョブとビルドのリンクを作ります。空欄または `localhost` のままだと、エージェントに壊れたリンクが渡ります。
  </Step>
  <Step title="API トークンを作成する">
    CloudThinker 用のユーザーで Jenkins にサインインし、`<your-jenkins-url>/user/<username>/security`（古い Jenkins では `/user/<username>/configure`）を開きます。**API Token** の下で **Add new Token** をクリックします。名前を `cloudthinker` にして **Generate** をクリックし、トークンをコピーします。Jenkins はトークンを一度しか表示しません。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開きます。**Discover** タブで **Jenkins** を検索し、**Connect** をクリックして、[接続の詳細](#接続の詳細)にあるフィールドを入力します。**Connect** をクリックします。

    CloudThinker は、ユーザー名とトークンで MCP エンドポイントを呼び出して接続をテストします。URL の誤り、拒否されたトークン、プラグインの未導入の場合は、**Connected** ではなくエラーが表示されます。

    **成功状態:** **Connected** タブで Jenkins に **Connected** と表示されます。
  </Step>
</Steps>

<Note>
テストではユーザーのジョブ権限は確認しません。下の確認用プロンプトを実行し、エージェントがジョブを見られることを確かめてください。
</Note>

## 接続の詳細

ダイアログには、次の名前のとおりにフィールドが表示されます。

| フィールド | 説明 | 例 |
|-------|-------------|---------|
| `JENKINS_URL` | Jenkins サーバーのベース URL。`/mcp-server/mcp` は含めません。このパスは CloudThinker が追加します | `https://jenkins.acme.com` |
| `JENKINS_USER` | トークンが属する Jenkins のユーザー名 | `cloudthinker` |
| `JENKINS_API_TOKEN` | そのユーザーのために生成した API トークン | `<your-api-token>` |

スキームを省略すると、CloudThinker は `https://` を使います。公開アドレスでは、`http://` と入力しても CloudThinker は常に HTTPS で接続するため、サーバーにはそのアドレスで有効な TLS 証明書が必要です。

## 必要な権限

Jenkins の認可方式（例: **Manage Jenkins → Security** の **Matrix-based security**）で、CloudThinker 用のユーザーに次の権限を付与します。

| 権限 | 用途 |
|------------|------------|
| **Overall / Read** | サインインとジョブの一覧表示 |
| **Job / Read** | ビルド、ログ、テスト結果、変更の読み取り |
| **Job / Discover** | フォルダーやビュー内のジョブの表示 |
| **View / Read** | ビューの読み取り |
| **Job / Build** | 任意: ビルドのトリガー |

トークンはこのユーザーの権限そのままで動作します。読み取り専用の接続にするには **Job / Build** を付与しないでください。ユーザーに **Overall / Administer** は不要で、Jenkins の認証情報やシークレットを読むエージェントツールはありません。

<Tip>
管理者アカウントではなく、CloudThinker 専用の Jenkins ユーザーを使ってください。フォルダー単位の権限を使っている場合は、エージェントに見せるフォルダーだけにアクセスを付与してください。
</Tip>

## エージェントの機能

読み取りは確認なしで実行されます。ビルドのトリガーは書き込みなので、まず Approvals を通ります。

<ApprovalDefault />

| 機能 | エージェントができること |
|------------|--------------------|
| **Jobs** | ジョブを一覧表示し、それぞれの最後のビルド状態を示します |
| **Build logs** | ビルドログを読んで検索し、失敗したステップを見つけます |
| **Test results** | テスト結果を読み、失敗したテストを指摘します |
| **Changes** | ビルドに含まれたコミットと SCM の変更を示します |
| **Trigger builds** | Rules と Approval mode に従ってビルドを開始します。エージェントは、依頼内容から取ったビルドパラメーターを渡せます |

### 接続を確認する

```text
List the Jenkins jobs you can reach and the result of the last build for each
```

接続が正常なら、実際のジョブ名と結果が返ります。一覧が空の場合は、たいていユーザーに **Job / Read** または **Job / Discover** がありません。

### プロンプト例

```text
Why did the last build of payments-api fail? Show the failing step and the error from the log
Which tests failed in the last 5 builds of the main pipeline, and are any of them flaky?
Which commits went into the latest build of web-frontend?
```

## トラブルシューティング

<Accordion title="This connection did not respond in time. Try connecting again.">
CloudThinker が Jenkins サーバーに到達できません。URL がネットワークの外から開けること、そしてファイアウォールが CloudThinker の送信元 IP からの HTTPS 受信を許可していることを確認してください。`localhost` や、ネットワーク内でしか解決できないアドレスは使わないでください。
</Accordion>

<Accordion title="The provider rejected these credentials. Update them, then connect again.">
ユーザー名またはトークンが誤っているか、トークンが取り消されています。`JENKINS_USER` がトークンを生成したユーザーであることを確認し、必要なら新しいトークンを生成してください。置き換えるには、**Settings → Workspace → Connections** で **Jenkins** を選択し、鉛筆アイコンをクリックし、**Credentials** の下の **Replace…** をクリックして、**Save and test** をクリックします。
</Accordion>

<Accordion title="The provider endpoint was not found. Check the connection settings.">
MCP Server plugin がインストールまたは有効化されていないか、`JENKINS_URL` が誤ったパスを指しています。プラグインをインストールし、ベース URL だけを入力してください。Jenkins が `/jenkins` などのパスで動いている場合は、それを含めます: `https://ci.acme.com/jenkins`。
</Accordion>

<Accordion title="ジョブの一覧が空、またはリンクが壊れている">
ユーザーに **Job / Read** または **Job / Discover** がないか、**Jenkins URL** が空欄または `localhost` になっています。権限を修正し、**Manage Jenkins → System** で **Jenkins URL** を設定してから、もう一度質問してください。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **ネットワークへの露出を制限してください。** Jenkins への受信トラフィックは必要な送信元からだけ許可し、Jenkins の UI は通常のアクセス制御の内側に置いてください。
- **ビルドは承認制にしてください。** エージェントにビルドを開始させる場合にのみ **Job / Build** を付与し、CloudThinker が開始するすべてのビルドを人が確認すべき場合は **Manual** を選んでください。

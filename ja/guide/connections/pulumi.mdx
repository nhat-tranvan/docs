Pulumi Cloud を接続すると、[CloudThinker](/ja/guide/agents/overview) がスタックを一覧表示し、Pulumi が管理するリソースを見つけ、ポリシー違反をトリアージできるようになります。サインインには Pulumi の OAuth フローを使うため、Pulumi のアクセストークンを CloudThinker に貼り付けることはありません。

## 前提条件

- スタックを持つ組織に属する Pulumi Cloud アカウント。
- CloudThinker ワークスペースの **Admin** ロール。接続を追加、編集、削除できるのはワークスペースの Admin だけです。[Roles](/guide/security/roles) を参照してください。

<Info>
プロンプトでそのアカウントが属する別の組織を指定しない限り、CloudThinker は認可したアカウントのデフォルトの Pulumi 組織を使います。
</Info>

## セットアップ

<Steps>
  <Step title="Pulumi の接続を開く">
    **Settings → Workspace → Connections** を開き、**Pulumi** を選んで **Connect** をクリックします。Pulumi の認可ページがポップアップで開きます。
  </Step>
  <Step title="サインインして認可する">
    スタックを閲覧できる Pulumi アカウントでサインインし、アクセスを承認します。
  </Step>
  <Step title="CloudThinker に戻る">
    Pulumi から CloudThinker に戻り、CloudThinker が OAuth トークンを保存します。

    **成功時の状態:** Pulumi の接続に **Connected** のステータスが表示されます。
  </Step>
</Steps>

入力するフィールドはありません。Pulumi が認可時に OAuth トークンを発行し、エンドポイントは `mcp.ai.pulumi.com` に固定されています。

## 必要な権限

CloudThinker は、認可したアカウントと同じ Pulumi のアクセス権を得ます。組織への読み取りアクセスで、下記のすべての読み取り機能をカバーできます。

AWS へのデプロイと Neo のタスクもそのアカウントとして実行されるため、そのアカウントが Pulumi で同じことを許可されている場合にのみ機能します。読み取り専用のアカウントでは、Pulumi がそれらを拒否します。

<Tip>
CloudThinker を通じてデプロイする予定がない限り、組織を読み取れるが管理はしないアカウントで認可してください。
</Tip>

## エージェントの機能

| 機能 | CloudThinker が行うこと | Approvals による確認 |
|------------|------------------------|----------|
| **Stack inventory** | スタックを、プロジェクトと最終更新とともに一覧表示します | いいえ |
| **Resource search** | Pulumi が管理するリソースを、名前、種類、プロジェクト、スタックで見つけます | いいえ |
| **Policy review** | ポリシー違反を、強制レベル別に、該当するスタックとともに一覧表示します | いいえ |
| **Registry lookup** | Pulumi Registry からプロバイダーのリソースと関数のスキーマを読みます | いいえ |
| **Organization members** | 組織のメンバーを一覧表示します | いいえ |
| **Pulumi Neo history** | 過去の Pulumi Neo のタスクを読みます | いいえ |
| **Deploy to AWS** | AWS にリソースをプロビジョニングします | はい |
| **Drive Pulumi Neo** | Neo のタスクを開始・続行するか、Neo の会話をリセットします | はい |

Pulumi Neo は Pulumi 独自の AI エージェントです。Neo のタスクはインフラをデプロイしたりリポジトリを変更したりできるため、開始や続行は Approvals を経由します。

スタックは組織、プロジェクト、スタック名の組み合わせで識別されるため、CloudThinker はその 3 つすべてを報告します。スタックの出力、設定値、シークレットは表示しません。

### 接続を確認する

```text
List my Pulumi stacks with their project and organization
```

スタックの表が返されることを確認します。結果が空の場合、接続が壊れているのではなく、認可したアカウントのデフォルトの組織にスタックがないことを意味します。

### プロンプトの例

```text
Which Pulumi stacks have mandatory policy violations, and which policies fail most often?
Find every S3 bucket Pulumi manages and name the stack that owns each one
Read the aws:s3/bucket schema from the Pulumi Registry and list its required inputs
```

## 書き込みアクセス

実際の状態を変更するツールは 4 つです。AWS へのデプロイと、Pulumi Neo を操作する 3 つのツールです。各呼び出しはそれぞれ単独で Approvals を経由し、1 つの呼び出しを承認しても次の呼び出しは承認されません。

<ApprovalDefault />

人が承認する場合、CloudThinker はまず組織、スタック、効果を示します。呼び出しを却下すると、CloudThinker はそれを再試行しません。気が変わった場合は、新しいメッセージでもう一度依頼してください。承認対象のツールの仕組みは [Approvals](/guide/approvals/overview) を参照してください。

<Warning>
デプロイは、そのスタックに心当たりがある場合にのみ承認してください。Pulumi のデプロイは実際のリソースを作成し、クラウドアカウントに課金されます。
</Warning>

CloudThinker は、レビュー済みの Pulumi のツールの一覧を公開します。Pulumi が後から追加したツールは、レビューされ、読み取りまたは書き込みとしてマークされるまで非表示のままです。

## トラブルシューティング

<Accordion title="OAuth フローが完了しない">
- **何も開かない:** ブラウザがポップアップをブロックしました。CloudThinker のポップアップを許可してから、もう一度 **Connect** をクリックしてください。
- **アカウントが違う:** ブラウザが別の Pulumi アカウントにサインインしています。app.pulumi.com で正しいアカウントにサインインしてから、もう一度 **Connect** をクリックしてください。
- **アクセスを拒否した:** もう一度 **Connect** をクリックし、Pulumi のページで承認してください。
</Accordion>

<Accordion title="CloudThinker がスタックがないと報告する">
プロンプトでそのアカウントが属する別の組織を指定しない限り、CloudThinker は認可したアカウントのデフォルトの Pulumi 組織を使います。スタックを持つ組織を指定してください。アカウントがメンバーでない場合は、メンバーであるアカウントで再接続してください。
</Accordion>

<Accordion title="CloudThinker が組織に到達できないと言う">
接続が到達できるのは、認可した Pulumi ユーザーが属する組織だけです。Pulumi でユーザーを組織に追加するか、切断してすでにその組織に属しているアカウントで認可してください。
</Accordion>

<Accordion title="デプロイで確認が繰り返し求められる">
それは Approvals で、各呼び出しをそれぞれ確認します。続行するには、会話でプロンプトに回答してください。信頼できるスタックで確認を求められないようにするには、**Allow** の [Rule](/guide/approvals/rules) でそれらの呼び出しを実行させられます。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **承認のゲートはオンのままにする。** AWS へのデプロイと Pulumi Neo のツールは、この接続でクラウドやリポジトリを変更できる唯一のツールです。
- **アカウントは意図して切り替える。** 接続は、認可したアカウントが到達できる範囲に到達します。アカウントを変更するには、**Settings → Workspace → Connections** を開き、**Pulumi** を選んで、詳細パネルの **Disconnect** をクリックしてから、別のアカウントで再度接続します。

Cloudflare を接続すると、CloudThinker がアカウントとゾーンを一覧表示し、HTTP トラフィックとキャッシュの挙動をまとめ、ファイアウォールイベントを確認し、Cloudflare のドキュメントを調べられるようになります。CloudThinker は Cloudflare がホストする MCP サーバーを使い、1 つの **API token** で認証します。そのトークンの権限によって CloudThinker がアクセスできる範囲が決まります。

## 前提条件

- 少なくとも 1 つのゾーンを持つ Cloudflare アカウント。
- [Cloudflare ダッシュボード](https://dash.cloudflare.com/)で API トークンを作成する権限。

## セットアップ

<Steps>
  <Step title="カスタム API トークンを作成する">
    Cloudflare ダッシュボードで **My Profile → API Tokens → Create Token** に移動します。**Create Custom Token** の下にある **Get started** をクリックします。[必要な権限](#必要な権限)の表にある各権限を追加します。Cloudflare のフォームの各行には 3 つのドロップダウンがあるため、**Zone → Analytics → Read** はグループ **Zone**、権限 **Analytics**、アクセス **Read** を意味します。
  </Step>
  <Step title="トークンを必要なアカウントとゾーンに限定する">
    **Account Resources** で **Include → your account** を選びます。**Zone Resources** では、CloudThinker に参照させる各ゾーンについて **Include → Specific zone** を選びます。CloudThinker にすべてのゾーンをカバーさせたい場合にのみ **All zones** を使ってください。
  </Step>
  <Step title="有効期限を設定し、トークンを作成してコピーする">
    **TTL** で終了日（例: 今日から 90 日後）を設定します。**Client IP Address Filtering** は空のままにしてください。API 呼び出しは、お客様が管理するアドレスからではなく、Cloudflare がホストする MCP サーバーを経由して Cloudflare に届きます。**Continue to summary → Create Token** をクリックします。今すぐトークンをコピーしてください。Cloudflare は一度しか表示しません。

    <Note>
    既知の IP アドレスに制限したトークンが必要ですか？IP ホワイトリストのサポートは Enterprise で利用できます。[support@cloudthinker.io](mailto:support@cloudthinker.io) までお問い合わせください。
    </Note>

    貼り付ける前にトークンを確認するには、次を実行します。

    ```bash
    curl -H "Authorization: Bearer <token>" https://api.cloudflare.com/client/v4/user/tokens/verify
    ```

    **成功時の状態:** レスポンスに `"status": "active"` が含まれます。
  </Step>
  <Step title="CloudThinker で接続を追加する">
    **Settings → Workspace → Connections** を開き、**Cloudflare** を選択して **Connect** をクリックします。**Alias**（例: `main-account`）と **Description**（例: `Main Cloudflare account, production zones`）を入力します。接続が複数ある場合、エージェントは説明を読んで正しい接続を選びます。**Cloudflare API token** にトークンを貼り付け、**Connect** をクリックします。

    **成功時の状態:** 接続に **Connecting** と **Verifying** が表示され、その後 **Connected** ステータスになります。続いて CloudThinker が[詳細調査](/ja/guide/connections/overview#接続した後に起こること)のチャットを開き、エージェントがアカウントを探索します。
  </Step>
  <Step title="環境を設定する">
    **Settings → Workspace → Connections** で **Cloudflare** を開き、接続の行の鉛筆アイコンをクリックして、**Edit Instance** で **Environment** を設定します。これは人とエージェントのための接続のラベルになります。
  </Step>
</Steps>

## 接続の詳細

| フィールド | 入力内容 |
|-------|---------------|
| **Alias** | この接続の短い名前。空欄の場合は自動で決まります。 |
| **Description** | アカウントがカバーする範囲。エージェントは接続を選ぶ際にこれを使います。 |
| **Cloudflare API token** | 作成した API トークン。CloudThinker は CloudThinker Cloud から直接、Cloudflare がホストする MCP サーバー `https://mcp.cloudflare.com/mcp` に Bearer トークンとして送信します。 |

データの経路は CloudThinker Cloud → Cloudflare の[ホスト型 MCP サーバー](https://github.com/cloudflare/mcp-server-cloudflare) → Cloudflare API です。そのため、トークンと API レスポンスは Cloudflare 自身のサービスを通過します。

アカウント ID を入力する必要はありません。CloudThinker がトークンで参照できるアカウントとゾーンを見つけます。トークンが複数のゾーンをカバーしていて、リクエストが複数のゾーンに一致する場合、CloudThinker はどのゾーンを指しているか尋ねます。Cloudflare 接続は複数追加できます（例: アカウントごとに 1 つのトークン）。

## 必要な権限

各権限は Cloudflare のフォームに表示されるとおり、グループ → 権限 → アクセスの形式で記載しています。

| 権限 | 有効になるもの | 必要 |
|---|---|---|
| **Account → Account Settings → Read** | アカウントの一覧表示 | はい |
| **Account → Account Analytics → Read** | アカウントレベルの分析 | はい |
| **Zone → Zone → Read** | ゾーンの一覧表示とゾーン設定の読み取り | はい |
| **Zone → DNS → Read** | DNS レコードの読み取り | はい |
| **Zone → Analytics → Read** | トラフィック分析とファイアウォールイベント | はい |
| **Account → Workers Scripts → Read** | Workers の確認 | Workers を確認する場合のみ |

CloudThinker がアクセスできるのは、トークンが許可する範囲だけです。

<Tip>
トークンは読み取り専用にし、特定のゾーンに限定してください。書き込み操作の固定リストはありません。**execute** は任意の Cloudflare API エンドポイントを呼び出せるため、**Zone → DNS → Edit** など、トークンに追加した編集権限はすべてエージェントが提案できる変更になります。各呼び出しは引き続き承認を経由します。
</Tip>

## エージェントの機能

この接続には 3 つのツールがあります。2 つは自由に実行されます。3 つ目は Cloudflare API を呼び出すもので、同じツールで変更も行えるため、読み取りであっても常に [Approvals](/guide/approvals/overview) を経由します。

| ツール | CloudThinker が行うこと | 承認 |
|------|------------------------|----------|
| **docs** | Cloudflare のドキュメントを検索する | 不要 |
| **search** | リクエストに適した Cloudflare API エンドポイントを見つける | 不要 |
| **execute** | Cloudflare API を呼び出す: アカウントとゾーンの一覧表示、ゾーン設定と DNS レコードの読み取り、GraphQL 分析の実行、ファイアウォールイベントの読み取り、Workers の確認 | 必要 |

<ApprovalDefault />

**execute** を呼び出すオートメーションは独自の Approval mode（デフォルトは **Refuse**）を使うため、確認が必要になる呼び出しは代わりに拒否されます。

組み込みのクエリ制限により結果は小さく保たれます。トラフィックのサマリーは 1 つのゾーンについて最大 7 日分の時間単位データ、ファイアウォールの確認は最大 24 時間分と 50 件のサンプルイベントが対象です。ファイアウォールの出力にはクライアントの IP アドレスは含まれません。

### 接続の確認

```text
List the Cloudflare accounts and zones this token can see
```

回答は **execute** ツールから得られるため、先に承認を経由します。CloudThinker がチャットに承認リクエストを投稿した場合は、承認してください。回答には実際のアカウント名とゾーン名が表示されます。

### プロンプト例

```text
Summarize HTTP requests, bandwidth, and cache behavior for example.com over the last 7 days
Show which firewall rules blocked or challenged requests on example.com in the last 24 hours
How do I set up a WAF custom rule to rate limit a login path? Use the Cloudflare docs
```

## トラブルシューティング

<Accordion title="権限が拒否される">
CloudThinker が `CLOUDFLARE_PERMISSION_DENIED` を報告します。質問した内容に必要な読み取り権限がトークンにありません。**My Profile → API Tokens** でトークンを編集して権限を追加し、もう一度質問してください。
</Accordion>

<Accordion title="ゾーンが見つからない">
`CLOUDFLARE_NO_ZONES` は、トークンでゾーンが 1 つも表示されないことを意味します。`CLOUDFLARE_ZONE_NOT_FOUND` は、指定したゾーンがトークンから見えないことを意味します。トークンの **Zone Resources** を確認し、正確なゾーン名を使ってください。
</Accordion>

<Accordion title="質問しても何も起こらない">
すべての Cloudflare API 呼び出しは承認を経由し、一部は人の判断を待ちます。チャットに保留中の承認リクエストがないか確認するか、[Approval mode](/guide/approvals/approval-mode) を見直してください。リクエストを却下した場合、CloudThinker は再試行しません。
</Accordion>

<Accordion title="分析が空で返ってくる">
新しいゾーンやトラフィックの少ないゾーンには、まだ分析データがない場合があります。ゾーンが Cloudflare 経由でトラフィックを受けていること、トークンに **Zone → Analytics → Read** があることを確認してください。
</Accordion>

<Accordion title="旧仕様: 古い接続に「Cloudflare moved to Cloudflare's hosted endpoint」と表示される">
新しい接続ではこの問題は起きません。Cloudflare のホスト型 MCP サーバーへの移行前に作成された接続には、このメッセージとともに **Error** が表示され、CloudThinker が自動で再接続します。ステータスが変わらない場合は、接続を開いて **Retry** をクリックしてください。古い Account ID と Enabled Services の値は使われなくなりました。
</Accordion>

## セキュリティ

<ConnectionSecurity />

- **ゾーンを制限する**: 影響範囲を小さくするため、トークンはすべてのゾーンではなく特定のゾーンに限定してください。
- **TTL が切れる前にローテーションする**: 作成時に設定した **TTL** の終了日より前に[トークンをローテーション](/ja/guide/connections/overview#認証情報をローテーションする)してください。

各ワークスペースへのアクセス権を持つメンバーとその権限を管理します。ワークスペースメンバーは、特定のワークスペースへのアクセス権が付与されたorganizationメンバーです。

## 概要

ワークスペースメンバー管理では以下ができます:

- **アクセスの制御** — どのorganizationメンバーがワークスペースを表示・使用できるかを決定する
- **ワークスペースロールの割り当て** — organizationロールとは異なるワークスペース固有のロールを設定する
- **メンバーシップの監視** — ワークスペースごとのメンバー数とクォータ使用量を表示する

<Info>
メンバーをワークスペースに追加する前に、まずorganizationに所属している必要があります。誰かをorganizationに招待するには、**Admin Settings > Organization** に移動してください。
</Info>

---

## ワークスペースへのメンバー追加

ワークスペースアクセスを付与する方法は2つあります:

### ワークスペースから

1. 管理したいワークスペースを開く
2. Membersセクションで **Add Member** をクリック
3. ドロップダウンからorganizationメンバーを選択（DeveloperとViewerのみ表示 — OwnerとAdminはすでに暗黙的なアクセス権を持つ）
4. ワークスペースロールを選択（organizationロールに基づいて事前入力される）

### Admin Settingsから

1. **Admin Settings > Organization** に移動
2. Membersセクションでメンバーを見つける
3. 名前の横のグリッドアイコンをクリックしてワークスペースアクセス設定を開く
4. 各ワークスペースのアクセスをトグルし、ワークスペースごとにロールを設定

<Info>
OrganizationのOwnerとAdminはすべてのワークスペースに自動的にアクセスできます — 手動で追加する必要はありません。
</Info>

---

## ワークスペースロール

各メンバーはそのワークスペースのorganizationロールをオーバーライドするワークスペース固有のロールを持てます。これにより、例えばorganizationレベルでViewerのメンバーに、特定のワークスペースでDeveloperアクセスを付与することができます。

| ロール | 権限 |
|------|-------------|
| **Admin** | ワークスペースメンバーの管理、エージェントと接続の設定、ナレッジベースの管理、オペレーションの実行 |
| **Developer** | エージェントの使用、オペレーションの実行、接続とナレッジベースへのアクセス |
| **Viewer** | ワークスペースリソースの表示（読み取り専用） |

**Admin Settings > Organization**（グリッドアイコン経由）からワークスペースアクセスを管理する場合、ワークスペースごとに以下を選択できます:
- **Inherit from Org** — organizationロールを使用
- **Admin / Developer / Viewer** — ワークスペース固有のロールでオーバーライド

## ワークスペースメンバーの管理

ワークスペースメンバーテーブルには以下が表示されます:

| カラム | 説明 |
|--------|-------------|
| **Member** | アバター、表示名、メールアドレス |
| **Organization Role** | organizationレベルでのメンバーのロール |
| **Workspace Role** | この特定のワークスペースでのメンバーのロール（編集可能） |
| **Actions** | ワークスペースからメンバーを削除 |

### メンバーのロールを変更する

メンバーの横のワークスペースロールドロップダウンをクリックしてロールを変更します。ロールを変更できるのはワークスペースadminとorganization admin/ownerのみです。暗黙的なメンバー（OrganizationのOwnerとAdmin）のワークスペースロールは変更できません。

### メンバーを削除する

ワークスペースからメンバーを削除してアクセス権を取り消します。organizationからは削除されないため、後で再度追加できます。

<Warning>
organizationからメンバーを削除する場合（**Admin Settings > Organization** 経由）、そのメンバーはすべてのワークスペースから自動的に削除されます。
</Warning>

## プロビジョニングとSSO

organizationがJITまたはSCIMプロビジョニングでSSOを使用している場合、新しいメンバーはプロビジョニング設定で構成された**デフォルトワークスペース**に自動的に追加されます。詳細は [SSOのセットアップ](/ja/guide/security/sso) を参照してください。

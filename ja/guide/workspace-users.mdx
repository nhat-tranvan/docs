ワークスペースメンバーとは、[組織](/ja/guide/organization)のメンバーのうち、特定の[ワークスペース](/ja/guide/workspaces)を開ける人のことです。各メンバーにはワークスペースロール（Admin、Developer、Viewer）があり、そのワークスペースで何ができるかを決めます。

## ワークスペースへのアクセスの仕組み

ワークスペースに追加する前に、その人が組織に所属している必要があります。組織ロールによって、デフォルトのアクセスが決まります。

| 組織ロール | ワークスペースへのアクセス | ワークスペースごとに変更できるか |
|---|---|---|
| **Owner** | すべてのワークスペースで自動的に Admin | いいえ |
| **Admin** | すべてのワークスペースで自動的に Admin | いいえ |
| **Developer** | 追加されたワークスペースのみ。デフォルトは Developer | はい |
| **Viewer** | 追加されたワークスペースのみ。デフォルトは Viewer | はい |

ワークスペースごとのロールをロールオーバーライドと呼びます。1つのサンドボックス用ワークスペースで Viewer に作業を実行させたい場合や、組織全体の管理権限を与えずに Developer をチームのワークスペースの Admin にしたい場合に使います。

<Warning>
ワークスペースの Admin は、接続と認証情報の追加・編集・削除、および承認の管理ができます。本番環境に接続されたワークスペースでは、付与を最小限にしてください。
</Warning>

## 前提条件

- あなたがワークスペースの **Admin** であること（組織の Owner と Admin は常に Admin です）。
- 対象者が組織に所属しているか、そのメールアドレスが分かっていること。メールアドレスを入力すると招待が送信されます。組織だけに招待する場合は、[メンバーを招待する](/ja/guide/organization#メンバーを招待する)を参照してください。

## ワークスペースからメンバーを追加する

<Steps>
  <Step title="Members を開く">
    **Settings → Workspace → Members** に移動します。Settings を開くには、サイドバー上部のワークスペースメニューをクリックし、**Settings** をクリックします。ページのタイトルは **Members and roles** です。
  </Step>
  <Step title="Invite people をクリックする">
    検索フィールド **Search by name, or enter an email** が開きます。組織内のメンバーを選ぶか、まだ組織にいない人のメールアドレスを入力します。
  </Step>
  <Step title="ロールを選ぶ">
    フィールドの横にある **Role** メニューでワークスペースロールを選びます。一度に追加したメンバーは全員そのロールで参加します。一部の人に別のロールを与えるには、追加した後で各メンバーの行でロールを変更します。
  </Step>
  <Step title="追加する">
    **Add** をクリックします。メールアドレスだけを入力した場合はボタンが **Invite**、両方を入力した場合は **Add and invite** になります。

    **成功状態：** 各メンバーがワークスペースロールとともに一覧に表示されます。招待したメールアドレスは、相手が承諾するまで保留中の招待として表示されます。
  </Step>
</Steps>

## 複数のワークスペースのアクセスをまとめて設定する

1人のメンバーが複数のワークスペースへのアクセスを必要とする場合に使います。組織の **Owner** または **Admin** である必要があります。オーバーライドによってワークスペースの Admin になっている人は、この画面を開けません。

<Steps>
  <Step title="メンバーを探す">
    **Settings → Organization → Members** に移動し、そのメンバーの行を見つけます。
  </Step>
  <Step title="ワークスペースへのアクセスを開く">
    行のアクションメニュー（**...**）を開き、**Edit workspace access** をクリックします。このオプションは Developer と Viewer にのみ表示されます。**Manage Workspace Access** ダイアログが開きます。
  </Step>
  <Step title="ワークスペースとロールを選ぶ">
    開けるようにするワークスペースにチェックを入れます。それぞれについて、**Inherit from Org** のままにするか、**Admin**、**Developer**、**Viewer** のいずれかを選びます。
  </Step>
  <Step title="保存する">
    **Save Changes** をクリックします。

    **成功状態：** 次にそのメンバーがワークスペースメニューを開くと、それらのワークスペースが表示されます。
  </Step>
</Steps>

## ワークスペースロール

Viewer は読み取り専用です。会話、検出結果、ダッシュボードを開けますが、チャットメッセージの送信や[スキル](/guide/commands#run-a-skill)の実行はできません。Viewer が行える唯一の変更は、[Skills Hub](/ja/guide/skills/overview) のスキルをワークスペースにインストールすることです。Developer は日々の作業を行います。Admin はそれに加えてワークスペースを設定します。

| 領域 | Viewer | Developer | Admin |
|---|---|---|---|
| チャット | 会話を閲覧 | 会話でのチャット、名前の変更、スター付け | 会話の削除も可能 |
| ダッシュボードとアーティファクト | 閲覧 | 作成と編集 | 作成と編集 |
| Optimize | 閲覧 | スキャンの実行、検出結果の移動・編集・割り当て | Developer と同じ。加えて検出結果を expected、snoozed、disputed に設定 |
| Review | 閲覧 | 検出結果の解決とマージ | リポジトリのセットアップと削除も可能 |
| Cyber | 閲覧 | テストの作成、編集、実行 | 削除も可能 |
| Resolve | 閲覧 | 閲覧のみ* | インシデントの編集と削除 |
| エージェントと自動化 | 閲覧 | カスタムエージェントの作成と編集。自動化の作成と編集は不可 | 自動化の作成、編集、削除も可能 |
| 接続 | 閲覧 | 閲覧 | 追加、編集、削除 |
| 認証情報 | ページに "Ask a workspace admin for edit access to view and manage stored credentials." と表示され、保存済みの認証情報は非表示 | Viewer と同じ | 閲覧、追加、編集、削除 |
| Autonomy（Rules、Approvers、Runbooks）、通知、Webhook | 閲覧 | 閲覧 | 管理 |
| ワークスペース設定、[capabilities](/guide/capabilities)、ブランディング、メンバー、BYOK | BYOK（非表示）を除くすべてのページを閲覧。認証情報はロックされたまま | BYOK（非表示）を除くすべてのページを閲覧。認証情報はロックされたまま | 管理 |

\*Developer は Resolve のインシデントを変更できません。オンコールのエンジニアに1つのワークスペースでインシデントを扱わせるには、そのワークスペースで Admin にしてください。

エージェントのアクションを誰が承認できるかは別に設定します。[approvers](/guide/approvals/approvers) を参照してください。

ワークスペースロールより上位にある管理機能もあります。**Settings → Organization**、[使用量](/ja/guide/billing/usage)、[監査ログ](/guide/security/audit-logs)は、組織の Owner と Admin のためのものです。例外は 2 つあります。ワークスペースの Admin は **Organization** タブを開けませんが、直接リンクから [Guardrails](/guide/security/custom-guardrails) と [BYOK](/ja/guide/byok) を開けます。[請求](/ja/guide/billing/subscription)と組織全体の BYOK キーは Owner だけが変更できます。

## ロールを変更する、またはメンバーを削除する

**Settings → Workspace → Members** を開きます。各行には、メンバー、メールアドレス、ワークスペースロールが表示されます。組織ロールに由来するロールの場合は、**Organization admin** のようにそれが表示されます。

| 作業 | 方法 |
|---|---|
| ロールを変更する | 行のロールメニューで新しい値を選びます |
| メンバーを削除する | 行のアクションメニュー（**...**）を開き、**Remove** をクリックして確定します |

組織の Owner と Admin のアクセスは組織に由来するため、固定のロールが表示され、削除のオプションはありません。ワークスペースから削除しても組織には残るため、後で再び追加できます。

そのメンバーがこのワークスペースで所有している [Automations](/guide/automation/automations) はオフになります。ワークスペースの Admin がそれぞれで **Take ownership** をクリックし、再びオンにします。すべてのワークスペースから一度に削除するには、**Settings → Organization → Members** で組織から削除してください。

## SSO でメンバーを自動的に追加する

これらのプロビジョニング設定を変更するには、組織の **Owner** である必要があります。

ジャストインタイムプロビジョニングまたは [SCIM](/ja/guide/security/scim) で SSO を使っている場合、新しいメンバーは作成されるとすぐにワークスペースに参加できます。**Settings → Organization → Identity** に移動し、**Provisioning** の **Auto-assigned workspaces** を設定します。新しいメンバーは **Auto-assigned organization role**（デフォルトは Viewer）でそれらのワークスペースに参加します。[SSO](/ja/guide/security/sso#ユーザーのプロビジョニング方法を選ぶ) と [SCIM のグループマッピング](/ja/guide/security/scim#グループをワークスペースに対応付ける)を参照してください。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="Invite people の検索に追加したい人が表示されない">
    **原因：** その人がまだ組織にいない、すでにこのワークスペースにいる、または組織の Owner か Admin である（すでにアクセス権を持っている）ためです。

    **対処：** まずメンバー一覧を確認してください。新しい人を追加するには、代わりにメールアドレスを入力します。組織にいない場合は、[招待してください](/ja/guide/organization#メンバーを招待する)。
  </Accordion>
  <Accordion title="メンバーのワークスペースロールを変更できない">
    **原因：** その人が組織の Owner か Admin であるか、あなたがワークスペースの Admin ではないためです。

    **対処：** **Settings → Organization → Members** でその人の組織ロールを変更するか、ワークスペースの Admin に依頼してください。
  </Accordion>
  <Accordion title="Viewer がチャットに入力できない">
    **原因：** Viewer は読み取り専用で、チャットメッセージを送信できません。

    **対処：** このワークスペースでのワークスペースロールを **Developer** に変更するか、すべてのワークスペースに適用するには **Settings → Organization → Members** で組織ロールを変更してください。
  </Accordion>
  <Accordion title="Invite people が表示されない">
    **原因：** あなたがワークスペースの Admin ではないためです。

    **対処：** このワークスペースの Admin、または組織の Owner か Admin に、メンバーの追加を依頼してください。
  </Accordion>
</AccordionGroup>

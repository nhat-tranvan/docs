CloudThinker はエージェントの作業をクレジットで計測します。チャットメッセージ、Review、Resolve、Optimize、Cyber の実行、オートメーションはすべて、組織の残高からクレジットを消費します。このページでは、クレジットの出所、実行コストが増える要因、そして **Usage** ページの読み方を説明し、誰が何にクレジットを使っているかを把握できるようにします。

## クレジットの種類

組織は最大 3 種類のクレジットと、任意の従量制の超過分を持てます。

| クレジットの種類 | 出所 | 支払える対象 | リセット |
|---|---|---|---|
| **Daily** | 組織全体で共有する 1 日 100 の無料クレジット（Enterprise: 契約で設定） | **Light** モデルでのチャットのみ | 毎日 00:00 UTC。未使用分は繰り越されません。 |
| **Bonus** | 紹介やプロモーション | プランに含まれるモデルと機能 | 期限なし |
| **Premium** | 組織の月間プラン割り当て（[料金](/ja/guide/billing/pricing)を参照） | プランに含まれるモデルと機能 | 請求サイクルごと |
| **Pay-As-You-Go** | 含まれるクレジットを超えた任意の従量課金。[料金](#pay-as-you-go)を参照 | プランに含まれるモデルと機能 | 月間上限はサイクルごとにリセット |

Premium クレジットは組織全体で 1 つのプールです。すべてのワークスペースがここから消費するため、1 つの忙しいワークスペースがほとんどを使ってしまうことがあります。これを防ぐには、ワークスペースごとに[クレジット上限](/guide/billing/credit-limits)を設定してください。

<Info>
  以前の年間サブスクリプションでは、Premium クレジットは請求の記念日に毎月補充されます。1 年分のクレジットが一度に付与されるわけではありません。
</Info>

利用できる機能はプランによって異なります。[料金](/ja/guide/billing/pricing)を参照してください。

## 実行が使うクレジット

CloudThinker は次の順序でクレジットを消費し、現在のプールが空になるか、その実行を支払えない場合にのみ次のプールに移ります。

<Steps>
  <Step title="Daily クレジット">
    最初に使われますが、Light モデルでのチャットに限られます。
  </Step>
  <Step title="Bonus クレジット">
    次に使われます。すべてのモデルと機能に使えます。
  </Step>
  <Step title="Premium クレジット">
    プランの月間プールです。すべてのモデルと機能に使えます。
  </Step>
  <Step title="Pay-As-You-Go">
    [Pay-As-You-Go](#pay-as-you-go) がオンの場合に限り、1 クレジットあたり $0.10 で課金されます。
  </Step>
</Steps>

**例:** Team のメンバーが Light でチャットに簡単な質問をします。この実行は Daily クレジットを使います。同じメンバーが次に Pro で Review の実行を開始します。Daily クレジットでは支払えないため、Bonus クレジットがあればそれを使い、次に Premium クレジットを使います。

## 実行コストが増える要因

実行の料金は、その間にモデルが読み書きしたトークン数に、モデルティアの倍率を掛けたものです。実行ごとの固定料金はないため、同じ種類の実行でも金額が大きく異なることがあります。コストを押し上げる要因は次のとおりです。

- **ツール呼び出しとその出力。** エージェントが読むコマンド、クエリ、ファイルごとにトークンが増えます。多数のリソースにまたがる調査は、1 行の回答よりもコストがかかります。
- **会話の長さ。** 長いスレッドは新しいメッセージごとにより多くのコンテキストを運ぶため、長いスレッドの後半のメッセージは、新しいスレッドでの同じ質問よりも通常コストが高くなります。
- **モデルティア。** 同じタスクでも、Ultra では Light の 5 倍以上のコストがかかります。

独自の [BYOK](/ja/guide/byok) キーで実行されたターンは、プロバイダーがトークンを請求するため、このうち減額された分だけが課金されます。これらのクレジットも下記の同じビューに表示されます。Usage には、自分のキーでの支出を示す別のビューはありません。

実行の実際のコストを確認するには、**Settings → Organization → Usage** を開き、機能別にグループ化します（[Read the Usage page](#usage-ページを読む) を参照）。

| ティア | クレジット倍率 | 用途 |
|---|---|---|
| **Light** | 0.3x | 簡単な質問への高速で低コストな回答 |
| **Pro**（デフォルト） | 1.0x | 日常的な作業 |
| **Ultra** | 1.7x | 最も深い推論が必要な難しい問題 |

チャットでティアを切り替えるには、メッセージボックス下段のティアボタン（**Pro** など現在のティアが表示されています）をクリックし、**Light**、**Pro**、**Ultra** のいずれかを選びます。各行に倍率が表示されます。選択はこのブラウザにのみ保存されるため、別のデバイスには引き継がれず、次に開始する実行に適用されます。

<Warning>
  チャットは **Pro** で開始し、Pro は Daily クレジットを使いません。そのため Team 以上では、**Light** に切り替えるまで、通常のチャットは Bonus または Premium クレジットを消費します。
</Warning>

実行が使えるティアを決めるルール:

- **Free プランは Light のみ実行します。** Pro と Ultra はアップグレードするまでロック表示になります。
- **Pro と Ultra は Daily クレジットを使いません。** チャットでも同じです。常に Bonus、Premium、または Pay-As-You-Go クレジットを消費します。
- **オートメーションは Light では実行されません。** [オートメーション](/guide/automation/automations)のティアピッカーには Pro と Ultra しかありません。以前に Light で保存されたオートメーションは Pro として実行されます。
- **カスタムエージェントは独自のティアを持ちます。** [エージェントを作成する](/ja/guide/agents/customize)ときに **Model Tier** フィールドで設定します。

<Tip>
  Premium クレジットを長持ちさせるには、日常的な質問は Light で行い、Ultra は Pro で十分な回答が得られなかった調査に取っておきます。
</Tip>

## Usage ページを読む

**Settings → Organization → Usage** には、組織のクレジット残量と、残りがどこに使われたかが表示されます。組織の Owner と Admin が開くことができ、**Billing** も同様です。

<Steps>
  <Step title="Usage を開く">
    **Settings → Organization → Usage** に移動します。
  </Step>
  <Step title="残高を確認する">
    上部の **This month** に、**Premium credits**、**Daily credits**、**Bonus credits** のうちどれだけ使ったかが表示されます。
  </Step>
  <Step title="期間を選ぶ">
    **Credit usage** グラフの上で、**7d**、**30d**、**90d**、**This month**、**Last month**、**Billing cycle** のいずれかを選ぶか、日付ピッカーで独自の日付を設定します。グラフは **Daily**、**Weekly**、**Monthly** でグループ化でき、**Yearly** はカスタム期間でのみ役立ちます。
  </Step>
  <Step title="誰が何に使ったかを調べる">
    **Usage breakdown** で、**By feature**、**By user**、**By workspace** を切り替えます。3 つのタブはいずれもグラフと同じ期間を対象とします。
  </Step>
</Steps>

各ビューの使い方:

| ビュー | 答えられる質問 | 次にすること |
|---|---|---|
| **By feature** | どの機能がクレジットを使ったか | 日常的な作業を安いティアに移すか、頻繁に動くオートメーションの頻度を下げます |
| **By user** | どのメンバーが最も使っているか | その人に Ultra が必要か、その支出が想定どおりかを確認します |
| **By workspace** | どのワークスペースが共有プールから最も消費しているか | そのワークスペースに[クレジット上限](/guide/billing/credit-limits)を設定します |

グラフ上の **All features** フィルターを使うと、推移を 1 つの機能に絞り込めます。

## 確認しなくても届くアラート

Usage ページを見張る必要はありません。CloudThinker は次のアラートを自動で送信します。

| アラート | 届くタイミング |
|---|---|
| **Credit usage warning** | 組織がそのサイクルの Premium クレジットの **80%** を超えたとき。サイクルごとに 1 回、アプリ内とメールで送信されます。 |
| **Pay-As-You-Go cap warning** | Pay-As-You-Go の支出が月間上限の **80%** に達したとき。 |
| **Renewal reminder** | 請求期間が更新される約 **3 日**前で、Premium クレジットの 10% 以上が未使用のとき。 |
| **Workspace limit alert** | ワークスペースが月間[クレジット上限](/guide/billing/credit-limits)の **80%** または **100%** を超えたとき（これらのアラートがオンの場合）。 |

Pay-As-You-Go とワークスペース上限のアラートは、組織の Owner にのみ、アプリ内とメールで届きます。Admin は代わりにこのページを確認してください。

## Pay-As-You-Go

Pay-As-You-Go は、利用可能な Daily、Bonus、Premium クレジットを超えた使用量をカバーします。Team と Scale では、設定した月間支出上限まで、1 クレジットあたり $0.10 がかかります。

| | 詳細 |
|---|---|
| **料金** | Team と Scale: 1 クレジットあたり $0.10。Enterprise: 個別見積もり |
| **プラン** | Team、Scale、Enterprise |
| **月間上限** | あなたが設定します。最低 $100。上限を編集すると、行に設定可能な範囲が表示されます。 |
| **請求** | 請求サイクルの終わりに使用分を支払います。使用量が上限に達した場合はその時点で請求されます。 |
| **変更できる人** | 組織の Owner |

<Warning>
  Pay-As-You-Go は Free では利用できず、Team トライアル中もオフのままです。オンにするには Team 以上にアップグレードしてください。
</Warning>

上限を設定する前に、**Pay as you go** 行に表示される設定可能な範囲を確認してください。Enterprise の使用料金は個別見積もりで設定されます。

<Steps>
  <Step title="Pay-As-You-Go を開く">
    **Settings → Organization → Billing** に移動します。**Pay as you go** 行は **Credit limits** セクションにあります。Owner にのみ表示されます。
  </Step>
  <Step title="オンにする">
    トグルをオンにします。"Pay-As-You-Go enabled successfully" と表示され、変更はすぐに有効になります。
  </Step>
  <Step title="月間上限を設定する">
    **Set cap**（または **Edit cap**）をクリックし、設定可能な範囲内の金額を入力して **Save** をクリックします。

    **期待される結果:** **Usage this cycle** 行に、上限に対する支出が表示されます（例: "$12.40 of $1000 cap"）。上限に達すると行に **Cap reached** と表示され、有料クレジットが必要な新しい実行は次の請求サイクルまでブロックされます。
  </Step>
</Steps>

<Info>
  上限は請求サイクルごとにリセットされます。サイクルの途中で引き下げても、すでに発生した使用分は返金されません。
</Info>

## トラブルシューティング

<AccordionGroup>
  <Accordion title="Daily クレジットが残っているのに、実行が Premium クレジットを使った">
    Daily クレジットで支払えるのは Light モデルでのチャットだけです。Pro や Ultra の実行、または Review、Resolve、Optimize、Cyber、オートメーションの実行は、代わりに Bonus、Premium、または Pay-As-You-Go クレジットを消費します。
  </Accordion>
  <Accordion title="サイクルの早い段階で Premium クレジットがなくなった">
    **Settings → Organization → Usage** を開き、**By workspace** と **By user** で最も多く使っている対象を確認します。日常的な作業を Light に移し、負荷の高いワークスペースには[クレジット上限](/guide/billing/credit-limits)を設定するか、[Pay-As-You-Go](#pay-as-you-go) をオンにします。
  </Accordion>
  <Accordion title="Pay-As-You-Go がオンなのに実行が止まった">
    月間上限に達した可能性があります。**Settings → Organization → Billing** の **Pay as you go** 行に **Cap reached** と表示されます。Owner がそこで上限を引き上げない限り、Pay-As-You-Go は次の請求サイクルまで停止したままです。
  </Accordion>
  <Accordion title="Out of Credits または Plan credits used up と表示される">
    組織に、その実行を支払えるクレジットが残っていません。**Plan credits used up** は Daily クレジットが残っていることを意味するため、**Switch to Light** をクリックするとチャットを続けられます。**Out of Credits** は何も残っていないことを意味します。Owner は **Enable Pay-As-You-Go** をクリックするか、プランをアップグレードするか、サポートに連絡できます。それ以外の場合は次のリセットを待ってください。
  </Accordion>
  <Accordion title="Pay-As-You-Go のスイッチが見つからない">
    **Pay as you go** 行は **Settings → Organization → Billing** の **Credit limits** セクションにあります。有料プランの組織 Owner にのみ表示されます。Team トライアル中は、トライアル終了後に Pay-As-You-Go が利用可能になると表示されます。
  </Accordion>
</AccordionGroup>

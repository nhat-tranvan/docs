CloudThinker のエージェントは、追加した接続を通じてクラウドアカウント、クラスター、ツールを読み取り、Approvals が許可した場合にのみそれらを変更できます。このページでは、セキュリティレビュー担当者が求める事実をまとめ、各コントロールを詳しく説明するページへのリンクを示します。

## 概要

| 質問 | 回答 | 詳細 |
|---|---|---|
| CloudThinker はどこで実行されますか? | 既定では、`app.cloudthinker.io` の CloudThinker が管理するクラウドサービスです。専用、セルフホスト、エアギャップのデプロイメントはアーリーアクセスです。 | [デプロイメント](/ja/guide/deployment/overview)、[AWS](/guide/deployment/aws-reference-architecture)、[Azure](/guide/deployment/azure-reference-architecture)、[Google Cloud](/guide/deployment/gcp-reference-architecture)、[FPT Cloud](/guide/deployment/fpt-cloud-reference-architecture) のリファレンスアーキテクチャ |
| エージェントのコマンドはどこで実行されますか? | CloudThinker が管理するサンドボックス、またはお客様が管理するマシン (environment、ベータ版) です。 | [Environments](/guide/workers) |
| エージェントはどのようにシステムにアクセスしますか? | ワークスペースの Admin が追加した [接続](/ja/guide/connections/overview) を通じてのみ、お客様が付与した認証情報と権限でアクセスします。 | [Connections](/ja/guide/connections/overview) |
| エージェントは自分で変更を加えられますか? | 読み取りは常に実行されます。すべての書き込みは Approvals を通り、人を待つことも拒否されることもあります。最初に Rule が判定し、どの Rule にも一致しない書き込みは Approval mode が決めます。読み取り専用の認証情報では書き込みは一切できません。 | [Approvals](/guide/approvals/overview)、[Rules](/guide/approvals/rules) |
| 誰がどのようにサインインできますか? | Google、GitHub、SSO (SAML 2.0 または OIDC)、または業務用アドレスにメールで送られるコードです。認証アプリで 2 要素目を追加できます。 | [シングルサインオン](/ja/guide/security/sso) |
| 誰が何をできますか? | 組織のロールとワークスペースのロールがあります: Admin、Developer、Viewer、および組織の Owner。 | [Roles](/guide/security/roles) |
| シークレットはチャットやモデルの呼び出しから除外されますか? | 既知の認証情報の形式で貼り付けられた値は、メッセージの送信前に検出されます。ただし、珍しい形式はすり抜けることがあります ([対処方法](/guide/security/data-protection#troubleshooting))。ツールの出力では、接続のシークレット、シークレットらしい名前 (`KEY`、`TOKEN`、`SECRET`、`PASSWORD` を含む) で保存された 6 文字以上の値の認証情報、一般的な認証情報の形式、保護された識別子が、モデルや画面に届く前にプレースホルダーに置き換えられます。一般的な名前で保存された認証情報や 6 文字未満の認証情報は、既知の形式に一致する場合にのみマスクされます。 | [データ保護](/guide/security/data-protection) |
| 監査証跡はありますか? | はい、[Scale と Enterprise](/ja/guide/billing/pricing) にあります。CloudThinker は既定で 365 日間監査イベントを保持し、CSV エクスポートに対応しています。 | [監査ログ](/guide/security/audit-logs) |
| 自社の LLM アカウントを使えますか? | はい、[Scale と Enterprise](/ja/guide/billing/pricing) の BYOK で使えます。 | [BYOK](/ja/guide/byok) |
| CloudThinker SaaS はデータをどのように扱いますか? | CloudThinker が収集するもの、顧客データをホストする場所、削除を依頼する方法を確認してください。 | [SaaS のデータの取り扱い](/guide/security/saas-data-handling) |
| セキュリティインシデントはどのように報告しますか? | 非公開の報告チャンネルから詳細を送ってください。 | [セキュリティインシデントを報告する](/guide/security/report-a-security-incident) |
| コンプライアンスレポートや再委託先の名称について、どこに問い合わせればよいですか? | ベンダーレビューを始める際に CloudThinker にお問い合わせください。 | [お問い合わせ](https://cloudthinker.io/contact) |

## CloudThinker が扱うデータ

| データ | CloudThinker が保持する理由 | 保護の方法 |
|---|---|---|
| 接続の認証情報 (クラウドのキー、トークン、データベースのログイン情報) | 接続したシステムにエージェントがクエリを実行できるようにするため | 保存時に暗号化されます。コマンドの実行時に管理サンドボックスに注入され、environment に送られることはありません。 |
| ワークスペースの [認証情報](/guide/credentials) (コマンドが必要とするその他の API キー) | 誰もキーを貼り付けずに、コマンドがベンダーの API を呼び出せるようにするため | 保存時に暗号化され、ブラウザに送り返されることはありません。チャットにはキーの名前だけが表示されます。 |
| 会話、発見事項、レポート、成果物 | エージェントが見つけたことと行ったことの記録 | ワークスペースの範囲内に限定され、ロールに応じて表示されます。ツールの出力内のシークレットと保護された識別子は、保存される前にプレースホルダーに置き換えられます。ワークスペースの Admin は、会話のタイトルメニュー (**Delete Conversation**) から会話を削除できます。 |

モデルの呼び出しは、組織が [BYOK](/ja/guide/byok) を使っていない限り、CloudThinker の LLM プロバイダーに送られます。BYOK を使うと、呼び出しはお客様自身の AWS Bedrock、Anthropic、FPT Cloud、Claude Code、または Codex のアカウントを経由します。BYOK の場合、失敗した呼び出しが CloudThinker のモデルにフォールバックする場合を除き、それらの呼び出しはお客様とそのプロバイダーとの契約の対象になります ([詳細](/ja/guide/byok#キーが動かなくなったとき))。

<Warning>
コマンドの出力は会話の一部になるため、接続の認証情報で読み取れるものはすべてモデルに届く可能性があります。AWS の `ReadOnlyAccess` の場合、S3 オブジェクトの内容も含まれます。各認証情報のポリシーは、エージェントが必要とするアカウント、リージョン、サービスに限定してください。
</Warning>

## エージェントが実行される場所

すべてのチャットと Automation は、次の 2 つの場所のいずれかで実行されます。

- **CloudThinker Cloud。** コマンドは、CloudThinker が管理する分離されたサンドボックスで実行されます。接続の認証情報はコマンドのためにそこに注入され、出力に表示されることはありません。
- **Environment。** ノートパソコン、サーバー、CI ランナーなど、お客様が管理するマシンが、指定した 1 つのフォルダーでファイルツールとシェルコマンドを実行します。接続のコマンドは引き続き管理サンドボックスで実行されるため、認証情報はクラウドに残ります。セルフホストの environment はベータ版です。

実行が environment からクラウドにフォールバックすることはありません。environment が利用できない場合、実行はエラーを報告します。[Environments](/guide/workers) を参照してください。

このドキュメントには送信元 IP の範囲は記載していません。セキュリティグループやファイアウォールで CloudThinker を許可リストに登録する必要がある場合は、[お問い合わせ](https://cloudthinker.io/contact) ください。

## 操作できる人

アクセスは 2 つのレベルで機能します。組織のロールはすべてのワークスペースに適用されます。ワークスペースのロールは、1 つのワークスペース内でメンバーができることを決めます。

| ワークスペースのロール | できること |
|---|---|
| **Admin** | 接続、認証情報、メンバー、Approvals、Guardrails、設定の管理、および [Skills Hub](/ja/guide/skills/overview) のスキルのインストール |
| **Developer** | エージェントとのチャット、および発見事項、レビュー、スキャンの作業 |
| **Viewer** | ダッシュボード、発見事項、インシデントの閲覧。エージェントとのチャットや変更はできません。 |

組織の Owner と Admin は、すべてのワークスペースでワークスペースの Admin 権限を持ちます。完全な一覧: [Roles](/guide/security/roles)。

**書き込みを承認できる人:** 既定では、実行を開始した人を含む、ワークスペースのすべての Developer または Admin です。Viewer は承認できません。自分の実行を自分で承認できないようにするには、2 人ルールをオンにするか、Rule の確認を指定した承認者グループに送ります。[Approvers](/guide/approvals/approvers) を参照してください。

**Settings → Organization** は、組織の Owner と Admin 向けの組織コンソールです。組織の Admin ではないワークスペースの Admin にはこれらのページは表示されませんが、直接リンクから 2 つを開けます。そのワークスペースの設定を表示する **Guardrails** と、Owner だけが組織のキーを変更できる **BYOK** です。

### サインインのコントロール

| コントロール | 場所 | プラン |
|---|---|---|
| 1 回限りのバックアップコード付きの認証アプリ (TOTP)。各自が自分のアカウントでオンにします。組織全体での 2FA の必須化はありません。 | **Settings → Personal → Security** の **Two-factor sign-in** セクション | すべて |
| SAML 2.0 または OIDC による SSO、ドメインの検証、SSO の強制 | **Settings → Organization → Identity** | [Scale と Enterprise](/ja/guide/billing/pricing) |
| SCIM によるユーザーとグループの同期 | **Settings → Organization → Identity** | [Scale と Enterprise](/ja/guide/billing/pricing) |

[シングルサインオン](/ja/guide/security/sso) と [SCIM](/ja/guide/security/scim) を参照してください。

## エージェントの変更の承認方法

**書き込み (write)** とは、サービスの再起動など、接続されたシステムを変更するエージェントの呼び出しです。読み取りは常に実行されます。各書き込みは、次のチェックを順に通ります。

1. **Always blocked**: 決して実行されない呼び出しの組み込みリストです。CloudTrail のログ記録の停止、AWS アカウントの閉鎖、`kube-system` 名前空間の削除などが含まれます。Rule、人、break-glass (Deny Rule が拒否した 1 件の呼び出しを Owner または Admin が実行できる、オプトイン方式の緊急時の上書き) のいずれもこれを上書きできません。
2. 特定の種類の書き込みを許可、事前確認、または拒否する **Rules**。どの Rule にも一致しない書き込みは Approval mode に進みます。
3. 実行の **Approval mode** (下記で説明)。
4. 承認または拒否する承認者。

Approval mode は **Manual** または **Auto** のいずれかです。**Auto · Rules + AI · Ask me** のような Auto のラベルでは、モードのあとにさらに 2 つの選択肢が加わります。

| 部分 | 選択肢 | 動作 |
|---|---|---|
| モード | **Manual** | すべての書き込みで人に確認します |
| | **Auto** | 次の部分が許可する場合、人を介さずに書き込みを実行します |
| 書き込みを許可できるもの | **Rules** | Allow の Rule のみ |
| | **Rules + AI** | Allow の Rule に加えて、どの Rule も対象としない書き込みに対する AI の判断 |
| 残りの扱い | **Ask me** | 人を待ちます |
| | **Refuse** | 待たずに拒否します |

新しいワークスペースは **Auto · Rules + AI · Ask me** で始まります。Automations は、応答する人がいない場合があるため、既定で **Auto · Rules + AI · Refuse** になります。AI の判断は次のように動作します。

| 書き込み | 結果 |
|---|---|
| 依頼した内容に一致し、その範囲内にとどまる | 実行され、判定は [監査ログ](/guide/security/audit-logs) に記録されます |
| 破壊的、または影響が不明確 | モードの最後の部分に進みます。**Ask me** は人を待ち、**Refuse** は待たずに拒否します。破壊的な書き込みは重大度の高いアラートも発生させます。 |
| AI の判断がチェックを完了できない | 同じフォールバックになります。既定で書き込みを許可することはありません。 |

書き込みには、接続がそれを許可していることも必要です。**Settings → Workspace → Connections** の接続の詳細パネルで **Allow writes** がオフの場合、または認証情報が読み取り専用の場合、モードに関係なく書き込みは拒否されます。すべての書き込みで人を必須にするには、ワークスペースを **Manual** に切り替えてください。[Approvals](/guide/approvals/overview) と [Approval mode](/guide/approvals/approval-mode) を参照してください。

## 監査と保持

**Settings → Organization → Audit log** には、すべてのワークスペースにわたるユーザー、エージェント、システムの操作が 1 つのタイムラインで表示されます。接続の変更、承認の判定、認証情報の変更、メンバーの変更、モジュールのアクティビティが含まれます。各エントリーには、操作者、ワークスペース、結果が記録されます。

| 項目 | 値 |
|---|---|
| 閲覧できる人 | 組織の Owner と Admin |
| プラン | [Scale と Enterprise](/ja/guide/billing/pricing) |
| 保持期間 | 既定で 365 日間で、その後自動的に削除されます。セルフホストのインストールでは期間を変更できます。 |
| エクスポート | 現在のフィルターを反映した **Export CSV**。SIEM へのストリーミングフィードはないため、より長い記録を残すには定期的にエクスポートしてください。 |

認証情報のエントリーには、値もキーの名前も含まれません。[監査ログ](/guide/security/audit-logs) を参照してください。

Free または Team では、エージェントが AWS で行ったことを自社の CloudTrail で監査してください。CloudThinker 用に作成したロール ([セットアップテンプレート](/ja/guide/connections/aws) を使った場合は `CloudThinkerAccessRole`) でイベントを絞り込みます。

## 暗号化とセッション

| レイヤー | CloudThinker が行うこと |
|---|---|
| 転送中 | アプリと API は HTTPS で提供されます |
| 保存されたシークレット | 接続の認証情報、ワークスペースの認証情報、BYOK のキー、連携のトークンは、Fernet (AES-128 と HMAC-SHA256) で保存時に暗号化されます。キーは CloudThinker が管理します。顧客管理の暗号化キーは提供していません。[BYOK](/ja/guide/byok) が対象とするのは LLM の認証情報であり、暗号化キーではありません。 |
| パスワード | アカウントのパスワードは bcrypt のハッシュとして保存されます |
| セッション | アクセストークンは RS256 で署名されます。リフレッシュトークンは使用時にローテーションされ、ハッシュとして保存されます。 |

## 本番環境を接続する前に

- 各接続は、エージェントが必要とするアカウントとリージョンに限定した読み取り専用の認証情報から始めてください。
- 本番のワークスペースは **Manual** のままにするか、人の承認が必要な本番の書き込みに **Ask first** の [Rule](/guide/approvals/rules) を追加してください。
- すべての Owner と Admin に 2FA をオンにするよう依頼するか、SSO を強制して、サインインが ID プロバイダーの MFA ポリシーに従うようにしてください。
- 各メンバーには、適合する最も低いロールを付与してください。
- **Settings → Organization → Guardrails** の組み込みの保護を確認し、自社の ID 形式のパターンを追加してください。

セキュリティアンケートや専用デプロイメントについては、[お問い合わせ](https://cloudthinker.io/contact) ください。

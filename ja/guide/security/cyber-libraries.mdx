[Code Audit](/ja/guide/security/code-audit) のリポジトリの **Issues** タブには、コードの Issue と並んで、ブランチが使っているライブラリのうち公開済みの脆弱性に一致するものが一覧表示されます。バージョンの一致と、それが自分のコードに与える影響は、同じブランチのソースの Issue とは別に判定されます。

## 前提条件

- Code Audit が監視しているリポジトリで、Code Audit が読み取れるロックファイルまたは依存関係ファイルがあること。
- 完了した監査が 1 回あること。監査がライブラリを収集し、新しいアドバイザリのチェックにはその一覧が必要です。
- **Run library scan now** と **Open fix pull request** には Admin または Developer のロールが必要です。Viewer はライブラリとレポートを閲覧できます。

## ライブラリのチェックの仕組み

- 各監査は、監査の他の部分が失敗した場合でも、固定されたコミットが宣言しているライブラリを収集します。
- その後、Code Audit は別の監査を行わなくても、新たに公開されたアドバイザリについて一覧を自動でチェックし続けます。一時停止や再開の操作は不要です。
- 一致したアドバイザリごとに、エージェントがコードが影響を受ける動作を使っているかどうかを評価します。エージェントは公開 Web でアドバイザリを調査し、検索でリポジトリの内容を送信することはありません。

一覧に含まれるのはリポジトリが宣言しているものであり、本番環境で実行されているものではありません。プライベートパッケージや正確なバージョンのないものなど、Code Audit が確認できなかったライブラリは、安全ではなく未チェックとしてマークされます。

## Issues 一覧でライブラリを見つける

**Code audit** からリポジトリを開き、**Issues** タブを選択します。ライブラリだけを表示するには **Type** フィルターを **Libraries** に設定し、コードの Issue と合わせて順位付けするには **All types** のままにします。各ライブラリの行には、名前、バージョン、エコシステムと、弱点 **A06** (脆弱なコンポーネント) が表示されます。

| ラベル | 読み方 |
| --- | --- |
| **Affected** | アドバイザリとの一致が確認された、オープンなライブラリ |
| **Needs review** | チェックでまだ判定できていない、オープンなライブラリ |
| **Last checked** / **Next check** | アドバイザリのチェックが最後に実行された日時と次に実行される日時。一覧の上に表示されます |
| **Collection is incomplete. A clean result cannot be established.** | 一部の依存関係ファイルを読み取れなかったため、空の一覧は安全の証明になりません |

## ライブラリの影響を読む

ライブラリをクリックすると、コードの Issue と同じ Issue ページが開きます。**CVE**、エコシステム、依存関係とその使われ方、**Matched advisories**、**Source trace**、**Source evidence**、そしてエージェントの **Verification** が表示されます。

一致するアドバイザリは、ライブラリが影響を受ける可能性があることを示します。評価はさらに踏み込み、コードが脆弱な動作に到達するかどうかを問います。それを判定できない場合は、不足している証拠や条件を一覧表示します。

影響なしという評価でも、アドバイザリとの一致は消えません。ソースの Issue、ライブラリの証拠、[Pentest](/ja/guide/security/security-testing) の証明は、それぞれ異なる問いに答えます。共有するには、ライブラリのアクションから **Download Markdown** を選びます。

## 今すぐスキャンする、またはライブラリを修正する

- リポジトリの **Issues** 一覧の上にある **Run library scan now** は、保存された一覧を現在のアドバイザリとすぐに照合します。監視対象のブランチでのみ実行されます。
- ライブラリの Issue ページの **Open fix pull request** はチャットを開き、CloudThinker がライブラリをアップグレードまたは固定して、レビュー用のプルリクエストを作成します。
- **Retry library assessment** は、失敗した影響評価を再実行します。

修正のプルリクエストによって、保存された証拠は変わりません。次の監査またはライブラリのチェックが新しいバージョンを読み取ります。

## トラブルシューティング

Cyber のすべての問題をまとめて確認するには、[Cyber のトラブルシューティング](/guide/security/cyber-troubleshooting) を参照してください。

<AccordionGroup>
  <Accordion title="ライブラリが収集されなかった">
    Code Audit が、監査したコミットで読み取れる依存関係ファイルを見つけられませんでした。ブランチにロックファイルがコミットされていることを確認してから、監査を実行してください。
  </Accordion>
  <Accordion title="ライブラリのチェックが一時停止された">
    再試行では解決しない形でチェックが失敗し、通知が 1 回届きます。**Issues** タブに表示されるソースまたは一覧の問題を修正してから、新しい監査を実行するとチェックが再開されます。
  </Accordion>
  <Accordion title="Run library scan now が無効になっている">
    ボタンにカーソルを合わせると理由が表示されます。スキャンは監視対象のブランチでのみ実行され、Admin または Developer のロールが必要で、チェックが一時停止している間は待機します。
  </Accordion>
  <Accordion title="ライブラリのチェックがオフになっている">
    ソースの監査が機能していても、ライブラリのチェックがオフになっている場合があります。CloudThinker のサポート、または社内で CloudThinker を運用している担当者に問い合わせてください。保存されたライブラリは引き続き閲覧できますが、現在の状況は分かりません。
  </Accordion>
</AccordionGroup>

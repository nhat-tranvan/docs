拡張機能を使うと、Review はプルリクエスト（PR）やマージリクエスト（MR）の背後にあるチケットを読み取れます。説明欄に Jira の issue、Confluence のページ、Linear や Backlog の issue、GitHub や GitLab の issue へのリンクがあると、レビュアーがそれを取得し、コードがチケットの要求どおりになっているかを確認します。拡張機能がない場合、Review は差分だけで判断するため、受け入れ条件の漏れを指摘できません。

## 利用できる拡張機能

| 拡張機能 | 読み取る内容 | 必要なもの |
|---|---|---|
| **Jira / Confluence** | リンクされたチケット（概要、受け入れ条件、リンクされたページ）と Confluence の仕様ページ | [Atlassian 接続](/ja/guide/connections/atlassian) |
| **Linear** | issue のタイトル、説明、ステータス、ラベル、issue の git ブランチ名。PR のブランチ名はスキャンされません | [Linear 接続](/guide/connections/linear) |
| **Backlog** | issue の概要、説明、ステータス | [Backlog 接続](/ja/guide/connections/backlog) |
| **GitHub Issues** | PR が参照する issue: タイトル、本文、ラベル、コメント | GitHub で設定済みの Review。同じ接続を使います |
| **GitLab Issues** | MR が参照する issue: タイトル、説明、ラベル、コメント | GitLab で設定済みの Review。同じ接続を使います |

GitHub Issues は Review のプロバイダーが GitHub の場合にのみ、GitLab Issues は GitLab の場合にのみ表示されます。

**非対応:** Jira と Confluence の Data Center または Server（Atlassian 接続は Atlassian Cloud でのみ動作します）、および拡張機能のない Azure Boards。これらの場合は、受け入れ条件を PR の説明欄に貼り付けてください。Review は変更とともに説明欄を読みます。

## 前提条件

- Review が少なくとも 1 つのリポジトリに接続されていること。[Review のセットアップ](/ja/guide/code-review/setup)を参照してください。
- トラッカーを接続するには: ワークスペースの **Admin** ロールと、**Settings → Workspace → Connections** へのアクセス。他のロールでは、タイルに **Connect** ではなく **View** が表示されます。[roles](/guide/security/roles) を参照してください。
- チケットがあるプロジェクトを読み取れる、トラッカーのアカウント。

## 拡張機能をオンにする

<Steps>
  <Step title="Extensions セクションを開く">
    **Review → Settings** に移動し、**Extensions**（"Link tickets and specs so Review can check changes against them"）までスクロールします。各トラッカーには、ステータス付きのタイルがあります。

    | タイルのステータス | 意味 |
    |---|---|
    | **Connected** | Review はすでにそこからチケットを取得しています |
    | **Not connected** | まだ接続がありません。**Connect** をクリックします |
    | **Needs attention** | 接続がエラーを報告しています。**Settings → Workspace → Connections** で修正します |
    | **Uses your GitHub connection**（または GitLab） | Review のプロバイダーを通じて動作します。設定は不要です |
    | **Status unavailable** | 接続一覧を読み込めませんでした。ページを再読み込みします |
  </Step>
  <Step title="トラッカーを接続する">
    タイルの **Connect** をクリックします。CloudThinker が、その接続のフォームを用意した状態で **Settings → Workspace → Connections** を開きます。[Atlassian](/ja/guide/connections/atlassian)、[Linear](/guide/connections/linear)、[Backlog](/ja/guide/connections/backlog) の接続ガイドに従って入力し、保存します。

    **成功時の状態:** **Review → Settings → Extensions** に戻ると、タイルに **Connected** と表示されます。
  </Step>
  <Step title="PR の説明欄でチケットを参照する">
    PR または MR の説明欄に、チケットのリンクまたはキーを書きます。コマンドや設定は不要です。

    | トラッカー | 説明欄に書く内容 |
    |---|---|
    | Jira | `https://myorg.atlassian.net/browse/OPS-1234` または `OPS-1234` |
    | Confluence | `https://myorg.atlassian.net/wiki/spaces/ENG/pages/123456/API-contract`。Confluence には短いキーがないため、ページの URL を使います |
    | Linear | `https://linear.app/myorg/issue/ENG-123/slug` または `ENG-123` |
    | Backlog | `https://myspace.backlog.com/view/PROJ-123` または `PROJ-123` |
    | GitHub または GitLab の issue | PR 自身のリポジトリには `Closes #123`、`Fixes #456`、または `#123`。別のリポジトリには `org/repo#123` または issue の URL |

    Jira、Linear、Backlog のキーは似ています。そのうち 1 つだけが接続されている場合、`OPS-1234` のような単独のキーはそのトラッカーに送られます。複数が接続されている場合、レビュアーはそれぞれを試す必要があり、2 つのトラッカーに存在するキーは別のチケットに一致してしまうことがあります。

    <Tip>
    キーベースのトラッカーを複数接続している場合は、常にチケットの完全な URL を使ってください。
    </Tip>
  </Step>
  <Step title="PR を開いてレビューを読む">
    レビューは通常どおり実行されます。検出事項は、コード自体に加えて、チケットとの差異も対象にします。

    **成功時の状態:** 変更がチケットの一部を満たしていない場合、レビューの検出事項がどの部分かを示します。
  </Step>
</Steps>

接続済みのタイルでは **Manage** を、それ以外では **View** をクリックすると、その拡張機能が読み取る内容と認識するパターンを確認できます。

拡張機能は、ワークスペースにその接続がある限りオンです。チャットや別のエージェント用に最初に作成された接続も含みます。Review が対象とするすべてのリポジトリに適用されます。個別のスイッチやリポジトリ単位の設定はありません。

<Warning>
Review にトラッカーを読ませないようにするには、**Settings → Workspace → Connections** で切断する必要があります。これにより、Review だけでなく、ワークスペース内のすべてのエージェントとチャットからその接続が削除されます。
</Warning>

## 例

次のような PR の説明があるとします。

```markdown
Add rate limiting to the login endpoint.

Implements OPS-1234. Spec: https://myorg.atlassian.net/wiki/spaces/ENG/pages/123456
```

OPS-1234 の受け入れ条件に「return 429 with a Retry-After header」があり、差分はヘッダーなしで 429 を返すとします。Jira 拡張機能があれば、レビュアーはその条件を手元に持っているため、チケットに照らしてヘッダーの欠落を指摘できます。たとえば "The login endpoint returns 429 without the Retry-After header that OPS-1234 requires." のようにです。拡張機能がなければ、同じ差分は正しく見えます。

[review workspace](/guide/code-review/review-workspace) では、**Ticket compliance** カードも、チケットに対する変更を **Fully compliant**、**Partially compliant**、**Not compliant** で評価します。どのレビューモードでも動作します。このカードは、確認したチケットがちょうど 1 件の Jira または Linear のチケットである場合に表示されます。複数のチケット、または Backlog のチケットや Git の issue の場合は、代わりにレビューの概要コメントに表があり、チケットごとに 1 つの判定が示されます。

## 読み取られる内容

- **説明欄のみ。** Review は PR または MR の説明欄からリンクとキーをスキャンします。
- **コードは対象外。** コードブロックやインラインコード（`` `OPS-1234` ``）内のキーは無視されるため、スニペット内の例の ID で検索が行われることはありません。
- **PR あたり最大 20 件の参照**。説明欄の最初の 65,535 文字から取得されます。最も重要なチケットを先頭に置いてください。
- **接続が閲覧できるチケット。** Review は接続されたアカウントのアクセス権で読み取るため、そのアカウントが開けないプロジェクトのチケットはレビューで利用できません。
- **ワークスペースに表示されます。** レビュアーがチケットから得た内容は検出事項に現れることがあります。これらは PR のレビューコメントと、ワークスペースで Review にアクセスできる人に表示されます。公開リポジトリでは PR を見られる人なら誰でもコメントを読めるため、そこでリンクするチケットに機密情報を含めないでください。[data protection](/guide/security/data-protection) を参照してください。

## レビューに役立つチケットを書く

- **受け入れ条件を別々の行に書く。** それぞれがレビュアーの確認項目になります。「うまく動く」は確認できませんが、「1 分間に 5 回失敗したら 429 を返す」は確認できます。
- **チケットだけでなく仕様もリンクする。** API コントラクトを記載した Confluence ページがあれば、レビュアーは正確なフィールド名とステータスコードを把握できます。
- **PR がクローズするすべてのチケットを参照する。** 2 つのバグを修正する PR は、両方を挙げてください。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="レビューがチケットに言及しない">
    **確認:** 参照がブランチ名やコミットメッセージだけでなく説明欄にあること、バッククォートやコードブロックの中にないこと。タイルに **Connected** と表示されていることを確認します。

    **対処:** 説明欄を編集してから、PR に `@cloudthinker-ai review` とコメントすると、レビューが再実行され新しい説明欄を読みます。AWS CodeCommit では、代わりに PR のソースブランチに新しいコミットをプッシュします。[メンションコマンド](/ja/guide/code-review/mention-commands)を参照してください。
  </Accordion>
  <Accordion title="GitHub Issues や GitLab Issues が表示されない">
    これらのタイルは、対応する Review プロバイダーでのみ表示されます。Bitbucket、Azure DevOps、AWS CodeCommit では、代わりに Jira、Linear、Backlog を使ってください。
  </Accordion>
  <Accordion title="タイルに Connect ではなく View と表示される">
    トラッカーを接続できるのはワークスペースの Admin だけです。ワークスペースの Admin に接続を依頼するか、ロールの変更を依頼してください。[roles](/guide/security/roles) を参照してください。
  </Accordion>
  <Accordion title="タイルは Connected なのにチケットが読み取られない">
    接続されたアカウントが、そのチケットのプロジェクトを開けません。トラッカーでアクセス権を付与するか、アクセス権のあるアカウントで再接続してください。
  </Accordion>
</AccordionGroup>

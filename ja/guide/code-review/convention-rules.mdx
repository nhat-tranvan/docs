Learnings は、解決済みの Review 発見事項から CloudThinker が導き出す再利用可能なルールです。チームがリポジトリに記述する規約ファイルとは別のものです。

## 仕組み

1. チームがリポジトリの Review 会話で発見事項を解決します。
2. Learnings のスケジュールに従い、CloudThinker が繰り返されるパターンを探します。
3. CloudThinker が根拠となる引用とともにリポジトリ単位のルールを作ります。
4. Review が有効な Learnings を後続の MR と PR に適用します。
5. チームは各 Learning を確認し、削除せず無効にできます。

新しいリポジトリでは、繰り返しパターンを確立できるだけの解決済み発見事項が必要です。

## 更新スケジュールを設定する

**Review → Settings** で、対象リポジトリの **Learnings** 列を使います。

| オプション | 動作 |
|---|---|
| Off | このリポジトリで新しい Learnings を作らない |
| Weekly | 毎週土曜日に更新する |
| Monthly | 毎月最初の土曜日に更新する |

最初の実行はスケジュールを有効にした直後に開始します。すぐに更新するには **Run now** を選びます。

## Learnings を確認する

**Review → Learnings** を開き、ルールを検索、絞り込み、有効化または無効化します。

ルールを選ぶと、説明、ガイダンス、例、カテゴリ、識別子、引用数を確認できます。

## リポジトリ規約ソースを設定する

リポジトリ管理の規約ソースは Learnings ではありません。Review は `AGENTS.md`、`CLAUDE.md`、`.cursorrules`、各コーディングアシスタントのルールディレクトリも読み取れます。

**Review → Settings** でリポジトリの **Actions** を開き、**Review convention sources** を選びます。

チームが使うコーディングアシスタントを選び、必要ならリポジトリ相対のファイルまたはディレクトリパスを追加します。

これらのソースは Review ですぐに適用され、解決済み発見事項や Learnings スケジュールを必要としません。どちらか一方でも、両方でも使用できます。

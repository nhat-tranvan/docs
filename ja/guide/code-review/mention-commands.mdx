マージリクエストまたはプルリクエストのコメントで `@cloudthinker-ai` をメンションしてコマンドをトリガーします — 発見事項の自動修正、レビューについての質問、ヘルプの取得などが可能です。

<Warning>
  Mention commands は現在 **GitLab** と **GitHub** のみで利用可能です。Bitbucket と Azure DevOps のサポートは近日公開予定です。
</Warning>

---

## コマンド

| コマンド | 機能 |
|---------|-------------|
| `@cloudthinker-ai help` | 利用可能なコマンドをコメントとして表示 |
| `@cloudthinker-ai autofix` | ソースブランチの未解決の発見事項を修正 |
| `@cloudthinker-ai autofix stacked pr` | 新しいブランチで発見事項を修正し、現在の MR/PR にプッシュ |
| `@cloudthinker-ai <question>` | コードレビューについて自由形式の質問をする |

---

## autofix の仕組み

<Steps>
  <Step title="コメントする">
    MR/PR にコメントとして `@cloudthinker-ai autofix` (または `@cloudthinker-ai autofix stacked pr`) を投稿します
  </Step>
  <Step title="分析する">
    CloudThinker がレビューからすべての未解決の発見事項を取得します
  </Step>
  <Step title="修正する">
    エージェントがコードベースの規約に従って各発見事項の修正を実装します
  </Step>
  <Step title="プッシュする">
    変更がコミットされてブランチにプッシュされます
  </Step>
</Steps>

### ダイレクト vs. スタック PR

- **`@cloudthinker-ai autofix`** — MR/PR のソースブランチに直接コミットします。修正後、発見事項は解決済みとしてマークされます。
- **`@cloudthinker-ai autofix stacked pr`** — 新しいブランチを作成し、現在の MR/PR のソースブランチに修正をプッシュします。発見事項はレビューのためにオープンのままです。

---

## 自由形式の質問

`@cloudthinker-ai` に続けて質問をメンションすることで、コードレビューについて何でも質問できます:

```text
@cloudthinker-ai why was this function flagged as a security risk?
@cloudthinker-ai can you explain the performance impact of this change?
@cloudthinker-ai what's the best way to refactor this?
```

### スレッドを考慮したコンテキスト

- **発見事項のスレッドに返信** — エージェントがその特定の発見事項の詳細 (重大度、ファイル、行番号、修正提案) のみを参照し、ピントを絞った回答を提供します。
- **トップレベルコメント** — エージェントがレビューのすべての未解決の発見事項を参照し、より広い視点からの回答を提供します。

## ヒント

- **autofix は 1 度に 1 つ** — MR/PR ごとに実行できる autofix は 1 つだけです。次を開始する前に現在のものが完了するまで待ちます。
- **会話のコンテキストを再利用** — 同じスレッドでの自由形式の返信は会話のコンテキストを再利用するため、フォローアップの質問が前の回答の上に積み上がります。
- **プッシュには承認が必要** — autofix のプッシュは、変更がブランチに適用される前に人間による承認が必要です。

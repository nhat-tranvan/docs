マージリクエストまたはプルリクエスト（MR/PR）のコメントで `@cloudthinker-ai` をメンションすると、Git プロバイダーを離れることなく、レビューの再実行、検出事項の修正、変更についての質問ができます。**検出事項（finding）** とは、レビューが人による確認のために指摘した 1 つの問題です。

## 前提条件

- [Review のセットアップ](/ja/guide/code-review/setup)で接続したリポジトリにある、オープンな MR/PR。
- Git プロバイダーで、その MR/PR にコメントできる権限。

## コマンド

コマンドは、コメント内の独立した行にプレーンテキストで書きます。ボットユーザーの名前に関係なく、`@cloudthinker-ai` と正確に入力してください。プロバイダーのオートコンプリートに候補が出なくても問題ありません。

| コマンド | 動作 |
|---|---|
| `@cloudthinker-ai` または `@cloudthinker-ai help` | プロバイダーが対応しているコマンドの一覧を投稿します |
| `@cloudthinker-ai <question>` | この MR/PR についての質問に回答します |
| `@cloudthinker-ai review` | 最初のレビューを開始するか、最後にレビューしたコミットから再度レビューします。`review again`、`continue`、`continue review` も同じ動作です |
| `@cloudthinker-ai autofix` | 重大度にかかわらず未解決のすべての検出事項を修正し、この MR/PR のソースブランチにコミットをプッシュします |
| `@cloudthinker-ai autofix stacked` | 未解決のすべての検出事項を新しいブランチで修正し、そのための別の MR/PR を開きます。`autofix stacked pr` も使えます |

`review` は行全体でなければなりません。`@cloudthinker-ai review this carefully` はコマンドではなく質問として扱われます。コードブロック、インラインコード、引用返信の中のメンションも、コマンドとして実行されることはありません。

## コマンドを実行する

<Steps>
  <Step title="プロバイダーで MR/PR を開く">
    CloudThinker がレビューした、GitHub、GitLab、Bitbucket、Azure DevOps、AWS CodeCommit 上の MR/PR を使います。
  </Step>
  <Step title="コマンドを新しいコメントとして投稿する">
    たとえば、途中で止まったレビューを再実行するには:

    ```text
    @cloudthinker-ai review
    ```

    **成功時の状態:** ボットが **CloudThinker Review Started** と返信します。実行が完了すると、MR/PR に新しいレビュー概要コメントが表示されます。Azure DevOps では、代わりにレビューの終了時に **CloudThinker Review Complete** または **CloudThinker Review Did Not Finish** と返信します。
  </Step>
</Steps>

レビューが概要の前に停止した場合、ボットは進捗コメントを **CloudThinker Review Did Not Finish** に編集します。すでに投稿された検出事項は有効なままです。`@cloudthinker-ai review` とコメントすると、最後にレビューしたコミットから続行します。AWS CodeCommit では、代わりにソースブランチに新しいコミットをプッシュします。

## 質問する

ボットをメンションし、続けて質問を書きます。

```text
@cloudthinker-ai does this change break any other caller of parseConfig?
@cloudthinker-ai what should I test before merging this?
```

質問する場所によって、エージェントが重点を置く対象が変わります。

| コメントする場所 | エージェントが最初に見るもの |
|---|---|
| 検出事項のスレッドへの返信 | その検出事項とそのファイル、および副作用を確認するための MR/PR の残りの部分 |
| 新しいトップレベルのコメント | MR/PR 全体と、未解決のすべての検出事項 |

同じスレッドでのフォローアップの質問は、以前の回答を踏まえて答えられます。

## 検出事項に反論する

あなたが MR/PR の作成者または担当者で、検出事項が誤っていると考える場合は、その検出事項のスレッドに返信します。メンションは不要です。理由を説明してください。例:

```text
This is intentional. The retry is capped by the caller in client.go, so it can't loop forever.
```

CloudThinker は現在のコードとあなたの返信に照らして検出事項を再確認し、次の 3 つのいずれかで決着させます。

| 結果 | 条件 | 結果として起こること |
|---|---|---|
| 取り下げ | 検出事項が誤っていた | クローズされ、以降のリポジトリのレビューには、変更のないコードでそれを再度指摘しないよう伝えられます。これはサムズダウンの[投票](/guide/code-review/review-workspace#work-the-findings)と同じメモを使います。各レビューには、過去 90 日間のリポジトリの最新 20 件が渡されます |
| 了承 | コードが意図的なもの | この MR/PR についてクローズされ、あなたの理由がスレッドに投稿されます |
| 未解決のまま | 検出事項がまだ当てはまる | オープンのままで、ボットがその理由を返信します |

反論は、レビューが完了した後に、AWS CodeCommit を除くすべてのプロバイダーで機能します。他の人もボットをメンションして検出事項について質問できますが、その返信で決着することはありません。

## autofix で検出事項を修正する

修正の届け方を選びます。

| コマンド | 修正が入る場所 | 使う場面 |
|---|---|---|
| `@cloudthinker-ai autofix` | この MR/PR のソースブランチへの新しいコミット | 修正を信頼しており、マージする MR/PR を 1 つにしたい場合 |
| `@cloudthinker-ai autofix stacked` | この MR/PR のソースブランチを対象とする、独自の MR/PR を持つ新しいブランチ | 修正があなたのブランチに入る前にレビューしたい場合（GitHub と GitLab のみ） |

<Steps>
  <Step title="コマンドをトップレベルのコメントとして投稿する">
    ```text
    @cloudthinker-ai autofix stacked
    ```
  </Step>
  <Step title="修正の実行を待つ">
    CloudThinker は、修正案の有無にかかわらず未解決の各検出事項を読み、コードを変更し、コミットしてプッシュします。1 つの MR/PR で同時に実行される autofix は 1 つだけです。実行中に 2 回目のリクエストをしても、別の実行は開始されません。

    CloudThinker はあなたのテストを実行しません。アーキテクチャ上の判断が必要な検出事項や、明確な修正がない検出事項はスキップします。修正の実行はエージェントの実行であり、クレジットを使います。

    **成功時の状態:** `fix: autofix findings from code review of ...` というタイトルのコミットがソースブランチに表示されるか、それを対象とする新しい MR/PR が開きます。コミットメッセージには、各修正が `Fixed:` の下に、スキップされた各検出事項がその理由とともに `Skipped:` の下に記載されます。
  </Step>
</Steps>

GitHub と GitLab では、1 つの検出事項のスレッド内の返信として `@cloudthinker-ai autofix` と入力することもできます。その場合、CloudThinker はその検出事項だけを修正します。

<Warning>
  `@cloudthinker-ai autofix` は、別の承認ステップなしでソースブランチにプッシュします。CloudThinker は実行できる人を MR/PR の作成者に限定しておらず、そのような CloudThinker の設定もありません。コメントできる人なら誰でも実行できます。広く共有されているリポジトリでは、プロバイダー側でコメントできる人を制限し、先に変更を読みたい場合は `autofix stacked` を使ってください。
</Warning>

## レビューをスキップする

MR/PR の説明欄のどこかに次の内容を書くと、CloudThinker はその MR/PR をレビューしなくなります。

```text
@cloudthinker:ignore
```

大文字と小文字は区別されます。CloudThinker は新しいイベントのたびに説明欄を読むため、マーカーを追加すると次のプッシュからレビューがスキップされ、削除すると次のプッシュがレビューされます。すでに実行中のレビューは最後まで実行されます。終了させるには、[Review workspace](/guide/code-review/review-workspace#re-run-fix-and-merge) の **Stop review** を使います。ボットによる依存関係の更新など、MR/PR のグループ全体をスキップするには、代わりに [Review のセットアップ](/ja/guide/code-review/setup)のリポジトリフィルターを使います。

## プロバイダーの対応状況

| プロバイダー | トップレベルの質問 | スレッドへの返信 | `review` | `autofix` | `autofix stacked` |
|---|---|---|---|---|---|
| GitHub | Yes | Yes | Yes | Yes | Yes |
| GitLab | Yes | Yes | Yes | Yes | Yes |
| Bitbucket Cloud | Yes | 一部 (1) | Yes | 一部 (2) | No |
| Azure DevOps | Yes | 一部 (1) | Yes | 一部 (2) | No |
| AWS CodeCommit | Yes | No | No | No | No |

1. 検出事項のスレッドでは、MR/PR の作成者または担当者の返信だけが読み取られます。それ以外の人のスレッドへの返信は、質問であっても回答されません。代わりにトップレベルのコメントで質問できます。
2. トップレベルのコメントのみです。検出事項のスレッド内では使えません。

AWS CodeCommit でも、新しい PR と、そのソースブランチへのプッシュのたびに、自動レビューは実行されます。`review` と `autofix` のコメントコマンドは対応していないため、CodeCommit の PR を再度レビューするには新しいコミットをプッシュします。

プロバイダーが対応していないコマンドには、その旨と代わりの方法を示す短い返信が届きます。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="ボットがコメントに返信しなかった">
    **確認:**

    - メンションがプレーンテキストであり、バッククォート、コードブロック、引用の中にないこと。
    - プロバイダーが[上の表](#プロバイダーの対応状況)でそのコマンドに対応していること。
    - Azure DevOps では、[Provider authentication](/guide/code-review/provider-auth) の説明どおり、**Resource version** が **2.0** に設定された **Pull request commented on** のサービスフックが存在すること。
    - プロバイダーの Webhook 配信履歴で、コメントイベントが配信され受け付けられていること。
  </Accordion>
  <Accordion title="コマンドが質問として回答された">
    **原因:** `review` は行全体でなければなりません。**対処:** 後ろに何も付けずに `@cloudthinker-ai review` を投稿します。
  </Accordion>
  <Accordion title="検出事項のスレッドへの返信で決着しなかった">
    **原因:** 返信によって検出事項を決着できるのは MR/PR の作成者または担当者だけで、レビューの完了後に限られます。**対処:** 作成者に返信を依頼するか、Review workspace で解決済みにします。
  </Accordion>
</AccordionGroup>

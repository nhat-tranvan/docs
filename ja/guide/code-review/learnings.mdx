Review は、すべてのプルリクエスト（PR）やマージリクエスト（MR）を、チームが書き残した基準と、チームが解決した検出から CloudThinker が導き出したルールに照らしてチェックします。このページでは、各ソースを有効にする方法、`BUSINESS.md` にプロダクト固有のルールを記述する方法、Review が学んだ内容を確認する方法、合わなくなったルールを廃止する方法を説明します。

<LearningsScene />

| 用語 | 書く人 | 内容 |
|---|---|---|
| **Learnings** | CloudThinker | チームがすでに解決したレビューの検出から導き出したルール |
| **Learning sources** | あなたのチーム | `AGENTS.md` など、リポジトリに置いている規約ファイル |
| **`BUSINESS.md`** | あなたのチーム | プロダクトのモジュールと、それらが守るべきルール（不変条件）のマップ |

## 前提条件

- [Review のセットアップ](/ja/guide/code-review/setup)でリポジトリが接続・有効化され、クローンが完了していること。
- スケジュール、ソース、ルールを変更するには、ワークスペースの **Admin** ロールが必要です。Developer と Viewer は Learnings を読めますが、変更はできません。[ロール](/guide/security/roles)を参照してください。
- Learnings には、そのリポジトリの解決済みの検出が必要です。最初の実行では、過去 30 日間に解決された検出をさかのぼって確認します。以降の実行では、前回の実行以降に解決された検出を読み取ります。Learning sources は初日から機能します。

## ソースを選ぶ

| | Learnings（CloudThinker が書く） | Learning sources（あなたが書く） |
|---|---|---|
| ルールの出どころ | チームが解決した検出に繰り返し現れるパターン | `AGENTS.md` や `.cursorrules` など、チームが書いたファイル |
| セットアップ | リポジトリごとに Weekly または Monthly のスケジュールを有効にする | なし。自動で検出されます |
| 適用されるタイミング | 実行で十分な根拠が見つかったあと | 次のレビューから |
| 向いている用途 | チームが手作業で直し続けているミス | すでに書き残している基準 |

2 つは独立して機能します。書き残した基準に加えて、Review が実際の修正から拾うパターンも使いたい場合は、両方を使ってください。Learnings と Learning sources は Review 独自のコンテキストです。ワークスペースのメモリやスキルとの比較は [CloudThinker に教える](/guide/teach-cloudthinker)を参照してください。

## リポジトリで Learnings を有効にする

<Steps>
  <Step title="リポジトリの一覧を開く">
    **Review → Settings** に移動し、リポジトリの表で対象のリポジトリを探します。
  </Step>
  <Step title="スケジュールを選ぶ">
    **Learnings** 列で **Weekly** または **Monthly** を選びます。**Off** にすると、そのリポジトリで新しい Learnings が作られなくなります。

    **Review → Learnings** から始めることもできます。スケジュールが設定されたリポジトリがまだない場合、ページに **Enable weekly learning** が表示されます。
  </Step>
  <Step title="今すぐ実行する（任意）">
    **Review → Learnings** に移動して **Run now** をクリックし、リポジトリを選んで **Update review rules now** ダイアログで **Run now** をクリックします。ピッカーには、スケジュールが設定されたリポジトリだけが表示されます。

    **完了の状態:** ページのサマリー行に **Running** と表示され、実行が終わると **Last run** に変わります。
  </Step>
</Steps>

スケジュール実行は土曜日に行われるため、新しいルールは週の作業が始まる前に用意されます。Weekly は毎週土曜日、Monthly は毎月最初の土曜日に実行されます。各リポジトリには 00:00 UTC か 12:00 UTC の固定の枠が割り当てられます。割り当ては CloudThinker が行い変更できませんが、**Run now** でいつでも実行を開始できます。**Review → Learnings** の **Next run** 行に予定が表示されます。実行は通常 10 分以内に終わります。

各 Learning は、このワークスペース内の 1 つのリポジトリの解決済みレビュー検出から作られ、そのリポジトリにのみ適用されます。

<Note>
実行が終わっても新しい Learnings がないことがあります。新しいリポジトリではそれが普通です。CloudThinker は、同じ種類の修正が繰り返されるのを見てはじめてルールを書きます。達成すべき決まった件数はないため、検出の解決を続け、次の実行のあとに確認してください。
</Note>

## CloudThinker が学んだ内容を確認する

**Review → Learnings** を開きます。各行は 1 つの Learning で、それを生んだレビューのリポジトリにスコープされています。

| 項目 | 表示内容 |
|---|---|
| Learning | 平易な言葉で書かれたルールと、その下のカテゴリ：Security、Performance、Patterns、Correctness |
| Repository | ルールが適用されるリポジトリ |
| Signal | 最近のレビューがどれだけそれに頼っているか（下記参照） |
| Created | CloudThinker がルールを書いてからの経過時間 |

**Search learning name...**、**All categories**、**All signals**、**All repositories** で絞り込みます。

| Signal | 意味 |
|---|---|
| Strong | このリポジトリのレビューで、頻繁かつ最近引用されています |
| Quiet | 有効ですが、Strong より引用が少ないもの |
| Weak | 最近引用されていません。レビューが引用しない限り、まもなく廃止されます |
| Retired | オフです。レビューはもう使いません |

Learning は、レビューの検出がそれを参照したときに引用されたことになります。レビューが引用しなくなった Learning は Weak になり、その後自動的に廃止されるため、ルールは常に最新に保たれます。

行をクリックすると Learning が開きます。ルール、**Citation trend**、およびそれを参照したレビュー検出へのリンクを含む **Recent citations** が表示されます。引用の多い Learning は、共通のヘルパーや lint ルールなど、根本で直す価値のある問題を示しています。

PR では、Learning に基づく検出に `Cites Learning:` で始まりルール名を示す行が付きます（複数ある場合は `Cites Learnings:`）。**Review → Learnings** でその名前を検索してルールを確認し、誤っていれば廃止してください。

Learning の文言を編集したり、手作業で作成したりはできません。自分でルールを追加するには、規約ファイルに書いてください（[独自の規約ファイルを追加する](#独自の規約ファイルを追加する)を参照）。

## Learning を廃止または復元する

ワークスペースの Admin は、Review にルールを適用させたくない場合、行のアクションメニューで **Retire** を選びます。元に戻すには **Restore** を選びます。廃止してもルールとその引用は残るため、何も失われません。

レビューが 30 日間引用も改良もしなかった Learning は、CloudThinker が自動的に廃止します。Learning の詳細に、どちらが起きたか（「Retired automatically」または「Retired by」とチームメイトの名前）が表示されます。

## 独自の規約ファイルを追加する

Review は、チームがすでにリポジトリに置いているガイドラインファイルを読み取り、セットアップなしでレビュー中に適用します。認識するパスは次のとおりです。

| ツールまたは範囲 | ファイルとフォルダー |
|---|---|
| リポジトリ内の任意のフォルダー | `AGENTS.md`、`AGENTS.override.md`、`CLAUDE.md`、`GEMINI.md` |
| リポジトリのルート | `CONVENTIONS.md`、`.rules` |
| Cursor | `.cursorrules`、`.cursor/rules/*.mdc` |
| GitHub Copilot | `.github/copilot-instructions.md`、`.github/instructions/**/*.instructions.md` |
| Windsurf | `.windsurfrules`、`.windsurf/rules/**/*.md` |
| Cline | `.clinerules`、`.clinerules/**/*.md` |
| Roo | `.roorules`、`.roo/rules/**/*.md` |
| Continue | `.continuerules`、`.continue/rules/*.md` |
| Augment | `.augment-guidelines`、`.augment/rules/*.md` |
| Junie | `.junie/AGENTS.md`、`.junie/guidelines.md`、`.junie/guidelines/` |
| Amazon Q | `.amazonq/rules/*.md` |
| Kiro | `.kiro/steering/` |
| Trae | `.trae/rules/` |

変更がファイルに触れると、そのファイルに最も近い規約ファイルが優先され、次にリポジトリのルートのファイルが適用されます。`services/payments/AGENTS.md` のガイドラインは payments のコードに、ルートのガイドラインはすべてに適用されます。同じフォルダー内では、`AGENTS.override.md` が最初で、次に `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` の順です。

Review はこれらのファイルを指示ではなく、規約の根拠として扱います。ファイル内のテキストで、レビュアーに検出をスキップさせたり、基準を変えさせたり、変更を承認させたりすることはできません。

Review が読み取る内容を確認・拡張するには:

<Steps>
  <Step title="Learning sources を開く">
    **Review → Settings** で、リポジトリのアクションメニューを開き、**Learning sources** を選びます。
  </Step>
  <Step title="見つかったものを確認する">
    **Detected sources** には、Review が見つけたファイルが一覧表示されます。**Detect sources automatically** をオンのままにすると、Review は毎回のレビュー前に新しいファイルをチェックします。オフにすると、Review は一覧を現状のまま保ち、新しいファイルの追加をやめます。カスタムパスは引き続き適用されます。
  </Step>
  <Step title="カスタムパスを追加する">
    **Custom convention paths** に、リポジトリ相対のパスを最大 10 個追加します。例：`docs/style-guide.md`。パスにはファイルか `docs/standards/` のようなフォルダーを指定でき、`docs/**/*.md` のような glob パターンも使えます。パスは `/` で始めたり、`..` を含めたり、`.claude/rules/` の中を指したりできません。ブランチが自身のルールファイルをレビュアーのポリシーに変えられないよう、Review はそのフォルダーをブロックします。**Save** をクリックします。

    **完了の状態:** **Save** のあと、パスが **Custom convention paths** に表示され、そのリポジトリの次のレビューがそれに従います。
  </Step>
</Steps>

## ビジネスルールを記述する

`BUSINESS.md` には、プロダクトのモジュールと、それらが守るべきルール（不変条件）を記述します。たとえば、どのプランでどの機能が使えるかです。Review は Learnings の設定に関係なくこのファイルを読み取ります。ターゲットブランチのリポジトリのルートに置いておけば、すべてのレビューが変更をそれに照らしてチェックします。ファイルの形式、例、トラブルシューティングは [Business flow checks](/guide/code-review/business-flow) を参照してください。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="Review → Learnings が空">
    **Review → Settings** でリポジトリに **Weekly** または **Monthly** のスケジュールがあり、クローンが完了していることを確認してください。**Last run** に完了した実行が表示されている場合、そのリポジトリにはパターンを形成できるだけの解決済みの検出がまだありません。検出の解決を続け、次のスケジュール実行を待ってください。
  </Accordion>
  <Accordion title="Run now に No scheduled repositories と表示される">
    **Run now** には、スケジュールのあるリポジトリだけが表示されます。**Review → Settings** の **Learnings** 列でスケジュールを設定してから、もう一度試してください。
  </Accordion>
  <Accordion title="Review がオフの間、スケジュールに Paused と表示される">
    そのリポジトリで Review がオフになると、Learnings は一時停止します。リポジトリで Review をオンに戻すと、スケジュールが再開します。
  </Accordion>
  <Accordion title="Review がガイドラインファイルを無視する">
    **Learning sources** を開き、ファイルが **Detected sources** に表示されているか確認してください。表示されていない場合は、**Custom convention paths** にそのパスを追加してください。
  </Accordion>
  <Accordion title="Learning が自分たちのコードベースに合わない">
    行のアクションメニューから廃止してください。Review は次のレビューからそれを適用しなくなり、あとで復元することもできます。
  </Accordion>
</AccordionGroup>

Code Review Analytics は、リポジトリ全体のレビュー活動、繰り返し発生する検出、証拠に基づく傾向を表示します。

ナビゲーションの **Code Review → Analytics** からアクセスしてください。

## Analytics タブ

Analytics セクションには 2 つのタブがあります。

| タブ | 表示内容 |
|-----|--------------|
| **Review Patterns** | 確認済みの Advanced Review 対象マージリクエストに影響する検出ドメインと、その結果を説明する検出事項 |
| **Reports** | 準備が完了したリポジトリ単位のレビューレポート |

Review Patterns が既定で開きます。廃止されたタブへの保存済みリンクも Review Patterns を開きます。

## Review Patterns

Review Patterns はコーチング用のビューです。マージリクエストの実際の結果を使い、各パターンをその検出事項の証拠に結び付けます。

### 対象条件

Review Patterns は、完了済みかつ下書きではない有効な Advanced Review のうち、正確な結果が永続化されたものだけを含みます。Fast Review、シャドウ判定、未完了のレビュー、パイプラインの検出、メインエージェントの検出、不明なスペシャリスト、ボット作成者は、ドメインの割合に影響しません。

正確な結果を持たない過去のレコードは除外されたままです。読み取り経路は、タイムスタンプや検出事項の有無から完了状態や検出の帰属を推測しません。

### 割合の読み方

このビューは Security、Performance、Correctness、Patterns の 4 ドメインを対象とします。各ドメインは検出なしマージリクエストの割合と、その分子と分母をそのまま表示します。

ドメインの割合は次のとおりです。

```text
検出なしマージリクエスト / レビュー済みマージリクエスト
```

1 つのマージリクエストは、選択した期間に一度だけ寄与します。対象となる結果が複数ある場合、作成者と期間は最新の対象完了から取り、対象となるすべての結果に紐づく検出事項の和集合がドメインの割合に影響します。同一ドメインで複数の検出があっても、そのマージリクエストへの影響は一度だけです。解決済みと未解決の検出は同じように数えます。

対象マージリクエストが 3 件未満の開発者も、**Not enough data** とレビュー件数とともに表示されます。その開発者のマージリクエストはチーム全体の割合には寄与します。

### 主なコーチング優先度

ページは、チーム全体で影響を受けたマージリクエストの割合が最も高いドメインを見出しとして示します。割合が完全に同点の場合は Critical と High の検出件数で決まり、なお同点のドメインはすべて表示されます。重大度が割合に重み付けすることはありません。

### 証拠の確認

開発者とドメインのセルを選択すると、選択した週次または月次の期間について、その開発者とチーム全体を確認できます。展開されたビューには、関連する検出事項が重大度、解決状態、マージリクエストの識別情報、レビューへのリンクとともに一覧表示されます。

解決済みの検出も、過去のコーチング証拠として残ります。

## 期間と状態

週次と月次のコントロールが Analytics で唯一のコントロールであり、Review Patterns に適用されます。データの読み込み中やリクエストの失敗時も、ビューは選択内容を保持します。

- 確認済みの Advanced Review がない場合: その期間に対象データがないことをページが説明します。
- 対象マージリクエストが 1 件または 2 件の場合: 割合を出さずに件数を表示します。
- 傾向グラフの区間に対象マージリクエストがない場合: グラフは **No data** と表示した空白を示します。
- サマリーまたは詳細のリクエストが失敗した場合: 該当する領域が Retry を提示し、現在の期間や選択は破棄されません。

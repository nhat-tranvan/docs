このチュートリアルを終える頃には、ライブ環境に対してロール固有のプロンプトを 1 つ実行し、フォローアップで精度を上げる方法を習得できます。**約 10 分**かかります。

<Info>
**必要なもの:** 少なくとも 1 つの接続が設定されたワークスペース — 接続がなければ CloudThinker は実際の結果を返せません。まだ設定していない場合は、先に [クイックスタート](/ja/quickstart) を完了してください。
</Info>

## 構文

<PromptSyntaxBasics />

<Steps>
  <Step title="チャットを開く">
    [app.cloudthinker.io](https://app.cloudthinker.io) にサインインし、左サイドバーの **New chat** をクリックします。

    **成功状態:** 空の会話が開きます。リクエストを普段の言葉で入力してください — メンションは不要で、CloudThinker が回答します。
  </Step>

  <Step title="ロールのクイックウィンを実行する">
    自分のロールに合ったタブを選び、クイックウィンを貼り付けてから、出力の形を確認したらフォローアップを試してみましょう。

    <Tabs>
      <Tab title="SRE / オンコール">
        **目標:** アラートから根本原因までの時間を短縮する。生のログではなく、構造化された調査を得る。

        **必要なもの:** [Pulse](/ja/guide/pulse/overview) が設定済みで、運用するシステムへの接続がある。

        **クイックウィン — アクティブなアラートを調査する:**

        ```text
        Investigate the current incident: pull related metrics, recent deploys, and topology, then propose the top 3 likely causes ranked by evidence
        ```

        CloudThinker が作業を [サブエージェント](/ja/guide/agents/overview#サブエージェント) に分担し、並行して証拠を収集し、各原因の根拠となる証拠とともに、可能性の高い原因のランク付きリストを返します。

        **フォローアップ:**

        ```text
        Draft a postmortem from this conversation
        Pull the matching runbook and walk me through the approval steps
        Check whether this pattern matches any past incident in memory
        ```
      </Tab>

      <Tab title="DevOps / プラットフォーム">
        **目標:** 使っていないクラウドへの支払いをやめる。1 分以内に無駄がどこにあるか確認する。

        **必要なもの:** [AWS](/ja/guide/connections/aws)、[Azure](/ja/guide/connections/azure)、または [GCP](/ja/guide/connections/gcp) 接続。

        **クイックウィン — アイドル状態および過剰プロビジョニングのリソースを見つける:**

        ```text
        Find EC2 instances with <20% CPU utilization over the last 30 days, plus any unattached EBS volumes and unused Elastic IPs
        ```

        CloudThinker がクラウド API を照会し、使用率メトリクスと結合して、月間節約見込み額付きのランク付きリストを返します。

        **フォローアップ:**

        ```text
        Right-sizing for the top 5 by waste
        Cost trend by service for this quarter
        Draft a reserved-instance plan for the stable workloads above
        ```
      </Tab>

      <Tab title="セキュリティ">
        **目標:** 監査担当者や攻撃者よりも先に最も危険な設定ミスを見つける。

        **必要なもの:** AWS、Azure、または GCP 接続。

        **クイックウィン — センシティブなポートへのパブリックアクセスを発見する:**

        ```text
        List security groups with 0.0.0.0/0 access on database, SSH, or RDP ports across all regions
        ```

        CloudThinker がリソースオーナー、リージョン、重大度ランキング付きで違反ルールを返します。

        **フォローアップ:**

        ```text
        SOC 2 compliance status with prioritized remediation
        Audit IAM policies for privilege-escalation paths
        Check for IMDSv1 instances or unencrypted EBS volumes
        ```
      </Tab>

      <Tab title="データベース">
        **目標:** 遅いと思っているクエリではなく、実際に問題を引き起こしているクエリを見つける。

        **必要なもの:** [PostgreSQL](/ja/guide/connections/postgresql) または [MySQL](/ja/guide/connections/mysql) 接続。

        **クイックウィン — 過去 24 時間で最も遅いクエリ:**

        ```text
        Show the top 10 queries by total time over the last 24 hours on production PostgreSQL, with execution count and P95 latency
        ```

        CloudThinker が `pg_stat_statements` (または相当するもの) から取得し、影響度でランク付けして、コストが集中している箇所を示します。

        **フォローアップ:**

        ```text
        Suggest indexes for the top 3 queries above
        Explain why query #2 isn't using the existing index
        Query latency P95 trends by endpoint
        ```
      </Tab>

      <Tab title="Kubernetes">
        **目標:** 次の OOMKill や予算レビューの前に、ポッドが過剰・過小・アンバランスになっている箇所を把握する。

        **必要なもの:** [Kubernetes 接続](/ja/guide/connections/kubernetes)。

        **クイックウィン — クラスター全体のポッドリソースの無駄:**

        ```text
        Analyze pod resource usage vs requests across all namespaces and surface the largest over- and under-provisioned workloads
        ```

        CloudThinker がリクエストと制限を実際の使用量と結合し、ノードコストへの影響でギャップをランク付けします。

        **フォローアップ:**

        ```text
        HPA policies for the variable workloads above
        Find nodes with <30% utilization for consolidation
        Check for pods without resource limits or liveness probes
        ```
      </Tab>

      <Tab title="エンジニアリングリーダー">
        **目標:** 4 回のミーティングをスケジュールせずに、コスト、セキュリティ、パフォーマンス、信頼性を横断した統合ビューを得る。

        **必要なもの:** カバーしたい領域の接続が設定済み。

        **クイックウィン — 四半期インフラレビュー:**

        ```text
        Run a quarterly infrastructure review covering top cost savings, security and compliance gaps, database performance hotspots, and Kubernetes utilization risk. Consolidate it into an executive summary with prioritized actions.
        ```

        CloudThinker が各領域を並行して処理し、発見事項の重複を排除して、4 つのタブの代わりに 1 つのエグゼクティブブリーフを返します。

        **フォローアップ:**

        ```text
        Turn this into a quarterly business review slide deck
        Track the open actions from last quarter — what shipped, what slipped
        Draft a roadmap that aligns cost reduction with reliability work
        ```
      </Tab>
    </Tabs>

    **成功状態:** CloudThinker が、一般的なベストプラクティスではなく、自分の環境で認識できるリソース、クエリ、またはルールを名指しして返答します。
  </Step>

  <Step title="会話を洗練させる">
    CloudThinker は会話のコンテキストを保持するので、最初からやり直さずに結果の上に積み上げましょう:

    - **最初から具体的に。** 「us-east-1 の過去 30 日間の EC2 コスト」は「コストを見せて」より優れています。
    - **やり直さずに、絞り込む。** 「上記の項目のうち RDS をドリルダウンして」で機能します。
    - **欲しい出力の形を伝える。** まずダッシュボードを求めて傾向を確認し、次に同じトピックについて推奨事項を求めます。
    - **複数の領域をまとめて 1 つのプロンプトで尋ねる。** コスト、セキュリティ、データベース、Kubernetes にまたがる内容は一度に尋ねてください — CloudThinker が作業を分担します。

    **成功状態:** フォローアップのプロンプトが、会話の前半の内容を繰り返さなくても、それを参照した回答を返します。
  </Step>
</Steps>

## 完了の確認

- [x] ロールのクイックウィンが、認識できるリソースやクエリを名指しした結果を返した
- [x] 少なくとも 1 つのフォローアッププロンプトが、最初の回答を繰り返さずにその上に構築された
- [x] ダッシュボード、レポート、推奨事項を普段の言葉で依頼できる

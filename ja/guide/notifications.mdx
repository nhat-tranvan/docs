Notifications ページでは、承認を待っているエージェントや失敗した automation など、CloudThinker がアプリの外に送るワークスペースのイベントと、それぞれの送信先を決めます。すべての通知は [Inbox](/guide/activity) の **Notifications** タブにも届きます。このタブは常にオンで、スイッチはありません。

## 前提条件

- 設定を変更するには、ワークスペースの **Admin** ロールが必要です。Developer と Viewer はページを開けますが、編集はできません。[ワークスペースのロール](/ja/guide/workspace-users) を参照してください。
- Slack、Microsoft Teams、Google Chat に配信するには、**Team** プラン以上 ([料金](/ja/guide/billing/pricing) を参照) と、次の連携の設定が必要です。
  - [Slack 連携](/ja/guide/slack-integration) が接続されていること。
  - [Teams 連携](/ja/guide/teams-integration) が接続され、ボットがインストールされ、ワークスペースがマッピングされていること。
  - [Google Chat 連携](/guide/google-chat-integration) が設定され、組織の管理者が Google Chat のスペースをこのワークスペースにマッピングしていること。

## 配信チャンネルを設定する

配信チャンネルとは、通知の送信先です。メールは既定で使える状態になっています。チャットのチャンネルは、それぞれ選んだ 1 つのチャンネルまたはスペースに投稿します。

<Steps>
  <Step title="Notifications を開く">
    **Settings → Workspace → Notifications** に移動します。Settings を開くには、サイドバー上部のワークスペースメニューをクリックし、**Settings** をクリックします。ページには、まず送信するイベントが一覧表示され、その下の **Where … sends them** (ワークスペース名が入る見出し) に配信チャンネルが表示されます。
  </Step>
  <Step title="メールの受信者を選ぶ">
    **Email** カードで **Manage email recipients** を開きます。ワークスペースのメンバーは既定でメールを受け取ります。チームのエイリアスなど、ワークスペース外の人を含めるには、アドレスを入力して **Add email** をクリックします。

    **成功時の状態:** カードに **Workspace members**、または 2 つのアドレスを追加した場合は **Members + 2 more** と表示されます。
  </Step>
  <Step title="Slack チャンネル、Teams チャンネル、または Google Chat スペースを選ぶ">
    接続済みの **Slack**、**Teams**、**Google Chat** カードには、選ぶまで **Pick a channel** (Google Chat の場合は **Pick a space**) と表示されます。カードの設定ボタン (**Change Slack channel**、**Change Teams channel**、**Change Google Chat space**) をクリックし、検索して 1 つ選択します。共有チャンネルに投稿すると、チーム全員がアラートを確認でき、参加することで各自がオプトインできます。各連携はワークスペースごとにちょうど 1 つのチャンネルまたはスペースに投稿するため、承認をある Slack チャンネルに、ダイジェストを別のチャンネルに送ることはできません。別の受け手に届けるには、そのメールエイリアスをメールの受信者として追加してください。

    **成功時の状態:** カードにチャンネル名またはスペース名が表示されます。**Not set up**、**Finish setup**、**Map a space to finish**、**Upgrade to enable** と表示されているカードは、まだ配信していません。[トラブルシューティング](#トラブルシューティング) を参照してください。
  </Step>
</Steps>

## 送信するイベントを選ぶ

<Steps>
  <Step title="モジュールのグループを開く">
    ページ上部では、イベントが Resolve、Review、Optimize、Agents & Tasks などのモジュールごとにグループ化されています。グループをクリックして展開します。
  </Step>
  <Step title="イベントごとにチャンネルをオンにする">
    各行が 1 つのイベント、各列が配信チャンネルです。そのイベントを届けるチャンネルのセルをオンにします。ダッシュは、そのイベントではそのチャンネルを使えないことを示します。
  </Step>
  <Step title="提供されている場合は重大度のしきい値を設定する">
    **Alerts** と **Keepers** の行では、チャンネルをオンにすると重大度の選択欄が表示されます。そのチャンネルに届ける最も低い重大度を選びます。

    | しきい値 | 送信対象 |
    |---|---|
    | **Low** | すべて |
    | **Medium** | Medium 以上 |
    | **High** | High と Critical |
    | **Critical** | Critical のみ |

    チャンネルごとに独自のしきい値があります。たとえば、Slack には Medium 以上を、メールには Critical だけを送れます。
  </Step>
</Steps>

**成功時の状態:** 変更は操作した時点で保存されます。次に一致するイベントは、オンにしたチャンネルに投稿されます。

## ルーティングできるイベント

「既定でメールがオン」列は、誰も設定を変更していない状態でメールを送るイベントを示します。Alerts と Keepers の行は一覧の上部にあり、独自の設定を持つため、現在の状態はページで確認してください。Slack、Teams、Google Chat のセルは最初はオフなので、各チャンネルに届けたいイベントをオンにしてください。

| モジュール | イベント | 送信されるタイミング | 既定でメールがオン |
|---|---|---|---|
| Alerts | Alerts | エージェントが新しいアラートを作成したとき。重大度のしきい値があります。 | 行を参照 |
| Keepers | Keepers | [Optimize](/ja/guide/cost-optimization/overview) がコスト削減を見つけたとき、または自動のコストチェックが完了したとき。1 つの行で両方を扱います。行には古い **Keepers** という名前が残っていますが、製品名は Optimize です。重大度のしきい値があります。 | 行を参照 |
| Assessment | Assessment completion | AWS Well-Architected Assessment が完了したとき | いいえ |
| Agents & Tasks | Agent approvals | エージェントが書き込みの実行に [承認](/guide/approvals/overview) を必要とするとき、およびそれが承認または拒否されたとき | はい |
| Agents & Tasks | Rule proposals | 人が関与しない実行が、レビュー待ちの Rule を提案したとき | いいえ |
| Agents & Tasks | Runbook proposals | 人が関与しない実行が、レビュー待ちの Runbook を提案したとき | はい |
| Agents & Tasks | Automation run failed | [automation](/guide/automation/automations) が、成功のあとに初めて実行に失敗したとき | はい |
| Agents & Tasks | Automation turned off | 繰り返しの失敗またはプランの変更によって automation がオフになったとき | はい |
| Agents & Tasks | Watched condition met | automation が、監視している条件が満たされたと報告したとき | はい |
| Agents & Tasks | Agent reduced its monitoring | 自律的に automation を実行しているエージェントが、トリガーの 1 つを削除または一時停止したとき、またはチェックの頻度を下げたとき | はい |
| Agents & Tasks | Automation resource missing | 必要なリソースが削除されたため、automation を実行できないとき | はい |
| Resolve | Incident created | 手動または Webhook によって新しい [インシデント](/ja/guide/incident/overview) が作成されたとき | はい |
| Resolve | Awaiting approval | インシデント内のアクションに承認が必要なとき | はい |
| Resolve | Runbook approvals | Runbook の実行に承認が必要なとき | はい |
| Resolve | RCA completed | インシデントの根本原因分析が完了したとき | いいえ |
| Resolve | Incident resolved | インシデントが解決済みとしてマークされたとき | いいえ |
| Resolve | Monitoring updates | Monitor が変更されたとき、Alert Audit の準備ができたとき、週次の Monitoring スコアカードが公開されたとき、または昇格用のプルリクエストがオープンまたは失敗したとき | いいえ |
| Resolve | Incident upkeep | 再チェックで、分析済みのインシデントが回復した、まだアクティブである、または人の対応が必要であると判明したとき | いいえ |
| Resolve | Incident upkeep digest | 1 日 1 回: まだアクティブなインシデント、維持されなかった修正、終了した監視、実行できないチェック、upkeep がクローズしたインシデント | はい |
| Resolve | Postmortem ready | インシデントのポストモーテムのレビュー準備ができたとき | いいえ |
| Resolve | Runbook draft generated | CloudThinker がインシデントの [Runbook](/ja/guide/incident/runbooks) を下書きしたとき | いいえ |
| Review | Review findings | プルリクエストまたはマージリクエストで [Review](/ja/guide/code-review/overview) の実行が完了したとき | はい |
| Review | Pipeline analysis | パイプライン分析が、失敗したパイプラインで問題を見つけたとき | はい |
| Review | Reports ready | リポジトリ単位の Review レポートの PDF の生成が完了したとき | いいえ |
| Cyber | Dependency risk changes | 監視対象のライブラリが脆弱になったとき、またはリスクが高まったとき。メールとチャットの投稿は High と Critical の変更のみが対象です | はい |
| Cyber | New Pentest findings | Pentest の実行で、新たに確認された発見事項が保存されたとき | いいえ |
| Cyber | New Code Audit findings | Code Audit が、新たに確認された発見事項を公開したとき | いいえ |
| Cyber | Pentest completion reports | Pentest が完了したとき。重大度の合計と優先度の高い発見事項が含まれます | はい |
| Cyber | Code Audit completion reports | Code Audit が完了または失敗したとき。重大度の合計と優先度の高い発見事項が含まれます | はい |
| Cyber | Cyber run failed or blocked | Pentest の実行が失敗したとき、または保存したログインが使えなくなったためにブロックされたとき | はい |
| Optimize | Optimize refresh paused | [Optimize](/ja/guide/cost-optimization/overview) がコストデータを更新する前に、接続の対応が必要なとき | はい |
| Optimize | Optimize report ready | スケジュールされた [コストレポート](/ja/guide/cost-optimization/reports) が閲覧可能になったとき | いいえ |
| Optimize | High cost anomalies | Optimize が接続で重大度の高いコスト異常を記録したとき | いいえ |
| Optimize | Optimize weekly digest | 月曜日に送られる、Cost Health、新しい発見事項、期限切れが近いコミットメント、レビュー済みの異常のまとめ | いいえ |
| Optimize | Optimize monthly digest | 毎月 2 日に送られる、前月の支出、新しい発見事項、異常、Cost Health | はい |
| Recommendations | Recommendation assignments | レコメンデーションがあなたに割り当てられたとき、または割り当てが解除されたとき | はい |
| Recommendations | Replies | 誰かがあなたのコメントに返信したとき | はい |
| Recommendations | Resolved discussions | 参加しているディスカッションが解決済みとしてマークされたとき | いいえ |
| Connections | Connection needs attention | [接続](/ja/guide/connections/overview) の認証情報が機能しなくなったとき (キーの期限切れや失効など) | はい |
| Rooms | Mentions | ほかの人と共有しているチャットであるルームで、誰かがあなたをメンションしたとき。メールのみ。 | はい |

**Automation run failed** は、失敗した実行ごとではなく、連続した失敗ごとに 1 回通知します。失敗が続いて automation がオフになると、**Automation turned off** が届きます。

2 つの承認通知には専用の行がありません。人を待つ破壊的な書き込みは High のアラートを発生させるため、**Alerts** 行でしきい値が High 以下のすべてのチャンネルに届きます。[break-glass](/guide/approvals/approvers#break-glass) の使用時は、ワークスペースのオーナーと、すべての組織の Owner と Admin を含むすべてのワークスペースの **Admin** に、アプリ内通知が送られます。

テストボタンはありません。ルーティングを一通り確認するには、あるチャンネルで **Agent approvals** をオンにし、テスト用のチャットを **Manual** の [Approval mode](/guide/approvals/approval-mode) に設定して、テスト用の接続で小さな書き込みを依頼し、カードで **Decline** をクリックします。

<Tip>
まずは承認、インシデント、接続の状態を共有チャンネルに送ることから始めてください。通常の量がチームで把握できたら、ダイジェストや重大度の低いイベントを追加します。
</Tip>

## ワークスペースの設定と個人のメール

このページでは、ワークスペースが送る内容を設定します。各メンバーは **Settings → Personal → Notifications** から、他の人の設定を変えずに自分宛てのメールをミュートできます。既定でメールがオフのイベントについては、メンバーがそこで自分宛てのメールをオンにできます。個人の設定はメールのみが対象です。Slack、Teams、Google Chat の投稿は、このページとチャンネル自体の設定に従います。

<Note>
[Agent CLI](/ja/guide/cli/agent) のセッションは、承認カードがすでにターミナルとブラウザにあるため、自動では承認通知を送りません。ワークスペースの承認者に一度通知するには、セッションで `/cloudthinker notify` を実行します。
</Note>

## トラブルシューティング

<AccordionGroup>
  <Accordion title="チャットのカードに Upgrade to enable と表示される">
    Slack、Teams、Google Chat への配信には Team プラン以上が必要です。メールとアプリ内通知はすべてのプランで使えます。[Subscription](/ja/guide/billing/subscription) を参照してください。
  </Accordion>
  <Accordion title="チャットのカードに Not set up または Finish setup と表示される">
    **Not set up** は、連携がまだ接続されていないことを意味します。Teams の場合、**Finish setup** はボットがインストールされていないか、ワークスペースがマッピングされていないことを意味します。Google Chat の場合は、組織の管理者がスペースをこのワークスペースにマッピングする必要があります。[前提条件](#前提条件) にリンクされている連携ガイドに従ってください。
  </Accordion>
  <Accordion title="Slack チャンネルが一覧にない">
    選択欄は入力に応じて検索し、名前の一部にも一致します。それでもチャンネルが表示されない場合は、Slack で CloudThinker アプリがそのチャンネルを参照できることを確認してから、もう一度検索してください。
  </Accordion>
  <Accordion title="トグルがロックされている">
    通知の設定を変更するには、ワークスペースの **Admin** ロールが必要です。ワークスペースの Admin に変更を依頼するか、ロールの変更を依頼してください。
  </Accordion>
  <Accordion title="イベントはオンなのに誰にもメールが届かない">
    そのイベントのメールのセルがオンであること、(Alerts と Keepers の場合) 重大度のしきい値がイベントより高くないこと、受信者が **Settings → Personal → Notifications** で自分宛てのメールをミュートしていないことを確認してください。Inbox の **Notifications** タブには常に記録が残ります。
  </Accordion>
</AccordionGroup>

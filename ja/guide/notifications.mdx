重要なクラウド運用情報を、インテリジェントなロール別通知でキャッチアップできます。重症度フィルタリングと複数の配信チャンネルを活用して、CloudThinkerの各機能に対するアラートの受信方法と受信先を柔軟に設定できます。

---

## アラート疲れの問題

一般的なクラウドアラートは、すべてのユーザーにすべての通知を送信します——しかし全員が全通知を受け取ると、誰も何も読まなくなります。セキュリティエンジニアはコスト最適化の推奨事項をすべて確認する必要はありません。財務チームはKubernetesのOOMKillアラートを必要としていません。オンコールエンジニアは午前3時にコンプライアンスダイジェストメールを受け取る必要はありません。

結果として、重要なアラートがノイズに埋もれ、チームが通知を完全に無効にしてしまい、重要な発見に対するアクションが取られなくなります。

CloudThinkerのNotifications Centerは、ロールベースのルーティングと重症度フィルタリングによってこの問題を解決します。各チームメンバーが自分に必要な情報を、どの重症度レベルで、どのチャンネルで受け取るかを設定できるため、適切な担当者が適切なタイミングで適切なアラートを受け取れます。

| 機能 | 説明 |
|---|---|
| **スマートルーティング**（チャンネルベースの配信） | 機能カテゴリと重症度レベルに基づいて、メールまたはSlackチャンネルに通知をルーティングする |
| **アラート疲れのコントロール**（インテリジェントフィルタリング） | 重症度のしきい値を設定して、自分のロールに関係するアラートのみを受け取る |
| **マルチチャンネルサポート**（柔軟なプリファレンス） | メール、Slack、Microsoft Teams、またはそれらの組み合わせで通知を受け取る（機能ごとにカスタマイズ可能） |
| **マルチワークスペース**（ワークスペース分離） | 管理する各ワークスペースで個別の通知プリファレンスを設定する |

## クイックスタート

<Steps>
  <Step title="通知設定に移動する">
    CloudThinkerで **Settings > Notifications** に移動します
  </Step>
  <Step title="機能カテゴリを選択する">
    通知を設定したいCloudThinkerの機能を選択します
    (Alerts、Agents & Tasks、Review など)
  </Step>
  <Step title="チャンネルを有効化する">
    選択した機能に対して、メール、Slack、Microsoft Teamsをオンにします
  </Step>
  <Step title="重症度レベルを設定する">
    最小重症度のしきい値を選択します（Critical、High、Medium、Low）
  </Step>
  <Step title="メールを確認する（該当する場合）">
    外部メール受信者の場合は、メールアドレスに送信された確認リンクを確認してください
  </Step>
</Steps>

通知システムはCloudThinkerのコア機能を中心に整理されており、各エリアを個別に設定できます。各機能カテゴリを選択すると、包括的な設定にアクセスできます。

### 機能カテゴリ

各エリアの通知を個別に設定します:

- **Alerts** - システムイベントに関する重要なオペレーションアラート通知
- **Agents & Tasks** - エージェントの中断とタスク完了
- **[Review](/ja/guide/code-review/setup) / Pipeline Monitoring** - Reviewの発見（重症度別）、パイプライン実行ステータス、障害通知
- **Discussions** - チームディスカッションのアクティビティ、返信、解決済みディスカッション
- **Resources** - インフラリソースの変更と更新

## チャンネルの設定

各機能カテゴリは、独立したコントロールによる柔軟なチャンネル設定をサポートしています:

### メール通知

<Frame caption="確認付きで複数のメールアドレスを追加する通知フォーム">
  <img
    src="/images/notification-center/06-email-recipients-form.webp"
    alt="通知用に複数のメールアドレスを追加する方法を示すメール受信者入力フォーム"
    style={{ width: "100%", height: "auto" }}
  />
</Frame>

ワークスペースメンバーと外部受信者の両方に対応した、確認済みメールアドレスへの通知送信。

**主な機能:**

- セキュリティのための確認済み外部受信者
- 機能ごとに複数のメールアドレスを設定可能
- ワークスペースメンバーのデフォルト設定
- 外部アドレスにはメール確認が必要

### [Slack連携](/ja/guide/slack-integration)

<Frame caption="チームへの通知ルーティング用のSlackチャンネルを選択する">
  <img
    src="/images/notification-center/08-slack-channel-selection.webp"
    alt="通知ルーティングに利用可能なチャンネルを表示するSlackチャンネルドロップダウンセレクター"
    style={{ width: "100%", height: "auto" }}
  />
</Frame>

ダイレクトメッセージではなくSlackチャンネルに通知をルーティングすることで、チームの状況把握を維持しながら通知疲れを軽減できます。チャンネル名を入力して絞り込み検索ができます——大規模なワークスペースでも、部分一致・大文字小文字を区別しない検索で目的のチャンネルを簡単に見つけられます。

**主な機能:**

- チャンネルベースのルーティング（ダイレクトメッセージではない）
- 先読みフィルタリング付きの検索可能なチャンネルピッカー
- 通知の過負荷を軽減
- チーム全体での可視性とオプトイン
- コンテキストに応じたチャンネル選択

### [Microsoft Teams連携](/ja/guide/teams-integration)

Adaptive Cardを使ってMicrosoft Teamsチャンネルに通知をルーティングし、リッチで構造化されたアラートを提供します。Teams通知はSlackと同様に機能します——機能カテゴリごとに設定し、Teamsチャンネルを選択して、重症度のしきい値を設定します。

**主な機能:**

- 構造化データとアクションボタンを備えたAdaptive Cardフォーマット
- 検索可能なピッカーによるチャンネルベースのルーティング
- カテゴリごとのチャンネル選択（例：Reviewの発見は `#code-reviews` へ、インシデントは `#incidents` へ）
- 他のチャンネルと同じ重症度しきい値フィルタリング
- 先に[Teams連携](/ja/guide/teams-integration)を接続する必要があります

## 重症度フィルタリング

<Frame caption="メールとSlackを通じたAlerts通知の重症度しきい値の設定">
  <img
    src="/images/notification-center/03-alerts-configuration.webp"
    alt="HighとMediumのしきい値を持つメールとSlackの重症度フィルターコントロールが表示されたAlertsセクション"
    style={{ width: "100%", height: "auto" }}
  />
</Frame>

重症度レベルで通知をフィルタリングして、しきい値を満たすアラートのみを受け取ります:

- **Low** - 情報的な更新と一般的な通知
- **Medium** - 注意とレビューが必要な重要な更新
- **High** - 迅速なアクションが必要な運用に影響する重大な問題
- **Critical** - 即時アクションが必要なシステム重大アラート

各チャンネルには独立した重症度しきい値を設定できます。例えば、SlackをMedium以上に設定し、メールをHigh以上に設定できます。

### [Review](/ja/guide/code-review/setup) / Pipeline Monitoring

#### Pipeline Monitoring

- パイプライン実行ステータスの更新
- AIで分析されたログを含むパイプライン障害通知

#### Reviewの発見

プルリクエスト／マージリクエストでのAI Reviewが完了すると、CloudThinkerは以下を含む通知を送信します:

- **重症度サマリー** — Critical、High、Medium、Lowの発見件数
- **発見の詳細** — 最大10件の発見のタイトル、重症度、ファイルパス、行番号
- **解決済み追跡** — 以前に特定された発見のうち解決された件数
- **アクションリンク** — Reviewダッシュボードへの直接リンク

<Info>
  Review発見の通知は、各レビューの完了後に自動的に送信されます。通知をトリガーするレビューを制御するには、重症度しきい値を設定します——例えば、**High** に設定すると、CriticalまたはHighの重症度の発見が検出された場合にのみ通知を受け取ります。
</Info>

各通知チャンネルはそれぞれのネイティブフォーマットで発見を表示します:
- **Slack** — 重症度の絵文字インジケーター付きの[Block Kitメッセージ](/ja/guide/slack-integration)
- **Microsoft Teams** — FactSet重症度テーブル付きの[Adaptive Card](/ja/guide/teams-integration)
- **Email** — 発見の詳細とダッシュボードリンク付きのHTMLテーブル

## 主な機能

### メール確認

不正アクセスとデータ漏洩を防止するために、外部メール受信者は通知を受け取る前に確認が必要です:

1. 通知設定に外部メールアドレスを入力する
2. そのメールアドレスに確認リンクが送信される
3. 受信者が確認リンクをクリックして確認する
4. 確認済みのアドレスのみがワークスペースの通知を受け取る

これにより、機密性の高いクラウド運用データが意図した受信者にのみ配信されることが保証されます。

### Slackのチャンネルベースルーティング

個人ユーザーへのダイレクトメッセージの代わりに、通知をSlackチャンネルにルーティングします:

- **より良いコンテキスト** - すべてのチームメンバーがチャンネル内の通知を確認できる
- **疲れの軽減** - 個別のメッセージの代わりに機能ごとに1つのチャンネル
- **オプトインサブスクリプション** - チームメンバーが特定の通知チャンネルへの参加を選択できる
- **チームの認識** - チーム全体での運用の可視性

### マルチワークスペースサポート

所属する各ワークスペースに対して個別の通知プリファレンスを設定します:

- ワークスペースごとに異なる重症度のしきい値
- ロール固有の設定
- ワークスペース固有のチャンネル
- ワークスペースのコンテキストに基づいたアラート戦略のカスタマイズ

## ベストプラクティス

### アラート疲れの軽減

- **重症度フィルターを適切に設定する** - 多くの機能を管理するロールにはHighまたはCriticalを設定する
- **SlackまたはTeamsチャンネルを使用する** - チームの通知はダイレクトメッセージではなくチャンネルにルーティングする
- **未使用の機能を無効にする** - チームが積極的に管理していない機能の通知をオフにする
- **段階的な有効化** - まずCriticalアラートから始め、徐々に低い重症度レベルを追加する

### セキュリティ上の考慮事項

- **常に外部メールを確認する** - 機密データへのアクセスが承認された受信者のみに許可されるようにする
- **ワークスペース固有のチャンネルを使用する** - 機密性の高い運用を専用のSlackまたはTeamsチャンネルにルーティングする
- **受信者を定期的にレビューする** - 誰が通知を受け取っているかを定期的に監査する
- **チャンネルアクセスを制限する** - 通知チャンネルのメンバーシップを関連するチームメンバーに限定する
- **通知アクティビティを監視する** - コンプライアンスのために誰が何の通知を受け取っているかを追跡する

### 設定戦略

1. 重要なオペレーションアラートには **まずCritical + High重症度** から始める
2. チームがシステムに慣れてきたら **Medium重症度を徐々に追加する**
3. **機能ごとに異なるチャンネルを使用する** - インフラのアラートとコストのアラートを分ける
4. **ロールごとにカスタマイズする** - チームメンバーの責任に応じてしきい値を調整する
5. **通知の配信をテストする** - メールとSlackメッセージが意図した受信者に届いていることを確認する

`cloudthinker` バイナリのすべてのコマンドと、そのフラグおよび終了コードです。CLI が初めての場合は、[CLI の概要](/ja/guide/cli/overview)から始めてください。

```bash
cloudthinker [--url <URL>] [--workspace <ID or NAME>] <command> [flags]
```

インストールしているバージョンの正確な構文は、`cloudthinker <command> --help` で確認できます。

## グローバルオプション

グローバルオプションはコマンド名の前に置きます。

| オプション | 説明 |
|---|---|
| `--url <URL>` | CloudThinker のアドレス。デフォルトは最後に `login --url` したアドレスで、なければ `https://app.cloudthinker.io` です。パスや末尾のスラッシュを付けないオリジンだけを渡します: `--url https://ct.example.com` |
| `--workspace <ID or NAME>` | このワークスペース用に保存されたログインを使います。`review setup` と `doctor` 以外では `CLOUDTHINKER_TOKEN` と併用できません（終了コード 2） |
| `--tui-mode <MODE>` | 引数なしの `cloudthinker` 専用: `fullscreen`（デフォルト）または `regular`（チャットをターミナルのスクロールバックに残します）。`cloudthinker agent` では、代わりに `agent` の後に渡します |
| `-y`、`--yes` | 削除や `connections disconnect` など、事前に確認するコマンドを確認なしで実行します。スクリプトや CI など、応答できるターミナルがない場合は必須です |
| `--skill [MODULE]` | AI コーディングエージェント向けの CLI 操作ガイドを表示して終了します。ログイン不要です。値なしでは索引を表示します。モジュールは `api`、`auth`、`chat`、`cloud`、`connections`、`policy`、`review`、`cyber`、`cyber-scan`、`cyber-verify`、`cyber-report`、`worker`、`remote` です |
| `-h`、`--help` | ヘルプを表示します |
| `-V`、`--version` | CLI のバージョンを表示します |

## サインインコマンド

| コマンド | 説明 |
|---|---|
| `login` | ブラウザでログインします。SSH 経由やディスプレイがない環境では、代わりに短いコードを表示します |
| `login --device-auth` | 常に短いコードのフローを使います |
| `login --no-browser` | ブラウザを開かずにサインイン URL を表示します |
| `login --token` | stdin から個人 API トークン（`ct_pat_`）を読み取り、サーバーで確認し、対象となる各ワークスペース用に保存します: `cloudthinker login --token < token.txt`。パイプ入力のないターミナルでは終了コード 2 で終了します |
| `logout` | 選択中またはアクティブなワークスペースのログインを消去します |
| `logout --all` | このホストに保存されたすべてのログインを消去します |
| `whoami [--json]` | ログインの背後にあるアカウントとワークスペースを、ライブで確認して表示します |
| `auth status [--json]` | このマシンに保存されたワークスペースのログインを一覧表示し、アクティブなものに印を付けます |
| `auth switch <WORKSPACE>` | 保存されたログインをアクティブにします |
| `auth token` | 現在のアクセストークンを stdout に表示します。これはシークレットです |
| `workspace ls [--json]` | 現在のログインの組織であなたがアクセスできるワークスペースを、あなたのロールとともにライブで一覧表示します。選択中のワークスペースに印を付け、各ワークスペースについてこのマシンに保存済みのログインがあるかを示します。一覧表示でアクティブなログインが変わることはありません |
| `doctor [--json]` | このマシンを診断します: サーバーアドレスとその出所、ログイン、API アクセス、記録された Connection のテスト、エージェントとそのスキル、最新リリース、ターミナルのサポート、このフォルダーの `AGENTS.md` または `CLAUDE.md`、インストールパス。問題がなければ 1 行を表示し、問題があれば問題ごとに対処法付きの行を表示します。テスト、修復、ログインは開始しません |

詳細と CI のパターン: [CLI 認証](/ja/guide/cli/authentication)。

## Agent

コマンドなしの `cloudthinker`、または `cloudthinker agent` は、現在のフォルダーで [CloudThinker Agent](/ja/guide/cli/agent) を起動します。`agent` の後のすべての引数は、そのままエージェントに渡されます。

以下のフラグには `agent` コマンドが必要です。セッションを再開するには `cloudthinker agent --session <id>` を実行します。CLI は `cloudthinker --session <id>` を拒否します。CLI 0.11.0 以前は終了時にその拒否される形式を表示していたため、`cloudthinker update` で更新してください。

| フラグ | 説明 |
|---|---|
| `-p`、`--print <PROMPT>` | ヘッドレスで実行します: 回答し、表示して終了します |
| `--mode json` | `-p` と併用し、イベントを JSON Lines でストリーミングします |
| `-c`、`--continue` | このフォルダーの最新のセッションを続行します |
| `-r`、`--resume` | 再開するセッションを選びます |
| `--session <ID>` | ID またはファイルでセッションを開きます |
| `-n`、`--name <NAME>` | このセッションに名前を付けます |
| `--model <MODE>` | エージェントのモード: `light`、`pro`、`ultra` |
| `--list-models` | ワークスペースが提供するエージェントのモードを一覧表示します |
| `--add-dir <PATH>` | このフォルダーもエージェントが読み取り・編集できるようにします。複数ある場合は繰り返します |
| `--max-turns <N>` | `-p` と併用し、N 回のモデルターンで停止してエラーで終了します |
| `--tools <NAMES>` | これらのローカルツールだけを許可します（カンマ区切り） |
| `--exclude-tools <NAMES>` | これらのローカルツールをオフにします（カンマ区切り） |
| `--tui-mode <MODE>` | `fullscreen`（デフォルト）または `regular`。引数なしの `cloudthinker` でのグローバルオプションと同じです |
| `-a`、`--approve` | この実行に限り、このプロジェクトのローカルファイルを信頼します |
| `-na`、`--no-approve` | この実行に限り、このプロジェクトのローカルファイルを無視します。表記はダッシュ 1 つと 2 文字です |

CLI 自身のオプションは `agent` の前に置きます。`--` の後のすべては、CLI が読まずにエージェントに渡されます。

```bash
cloudthinker --workspace Production agent    # start the agent in the Production workspace
cloudthinker agent --help                    # the CLI's summary of agent flags
cloudthinker agent -- --help                 # the agent's own, full help
```

`agent` はエージェントのプロセスに処理を引き渡すため、`agent -p` は[終了コード](#終了コード)のコードではなく、エージェント自身の終了コードを返します。

### リモートエージェント

`remote [TARGET]` は、SSH 経由で別のマシン上でエージェントを実行し、接続が切れたりノート PC がスリープしたりしても実行を続けます。リモートマシン自身の CLI がエージェントをバックグラウンドプロセスで保持するため、`tmux` は不要です。`TARGET` は `~/.ssh/config` のホスト、`user@host`、`user@host:port`、`ssh://user@host:port` のいずれかで、デフォルトは最後に使ったマシンです。初回は名前を指定してください。ターゲットも以前のマシンもない場合、コマンドは `Which machine? Run: cloudthinker remote <ssh-host>` を表示して終了コード 2 で終了します。どちらのマシンにも macOS または Linux 上の CLI が必要です。Linux マシンに CLI がない場合、または自己更新できないほど古い場合は、ノート PC が同じ SSH ログインで対応するビルドをコピーすることを提案します。マシンに必要なのは `tar` だけです。

| フラグ | 説明 |
|---|---|
| `--cwd <DIR>` | 選ぶ代わりに、リモートマシン上のフォルダーを指定します |
| `--name <NAME>` | この名前のエージェントにアタッチするか、この名前で起動します |
| `--detach` | アタッチせずにエージェントを起動し、戻る方法を表示します。ターミナルなしでも動作します |
| `--via <COMMAND>` | `ssh -J` など、別のコマンドでマシンに到達します。マシンとともに保存されます |
| `-- <AGENT_ARGS>` | 起動時にエージェントに渡す引数 |

`remote ls` は保存されたマシンを、`remote ls <MACHINE> [--json]` はそこで実行中のエージェントを一覧表示し、`remote forget <MACHINE>` は保存されたマシンを削除します。

リモートエージェントはリモートマシン自身の `cloudthinker` を実行するため、そのマシンのログインとワークスペースを使います。先にそこで `cloudthinker login` を実行してください。SSH 経由では短いコードが表示されます。

<Note>
`cloudthinker remote` の中では、Ctrl+Z でデタッチし、エージェントをリモートマシンで実行したままにします。ローカルのジョブを一時停止するわけではありません。戻るには、もう一度 `cloudthinker remote` を実行します。
</Note>

## Chat

| コマンド | 説明 |
|---|---|
| `chat -p <PROMPT>` | CloudThinker にプロンプトを送信し、回答を待ちます。`-p -` は stdin からプロンプトを読み込みます |
| `chat -p … --continue <UUID>` | 実行 ID または会話 ID で会話を続行します |
| `chat -p … --agent <UUID or ALIAS>` | このターンにカスタムエージェントを回答させます |
| `chat -p … --no-wait` | 実行がキューに入るとすぐに戻ります |
| `chat -p … --timeout <SECS>` | この秒数が経過したら待機を止めます。デフォルトは 2400 です。実行は継続します |
| `chat -p … --json` | プレーンな回答の代わりに JSON オブジェクトを 1 つ出力します |
| `chat status <RUN_ID> [--wait] [--timeout <SECS>] [--json]` | 実行の状態と回答を表示します。`--wait` は完了するまでポーリングします |
| `chat ls [--conversation <UUID>] [--limit <N>] [--json]` | 最近のヘッドレス実行を新しい順に一覧表示します。`--limit` は 1〜50、デフォルトは 10 です |
| `chat search <QUERY> [--regex \| --fuzzy [--min-score <SCORE>]] [--json]` | 閲覧できる過去の会話を検索します。クエリはデフォルトでリテラルのテキストとして扱われ、最大 200 文字です。`--regex` は正規表現として読み、`--fuzzy` はタイプミスなどの近い一致を見つけます（`--min-score` は 60〜100、デフォルトは 85）。タイトル、メッセージ本文、ツール名、ツールの入力と出力、添付ファイル名を検索しますが、思考や添付ファイルの内容は検索しません。各一致にはタイトル、会話の UUID、シークレットを隠した抜粋、リンクが表示されます。`--since`、`--until`、`--time-field`、`--type`（`chat`、`headless`、`rca` など、複数指定する場合は繰り返します）で絞り込みます。`--limit` は 1〜50、デフォルトは 10 です。部分的な検索では続きを取得するための `--cursor` が表示され、一致がない部分的な検索は終了コード 1 で終了します。エージェントの実行は開始せず、モデルも使用しません |
| `chat trace <CONVERSATION_ID> [--limit <N>] [--json]` | 会話の最近のメッセージ、ツール名、失敗、使用量を表示します。ツールの引数、ツールの出力、思考は除外され、古いメッセージには上限があるため、完全な記録ではありません。実行 ID ではなく会話 ID を指定します。エージェント CLI のセッションには対応していません |

`--json` なしでは、stdout には回答だけが出力され、進捗と `continue_with=` の行は stderr に出力されます。[ヘッドレスチャット](/ja/guide/cli/headless-chat)を参照してください。

## Review

ローカルの Git の変更をレビューするか、CloudThinker がマージリクエストやプルリクエストですでに実行している [Review](/ja/guide/code-review/overview) を読みます。

| コマンド | 説明 |
|---|---|
| `review` | ステージ済み、未ステージ、未追跡の変更を `HEAD` と比較してレビューします |
| `review --base <REF>` | `REF` とのマージベースからのブランチの差分を、未コミットの編集も含めてレビューします |
| `review status <MR_URL>` | 概要: プロバイダー、タイトル、ステータス、判定、検出事項の数 |
| `review findings <MR_URL>` | 検出事項を、重大度の高い順に一覧表示します |
| `review findings <FINDING_ID>` | 検出事項を 1 件読みます |
| `review --no-upload` | ローカルレビューの検出事項を CloudThinker に送らず、このマシンに保持します |
| `review setup`、`review doctor` | 共有 Worker で Loupe を準備するか、Worker の前提条件を確認します |
| `review watch <MR_URL>` | レビューが完了するまでポーリングします |

すべての review コマンドは `--json` を受け付けます。`review` と `review watch` は、`--timeout <SECS>`（デフォルト 2400。ローカルの `review` では、大きな差分のすべての部分を合わせた合計）と、`--fail-on <low|medium|high|critical>`（その重大度以上の検出事項があれば終了コード 6 で終了）も受け付けます。

ローカルの `review` は、読み取り専用のツールでチェックアウトを読み、検出事項をターミナルに表示します。コメントの投稿、修正の適用、Git のインデックスや作業ツリーの変更は行いません。完了後、検出事項を CloudThinker に送信するため、このブランチのプルリクエストの最初の Review がそれらを評価に含めます。`--no-upload` を付けると、検出事項はあなたのマシンにとどまります。ワークスペースの Code Review モデルで実行されるため、差分と読み込んだファイルは CloudThinker のモデルゲートウェイに送られ、ワークスペースのクレジットを使います。[What leaves your machine](/ja/guide/cli/agent#マシンの外に出るもの) を参照してください。

```bash
cloudthinker review --base origin/main --fail-on high
cloudthinker review findings https://github.com/acme/api/pull/412 --json
```

| フィールド | 値 |
|---|---|
| Review のステータス | `queued`、`in review`、`review complete`、`filtered`、`failed`、`stopped` |
| Review の判定 | `in review`、`approved`、`review suggested`、`changes requested`、`filtered`、`failed`、`stopped` |

`filtered` はリポジトリのフィルターがマージリクエストをスキップしたことを意味し、レビューは実行されていません。`review suggested` は、確認する価値のある検出事項があるものの、ブロックするものはないことを意味します。終了コード: `--fail-on` に該当せずに完了したレビューは 0 で終了し、`filtered` や `stopped` のものも同様です。`failed` のレビュー、またはレビューのない MR URL は 1 で終了します。`--timeout` を超えた待機は 4 で終了します。

## インシデントと推奨事項

| コマンド | 説明 |
|---|---|
| `incident ls [--status <STATUS>] [--limit <N>] [--json]` | [インシデント](/ja/guide/incident/overview)を新しい順に一覧表示します。`--limit` は 1〜100、デフォルトは 25 です |
| `incident status <ID> [--wait] [--timeout <SECS>] [--json]` | インシデントを表示します。`--wait` はクローズされるまでブロックします |
| `recommendations ls [--status <STATUS>] [--limit <N>] [--json]` | [コストの推奨事項](/ja/guide/cost-optimization/recommendations)を月間の削減額とともに一覧表示します。`--limit` は 1〜100、デフォルトは 25 です |

インシデントのステータス: `open`、`acknowledged`、`investigating`、`identified`、`on-hold`、`not-found`、`false-alarm`、`resolved`、`auto-resolved`。`not-found` は検索エラーではなくステータスです。調査で、証拠に裏付けられた根本原因が見つからなかったことを意味します。`incident status --wait` は、インシデントが `resolved`、`auto-resolved`、`false-alarm`、`not-found` のいずれかになると 0 で終了します。先に `--timeout` を超えた場合は 4 で終了します。

推奨事項のステータス: `pending`、`in-progress`、`implemented`、`ignored`。

## Cyber

セキュリティテストを実行するには、エージェントを起動して平易な言葉で依頼します（例: "Test http://localhost:3000 for security issues"）。以下のコマンドは結果を確認するためのものです。[Cyber](/guide/security/cyber-overview) を参照してください。

| コマンド | 説明 |
|---|---|
| `cyber app ls` | このワークスペースがテストするアプリを一覧表示します |
| `cyber domain ls` | ワークスペースのドメインと、その所有権の証明を一覧表示します |
| `cyber domain add <DOMAIN>` | DNS TXT レコードで所有権を証明するドメインを追加します。[Register the app](/ja/guide/security/security-testing#アプリを登録する) を参照してください |
| `cyber domain verify <ID>` | ドメインの所有権の証明を再確認します |
| `cyber run status <RUN_ID> [--wait]` | 実行の状態と検出事項の数を表示します。実行を一覧表示するコマンドはありません。実行 ID は、エージェントがテスト実行を開始したときの出力にあります |
| `cyber run cancel <RUN_ID>` | 実行中のテストを停止します |
| `cyber finding ls <APP_ID>` | アプリの検出事項を一覧表示します。フィルター: `--severity`、`--status`、`--triage`。ページング: `--page`（1 から、デフォルト 1）と `--take`（1 ページあたり、デフォルト 50） |
| `cyber finding get <FINDING_ID>` | 検出事項を 1 件表示します |
| `cyber finding export <APP_ID> [--finding-id <ID>]` | 検出事項を PDF レポートとしてエクスポートします。ローカルファイルは書き出さず、`filename` と、取得元の `download_url` を表示します |
| `cyber config show`、`get <KEY>`、`set <KEY> <VALUE> [--user]` | このプロジェクトの Cyber 設定、またはあなたのデフォルト設定を読み取り・変更します |
| `cyber doctor [--fix]` | このマシンでローカルの Cyber テストを実行できるかを確認します。`--fix` は不足しているツールをインストールします |

すべての Cyber コマンドは `--json` を受け付けます。

`finding ls` のフィルター値: `--severity` は `critical`、`high`、`medium`、`low`、`info`。`--status` は `open`、`resolved`、`dismissed`、`needs-verification`。`--triage` は `none`、`in-progress`、`awaiting-retest`。

`cyber doctor --fix` は、固定バージョンの `httpx` と `katana` をホームフォルダーの `~/.cloudthinker/tools/` にインストールするため、`sudo` は不要です。`curl` がない場合は報告しますが、インストールはしません。

`cyber config` は、プロジェクトの `.cloudthinker/config.toml` と、あなたのデフォルト（`--user`）用の `~/.cloudthinker/config.toml` を読み込みます。設定した値は、導出された値より優先されます。`cyber config show` は両方を一覧表示します。

| キー | 意味 |
|---|---|
| `app` | このプロジェクトがテストするアプリ |
| `repo_path` | リポジトリのルート。設定されていない場合は Git から導出されます |
| `auth.<role>` | そのテスト ID の認証ヘッダーを保持する環境変数の名前。シークレットそのものではありません。プロジェクトファイルでは `CYBER_<ROLE>_AUTH` でなければなりません |
| `context.<name>` | OpenAPI 仕様、Postman コレクション、HAR ファイルなど、テストのコンテキストへのパスまたは URL |

## Public API

| コマンド | 説明 |
|---|---|
| `api <module>.<resource>.<verb> [IDS…] [--<param> <VALUE>]` | Public API の操作を 1 つ呼び出し、その JSON を表示します。クエリパラメーターはフラグになります |
| `api … --all` | すべてのページをたどり、全項目（最大 10,000 件）を表示します |
| `api … --body <JSON or @FILE or ->` | リクエストボディをインライン、ファイル、または stdin から送信します |
| `api … --set <KEY=VALUE>` | ボディのフィールドを 1 つ設定します |
| `api … --key <KEY>` | `Idempotency-Key`。省略すると新しいキーが送信されます |
| `api … --etag <ETAG>` | 更新時の `If-Match` の値。読み取りでは stderr に `ETag: …` が表示されます |
| `api <METHOD> <PATH> [--query <NAME=VALUE>]` | メソッドとパスに一致する操作を呼び出します。`--query` はこの形式でのみクエリパラメーターを渡します。複数ある場合は繰り返します |
| `api … --yes` | 事前に確認する操作で、確認をスキップします。ターミナルがない場合は必須です |
| `api --list [--json]` | すべての操作を、コマンド、名前、メソッド、スコープとともに一覧表示します |
| `<module> <resource> <verb>` | `review reviews list` など、モジュール形式での同じ呼び出し |

[CLI for the Public API](/guide/cli/api) を参照してください。

## 接続、エージェント、Policy

TARGET は、`connections list` の接続 ID、エイリアス、またはプレフィックスです。

| コマンド | 説明 |
|---|---|
| `connections list [--json]`（エイリアス `ls`） | 選択中のワークスペースに追加された[接続](/ja/guide/connections/overview)を一覧表示します |
| `connections show <TARGET> [--json]` | Connection を 1 つ表示します: 種類、ステータス、接続先。認証情報は表示されません |
| `connections status <TARGET> [--wait] [--timeout <SECS>] [--json]` | 最新のテストを表示します。`--wait` は終了するまでブロックし、失敗した場合は 1 で終了します |
| `connections retry <TARGET> [--wait] [--timeout <SECS>] [--json]` | 組み込みの Connection を、保存された認証情報で再テストします（ワークスペース管理者） |
| `connections disconnect <TARGET> [--json]` | Connection とその保存された認証情報を削除します（ワークスペース管理者）。事前に確認します。`--yes` は確認をスキップし、ターミナルがない場合は必須です |
| `connections connect-url <PREFIX> [--wait] [--timeout <SECS>] [--json]` | `aws` や `github` など、Connection を追加するページを表示し、デスクトップでは開きます。認証情報はブラウザにとどまります。`--wait` は新しい Connection の最初のテストを追跡します |
| `agents ls [--json]` | ワークスペースのエージェントと、それぞれを `chat --agent` で選べるかを一覧表示します |
| `agents show <UUID_OR_ALIAS> [--json]` | エージェント 1 つの ID、説明、チャットで選べるかを表示します。エイリアスは大文字小文字を区別せず完全一致で照合されます |
| `policy export [--output <PATH>]` | ワークスペースの Policy を YAML で表示するか、新しいプライベートファイルに書き出します |
| `policy import <PATH> [--apply] [--prune] [--activate] [--json]` | YAML または JSON の Policy ファイルのインポートをプレビューします。書き込むのは `--apply` だけです。`--prune` は存在しない Rules を却下し、省略されたオーバーライドを消去します。`--activate` はインポートした Allow Rules をオンにします |

## 環境

`worker` はこのマシンを環境として実行し、チャットやオートメーションがここのフォルダーで作業できるようにします。完全なガイド: [Environments](/guide/workers)。

| コマンド | 説明 |
|---|---|
| `worker outpost create <NAME> [--shared]`、`ls`、`archive <OUTPOST>` | 環境を登録、一覧表示、または廃止します |
| `worker start --outpost <OUTPOST> --workdir <DIR>` | 中断されるまで 1 つのフォルダーを提供します。`--background` はターミナルを閉じた後も実行を続けます |
| `worker service install`、`uninstall`、`status`、`start`、`stop` | 環境を systemd（Linux）または launchd（macOS）で実行します。`install --system --user <ACCOUNT>`（root として）はマシン全体のサービスをインストールします |
| `worker status --outpost <OUTPOST>` | ワークスペースから見た環境の可用性を表示します |
| `worker doctor` | このマシンで環境を実行できるかを確認し、問題ごとに対処法を 1 つ示します |
| `worker worktrees ls`、`prune` | 会話用に作成された Git の worktree を一覧表示またはクリーンアップします |

## 更新とシェル補完

| コマンド | 説明 |
|---|---|
| `update` | CLI とエージェントの最新リリースを一緒にインストールします |
| `update --force` | すでに最新でも再インストールします |
| `update --version <VERSION>` | 最新版の代わりに、そのリリース（古くても新しくても）をインストールします（例: `0.12.2`）。ホストの固定やロールバックに使います。リリースされたことのないバージョンは 2 で終了します |
| `update --json` | 結果を JSON で表示します |
| `completion <bash\|zsh\|fish\|…>` | シェル補完スクリプトを表示します |

対話型のターミナルでは、新しいリリースがあると、CLI が最大 20 時間ごとに更新を提案します。`update` は CLI インストーラーで作成したインストールでのみ動作します。それ以外のインストールでは拒否し、再インストールのコマンド `curl -fsSL https://cloudthinker.io/install.sh | sh` を表示します。[CLI の概要](/ja/guide/cli/overview)を参照してください。

```bash
cloudthinker completion zsh > "${fpath[1]}/_cloudthinker"
cloudthinker completion bash > ~/.local/share/bash-completion/completions/cloudthinker
cloudthinker completion fish > ~/.config/fish/completions/cloudthinker.fish
```

`${fpath[1]}` に書き込めない場合は、zsh のファイルを自分のフォルダーに保存し、`~/.zshrc` で `compinit` の前にそのフォルダーを `fpath` に追加します。

## 環境変数

| 変数 | 効果 |
|---|---|
| `CLOUDTHINKER_URL` | `--url` と同じ |
| `CLOUDTHINKER_WORKSPACE` | `--workspace` と同じ |
| `CLOUDTHINKER_TOKEN` | 保存されたログインの代わりに使う、個人（`ct_pat_`）またはサービスアカウント（`ct_sat_`）の [API トークン](/guide/api/tokens)、または `auth token` のトークン。API トークンは `chat`、`incident ls` と `incident status`、Public API のコマンド、`api` 向けです。その他のほとんどのコマンドには、ログインまたは `auth token` のトークンが必要です。`review setup` と `doctor` 以外では、`--workspace` や `CLOUDTHINKER_WORKSPACE` と併用できません |
| `CLOUDTHINKER_LOGIN` | `browser` または `device` で、このマシンのログインフローを強制します |
| `CLOUDTHINKER_NO_UPDATE_CHECK` | `1` に設定すると更新の提案をオフにします |
| `CLOUDTHINKER_OUTPOST_ID` | `worker` コマンドのデフォルトの環境 |
| `CLOUDTHINKER_CONFIG_DIR` | 認証情報と worker の状態を、プラットフォームの設定フォルダーではなくこのフォルダーに保存します。1 つの OS アカウントを共有する人が、それぞれ自分のログインを保てます |
| `CLOUDTHINKER_RELEASE_URL` | `https` のミラー、`file://` の URL、または `<base>/v<version>/<asset>` の構成のローカルフォルダーからエージェントをインストールします。チェックサムの確認は同じです |
| `CLOUDTHINKER_REMOTE` | `0` に設定すると、SSH 経由の引数なしの `cloudthinker` を、接続が切れても生き残るバックグラウンドエージェントではなく、現在のシェルで実行します |
| `CLOUDTHINKER_AUTO_BACKGROUND_SECONDS` | エージェントが長いシェルコマンドをバックグラウンドに移すまでの秒数。デフォルトは 10、`0` でオフ |
| `NO_COLOR` | stderr の色をオフにします。stderr がターミナルでない場合も色はオフです |
| `HTTPS_PROXY`、`ALL_PROXY` | CLI の通信をこのプロキシ経由で送信します。`NO_PROXY` のホストはプロキシを経由しません |
| `SSL_CERT_FILE`、`SSL_CERT_DIR` | HTTPS を再署名するプロキシ向けに、この CA バンドルまたはフォルダーを信頼します。設定しない場合、CLI は OS の信頼ストアを使います |

## 終了コード

| コード | 意味 |
|---|---|
| 0 | 成功 |
| 1 | ジョブが失敗した: 実行の失敗、不明な実行またはレビュー、競合やレート制限などのサーバーエラー、ネットワークの再試行の上限到達 |
| 2 | 使い方の誤り、またはサーバーがリクエストを無効として拒否した（HTTP 422） |
| 3 | 未ログイン、認証情報の期限切れ、またはアクセス拒否 |
| 4 | CLI が待機を止めた。作業はサーバー上で継続します |
| 5 | 実行がブラウザでの承認待ちで一時停止した |
| 6 | レビューが `--fail-on` の重大度以上の問題を検出した |
| 130 | Ctrl-C で `chat` の待機、`incident status --wait`、または `login` を停止した。実行やインシデントはサーバー上で継続します |

## ファイル

| パス | 内容 |
|---|---|
| `~/.local/bin/cloudthinker` | インストーラーが `PATH` に配置するバイナリ |
| `~/Library/Application Support/cloudthinker/credentials.json`（macOS）、`$XDG_CONFIG_HOME/cloudthinker/credentials.json` または `~/.config/cloudthinker/credentials.json`（Linux）、設定時は `$CLOUDTHINKER_CONFIG_DIR/credentials.json` | ホストごと、ワークスペースごとに 1 つのログイン |
| `~/.cloudthinker/agent/` | `settings.json` を含むエージェントの設定 |
| `~/.cloudthinker/agent/bin/<version>/` | その CLI バージョン用のエージェントビルド |
| `~/.cloudthinker/agent/sessions/` | ローカルのエージェントセッションのトランスクリプト |
| `~/.cloudthinker/tools/` | `cyber doctor --fix` がインストールしたツール |
| `.cloudthinker/config.toml` | プロジェクト用に保存された Cyber 設定（そのプロジェクトのフォルダー内） |
| `~/.cloudthinker/config.toml` | `cyber config set --user` によるあなたのデフォルトの Cyber 設定 |

`credentials.json` は、`0700` のフォルダー内にあるファイルモード `0600` のプレーンな JSON で、あなたのユーザーだけが読めます。CLI は OS のキーチェーンを使いません。0.5.3 より前のリリースは使っていたため、新しいリリースの初回実行時にそれらのログインをファイルに移し、キーチェーンのエントリを削除します。他の人もログインするマシンでは、各人に専用の OS アカウントを用意し、作業が終わったら `cloudthinker logout --all` を実行してください。

### アンインストール

1. このマシンで環境をサービスとして実行している場合は、`cloudthinker worker service uninstall` を実行します。
2. ログインしたホストごとに `cloudthinker logout --all` を 1 回実行します。デフォルト以外のホストには `--url` を使います。または `credentials.json` を削除します。
3. バイナリ `~/.local/bin/cloudthinker` を削除します。
4. `~/.cloudthinker` フォルダーと、保存した補完スクリプト（`"${fpath[1]}/_cloudthinker"` など）を削除します。
5. 任意: プロジェクト内の `.cloudthinker/` フォルダーを削除します。

スキルとは、`SKILL.md` ファイルとして保存される、文書化された手順やルールの集まりで、目の前のタスクが一致するときにエージェントがそれに従います。トリアージの手順、レビューのチェックリスト、命名規則を一度書けば、プロンプトのたびに繰り返さなくてもエージェントがそれを適用します。

## スキルを使う場面

エージェントに一歩ずつ従わせたいものにはスキルを使います。「CPU を確認し、次にクレジット、次にトラフィック」というトリアージの runbook、レビューのチェックリスト、タグ付けのポリシーなどです。スキルはエージェントの作業方法を変えます。スキルは `SKILL.md` ファイルで、CloudThinker で書くか、`.zip` でアップロードします。

スキルは、CloudThinker に与えるコンテキストを保持するいくつかの場所の 1 つです。[Teach CloudThinker](/guide/teach-cloudthinker) でそれらすべてを比較しています。

## スキルが使われる仕組み

スキルが使われるのは、次の 3 つがすべて満たされる場合だけです。

1. **有効になっている。** スキルのスイッチがオンになっています。新しいスキルは有効な状態で始まります。
2. **その場所で利用できる。** 作業が行われる場所が、**Available in** でチェックされています（下の表を参照）。新しいスキルは **Chat** だけで始まります。これは `/` にも当てはまります。`/` メニューには有効なすべてのスキルが一覧されますが、**Chat** がチェックされていないとチャットはそれを使えず、エージェントはそれなしで作業を続けます。名前で実行する予定のスキルには、**Chat** をチェックしてください。
3. **タスクに合っている。** Review を含むすべての場所で、エージェントはそこで利用できるスキルだけを見て、名前と説明が作業に一致するものを読み込みます。1 つのタスクで複数のスキルを読み込むこともあります。そのため、説明はリクエストの言葉で書いてください。悪い例: "CPU stuff"。良い例: "Investigate high CPU or a slow EC2 instance"。

| 場所 | 実行される場所 |
|---|---|
| **Chat** | ワークスペースのチャットと、オートメーションや Webhook など独自の場所を持たない実行 |
| **Review** | [Review](/ja/guide/code-review/overview) でのマージリクエストとプルリクエストのレビュー |
| **Incident** | [Resolve](/ja/guide/incident/overview) でのインシデントの分析と根本原因 |
| **Assessment** | Well-Architected とポスチャーのアセスメント |

スキルを名前で実行することもできます。チャットのプロンプトボックスで `/` を入力し、メニューから選びます。エージェントがスキルを使うと、そのアクティビティに **Load Skill** のステップが表示されます。

CloudThinker は、すぐに使えるスキルを [Skills Hub](https://www.cloudthinker.io/skills) でも公開しています。インストールしたハブのスキルは、自分のものと同様に管理するワークスペースのスキルになり、ハブのバージョンが変わっても変わりません。インストールするには、[カスタムスキル](/ja/guide/skills/custom-skills#スキルを作成する)を参照してください。

新しいワークスペースのスキルの一覧は空で始まります。`pdf`、`docx`、`pptx`、`xlsx`、`deep-research` など、CloudThinker の組み込みのスキルはセットアップなしで機能します。それらは一覧に表示されないため、編集やオフにすることはできません。その名前は予約されており、自分のスキルでは使えません。

## 誰が何をできるか

**Settings → Workspace → Skills** でスキルを作成、編集、関連付け、削除できるのは、ワークスペースの **Admin** だけです（スイッチのオン・オフと **Available in** の変更を含みます）。Developer はスキルの一覧を見て、`/` でスキルを実行できます。Viewer はスキルを見られますがチャットできないため、実行できません。[ロール](/guide/security/roles)を参照してください。

<Note>
Admin なしでスキルを追加する方法が 2 つあり、どちらもすべてのエージェントの **Chat** で有効になります。

- **チャットでの `/creating-skill`。** チャットできるメンバーなら誰でも実行でき、エージェントが自らスキルを書きます。
- **[Learning Mode](/ja/guide/agents/customize#learning-mode)。** **Auto** または **Offer** のカスタムエージェントは、チャットからスキルを保存します。[Audit Logs](/guide/security/audit-logs) にはこれらは記録されません。すべてのスキルを Admin が用意すべき場合は **Off** に設定してください。

ときどき **Settings → Workspace → Skills** を確認してください。Admin はそこで、これらのスキルのいずれもオフにしたり、範囲を変えたり、削除したりできます。
</Note>

## スキルの作成方法

| 方法 | 最適な用途 |
|---|---|
| **Create with CloudThinker** | 最初のスキル: CloudThinker があなたに質問し、ファイルの下書きを作成します |
| **Write skill instructions** | すでに分かっているルール: 名前、説明、指示のフォーム |
| **Upload zip file** | リポジトリで管理しているスキルや、スクリプトと参照ファイルを含むスキル |
| **Browse skills hub** | CloudThinker のすぐに使えるスキル（セルフホストのインストールでは利用できません） |

手順は[カスタムスキル](/ja/guide/skills/custom-skills)にあります。ファイル自体については、[スキルの形式](/ja/guide/skills/skill-format)を参照してください。

カスタムスキルとは、レビューのチェックリスト、エスカレーションの順序、タグ付けの規則など、チームの仕事の進め方を CloudThinker に教える、文書化された指示のセット（`SKILL.md` ファイル）です。**Settings → Workspace → Skills** で一度書けば、利用可能にした場所でエージェントがそれを適用するため、同じルールをプロンプトのたびに入力し直す必要がなくなります。

## スキルを書くべきとき

同じ指示を繰り返していることに気づいたら、スキルを書きましょう。典型的な例を挙げます。

| 領域 | スキルに持たせられるルールの例 |
|---|---|
| Review | 「文字列連結で組み立てた SQL をすべて指摘する。パラメータ化クエリを必須にする。」 |
| Incident | 「アプリケーションの Pod より先に、ロードバランサーとデータベースを確認する。」 |
| クラウド運用 | 「すべてのリソースに `team`、`env`、`cost-center` タグが必要。」 |
| レポート | 「成果、阻害要因、次のステップの3つのセクションで要約する。」 |

スキルは、エージェントに**どう行動するか**を伝えます。[スキルを使うべきとき](/ja/guide/skills/overview#スキルを使う場面)を参照してください。

## 前提条件

- 使う方法に応じた適切なロール。Developer と Viewer はスキルを閲覧できますが、**+** ボタンや **New skill** は表示されません。[ロール](/guide/security/roles)を参照してください。

| 方法 | 使える人 |
|---|---|
| **Write skill instructions**、**Upload zip file**、編集、削除 | ワークスペースの Admin |
| チャットでの `/creating-skill`（Admin にはメニューに **Create with CloudThinker** も表示されます） | チャットできるすべてのメンバー（Admin または Developer） |
| **Skills Hub** のインストールリンク | ワークスペースのすべてのメンバー |
- `SKILL.md` を手で書くか、パッケージをアップロードする予定であれば、[スキルの形式](/ja/guide/skills/skill-format)にざっと目を通してください。

## スキルを作成する

<Steps>
  <Step title="Skills を開く">
    **Settings → Workspace → Skills** に移動します。ページの左側にワークスペースのスキルの一覧が、右側に選択したスキルが表示されます。
  </Step>
  <Step title="新しいスキルのメニューを開く">
    スキル一覧の上部にある **Search skills** の横の **+** ボタンをクリックします（スキルがまだない場合は、代わりに **New skill** ボタンが表示されます）。メニューから作成方法を1つ選びます。選んだ方法については、下のタブを参照してください。
  </Step>
  <Step title="スキルを作成する">
    <Tabs>
      <Tab title="Create with CloudThinker">
        最初のスキルに最適です。CloudThinker がヒアリングを行い、ファイルの下書きを作成します。

        1. **Create with CloudThinker** をクリックします。`/creating-skill` コマンドが入力された状態でチャットが開きます。
        2. それを送信し、質問に答えます。チームが適用している具体的なルールを1つ、例とともに説明してください。
        3. CloudThinker が提案する下書きを確認します。**Proceed with creating this skill?** と尋ねられたら、**Yes, create it** を選ぶか、**Change something** を選んで変更点を伝えます。その後、**Settings → Workspace → Skills** を開き、スキルが存在し、有効で、**Chat** で利用可能になっていることを確認します。

        同じフローは、任意のチャットで `/creating-skill` と入力して開始することもできます。通常のチャットなので、クレジットを消費します。**Yes, create it** を選ぶまでは何も保存されないため、途中でやめても作りかけのスキルは残りません。
      </Tab>
      <Tab title="Write skill instructions">
        正確なルールがすでに分かっている場合に最適です。

        1. **Write skill instructions** をクリックします。
        2. フォームに入力します。

        | フィールド | 入力する内容 |
        |---|---|
        | **Skill name** | 英字または数字で始まり、その後に英字、数字、`_`、`-` が続きます。例：`weekly-status-report`。最大255文字です。 |
        | **Description**（必須） | エージェントがスキルを使うべきとき。例：「Generate weekly status reports. Use when asked for updates or progress summaries.」必ず入力してください。エージェントは説明でスキルを選び、説明がないと CloudThinker はスキルを保存できません。最大2,000文字です。 |
        | **Instructions** | Markdown で書いたルール。最大50,000文字です。 |

        3. **Create** をクリックします。

        貼り付けて使える完全な例です。[スキルをテストする](#スキルをテストする)でも再び使います。

        - **Skill name:** `weekly-status-report`
        - **Description:** `Generate weekly status reports. Use when asked for updates or progress summaries.`
        - **Instructions:**

        ```markdown
        # Weekly status report

        Write the report in exactly three sections, in this order:

        ## Wins
        What shipped or finished this week. One bullet per item, with the owner.

        ## Blockers
        What is stuck, why, and who can unblock it. Write "None" if nothing is blocked.

        ## Next steps
        What the team will do next week. One bullet per item, with the owner.

        Keep the whole report under 200 words. No other sections.
        ```
      </Tab>
      <Tab title="Upload zip file">
        リポジトリで管理しているスキルや、ワークスペース間で共有するスキルに最適です。

        1. **Upload zip file** をクリックします。
        2. `SKILL.md` を含む `.zip` をドロップします。フォルダー構成と制限については、[zip パッケージの構成](/ja/guide/skills/skill-format#zip-パッケージの構成)を参照してください。
        3. **Upload** をクリックします。

        zip のファイル名が既存のスキルと一致する場合（例：`weekly-status-report.zip`）、CloudThinker はそれを **Replace** するかどうかを尋ねます。**Replace** は古いスキルを削除して新しいスキルをアップロードするため、スイッチはオンに戻り、**Available in** は **Chat** のみにリセットされます。その後、ほかの利用場所にもう一度チェックを入れてください。Scale 以上では、[Audit Logs](/guide/security/audit-logs) に削除とアップロードの両方が記録されます。いずれにしても、古いファイルと設定は失われます。

        一致の判定は zip のファイル名で、大文字と小文字を含めて完全一致で行われます。zip の名前が既存のスキルと一致していてもフロントマターの `name` が異なる場合、**Replace** は一致したスキルを削除したうえで、新しいスキルをフロントマターの名前でアップロードします。
      </Tab>
      <Tab title="Browse skills hub">
        ハブは別のサイトです。CloudThinker を離れてスキルを選び、そのインストールリンクから戻ってきます。

        1. **Browse skills hub** をクリックします。公開カタログが新しいタブで開きます。
        2. 使いたいスキルを見つけます。
        3. そのインストールリンクをクリックします。CloudThinker がワークスペースで **Install Skill** ページを開きます。
        4. **Install** をクリックします。スキルがスキル一覧に追加され、**Chat** でのみ有効になります。

        インストールしたハブのスキルは、ハブ側のバージョンが変わっても更新されません。同じ名前のスキルがすでにワークスペースにある場合、インストールは **Skill already installed in this workspace** というエラーで失敗します。
      </Tab>
    </Tabs>

    **成功状態：** スキルがスイッチがオンの状態で一覧に表示され、**Available in** で **Chat** にチェックが入っています。
  </Step>
</Steps>

## スキルを適用する場所を選ぶ

新しいスキルは有効な状態で、Chat でのみ利用可能な状態から始まります。ほかの領域はオンにするまでオフのままなので、テストが不十分なルールがレビューやインシデント対応を変えてしまうことはありません。

<Steps>
  <Step title="スキルを選択する">
    **Settings → Workspace → Skills** で、一覧からスキルをクリックします。
  </Step>
  <Step title="Available in で領域にチェックを入れる">
    スキルを適用する場所にそれぞれチェックを入れます。

    | オプション | エージェントが使う場所 |
    |---|---|
    | **Chat** | ワークスペースのチャット、および自動化と Webhook |
    | **Review** | このワークスペースで CloudThinker がレビューするすべてのマージリクエストとプルリクエスト。接続されたすべてのリポジトリが対象で、レビューが自動で始まった場合も `@cloudthinker-ai review` コメントから始まった場合も含みます。[Review](/ja/guide/code-review/overview) を参照してください。 |
    | **Incident** | [Resolve](/ja/guide/incident/overview) でのインシデント分析と根本原因の調査 |
    | **Assessment** | Well-Architected とポスチャーのアセスメント |

    スキルを一時停止するには、すべてのチェックを外すのではなく、スイッチを使ってください。

    <Warning>
    **Review** にはリポジトリごとのフィルターがありません。チェックを入れると、すべてのリポジトリの次のレビューにスキルが適用されます。まず **Chat** でスキルをテストし、その後 [スキルをテストする](#スキルをテストする) の Review のテストに従ってください。
    </Warning>
  </Step>
  <Step title="スイッチがオンになっていることを確認する">
    スキル名の横のスイッチで、スキルを有効または無効にします。無効にしたスキルは保存されたままですが、どのエージェントも使いません。
  </Step>
</Steps>

## スキルをテストする

<Steps>
  <Step title="ルールが重要になるタスクを実行する">
    両方の方法を、それぞれ新しいチャットで試してください。**Write skill instructions** タブの `weekly-status-report` の例では次のようになります。

    名前を指定して実行します（`/` を入力してメニューから選びます）。

    ```text
    /weekly-status-report Notes: shipped the new login page (Ana). Billing export blocked on finance sign-off (Raj). Next week: start the search rewrite (Ana).
    ```

    名前を指定せずに実行します。

    ```text
    Write a status update for the platform team from these notes: shipped the new login page (Ana). Billing export blocked on finance sign-off (Raj). Next week: start the search rewrite (Ana).
    ```

    エージェントが実際の内容を扱えるよう、このようなメモを貼り付けてください。メモや接続されたトラッカーがないと、報告する内容がないため、代わりに質問してくることがあります。**Wins**、**Blockers**、**Next steps** の3つのセクションがあり、それぞれに担当者付きの箇条書きが1つずつ含まれることを期待してください。

    **成功状態：** エージェントのアクティビティに **Load Skill** ステップが表示され、ルールを繰り返し伝えなくても、両方の回答がスキル（ここでは成果、阻害要因、次のステップの構成）に従っています。
  </Step>
  <Step title="うまくいったら適用範囲を広げる">
    Chat で何度か良い結果が出たら、**Review**、**Incident**、**Assessment** にチェックを入れ、そこでの次の実行を確認します。Review にはサンドボックスがないため、次のようにテストします。

    1. **Review** にチェックを入れます。
    2. Review の対象になっている検証用リポジトリで、小さなプルリクエストを作成します。ドラフトとして作成しないでください。ドラフトは準備完了にするまでレビューされません。または、既存のプルリクエストに `@cloudthinker-ai review` とコメントします。
    3. レビューがスキルに従っていることを確認します。従っていない場合は、チェックが入っている間はすべてのリポジトリがそのスキルを使うため、すぐに **Review** のチェックを外してください。

    そのリポジトリには CloudThinker アプリがインストールされている必要があります。[Review のセットアップ](/ja/guide/code-review/setup)と[メンションコマンド](/ja/guide/code-review/mention-commands)を参照してください。
  </Step>
</Steps>

出力がルールを無視する場合は、ルールをより具体的にし、良い例と悪い例を追加してください。「スタイルに従う」のような曖昧な指示では、結果はほとんど変わりません。

## スキルを編集、ダウンロード、削除する

スキルを選択し、**Available in** の横にあるアイコンボタンを使います。アイコンにカーソルを合わせると名前が表示されます。

| 操作 | 方法 | 補足 |
|---|---|---|
| CloudThinker で編集する | 鉛筆アイコン（**Edit skill**）→ **CloudThinker** | スキルを読み込んだチャットが開き、改善を手伝います。 |
| 手で編集する | 鉛筆アイコン（**Edit skill**）→ **Manual** | `SKILL.md` だけを編集します。**Preview** で表示を確認してから **Save** します。フロントマターの `name` は変更しないでください。`references/`、`scripts/`、`schemas/` のファイルを変更するには、スキルをダウンロードして編集し、**Replace** で `.zip` をアップロードします。**Replace** は **Available in** を **Chat** のみにリセットするため、ほかの利用場所にもう一度チェックを入れてください。 |
| ダウンロードする | ダウンロードアイコン（**Download**） | スキルを `.zip` として保存し、別のワークスペースにアップロードできます。 |
| 削除する | ゴミ箱アイコン（**Delete**） | 完全に削除されます。 |

<Warning>
スキルの削除は元に戻せず、編集をロールバックするためのバージョン履歴もありません。編集や削除の前に `.zip` をダウンロードするか、後でまたスキルが必要になりそうなら、代わりにスイッチをオフにしてください。
</Warning>

[Audit Logs](/guide/security/audit-logs) は、**Settings → Workspace → Skills** でスキルを作成、アップロード、編集、適用範囲の変更、削除した人を記録します。ただし、記録されるのは Scale と Enterprise のみで、エージェントがチャットから保存したスキルは対象外です。ほかのプランではスキルの変更は何も記録されないため、すべてのスキルの `.zip` をリポジトリで管理し、変更はそこからアップロードしてください。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="This skill name is already in use">
    このワークスペースの別のスキルがその名前を使っています。別の名前を選ぶか、`.zip` をアップロードして **Replace** を選び、既存のスキルを上書きしてください。
  </Accordion>
  <Accordion title="This skill name is reserved">
    その名前は、`pdf`、`docx`、`deep-research` などの CloudThinker の組み込みスキルと一致しています。別の名前を選んでください。
  </Accordion>
  <Accordion title="Failed to create skill">
    フォームでは **Description** を空のまま送信できますが、その場合は保存がこのエラーで失敗します。スキルを使うべきときを1文で追加し、もう一度 **Create** をクリックしてください。説明を入力しているのにこのエラーが出る場合は、スキルストアがファイルを受け付けなかったため、もう一度試してください。
  </Accordion>
  <Accordion title="This skill file could not be saved">
    スキルファイルを保存するサービスがアップロードを拒否しました。通常は、`SKILL.md` のフロントマターがない、無効である、または `name` や `description` がないことが原因です。[スキルの形式のトラブルシューティング](/ja/guide/skills/skill-format#トラブルシューティング)を参照してください。
  </Accordion>
  <Accordion title="Only .zip files are accepted">
    アップロードは `.zip` のみを受け付けます。`SKILL.md`（および `scripts/`、`schemas/`、`references/` フォルダー）を1つのフォルダーにまとめて zip にし、その zip をアップロードしてください。
  </Accordion>
  <Accordion title="No agent can load this skill">
    これは **Settings → Workspace → Skills** のスキルの詳細パネルにアラートとして表示されます。スキルの `SKILL.md` のフロントマターに使用可能な `description` がありません。多くの場合、手動編集で `description:` 行が削除されたか壊れたことが原因です。手で編集して `description:` 行を追加し、**Save** をクリックしてください。それまでは、スキルは `/` メニューに表示されません。
  </Accordion>
  <Accordion title="Cannot preview this skill">
    スキルのファイルの内容を読み込めません。**Recovery with AI** をクリックして短いヒアリングを通じて CloudThinker で `SKILL.md` を再構築するか、**Re-upload** をクリックして保管している `.zip`（以前にダウンロードしたものなど）から復元してください。
  </Accordion>
  <Accordion title="エージェントがスキルを無視する">
    - スイッチがオンになっていることを確認します。
    - **Available in** で適切な領域にチェックが入っていることを確認します（たとえばプルリクエストのレビューなら **Review**）。
    - 指示を具体的にし、例を追加します。長く広範なスキルは、短いスキルに分割します。
  </Accordion>
</AccordionGroup>

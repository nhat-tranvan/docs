ワークスペースとは、[組織](/ja/guide/organization)の中の独立した領域で、独自の接続、エージェント、メモリ、会話、設定を持ちます。あるワークスペースのエージェントとメンバーは、別のワークスペースの接続、データ、会話を使えないため、ワークスペースは本番とステージングを分けておく手段になります。組織の Owner と Admin はすべてのワークスペースを開くことができ、使用量と監査ログはそのすべてを対象にします。

## ワークスペースが持つもの

作業中にセットアップしたものはすべて、現在のワークスペースにあります。

| 領域 | 例 |
|---|---|
| システムへのアクセス | [接続](/ja/guide/connections/overview)と[認証情報](/guide/credentials) |
| エージェントの振る舞い | [カスタムエージェント](/ja/guide/agents/customize)、[スキル](/ja/guide/skills/overview)、[メモリ](/guide/memory) |
| 安全のための制御 | [Approvals](/guide/approvals/overview) のモードとルール |
| 作業と結果 | 会話、[アーティファクト](/ja/guide/artifacts/overview)、[オートメーション](/guide/automation/automations)、Optimize、Review、Cyber、Resolve のデータ |
| 人 | [ワークスペースのメンバー](/ja/guide/workspace-users)とそのワークスペースのロール |

請求、メンバーシップ、SSO、監査ログは、ワークスペースではなく組織に属します。

## レイアウトを選ぶ

ほとんどのチームは 1 つのワークスペースから始め、アクセスやノイズが問題になったときに分けます。

| パターン | 分け方 | 選ぶ場面 |
|---|---|---|
| 環境 | 本番、ステージング、開発 | 本番により厳しい承認と、書き込みアクセスを持つ人の削減が必要な場合 |
| チーム | プラットフォーム、セキュリティ、アプリのチーム | 各チームが異なる接続、スキル、メモリを使う場合 |
| 顧客または事業部 | 顧客ごとに 1 つのワークスペース | 複数のクライアントの運用を担い、そのデータを分けておく必要がある場合 |

例: 12 の AWS アカウントを持つプラットフォームチームは、1 つのワークスペースを使い、アカウントごとに 1 つの接続を追加し、各接続に **Environment**（Production、Staging、Development）を設定して、[承認のルール](/guide/approvals/rules)が本番の変更をより厳しく扱えるようにします。[環境を設定する](/ja/guide/connections/overview#環境を設定する)を参照してください。本番を独自のワークスペースに分けるのは、より厳しい Approvals や別のクレジット上限が必要になったときだけです。

作成できるワークスペースの数はプランによって決まります。[プランと料金](/ja/guide/billing/pricing)を参照してください。

## 前提条件

- ワークスペースの作成や削除には、組織の **Owner** または **Admin** である必要があります。
- ワークスペースの名前の変更や設定の変更には、ワークスペースの **Admin** である必要があります。組織の Owner と Admin は常にそうです。ワークスペースの Admin は、ワークスペースの設定からワークスペースを削除できません。
- Developer と Viewer は、割り当てられたワークスペースでのみ作業できます。

## ワークスペースを作成する

最初のワークスペースはサインアップ時にすでに作成されています。[レイアウトを選ぶ](#レイアウトを選ぶ)のように、別のアクセス、Approvals、データが必要な場合にのみ、別のものを作成してください。

<Tip>
すでに実際の作業がある組織で CloudThinker を試す場合は、試用のために `Eval` のワークスペースを作成してください。終わったら、それを削除すれば、試用の接続と会話が一度に削除されます。
</Tip>

<Steps>
  <Step title="新しいワークスペースを開始する">
    サイドバー上部のワークスペースメニューをクリックし、組織のワークスペースの下にある **New workspace** をクリックします。**Settings → Organization → Workspaces** に移動して **New workspace** をクリックすることもできます。
  </Step>
  <Step title="名前を付ける">
    **Create workspace in &lt;organization&gt;** ダイアログで、**Name**（必須）と任意の **Description** を入力します。`Production` や `Platform team` など、切り替えの一覧で人が認識できる名前を使ってください。
  </Step>
  <Step title="作成する">
    **Create** をクリックします。

    **成功時の状態:** ワークスペースが **Settings → Organization → Workspaces** の一覧とワークスペースメニューに表示されます。
  </Step>
  <Step title="システムを接続する">
    新しいワークスペースは空で始まります。切り替えて[接続](/ja/guide/connections/overview)を追加し、エージェントが作業できるものを用意してください。**No cloud connected** と表示されるワークスペースの行には、まだ接続が必要です。
  </Step>
  <Step title="チームを追加する">
    最初は、新しいワークスペースを見られるのは組織の Owner と Admin だけです。その **Members** ページから Developer と Viewer を追加してください。[ワークスペースのメンバー](/ja/guide/workspace-users)を参照してください。
  </Step>
</Steps>

## ワークスペースを切り替える

サイドバー上部のワークスペースメニューをクリックし、一覧からワークスペースを選びます。他の組織のワークスペースは **Other organizations** の下にあります。**Settings → Organization → Workspaces** から、行の **Go to workspace** をクリックして **Switch workspace** を確定することもできます。

**成功時の状態:** ページが再読み込みされ、サイドバーに新しいワークスペースの名前が表示されます。

## ワークスペースの設定を開く

サイドバー上部のワークスペースメニューをクリックし、**Settings** をクリックします。Settings は **Workspace** タブで開きます。⌘⇧,（Windows と Linux では Ctrl+Shift+,）を押すか、**Settings → Organization → Workspaces** で現在のワークスペースの行の **Settings** をクリックすることもできます。

[Workspace settings](/guide/workspace-settings) には、すべてのページ、そこで設定する内容、誰が見られるかが一覧されています。各ロールが何を変更できるかは、[ワークスペースのロール](/ja/guide/workspace-users#ワークスペースロール)を参照してください。

**BYOK** のページでは、このワークスペースがどの LLM のキーで実行されるかを選びます: 組織のキー、ワークスペースのキー、またはなし。ワークスペースのキーはこのページで設定します。組織のキー自体は、Owner が **Settings → Organization → BYOK** で設定し、Owner はそれをすべての場所で必須にできます。[組織とワークスペースのキー](/ja/guide/byok#組織キーとワークスペースキー)を参照してください。

## ワークスペースの名前を変更する

<Steps>
  <Step title="General を開く">
    **Settings → Workspace → General** に移動します。
  </Step>
  <Step title="編集して保存する">
    ワークスペース名の横の **Edit** をクリックします。**Edit workspace** ダイアログで **Name** または **Description** を変更し、**Save** をクリックします。

    **成功時の状態:** サイドバーとワークスペースメニューに新しい名前が表示されます。
  </Step>
</Steps>

レポートに使うロゴと色を変更するには、[ワークスペースのブランディング](/ja/guide/workspace-branding)を参照してください。

## ケイパビリティをオン・オフする

**Settings → Workspace → Capabilities** には Advisor と Blind Spot が一覧されています。組織で利用可能な場合、どちらもすべてのワークスペースでオンの状態で始まり、ワークスペースのクレジットを使います。組織の Owner がすべてのワークスペースに設定していない限り、ワークスペースの Admin はそれぞれのスイッチでオフにしたり、再びオンにしたりできます。[Capabilities](/guide/capabilities) を参照してください。

## ワークスペースを削除する

<Warning>
ワークスペースを削除すると、その接続、会話、設定を含め、すべてのメンバーにとってワークスペースが削除されます。アプリには復元のボタンはありません。削除する前に、ワークスペースのメンバーに確認してください。
</Warning>

<Steps>
  <Step title="そのワークスペースから切り替える">
    今いるワークスペースは削除できません。まず別のワークスペースに切り替えてください。
  </Step>
  <Step title="削除する">
    **Settings → Organization → Workspaces** に移動し、ワークスペースの行の **Delete**（ゴミ箱アイコン）をクリックして、**Delete Workspace** ダイアログで確定します。名前を入力する必要はないため、先に行を確認してください。

    **成功時の状態:** 行が一覧から消えます。
  </Step>
</Steps>

他に起こること:

| 項目 | 起こること |
|---|---|
| スケジュールされたリソースの検出 | オフになります。ワークスペースの作成者に通知が届きます |
| ワークスペースの数 | 1 つ減り、プランの上限内に余裕ができます |
| 監査ログ | 削除がワークスペース名とともに[監査ログ](/guide/security/audit-logs)に記録されます |

## トラブルシューティング

<AccordionGroup>
  <Accordion title="New workspace がグレー表示になっている">
    **原因:** あなたが Developer または Viewer であるか、組織がプランのワークスペースの上限に達しています。上限に達すると、**Settings → Organization → Workspaces** に **Workspace limit reached** と表示されます。

    **対処:** Owner または Admin に作成を依頼するか、使わなくなったワークスペースを削除するか、[プランをアップグレード](/ja/guide/billing/subscription)してください。既存のワークスペースは上限に達しても引き続き機能します。
  </Accordion>
  <Accordion title="削除のアイコンがない">
    ワークスペースを削除できない場合、行のゴミ箱アイコンは非表示になります。

    - 今いるワークスペースです。まず別のワークスペースに切り替えてください。
    - 組織の最後のワークスペースです。これを削除する前に、別のワークスペースを作成してください。
  </Accordion>
  <Accordion title="チームメイトがワークスペースを見られない">
    **原因:** その人は Developer または Viewer で、そのワークスペースに追加されていません。

    **対処:** ワークスペースの **Members** ページから追加してください。[ワークスペースのメンバー](/ja/guide/workspace-users)を参照してください。
  </Accordion>
  <Accordion title="追加した接続をエージェントが見つけられない">
    **原因:** 接続は 1 つのワークスペースに属します。接続はおそらく別のワークスペースで追加されました。

    **対処:** サイドバーでワークスペース名を確認し、チャットしているワークスペースで接続を追加してください。
  </Accordion>
</AccordionGroup>

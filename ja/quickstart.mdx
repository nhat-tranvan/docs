このクイックスタートでは、サインインから最初の AI 調査までを案内します。CloudThinker が根本原因を特定し、修正案を提示します。所要時間は **約 10 分** です。デモから始めれば、クラウドの認証情報は不要です。

<Info>
**必要なもの:** Google または GitHub のアカウント、あるいは任意の業務用メールアドレス。自分の AWS、Azure、Google Cloud、Kubernetes へのアクセスは任意です — 読み取り専用のデモはそれらなしで利用できます。
</Info>

## 30 秒で覚える構文

<PromptSyntaxBasics />

<Steps>
  <Step title="サインインする">
    [app.cloudthinker.io](https://app.cloudthinker.io) にアクセスし、Google、GitHub、または SSO でサインインします。メールを使う場合は、アドレスを入力して **Continue with email** をクリックし、CloudThinker から届く 6 桁のコードを入力します。

    初回サインイン時には、短い質問が 2 つ続きます: **Tell us about you** (あなたのロール) と、組織のオーナーには **How can I help you?** です。回答するか **Skip** をクリックします — このガイドに沿って進める場合は **Just exploring** を選択してください。

    **成功状態:** Home に移動し、チャットボックスと **Needs you**、**Modules**、**Automation today** のカードが表示されます。サイドバーには **New chat**、**Artifacts**、**Automations**、**Investigation** が表示されます。

    <Tip>
    新しい組織は、カード登録不要の 14 日間の Team トライアルから始まります。プランの制限については [料金](/ja/guide/billing/pricing) をご確認ください。
    </Tip>
  </Step>

  <Step title="デモまたは自分のクラウドを接続する">
    <Tabs>
      <Tab title="デモ (認証情報不要)">
        1. サイドバーの **Try a demo environment** をクリックするか、**Settings → Connections** に移動します。
        2. **Demo available** と表示されたサービスを選択します — AWS、Google Cloud、Azure、Kubernetes のうち、提供されているものです。
        3. **Connect** をクリックし、次に **Use demo** をクリックします。セットアップには約 1 分かかります。

        [デモ環境](/ja/guide/connections/overview) は読み取り専用で、試用中の他のユーザーと共有されています。デモのチャットも、他のチャットと同様に [クレジット](/ja/guide/billing/usage) を消費します。
      </Tab>
      <Tab title="自分のクラウド">
        1. **Settings → Connections** に移動し、プロバイダーを選択します。
        2. **Connect** をクリックし、プロバイダーのフォームに従います。AWS の場合は **Role-Based** (推奨) または **Access Keys** を選択します。
        3. スターター権限は読み取り専用のままにしておきます。エージェントは変更を加える前に必ずあなたの [承認](/ja/guide/approval) を求めます。

        完全なウォークスルー: [AWS](/ja/guide/connections/aws)、[Azure](/ja/guide/connections/azure)、[Google Cloud](/ja/guide/connections/gcp)、[Kubernetes](/ja/guide/connections/kubernetes)。
      </Tab>
    </Tabs>

    **成功状態:** 接続に **Connected** と表示されます。**Connection error** と表示された場合は、[トラブルシューティング](#トラブルシューティング) をご確認ください。
  </Step>

  <Step title="最初の質問をする">
    デモの場合、CloudThinker は *Give me an overview of this AWS account.* のような編集可能なスタータープロンプト付きのチャットを開きます。そのまま送信してください。

    自分のクラウドの場合は、**New chat** をクリックして以下を送信します:

    ```text
    Give me an overview of this AWS account: resources by service and region, and anything that looks idle
    ```

    プロバイダー名またはクラスター名を自分のものに置き換えてください。

    **成功状態:** CloudThinker が、一般的なベストプラクティスではなく、アカウント内で見覚えのあるサービス、リージョン、リソースを挙げて回答します。
  </Step>

  <Step title="最初の調査を実行する">
    1. サイドバーの **Investigation** をクリックします。Resolve が最初のアラートソースの接続を求めてきた場合は、**Skip for now** をクリックします — 次のステップで扱います。
    2. **Log Incident** をクリックします。
    3. **What's happening?** に実際の問題を記述します — たとえば、前の回答で指摘された事項などです。または **Service Degradation** などの **Quick Start Template** を選んでフォームを事前入力します。
    4. **Severity** を選択し、**Context** に詳細を追加して、**Log Incident** をクリックします。

    CloudThinker がすぐに根本原因分析を開始します。手動で記録したインシデントにアラートソースは不要です。

    **成功状態:** インシデントが Investigation ビューの **AI is handling** の下に表示されます。調査が完了すると、根本原因と証拠、タイムライン、承認待ちの修復案が表示されます — 読み方については [調査と RCA](/ja/guide/incident/root-cause-analysis) をご覧ください。
  </Step>

  <Step title="すべてのインシデントを自動で調査する (任意)">
    **Resolve** に移動し、**Connect a source** をクリックします。Webhook (Datadog、PagerDuty、Grafana、Opsgenie、またはカスタムアラート)、クラウドポーリング (AWS、Azure Monitor、Google Cloud Monitoring)、または Slack や Microsoft Teams を選択します。

    **On Duty** — 自動調査 — はデフォルトでオンになっているため、そのソースから [Pulse](/ja/guide/pulse/overview) がルーティングするすべてのインシデントは、誰かが **Investigate** をクリックしなくても調査されます。完全なセットアップは [Pulse ソースを接続する](/ja/guide/pulse/setup) にあります。

    **成功状態:** ツールから送信されたイベントが Pulse に Signal として表示されます。
  </Step>
</Steps>

## 完了の確認

- [x] デモまたは自分の接続に **Connected** と表示されている
- [x] エージェントが、その環境で見覚えのあるリソースを挙げて回答した
- [x] 記録したインシデントに調査結果が表示され、証拠をたどって確認できる

**Getting started checklist** はこれらの最初のステップを記録し、完了するとクレジットを追加します。次回のサインインからは [Home](/guide/activity) が出発点になります: **Needs you** には承認待ちの項目が一覧表示され、進行中のインシデントがあるとバナーが表示されます。

## トラブルシューティング

<AccordionGroup>
  <Accordion title="サインインコードが届かない" icon="envelope">
    **確認事項:** 迷惑メールやプロモーションのフォルダー、およびコード画面に表示されたアドレスのスペルが正しいか。

    **修正:** **Resend code** をクリックするか、Google または GitHub でサインインします。
  </Accordion>

  <Accordion title="「Demo available」と表示されるサービスがない" icon="flask">
    **考えられる原因:** デモは、そのデモ対象が利用可能な間のみ提供されます。

    **修正:** **Show all connections** をクリックして他のプロバイダーを確認するか、後でもう一度試すか、代わりに自分のクラウドを接続します。
  </Accordion>

  <Accordion title="接続に「Connection error」と表示される" icon="circle-exclamation">
    **考えられる原因:** 認証情報が誤っているか、権限が不足しています — AWS の場合、通常はロールの信頼ポリシーにおける External ID の不一致です。

    **修正:** クラウドプロバイダー側で認証情報を修正し、接続の **Retry** をクリックします。プロバイダー固有の確認事項は、[AWS のトラブルシューティング](/ja/guide/connections/aws#トラブルシューティング) など各接続ガイドにあります。
  </Accordion>

  <Accordion title="エージェントがアクセスできないと言う、または一般的な回答をする" icon="user-slash">
    **考えられる原因:** 接続が、現在チャットしているものとは別の [ワークスペース](/ja/guide/workspaces) にあります。

    **修正:** サイドバー上部のワークスペースセレクターを確認し、接続を追加したワークスペースに切り替えて、もう一度質問します。
  </Accordion>

  <Accordion title="調査が「Not found」で終了した" icon="magnifying-glass">
    **考えられる原因:** 利用可能な証拠では根本原因を裏付けられませんでした — 接続された環境で実際には発生していないインシデントでよく起こります。

    **修正:** その環境で実際に起きている事象についてインシデントを記録するか、**Context** に詳細を追加するか、証拠を保持しているクラウドまたは監視ツールを接続します。
  </Accordion>
</AccordionGroup>
